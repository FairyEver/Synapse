# 数据服务 - 产品设计

## 概述

Synapse 内置一个本地 SQLite 数据服务，让用户自由记录数据，不需要考虑数据存哪里。数据完全存在用户本地，不进仓库，不上云。通过 API、MCP、CLI 三种方式访问，所有功能依赖 app 在运行。

## 架构

```
用户 ──→ 管理界面（渲染进程）──→ IPC ──→ 主进程 ──→ SQLite
                                              ↑
CLI ──→ HTTP (动态端口) ──→ 主进程 ──→ SQLite
                              ↑
MCP Server (stdio 脚本) ──→ HTTP ─┘
```

### 文件结构

模块级分离，与现有功能解耦。主进程侧、渲染进程侧、外部脚本各自独立目录。

```
electron/
  data-store/                    # ← 主进程侧，独立目录
    service.ts                   # SQLite 数据库操作（CRUD、建表、raw SQL）
    http-server.ts               # HTTP API server（动态端口、RPC 路由）
    ipc-handlers.ts              # IPC handler 注册（渲染进程桥接）
    channels.ts                  # IPC channel 常量
    cli-installer.ts             # synd CLI 安装逻辑
    mcp-installer.ts             # MCP server 注册逻辑
    types.ts                     # 数据服务相关类型定义
    index.ts                     # 统一入口，导出 initDataStore / shutdownDataStore
  services/                      # 现有服务，不动
  ipc/                           # 现有 IPC，不动
  main.ts                        # 新增两处：initDataStore() 和 shutdownDataStore()

src/
  modules/
    data-store/                  # ← 渲染进程侧，独立模块
      index.tsx                  # 模块入口（SidebarContentLayout）
      components/
        data-store-sidebar.tsx   # 左侧表列表
        data-table-view.tsx      # 右侧数据表格
        create-table-dialog.tsx  # 新建表弹窗
        table-schema-sheet.tsx   # 表结构查看
        row-editor.tsx           # 行内编辑
      hooks/
        use-data-store.ts        # IPC 调用封装
  types/
    bridge.ts                    # 仅扩展 SynapseBridge 接口，新增 dataStore 命名空间

data-store/                      # ← 顶层，独立于 Electron 进程
  shared/
    resolve-user-data.ts         # 根据 process.platform 解析 userData 路径，CLI 和 MCP 共用
  cli/
    index.ts                     # synd CLI 入口脚本
  mcp/
    index.ts                     # MCP server 入口脚本（stdio）
```

主进程集成点极小——`main.ts` 只加两处：
- 启动时：`await initDataStore()`
- 退出时：`await shutdownDataStore()`

渲染进程集成点：
- `bridge.ts` 扩展接口
- `preload.ts` 新增 `dataStore` 命名空间
- 顶部导航 Tabs 新增 DataStore 入口

## 数据库

- 文件位置：`userData/synapse-data.db`，全局唯一，跟仓库无关
- 初始化时执行 `PRAGMA journal_mode=WAL`，开启 WAL 模式提升并发读写性能
- 所有写操作包在事务中，`batchInsert` 必须在单个事务内完成
- 系统表 `_meta_tables`：追踪所有用户表的元数据，用户不可直接操作，API 自动维护
- 初始自带一张 `bookmarks` demo 表，含几条示例数据，仅作演示用途

### `_meta_tables` schema

| 列 | 类型 | 说明 |
|---|---|---|
| name | TEXT PK | 表名 |
| description | TEXT | 用户填的描述 |
| created_at | TEXT | ISO 时间戳 |
| updated_at | TEXT | 最后修改结构的时间 |

### bookmarks demo 表

列定义：

| 列 | 类型 |
|---|---|
| id | INTEGER（自增主键） |
| title | TEXT |
| url | TEXT |
| tags | TEXT |
| note | TEXT |

示例数据：

| id | title | url | tags | note |
|---|---|---|---|---|
| 1 | GitHub | https://github.com | dev,tools | 代码托管平台 |
| 2 | Claude | https://claude.ai | ai,assistant | AI 助手 |
| 3 | Tailwind CSS | https://tailwindcss.com | css,frontend | 实用优先的 CSS 框架 |

### 建表规则

- 每张用户表自动加自增 `id` 列做主键，用户无需定义主键
- 表名只允许字母、数字、下划线，不能以 `_` 开头（`_` 前缀保留给系统表）
- 支持的字段类型：TEXT, INTEGER, REAL, BLOB, JSON
- 建表后可加列，不可删列、不可改列类型
- 所有生成的 SQL 中，表名和列名一律用双引号包裹（`"table_name"."column_name"`），避免 SQLite 保留字冲突

### 导入导出

- 全量导入导出，格式为 `.db` 文件（SQLite 原始格式）
- 导出即复制数据库文件
- 导入流程：先用临时连接打开待导入文件，检查 `_meta_tables` 是否存在且 schema 正确，通过后关闭当前数据库连接 → 替换 `.db` 文件 → 重新打开。验证失败则拒绝导入并提示原因

## HTTP API

### 服务启动

- 主进程启动时起 HTTP server，动态分配端口
- 启动时生成随机 token，与端口信息一起写入 `userData/data-server.json`：

```json
{
  "port": 19530,
  "token": "a1b2c3d4e5f6...",
  "pid": 12345,
  "startedAt": "2026-04-22T10:00:00.000Z"
}
```

- CLI 和 MCP 启动时读取此文件获取端口和 token，可通过 PID 检查 app 是否存活
- 所有 HTTP 请求必须在请求头带上 `Authorization: Bearer <token>`，未通过认证的请求返回 401

### 接口风格

RPC 风格，统一入口 `POST /api`，通过 body 中的 `action` 字段区分操作。

### 结构化接口

| action | 说明 | 参数 |
|---|---|---|
| `listTables` | 列出所有用户表 | 无 |
| `createTable` | 新建表 | `name`, `description?`, `columns: [{ name, type }]` |
| `dropTable` | 删除表 | `name` |
| `describeTable` | 查看表结构 | `name` |
| `addColumn` | 给表加列 | `name`, `column: { name, type, default? }` |
| `insert` | 插入单条 | `table`, `data: { ... }` |
| `batchInsert` | 批量插入 | `table`, `rows: [{ ... }, ...]` |
| `query` | 查询数据 | `table`, `where?`, `orderBy?`, `limit?`, `offset?` |
| `update` | 更新数据 | `table`, `id`, `data: { ... }` |
| `delete` | 删除数据 | `table`, `id` |

`query` 不传 `limit` 时默认返回 100 条。响应中包含 `total` 字段表示符合条件的总行数，方便分页。

### 特殊接口

| action | 说明 | 参数 |
|---|---|---|
| `rawSQL` | 执行原始 SQL | `sql`, `params?` |

`rawSQL` 限制规则：
- 禁止操作 `_` 前缀表（如 `_meta_tables`），防止破坏系统元数据
- 禁止 `ATTACH` / `DETACH` 语句，防止访问其他数据库文件
- 其余 SQL 不做限制

返回值根据语句类型自动判断，统一包在标准 `{ ok, data }` 结构中：
- `SELECT` / `PRAGMA` / `EXPLAIN` 开头 → `{ "ok": true, "data": { "rows": [...] } }`
- 其他写操作 → `{ "ok": true, "data": { "changes": number, "lastInsertRowid": number } }`

### query 的 where 语法

支持两种形式，每次请求选择其中一种。多条件之间为 AND 关系。需要 OR 逻辑请使用 `rawSQL`。

**简单等值匹配**（对象形式）：

```json
{ "where": { "tags": "dev", "status": "active" } }
```

**表达式匹配**（数组形式）：

```json
{ "where": [
  { "field": "tags", "op": "=", "value": "dev" },
  { "field": "score", "op": ">", "value": 80 },
  { "field": "title", "op": "LIKE", "value": "%claude%" }
] }
```

支持的操作符：`=`, `!=`, `>`, `<`, `>=`, `<=`, `LIKE`

### query 的 orderBy 语法

支持两种形式：

**简单排序**（字符串，默认升序）：

```json
{ "orderBy": "created_at" }
```

**指定方向**（对象形式）：

```json
{ "orderBy": { "field": "created_at", "dir": "desc" } }
```

### JSON 列处理

- API 接收时：JSON 列接受解析后的对象，内部序列化为字符串存储
- API 返回时：JSON 列自动反序列化为对象返回
- 对调用方完全透明，无需手动 JSON.stringify/parse
- `where` 条件不支持 JSON 列内部字段查询，仅支持整体等值匹配。需要 `json_extract` 等高级查询请使用 `rawSQL`

### 响应格式

所有接口统一响应结构：

```jsonc
// 成功 - 查询
{ "ok": true, "data": [...], "total": 100 }

// 成功 - 写操作（insert/update/delete）
{ "ok": true, "data": { "id": 4 }, "affected": 1 }

// 成功 - 批量插入
{ "ok": true, "data": { "ids": [4, 5, 6] }, "affected": 3 }

// 成功 - 结构操作（createTable/dropTable/addColumn）
{ "ok": true }

// 失败
{ "ok": false, "error": "table 'xxx' not found" }
```

`affected` 仅在写操作时出现，表示影响行数。

## 消费端

### 管理界面（渲染进程）

- 通过 IPC 访问主进程数据库服务
- 轻量表格浏览器：查看表结构、翻页浏览数据、手动增删改
- 显示当前 HTTP 服务端口号
- 提供导入/导出按钮

### CLI

- 命令名：`synd`
- 打包在 Synapse app 内，app 安装时自动将 CLI 脚本安装到系统 PATH
- 设置界面提供"重新安装 CLI"按钮
- 通过读取 `userData/data-server.json` 获取端口和 token，调用 HTTP API
- 依赖 app 在运行

#### 命令列表

```bash
synd tables                                     # 列出所有表
synd create <name> <col:type> [col:type...]     # 建表，如 synd create notes title:text body:text
synd drop <name>                                # 删表
synd describe <name>                            # 查看表结构
synd add-column <table> <col:type>              # 加列
synd insert <table> --data '{"k":"v"}'          # 插入单条
synd insert <table> --batch '[{...},{...}]'     # 批量插入
synd query <table> [--where k=v] [--limit N]    # 查询
synd update <table> <id> --data '{"k":"v"}'     # 更新
synd delete <table> <id>                        # 删除
synd sql '<SQL>'                                # 原始 SQL
synd status                                     # 查看服务状态/端口
```

### MCP Server

- 独立 stdio 脚本，打包在 app 内
- 内部通过 HTTP 调用 API，与 CLI 共享同一套接口
- app 内提供一键注册按钮，支持 Claude Code 和 Codex 两个编辑器
- 设置界面提供"重新注册 MCP"按钮（分别对应两个编辑器）
- 依赖 app 在运行

#### MCP 注册写入内容

注册逻辑幂等：目标配置中已存在则更新路径，不存在则新增。卸载 app 时不主动清理注册。

Claude Code 注册时向 `~/.claude/settings.json` 的 `mcpServers` 中写入：

```json
{
  "mcpServers": {
    "synapse-data": {
      "command": "node",
      "args": ["/Applications/Synapse.app/Contents/Resources/data-store/mcp/index.js"]
    }
  }
}
```

Codex 注册时向 `~/.codex/settings.json` 的 `mcpServers` 中写入相同结构。

Windows 路径相应替换为安装目录下的对应位置。

## CLI 和 MCP 的构建与分发

### 构建方式

使用 esbuild 将 `data-store/cli/index.ts` 和 `data-store/mcp/index.ts` 各自 bundle 成单个 JS 文件。

选择 esbuild 的原因：
- 项目主进程已经用 tsc 编译，但 tsc 不做 bundle，外部脚本需要独立运行，不能依赖 node_modules 解析
- esbuild 单文件 bundle，零外部依赖，CLI 和 MCP 脚本可以直接 `node xxx.js` 运行
- 速度极快，不影响构建流程

在 `package.json` 中新增构建脚本：

```json
{
  "build:data-store": "esbuild data-store/cli/index.ts --bundle --platform=node --outfile=dist-data-store/cli/index.js && esbuild data-store/mcp/index.ts --bundle --platform=node --outfile=dist-data-store/mcp/index.js"
}
```

### 打包分发

在 electron-builder 配置中通过 `extraResources` 将构建产物打入 app：

```json
{
  "extraResources": [
    {
      "from": "dist-data-store",
      "to": "data-store"
    }
  ]
}
```

打包后位于 `Resources/data-store/cli/index.js` 和 `Resources/data-store/mcp/index.js`。

### CLI 安装

`cli-installer.ts` 在安装时创建一个 shell 脚本到 `/usr/local/bin/synd`：

```bash
#!/bin/sh
exec node "/Applications/Synapse.app/Contents/Resources/data-store/cli/index.js" "$@"
```

Windows 下创建 `synd.cmd` 到对应 PATH 目录。

### 端口文件发现

CLI 和 MCP 脚本需要找到 `userData/data-server.json`。采用平台路径硬编码：

| 平台 | userData 路径 |
|---|---|
| macOS | `~/Library/Application Support/Synapse/` |
| Windows | `%APPDATA%/Synapse/` |
| Linux | `~/.config/Synapse/` |

在 `data-store/shared/resolve-user-data.ts` 中实现路径解析，CLI 和 MCP 共同引用。这与 Electron 的 `app.getPath('userData')` 行为一致。

### Node.js 版本要求

CLI 和 MCP 脚本使用系统 `node` 运行。脚本入口处检查 Node.js 版本，低于 18 时输出错误提示并退出：

```
Error: synd requires Node.js >= 18.0.0 (current: X.X.X)
```

## MCP Tool 定义

MCP Server 暴露的 tool 与结构化 API 一一对应：

- `list_tables` — 列出所有表
- `create_table` — 新建表
- `drop_table` — 删除表
- `describe_table` — 查看表结构
- `add_column` — 加列
- `insert` — 插入数据
- `batch_insert` — 批量插入数据
- `query` — 查询数据
- `update` — 更新数据
- `delete` — 删除数据
- `raw_sql` — 执行原始 SQL

## 生命周期

- app 启动 → 打开数据库 → `PRAGMA integrity_check` 检查完整性 → 启动 HTTP server → 写入端口文件
- 数据库损坏时 → 将 `.db` 文件重命名为 `.db.corrupt.{timestamp}` → 创建新的空数据库 → 在管理界面弹通知告知用户
- app 正常退出 → 关闭 HTTP server → 关闭数据库 → 删除端口文件
- app crash → 端口文件残留，CLI/MCP 通过 PID 检测兜底
- 导入数据库 → 验证待导入文件（临时连接检查 `_meta_tables` schema）→ 关闭数据库连接 → 替换 .db 文件 → 重新打开 → HTTP 端口保持不变，无需重启
