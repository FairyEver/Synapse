# 编辑器设置扫描 - 产品设计

## 概述

Synapse 新增一个独立顶层 Tab「编辑器」，扫描并展示 Cursor、Claude Code、Codex 三个编辑器在本机的全局 skill、全局规则，以及用户已配置项目中的项目级 skill 和规则。只读查看，不做修改。

## 定位

审计工具。用户打开这个 Tab 就能看到三个编辑器各自装了什么、配了什么，不需要手动翻文件系统。

当前版本只读。后续可能扩展为支持删除、编辑、从 Synapse 仓库重新安装等写操作。

### 与 Settings > 工具 的关系

Settings > 工具 > IDE 面板展示的是各编辑器全局目录的路径和是否存在，功能是「创建/打开目录」。本 Tab 展示的是目录里的具体内容（每个 skill 和 rule 的名称、来源、正文预览），功能是「审计内容」。两者互补，不重复。

## 架构

```
渲染进程（编辑器 Tab）──→ IPC ──→ 主进程 ──→ 文件系统扫描
```

### 数据来源

- 全局 skill / 规则：直接读取各编辑器的全局目录
- 项目级 skill / 规则：遍历 Settings > 项目 中已配置的项目路径，读取各编辑器的项目级目录

### 文件结构

主进程侧新增扫描服务，渲染进程侧新增独立模块。

```
electron/
  services/
    editor-scan-service.ts           # 扫描逻辑：读取各编辑器的 skill/rule 文件
  ipc/
    editor-scan-handlers.ts          # IPC handler 注册

src/
  modules/
    editor-scan/                     # 渲染进程侧，独立模块
      index.tsx                      # 模块入口（SidebarContentLayout）
      components/
        editor-scan-sidebar.tsx      # 左侧编辑器列表
        global-overview.tsx          # 全局 skill + rule 展示
        project-overview.tsx         # 项目级 skill + rule 展示
        scan-item-card.tsx           # 单个 skill/rule 卡片
        empty-scan-state.tsx         # 空状态
      hooks/
        use-editor-scan.ts           # IPC 调用封装
  types/
    editor-scan.ts                   # 扫描结果类型定义
```

集成点：
- `App.tsx` 顶部导航新增「编辑器」Tab
- `bridge.ts` 扩展 `editorScan` 命名空间
- `preload.ts` 新增 `editorScan` 桥接
- `channels.ts` 新增扫描相关 IPC 通道

## 各编辑器的扫描路径

### 全局

| 编辑器 | 全局 Skill 目录 | 全局规则路径 |
|---|---|---|
| Claude Code | `~/.claude/skills/` | `~/.claude/rules/` |
| Cursor | `~/.cursor/skills/` | 不支持（显示占位说明） |
| Codex | `~/.agents/skills/` | `~/.codex/AGENTS.md`（单文件，非目录） |

Codex 全局规则路径支持 `$CODEX_HOME` 环境变量覆盖，未设置时默认 `~/.codex/`。

### 项目级

| 编辑器 | 项目 Skill 目录 | 项目规则路径 |
|---|---|---|
| Claude Code | `{project}/.claude/skills/` | `{project}/.claude/rules/` |
| Cursor | `{project}/.cursor/skills/` | `{project}/.cursor/rules/` |
| Codex | `{project}/.agents/skills/` | `{project}/AGENTS.md` |

### Skill 识别规则

Skill 以目录为单位。扫描时：
- 目录下存在 `SKILL.md` → 读取其内容作为 skill 正文
- 目录下存在 `.synapse.json` → 标记为 Synapse 安装的 skill（读取 `id` 字段）
- 目录下既无 `SKILL.md` 也无其他 `.md` 文件 → 跳过
- 目录下无 `SKILL.md` 但有其他 `.md` 文件 → 按文件名字母序取第一个 `.md` 文件作为 skill 正文

Skill 卡片展示：名称（目录名）、来源标记（Synapse / 外部）、正文预览（前 3 行）。

### Rule 识别规则

**Claude Code**：`rules/` 目录下的每个 `.md` 文件是一条规则。读取文件名作为规则名，读取 frontmatter 中的 `paths` 字段，读取正文预览。

**Cursor**：`rules/` 目录下的每个 `.mdc` 文件是一条规则。读取 frontmatter 中的 `description`、`globs`、`alwaysApply` 字段。

**Codex**：`AGENTS.md` 是一个合并文件。扫描其中的 `<!-- synapse-rule:{id}:begin -->` 标记识别 Synapse 安装的规则段落。无标记的内容按顶级 heading（`#`）拆分为独立规则条目；如果没有 heading 则作为一条「手写规则」整体展示。

Rule 卡片展示：名称（文件名或标记 ID）、来源标记（Synapse / 外部）、正文预览（前 3 行）、元数据（globs / paths / alwaysApply 等）。

### 有意排除的文件

- `~/.claude/CLAUDE.md` 和项目级 `.claude/CLAUDE.md`：这是 Claude Code 的全局/项目指令文件，不在 `rules/` 目录体系内，概念上不属于"规则"。当前版本不纳入扫描。
- `.cursorrules`（Cursor 旧版项目规则文件）：已被 `.cursor/rules/` 目录取代，不扫描。

## IPC Channels

```ts
editorScan: {
  scanAll: "synapse:editor-scan:scan-all",    // → EditorScanResult
}
```

### 接口定义

**scanAll**：无参数。一次性扫描三个编辑器的全局 skill/规则 + 所有已配置项目的项目级 skill/规则，返回完整结果。渲染侧按选中编辑器过滤展示，切换编辑器无需重新请求。

合并为单个 IPC 调用的原因：全局扫描和项目扫描都是纯文件系统读取，主进程内部可并行执行，合并后减少 IPC 往返次数，渲染侧状态管理也更简单（一个 loading 态而非两个）。

## 类型定义

```ts
type EditorScanItemSource = "synapse" | "external"

type EditorScanSkillItem = {
  name: string                        // 目录名
  path: string                        // 完整路径
  source: EditorScanItemSource        // synapse 安装 or 外部
  synapseContentId: string | null     // .synapse.json 中的 id
  preview: string                     // 正文前 3 行
  fileCount: number                   // 目录内文件数
}

type EditorScanRuleItem = {
  name: string                        // 文件名或标记 ID
  path: string                        // 完整路径
  source: EditorScanItemSource
  synapseContentId: string | null
  preview: string                     // 正文前 3 行
  metadata: Record<string, string>    // frontmatter 中的元数据（globs、paths 等）
}

type EditorScanEditorStatus = "detected" | "not-detected"

type EditorScanGlobalResult = {
  editorId: SynapseEditorId
  editorLabel: string
  status: EditorScanEditorStatus      // 基于配置目录是否存在判断
  skills: EditorScanSkillItem[]
  rules: EditorScanRuleItem[]
  rulesSupported: boolean             // false 时显示占位说明（如 Cursor 全局规则）
}

type EditorScanProjectEntry = {
  editorId: SynapseEditorId
  editorLabel: string
  skills: EditorScanSkillItem[]
  rules: EditorScanRuleItem[]
}

type EditorScanProjectResult = {
  projectPath: string
  projectName: string                 // 路径最后一段
  pathExists: boolean                 // 项目路径是否存在于磁盘
  editors: EditorScanProjectEntry[]
}

type EditorScanResult = {
  global: EditorScanGlobalResult[]
  projects: EditorScanProjectResult[]
}
```

### 编辑器检测逻辑

`status` 字段基于编辑器配置目录是否存在判断，不依赖 CLI 安装检测：

| 编辑器 | 检测目录 |
|---|---|
| Claude Code | `~/.claude/` |
| Cursor | `~/.cursor/` |
| Codex | `~/.codex/` 或 `$CODEX_HOME/` |

目录存在 → `"detected"`，不存在 → `"not-detected"`。这与"编辑器是否安装"不完全等价（用户可能安装了编辑器但从未使用过），但对审计场景足够准确。

### 左侧边栏

- 三个编辑器固定列出，不管是否检测到
- 每个编辑器显示图标 + 名称 + 摘要计数（如「3 skill · 2 规则」，计数 = 全局 + 所有项目的总和）
- 未检测到配置目录的编辑器：名称后显示灰色「未检测到」标记，计数不显示
- 选中态高亮

### 右侧内容区

纵向滚动，分为两大区域：

**全局区域**：
- 标题「全局 Skill (N)」+ 列表
- 标题「全局规则 (N)」+ 列表
- 不支持的功能显示占位说明（如 Cursor 全局规则：「Cursor 暂不支持全局规则目录」）
- 全局区域为空时显示「未检测到全局 skill」/「未检测到全局规则」

**项目区域**：
- 按项目分组，每个项目一个可折叠区块，默认折叠
- 标题格式：「项目: {项目名} ({N} skill, {M} rule)」，计数仅统计当前选中编辑器
- 项目下按编辑器当前选中的那个展示 skill 和 rule
- 项目内无任何 skill/rule 时不显示该项目（减少噪音）
- 项目路径已不存在时：显示项目名 + 灰色「路径不存在」标记，不展开
- 所有项目对当前编辑器都为空时显示：「已配置的项目中未检测到 {编辑器名} 的 skill 或规则」
- 没有配置任何项目时显示提示：「在 设置 > 项目 中添加项目路径」

### Skill/Rule 卡片

每个 skill/rule 用一行紧凑卡片展示：

```
┌────────────────────────────────────────────────────────────────┐
│ ◆ my-db-skill                                      Synapse    │
│   查询本地数据库的 MCP 工具，支持 list_tables...               │
└────────────────────────────────────────────────────────────────┘
```

- 左侧图标：◆ 表示 Synapse 安装，○ 表示外部
- 名称：skill 目录名 / rule 文件名
- 右侧来源标签：Synapse（Badge accent）/ 外部（Badge muted）
- 第二行：正文预览（单行截断）
- Rule 额外显示元数据行（paths / globs / alwaysApply），用 muted 小字

列表排序：Synapse 来源排在前面，同来源内按名称字母序。

点击卡片内联展开完整内容（手风琴式），展开区域包含：
- 正文全文（限制最大高度 320px，超出部分 ScrollArea 滚动）
- 完整元数据
- 文件路径（可点击，Skill 在 Finder 中打开目录，Rule 打开文件所在目录并选中文件）

### 不支持的功能占位

当某编辑器不支持某功能时（如 Cursor 全局规则），在对应位置显示：

```
┌────────────────────────────────────────────────────────────────┐
│  全局规则                                                      │
│  Cursor 暂不支持全局规则目录                                   │
└────────────────────────────────────────────────────────────────┘
```

使用 muted 文字，不显示空状态图标。

### 刷新

右上角「刷新」按钮，重新扫描所有编辑器的所有内容。扫描期间按钮显示 loading 状态。

扫描结果在渲染侧按选中编辑器过滤展示，切换编辑器时直接从已有结果中筛选，无需重新请求。

首次进入 Tab 时自动触发一次扫描。

### 加载态

首次扫描期间，右侧内容区显示骨架屏（两组 Skeleton 行模拟全局 Skill 和全局规则区域）。后续刷新时保留旧数据展示，仅刷新按钮显示 loading。

### 空状态

当选中的编辑器完全没有任何 skill 和 rule（全局 + 所有项目）时：

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│              未检测到 Claude Code 的 skill 或规则             │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 扫描逻辑

### 性能考虑

- 单个 IPC 调用 `scanAll`，主进程内部并行执行全局扫描和项目扫描
- 项目扫描按项目并行，每个项目内按编辑器并行
- 单个目录扫描使用 `readdir` + `stat`，不递归子目录（skill 目录只看一层）
- 文件预览只读前 512 字节，不读全文
- 扫描结果不缓存，每次都重新读取文件系统（保证实时性）
- 渲染侧从完整结果中按选中编辑器过滤，切换编辑器零延迟

### 错误处理

- 目录不存在 → 返回空数组，不报错
- 项目路径不存在 → `pathExists: false`，跳过扫描，界面显示「路径不存在」标记
- 单个文件读取失败（权限、编码等）→ 跳过该文件，记录 warn 日志
- 整个扫描失败（IPC 异常）→ 界面显示错误提示，支持重试

## 后续扩展方向（不在当前版本）

- 支持删除编辑器中的 skill/rule
- 支持从 Synapse 仓库重新安装 skill/rule 到编辑器
- 支持对比 Synapse 仓库版本与编辑器本地版本的差异
- 支持批量操作（全部更新、全部清理等）
- 纳入 CLAUDE.md（全局/项目指令文件）的扫描展示
- 纳入 `.cursorrules`（Cursor 旧版规则文件）的扫描
- 搜索/过滤功能（跨编辑器、跨项目搜索 skill/rule）
