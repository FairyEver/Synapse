# 本地运行 — 提示词快速测试功能

## 背景

Synapse 管理三种内容类型：规则、技能、提示词。其中提示词是纯文本、无附件、一发一收，天然适合快速测试。规则和技能依赖特定上下文环境，不适合直接测试。

用户电脑上可能安装了 Claude Code 或 Codex CLI，可以通过 spawn 子进程的方式将提示词发送给这些工具，并流式接收返回结果。

## 核心原理

### CLI 工具的程序化调用

所有命令行工具都通过三根标准管道通信：

- **stdin** — 标准输入，程序往里写数据，子进程能收到
- **stdout** — 标准输出，子进程的输出，程序可以逐行读取
- **stderr** — 标准错误，子进程的错误信息

Node.js 的 `child_process.spawn()` 可以启动子进程并拿到这三根管道的引用。

### Claude Code 调用方式

```bash
claude --output-format stream-json -p "提示词内容"
```

- `--output-format stream-json`：stdout 逐行输出 JSON 事件
- `-p`：非交互模式，直接传入提示词
- 每行 JSON 有 `type` 字段区分事件类型：`assistant`（模型输出）、`result`（最终结果）、`tool_use`（工具调用）等

### Codex CLI 调用方式

```bash
codex exec "提示词内容"
```

- 非交互模式，stdout 输出纯文本
- 没有结构化 JSON，只能按文本流处理
- 任务完成后进程自动退出

## 现有架构支撑

| 已有能力 | 位置 | 复用方式 |
|---------|------|---------|
| `child_process.spawn()` 模式 | `electron/services/git-command.ts` | 照搬逐行读取 stdout 的模式 |
| IPC 通道体系 | `electron/ipc/channels.ts` + `preload.ts` + `bridge.ts` | 新增 test 域的 channel |
| main→renderer 事件推送 | `repository.onProgress` | 测试输出流照此模式实现 |
| 读取提示词内容 | `readContent(type, id)` → `SynapseTextContentFile` | 直接复用 |

## 实现方案

### 1. CLI 检测服务（Electron main 进程）

新建 `electron/services/cli-detect-service.ts`：

- 启动时执行 `which claude` / `which codex`（Windows 用 `where`）检测本机安装的 CLI 工具
- 缓存检测结果，提供 `getAvailableAgents()` 方法
- 通过 IPC 暴露给 renderer

### 2. 测试执行服务（Electron main 进程）

新建 `electron/services/prompt-test-service.ts`：

- `startTest(agentType, promptContent)` — spawn 子进程，返回 testId
- `stopTest(testId)` — kill 子进程
- 子进程 stdout 逐行读取，通过 `webContents.send()` 推送给 renderer

```typescript
// 伪代码
function startTest(agent: "claude-code" | "codex", content: string): string {
  const testId = generateId();
  const args = agent === "claude-code"
    ? ["--output-format", "stream-json", "-p", content]
    : ["exec", content];
  const bin = agent === "claude-code" ? "claude" : "codex";

  const proc = spawn(bin, args);
  proc.stdout.on("data", (chunk) => {
    mainWindow.webContents.send("synapse:test:output", {
      testId,
      text: chunk.toString(),
    });
  });
  proc.on("close", (code) => {
    mainWindow.webContents.send("synapse:test:done", { testId, code });
  });

  runningTests.set(testId, proc);
  return testId;
}
```

### 3. IPC 通道

在 `channels.ts` 新增：

```typescript
export const test = {
  getAvailableAgents: "synapse:test:get-available-agents",  // invoke → string[]
  start: "synapse:test:start",                               // invoke → testId
  stop: "synapse:test:stop",                                 // invoke → void
  onOutput: "synapse:test:output",                           // event (main→renderer)
  onDone: "synapse:test:done",                               // event (main→renderer)
} as const;
```

### 4. Bridge 接口

在 `bridge.ts` 的 `SynapseBridge` 中新增：

```typescript
test: {
  getAvailableAgents(): Promise<Array<{ type: string; name: string }>>;
  start(agentType: string, contentType: string, contentId: string): Promise<string>;
  stop(testId: string): Promise<void>;
  onOutput(callback: (data: { testId: string; text: string }) => void): () => void;
  onDone(callback: (data: { testId: string; code: number }) => void): () => void;
};
```

### 5. UI 变更

**content-detail-menubar.tsx**：
- 提示词类型增加"测试"按钮（仅当检测到本机有可用 CLI 工具时显示）
- 如果有多个工具可用，按钮带下拉菜单选择

**新建测试结果 dialog**：
- 流式文本展示区域（终端风格，等宽字体，深色背景）
- 顶部显示使用的工具名称和提示词标题
- 底部有"停止"按钮和运行状态指示
- 完成后显示耗时和 token 统计（Claude Code 的 result 事件包含此信息）

## 工作量评估

| 模块 | 工作量 | 说明 |
|------|--------|------|
| CLI 检测 | 0.5 天 | `which` 命令 + 缓存 + IPC |
| spawn + 流式读取 | 0.5 天 | 照搬 git-command 模式 |
| IPC 通道 + Bridge | 0.5 天 | channels + preload + bridge 三处同步新增 |
| 测试结果 UI | 1 天 | dialog + 流式文本渲染 + 状态管理 |
| 联调 + 边界处理 | 0.5 天 | 进程异常退出、超时、取消 |

总计约 **2-3 天**。

## 注意事项

- Claude Code 的 stream-json 有结构化事件，可以精细展示（区分文本、工具调用、思考过程）
- Codex 只有纯文本流，展示相对粗糙
- 需要处理 CLI 工具不在 PATH 中的情况（提示用户安装或配置路径）
- 子进程需要设置合理的超时时间，防止挂起
- 提示词可能很长，需要考虑命令行参数长度限制（可改用 stdin 传入）
