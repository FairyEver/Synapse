# 数据服务类型系统 · 第一性原理设计

按第一性原理从零重建：`DataStoreColumnDef` 用 `kind + choices` 替代 `type + enumValues`，SQLite DDL 只使用原生 affinity（TEXT/INTEGER/REAL/BLOB），`_meta_columns` 成为 kind 与 choices 的唯一真相，无迁移、无兼容层、无别名。

---

## 1. 设计原则

1. **意图优先**：列声明描述"这列放什么"，不是"SQL 存什么"。
2. **正交拆分**：语义（kind）与存储（SQLite affinity）是两个层次，决不共用一个字段。
3. **单一真相**：kind / choices 只在 `_meta_columns` 存一份；SQLite column type 仅做 affinity 提示。
4. **无 SQL 词汇冲突**：对外字面量不与 SQL 关键词同名（`ENUM`/`JSON`/`BLOB`/`REAL`/`DATETIME` 彻底消失于公开接口）。
5. **一种语言跨所有层**：MCP / HTTP / IPC / CLI / UI 共用同一个 `Column` 形状。
6. **无包袱**：不保留别名、不做迁移、首次启动直接重建 DB。

## 2. 规范 kind（10 个）

| kind | SQLite affinity | 运行时值 | 序列化 | 典型列 |
|---|---|---|---|---|
| `text` | TEXT | string | 原样 | title, notes |
| `integer` | INTEGER | number | 原样 | count, age |
| `decimal` | REAL | number | 原样 | price, weight |
| `boolean` | INTEGER | boolean | 0/1 | done, enabled |
| `date` | TEXT | string | YYYY-MM-DD | birthday |
| `timestamp` | TEXT | string | ISO 8601 | published_at |
| `single_choice` | TEXT | string | ∈ choices | priority, status |
| `multi_choice` | TEXT | string[] | JSON 数组 | tags, categories |
| `json` | TEXT | object/array | JSON 字符串 | metadata |
| `binary` | BLOB | Uint8Array | base64 over MCP | thumbnail |

**命名取舍**：全部小写，避免 SQL 大写关键字观感；`ENUM`→`single_choice`、`MULTI_ENUM`→`multi_choice`、`BLOB`→`binary`、`REAL`→`decimal`、`DATETIME`→`timestamp`；`json` 保留（通用术语，多选错选风险由 `multi_choice` 并列解决）。

## 3. 统一 Column 形状

同一类型跨所有层：

```ts
type ColumnKind =
  | "text" | "integer" | "decimal" | "boolean"
  | "date" | "timestamp"
  | "single_choice" | "multi_choice"
  | "json" | "binary"

type Column = {
  name: string
  kind: ColumnKind
  choices?: string[]          // 当且仅当 kind ∈ {single_choice,multi_choice} 时必填非空；其他 kind 严禁出现
  description?: string
  primaryKey?: true            // describe 返回时才有
  system?: true                // describe 返回时才有
}
```

合并原 `DataStoreColumnDef` 与 `DataStoreColumnInfo` 为同一 `Column`。create 入参与 describe 返回走同一形状。

## 4. 存储模型

### 4.1 `_meta_columns` 新 schema

```sql
CREATE TABLE _meta_columns (
  table_name  TEXT NOT NULL,
  column_name TEXT NOT NULL,
  kind        TEXT NOT NULL,
  choices     TEXT,
  description TEXT NOT NULL DEFAULT '',
  PRIMARY KEY (table_name, column_name)
)
```

- 废弃 `enum_values`；用 `choices` + `kind` 取代。
- 系统列不入此表，describe 时由 service 按名字注入。

### 4.2 SQLite DDL 只用原生 affinity

`CREATE TABLE` 仅拼 `TEXT` / `INTEGER` / `REAL` / `BLOB`，不再出现 `ENUM`/`MULTI_ENUM`/`BOOLEAN`/`JSON`/`DATE`/`DATETIME` 等 custom type。

### 4.3 首次启动重建 DB

`open()` 启动时检测 `_meta_columns` 是否含 `kind` 列。不符则把旧 `synapse-data.db` rename 为 `.legacy.{ts}` 备份后新建空库。**无 schema migration。**

## 5. 服务端契约

### 5.1 公共方法签名

```ts
createTable(name, columns: Column[], description?): void
addColumn(table, column: Column & { default?: unknown }): void
describeTable(name): { name, description, columns: Column[], rowCount, createdAt, updatedAt }
updateColumnDescription(table, column, description): void
updateColumnChoices(table, column, choices: string[]): void   // 原 updateColumnEnumValues
getColumnChoicesUsage(table, column): Record<string, number>  // 原 getColumnValueUsage
// 未变：listTables / dropTable / insert / batchInsert / query / update / delete
//      / updateWhere / deleteWhere / count / renameTable / renameColumn / dropColumn / rawSQL
```

### 5.2 入口校验顺序

`createTable` / `addColumn` 每列：

1. 列名合法
2. kind ∈ 10 种
3. choices 一致性：choice 系 kind 必非空；其他 kind 严禁
4. Semantic guard（§5.3）
5. 写入 `_meta_columns(kind, choices, description)`
6. DDL 拼接用 `kindToAffinity(kind)`

### 5.3 Semantic guard

基于 kind 的规则，错误消息用 kind 词汇：

```
kind=text|json & name ∈ priority/status/level/优先级/级别/…
  → "Use kind=\"single_choice\" with choices=[...]."

kind=text|json & name ∈ tags/labels/categories/标签/分类/…
  → "Use kind=\"multi_choice\" with choices=[...]."

kind=integer & name ∈ {done,enabled,…} ∪ is_*/has_*/can_*/should_*/是否*
  → "Use kind=\"boolean\"."

kind=text|json & name ∈ category/type/kind/tag/label/种类
  → 同时提示 single_choice 或 multi_choice
```

关键词常量改名：`SINGLE_CHOICE_NAME_HINTS` / `MULTI_CHOICE_NAME_HINTS` / `CHOICE_AMBIGUOUS_NAME_HINTS` / `BOOLEAN_NAME_EXACT` / `BOOLEAN_NAME_PREFIXES` / `BOOLEAN_NAME_PREFIXES_CN`。

### 5.4 运行时缓存简化

当前 6 个 Map 合并为：

```ts
private columnMeta: Map<string, Map<string, { kind: ColumnKind; choices?: string[] }>>
```

派生谓词通过 helper（`isJsonSerializedKind` / `isBooleanKind` / `isDateKind` / `isTimestampKind` / `isChoiceKind` / `isMultiChoiceKind`）。

### 5.5 `describeTable` 组装

1. `PRAGMA table_info(table)` 拿列顺序与主键
2. `SELECT kind, choices, description FROM _meta_columns WHERE table_name = ?`
3. 按 PRAGMA 顺序拼 `Column[]`：系统列注入固定 kind（`integer` / `timestamp` / `timestamp`）与 `system: true`；业务列从 meta 取值

### 5.6 `rawSQL` DDL hook

DDL 执行后同步 `_meta_columns`。没有 meta 行的列按 SQLite affinity 反推：`INT*`→`integer`、`REAL/FLOA/DOUB`→`decimal`、`BLOB`→`binary`、其他→`text`。rawSQL 无法得到 `boolean`/`date`/`timestamp`/`choice`/`json` 这些富语义——需要这些必须走 `create_table`/`add_column`。

## 6. MCP 工具 schema

### 6.1 `create_table` 列 schema

```json
{
  "name":        { "type": "string" },
  "kind":        { "type": "string", "enum":
                    ["text","integer","decimal","boolean","date","timestamp",
                     "single_choice","multi_choice","json","binary"] },
  "choices":     { "type": "array", "items": { "type": "string" } },
  "description": { "type": "string" }
}
```

Tool description 里 kinds 逐条列清：

```
text           Free-form string
integer        Whole number
decimal        Fractional number
boolean        true or false
date           YYYY-MM-DD
timestamp      ISO 8601 timestamp
single_choice  One value from a fixed list; requires non-empty choices
multi_choice   Multiple values from a fixed list; requires non-empty choices
json           Free-form object or array (use only when value has no fixed structure)
binary         Raw bytes
```

### 6.2 工具名

- `update_column_enum_values` → `update_column_choices`（参数 `values` → `choices`）
- 其余工具名不变

### 6.3 其它工具 description 清扫

insert / update / batch_insert / query / describe_table 的描述里所有 `BOOLEAN` / `DATE` / `DATETIME` / `ENUM` / `MULTI_ENUM` / `JSON` / `BLOB` / `REAL` 字面量 **100% 消除**。值格式用自然语言：

- "boolean values accept true or false"
- "date values expect YYYY-MM-DD"
- "timestamp values expect ISO 8601 (e.g. 2026-04-24T15:30:00)"
- "multi_choice values expect an array of strings, each in the column's choices"
- "json values accept any object or array"

## 7. IPC / Bridge / Dispatcher

- `channels.ts`：`updateColumnEnumValues` → `updateColumnChoices`；`getColumnValueUsage` → `getColumnChoicesUsage`（包括 channel 字符串）
- `dispatcher.ts`：同步重命名，参数字段 `values` → `choices`
- `bridge.ts`：dataStore 签名同步；`DataStoreColumnDef`/`DataStoreColumnType` 导出删除，换为 `Column`/`ColumnKind`
- preload：随 channel 重命名

## 8. CLI 新语法

```
synapse create todo \
  title:text \
  priority:single_choice:high,medium,low \
  tags:multi_choice:work,study,home \
  done:boolean \
  due:date
```

`parseColDef` 规则：`name:kind` 或 `name:kind:v1,v2,v3`；kind 必须是 10 种之一；旧名（ENUM/MULTI_ENUM/BOOLEAN/…）不接受，直接报错提示新名。`--help` 重写。

### 9.3 组件级改动

所有 `col.type === "ENUM"` / `"MULTI_ENUM"` / `"BOOLEAN"` / `"JSON"` / `"DATE"` / `"DATETIME"` / `"INTEGER"` / `"REAL"` → `col.kind === "single_choice"` 等。所有 `.enumValues` → `.choices`。

重命名 `enum-values-editor-dialog.tsx` → `choices-editor-dialog.tsx`，`columnType` prop → `kind`。

`schema-copy-formats.ts` 的 `sqlType`/`tsType` 改为基于 `col.kind`：

```ts
function sqlType(col: Column): string {
  if (col.primaryKey) return "INTEGER PRIMARY KEY AUTOINCREMENT"
  switch (col.kind) {
    case "integer": case "boolean": return "INTEGER"
    case "decimal": return "REAL"
    case "binary":  return "BLOB"
    default:        return "TEXT"
  }
}
```
