# Apple Design

此 Skill 是官方资料的目录与阅读路线，不是 HIG 的本地副本。设计与实现 `SynapseMobile/` 界面时，Apple 当前原文是界面依据；旧项目界面稿、原型和现有样式只说明历史与现状。业务协议、安全、运行时约束仍见仓库规则。

## 先读什么

1. 确认本次涉及的页面、iPhone/iPadOS 窗口形态和 Xcode 工程中的最低系统版本。当前最低版本为 iOS 18，实施时重新核对。
2. 从 [iOS/iPadOS 选读路线](references/ios-ipados.md) 找到相关主题；需要完整目录时查 [HIG 官方目录](references/hig-directory.md)。打开 Apple 当前网页或其官方文档数据，**阅读与本次决策相关的正文、平台说明和关联页面**，不能只看本地目录或搜索摘要。
3. 涉及图标、字体、设计模板或讲座时，按 [Apple Design 其他入口](references/design-entrypoints.md) 进入官方资源。视频与样例提供背景；具体界面决策优先以当前 HIG 和对应 Apple 框架文档为据。
4. 对所选 SwiftUI/UIKit 控件与修饰符查 Apple API 文档，确认最低部署版本可用；较新系统的视觉效果不得未经依据自行仿造为旧系统控件。

## 设计与实现

- 每项页面组织、导航、呈现方式、控件和视觉选择，都在设计说明或交付说明中写出对应的 Apple 原文链接及其如何支持该选择。引用要具体到主题，不以“符合 HIG”代替依据。
- 优先使用 Apple 系统控件、语义颜色、系统字体、SF Symbols、系统布局与自适应呈现。不要从旧原型或另一平台复制组件形制，也不要自行发明系统控件、配色或装饰。
- Apple 没有规定某个具体排列时，先依官方布局原则和系统组件能力形成有出处的方案；若仍需决定 Apple 未覆盖的产品形制，明确缺口并请用户决定，不把推测说成 Apple 要求。
- 同时检查 iPhone、iPadOS 可缩放窗口、动态字体、深浅外观、VoiceOver、键盘、指针和减弱动态效果。保持仓库现有业务状态与运行时不变量；若它们与官方界面指引无法兼容，指出具体冲突和原文，不静默覆盖。

Apple 文档会变化。本地链接是发现入口；每次任务重新阅读相关官方页面。无法访问原文时说明未核实，不据本地摘要继续作规范判断。
