# End Node Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a mandatory singleton End Node to the workflow orchestration system that serves as an explicit termination signal, defines workflow output text, and causes the engine to only execute ancestor nodes.

**Architecture:** End Node follows the existing node plugin pattern (`workflow-nodes/end/`). The engine adds a reverse-BFS pre-pass to prune non-ancestor nodes before execution, then promotes the End Node's rendered text to `WorkflowRunResult.output`. Validator enforces exactly one End Node. UI pre-places it on creation and blocks deletion.

**Tech Stack:** TypeScript, Zod, Vitest, React, @xyflow/react, lucide-react, Tailwind CSS / shadcn

function reachableFromEnd(def: WorkflowDefinition): Set<string> {
  const endNode = def.nodes.find((n) => n.type === "end")
  if (!endNode) return new Set(def.nodes.map((n) => n.id))
  const visited = new Set<string>()
  const queue = [endNode.id]
  while (queue.length) {
    const id = queue.shift()!
    if (visited.has(id)) continue
    visited.add(id)
    for (const e of def.edges.filter((e) => e.to === id)) queue.push(e.from)
  }
  return visited
}
