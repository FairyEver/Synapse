# Synapse 夜间品质扫描（只读模式）

你正在对 Synapse 桌面应用做全局品质扫描。**你只负责发现和记录问题，绝不修改任何代码文件。**

本 Prompt 会被多个 Agent 在同一工作目录中并行执行。由于不修改代码，不需要任何文件锁或 claim 协议。

## 核心规则

1. **只读**：不得修改项目中的任何源代码文件。不得 git commit/add/push。
2. **只记录**：所有发现写入 `/Users/liyang/Documents/code/github/Synapse/auto/state/issues.jsonl`（append-only）。
3. **要有证据**：每个问题必须有代码级证据链，不能凭感觉。
4. **不重复**：记录前先读 `/Users/liyang/Documents/code/github/Synapse/auto/state/issues.jsonl`，跳过已记录的同文件同问题。

## 扫描目标

按优先级从高到低：

1. **健壮性**：崩溃、未捕获异常、静默失败、状态卡死、资源泄漏、竞态条件
2. **错误处理**：空 catch、吞掉的 Promise rejection、缺少 error boundary、缺少用户可见错误提示
3. **死代码与冗余**：未使用的 imports/exports/函数/类型、重复定义、废弃旧路径代码
4. **UI 品质**：视觉不一致、间距错乱、颜色不走 token、未用 shadcn 现有组件、深浅主题异常
5. **交互完整性**：缺失的 loading/error/empty/disabled 状态、键盘不可操作、hover/focus 态缺失

- 未使用的 exports、重复类型/常量/工具函数
- 废弃旧代码路径（Codex/Hermes 残留）
- 空 catch 块、console.log 式伪日志
- 不一致的错误处理模式

## 方向选择策略

为避免所有 Agent 扫同一批文件：

1. 先读 `/Users/liyang/Documents/code/github/Synapse/auto/state/issues.jsonl` 最后 30 条，看哪些方向/文件已经被扫过。
2. 优先选择已记录问题最少的方向。
3. 同一方向内，优先选择 issues.jsonl 中未出现过的文件。
4. 加入随机性：不要总从同一个入口文件开始。

## 问题发现标准

每个问题必须有完整证据链：

```
触发入口 → 代码链路（文件:行号 → 文件:行号） → 错误结果/品质缺口
```

合格条件：
- 能在代码中证明问题存在，不需要运行 App
- 影响正常使用路径，不是极端边界
- 用 `rg` 确认过影响范围

不合格条件：
- 需要运行 App 才能确认
- 只是"感觉不太好"但逻辑没错
- 仅缺测试覆盖或仅缺日志

## 输出格式

所有发现追加到 `/Users/liyang/Documents/code/github/Synapse/auto/state/issues.jsonl`，每条一行 JSON：

```json
{"id":"issue-<时间戳>-<4位随机>","agent":"<agentId>","time":"<ISO>","direction":"A|B|C|D","priority":"P0|P1|P2|P3","type":"crash|errorHandling|deadCode|uiQuality|interaction","file":"<主要问题文件>","symbol":"<问题函数/组件名>","summary":"<一句话>","evidence":"<触发入口> → <代码链路> → <错误结果>","relatedFiles":["file1","file2"],"estimatedComplexity":"trivial|small|medium|large","suggestedFix":"<一句话修复建议>"}
```

**写入方式**：用 `echo '{"..."}' >> /Users/liyang/Documents/code/github/Synapse/auto/state/issues.jsonl` 追加。单行 < 4KB，macOS `O_APPEND` 保证并发安全，不需要锁。

### 字段说明

| 字段 | 说明 |
|------|------|
| priority | P0=崩溃 P1=功能受损 P2=体验问题 P3=代码异味 |
| type | crash/errorHandling/deadCode/uiQuality/interaction |
| estimatedComplexity | trivial=1行 small=1文件 medium=2-3文件 large=4+文件 |
| suggestedFix | 给后续修复 agent 的一句话指引 |
