02

连接器：用户怎样连上 Portal

用户路径：登录 SY → 打开 Portal 连接 → 在 Portal 授权页确认账号和租户 → 回到 SY 显示已连接 → 在对话里提出业务请求。该链路是接入规划。

连接器职责设计边界
产品入口“Portal 连接”是用户可见的连接入口。现有 Connectors V1 的本地 MCP 模式不能直接套用；草案建议独立 System App + portal MCP 域，归属待决。
本地存储拟用 DataRepository 的 app.secrets.items（encrypted-json）保存 token / tenantId / portalWebUrl；连接状态另行保存。模型得到连接状态与业务结果，不得到原始凭据。
SY 身份与 Portal 身份SY 会话用于确认谁在调用 SY；Portal token + tenantId 决定以谁的身份访问 Portal。SY userId 必须取自服务端鉴权结果，不能信任客户端自报。跨身份代理是否允许仍待决。
过期 / 断开凭据拒绝时提示重新连接。断开清理本地连接和服务端会话；无法据此承诺撤销 Portal 已签发 token。此限制来自项目现有凭据约束。
版本原始要求为版本严格对齐。草案提出契约版本及不匹配降级只读，但未定稿；不能把 SDK 内容哈希与 Portal buildId 直接当同一种值比较。
03

日常调用：先知道怎么用，再执行业务

目录下钻

listDomains → listPages → describePage
→ describe → candidates / dynamic schema
→ invoke → completion / next

已知目标可从 recommend / search 进入，无需每次从根目录遍历。

以会议室预订为例

日期与时段 → 查询房间及占用 → 选择真实 roomId → prepare → 补齐所需审批人 → submit → 查询占用核实。cancel 只在需要撤销时执行。

普通 CRUD 不必都有 prepare；以各能力实际描述为准。短信等交互闸门需要用户参与。

04

SDK 内部结构与运行边界

模块职责输入 → 输出 / 状态
src/server.ts多用户入口 createPortalServer / forSession进程启动建立一份 server；请求按用户、租户、语言取得 scoped 门面。单用户程序另可用 createPortalHeadless。
src/session/会话、基础数据缓存、依赖加载、两层单飞默认绝对 / 空闲 TTL 均 30 分钟，取先到者；默认容量 64，LRU 淘汰。SY 应按并发用户与租户规模配置。
src/catalog/动态目录、推荐、逐字段 AI 说明、可见性视图共享静态索引；visibleCatalog 显式生成每用户 / 租户 / project 的视图。菜单不可用默认失败关闭。菜单视图不是最终权限裁决。
src/capabilities/页面能力定义、参数校验、业务方法与统一调用绑定capabilityId + args → SDK 最终业务结果。定义、执行和 describe 由同一能力绑定关系关联。未接线能力不应作为可调用功能发布。
src/call.ts
src/context/		从页面确定 module-type 与 HTTP 实例module-type 无规则时按浏览器省略；HTTP 实例解析不了则拒绝。非默认实例必须配置对应 baseURL。
src/http/集中请求客户端、凭据头、前缀、分页、序列化、拆包一份会话一份绑定凭据的请求函数；按实例复刻响应语义。SY 不向远程调用方开放原始 URL / call(pagePath, …)。
src/idempotency/
src/invalidation/		短窗口防重；写后缓存失效规则适用写动作按契约传 requestId；默认防重窗口 10 分钟。同键异载荷报错；结果不确定先核实，不盲目重发。
generated/
tools/generate/		由 Portal 源码推导目录、上下文规则和规格生成物 + 人工能力定义构成权威；SY 不维护第二份能力目录。源码推导还需浏览器基准验证。

部署与状态

一期草案采用单实例 SY 服务端 + 内存 SessionStore / IdempotencyStore。SDK 无数据库依赖；Portal 业务数据仍由 Portal 后端持久化。SY 的账号和审计设施沿用其自身机制。进程重启后会话可由客户端凭据重建，防重记录会丢失；多副本与共享缓存属于后续待决事项。

05

通信协议、工具面与开发者调用

两种网络入口拟复用同一 PortalModule 与 schema；它们都通过函数调用使用 SDK。下面的 HTTP 路由和 MCP 名称来自接入草案，尚不是已上线接口。

通道鉴权 / 作用状态
/api/console/portal/**SY 登录会话；桌面客户端主通道。Portal 凭据由桌面桥随请求交给服务端。规划
/api/open/v1/portal/**SY API key + portal.invoke scope；面向 CLI / 自动化。API key 不替代 Portal 会话 token。二期可用性 / 身份绑定待定
手机 / 无桌面客户端桌面凭据模式不能直接保证离线桌面时仍可调用。独立授权、凭据持有及调用通道尚未闭合。待定

拟议固定 HTTP 表面

请求职责
GET /portal/session查看绑定身份、租户、连接状态与版本信息。
POST /portal/session/bindings草案同时用于“发起”和“完成”绑定；必须拆分或用明确阶段协议消除歧义，目前不作为可直接调用的契约。
DELETE /portal/session断开服务端绑定；桌面同步清理本地连接。
POST /portal/catalogop = domains / pages / page / search / recommend；按当前身份返回目录数据。
POST /portal/capabilities/{id}/describe返回怎么调、每个字段含义、如何消费、后续动作与失败处理。
POST /portal/capabilities/{id}/invoke调用已注册能力；不让调用方指定任意接口路径或页面上下文。

SY 适配层如何调用现有 SDK

import { createPortalServer } from 'portal-headless'

// SY 进程启动时创建一份；服务端配置决定目标后端。
const portal = createPortalServer({ baseUrl: portalApiBaseUrl })

// 下列值由 SY 接入层提供；userId 必须来自鉴权结果。
const scoped = await portal.forSession({
  userId: authenticatedSyUserId,
  credential: { token: portalToken, tenantId },
})
const { catalog } = await scoped.visibleCatalog({ project })
const description = catalog.describe('meeting-room-usage')
// 将 description 返回给 AI；按其中字段契约消费结果。
const result = await scoped.capabilities.invoke('meeting-room-usage', {
  date: '2026-09-23',
})

这是 SDK 调用形状示例，变量由 SY 适配层提供；HTTP 控制器、凭据注入和鉴权尚待实现。SDK 当前返回最终业务数据或错误；统一 data/code/message/llm 网络包络仍需 SY 契约定稿。

SY 发布

更新包 + 接入层 / 客户端
真实用户连接与读写闭环

Portal 前端固定读取 test/portal/main，后端固定读取 test/test；源码使用前更新。静态推导用于发现能力，浏览器基准用于核对真实行为。每个页面同时交付执行逻辑、AI 说明、操作记录和测试；目录计入覆盖不等于整页功能完成。

能力目录随 SDK 包更新，由 SY 运行时下发；Skill 只描述检索和调用方法。生成物新鲜度按内容哈希判断，不能用生成时间戳。运行期版本兼容机制尚待落地。

07

接入前仍需定稿的边界

事项当前依据 / 尚缺部分
连接器归属System App + portal MCP 域是草案建议；现有 Connectors 的 Token、多账号、远程能力边界需单独定稿。
授权与回调token 直接回跳还是一次性 code；state 在两端如何登记、签发、核销；绑定发起与完成接口如何区分。
版本兼容严格匹配还是错配只读；buildId 与契约哈希的映射；版本探针在生成期还是运行期；portalWebUrl 归属。
外部调用与身份手机 / CLI 无桌面时的凭据来源；SY 服务端是否可持久化用户凭据；是否允许 SY 用户与 Portal 用户不同。
规模与开放范围单实例或共享缓存；限流规则；一期开放哪些已接线且说明完整的能力；独立 OpenAPI 目录契约是否采用。
最新 AI 契约接线补齐 describeSchema / describeMethod / listMethods 与动态入口传输；确保 AI 只读服务端描述即可完成调用。
