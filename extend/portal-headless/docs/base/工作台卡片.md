# 工作台卡片（基础能力 `base-home-widgets`）

**这不是一个页面**。`GET /admin-api/homePage/get` 是**首屏必打**的一条
（`app/portal/views/dashboard/common/home/index.vue` 的 setup 顶层），
它决定首页工作台上摆哪些卡片。

四件套的其它三件分别在：能力定义与参数契约 → `src/capabilities/base-shell.ts`；
回归测试 → `test/base-shell.test.ts`；真实环境只读冒烟 → `smoke/read-base-shell.mjs`。

## 它回答的问题

> 「这个用户的工作台上摆了哪些卡片？」——那是**用户自己声明的关注面**。

调查 §2.6 说"卡片集合由 #25 返回的配置决定，**因人而异**"，本次抓取窗口里
两个窗口合计打出了 **101 个不同 URL** 的卡片接口。而这一切的**源头**就是本接口 ——
它不做任何统计，只回答"用户想看什么"。

## 接口

| 项 | 值 |
| --- | --- |
| 路径 | `GET /admin-api/homePage/get` |
| 参数 | **无**（当前登录用户由 token 决定） |
| 分页 | 没有 |
| 返回 | 单个对象：`{id, userId, config, deleted, creator, createTime, updater, updateTime, tenantId}` |
| http 实例 | `platform` |
| Portal 调用点 | `views/dashboard/common/home/index.vue`，setup 顶层，首屏必打 |

## ⭐ `config` 是一个 JSON **字符串**，不是对象

实测：顶层 9 个字段里，`config` 的 JSON 类型是 **`string`**（长度 7,506），
内容是卡片布局的 JSON 数组序列化后的样子。

**能力负责解析它**，把它拆成：

```ts
type HomeWidget = {
  cardId: string | null            // config[].id，短随机串（如 "0yy5U74S"），是**布局项自己的 id**
  widget: string                   // 如 "hr/salary/my-payslip"（模块/域/卡片 三段式）
  knownModules: string[]           // 该卡片自己声明的依赖模块
  layout: { x, y, w, h }           // 原样保留
}
```

真机的一张：

```json
{"x":0,"y":0,"w":4,"h":5,"id":"0yy5U74S","widget":"hr/learning/course-completion",
 "knownModules":["hr/learning","hr/performance","hr/salary","hr/risk","hr/approval",
                 "hr/organization","finance/income","finance/expenditure", ...]}
```

## 参数契约

| 能力 id | 入口方法 | 参数 | 必填 | 默认 / 上限 |
| --- | --- | --- | --- | --- |
| `base-home-widgets` | `listHomeWidgets({keyword, limit})` | `keyword` | 否 | 同时匹配 `widget` **与** `knownModules`（如 `salary`、`hr/`） |
| | | `limit` | 否 | 默认 **60**，硬上限 **100** |

返回：`Promise<{ widgets: HomeWidget[]; total: number; matched: number; configured: boolean }>`

**为什么不强制关键字**：这个接口的规模**有界** —— 实测 **61 张卡片 / 9,019 B**。
这与人员候选（4225 人）不是一回事。判据是**实测规模**，不是"集合型接口一律要关键字"。

### `configured: false` 的含义

`config` 为 `null` / `undefined` / 空串时，返回 `{ widgets: [], configured: false }`
—— **用户没配过工作台是正常状态**（Portal 在这种情况下会 `POST /homePage/save`
回写一份默认卡片，见下）。

`config` 存在但**不是合法 JSON** 时**报错**（`BaseShellShapeError`），不静默返回空列表：
"配置坏了"与"没配过"是两件事，混在一起会让调用方以为工作台是空的。

## 体积怎么切

| 入口 | 一次拿到多少 | 上限 |
| --- | --- | --- |
| `listHomeWidgets()` | 全部卡片（实测 61 张） | 默认 **60** / 硬上限 **100** |
| `listHomeWidgets({keyword})` | 命中的前 N 张 + `total` / `matched` | 同上 |

**没有 `listAll()`**。这个接口本来就只有 9 KB，上限是形式上的防线
（`total` 与 `matched` 两个数让调用方知道有没有被削）。

## 缓存

| 场景 | 行为 |
| --- | --- |
| 没挂会话 | 实例内缓存，切片键 `home-widgets`，TTL = `BASE_SHELL_CACHE_TTL_MS`（30 分钟） |
| 挂了会话 | 同左（没有合适的会话基础数据键：不是每个会话都会用到工作台） |
| 并发 | 单飞合并 |
| 手动失效 | `invalidate('home-widgets')` |

**为什么敢缓存**：9 KB、只读、变更频率低（用户不会每分钟改一次工作台布局）。

> ⚠️ 但**它确实会变**：冒烟时观察到"同一参数连打两次，`data` 已经不同"
> （`updater` / `updateTime` / `config` 都变了），说明测试环境里有别的会话在写它。
> 所以这条缓存是"30 分钟内可能是旧的"——要最新的用 `invalidate('home-widgets')`。
> 详见 `smoke/read-base-shell.mjs` 的 `moduleTypeControl` 注释（那个假阳性就是这么来的）。

## module-type：**不发这个头**，但**没有结论**

- **合成路径**：`/base-data/home-widgets` → `resolveModuleType()` 返回 `null` → 不发
  （依据是 conventions 第 2 条：算不出就不发）。
- **实测状态**：**没有结论**。多次跑的结果不一致，其中一次"同一参数连打两次"就已经不同了
  —— 也就是**基线自己在动**，那种情况下对照方法给不出结论。
  脚本会如实报"本次对照无效，不给结论"而不是硬判一个。
- **所以**：对这条接口，"不发 `module-type` 会不会影响返回"**本单没有验证**。
  需要收窄时由接线方通过 `BaseShellOptions.moduleType` 显式给。

## ⚠️ 能力的价值边界：widget 标识**映射不到页面**

`widget` 是 `hr/salary/my-payslip` 这种三段式（**模块/域/卡片**），
而 `generated/page-catalog.json` 的 `menuPath` 是 `/dashboard/...`。
两者**对不上**，本能力**不做这个映射** —— 没有一张表能证明 `hr/salary/my-payslip`
对应哪个页面，硬编一张就是猜。

所以这个能力的正确用法是**当"关注面"读**，不是当"页面清单"读：

- ✅ "这个用户的工作台上有 10 张 finance 的卡片 → 他大概关心财务域"
- ❌ "用户有 `hr/salary/my-payslip` 卡片 → 所以他要调 `/dashboard/hr/salary/...`"

`knownModules` 稍微更有用一点：它是卡片**自己声明**的依赖模块，
实测一级模块只有 7 个（`common` / `finance` / `hr` / `material` / `product` / `sales` / `supply`）。

（2026-09-20，`biz-api-test.wodecorp.cn`，租户 1；**全程只读 GET**）


## 没做 / 不确定

- **`homePage/save`（`POST /admin-api/homePage/save`）一条都没碰**。
  它在 Portal 里是"布局为空时回写默认卡片"，实测被抓到 POST 了 5 次。
  但它是**写操作**，改的是用户个人工作台布局 —— SDK 去写它属越界
  （调查 §7「不建议做」的结论，复核后同意）。**本单全程只读。**
- **widget 标识 ↔ 页面路径的映射不做**（见上）。
- **没有返回 `userId` / `id` / `tenantId`**：它们对本能力的用途（看卡片）没有帮助。
  要"我是谁"用 `base-user-info`。
- **卡片自己的统计接口一条都没建**：那是 101 个 URL 的第二波（调查 §2.6），
  由逐页推进时各自建能力，不属于外壳。
- **`config` 里 `deleted` 字段的语义没有查**（实测 `0`），所以不返回它。
