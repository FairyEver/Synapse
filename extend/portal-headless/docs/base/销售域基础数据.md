# 销售域基础数据（基础能力 `base-sale-*`）

**这不是一个页面**。它是 Portal 首屏 `runLegacyFullInitTasks` 里**剩下最大的一块**：
`docs/base-capabilities.md` §2.1 的 **#14~#17** 与 §2.2 的 **#20**，五条**每次刷新都打**的接口。

四件套的其它三件：能力定义与参数契约 → `src/capabilities/base-sale.ts`；
回归测试 → `test/base-sale.test.ts`；真实环境只读冒烟 → `smoke/read-base-sale.mjs`。

## 它为什么入选：三条标准里**第 1 条不成立，写在最前面**

| 标准 | 结论 | 依据 |
| --- | --- | --- |
| ① 别的能力依赖它 | **不成立** | 本仓库现有能力里**没有一个**是销售域的，今天没有任何能力依赖这份数据。它是**为将来的销售域页面能力预铺的地基**，别读成"已经有下游在等" |
| ② 是刷新时必打的「外壳」接口 | **成立，且是剩下最大的一块** | 首屏 21 个后端接口里，这一族一次占 5 条；与用户落在哪一页无关，在 `Promise.all` 里并发打 |
| ③ 契约清晰、能只读验证 | **成立** | 五条全是**无参 GET**（实测后端不接受任何查询参数），本页每个数字都是本单实测 |

## 接口：五条，**全部走 `sale` 实例**

| # | 路径（相对 `sale` 的 baseURL） | 用途 | Portal 调用点 |
| --- | --- | --- | --- |
| 14 | `GET /admin/shop/getInfo` | 销售店铺 | `utils/system.js:1126` `fetchShopInfo` |
| 15 | `GET /admin/area/allArea` | 销售地区（省市区全量） | `system.js:1142` `fetchAreaInfo` |
| 16 | `GET /admin/categoryManufacturer/manufacturerInfoList` | 厂商 | `system.js:1158` `fetchManufacturerInfo` |
| 17 | `GET /admin/categoryBrand/brandAllList` | 品牌 | `system.js:1174` `fetchBrandInfo` |
| 20 | `GET /admin/trade/adjustTradeProcessTip` | 首页待处理订单提示 | `utils/router/sale.js:29,32`（**仅 `/dashboard/home`**） |

前四条在 Portal 里都是 `httpSale.get(...)` + `silenceOnError: true` —— 失败不阻塞首屏。

### ⚠️ 接线前提：baseURL 必须由调用方显式给

`sale` 实例的 baseURL 是 `VITE_SHOP_ADMIN_API`，测试环境
`https://biz-api-test.wodecorp.cn/admin-shop-api`（`build/env/.env.build.test:21`）——
**与 platform 同 host、不同前缀**。conventions 第 27 条：这种范围决策 **SDK 不替调用方做**。

所以 `createBaseSale` 收的是**单独的** `saleRequest`；**没给就在调用时抛 `SaleNotWiredError`**，
消息里自带两种接法（见 `src/capabilities/base-sale.ts` 的错误类型）。
**它不会静默退回默认 baseURL** —— 那正是 conventions 第 27 条要防的失败方式
（打到错的 URL，症状只是个 404 或字段不同的 200）。

> 与第二批没做 `{CRM}` / `{SHOP}` 那批的差别要说清楚：**不是"跑不到"，是"要显式配 base"**。
> 本单已经在测试环境把这五条**全部实测跑通**（下面的数字就是证据），所以这次做，上次不做。

## 敏感字段：`shop/getInfo` 里有**身份证号与证件照 URL**

`GET /admin/shop/getInfo` 实测返回 **43 个字段**，白名单留 18、裁 25。裁掉的第一组是实名信息：

| 字段 | 实测（**值不落盘**） | 处置 |
| --- | --- | --- |
| `shopuserIdentity` | 非空字符串，**长度 18** —— 18 位身份证号 | **裁掉** |
| `shopuserIdentityImg` | 非空字符串，长度 **240**（`a:2:{…}` 串，内含两张证件照 URL） | **裁掉** |
| `shopuserIdentityImgZ` / `shopuserIdentityImgF` | 非空字符串，长度各 **100**（证件照正面 / 反面 URL） | **裁掉** |
| `mobile` | 非空字符串，长度 **11** —— 个人手机号 | **裁掉** |

第二组是**取舍，不是安全问题**（逐个点名，免得被读成"漏了"）：
`qq`、`wangwang`、`zzts`、`isShowShopName`、`isShowShopLogo`、`isShowShopBackground`、
`isShowShopDescript`、`isShopDecorated`、`undecoratedItem`、`isShopPcDecorated`、
`pcUndecoratedItem`、`isIntegrateSap`、`isOpenSynchro`、`isOpenRechargePayment`、
`shopDescript`、`typeSuffix`、`shopInfo`、`shopRate`、`imPlugin`、`isImportDelivery`
—— 它们是**店铺装修配置 / 内部标记**，不是"这家店是什么、谁在管、什么状态"，端给模型只是噪声。

`ShopInfo` 保留的 18 个：
`shopId`、`shopName`、`shopAllName`、`shopType`、`shopTypeName`、`status`、`sellerId`、
`shopuserName`、`servicesTel`、`email`、`shopLogo`、`shopAddr`、`shopArea`、`bulletin`、
`openTime`、`closeTime`、`closeReason`、`openType`。

保留 `shopuserName`（实测是店铺使用人姓名）与 `servicesTel`（公司级服务电话），
裁掉 `mobile`（个人手机号）—— 这条界线是"**岗位身份** vs **个人联系方式**"。
冒烟脚本每次跑都会把这份差集重新打出来（只报"有没有、多长"，**不打印值**）。

## 体积怎么切：236 KB 省不掉，但**不进上下文**

这五条接口**后端不接受任何查询参数**（`allArea` / `manufacturerInfoList` / `brandAllList`
连分页都没有）。也就是说：**过滤只能在 SDK 侧做，网络上的字节省不掉。**
能省的是**进上下文的字节数**：

| 入口 | 返回条数上限 | 每次仍拉回来的字节 | 进上限的实测依据 |
| --- | --- | --- | --- |
| 地区三个入口 | 50 / 200 | **235,914 B**（3440 节点 / 34 省 / 深度 3） | 一次调用不能倒出 3440 条 |
| 厂商 | 20 / 100 | **70,208 B**（711 条） | 711 条属长选项 |
| 品牌 | 20 / 100 | **46,533 B**（741 条） | 741 条属长选项 |

**没有 `listAll()`**，任何入口都没有。

三个大件都**按实例内 TTL 缓存 + 单飞**：一辈子只拉一次，之后都走内存索引。
于是"拉全量"每 30 分钟最多发生一次，而不是每次调用发生一次。
（`getShopInfo` 例外：**不缓存**，它是会变的业务状态，且只有 1,928 B。）

## 两个实测到的坑

### 1. 地区节点的名称字段叫 `value`，**不叫 `name`**

```
根节点字段：["id","parentId","value","children"]
实测 value="北京市"、name=undefined
```

照 `base-dept-*`（那个是 `name`）的习惯写会**静默拿到 undefined**。
本能力把 `value` 原样保留 + 额外给 `pathNames`，**不做改名**（改名会两边都对不上）。
冒烟脚本每次跑都会验一遍这件事。

### 2. 地区名称会重复，所以每条都要带路径

`北京市(110000) → 北京市(110100) → 东城区(110101)`，最大深度 **3**（实测），
3440 个节点里"北京市"出现两次。所以 `AreaEntry` 带 `pathIds` / `pathNames`
（`["北京市","北京市","东城区"]`）—— **只给 `value` 是没法用的**。

`describeAreas` 的 `path` 字段取的是**最深的那个节点**的路径，而不是把各级拼起来：
`shopArea` 的 ids 是**从省到区的一条链**（实测 `"110000,110100,110117"`），
链上每段都是下一段的前缀，拼起来会得到 `北京市/北京市/北京市/北京市/平谷区` 那种重复串。

### 3. ⭐ 本族内部唯一一处"能力依赖能力"

`base-sale-shop-info` 的 `shopArea` 实测是 `"110000,110100,110117"`（**逗号串的 id**），
把它翻成名字要用 `base-sale-area-describe` —— 两者直接对接，测试里有一条断言
**拿 `getShopInfo()` 的返回值原样喂进 `describeAreas()`**。不验一遍等于没接上。

另一条实测到的口径：**品牌表每条都带 `manufacturerId`（741/741），但厂商表的 `brandList` 全是 `null`（0/711）**
—— 所以「厂商 → 品牌」这个方向**只能靠品牌表**，不能靠厂商表。

## 缓存

| 数据 | 缓存 | 切片键 |
| --- | --- | --- |
| 地区树 | 实例内 TTL，默认 **30 分钟**（与 `DEFAULT_ABSOLUTE_TTL_MS` 同值，测试里钉死） | `sale-area` |
| 厂商 | 同左 | `sale-manufacturer` |
| 品牌 | 同左 | `sale-brand` |
| 店铺 | **不缓存** | — |

- 三个大件共用一份索引：`searchAreas` / `listAreaChildren` / `describeAreas`
  **一共只拉一次**（测试里用请求计数钉了这件事）。
- 出口一律交出**新建的对象**（`pathIds` / `pathNames` 连数组一起拷）：
  给缓存里那一份的话，调用方随手 `push` 一下就污染了 3440 个节点的索引，
  而**下一个调用方会拿到改过的数据**。
- 并发走 `src/session/single-flight.ts`，失败**不进缓存**。

## module-type 与 `_t`：两个「发不发」的决定，都做了实测对照

**`module-type` 不发。** 五个合成路径都在 `/base-data/*` 下，`resolveModuleType()` 返回 `null`
（conventions 第 2 条）。实测（**交错四次**：不带 → 带 11 → 不带 → 带 11）：

```
店铺：      不带 1928 B / 带 11 1928 B → data 完全相同（基线稳）
地区：      不带 235914 B / 带 11 235914 B → data 完全相同（基线稳）
待处理提示：不带 89 B / 带 11 89 B → data 完全相同（基线稳）
（厂商与品牌同族，本单未做该对照）
```

口径：这是"**本账号实测**不敏感"，不是"后端不读这个头"。

**`_t` 不发。** `sale.js:22-27` 的请求拦截器给每个 GET 加 `_t=时间戳`（防缓存）。
本能力刻意不加：它不改变返回内容，却会让**任何一层缓存都失效** —— 而那正是本族
（236 KB 的地区树）最需要的东西。这不是推测，是对照过的：

```
不带 _t 1928 B / 带 _t 1928 B → data 完全相同
```

另：`sale.js:38-41` 会把 `pageSize` 改名成 `limit`。本族五个接口**一个都不传分页参数**，
所以那个别名在这里用不上（记在这里是为了别有人后来"顺手"加个 `pageSize`）。

## 没做 / 不确定

- **`{MALL_ADMIN}/sys/crm/area/list?id=`（调查 #19）没有做**：实测 **349,985 B / 34 个根**，
  与销售地区 `allArea` **同为 34 个省**（同一份行政区划），体量却是 **1.48 倍**。多建一条同义词纯浪费。
- **`/adminmanage-api/system/dict-data/list-all-simple`（#18）没有做**：实测
  **1,021,377 B / 5983 条**（调查记的是 954 KB，本轮量到 **1.02 MB，比调查更大**），
  与第一批已覆盖的 `grouped-list` 内容高度重叠。
- **`{FM}/getUser`（#2）与 `{CRM}/vue/getUserInfo`（#3）没有做**：`product` 在
  `fmtest.zhihuidanji.com`（异地 host），`crm` 在 `biz-api-test.wodecorp.cn/admin-crm-api`。
  **本单没有实测过它们任何一条返回** —— "没实测就不建"。
- **厂商 / 品牌的关键字是 SDK 本地过滤，不是服务端过滤**：后端不接受参数，
  所以每次调用仍会拉回 70 KB / 46 KB。**省下的是上下文，不是网络字节** ——
  这条写进了参数描述，别把它读成"按关键字查很便宜"。
- **`adjustTradeProcessTip` 的"该怎么用"没有定**：Portal 只在 `/dashboard/home` 打它，
  而调用方**可能不在首页**。本能力只如实返回两个布尔，不替调用方判断该不该问。
- **`searchAreas` 不支持按 id 前缀过滤**（如"只要北京的"）：后端没有参数，
  本地按 `value.includes` 匹配；要按行政区划树过滤请用 `listAreaChildren` 往下钻，
  或用 `describeAreas` 反查。**没有做 id 前缀这种"看起来应该能"的参数。**
