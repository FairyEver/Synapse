## 能力定义

本页只提供以下六项能力，均绑定同一页面路径、权限和 `platform` 实例：

| 能力 | 作用 | 请求 |
| --- | --- | --- |
| `setting-dict-platform-hr-type-list` | 查询人力字典类型分页 | `GET /admin-api/system/dict-type/page` |
| `setting-dict-platform-hr-data-list` | 查询某类型的字典数据分页 | `GET /admin-api/system/dict-data/page` |
| `setting-dict-platform-hr-data-get` | 读取一条字典数据详情 | `GET /admin-api/system/dict-data/get` |
| `setting-dict-platform-hr-data-create` | 新建当前租户字典数据 | `POST /admin-api/system/dict-data/create` |
| `setting-dict-platform-hr-data-update` | 编辑当前租户字典数据 | `PUT /admin-api/system/dict-data/update` |
| `setting-dict-platform-hr-data-remove` | 删除当前租户字典数据 | `DELETE /admin-api/system/dict-data/delete` |

Portal wrapper 使用 `SYSTEM_HR_VALUE = 1`。该值由 SDK 自动写入类型分页请求的 `useSystem`，不是调用参数。数据分页、详情和数据写入请求不额外发送 `useSystem`。

根页面实际只有名称/类型筛选和“字典数据”入口。类型新建、编辑、删除、批量删除、导入、导出控件未启用；数据子页有标签/状态筛选、分页、新建、编辑和单条删除，没有批量删除、导入或导出。

## 参数契约与请求序列化

类型分页固定发送：

```text
order=&orderField=&useSystem=1&name=<name>&type=<type>&pageNo=<pageNo>&pageSize=<pageSize>
```

`name`、`type` 省略时发送空字符串；`pageNo` 默认 1；`pageSize` 默认 20，只接受页面支持的 10、20、50、100。

数据分页固定发送：

```text
order=&orderField=&dictType=<dictType>&label=<label>&status=<status>&pageNo=<pageNo>&pageSize=<pageSize>
```

`dictType` 必填，来源是类型列表行的 `type`，不是类型 `id`。`label` 省略时发送空字符串；`status` 省略或传 `null` 时发送 `undefined`，表示不按状态筛选。

数据新建表单要求 `dictType`、`label`、`value`；`label` 和 `value` 不能空或全为空格，Java DTO 限制长度不超过 100。`sort` 默认 0 且不能为负数，`status` 默认 0（开启），可选 0/1，`remark` 省略或为 `null` 时序列化为空字符串。Portal 实际 POST body 为：

```json
{
  "id": "",
  "dictTypeId": "<dictType>",
  "label": "<label>",
  "value": "<value>",
  "status": 0,
  "sort": 0,
  "remark": "",
  "dictType": "<dictType>"
}
```

`dictTypeId` 是 Portal 表单初始化字段，`dictType` 是通过 bridge 注入的真实类型代码；SDK 两者都按页面发送。编辑发送表单字段及 `dictType`，并保留调用方提供的扩展字段；删除只发送 `{ id }` 查询参数。

## 返回字段与消费方式

请求层先按 `platform` 实例规则解包 Portal 的响应包络；能力只接收解包后的业务值，并拒绝错误结构。

类型和数据分页最终返回 `{ list, total }`：`list` 是当前页，`total` 是当前筛选条件下的总数。空 `list` 不是权限失败；权限、网络、后端业务错误会抛出，不能降级为空页。

类型行字段：

- `id`：类型主键；进入数据子页使用 `type`，不能用 `id`。
- `name`、`type`、`remark`、`createTime`：页面展示/导航使用；`type` 为空时不能进入数据子页。
- `status`：0 开启、1 关闭。
- `useSystem`：本页应为 1，表示人力。
- `tenantEditable`：1 才满足 Java 租户数据写入的类型前置条件。

数据行字段：

- `id`：数据主键，用于详情、编辑、删除。
- `sort`、`label`、`value`、`dictType`、`status`、`remark`、`createTime`：列表展示、表单回显或写入。
- `tenantId`：0 为平台共享，正数为租户私有。
- `platform`：平台共享标记；`true` 时 Portal 禁止编辑和删除。
- `colorType`、`cssClass`：后端可能返回，但当前页面不展示；保留透传，不把它们当作页面筛选或业务判断依据。

新建最终返回新数据 ID（保留字符串或数字形态）；更新和删除最终返回严格的 `true`。详情没有记录时返回 `null`，不能把 `null` 当作可编辑草稿。

## 操作步骤、权限和失败规则

1. 调用类型列表，使用返回行的 `type` 进入数据子页；不将类型 `id` 传给 `dictType`。
2. 按标签/状态和分页读取数据；从当前行取得 `id`。编辑前可调用详情能力，保留详情中的完整字段。
3. 新建时提交完整表单；编辑/删除前确认 `platform !== true`。Java 服务还会校验当前租户归属、字典类型 `tenant_editable=1`、类型开启状态和 `(dictType, value)` 全局唯一性。
4. 写请求返回成功或超时后，必须按同一 `dictType` 分页回查：新建核对新条目和字段，编辑核对同一 ID，删除确认同一 ID 消失。回查失败或结果不唯一时报告结果不确定，不盲目重试。

已知失败包括：参数非法、类型不存在/未开启、类型不允许租户维护、平台共享数据只读、当前租户缺失或不拥有目标数据、权限错误、网络错误、后端业务错误以及错误/非 `true` 的写回执。失败不会被包装成成功或空列表。

本页没有 `prepare → submit → cancel` 协议，也没有批量删除能力；后端没有 requestId 幂等包装，创建重试可能触发 `(dictType, value)` 冲突，编辑/删除超时必须先回查。
