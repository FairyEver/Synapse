# 老母鸡销售

## 1. 能力定义

- 菜单归属：门户 → 系统设置 → 销售设置 → 老母鸡销售。
- 页面路径：`/dashboard/sale/setting/old-chicken-sale/list`。
- 可达流程表单：`/simple/sales/form/008`，流程定义 `eliminated_chicken_sales_apply`。
- 页面权限：`/dashboard/sale/setting/old-chicken-sale`。
- module-type：`60`（销售管理）。
- 请求实例：Portal platform（`VITE_ZHDJ_PLATFORM_API`）。
- 按钮权限：设置价格区间 `setting:old-chicken-sale:set-price-range`，创建申请 `setting:old-chicken-sale:create-sales-apply`，查看 `setting:old-chicken-sale:detail-sales-apply`。
- 列表删除按钮在 Portal 源码中没有 `buttonPermissionFlag`；后端仍校验申请归属、状态和流程，SDK 不把它解释成绕过授权。
- 这是保留的 `系统设置` 子树页面，不是被范围排除的独立“生产”根菜单，也不是“生产环境”能力。

对应 SDK 能力：

| capability | 作用 | 写入 |
| --- | --- | --- |
| `sale-old-chicken-sale-list` | 分页查询申请列表 | 否 |
| `sale-old-chicken-sale-customer-search` | 按农场名或手机号搜索销售客户候选 | 否 |
| `sale-old-chicken-sale-organization-tree` | 读取申请表单可见的管控工厂组织树 | 否 |
| `sale-old-chicken-sale-get-control-config` | 读取价格/日期管控配置 | 否 |
| `sale-old-chicken-sale-prepare-control-config` / `sale-old-chicken-sale-save-control-config` | 准备并保存价格/日期管控配置 | 后者是 |
| `sale-old-chicken-sale-get` | 查询申请详情，供列表查看和回查 | 否 |
| `sale-old-chicken-sale-prepare-create` / `sale-old-chicken-sale-create` | 准备并提交008老母鸡审批申请 | 后者是 |
| `sale-old-chicken-sale-prepare-remove` / `sale-old-chicken-sale-remove` | 准备并删除列表申请 | 后者是 |

## 2. 参数契约

### 列表

Portal 公共列表默认发送空排序字段、筛选表单和分页参数：

```json
{
  "order": "",
  "orderField": "",
  "pageNo": 1,
  "pageSize": 20,
  "salesVariety": null,
  "orgId": null,
  "applicantName": null
}
```

请求为 `GET /admin-api/sales/eliminated-chicken-sales-apply/page`，响应为 `{ list, total }`。当页面选择 `applyTimeRange: [start, end]` 时，Portal 删除原数组并改发 `applyTimeStart`、`applyTimeEnd`；SDK 保留同样的转换。`pageSize` 接受 Portal 全局选项 `10/20/50/100`。

`salesVariety` 是 `visit_record_related_varieties` 字典 value；`orgId` 是销售组织 ID；`applicantName` 是申请人姓名关键字。列表行的 `processInstanceId` 有值时，Portal“查看”跳转通用流程详情，否则以行 `id` 打开008详情表单。

### 客户和组织候选

008表单的销售客户弹窗在 `isOldChickenApply` 模式下请求：

```text
GET /admin-api/sales/customer/page?pageNo=<pageNo>&pageSize=<pageSize>&farmName=<keyword>&mobilePhone=<keyword>
module-type: 60
```

Portal允许空关键字查询，但客户候选属于长选项，SDK要求至少提供 `farmName` 或 `mobilePhone`，避免一次拉取几千条候选。选中同一条候选时，`customerId` 填 `salesCustomer`，`salesCustomerCompanyId` 和 `salesCustomerCompanyName` 一并带入，`farmName` 填 `salesCustomerName`。

管控工厂请求为 `GET /org/organization/getRoleOrganizationTree`。SDK保留树节点的 `id/name/isStandardUnit/children`；Portal 的 role-org 组件和移动端树都将 `isStandardUnit=0` 的节点置为不可选，只能从 `isStandardUnit=1` 的角色可见节点选择 `factoryId`，不能用工厂名称代替 ID。

### 老母鸡销售价格管控表单

价格管控页先请求：

```text
GET /admin-api/sales/eliminated-chicken-sales-apply/control-config/get
```

保存请求为 `POST /admin-api/sales/eliminated-chicken-sales-apply/control-config/save`，成功回执是 `true`。字段规则如下：

| 字段 | 页面/后端规则 | 单位 |
| --- | --- | --- |
| `salesQuantity` | 页面0~1000000整数；后端实际上限99999，SDK按有效后端上限校验 | kg |
| `malePriceMin` / `malePriceMax` | 可空；页面非空时0.01~100、最多2位小数，max不能小于min | 元/kg |
| `femalePriceMin` / `femalePriceMax` | 与公鸡价格相同 | 元/kg |
| `expectedSaleDateMaxRange` | 页面输入整数，后端要求大于0；SDK按大于0校验 | 天 |

后端把空价格规范化为 `0`，因此读取到0表示未设置的后端默认值，不应误报为用户填写了零差值。保存成功或超时后必须重新读取逐字段核对。

### 008申请表单和提交

Portal PC页先校验表单，然后将 `expectedSaleDateRange` 转换为两个字段并删除原数组：

```json
{
  "applicantId": 1,
  "applicantName": "张三",
  "salesCustomerCompanyId": "org-7",
  "salesCustomerCompanyName": "绿源组织",
  "factoryId": 8,
  "salesVariety": "native",
  "salesCustomer": "customer-7",
  "salesCustomerName": "绿源农场",
  "expectedSalesQuantity": 100,
  "expectedSalesNum": 20,
  "eliminatedAge": 500,
  "maleAvgWeight": 2.1,
  "femaleAvgWeight": 1.8,
  "maleQuotePrice": 12.3,
  "femaleQuotePrice": 11.2,
  "expectedSaleStartDate": "2026-10-01",
  "expectedSaleEndDate": "2026-10-10",
  "applyReason": "",
  "attachments": []
}
```

请求为 `POST /admin-api/sales/eliminated-chicken-sales-apply/create`，返回新申请业务 ID并启动审批流程。页面/后端共同有效的提交规则：

- `applicantId`、`applicantName`、`factoryId`、客户组织、客户、数量、只数、日龄、四个重量/报价和起止日期必填；SDK不接受缺少后端 `@NotNull` 的 `expectedSalesNum`。
- 数量、只数和日龄为至少1的整数；重量和报价至少1，最多2位小数；日期为 `YYYY-MM-DD`，结束日期不能早于开始日期。
- `salesVariety` 可空；申请原因可空但 SDK按移动端和后端有效限制最多200字符。PC源码的 `maxlength=500` 与后端DTO不一致，不能把500字符当作可提交保证。
- `attachments` 可空数组；每个已上传OSS资源至少保留 `url` 和 `name`。PC最多50个且扩展名集合较窄，移动端最多10个且扩展名集合更宽；SDK不伪造上传结果，只校验最终资源结构。
- 后端还按价格管控配置校验预计销售日期区间；准备阶段可先读取配置，提交时以后端最终校验为准。

删除请求为 `DELETE /admin-api/sales/eliminated-chicken-sales-apply/delete?id=<id>`。后端要求当前用户是申请人，且申请处于草稿、驳回或撤回等可删除状态；审批中/已通过等状态可能拒绝删除。

## 3. 逐字段基准

| 字段 | 页面含义 | 空值/归属 |
| --- | --- | --- |
| `id` | 申请主键 | 来自当前列表/详情；详情、删除和回查使用，不能用流程实例ID替代 |
| `processInstanceId` | 审批流程实例 | 有值时交给通用流程详情能力；不是业务申请ID |
| `applicantId` / `applicantName` | 申请人ID/姓名 | Portal从当前用户预填；后端创建要求ID存在，删除校验当前用户归属 |
| `salesCustomerCompanyId` / `salesCustomerCompanyName` | 客户管控组织ID/名称 | ID来自同一客户候选，名称是展示快照 |
| `factoryId` | 管控工厂组织ID | 来自角色可见组织树；禁选 `isStandardUnit=0` 节点 |
| `salesVariety` / `salesVarietyName` | 销售品系value/名称 | value来自 `visit_record_related_varieties` 字典，名称只读 |
| `salesCustomer` / `salesCustomerName` | 客户业务ID/农场名称 | ID和名称必须来自同一客户候选 |
| `expectedSalesQuantity` | 预计销售数量 | 单位kg；提交整数且至少1 |
| `expectedSalesNum` | 预计销售只数 | 单位只；后端必填，提交整数且至少1 |
| `eliminatedAge` | 淘汰日龄 | 单位天；提交整数且至少1 |
| `maleAvgWeight` / `femaleAvgWeight` | 公鸡/母鸡平均体重 | 单位kg；至少1，最多2位小数 |
| `maleQuotePrice` / `femaleQuotePrice` | 公鸡/母鸡市场报价 | 单位元/kg；至少1，最多2位小数 |
| `expectedSaleStartDate` / `expectedSaleEndDate` | 预计销售起止日期 | `YYYY-MM-DD`；PC由范围选择器转换，结束日不能早于开始日 |
| `applyReason` | 申请原因 | 可空；SDK按后端有效上限200字符 |
| `attachments` | OSS附件资源 | 可空；上传已在Portal完成，SDK只保留资源对象 |
| `statusName` | 状态展示名称 | 只读；删除是否允许由后端状态规则裁决 |

## 4. 操作步骤与证据

1. 需要客户时先调用 `sale-old-chicken-sale-customer-search`，必须提供农场名或手机号关键字；从同一候选取得客户ID、管控组织ID和展示名称。
2. 调用 `sale-old-chicken-sale-organization-tree`，只从可见且非标准单位节点选择 `factoryId`；销售品系使用已有字典能力查询候选。
3. 进入价格管控时先调用 `sale-old-chicken-sale-get-control-config`；修改后调用 `sale-old-chicken-sale-prepare-control-config`，用户取消只丢弃草稿，确认后把同一草稿交给 `sale-old-chicken-sale-save-control-config`。
4. 查询列表时保留目标行完整字段。查看按 `processInstanceId` 分流到通用流程详情或调用 `sale-old-chicken-sale-get` 查看008详情。
5. 创建申请时调用 `sale-old-chicken-sale-prepare-create`；先检查必填、数值精度、原因200字符、附件结构和日期顺序。用户取消不发请求，确认后把同一 `draft` 交给 `sale-old-chicken-sale-create`。
6. create返回业务ID、超时或响应丢失后，用 `sale-old-chicken-sale-get` 或列表按业务字段独立回查；成功只表示流程已启动，不表示审批通过。
7. 删除先调用 `sale-old-chicken-sale-prepare-remove`，明确展示目标ID、客户和状态并获得确认，再调用 `sale-old-chicken-sale-remove`；成功或超时后刷新列表核对目标ID消失。运行中或非本人记录被拒绝时不重试绕过。

离线证据由 `test/sale-old-chicken-sale.test.ts` 和 AI 说明契约提供，覆盖菜单归属、三项按钮权限、platform/module-type、列表排序/分页/时间范围转换、客户关键词短路、组织树、价格配置、PC日期转换、申请必填/精度/原因长度、删除参数、坏回执和 prepare → submit → cancel 分支。当前尚未在真实测试环境执行本页列表、客户/组织候选、价格保存、申请提交、详情、删除及写入后的独立回查；该缺口保持如实记录。
