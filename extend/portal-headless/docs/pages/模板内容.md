## 参数契约

**没有分页**（走 `customLoad`，`getDataListIsPage` 默认 `false`），返回整棵树
（后端 `CommonResult<List<KpiTemProtocolDTO>>`）。顺序逐字：

`order → orderField → templateType → _t`

| 字段 | 默认 | 谁给的 | 说明 |
| --- | --- | --- | --- |
| `order` | `''` | 页面钉死 | 空串照发 |
| `orderField` | `''` | 页面钉死 | 空串照发 |
| `templateType` | `0` | 调用方（枚举） | `0` 年度 / `1` 月度。初值是 `TEMPLATE_TYPE_OPTIONS[0].value`，且下拉 `:allowClear="false"` ⇒ **永远有值、永远发** |

## ⚠️ 三个坑

1. **`getDataListURL` 是死配置。** 这一页同时写了 `getDataListURL` **和** `customLoad`
   （两个 URL 恰好相同），看着像普通分页页；但 `list.js:484` 是 `if (customLoad)` 先命中
   ⇒ 分页参数**一个都不会加**。别照"有 getDataListURL 就有 pageNo"去推。
2. **「名称」不上请求。** `customLoad` 第一句 `omit(form, ['templateName'])`，
   过滤在返回的树上做（`reduceTree` + `name.includes`，只留 `type === 1`，结果变平）。
   能力里没有 `templateName` 参数，要按名字找用
   `filterTreeNodeByName(rows, keyword, isTemplateLeaf)`。
3. **切换 `templateType` 不会自动重查**（这一页没有那个 `watch`，模板结构页的还注释掉了），
   页面上要再点「查询」。

## 已覆盖的读写动作

接口见 `KpiTemProtocolController`，已接入统一目录并按 `prepare → submit → cancel` 建模：

- **删**：`DELETE /performance/temcontent/kpitemprotocol`，body 是**裸数组 `Long[] ids`**
  （⚠️ 与利润/薪资结构相反：那两页是 `{ ids }`）。页面 `customDelete` 里是
  `http.delete(url, { data: list })` 且 `mapTree` 收子节点 id —— **递归删除**。
- **建 / 改**：`POST` / `PUT /performance/temcontent/kpitemprotocol`。
- **子页面**：`./template/edit/<id>`（编辑模板内容）—— 真正改模板的是里面的
  `saveProtocolInfo`，不在本页。
- 行内「使用情况」走 `components/view-usage.vue` 的 `usedInfo` 几条 POST；
  表格的展开行只读，不发请求。

SDK 还覆盖基础详情、深层详情读取/保存、年度模板候选、月度信息和年度/月度使用情况；
删除严格发送 Java 要求的裸 ID 数组，基础保存与深层 `saveProtocolInfo` 不混用。真实环境写冒烟仍未执行。

### `perf-manage-template-content-list`

读取模板内容全树；templateType=0 年度、1 月度，默认年度。

- 执行：`sdk.perfManageTemplate.listTemplateContents`；通过 `capabilities.invoke('perf-manage-template-content-list', args)` 调用时按 `params` 填参。性质：read。
- 参数：`templateType` 可选 (string | number)。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`object[]`。[] 表示本次查询没有条目；这是数组，不读取 list/total。
- 字段：`[].id`、`[].name`、`[].parent`、`[].parentIds`、`[].children`、`[].updateTime`、`[].updaterName`、`[].type`、`[].templateType`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：递归 children；type=0 文件夹、1 才是业务模板，与利润树 type=1 文件夹的规则相反。名称查找在本地完成，不发送不存在的筛选参数。
- 完成条件：交付模板内容名称、ID 和目录路径；本能力不编辑模板。
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。
