# 个人用量（`/dashboard/model-usage/list`）

本页属于提示词保留的 `portal/个人用量` 范围，不是独立的「生产」模块。页面实现位于 Portal 的共享 `common/model-usage` 目录，但本能力只按个人根入口的实际行为接入；`statisticsDimension` 固定为 `1`，不能通过参数切换到企业或平台维度。

证据边界：已逐页核对个人入口、额度/用量两个 Tab、申请弹窗、申请记录弹窗、导出按钮、按钮权限、共享请求构造器及固定 `test/test` Java Controller/ReqVO/RespVO，并用离线请求断言锁定关键行为。尚未在真实测试环境执行当前用户/无权限/跨租户权限矩阵、读取冒烟或真实 `prepare → submit → cancel` 写入回查。

来源锚点：Portal `CodeReview_Projects_Js@test/portal/main`；Java `CodeReview_Mall_Platform_Java@test/test` 固定检出。

## 一、页面上下文、权限和范围

| 项 | SDK/Portal 事实 |
| --- | --- |
| 菜单路径 | `/dashboard/model-usage/list` |
| 页面权限 | `/dashboard/model-usage` |
| HTTP 实例 | `platform`；页面未声明其他实例，沿用 Portal 全局默认 |

## 二、已接入能力

调用门面为 `sdk.modelUsage.<method>`；能力说明由 `catalog.describe(id)`、`catalog.describePage(pagePath)` 和 `catalog.describeMethod(sdkPath)` 实际返回。

| 能力 ID | SDK 方法 | 请求/效果 |
| --- | --- | --- |
| `personal-usage-quota-list` | `listQuota` | `GET /admin-api/ai-token/quota-usage/page`，个人额度分页 |
| `personal-usage-quota-summary` | `getQuotaSummary` | `GET /admin-api/ai-token/quota-usage/summary`，不带分页 |
| `personal-usage-usage-list` | `listUsage` | `GET /admin-api/ai-token/usage/page`，个人调用明细分页 |
| `personal-usage-usage-analytics` | `usageAnalytics` | `GET usage/{summary,trend,model-ratio,module-ranking}`；模型上下文可关闭三张分解图 |
| `personal-usage-usage-detail` | `getUsageDetail` | `GET /admin-api/ai-token/usage/detail?id=...` |
| `personal-usage-usage-export` | `exportUsage` | `GET /admin-api/ai-token/usage/export`，返回 Base64 文件对象 |
| `personal-usage-function-module-list` | `listFunctionModules` | `GET /admin-api/ai-token/common/function-module-list`，关键字本地过滤 |
| `personal-usage-model-detail` | `getModelDetail` | `GET /manager/aiModelConfig/get/{id}`，模型上下文展示 |
| `personal-usage-apply-prepare` | `prepareApply` | 本地校验并生成申请 body，不发请求 |
| `personal-usage-apply-submit` | `submitApply` | `POST /admin-api/ai-token/apply/create`，提交额度提升申请 |
| `personal-usage-apply-record-list` | `listApplyRecords` | `GET /admin-api/ai-token/apply/page`，需要 `ai-token:apply:query` |
| `personal-usage-apply-cancel` | `cancelApply` | 只丢弃未提交草稿；Portal没有服务端取消端点 |

只有 `personal-usage-apply-submit` 是写能力。获得申请 ID 只表示申请已受理，不表示审批通过或额度已经改变。

## 三、逐字段基准、默认值和表单规则

### 3.1 额度 Tab

- 默认 `quotaCycle=3`（月）、`pageNo=1`、`pageSize=20`；请求始终带 `statisticsDimension=1`。
- 个人根入口只显示模型名称、额度周期、使用状态；不显示企业和用户筛选，也不触发租户全量翻页。
- 列表结果按 `list` 和 `total` 消费；额度行的 `modelId/modelName/quotaCycle/cycleQuota/usedQuota/remainingQuota/usageRate/maxTokenPerRequest/usageStatus/usageStatusName` 只按返回值展示，空值不能当作 0。
- 汇总请求与列表使用相同业务筛选但去掉 `pageNo/pageSize`，返回 `cycleTotalQuota/cycleUsedQuota/cycleRemainingQuota/currentCycleAvailableQuota`。

### 3.2 用量 Tab

- 默认 `quotaCycle=2`（周）、`timeRangeType=2`（本月）、`pageNo=1`、`pageSize=20`；根入口无 `modelId` 时请求汇总、明细、趋势、模型占比和功能模块排行。
- 路由带 `modelId` 时先取模型详情，并按 Portal 语义只请求汇总和明细；调用 `usageAnalytics` 时传 `includeBreakdowns=false`。
- 自定义日期的 10 位日期按闭区间转换为 `startTime=00:00:00`、`endTime=23:59:59`；非空时间字符串不再改写。
- 用量明细消费 `requestId/callTime/durationMsStr/functionModule/callStatus/callStatusName/modelName/inputTokens/outputTokens/totalTokens/consumedQuota/quotaDeducted/userName/tenantName/limitType/failureReason` 等字段；详情弹窗还消费额度前后快照、命中的额度/流速规则和失败信息。
- 页面把统计接口的异常降级为空展示；SDK 保留“不拖垮其他统计请求”的语义，同时在 `errors` 中记录每一路错误，避免把请求失败伪装成没有数据。
- 导出与列表共享筛选条件但不带分页，返回 `{ fileName, contentType, base64, byteLength }`；空文件或非二进制响应抛错。

### 3.3 额度提升申请

Portal `ApplyFormModal.vue` 的客户端规则是：`modelId` 必填；`expectedMonthlyQuota` 与 `expectedMaxToken` 至少填一个；填写的值为最小 `0`、整数；`reason` 必填且最多 200 字符。提交 body 的字段映射为：

```text
modelId
currentMonthlyQuota <- monthlyQuota
expectedMonthlyQuota
currentMaxToken <- maxTokenPerRequest
expectedMaxToken
statisticsDimension = 1
reason
```

`modelName` 只用于禁用展示，不发送。`prepareApply` 还会提示一个已经核实的前后端差异：固定 Java `AiTokenQuotaApplySaveReqVO` 对 `expectedMonthlyQuota` 声明了 `@NotNull @Positive`，因此 Portal 允许的“只填最大 Token”或月额度为 `0` 可能被后端拒绝；SDK 不静默改变 Portal 表单规则。

`submitApply` 是 `POST /ai-token/apply/create`。该接口在固定 Java 源码中为 `PermitAll`，但仍需有效会话；申请记录 `GET /ai-token/apply/page` 另需 `ai-token:apply:query`。提交超时先用 `listApplyRecords` 按模型和时间回查，不要盲目重试。提交前取消只丢弃草稿，提交后本页面没有可达的服务端撤回动作。

申请记录筛选按共享页面 `buildApplyQuery` 原样发送 `startDate/endDate` 日期字符串，不补 `00:00:00/23:59:59`；页面状态筛选值按 Portal 原样透传。固定 Java 枚举与页面回退标签存在 `0/1/2/3` 对 `0/3/4` 的差异，不能仅凭页面标签宣称审批状态含义。
