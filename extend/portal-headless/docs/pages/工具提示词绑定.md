> 三页参数装配各不相同在哪、写链路 `prepare → submit → cancel` 怎么分）
> 写在 [`src/capabilities/ai-prompt-tool.ts`](../../src/capabilities/ai-prompt-tool.ts) 的文件头，
> 这里只记这一页自己的东西。

## 权限码：与当前目录逐字一致

- 页面自己的 `<route>` 块：`permission: /dashboard/platform-v2/intelligence/prompt/template`
- 当前菜单入口 `app/portal/menus/index.js` 加载的 `menus/mall.v2.js:233`：**同一条**（带 `platform-v2`）
- `generated/page-catalog.json`：按当前菜单入口记录同一条权限。

旧菜单 `mall.js:447` 仍保留 v1 作为历史对照；可见性归一化会把两代权限视为同一页面，
但 SDK 能力与当前 Web 端都使用生效的 v2。

（对比：「业务事件绑定技能」只在 v2 菜单里 ⇒ 两处一致；「开放接口」在 v2 菜单里本来就不带前缀 ⇒ 也一致。
三条各不一样。）

## 列表：⚠️ **这一页的 URL 上会带 `order=`/`orderField=`**

`list.vue` 的写法是：

```js
customLoad: async (form) => {
  const result = await http.get('/admin-api/sales/ai-template/page', { params: form })
  return result
},
```

`form` 是 `useListPageModule` 的 `logicFetch` 拼出来的
`{ order, orderField, ...formState, pageNo, pageSize }`（`common/libs/renren/list.js:475-481`）
—— **整份原样交给 axios**。表单初值只有 `{ func: '' }`，所以无筛选时是：

```
GET /admin-api/sales/ai-template/page?order=&orderField=&func=&pageNo=1&pageSize=20&_t=<ts>
```

**别照抄隔壁两页把 `order`/`orderField` 省掉**（那两页的 `customLoad` 是逐个挑字段的）。

后端 `SalesAiFuncTemplatePageReqVO` 只有 `func` 一个筛选位，`SalesAiFuncTemplateServiceImpl.getTemplatePage`
用的是 `likeIfPresent(getFunc, …)` ⇒ **包含**匹配（`%x%`）；`order`/`orderField` 会被忽略。
排序写死 `update_time desc`。

⚠️ 同一处还有一个**页面与后端对不上的地方**（只是顺带记一笔，不影响 SDK）：
后端在这条链路上补的是 `creatorName` / `updaterName`（`adminUserApi.setOperatorName(...)`），
而列表页那一列渲染的是 `record.lastUpdaterName || '无'` —— DO 里没有这个字段。
也就是说「修改人」那一列**大概永远是"无"**。SDK 返回原始行，不做改名。

## 写链路：`create` 用 POST、`update` 用 **PUT**（这一组里唯一）

| 动作 | 能力 | 请求 | 撤销 |
| --- | --- | --- | --- |
| 新建 | `-create` | `POST /admin-api/sales/ai-template/create` | 走 `-remove`（create 返回 `success(null)`、**不回传 id**） |
| 修改 | `-update` | **`PUT`** `/admin-api/sales/ai-template/update` | `cancel` 把 GET 到的那一行**原样**写回 |
| 删除 | `-remove` | `DELETE …/delete?id=`（**query 传参**，路径里没有 id） | ⚠️ **撤不回** ⇒ `cancel` 抛 |

**删除到底删了什么**（收尾时要知道）：后端 `SalesAiFuncTemplateServiceImpl.deleteTemplate`
= `validateTipTemplateExists(id)` + `salesAiFuncTemplateMapper.deleteById(id)`，
表是 **`sales_ai_func_template`**（`SalesAiFuncTemplateDO` 的 `@TableName`）。
它**只动这一张表**，不碰 `sys_tip_template`、也不碰任何节点表 ——
与「技能列表」页那条 `DELETE /admin-api/sys/tip-template/{id}` **不是一回事**
（那条不删 `ai_skill_v2_node` 的节点行、撤销不干净，记在 `docs/pages/技能列表.md`，属于另一页）。

三处与页面同形、但值得单独说的地方：

1. **新建的 body 是 `{ id: null, templateId, useType, funcId, templateContent }`** —— `id` **打头且是 `null`**。
   逐字抄自 `customSubmit` 的 `{...form, templateContent}`，而 `form` 的初值是
   `{ id: null, templateId: null, useType: null, funcId: null }`。
2. **修改的 body 是"GET 回来的那一行 + `templateContent`"**，不是四个表单字段。
   页面编辑态下 `formState` 就是 `customLoad` 的返回值（`form.js` 的 `loadFormData` 直接
   `formStateSet(await customLoad(id))`，而 `customLoad` 返回的是**原始响应**），
   所以服务端的 `creator`/`createTime`/`updateTime` 都会**一起回传**。
   SDK 照做（摊开 GET 到的对象再覆盖调用方给了的字段）—— 手工拼四个字段会漏，
   而且键序会与浏览器不一致。
3. **`templateContent` 在页面上不是手填的**：页面写的是
   `templateContent: selectedTemplate?.name`，即"所选项的名字"。SDK 只能由调用方给
   （候选入口在另一条线上，见下）。

## 候选（长选项）从哪来 —— 两条都**指另一条线**（`ai-prompt.ts`）

| 参数 | 页面自己的调用 | SDK 侧入口（`lookup` 指向） |
| --- | --- | --- |
| `useType` | `GET /admin-api/system/tip-type/page`（`loopFetch`，每页 100 × 最多 100 页，**无关键字**） | `ai-prompt-tip-type-list`（`ai-prompt.ts` 的「提示词类型」列表能力，关键字 `name` = 类型值） |
| `templateId` | `GET /admin-api/sys/tip-template/page?typeId=`（同样是 `loopFetch` 全量循环） | `ai-prompt-skill-list`（`ai-prompt.ts` 的「技能列表」能力，关键字 `name`；用它自己的 `typeId` 收窄） |

两条都是 **conventions 11** 说的"页面自己全量拉、无头不能照抄"的形式，所以 SDK 侧**不重复实现**，
只把 `lookup` 指过去。语义对应关系：

- 页面拿提示词类型行的 **`name`（类型值）** 当 `useType`，拿 **`id`** 当筛模板用的 `typeId`；
- `templateId` 存的是 `sys/tip-template` 那一行的 **`id`**，而 `templateContent` 存的是它的 **`name`**。

⚠️ 这两个 id 属于**别的文件**。`test/ai-prompt-tool.test.ts` 里有一条"跨文件解析"的用例：
如果 `ai-prompt.ts` 把这两个 id 改了，会在**我这边**先红，而不是等 `catalog.validate().lookups`
在别人那一轮报"候选入口能力不在目录里"。

`funcId` 的候选不在上面两条里：它是**字典** `Prompt_word_template`（页面用 `portal-common-dict-select`），
走 `base-dict-get`（`dictType=Prompt_word_template`）。⚠️ 那个字典名**只在页面源码里出现**
（后端仓库里搜不到 —— 它是数据不是代码），所以这一条是**源码推导**，没有后端代码佐证。

## 基准（`baseline/ai-prompt-tool.browser.json`，2026-09-21 抓到）

这一页在基准里有**三条**请求，其中**只有一条是页面自己发的**：

| 请求 | 是谁发的 |
| --- | --- |
| `GET /admin-api/org/sensitive/info` | ❌ **不是这一页** —— app 外壳的全局敏感词检查，跟着每页一起被抓进来 |
| `GET /admin-api/bpm/task/list-by-category?finished=1&pageNo=1&pageSize=10` | ❌ **不是这一页** —— 外壳的待办角标 |
| `GET /admin-api/sales/ai-template/page` | ✅ 这一页的列表请求 |

三条列表契约**全部与源码推导逐字段相符**（含键序），**没有冲突**：

```
GET /admin-api/sales/ai-template/page?order=&orderField=&func=&pageNo=1&pageSize=20&_t=<ts>
```

另外基准给了一条**浏览器实测**（不再是推断）：`headers` 里只有
`Accept` / `Accept-Language` / `tenant-id` / `token` —— **没有 `module-type`**，
与"规则表里匹配不到就不发"完全一致（conventions 2 / D34）。

**基准是什么、不是什么**：这一轮**全是只读 GET**（一个写请求都没发），所以
`get` / `create` / `update` / `delete` / `retry` 的形状**仍然只有源码 + 后端代码两份证据**，
没有浏览器证据。别把"列表对上了"读成"这一页整页都验过了"。

### 基准**没有**覆盖的（仍然只有源码 + 后端代码两份证据）

1. `create` 的 body 键序（`{id:null, templateId, useType, funcId, templateContent}`）与 `update` 用 **PUT**；
2. `update` 的 body 是不是"GET 那一行 + `templateContent`"（服务端字段有没有一起回传）；
3. `delete` 是 `?id=` 而不是路径 id；
4. `func` 的匹配语义（**包含**，来自后端 `likeIfPresent`）。

## 待派单方真机验证的清单

> 按派单方的要求：**真机写验证由派单方统一跑**，本节只写"跑什么、期望什么、怎么撤、什么风险"。

> **写验证的红线**（派单方 2026-09-21 的要求，逐条照做）：

> 本节标了「会改到**已有**数据」的那几条，只能拿**同一轮里自建的 `SDK-TEST-` 记录**去跑 ——
> 下面各条的"前置条件"已经按这个写死了，没有自建记录就先跑①的那条自建流程。
> 本轮**我没有对测试环境发出过任何请求**（没有 browser、没有 `bsk`、没有 smoke 脚本）。

### ① 只读冒烟（风险：无）

| # | 请求 | 前置条件 | 期望 |
| --- | --- | --- | --- |
| 1 | `GET /admin-api/sales/ai-template/page?order=&orderField=&func=&pageNo=1&pageSize=20&_t=<ts>` | 账号能进这一页 | `ret=SUCCESS`、`data={list,total}`。**重点核 `order=`/`orderField=` 真的在** |
| 2 | `GET …/page?…&func=<某个功能名的片段>&_t=` | 列表有数据 | 命中数 ≤ 不带 `func` 时的数量 |
| 3 | `GET /admin-api/sales/ai-template/get?id=<①里某条的 id>&_t=<ts>` | 有 id | `ret=SUCCESS`，含 `funcId`/`templateId`/`templateContent`/`useType`/`updateTime` |
| 4 | `GET /admin-api/system/tip-type/page?pageNo=1&pageSize=100&_t=<ts>` | 无 | 候选非空（页面就是靠它填 `useType` 下拉）。**同时记下返回行的 `id`/`name`，②要用** |
| 5 | `GET /admin-api/sys/tip-template/page?pageNo=1&pageSize=100&typeId=<④里某个 id>&_t=<ts>` | ④有数据 | 候选非空，行里有 `id`/`name`（`name` 就是 `templateContent` 要填的值） |

### ② 候选链路核对（风险：无，但**要先做**）

用 ④⑤ 的真实数据确认两件事，②的写验证要用：

- `useType` 应填 ④ 里某一行的 **`name`**；
- `templateId` 应填 ⑤ 里某一行的 **`id`**，`templateContent` 应填**同一行的 `name`**。

### ③ 真写一轮：新建 → 撤销（风险：**中高**）

⚠️ 这一页写的是"功能点 → 提示词模板"的绑定，**会影响线上 AI 的行为**
（`GET /admin-api/sales/ai-template/get-by-func-id` 就是按 `funcId` 取模板的，而它 `eq(useType, "report")`）。
所以：

- 用 ④ 里**最不敏感**的一个 `funcId`，或者如果候选里有明显是测试用的值就优先用它；
- 名字/内容一律带 `SDK-TEST-`；
- **同一轮内撤销**，并把"改前是什么"记下来（如果那个 `funcId` 本来就有绑定，
  `create` 会**新增一条**还是覆盖 —— 这一点没有实测过，**先查一次 `list({func})` 看它有没有既有绑定**，
  有的话**换一个 funcId**，不要拿一个已经在用的去试）。

步骤：

- **prepare**：`prepareCreate({ funcId: '<④的值>', templateId: <⑤的 id>, useType: '<④的 name>', templateContent: 'SDK-TEST-模板' })`
  - 期望：**不发请求**
- **submit**：`POST /admin-api/sales/ai-template/create`，body `{id:null, templateId, useType, funcId, templateContent}`
  - 期望 `ret=SUCCESS`（`msg` 是"保存成功"）；**响应里没有新 id**
- **确认存在**：`list({ func })` → 取到新那条的 `id`
- **撤销**：`prepareRemove(id)` → `submit` → `DELETE …/delete?id=<id>`
  - 撤销后**再查一次列表**确认为空

### ④ 真写一轮：修改 + 撤销（风险：**中**，⚠️ **会改到已有数据** —— 只拿③里那条自建记录跑**）

- 用③里那条自建的记录：`prepareUpdate(id, { templateContent: 'SDK-TEST-改过的内容' })` → `submit`
  - 期望：`prepare` 那次 GET 到的那一行**所有字段**都出现在 PUT body 里（只多了 `templateContent` 的新值）；
    method 必须是 **PUT**
- **撤销**：`cancel(plan)` → `PUT`，body 与 GET 到的那一行**逐字段相同**
  - 撤销后再 `GET` 一次，`templateContent` 回到 `SDK-TEST-模板`

### ⑤ **不要跑**（本清单里明确排除）

- 拿一个**已在用**的 `funcId` 做 create（可能覆盖线上 AI 的实际绑定）。
- 删除**非 SDK-TEST-** 的记录（没有恢复接口）。
- 用 `update` 去改一条**真实绑定**的 `templateId`（会真的换掉线上模板）。
  ——③④ 都用自建记录，就是为了不碰它们。

### ⑥ 撤销不了时怎么收尾

- 新建成功但 `delete` 失败：**留着**并在报告里给出 `id` + `funcId` + `templateContent`，
  由派单方删。这一条**优先级最高**（它是 AI 行为的数据源）。
