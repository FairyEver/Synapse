### 基准的覆盖边界（别越过它下结论）

那一份 14 条 / 4 页的基准里：**0 条非 GET**、**没有 `getMixedHotQuestion` / `getManualHotQuestion`**、
没有任何"带筛选值"的请求。所以这一页：

- **有基准背书**：`role = system`（挂载默认）时那条无筛选列表请求，逐字段一致。
- **仍然只有源码推导**：写链路（`add` / `update` / `logicalDelete` 的 method、URL、body）、
  `user` / `mix` 两个角色、带筛选值的键位。

## ⚠️ `hotTopics/` 下的 `list1.vue` **不算数**

那个目录里同时存在 `list.vue` 与 `list1.vue`：

| 文件 | 打的接口 | 在菜单里吗 |
| --- | --- | --- |
| `list.vue` | `/manage/ai/get{Sys,Manual,Mixed}HotQuestion` | ✅ 菜单指向 `/hotTopics/list` |
| `list1.vue` | `/manage/ai/getHotQuestionListByPage` | ❌ 侧边栏没有入口 |

菜单（`app/portal/menus/mall.v2.js:215`）指向的是 `…/hotTopics/list` ⇒ **`list.vue` 才是线上那一版**。
`list1.vue` 那一页按 URL 直接敲**能渲染**，但用户从侧边栏**到不了** ⇒
**"能渲染"不等于"用户能做的事"**（conventions 第 28 条，`docs/conventions.md`）。
所以本能力**一个字都不从 `list1.vue` 推导**，`getHotQuestionListByPage` 这个接口号也不进目录。

## 三种角色：同一个列表，三个端点，**参数形状完全一样**

页面上那个 `a-segmented`（`role = 'system' | 'user' | 'mix'`）切的就是端点：

| role | 界面标签 | 端点 | 后端语义 |
| --- | --- | --- | --- |
| `system`（默认） | 系统 | `GET /manage/ai/getSysHotQuestion` | `type = 2`（系统生成），`order by sort desc` |
| `user` | 人工 | `GET /manage/ai/getManualHotQuestion` | `type = 1`（人工录入），`order by sort` |
| `mix` | 预览 | `GET /manage/ai/getMixedHotQuestion` | 后端把 `type=1`（`sort ≤ 10` 的）与 `type=2` 的**合并**成一份（`TreeMap` 去重，`sysDisplay=1`） |

⚠️ **别按"预览模式不分页"去裁参数。** 页面写的是
`getDataListIsPage: role.value !== 'mix'`，但这一句在 **setup 时就求值完了**（那时 `role` 还是
`'system'`）⇒ 传进 `useListPageModule` 的是一个常量 `true`，`a-segmented` 怎么切都改不了它。
模板里 `v-if="role !== 'mix'"` 只藏掉了分页控件与新建/编辑/删除按钮，**请求里的
`pageNo`/`pageSize` 三种角色都照发**。

`role !== 'mix'` 时页面上才有：新建、编辑、删除（多选）、分页。`mix` 模式下只有「详情」。

## 参数（无筛选时的键序）—— ⭐ **基准证实**

```
order=&orderField=&pageNo=1&pageSize=20&_t=<ts>
```

基准里这一页的那条就是：

```
GET /admin-api/manage/ai/getSysHotQuestion?order=&orderField=&pageNo=1&pageSize=20&_t=<ts>
```

与能力构造出来的**逐字段一致**（含 `_t` 在最后、`order=`/`orderField=` 两个空值照发
—— conventions 第 4 条那条"列表页要带 renner 的默认空值参数"），测试是
`test/ai-interaction-qa.test.ts` 的 **B2 组**。

`null` 的四项（`question`/`createName`/`startInputTime`/`endInputTime`）**整项不出现**
—— 基准证实了**结果**（这四页无筛选时 URL 上只有那四项），源码解释了**原因**
（表单初值是 `null`，`platform.js` 的 `qs.stringify({ skipNulls: true })` 把它丢掉；
空串不在此列、会照发）。传了值就插回**原来的位置**：

| 键 | 来源 | 说明 |
| --- | --- | --- |
| `order` / `orderField` | `useListPageModule` 固定加的两个空串 | 这一页没有排序入口，恒为 `''` |
| `question` | 表单 `question` | 后端**前缀**匹配（`like 内容%`） |
| `createName` | 表单 `createName` | 按 `hr_sys_user.real_name` 前缀匹配；`create_id=0` 的行显示为「系统」 |
| `startInputTime` / `endInputTime` | 表单 `date[0]` / `date[1]` | `YYYY-MM-DD HH:mm:ss`。⚠️ 区间选择器带 `show-time`，**不做「结束日 +1 天」** —— 与学习管理域那几页不是一回事 |
| `pageNo` / `pageSize` | 分页 | `styleV2: true` ⇒ 默认每页 20 |

⚠️ 时间字段排在 `pageNo`/`pageSize` **之后**：页面在 `customLoad` 里是
`{ ...omit(form, ['date']), startInputTime, endInputTime }` —— `omit` 只删 `date` 这个键、
留下其余键**连同位置**，两端时间是**追加**上去的。写进能力时按这个顺序构造，别"整理"成表单顺序。

## 写链路

| 动作 | 请求 | 出处 | 撤销 |
| --- | --- | --- | --- |
| 新建 | `POST /admin-api/manage/ai/addHotQuestion`，body `{"id":null,"sort":…,"question":"…"}` | `[mode]/[id].vue` 的 `customSubmit`（`form.id` 为空那一支） | `DELETE /manage/ai/logicalDelete`，body `[新行 id]` |
| 修改 | `POST /admin-api/manage/ai/updateHotQuestion`，body `{"id":…,"sort":…,"question":"…"}` | 同上（`form.id` 有值那一支） | 用**原值**再 `updateHotQuestion` 一次 |
| 删除 | `DELETE /admin-api/manage/ai/logicalDelete`，body `[id, …]` | `list.vue` 的 `deleteURL` + renren 通用删除（`deleteIsBatch: true`） | **没有** |

三条细节，都是读源码 + 后端代码得到、**没有基准**的：

1. **新建的 body 里 `id` 是 `null` 而不是"没有这个键"**：页面写的是
   `pick(form, ['id','sort','question'])`，`form` 初值 `{ id: null, sort: '', question: '' }`，
   `pick` 保留 `null`。能力照抄这个形状（后端 `insert` 见 id 为 null 走自增，没有副作用）。
2. **`sort` 的形态取决于改动方式**：表单页那个字段是 `a-input type="number"` +
   `v-model:value`，**手敲进去的是字符串**（`"3"`）；而编辑时表单初值来自 list 页塞进 bridge 的
   **整行记录**（`rrList.actionEdit(record, { ...record })`），那时 `sort` 是后端给的**数字**。
   所以两种形态都真实存在，能力**按调用方给的形态原样发**。后端
   （`AiQuestionHotInfo.sort` 是 `TINYINT`）两种都收。
3. **删除是逻辑删除**：`zhdj_ai_question_hot.del_flag = 1`，**没有复原接口**。
   它**顺带**做第二件事 —— 把这些行 `question_code` 对应的**问答行 `is_hot` 改回 0**
   （`AiQuestionHotInfoServiceImpl.logicalDelete` → `updateIsHotByQuestionCode`）。
   这一条是下面「交互历史」页「转为热门」的撤销依据。

⚠️ **`addHotQuestion` 不回传新 id**（后端 `success(null)`）⇒ 撤销前必须按 `question`
回查 `listHotQuestions({ role: 'user', question })` 拿到 id，再 `cancelCreatedHotQuestion(id)`。

## 「详情」不发请求

`handlePreview` 弹的是 `components/preview.vue`，纯展示（`a-descriptions`），**一个接口都不打**。

## 真实验证（**读路径有基准，写链路未做**，如实记）

- **读**：这一页的列表请求有基准背书 —— `baseline/ai-interaction-qa.browser.json` 里那条
  `getSysHotQuestion`，与能力逐字段一致（见上）。
- **写**：`addHotQuestion` / `updateHotQuestion` / `logicalDelete` **一次都没在测试环境发过**。
  原因是这一单的约束：派单明确「**你没有授权用浏览器**、不要 `bsk`、不要新建 smoke 脚本」，
  而取测试环境会话 token 的唯一受控入口是 `smoke/with-portal-token.sh`（它起的正是 `bsk` 会话，
  `docs/conventions.md` 第 8 条）；基准也只是**只读抓取**，14 条里 0 条非 GET。
  所以写链路没有"实际请求 / 响应"可以记进来 —— **不是"接口返回成功"被当成验证，是压根没发出去**。

要补这一条，需要一个能拿 token 的执行环境，然后按
`prepare → submit → cancel` 跑一遍：

1. `prepareCreateHotQuestion({ sort: <找一个没被占用的>, question: 'SDK-TEST-热门问题-<时间戳>' })`；
2. `createHotQuestion(...)`；
3. `listHotQuestions({ role: 'user', question: 'SDK-TEST-热门问题-<时间戳>' })` 拿新行 id
   —— 这一步本身就**独立证明写进去了**；
4. `cancelCreatedHotQuestion(id)` 撤销，再查一次列表确认它已经不在了
   （⚠️ 逻辑删除 ⇒ 只能看列表，别看单行）。

测试数据一律带 `SDK-TEST-` 前缀、同一轮内撤销（`tools/baseline/README.md` 第 0 节）。

## 基准兑现了什么 / 还剩什么没判据

**已落成真断言**（`test/ai-interaction-qa.test.ts` 的 B2 组，全部做了反证）：

- ✅ 无筛选列表请求与基准**逐字段一致**（URL、键序、`_t` 位置、`order=`/`orderField=` 空值）。
- ✅ 四页无筛选时的 query **逐字相同** —— 现在是基准证实的（`expect(mine).toEqual(base)`）。
- ✅ 这一页**不发** `module-type`：基准 14 条的 `headers` 只有
  `Accept` / `Accept-Language` / `tenant-id` / `token` 四个键，一条都没有它。
- ✅ 请求头**逐键一致**（四页各比一遍，多一个头就会红）。
- ✅ 这一页"页面自己的请求只有那一条"（去掉两条外壳请求后，去重只剩 1 条）。

**仍然没有判据**（测试里留着 `it.todo`，别硬编）：

- ❌ `user`（人工）/ `mix`（预览）两个角色的参数。⚠️ 基准里**没有**
  `getMixedHotQuestion` / `getManualHotQuestion` —— 抓基准时页面挂载在默认的 `system`、
  没人切过那个 `a-segmented`。所以「`mix` 带不带 `pageNo`/`pageSize`」**仍然只有源码推导**
  （`getDataListIsPage` 在 setup 时算死为 `true`），**不要拿 `getSysHotQuestion` 那条当它**。
- ❌ 写请求的 method / URL / body（基准 0 条非 GET）。
- ❌ 带筛选值的请求形状（基准只抓了"挂载时无筛选"那一条）。

## 尚未覆盖

- `role = 'mix'` 时模板里没有分页控件，但请求仍带分页参数 —— 这一条**只有源码推导**，
  基准也没能证伪（它只抓到 `system` 那一条，见上）。
- 基准里**点「查询」重发**的现象：这一页在基准里只有 1 条列表请求（没被点过「查询」），
  而敏感词 / 意见反馈各多一条只差 `_t` 的相同请求 —— 别基于"每页恰好一条"去写断言。
- 后端的 `sysDisplay` 参数只在 `AiQuestionHotInfoMapper.xml` 的 **`findListByPage`** 里被用到
  （`AND ((z.create_id = 0 AND z.create_time <= current_date()) OR z.create_id != 0)`）。
  也就是说：`getMixedHotQuestion`（走 `findListByPage`，控制器强制 `sysDisplay=1`）**会**过滤"系统
  未来才生效"的行，而 `getSysHotQuestion` / `getManualHotQuestion`（走各自那个不分页 mapper）
  **不受它约束**。这是**后端差异**，SDK 如实透传、不替调用方补参数；上线那一版
  `list1.vue`（走 `getHotQuestionListByPage`，同样会 `sysDisplay=1`）已经**不算数**了，见上文。
