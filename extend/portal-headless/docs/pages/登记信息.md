## Portal 页面行为

列表筛选只有 `name` 和 `type`，初始值都是空字符串。列表调用 `GET /admin-api/hr/business-registration/page`，Portal 的通用分页模块补充 `order=''`、`orderField=''`、`pageNo=1`、`pageSize=20`。列表操作包括导出、企业登记、编辑、删除、变更、变更记录和共享设置；共享弹窗传 `type: 5`。

导出调用 `/admin-api/hr/business-registration/export-excel`，只把当前 `name/type` 筛选发送给 GET 请求，页面收到二进制后固定下载为 `企业登记.xlsx`，不把分页参数带入导出。

完整表单读取 `/get`；新建 POST `/create`；编辑 PUT `/updateALL`。提交前把 `pdfUrl/pdfName` 数组分别逗号连接；`isForever=1` 时把 `timeBusiness` 发送为空字符串；`isUnit` 转成布尔值；本单位法人发送 `legalRepresentative`，外部法人发送 `legalRepresentativeOutside`；空注册资本发送 `0`。详情中的逗号串附件在编辑页还原为数组。

变更页读取最新登记详情，用户选择的字段来自页面本地白名单。提交时有变更记录先 POST `/admin-api/hr/business-registration-log/createBatch`，再按实际变化 PUT `/admin-api/hr/business-registration/update`；相同的变更前/后值不生成普通记录。变更记录页读取 `/business-registration-log/get`，删除同一 `createTime` 批次时把该批次全部 ID 作为 DELETE body 数组发送。

## 表单、人员和权限规则

- `status` 只能是 `1=存续`、`2=注销`、`3=吊销`；`name` 最多20字符，`signNumber` 最多30字符，`address` 最多200字符。
- `organizationId`、`type`、`establishmentTime`、`remindTime`、`registrationAuthority` 必填；登记机关最多200字符，经营范围和股权结构最多1000字符；提醒天数是至少1的整数。
- `isUnit=1` 时法定代表人来自用户选择器，提交的是用户 ID `legalRepresentative`，不是工号；`isUnit=0` 时提交外部法人文本 `legalRepresentativeOutside`，纯数字会被页面拒绝，二者互斥。
- `isForever=0` 时营业期限 `timeBusiness` 必填；`isForever=1` 时发送空字符串。成立日期、营业期限、变更日期均为 `YYYY-MM-DD`。
- 董事、监事、高级管理人员分别维护内部、外部和未注册人员数组；人员关系的 `staffCode` 是工号或未注册文本，不与法人用户 ID 混用。
- 附件只允许 PDF，最多10项；`pdfUrl` 与 `pdfName` 必须逐下标对应、数量一致，提交时分别 join 为逗号串。
- 列表、详情、写入、变更和共享受当前会话、租户、页面权限和后端数据范围约束。Java 服务写入当前用户/租户并按业务登记共享类型 `5` 处理；SDK 不扩大权限，也不把空结果或 `true` 回执当作已完成业务证据。
- 共享读取和保存使用 `/admin-api/system/share-user/getShare`、`/createShare`；企业登记保存时每类成员只发送 `{ id }`，不把读取响应中的 `managerType` 回传。

## 后端与 SDK 对齐

Java `BusinessRegistrationController` 提供分页、详情、创建、完整更新 `updateALL`、部分更新 `update`、删除和 Excel 导出；`BusinessRegistrationLogController` 提供变更批量创建、按登记读取和按批次 ID 删除。`BusinessRegistrationServiceImpl` 写入当前用户/租户、维护人员关系，并使用 `ShareTypeEnum.BUSINESSREGISTRATION(5, "企业登记")` 参与资源范围处理。

实现文件：`src/capabilities/business-registration.ts`；AI 说明：`src/catalog/contracts-business-registration.ts`。SDK 把 Portal 可达动作分别暴露为列表、详情、导出、准备/提交表单、删除、准备/提交变更、变更记录和共享；变更严格保持 Portal 的 POST→PUT 顺序，写操作完成后由调用方按说明回查。
