## 后端基准

源码锚点：Java `test/test` 检出 `dcb3f360194e`。

- `IncomeCategoryController` 的有效接口是 `POST /finance/income-category/create`、`PUT /finance/income-category/update`、`GET /finance/income-category/get`、`GET /finance/income-category/page` 和 `GET /finance/income-category/getControlInfo`。本页只调用 create、update、page；详情按钮使用桥接，因而不发布 get。
- `IncomeCategorySaveReqVO` 业务字段为 `id`、`status`、`categoryName`、`categoryType`、`pid`。SDK编辑/废弃按 `id,status,categoryName,categoryType,pid` 的固定键序发送；创建按 `pid,categoryName,categoryType` 发送页面实际需要的后端字段子集。
- `IncomeCategoryServiceImpl.createIncomeCategory` 返回数据库生成的 `Long` ID，并检查启用类目名称重复。创建表单本身不显式发送 `status`，数据库默认状态未在当前源码范围内确认，SDK不擅自补写 `status=1`。
- `IncomeCategoryServiceImpl.updateIncomeCategory` 成功返回 `true`。修改父级时，被绑定类目不能调整结构；`status != 1` 时，被绑定类目或存在启用子节点会被拒绝；因此“废弃”不是无条件状态切换。
- `getIncomeCategoryPage` 将页大小设置为 `PageParam.PAGE_SIZE_NONE`，Mapper始终追加 `status=1`，映射后将 `parentId` 设为 `pid`，再由 `TreeUtils.build` 返回树数组。返回值不是 `{ list, total }`。
- `IncomeCategoryEnum` 当前源码列出 `1=主营业务收入`、`3=补贴收入`、`4=其他收入`。前端标签仍来自运行时 `category_type` 字典；SDK允许安全整数扩展值，不把标签或字典条目ID冒充 value。
- Controller中没有 DELETE 类目接口，导出接口也是注释代码。本页创建记录不存在 Portal/后端可逆删除动作。

### 1. 列表请求与返回

SDK请求对象固定为：

```json
{
  "url": "/admin-api/finance/income-category/page",
  "method": "get",
  "params": { "order": "", "orderField": "" }
}
```

platform 请求层会按通用规则追加当前会话需要的鉴权头和 GET 防缓存 `_t`；本页不加 `module-type`，也不把 token 放进业务参数。当前页面没有可用的 `pageNo`、`pageSize`、`categoryName`、`categoryType`、`pid` 或 `status` 筛选控件，SDK不开放这些隐藏筛选参数。

SDK返回 `FinanceSettingCatConfigRow[]`：

| 字段 | 类型/空值 | 含义 |
| --- | --- | --- |
| `id` | `string \| number` | 类目主键；长 Java Long 保留字符串 |
| `status` | `0 \| 1` | `1` 启用且由当前列表返回；`0` 停用/废弃 |
| `createTime` | `string \| number \| null` | 后端录入时间原值，不猜时区 |
| `categoryName` | `string` | 类目名称 |
| `categoryType` | `number` | `category_type` 字典 value |
| `pid` | `string \| number \| null` | 父类目主键；根的 `0`、`"0"`、`null`、空值归一为 `null` |
| `parentId` | `string \| number \| null` | 后端 `pid` 的响应别名，同样归一根值 |
| `children` | `FinanceSettingCatConfigRow[]` | 直接下级，递归同构；后端缺失/null时 SDK 输出空数组 |

SDK去掉 Portal 客户端临时的 `topIndex`，也不把 DO 的 `bindTime`、`isBind` 或其它未进入 Response VO 的字段伪造到返回中。空树是 `[]`，不是分页对象。

### 2. 创建

`prepareCreate({ pid?, categoryName, categoryType? })`：

- `categoryName` 去首尾空白后不能为空，但发送时保留调用方原字符串。
- `categoryType` 省略时使用页面默认数值 `1`；运行时字典的实际标签由 Portal 解释。
- 顶级 `pid` 省略、传 `null` 或空字符串，草稿和请求统一为 `pid: ""`；子类目必须传当前树节点 `id`。
- 草稿/请求键序固定为 `pid`、`categoryName`、`categoryType`。`pName`、`id`、`pList` 是 Portal 表单桥接字段，SDK不发送。

`create` 成功返回安全正整数或其十进制字符串形式的后端主键ID。不能仅凭返回ID报告业务完成，需重新 `list`，递归核对同一ID、父级、名称和类别。

写闭环：

1. `prepare-create` 生成草稿并让用户确认。
2. `create` 提交；超时先按父级、名称、类别刷新树，不要盲目重建。
3. **无 cancel**：当前 Controller/Service/Portal 页面都没有 DELETE 或可逆创建接口。创建后的 cleanup 只能依赖部署方受控数据库/运维清理；本次未创建真实记录，也没有 cleanup 证据。

### 3. 编辑

`prepareUpdate({ current, changes? })` 只允许变更 `pid`、`categoryName`、`categoryType`，并保留 `current` 的 `id`、`status` 与完整 `previous`。页面没有状态编辑控件。

`update({ draft })` 提交完整后端保存字段，固定键序为：

```json
{
  "id": "类目ID",
  "status": 1,
  "categoryName": "类目名称",
  "categoryType": 1,
  "pid": "父类目ID或空字符串"
}
```

成功业务值必须是 `true`。之后重新 `list` 按 `draft.id` 核对全部业务字段；`true` 不含更新后的记录。

取消/恢复不是事务回滚：只有保存了 `prepareUpdate` 返回的 `previous`，且用户明确要求恢复时，才把 `previous` 作为新的 `update({ draft })` 再写一次并回查。

### 4. 废弃

`prepareDiscard({ current })` 只接受最新 `status=1` 的完整节点，保存 `previous`，并生成相同业务字段但 `status=0` 的草稿。`discard({ draft })` 仍调用：

```text
PUT /admin-api/finance/income-category/update
```

请求体仍包含 `id,status,categoryName,categoryType,pid`，不能只传ID。后端会拒绝被绑定的类目或存在启用子节点的类目。由于 page 查询强制 `status=1`，成功废弃后目标ID从启用树中消失是页面可见性核对证据，不是 DELETE 证据。

如需取消废弃，必须保存操作前 `previous(status=1)`，再用 `update` 提交该 previous；这只是补偿写，不能保证并发场景下恢复原状。
