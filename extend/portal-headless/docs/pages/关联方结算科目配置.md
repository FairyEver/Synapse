## 参数契约

### 选项来源

- `paymentContent` 是平台字典 `finance_related_settlement_content` 的 `value`。Portal 会话初始化通过 `GET /admin-api/system/dict-data/grouped-list` 获取字典分组；页面组件只从 store 取值，不在本页另发字典请求。提交字典 `value`，不提交 `entry.id` 或标签。
- 四个科目选择器使用 `portal-finance-ledger-select`。组件默认读取 `/admin-api/finance/ledger-accounts/page`，请求带 `pageSize=-1`；弹窗查询另带 `status=0`、`ledgerType`、`balanceDirection`、名称/编码和排序条件。SDK契约用既有 `finance-ledger-account-list` 返回的科目 `id` 作为四个主键。
- 当前Java controller的保存 VO 要求 `paymentContent`、四个科目ID和`status`非空，`status`只能是0/1；启用状态下同一付款内容只能有一条配置。SDK不硬编码字典值，候选必须来自运行时字典。

### 列表

默认请求参数按 Portal `useListPageModule` 顺序发送：

```json
{
  "order": "",
  "orderField": "",
  "paymentContent": "",
  "payerSubjectId": "",
  "receiverSubjectId": "",
  "status": null,
  "pageNo": 1,
  "pageSize": 20
}
```

请求：`GET /admin-api/finance/payment-slip-society-related-settlement/subject-config/page`。

返回 `{ list, total }`：

| 字段 | 类型/空值 | 含义 |
| --- | --- | --- |
| `list` | array | 当前页，不是全部匹配记录 |
| `list[].id` | `string \| number` | 配置主键；编辑、详情、启停使用 |
| `list[].paymentContent` | `integer \| null` | `finance_related_settlement_content` 字典 value |
| `list[].payerDebitSubjectId` / `payerCreditSubjectId` | `string \| number \| null` | 付款方借/贷科目主键 |
| `list[].payerDebitSubjectName` / `payerCreditSubjectName` | `string \| null` | 后端按科目ID填充的展示名称 |
| `list[].payeeDebitSubjectId` / `payeeCreditSubjectId` | `string \| number \| null` | 收款方借/贷科目主键 |
| `list[].payeeDebitSubjectName` / `payeeCreditSubjectName` | `string \| null` | 后端按科目ID填充的展示名称 |
| `list[].status` | `0 \| 1` | `1`启用，`0`停用 |
| `list[].remark` | `string \| null` | 后端备注；页面未展示 |
| `total` | integer | 当前筛选条件下的总条数 |

⚠️ 页面筛选控件名是 `receiverSubjectId`，当前 Java `PageReqVO`/Mapper 读取的是 `payeeSubjectId`。SDK忠实发送页面字段，不把它静默改名；收款方科目筛选是否在部署环境生效仍是缺口。

## 保存、编辑与启停 payload

### 创建

`prepareCreate` 校验并生成：

```json
{
  "paymentContent": "字典value",
  "payerDebitSubjectId": "付款方借方科目ID",
  "payerCreditSubjectId": "付款方贷方科目ID",
  "payeeDebitSubjectId": "收款方借方科目ID",
  "payeeCreditSubjectId": "收款方贷方科目ID",
  "status": 1
}
```

`POST /admin-api/finance/payment-slip-society-related-settlement/subject-config/create`，成功返回新配置主键。页面表单初始状态为1；`remark`仅作为后端可选扩展字段，页面没有输入控件。

### 编辑

`prepareUpdate` 从最新列表/详情行保留 `id`、`status`，只允许变更 `paymentContent`、四个科目ID和可选`remark`。`PUT /admin-api/finance/payment-slip-society-related-settlement/subject-config/update` 发送完整保存字段，不发送科目名称：

```json
{
  "id": "配置ID",
  "paymentContent": "字典value",
  "payerDebitSubjectId": "付款方借方科目ID",
  "payerCreditSubjectId": "付款方贷方科目ID",
  "payeeDebitSubjectId": "收款方借方科目ID",
  "payeeCreditSubjectId": "收款方贷方科目ID",
  "status": 1
}
```

后端成功业务值为`true`。Portal源码的表单初始键和校验仍写成`receiverDebitSubjectId`/`receiverCreditSubjectId`，模板绑定却使用`payeeDebitSubjectId`/`payeeCreditSubjectId`；SDK按后端有效字段校验，不把这个页面缺陷隐藏成“校验通过”。

### 启停

页面按钮权限为 `finance:setting:related-party-settlement-account:status`。页面实际执行：`{ ...record, status: nextStatus }` 后 `PUT /admin-api/finance/payment-slip-society-related-settlement/subject-config/update`。SDK的`prepareSetStatus`保存`previous`，并生成包含列表整行展示字段、ID、四个科目ID、备注和目标`status`的草稿；目标状态必须与当前状态相反。

启停成功或超时后，必须按同一`id`重新列表/详情核对目标状态。恢复使用`previous`再次PUT，是补偿写，不是事务回滚。后端没有requestId或幂等键。

## 详情路径冲突

Portal表单源码的详情加载是：

```text
GET /admin-api/finance/related-party-settlement-account/getConfig?id=<id>
```

当前 Java controller 的有效映射是：

```text
GET /admin-api/finance/payment-slip-society-related-settlement/subject-config/get?id=<id>
```

SDK实现按Portal源码保留 `getConfig`，返回表单实际消费字段，并在AI契约中登记与Java `/subject-config/get` 的冲突；本地静态检出未提供部署版本或浏览器基准来裁决，不能宣称详情真实可用。

## 操作步骤与撤销/清理

1. `list`读取当前页，分别用平台字典解释付款内容、用会计科目候选解释四个科目ID。
2. 创建：`prepareCreate → create → list`，按返回ID核对四个科目和状态；超时先回查，不要盲目重复创建。
3. 编辑：用最新行执行`prepareUpdate → update → list/detail`逐字段核对；保留`previous`，需要撤销时再次提交previous并回查。
4. 启停：`prepareSetStatus → setStatus → list`按同一ID核对状态；恢复时使用previous补偿写。
5. 页面没有删除或cancel接口；创建后的清理必须转交部署方受控运维流程。本任务没有真实写入，故没有真实清理记录。
