## Portal 页面行为

列表由 `useListPageModule` 注入 `order`、`orderField`、`pageNo`、`pageSize`，默认页大小为20，页面选项为10/20/50/100。默认请求体为：

```text
order=&orderField=&name=null&code=null&unitName=null&accountingSetId=null&orgId=null&orgAttribute=null&status=1&pageNo=1&pageSize=20
```

列表状态是数值 `1/0`，行展示把 `1` 显示为启用、`0` 显示为停用。列表可见动作是编辑和启停，权限分别为 `finance:setting:cost-center:edit`、`finance:setting:cost-center:status`；新增权限为 `finance:setting:cost-center:create`。

编辑表单读取详情并把 `orgList[].orgId` 映射为 `orgIds`。新增时选择 `unitId` 会先调用 `resolve-org-scope` 回填账套，再调用 `generate-code` 回填编码；请求竞态以页面请求序号处理。`orgIds` 没有必填校验，允许空数组。

## 表单提交规则

Portal 表单会复制表单状态并删除 `accountingSetName`，随后发送以下业务字段：

| 字段 | 新建 | 编辑 |
| --- | --- | --- |
| `id` | 空字符串占位 | 当前成本中心ID |
| `name` | 必填，最多500字符 | 可编辑，必填 |
| `unitId` | 必填，组织ID | 页面禁用，沿用当前值 |
| `code` | 页面按unitId预填；服务端覆盖 | 页面禁用，沿用当前值 |
| `orgAttribute` | 必填，`1`至`6` | 可编辑，必填 |
| `orgIds` | 组织ID数组，可为空 | 页面禁用，沿用详情关联组织 |
| `accountingSetId` | 页面按unitId解析；服务端覆盖 | 沿用当前值，服务端最终校验 |
| `status` | 页面默认`1`启用 | 沿用当前值；无可见表单控件 |
| `accountingSetName` | 不发送 | 不发送 |

树选择器值可能带节点前缀，Portal 提交前取下划线后的原始组织ID；SDK 保留长ID字符串，避免转换为不安全数字。

## 权限与后端规则

- SDK 使用 `platform` 实例，页面权限、按钮权限、租户和数据范围由会话与后端共同裁决；不从浏览器提取凭据。
- 后端按所属组织解析法人和账套，并按账套生成/覆盖成本中心编码；调用方传入的 `code`、`accountingSetId` 不是最终权威值。
- 创建时 `orgIds=[]` 会由后端建立虚拟组织；更新时空 `orgIds` 保留既有关联，不能把空数组误解释成删除全部关联。
- 后端还会校验组织归属、编码唯一性、成本中心可编辑状态和启用条件；SDK 不以接口成功或 `true` 回执替代写后回查。
- Java 的删除、导入、初始化、当前用户列表和混合组织树接口未被当前 Portal 页面调用，因此不扩展到本页能力。

## 后端与 SDK 对齐

Java `CostCenterController` 的 page、get、create、update、update-status、generate-code、resolve-org-scope 均有页面对应调用。SDK 在 `src/capabilities/finance-setting-cost-center.ts` 集中实现默认请求体、数值状态、完整响应投影、表单必填规则、联动端点、`accountingSetName` 排除、Long ID 保留、绝对状态启停和坏响应拒绝。
