## 参数契约与逐字段基准

列表默认发送 `order=''`、`orderField=''`、`unitId=null`、`name=null`、`pageNo=1&pageSize=20`。新增每行必须有 `unitId`、`materielCategoryId`、`name`；名称最多 20 字符，`minQuantity`/`maxQuantity` 可空、非负且最多 2 位小数。Portal创建时固定把 `status` 写为 `true`，SDK保持该规则。

启停必须同时提供同一次列表读取的 `id`、`currentStatus` 和用户明确选择的绝对 `status`；目标状态必须与当前状态相反。`prepareSetStatus` 返回 `{ draft: { id, status }, previous: { id, status: currentStatus } }`，submit 只接受 `draft`。返回值只接受 `true`，列表行状态为布尔值，数量和关联ID按原值返回。

## 操作步骤、失败处理与验证边界

1. 新增前先读取所属单元和物料分类树，保存用户选择的节点ID；名称不参与ID推断。
2. 调用 `.prepareCreate`，用户确认后 `.create`；取消只丢弃草稿。成功或超时后按单元、分类、名称和数量回查，因为创建没有新ID回执。
3. 启停必须从最新列表行构造绝对目标状态；调用 `.prepareSetStatus` 后，用户确认才 `.setStatus`，目标为 `true` 发 `/open`、目标为 `false` 发 `/close`，完成后按同一ID回查。确认前取消只丢弃本地草稿；页面源码的空 catch 不代表成功，SDK传播错误。
4. 缺字段、名称/数量越界、同状态切换、坏树、非 `true` 回执、权限、网络和后端错误均失败；超时先回查，不盲目重发。
