## 参数、提交规则与返回字段

### 列表

Portal styleV2 的默认请求参数为：

```json
{
  "order": "",
  "orderField": "",
  "name": "",
  "pName": "",
  "code": "",
  "typeId": "",
  "level": "",
  "status": 1,
  "pageNo": 1,
  "pageSize": 20
}
```

`status` 为数值 `1` 启用、`0` 停用；显式传 `null` 表示清除状态筛选。`level` 只能是正整数或空筛选。
页面支持的每页数量是 10、20、50、100。SDK 保留长 ID 的字符串形态，不把组织 ID、组织类型 ID、岗位 ID
和变更记录 ID 混用。

列表返回 `{list,total}`。`list` 是当前页，`total` 是当前筛选条件下的后端总数。页面字段逐项投影为：

`id`、`name`、`code`、`type`、`level`、`parentOrg`、`director`、`foundDate`、`isCorporation`、
`legalName`、`mainInvest`、`isStandardUnit`、`standardUnit`、`standardLine`、`fullPath`、`containJob`、
`createTime`、`country`、`address`、`officeAddress`、`remark`、`status`。除 `id/name/status` 外，页面字段可为
`null`；`status` 之外的未知后端字段不作为列表消费契约返回。

### 创建与编辑表单

Portal 表单初始值包含 `country='中国'`、各数组为空、`isCorporation=0`、`isStandardUnit=0`、
`isCostCenter=0` 以及空字符串字段。SDK 在 `prepareCreate`/`prepareUpdate` 中复刻以下规则：

- `name` 必填、不能全为空格、最多 50 个字符；`code` 可空，只能由数字和英文字母组成，提交前转大写。
- `typeList` 至少选择一个组织类型；`pid`（上级组织）和 `foundDate` 必填。Portal 只做成立日期必填校验，
  SDK 不额外猜测日期时区或格式。
- `remark` 可为空，最多 200 个字符；非空时不能全为空格。
- `jobList` 每行必须有 `postId`、`isExternal=0/1`。编内岗位 (`0`) 的 `needNumber` 必须是非负整数；
  编外岗位 (`1`) 的目标编制为空并在页面显示无限。岗位备注不能全为空格。`partTimeJobList` 无论输入是
  ID 还是 `{postId,...}`，最终都提交为 `[{postId}]`。
- `isCorporation=1` 时 `corporation` 必填，证照数量必须是非负整数；此时保留 `hrLegalPersonDTO` 和
  `hrOrganizationLicenseDTOList`。`isCorporation=0` 时清空并删除这两个字段。
- `isStandardUnit=1` 时 `standardUnit`、`standardLine` 必填；`isCostCenter=1` 时 `costCenter` 必填。
  这些条件关闭时页面清空对应字段，SDK 也提交清空后的值。
- Portal 对字符串形态的 `directorList` 单值转成单元素数组；数值单值按原页面对象保留。`directorPostName`、`checkedIdList`、`belongLegalPersonName`
  始终是 UI 显示/选择状态，按 Portal 的 `omit` 规则不提交；创建只取页面表单字段，编辑会保留详情对象中
  其他页面状态字段，再删除上述 UI 字段。

创建和编辑均无业务返回 ID，成功返回 `undefined`。写入超时或网络错误时不能自动重试；应重新 `list` 或
`detail` 回查后再决定是否重试。表单底部“取消”只是路由返回，不会调用服务器撤销；已提交组织没有本页面提供的
撤销/删除动作。

岗位编制还有一个页面级前置条件：当 `isStandardUnit=0` 且 `jobList` 非空时，页面先读取
`checkHaveStandardUnit(pid)`，返回 false 会阻止提交并提示必须创建标准化单元；没有岗位时页面只是警告，仍会继续
表单校验和保存。SDK 将该检查作为独立能力，调用方应在添加岗位前执行，不把它错误地当成服务端 POST 的隐含保证。

### 启停与组织关系

- 页面行状态为 `1` 才显示“停用”，先 POST `checkCanDisable/{id}`，将返回的确认文案交给用户确认，再 POST
  `disable/{id}`；SDK 的 `disable` 要求调用者提供同一最新列表行的 `currentStatus=1`，不在写请求中重复调用检查。
- 页面行状态为 `0` 才显示“启用”，确认后 POST `enable/{id}`；SDK 要求 `currentStatus=0`。
- `checkCanDisable` 返回空字符串、`null` 或无值时统一为 `null`，表示使用页面默认确认文案；它不是“可以停用”的持久化结论，
  检查和写入之间可能发生并发变化。
- “变更组织隶属关系”由 `useSensitiveAction` 门控。`prepareChangeRelation` 读取敏感配置；若要求验证，先用配置手机号
  调 `sendChangeRelationCode`，再由用户提供验证码，`changeRelation` 内部校验后才 PUT `{id,pid}`。敏感配置免验证时直接 PUT。
  取消弹窗不会发 PUT；写入成功也不代表历史记录已被独立回查确认。

### 导入、导出和模板

- 导入前端 `accept=".xlsx"` 且 custom request 严格要求
  `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`。SDK 同样拒绝 `.xls` 和其他 MIME，
  虽然 Java listener 兼容 `.xls`；这是按当前 Portal 可达行为对齐。`prepareImport` 只做本地 Base64、扩展名、MIME、非空校验。
- `importFile` 以 multipart 字段 `file` POST `/org/organization/import`。Java listener 还会检查最多 2000 行、标准化单元、岗位名称、
  编内岗位已有编制时不能改编外等规则；这些业务错误由后端返回，SDK 不把请求成功猜成每行都导入成功。
- `export` GET `/org/organization/export`，只发送列表筛选字段 `name/pName/code/typeId/level/status`，不发送分页和排序；
  返回非空二进制并固定文件名 `组织.xlsx`。后端当前响应头是 Excel 类型，SDK 不按 ZIP 特征错误拒绝 `.xls` 响应。
- 模板下载先 GET `/org/organization/downloadTemplate?orgId=...` 取得 OSS URL，再用同一页面请求上下文二次 GET 二进制；
  URL 为空或没有标准化单元时失败，不会发第二次请求。文件名取 URL 最后路径段。

### 历史和兼职人员

历史列表默认同样是 styleV2 每页 20 条，发送 `orgName/operatorName/startTime/endTime`；时间范围必须是
`YYYY-MM-DD HH:mm:ss`。返回行字段为 `id/orgId/orgName/changeTypeDesc/changeFieldCount/changeTime/operatorName`。
详情返回同一基本信息和 `changeItems[]`，每项为 `field/oldValue/newValue/changeDesc`。这是只读对比，页面没有恢复历史的动作。

编辑页的兼职人员弹窗先 GET `/hr/organization-scene/post-scene/list`，读取 `partTimePosts[]` 的
`postId/postName/partTimeStaffCount/existNumber`；选中岗位后 GET `/hr/organization-scene/post-level/staff-page`，
固定发送 `postKind='PART_TIME'`、`pageSize=20`，关键字先 trim。人员行按页面消费返回
`relationId/name/staffCode/organizationName/postName/status`。

## 请求逐字段基准

platform 客户端会把以下逻辑路径补成 `/admin-api/...`，注入 tenant/token/language 和 `module-type: 11`，
并拆 Portal 标准响应包络；文件响应使用原始二进制。表单详情源码虽然部分写成 `/admin-api/...`，实际请求与下面的逻辑路径一致。

| 动作 | HTTP | 逻辑路径 | 参数/请求体 |
|---|---|---|---|
| 列表 | GET | `/org/organization/page` | order/orderField/name/pName/code/typeId/level/status/pageNo/pageSize |
| 详情 | GET | `/org/organization/{id}` | 路径 id |
| 标准化单元检查 | GET | `/org/organization/checkHaveStandardUnit` | `pid` |
| 创建/编辑 | POST/PUT | `/org/organization` | 表单投影后的 JSON |
| 停用检查 | POST | `/org/organization/checkCanDisable/{id}` | 无 body |
| 停用/启用 | POST | `/org/organization/disable/{id}`、`/enable/{id}` | 无 body |
| 关系变更 | PUT | `/org/organization/updateBelongRelation` | `{id,pid}` |
| 导出 | GET | `/org/organization/export` | 当前筛选，不含分页 |
| 导入 | POST | `/org/organization/import` | multipart `file` |
| 模板 URL | GET | `/org/organization/downloadTemplate` | `orgId` |
| 变更历史 | GET | `/hr/org/organization/changeLog/page`、`/{id}` | 列表筛选或路径 id |
| 兼职岗位/人员 | GET | `/hr/organization-scene/post-scene/list`、`/post-level/staff-page` | 组织、岗位、`PART_TIME`、关键字、分页 |
| 岗位树 | GET/POST | `/org/hrpost/searchPage`、`/nodeDetails` | 关键字分页；已选 ID 最多 100 个 |
| 负责人 | GET | `/sys/user/getUserPageInfo`、`/getUserListInfoByIds` | 必须先关键字；ID 回显使用逗号数组参数 |
| 表单候选 | GET | `/org/organizationType/selectAll`、`/hr/org/organizationProperty/page`、`/system/license-category/page`、`/org/corporation/getAllLegalPerson`、`/salary/costcenter/list` | 页面固定查询参数 |

## 操作步骤与验证记录

1. 查询：`list` → 按 `total` 翻页 → 只使用当前行的 `id/status` 执行启停或关系动作；列表字段不作为详情全量替代品。
2. 创建：填写表单 → 有岗位且非标准化单元时先 `checkHaveStandardUnit` → `prepareCreate` → `create` → 重新列表并按名称/编码等业务字段核对。
3. 编辑：`detail(id)` → 将兼职对象转 ID、证照对象保留 `typeId/typeNum` → `prepareUpdate` → `update` → `detail(id)` 回查。
4. 停用：最新列表行 `status=1` → `checkCanDisable` → 用户确认 → `disable` → 回查列表 `status=0`。启用同理要求 `status=0`。
5. 关系变更：敏感准备 → 按需发送/校验验证码 → `changeRelation` → 回查列表及历史；取消验证或弹窗直接结束，不产生写入。
6. 导入：先 `prepareImport` → `importFile` → 重新列表核对受影响组织的岗位编制；导入失败时保留后端错误，不自动重复上传。
7. 模板/导出：模板选择有标准化单元的 `orgId`，完成两段下载；导出只按当前筛选，不把下载成功当作业务写入。
8. 历史：`historyList` → 选取 `id` → `historyDetail`，逐项展示 `oldValue/newValue`，不承诺恢复。

离线验证：`test/org-setting.test.ts` 共 14 项，覆盖列表默认值和字段投影、详情/标准化单元/停用检查、创建和编辑条件载荷、
状态保护、敏感门控和验证码顺序、导入 MIME/二进制、导出筛选、模板二次下载、历史、兼职人员、岗位/用户候选，以及固定 Portal
权限/路径/omit 反证。负例会在业务请求前失败，关键反证恢复后全绿。

## 实测与推断边界、接线事项

  后端每种失败文案和写入后的真实回查。这些不能从本轮离线测试推断为已通过。
