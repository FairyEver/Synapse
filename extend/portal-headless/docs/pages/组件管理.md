## 参数契约

⚠️ **这是本组唯一的 GET。** 它不用 `customLoad`，走的是列表模块的默认通道
（`list.js:487-489` 的 `_http.get(getDataListURL, { params })`）。
于是与三个薪酬页有**两点不同**：

1. 参数在 **query** 上（不是 body）；
2. **会补 `_t`**（`platform.js:36-41` 只给 GET 加），且 `_t` 排在**最末**。

顺序逐字取自页面 `form:` 初值（`block/main/list.vue:72-76`）：

```
order → orderField → name → warehouseType → type → pageNo → pageSize → _t
```

初值：`{ name: '', warehouseType: '', type: '' }`（全空）

## 逐字段基准

```
GET /admin-api/performance/basedata/kpisubassembly/page
    ?order=&orderField=&name=&warehouseType=&type=&pageNo=1&pageSize=20&_t=<ts>
```

**空值照发**（`name=` / `warehouseType=` / `type=` 都在 URL 上，值为空串）——
与 conventions 第 4 条一致。

## 动作审计与覆盖边界

本页只有一个服务端写动作：行内启用/禁用；「查看」是纯本地弹窗，不新增接口。接口、权限上下文和状态翻转规则已按 Portal 源码及 Java 控制器静态核对。

| 入口 | Portal 请求 / 规则 | SDK 使用边界 |
| --- | --- | --- |
| 行内「启用 / 禁用」 | `PUT /performance/basedata/kpisubassembly`，body 严格为 `{ id, status }`；`record.status === 0` 时发送 `status: 1`（启用），否则发送 `status: 0`（禁用）。Portal 先确认再发送。 | `prepare` 读取/接收当前 `status`，只生成目标状态草稿；`submit` 才 PUT；`cancel` 放弃草稿、不发请求。成功后重新查询列表，按 ID 核对状态已从 0↔1 翻转。 |
| 行内「查看」 | `createModal` 打开 `./components/modal.vue`，纯本地渲染，没有额外 HTTP。 | 不伪造查看接口；使用列表返回的组件数据展示。 |

### prepare → submit → cancel

1. `prepare` 只接受当前状态 `0` 或 `1`，按 `0 → 1`、`1 → 0` 计算目标状态并形成待确认草稿，不发请求。
2. `submit` 发送 `{ id, status }`；成功后重新查询组件列表，核对同一 ID 的状态和页面显示。
3. `cancel` 仅放弃草稿，不调用 PUT。没有服务端撤销动作；如果提交后的状态不符合预期，必须重新按当前状态发起一次明确的反向操作。

启用/停用会改变下游协议模板可见的组件集合，不能只凭 HTTP 成功判断影响已经正确生效。当前没有真实浏览器启用/禁用写冒烟，也没有提交后的真实列表复核或权限拒绝证据。

## 未核实的推断

状态写入口必须通过 `invoke` 传非空 `requestId`；同一次超时重试原样复用，新的业务意图使用新值。`requestId` 只用于 SDK 本地防重，不进入 Portal body。
