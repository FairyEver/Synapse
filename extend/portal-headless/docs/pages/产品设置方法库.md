# 产品设置方法库

页面路径：`/dashboard/product/setting/hatch-manage/method-lib/list`。

菜单归属是 `系统设置 → 生产设置 → 养殖预案 → 方法库`。这里的“生产设置”是 Portal 保留的“系统设置”子菜单，不是范围外的独立生产业务菜单。当前路径使用 `programNew` 方法库接口；源码中另有 `hatchery-manage` 分支，那是另一个页面场景，不并入本页。

## 页面能力定义

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询舍内温度选项 | `product-setting-hatch-manage-method-lib-temperature-options` / `productSettingHatchManageMethodLib.temperatureOptions` | `GET /programNew/baseSetting/temp/getTempInList` |
| 查询方法库 | `product-setting-hatch-manage-method-lib-list` / `productSettingHatchManageMethodLib.list` | `GET /programNew/methodLib/getPage` |
| 准备新建 | `product-setting-hatch-manage-method-lib-prepare-create` / `productSettingHatchManageMethodLib.prepareCreate` | 本地表单和文件校验，不发请求 |
| 新建/导入首次提交 | `product-setting-hatch-manage-method-lib-create` / `productSettingHatchManageMethodLib.create` | `POST /programNew/methodLib/importMethodLib`（无flag） |
| 重复预案二次提交 | 同上 | `POST /programNew/methodLib/importMethodLib`（带flag） |
| 准备编辑 | `product-setting-hatch-manage-method-lib-prepare-update` / `productSettingHatchManageMethodLib.prepareUpdate` | 本地表单校验，不发请求 |
| 编辑 | `product-setting-hatch-manage-method-lib-update` / `productSettingHatchManageMethodLib.update` | `POST /programNew/methodLib/edit` |
| 准备删除 | `product-setting-hatch-manage-method-lib-prepare-remove` / `productSettingHatchManageMethodLib.prepareRemove` | 本地确认前准备，不发请求 |
| 删除 | `product-setting-hatch-manage-method-lib-remove` / `productSettingHatchManageMethodLib.remove` | `GET /programNew/methodLib/delete` |
| 下载模板 | `product-setting-hatch-manage-method-lib-download-template` / `productSettingHatchManageMethodLib.downloadTemplate` | `GET /programManage/exportFile?fileName=方法库模板` |

请求使用 `product` HTTP 实例，补 `devicetype=PC`，不发送 `module-type`。菜单权限为 `/dashboard/frame/breeding-plan/method-lib`；新建、编辑和查看方法按钮要求 `program:method-lib:submit`，删除按钮要求 `program:method-lib:delete`。页面声明了 `program:method-lib:query`，但列表源码没有用它包住查询按钮，SDK不绕过服务端权限。

## 参数契约与提交规则

列表表单只有 `variety`（品种）、`gen`（代次）、`tempId`（舍内温度），默认都是空字符串；页面还固定保留 `scope=1`。Portal公共列表模块加入 `order=""`、`orderField=""`、`pageNo`和`pageSize`，styleV2默认每页20条，页面支持10、20、50、100。舍内温度下拉由 `getTempInList`返回的每条记录映射为 `label=inTitle、value=id`。

新建弹窗的品种、代次和舍内温度必填；文件上传控件只接受 `.xls` 或 `.xlsx`，但方法库页面没有文件必填规则，允许只提交基础信息。Portal构造FormData时严格按顺序发送：

```text
variety
gen
tempId
suiteCode
file（选择文件时）
flag（重复预案二次提交时）
```

新建页面没有可见的 `suiteCode`输入项，但源码仍发送 `suiteCode || ''`；没有发送 `id`、`line`、`moulting`、`isBs`或`year`。SDK用 `{ fileName, base64, contentType? }`描述无头文件，文件可为 `null`。第一次提交不发送 `flag`。

如果第一次导入带文件并返回页面识别的重复标记1，Portal打开“替换 / 增加 / 覆盖”弹窗：`1`替换、`2`增加、`3`覆盖。SDK返回 `{ status: 'conflict', flag: 1 }`，不会自动替用户选择；用户确认后把同一份 `draft`和明确的 `flag`再次交给 `create`，第二次FormData才带 `flag`。没有选择文件时，Java接口对已存在预案直接返回“未选择导入文件，不做更新”，不会虚构冲突。

编辑请求体固定包含 `id`、`variety`、`gen`、`tempId`、`suiteCode`和 `file:null`。当前Java `ProgramNewStandardLibDTO`不声明 `id`，列表结果通常没有可用id；Java编辑实际按品种、代次、温度和 `suiteCode` 处理。Portal编辑页没有处理Java返回的覆盖标记，SDK保持这一页面行为，编辑后必须回查列表。

删除请求是GET并只发送 `{ suiteCode }`，不能改成DELETE。模板下载在浏览器中由 `newPage`直接打开并把token放进URL；SDK通过product实例的会话请求发送同一 `fileName`并返回二进制文件描述，不把token暴露到返回值。

## 逐字段基准

| 字段 | 含义 |
| --- | --- |
| `temperatureOptions[].id` | 舍内温度选项ID；筛选和表单提交值。 |
| `temperatureOptions[].inTitle` | 后端温度展示文本。 |
| `temperatureOptions[].label` | Portal下拉映射字段，等于 `inTitle`。 |
| `temperatureOptions[].value` | Portal下拉映射字段，等于 `id`。 |
| `list` | 当前页方法库记录数组。 |
| `total` | 当前品种、代次、温度和 `scope=1` 条件下的总数。 |
| `list[].id` | 页面尝试使用的记录ID；当前Java列表DTO不返回，通常为null。 |
| `list[].variety` / `varietyName` | 品种编码 / 展示名称。 |
| `list[].gen` / `genName` | 代次编码 / 展示名称。 |
| `list[].tempId` / `tempName` | 舍内温度ID / 展示名称。 |
| `list[].suiteCode` | 方法库预案业务编码；编辑和删除目标。 |
| `list[].ageStage` / `ageStageName` | Java DTO保留的龄段字段；当前方法库SQL不选择。 |
| `list[].flag` | Java DTO保留的编辑覆盖标记；当前列表SQL通常不返回。 |
| `create`结果 `status` | `submitted`表示本次请求完成；`conflict`表示需要用户选择flag。 |
| 下载结果 `base64` | 模板二进制标准Base64，需由调用方保存。 |

## 操作步骤、权限和证据边界

1. 调用 `temperatureOptions()`获取温度候选，再调用 `list()`读取当前方法库；编辑和删除只使用最新列表行的 `suiteCode`。
2. 新建时用用户表单和可选文件调用 `prepareCreate()`；用户确认后首次调用 `create({ draft })`。如果返回 `conflict`，向用户展示三种方式，明确选择后调用 `create({ draft, flag })`。
3. 编辑时调用 `prepareUpdate()`，用户确认后把同一份 `draft`交给 `update()`；写入成功或超时后按 `suiteCode`调用 `list()`回查。
4. 删除前调用 `prepareRemove()`并取得确认；确认后调用 `remove()`，取消不发GET；成功或超时后调用 `list()`确认 `suiteCode`已消失。
5. 下载模板调用 `downloadTemplate()`并把返回的Base64保存为 `fileName`。
