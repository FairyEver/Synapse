# 流程模型 双赢协议（`/dashboard/flow/old/model/list`）

审批管理域「流程治理」四页里的第一页。四件套的其它三件分别在：
能力定义与参数契约 → `src/capabilities/flow-manage.ts`；逐字段基准 → `baseline/flow-management.browser.json`；
回归测试 → `test/flow-management.test.ts`。

这一页是这四页里**唯一的声明式列表页**（`getDataListURL`，没有 `customLoad`），
也是**唯一一个分页参数名不是 `pageSize` 的**。

## 逐字段基准

基准文件：`baseline/flow-management.browser.json` 第 7 条（打开页面时自动查询）。

```text
GET https://biz-api-test.wodecorp.cn/admin-api/bpm/hr/model/page
    ?order=&orderField=&key=&name=&category=&pageNo=1&limit=20&_t=<ts>
```

请求头（**没有 `module-type`**）：`tenant-id` / `token` / `Accept-Language: zh-CN` /
`Accept: application/json, text/plain, */*`。

### ⚠️ 这一页最要紧的一点：每页条数叫 **`limit`**，不叫 `pageSize`

页面显式写了 `fieldNamePageSize: 'limit'`（`list.vue:90`），覆盖掉全局默认的 `pageSize`
（`app/portal/main.js:48` 把默认设成 `pageSize`）。所以 URL 上是 `limit=20`。

- **SDK 照实叫 `limit`**，与 `study-teacher.ts` 对 `.lay` 接口的处理同一个口径
  （那边是 `page` / `limit`，参数名也照实叫）。
- 代价是这一个参数的名字在 SDK 里**与别处不一致**，所以参数说明里逐字写了
  「**是 `limit`，不是 `pageSize`**」。调用方给 `pageSize` **不会进 URL**（只会被忽略）——
  测试里有一条专门钉这件事。

### 其它两个性质

**1. 空值照发。** 这一页没有 `convertFetchForm`，`form` 的三个字段恒为空串，原样进 qs：
无筛选时 URL 上照样有 `key=` `name=` `category=`。这与同文件的 AI审核配置页**正相反**
（那一页把空值整个丢掉，连 `order=` 都没有）。

**2. `order` / `orderField` 是列表模块自己加的**（`list.js:474-475`），页面没有这两个控件，
所以钉死成空串、不开放。

## 参数契约

| 参数 | kind | 必填 | 说明 |
| --- | --- | --- | --- |
| `key` | text | 否 | 流程标识（流程定义 key），模糊匹配 |
| `name` | text | 否 | 流程名称，模糊匹配 |
| `category` | enum | 否 | 流程分类，字典 `bpm_model_category`（如 `human_process`）。【推断】取值未实测；候选用 **`base-dict-get`**（`dictType=bpm_model_category`）—— 不是 `base-dict-search`（那个要的是 dictType 的**名字关键字**） |
| `pageNo` | number | 否 | 页码，默认 1 |
| `limit` | number | 否 | 每页条数，默认 20。**⚠️ 参数名是 `limit` 不是 `pageSize`** |

请求参数的**顺序是契约的一部分**（D20 逐字段一致）：

```text
order, orderField, key, name, category, pageNo, limit, _t
```

实现按固定表拼参数，调用方实参的书写顺序不影响结果。

## 页面列与返回结构

列表列：流程标识 / 流程名称 / 流程分类（字典 `bpm_model_category`）/ 流程版本 /
激活状态 / 部署时间 / 创建时间 / 操作。

**版本、激活状态、部署时间三项都挂在 `processDefinition` 下面**，不在这层：
`get(record, 'processDefinition.version' | '.suspensionState' | '.deploymentTime')`。
页面用 `showDefinitionItem()` 判 `!== undefined` —— 为 `undefined` 时渲染「未部署」。
SDK 的 `FlowModelRow` 原样保留这个嵌套结构（不摊平）。

激活状态那一列是个 `a-switch`，`checked-value={1}` / `un-checked-value={2}` ——
也就是 **1 = 激活、2 = 挂起**。

## 分配规则新增：Portal/Java 逐项核对（2026-09-25）

### 可达性与权限

- 菜单来自 `app/portal/menus/hr.js:258`，路径和权限码都是 `/dashboard/flow/old/model/list`，不是注释菜单。
- `list.vue` 的分配规则入口跳到 `./rule/main?modelId=...`；规则列表对未配置的用户任务行仍渲染操作，`actionEdit()` 在无 `id` 时进入 `[mode]/[id].vue` 的新增分支，因此 `create` 不是死代码。
- 本页新增能力沿用 `FLOW_MANAGE_MODEL_PERMISSION`，即 `/dashboard/flow/old/model/list`。

### 表单字段、DTO 与请求

规则表单的可用字段是 `modelId`、`taskDefinitionKey`、`type`、`options`；`id` 为空时走新增，`processDefinitionId` 只是 Portal 表单可能带回的可选字段。Portal 的 `customSubmit()` 实际发送：

```json
{
  "id": null,
  "modelId": "<modelId>",
  "options": ["<userId>"],
  "taskDefinitionKey": "<taskDefinitionKey>",
  "type": 30
}
```

对应 Java `BpmTaskAssignRuleCreateReqVO` / `BpmTaskAssignRuleBaseVO` 的必填字段为 `modelId`、`taskDefinitionKey`、`type`、`options`；服务端不接收 `processDefinitionId`，并在服务层把 `processDefinitionId` 设为空字符串。SDK 因此省略未提供的 `processDefinitionId`，不把它误当成模型 ID；Portal 明确传 `null` 或空字符串时按原值保留该键，Java 不使用它。

- 方法/路径：`POST /bpm/hr/task-assign-rule/create`
- 成功返回：Java `CommonResult<Long>`；SDK 返回其中的规则 ID
- 取消：仅丢弃本地草稿。Java 当前没有规则删除接口，不能把“取消”伪装成已提交规则的回滚

### 操作链与反证

`prepareTaskAssignRuleCreate → createTaskAssignRule → cancelTaskAssignRuleCreate` 已接入 `flow-manage.ts`、能力定义和 `FLOW_MANAGE_METHODS`。测试锁定了 POST 的 URL/method/body、页面权限、Java 返回 ID，以及以下反证：已有 `id`、非法 `type`、空 `options`、缺少 `modelId` 或 `taskDefinitionKey` 时不发 POST。

### 证据范围

Portal 当前检出分支为 `test/portal/main`（静态源码核对），Java 当前检出分支为 `test/test`（静态源码核对）；本次按“禁止写 Git”要求未执行 pull。没有启动浏览器或真实写入冒烟，因此没有声明真实环境 POST 已成功。`src/catalog/**` 属于并行代理且不在本次允许文件集，目录 AI 契约接线未在本动作节点修改。

## SDK AI 说明契约（2026-09-22）

本节由当前 SDK 描述结果整理；说明权威来源为 `src/catalog/contracts-business.ts`。调用 `catalog.describe(id)`（或 `id-llm`）可得到参数来源、返回字段/状态、数据消费与后续映射；`catalog.describePage(页面路径)` 用于选择页面功能。以下更新以本节为准；前文历史请求/实测记录仍保留其记录日期。

### `flow-manage-model-list`

管理员查询流程模型及部署状态；模型定义与运行中的流程实例不同。

- 执行：`sdk.flowManage.listModels`；通过 `capabilities.invoke('flow-manage-model-list', args)` 调用时按 `params` 填参。性质：read。
- 参数：`key` 可选 (string)；`name` 可选 (string)；`category` 可选 (string | number)；`pageNo` 可选 (number)；`limit` 可选 (number)。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`{ list: object[], total: number }`。list=[] 为当前页无记录；total=0 表示该筛选无结果。保留筛选条件检查页码，不将空结果解释成权限判定。
- 字段：`list`、`total`、`list[].id`、`list[].key`、`list[].name`、`list[].category`、`list[].createTime`、`list[].processDefinition`、`list[].processDefinition.version`、`list[].processDefinition.suspensionState`、`list[].processDefinition.deploymentTime`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：processDefinition 嵌套字段缺失表示未部署，不把顶层 key/id 当版本号；本 SDK 不部署、挂起或删除模型。
- 完成条件：按用户要求交付本次筛选范围的结果；需要完整清单时继续翻页至覆盖 total，不能把当前页当全集。
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。
