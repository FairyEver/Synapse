# 支付计划时间管理

## 页面与能力定义

- 菜单路径：`/dashboard/finance/setting/date-config/list`
- 页面权限：`/dashboard/finance/setting/date-config`
- 页面类型：列表页（声明式 `getDataListURL`），写能力：是
- HTTP 实例：`platform`
- `moduleType`：`null`；页面请求不发送 `module-type`
- 页面按钮权限：
  - 新增：`finance:setting:date-config:create`
  - 启停：`finance:setting:date-config:status`
- 实际交付能力：
  - `finance-setting-date-config-list` → `list`
  - `finance-setting-date-config-prepare-create` → `prepareCreate`
  - `finance-setting-date-config-create` → `create`
  - `finance-setting-date-config-set-status` → `setStatus`

页面源码只渲染新增和启用/停用动作；没有编辑按钮、删除按钮，也没有使用 `get`、`update`、`delete` 接口。因此 SDK 不发布这些后端存在但页面不可达的动作。

## 请求与参数契约

### 列表

`GET /admin-api/finance/payment-plan-time-management/page`

默认请求参数按 Portal `useListPageModule({ styleV2: true, getDataListIsPage: true })` 复刻：

```text
order=""
orderField=""
tenantName=""
yearMonth=<Asia/Shanghai 当前月份，YYYY-MM>
status=1
pageNo=1
pageSize=20
```

调用方可传：

- `tenantName?: string | null`：所属租户名称包含筛选；省略或 `null` 发送空字符串。
- `yearMonth?: string | null`：`YYYY-MM`；省略使用当前月份，空字符串或 `null` 表示不按年月筛选。
- `status?: 0 | 1`：绝对状态，`0` 停用、`1` 启用；默认 `1`。
- `pageNo?: number`：正整数，默认 `1`。
- `pageSize?: number`：只允许 `10/20/50/100`，默认 `20`。

### 新增准备与提交

表单初始状态包含 `status: 1`、`yearMonth: ''`、`timeDimension: '2'`、`weekList: [[]]`。SDK 的调用输入不要求调用方传 `status`，始终固定为 `1`。

输入：

- `yearMonth`：`YYYY-MM`，不能早于当前月份。
- `timeDimension`：Portal 字典字符串：`'1'` 日、`'2'` 周、`'3'` 月。
- `weekList`：仅周维度必填；每项为 `[startDate, endDate]`，日期格式 `YYYY-MM-DD`，必须在 `yearMonth` 所属月份内，起止不能倒序，周次不能重叠；Portal 没有额外的周次数量上限。

`prepareCreate` 只做本地校验，不发请求，返回用户层草稿：

```json
{
  "draft": {
    "yearMonth": "2026-10",
    "timeDimension": "2",
    "weekList": [["2026-10-01", "2026-10-07"]]
  }
}
```

`POST /admin-api/finance/payment-plan-time-management/create` 的实际 body：

```json
{
  "status": 1,
  "yearMonth": "2026-10",
  "timeDimension": "2",
  "weekList": [
    {
      "weekName": "第1周",
      "weekNumber": 1,
      "startDate": "2026-10-01",
      "endDate": "2026-10-07"
    }
  ]
}
```

日、月维度强制发送 `weekList: []`。周次名称和编号由 SDK 按 Portal 数组顺序生成，不从调用方接收内部 `weekNumber`。

### 启用/停用

`POST /admin-api/finance/payment-plan-time-management/update-status`

Portal 使用 `FormData`，字段顺序和内容为：

```text
id=<列表行id>
status=<目标绝对状态，0或1>
```

SDK 同时要求 `currentStatus`，只用于本地防止过期切换，不进入请求体；`status` 必须与 `currentStatus` 相反。后端返回必须严格为 `true`。

## 返回字段基准

### 列表返回

根结构为 `{ list, total }`：

- `list`：当前页数组，不是全量结果。
- `list[].id`：支付计划时间管理主记录 ID；启停使用此 ID。
- `list[].tenantName`：所属租户名称，页面原文显示。
- `list[].yearMonth`：所属年月，`YYYY-MM`。
- `list[].timeDimensionName`：提报时间维度名称，页面显示文本。
- `list[].weekList`：周维度的周次数组；非周维度通常为 `null`。元素包含 `weekName`、`startDate`、`endDate`。
- `list[].status`：绝对状态，`0` 停用、`1` 启用。
- `list[].updateTime`：更新时间原值；可能为 `null`，不做时区换算。
- `total`：筛选结果总数，不是当前页长度。

### 写返回

- `create`：根值为新建主记录 ID（字符串或数字）；不能把它解释为后续预算流程已启动或已生效。
- `setStatus`：根值必须为 `true`；不包含更新后的记录，必须重新 `list` 核对。

## 操作步骤、完成与失败

### 新增

1. 向用户收集年月和提报时间维度。
2. 选择周维度时收集至少一项月内日期范围，校验非空、起止顺序和互不重叠。
3. 调用 `prepareCreate`，把 `draft` 展示或留作确认；此时没有后端写入。
4. 用户确认后调用 `create`，只传 `draft.yearMonth`、`draft.timeDimension`、`draft.weekList`；`status` 由 SDK 固定为 `1`。
5. 保存返回 ID，分页读取列表并精确查找该 ID，核对年月、维度、周次和 `status=1`。

创建没有 `requestId` 幂等包装。超时或断网时结果不确定，必须先查询再决定是否重试。页面和后端没有删除接口；用户若明确要补偿，只能在后端允许时调用启停把已核实的记录设为 `0`，这不是删除或事务回滚。

### 启停

1. 从最新列表保存同一行的 `id` 和 `status`。
2. 获取用户明确的相反目标状态，调用 `setStatus`。
3. 返回 `true` 后重新列表查询，确认同一 ID 的 `status` 达到目标值。
4. 恢复操作也必须先核对当前状态，不能把“点击切换”直接重发成相反状态。

### 已核对的静态失败规则

- 前端：年月必填；年月不能早于当前月份；时间维度必填；周维度每项日期必填、不能倒序、不能跨月或重叠；至少保留一个周。
- 后端静态实现：时间维度只能为 1/2/3；周编号为 1～5；启用配置按年月唯一；已有收入预算数据时禁止变更；当前年月及过去年月的配置不可停用。
- 通用：401/403、网络错误、后端业务错误或非预期响应都必须报告失败；不能改写为空列表或成功。
