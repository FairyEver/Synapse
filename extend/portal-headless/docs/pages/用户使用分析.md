# 用户使用分析（`/dashboard/product/operation/business/user-analysis/list`）

Portal「产品运营 → 业务分析 → 用户使用分析」是只读统计页。页面按用户群体、是否使用和日期范围查询用户登录及 App/PC 使用情况，并支持导出服务端生成的 Excel 文件。

## 页面标识

| 项 | 值 |
| --- | --- |
| 菜单路径 | `/dashboard/product/operation/business/user-analysis/list` |
| 菜单权限 | `/dashboard/frame/business/analysis` |
| Portal 页面文件 | `app/portal/views/dashboard/product/operation/business/user-analysis/list.vue` |
| HTTP 实例 | `product` |
| `module-type` | `null`（不发送） |
| 页面形态 | 筛选表单 + 用户使用统计列表 + Excel导出 |
| Portal 静态锚点 | `CodeReview_Projects_Js@test/portal/main`；本轮逐页核对 |
| Java 静态锚点 | `CodeReview_Mall_Platform_Java@test/test`；本轮逐页核对 |

## 1. 能力定义

| 页面动作 | 能力 / 方法 | 请求 |
| --- | --- | --- |
| 查询列表 | `product-user-analysis-list` / `productUserAnalysis.list` | `POST /use/statistics/userLogReport2` |
| 导出 Excel | `product-user-analysis-export` / `productUserAnalysis.export` | `POST /use/statistics/userLogReport2/export` |

页面的列表与导出使用同一个 product 实例和权限码；高产、稳产用户使用分析是不同菜单和端点，不归入本页。

## 2. 参数契约与表单提交规则

页面表单默认值为：`userPermissionList=[]`、`isUsed='1'`、`startDate=当前日期前30天`、`endDate=当前日期`。日期字段在 Portal 表单规则中必填；SDK省略时复刻页面默认值。

### 筛选参数

| 参数 | 规则 | 提交值 |
| --- | --- | --- |
| `userPermissionList` | 可多选；省略、`null`或空数组表示全部 | `PS=父母代`、`CS=商品代`、`YS=青年鸡`、`BS=种鸡` |
| `isUsed` | 页面单选值 | `'1'=是`、`'0'=否`、`''=全部` |
| `startDate` / `endDate` | `YYYY-MM-DD`，结束日期不能早于开始日期 | 含首尾日期，范围最多1000天 |

列表请求体严格复刻 Portal `convertFetchForm`：

```json
{
  "userPermissionList": ["PS", "CS"],
  "isUsed": "0",
  "startDate": "YYYY-MM-DD",
  "endDate": "YYYY-MM-DD",
  "scope": 1,
  "menuName": "用户使用分析"
}
```

Portal 的“否”选项实际提交字符串 `0`。Java 当前服务内部对 `Integer 2` 才进入未使用分支，SDK忠实发送页面的 `0`，不擅自改成 `2`，也不承诺后端会按“否”过滤。

### 列表返回字段

SDK保留 Java `UserLogReport2DTO` 的完整字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `userPermission` / `companyName` / `userName` / `userPhone` | `string \| null` | 用户群体、公司、姓名、手机号展示值；手机号按敏感字段处理，不写入日志 |
| `isUsed` | `string \| null` | 后端计算后的是否使用展示值，不是请求参数原值 |
| `loginCount` / `appUseCount` / `pcUseCount` | `integer \| null` | 查询期间登录、非PC设备、PC设备使用次数 |
| `useDateList` / `useFunctionList` | `string[] \| null` | 实际使用日期、使用功能明细数组；Portal列表将其拼接展示 |
| `useDateStr` / `useFunctionStr` | `string \| null` | 后端为导出列准备的拼接字符串 |
| `useRate` / `weekUseRate` | `string \| null` | 日使用率、周使用率原字符串，不擅自转换单位 |
| `sort` | `integer \| null` | Java排序辅助字段，Portal当前列表不展示 |

`null`表示后端未返回该字段或没有对应统计值；`[]`表示没有列表记录，是合法业务结果。后端权限、网络、业务错误和非数组响应不会被伪装成空数组。

### 导出

导出请求体使用同一组筛选字段，并增加固定 `columnHeader`：

```text
userPermission,用户群体;companyName,公司;userPhone,手机号;userName,用户名;isUsed,是否使用;loginCount,登录次数;appUseCount,app使用次数;pcUseCount,pc使用次数;useDateStr,使用日期;useFunctionStr,使用功能;useRate,日使用率;weekUseRate,周使用率
```

`useDateList`和`useFunctionList`在 Portal 导出钩子中分别替换为 `useDateStr`和`useFunctionStr`。Java 导出控制器会把菜单名覆盖为“用户使用情况报表”，生成服务器文件并返回 `fileName`。SDK将标准字符串响应或 product 标准封装中的 `{ fileName }` 归一为非空文件名字符串；不伪造二进制内容，也不把文件名当成业务写入回执。

## 4. 操作步骤与未覆盖项

1. 根据用户确认的群体、使用状态和日期调用 `productUserAnalysis.list()`；不传筛选时使用页面默认值。
2. 用返回记录填充列表；数组字段按 `useDateList`、`useFunctionList`消费，导出辅助字段只按其明确含义消费。
3. 用户明确需要 Excel 时，用相同筛选调用 `productUserAnalysis.export()`，取得非空服务端文件名，再由调用方按下载策略处理；仅取得文件名不等于下载已经完成。
4. 本页全部是只读能力，不存在 `prepare → submit → cancel` 写链；取消筛选或取消导出只是不调用对应接口。

四件套状态：能力实现已接入 SDK、`catalog.describe`、`-llm` 和 `capabilities.invoke`；页面静态逐文件核对、列表/导出请求基准、AI说明契约和离线反证测试已完成。真实测试环境读请求与导出下载仍未执行。
