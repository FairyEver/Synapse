## 列表参数、权限与返回字段

Portal 列表表单初值为 `name: ''`、`idCard: ''`、`organizationId: ''`、`useYearMonth: null`、`status: null`。组织控件来自角色组织树，只允许末级组织；月份控件格式化为 `YYYY-MM`。状态为 `0`未使用、`1`已使用。

列表请求顺序和参数为：

```json
{
  "order": "",
  "orderField": "",
  "name": "张",
  "idCard": "masked",
  "organizationId": 9,
  "useYearMonth": "2026-09",
  "status": 0,
  "pageNo": 1,
  "pageSize": 20
}
```

Java 列表 Service 先调用 `getOrgIdListByModuleType()`，写入 `roleOrganizationIdList`，再由 Mapper 与 `organizationId` 共同筛选。因此空组织筛选不是权限绕过，`list=[]` 也不能直接解释为没有权限。

列表/详情 `list[]` 字段为：`id`、`useYearMonth`、`name`、`idCard`、`organizationId`、`organizationName`、`entryDate`、`bankAccount`、`openingBank`、`attendanceDays`、`dailyValue`、`attendanceSalary`、`otherSalary`、`grossSalary`、`individualIncomeTax`、`netSalary`、`status`。后端详情还可能带 `createTime`，SDK 保留原值。金额字段保持服务端 `BigDecimal` 原值；`idCard`、`bankAccount` 是敏感字段，不写日志。页面底部合计只对当前页数值求和，不是全量合计。

## 新建与编辑表单规则

Portal 提交时把月份转为 `YYYY-MM`、入场日期转为 `YYYY-MM-DD`，并计算组织名称快照。SDK 的请求体只发送 Java Save VO 接受的业务字段；页面状态中的 `remark` 等未被 Java VO 接受的多余字段不作为能力参数发布。

必填字段及规则：

| 字段 | 规则 |
| --- | --- |
| `useYearMonth` | 必填，`YYYY-MM` |
| `name` | 必填，最多10个字 |
| `idCard` | 必填，只能数字和字母，最多18位 |
| `organizationId` | 必填，角色组织树中的末级组织ID；`organizationName`同时作为页面快照提交 |
| `bankAccount` | 必填，只能数字和字母，最多30位 |
| `openingBank` | 必填，最多20个字 |
| `attendanceSalary`、`otherSalary`、`grossSalary`、`individualIncomeTax`、`netSalary` | 必填，非负数字，最多2位小数；页面最多10位数字 |

可选字段：`entryDate`（`YYYY-MM-DD`）、`attendanceDays`（最多4位数字、最多2位小数）、`dailyValue`（最多10位数字、最多2位小数）。空的可选数值按 `null` 发送。创建时后端无条件把 `status` 设为 `0`；编辑时页面只对 `status=0`显示编辑按钮，SDK 也要求更新载荷的最新 `status` 为 `0`。

新建请求示例：

```json
{
  "useYearMonth": "2026-09",
  "name": "张三",
  "idCard": "masked",
  "organizationId": 9,
  "organizationName": "总部/财务",
  "entryDate": "2026-08-01",
  "bankAccount": "MASKED123",
  "openingBank": "示例银行",
  "attendanceDays": "20.00",
  "dailyValue": 100,
  "attendanceSalary": 2000,
  "otherSalary": "0.00",
  "grossSalary": "2000.00",
  "individualIncomeTax": 20,
  "netSalary": "1980.00"
}
```

新建成功返回单条记录 ID；编辑/删除成功必须是 `true`。成功或超时都要用 `.get` / `.list` 回查，不能只以成功回执证明数据已经落库。

## 删除、模板和导入

页面配置的 `deleteURL` 不带 ID，但共用 `useListPageModule` 对单条删除实际拼接 `${deleteURL}/${id}`，因此 SDK 请求为 `DELETE /hr/temporary-worker-salary/delete/{id}`。删除前必须用当前列表最新 `status` 做 prepare；`status=1` 已使用时页面隐藏按钮，Service 也拒绝删除。

模板下载固定使用 `fileName=临时工工资模板`，SDK 返回文件名、Content-Type、Base64 和字节数，并拒绝空文件。导入只接受 `.xml`、`.xlsx`、`.xls`，以 multipart 字段 `file` 上传；后端逐行校验年月、姓名、身份证、组织全路径、银行和金额，未知组织或非末级组织会使整批失败。导入成功后重新列表回查，文件请求超时或结果未核实前不能盲目重试。

## 创建汇总

“创建汇总表”复用 Portal 的汇总弹窗：选择末级组织、月份和 `status=0` 的未使用人员，提交：

```json
{
  "organizationId": 9,
  "organizationName": "财务部",
  "useYearMonth": "2026-09",
  "staffIdList": [101, 102]
}
```

Java 接口返回 `List<Long>`，因为服务端可能按年月/组织分组创建多个汇总表；SDK 返回 ID 数组。服务端会建立汇总与明细关系并把选中的明细状态更新为 `1`。成功后应逐个用 `reportTemporarySalarySummary.detail` 回查；没有安全的本页撤销接口，不能重复提交同一批明细。

## 权限差异、失败处理与验证边界

列表查询的模块组织权限已由 Java `getOrgIdListByModuleType` + `roleOrganizationIdList` 证实。相对地，Java 创建、更新、删除和导入源码只校验组织存在/是否末级，或按 Excel 部门全路径查租户组织，没有独立复用同一模块组织范围。SDK 不复制长组织候选，也不宣称本地校验能替代后端权限；调用方必须使用当前角色组织树和当前列表中已核实的 ID，并把实际 401/403 当作权限证据处理。

非法 ID、月份、日期、必填文本、金额、状态、页码、页大小或文件会在请求前失败；后端业务错误、401/403、网络错误原样抛出。离线测试已逐项覆盖菜单/权限/module-type、列表/详情、表单必填与数值规则、prepare→submit→取消不发请求、状态删除门禁、模板、multipart 导入、创建汇总多 ID、Java Controller/VO/Service/Mapper 和 AI 契约。真实测试环境的写入及独立回查尚未执行，不能宣称线上已验证。
