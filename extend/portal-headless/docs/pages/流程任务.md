# 流程任务（`/dashboard/flow/task/manager/list`）

审批管理域「流程治理」四页里的第四页，也是这四页里**唯一一个没有任何写操作**的
（行上只有一个「历史」，跳走看流程详情）。四件套的其它三件分别在：
能力定义与参数契约 → `src/capabilities/flow-manage.ts`；逐字段基准 → `baseline/flow-management.browser.json`；
回归测试 → `test/flow-management.test.ts`。

⚠️ **这一页与「待办任务 / 已办任务」不是同一个东西**，虽然名字都像"任务列表"：

| | `/dashboard/flow/task/{todo,done}/list` | **本页** |
| --- | --- | --- |
| 接口 | `/bpm/hr/task/list-by-category-web` | **`/bpm/task/manager-page`** |
| 看的是谁 | **我**的待办 / 已办 | **全公司**的任务流水（每一个实例的每一步） |
| 行结构 | 流程信息挂在 `processInstance` 下 | 流程信息挂在 `processInstance` 下，**审批人挂在 `assigneeUser` 下** |

两条接口都在 `bpm` 下、都叫"任务列表"，**别拿一个的结果去对另一个的字段**。

## 逐字段基准

基准文件：`baseline/flow-management.browser.json` 第 22 条（打开页面时自动查询）。

```text
GET https://biz-api-test.wodecorp.cn/admin-api/bpm/task/manager-page
    ?order=&orderField=&name=&pageNo=1&pageSize=20&_t=<ts>
```

请求头（**没有 `module-type`**）：`tenant-id` / `token` / `Accept-Language: zh-CN` /
`Accept: application/json, text/plain, */*`。

**参数顺序是契约的一部分**（`list.js:473-483`）：

```text
order, orderField, name, createTime[0], createTime[1], pageNo, pageSize, _t
```

这一页是「流程治理」四页里**参数最少的一页**（只有 `name` + 时间区间）：
页面 `form` 只有 `{ name: '', createTime: [] }`。

### 两个性质（与流程实例页同源，但要分别记）

**1. 空串照发。** 没有 `convertFetchForm`，`name` 恒为空串、原样进 qs ⇒ `name=`。
`order` / `orderField` 由列表模块自己加（`list.js:474-475`）⇒ 也照发空串。

**2. 时间区间与流程实例页**完全相同**的语义：按天归边的闭区间。**
`customLoad` 里是同一份 `formatCreateTimeRange()`（两个文件各有一份**逐字相同**的实现）：

```js
index === 0 ? dayjs(item).startOf('day').format('YYYY-MM-DD HH:mm:ss')
            : dayjs(item).endOf('day').format('YYYY-MM-DD HH:mm:ss')
```

⇒ 起点 `<开始日> 00:00:00`、终点 `<结束日> 23:59:59`。helper 复用同一个
`buildFlowManageDayRange()`。

⚠️ **基准里没有带时间区间的请求**（打开页面时区间是空的），所以这条是**从源码读出来的，
基准没有复核到**。

## 参数契约

| 参数 | kind | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | text | 否 | 任务名称，模糊匹配。空串照发 |
| `createTimeStart` / `createTimeEnd` | date | 否 | 必须**成对**给；用 `buildFlowManageDayRange()` 生成（按天归边：起点当日 00:00:00、终点当日 23:59:59） |
| `pageNo` / `pageSize` | number | 否 | 默认 1 / 20 |

两条本地校验（都是 `Promise.reject`、**不发请求**）：区间成对；两端格式必须是
`YYYY-MM-DD HH:mm:ss`。

## 页面列与返回结构

列表列：流程 / 发起人 / 发起时间 / 当前任务 / 任务开始时间 / 任务结束时间 / 审批人 /
审批状态 / 审批建议 / 耗时 / 流程编号 / 任务编号 / 操作（历史）。

- **流程名、发起人、流程编号都从 `processInstance` 取**：
  `['processInstance','name']`、`['processInstance','startUser','nickname']`、
  `['processInstance','id']`。
- **审批人从 `assigneeUser` 取**：`['assigneeUser','nickname']`。
- ⚠️ 页面上有两列都绑了 `createTime`（「发起时间」与「任务开始时间」是**同一个字段**）——
  「任务开始时间」那一列的 `dataIndex` 就是 `createTime`，只是 `key` 改成 `taskStartTime`。
  这是页面自己的呈现，不影响能力（返回的就是那一个 `createTime`）。
- 审批状态用字典 `bpm_task_status`；审批建议是 `reason`；耗时是 `durationInMillis`（毫秒）。

## 操作步骤

```text
1. 进入「流程任务」（/dashboard/flow/task/manager/list）
2. （可选）填任务名称
3. （可选）选创建时间区间
4. 查询
5. 行上「历史」→ 跳流程表单详情页（goFlowFormDetailByInstanceId，用的是
   record.processInstance.id），不是本能力的接口
```

## 真实验证

- **基准来自真实环境**：2026-09-21 由 `bsk` 抓于 `https://webtest01.wodecorp.cn/portal.html#/`
  （`baseline/flow-management.browser.json` 第 22 条）。
- **契约与基准逐字段一致**：`test/flow-management.test.ts` 比有序的 `[key, value]`，
  并把整条 URL 断言成那六个键；另有「区间与流程实例页同一套：按天归边」「单边 reject」各一条；
  权限码的拼写也有一条用例单独钉住。
- **没做**：SDK 对真实后端的**冒烟**（本波不跑浏览器、也没有这一页的 smoke 脚本）；
  区间语义也**没有**在真实环境验证过（基准里没有带区间的请求）。

## 尚未覆盖

- **写操作：没有。** 这一页行上只有「历史」，跳到流程表单详情页看**只读**内容。
  （`page-catalog` 把这一页标成 `write: false`，是对的。）
- **「历史」的落点**（`goFlowFormDetailByInstanceId` → `/dashboard/flow/form/detail?...`）
  只从 `flow/index.js` 读出，没有实际走一遍。
- **`status` 的取值表**没有枚举（字典 `bpm_task_status` 是页面控件，未实测）。
- **「发起时间」与「任务开始时间」是同一字段**这件事只从源码读出，
  **没有拿真实响应对照过**（基准只抓了请求，没抓响应）——
  如果后端其实返回了另一个字段，页面这一列会显空，本轮看不到。
- **列表行的字段只在源码里核对过**，**没有拿真实响应体逐字段核过**。

## SDK AI 说明契约（2026-09-22）

本节由当前 SDK 描述结果整理；说明权威来源为 `src/catalog/contracts-business.ts`。调用 `catalog.describe(id)`（或 `id-llm`）可得到参数来源、返回字段/状态、数据消费与后续映射；`catalog.describePage(页面路径)` 用于选择页面功能。以下更新以本节为准；前文历史请求/实测记录仍保留其记录日期。

### `flow-manage-task-list`

管理员视角查询全公司任务流水，一个流程可能有多行任务；不同于我的待办/已办。

- 执行：`sdk.flowManage.listFlowTasks`；通过 `capabilities.invoke('flow-manage-task-list', args)` 调用时按 `params` 填参。性质：read。
- 参数：`name` 可选 (string)；`createTimeStart` 可选 (string)；`createTimeEnd` 可选 (string)；`pageNo` 可选 (number)；`pageSize` 可选 (number)。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`{ list: object[], total: number }`。list=[] 为当前页无记录；total=0 表示该筛选无结果。保留筛选条件检查页码，不将空结果解释成权限判定。
- 字段：`list`、`total`、`list[].id`、`list[].name`、`list[].createTime`、`list[].endTime`、`list[].status`、`list[].reason`、`list[].durationInMillis`、`list[].assigneeUser`、`list[].assigneeUser.nickname`、`list[].processInstance`、`list[].processInstance.id`、`list[].processInstance.name`、`list[].processInstance.startUser.nickname`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：同一 processInstance.id 可以有多个任务，统计流程数要按实例去重；列表可见不证明当前用户有权办理该 taskId。
- 完成条件：按用户要求交付本次筛选范围的结果；需要完整清单时继续翻页至覆盖 total，不能把当前页当全集。
- 后续：optional → `base-dict-get`：dictType=bpm_task_status；解释任务状态（dictType ← context.dictType）
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。


验证：`test/ai-contract-business.test.ts` 直接检查 SDK 描述输出及业务夹具；本批未重放真实写操作。逐能力状态、证据与反证见 [补齐清单](../ai-contract-business-evidence.md)。
