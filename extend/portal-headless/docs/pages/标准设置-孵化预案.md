# 标准设置（孵化预案）

## 能力定义

- 页面：`/dashboard/product/setting/hatchery-manage/unit/list`
- 菜单/路由权限：`/dashboard/frame/hatchery-plan/unit`
- 页面组件：Portal 的 `hatchery-manage/unit/list.vue` 仅包装并复用 `hatch-manage/unit/list.vue`；因此接口、列表筛选和表单规则按复用组件核对，页面路径和权限仍独立绑定。
- HTTP 实例：`product`；页面没有可推导的 `module-type`，不发送该请求头。
- 页面按钮权限：查询 `program:unit:query`，新建/编辑 `program:unit:submit`，删除 `program:unit:delete`。

## 参数契约

能力和方法如下：

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询标准设置 | `product-hatchery-unit-list` / `productHatcheryUnit.list` | `GET /programUnit/getList` |
| 准备新建 | `product-hatchery-unit-prepare-create` / `productHatcheryUnit.prepareCreate` | 本地表单校验，不发请求 |
| 新建 | `product-hatchery-unit-create` / `productHatcheryUnit.create` | `POST /programUnit/add` |
| 准备编辑 | `product-hatchery-unit-prepare-update` / `productHatcheryUnit.prepareUpdate` | 本地表单校验，不发请求 |
| 编辑 | `product-hatchery-unit-update` / `productHatcheryUnit.update` | `POST /programUnit/update` |
| 准备删除 | `product-hatchery-unit-prepare-remove` / `productHatcheryUnit.prepareRemove` | 本地确认前准备，不发请求 |
| 删除 | `product-hatchery-unit-remove` / `productHatcheryUnit.remove` | `GET /programUnit/delete?id=...` |

列表筛选字段是 `classification`（指标归类）和 `search`（指标名称或编码前缀），请求固定带 `scope=1`。公共列表模块补充 `order=""`、`orderField=""`、`pageNo` 和 `pageSize`；SDK默认 `pageNo=1`、`pageSize=20`，页面支持10、20、50、100。指标归类候选来自Portal全局平台字典 `standard_class`，不是本页单独请求。Portal首次自动加载可能在归类为空时发送空字符串，SDK保留该请求形状。

新建和编辑表单中，归类、文本类型、名称、编码全部必填。`contentType` 只有三种值：`1` 纯文本、`2` 富文本、`3` 数值。只有 `contentType=3` 时，`unit` 和 `scale` 才进行必填校验并发送用户值；纯文本和富文本会把两者固定发送为空字符串。Portal 的 `scale` 输入控件只校验非空，SDK不额外添加整数或最小值限制；Java实体以 `Integer` 接收，服务端类型错误仍会抛出。

编辑提交对象先展开当前列表行 `raw`，再覆盖 `id`、`classification`、`contentType`、`name`、`code`、`unit`、`scale`，因此SDK保留列表行中的扩展字段。新建草稿的 `id` 是 `undefined`，JSON序列化时不会发送。

## 逐字段基准

| 字段 | 含义 |
| --- | --- |
| `list` | 当前归类、名称/编码前缀筛选和分页下的ProgramUnit标准设置记录；SDK兼容Portal可能收到的直接数组或Java分页对象。 |
| `total` | 当前筛选条件下的总数；直接数组响应时等于数组长度。 |
| `list[].id` | ProgramUnit记录ID；编辑和删除目标。 |
| `list[].classification` | 指标归类原始字典值；编辑回填字段。 |
| `list[].traitTypeName` | 指标归类展示名称；表格第一列。 |
| `list[].name` / `code` | 指标名称 / 指标编码；新建和编辑必填。 |
| `list[].unit` | 指标单位；数值类型使用。 |
| `list[].contentType` | 文本类型数值：1纯文本、2富文本、3数值；页面本地映射展示。 |
| `list[].contentTypeName` | 后端可能提供的类型展示扩展字段；页面当前不依赖它。 |
| `list[].scale` | 数值类型小数位数；非数值类型可能为空。 |
| `prepareCreate().draft` | 已通过条件表单校验、尚未发送请求的新建ProgramUnit对象。 |
| `prepareUpdate().draft` | 已按Portal raw透传和字段覆盖规则整理、尚未发送请求的编辑对象。 |
| 写操作结果 `true` | 请求未抛错的本地确认，不代表服务端已按预期落库。 |

列表分页响应可以是直接数组，也可以是 `{ page: { records/list/rows, total/count } }`；SDK统一返回 `{ list, total }`，保留列表行扩展字段。缺少有效列表、非法ID、未知文本类型或负数总数均抛错，不降级为空结果。

## 操作步骤、权限和证据边界

1. 使用当前用户会话和租户上下文调用 `list()`；需要筛选候选时先读取 `standard_class` 字典。
2. 新建时调用 `prepareCreate()`，经用户确认后把同一份 `draft` 交给 `create()`；取消只丢弃本地草稿。
3. 编辑时把最近一次列表行与用户修改结果交给 `prepareUpdate()`，经用户确认后把同一份 `draft` 交给 `update()`；取消不发请求。
4. 删除前调用 `prepareRemove()`，明确获得用户确认后再调用 `remove()`；取消不发GET，不能把删除接口改成DELETE。
5. 新建、编辑或删除成功、失败或响应不确定后，都重新调用 `list()` 回查；不能只依据 `true` 宣布业务状态已改变。回查应按 `id`、`code`、`name`、`contentType`、`unit` 和 `scale` 核对写入结果。

本轮逐页核对了Portal菜单、孵化预案路由、包装组件、复用列表、复用弹窗、公共分页、product响应解包，以及Java `ProgramUnitLayController`、`ProgramUnit`实体和`ProgramUnitMapper.xml`。当前未启动浏览器、未执行真实测试环境列表/新建/编辑/回查/删除闭环；实现证据是固定Portal/Java源码和离线请求形状、表单边界及契约测试。后端没有requestId幂等包装，写请求响应不确定时先回查，不自动重放。
