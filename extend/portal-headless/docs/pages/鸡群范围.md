# 鸡群范围

## 能力定义

- 页面：`/dashboard/product/setting/base-setting/user-dict/list`
- 菜单权限：`/dashboard/frame/base-setting/user-dict`
- HTTP 实例：`product`；页面未推导出 `module-type`，不发送该请求头
- 页面查询权限：`management:user-dict:query`
- 页面提交权限：`management:user-dict:submit`
- 能力 ID：`product-setting-user-dict-list`、`product-setting-user-dict-type-list`、`product-setting-user-dict-enable`、`product-setting-user-dict-deactivate`、`product-setting-user-dict-prepare-save`、`product-setting-user-dict-save`、`product-setting-user-dict-cancel-save`

## 参数契约

`prepareUserDictSave` 接收 Portal 弹窗实际提交的五个字段：

```ts
{
  id: string | number | '',
  type: string,
  description: string,
  label: string,
  value: string
}
```

新建时 `id` 仍发送空字符串；编辑时使用当前字典 ID。`type`、`label`、`value` 对应弹窗的必填项，`description` 是类型候选的展示名称，缺省时发送空字符串。

`submitUserDictSave({ draft })` 原样 POST 到 `/sys/dict/userDictSave`，不包装成 `{data: ...}`；`cancelUserDictSave()` 只返回 `{ cancelled: true }`，不调用后端。

## 逐字段基准

Portal `modal-form-content.vue` 的 `modalEmit('submit', ...)` 明确发出 `id/type/description/label/value`；`list.vue` 的新建和编辑两个 `modal.on('submit')` 都调用同一个 `http.post('/sys/dict/userDictSave', payload)`。即使列表中的新建按钮当前以注释包裹，两个弹窗提交处理仍是页面源码中的真实动作，不能按未绑定静态代码丢弃。

Java 当前检出已核对 `DictController`、`DictVO`、`HRDict`、`HRDictMapper.xml`、`HRDictServiceImpl`：分页、类型候选、租户字段、启用/停用限制均存在，但 `DictController` 当前没有 `userDictSave` 映射。SDK 仍按 Portal 的真实 POST 注册动作；Java 路由缺口和真实环境结果待主线/后端确认。

## 操作步骤

1. 读取 `typeList`，把返回的 `value` 用作 `type`，`label` 只用于展示。
2. 从弹窗字段构造 `prepareUserDictSave`，保留新建空 `id` 或编辑行 ID。
3. 获得用户确认后调用 `submitUserDictSave`；成功回执不等于列表已落库，应重新调用 `list` 按类型和 ID 回查。
4. 用户取消时调用 `cancelUserDictSave`，不得发送保存请求。
