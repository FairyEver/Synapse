# 角色管理

## 1. 能力定义

页面路径：`/dashboard/setting/role/list`

页面权限：`/dashboard/setting/role`

HTTP 实例：`platform`

`module-type`：不发送。

本页属于保留范围内的“系统设置”。页面管理角色本身、菜单授权和模块数据权限。系统下拉、模块下拉中可以出现生产、财务等值，但它们只是角色管理表单的字段，不代表 SDK 实现了独立生产、财务、资产、采购、销售或科技根模块页面。

SDK 登记的能力：

- `setting-role-list` / `settingRole.list`：查询角色分页。
- `setting-role-get-info` / `settingRole.getInfo`：读取编辑表单。
- `setting-role-menu-options`：按系统读取菜单树。
- `setting-role-organization-tree`、`setting-role-standard-tree`：读取数据权限树。
- `setting-role-organization-type-options`、`setting-role-legal-person-options`、`setting-role-grade-options`：读取表单候选。
- `setting-role-prepare-create` → `setting-role-create`：准备并新建角色。
- `setting-role-prepare-update` → `setting-role-update`：准备并编辑角色。
- `setting-role-prepare-delete` → `setting-role-remove`：准备并批量删除角色。

## 2. 参数与提交契约

列表请求实际为：

```text
GET /admin-api/sys/role/allProjectRoleByPage
{ order: "", orderField: "", name: "", pageNo: 1, pageSize: 20 }
```

详情请求为：

```text
GET /admin-api/sys/role/info/<roleId>
```

菜单树在选择系统后请求：

```text
GET /admin-api/sys/menu/select-role-menu-by-tenant?useSystem=<useSystem>
```

数据权限候选请求为：

```text
GET /org/organization/getRoleOrganizationTree
GET /admin-api/sys/role/getStandardTree
GET /org/organizationType/selectAll
GET /org/corporation/getAllLegalPerson
GET /study/grade/studygrade/page?pageSize=99999&pageNo=1
```

创建和编辑都必须先 `prepare`。最终保存请求分别为：

```text
POST /admin-api/sys/role/saveRoleV1
POST /admin-api/sys/role/updateRoleV1
```

提交体保留 Portal 表单字段，`dataScope` 强制为 `2`，`parentId` 不发送。`roleModuleDataScopeRelList` 会逐行按以下规则归一：

- `moduleType` 和 `dataScopeType` 必填，页面不允许重复模块；学习模块 `12` 只允许范围 `4` 或 `128`。
- 范围 `4/32/64` 的非学习模块必须有组织/标准化单元/组织类型 ID；学习模块范围 `4` 必须有班级 ID。
- 范围 `128` 会把组织、班级、法人列表全部清空。
- 资金管理模块 `23` 才保留 `legalPersonIdList`；范围 `1/128` 为空，其他模块不发送该字段。
- `organizationIdList` 同时兼容页面详情中的数组和范围 `64` 组件可能产生的逗号字符串。

批量删除：

```text
DELETE /admin-api/sys/role
body = [roleId, ...]
```

这是不可恢复操作。`prepare` 或用户取消只丢弃内存草稿；页面没有服务端撤销接口。保存、删除成功或超时后都必须重新读取列表/详情回查，不能把空返回或 HTTP 成功当作权限已经生效。

## 3. 逐字段基准

角色列表行：

| 字段 | 含义 |
| --- | --- |
| `id` | 角色ID；编辑和删除使用 |
| `name` | 角色名称 |
| `roleIdentifier` | 角色编码 |
| `remark` | 备注 |
| `useSystem` | 所属系统值；只用于本页展示 |
| `createDate` | 创建时间原值，SDK不转换时区 |
| `total` | 符合名称筛选的角色总数 |

详情及草稿字段：

| 字段 | 含义 |
| --- | --- |
| `menuIdList` | 已授权菜单ID数组，不是菜单名称 |
| `dataScope` | 旧版数据范围字段；提交固定为 `2` |
| `roleModuleDataScopeRelList[].moduleType` | 模块类型配置值，不等于 SDK 已实现该模块页面 |
| `roleModuleDataScopeRelList[].dataScopeType` | `1`所有、`4`自定义、`8`部门及以下、`32`标准化单元、`64`组织类型、`128`所在法人 |
| `organizationIdList` | 组织/标准化单元/组织类型范围ID |
| `gradeIdList` | 学习模块班级范围ID |
| `legalPersonIdList` | 资金管理模块手动法人范围ID |

Java 删除会级联清理用户角色、角色菜单、旧数据权限、模块数据权限和岗位角色关系。后端角色名重复会拒绝保存；页面没有恢复能力。

## 4. 操作步骤与验证

1. 调用 `settingRole.list`，从 `list[].id` 获取角色ID；编辑前调用 `settingRole.getInfo`，不要直接用列表行拼接表单。
2. 若需要填写菜单授权，先按 `useSystem` 调用 `settingRole.menuOptions`；数据权限范围使用对应树/候选能力，提交只使用ID。
3. 新建调用 `settingRole.prepareCreate({ form })`；编辑调用 `settingRole.prepareUpdate({ current, changes })`。两者都只在内存校验和生成完整草稿。
4. 用户取消时丢弃草稿；确认后分别调用 `settingRole.create({ draft })` 或 `settingRole.update({ draft })`，再按角色ID回查详情核对名称、菜单和模块权限。
5. 删除先调用 `settingRole.prepareDelete({ ids })`，确认后 `settingRole.remove({ draft })`；再查询列表确认目标ID消失，并把级联删除视为不可恢复。
