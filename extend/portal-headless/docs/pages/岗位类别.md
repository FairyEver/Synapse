## 参数与返回契约

- 列表默认 `{order:'',orderField:'',name:'',pageNo:1,pageSize:20}`；name 模糊匹配。后端固定按 sort 升序。页面未提供任意列排序控件。
- 名称必填、不全为空格、最长 50 字符；排序必填、非负整数；备注最长 200 字符，可空串、不允许非空的全空格字符串。SDK 不自动修剪用户名称。
- ID 为岗位类别主键，不是岗位 ID；保留长整数字符串。数组单删也使用一个元素的 `ids`，SDK 去重。
- 新建不接受调用方附加 ID；仅投影 name/sort/remark。修改另带 id。备注省略会补空串，修改前须保留未改旧值。
- 列表返回 `{list,total}`；list 仅当前页，total 为当前条件未删除总量。页面消费 id/name/sort/remark；额外审计字段不属于本页操作契约。
- 详情返回行或 null；备注可能省略或 null，页面显示横杠。
- create/update/remove 成功统一 `undefined`，不伪造 ID/删除数量。创建后通过名称分页查询、精确比对取得新 ID。
- prepareRemove 返回 `{ids:string[],verificationRequired:boolean,phone:string|null}`；不锁定状态。sendDeleteCode 返回 `{smsRequestId:string}`，不是幂等键；验证码只由用户提供，不猜测，不写日志。
- sendDeleteCode 是真实短信外部副作用，只在用户明确要求发送时调用。其余删除链路不得改变敏感配置以绕过验证。
- 没有 SDK 幂等包装；写入超时先回查。后端同名校验不能充当幂等回执；短信发送后端限制一分钟一条，超时不自动重发。

## 请求逐字段依据（源码推导，未抓本轮浏览器基准）

| 操作 | HTTP | 请求 |
|---|---|---|
| 列表 | GET /org/hrposttype/page | params order/orderField/name/pageNo/pageSize |
| 详情 | GET /org/hrposttype/{id} | 路径类别 ID |
| 新建 | POST /org/hrposttype/save | JSON name/sort/remark |
| 修改 | POST /org/hrposttype/save | JSON name/sort/remark/id |
| 删除前检 | POST /org/hrposttype/checkCanDelete | JSON ID 数组 |
| 敏感配置 | GET /org/sensitive/info | 无参数；读取 mobile/isDel |
| 发送验证码 | GET /sys/sms/send | params phone=配置 mobile、templateId='17709' |
| 验证 | GET /sys/sms/checkSms | params requestId=短信发送标识、code=用户验证码 |
| 删除 | DELETE /org/hrposttype | JSON ID 数组 |

平台客户端统一补 `/admin-api`，统一检查业务失败包络。前检或验证码失败不发送 DELETE。后端批删在事务中，一条被占用则整体失败。

## 操作流程与验证

1. list → 用户选类别 → get → 修改完整表单 → update → get 核对。
2. 新建：create → list 名称筛选并分页 → 精确核对名称/排序/备注取得 ID。
3. 删除：prepareRemove → 如需验证且用户要求发短信，sendDeleteCode → 用户提供 code → remove。remove 会重新执行占用/敏感配置检查，再按需验证和删除。无需验证时直接 remove。
4. 删除后列表复查所选 ID 不再出现。详情可能保留逻辑删除行，不能用详情存在判断删除失败。创建回滚也走同一删除保护链。
