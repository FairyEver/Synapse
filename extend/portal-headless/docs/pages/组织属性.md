## 能力定义与 AI 说明

| 能力 ID | SDK 方法（单个对象参数） | 行为 |
|---|---|---|
| `hr-organization-property-list` | `hrOrganizationProperty.list(query?)` | 名称筛选与分页，只返回页面字段 |
| `hr-organization-property-create` | `hrOrganizationProperty.create({name,code,remark?})` | 新建，成功无返回 ID |
| `hr-organization-property-deactivate` | `hrOrganizationProperty.deactivate({id,currentStatus,useNumber})` | 仅启用且未关联组织的行可作废 |
| `hr-organization-property-enable` | `hrOrganizationProperty.enable({id,currentStatus})` | 仅已作废行可重新启用 |

定义和实现：`src/capabilities/hr-organization-property.ts`。AI 契约：`src/catalog/contracts-hr-organization-property.ts`，导出 `HR_ORGANIZATION_PROPERTY_AI_CONTRACTS` 与 `HR_ORGANIZATION_PROPERTY_METHOD_CONTRACTS`。共享目录、单用户/多用户门面和 invoke 已接线；`catalog.describe(id)`、`-llm`、`describeMethod(path)` 与 `capabilities.invoke(id,args)` 均走实际公开入口。

不发布 delete/get/update 能力不是遗漏：删除与勾选代码已注释，列表无编辑/详情入口。后端接口存在或可手输 URL 不等于 PC 正常可达。

## 参数、返回与字段契约

- 列表默认发送 `{order:'',orderField:'',name:'',pageNo:1,pageSize:20}`；`name` 按后端 SQL 做包含匹配。页面没有列排序控件，后端固定按 `create_time`、`id` 升序；不承诺 order/orderField 改变排序。
- 列表返回 `{list,total}`：`list` 是当前页，`total` 是同一名称条件下未删除总数。只输出 `id/name/code/remark/status/useNumber`；审计字段不属于页面消费契约。
- `id` 是组织属性记录主键，不是组织 ID，也不是业务编码 `code`。长 ID 保留字符串。
- `remark` 为 null 或空字符串都表示未填写，页面显示横杠。`status` 只接受数值 0/1：0 已作废、1 启用。未知值不猜状态、不执行写动作。
- `useNumber` 是当前关联该属性的组织数量，不是历史使用次数；严格为数值 0 才可从启用状态作废。
- 新建名称必填、不全空格、最多 20 字符；组织编码必填、不全空格、最多 10 字符；备注最多 50 字符、可空串但非空值不得全空格。SDK 保留首尾空格，只投影 `name/remark/code`。
- create/deactivate/enable 成功均返回根 `undefined`。新建没有 ID；按名称查询并完成分页，以精确 name/code/remark 唯一匹配识别新记录。
- 作废输入的 id/currentStatus/useNumber 必须来自同一条最新列表行；启用的 id/currentStatus 同理。SDK 复现 PC 按钮条件，但不锁记录；后端 `updateStatus` 只绝对赋值，校验与写入之间仍可能有并发变化。
- 新建没有幂等键；名称/编码重复错误不是幂等回执。状态接口重复设置同一绝对值会收敛，但没有 requestId。所有写超时先列表回查，不自动重发。

## 请求逐字段基准

| 操作 | HTTP | 请求 |
|---|---|---|
| 列表 | GET `/hr/org/organizationProperty/page` | params `order/orderField/name/pageNo/pageSize` |
| 新建 | POST `/hr/org/organizationProperty/save` | JSON `name/remark/code`，顺序与 PC 表单对象一致 |
| 作废 | POST `/hr/org/organizationProperty/updateStatus` | JSON `{id,status:0}`；调用前 currentStatus=1、useNumber=0 |
| 启用 | POST `/hr/org/organizationProperty/updateStatus` | JSON `{id,status:1}`；调用前 currentStatus=0 |

四项均使用页面上下文的 platform 请求函数；客户端统一补 `/admin-api`、注入 tenant/token/language 与 `module-type=11`、拆标准包络。SDK 不公开页面已注释的 DELETE。

## 操作步骤与验证记录

1. 查询：list → 展示 name/code/remark → 按 total 完成用户要求的分页范围；status/useNumber 只用于动作条件。
2. 新建：create → list(name) → 完成分页 → 精确核对 name/code/remark 并取得新 id。取消尚未提交的新建页只是返回，不产生业务写入；已提交后当前 PC 没有删除动作，不能承诺删除式撤销。
3. 作废：最新 list 行满足 `status=1 && useNumber=0` → deactivate → 完整分页按 id 回查 `status=0`。记录仍保留，不是删除。
4. 启用：最新 list 行满足 `status=0` → enable → 完整分页按 id 回查 `status=1`。启用后是否可作废还取决于最新 useNumber。

离线测试：`test/hr-organization-property.test.ts` 覆盖列表/表单逐字段请求、页面字段投影、表单与状态保护、浏览器基准、AI 字段/状态/动作映射以及“不发布删除”边界。关键反证把列表到作废的 `useNumber` 来源改成 `result.list[].id`，对应映射断言必须变红；恢复后重跑通过。
