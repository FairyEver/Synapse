## 参数契约

列表不是分页接口。它固定发送：

```text
order=&orderField=&name=&accountingStandardsApply=&organizationId=&tenantName=
&ledgerType=1&subjectLevel=&type=&code=&status=0
```

可筛选名称、科目等级、适用会计准则、企业名称（PC 仅 `username === 'admin'` 显示）、组织、编码和状态。科目类型不是普通下拉，而是 `account_type` 字典驱动的页签；无明确值时 SDK 与页面 fallback 一致使用数值 `1`。状态只能传数值 `0`（启用）或 `1`（停用），默认只查启用；页面没有“全部”。组织树规模长，SDK 必须先取得非空关键字再搜索，最多返回 50 个当前角色树候选。

创建参数中 `name/code/type` 必填。`type`、`subjectFormat`、`useSystem[]`、`ancillaryAccountings[]`、`balanceDirection`、`accountingStandardsApply` 分别使用运行时字典 `account_type`、`subject_format`、`system_tenant_apply_use_system`、`ancillary_accounting`、`balance_direction`、`accounting_standards_apply` 的 `value`，不能使用字典条目 ID 或标签。页面创建表单的 `organizationId` 固定为 `34`，没有可编辑组织控件；SDK 忠实发送该常量。

顶级新建的 `code` 是完整编码，`pid/parentCode/parentName` 均省略。添加下级时，四项必须来自同一条最新启用树节点：`pid=id`、`parentName=name`、`parentCode=code`、`balanceDirection=balanceDirection`；用户输入的 `code` 只是后缀，SDK 按 PC 行为直接拼成完整编码。余额方向必须与上级一致。创建另需 `requestId`；它只在 SDK 当前进程的短窗口内按用户、租户和能力防重，不发给后端。

导入输入为 `fileName/base64/contentType?`；文件扩展名仅接受 PC 声明的 `.xml/.xlsx/.xls`。`base64` 是文件二进制的标准 Base64，不是 data URL。`prepareImport` 只校验扩展名、Base64 和非空大小，不解析工作簿行。真正导入另需 `requestId`。固定 Java 后端使用 `ExcelUtils.read`，XML 是否能在部署环境解析尚未验证，不能把扩展名通过说成导入可用。

## 逐字段基准

浏览器默认请求：

```text
GET /admin-api/finance/ledger-accounts/page?order=&orderField=&name=&accountingStandardsApply=&organizationId=&tenantName=&ledgerType=1&subjectLevel=&type=&code=&status=0&_t=...
```

使用 `platform` HTTP 实例，携带当前会话 token、`tenant-id` 与语言头；浏览器没有 `module-type`，SDK 同样省略。请求没有 `pageNo/pageSize`，后端强制全量查询后以 `TreeUtils.build` 返回根数组；`children` 递归同构。不能只数根节点，也不能把结果包装成虚假分页。

SDK 每个节点只公开本页展示/动作字段：

- `id`：会计科目主键，供详情、添加下级和启停；不是编码。
- `tenantName/name/subjectLevel/code`：所属企业、名称、等级和完整编码。
- `type/subjectFormat/useSystemList`：科目类型、格式和受控系统字典值。
- `parentId/pid/parentName`：上级科目；Java `TreeNode` 或真实树可能用数值 `0`、字符串 `"0"` 表示根，SDK 将它们与空值统一归一为 `null`，页面显示“顶级”。
- `ancillaryAccountings/balanceDirection/accountingStandardsApply`：辅助核算、余额方向和准则字典值。
- `status`：数值 `0` 启用、`1` 停用。
- `createTime`：录入时间原值；SDK 不猜时区。
- `children`：直接下级数组，递归使用同一字段契约。

详情返回上述核心字段的本地快照，不含状态、企业、等级、录入时间或子树；这些仍以刷新后的列表为准。

创建请求：

```text
POST /admin-api/finance/ledger-accounts/create
body = {
  organizationId: 34,
  name,
  accountingStandardsApply,
  balanceDirection,
  ancillaryAccountings,
  pid,
  parentName,
  type,
  code: parentCode + codeSuffix,
  subjectFormat,
  useSystem: useSystemValues.join(',')
}
```

后端返回根 Long ID。状态请求为 `GET /admin-api/finance/ledger-accounts/enableOrStop?id=<科目ID>&status=<0|1>`，成功业务数据为 `null`。

导出和模板下载分别是 `GET /admin-api/finance/ledger-accounts/export-excel` 与 `/down-excel`。浏览器通过 `newPageWithPlatformAuth` 打开同一 platform host；SDK 使用已绑定会话请求头读取 `arraybuffer`，验证 xlsx ZIP 签名后返回 `{fileName, contentType, base64, byteLength}`，不暴露 URL 中的 token。导入是 `POST /admin-api/finance/ledger-accounts/import-excel`，multipart 字段名固定为 `file`，后端严格返回 `true` 才算请求成功。

## 操作步骤与验证

1. 查询时按 `account_type` 值切换页签；递归消费根和 `children`。要按组织筛选，先用关键字搜索并让用户按 `pathNames` 确认组织 ID。
2. 查看详情直接传选中节点的详情字段；如需最新状态先刷新列表。
3. 创建先调用 `prepareCreate` 核对完整编码、上级、余额方向、字典项与固定组织 34，再用新的 `requestId` 调 `createIdempotent`。返回 ID 后按名称、科目类型、状态 0 刷新树，递归读回同一 ID 并核对字段。
4. 启停前保存最新 `status`，传相反的绝对目标值；随后按目标状态和所有相关类型页签回查同一 ID。用户明确要求恢复时才写回原状态，再次回查。
5. 导出/模板结果把 Base64 解码成文件，不把 Base64 全文写入日志。导入先下载模板、让用户填写、`prepareImport` 核对文件，再调用 `importIdempotent`；成功后从文件读取预期名称/编码/类型，逐项回查树。

离线测试覆盖浏览器默认 URL、无分页/无 `module-type`、全部筛选、递归树投影、详情零请求、长组织候选、顶级默认值、下级编码拼接、根 ID、绝对状态、同 host 文件下载、multipart 导入、错误透传以及 AI 映射。关键反证把添加下级映射的 `parentCode` 错指成 `id`，定向契约断言会失败；恢复后测试通过。
