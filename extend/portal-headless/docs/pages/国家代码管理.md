# 国家代码管理

## 能力定义

- 菜单归属：门户 → 系统设置 → 销售设置 → 国家代码管理
- 页面路径：`/dashboard/sale/customer/register-code/list`
- 页面权限：`/dashboard/sale/frame/customer/registerCode`
- 导入、删除按钮权限：`customer:registerCode:edit`
- 请求实例：Portal `app/portal/utils/http/crm.js`，调用 SDK 时必须配置 `httpBaseUrls.crm`；不能把默认 `baseUrl` 当作 CRM 地址。
- `module-type`：`60`
- 页面可达动作：分页查询、按三个字段筛选、导入 `.xls/.xlsx`、单条删除；Portal公共列表状态还会发送默认空的 `order`、`orderField`，页面没有排序控件。
- 页面没有新建按钮、编辑入口或详情入口，所以不暴露后端虽存在的 `POST /vue/customer/registerCode/save` 和 `GET /vue/customer/registerCode/registerCode`。

对应 SDK 能力：

| capability | 作用 | 写入 |
| --- | --- | --- |
| `sale-register-code-list` | 查询国家代码 | 否 |
| `sale-register-code-prepare-import` | 本地检查导入文件并生成预览 | 否 |
| `sale-register-code-import` | 提交导入文件 | 是 |
| `sale-register-code-prepare-remove` | 本地准备单条删除并等待确认 | 否 |
| `sale-register-code-remove` | 删除一条记录 | 是 |

## 参数契约

### 查询

`sale-register-code-list` 接受：

| 参数 | 页面默认值 | 请求字段 | 说明 |
| --- | --- | --- | --- |
| `order` | `''` | `order` | Portal公共列表排序值；页面没有排序控件 |
| `orderField` | `''` | `orderField` | Portal公共列表排序字段；页面没有排序控件 |
| `breedingCode` | `''` | `breedingCode` | 畜禽养殖代码模糊筛选 |
| `farmerName` | `''` | `farmerName` | 养殖场户名称模糊筛选 |
| `name` | `''` | `name` | 姓名模糊筛选 |
| `pageNo` | `1` | `pageNo` | 从 1 开始 |
| `pageSize` | `20` | `pageSize` | Portal 常用值为 10/20/50/100/200/500 |

Portal CRM 列表接口返回 `{ list, count }`；SDK 对外返回 `{ list, total }`，`total` 是筛选后的总记录数。CRM 请求拦截器还会自动追加 `_t` 防缓存参数，这由集中 HTTP 客户端处理。

### 返回字段

`list[]` 的页面字段如下：

| 字段 | 含义 |
| --- | --- |
| `id` | 国家代码记录 ID，删除时使用 |
| `number` | Excel 序号 |
| `provinceCode` | 省份代码 |
| `city` | 市名称 |
| `area` | 区县名称 |
| `breedingCode` | 畜禽养殖代码 |
| `farmerName` | 养殖场户名称 |
| `formerBreedingCode` | 原有畜禽养殖代码 |
| `farmAddress` | 养殖场地址 |
| `name` | 姓名 |

字段可能为空时保留为 `null`；`id` 必须从当前页面返回的记录中取得，不能用名称或畜禽代码替代。

### 导入文件

Portal 文件控件的规则是文件名以 `.xls` 或 `.xlsx` 结尾，大小写不敏感；页面源码没有把 MIME 类型作为拒绝条件。SDK 输入：

```ts
{
  fileName: string,
  base64: string,
  contentType?: string | null
}
```

`prepareImport` 只解码并检查文件名、Base64 和非空字节数，不发请求。`importFile` 必须使用用户确认过的同一份文件，以 multipart 字段 `file` 上传。省略 `contentType` 时，SDK 对 `.xls` 使用 `application/vnd.ms-excel`，对 `.xlsx` 使用 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`。

后端导入时逐行把记录绑定到当前租户，并要求 `provinceCode` 为数字；错误时返回后端错误信息。导入成功回执按当前 Java Controller 是字符串，SDK同时兼容字符串或数字，不把回执解释为可靠的导入条数。

### 删除

删除输入只有当前列表记录的 `id`。Portal 先显示“确定删除这条数据？”确认框，然后发送：

```text
DELETE /vue/customer/registerCode/{id}
Content-Type: application/x-www-form-urlencoded
```

SDK 的 `prepareRemove` 不发请求；用户确认后才调用 `remove`。后端会检查该畜禽代码是否已被客户使用，使用中的记录会拒绝删除。成功回执没有业务数据，必须重新查询确认记录不再出现。

| 页面动作 | 方法 | 路径 | 请求体/参数 | SDK结果 |
| --- | --- | --- | --- | --- |
| 查询 | GET | `/vue/customer/registerCode/list` | `order/orderField` + 三个筛选字段 + `pageNo/pageSize` | `{ list, total }` |

## 操作步骤

### 查询

1. 用用户给出的筛选条件调用 `sale-register-code-list`。
2. 展示 `list` 字段，使用 `total` 做分页。
3. 用户翻页时递增 `pageNo`，不要把一页结果当成全量。

### 导入

1. 取得用户明确选择的 `.xls/.xlsx` 文件，调用 `sale-register-code-prepare-import`。
2. 向用户展示文件名、MIME 和字节数，说明准备阶段没有写入。
3. 用户取消时丢弃预览，不发送请求。
4. 用户明确确认后，把同一组文件参数交给 `sale-register-code-import`。
5. 成功后重新分页查询，并根据 `breedingCode` 等字段核对导入结果；失败时按后端行号/校验信息修正文件，不盲目重发。

### 删除

1. 先从当前列表取得目标记录的 `id`，调用 `sale-register-code-prepare-remove`。
2. 向用户展示将删除的记录，等待明确确认。
3. 用户取消时丢弃准备结果。
4. 用户确认后调用 `sale-register-code-remove`。
5. 重新查询并逐页核对目标 ID；若后端提示代码已被客户使用，应报告失败原因，不把请求完成当作删除成功。
