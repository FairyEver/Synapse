# 产品设置温度设置

页面路径：`/dashboard/product/setting/hatch-manage/season/list`。

菜单归属是 `系统设置 → 生产设置 → 养殖预案 → 温度设置`。这里的“生产设置”是系统设置内的 Portal 子菜单，不是范围外的独立生产业务菜单。

## 页面能力定义

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询温度设置 | `product-setting-hatch-manage-season-list` / `productSettingHatchManageSeason.list` | `GET /programNew/baseSetting/temp/getPage` |
| 准备新建 | `product-setting-hatch-manage-season-prepare-create` / `productSettingHatchManageSeason.prepareCreate` | 本地表单校验，不发请求 |
| 新建 | `product-setting-hatch-manage-season-create` / `productSettingHatchManageSeason.create` | `POST /programNew/baseSetting/temp/create` |
| 准备编辑 | `product-setting-hatch-manage-season-prepare-update` / `productSettingHatchManageSeason.prepareUpdate` | 本地表单校验，不发请求 |
| 编辑 | `product-setting-hatch-manage-season-update` / `productSettingHatchManageSeason.update` | `POST /programNew/baseSetting/temp/edit` |
| 准备删除 | `product-setting-hatch-manage-season-prepare-remove` / `productSettingHatchManageSeason.prepareRemove` | 本地确认前准备，不发请求 |
| 删除 | `product-setting-hatch-manage-season-remove` / `productSettingHatchManageSeason.remove` | `GET /programNew/baseSetting/temp/delete?id=...&tempId=...` |

请求使用 `product` HTTP 实例，补 `devicetype=PC`；本页没有页面推导出的 `module-type`，因此不发送该请求头。菜单权限是 `/dashboard/frame/breeding-plan/season`；查询、提交、删除权限分别是 `program:season:query`、`program:season:submit`、`program:season:delete`。SDK只复刻页面请求，不绕过服务端权限。

## 参数契约与提交规则

列表表单的外界温度筛选默认 `min=-99`、`max=99`，请求固定带 `scope=1`。公共列表模块加入 `order=""`、`orderField=""`、`pageNo` 和 `pageSize`；styleV2默认每页20条，页面支持10、20、50、100。SDK调用 `list({ min: null, max: null })` 时保留显式的null，等价于页面清空对应筛选条件。

新建弹窗的 `inMin`、`inMax`、`outMin`、`outMax` 四项全部必填，输入控件范围为 `-99..99`。Portal表单状态还初始化 `id`、`tempId` 为 `undefined`，新建提交对象展开空的 `raw`后覆盖这六个字段；JSON序列化时undefined字段不会发送，Java创建接口会自行生成新的舍内温度ID。

编辑弹窗把当前行 `raw` 全量展开，再覆盖 `id`、`tempId`、`inMin`、`inMax`、`outMin`、`outMax`，所以SDK保留列表行中的扩展字段。页面没有声明“最小值必须小于最大值”的校验，SDK不擅自增加该规则；服务端业务结果仍须回查。

删除是GET，并且必须同时发送当前行的 `id`（外界温度记录）和 `tempId`（舍内温度记录）。不能改成DELETE，也不能只发送其中一个ID。

## 逐字段基准

| 字段 | 含义 |
| --- | --- |
| `list` | 当前外界温度筛选条件和分页下的内外温度对照记录。 |
| `total` | 当前筛选条件下的总数，不是当前页长度。 |
| `list[].id` | 外界温度记录ID；编辑和删除请求的 `id`。 |
| `list[].tempId` | 舍内温度记录ID；编辑和删除请求的 `tempId`。 |
| `list[].inMin` / `inMax` | 舍内温度下限 / 上限；页面标签分别是最低（不包含）和最高（包含）。 |
| `list[].inTitle` | 舍内温度展示文本。 |
| `list[].outMin` / `outMax` | 外界温度下限 / 上限；页面标签分别是最低（不包含）和最高（包含）。 |
| `list[].outTitle` | 外界温度展示文本。 |
| `prepareCreate().draft` | 已通过四项必填和范围校验、尚未发送请求的新建对象。 |
| `prepareUpdate().draft` | 已按Portal raw透传和字段覆盖规则整理、尚未发送请求的编辑对象。 |
| 写操作结果 `true` | 请求未抛错的本地确认，不代表服务端已按预期落库。 |

## 操作步骤、权限和证据边界

1. 使用当前用户会话和租户上下文调用 `list()`读取温度设置；筛选条件按页面默认值或用户明确输入传递。
2. 新建时调用 `prepareCreate()`，经用户确认后把同一份 `draft`交给 `create()`；取消只丢弃本地草稿。
3. 编辑时把最近一次列表行与用户修改结果交给 `prepareUpdate()`，经用户确认后把同一份 `draft`交给 `update()`；取消不发请求。
4. 删除前调用 `prepareRemove({ id, tempId })`，明确获得用户确认后再调用 `remove()`；取消不发GET。
5. 新建、编辑或删除成功、失败或响应不确定后，都重新调用 `list()`回查；不能只依据 `true`宣布业务状态已改变。

本轮逐页核对了Portal菜单、路由、列表、弹窗、公共分页、product响应解包，以及Java `BaseSettingTempController`、DTO、VO、Service和Mapper。当前没有真实测试环境浏览器会话的列表/新建/编辑/回查/双ID删除闭环证据。

Java实现会把新建拆为一条舍内温度记录和一条外界温度记录；编辑按 `tempId` 更新舍内记录、按 `id` 更新外界记录；删除同时软删两张表。SDK保持Portal的双ID请求规则，写操作最终状态以重新查询为准。
