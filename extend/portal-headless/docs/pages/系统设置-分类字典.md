# 系统设置：分类字典

页面：`/dashboard/setting/category-dict/list`
菜单权限：`/dashboard/setting/category-dict`
HTTP 实例：`platform`
module-type：不发送（该路径不命中 Portal 的模块类型规则）

## 能力定义

| capability | 页面动作 | 请求 |
| --- | --- | --- |
| `setting-category-dict-list` | 查询树、名称/编码筛选 | `GET /admin-api/system/category-dict/tree` |
| `setting-category-dict-create` | 在选中节点下添加下级 | `POST /admin-api/system/category-dict/create` |
| `setting-category-dict-update` | 弹窗编辑或名称/编码行内编辑 | `PUT /admin-api/system/category-dict/update` |
| `setting-category-dict-remove` | 删除租户自有叶子/无子节点分类 | `DELETE /admin-api/system/category-dict/delete/{id}` |

该页不是分页列表。Portal 的 `useListPageModule` 仍会发 `order`、`orderField`、`name`、`code` 和 `onlyTenantEditable`；页面初始值为 `onlyTenantEditable: true`。SDK 默认保持这个可维护范围，树节点递归保留 `children`。

## 参数契约

树节点至少包含：

- `id`、`pid`：节点及父节点主键；`pid=0` 是平台根节点。
- `name`、`code`：名称和可空编码。
- `tenantId`、`platform`：平台共享/租户私有来源信息。
- `tenantEditable`：根节点的租户维护开关，`1` 才允许租户在该根下维护；子节点固定为 `0`。
- `createTime`、`children`：创建时间和子树。

创建、更新只提交 `pid`、`name`、`code`。`name` 不能是空字符串；Java 使用 `@NotEmpty`，SDK 不把空格擅自 trim。Portal 弹窗的 `code` 默认是 `null`，SDK 未填写时保留 `null`。租户不能创建根节点，更新也不能把节点改成根节点。

## 逐字段基准

Portal 页面源码：

- `app/portal/menus/common.js`：菜单路径和权限。
- `app/portal/views/dashboard/hr/setting/category-dict/list.vue`：树请求、筛选、行内编辑、弹窗新增/编辑、删除 URL 和平台节点显示条件。
- `app/portal/views/dashboard/hr/setting/category-dict/components/ModalForm.vue`：`pid`、`name`、`code` 表单以及仅 `name` 的前端必填规则。
- `app/portal/utils/http/platform.js`：`/admin-api` 已在请求路径中，平台拦截器不再重复补前缀；module-type 由请求上下文生成，但本页推导为空。

Java 基准：

- `CategoryDictController` 将租户页面绑定到 `/system/category-dict/{tree,create,update,delete/{id}}`。
- `CategoryDictSaveReqVO` 要求 `pid` 非空、`name` 非空；`code` 可空。
- `CategoryDictServiceImpl` 要求写操作有真实租户上下文，写入对象必须属于当前租户，父节点必须可见，根链的 `tenantEditable=1`，租户只能维护非根节点；删除前检查当前租户是否仍有子节点。
- `CategoryDictMapper` 对树查询显式合并平台租户 `0` 与当前租户；该表绕过自动租户条件。

上述为固定检出源码核对和离线测试证据。尚未在真实测试环境完成浏览器读请求及安全测试数据上的 `create/update/delete` 写入回查；写请求成功或超时均不能替代树查询核实。该后端没有通用 cancel 接口，不对真实业务数据盲测删除。

## 操作步骤

1. 先调用 `setting-category-dict-list`，从递归树中选择当前可见父节点和目标节点，保留原始 ID、父级、名称和编码。
2. 添加下级时传所选父节点 `id` 作为 `pid`；平台节点是否开放租户维护由后端 `tenant_editable` 决定。
3. 编辑或行内保存时提交完整 `id`、`pid`、`name`、`code`，不要把 `tenantId`、`platform` 或 `tenantEditable` 当作表单字段。
4. 删除只传节点 ID；后端不递归删除，有子节点、平台节点、根节点或非当前租户节点时会失败。
5. 创建后按 `pid + name + code` 回查；修改后按 `id` 逐字段回查；删除后递归检查树中目标 ID 已消失。权限、父级不可见、根不可维护和业务错误原样报告。
