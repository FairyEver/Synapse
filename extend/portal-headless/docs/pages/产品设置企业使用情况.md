# 产品设置企业使用情况

页面路径：/dashboard/product/setting/business-manage/tenant-log/list。

菜单归属是 系统设置 → 生产设置 → 业务管理 → 企业使用情况。这里的“生产设置”是 Portal 保留的“系统设置”子菜单，不是范围外的独立生产业务菜单。

## 页面能力定义

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询企业候选 | product-setting-tenant-log-company-list / productSettingTenantLog.companyList | GET /sys/office/getTenantCompanyList?id=0 |
| 查询功能树 | product-setting-tenant-log-function-tree / productSettingTenantLog.functionTree | GET /config/leaf/getTree?code=functionUrl |
| 查询企业用户候选 | product-setting-tenant-log-user-list / productSettingTenantLog.userList | GET /sys/user?pageSize=99999&pageNo=1&office.id=<companyId> |
| 查询企业统计 | product-setting-tenant-log-list / productSettingTenantLog.list | POST /use/statistics/companyModuleUseSituation、companyFunctionUseSituation 或 companyUserUseSituation |
| 查询模块明细 | product-setting-tenant-log-module-detail / productSettingTenantLog.moduleDetail | POST /use/statistics/companyModuleUseSituationDetail |
| 查询功能明细 | product-setting-tenant-log-function-detail / productSettingTenantLog.functionDetail | POST /use/statistics/companyFunctionUseSituationDetail |
| 查询用户明细 | product-setting-tenant-log-user-detail / productSettingTenantLog.userDetail | POST /use/statistics/companyUserUseSituationDetail |

请求使用 product HTTP 实例，补 devicetype=PC，不发送 module-type。页面权限为 /dashboard/frame/job-saas/tenant-log；Portal 本页的 query 和 submit 权限配置都为空，没有额外的按钮提交权限。数据仍受当前用户、租户和后端业务权限限制。

## 参数契约与表单规则

页面表单默认值为：pageType=1、deviceType=""、日期范围为当前日期前30天到当前日期，companyId、functionList、userIdList为空。公司和日期范围必填；pageType=2/3时功能必填；pageType=3时用户必填。日期发送为 YYYY-MM-DD，结束日期不能早于开始日期。

企业候选请求固定发送 { id: 0 }。Java OfficeController 只保留 useSystem 包含 4 的企业。功能树请求固定发送 { code: "functionUrl" }，SDK 为每个节点递归补 fullName 和空的 childList。Portal 只把完整路径按 - 拆分后恰好得到三段的叶节点转换为：

    { "module1": "一级模块", "module2": "二级模块", "module3": "三级功能" }

选择公司后，Portal 按 office.id 请求全部用户，固定 pageSize=99999、pageNo=1；公司为空时只清空用户，不请求用户接口。SDK 的 userList 要求显式传入有效公司ID。

统计请求体按模式严格区分：

    {
      "companyId": "企业ID",
      "startDate": "YYYY-MM-DD",
      "endDate": "YYYY-MM-DD",
      "deviceType": "PC、APP或空字符串"
    }

功能模式在上面基础上追加 functionList；用户模式再追加 userIdList。三种模式都使用 POST，Portal 按非分页数组消费。Java 要求公司必填；功能和用户模式分别要求非空 functionList，用户模式还要求非空 userIdList。功能统计结果量受后端1000条限制。

明细请求分别为：

- 模块明细：基础筛选 + module，值来自统计行的 moduleName。
- 功能明细：基础筛选 + module、module1、module2、module3，值来自同一统计行。
- 用户明细：基础筛选 + userIdList、functionList；列表行有可靠用户ID时优先使用该用户，否则使用当前筛选用户。

## 逐字段基准

候选结果字段：

| 字段 | 含义 |
| --- | --- |
| companyList[].id | 企业ID；后续统计和用户查询的 companyId。 |
| companyList[].name | 企业名称；Portal 下拉展示文本。 |
| functionTree[].id / functionTree[].childList[].id | 功能树节点ID。 |
| functionTree[].name | 当前节点名称。 |
| functionTree[].fullName | SDK 从根到当前节点用 - 拼接的完整路径。 |
| functionTree[].childList | 递归子节点；叶节点为空数组。 |
| userList[].id | 用户ID；用户统计和明细的 userIdList 来源。 |
| userList[].name | 用户姓名；Portal 下拉展示文本。 |

统计和明细行字段：

| 字段 | 含义 |
| --- | --- |
| [].module1 / [].module2 / [].module3 | 功能层级；可能因统计模式不同为空。 |
| [].moduleName | 模块展示名称。 |
| [].functionName | 功能展示名称；Java 可能用 :: 连接层级。 |
| [].recordCount | 记录类使用次数。 |
| [].searchCount | 搜索类使用次数。 |
| [].totalCount | Java 计算的记录次数与搜索次数之和。 |
| [].userId | 明细所属用户ID；用户汇总行可能为空，不能从姓名猜ID。 |
| [].officeName | 用户所属组织名称。 |
| [].userName | 用户姓名。 |
| [].phone | 用户手机号。 |
| [].date | 用户统计汇总日期。 |
| [].createDate | 明细事件创建时间。 |
| [].requestType | Portal 使用记录请求类型。 |

空值按字段语义处理：空的层级、用户、组织、日期或计数字段表示后端该统计模式没有提供对应值，不应由调用方用展示名称补造ID或层级。

## 操作步骤、权限和证据边界

1. 调用 companyList()，只从返回的企业ID中选择公司；需要功能或用户模式时调用 functionTree()，将三段叶节点转换为 functionList。
2. 用户模式先用当前公司调用 userList({ companyId })，再选择非空 userIdList；公司改变后重新读取用户候选，不沿用旧公司用户ID。
3. 按当前模式、日期和平台调用 list()。模块模式不发送功能或用户数组；功能模式发送功能数组；用户模式同时发送功能和用户数组。
4. 点击模块或功能行详情时，保留同一筛选条件并分别调用 moduleDetail() 或 functionDetail()。用户模式详情使用当前行用户ID；没有可靠行ID时回退当前筛选用户数组。
5. 三种统计和三种明细均为只读查询，没有 prepare → submit → cancel 写闭环；请求失败或响应超时必须报告并按最新筛选重新查询，不能把空数组或旧结果当作成功。
