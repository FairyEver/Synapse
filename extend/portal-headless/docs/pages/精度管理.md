## 权限与请求上下文

页面根权限为 `/dashboard/finance/setting/accuracy`。页面按钮权限由源码条件决定：

- 新增：`finance:setting:accuracy:create`。
- 编辑：`finance:setting:accuracy:edit`，且 `record.status === 0`、`record.isUsedByAccountSet !== 1`。
- 删除：`finance:setting:accuracy:delete`，且 `record.status === 0`、`record.isUsedByAccountSet !== 1`。
- 启停：`finance:setting:accuracy:status`；不受 `isUsedByAccountSet` 限制。

能力使用 `platform` HTTP 实例。目录没有匹配到 `module-type` 规则，SDK与Portal一致不发送该头；会话请求仍由共享请求层携带显式 `tenant-id`、会话 token 和语言头。一个 HTTP 实例只绑定一个用户和租户。

## 参数契约

列表页面 `form: {}`，没有用户筛选字段；`styleV2` 默认分页为20，页面选项为10、20、50、100。源码推导的参数键序为：

```text
GET /admin-api/finance/accuracy-manage/page
params = { order: '', orderField: '', pageNo: 1, pageSize: 20 }
```

`pageNo` 必须为正整数；`pageSize` 只能取10、20、50、100。`order`、`orderField` 是Portal列表组件固定发送的空字符串，不对调用方开放任意排序。

新增和编辑表单字段及规则：

- `currencyType`：币种字典数值，必填安全整数；源码只提供 `currency_type` 选择器，未提供完整枚举，SDK不猜币种标签。
- `decimalQuantity`：数量小数位，必填、整数、0–9，单位为“位”。
- `decimalUnitPrice`：单价小数位，必填、整数、0–9，单位为“位”。
- `decimalAmount`：金额小数位，必填、整数、0–9，单位为“位”。
- `status`：表单初始值为0；页面没有状态输入控件，新增和编辑提交固定保持0。

编辑页先调用：

```text
GET /admin-api/finance/accuracy-manage/get?id=<id>
```

Portal `customLoad` 会把 `decimalQuantity`、`decimalUnitPrice`、`decimalAmount` 的 `null/undefined` 补成0，再用表单对象展开提交。SDK的 `get` 同样补0。编辑更新会保留详情中存在的历史字段及响应快照字段，键序按详情对象构造为：

```text
id, accuracyName, currencyType, accuracyDelimiter, decimalPlaces,
decimalQuantity, decimalUnitPrice, decimalAmount, status,
isUsedByAccountSet, createTime, tenantName
```

调用方只能通过 `changes` 修改 `currencyType`、`decimalQuantity`、`decimalUnitPrice`、`decimalAmount`；不能改ID、状态、引用标记或历史字段。

## 逐字段返回与端点

列表：

```text
GET /admin-api/finance/accuracy-manage/page
```

SDK返回 `{ list, total }`。`list[]` 字段为：

- `id`：精度管理主记录ID；编辑、启停和删除都使用它，不是租户ID或币种值。
- `tenantName`：企业名称，可为 `null`。
- `currencyType`：币种字典数值，可为 `null`；保持原值，不翻译、不补值。
- `decimalQuantity`、`decimalUnitPrice`、`decimalAmount`：三类小数位，可为 `null`；列表不把空值自动改成0。
- `status`：`0=启用`、`1=停用`。页面在0时显示“停用”按钮，在1时显示“启用”按钮。
- `isUsedByAccountSet`：`0=未被账套引用`、`1=已被账套引用`，缺失时为 `null`；用于复现编辑/删除按钮条件。
- `createTime`：录入时间原值，可为字符串、有限数值或 `null`；不做时区换算。
- `total`：当前租户/权限范围内的总记录数，不是当前页长度。

详情：

```text
GET /admin-api/finance/accuracy-manage/get
params = { id }
```

找不到记录时SDK返回 `null`。非空详情除上述列表字段外还返回 `accuracyName`、`accuracyDelimiter`、`decimalPlaces` 三个历史兼容字段；这三个字段可以为空，不属于可编辑输入。详情的三个新小数位按Portal表单逻辑归一为0。

创建：

```text
POST /admin-api/finance/accuracy-manage/create
body = {
  currencyType,
  decimalQuantity,
  decimalUnitPrice,
  decimalAmount,
  status: 0,
}
```

返回后端分配的根ID（字符串或安全整数）。`requestId` 只供SDK的 `createIdempotent` 防重，不进入HTTP body。

更新：

```text
PUT /admin-api/finance/accuracy-manage/update
body = prepareUpdate({ current, changes }).draft
```

`current` 必须是 `get` 返回的完整详情或此前 `prepareUpdate` 返回的草稿；不能直接把列表行作为编辑快照，因为列表行没有 `accuracyName`、`accuracyDelimiter`、`decimalPlaces`，而Portal编辑页会把这些历史字段随表单一起提交。

返回业务值必须严格为 `true`。更新会再次检查记录存在、未被账套引用以及三个小数位的0–9范围。

启停：

```text
PUT /admin-api/finance/accuracy-manage/enableOrStop
body = { id, status }
```

只发送 `id/status`，不发送 `currentStatus`；`status` 是绝对目标，必须与调用方提供的最新 `currentStatus` 相反。返回业务值必须严格为 `true`。

删除：

```text
DELETE /admin-api/finance/accuracy-manage/delete
params = { id }
```

`currentStatus` 和 `isUsedByAccountSet` 只用于SDK侧复现页面按钮保护，不进入请求。返回业务值必须严格为 `true`。后端是物理删除，不能恢复。

## 操作步骤与撤销/清理

创建：

1. 调 `prepareCreate`，核对币种和三类小数位。
2. 用户确认后生成新的 `requestId`，调用 `createIdempotent`。
3. 用返回ID通过 `list`/`get` 独立核对币种、三类小数位和 `status=0`；请求回ID本身不等于持久化已验证。
4. 如果用户明确要求清理，且回查确认同一ID仍为 `status=0`、`isUsedByAccountSet=0`，调用 `remove`，再回查ID消失。删除是新的物理DELETE，不是事务回滚。

编辑：

1. 用最新列表行ID调用 `get`，确认详情非null、`status=0`、`isUsedByAccountSet !== 1`。
2. 调 `prepareUpdate({ current, changes })`，保存 `previous` 和 `draft`。
3. 用户确认后把 `draft` 作为 `current`、空 `changes` 调 `update`，再用 `get`/`list` 核对同一ID的四个页面字段。
4. 若用户明确要求恢复，且没有要保留的并发修改，使用保存的 `previous` 四个可编辑字段再次update；这是反向PUT，不是服务端回滚，恢复后仍需回查。

启停：保存操作前的 `currentStatus`，向 `setStatus` 提交相反绝对值；成功或超时后列表回查同一ID。需要恢复时确认当前仍是目标状态，再用原 `currentStatus` 作为新的目标值提交并回查。

删除没有可逆 `cancel` 端点。成功或超时后只能通过列表/get确认ID是否消失；未确认前不要重复删除。对真实环境的创建、编辑、启停、删除和清理，本轮均未执行。
