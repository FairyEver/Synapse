# 失败队列

## 能力定义与页面范围

平台设置 → 定时任务 → 失败队列，菜单 `/dashboard/platform/system/regular/fail/list`，权限为
`/dashboard/platform-v2/system/regular/fail`。页面使用 platform-mall-admin.js，列表、删除和手动执行请求不发送 `module-type`。

页面包含按“队列数据”查询、分页列表、批量删除、详情展示和“手动执行失败队列”。详情页只读取列表按钮放入 URL query 的
`queueName/createTime/data/reason`，没有独立 GET；SDK 不伪造不可达详情能力。

依据 Portal `test/portal/main @ 3622e02147` 的 `list.vue`、`detail/[id].vue`、`mall.v2.js`，以及 Java
`test/test @ c3348150f42` 的 `ManageSysQueueFailedController` 和 `SysQueueFailedDTO`。

## 能力和请求

| 能力 | SDK 方法 | 请求 | 页面行为 |
|---|---|---|---|
| `platform-system-queue-failed-list` | `list(query?)` | GET `/mall-manage-api/sys/queueFailed/page` | 默认 `data=''`、styleV2 pageSize=20 |
| `platform-system-queue-failed-prepare-remove` / `…remove` | `prepareRemove({ids})` / `remove({ids})` | 不发请求 / DELETE `/mall-manage-api/sys/queueFailed/delete`，body 为 ID 数组 | 批量删除 |
| `platform-system-queue-failed-prepare-run` / `…run` | `prepareRun({id})` / `run({id})` | 不发请求 / GET `/mall-manage-api/sys/queueFailed/run?id=<id>` | 手动执行一条失败队列；页面使用 URL 字符串拼接 query |

列表请求参数为 `{order:'', orderField:'', data, pageNo, pageSize}`，`data` 原样保留，不自动 trim。返回 `{list,total}`，行字段为
`id/queueName/data/createTime/reason`；长 ID 保留字符串，时间整数保留原值。

## 提交规则和操作步骤

页面多选值是行 `id`。删除要求非空 ID 数组，SDK 拒绝空数组、0、负数、行号和无法安全表达的 ID。顺序为：`list()` → 用户选择 ID →
`prepareRemove` → 用户确认 → `remove` → 按原筛选条件重新分页核对所有 ID 已消失。删除没有撤销接口，超时先查询，不盲目重试。

手动执行顺序为：最新列表行 ID → `prepareRun` → 用户确认 → `run`。页面只根据请求成功显示“执行成功”，没有执行状态字段或独立结果读取；
SDK 不把空列表或请求成功夸大为队列业务已完成。详情展示是本地字段消费，不需要也不允许额外请求。
