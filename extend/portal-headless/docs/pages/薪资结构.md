## ⚠️ 本地源码不是线上那一版

本地检出里的 `list.vue` 是旧版（`…/kpisalarystructure/page`、**没有分页**、名称在本地过滤）。
线上跑的是 `2f29dd5f291 fix(hr): 适配树数据按层分页与回显`
（`test/portal/main` / `develop` 分支上有，本地 HEAD 没有；后端对应
`KpiSalaryStructureController:139/145`）。

| | 本地旧版（**未部署**，别照它写） | 线上 / 基准 |
| --- | --- | --- |
| 列表接口 | `…/kpisalarystructure/page` | `…/kpisalarystructure/treePage`，带 `keyword` 时 `searchPage` |
| 分页 | 无 | **有**：`pageNo=1&pageSize=20`，上限 100 |
| `order`/`orderField` | 有（空串） | **没有** |
| 名称 | 本地过滤（`omit` 掉） | **服务端** `keyword` |
| 删目录 | 客户端收齐子树 id 递归删 | `ids = [record.id]`，只删那一条 |

那个改动的形态是**树按层分页**：一次只取一层，点目录名 = 用它的 id 再发一次。

## 参数契约

`customLoad` **自己拼了一个新的 params 对象**（模块给的那份一个字段都没用），
所以 URL 上没有 `order`/`orderField`。顺序逐字：

`parentId → keyword → dataType → selection → pageNo → pageSize → _t`

| 字段 | 默认 | 谁给的 | 说明 |
| --- | --- | --- | --- |
| `parentId` | `0` | 调用方 | 0 = 根层；往下一层用上一层里 `dataType === 1` 的行 id |
| `keyword` | `''`（先 `trim`） | 调用方 | 非空 → 端点换成 `searchPage` |
| `dataType` | `undefined` | 页面钉死 | `keyword` 非空时是 `2`；为空时**必须 undefined**（`qs` 的 `skipNulls` 才会整个丢掉它，发空串就多一个键） |
| `selection` | `false` | 页面钉死 | **页面身份，不是筛选**：后端 `HrBoundedTreeQueryDTO` 注释写着「selection 仅区分薪资已有的选择器与管理页可见范围」，DTO 默认值还是 `true` —— 漏发等于换到"选择器"那个可见范围。调用方传 `true` 也盖不掉 |
| `pageNo` | `1` | 调用方 | **按层**分页：每一层各自算 |
| `pageSize` | `20` | 调用方 | 页面 `Math.min(Number(…) || 20, 100)`，本能力同样压到 100 以内（后端也校验 1..100） |

返回 `{ list, total }`；每行交给调用方前会**剥掉 `children`**
（页面最后一句 `omit(node, ['children'])`，位置信息由 `ancestorPath` 带回来）。

## 逐字段基准

**默认（空关键字）—— 基准里那条，逐字：**

```
https://biz-api-test.wodecorp.cn/admin-api/performance/basedata/kpisalarystructure/treePage?parentId=0&keyword=&selection=false&pageNo=1&pageSize=20&_t=<ts>
```

**带关键字那条分支 —— 按线上源码推，基准里没有：**

```
…/kpisalarystructure/searchPage?parentId=0&keyword=<kw>&dataType=2&selection=false&pageNo=1&pageSize=20&_t=<ts>
```

（页面原文 `'…' + (keyword ? 'searchPage' : 'treePage')` + `dataType: keyword ? 2 : undefined`。
实抓的那一次页面是空关键字，所以只有 `treePage` 这一条进了基准 ——
**`searchPage` 那条是推断，不是实测**，单测钉的是源码推导出来的键序。）

## 真实验证

- **基准**：`baseline/perf-manage-template.browser.json` 里 `treePage` 那条与能力构造的 URL
  逐字段一致（含键顺序）。
- **回归测试**：`pnpm vitest run test/perf-manage-template.test.ts`（这一页有 10 条）。
- ⚠️ **没做**：真实后端冒烟（不开浏览器、不取凭据）。所以
  **`treePage` 的响应形状没有实测**（`{list,total}` 与 `ancestorPath` 都是从页面源码读出来的），
  也**没有任何一层真被翻开过**。

## 已覆盖的读写动作

接口见 `KpiSalaryStructureController`，已接入统一目录并按 `prepare → submit → cancel` 建模：

- **启用 / 停用**：`PUT /performance/basedata/kpisalarystructure/updateStatus`，
  body `{ id, status }` —— 形状正好是 `prepare → submit` 那两步。
- **删**：`DELETE /performance/basedata/kpisalarystructure`，body `{ ids: [...] }`。
  页面在**启用中**（`status === 1 && dataType === 2`）时禁用删除按钮 ——
  前置检查得自己带上。⚠️ 线上版**不再递归删子树**（`ids = [record.id]`）。
- **建 / 改**：`POST` / `PUT /performance/basedata/kpisalarystructure`。
- **子页面**：`./salary-structure-config?id=<id>`（薪资结构配置，另有自己的读写接口）；
  行内的「使用情况」走 `components/view-usage.vue`（`usedInfo` 那几条 POST）。

SDK 还覆盖薪资结构详情、薪资标准候选/详情、结构配置保存；删除保持线上版的单条
`ids = [record.id]` 语义，不递归收集子树。启停按当前状态反转，启用中的薪资结构删除在
prepare 阶段拒绝；薪资结构使用情况按 Java 实际的非分页数组返回，不伪装成 `{ list, total }`。
真实环境写冒烟仍未执行。

### `perf-manage-salary-structure-list`

按层分页浏览薪资结构或跨层按关键字找结构；父目录与薪资结构是两种行。

- 执行：`sdk.perfManageTemplate.listSalaryStructures`；通过 `capabilities.invoke('perf-manage-salary-structure-list', args)` 调用时按 `params` 填参。性质：read。
- 参数：`parentId` 可选 (number)；`keyword` 可选 (string)；`pageNo` 可选 (number)；`pageSize` 可选 (number)。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`{ list: object[], total: number }`。list=[] 为当前页无记录；total=0 表示该筛选无结果。保留筛选条件检查页码，不将空结果解释成权限判定。
- 字段：`list`、`total`、`list[].id`、`list[].name`、`list[].dataType`、`list[].status`、`list[].ancestorPath`、`list[].ancestorPath[].id`、`list[].ancestorPath[].name`、`list[].ancestorPath[].available`、`list[].baseWageBaseNum`、`list[].baseWageRangeLow`、`list[].baseWageRangeHigh`、`list[].assessmentWageBaseNum`、`list[].assessmentWageRangeLow`、`list[].assessmentWageRangeHigh`、`list[].profitWageBaseNum`、`list[].profitWageRangeLow`、`list[].profitWageRangeHigh`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：dataType=1 的 id 作为 parentId 下钻。keyword 非空改为跨层搜索，仅搜索 dataType=2。每页最多 100；不能递归不存在的 children。
- 完成条件：按用户要求交付本次筛选范围的结果；需要完整清单时继续翻页至覆盖 total，不能把当前页当全集。
