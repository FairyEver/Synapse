# 外部员工（`/dashboard/staff/external-staff-list/list`）

## 页面范围与证据

Portal 菜单“人力 → 员工管理 → 外部员工”，权限 `/dashboard/staff/external-staff-list`，页面路径按当前规则使用 `platform` HTTP 实例和 `module-type=11`（组织管理）。列表可见查询、新建、编辑、行删除；模板还声明批量删除和 `exportURL`，但导出按钮不存在，复选框只有 `record.status === 2` 时可选，而 Java `HrOutsideStaffDTO` 没有 `status` 字段，因此当前后端返回形状下批量选择不可达。

Portal 证据：`app/portal/menus/hr.js`、`app/portal/views/dashboard/hr/staff/external-staff-list.vue`、`list.vue`、`[mode]/[id].vue`，固定提交 `bbcfc35154`。

Java 证据：`HrOutsideStaffController`、`HrOutsideStaffDTO`、`HrOutsideStaffSelectDTO`、`HrOutsideStaffServiceImpl`、`HrOutsideStaffDao.xml`，固定提交 `b7a359adc9e`。

## 能力与请求

| 页面动作 | SDK 能力 / 方法 | 请求与副作用 |
| --- | --- | --- |
| 列表 | `hr-external-staff-list` / `hrExternalStaff.list` | `GET /org/outsideStaff/page`；发送 `order`、`orderField`、`name`、`mobile`、`orgId`、`pageNo`、`pageSize` |
| 编辑详情 | `hr-external-staff-get` / `hrExternalStaff.get` | `GET /org/outsideStaff/{id}` |
| 新建准备 | `hr-external-staff-prepare-create` / `hrExternalStaff.prepareCreate` | 本地校验并生成与 Portal 空白表单一致的草稿，不发请求 |
| 新建提交 | `hr-external-staff-create` / `hrExternalStaff.create` | `POST /org/outsideStaff`；后端检查手机号重复并把 `staffCode` 设置为 `mobile` |
| 编辑准备 | `hr-external-staff-prepare-update` / `hrExternalStaff.prepareUpdate` | 合并详情和明确变更，保留其它后端字段，不发请求 |
| 编辑提交 | `hr-external-staff-update` / `hrExternalStaff.update` | `PUT /org/outsideStaff`；手机号变化时后端重新检查重复并更新 `staffCode` |
| 删除准备 | `hr-external-staff-prepare-remove` / `hrExternalStaff.prepareRemove` | 读取 `/org/sensitive/info`，判断是否需要短信验证，不删除 |
| 发送删除验证码 | `hr-external-staff-send-delete-code` / `hrExternalStaff.sendDeleteCode` | 必要时 `GET /sys/sms/send`，固定使用敏感配置手机号和 `templateId=17709` |
| 删除 | `hr-external-staff-remove` / `hrExternalStaff.remove` | 必要时先 `GET /sys/sms/checkSms`，再 `DELETE /org/outsideStaff`，body 是 ID 数组；后端逻辑删除 |

`exportURL` 没有页面按钮，所以 SDK 不发布导出能力。当前页面行删除传一个 ID；SDK 保留后端 `Long[]` 数组请求形状，`ids` 会去重并可表达未来确实可选的多行删除。

## 查询参数

默认请求参数为：

```json
{
  "order": "",
  "orderField": "",
  "name": "",
  "mobile": "",
  "orgId": "",
  "pageNo": 1,
  "pageSize": 20
}
```

`name` 和 `mobile` 是输入框原值；`orgId` 是组织 ID，不是组织名称。`pageSize` 只接受 Portal 分页选项 `10、20、50、100`。Java 查询固定 `a.is_del = 0`，姓名和手机号是包含匹配，组织条件由 `orgId` 传入，所属组织全路径由 SQL 关联返回 `fullPath`。

## 表单参数与校验

新建表单的默认值与 Portal 一致：组织为空，文本项为空字符串，日期项为空值（`birthday` 初始为空字符串），字典项初始为空字符串；提交选中的字典值为数字。编辑页的 `customLoad` 直接替换整个 `formState`，因此编辑提交是完整表单对象而非差异对象，并启用 `transformUndefinedToNull: true`。

前端规则必须逐条保留：

- `appointmentFirm` 必填、不能全为空格、最多 30 个字符。
- `appointmentPost` 必填、不能全为空格、最多 10 个字符。
- `appointmentTime` 必填，日期值格式为 `YYYY-MM-DD HH:mm:ss`。
- `name` 必填、不能全为空格、最多 10 个字符。
- `idType`、`sex`、`birthday` 必填。
- `idCard` 必填、不能全为空格、最多 20 个字符，只允许数字和英文字母。
- `mobile` 必填、不能全为空格；Java DTO 按 `Long` 接收，SDK保留 Portal 输入的字符串/数字形态，不臆加手机号正则。
- 其它组织、民族、籍贯、户口、地址、政治、教育、任职高管和文本字段按页面的可空/原值规则提交；清空日期传 `null`。

详情和分页都保留 Java DTO 的全部业务字段，包括 `organization`、`name`、`idType`、`idCard`、`birthday`、`sex`、`mobile`、`staffCode`、教育/政治/任职字段、审计字段、`tenantId`、`studyPost`、`fullPath`。Long 可能序列化为字符串，时间不做时区转换。`id`、组织 ID 和员工 ID 不能用名称替代。

## 操作步骤、权限与失败处理

1. 用 `list` 查询当前会话和组织权限可见的外部员工，并保存目标行 `id`。
2. 新建：填写表单 → `prepareCreate` → 用户确认后 `create`；取消时丢弃草稿，不发 POST。
3. 编辑：先 `get` → `prepareUpdate` → 用户确认后 `update`；取消时丢弃草稿，不发 PUT。
4. 删除：`prepareRemove` 读取敏感配置。`isDel === 1` 或敏感配置完全为空时可直接删除；其它情况必须 `sendDeleteCode`，由真人提供验证码后再 `remove`。取消不发短信也不发 DELETE。
5. 新建、编辑、删除成功或超时后都要回查：新建/编辑用 `get` 或 `list` 核对字段；删除用 `list` 核对目标 ID 不再可见，因为后端是逻辑删除，不能只看详情接口。

菜单权限只是页面入口；后端还按当前会话、租户和组织数据范围裁剪结果。手机号重复、权限、敏感短信配置、验证码、后端校验、网络或响应形状错误都原样报告，不把空列表解释为无权限，也不把 HTTP 成功回执解释为已落库。后端没有 `requestId` 幂等键：新建超时先按姓名/手机号回查，编辑超时先按 ID 回查，删除超时先查列表，均不得盲目重发。
