# 任务管理

## 能力定义

- 菜单归属：门户 → 系统设置 → 销售设置 → 任务管理 → 任务管理
- 页面路径：`/dashboard/sale/job/schedule-job/list`
- 页面权限：`/dashboard/sale/frame/job/scheduleJob`
- 新建、编辑、删除、立即开始、暂停、恢复和保存按钮权限：`job:scheduleJob:edit`
- 请求实例：Portal `app/portal/utils/http/crm.js`，调用 SDK 时必须配置 `httpBaseUrls.crm`。
- `module-type`：`60`
- 页面可达动作：分页查询、按任务名称/Bean名称/方法名/状态筛选、新建、编辑、单条删除、立即开始、暂停、恢复。
- 页面编辑直接把当前列表行传给 `ModalFormContent`，没有详情 GET；页面也没有同步任务入口，因此不暴露后端虽存在的详情和 `syncJob`。
- Portal 公共列表状态会固定发送默认空的 `order`、`orderField`，页面没有排序控件。

对应 SDK 能力：

| capability | 作用 | 写入 |
| --- | --- | --- |
| `sale-schedule-job-list` | 查询任务管理 | 否 |
| `sale-schedule-job-prepare-create` / `sale-schedule-job-create` | 准备并新建定时任务 | 后者是 |
| `sale-schedule-job-prepare-update` / `sale-schedule-job-update` | 准备并编辑定时任务 | 后者是 |
| `sale-schedule-job-prepare-remove` / `sale-schedule-job-remove` | 准备并删除单条定时任务 | 后者是 |
| `sale-schedule-job-prepare-run` / `sale-schedule-job-run` | 准备并立即执行定时任务 | 后者是 |
| `sale-schedule-job-prepare-pause` / `sale-schedule-job-pause` | 准备并暂停当前正常任务 | 后者是 |
| `sale-schedule-job-prepare-resume` / `sale-schedule-job-resume` | 准备并恢复当前暂停任务 | 后者是 |

## 参数契约

### 查询

`sale-schedule-job-list` 接受：

| 参数 | 页面默认值 | 请求字段 | 说明 |
| --- | --- | --- | --- |
| `order` | `''` | `order` | Portal公共列表排序值；页面没有排序控件 |
| `orderField` | `''` | `orderField` | Portal公共列表排序字段；页面没有排序控件 |
| `jobName` | `''` | `jobName` | 任务名称模糊筛选 |
| `beanName` | `''` | `beanName` | Spring Bean名称模糊筛选 |
| `methodName` | `''` | `methodName` | 方法名模糊筛选 |
| `status` | `''` | `status` | `schedule_status` 字典值；`0` 正常、`1` 暂停；空字符串不筛选 |
| `pageNo` | `1` | `pageNo` | 从 1 开始 |
| `pageSize` | `20` | `pageSize` | `styleV2` 页面默认值；Portal 常用值为 10/20/50/100/200/500 |

Portal CRM 列表接口返回 `{ list, count }`；SDK 对外返回 `{ list, total }`，`total` 是筛选后的总记录数。列表请求由 CRM 请求拦截器继续处理 Portal 通用请求头和防缓存参数。

### 返回字段

`list[]` 的页面消费字段如下：

| 字段 | 含义 |
| --- | --- |
| `id` | 任务管理记录主键，删除时使用 |
| `jobId` | 定时任务 ID，立即开始/暂停/恢复时使用 |
| `jobName` | 任务名称 |
| `beanName` | Spring Bean 名称 |
| `methodName` | Bean 方法名 |
| `params` | 任务执行参数原文 |
| `cronExpression` | Cron 表达式 |
| `status` | 数值状态：`0` 正常、`1` 暂停；页面以此决定显示“暂停”还是“恢复” |
| `createDate` | 创建时间原值 |
| `updateDate` | 更新时间原值；编辑弹窗不会回传 |
| `remarks` | 备注信息 |

字段缺失或空值按 `null` 返回；`id` 和动作使用的 `jobId` 必须来自当前页面返回的记录，不能用名称猜测。

### 新建和编辑表单

Portal 的 `ModalFormContent.vue` 先形成完整表单，再由 `list.vue` 把整份表单提交到同一个接口：

```text
POST /vue/job/scheduleJob/save
Content-Type: application/x-www-form-urlencoded
```

表单字段：

| 字段 | 页面规则 | 后端规则 |
| --- | --- | --- |
| `jobId` | 必填 | 最多 64 个字符 |
| `jobName` | 必填 | 非空，最多 64 个字符 |
| `beanName` | 必填 | 非空，最多 200 个字符 |
| `methodName` | 必填 | 非空，最多 100 个字符 |
| `params` | 可空 | 最多 2000 个字符 |
| `cronExpression` | 必填 | 非空，最多 100 个字符 |
| `remarks` | 可空 | 最多 2000 个字符 |
| `id` | 新建省略；编辑保留当前行 ID | 编辑时作为实体主键 |

页面表单没有 `status` 字段。新建时 Java `ScheduleJobService.save` 强制把状态设为 `1`（暂停）；编辑保存不会通过该弹窗修改状态。SDK 的 `prepareCreate` / `prepareUpdate` 只做本地校验和表单整理，不发请求；用户确认后把准备结果中的完整 `form` 交给 `create` / `update`。页面提交不是差异 PATCH，不能只提交修改过的字段。

保存成功回执是字符串文案，页面只提示“保存成功”并刷新列表；SDK 对外返回 `undefined`，必须重新查询核对字段，不把文案解释成新 ID。

### 删除

Portal 删除按钮确认后发送：

```text
DELETE /vue/job/scheduleJob/{id}
```

页面没有批量删除，也没有额外删除请求头。后端将 `del_flag` 更新为删除标记并同步删除调度器任务，属于逻辑删除；SDK 的 `prepareRemove` 不发请求，用户确认后才调用 `remove`，完成后必须列表回查确认目标 ID 已消失。

### 立即开始、暂停和恢复

三个动作都由带确认的行按钮触发，发送无业务请求体的表单编码 POST：

| 页面动作 | 方法 | 路径 | 查询参数 | 页面状态门禁 |
| --- | --- | --- | --- | --- |
| 立即开始 | POST | `/vue/job/scheduleJob/run` | `jobId` | 无 |
| 暂停 | POST | `/vue/job/scheduleJob/pause` | `jobId` | 只在当前行 `status === 0` 时显示 |
| 恢复 | POST | `/vue/job/scheduleJob/resume` | `jobId` | 页面对非 `0` 状态显示；SDK按有效状态 `1` 校验 |

SDK 为每个动作提供 `prepare → submit`；用户取消只丢弃准备结果，不发 POST。暂停/恢复准备阶段还会核对当前列表行状态，防止把相反动作提交给错误状态的记录。动作回执没有业务数据，立即开始应结合任务日志或任务自身查询核实，暂停/恢复应重新 list 按 `jobId` 核对最终 `status`。

## 逐字段基准

基准来源：

- Portal：`app/portal/menus/sale.js:208-209`、`app/portal/views/dashboard/sale/job/schedule-job/list.vue`、`ModalFormContent.vue`、`common/libs/renren/list.js`
- CRM 后端：`ScheduleJobVueController`、`ScheduleJob`、`ScheduleJobService`、`CrmScheduleJobDao.xml`
- SDK：`src/capabilities/sale-schedule-job.ts`、`test/sale-schedule-job.test.ts`

已核对的请求映射：

| 页面动作 | 方法 | 路径 | 请求体/参数 | SDK结果 |
| --- | --- | --- | --- | --- |
| 查询 | GET | `/vue/job/scheduleJob/list` | `order/orderField` + 四个筛选字段 + `pageNo/pageSize` | `{ list, total }` |
| 新建 | POST | `/vue/job/scheduleJob/save` | 完整表单，无 `id`，表单编码头 | `undefined` |
| 编辑 | POST | `/vue/job/scheduleJob/save` | 完整表单，带当前行 `id`，表单编码头 | `undefined` |
| 删除 | DELETE | `/vue/job/scheduleJob/{id}` | 无业务体、无额外头 | `undefined` |
| 立即开始 | POST | `/vue/job/scheduleJob/run` | `data=null`，query `{ jobId }`，表单编码头 | `undefined` |
| 暂停 | POST | `/vue/job/scheduleJob/pause` | `data=null`，query `{ jobId }`，表单编码头 | `undefined` |
| 恢复 | POST | `/vue/job/scheduleJob/resume` | `data=null`，query `{ jobId }`，表单编码头 | `undefined` |
| 编辑页加载 | 无请求 | 当前列表行传入弹窗 | 不调用详情 GET | 列表行已包含页面字段 |

以下内容是源码基准和离线测试证据，不冒充真实环境验证：当前尚未在测试环境执行本页列表、新建、编辑、删除、立即开始、暂停、恢复和写入回查闭环。

## 操作步骤

### 查询和编辑

1. 用用户给出的筛选条件调用 `sale-schedule-job-list`。
2. 展示 `list` 字段，使用 `total` 做分页。
3. 编辑时从当前列表取得目标记录的完整字段和 `id`，调用 `sale-schedule-job-prepare-update`。
4. 用户取消时丢弃准备结果；明确确认后把同一 `form` 交给 `sale-schedule-job-update`。
5. 成功或超时后按同一 `id` 重新查询并逐字段核对。

### 新建

1. 取得用户明确填写的完整表单，调用 `sale-schedule-job-prepare-create`。
2. 向用户展示将提交的字段；准备阶段没有写入。
3. 用户取消时丢弃准备结果，不发送 POST。
4. 用户明确确认后，把同一 `form` 交给 `sale-schedule-job-create`。
5. 成功或超时后按关键字段分页查询核对；确认新记录状态为暂停，匹配不唯一时不能猜测哪条是本次创建。

### 删除

1. 从当前列表取得目标记录 `id`，调用 `sale-schedule-job-prepare-remove`。
2. 向用户展示将删除的记录并等待明确确认。
3. 用户取消时丢弃删除准备结果。
4. 用户确认后调用 `sale-schedule-job-remove`。
5. 重新查询并逐页核对目标 ID 不再出现；超时先核实，不盲目重试。

### 立即开始、暂停和恢复

1. 从当前列表取得目标记录的 `jobId`；立即开始调用 `sale-schedule-job-prepare-run`，暂停/恢复同时带当前 `status` 调用对应准备能力。
2. 向用户展示目标任务并等待确认；取消时只丢弃准备结果。
3. 用户确认后，把同一组参数交给对应的 `run`、`pause` 或 `resume` 能力。
4. 立即开始按任务日志或业务结果核实；暂停/恢复按 `jobId` 重新 list，逐条确认状态变为目标值。
