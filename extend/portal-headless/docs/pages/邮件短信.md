# 邮件短信

## 能力定义与页面范围

平台设置 → 邮件短信，菜单 `/dashboard/platform/system/email/list`，页面权限为
`/dashboard/platform-v2/system/email`。列表和动作使用 platform 请求实例；页面不发送 `module-type`。

本节点覆盖列表中的渠道开关、模板初始化、邮件账号设置、短信签名设置和邮件/短信/应用模板编辑。短信平台设置入口
不是当前页面可达动作，因此不单独发布能力。

实现与接线：`src/capabilities/platform-system-email.ts`、`src/capabilities/index.ts`、
`src/capabilities/invoke.ts`、`src/index.ts`、`src/server.ts`；AI 契约由
`src/catalog/contracts-business.ts` 发布。依据 Portal `test/portal/main @ acab69acc77b6d6c0da21310cdfd26b91a01641e` 的邮件短信页面、模板编辑页、邮件账号和短信签名设置页，
以及 Java `test/test @ 0f1a55718ebc1987affb8bf245106e809dd51da4` 的 `ManageSysMailSmsController`、DTO/VO 和服务实现。

## 列表和渠道提交规则

每行返回 `project`、`action`、`mail`、`sms`、`msgPush`、`smsSetting`。渠道对象中的 `type` 和 `isChoose` 是底部保存的关键字段。
页面只在用户点击底部“保存”时发请求：按每行 `mail → sms → msgPush` 的固定顺序收集 `isChoose === 1` 的 type，以逗号连接为
`multiType`，以行的 `action` 作为 `tmplAction`，然后用 `compact` 丢弃没有任何选中渠道的行。SDK 的
`prepareSetAccount` 和 `setAccount` 完全复刻这个顺序、连接和丢弃规则；`smsSetting` 不参与该请求。

`setAccount` 成功没有业务返回值。响应成功或超时时都应重新 `list()`，按每个 action 逐项核对渠道状态；后端没有 requestId 或页面可达的撤销接口，
不能把重复提交当作安全重试。

## 模板编辑规则

从列表点击某个渠道编辑时，页面以行 `action` 和路由 `type` 请求详情。详情字段包括 `content`、`title`、`action`、`type`、`varMap`、`isEnable`、`label`。
页面只对 `title` 和 `content` 做 required 校验，空字符串在请求前失败；没有额外的 trim 或长度规则。

提交时页面构造 `{...form, type: route.query.type}` 后 `omit(data, ['varMap'])`，因此 SDK 保留回显表单的其他字段并删除 `varMap`，不会把变量说明当作可写字段。
`action` 和 `type` 必须来自读取详情/编辑入口，`isEnable` 保留整数原值。模板保存不代表发送消息或审批完成。

## 邮件账号和短信签名

邮件账号字段按 Java `MailSmsSettingDTO` 记录为 `smtpPassword`、`smtpPort`、`smtpServer`、`smtpUserName`、`userMail`。页面读取后直接展开表单保存，
没有 required 校验；SDK 保留未知字段，已知字段只校验字符串或 null。

短信签名设置页读取时不传 query，保存时先经过页面 required 校验，然后将签名字符串作为 JSON body 发送，并显式设置
`content-type: application/json;charset=UTF-8`。列表预览的读取是另一个页面动作，传 `smsSign:''`，SDK 通过可选参数区分两种真实请求。

## 操作步骤与证据边界

1. 读取列表：`list()` → 使用返回的 `action`、渠道 `type/isChoose`；不要从列表数组推导 `total`。
2. 保存渠道：读取列表 → 修改本地行的 `isChoose` → `prepareSetAccount` → `setAccount` → 再次 `list()` 核对每个 action；现有能力已覆盖 `setAccount`，本轮只做定向核对。
3. 编辑模板：`getTemplate({action,type})` → 修改标题/正文/启用状态 → `prepareUpdateTemplate` → `updateTemplate` → 用相同 action/type 再读核对；现有能力已覆盖 `editTemplate`，本轮只做定向核对。
4. 保存账号或短信签名：先读取当前设置 → prepare → save → 再次读取设置核对；prepare 通过不表示服务端已保存。
5. 初始化模板：`maintainTemplate()` → 再 `list()`，需要具体内容时按 action/type `getTemplate()`。
