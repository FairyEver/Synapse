## 参数契约

列表按 Portal `useListPageModule` 的顺序发送：

```text
order='', orderField='', quickNumber=null, status=0, pageNo=1, pageSize=20
```

`quickNumber` 是指标名称包含筛选；页面初始值是 `null`，platform 实例的查询序列化会省略这个空值键。`status` 是数值绝对状态：`0` 启用、`1` 停用，默认只查启用，页面没有“全部”。分页条数只能是页面默认选项 `10/20/50/100`。

状态写入参数为：

```ts
{ id, currentStatus, status }
```

`id` 必须来自同一次最新列表行；`currentStatus` 是该行当前的 `0/1`，只用于写入前复现页面按钮条件；`status` 是用户明确的绝对目标值，必须与 `currentStatus` 相反。SDK 实际只向 Portal 发送 `{ id, status }`，不发送 `currentStatus`。

## 逐字段基准（源码推导，未浏览器实测）

列表请求由页面声明的 `platform` 实例发出：

```text
GET /admin-api/finance/indicator-library/page
params = {
  order: '',
  orderField: '',
  quickNumber: null,
  status: 0,

  pageSize: 20,

```

当前目录规则没有匹配到 `module-type`，SDK与页面规则均不发送该头；会话请求仍携带 `tenant-id`、会话 token 和语言头。`platform` 实例使用 `/admin-api` 路径透传规则。

SDK分页返回 `{ list, total }`，其中 `list` 是当前页，`total` 是筛选条件下的匹配总数。每行只返回页面展示或状态动作需要的字段：

- `id`：指标库主键，供状态更新使用。
- `quickNumber`：指标名称；允许后端空值，页面按原文展示。
- `abstracts`：`voucher_indicator_unit` 字典值，页面翻译后显示“单位”；SDK不猜标签。
- `dataSource`：`system_tenant_apply_use_system` 字典值，页面翻译后显示“数据来源”；SDK不猜标签。
- `instruction`：说明原文，可为空。
- `update`：页面显示的更新日期，格式为 `YYYY-MM-DD`，不做时区换算。
- `status`：后端响应 `Boolean` 归一为 SDK 数值 `0/1`；页面用它决定显示“启用”还是“停用”。后端的 `updateTime` 等页面未消费字段不纳入本页返回契约。

状态请求：

```text
PUT /admin-api/finance/indicator-library/update
body = { id, status }
```

Java 控制器返回业务数据 `true`。SDK只把 `true` 作为正常回执；它不包含更新后的行，不能替代列表回查。

## 操作步骤与撤销/清理

1. 调用 `list`，按 `pageNo/pageSize` 读取目标范围；用字典能力解释 `abstracts` 和 `dataSource`，保留选中行的 `id/status`。
2. 用户明确要启用或停用时，以同一行的 `status` 作为 `currentStatus`，传相反的绝对 `status` 调用 `setStatus`。
3. `PUT` 成功或超时后，重新列表分页定位同一 `id`，确认读回的 `status` 等于目标值；未确认前不盲目重发。
4. 本页没有独立 cancel 接口。若用户明确要求恢复，且保存了操作前状态，先确认当前值仍是目标状态，再用同一个 `PUT /update` 写回保存的 `currentStatus`，随后再次列表回查。这是可逆的反向状态写入，不是事务回滚；本页没有创建记录，因此不存在新增记录清理步骤。

撤销/cleanup 证据：Portal 行操作源码把 `record.status` 的真假映射为相反的 `0/1`，Java `update` 按 `id` 更新状态；本页离线测试锁定了正向与反向 `{ id, status }` 请求以及同状态拒绝。未执行真实 PUT、回查或恢复，不能把这些源码和离线证据表述为线上 cleanup 实测。
