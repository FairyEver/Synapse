# 历史归档记录（`/dashboard/history-archive/list`）

本页覆盖 Portal「人力 → 历史归档记录」的两个列表页签，以及从列表实际可达的历史组织架构、历史员工列表、历史员工详情和员工自定义列配置。它属于提示词保留的 `portal/人力` 范围；页面中调用的组织归档接口不等于独立顶层「生产」「财务」等系统，因此不扩展到那些顶层系统。

证据边界：已逐页核对 Portal 菜单、两个列表、历史组织树状态/图表、历史员工列表/详情和自定义列请求，并逐项核对 Java Controller、DTO、投影服务和 DTO/SQL 字段。SDK 请求投影、响应校验、分页/日期/字典边界、投影令牌、二进制导出和 AI 说明反证有离线测试；尚未在真实测试门户执行本页读请求、权限矩阵或导出文件回执验证。

来源锚点：Portal `CodeReview_Projects_Js@test/portal/main@acab69acc77b6d6c0da21310cdfd26b91a01641e`；Java `CodeReview_Mall_Platform_Java@test/test@0f1a55718ebc1987affb8bf245106e809dd51da4`。

## 一、页面上下文、权限和范围

| 项 | SDK/Portal 事实 |
| --- | --- |
| 菜单路径 | `/dashboard/history-archive/list` |
| 页面权限 | `/dashboard/history-archive` |
| HTTP 实例 | `platform`；SDK 使用 `/hr/...` 逻辑路径，由实例补 Portal 的 `/admin-api` 前缀；`/org/staff/getCustomInfo` 同样走默认平台实例 |
| `module-type` | 页面无法推导模块类型，SDK 为 `null`，不主动发送该请求头 |
| 页面形态 | `org`/`people` 两个页签，默认 `org`；顶部列表 `styleV2` 分页默认 1/20，页面支持 10/20/50/100 |
| 查询范围 | 当前会话、租户、菜单权限和服务端历史归档数据范围；SDK 不从浏览器提取凭据 |

本页是只读查询。页面实际可达的后续链路只有组织架构树分页/搜索/导出、历史员工列表/详情和 `hr_staff` 自定义列读取；不登记快照执行、归档删除、旧的完整树接口、普通员工自定义导出或当前员工写入接口。Java 源码没有这些方法的局部 `@PreAuthorize`，SDK 不把注解缺失解释为无权限限制，真实可见性仍由会话、租户、网关/全局安全和数据隔离共同决定。

## 三、逐字段基准与表单规则

### 3.1 组织归档和人员快照列表

Portal 两个顶部列表都把公共页码字段改为 `page`，默认请求参数分别是：

```text
order=&orderField=&archiveDate=null&page=1&pageSize=20
order=&orderField=&snapshotMonth=null&page=1&pageSize=20
```

平台请求层会从最终查询串中省略 `null`，但保留空字符串；`order`/`orderField` 是公共列表固定发送的空字段，不是 SDK 暴露的排序开关。日期选择器只产生 `YYYY-MM-DD`，月份选择器只产生 `YYYY-MM`；SDK 在请求前拒绝无效日历日期、非法月份和非 10/20/50/100 的列表页大小。

组织归档行的关键字段是 `id`、`archiveDate`、`archiveTime`、`archiveType`、`orgCount`、`operator`；组织列表接口由后端固定 `archiveType=1` 并按归档日期倒序。人员快照行的关键字段是 `id`、`snapshotMonth`、`snapshotTime`、`staffCount`、`operator`，后端按快照月份倒序。`id` 作为后续 `archiveId`/`snapshotId`，Java Long 序列化为字符串时必须原样保留。

### 3.2 历史员工筛选和分页

Portal 历史员工列表的默认表单是 `staffName=''`、`staffCode=''`、`status=''`、`mobile=''`、`postName=''`、`orgId=''`。它不覆盖公共页码字段，因此员工接口沿用 `pageNo/pageSize`：

```text
order=&orderField=&staffName=&staffCode=&status=&mobile=&postName=&orgId=&pageNo=1&pageSize=20
```

筛选规则如下：

| 页面字段 | 请求字段 | SDK 规则 |
| --- | --- | --- |
| 姓名 | `staffName` | 字符串模糊筛选；省略时发送空字符串 |
| 员工号 | `staffCode` | 数字或数字字符串；Java 按 `Long` 精确解析 |
| 在职类型 | `status` | `job_status` 字典值 1 在职、2 离职、3 退休、4 返聘、5 在编不在岗；空值发送空字符串 |
| 手机号 | `mobile` | 精确筛选；默认空字符串 |
| 岗位 | `postName` | 字符串模糊筛选；默认空字符串 |
| 组织筛选 | `orgId` | 历史组织 ID；后端展开该快照月份的历史下级组织；空值发送空字符串 |
| 分页 | `pageNo/pageSize` | 默认 1/20；页面支持 10/20/50/100 |

SDK 保留服务端原始员工行字段，并校验 `id`、姓名、工号、状态、组织路径、岗位和手机号的基本形状。`organization`、`post` 允许为 `null`。DTO 中声明但当前快照 SQL 未填充的 `salaryLevelName`、`leaderName`、`insuranceCostName`、`postTypeName`、`otherPostsName` 等名称扩展字段不能从底层 ID 推断存在。

### 3.3 历史员工详情和自定义列

`getStaffDetail` 的 `snapshotId` 和 `staffId` 必须来自同一条页面链路；后端没有匹配记录时返回 `null`，Portal 展示“未找到该员工的历史详情”，不能把 `null` 改成空对象。非空详情按 Portal 的基本信息、组织信息、薪酬信息、兼职信息、联系方式、学历信息和其它信息分段消费；`contractList` 和 `workList` 是快照生成时保存的历史内容，不代表当前员工可编辑数据。

`getCustomInfo` 固定发送 `tableName=hr_staff`，返回 `tableName`、`customColumnsInfo` 以及服务端可能返回的 `customExportColumns`/`customQueryColumns`。当前历史员工页面只把 `customColumnsInfo` 交给列控制器，不因此开放普通员工导出或把自定义查询列追加为历史员工筛选参数。

### 3.4 历史组织树、搜索和导出

组织树使用一次性投影上下文。首次根请求可省略令牌，Portal 固定每页 20 个节点；响应必须保存 `projectionToken` 和 `archiveDate`。后续根分页、下级加载和搜索都原样复用同一令牌。节点字段为 `id`、`parentId`、`name`、`code`、`managerId`、`managerName`、`hasChildren`、`sort`；搜索命中还带 `ancestorPath[]`，用于按祖先链定位。

搜索关键字必须去首尾空白后非空且不超过 100 字。令牌必须是同一 `archiveId` 根请求返回的 1 至 64 字符值；投影过期、令牌变化或跨归档复用时应重新从根初始化，不能把令牌当永久凭据。

导出只接受 Portal 菜单的 `drawio-vertical`、`drawio-horizontal` 和 `text`，并要求当前投影令牌及选中的 `rootId`。SDK 返回 `{ fileName, contentType, byteLength, base64 }`；纯文字文件保留 UTF-8，Draw.io 文件保留 XML。Portal 还会检查纯文字结尾的 `总节点数: N` 或 Draw.io 的 `</mxfile>`，SDK 不把空文件或非二进制错误响应报告为成功导出。

## 四、操作步骤、失败处理和验证边界

1. 先调用 `listOrganizationArchives` 或 `listStaffSnapshots`，只使用当前页返回的归档/快照 ID。
2. 组织链路先用 `organizationTreePage({ archiveId })` 建立投影，再按返回令牌调用下级分页、搜索或导出。
3. 人员链路使用同一 `snapshotId` 调 `listStaff`，再用选中行的 `id` 调 `getStaffDetail`；需要恢复列显示时单独调 `getCustomInfo`。
4. 空分页表示当前筛选无记录；详情 `null` 表示目标快照中没有匹配员工。权限、租户、网络、参数转换或响应结构错误均抛错，不降级为空结果。
5. 本页没有写入能力，因此没有 `prepare → submit → cancel` 写闭环；导出是只读文件回执。真实门户读请求、真实权限差异和导出内容仍需在后续环境验证中单独记录。
