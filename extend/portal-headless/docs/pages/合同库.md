# 合同库（`/dashboard/contract/library/list`）

人力域合同库列表、详情、操作记录、补充协议、签订证明、模拟修改和作废能力。Portal、Java 与 SDK 按本页逐项核对。

## 页面标识

| 项 | 值 |
| --- | --- |
| 菜单路径 | `/dashboard/contract/library/list` |
| 菜单名 | 合同库 |
| 菜单/路由权限 | `/dashboard/contract/library` |
| 列表文件 | `app/portal/views/dashboard/hr/contract/library/list.vue` |
| 详情文件 | `app/portal/views/dashboard/hr/contract/library/detail/[id].vue` |

| module-type | **15 风险防控**，按页面路径推导 |
| HTTP 实例 | `platform` |
| 页面形态 | 分页列表 + 只读详情 + 条件操作弹窗/编辑预览 |
| SDK 能力 | `contract-library-*` 共 14 项 |

## Portal 页面行为

列表通过 `GET /hr/contract/page` 查询，默认筛选对象为 `name/typeId/startDate/endDate/signDate/status` 全部 `null`；日期参数按 `YYYY-MM-DD` 发送，分页由 Portal 的 `pageNo/pageSize` 传递。状态下拉使用 1 至 16 的合同状态字典，切换状态会重新查询。列表结果是分页对象，至少包含 `list` 和 `total`，行数据中的 `id` 是后续详情和操作的唯一定位。

列表可达操作逐行核对如下：详情跳转到合同详情；下载动作先读详情再打开打印页，并不调用独立文件下载接口；操作记录读取 `/hr/contract/getContractOperate`；补充协议和签订证明分别读取对应信息并按弹窗规则保存；作废确认调用 `/hr/contract/voidContract/{id}`。状态为 1 草稿或 3 审核驳回时，Portal 不显示作废下拉项；状态为 16 作废时，不显示补充协议和签订证明入口。

详情页读取 `/admin-api/hr/contract/get?id=...`，使用 ContractCraft 只读渲染合同内容；状态为 1、2、3 时禁用详情页操作按钮。编辑入口只在开发/测试环境存在，预览保存调用 `/hr/contract/updateContractByCommon`。

## 表单、权限和数据规则

- 页面权限是 `/dashboard/contract/library`，请求使用当前会话和当前租户；`module-type` 固定由本页推导为 15。SDK 不把页面权限、租户或数据范围校验下沉为调用方自定义参数。
- 列表筛选字段是合同名称、合同类型、签订日期、生效日期、终止日期和状态；日期只接受 `YYYY-MM-DD`，状态只能是 1 至 16。空筛选按 Portal 的 `null` 语义发送，不能把未填写日期编造成当前日期。
- 合同编辑第一步的必填字段是 `name`、`typeId`、`organizationId`、`contractTemplateId`；请求字段按 Portal 映射为 `templateId`。内容必须是 Portal 预览可解析的 JSON 字符串，至少包含 `version` 和 `blocks`，块 ID 唯一且必须有封面、目录位置；变量 `dataList.contractKey` 去空格后不能重复。
- 补充协议保存体是 `{ contractId, nextUrl, nextUrlName }`。每项文件必须有非空 URL 和名称；已有签订证明时 Portal 不允许删除已有补充协议文件。
- 签订证明的 `fileList`、`signDate`、`startDate`、`endDate` 均必填；已有签订证明时弹窗只读，不应再次提交。保存体是 `{ contractId, nextImg, nextImgName, signDate, startDate, endDate }`。
- 作废是不可逆动作，只能从最新状态判断是否可执行；提交路径含 ID，请求体仍按 Portal 原样发送 `{ params: { id } }`。成功不能只看 `true`，必须回查合同状态为 16、`isVoid=1` 并读取操作记录。
- Java 作废服务当前将操作记录 `operateType` 写为 3，和页面语义的作废类型不一致；SDK 说明和测试记录这一后端事实，不擅自改写为 5。
- 后端没有 `requestId` 幂等键。所有写入超时先按合同 ID 回查，未确认前不得盲目重复提交；更新回执不是完整合同详情，必须再次调用详情能力。

## 后端与 SDK 对齐

Java `ContractController` 提供分页、详情、补充协议、签订证明、操作记录、作废和通用更新接口；`ContractServiceImpl` 的通用更新在当前状态为 2 待审核时拒绝，并按 `onlySave` 记录操作。`ContractOperateServiceImpl` 负责补充协议状态推进、签订证明状态推进和作废状态写入。`ContractDO` 继承租户基类，操作记录按合同 ID 分页。

SDK 在 `src/capabilities/contract-library.ts` 中集中实现请求、表单校验、状态门槛、响应解析和回查指引；`src/catalog/contracts-contract-library.ts` 为 14 项能力提供实际 `catalog.describe(id)` 返回的 AI 说明。SDK 的更新能力返回后端回执 `{ id, code, contractVersionId, onlySave }`，不会把部分回执冒充完整详情。

### `contract-library-list`

按 Portal 合同库筛选条件读取当前用户可见的合同分页列表。

执行：`sdk.contractLibrary.list`；性质：read。操作 Portal「风控管理 → 合同库」列表、详情或合同编辑/附件弹窗。

- 边界：页面路径是/dashboard/contract/library/list，权限是/dashboard/contract/library；请求使用 platform HTTP 实例和 module-type=15（风险防控），调用方不要另拼页面上下文。
- 边界：列表可见筛选只有 name、typeId、signDate、startDate、endDate、status；日期按YYYY-MM-DD发送，status是1至16的页面状态，默认值均为null，分页默认pageNo=1、pageSize=20并发送空order/orderField。
- 边界：合同编辑第一步要求 name、typeId、organizationId、contractTemplateId；预览提交还要求 content 是含 version/blocks 的JSON字符串、block id/name/data有效且变量contractKey去空格后唯一。更深组件规则仍由 Portal 和 Java 校验器共同执行。
- 边界：补充协议和签订证明的文件字段都是按下标对应的逗号字符串；签订证明未保存时日期和至少一个文件均必填，已有签订证明时 Portal 弹窗只读；已有签订证明的合同不能删除已有补充协议。
- 边界：列表只在 status 不是1草稿且不是3审核驳回时显示作废；作废接口的请求体按 Portal 原样是 { params: { id } }。后端当前把作废操作记录为 operateType=3，读取记录时按后端实际值解释。
- 边界：写操作没有 requestId 幂等协议；超时必须先用详情、列表或操作记录回查，不要盲目重发。true、回执或 HTTP 成功都不是最终业务证据。

| 参数 | 意义与来源 |
| --- | --- |
| name | 合同名称筛选；省略时按 Portal 初始 null 发送。；来源：用户明确输入 |
| typeId | contract_type 分类字典叶子节点 ID；省略时为 null。；来源：用户从合同类型树确认的叶子节点 |
| signDate | 签订日期筛选，YYYY-MM-DD；省略时为 null。；来源：用户明确日期 |
| startDate | 生效日期筛选，YYYY-MM-DD；省略时为 null。；来源：用户明确日期 |
| endDate | 终止日期筛选，YYYY-MM-DD；省略时为 null。；来源：用户明确日期 |
| status | 合同状态筛选；只能是1至16，省略时为 null。；来源：用户明确状态 |
| pageNo | 从1开始的页码；Portal 默认1。；来源：调用方分页位置 |
| pageSize | 每页条数；Portal 默认20。；来源：调用方分页设置 |

返回：`{ list: object[], total: number }`。list=[] 表示当前页没有合同；total=0 表示当前筛选没有合同，不等同于没有权限。

- list[].status：合同状态；1至16的值见状态表；{"1":"草稿","2":"待审核","3":"审核驳回","4":"待签署","5":"合同签署完成","6":"合同成立（未生效）","7":"合同成立（生效）","8":"正常履行","9":"部分履行","10":"履行抗辩","11":"变更履行","12":"正常终止","13":"协议终止","14":"单方解除","15":"其他终止","16":"作废"}
- list[].isReplenishment：是否已有补充协议；1=有、0=无；{"0":"无","1":"有"}
- list[].isSignCertificate：是否已有签订证明；1=有、0=无；{"0":"无","1":"有"}
- list[].isVoid：是否作废；1=是、0=否；{"0":"否","1":"是"}

- 消费：用 list[].id 作为详情、下载数据、操作记录、补充协议、签订证明、模拟修改和作废的唯一定位；需要全集时继续翻页覆盖 total。
- optional：需要查看或写入某份合同 → `contract-library-get`。先读取同一合同的最新详情，不使用可能过期的列表行直接提交。 映射：{"id":"list[].id"}

完成条件：返回当前筛选的一页合同和 total；查询不修改数据。

- 失败处理：字段必填、日期、ID、内容结构、文件删除限制、合同状态、权限、租户、网络或响应形状错误原样抛出；不把空列表、true 或修改回执单独当作最终业务完成。

- **仍有缺口**：已完成 Portal/Java 逐页源码核对与离线请求断言；尚未在真实测试环境执行本页每条写链的 prepare→submit→回查→cancel/清理。

逐字段嵌套结构、可空性、格式及证据由同一 describe 返回；完整生成参考见 ai-contract-reference.generated.md。
