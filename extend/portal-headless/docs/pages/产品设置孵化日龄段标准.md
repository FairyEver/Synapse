# 产品设置孵化日龄段标准

页面路径：`/dashboard/product/setting/standard-manage/egg-standard-age-stage/list`。

## 页面能力定义

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询列表 | `product-setting-egg-standard-age-stage-list` / `productSettingEggStandardAgeStage.list` | `GET /egg/standardAgeStage/page` |
| 准备新建 | `product-setting-egg-standard-age-stage-prepare-create` / `productSettingEggStandardAgeStage.prepareCreate` | 不发请求 |
| 新建 | `product-setting-egg-standard-age-stage-create` / `productSettingEggStandardAgeStage.create` | `POST /egg/standardAgeStage/save` |
| 准备编辑 | `product-setting-egg-standard-age-stage-prepare-update` / `productSettingEggStandardAgeStage.prepareUpdate` | 不发请求 |
| 编辑 | `product-setting-egg-standard-age-stage-update` / `productSettingEggStandardAgeStage.update` | `POST /egg/standardAgeStage/save` |
| 准备删除 | `product-setting-egg-standard-age-stage-prepare-remove` / `productSettingEggStandardAgeStage.prepareRemove` | 不发请求 |
| 删除 | `product-setting-egg-standard-age-stage-remove` / `productSettingEggStandardAgeStage.remove` | `DELETE /egg/standardAgeStage/{id}` |

页面属于 `门户 → 系统设置 → 生产设置 → 标准库管理`，不是独立顶层生产系统。请求使用 `product` HTTP 实例，固定追加 `devicetype=PC`，不发送 `module-type`。菜单权限为 `/dashboard/frame/standard-library/egg-standard-age-stage`。

Portal 页面声明了 `base:egg-standard-age-stage:query` 和 `base:egg-standard-age-stage:submit`；页面实际用 `permissionCheck(permissions.submit)`控制新增、编辑和删除，查询没有单独调用 query 权限检查。SDK保留该权限事实，服务端仍执行当前会话的实际权限校验。

## 参数契约与表单提交规则

列表是 `useListPageModule({ styleV2: true, customLoad, getDataListIsPage: true })`，默认请求参数为：

```json
{
  "order": "",
  "orderField": "",
  "moulting": 0,
  "stage": "",
  "pageNo": 1,
  "pageSize": 20
}
```

`moulting` 为 `0=否、1=是`；`stage` 在 Java Mapper 中按前缀筛选；分页支持 `10/20/50/100`。页面切换换羽单选项时会直接触发查询。

新建和编辑弹窗的 `moulting`、`stage`、`begin`、`end` 均必填；起止日龄范围为 `0` 到 `10000000`。提交时 `begin` 和 `end` 使用 `Number()` 转换，示例请求体为：

```json
{
  "moulting": 1,
  "stage": "1-7日龄",
  "begin": 1,
  "end": 7
}
```

编辑提交先展开 `...props.raw`，所以 SDK 的 `prepareUpdate()` 保留列表行的 `updateByName`、`updateDate` 以及其他扩展字段，再覆盖可编辑字段和ID。用户取消新建、编辑或删除确认时只丢弃本地草稿，不发送写请求。

## 逐字段基准

| 字段 | 含义 |
| --- | --- |
| `id` | 孵化日龄段标准记录ID；编辑和删除目标。 |
| `moulting` | `0` 否、`1` 是。 |
| `stage` | 日龄段名称；Java setter 会去除首尾空白。 |
| `begin` / `end` | 母鸡起始日龄、终止日龄。 |
| `updateByName` | 最后修改人；服务层根据 `updateBy.id` 查询HR用户名称。 |
| `updateDate` | 最后修改时间。 |
| `total` | 当前筛选条件下的总记录数。 |

SDK保留后端返回的页面无关扩展字段，但不把它们当作页面业务字段；网络、权限、Java业务错误或响应结构错误会抛出，不降级为空列表。

## 逐页操作步骤、权限与证据边界

1. 用 `list()` 读取最新列表，确认目标行的 `id`、日龄段和起止日龄。
2. 新建先调用 `prepareCreate()`；编辑调用 `prepareUpdate()`，确认 `draft` 保留当前行ID和所需raw字段。
3. 用户明确确认后，把同一 `draft` 原样交给 `create()` 或 `update()`；成功或响应不确定后重新调用 `list()` 回查。
4. 删除先调用 `prepareRemove({ id })`，用户确认后调用 `remove({ id })`；成功或响应不确定后重新查询，确认目标ID不再出现。

本轮逐页核对了 Portal 菜单、列表、弹窗、product HTTP、权限声明与实际调用、Java `StandardAgeStageController`/`StandardAgeStage`/`StandardAgeStageServiceImpl`/Mapper、SDK请求和离线反证测试。尚未在真实测试环境使用浏览器会话执行列表、`prepare → submit → 回查`及删除闭环；`updateByName`的真实HR名称补充结果仍需在线验证。
