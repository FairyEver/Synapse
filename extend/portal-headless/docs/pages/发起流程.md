# 发起流程（`/dashboard/flow/task/create/list`）

审批管理域「我的流程」四页里的第一页，也是**这四页里唯一不是列表页**的一页：
它是一张流程定义的**卡片墙**。四件套的其它三件分别在：
能力定义与参数契约 → `src/capabilities/flow-task.ts`；逐字段基准 → `baseline/flow-management.browser.json`；
回归测试 → `test/flow-management.test.ts`。

这一页在**别的线里已经被引用过多次**、但一直没有自己的能力入口：`docs/process-forms.md`
整份文档讲的就是"怎么用这一页的接口枚举出全部 82 个流程表单"，
`docs/plan.json` 的「不在清单里的入口」写着流程表单「由「发起流程」页的能力动态列出（设计 D9）」——
这一份就是把那个入口落地。

## 页面标识

| 项 | 值 |
| --- | --- |
| 菜单路径 | `/dashboard/flow/task/create/list`（菜单标题「发起流程」，域 `flow`） |
| 权限码 | `/dashboard/flow/task/create`（比菜单路径少 `/list`） |
| 路由文件 | `app/portal/views/dashboard/hr/flow/task/create/list/index.vue` |
| 清单行 | `page-catalog.json` 的 `5e7066`，`kind` = 其他/自定义页面，`write` = false |
| 菜单来源 | `app/portal/menus/hr.js:247` |
| module-type | **没有** —— `resolveModuleType()` 匹配不到任何规则，`matchedBy: 'none'`；基准里浏览器**同样不发这个头** |
| http 实例 | **全局默认的 `platform.js`**（页面 `index.vue:105` 显式 import） |
| 形态 | **不是列表页**：不走 `useListPageModule`，没有 `order` / 分页 / `getDataListURL` |
| 写操作 | 点卡片 → 走流程表单（写操作本身在表单页里，见「尚未覆盖」） |

## 这一页在干什么

页面挂载时打**一条**请求，拿到「当前用户能发起的全部流程定义」，然后：

- 顶部一个 `a-segmented`（流程类型）+ 一个搜索框；
- 有搜索词：所有卡片拉平、按名字本地过滤；
- 没有搜索词：按**分类**分组渲染卡片，另有「最近使用」chips（那是 `localStorage`
  的 `flow-task-create-recent`，纯前端状态，无头不涉及）。

点一张卡片走 `openFlowForm()`：跳 `/dashboard/flow/form/edit?…`（`bpmMode: 'edit'`），
把 `processDefinitionKey` / `formCustomCreatePath` / `formType` / `baseUrl` 带过去。

## 逐字段基准

基准文件：`baseline/flow-management.browser.json` 第 1 条（打开页面时自动发的一条）。

```text
GET https://biz-api-test.wodecorp.cn/admin-api/bpm/process-definition/create-list
    ?suspensionState=1&processType=1&_t=<ts>
```

请求头（**没有 `module-type`**）：`tenant-id` / `token` / `Accept-Language: zh-CN` /
`Accept: application/json, text/plain, */*`。

参数只有**两个**，顺序即字面量顺序（`index.vue:218-223` 的 `params: {...}`），
**没有 `order` / `orderField`，也没有分页** —— 这一页不是列表模块。

### 三个必须记住的点

**1. 两个 `processType` 都要拉，只拉一个会漏掉一大半。**
取值来自平台字典 `bpm_process_type`（`getPlatformDictListByType('bpm_process_type', true)`，
页面默认 `ref(1)`）。【实测，来自 `docs/process-forms.md` §1.2】字典两个值
`1 = 审核`（25 个流程）、`2 = 审批`（57 个流程），合计 **82 个**。

**2. `suspensionState=1` 是页面硬编码的**（只要启用中的流程），所以 SDK **钉死、不开放**。
页面上没有"看停用流程"的入口，开放它会造出一个用户到不了的状态。

**3. 返回的是「分类数组」，不是扁平列表。**
`data` 是 `[{code, name, processDefinitionList: [...]}]`。每张卡片的
`formCustomCreatePath`（表单路径，形如 `simple/hr/form/033`）**只有这个接口返回** ——
`GET /bpm/process-definition/get` 里那个字段是 `null`（实测，见 `docs/process-forms.md` §3.4）。

## 参数契约

| 参数 | kind | 必填 | 说明 |
| --- | --- | --- | --- |
| `processType` | enum | 否 | 1=审核（默认）/ 2=审批。**两个都要试** |
| `suspensionState` | — | — | **钉死 1，不开放** |

请求参数的**顺序是契约的一部分**（D20 逐字段一致）：`suspensionState, processType, _t`。
调用方实参的书写顺序不影响结果（实现按固定字面量拼）。

### 卡片可用性判定（SDK 侧也导出成函数了）

页面自己对每张卡做一次判定（`hasError()`，`index.vue:178-185`），不满足的渲染成**红色**并带 tooltip。
四条判据**同时**成立才算可用：

```text
baseUrl === 'portal'
formType === 20
formCustomCreatePath 非空
formCustomCreatePath 以 'simple/' 开头
```

【实测】这 82 个**全部满足**（页面上没有红色卡片）。无头没有"红色卡片"这个信号，
所以 SDK 把它做成了 `isUsableProcessDefinition()` / `describeProcessDefinitionError()`
（后者逐字复刻页面的 tooltip 文案：「项目错误」「类型错误」「空地址」「地址错误」）。

## 操作步骤

```text
1. 进入「发起流程」（/dashboard/flow/task/create/list）
2. （可选）顶部切「审核 / 审批」——这是 processType=1 / 2
3. （可选）搜索框输入关键字——那是纯前端本地过滤，不发请求
4. 点一张卡片 → 跳到 /dashboard/flow/form/edit?... 填表并提交
```

第 3 步是**本地过滤**（`flatFilteredList` computed），SDK 不提供：
调用方自己 `listDefinitions()` 拿到清单后按 `name` 过滤即可，与页面等价。

## 真实验证

- **基准来自真实环境**：2026-09-21 由 `bsk` 在 `https://webtest01.wodecorp.cn/portal.html#/` 抓到，
  后端 `https://biz-api-test.wodecorp.cn`（`baseline/flow-management.browser.json` 第 1 条）。
- **契约与基准逐字段一致**：`test/flow-management.test.ts` 有一条用例比有序的 `[key, value]`，
  另有「这一页不是列表页（键只有三个）」「两个 processType 都发得出去」「`suspensionState` 改不动」
  「四条可用性判据的真值表」「tooltip 文案」各一条。
- **没做**：SDK 对真实后端的**冒烟**（本波不跑浏览器、也没有这一页的 smoke 脚本）。
  基准证明了"浏览器发的是什么"，但 SDK 自己发出去那一次**没有**在真实环境跑过。

## 尚未覆盖

- **写操作：提交流程**。点卡片之后走的是流程表单（`/dashboard/flow/form/edit`），
  写操作落在**各流程自己的业务控制器**上（`POST /bpm/process-instance/...`），
  不在这一页的接口里。流程表单那条线的授权边界（`docs/plan.json`）只覆盖
  **流程表单的提交**，与这一页的枚举能力无关，所以这里一条写都没做。
- **重新发起流程（`?processInstanceId=` 深链）**：页面在这条路径上会多打
  `GET /bpm/process-instance/get` 找定义，再复用 `bpmBusinessKeyLast`。
  该接口**已有能力** `task-action-instance`（同接口、同参数 `{id}`），
  所以**不重复建**；调用方拿 `taskAction.instance(id)` 之后用本能力的 `listDefinitions()`
  按 `key` 匹配即可——那正是页面 `findProcessDefinitionByKey()` 干的事。
- **「最近使用」的持久化**（`localStorage` 的 `flow-task-create-recent`）没做：纯前端状态。
- **页面的 sessionStorage 状态恢复**（`usePageState.js`：把 `processType` 与 `searchKeyword`
  存进 `flow-task-create-list-page-state`，刷新时恢复、reload 时清）没做。
  SDK 的调用是无状态的，**刻意不模拟**这一层。
- **`route.query.processInstanceId` 那条路径上的错误分支**（流程实例不存在 / 流程定义不存在时的
  `message.error` 文案）只从源码读出，没有构造数据验证。

## SDK AI 说明契约（2026-09-22）

本节由当前 SDK 描述结果整理；说明权威来源为 `src/catalog/contracts-business.ts`。调用 `catalog.describe(id)`（或 `id-llm`）可得到参数来源、返回字段/状态、数据消费与后续映射；`catalog.describePage(页面路径)` 用于选择页面功能。以下更新以本节为准；前文历史请求/实测记录仍保留其记录日期。

### `flow-task-create-definitions`

获取当前用户能发起的审核/审批流程定义分类，供选择业务表单；本次不发起流程。

- 执行：`sdk.flowTask.listDefinitions`；通过 `capabilities.invoke('flow-task-create-definitions', args)` 调用时按 `params` 填参。性质：read。
- 参数：`processType` 可选 (string | number)。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`object[]`。[] 表示本次查询没有条目；这是数组，不读取 list/total。
- 字段：`[].code`、`[].name`、`[].processDefinitionList`、`[].processDefinitionList[].id`、`[].processDefinitionList[].key`、`[].processDefinitionList[].name`、`[].processDefinitionList[].formType`、`[].processDefinitionList[].baseUrl`、`[].processDefinitionList[].formCustomCreatePath`、`[].processDefinitionList[].category`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：先按分类 name 再选 processDefinitionList[].name；流程 key 与版本 id 不可互换。需要全范围时分别 processType=1 审核和 2 审批。 可用表单要求 baseUrl=portal、formType=20、formCustomCreatePath 非空且 simple/ 开头；即使符合页面要求，也需 catalog.describePage/路由下钻判断该表单是否已有 SDK 实现。
- 完成条件：查询任务完成于展示候选；发起任务必须继续到对应表单 prepare/submit 并取得业务回执。
- 后续：required → `catalog.describePage`：根据表单路径获取已实现能力，选择其 definition/prepare/submit 链；目录没有已实现能力时明确说明不支持，不调用相似表单代替。（pagePath ← [].processDefinitionList[].formCustomCreatePath）
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。


验证：`test/ai-contract-business.test.ts` 直接检查 SDK 描述输出及业务夹具；本批未重放真实写操作。逐能力状态、证据与反证见 [补齐清单](../ai-contract-business-evidence.md)。
