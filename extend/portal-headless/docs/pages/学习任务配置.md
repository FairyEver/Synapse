> ⚠️ **这一页不是列表页。** `generated/page-catalog.json` 把它标成「其他/自定义页面」是对的：

## 参数契约

**一个参数都没有。** 页面写的是 `http.get(CONFIG_URL)` —— 连 config 都没传
（与任务类型配置页相反，那里是 `list(params = {})` 的显式空对象），
所以 URL 上只有客户端补的 `_t`：

| 字段 | 默认 | 谁给的 |
| --- | --- | --- |
| `_t` | 时间戳 | 客户端（GET 防缓存） |

返回的是一个**对象**（后端 `CommonResult<KpiStudyTaskConfigDTO>`），字段：

| 字段 | 含义 | 后端类型 |
| --- | --- | --- |
| `weeklyProgressPercent` | 周课堂每节进度比例 | `Integer`（DTO 默认 25） |
| `morningProgressPercent` | 晨课堂每节进度比例 | `Integer`（DTO 默认 5） |
| `weeklyFlowerBaseline` | 周课堂基准花朵 | `Integer`（DTO 默认 6） |
| `weeklyBonusScoreLimit` | 周课堂自动超额上限 | `Integer`（DTO 默认 2） |
| `status` | `0` 禁用 / `1` 启用 | `Integer` |

页面拿到后会把 `status` 强行 `Number(…)`、其余原样铺进表单。

## 真实验证

- **基准**：`baseline/perf-manage-template.browser.json` 那条与能力构造的 URL 逐字段一致。
- **回归测试**：`pnpm vitest run test/perf-manage-template.test.ts`。
- ⚠️ **没做**：真实后端冒烟（不开浏览器、不取凭据）—— 所以**这份配置的真实现值没有打出来过**，
  上面的字段表是从页面表单 + 后端 DTO 读的。

## 保存规则与验证边界

SDK 已接入保存请求，但尚未在真实测试环境写入。接口是
`POST /performance/protocol/kpimonthprotocol/study-task-config`，
  body 就是上面那五个字段（`KpiStudyTaskConfigDTO`）。
  页面的表单校验：两个比例**都必填**，且 `0 < x <= 100`（`validatePercent`，不满足时
  红字是「比例需大于0且不超过100」）。
- ⚠️ **页面与后端类型不一致**：两个比例在前端是
  `a-input-number :precision="2"`（**允许两位小数**），而后端 DTO 字段是 **`Integer`** ——
  真填 `12.5` 是否被接受需以真实接口为准；SDK 不擅自四舍五入。
- `weeklyFlowerBaseline` 页面最小值为 0，但后端当前校验要求大于 0；传 0 会被服务端拒绝。
- 保存成功后必须重新 GET 逐字段核实；接口没有 requestId，不要在超时后换新请求盲目重发。
- 这一页没有其它写入口（没有新建/删除/导入）。

能力目录同时提供 `perf-manage-study-task-config-prepare-save`、
`perf-manage-study-task-config-save`、`perf-manage-study-task-config-cancel-save`；目录调用的保存能力接收
prepare 返回的 `draft`，直接门面方法 `saveStudyTaskConfig(update)` 仍接收五字段对象。两种入口最终发送同一
五字段 POST，均要求保存后重新 GET 回查。

### `perf-manage-study-task-config-save`

按学习任务配置页提交五个字段，保存晨/周课堂进度、基线、奖励上限与启用状态。

执行：`sdk.perfManageTemplate.saveStudyTaskConfig`；性质：write。按学习任务配置页提交五个字段，保存晨/周课堂进度、基线、奖励上限与启用状态。

- 边界：接口是 POST /performance/protocol/kpimonthprotocol/study-task-config，无查询参数，body 固定五个字段。
- 边界：Portal 输入框允许比例和奖励上限出现小数，但 Java DTO 是 Integer；真实提交前必须按后端可接受类型处理，SDK 不擅自四舍五入。
- 边界：Portal 对 weeklyFlowerBaseline 的最小输入值为 0，而后端校验要求大于 0；传 0 会由服务端拒绝。

| 参数 | 意义与来源 |
| --- | --- |
| draft | prepare-save 返回的完整五字段草稿；来源：perf-manage-study-task-config-prepare-save.result.draft；必须一起提交，百分比大于0且不超过100，weeklyFlowerBaseline满足后端大于0，status只能是0/1 |

返回：`null | undefined`。正常空回执；必须重新读取配置核实保存值。


- 消费：保存成功后调用 perf-manage-study-task-config-get，逐字段比较五个值；不要用“保存成功”字符串替代读回核实。

完成条件：按上述数据消费规则交付查询结果；本能力的读取到此结束。

- 失败处理：百分比或后端 Integer 反序列化校验失败时按原错误修正，不把后端拒绝解释成保存成功。
- 失败处理：网络超时先重新读取配置；接口没有 requestId，不要换新请求盲目重发。
