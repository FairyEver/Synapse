## 参数契约：列表**零参数**

页面就是 `http.get(url)`（`protocol-deduct-rule/api.js:5-9`），**没有 params**：

```js
export function getProtocolDeductRuleList() {
  return http.get(`${BASE_URL}/list`, { silenceOnError: true })
}
```

⇒ URL 上除 `_t` 外**什么都没有**，参数表是**空的**（刻意，不是漏了）。
`silenceOnError: true` 只影响页面的 toast（它自己渲染错误卡片），
无头侧错误照样抛，所以能力里不体现。

| 方法 | 接口 | 参数 |
| --- | --- | --- |
| `listProtocolDeductRules()` | `GET …/protocol-deduct-rule/list` | 无 |
| `getProtocolDeductRule(ruleCode)` | `GET …/get` | `ruleCode`（后端 `@NotBlank`） |
| `listProtocolDeductRuleHistory(ruleCode)` | `GET …/history` | `ruleCode`（同上） |

`ruleCode` 是**固定六条**（页面本地常量 `RULE_METADATA` 的键，与后端注解一致）：

```
YEAR_PROTOCOL_SIGN / YEAR_PROTOCOL_REVIEW / MONTH_PROTOCOL_SIGN
MONTH_PROTOCOL_REVIEW / MONTH_PROTOCOL_SELF_EVALUATION / MONTH_PROTOCOL_SCORE
```

后端的 `/list` 接口注释写的就是"查询**固定六条**协议考核扣分规则"。

### 值的枚举是页面本地常量（不是字典）

逐字抄 `protocol-deduct-rule/rule-utils.mjs`（能力文件里也导出了这四个）：

| 字段 | 取值 |
| --- | --- |
| `periodType` | 1 年度 / 2 月度 |
| `deadlineType` | 1 固定日期 / 2 每月最后一天 / 3 次月固定日 |
| `calculationMode` | 1 固定扣一次 / 2 每个逾期自然日累计 |
| `deductTarget` | 1 员工本人 / 2 直属上级 |

`ruleName` / `unmetDescription` 后端可能不给，页面会按 `ruleCode` 从本地
`RULE_METADATA` 补文案 —— 补的是**展示文案**，本能力原样返回接口给的东西。
生效周期那块页面兼容了两种字段名（`effectiveYear ?? configEffectiveYear`），
其中 `1970` 表示**初始版本**。

⚠️ **这一族接口带 `@PreAuthorize("@ss.hasPermission('hr:performance-config:manage')")`**
（三条 GET 都有）⇒ **403 是可能的**，而菜单可见性判不出它（conventions 第 15 条）。
别拿"侧边栏里有这一页"预判可调。

## 逐字段基准

（`baseline/perf-manage-config.browser.json` 的 `protocol-deduct-rule/list` 那条，`_t` 已归一）

```
GET /admin-api/performance/basedata/protocol-deduct-rule/list?_t=<ts>
```

**与源码推导逐字段一致**：URL 上**只有** `_t`。

基准里**没有** `get` / `history` 两条 —— 它们只有点开抽屉才发（基准抓的是页面挂载）。
本能力把两条都做了（`ruleCode` 排在最前、`_t` 在最后），并在测试里钉住了键序。

## 保存规则与验证边界

SDK 已接入页面编辑抽屉的更新请求，但尚未在真实测试环境写入。请求是
`PUT /performance/basedata/protocol-deduct-rule/update`，body
  `{ruleCode, enabled, deadlineType, deadlineMonth, deadlineDay, calculationMode, singleScore, maxScore, version}`
  （页面的 `buildUpdatePayload()`；`version` 是**乐观锁**，冲突码 `1010002001`
  → 页面提示「规则已被其他人修改，请刷新后重新编辑」）。
改的是**全公司的扣分口径**，一次误写会改所有人的绩效分。

- 年度规则只能使用 `deadlineType=1` 并保留月份/日期；月度规则的月份必须为 `null`，每月最后一天的日期必须为 `null`。
- 固定扣一次时页面把 `maxScore` 归一为 `singleScore`；累计模式要求最高扣分不小于单次扣分。
- 页面还校验分值格式和年度日期（2 月按 29 天算）；后端 DTO 继续做最终校验。版本冲突或超时都要先读回，不要盲目覆盖。

## ⚠️ 实测：这一页**必报 403**「没有该操作权限」（2026-09-21）

真机冒烟实测：三条 GET（`/list`、`/get`、`/history`）全部返回
**「没有该操作权限」**。后端给这三条都挂了
`@PreAuthorize('hr:performance-config:manage')`。

**这正是 conventions 第 15 条说的那种情况**：菜单树不是权限裁决 ——
这一页在菜单里看得见，但**菜单可见性判不出这个权限码**，所以"能打开页面"与"能调接口"是两回事。

调用方拿到 403 时的正确反应是**如实告诉用户没有这个权限**，不要重试、也不要换参数试。
冒烟里这条**按预期报错处理**。

### `perf-manage-protocol-deduct-rule-list`

- 边界：使用当前 SDK 用户与租户的数据权限；页面上下文由 SDK 绑定，调用方不要另拼 module-type。

| 参数 | 意义与来源 |
| --- | --- |

### `perf-manage-protocol-deduct-rule-update`

更新一条固定协议考核扣分规则；保存启用状态、截止日期、扣分方式与乐观锁版本。

执行：`sdk.perfManageConfig.updateProtocolDeductRule`；性质：write。更新一条固定协议考核扣分规则；保存启用状态、截止日期、扣分方式与乐观锁版本。

- 边界：接口是 PUT /performance/basedata/protocol-deduct-rule/update，后端权限为 hr:performance-config:manage；页面菜单权限不能替代接口权限。
- 边界：年度规则 deadlineType 只能为 1 并保留 deadlineMonth/deadlineDay；月度规则 deadlineMonth 必须为 null，deadlineType=2 时 deadlineDay 为 null。
- 边界：固定扣一次模式 Portal 会把 maxScore 改成 singleScore；累计模式要求 maxScore 不小于 singleScore。Web 单次扣分最小值为 0.01，但后端 DTO 允许 0，SDK 不替页面偷偷放宽或补值。

| 参数 | 意义与来源 |
| --- | --- |
| ruleCode | 固定六条规则编码；来源：perf-manage-protocol-deduct-rule-list.rules[].ruleCode |
| enabled | 是否启用；来源：当前规则详情；保留 Portal 表单归一后的值 |
| deadlineType | 截止类型：1 年度固定日期、2 每月最后一天、3 次月固定日；来源：当前规则详情；保留 Portal 表单归一后的值 |
| deadlineMonth | 年度月份；月度必须为 null；来源：当前规则详情；保留 Portal 表单归一后的值 |
| deadlineDay | 年度或次月固定日；每月最后一天必须为 null；来源：当前规则详情；保留 Portal 表单归一后的值 |
| calculationMode | 计算方式：1 固定扣一次、2 每个逾期自然日累计；来源：当前规则详情；保留 Portal 表单归一后的值 |
| singleScore | 单次/每日扣分；来源：当前规则详情；保留 Portal 表单归一后的值 |
| maxScore | 累计模式最高扣分；固定模式由 Portal 归一为 singleScore；来源：当前规则详情；保留 Portal 表单归一后的值 |
| version | 乐观锁版本；来源：当前规则详情；保留 Portal 表单归一后的值 |

返回：`object`。后端返回更新后的规则 DTO；缺失字段按服务端返回原样处理，不自行补展示文案。

- periodType：周期；{"1":"年度","2":"月度"}
- deductTarget：扣分对象；{"1":"员工本人","2":"直属上级"}
- deadlineType：截止日期类型；{"1":"固定日期","2":"每月最后一天","3":"次月固定日"}
- calculationMode：计算方式；{"1":"固定扣一次","2":"每个逾期自然日累计"}

- 消费：更新成功后调用 perf-manage-protocol-deduct-rule-list 或 getProtocolDeductRule，按 ruleCode 读回并核对目标字段与新 version。

完成条件：按上述数据消费规则交付查询结果；本能力的读取到此结束。

- 失败处理：版本冲突业务码为 1010002001；重新读取最新详情并由用户决定合并，不盲目覆盖。
- 失败处理：校验失败按 Portal/后端原始规则修正；网络超时先读回，接口没有 requestId，不要换新请求重建。
