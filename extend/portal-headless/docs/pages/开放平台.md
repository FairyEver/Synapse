# 开放平台（`/dashboard/platform/setting/open-interface/list`）

## 能力定义

本页属于 Portal 保留范围中的「平台设置 → 开放平台」，不是独立的生产、销售或其他业务系统入口。Portal 顶层 wrapper 复用「人工智能 → 开放接口」的列表和表单组件，但菜单路径、菜单权限和页面能力上下文独立登记：

| 项 | 值 |
| --- | --- |
| 菜单路径 | `/dashboard/platform/setting/open-interface/list` |
| 菜单权限 | `/dashboard/platform/setting/open-interface` |
| 列表 wrapper | `app/portal/views/dashboard/platform/setting/open-interface/list.vue` |
| 表单 wrapper | `app/portal/views/dashboard/platform/setting/open-interface/[mode]/[id].vue` |
| 共享实现 | `app/portal/views/dashboard/platform/intelligence/prompt/interface/**` |
| 后端前缀 | `/admin-api/system/openApiRegistry` |
| HTTP 实例 | `platform` |
| `module-type` | 不发送；当前页面规则推导结果为 `null` |

SDK 用 `platform-open-interface-*` 六个能力覆盖该入口，执行时复用 `aiPromptTool.openApiRegistry` 的同一套实现，不复制一份请求组装逻辑。逐页源码、菜单、后端和绑定检查见 [test/platform-open-interface.test.ts](/Users/liyang/Documents/code/github/portal-headless/test/platform-open-interface.test.ts)。

## 页面动作与能力

| capabilityId | SDK 执行路径 | Portal 动作 | 类型 |
| --- | --- | --- | --- |
| `platform-open-interface-list` | `aiPromptTool.openApiRegistry.list` | 分页、名称/状态/开放状态筛选 | 只读 |
| `platform-open-interface-get` | `aiPromptTool.openApiRegistry.get` | 查看/编辑前读取详情 | 只读 |
| `platform-open-interface-scan` | `aiPromptTool.openApiRegistry.scan` | 扫描导入候选接口 | 只读；无匹配时业务错误 |
| `platform-open-interface-create` | `aiPromptTool.openApiRegistry.prepareCreate` | 新建登记 | prepare；submit 才写入 |
| `platform-open-interface-update` | `aiPromptTool.openApiRegistry.prepareUpdate` | 编辑登记 | prepare；submit 才写入 |
| `platform-open-interface-remove` | `aiPromptTool.openApiRegistry.prepareRemove` | 删除登记 | prepare；submit 才写入 |

三个写能力均遵守 `prepare → submit → cancel`。新建没有直接可用的新 ID，删除没有恢复接口；修改的撤销体来自同一次详情读取。列表行 `isBound` 为真时，Portal 删除按钮前端拦截；SDK 不把这个页面行快照伪装成服务端并发锁。

## 请求与返回

Portal 实际请求为：

```text
GET    /admin-api/system/openApiRegistry/getByPage
GET    /admin-api/system/openApiRegistry/get/{id}
GET    /admin-api/system/openApiRegistry/scanByUrl
POST   /admin-api/system/openApiRegistry/create
POST   /admin-api/system/openApiRegistry/update
DELETE /admin-api/system/openApiRegistry/delete/{id}?id={id}
```

列表只投影 `pageNo`、`pageSize`、`name`、`status`、`enabled`；空 `name` 仍发送为 `name=`，空 `status`/`enabled` 被省略。返回是 `{ list, total }`，`list[]` 是登记记录，不是目标接口的执行结果。

详情和扫描结果带参数树。扫描结果还没有登记主键，不能直接作为技能 `apiIds`；必须先按用户确认的候选准备新建、提交后回查登记 ID。

## 表单提交规则

Portal 保存前校验：

- `name` 必填，只允许中文、英文、数字、下划线，最多 50 个字符；
- `httpMethod`、`apiPath`、`groupName`、`scopeKey`、`description`、`sort` 必填；
- `apiPath` 必须是 `http` 或 `https` 绝对 URL；
- 参数树按页面的 `validateParamTree` 校验；已填写节点必须有名称、位置和说明，必填叶子参数必须有测试值，测试值最多 800 字符；
- `show-enabled` 使 `enabled` 出现在列表和表单中，值只按 `0/1` 提交。

保存请求体按 Portal 顺序组装：

```json
{
  "name": "",
  "apiPath": "",
  "httpMethod": "GET",
  "scopeKey": "",
  "groupName": "",
  "description": "",
  "responseExample": "",
  "sort": "1",
  "status": 0,
  "enabled": 0,
  "params": []
}
```

修改请求在末尾追加 `id`。参数树提交会过滤空节点，并按同级下标重新计算 `sort`；`required` 归一为字符串布尔值。不能把后端详情树未经页面规则处理后直接当成稳定提交体。

“测试”按钮不是 SDK 的登记 CRUD：Portal 用浏览器原生 axios 请求调用方填写的目标地址，并在已有记录上把测试状态和返回示例再提交一次更新。SDK 的开放平台能力不开放一个可向任意地址发请求的通用入口；需要登记时仍只走上述 prepare/submit 写链路。

## 权限规则

页面权限码是 `/dashboard/platform/setting/open-interface`。后端 `OpenApiController` 的普通登记 CRUD 没有统一的 `@PreAuthorize`；服务层只对企业微信 Webhook 地址做特殊权限校验：创建、修改、删除 Webhook 必须具备该权限，无权限读取时会隐藏 Webhook key。普通开放接口的管理权限不能从页面名称推断成后端对所有记录的统一拦截，SDK 不擅自加一层请求前检查。

这条差异必须保留：Portal 的 `record.isBound` 删除拦截是页面规则，Webhook 权限是后端特殊规则，二者都不能泛化成“所有开放接口都能删”或“所有开放接口都由 SDK 预授权”。
