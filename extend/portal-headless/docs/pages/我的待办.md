# 我的待办（`/dashboard/urge/my-todo-urge/list`）

本页覆盖 Portal「人力 → 督办事项 → 我的待办」列表、详情读取、完成弹窗提交，以及列表页实际可达的「发起督办」和「详情」路由准备。它是督办业务，不是 BPM 待办；发起督办页面本身和「我的督办」列表属于后续页面节点。

证据边界：已逐字段核对 Portal 列表、详情、完成组件、督办公共工具和 Java Controller/VO/Service/Mapper；SDK 请求投影、完成载荷、输入边界和 AI 说明有离线测试。当前没有启动测试门户，未把真实读请求、附件上传、完成写入及回查写成真实环境证据。

来源锚点：Portal `CodeReview_Projects_Js@test/portal/main@acab69acc77b6d6c0da21310cdfd26b91a01641e`；Java `CodeReview_Mall_Platform_Java@test/test@0f1a55718ebc1987affb8bf245106e809dd51da4`。

## 三、参数、显示和提交规则

### 3.1 列表

Portal 初始筛选为：`taskName=null`、`endDate=null`、`isComplete=0`、`pageNo=1`、`pageSize=20`。请求参数还固定带 `order=''`、`orderField=''`，SDK 保持同样的字段和值：

| 参数 | 页面含义 | 规则 |
| --- | --- | --- |
| `taskName` | 督办内容 | 文本筛选；空值按 Portal 初值发送 `null` |
| `endDate` | 完成时间 | `YYYY-MM-DD`；空值不筛选 |
| `isComplete` | 待办/已办 | `0=待办事项`、`1=已办事项`；默认 `0` |
| `pageNo` / `pageSize` | 分页 | 默认 `1/20`；页面选项为 10/20/50/100 |

请求的逻辑 URL 为 `GET /hr/supervisee/page`。待办列显示 `taskName`、`superviseeList[].superviseeName`、紧急程度、`endDate`、未完成提示和详情/完成操作；已办列隐藏提示和完成操作。紧急程度为：`1=重要紧急`、`2=不重要紧急`、`3=不重要不紧急`、`4=重要不紧急`。`tip` 由后端生成为 `已逾期:N天`、`剩余:N天` 或 `剩余:0天`。

### 3.2 详情

调用 `getTaskInfo({ overseeTaskId })` 时发送 `GET /hr/supervisee/getTaskInfo`，参数名映射为 `{ taskId: overseeTaskId }`。详情根记录包含任务内容、计划日期、紧急程度、当前用户完成状态和 `isCanComplete`；`superviseeList[]` 包含负责人、完成状态、完成日期、完成说明、附件 URL/名称和 `isCanEdit`。

创建人可看到负责人完成信息；普通负责人只能把自己 `isCanEdit=1` 的记录作为完成/修改输入，其他负责人的 `completeDetails` 可能被后端隐藏。任务根 `isComplete` 表示当前用户记录的状态，不等于所有负责人都完成。

### 3.3 完成表单和附件

Portal 完成组件声明 `remark` 必填、最多 500 字，上传控件最多 5 张图片、单张最大 6 MiB，并立即通过 `base-upload-file` 上传到 `Portal/public`。但确认按钮是普通按钮，`actionComplete()` 直接调用 POST，没有执行 `formValidate()`/`formTriggerSubmit()`；所以空说明实际会进入请求。SDK 保留这个实际行为：`remark` 省略或 `null` 转为空字符串，只限制最多 500 字。

提交前先调用：

```text
prepareComplete({ overseeTaskId, remark?, fileList? })
  → 用户确认
complete({ draft })
  → getTaskInfo({ overseeTaskId: draft.overseeTaskId }) 回查
```

草稿严格投影为：

```text
{
  url: fileList.join(','),
  isComplete: 1,
  completeDetails: remark,
  completeDate: YYYY-MM-DD,
  overseeTaskId
}
```

不发送 `urlName`，不把附件对象或本地文件路径放入完成请求。SDK 的 `completeDate` 按 `Asia/Shanghai` 当天生成；Java 服务实际用服务端 `LocalDate.now()` 覆盖日期。Java 完成接口按「任务 ID + 当前登录用户」更新，并且无当前用户负责人记录时仍可能返回 `true`，因此 `true` 只是接口回执，不能替代回查。

## 四、操作步骤、失败处理和回查

1. 用 `list` 查询当前用户的待办或已办任务。
2. 用列表记录的 `overseeTaskId` 调 `getTaskInfo`，确认当前用户负责人行仍未完成且可编辑。
3. 附件先走公共上传能力；调用 `prepareComplete` 生成草稿。
4. 用户确认后调用 `complete`。
5. 无论成功还是超时，都用同一 `overseeTaskId` 调 `getTaskInfo`，核对当前用户负责人行的 `isComplete=1`、完成说明和附件；所有负责人都完成时再检查任务根状态和列表。
6. 用户取消时丢弃草稿；Portal 已上传的附件不会因取消弹窗自动删除。

会话、租户、权限、网络、业务错误和响应结构错误均抛出。空列表表示当前用户筛选结果为空，不表示没有权限。不能把 `overseeTaskId` 当成 BPM `taskId`，也不能复用 `flowTask`/`taskAction` 能力。
