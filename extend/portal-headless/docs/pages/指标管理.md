# 指标管理

## 能力定义

- 页面：`/dashboard/manage/indicator/list`
- 菜单权限：`/dashboard/manage/indicator`
- HTTP 实例：`platform`；页面推导 `module-type=13`，能力定义不覆盖该页面推导值
- 能力 ID：`perf-manage-indicator-list`、`perf-manage-indicator-prepare-save-data`、`perf-manage-indicator-save-data`、`perf-manage-indicator-cancel-save-data`，以及既有导入、启停、删除能力

## 既有列表基准

`listIndicators(query)` 调用 `GET /performance/basedata/kpitarget/page`，Portal 首屏参数顺序为 `order → orderField → name → creatorName → targetType → type`，不发送 `pageNo/pageSize`，返回树节点数组而不是 `{ list, total }`。`targetType` 是服务端实际筛选，名称需要对返回树做本地筛选；导入、启停、删除能力保持原有定义。

## 参数契约

指标详情页的 Portal 提交逻辑先取出 `actualTarget`、`forecastTarget`，再追加当前指标 ID：

```ts
{
  actualTarget: {
    year: number,
    targetDataList: Array<{
      lineType?: string,
      lineName?: string,
      formula?: string,
      dataList?: number[],
      forecastIndicator?: number,
      floatRatio?: number,
      assessmentStandards?: number,
      expected?: number
    }>
  },
  forecastTarget: {
    year: number,
    targetDataList: Array<Record<string, unknown>>
  },
  targetId: string | number
}
```

`prepareIndicatorDataSave` 只做本地字段和年份/数组校验；Portal 在预测行数不等于 1 时要求每行 `formula !== ''`，SDK 保留该前置校验。`submitIndicatorDataSave({ draft })` POST `/performance/basedata/kpitarget/saveData`，不改成 `{ids}` 或其它包装；`cancelIndicatorDataSave()` 为本地取消。

## 逐字段基准

Portal `indicator-data.vue` 和 `indicator-data-bat.vue` 都使用 `platform` 实例，并执行：

```js
const data = pick(indicatorState.value, ['actualTarget', 'forecastTarget'])
http.post('/performance/basedata/kpitarget/saveData', {
  ...data,
  targetId: indicatorState.value.id
})
```

Java `KpiTargetController` 的 `@PostMapping("saveData")` 接收 `SaveTargetDataDTO`，字段为 `targetId`、`forecastTarget`、`actualTarget`；嵌套 DTO 分别包含 `year/targetDataList` 和指标行字段。Service 会校验预测公式、删除该指标对应年度旧数据、写入预测与实际数据并按实际年度计算薪资。

菜单权限存在；保存方法上的 `@RequiresPermissions("basedata:kpiprofit:save")` 当前是注释状态，没有有效的接口权限注解。SDK 不据此绕过菜单或服务端鉴权。

## 操作步骤

1. 从当前指标详情读取或由页面表单构造 `actualTarget`、`forecastTarget` 和 `targetId`。
2. 调用 `prepareIndicatorDataSave`，向用户展示将覆盖的预测/实际年度及公式。
3. 用户确认后调用 `submitIndicatorDataSave`。
4. 成功回执只表示请求完成；应重新读取指标详情或列表确认年度数据，超时先回查再重试。
5. 用户取消时调用 `cancelIndicatorDataSave`，不发请求。
