## Portal 页面行为

筛选表单有五个字段：

| 控件 | 参数 | Portal 规则 |
| --- | --- | --- |
| 月份 | `yearMonth` | 月份选择器，格式 `YYYY-MM`，默认当前月份，未来月份禁用 |
| 组织 | `organizationIdList` | 角色组织树多选，未选择时发送 `[]` |
| 姓名 | `name` | 初始值 `null`，输入值原样发送 |
| 工号 | `staffCode` | 初始值 `null`，输入值原样发送；后端按工号模糊匹配 |
| 是否上传附件 | `isUploadFile` | `null` 不筛选，`1` 已上传，`0` 未上传 |

列表使用 `customLoad` 调用 `POST /org/hrWorkSchedule/getAbsentUserList`。`getDataListIsPage: true` 时，列表模块把排序、表单和分页合并为：

```json
{
  "order": "",
  "orderField": "",
  "yearMonth": "2026-09",
  "organizationIdList": [],
  "name": null,
  "staffCode": null,
  "isUploadFile": null,
  "pageNo": 1,
  "pageSize": 20
}
```

列表返回的 `type` 只是 `absent_type` 字典原码，页面通过字典渲染中文标签；`absentResourceId` 是否为空决定是否显示附件入口。行上有 `processInstanceId` 时，详情按钮跳转流程实例详情，否则打开本地详情弹窗。SDK 保留 `absentId` 与 `processInstanceId` 的区别，不能互换。

详情调用 `GET /org/hrWorkSchedule/getAbsentUserInfo?absentId=<absentId>`。`amPm === 1` 显示“上午”，其它非空值显示“下午”；附件用 `absentFileList[].url` 预览、`name` 展示。后端对不存在的记录可能返回空对象，SDK 将其解释为没有可展示的详情。

上传弹窗只在当前行没有 `absentResourceId` 时显示。附件先通过已有 `base-upload-file` 上传到 `HR/risk` 目录，页面只接受 `application/pdf`，最多 10 项；随后提交：

```json
{
  "absentFileList": [{ "url": "https://oss.example/a.pdf", "name": "a.pdf" }],
  "absentId": 18
}
```

页面生成的 `id8()` 只是本地列表 key，不会提交给后端。上传成功后后端创建 OSS 资源并写回 `absent_resource_id`；若异常记录存在 `processInstanceId`，还会同步该流程中的相关异常记录。由于接口没有业务回执，不能把 HTTP 成功直接当作附件已经生效，必须用详情或列表回查。

## 后端与权限核对

Java `HrWorkScheduleController` 在 `org/hrWorkSchedule` 下提供 `getAbsentUserList`、`getAbsentUserInfo` 和 `uploadAbsentFile`。列表服务按月份计算日期范围，按组织展开子组织，叠加姓名、工号、附件状态、员工有效性和当前用户 `DataScope`；查询还排除不属于缺勤统计的记录。

详情服务按 `absentId` 查询异常关联员工，使用 `absent_type` 字典生成 `typeName`，并在存在资源 ID 时读取附件 URL 和名称。上传服务消费 `AbsentFileDTO.absentFileList` 的 `url/name`，创建资源后更新缺勤记录及同流程记录的资源 ID。

组织候选复用 `contractSupport.roleOrganizationSearch({ scope: 'attendance', keyword })`。Portal 组件会拉角色组织树；无头调用必须先要关键字，再在 SDK 本地限量过滤，提交时只把用户确认的 `list[].id` 组成 `organizationIdList`。

### `attendance-exception-list`

按月份、角色组织、姓名、工号和附件状态查询当前用户数据范围内的异常考勤员工分页列表。

执行：`sdk.attendanceException.list`；性质：read。操作 Portal「组织管理 → 考勤管理 → 异常统计」页面的列表、详情和异常附件入口。

- 边界：页面权限是/dashboard/attendance/attendance-exception；请求使用 platform HTTP 实例和 module-type=11。
- 边界：列表的“考勤异常情况”只返回类型原码；要展示中文标签，使用 base-dict-get(dictType=absent_type)，不要猜枚举。
- 边界：组织筛选复用 contractSupport.roleOrganizationSearch({ scope: "attendance", keyword })；无头调用必须先按关键字取得候选，不能直接拉全量角色组织树。
- 边界：上传能力只提交已上传 OSS 的 { url, name }；页面上的本地 id8 是前端列表 key，不是后端附件资源 ID，SDK 不把它伪造成业务 ID。
- 边界：上传是实际写操作，后端会创建 OSS 资源记录并替换缺勤记录的 absent_resource_id；若该记录有 processInstanceId，后端还会同步同流程的相关异常记录。

| 参数 | 意义与来源 |
| --- | --- |
| yearMonth | 月份选择器值，YYYY-MM；页面默认当前月份且禁选未来月份。；来源：用户明确选择的月份 |
| organizationIdList | 角色组织树多选结果的组织 ID 数组；未筛选时发送 []。；来源：contractSupport.roleOrganizationSearch({ scope: "attendance", keyword }) 的 list[].id；用户确认选择后组成数组；候选：contract-support-role-organization-search list[].id |
| name | 姓名模糊筛选；初始值为 null，保留用户输入。；来源：用户输入的姓名 |
| staffCode | 工号模糊筛选；页面是文本输入，后端把可解析值绑定为 Long。；来源：用户输入的工号文本 |
| isUploadFile | 附件状态筛选；null不筛选、0只看未上传、1只看已上传。；来源：用户选择的页面下拉值 |
| pageNo | 从1开始的页码；页面默认1。；来源：调用方分页状态 |
| pageSize | 每页条数；页面支持10、20、50、100，默认20。；来源：调用方分页状态 |

返回：`{ list: object[], total: number }`。list=[] 表示当前页没有记录；total=0 才表示筛选范围没有记录。权限、会话、网络或响应形状错误会抛出，不降级为空页。


- 消费：用 total 判断继续翻页；absentId 是详情/上传的目标 ID，processInstanceId 是流程实例 ID，二者不可互换。
- 消费：用 absentResourceId 是否为空展示附件状态；用 base-dict-get(dictType=absent_type) 将 type 原码映射成标签。
- optional：用户要看某条异常详情且 list[].absentId 非空 → `attendance-exception-detail`。用同一行的 absentId 查询详情，不要把 userId 或 processInstanceId 当作 absentId。 映射：{"absentId":"result.list[].absentId"}
- optional：用户要查看流程异常的审批表单且 list[].processInstanceId 非空 → `task-action-instance`。把流程实例 ID 交给流程实例详情能力；不要用它调用上传接口。 映射：{"processInstanceId":"result.list[].processInstanceId"}

完成条件：返回当前筛选的一页异常记录和 total；列表读取本身没有修改业务数据。

- 失败处理：月份格式/未来月份、附件数量/字段、ID、分页、权限、租户、网络或响应形状错误原样抛出；列表不能以空页替代权限失败。
- 失败处理：上传响应没有业务回执；请求完成后必须调用 detail 或重新 list 核实附件资源，不把 HTTP 成功当作数据库已生效。

- **仍有缺口**：已完成 Portal/Java 逐页静态核对与离线请求断言；尚未在真实测试环境执行异常列表、详情、PDF上传及流程记录同步回查。

### `attendance-exception-upload-file`

为一条异常考勤记录保存已经上传到 OSS 的 PDF 附件列表。

执行：`sdk.attendanceException.uploadFile`；性质：write。操作 Portal「组织管理 → 考勤管理 → 异常统计」页面的列表、详情和异常附件入口。

- 边界：页面权限是/dashboard/attendance/attendance-exception；请求使用 platform HTTP 实例和 module-type=11。
- 边界：列表的“考勤异常情况”只返回类型原码；要展示中文标签，使用 base-dict-get(dictType=absent_type)，不要猜枚举。

| 参数 | 意义与来源 |
| --- | --- |
| absentId | 缺勤记录 ID；来自列表行的 absentId，不是流程实例 ID。；来源：attendance-exception-list.list[].absentId |
| absentFileList | 待保存附件数组，1至10项，每项只有页面提交需要的 url/name；文件字节需先由 base-upload-file 上传。；来源：base-upload-file 返回的 url 与用户确认的文件名 |

返回：`undefined (Promise<void>)`。undefined 是 Portal uploadAbsentFile 成功响应的正常 SDK 表示，不是空列表或失败。

- required：POST 完成或响应超时 → `attendance-exception-detail`。回查同一异常记录，确认 absentFileList 中出现本次附件；超时不确定时先回查，未确认前不要重复提交。 映射：{"absentId":"args.absentId"}

完成条件：请求已完成且详情回查确认附件资源已保存；不能仅凭 Promise 完成报告数据库写入成功。

- 失败处理：月份格式/未来月份、附件数量/字段、ID、分页、权限、租户、网络或响应形状错误原样抛出；列表不能以空页替代权限失败。
- 失败处理：上传响应没有业务回执；请求完成后必须调用 detail 或重新 list 核实附件资源，不把 HTTP 成功当作数据库已生效。
