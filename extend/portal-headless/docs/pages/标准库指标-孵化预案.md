# 标准库指标（孵化预案）

## 能力定义

- 菜单入口：`系统设置 → 生产设置 → 孵化预案 → 标准库`的列表“查看标准”。菜单页路径为 `/dashboard/product/setting/hatchery-manage/lib/list`，隐藏指标页实际路径为 `/dashboard/product/setting/hatch-manage/lib/indicator/list`。
- 菜单/路由权限：`/dashboard/frame/hatchery-plan/lib`。隐藏页动作权限：查询 `program:suite-indicator:query`，新建/编辑 `program:suite-indicator:submit`，删除 `program:suite-indicator:delete`。
- HTTP 实例：`product`。该页没有可推导的 `module-type`，不发送该请求头。
- 该页由孵化预案标准库包装器复用养殖预案的指标组件；入口列表把 `suiteCode` 等 query 传给隐藏页。SDK 节点保持隐藏页的实际路径与请求，而不把它登记成新的菜单页。

## 参数契约

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询指标候选 | `product-hatchery-standard-indicator-trait-options` / `productHatcheryStandardIndicator.traitOptions` | `GET /programUnit/getTraitList`，参数 `classification=traitType` |
| 查询标准指标 | `product-hatchery-standard-indicator-list` / `productHatcheryStandardIndicator.list` | `GET /programNew/standardLib/getTraitPage` |
| 准备新建 | `...-prepare-create` / `prepareCreate` | 本地校验，不发请求 |
| 新建首次提交 | `...-create` / `create` | `POST /programNew/standardLib/createTrait`，`flag=0` |
| 新建冲突覆盖 | 同上 | 同一请求，用户确认后 `flag=1` |
| 准备编辑 | `...-prepare-update` / `prepareUpdate` | 本地校验，不发请求 |
| 编辑 | `...-update` / `update` | `POST /programNew/standardLib/editTrait`，`flag=1` |
| 准备删除 | `...-prepare-remove` / `prepareRemove` | 本地 ID 校验，不发请求 |
| 删除 | `...-remove` / `remove` | `GET /programNew/standardLib/deleteTrait?id=...` |
| 导出 | `...-export` / `exportData` | `GET /programNew/standardLib/exportStandardLib`，二进制响应 |

指标归类不是本页写死的枚举；Portal 从平台字典 `standard_class` 取候选，应调用已有 `base-dict-get`，把返回的 `value` 作为 `traitType`。指标名称候选依赖当前归类，动态请求返回 `code/name/contentType/unit/scale`，SDK 另补 Portal 下拉所需的 `label=name`、`value=code`。

列表筛选为 `traitType`、`traitCode`、`age`、`suiteCode`，请求固定带 `scope=1`、`order=''`、`orderField=''`、`pageNo`、`pageSize`；页面分页默认20，支持10/20/50/100。后端 `getTraitPage` 固定 `ageType=1`、`searchType=1`，只查指标归类22、23范围，并按 `suiteCode`、归类、编码和日龄筛选。

新建和编辑表单字段为 `suiteCode`、`traitType`、`traitCode`、`contentType`、`unit`、`scale`、`age`、`min`、`max`、`txt`。`contentType` 为1文本、2富文本、3数值；日龄范围为1至700；数值型要求 `min/max` 且 `min <= max`；文本/富文本内容必填，最大3000字符。Portal 新建先传 `flag=0`，Java 检测同标准库、指标和日龄冲突时返回冲突标记；只有用户明确确认覆盖才用同一草稿传 `flag=1`。

## 逐字段基准

### 动态候选

| 字段 | 含义 |
| --- | --- |
| `label` | 下拉展示文本，来自后端 `name`；不能代替提交编码。 |
| `value` | 下拉提交值，来自后端 `code`；回填 `traitCode`。 |
| `contentType` | 该指标的内容类型：1文本、2富文本、3数值。 |
| `unit` | 指标单位；没有单位时为 `null`。 |
| `scale` | 数值指标小数位；没有定义时为 `null`。 |

### 列表记录

SDK 返回 `{ list, total }`。`total` 是筛选结果总数，不是当前页长度。列表行保留 Java 扩展字段，并规范以下字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 标准指标记录 ID；编辑、删除必须使用它，缺失时为 `null`，不能用名称或编码猜测。 |
| `suiteCode` | 来源标准库业务编码；查询、导出和写后回查的范围。 |
| `traitCode` / `traitName` | 指标编码 / 展示名称。 |
| `traitType` / `traitTypeName` | 指标归类值 / Java 翻译后的名称。 |
| `age` / `ageType` | 标准生效日龄 / 日龄类型；本页查询固定 `ageType=1`。 |
| `contentType` / `contentTypeName` | 内容类型值 / 展示名称。 |
| `scale` / `unit` | 小数位 / 单位。 |
| `min` / `max` | 数值标准上下限；文本标准通常为 `null`。 |
| `txt` | 标准内容；富文本已按 Portal 内容提交，数值标准也可能保留文本表示。 |
| `flag` | Java 扩展字段；不单独作为写入成功证据。 |

### 写入与导出返回

- `prepareCreate` / `prepareUpdate` 返回 `{ draft }`，只代表本地校验通过；取消只丢弃草稿。
- `create` 返回 `{ status: 'submitted' }` 或 `{ status: 'conflict', flag: 1 }`。前者只是请求完成，后者明确表示尚未覆盖。
- `update`、`remove` 返回 `true` 只代表请求未抛错，不替代列表回查。
- `exportData` 返回 `{ fileName, contentType, base64, byteLength }`；Base64 是 Excel 二进制，不是业务字段。默认文件名为 `标准库标准.xlsx`。

## 操作步骤

1. 先用 `base-dict-get(dictType="standard_class")` 取得当前指标归类值，再用 `traitOptions({ traitType })` 取得指标编码候选。
2. 用隐藏页 query 中的 `suiteCode` 和用户筛选调用 `list()`；按 `total` 继续分页。
3. 新建或编辑先调用对应 `prepare`，向用户展示草稿并等待确认；取消不调用写能力。
4. 新建首次用 `create({ draft })`。返回 `conflict` 时说明同一标准库、指标和日龄已有记录；仅在用户明确确认覆盖后用同一草稿传 `flag=1`。
5. 编辑确认后调用 `update({ draft })`。删除先 `prepareRemove({ id })`，用户确认后调用 `remove({ id })`；不要把删除改成 DELETE，也不要用 `suiteCode` 替代记录 ID。
6. 写请求成功或响应不确定时，使用最近一次列表的 `suiteCode` 和筛选条件重新 `list()` 回查；未回查前不盲目重试，也不把 `true/submitted` 说成业务终态。
7. 导出按当前筛选调用 `exportData()`，将返回的 Base64 保存为 `fileName`。

## 证据与缺口

已核对 Portal 菜单、孵化预案包装器、复用列表、隐藏指标列表、指标弹窗和 product HTTP 实例；已核对 Java `StandardLibController`、指标 DTO/VO、`ProgramNewServiceImpl`、`ProgramLibMapper.xml`、`ProgramUnitLayController` 与指标候选 Mapper。离线测试锁定了页面路径、请求方法/参数、动态候选、新建冲突二阶段、编辑、删除、导出、权限和 AI 契约反证。

本次没有启动服务器或浏览器，也没有在真实测试环境执行动态候选、列表、新建冲突二阶段、编辑、删除、导出及写后回查；这些仍是未完成的真实环境证据。`standard_class` 的当前租户标签未实测，调用方必须以 `base-dict-get` 当前返回为准。后端没有 requestId 幂等包装，响应不确定时必须先回查。
