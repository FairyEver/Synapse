# 产品设置方法设置

页面路径：`/dashboard/product/setting/hatch-manage/method/list`。

菜单归属是 `系统设置 → 生产设置 → 养殖预案 → 方法设置`。这里的“生产设置”是系统设置内的 Portal 子菜单，不能与范围外的独立生产业务菜单混淆。

## 页面能力定义

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询方法设置 | `product-setting-hatch-manage-method-list` / `productSettingHatchManageMethod.list` | `GET /programUnit/getList` |
| 准备新建 | `product-setting-hatch-manage-method-prepare-create` / `productSettingHatchManageMethod.prepareCreate` | 本地表单校验，不发请求 |
| 新建 | `product-setting-hatch-manage-method-create` / `productSettingHatchManageMethod.create` | `POST /programNew/methodLib/createTrait` |
| 准备编辑 | `product-setting-hatch-manage-method-prepare-update` / `productSettingHatchManageMethod.prepareUpdate` | 本地表单校验，不发请求 |
| 编辑 | `product-setting-hatch-manage-method-update` / `productSettingHatchManageMethod.update` | `POST /programNew/methodLib/editTrait` |
| 准备删除 | `product-setting-hatch-manage-method-prepare-remove` / `productSettingHatchManageMethod.prepareRemove` | 本地确认前准备，不发请求 |
| 删除 | `product-setting-hatch-manage-method-remove` / `productSettingHatchManageMethod.remove` | `GET /programNew/methodLib/deleteTrait?id=...` |

请求使用 `product` HTTP 实例，补 `devicetype=PC`；本页没有页面推导出的 `module-type`，因此不发送该请求头。菜单权限是 `/dashboard/frame/breeding-plan/method`；查询、提交、删除权限分别是 `program:method:query`、`program:method:submit`、`program:method:delete`。SDK只复刻页面请求，不绕过服务端权限。

## 参数契约与提交规则

列表表单字段是 `classification`（方法归类）、`search`（方法名称），表单源码还保留固定字段 `scope=1`。公共列表模块加入 `order=""`、`orderField=""`、`pageNo` 和 `pageSize`；styleV2默认每页20条，页面支持10、20、50、100。`classification`在Portal规则中声明必填，但页面首次自动加载时仍会发空字符串，SDK保留该现状以对齐真实页面请求。

方法归类候选来自Portal全局平台字典 `method_class`，不是本页单独请求；需要候选时调用已有基础字典能力，不猜测字典值。列表返回 `list` 和 `total`，并保留后端原始扩展字段。

新建弹窗的 `traitType`（方法归类）、`name`（名称）、`title1`、`title2`、`title3` 五项全部必填。Portal新建时构造的对象含有 `id: undefined`，JSON序列化不会发送id；数字方法归类在弹窗中转成字符串后提交。编辑弹窗先从当前行回填：`traitType`优先取当前行 `traitType`，否则取 `classification`；`name`优先取 `name`，否则取 `traitName`。提交对象先展开当前行 `raw`，再覆盖 `id`、`traitType`、`name`、`title1`、`title2`、`title3`，因此SDK保留扩展字段。

Portal当前页面实际发送的是 `traitType/name/title1/title2/title3`，而不是另一个相似页面的 `ProgramUnit add/update`字段。SDK不会因为Java中存在相似接口就擅自替换页面接口。

## 逐字段基准

| 字段 | 含义 |
| --- | --- |
| `list` | 当前筛选条件和分页下的方法设置记录。 |
| `total` | 当前 `classification`、`search`、固定 `scope=1` 条件下的总数，不是当前页长度。 |
| `list[].id` | `/programUnit/getList`返回的ProgramUnit记录ID；页面编辑和删除都从该字段取值。 |
| `list[].classification` | 方法归类原始字典值；编辑回填 `traitType` 的备用字段。 |
| `list[].traitTypeName` | 方法归类展示文本；表格第一列。 |
| `list[].name` | 方法名称；列表和编辑回填的优先字段。 |
| `list[].traitName` | 方法名称备用字段；仅在 `name` 为空时用于编辑回填。 |
| `list[].title1` / `title2` / `title3` | 一级、二级、三级标题；编辑表单必填。 |
| `prepareCreate().draft` | 已通过五项必填校验、尚未发送请求的新建对象。 |
| `prepareUpdate().draft` | 已按Portal raw透传和字段覆盖规则整理、尚未发送请求的编辑对象。 |
| 写操作结果 `true` | 请求未抛错的本地确认，不代表服务端已按预期落库。 |

## 操作步骤、权限和证据边界

1. 使用当前用户会话和租户上下文调用 `list()`；需要筛选候选时先读取 `method_class` 字典。
2. 新建时调用 `prepareCreate()`，经用户确认后把同一份 `draft`交给 `create()`；取消只丢弃本地草稿。
3. 编辑时把最近一次列表行与用户修改结果交给 `prepareUpdate()`，经用户确认后把同一份 `draft`交给 `update()`；取消不发请求。
4. 删除前调用 `prepareRemove()`，明确获得用户确认后再调用 `remove()`；取消不发GET。
5. 新建、编辑或删除成功、失败或响应不确定后，都重新调用 `list()`回查；不能只依据 `true`宣布业务状态已改变。

本轮逐页核对了Portal菜单、路由、列表、弹窗、公共分页、product响应解包，以及Java `ProgramUnitLayController`、`MethodLibController`、DTO、Mapper和Service。当前没有真实测试环境浏览器会话的列表/新建/编辑/回查/删除闭环证据。

另有两个必须保留的前后端风险：Java `createTrait`要求 `age`并由服务按 `traitCode/age`写入 `fm_simu_program_lib`，与Portal当前五字段方法表单不一致；列表来自 `ProgramUnit.id`，而Java `editTrait/deleteTrait`按 `ProgramLib.id`处理。SDK保持Portal实际请求形状并在AI说明中披露该差异，不伪造写入成功，也不改发相似但不属于页面的接口。
