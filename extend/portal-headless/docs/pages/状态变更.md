## ⚠️ 这一页声明的 `getDataListURL` 是**死的**

源码里写的是 `getDataListURL: '/performance/protocol/kpimonthprotocol/page'`，
但同一个 options 对象里也有 `customLoad`，而 `common/libs/renren/list.js:485-494` 是**二选一**：

```js
if (customLoad) { result = await customLoad(params) } else { result = await _http.get(getDataListURL, …) }
```

`customLoad` 赢。它实际打的是（`list.vue:101-108`）：

```js
const url = agreementType.current === 1
  ? '/performance/protocol/kpimonthprotocol/othersPage'
  : '/performance/protocol/kpiyearprotocol/othersPage'
```

所以这一页**从来不**打 `/page`，而且**两个端点都是 `othersPage`** —— 它看的是"待我变更的协议"，
不是"我的协议"。基准 15 条请求里，本页只有一条，且就是 `othersPage`（`[0]`）。

## 参数契约

顺序逐字推自 `list.js:473-483`（`order → orderField → convertFetchForm 返回值 → pageNo → pageSize → _t`）。
本页**没有** `convertFetchForm`（默认钩子是恒等函数的 `createHook(e => e)`），所以
order 表 = `form` 字面量（`list.vue:93-100`）：

`order → orderField → year → month → status → creator → include → pageNo → pageSize → _t`

| 参数 | kind | 说明 |
| --- | --- | --- |
| `year` | text | 四位年份 `2026`（`picker="year"` + `value-format="YYYY"`） |
| `month` | enum | **数字 1~12**（值域读自 `monthOptionsMaker()`）。⚠️ 不是 `03` |
| `status` | text | 字典值，随月度/年度切换类型（`month_task_review_status` / `protocol_status`）。**取值域未实测** |
| `creator` | text | 创建人，模糊匹配 |
| `include` | number | 页面初值固定 `1`（包含自己），**没有对应控件** |
| `pageNo` / `pageSize` | number | 默认 `1` / `20`（`styleV2: true` → 20） |

`kind`（月度/年度）是**端点选择器、不是 URL 字段**，所以**不在 `params` 里**，
只作为方法的第一个入参（与 `study-statistics.ts` 的 `kind` 同一个处理）。

## 逐字段基准

无筛选时浏览器发的是（`baseline/perf-agreement.browser.json` `[0]`，`_t` 已归一）：

```
GET /admin-api/performance/protocol/kpimonthprotocol/othersPage
    ?order=&orderField=&year=&month=&status=&creator=&include=1&pageNo=1&pageSize=20&_t=<ts>
```

**与源码推导逐字段一致（含键顺序）**，一处修正都不需要。

⚠️ **年度那一支也会带 `month`**：`form` 里一直有这个键，而这一页**没有** `convertFetchForm`
去删它 ⇒ `kind='year'` 的 URL 键集与月度**完全相同**，只有端点不同。
这是页面的真实行为（`form` 字面量 + 恒等钩子），不是本能力的疏漏。

**没实测到的一处**：切换月度→年度时页面调 `rrList.initialize()`（重置表单），
但月份控件的 `a-form-item` 带 `v-if`，控件卸载后 antd 的 `resetFields()` 会不会把它清成 `''`
—— **没有验证**（基准只抓了初次加载那一跳）。本能力只保证"键一定在"，值由调用方给。

### `perf-agreement-change-list`

查询可做状态变更的所辖月度/年度协议；只查询，绝不实际变更状态。

- 执行：`sdk.perfAgreement.listAgreementChange`；通过 `capabilities.invoke('perf-agreement-change-list', args)` 调用时按 `params` 填参。性质：read。
- 参数：`year` 可选 (string)；`month` 可选 (string | number)；`status` 可选 (string)；`creator` 可选 (string)；`include` 可选 (number)；`pageNo` 可选 (number)；`pageSize` 可选 (number)。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`{ list: object[], total: number }`。list=[] 为当前页无记录；total=0 表示该筛选无结果。保留筛选条件检查页码，不将空结果解释成权限判定。
- 字段：`list`、`total`、`list[].id`、`list[].name`、`list[].year`、`list[].month`、`list[].promoterName`、`list[].creatorName`、`list[].signatoryName`、`list[].createTime`、`list[].status`、`list[].actionButtons`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：展示协议名、年月、创建人及签订人；按动态字典解释 status。actionButtons 仅用于解释页面可选动作，本组 SDK 没有签订、评分、撤销或状态变更写能力。
- 完成条件：在请求的数据范围交付协议列表；不要宣称签订/变更已完成。
- 后续：optional → `base-dict-get`：读取状态标签；变更页选择年度时改用 protocol_status（dictType ← context.protocolStatusDictType）
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。
