# 员工借款额度（`/dashboard/finance/setting/employee-loan-amount/list`）

Portal「财务设置 → 员工借款额度」是一个分页列表页，提供员工借款额度查询、Excel模板下载和Excel导入。本页没有详情、编辑、删除、导出或撤销按钮；Java 中存在但当前页面没有调用的端点不登记为本页 SDK 能力。

## Portal 页面行为

列表使用 `platform` HTTP 实例和 `useListPageModule({ styleV2: true, getDataListIsPage: true })`。默认表单与分页请求体逐字段为：

```json
{
  "order": "",
  "orderField": "",
  "employeeName": null,
  "phone": null,
  "organizationIds": [],
  "employeeTypes": [],
  "pageNo": 1,
  "pageSize": 20
}
```

页面可见筛选只有员工姓名、联系电话、所属组织多选和员工属性多选。`organizationIds` 是组织树 ID 数组；`employeeTypes` 来自 `employee_origin` 字典并按数字发送，Java 枚举为 `1=内部`、`2=外部`。页大小沿用页面组件的 10/20/50/100 选项。

页面表格逐列展示：`employeeName`、`employeeNo`、`idCardNo`、`genderName`、`age`、`organizationName`、`position`、`employeeTypeName`、`loanQuota`、`debtAmount`、`availableQuota`、`quotaPeriod`。服务端从借款额度和凭证分录计算 `debtAmount`，再计算不小于零的 `availableQuota`；SDK 不把这两个计算字段自行重算后覆盖服务端结果。

## 表单提交与文件规则

Portal 模板下载使用 `responseType: 'blob'`，固定文件名为 `员工借款额度导入模板.xlsx`。SDK 的请求层等价使用二进制 `arraybuffer`，返回文件名、Content-Type、字节数和 Base64，不将文件误当作 JSON。

导入文件控件的 `accept` 是 `.xml,.xlsx,.xls`；SDK `prepareImport` 只校验这三个扩展名、标准 Base64 和非空文件，并根据扩展名补齐 MIME。真正导入时构造 `FormData`，只追加一个名为 `file` 的文件字段，与 Portal 浏览器提交一致。

Java `EmployeeLoanQuotaExcelVO` 的模板列顺序固定为：

1. 员工姓名
2. 员工号
3. 身份证号
4. 联系电话
5. 性别
6. 年龄
7. 所属组织
8. 岗位
9. 员工属性
10. 借款额度
11. 额度有效期起始日期
12. 额度有效期结束日期

服务端逐行校验员工姓名、身份证号、借款额度、起止日期；身份证号必须符合 18 位规则，借款额度必须大于 0，起止日期必须为 `yyyy-MM-dd` 且起始日期不能晚于结束日期。同一文件内重复身份证号会进入失败列表。返回结构为 `successCount`、`failCount`、`failList[]`，失败项包含 Excel 行号、员工姓名、身份证号和原因。

最重要的业务规则是：只要导入文件中存在一条有效行，服务端会先删除当前租户的全部旧员工借款额度，再批量写入有效行；无有效行时不执行替换。Portal 页面只显示“导入成功”并刷新列表，没有删除、撤销、恢复旧文件或 cancel 接口。调用方必须在导入前获得用户对全量替换的确认，导入后再查询并逐字段核对，不能只依据 HTTP 成功或 `successCount` 报告落库成功。

## 权限与后端规则

- SDK 能力统一声明页面权限 `/dashboard/finance/setting/employee-loan-amount`、`moduleType=null` 和 `platform` 实例；按钮权限由调用方会话与后端裁决。
- 下载和导入共用 Portal 源码中的 `finance:setting:employee-loan-amount:download-template` 权限；没有凭据时不从浏览器页面提取 token/cookie。
- 查询只发送当前页面可见字段，不发送 Java `positionList`，也不把后端存在的不可达端点加入目录。
- Long ID 以字符串保留，金额 Decimal 以数字或十进制字符串保留；不因 JavaScript 数字精度而改写身份证号或主键。
- 导入超时后结果不确定，必须先重新查询并按身份证号、额度、有效期核对，再决定是否提交一份用户确认过的完整文件；不得盲目重传。
