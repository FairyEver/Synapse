# 工厂管理

## 1. 能力定义

- 菜单归属：门户 → 系统设置 → 销售设置 → 工厂管理。
- 页面路径：`/dashboard/sale/order/trade-storeroom/list`。
- 页面权限：`/dashboard/sale/frame/order/trade-storeroom`。
- module-type：`60`。
- 按钮权限：新建、编辑、删除和同步基地都检查 `order:tradeStoreroom:edit`。
- 这是保留的 Portal `系统设置` 子树页面，不是独立的生产根菜单，也不是“生产环境”能力。
- CRM 请求走 `httpCrm`（`VITE_CRM_API`），同步基地弹窗的组织树走 platform（`VITE_ZHDJ_PLATFORM_API`）。
- 页面没有详情路由；编辑直接使用当前列表行打开弹窗。后端存在但页面未调用的 `getByFactoryId`、`findStoreroomByIds` 不纳入 SDK。

对应 SDK 能力：

| capability | 作用 | 写入 |
| --- | --- | --- |
| `sale-trade-storeroom-list` | 按类型、名称、供应商和类别分页查询 | 否 |
| `sale-trade-storeroom-supplier-list` / `sale-trade-storeroom-company-list` | 读取表单候选 | 否 |
| `sale-trade-storeroom-factory-list` / `sale-trade-storeroom-base-list` | 读取父级工厂/基地候选 | 否 |
| `sale-trade-storeroom-organization-tree` / `sale-trade-storeroom-selected-base-list` | 读取组织树和已同步基地 | 否 |
| `sale-trade-storeroom-prepare-create` / `sale-trade-storeroom-create` | 准备并新建记录 | 后者是 |
| `sale-trade-storeroom-prepare-update` / `sale-trade-storeroom-update` | 准备并编辑记录 | 后者是 |
| `sale-trade-storeroom-prepare-remove` / `sale-trade-storeroom-remove` | 准备并删除单条记录 | 后者是 |
| `sale-trade-storeroom-prepare-sync-base` / `sale-trade-storeroom-sync-base` | 准备并覆盖同步基地范围 | 后者是 |

## 2. 参数契约

### 列表和候选

Portal 首次进入页面默认 `type: '0'`，列表请求发送：

```json
{
  "pageNo": 1,
  "pageSize": 20,
  "type": "0",
  "name": "",
  "shopName": "",
  "factoryKind": ""
}
```

请求为 `GET /vue/order/tradeStoreroom/list`，使用 CRM 的
`Content-Type: application/x-www-form-urlencoded`；CRM 返回 `{ list, count }`，SDK 对外返回
`{ list, total }`。`pageSize` 只接受 Portal 全局选项 `10/20/50/100`。

- `GET /vue/order/tradeStoreroom/getSupplier` 固定发送 `{ type: 1 }`，返回供应商店铺的 `shopId/shopName`。
- `GET /vue/order/tradeStoreroom/companyList` 返回发货工厂所属公司的 `id/name/code/type/valid`。
- `GET /vue/order/tradeStoreroom/findFactory` 发送 `{ factoryKind, supplier }`，用于库房/装运点的父级工厂。
- `GET /vue/order/tradeStoreroom/findBase` 发送 `{ factoryKind, shopId }`，用于工厂的父级基地；SDK 对外参数名为 `supplier`，请求字段按 Portal 改为 `shopId`。
- `factoryKind` 或供应商缺失时，Portal 不发上述级联请求，SDK 返回空数组。

列表类型、类别候选使用 Portal 的 `trade_storeroom_type`、`item_kind` 字典值；标签和原码不能混用。

### 组织树和已同步基地

- `GET /admin-api/sales/organization/tree` 使用 platform 实例。Portal 源码把 `isAll: true`、`isSalesTree: false` 放在 Axios 配置对象而不是 `params`，因此实际请求不附加这两个查询参数，SDK 保持这一行为。
- `GET /vue/order/tradeStoreroom/selectShippingBaseList` 使用 CRM 实例，返回已同步记录的 `hrOrgId/hrOrgName`；`hrOrgId` 才是组织树的勾选值，记录自身 `id` 不是组织 ID。
- `POST /vue/order/tradeStoreroom/saveShippingBaseList` 使用 CRM 表单编码，字段 `list` 是组织 ID 按逗号连接的字符串。后端先清空旧同步关系，再写入本次列表；空字符串表示用户确认清空。

### 表单、权限和提交

页面表单字段及规则：

| 字段 | 页面规则 | 提交含义 |
| --- | --- | --- |
| `id` | 新建为空；编辑必须保留当前行 ID | save 草稿主键 |
| `shopId` | 必填 | 供应商店铺 ID |
| `code` | 必填；`type=0` 时匹配 `/^[a-zA-Z0-9]{0,30}$/` | 记录编码 |
| `factoryKind` | 必填 | `item_kind` 字典值 |
| `name` | 必填 | 基地、工厂、库房或装运点名称 |
| `type` | 必填 | `trade_storeroom_type` 字典值 |
| `parentId` | 控件存在，但 required 规则被注释 | 当前父级 ID；可为空 |
| `companyOfficeId` | 仅 `type=1` 必填 | 发货工厂所属公司 ID |

新建和编辑都发送 `POST /vue/order/tradeStoreroom/save`，请求体只保留上述页面字段；列表中的日期、公司名称、公司编码、有效标记等展示字段不能拼回请求。删除发送：

```text
DELETE /vue/order/tradeStoreroom/delete?id=<id>&type=<type>
```

删除必须同时传当前列表行的 `id` 和 `type`。保存、删除和同步接口的成功回执没有页面消费的新 ID，SDK 返回 `undefined`；不能把 Promise 完成当成已落库证据。

## 3. 逐字段基准

| 字段 | 页面含义 | 空值/提交规则 |
| --- | --- | --- |
| `id` | 工厂管理记录主键 | 编辑、删除必须使用当前列表行值 |
| `parentId` | 父级基地或工厂 ID | 页面不强制必填；不使用名称代替 ID |
| `name` | 基地、工厂、库房或装运点名称 | 表单必填 |
| `type` | 记录类型 | 0 基地、1 工厂、2 库房、3 装运点；标签通过字典解释 |
| `code` | 记录编码 | 表单必填；只有 type=0 有数字/字母最多30位规则 |
| `shopId` / `shopName` | 供应商店铺 ID / 名称 | shopId 提交，shopName 只展示 |
| `factoryKind` | 商品类别原码 | 表单必填；使用 `item_kind` 字典 |
| `belongFactory` | 库房/装运点所属工厂名称 | 只读列表扩展字段 |
| `companyOfficeId` / `companyName` | 发货工厂所属公司 ID / 名称 | type=1 提交 ID，名称只展示 |
| `companyCode` | 公司编码 | 只读 |
| `companyValid` | 公司有效标记 | SDK 将后端 0/1 归一化为布尔值，列表只读 |
| `createDate` / `updateDate` | 创建/更新时间 | 编辑时不提交 |
| 组织树节点 `id/name/children` | 可同步的销售组织 | 提交节点 `id`；name 仅用于确认展示 |
| 已同步记录 `hrOrgId/hrOrgName` | 当前同步基地范围 | 用 `hrOrgId` 回填勾选，不使用关系记录 `id` |

基准来源：Portal `app/portal/menus/sale.js`、
`app/portal/views/dashboard/sale/order/trade-storeroom/list.vue`、
`ModalFormContent.vue`、`ModalBaseContent.vue`；CRM 后端
`TradeStoreroomVueController`、`TradeStoreroomService`、`TradeStoreroom`、`TradeStoreroomDao.xml`；平台后端销售组织响应 DTO。

## 4. 操作步骤与证据

1. 先调用 `sale-trade-storeroom-supplier-list`；从候选中取 `shopId`，不要用店铺名称提交。
2. 按当前 `type`、名称、供应商名称和 `factoryKind` 调用列表，保存目标行完整字段；编辑不调用详情接口。
3. 新建/编辑前按页面规则准备表单；`type=1` 先从公司候选取 `companyOfficeId`，库房/装运点或工厂需要父级时再从对应候选取 `parentId`。
4. 调用对应 `prepare-create` 或 `prepare-update`，把同一份 `draft` 交给用户确认；取消只丢弃草稿，不发 save。
5. 用户明确确认后调用 `create` 或 `update`；成功、超时或响应丢失后重新 list，按 ID和关键字段逐项核对。
6. 删除先调用 `prepare-remove`，确认后调用 `remove`；重新 list 确认目标 ID 消失。后端存在子级时会拒绝删除基地或工厂，不能绕过保护。
7. 同步基地先读取 `selected-base-list` 和 `organization-tree`，调用 `prepare-sync-base` 后展示将被覆盖的组织集合；确认后调用 `sync-base`，再读取已同步列表核对 `hrOrgId` 集合。取消不发请求。

离线证据由 `test/sale-trade-storeroom.test.ts` 和 AI 说明契约提供，覆盖页面路径、权限、实例、列表映射、候选短路、表单规则、删除参数、覆盖式同步以及 prepare → submit → cancel 约束。当前尚未在真实测试环境执行本页列表、候选、组织树、同步基地、新建、编辑、删除和写入后的回查闭环；该缺口保持如实记录。
