# 我的流程（`/dashboard/flow/task/my/list`）

人力审批管理中的流程实例列表。页面只展示当前会话用户发起的流程；它与「待办任务」「已办任务」的任务列表不是同一个接口。

## 页面标识

| 项 | 值 |
| --- | --- |
| 菜单路径 | `/dashboard/flow/task/my/list` |
| 权限码 | `/dashboard/flow/task/my` |
| 路由文件 | `app/portal/views/dashboard/hr/flow/task/my/list.vue` |
| HTTP 实例 | `platform.js` |
| module-type | 不发送；页面路径在 module-type 规则中无匹配 |
| 主接口 | `GET /bpm/process-instance/my-page` |

## 列表请求规则

Portal 的 `formState` 初值为：

```text
name: ''
title: ''
processDefinitionId: null
category: ''
status: null
createTime: []
```

分页模块追加 `pageNo=1&pageSize=20`。因此无筛选请求按以下顺序发送：

```text
GET /bpm/process-instance/my-page
  ?order=&orderField=&name=&title=&category=&pageNo=1&pageSize=20&_t=<ts>
```

`processDefinitionId`、`status` 和空 `createTime` 由 `skipNulls` / 空数组序列化规则省略；`category` 没有可见控件，始终保留页面初值空串。日期区间先按 `YYYY-MM-DD HH:mm:ss` 格式化，两个端点原样发送，不做结束日加一天。

请求头只有 `tenant-id`、`token`、`Accept-Language`、`Accept`，不带 `module-type`。

## 参数契约

| 参数 | kind | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | text | 否 | 流程名称，模糊匹配 |
| `title` | text | 否 | 审批内容，模糊匹配 |
| `processDefinitionId` | text | 否 | 所属流程文本筛选值；不把流程名称猜成 ID |
| `status` | enum | 否 | `bpm_process_instance_status` 字典值 |
| `createTimeStart` / `createTimeEnd` | date | 否 | 必须成对，完整格式 `YYYY-MM-DD HH:mm:ss` |
| `pageNo` / `pageSize` | number | 否 | 默认 1 / 20 |

返回 `list` 中的 `id` 是流程实例 ID。`businessKey` 是业务单据主键，不能代替流程取消接口的 `id`；
会议预定动作例外使用 `businessKey`，`tasks[].id` 是任务 ID，也不能与流程实例 ID 混用。

## 页面动作

- **详情**：使用现有 `task-action-instance`，参数映射为 `processInstanceId = list[].id`。
- **重新发起**：页面跳转到流程表单；先读取流程实例和流程定义，再选择对应表单能力。
- **取消**：仅 `record.status === 1` 时显示。SDK 能力 `flow-task-my-cancel` 发送：

  ```text
  DELETE /bpm/process-instance/cancel-by-start-user
  body { id, reason }
  ```

  服务端还会校验当前用户是流程发起人且流程仍在运行。成功返回业务值 `true`，但不能替代回查。SDK 在发送前拒绝空白 `reason`；Portal 弹窗虽然会把空串交给后端，但后端 `@NotEmpty` 会拒绝该请求。应再次调用 `flowTask.listMy()` 或 `taskAction.instance()` 核实状态。

- **取消预定**：仅 `record.canCancelReservation === 1` 时显示。这里使用该行的业务单据
  `businessKey`，不是流程实例 `id`；SDK 能力 `flow-task-my-cancel-reservation` 发送：

  ```text
  PUT /hr/meeting-application/cancel-reservation/{businessKey}
  ```

  这是会议预定控制器的动作，但请求必须沿用“我的流程”页面上下文；当前页没有独立动作权限，也不发送
  `module-type`。`canCancelReservation` 是页面可见性 gate，不是该取消接口自己的安全授权；控制器只按单据 ID 检查记录存在和 `isUsing`，不会重新校验当前用户、流程类型、结束时间或 gate。服务端成功后把 `isUsing` 置为 `0`。接口没有幂等键，超时或重复操作先回查 `flowTask.listMy()`，确认 `canCancelReservation` 已不为 `1` 后才算完成；不能把重复取消错误当作成功，也不能把该接口当成通用会议单据取消权限。

- **流程跟进**：列表仅在 `record.status === 1` 时显示。先调用
  `flowTask.getFollowUpCapability(processInstanceId)`，只有 `canView=true` 才调用
  `flowTask.listFollowUps()`，只有 `canFollowUp=true` 才提交。创建请求为：

  ```text
  POST /bpm/process-follow-up/create
  body { processInstanceId, content, resourceIds, clientRequestId }
  ```

  `content` 会去首尾空白后提交，不能为空且最多 500 个字符；附件先用
  `flowTask.registerFollowUpAttachment({ name, url, size })` 登记，最多 3 个、单个不超过
  100 MiB，再把返回的资源 ID 放入 `resourceIds`。`clientRequestId` 是同一用户/流程/提交意图的
  服务端幂等键，失败或超时未回查前必须复用，不能自动换新值。创建返回跟进 ID 后回查列表；
  服务端通知是异步副作用，不能把记录落库当作通知送达。

- **短信提醒**：列表按钮由 `canSmsRemind` / `remindedToday` 控制，弹窗发送按钮以
  `flowTask.getSmsRemindDetail()` 返回的 `canSend` 为准。详情和历史分别对应：

  ```text
  GET  /bpm/process-sms-remind/detail?processInstanceId=...
  GET  /bpm/process-sms-remind/history?processInstanceId=...
  POST /bpm/process-sms-remind/send
  body { processInstanceId, clientRequestId }
  ```

  仅流程发起人、运行中的流程、存在当前审批人且短信模板启用时可发送；同一流程每日最多一次。
  返回的 `status` 需区分 0~6 的处理中、受理、同步失败和最终发送失败/成功，
  `acceptedCount` 不是最终送达数。发送超时先用原 `clientRequestId` 回查历史，不自动重试。

## 证据边界

- 已有基准：`baseline/general-approval.browser.json` 记录了该页面无筛选列表请求的真实 URL 顺序和空值规则；Portal 页面源码逐项核对了筛选字段、分页和取消 body。
- 离线回归：`test/flow-management.test.ts` 锁定无筛选 URL、带筛选 URL、日期区间校验、取消 body 顺序和空参数反证。
- 本节点未执行真实取消写请求；真实权限、发起人校验和写后状态回查仍需测试环境授权后验证。
- 本节点未执行真实跟进、附件登记或短信发送；真实权限、写入落库、通知/短信渠道结果和写后回查仍需测试环境授权后验证。
- 本节点未执行真实取消预定写请求；真实单据权限、重复取消错误和写后 `canCancelReservation` 回查仍需测试环境授权后验证。
- `flow-task-my-cancel-reservation` 使用 `businessKey`；`flow-task-my-cancel` 仍使用流程实例 `id`，两者不能互换。

## SDK AI 说明契约

权威说明在 `src/catalog/contracts-business.ts`，并由 `catalog.describe()` / `catalog.describe('-llm')` 返回。

### `flow-task-my-list`

查询当前用户发起的流程实例。入口是 `sdk.flowTask.listMy`，也可通过
`capabilities.invoke('flow-task-my-list', args)` 调用。返回 `{ list, total }`；`list=[]`
只表示当前筛选页没有记录，不代表没有权限。`list[].id` 是流程实例 ID，后续详情映射到
`taskAction.instance(processInstanceId)` 的 `processInstanceId`；`businessKey` 和 `tasks[].id` 不能替代它。

### `flow-task-my-cancel`

取消本人发起且 `status === 1` 的流程。入口是 `sdk.flowTask.cancel({ id, reason })`，也可通过
`capabilities.invoke('flow-task-my-cancel', args)` 调用。返回后端 `CommonResult<Boolean>` 的业务值；
`true` 仍需再次 `listMy()` 或 `taskAction.instance()` 回查。服务端校验发起人、流程存在和当前状态，
SDK 不自动重试；空白 `reason` 在本地拒绝。

### `flow-task-my-cancel-reservation`

仅对 `flow-task-my-list` 中 `canCancelReservation === 1` 的会议流程调用，参数是该行的
`businessKey`（会议审批单据 ID），不是流程实例 `id`。入口是
`sdk.flowTask.cancelReservation(businessKey)`，也可通过
`capabilities.invoke('flow-task-my-cancel-reservation', { businessKey })` 调用。返回
`CommonResult<Boolean>` 的业务值；服务端成功后把会议预定标记为不使用，调用方必须重新读取列表确认
`canCancelReservation` 已不再为 `1`。接口没有幂等键，超时先回查，不要盲目重试；已取消单据的错误不等于成功。

### `flow-task-my-follow-up-capability` / `flow-task-my-follow-up-list`

先以流程实例 ID 查询服务端返回的 `canView`、`canFollowUp`、`disabledReason`；权限不足时，
`list=[]` 不能被解释为“没有跟进记录”。列表记录包含创建人、角色、正文和附件资源信息。

### `flow-task-my-follow-up-attachment-register` / `flow-task-my-follow-up-create`

先完成文件上传，再登记 `{ name, url, size }` 取得 `resourceId`；登记不上传二进制。
创建跟进时内容会 trim，最多 3 个资源 ID，需带 `clientRequestId`。成功后回查跟进列表，
通知送达不由创建接口保证。

### `flow-task-my-sms-remind-detail` / `flow-task-my-sms-remind-history` / `flow-task-my-sms-remind-send`

详情返回模板正文、可发送 gate 和当前接收人；历史/发送结果包含提醒聚合状态及逐接收人状态。
发送前确认 `canSend=true`，同一意图复用 `clientRequestId`；超时先查历史，不用新键盲目重发。
状态 3 表示全部同步失败，服务端可能释放当天限制；状态 5/6 没有独立重试接口。
