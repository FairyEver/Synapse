# 合同创建（`/dashboard/contract/create/list`）

本页覆盖 Portal「人力 → 风控管理 → 合同管理 → 合同创建」从入口、第一步表单、模板选择、预览变量到创建后回调的实际可达链路。独立的合同模板管理、合同库编辑和审批入口不属于本页能力。

证据边界：已逐页核对 Portal 入口、表单、模板弹窗、预览提交脚本和 Java Controller/VO/Service/内容校验器；SDK 请求投影、表单边界、创建回执、回调顺序和坏输入反证有离线测试。当前没有在测试门户执行真实租户写入，因此本页不把离线请求断言称为真实冒烟或持久化回查。

来源锚点：Portal `CodeReview_Projects_Js@test/portal/main@acab69acc77b6d6c0da21310cdfd26b91a01641e`；Java `CodeReview_Mall_Platform_Java@test/test@0f1a55718ebc1987affb8bf245106e809dd51da4`。

## 一、页面上下文和权限

| 项 | SDK/Portal 事实 |
| --- | --- |
| 菜单路径 | `/dashboard/contract/create/list` |
| 页面权限 | `/dashboard/contract/create` |
| HTTP 实例 | `platform`；逻辑路径由实例补 `/admin-api` 前缀 |
| `module-type` | `15`，从人力合同创建页面推导；调用方不另拼请求头 |
| 页面形态 | 入口重定向 → 创建表单 → 合同预览/编辑 → 仅保存或创建并下载 |
| 数据范围 | 当前会话、租户和 `module-type=15` 的 Portal 数据权限；组织候选不能跨权限猜 ID |

入口页面调用 `startContractCreate` 时显式传入 `/admin-api/hr/contract/callback`；Portal 通用 helper 对省略的 `callbackApi` 使用空字符串并跳过回调。第一步表单可达字段为 `name`、`typeId`、`organizationId`、`contractTemplateId`，四项均必填；模板选择依赖已选合同类型。

## 二、已接入能力

调用门面为 `sdk.contractCreate.<method>`，能力说明由 `catalog.describe(id)` 和 `catalog.describe(id, { format: 'llm' })` 返回。

| 能力 ID | 方法 | 请求/效果 |
| --- | --- | --- |
| `contract-create-template-options` | `templateOptions` | `GET /hr/contract-template/getEnableContractTemplate`，按 `typeId/useSystem`读取候选 |
| `contract-create-template` | `template` | `GET /hr/contract-template/get`，读取预览模板内容 |
| `contract-create-variables` | `variables` | 按页面 bridge 的动态 `variableApi` 和 JSON 参数读取变量；空接口不请求 |
| `contract-create-prepare` | `prepare` | 本地校验并生成完整创建草稿，不写入 |
| `contract-create` | `create` / `createIdempotent` | `POST /hr/contract/createContractByCommon`，返回 `{ id, code, contractVersionId, onlySave }`；`invoke` 使用 SDK 本地短窗口防重，需提供 `requestId` |
| `contract-create-callback` | `callback` | 按页面顺序 POST 创建后回调；空路径跳过 |

## 三、表单、预览和权限规则

### 表单与候选

- `name`、`typeId`、`organizationId`、`contractTemplateId` 必填；ID 必须来自当前会话可见候选，合同类型必须是 `contract_type` 分类树叶子节点。
- 选择合同类型后，模板候选请求为 `GET /hr/contract-template/getEnableContractTemplate`，参数是 `{ typeId, useSystem }`。Portal 直接菜单的 `useSystem` 是 `null`，SDK 保留这个语义。
- 选定模板后读取 `GET /hr/contract-template/get?id=...`。页面在预览中加载模板 `content`，不会用模板名称代替模板 ID 或内容。
- 第一页没有默认生效日期和结束日期；调用方明确传日期时使用 `YYYY-MM-DD`，未设置时不向创建体添加日期字段，明确传 `null` 则保留 `null`。

### 预览、变量和提交

预览先执行 Portal 的模板配置和解析后内容校验。SDK 复用合同库的共同根校验：`content` 必须是非空 JSON 字符串，含 `version` 和 `blocks`，块 `id/name/data` 有效，块 ID 唯一，并遵守封面、自动目录和签署信息的版本/位置规则；各可视组件的深层规则仍由 Portal 和 Java `ContractContentValidator` 共同执行。

变量接口由 bridge 动态提供。`variableApi` 为空时不请求；`variableApiData` 非法 JSON 时按 Portal 降级为空对象。预览变量 `{ name, value }` 提交时映射为 `{ contractKey: name, contractValue: value }`，去空格后不能重复。

最终创建体按 Portal 原样保留：

```text
{
  name, templateId, typeId, code: null, startDate?, endDate?, organizationId,
  dataList, content, businessId, featureId, useSystem, onlySave,
  variableApi, variableApiData, callbackApi, callbackApiData,
  callbackApiForSignAfterApi, callbackApiForSignAfterApiData
}
```

`onlySave=1` 是“仅保存”，`onlySave=0` 是“创建并下载”；后端据此设置合同状态。创建返回的只是部分回执，不能把回执当作完整详情。

### 创建后回调与回查

Portal 在创建请求成功后，若 `callbackApi` 非空，会把 `callbackApiData` JSON 对象与创建回执、`onlySave` 浅合并后 POST 回调；回调失败由请求层抛出，页面不把回调响应体当合同详情。SDK 的 `callback` 保留该顺序和空路径跳过行为。

创建回执或响应超时后，必须用 `contractLibrary.get({ id })` 独立回查名称、模板、类型、组织、日期、变量、`content` 和状态；Java 没有服务端 `requestId`，SDK 的 `createIdempotent` 只在当前进程短窗口内防重，未回查前不能盲目重复创建。
