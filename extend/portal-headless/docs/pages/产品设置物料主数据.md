# 产品设置物料主数据

页面路径：`/dashboard/product/setting/business-manage/material/list`。

菜单归属是 `系统设置 → 生产设置 → 业务管理 → 物料主数据`。这里的“生产设置”是 Portal 保留的“系统设置”子菜单，不是范围外的独立生产业务菜单。

## 页面能力定义

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询物料主数据 | `product-setting-material-master-list` / `productSettingMaterialMaster.list` | `GET /base/material/page` |
| 准备保存 | `product-setting-material-master-prepare-save` / `productSettingMaterialMaster.prepareSave` | 本地表单校验，不发请求 |
| 保存新建/编辑 | `product-setting-material-master-save` / `productSettingMaterialMaster.save` | `POST /base/material/save` |
| 准备删除 | `product-setting-material-master-prepare-remove` / `productSettingMaterialMaster.prepareRemove` | 本地确认前准备，不发请求 |
| 删除 | `product-setting-material-master-remove` / `productSettingMaterialMaster.remove` | `DELETE /base/material/delete` |

请求使用 `product` HTTP 实例，补 `devicetype=PC`，不发送 `module-type`。菜单权限为 `/dashboard/frame/business/material`；新建、编辑和删除按钮要求 `base:material:submit`。列表没有单独声明查询权限。

## 参数契约与表单规则

列表筛选表单只有三项，默认都是空字符串：`materialDescription`（物料描述）、`materialCode`（物料编码）、`materialGroup`（物料组）。Portal列表请求还固定加入 `order=""`、`orderField=""`，分页默认 `pageNo=1`、`pageSize=20`，页面支持 `10/20/50/100`。

保存弹窗的请求体只包含以下六个键：

```json
{
  "id": "编辑时当前行ID；新建时为undefined/null/空字符串之一",
  "materialDescription": "物料描述",
  "materialCode": "纯数字物料编码",
  "materialGroup": "物料组",
  "specification": "规格或空字符串",
  "measureUnit": "基本计量单位或空字符串"
}
```

表单校验与 Portal 对齐：物料描述必填、最多100个字符；物料编码必填、只允许数字、最多9个字符；物料组必填、不能包含空白字符、最多50个字符；规格和基本计量单位非必填、各最多10个字符。保存时不发送 `remark`、`type`、`isSystem` 等Java实体字段，Controller会把 `remark`固定覆盖成 `yukou`。

`id`非空时Java按ID更新；没有可用ID时按新建处理。保存返回值是 `true`，不是保存后的物料对象，必须回查列表。

删除请求只发送当前列表行的非空 `id`。Portal源码实际使用 `method: 'DELETE'`，但当前Java `MaterialController`只声明了 `@GetMapping("delete")`；SDK保持Portal实际方法，真实环境如果返回405必须报告协议差异，不能自动改成GET。

## 逐字段基准

| 字段 | 含义 |
| --- | --- |
| `list` | 当前页物料主数据记录数组。 |
| `total` | 当前筛选条件下的总条数，不是当前页长度。 |
| `list[].id` | 物料记录ID；编辑和删除目标。 |
| `list[].materialDescription` | 物料描述。 |
| `list[].materialCode` | 物料编码。 |
| `list[].materialGroup` | 物料组。 |
| `list[].specification` | 规格。 |
| `list[].measureUnit` | 基本计量单位。 |
| `list[].type` | Java实体物料类型；本页分页SQL可能没有返回。 |
| `list[].isSystem` | Java实体系统物料标记。 |
| `list[].supplier` | Java实体供应商字段，本页不编辑。 |
| `list[].image` | Java实体图片字段，本页不编辑。 |
| `list[].remark` | Java备注字段；保存请求不接收用户输入，Controller会设为 `yukou`。 |
| `list[].createDate` | 创建时间。 |
| `list[].updateDate` | 最近修改时间；页面展示该字段。 |
| `list[].delFlag` | 软删除标记；正常列表应为0。 |

## 操作步骤、权限和证据边界

1. 用当前会话调用 `list()`，从返回的非空 `list[].id`中选择编辑或删除目标。
2. 新建或编辑时用用户确认的六字段表单调用 `prepareSave`；校验通过后，用户确认才把同一份 `draft`交给 `save`，取消只丢弃draft。
3. 保存成功或响应超时后调用 `list()`，按ID或物料编码回查，不把 `true`直接解释成已落库。
4. 删除前调用 `prepareRemove({ id })`并取得用户确认；确认后调用 `remove`，取消不发请求。
5. 删除成功或超时后调用 `list()`确认该ID不再出现。若收到405，记录Portal使用DELETE而Java只映射GET的协议差异。

本轮逐页核对了Portal菜单、路由权限、列表、弹窗、公共分页实现、Java Controller/Entity/VO/Mapper/Service、SDK请求和离线反证测试。尚未在真实测试环境执行列表、保存、回查和删除闭环；DELETE与Java GET映射冲突也尚未在线确认。
