# 计价配置（`/dashboard/material/store/valuation/list`）

## Portal 页面行为

### 列表与候选

- 列表 `customLoad` 实际调用 `GET /admin-api/inventory/pricing-method-config/page`。公共参数保持 `order=''`、`orderField=''`、`factoryId`、`pricingMethod`、`materielCategoryIds`、`moveType`、`pageNo`、`pageSize`；其中 `materielCategoryIds` 是页面数组直接执行 `join(',')`，空数组发送空字符串。
- 所属单元来自 `GET /admin-api/supply/organization/tree?isFactory=1&includeParents=1`，Portal 组件只允许 `isFactory === 1` 的节点选择。物料分类来自 `GET /admin-api/inventory/asset-depreciation-config/get-materiel-category-tree?level=5`，SDK按树位置把根层级重算为1。
- 出入库类型来自 `GET /admin-api/inventory/stock/typeList`，候选 `value` 是 `type-subtype`，例如 `inventory_inbound_type-1`。计价方式下拉框不是页面独立请求，而是全局平台字典 `inventory_pricing_method_type`；需要当前候选时调用 `base-dict-get`，不要猜标签或值。
- Java 的 `stock/typeList` Controller 使用的是 `material:store:material:detail` 权限字符串；计价配置主接口使用 `/dashboard/material/store/valuation`。SDK 的页面能力统一绑定页面权限，端点级权限差异记录在本页，不把候选接口误报成主页面按钮权限。

### 新增表单与提交规则

- 新增表格初始有一行：`factoryId`、`materielCategory`、`pricingMethod`、`moveType`、`price` 均为空；删除按钮可以把行删空，Portal 没有额外的空数组校验，最终可能向后端发送 `[]`。
- 页面表单校验要求所属单元、物料分类、计价方式；`moveType` 没有独立的表单规则，但提交代码会对它执行 `split('-')`，因此缺失时会在发请求前失败。SDK 的 `prepareCreate` 将其明确拒绝。
- Portal 实际请求是 `POST /admin-api/inventory/pricing-method-config/create`，body 是数组。每行映射为：

  ```text
  { factoryId, materielCategoryId, pricingMethod: Number(pricingMethod),
    type: moveType.split('-')[0], subtype: moveType.split('-')[1], price }
  ```

  创建时 `subtype` 保持拆分出的**字符串**；SDK 不把它提前转换成数字。
- 计价方式为 `4`（标准价法）时，页面自定义提交检查 `price` 不得为 `null/undefined`；价格输入非负、精度3位。出入库类型包含 `outbound_type` 时，计价方式 `5` 被禁用并会被清空。新增页没有单独监听 pricingMethod 清空 price，因此已有的隐藏 price 值按页面原样保留，SDK也不擅自丢弃非4的显式 price。

### 编辑表单与提交规则

- 编辑页先 `GET /admin-api/inventory/pricing-method-config/get?id=...`，把 `type` 与 `subtype`组装成 `moveType`，并把 `pricingMethod`转为字符串；所属单元和物料分类只展示，不可编辑。
- `moveType`、`pricingMethod` 是必填；计价方式为 `4` 时 `price` 必填。切换到非4时编辑页 watcher 会把 `price` 清为 `null`；出库类型下计价方式 `5` 被禁用并清空。
- Portal 实际 `PUT /admin-api/inventory/pricing-method-config/update` body 是：`id`、`factoryId`、`materielCategoryId`、`pricingMethod: Number(...)`、`type`、`subtype: Number(...)`、`price`。与新增不同，编辑的 `subtype` 是数字。SDK 的 `prepareUpdate` 和反证测试分别锁定了这两个线格式。

### 删除、变动详情和单价历史

- 列表删除实际是 `DELETE /admin-api/inventory/pricing-method-config/delete?id=...`。Portal 没有按列表状态隐藏删除按钮；Java 服务会检查配置存在、当月不能已有入库/出库单且历史单据必须已定价。SDK 只校验ID，不把删除按钮点击当成业务成功。
- “变动详情”页调用 `GET /admin-api/inventory/pricing-method-change-log/page`，通过 `loopFetch` 以 `pageSize=500`、最多100页拉平结果；页面把 `route.params.id`（计价配置ID）放入请求的 `materielId` 参数，这是实测代码行为，SDK 保留并在契约中明示，不擅自改成列表行 `materielId`。
- 详情页随后读取同一个配置 `GET /admin-api/inventory/pricing-method-config/get?id=...`，展示旧/新计价方式、变动日期和变动人。计价方式显示名仍需查 `inventory_pricing_method_type` 字典。
- 价格单元进入 `actions/view-price.vue` 后，分页调用 `GET /admin-api/inventory/stock-avg-price-history/page`，发送 `order=''`、`orderField=''`、`factoryId`、列表行 `materielId`、`pageNo`、`pageSize`，按 `year-month`、`inAvgPrice`、`outAvgPrice`展示。

## Java 后端校验与权限

`PricingMethodConfigController` 的 create/update/delete/get/page 均使用 `/dashboard/material/store/valuation`。创建返回 `Boolean true`；修改和删除也返回 `Boolean true`，但服务层会拒绝不存在配置、当月已有入出库单或存在未定价单据。`PricingMethodConfigSaveReqVO` 接受 `factoryId`、`materielCategoryId`、`pricingMethod`、`type`、`subtype`、`price`；更新服务实际按ID更新计价方式、分类、类型、子类型和单价，factoryId只随Portal请求带回。

`StockHistoryController` 的单价历史分页受 `material:store:material:detail` 保护，返回 `id`、`materielId`、`factoryId`、`year`、`month`、`inAvgPrice`、`outAvgPrice`、`createTime`。变动日志分页 Controller 未声明独立 `PreAuthorize`，由页面调用链和服务端会话控制。

## SDK 能力与说明

实现文件为 `src/capabilities/inventory-valuation.ts`，AI契约为 `src/catalog/contracts-inventory-valuation.ts`，已接入 `catalog.describe`、`-llm`、`capabilities.invoke` 和 SDK 门面。

能力按页面动作组织：

- `list`、`typeList`、`materialCategoryTree`、`unitTree`、`get`；
- `prepareCreate → create`；
- `prepareUpdate → update`；
- `prepareRemove → remove`；
- `changeLogs`、`priceHistoryList`。

所有写动作均保留 `prepare → submit → cancel` 路径；成功或超时后要按组合字段、详情或列表回查，不能只凭 `true` 回执判定完成。计价方式候选复用基础 `base-dict-get`，没有重复注册全量字典接口。
