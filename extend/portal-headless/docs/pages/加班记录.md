## Portal 页面行为

筛选表单只有两个字段：

| 控件 | 参数 | Portal 规则 |
| --- | --- | --- |
| 姓名 | `applicantName` | 初始值为空字符串，后端按姓名模糊匹配 |
| 组织 | `organizationIdList` | 角色组织树多选，未选择时发送 `[]` |

列表使用 `customLoad` 调用 `POST /admin-api/hr/overtime-application/record/page`。`getDataListIsPage: true` 时，列表模块把排序、表单和分页合并为：

```json
{
  "order": "",
  "orderField": "",
  "applicantName": "",
  "organizationIdList": [],
  "pageNo": 1,
  "pageSize": 20
}
```

页面列为申请人、工号、部门路径、岗位和剩余调休时长。`remainingRestHours` 的单位是小时；后端按通过审批且 `subsidyType=0` 的加班时长减已审批调休时长计算，负数归零并保留两位小数。点击“查看已调休日期”只把当前行的 `applicantId` 传入详情弹窗，不把列表行 ID 或工号当作用户 ID。

详情弹窗默认选择当前年份，使用年份选择器可切换年份；每次加载调用 `GET /admin-api/hr/overtime-application/record/detail`，query 为：

```json
{ "year": "2026", "userId": 7 }
```

响应字段包括申请人姓名、组织、岗位、该年份已调休小时数、用“、”连接的日期文本和日期数组。后端对空年份或不存在用户返回带默认值的详情对象：`usedRestHours=0`、`restDates="无"`；这不代表存在调休记录。

## 后端与权限核对

Java `OvertimeApplicationController` 在 `/hr/overtime-application` 下提供 `record/page` 和 `record/detail` 两个页面实际调用的端点。分页服务只统计状态为已审批、补贴类型为调休的加班申请，并在服务层扣除已审批调休时长；分页查询使用当前用户 `DataScope` 和组织筛选。

详情服务按 `userId` 找用户，再按年份边界查询状态为已审批的调休申请，合计 `usedRestHours`，读取调休日期明细并按日期去重、排序生成 `restDates`。页面没有调用创建申请、申请详情、剩余时长或流程提交接口，因此这些接口不计入本页能力。

组织候选复用 `contractSupport.roleOrganizationSearch({ scope: 'attendance', keyword })`。Portal 组件会拉角色组织树；无头调用必须先要关键字，再在 SDK 本地限量过滤，提交时只把用户确认的 `list[].id` 组成 `organizationIdList`。

### `attendance-overtime-list`

按姓名和角色组织筛选读取当前用户数据范围内的加班记录汇总分页列表。

执行：`sdk.attendanceOvertime.list`；性质：read。操作 Portal「组织管理 → 考勤管理 → 加班记录」页面的列表或“查看已调休日期”入口。

- 边界：页面权限是/dashboard/attendance/attendance-overtime；请求使用 platform HTTP 实例和 module-type=11。
- 边界：页面只有列表和已调休日期详情，没有创建、编辑、删除或审批入口；列表 POST 是读取操作，不要报告成业务写入。
- 边界：organizationIdList 必须来自 contractSupport.roleOrganizationSearch({ scope: "attendance", keyword }) 的候选 ID；候选搜索必须有关键字，不能无头照搬 Portal 全量组织树。
- 边界：remainingRestHours 是后端按通过审批的加班小时减已审批调休小时计算的剩余值，单位为小时、负数归零；不要把它解释成工资或加班申请单状态。

| 参数 | 意义与来源 |
| --- | --- |
| applicantName | 姓名模糊筛选；页面初始值为空字符串，省略时按 Portal 表单发送空字符串。；来源：用户明确提供的姓名筛选 |
| organizationIdList | 角色组织树多选结果的组织 ID 数组；未筛选时发送 []。；来源：contractSupport.roleOrganizationSearch({ scope: "attendance", keyword }) 的 list[].id；用户确认选择后组成数组；候选：contract-support-role-organization-search list[].id |
| pageNo | 从1开始的页码；页面默认1。；来源：调用方分页状态 |
| pageSize | 每页条数；Portal 分页器支持10、20、50、100，默认20。；来源：调用方分页状态 |

返回：`{ list: object[], total: number }`。list=[] 表示当前页没有记录；total=0 才表示当前筛选没有记录。权限、会话、网络或响应形状错误会抛出，不降级为空页。

- list[].overtimeHours：通过审批且 subsidyType=0 的加班总时长；单位小时；单位：小时
- list[].remainingRestHours：剩余调休时长；加班总时长减已审批调休时长，负数按0处理并保留两位小数；单位：小时

- 消费：用 total 判断是否继续翻页；list[].applicantId 是查看已调休日期所需的 userId。
- 消费：remainingRestHours 和 overtimeHours 的单位是小时；它们是汇总值，不是单条申请明细。
- optional：用户要查看某行的已调休日期且 list[].applicantId 非空 → `attendance-overtime-detail`。打开 Portal 同款详情时默认使用当前年份；用户切换年份后重新查询 detail。 映射：{"userId":"result.list[].applicantId","year":"user.selectedYear ?? currentYear"}

完成条件：返回当前筛选的一页加班记录和 total；读取列表不修改加班或调休数据。

- 失败处理：年份格式、用户 ID、组织 ID、分页、权限、租户、网络或响应形状错误原样抛出；列表不能以空页替代权限失败。

- **仍有缺口**：已完成 Portal/Java 逐页静态核对与离线请求断言；尚未在真实测试环境执行加班列表、详情及数据范围拒绝冒烟。

### `attendance-overtime-detail`

按申请人和年份读取已审批调休时长及调休日期，供加班记录详情弹窗展示。

执行：`sdk.attendanceOvertime.detail`；性质：read。操作 Portal「组织管理 → 考勤管理 → 加班记录」页面的列表或“查看已调休日期”入口。

- 边界：页面权限是/dashboard/attendance/attendance-overtime；请求使用 platform HTTP 实例和 module-type=11。
- 边界：页面只有列表和已调休日期详情，没有创建、编辑、删除或审批入口；列表 POST 是读取操作，不要报告成业务写入。
- 边界：organizationIdList 必须来自 contractSupport.roleOrganizationSearch({ scope: "attendance", keyword }) 的候选 ID；候选搜索必须有关键字，不能无头照搬 Portal 全量组织树。
- 边界：remainingRestHours 是后端按通过审批的加班小时减已审批调休小时计算的剩余值，单位为小时、负数归零；不要把它解释成工资或加班申请单状态。

| 参数 | 意义与来源 |
| --- | --- |
| year | 年份选择器值，YYYY 字符串；页面默认当前年份，用户可以切换到其它年份。；来源：用户明确选择的年份 |
| userId | 申请人用户 ID；来自 attendance-overtime-list.list[].applicantId。；来源：attendance-overtime-list.list[].applicantId |

返回：`object`。后端对缺失年份或不存在的用户返回带 year、usedRestHours=0 和 restDates=无的空详情；这不表示存在调休记录。权限、会话、网络或字段形状错误仍抛出。

- usedRestHours：该用户在查询年份已审批调休的总时长；单位：小时

- 消费：用 usedRestHours 读取该年份已调休小时数；restDates 直接作为 Portal 展示文本，restDateList 用于需要逐日期处理的调用方。
- 消费：年份切换后必须以相同 userId 重新调用 detail；不要复用上一年的日期。

完成条件：取得指定用户和年份的详情快照；restDates=无表示没有已审批调休日期，不是请求失败。

- 失败处理：年份格式、用户 ID、组织 ID、分页、权限、租户、网络或响应形状错误原样抛出；列表不能以空页替代权限失败。
