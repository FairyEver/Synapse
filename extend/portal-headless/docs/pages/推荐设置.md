## 页面行为与请求

页面挂载和点击右上角重置都会调用：

```text
GET /admin-api/sales/recommend-setting/get
```

详情响应是 `{ setting, keyAgeSettings }`：

- `setting.advancePushDays`：提前推送天数，页面转为数字；前端表单范围为 1–29 天。
- `setting.visitLateSubmitDays`：拜访单晚交天数，页面转为数字；前端表单范围为 1–29 天。
- `setting.recommendRatio`：推荐总数占比，页面转为 `totalPercent`；原值按百分比点保存，例如 `20` 表示 20%。范围为 0–100 的整数。
- `setting.businessServiceRatio`：商务类与服务类占比的动态字典值；字典类型为 `business_analog_services`，默认值为字符串 `'5'`，允许清空。
- `keyAgeSettings[]`：页面转换为 `keyDayItems[]`；详情 VO 不返回关键日龄行 ID，因此页面保存时这些行的 `id` 为 `0`。
- `keyAgeSettings[].keyAge`：关键日龄，页面允许大于等于 0 的整数。
- `keyAgeSettings[].pushPoint`：推送要点，页面要求非空，最多 100 个汉字。

缺少主配置时 SDK 将 `setting` 归一为 `null`；后端 `keyAgeSettings` 为 `null` 或缺失时 SDK 将其归一为空数组。网络、权限和响应结构错误不会被当作空配置吞掉。

保存请求：

```text
POST /admin-api/sales/recommend-setting/save
```

页面最终发送的请求体为：

```json
{
  "setting": {
    "id": 0,
    "advancePushDays": 3,
    "visitLateSubmitDays": 5,
    "recommendRatio": 20,
    "businessServiceRatio": "5"
  },
  "keyAgeSettings": [
    { "id": 0, "keyAge": 30, "pushPoint": "关注客户" }
  ]
}
```

`prepareSave` 复刻页面保存前规则：

1. `advancePushDays`、`visitLateSubmitDays` 必须是 1–29 的整数。
2. `totalPercent` 必须是 0–100 的整数。
3. `keyDayItems` 至少一条；`keyDay` 必须是大于等于 0 的整数，不能重复。
4. `pushPoint` 去除首尾空白后不能为空，最多 100 个汉字；提交值使用去除首尾空白后的文本。
5. `businessServiceRatio` 未选择时按空字符串提交；不把动态字典值擅自解释为固定比例。
6. 页面“添加关键日龄”和“删除”只改变本地数组；删除最后一条会被页面拦截，不存在单行 DELETE 请求。

Java `RecommendSettingServiceImpl` 按当前租户处理保存：主配置不存在则新增，存在则更新；非空 `keyAgeSettings` 会先删除当前租户旧关键日龄，再逐条插入提交数组。后端只按当前租户查找，不能把页面表单中的 `id: 0` 当成用户需要填写的记录 ID。

## 权限和请求上下文

Controller 的 GET/POST 均使用：

```java
@PreAuthorize("@ss.hasPermission('/dashboard/sale/frame/visit/recommendSetting')")
```

SDK 请求由页面路径绑定 `platform` 实例，并发送会话 `token`、显式 `tenant-id` 和 `module-type: 60`。module-type 只限定后端数据范围，不替代权限码校验。

Controller 同时暴露 `GET /sales/recommend-setting/key-age/push-point?age=…`，但当前 Portal 页面没有调用它；它不属于本页能力，SDK 没有把它发布成推荐设置页面动作。

## AI 说明与写后核验

权威契约在 `src/catalog/contracts-sale-visit-recommend-setting.ts`，由主代理接入共享目录后通过 `catalog.describe(id)` 返回。

- `get`：读取表单，编辑时将 `recommendRatio` 映射为 `totalPercent`，将 `keyAgeSettings` 映射为 `keyDayItems`。
- `prepareSave`：只做本地校验和字段映射，不发网络请求；返回包含 `setting`、`keyAgeSettings` 的完整 `draft`。
- `save`：只提交 `prepareSave` 的 `draft`，后端 `true` 只表示保存请求回执。
- `save` 成功或超时后必须再次调用 `get`，逐字段核对四个主配置字段及关键日龄/推送要点；未回查不能报告配置已生效。
- 页面和 Java 均没有服务端 cancel/恢复接口。若用户要求恢复，只能保留保存前的 `get` 快照，再经过 `prepareSave → save` 做一次完整覆盖；这不是事务回滚，仍需 `get` 回查。
- 后端没有 requestId 幂等键。超时先回查，未确认前不要盲目重试。
