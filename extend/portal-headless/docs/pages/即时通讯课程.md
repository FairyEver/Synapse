# 即时通讯课程（`/dashboard/course/im-course/list`）

## 页面与权限

| 项 | 值 |
| --- | --- |
| 菜单路径 / SDK 页面上下文 | `/dashboard/course/im-course/list` |
| 权限码 | `/dashboard/course/im-course` |
| module-type | `12`（学习管理） |
| 列表路由 | `app/portal/views/dashboard/education/course/im-course/list.vue` |
| 新建隐藏路由 | `app/portal/views/dashboard/education/course/im-course/[mode]/[id].vue` |
| 消息隐藏路由 | `app/portal/views/dashboard/education/course/im-course/message/[id]/[roomId]/item-list.vue` |
| 合并语音隐藏路由 | `app/portal/views/dashboard/education/course/im-course/merge/[roomId]/item-list.vue` |

列表行操作只在 `userId === record.creator` 时由 Portal 显示。后端三个控制器当前没有
`@RequiresPermissions` 约束；SDK 仍将所有动作绑定到上面的页面权限上下文，不把前端行条件
当作服务端鉴权替代品。隐藏路由没有菜单项，但确实由列表行和语音合并组件 `push` 到，故纳入
同一页面能力。

## 列表读取

`study-course-im-list` 调用：

```text
GET /study/course/studycourse/courseList?type=4
```

请求字段顺序为 `order, orderField, keyword, numberMin, numberMax, status, createTimeStart,
createTimeEnd, deleteTimeStart, deleteTimeEnd, pageNo, pageSize`；空筛选值也发送空字符串，
默认 `pageNo=1`、`pageSize=20`。日期结束日按页面规则加一天。返回 `{ list, total }`，课程行
的群组信息在 `imGroupDTO`，状态列读外层 `isDel`。

### 当前已知失败

2026-09-21 浏览器实测，测试租户的 `type=4` 列表返回 HTTP 200、业务 `code=500`：
`用户查询结果超过500条，请缩小name条件或调用已有分页接口`。根因是 Java
`StudyCourseServiceImpl#matchResourceByType` 无条件拉取全量用户，撞上 500 条上限；SDK 保留
该读取能力并抛出 `PortalApiError`，不把失败伪装成空列表。筛选语义没有因此被真实数据验证。

隐藏消息页的读取方法为 `listMessages`：

```text
GET /study/interaction/page
```

必填 `id`（课程行 ID）和 `roomId`（群组 ID），固定 `sessionType=2`。消息页默认
`order=''`、`orderField=''`；voice-merge 弹窗会传 `order=asc`、`orderField=createTime`、
`type=2`。其余可选筛选字段按 Portal 原样传递：`content/status/name/staffCode/isProhibition`、
`createTimeStart/createTimeEnd`、`pageNo/pageSize`。返回 `{ list, total }`。

隐藏合并语音页的读取方法为 `listMergedAudio`：

```text
GET /study/audio/page
```

必填 `roomId`，默认 `order=''`、`orderField=''`、`pageNo=1`、`pageSize=20`，返回 `{ list, total }`。

## 动作契约

所有写动作都按 `prepare → submit → cancel` 暴露。`prepare` 只校验和生成草稿，`cancel` 只
取消本地草稿；没有对应服务端撤销接口的动作不会伪造回滚成功。

| 能力方法 | 页面实际请求 | prepare 输入 / 草稿规则 |
| --- | --- | --- |
| `prepareCreateIm` → `createIm` | `POST /study/course/studycourse` | `form={gradeId,title,staffCode}`；固定 `type=4`、`imGroupDTO.joinmode=0`、`imGroupDTO.msg="即时通讯课程"` |
| `prepareMute` → `mute` | `PUT /study/course/studycourse/{id}/chatroom/mute?muted={boolean}`，body `null` | 输入课程行 `id`、`currentMuted`；草稿 `muted=!currentMuted`，路径用课程行 ID，不用 `groupId` |
| `prepareMessageStatus` → `updateMessageStatus` | `PUT /study/interaction/updateStatus`，JSON body `{id,status}` | 输入互动消息 `id` 和绝对目标 `status`（0/1），不取反 |
| `prepareAudioStatus` → `updateAudioStatus` | `PUT /study/audio/updateStatus`，multipart | 输入 `id、roomId、currentStatus、lessonId?`；按页面取反 status，FormData 顺序为 `roomId、id、status`，有 `lessonId` 才追加它 |
| `prepareAudioDelete` → `deleteAudio` | `DELETE /study/audio`，JSON body `[id,...]` | 输入非空 `ids` 数组；单行删除也必须发送数组，不能改成 `{ids:[...]}` |
| `prepareAudioMerge` → `audioMerge` | `POST /study/audioMerge`，JSON body `{lessonId,lessonName,roomId,fileList}` | `fileList` 至少两个外部音频地址；成功返回合并音频 URL |

对应取消方法依次为 `cancelCreateIm`、`cancelMute`、`cancelMessageStatus`、
`cancelAudioStatus`、`cancelAudioDelete`、`cancelAudioMerge`。

### 外部依赖、完成条件与失败判据

- 新建先由 Java 调用外部内容平台 `/api/study/course/add.json` 创建课程/群组，再写本地
  `hr_study_course`；Portal 业务错误包络、HTTP 错误或外部非 200 都算失败。超时可能已经在
  外部创建成功，不能盲目重试；应重新查询课程/外部资源后再决定。
- 禁言/解禁由 Java 转发到 `/api/study/course/muteGroupChatRoom.json`。成功只代表请求链路
  接受；外部非 200、参数为空、课程不存在或课程类型不是 4 都是明确失败。没有 SDK 侧补偿动作。
- 互动消息状态由 Java 转发到 `/api/study/liveMsg/updateStatus.json`；远程异常或非 200
  会失败。提交后应重新调用 `listMessages` 读取状态；网络超时下不自动重试，避免重复外部写入。
  当前消息页状态操作模板被注释，能力保留是因为页面函数和后端入口仍存在。
- 语音发布/取消发布写本地合并语音记录；同一 `roomId + lessonId` 已有一条发布记录且目标
  `status=1` 时，Java 返回“该课程只能选择一条语音发布”。multipart 缺少 `roomId/id/status`
  或响应错误也算失败。
- 语音删除是批量删除，没有服务端恢复接口；请求接受不等于已独立证明记录消失，应重新调用
  `listMergedAudio` 检查。网络结果不确定时不要重复删除。
- 语音合并依赖外部音频 URL 可下载、FFmpeg/FFprobe、阿里云 OSS 和本地/远端存储。少于两个
  文件时 Java 返回文件数错误，下载/转码/上传失败返回“音频合并失败”；成功会落本地合并记录，
  没有服务端 cancel。失败或超时后应先查列表和 OSS，再决定是否重试。

## 隐藏新建表单与语音合并弹窗的候选（本轮补的 3 条）

隐藏新建表单（`[mode]/[id].vue`）与语音合并弹窗（`voice-merge.vue`）里有三个**候选**请求，
它们不是列表、也不是动作，本轮补成三条只读能力：

| 能力 id | 入口（页面动作） | 请求 | 实例 | 参数 |
| --- | --- | --- | --- | --- |
| `study-course-im-student-list` | 新建表单「群主」下拉 | `GET /study/base/studystudent/list` | platform | **`keyword` 必填** |
| `study-course-im-owner-level-options` | 群主/讲师候选上把 `level` 显示成中文名 | `GET /manage/selectAllTeacherLevel.lay` | `smart-layer-admin` | 无参 |
| `study-course-im-lesson-list` | 新建表单与语音合并弹窗的班课下拉 | `GET /study/lesson/studylessongraderel/getLessonListByGradeId` | platform | `gradeId` |

### 三个必须记住的点

**1. 群主候选**必须**先要关键字，这一条是**刻意不照抄页面**的。**
页面那一句是 `http.get('/study/base/studystudent/list')` —— **一个参数都不带**，
一次把全部"在职学员"拉回来；而这条 SQL（`StudyStudentDao.xml:443-460`）
**没有分页、也没有 LIMIT**，只有一个可选的 `name LIKE` 过滤。
按 `docs/conventions.md` 第 11 条（D6 / H35：长选项参数必须先要关键字），
SDK 直接拒绝无关键字的调用。返回的是**过滤后的全集**（这条接口没有下一页）。
群主表单提交的是候选项的 `staffCode`（工号），**不是 `id`**。

**2. 讲师级别的 `level` 是匹配键，`name` 才是展示值。**
页面用它把候选上的 `level` 数字渲染成中文名（`getTeacherLevelName` 按相等匹配）。
这条走 `.lay` 网关，响应体业务数据在 `StudyTeacherLevelDTOList` 键上，必须带 `isOriginal`。
接口无参（`@GetMapping("selectAllTeacherLevel.lay")` 一个形参都没有），
是**全量字典**，当场取回当对照表用即可。

**3. 班课候选的 `id` 与班级 `gradeId` 不是一回事。**
新建表单要的是 `gradeId`（班级 ID），语音合并要的是班课的 `id` / `title`；
两个组件的候选都来自这一条接口，但下游用途不同，**不能互换**。

### 未验证项（这一批全部是离线形状）

- **没有浏览器基准、没有线上冒烟**。这一页的列表本身在当前租户就因 500 条上限不可用
  （见上），隐藏子页更没有线上结果。
- `smart-layer-admin` 的 baseURL 必须由调用方在 `httpBaseUrls` 里配，没配就拒绝发请求；
  本轮没有在真实环境验证过它可用。
- 学员候选的**规模没有实测**：只从 SQL 确认了"无分页、无 LIMIT、只按 name 过滤"。
- 讲师级别候选是否真的只回"启用中"的，只按接口注释与 `selectAll` 的语义推断，没有实测。
