# 讲师管理（`/dashboard/base/teacher/list`）

> 这一页的**共享机制**（参数顺序怎么来的、空值发不发、时间区间怎么算）写在
> [学习管理域](./学习管理域.md) 里，这里只记这一页自己的东西。

| 项 | 值 |
| --- | --- |
| 菜单路径 | `/dashboard/base/teacher/list` |
| 权限码 | `/dashboard/base/teacher` |
| 路由文件 | `app/portal/views/dashboard/education/base/teacher/list.vue` |
| 接口 | `GET /manage/getAllProfessorPage.lay`（**smart-layer-admin 实例** + `isOriginal`） |
| module-type | 12 学习管理 |
| 能力 id | `study-teacher-list`、`study-teacher-prepare-save-teacher`、`study-teacher-save-teacher`、`study-teacher-cancel-save-teacher` |

## ⚠️ 这一页走的是 **smart-layer-admin** 实例，不是 platform

请求落在 `smarterlayeradmintest.zhihuidanji.com/admin`，**另一个 host**。
这个实例的响应规则是 `smart-layer` 那一档（见 `src/context/http-instance.ts`）：
**不看 `ret`、看 `code`**；而且页面调用时都带 `isOriginal: true` ——
拿到的就是**整个响应体**，页面自己去取 `result.page.results`。

实测原始体（2026-09-21）：

```json
{"ret":"SUCCESS","code":200,
 "page":{"pageNo":1,"pageSize":2,"totalRecord":133,"totalPage":67,"results":[…]}}
```

⇒ 本能力把 `{page: {results, totalRecord}}` 归一成 `{list, total}`，与其它能力同形。
**响应里没有 `page` 时当场抛**，不静默返回空列表 —— 后者会让调用方以为"真的没有数据"，
而实际是响应形状变了。

## 实例是**逐请求**声明的，不是页面级规则

这一页的**列表**走 smart-layer-admin，而**删除**（`DELETE /study/base/studyteacher`）走 **platform**。
`src/context/http-instance.ts` 的 `isPageShapedPath` 注释写着这条道理：
"同一次页面操作里可能有多个实例，所以实例必须能逐请求指定，不能只当页面属性"。

本轮试过往 `HTTP_INSTANCE_PAGE_RULES` 加页面级规则，被 `test/http-instances.test.ts`
的相等性断言拦下 —— **它是对的**。

**代价（conventions 第 27 条）**：这个实例的 baseURL 必须由调用方显式给
（`createPortalHeadless({ httpBaseUrls: { 'smart-layer-admin': 'https://smarterlayeradmintest.zhihuidanji.com/admin' } })`），
没给就**拒绝发请求**（失败关闭），不会拿默认 baseURL 去凑。

## 它曾经"做不了"，原因是 SDK 当时没复刻这一族包络

早先 SDK 只实现了 `portal-standard` 一种包络，其余四档一律抛
`HttpInstanceUnsupportedError`。用户 2026-09-21 要求**按各实例自己的规则复刻**，
`src/http/client.ts` 里补上了 `applyEnvelope()` 的四条规则（测试 `test/http-envelope.test.ts`），
这两页才做得成。

## 参数契约

| 参数 | kind | 说明 |
| --- | --- | --- |
| `name` | text | 讲师姓名（模糊） |
| `level` | text | 讲师类型。页面是下拉但**取值域未实测**（无筛选时它根本不发这一项）→ 只透传、不给枚举 |
| `page` | number | 页码，默认 1。**参数名是 `page`，不是 `pageNo`**（页面覆写了 `fieldNamePageNo`） |
| `limit` | number | 每页条数，默认 20。**是 `limit`，不是 `pageSize`** |

⚠️ `level` 的初值是 **`undefined`**（不是空串）—— 与同域其它页"空值也照发"**相反**。
实测基准里也没有这一项。

## 真实验证（2026-09-21）

- `list({pageNo:1,pageSize:3})` → **133 条**（本页 3 条），归一后的 `total` 是数字。
- 冒烟：`smoke/read-study-module.mjs` 的 ⑥ 段。

## 已覆盖的写动作：创建外部讲师学员记录

`study-teacher-prepare-save-teacher` → `study-teacher-save-teacher` →
`study-teacher-cancel-save-teacher` 对应讲师创建页在没有 staffCode 时发出的
`POST /study/base/studystudent/saveTeacher`。请求使用 platform、权限
`/dashboard/base/teacher`、module-type 12；body 是 DTO `{ name }`，不是裸姓名字符串，也没有
query。成功返回后端生成的 `staffCode`（Java `Long`，SDK 返回解包后的 number）。prepare 只校验
姓名非空并保留原字符串，cancel 只返回本地 `{ cancelled: true }`。

Portal 的实际调用是 `http.post(path, { name: form.name })`。Java 的方法签名是
`saveStudent(String name)` 且没有 `@RequestBody`，因此“JSON DTO body 是否由当前 Spring
绑定配置稳定接收”仍是源码无法证明的盲区；SDK 按 Portal 实际 wire body 实现，未在真实环境
写入验证。

这只是创建外部讲师对应学员记录的辅助动作，不等于后续 `.lay` 的讲师主体保存。

### `study-teacher-list`

查询讲师及讲师类型；SDK 将 smart-layer 的 page.results/totalRecord 归一成 list/total。

- 执行：`sdk.studyTeacher.list`；通过 `capabilities.invoke('study-teacher-list', args)` 调用时按 `params` 填参。性质：read。
- 参数：`name` 可选 (string)；`level` 可选 (string)；`page` 可选 (number)；`limit` 可选 (number)。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`{ list: object[], total: number }`。list=[] 为当前页无记录；total=0 表示该筛选无结果。保留筛选条件检查页码，不将空结果解释成权限判定。
- 字段：`list`、`total`、`list[].id`、`list[].name`、`list[].briefIntro`、`list[].level`、`list[].teacherType`、`list[].status`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：展示姓名、简介、类型；这是归一后的列表，不再读取 page.results。
- 完成条件：按用户要求交付本次筛选范围的结果；需要完整清单时继续翻页至覆盖 total，不能把当前页当全集。
- 后续：optional → `study-teacher-level-list`：需要解释讲师类型时读取类型表并比较同一编码（）
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。
