# 低价设置

## 1. 能力定义

- 菜单归属：门户 → 系统设置 → 销售设置 → 价格管控 → 低价设置。
- 页面路径：`/dashboard/sale/setting/price-control/low-price/list`。
- 页面权限：`/dashboard/sale/setting/price-control/low-price`。
- module-type：`60`（销售管理）。
- 请求实例：Portal platform（`VITE_ZHDJ_PLATFORM_API`）。
- 写权限：新增 `setting:price-control:low-price:create`，编辑 `setting:price-control:low-price:edit`，删除 `setting:price-control:low-price:delete`。
- 本页属于保留的 `系统设置 → 销售设置` 子树；不等于独立的“生产”根菜单，也不覆盖其它生产页面。

对应 SDK 能力：

| capability | 作用 | 写入 |
| --- | --- | --- |
| `sale-low-price-category-options` / `sale-low-price-list` | 查询列表页品类筛选项和分页数据 | 否 |
| `sale-low-price-sku-tree-categories` / `sale-low-price-sku-tree-skus` | 查询新增/编辑页可用的品类和商品规格 | 否 |
| `sale-low-price-get` | 查询单条配置详情 | 否 |
| `sale-low-price-prepare-create` / `sale-low-price-create` | 准备并新增管控标准 | 后者是 |
| `sale-low-price-prepare-update` / `sale-low-price-update` | 准备并编辑管控标准 | 后者是 |
| `sale-low-price-prepare-remove` / `sale-low-price-remove` | 准备并删除管控标准 | 后者是 |

## 2. 参数契约

### 列表页

品类筛选项：

```text
GET admin-api/priceControlStandardConfig/categoryOptions
```

列表请求为：

```text
GET admin-api/priceControlStandardConfig/page
```

Portal `customLoad` 发送的关键参数为：

```json
{
  "order": "",
  "orderField": "",
  "pageNo": 1,
  "pageSize": 20,
  "categoryId": 1165,
  "operatorKeyword": "张",
  "updateTimeStart": "2026-09-01",
  "updateTimeEnd": "2026-09-24"
}
```

`updateTimeRange` 只有完整两端时才拆成 `updateTimeStart/updateTimeEnd`；空范围不会发送这两个字段。分页大小沿用页面支持的 `10/20/50/100`。返回为 `{ list, total }`，每行含 `skus` 与 `rules`。

### 新增/编辑候选和详情

新增时读取品类：

```text
GET admin-api/priceControlStandardConfig/skuTree/categories
```

编辑时额外发送 `excludeConfigId=<当前配置ID>`，这样当前配置占用的SKU不会把自身置灰。选择二级品类后读取规格：

```text
GET admin-api/priceControlStandardConfig/skuTree/skus?categoryId=<二级品类ID>&excludeConfigId=<可选当前配置ID>
```

详情请求为：

```text
GET admin-api/priceControlStandardConfig/get?id=<配置ID>
```

只有 `disabled=false` 的品类和SKU能进入表单。SKU候选中的 `itemId/itemName/skuId/specInfo` 必须作为完整对象保留；不能只传规格名称，也不能跨品类手写ID。

### 表单校验与提交

页面表单字段为 `parentCategoryId`、`controlCategoryId`、`controlSkuIds` 和 `standards`。SDK的 `prepare` 接受规范化后的 `categoryId` 与选中的 `skus`，并生成后端草稿：

```json
{
  "parentCategoryId": 100,
  "categoryId": 1165,
  "skus": [
    { "itemId": 26542, "itemName": "商品A", "skuId": 14634, "specInfo": "规格A" }
  ],
  "rules": [
    {
      "qtyLowerOp": ">=",
      "qtyLowerValue": 1000,
      "qtyUpperOp": "<",
      "qtyUpperValue": 10000,
      "priceLowerOp": ">",
      "priceLowerValue": 0.2,
      "priceUpperOp": "<",
      "priceUpperValue": 0.3,
      "approvalTag": "chick_1"
    }
  ]
}
```

业务规则：

- `skus` 至少一项，`itemId` 和 `skuId` 必填，同一提交内 `skuId` 不能重复。
- 数量和低于指导价的每一侧都必须是“运算符 + 数值”成对出现；数值不能小于0。
- Portal下限运算符为 `>`、`>=`、`=`，上限运算符为 `<`、`<=`；下限选择 `=` 时会清空对应上限，SDK也发送 `null`。
- 每条规则的低于指导价至少完整填写下限或上限一侧；价格最多保留2位小数。
- 两端都存在时，下限数值不能大于上限数值。Java还会检查不同规则在“管控数量 × 低于指导价”上的范围不得重叠。
- Portal本地生成的规则行 `uid` 只用于Vue渲染，`sortNo` 在提交前被删除；SDK草稿不包含这两个字段。编辑时已有规则的 `id` 保留，以便Java按ID同步更新。

新增请求：

```text
POST admin-api/priceControlStandardConfig/create
```

编辑请求：

```text
PUT admin-api/priceControlStandardConfig/update
```

编辑请求在同一JSON中额外包含配置 `id`。两者正文都只包含 `parentCategoryId/categoryId/skus/rules` 及后端允许的规则与SKU字段。

### 删除

删除请求为：

```text
DELETE admin-api/priceControlStandardConfig/delete?id=<配置ID>
```

Portal只在有删除权限时显示按钮；Java删除前还会检查该配置规则是否被订单引用，以及最新低价审批是否允许删除，因此 `true` 回执仍需刷新列表回查。

## 3. 逐字段基准

| 字段 | 页面含义 | 空值/归属 |
| --- | --- | --- |
| `id` | 配置主键；编辑和删除目标 | 来自当前列表/详情，不能用SKU ID代替 |
| `parentCategoryId` | 一级品类ID | 由所选二级品类候选带出，提交必填 |
| `categoryId` / `controlCategoryId` | 二级管控品类ID | 页面内部字段为`controlCategoryId`，提交映射为`categoryId` |
| `categoryFullName` | 一级>>二级品类展示文本 | 只读，不能当ID提交 |
| `skus[].itemId` / `itemName` | 商品ID/名称 | ID提交，名称来自当前候选用于回显 |
| `skus[].skuId` / `specInfo` | 规格ID/名称 | ID提交，名称来自当前候选用于回显 |
| `skus[].disabled` | SKU是否已被其它配置占用 | 候选只读状态；`true`不可选 |
| `rules[].qtyLowerOp/qtyLowerValue` | 管控数量下限 | 可空，但必须成对 |
| `rules[].qtyUpperOp/qtyUpperValue` | 管控数量上限 | 可空，但必须成对；下限为`=`时置空 |
| `rules[].priceLowerOp/priceLowerValue` | 低于指导价下限 | 至少与上限一侧完整存在，价格最多2位小数 |
| `rules[].priceUpperOp/priceUpperValue` | 低于指导价上限 | 可空，但必须成对 |
| `rules[].approvalTag` | 审批标识字典值 | 可空；提交原值 |
| `rules[].id` | Java编辑同步用规则ID | 详情回显可有；新增规则不传，不能伪造 |
| `rules[].sortNo` / `uid` | 后端序号/Vue本地键 | `sortNo`和`uid`不进入SDK提交草稿 |
| `updaterId` / `updaterName` | 最后操作人 | 只读回显 |
| `updateTime` / `createTime` | 更新时间/创建时间 | 只读原值 |

## 4. 操作步骤与证据

1. 列表查询先调用 `sale-low-price-category-options`（需要筛选时），再调用 `sale-low-price-list`；保留目标行完整的 `id/skus/rules`。
2. 新增先调用 `sale-low-price-sku-tree-categories`，选择未置灰的二级品类，再调用 `sale-low-price-sku-tree-skus`；编辑时两个候选请求都带 `excludeConfigId`。
3. 用户确认新增时调用 `sale-low-price-prepare-create`，展示草稿；取消只丢弃草稿，确认后将同一 `draft` 交给 `sale-low-price-create`。
4. 编辑先调用 `sale-low-price-get` 回填详情，保留已有规则ID；确认后调用 `sale-low-price-prepare-update`，再将同一草稿交给 `sale-low-price-update`。
5. 删除先调用 `sale-low-price-prepare-remove`，向用户说明Java可能因订单低价审批引用阻断；确认后调用 `sale-low-price-remove`。
6. 新增、编辑、删除成功或超时后都按同一配置ID刷新详情/列表；不要把ID回执或`true`回执当作独立写入证据。

离线证据由 `test/sale-low-price.test.ts` 和 AI说明契约提供，覆盖菜单归属、所有页面请求、权限常量、表单净载荷、规则校验、Java约束和坏回执。当前尚未在真实测试环境执行本页新增、编辑、删除及写入后的独立回查；该缺口保持如实记录。
