# 任务日志

## 能力定义

- 菜单归属：门户 → 系统设置 → 销售设置 → 任务管理 → 任务日志
- 页面路径：`/dashboard/sale/job/schedule-job-log/list`
- 页面权限：`/dashboard/sale/frame/job/scheduleJobLog`
- 新建、编辑、删除和保存按钮权限：`job:scheduleJobLog:edit`
- 请求实例：Portal `app/portal/utils/http/crm.js`，调用 SDK 时必须配置 `httpBaseUrls.crm`。
- `module-type`：`60`
- 页面可达动作：分页查询、按三个字段筛选、点击当前行查看只读详情、新建、编辑、单条删除；Portal公共列表状态还会发送默认空的 `order`、`orderField`，页面没有排序控件。
- 页面点击任务 `jobId` 时直接把当前列表行传给只读弹窗，没有发详情 GET；因此不暴露后端虽存在的 `GET /vue/job/scheduleJobLog/scheduleJobLog`。

对应 SDK 能力：

| capability | 作用 | 写入 |
| --- | --- | --- |
| `sale-schedule-job-log-list` | 查询任务日志 | 否 |
| `sale-schedule-job-log-prepare-create` | 本地整理并校验新建表单 | 否 |
| `sale-schedule-job-log-create` | 新建任务日志 | 是 |
| `sale-schedule-job-log-prepare-update` | 本地整理并校验编辑表单 | 否 |
| `sale-schedule-job-log-update` | 编辑任务日志 | 是 |
| `sale-schedule-job-log-prepare-remove` | 本地准备单条删除并等待确认 | 否 |
| `sale-schedule-job-log-remove` | 删除一条任务日志 | 是 |

## 参数契约

### 查询

`sale-schedule-job-log-list` 接受：

| 参数 | 页面默认值 | 请求字段 | 说明 |
| --- | --- | --- | --- |
| `order` | `''` | `order` | Portal公共列表排序值；页面没有排序控件 |
| `orderField` | `''` | `orderField` | Portal公共列表排序字段；页面没有排序控件 |
| `beanName` | `''` | `beanName` | Bean名称；后端按等值条件筛选 |
| `methodName` | `''` | `methodName` | 方法名；后端按等值条件筛选 |
| `status` | `''` | `status` | `execute_status` 字典值；后端按等值条件筛选 |
| `pageNo` | `1` | `pageNo` | 从 1 开始 |
| `pageSize` | `20` | `pageSize` | Portal 常用值为 10/20/50/100/200/500 |

Portal CRM 列表接口返回 `{ list, count }`；SDK 对外返回 `{ list, total }`，`total` 是筛选后的总记录数。列表请求还会由 CRM 请求拦截器处理 Portal 的通用请求头和防缓存参数。

### 返回字段

`list[]` 的页面消费字段如下：

| 字段 | 含义 |
| --- | --- |
| `id` | 任务日志记录 ID，编辑和删除时使用 |
| `jobId` | 定时任务 ID，页面第一列可点击查看当前行 |
| `beanName` | Spring Bean 名称 |
| `methodName` | 执行方法名 |
| `params` | 任务执行参数原文，详情/编辑弹窗使用 |
| `status` | 执行结果字典值，页面用 `execute_status` 标签展示 |
| `times` | 耗时整数 |
| `createDate` | 触发时间 |
| `updateDate` | 更新时间，编辑时页面会从提交表单中去掉 |
| `error` | 执行失败信息，详情/编辑弹窗使用 |
| `remarks` | 备注信息，详情/编辑弹窗使用 |

字段缺失或空值按 `null` 返回；`id` 必须来自当前页面返回的记录，不能用 `jobId`、Bean 名称或方法名代替。

### 新建和编辑表单

Portal 的 `ModalFormContent.vue` 先形成完整表单，再由 `list.vue` 把整份表单提交到同一个接口：

```text
POST /vue/job/scheduleJobLog/save
Content-Type: application/x-www-form-urlencoded
```

表单字段：

| 字段 | 页面规则 | 后端规则 |
| --- | --- | --- |
| `jobId` | 必填 | 非空，最多 64 个字符 |
| `beanName` | 可空 | 最多 200 个字符 |
| `methodName` | 可空 | 最多 100 个字符 |
| `params` | 可空 | 最多 2000 个字符 |
| `status` | 必填；新建默认字符串 `10`；来自 `execute_status` 字典 | 非空，最多 4 个字符 |
| `times` | 必填，输入框最小值为 1 | Java `int`；SDK要求安全正整数 |
| `error` | 可空 | 最多 2000 个字符 |
| `remarks` | 可空 | 按页面原字符串提交 |
| `id` | 新建省略；编辑保留当前行 ID | 编辑时作为实体主键 |

SDK 的 `prepareCreate` / `prepareUpdate` 只做本地校验和表单整理，不发请求；用户确认后把准备结果中的完整 `form` 交给 `create` / `update`。页面提交不是差异 PATCH，不能只提交修改过的字段。

保存成功回执是字符串文案，页面只提示“保存成功”并刷新列表；SDK 对外返回 `undefined`，必须重新查询核对字段，不把文案解释成新 ID。

### 删除

Portal 删除按钮会先显示确认框，确认后发送：

```text
DELETE /vue/job/scheduleJobLog/{id}
```

页面没有额外删除请求头，也没有批量删除。SDK 的 `prepareRemove` 不发请求；用户确认后才调用 `remove`。后端把 `del_flag` 更新为删除标记，属于逻辑删除；成功回执是字符串文案，SDK返回 `undefined`，必须列表回查确认目标 ID 已消失。

## 逐字段基准

基准来源：

- Portal：`app/portal/menus/sale.js:208-209`、`app/portal/views/dashboard/sale/job/schedule-job-log/list.vue`、`ModalFormContent.vue`
- CRM 后端：`ScheduleJobLogVueController`、`ScheduleJobLog`、`ScheduleJobLogService`、`CrmScheduleJobLogDao.xml`
- SDK：`src/capabilities/sale-schedule-job-log.ts`、`test/sale-schedule-job-log.test.ts`

已核对的请求映射：

| 页面动作 | 方法 | 路径 | 请求体/参数 | SDK结果 |
| --- | --- | --- | --- | --- |
| 查询 | GET | `/vue/job/scheduleJobLog/list` | `order/orderField` + 三个筛选字段 + `pageNo/pageSize` | `{ list, total }` |
| 新建 | POST | `/vue/job/scheduleJobLog/save` | 完整表单，无 `id` | `undefined` |
| 编辑 | POST | `/vue/job/scheduleJobLog/save` | 完整表单，带当前行 `id` | `undefined` |
| 删除 | DELETE | `/vue/job/scheduleJobLog/{id}` | 无业务体、无额外头 | `undefined` |
| 查看详情 | 无请求 | 当前列表行传入只读弹窗 | 不调用后端详情接口 | 列表行已包含页面字段 |

以下内容是源码基准和离线测试证据，不冒充真实环境验证：当前尚未在测试环境执行本页列表、查看、新建、编辑、删除和写入回查闭环。

## 操作步骤

### 查询和查看

1. 用用户给出的 `beanName`、`methodName`、`status` 调用 `sale-schedule-job-log-list`。
2. 展示 `list` 字段，使用 `total` 做分页。
3. 用户点击 `jobId` 时直接展示当前记录字段，不额外调用不可达详情接口。

### 新建

1. 取得用户明确填写的完整表单，调用 `sale-schedule-job-log-prepare-create`。
2. 向用户展示将提交的字段；准备阶段没有写入。
3. 用户取消时丢弃准备结果，不发送 POST。
4. 用户明确确认后，把同一 `form` 交给 `sale-schedule-job-log-create`。
5. 成功或超时后按关键字段分页查询核对；匹配不唯一时不能猜测哪条是本次新建。

### 编辑

1. 从当前列表取得目标记录 ID，并保留页面表单所需的完整字段。
2. 调用 `sale-schedule-job-log-prepare-update`，确认 `jobId`、`status`、`times` 和其余字段均符合规则。
3. 用户取消时丢弃准备结果，不发送 POST。
4. 用户明确确认后调用 `sale-schedule-job-log-update`。
5. 按同一 `id` 重新查询并逐字段核对；不能用空回执代替回查。

### 删除

1. 从当前列表取得目标记录的 `id`，调用 `sale-schedule-job-log-prepare-remove`。
2. 向用户展示将删除的记录并等待明确确认。
3. 用户取消时丢弃删除准备结果。
4. 用户确认后调用 `sale-schedule-job-log-remove`。
5. 重新查询并逐页核对目标 ID 不再出现；超时先核实，不盲目重试。
