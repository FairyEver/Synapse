# 机构扩展

页面路径：`/dashboard/sale/sys/office/list`；菜单权限：`/dashboard/sale/frame/sys/office`；销售页面 `module-type=60`。

本页属于提示词保留范围的「系统设置 → 销售设置」，不是独立的生产根菜单。Portal 顶部明确提示“如需新增组织、用户请前往人系统创建”，因此 SDK 不发布新增组织能力。

## 能力定义

| 能力 | SDK 方法 | Portal 请求 | 性质 |
| --- | --- | --- | --- |
| 列表 | `sale-sys-office-list` / `saleSysOffice.list` | `GET /admin-api/sales/organization/page` | 读 |
| 人系统机构树 | `sale-sys-office-organization-tree` / `.organizationTree` | `GET /admin-api/sales/organization/tree`，`isSalesTree=false` | 读 |
| 状态/级别/类型选项 | `sale-sys-office-status-options`、`sale-sys-office-grade-options`、`sale-sys-office-type-options` | `GET /admin-api/system/dict-data/page`，每次`pageNo=1,pageSize=100` | 读 |
| 详情 | `sale-sys-office-get` / `.get` | `GET /admin-api/sales/organization/detail/{id}` | 读 |
| 销售上级树 | `sale-sys-office-sales-tree` / `.salesTree` | `GET /admin-api/sales/organization/tree`，空参数 | 读 |
| 负责人树 | `sale-sys-office-primary-person-tree` / `.primaryPersonTree` | `GET /admin-api/sales/organization/tree`，`isNeedUsers=true,isSalesTree=false` | 读 |
| 销售业务树 | `sale-sys-office-business-tree` / `.businessTree` | `GET /admin-api/sales/item/getShopCategoryItemTree` | 读 |
| 编码校验 | `sale-sys-office-check-code` / `.checkCode` | CRM `GET /vue/sys/office/checkOfficeCode` | 读 |
| 编辑 | `sale-sys-office-prepare-update` → `sale-sys-office-update` | `PUT /admin-api/sales/organization/update` | 写 |
| 单条停用 | `sale-sys-office-prepare-stop` → `sale-sys-office-stop` | `PUT /admin-api/sales/organization/update` | 写 |
| 批量停用 | `sale-sys-office-prepare-batch-stop` → `sale-sys-office-batch-stop` | `POST /admin-api/sales/organization/batch-disable`，JSON数组 | 写 |
| 导出 | `sale-sys-office-export` / `.export` | `GET /admin-api/sales/organization/export` | 读文件 |

列表、树、字典、详情、编辑、停用、批量停用和导出使用 Portal `platform` 实例；编码唯一性检查使用 `crm` 实例。编辑按钮要求 `sys:office:edit`，单条停用要求 `sys:office:stop`，批量停用要求 `sys:office:stopBatch`。

## 参数契约与提交规则

### 列表

Portal 公共列表实际发送：

```text
order='', orderField='', parentId='', name='', code='', salesCode=''
salesType='', salesStatus=1, pageNo=1, pageSize=20
```

`parentId` 来自人系统机构树节点 `id`；`salesType`、`salesStatus` 是字典 `value`，不是展示 `label`。筛选状态默认 `1`。导出复用筛选字段和当前分页，但不发送 `order/orderField`，SDK 使用会话请求头，不在URL拼接浏览器token。

### 编辑表单

Portal 详情回显时把 `groupSalesAreaCodes` 按逗号拆成数字数组，把 `salesBusiness` 按逗号拆成数组；`salesParentId` 为空时回退到 `defaultSalesParentId`。

Portal 表单校验规则：

- `salesCode`、`salesType`、`salesStatus` 必填；销售编码变化时先调用 CRM `checkOfficeCode`，原编码未变化则不发校验请求。
- `salesParentId` 必填，且不能选择当前 `salesId` 自身。
- `salesGrade`、`salesMaster`、销售范围和销售业务没有额外 required 规则；`salesMaster` 默认空字符串。
- `salesType == 3` 时，`groupSalesAreaCodes` 和 `groupSalesBusinessCodes` 数组分别 `join(',')` 成 `groupSalesAreaCodes`、`salesBusiness`；其它类型完全省略这两个提交字段。

编辑提交严格等价于：

```text
pick(formData, [
  id, salesId, salesCode, salesType, salesParentId, salesParentIds,
  salesGrade, salesMaster, salesStatus, groupSalesAreaCodes, salesBusiness
])
```

因此 `name`、人系统 `code`、人系统 `parentId`、`remarks`、`groupSalesBusinessCodes` 等不会进入 PUT body。SDK 的 `prepareUpdate` 不发请求；编码变化时由调用方先执行 `checkCode`，确认返回 `true` 后再把同一草稿交给 `update`。

### 停用

Portal 只有在当前列表筛选 `salesStatus == 1` 时显示单条和批量停用；批量按钮还要求有勾选行和 `sys:office:stopBatch`。单条 body 固定为 `{ id, salesStatus: 2 }`。批量 body 是选中机构ID数组本身，不是 `{ ids }` 对象。SDK 的两个 `prepare` 阶段会校验这些前置条件且不发请求。

## 逐字段基准

| 字段 | 来源/含义 | 提交形态 |
| --- | --- | --- |
| `id` | 人系统组织主键 | 编辑/停用使用；不能用`salesId`替代 |
| `salesId` | 销售组织自身ID | 编辑必带；不能用人系统`id`替代 |
| `salesCode` | 销售机构编码 | 非空；变更前CRM校验 |
| `salesType` | `sys_office_type` value | 数字；3控制扩展字段 |
| `salesParentId` | 销售上级树节点`salesId` | 非空且不能等于当前`salesId` |
| `salesParentIds` | 详情返回的销售上级链 | 有值时原样带回 |
| `salesGrade` | `sys_office_grade` value | 可选数字 |
| `salesMaster` | 负责人树用户节点`id` | 可选；默认空字符串 |
| `salesStatus` | `sales_organization_status` value | 编辑必填；停用固定为2 |
| `groupSalesAreaCodes` | 销售范围多选 value 数组 | 仅类型3，逗号字符串 |
| `groupSalesBusinessCodes` | 销售业务树多选 value 数组 | 仅类型3，改名为`salesBusiness`后逗号字符串 |
| `orgPath`、`name`、`code`、`updateTime` | 人系统/销售组织列表展示字段 | 只读，不进入编辑pick |

负责人树是 Portal 的显示转换结果：组织节点保留为不可选节点，用户节点追加到其 `children`，并用 `realName` 覆盖 `name`。销售业务树接口返回根对象，页面只把根对象的 `children`作为树数据源。

## 操作步骤与验证

1. 先调用三组字典和需要的组织树；列表筛选时从 `organizationTree` 取`parentId`。
2. 编辑时用当前行 `id` 调 `get`，加载 `salesTree`、`primaryPersonTree`；当类型为3时加载 `businessTree`。
3. 销售编码改变时调用 `checkCode`；返回 `false` 或请求失败都停止提交。
4. 调 `prepareUpdate`，向用户展示整理后的 draft 并取得确认；取消只丢弃 draft。确认后调用 `update`。
5. 单条或批量停用先确认当前筛选状态为1，再调用对应 `prepare`；用户取消不发写请求。
6. 每次编辑、停用或批量停用成功、超时或响应丢失后，都重新查询列表和机构树，按机构ID核对状态、销售编码、上级和扩展字符串；不能只凭 `true` 回执报告落库成功。
7. 导出调用 `export`，保存返回的 Base64 文件；Java 默认文件名为 `机构.xls`。
