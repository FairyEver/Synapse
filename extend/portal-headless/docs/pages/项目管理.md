## 参数与列表请求

列表默认表单由 Portal 写死为：

```text
projectName=null
projectCode=null
projectTypes=[]
projectAttributes=[]
stages=[]
companyIds=[] → 请求前转换为 null
principalName=null
status=1
pageNo=1
pageSize=20
```

SDK在请求配置中保留 Portal 的 `order=''`、`orderField=''`、上述筛选字段和分页字段。`companyIds` 按页面 `normalizeCompanyIds` 转成逗号字符串，例如 `[71, 72]` → `"71,72"`。平台 HTTP 拦截器随后会移除 null、加 `_t`，并负责会话头；SDK不手拼认证头。

类型字典值来自固定 Java 枚举：项目类型 `1/2/3` 为生物技术类/信息技术类/工程类；项目属性 `1/2/3` 为自主开发/外部科研/受托开发；阶段 `1/2` 为研究/开发；状态 `0/1` 为停用/启用。运行时字典标签和部署扩展值未独立观测。

公司选择器请求完整组织树，页面通过 `companyOnly` 和法人标记本地禁用不可选节点。负责人选择器按姓名关键字分页，只查询状态 `1,4`；SDK拒绝空关键字和超过100条的页大小，避免无头调用全量拉取人员。

## 表单与写入规则

新增表单必填项目名称、项目编号、项目类型、项目属性、课题负责人；名称和编号最多500字符。所属公司可空。新增默认 `status=1`，并补齐两个空阶段：

```json
[
  {"stage":1,"startDate":"","endDate":""},
  {"stage":2,"startDate":"","endDate":""}
]
```

阶段开始和结束日期必须同时填写或同时为空；单阶段开始日期不得晚于结束日期；研究阶段结束日期不得晚于开发阶段开始日期。日期格式为 `YYYY-MM-DD`，空日期按页面发送空字符串，详情明确返回的 null 保留为 null。

编辑页禁用项目名称、编号、类型、属性、所属公司和负责人，只能修改两个阶段日期。`prepareUpdate` 保留完整 `current` 和 `previous` 快照，`changes` 只接受 `stages`。后端 `update` 实际删除并重建该项目的阶段记录，返回 true 不包含详情。

启用和停用是两个绝对动作，不是 toggle：启用只接受当前 `status=0`，停用只接受当前 `status=1`。启用时后端还校验同租户内项目编号不能与其它启用项目重复。删除会被付款单或差旅申请引用阻断。

## 正常消费步骤

1. 需要负责人时，先调用 `finance-setting-project-user-search`，给姓名关键字；把所选候选的 `id`、`username`、`realName` 分别写入 `principalStaffId`、`principalStaffNo`、`principalName`。
2. 需要公司时调用 `finance-setting-project-organization-tree`，递归查找法人公司节点，把节点 `id` 作为 `companyId` 或列表 `companyIds`，不要把名称当ID。
3. 新增先 `prepare-create`，确认草稿后 `create`；返回ID后用 `get` 回查全部字段和阶段。
4. 编辑先用列表行ID调用 `get`，再 `prepare-update` → `update`；如需恢复，使用 `previous.stages` 再次 `update`。这是再次写入，不是服务端事务回滚。
5. 启停或删除前保留同一列表行的ID和状态；写请求成功或超时都要用 `get`/`list` 回查，不能把 true 当成业务已验证。
