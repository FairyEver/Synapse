## 这一段是「分歧史」留档：基准一度记成 `finished=1`，已定案

**结论先写**：这一页现在的契约与基准**逐字节一致**，`finished=2`。
下面这段留着，是因为它同时记下了**一次抓取方法的系统性缺陷**，比这一页本身值钱。

### 初版基准里那条是 `finished=1`

初版基准（八页在**同一次 SPA 会话**里按 create → todo → done → copy 顺序抓）里，
标着 `/dashboard/flow/task/done/list` 的那条请求发的是 `finished=1`：

```text
GET /admin-api/bpm/hr/task/list-by-category-web
    ?order=&orderField=&name=&title=&startUserName=&finished=1&selectType=1&pageNo=1&pageSize=20&_t=<ts>
```

**它与基准里前一条「待办任务」的 URL 逐字节相同。** 但这一页自己的声明是

```vue
<!-- app/portal/views/dashboard/hr/flow/task/done/list.vue -->
<PageView :finished="2" :componentMode="true" key="done"/>
```

### 当时判定：**采集会话的状态泄漏**，不是这一页的契约

证据链（都在源码里）：

1. 两页渲染的是**同一个组件**，而组件在**非 setup 的 `<script>` 块**里有一个**模块级**变量
   `let stateCache = null`（`backlog/task-examine/list.vue:130`）；
2. 该实例 `onBeforeUnmount` 时把整个 `formState`（**含 `finished`**）存进去
   （`:267-274`），下一次 setup 时 `Object.assign(rrList.formState, stateCache.formState)`
   覆盖回来（`:259-264`）——**这个变量不按路由分**；
3. 采集顺序是「待办 → 已办」，所以在待办页存下的 `finished=1` 被已办页读走。

换句话说：**只要用户先打开过待办任务、再打开已办任务，这一页就会显示待办的数据**。
这是**页面自己的 bug**（同一个组件挂在两条菜单下时状态互相污染），
不是"这一页本来就用 `finished=1`"。反过来也成立：先进已办再进待办，待办页会显示已办数据。

### 定案：2026-09-21 新会话直开，发的是 `finished=2`

新会话**直接打开** `#/dashboard/flow/task/done/list`（不先经过待办页）：

```text
GET /admin-api/bpm/hr/task/list-by-category-web
    ?order=&orderField=&name=&title=&startUserName=&finished=2&selectType=1&pageNo=1&pageSize=20&_t=<ts>
```

⇒ 泄漏判断成立，`flowTask.listDone()` 钉死 **2** 是对的。基准已按新会话重抓修正，
该行标注为「**已办任务（新会话直开）**」。

期间 SDK 一直按 **2** 发（把 1 写死会**静默地把待办数据当成已办返回**，
正是本仓库最不想要的那种"不报错但是错的"）；测试用例也改回了与另外七页同形的
普通逐字段一致断言，那段历史写在用例上方的注释里。

### ⚠️ 方法学结论：抓基准时「同域多页」要当心

`tools/baseline/install-hook.js` 装在 SPA 里、**跨 hash 导航不卸载**，
所以**先访问的页面会把模块级状态漏给后访问的页面**。
⇒ 同域多页抓基准，要么**每页一个新会话**，要么**按顺序复核**。
这条已经写进基准手册。

## 逐字段基准（除 `finished` 外）

```text
order, orderField, name, title, createTime[0], createTime[1], startUserName,
finished, selectType, processCategory, pageNo, pageSize, _t
```

请求头（**没有 `module-type`**）：`tenant-id` / `token` / `Accept-Language: zh-CN` /
`Accept: application/json, text/plain, */*`。

三条与「待办任务」完全一样的性质（两页共用一个组件，所以**不要分别记**）：

1. 空值**照发**（空串，不是省略）；只有 `processCategory` 初值是 `null`、被 `skipNulls` 丢掉。
2. `createTime` **没有 +1 天**改写，原样两端序列化成 `createTime[0]` / `createTime[1]`。
3. `selectType` 在请求里恒有（初值 1）；本页**开放**它。

## 操作步骤

```text
1. 进入「已办任务」（/dashboard/flow/task/done/list）
2. （可选）把「时间范围」改成「全部」——这是 selectType=2（本页独有）
3. （可选）填流程名称 / 审批内容 / 发起人
4. （可选）选发起时间区间
5. 查询
6. 行上：「详情 / 跟进」总有；「撤销审批」只在 canWithdraw === true 时出现
```

点击「撤销审批」后，Portal 打开原因弹窗；原因可不填，提交前先 `trim`，空值实际发送
`reason: "无"`。请求体严格为 `{ id: taskId, reason }`，其中 `id` 是当前已办行的历史任务 ID，
不是流程实例 ID 或下一节点任务 ID。撤销成功后必须重新查询待办、已办和流程详情；原历史任务
仍保留但不会复用旧 ID，原审批节点会生成新的待办。

### `flow-task-done-withdraw`

在我的已办任务页撤销当前用户已通过且仍允许撤销的审批。

执行：`sdk.flowTask.withdrawDone`；性质：write。在我的已办任务页撤销当前用户已通过且仍允许撤销的审批。

- 边界：按钮条件是 `finished=2 && canWithdraw===true`；列表快照可能在提交前过期，最终能否撤销以服务端实时校验为准。
- 边界：后端要求当前用户是原审批人、历史任务已完成且通过、是最近完成任务、流程仍运行、只有一条未处理的串行下一节点、下一节点未挂起且业务守卫允许；并行/多实例/会签多个活动任务不支持。
- 边界：不允许时常见业务码为 `1009005015`；应保留后端消息并刷新相关列表，不能把按钮仍在当成成功。撤销只改变流程任务和操作记录，不自动回滚业务模块已写入的数据。
- 边界：后端 DTO 允许省略/空 reason，但 Portal Web 在发送前将空原因替换成「无」；SDK 按 Web 端实际请求而不是后端宽松 DTO 生成载荷。

| 参数 | 意义与来源 |
| --- | --- |
| taskId | 已办列表行的历史任务 ID；不是流程实例 ID、业务单据 ID 或下一节点任务 ID。只能使用对应列表返回的 list[].id。；来源：同一页面列表能力返回的 result.list[].id；仅选择 canWithdraw === true 的行 |
| reason | 撤销原因，可省略。Portal 表单会先 trim，空串或全空白最终发送「无」；SDK 保持该 Web 请求规则。；来源：用户在 Portal 撤销弹窗中填写；不填时沿用 Portal 的默认值「无」 |

返回：`boolean`。正常成功回执不是空值；未收到 true 不能当作撤销成功。


- 消费：调用前必须从同一页面的已办列表取得历史任务 ID，并确认该行 `canWithdraw === true`；这个字段只是 Portal 的按钮 gate，不是调用方可以替代的后端授权。
- 消费：Portal 的 PUT body 固定为 `{ id, reason }`；taskId 映射到 id，reason 先 trim，空值发送「无」。不要把流程实例 ID、业务单据 businessKey 或下一节点任务 ID 放进 id。
- 消费：成功后重新读取待办、已办和流程详情：原历史任务保留但 ID 不复用，下一节点被撤销，原审批节点会产生新的待办任务。

完成条件：收到 true 后重新查询待办、已办和流程详情，并使用新生成的待办任务 ID；旧历史任务 ID 不得再次提交。

- 失败处理：权限或会话错误交由用户恢复登录态；不要用其他页面上下文或其他租户重试。
- 失败处理：收到 `1009005015` 时说明实时流程条件已不满足：展示后端消息并刷新，不要盲目重复提交。
- 失败处理：网络超时无法判定结果时先查询待办/已办/详情；没有 requestId，不能用新幂等键盲目重试。

- **仍有缺口**：本轮只有源码、后端单元测试语义和离线 HTTP 载荷回归；没有在测试租户执行真实撤销，因此未宣称写入和回查已实测。
