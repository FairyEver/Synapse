## 参数契约与逐字段基准

### 列表、候选和详情

列表默认发送：

```json
{
  "order": "",
  "orderField": "",
  "name": "",
  "type": null,
  "pageNo": 1,
  "pageSize": 20
}
```

`name`是报表名称模糊条件；`type`是 `salary_report_type` 字典值，不是分类名称；页大小只接受 `10/20/50/100/200/500`。返回 `{ list, total }`，`list`是当前页，`total`用于继续翻页。

`reportFields({ type: 0 })` 返回字段候选 `{ name, tableName, columnName, type }`。创建/编辑必须保留同一候选项的四个字段和用户选择顺序，不能只用展示名拼来源表列。`all()`只用于复制弹窗候选，后续动作仍使用对应模板 `id`。

`get({ id })` 返回模板基本字段和 `detailList`。详情字段中：

- `name`是展示名称；`tableName`/`columnName`是提交时的来源表列；
- `fieldName`是后端由 `tableName + '_' + columnName` 转驼峰后生成的动态结果键；
- `isFilterable=1`的项才在详情页形成筛选控件；`filterType`当前页面提交固定为 `=`；
- `sort`和数组顺序决定列顺序；`lockTopColumnsCount`是冻结前置列数量，页面默认 `0`；
- `tag=1`表示明细表，`tag=2`表示汇总表；`type`和 `tag`的其他分类字典标签仍以Portal字典为准，SDK不猜标签。

### 动态明细与导出

`getDetail`和`export`都接收 `{ id, year?, month?, filters? }`。先用 `get` 建立 `detailList[].fieldName → detailList[].name` 映射，再按运行时真实 `fieldName`组织 `filters`；不要把中文展示名、`tableName`或`columnName`当筛选键。省略 `year/month`时，Java服务端使用当前年/月；导出返回 `{ fileName, contentType, base64, byteLength }`，空文件会抛错。

Java `getDetail` 控制器会把 `hrStaffName`、`hrStaffStaffCode`、`hrStaffMobile`、`hrOrganizationName`、`hrPostName` 强制写成 `null`。SDK仍忠实发送调用方给出的动态参数，但不承诺这五个筛选在当前后端实现中生效；这是后端差异，不在SDK里静默改写。

### 创建/编辑提交规则

Portal表单实际提交的是：

```json
{
  "name": "工资明细",
  "type": "3",
  "tag": "1",
  "lockTopColumnsCount": 0,
  "detailList": [
    {
      "name": "员工姓名",
      "tableName": "hr_staff",
      "columnName": "name",
      "type": 0,
      "isFilterable": 1,
      "filterType": "="
    }
  ]
}
```

SDK的表单输入用 `fields` 表示字段候选，用 `filterFieldNames` 表示页面 `searchKey`；准备和实际写入都会按同一规则生成 `detailList`：字段顺序保持不变，`isFilterable`按字段名映射成 `0/1`，`filterType`固定为 `=`。`name`必须非空、不能全空格且最多50字符；`tag`必须为1或2；`lockTopColumnsCount`必须为非负整数；页面没有字段非空、`type`或`tag`的完整必填校验，后端仍可能拒绝不完整字段配置。

`prepareCreate`/`prepareUpdate`只做本地校验和请求草稿生成，不写服务端；取消时丢弃草稿。创建使用 POST，编辑使用带 `id` 的 PUT。写请求没有 `requestId`或页面撤销接口，空回执不等于记录已经可见；成功或超时后应重新 `list`/`get`逐项核对名称、分类、冻结列、字段顺序和筛选标记。

复制弹窗从 `allReport`取源模板，名称必填且最多30字符；`copy`使用 multipart 字段 `id`、`name`。复制接口不返回新模板ID，成功或超时后必须按完整新名称 `list`，多条同名时逐个 `get`，不能把请求成功直接当作已定位新记录。

## 操作步骤、失败处理与验证边界

1. 需要编辑、动态明细或导出时先用 `list`/`get`取得当前模板ID和字段定义。
2. 创建/编辑先调用对应 `prepare`，逐项检查 `draft.detailList` 的来源表列、顺序和 `isFilterable`，用户确认后再提交；用户取消不发写请求。
3. 删除先以最新列表行ID调用 `prepareRemove`，确认后调用 `remove`；成功或超时后翻页确认所有原ID消失。
4. 动态查询和导出使用 `get`得到的 `fieldName`，按 `byteLength`确认导出非空；空列表只代表当前条件无行。
5. 非法ID、重复删除ID、错误字段映射、非法动态键、名称长度/空白、标签、冻结列和页大小会在请求前失败；401/403、网络错误和后端校验错误原样保留，不能用空结果代替。
