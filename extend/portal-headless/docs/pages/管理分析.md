## 参数契约

### 四条统计 POST —— 同一个 body，四个端点

body 取自 `formComputed`（`department/list.vue:354-361`）：

```
year → month → organizationIdList → temIdList
```

| 端点 | 喂给 |
| --- | --- |
| `/performance/statistics/homepage/deptMonthProtocolInfo` | 顶部表格 + 签订情况饼图 |
| `/performance/statistics/homepage/deptSignStatisticsInfo` | 签订数量折线图 |
| `/performance/statistics/homepage/branchDeptSignInfo` | 部门柱状图 |
| `/performance/statistics/homepage/deptScoreStatisticsInfo` | ⚠️ **卡片已被注释掉**（见下） |

⚠️ **`year`/`month` 是数字**（`Number(format('YYYY'))` / `Number(format('MM'))`）——
与[个人分析](./个人分析.md)的同名字段（字符串）**类型相反**。
用 `buildDeptYearMonth('2026-09')` → `{ year: 2026, month: 9 }`。

⚠️ **默认值是"上月"**（`formState.yearMonth = dayjs().subtract(1,'month')`，`list.vue:349`），
不是"当前月"，也不是空。

`temIdList` 页面表单里有这个字段但**没有控件**，恒为 `[]`。

### 自查分析 POST —— 另一套 body

`/performance/statistics/homepage/selfCheck`（`rrListSelf` 的 `customLoad`，`list.vue:408-414`）：

```
order → orderField → staffCodeList → year → month
```

- **没有 `pageNo`/`pageSize`** —— `getDataListIsPage` 被注释掉了（`list.vue:402`）。
- **`yearMonth` 与 `staffNameList` 不在 body 里**（被 `omit` 掉）。
- ⚠️ **`staffCodeList` 为空时页面发的是 `null`，不是 `[]`**（`list.vue:409`）。
  本能力照此处理，但**空数组时直接拒绝发请求**（见下）。

## 逐字段基准

`baseline/perf-salary.browser.json`（2026-09-21 抓，测试环境）里本页有 **5 条**：

```
GET  /admin-api/org/organization/getRoleOrganizationTree?_t=<ts>

POST /admin-api/performance/statistics/homepage/deptMonthProtocolInfo
POST /admin-api/performance/statistics/homepage/deptSignStatisticsInfo
POST /admin-api/performance/statistics/homepage/branchDeptSignInfo
POST /admin-api/performance/statistics/homepage/deptScoreStatisticsInfo
     ← 四条 body 逐字相同：
       {"year":2026,"month":8,"organizationIdList":["34"],"temIdList":[]}
```

四条 body 逐字相同这一点**已被基准证实**（四条 `body` 字符串完全一致）。

⚠️ 抓取时间是 **2026-09-21**，抓到的是 **`month=8`** —— 即**上月**，
与源码的 `dayjs().subtract(1,'month')` 一致（**不是"当前月"**）。
`month` 是**裸数字** `8`（不是 `"8"`），`organizationIdList` 是**数组** `["34"]`（元素是字符串 id）。

第一条 `getRoleOrganizationTree` 是页面上「组织」筛选下拉
（`portal-hxr-tree-select-role-org`）的候选 —— 按角色返回整棵树（约 580 KB），
**不是**本页的数据请求，本能力**不提供**（D6 / H35）。

> 📌 基准的第一版**只抓到了候选那一条**，四条统计 POST 一条都没有。我据此推测过
> "`initialize()` 里 `await getFirstOrg()` 没有 try/catch，它一抛后面四条就不执行"。
> **补抓后四条全在 ⇒ 那个推测是错的，已删。** 线上就是会发这四条。
> 记在这里是为了说明：当时那个推测看起来很像真的（源码里确实没有 try/catch），
> **但它是错的** —— 缺基准时推出来的因果链，再自洽也不能当结论用。

**自查分析那一条**（`POST …/selfCheck`）**基准里仍然没有** ——
这符合预期：页面只在本地勾选表非空时才发它（`department/list.vue:612-616`），
抓取时没有勾选任何人。所以**它仍是纯静态推导**，见下。

## ⚠️ 「第 4 条卡片被注释掉，但请求照发」

`deptScoreStatisticsInfo` 对应的图表卡片在模板里**整块被注释掉**了
（`department/list.vue:106-126`，注释里还写着"业务方要求隐藏"），
**但 `search()` 与 `initialize()` 里仍然在调 `deptScoreStatisticsExecute()`**
（`list.vue:495`，两处调用在 `:573-580` / `:582-590`）。

⇒ **页面每次查询都会白打一次这个接口。**

本能力**照实际行为保留**（不是照"应该怎样"）：能力会发四条 POST，
`getAnalysisDepartmentSummary()` 的返回值里也有 `deptScoreStatisticsInfo` 这一项。
有一条测试专门钉住"这条请求照样发"，防止后来的人"顺手清理"掉它 ——
清理掉就不再与浏览器一致了。

## 真实验证

### 与基准逐字段核对（2026-09-21）—— ✅ 四条统计 POST 已核准

- **URL 与顺序**：四条 POST 的 URL 与基准**逐条相同**（`normalize()` 后逐字比较）。
- **body**：四条 body 的**键序与值**都与基准逐字一致
  （喂 `{ year: 2026, month: 8, organizationIdList: ['34'] }`，即基准抓到的那一组）。
  另有一条断言钉住"基准里四条 body 逐字相同"这件事本身。
- **年月是数字**：与基准里的裸数字 `2026` / `8` 对上（**不是**字符串）。
- **默认值是上月**：不传参时发出的是"上月"，而基准抓于 2026-09-21 抓到 `month=8`，
  两条互相印证（也明确断言了 `month !== 9`）。
- **第 4 条照样发**：本地断言 + 基准里确实有它，两头都钉住。

⚠️ **`selfCheck` 那一条仍然没有基准**（页面只在勾选表非空时才发，抓取时没勾选）。
它的 body 键序（`order → orderField → staffCodeList → year → month`）、
"没有 `pageNo`/`pageSize`"、"`yearMonth`/`staffNameList` 被 omit"、
以及"空 `staffCodeList` 直接拒绝发请求"这几条，**都是静态推导 + 本地测试**，
**没有真实请求佐证**。

### 本地回归测试

- `test/perf-salary.test.ts` 里本页共 **8** 例，**全绿**。
- 反证（逐条改坏实现，确认会红）：

  把第 4 条从 `getAnalysisDepartmentSummary` 里去掉 → **红 2**；

## 敏感字段

四条统计接口返回的是**部门口径的汇总**（签订率、签订数量、平均分、签订/未签订比例），
**不是逐人明细** —— 这一页的表格里没有姓名。

⚠️ 但**自查分析那张表是逐人明细**：`name`（姓名，可点进详情）、`staffCode`（工号）、
`postName`（岗位）、`standardUnitName`（部门）以及各项得分
（`baseScore` / `assignFullExamineScore*` / `examineKeyIndicatorsScore` / `adjustScore` /
`fullProfitScore` / `totalScore`）。

**这些在类型里没有具名**（`listAnalysisDepartmentSelfCheck` 的返回是 `unknown`）。
逐人得分明细与[个人分析](./个人分析.md)的工资数据是同一个敏感档位 ——
处理理由见 [`docs/pages/奖励导入.md`](./奖励导入.md) 的「敏感字段」一节。

## 尚未覆盖（写入口，已查清）

**这一页没有写接口。** 只有路由跳转：

| 入口 | 行为 |
| --- | --- |
| 行内「移除」 | 只改**本地** `formState.staffCodeList` + `localStorage`（`list.vue:660-686`），**不发请求** |
| 姓名 / 各得分列 | 路由跳转 `/dashboard/month-agreement/common/detail/{protocolId}`（`list.vue:625-641`） |
| 「添加人员」/「人员编组」 | 弹窗，内部读本地选择，**不发写请求** |
| 「签订情况」饼图扇区点击 | 弹窗 `detail-table-view`（`list.vue:600-610`），**不发请求** |
| 组织筛选候选 | `GET /org/organization/getRoleOrganizationTree`，**不照抄** |

⚠️ 「移除」看起来像写操作但**不是** —— 它只从本地表格里摘掉一行，
下次刷新就回来了。**不要**把它实现成一个"删除人员"能力。

## 未核实的推断

- 四条统计接口的真实返回结构（见「真实验证 / 未测到」）。
- **自查分析那条 POST** 的全部细节（基准里没有它，见上）。
- `yearMonth` 的值来源：`useStorage('rrListSelfFormStateYearMonth', dayjs().subtract(1,'month'))`
  —— 用户上次选过的月份会被记住。SDK 无这份存储，取**与初值一致的上月**。
  这**不是**逐字段一致（有本地存储的浏览器会发别的月份），已在文件里注明。
  ⚠️ 基准那一次抓到的 `month=8` 是**干净会话**（没存过）的结果，所以它与"上月"一致；
  但它**没有**验证"有本地存储时会发别的月份"这一条。

### `perf-analysis-department-summary`

汇总管辖部门月度协议签订、进度与得分分析；四个只读请求组合成对象。

执行：`sdk.perfSalary.getAnalysisDepartmentSummary`；性质：read。汇总管辖部门月度协议签订、进度与得分分析；四个只读请求组合成对象。

- 边界：使用当前 SDK 用户与租户的数据权限；页面上下文由 SDK 绑定，调用方不要另拼 module-type。

| 参数 | 意义与来源 |
| --- | --- |
| year | 年，**数字**（与个人分析页的字符串不同）。默认上月所属年。用 buildDeptYearMonth 生成；来源：用户给出的业务条件；格式和必填性按参数契约。 |
| month | 月，**数字**。默认上月。用 buildDeptYearMonth 生成；来源：用户给出的业务条件；格式和必填性按参数契约。 |
| organizationIdList | 角色组织树所选组织 ID 数组；只选择 selectable=true 的节点；来源：contract-support-role-organization-search 返回 list[].id；由用户选定，不能以名称、编码或其他实体 ID 替代；候选：contract-support-role-organization-search list[].id |

返回：`object`。可选字段缺省或 null 时展示为空，不当作数值 0。

- monthProtocolInfo.monthProtocolInfo.signRate：签订率；百分比 0..100，后端已乘 100，页面直接追加百分号；单位：%
- monthProtocolInfo.monthProtocolInfo.avgCompleteRate：平均完成率百分数；页面直接追加 %，不再乘 100。当前契约不承诺该平均得分/进度值必在 0..100 内，不应自行截断；单位：%
- monthProtocolInfo.signInfoDTO.unSignRate：未签订；百分比 0..100，后端已乘 100，页面直接追加百分号；单位：%
- monthProtocolInfo.signInfoDTO.onTimeSignRate：按时签订；百分比 0..100，后端已乘 100，页面直接追加百分号；单位：%
- monthProtocolInfo.signInfoDTO.lateSignRate：晚签订；百分比 0..100，后端已乘 100，页面直接追加百分号；单位：%
- branchDeptSignInfo[].value.signRate：签订率；百分比 0..100，后端已乘 100，页面直接追加百分号；单位：%

- 消费：按 key 展示统计序列，签订人数与得分使用不同单位，不互相相加。空值保持缺失；组合中任一路请求失败会使整体 reject，SDK 不返回部分成功对象。

完成条件：交付选定年月与组织范围的签订和得分统计。

- 失败处理：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。

### `perf-analysis-department-self-check`

对明确选定工号的人员读取协议自查评分明细；必须给非空 staffCodeList，不分页。

执行：`sdk.perfSalary.listAnalysisDepartmentSelfCheck`；性质：read。对明确选定工号的人员读取协议自查评分明细；必须给非空 staffCodeList，不分页。

- 边界：使用当前 SDK 用户与租户的数据权限；页面上下文由 SDK 绑定，调用方不要另拼 module-type。

| 参数 | 意义与来源 |
| --- | --- |
| staffCodeList | 非空工号数组；空数组本地直接抛错，不发送 null；来源：base-user-search 返回的 list[].staffCode；显示 list[].nickname 后让用户确定具体条目。；候选：base-user-search list[].staffCode |
| year | 年，**数字**。默认上月。用 buildDeptYearMonth 生成；来源：用户给出的业务条件；格式和必填性按参数契约。 |
| month | 月，**数字**。默认上月。用 buildDeptYearMonth 生成；来源：用户给出的业务条件；格式和必填性按参数契约。 |

返回：`object[]`。[] 表示本次查询没有条目；这是数组，不读取 list/total。


- 消费：工号与 protocolId 识别人和协议；比较目标分与 actual 实际分。totalScore/actualTotalScore 已由后端计算，实际考核分为空时可能回退自评分，不自行把缺值全补 0 重算。

完成条件：交付选中员工的各项分数和总分；该能力不修改自评。

- 失败处理：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。
- 失败处理：人员候选 staffCode 可能为 null；此时不能回退用户 id，请用户提供已核实工号。

逐字段嵌套结构、可空性、格式及证据由同一 describe 返回；完整生成参考见 ai-contract-reference.generated.md。
