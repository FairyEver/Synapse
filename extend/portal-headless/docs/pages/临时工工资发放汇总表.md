## 参数契约与逐字段基准

Portal 表单初值为：`organizationIdList: []`、`useYearMonth: null`、`status: null`。组织控件是角色组织树的多选、叶子节点选择；SDK 保留数组形状，不把它连接成逗号字符串。月份控件格式化为 `YYYY-MM`，空值发送 `null`。状态选项为：`0`待提交、`1`待审核、`2`待付款、`3`已驳回、`4`已付款。

列表请求按 Portal 列表模块顺序发送：

```json
{
  "order": "",
  "orderField": "",
  "organizationIdList": [9, 10],
  "useYearMonth": "2026-09",
  "status": 0,
  "pageNo": 1,
  "pageSize": 20
}
```

`organizationIdList` 为空只表示不增加额外组织筛选，并不代表绕过权限。Java Service 先调用 `getOrgIdListByModuleType()`，将结果写入 `roleOrganizationIdList`；Mapper 同时对用户选择的 `organizationIdList` 和角色组织集合执行 `inIfPresent`，两者实际取交集。没有角色组织范围时服务端直接返回空页。

列表返回 `{ list, total }`。页面字段为：

| 字段 | 含义 |
| --- | --- |
| `list[].id` | 临时工工资发放汇总表主键；打开详情时映射为 `summaryId` |
| `list[].useYearMonth` | 工资月份 |
| `list[].staffCount` | 临时工人数 |
| `list[].organizationId` / `organizationName` | 部门 ID / 部门名称 |
| `list[].grossSalaryTotal` | 应发工资总额 |
| `list[].individualIncomeTaxTotal` | 个税总额 |
| `list[].netSalaryTotal` | 实发工资总额 |
| `list[].paymentDate` | 付款日期 |
| `list[].status` | `0`待提交、`1`待审核、`2`待付款、`3`已驳回、`4`已付款 |

金额保持服务端 `BigDecimal` 原值，不擅自转换为浮点数。页面底部“合计”只对当前页的 `staffCount`、`grossSalaryTotal`、`individualIncomeTaxTotal`、`netSalaryTotal` 求和，不是跨页全量合计；SDK 返回后端原始分页结果。

详情请求把汇总行 `list[].id` 映射成 `temporaryWorkerSalarySummaryId`：

```json
{
  "order": "",
  "orderField": "",
  "temporaryWorkerSalarySummaryId": 101,
  "name": "张",
  "pageNo": 1,
  "pageSize": 20
}
```

详情 `list[]` 字段为：`id`、`useYearMonth`、`name`、`idCard`、`organizationId`、`organizationName`、`entryDate`、`bankAccount`、`openingBank`、`attendanceDays`、`dailyValue`、`attendanceSalary`、`otherSalary`、`grossSalary`、`individualIncomeTax`、`netSalary`、`status`。其中 `idCard`、`bankAccount` 是敏感字段，按原值消费且不写日志；明细 `status` 是底层使用状态，`0`未使用、`1`已使用，不与汇总状态混用。

## 操作步骤、失败处理与验证边界

1. 先使用当前会话可见的角色组织树确认组织 ID 数组，再用 `.list` 按 `total` 翻页。
2. 需要查看某一汇总行时，把该行 `id` 原样传给 `.detail({ summaryId })`；`name` 只用于详情姓名筛选。
3. `list=[]` 且 `total=0` 只表示当前筛选无记录，不能据此判断没有权限；当前页合计也不能当成全量合计。
4. 非法组织 ID、月份、状态、汇总 ID、页码或页大小会在请求前失败；401/403、网络和后端业务错误原样抛出；坏分页响应不会静默变成空列表。
5. “工资支出”需要进入独立 `simple/hr/form/016` 流程表单；该导航以及其后续提交规则不属于本只读页面能力，待该流程页面单独完成源码与真实提交证据后再发布对应能力。
