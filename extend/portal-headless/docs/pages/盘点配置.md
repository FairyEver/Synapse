## Portal 页面行为

### 列表、筛选和候选

- 列表 `customLoad` 调用 `GET /admin-api/inventory/asset-stocktaking-config/page`，公共列表逻辑先生成 `order=''`、`orderField=''`、`type`、`stocktakerUserId`、`createTime`、`orgId`、`pageNo`、`pageSize`。页面启用分页，默认 `pageNo=1`、`pageSize=20`，可选 `10/20/50/100`。
- `customLoad` 先从参数中移除 `createTime`，再把日期选择器的两个 `YYYY-MM-DD` 转成 `['起始日 00:00:00', '结束日 23:59:59']`；请求配置设置 `paramsArrayFormat: 'repeat'`，所以数组按重复键发送，而不是 `createTime[0]`。
- 盘点类型来自平台字典 `inventory_stocktaking_type`，页面只保留 `2=抽盘`、`3=清盘`。列表筛选、表单和后端 VO 都使用数值类型。
- 列表挂载时 Portal 通过 `GET /admin-api/system/user/simple-page`、`pageSize=500` 循环加载全部盘点人；切换组织时表单再次调用相同接口并带 `companyUnitId=orgId`。SDK 的 `searchStocktakerUsers` 按长选项约束要求先给 `keyword`，可选传 `orgId` 映射为 `companyUnitId`，不把全量人员倒入调用上下文。

### 新建和编辑表单

- 表单字段是 `type`、`orgId`、`stocktakerUserId`、`triggerMonth`、`triggerDay`；类型和组织、盘点人必填。
- 类型为 `3=清盘` 时，月日均必填，月范围为 1 至 12、日范围为 1 至 31；类型为 `2=抽盘` 时，Portal 在提交 payload 时无条件把 `triggerMonth`、`triggerDay` 置为 `null`，即使表单状态曾经残留日期。
- 新建请求是 `POST /admin-api/inventory/asset-stocktaking-config/create`，完整 payload 不含 `id`，响应是新记录 Long ID。编辑请求是 `PUT /admin-api/inventory/asset-stocktaking-config/update`，payload 含 `id` 和完整表单字段，响应要求为 `true`。
- Portal 表单本身没有把类型控件设为只读，但 Java 服务会拒绝编辑时改变既有类型；SDK 说明并保留这个后端规则。用户取消只关闭弹窗，不发写请求。

### 删除和权限

- 列表删除调用 `DELETE /admin-api/inventory/asset-stocktaking-config/delete`，查询参数是 `{ id }`；删除前由 Portal 弹出“删除后不可恢复”的确认框。
- 新增、编辑、删除按钮分别受 `material:assets:stocktaking-config:create`、`material:assets:stocktaking-config:edit`、`material:assets:stocktaking-config:delete` 控制；列表和详情接口受页面权限 `/dashboard/material/assets/stocktaking-config` 控制。

## Java 后端与权限规则

`AssetStocktakingConfigController` 的根路径是 `/inventory/asset-stocktaking-config`，提供 `POST /create`、`PUT /update`、`DELETE /delete?id=...`、`GET /get?id=...` 和 `GET /page`。SDK 只注册本页面实际使用的列表、候选搜索和 create/update/delete，不把不可达的详情请求当成页面动作。

`AssetStocktakingConfigPageReqVO` 的筛选字段是 `type`、`orgId`、`stocktakerUserId`、`createTime[]`；Mapper 使用等值筛选、创建时间区间和 `id DESC`。保存 VO 使用 `Long id/orgId/stocktakerUserId`、`Integer type/triggerMonth/triggerDay`，月日有 `@Min/@Max` 范围校验。

服务层只允许抽盘或清盘；清盘必须有月日，抽盘保存时清空月日；编辑不允许改变类型；同组织同类型只能有一条配置，并额外检查组织、类型、盘点人的重复组合；删除前检查是否已有资产盘点记录引用，被引用时拒绝删除。按钮权限和页面查询权限与 Portal 页面分别对齐。

## SDK 能力与说明

实现文件为 `src/capabilities/inventory-asset-stocktaking-config.ts`，AI 契约为 `src/catalog/contracts-inventory-asset-stocktaking-config.ts`。能力按列表、盘点人关键字搜索、创建/修改/删除的 `prepare → submit` 拆分；取消只丢弃草稿。

SDK 还在公共请求层接入了 Portal 的 `paramsArrayFormat`，仅当页面显式指定时改变数组编码；本页列表显式使用 `repeat`，其它页面仍保留原有默认序列化规则。创建返回 ID、更新/删除只接受 `true`，完成后必须按 ID 或组织+类型回查，不能把 HTTP 成功回执当作业务终态。
