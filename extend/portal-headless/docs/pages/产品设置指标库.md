# 产品设置指标库

页面路径：`/dashboard/product/setting/indicator-lib/list`。

菜单归属是 `系统设置 → 生产设置 → 养殖预案 → 指标库-新`。这里的“生产设置”是 Portal 保留的系统设置子菜单，不是范围外的独立生产业务菜单。详情页和指标配置页是本页面的同一操作单元：

- 详情：`/dashboard/product/setting/indicator-lib/detail?versionId=...`
- 指标配置：`/dashboard/product/setting/indicator-lib/configure`

## 参数契约与提交规则

列表默认 `versionScope=latest`，请求发送 `latestOnly=true`；只有明确传 `versionScope=all` 才发送 `latestOnly=false`。筛选字段映射为：`gen → generation`、`variety → variety`、`line → strain`。分页默认 `pageNo=1`、`pageSize=10`，页面支持10、20、50。

新建、编辑和复制的维度表单遵循 Portal 动态规则：`generation` 必填；代次展示值不是“曾祖代”时 `variety` 必填；只有“祖代”和“曾祖代”启用 `strain`，其他代次提交空字符串。SDK在 `prepare*` 草稿中保留可选的 `generationLabel`，以便字典 value 在后续提交时仍能复刻页面判断；该字段不会进入 HTTP body。

复制固定提交 `versionName=V1` 和当前时间 `effectiveStart`。版本编辑与新建版本遵循页面的生效时间规则：最新版本结束时间必须为空，历史版本必须有结束时间，结束时间必须晚于开始时间。删除批量操作按 Portal 行为逐个发送 DELETE。

指标配置页应用顺序是：更新已有定义 → 创建新增定义 → 删除已移除定义 → 如果顺序改变则调用 `definition/sort`。指标名称、Code、分类必填；Code必须匹配 `^[a-z][a-z0-9_]{0,63}$` 且不可重复；小数位必须为0至3的整数；温度带关联可为空。

详情页增量保存只提交发生变化的 `rows`，不会把 `definitions` 放进 HTTP body。日龄必须是1至700的整数且不能重复；单元格支持 `EXACT`、`RANGE`、`LT`、`GT`，`null` 表示清空单元格；数值按对应指标定义的小数位校验。快速录入最多50组，并且复刻 Portal 只提交 `EXACT` 数值。

导入控件只接受 `.xlsx`，SDK用 `{ fileName, base64, contentType? }` 描述无头文件，并以 multipart 字段 `file` 和查询参数 `versionId`提交。模板下载、导出返回文件的Base64描述，调用方负责保存。

## 逐字段基准

| 字段 | 含义 |
| --- | --- |
| `list` | 当前筛选、版本范围和分页下的指标库版本记录。 |
| `total` | 筛选后的版本总数，不是当前页长度。 |
| `latestCount` / `historyCount` | 最新版本数 / 历史版本数。 |
| `list[].id` / `versionId` | 当前行版本ID；详情、复制、删除和版本操作目标。 |
| `list[].libraryId` | 指标库维度ID；新建版本目标。 |
| `list[].generation` / `variety` / `strain` | 代次、品种、品系编码；不适用的维度为空。 |
| `list[].versionName` | 版本名称，例如 `V1`。 |
| `list[].effectiveStart` / `effectiveEnd` | 生效起止时间；`effectiveEnd=null` 表示最新版本。 |
| `get().definitions` | 当前详情使用的指标定义；Code、单位、小数位和温度带关联来自这里。 |
| `get().rows[].dayAge` | 日龄，范围1至700。 |
| `get().rows[].values.<code>` | 按指标Code索引的结构化单元格值；`null` 表示空单元格。 |
| `prepare*().draft` | 已通过页面规则、尚未改变服务端的草稿；写入前必须经过用户确认。 |
| 写操作结果 `true` / 新建ID / 导入条数 | 请求未抛错、返回ID或服务端导入条数；都不能替代后续 `list()`/`get()` 回查。 |

## 操作步骤、权限和证据边界

1. 使用当前用户会话和租户上下文调用 `list()`；详情和配置动作继续使用同一页面权限与 `platform` 实例。
2. 新建、编辑、复制、版本编辑、配置应用、数据保存、快速录入或导入时，先调用对应 `prepare*()`；用户确认后把同一份草稿交给写能力，取消只丢弃草稿。
3. 详情页切换版本、改名或保存数据前按 Portal 规则处理未保存草稿确认；SDK调用方也必须避免在有未确认修改时直接切换目标版本。
4. 写操作成功、失败或响应不确定后，列表类动作重新调用 `list()`，详情、定义、数据和导入类动作重新调用 `get()` 或 `definitionList()`核对业务终态；不能只依据 `true`、ID或导入条数宣布完成。

本轮逐页核对了 Portal 菜单、列表页、详情页、配置页、四类弹窗/编辑器、平台HTTP与Excel工具，以及 Java `RearingPlanIndicatorController`、请求VO和 `RearingPlanIndicatorServiceImpl`。离线测试覆盖了页面路径、共用权限、平台实例、所有页面端点、动态表单、版本规则、定义配置顺序、结构化数据、快速录入、文件上传和关键反证。

当前没有真实测试环境浏览器会话的列表、详情、配置、版本、数据保存、快速录入、导入导出闭环证据；文档和AI说明已明确这一证据边界，写操作仍须在真实环境按“prepare → submit → 回查”执行。
