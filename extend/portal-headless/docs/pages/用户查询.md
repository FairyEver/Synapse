# 用户查询（`/dashboard/setting/user/list`）

## 页面范围与证据

Portal 菜单“系统设置 → 用户查询”，权限 `/dashboard/setting/user`，使用 `platform` HTTP 实例；页面路径不命中 module-type 规则，SDK 与 Portal 一样不发送 `module-type`。

列表页可见动作是查询和行内“编辑”。列表配置虽然声明了 `deleteURL`、批量选择和 `exportURL`，但当前模板没有删除或导出按钮；`actionSync` 函数虽定义了 `POST /sys/user/synchronous`，当前也没有绑定到按钮。SDK 将这个已被 Java 保留但当前模板未绑定的后端动作显式标记为 `prepareSynchronous → submitSynchronous → cancelSynchronous` 链：prepare/cancel 只处理本地确认草稿，submit 才发无 body 的 POST；不把它描述成当前页面可点击按钮。编辑动作进入 `[mode]/[id].vue`，读取 `/sys/user/getInfo`，保存时 `PUT /sys/user`。创建分支存在于表单代码，但列表没有新建入口，且表单没有 password 字段而 Java 新建校验要求 password，因此 SDK 不发布一个会把失败请求伪装成可用的创建能力。

Portal 证据：`app/portal/menus/common.js`、`app/portal/views/dashboard/hr/setting/user.vue`、`list.vue`、`[mode]/[id].vue`，当前检出 `acab69acc7`。

Java 证据：`HrSysUserController`、`SysUserDTO`、`HrSysUserServiceImpl`、`SysUserDao.xml`，当前检出 `0f1a55718eb`。普通管理员分页会叠加当前角色模块组织范围，不能通过 SDK 参数切换或扩大数据权限。

## 能力与权限边界

| 页面动作 | SDK 能力 / 方法 | 请求与副作用 |
| --- | --- | --- |
| 用户分页 | `setting-user-list` / `settingUser.list` | `GET /sys/user/page`；按 Portal 表单和时间区间构造查询参数 |
| 编辑表单读取 | `setting-user-get-info` / `settingUser.getInfo` | `GET /sys/user/getInfo?id=...&useSystemList=1,2,3,4,5,6` |
| 手机号唯一性校验 | `setting-user-phone-is-exist` / `settingUser.phoneIsExist` | 非空合法手机号才请求 `GET /sys/user/phoneIsExist?phone=...`；空值按 Portal 本地校验返回0 |
| 编辑前准备 | `setting-user-prepare-update` / `settingUser.prepareUpdate` | 本地合并当前完整用户和允许变更，不发请求；取消时丢弃 draft |
| 保存编辑 | `setting-user-update` / `settingUser.update` | `PUT /sys/user`；发送完整表单字段并固定 `useSystemList: [1,2,3,4,5,6]` |
| 用户同步准备 | 低层方法 `settingUser.prepareSynchronous` | 返回固定同步草稿；不发请求、不修改服务端 |
| 用户同步提交 | 低层方法 `settingUser.submitSynchronous` | `POST /sys/user/synchronous`；无 query、无 JSON/form body；成功无业务数据回执 |
| 用户同步取消 | 低层方法 `settingUser.cancelSynchronous` | 丢弃尚未提交的同步草稿；不发请求，不能撤销已提交同步 |

页面菜单权限是 `/dashboard/setting/user`；Java Controller 上的若干 `@RequiresPermissions` 当前以注释存在，不能把它们当成已启用的独立按钮权限。后端仍会按会话用户和组织数据范围裁剪分页结果。

## 查询参数与时间规则

- 默认请求参数为：

  ```json
  {
    "order": "",
    "orderField": "",
    "staffCode": "",
    "name": "",
    "mobile": "",
    "role": "",
    "status": "",
    "useSystemList": "1,2,3,4,5,6",
    "startTime": "",
    "endTime": "",
    "pageNo": 1,
    "pageSize": 20
  }
  ```

- `time` 是 SDK 对 Portal `a-range-picker` 的可序列化表达：`[开始日期,结束日期]`。SDK按页面代码生成 `startTime=开始日 00:00:00`，并生成 `endTime=结束日次日 00:00:00`；这是开区间边界，不能改成结束日当天 23:59:59。空数组表示两个字段都为空。
- `role` 来自 Portal 角色选择器，`status` 来自 `status` 字典；SDK保留选中的 ID/值，不把显示标签当作请求参数。
- `useSystemList` 是页面固定范围 `1,2,3,4,5,6`，不是调用方切换系统或租户权限的参数。

## 用户同步动作

- `prepareSynchronous()` 无参数，返回 `{ draft: { action: 'setting-user-synchronous' } }`；它只表示调用方已进入同步确认流程。
- `submitSynchronous({ draft })` 只接受上述 prepare 草稿，发送 `POST /sys/user/synchronous`，不传第二个参数，因此没有请求 body。Java Controller 没有 DTO 或表单字段；返回成功时没有业务数据。
- `cancelSynchronous({ draft })` 只校验并丢弃本地草稿，返回 `{ cancelled: true }`。Java 没有对应撤销端点；POST 发出后不能通过本能力回滚。
- 提交前必须使用当前用户会话、当前租户和用户查询页权限，并取得用户对“同步用户所属班级将按最新组织结构分配”的明确确认。Java 服务会把 `synchronous` 作为 Redis 节流键，60 秒内重复请求返回“请稍后请求”；这不是 requestId 幂等。
- Java 同步服务读取 HR 人员源数据：无组织的员工跳过；已有用户按工号更新，缺失于 HR 源的非 `admin` 用户改为停用，新员工插入。成功回执只表示 Controller 调用未抛错；由于响应没有结果集，完成后应按列表/详情重新读取受影响用户核对，不能把 Portal 的“约 5 分钟”提示当作独立完成证明。

## 返回字段与编辑表单

分页和详情都保留 Java `SysUserDTO` 的业务字段：`id`、`username`、`realName`、`headUrl`、`gender`、`email`、`mobile`、`gradeId`、`deptId`、`status`、`createDate`、`creator`、`superAdmin`、`roleIdList`、`gradeName`、`roleList`、`organizationCode`、`organizationName`、`organizationFullPathName`、`organizationId`、`updaterName`、`updateDate`、`creatorName`、`type`、`project`、`postId`、`tenantId`、`tenantAdmin`、`postName`、`staffId`、`setPwd`。Long ID 可能序列化为字符串，时间保留原值，不做时区换算；SDK不会把 password、password2、salt 放进输出或编辑请求。

- 用户名、姓名是编辑页必填；Portal当前输入框禁用，通常应从 `getInfo` 原值保留。
- 手机号为空可以提交；非空必须匹配 `^1[3456789]\d{9}$`。手机号改变时先执行 `phoneIsExist`，返回0后再提交；Portal源码不发送 `userId` 排除参数。
- 角色选择默认被注释，只有执行 `setting-user-role-v2-edit` 或保持开启命令后才显示。没有用户明确角色变更时，必须保留 `getInfo.roleIdList`，不能自行清空或猜角色。
- 编辑保存会发送完整 `formState`，不是只发送差异字段；SDK 的 `prepareUpdate` 会保留 current 中的其它字段，只允许覆盖 `username`、`realName`、`mobile`、`roleIdList`，并固定补上 `useSystemList` 数组。

## 操作步骤与失败处理

1. 用 `list` 读取当前组织权限范围内的用户，按 `total` 翻页并保存行 ID。
2. 编辑时先 `getInfo` 取完整表单；需要改手机号时先 `phoneIsExist`，再 `prepareUpdate`，用户确认后 `update`。取消只丢弃 draft，不发 PUT。
3. 保存成功或超时后用同一 ID 的 `getInfo` 回查 username、realName、mobile、roleIdList、status 和其它受影响字段；不能只看 Promise 完成。
4. 权限、组织数据范围、手机号校验、后端验证、网络或响应形状错误均原样报告；不能把空分页解释为没有权限或把成功回执解释为字段已经回写。
5. 删除、导出和创建仍不调用，因为当前页面没有可达入口。同步的 Java POST 已核对且 SDK 提供显式 prepare/submit/cancel 方法，但当前 Portal `actionSync` 没有模板按钮绑定；调用方只有在获得明确确认且接受该页面差异时才应调用 `submitSynchronous`。
6. 同步 POST 成功或超时后先按工号/姓名等受影响字段重读用户列表或详情；结果不确定时不要在 60 秒节流窗口内盲目重试。
