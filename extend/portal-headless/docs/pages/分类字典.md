# 分类字典（`/dashboard/platform/setting/category-dict/list`）

本页是 Portal「平台设置 → 分类字典」的树形管理页，维护 `tenant_id=0` 的平台共享分类。所有租户可以读取平台分类；租户是否可以在某个根分类下自定义子分类，由根节点的 `tenantEditable` 控制。

| 项 | 值 |

| 菜单路径 | `/dashboard/platform/setting/category-dict/list` |
| 权限码 | `/dashboard/platform-v2/setting/category-dict` |

## 能力定义与请求契约

实现位于 `src/capabilities/platform-category-dict.ts`，能力与页面动作一一对应：

| 能力 ID | 页面动作 | 请求 |
| --- | --- | --- |
| `platform-category-dict-list` | 查询树 | `GET /adminmanage-api/system/category-dict/tree` |
| `platform-category-dict-create` | 新增字典/添加下级 | `POST /adminmanage-api/system/category-dict/create` |
| `platform-category-dict-update` | 弹窗编辑 | `PUT /adminmanage-api/system/category-dict/update` |
| `platform-category-dict-update-inline` | 行内修改名称或编码 | `PUT /adminmanage-api/system/category-dict/update` |
| `platform-category-dict-set-tenant-editable` | 修改根节点租户自定义开关 | `PUT /adminmanage-api/system/category-dict/update` |
| `platform-category-dict-remove` | 删除节点 | `DELETE /adminmanage-api/system/category-dict/delete/{id}` |

列表筛选只提交 `order:''`、`orderField:''`、`name` 和 `code`；省略或传 `null` 的筛选值按 Portal 归一为空字符串。返回值是树数组，不是 `{list,total}`，每个节点保留 `id`、`pid`、`name`、`code`、`tenantId`、`platform`、`tenantEditable`、`createTime` 和递归 `children`。

## 表单与权限规则

- `name` 是唯一必填项；Portal 只做必填校验，SDK 也不擅自增加长度或格式限制。
- 根节点的 `pid` 在提交时归一为 `0`；添加下级时沿用父节点 ID。`code` 未填时按空字符串提交。
- 弹窗新建/编辑只有根节点提交 `tenantEditable`；弹窗缺省开关值按 Portal 表单初始化为 `0`，提交值固定为 `0` 或 `1`。
- 行内编辑会携带当前行完整的 `id`、`pid`、`name`、`code` 和 `tenantEditable`；即使当前行为子节点，也复刻 Portal 的 `data.tenantEditable === 0 ? 0 : 1` 投影。
- 租户自定义开关只允许根节点（`pid=0`），不是当前调用用户的权限开关。删除使用单个节点 ID，后端存在子节点或其他业务约束时应保留错误，不递归删除。

## 操作步骤与验证状态

```text
1. 确认当前 SDK 会话具有 /dashboard/platform-v2/setting/category-dict 权限。
2. 调用 platform-category-dict-list，先取得目标节点的完整 id/pid/name/code/tenantEditable。
3. 新建、弹窗编辑、行内编辑或修改根开关时，沿用同一节点的上下文字段再提交；删除前确认用户明确要求删除该节点。
4. 写操作完成或超时后重新调用 platform-category-dict-list，逐字段核实结果；子节点存在时不要改用递归删除。
```

本节点的离线验证在 `test/platform-category-dict.test.ts`：锁定 Portal 路径、接口前缀、树字段、根/子节点表单投影、行内编辑、根开关、删除、权限错误和坏响应。Java 控制器与保存请求规则已逐项核对；真实测试环境的浏览器基准、在线读写冒烟和写后清理尚未在本节点声称完成，后续代码检查需补充或明确记录外部环境阻塞。
