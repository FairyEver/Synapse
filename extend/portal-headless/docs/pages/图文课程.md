# 图文课程（`/dashboard/course/text-course/list`）

学习管理域「课程管理」下的三个列表页之一。**三页打的是同一个后端接口，靠 `type` 分片**，
所以这一份写全三页共用的部分，另外两页（[视频课程](./视频课程.md) /
[即时通讯课程](./即时通讯课程.md)）只记各自的差异。

| 项 | 值 |
| --- | --- |
| 菜单路径 | `/dashboard/course/text-course/list` |
| 权限码 | `/dashboard/course/text-course` |
| 路由文件 | `app/portal/views/dashboard/education/course/text-course/list.vue` |
| 列表接口 | `GET /admin-api/study/course/studycourse/courseList?type=1` |
| module-type | 12 学习管理 |
| 能力 id | `study-course-text-list` |
| 页面形态 | 列表页(声明式 `getDataListURL`)，**含 `convertFetchForm`** |

---

## 页面标识

**这一页是哪一页，由 URL 上那个 `type=1` 决定，不是由筛选条件决定。**

三页的 `getDataListURL` 逐字如下（`list.vue` 源码）：

| 页面 | `getDataListURL` |
| --- | --- |
| 图文课程 | `/study/course/studycourse/courseList?type=1` |
| 视频课程 | `/study/course/studycourse/courseList?type=2` |
| 即时通讯课程 | `/study/course/studycourse/courseList?type=4` |

后端只有一个入口 `StudyCourseController#selectNewsCourseList(SelectCourseDTO)`，对应 SQL
（`mapper/study/course/StudyCourseDao.xml` 的 `selectCourseList`）第一句就是：

```sql
WHERE t1.type = #{dto.type}
```

⇒ `type` 不是可选筛选，**是"这一页是哪一页"的定义**。形态与
[考勤统计](./考勤统计.md)/[考勤档案](./考勤档案.md) 那一对相同（共用接口、按固定参数分界）：
每个页面一个能力，`type` 钉死在自己能力里，**不接受调用方传**。

> **`type=3`（直播课程）不在 SDK 里。** `app/portal/menus/hr.js:299` 的菜单项是整行注释掉的，
> 侧边栏「课程管理」下只有图文 / 视频 / 即时通讯三项（浏览器实测确认）——**用户到不了这一页**。
> 按项目规则（`docs/conventions.md` 的「注释掉的代码不算代码」）不搬进来。
> 路由文件还在、按 URL 直接访问也能渲染（当时的基准：`?type=3` 与另外两页逐字段同形、
> 实测 `total=0`），但那不构成"用户能做的事"。

## 筛选条件与列表字段（实测自真实页面）

页面上只有两个筛选框（`list.vue` 的 `form` 初值就这两个字段）：

| 控件 | 字段 | 初值 | 说明 |
| --- | --- | --- | --- |
| 关键字（`a-input`） | `keyword` | `''` | 匹配**远端资源名**，不是本地课程行 |
| 创建时间（`a-range-picker`） | `date` | `[]` | 日期区间，**提交前被改写掉**（见下） |

列（`columns`）：ID / 标题（`news.title`）/ 录入人员 / 录入时间 / 最后修改人 / 最后修改时间 /
查看次数（`news.views`）/ 导流（`news.diversionMark`）/ 语音（`news.voiceState`）/ 操作。

**行里资源本体挂在哪，取决于 `type`**：`StudyCourseListDTO` 有 `news` / `videos` / `live` /
`imGroupDTO` 四个字段，只有与 `type` 对应的那个有值。实测反例：视频课程（`type=2`）的首行
**四个字段全是 `null`** —— 那一行的远端资源在智慧蛋鸡侧已经取不到了，而这一列**不会因此报错**，
只是空着。调用方看到 `videos: null` 不代表类型不对，代表资源失联。

## `convertFetchForm`：这一页真正难的地方

页面在 `list.vue` 里挂了一个改写函数（图文/视频两份源码**一字不差**；即时通讯那页是另一份，见它的文档）：

```js
rrList.convertFetchForm((data)=>{
  return {
    keyword: data.keyword.trim(),
    startTime: data.date && data.date[0] ? data.date[0].startOf('date').format('YYYY-MM-DD HH:mm:ss') : '',
    endTime: data.date && data.date[1] ? data.date[1].startOf('date').add(1, 'day').format('YYYY-MM-DD HH:mm:ss') : '',
  }
})
```

三件事，每一件都是"看不出来但会错"：

1. **返回值只有三个字段。** `date` 区间被拆成两个标量，其余一律不透传。
2. **空值是空字符串，不是省略。** 浏览器实测：无筛选时也照样发 `keyword=&startTime=&endTime=`。
   少了这几个等号就不与基准逐字段一致了。
3. **结束日 +1 天，是开区间。** 实测（选区选 2026-09-01 ~ 2026-09-15）：
   `startTime=2026-09-01 00:00:00&endTime=2026-09-16 00:00:00`。
   自己拼就会**静默少一天**（选到 9-15 却查不到 9-15 当天的数据），所以 SDK 单独给了
   `buildStudyCourseTimeRange()`，不让调用方手拼。

> ⚠️ 与后端的比较符不对齐：SQL 写的是 `AND t1.create_time <= #{dto.endTime}`（闭区间），
> 而前端给的是结束日**次日** 00:00:00，所以恰好落在 00:00:00 那一秒的记录会被多收进来。
> 这是页面与后端两边拼出来的效果，**SDK 照抄页面、不"修正"它** —— 改了就不逐字段一致了。

**为什么要专门写这一节**：生成器只扫 `getDataListURL`，看不到这个函数，所以把这类页面判成
`partial/contract`（`tools/generate/batch-capabilities.mjs`）。全量 241 个声明式列表页里
**69 页命中它**，而 `auto` 桶里 0 页 —— 它就是"需人补"那 112 页的主要成因。可复用配方见
`tools/baseline/README.md` §3。

## 真实请求序列（浏览器实测，2026-09-21）

```
GET https://biz-api-test.wodecorp.cn/admin-api/study/course/studycourse/courseList
    ?order=&orderField=&keyword=&startTime=&endTime=&pageNo=1&pageSize=20&_t=<ts>&type=1
headers: tenant-id: 1 ; token: <redacted> ; module-type: 12 ;
         Accept-Language: zh-CN ; Accept: application/json, text/plain, */*
```

完整三条（三页各一）＋两条填值路径在 `baseline/study-course.browser.json`。

### 三个必须记住的点

**1. `type` 排在 `_t` 之后，而 SDK 的 client 原本会把它排到最前。**
这是本轮**修掉的一个真 bug**：前端 `platform.js:57-62` 是
`config.params = { ...config.params, ...qs.parse(fixParamsString) }`（inline query **后**合），
而 `src/http/client.ts` 原来写成了 `{ ...qs.parse(inlineQuery), ...params }`（**反的**）。
两种写法在**不冲突时只差键序**，在**键冲突时差的是谁赢** —— 都属于"不报错但是错的"。
现有能力没有一个传过 URL 自带 query，所以修它对既有行为**可证明是惰性的**；
配了两条测试（含冲突用例），改回去会红。

**2. `module-type` 浏览器上读的是 cookie，不是当前页。**
`module-type=12` 与规则表（`/dashboard/course/` 前缀 → 12 学习管理）一致，
但要知道这个头在浏览器里取自 cookie `hr-0.0.0-menuPath`（**全局共享、不分标签页**），
并行任务跳别的域时会被带偏。SDK 侧不受影响：`resolveModuleType(页面路径)` 是确定性的。

**3. `pageNo` / `pageSize` 之外的 `order` / `orderField` 是列表模块加的**，
页面没有这两个控件，所以 SDK 把它们**钉死成空串、不开放**。

## 操作步骤

```ts
import { createPortalHeadless } from 'portal-headless'
import { buildStudyCourseTimeRange } from 'portal-headless'

const sdk = createPortalHeadless({ baseUrl, credential })

// 1) 无筛选：拿最新的一页（后端 ORDER BY create_time DESC）
const page = await sdk.studyCourse.listText({ pageNo: 1, pageSize: 20 })
// → { list: StudyCourseRow[], total: number }

// 2) 按时间区间：**必须**用 buildStudyCourseTimeRange 生成，别手拼（会少一天）
const range = buildStudyCourseTimeRange('2026-08-01', '2026-08-31')
const august = await sdk.studyCourse.listText({ ...range, pageNo: 1, pageSize: 20 })
```

**关键字这条路要慎用**，原因见下一节。

## 参数契约

| 参数 | kind | 必填 | 说明 |
| --- | --- | --- | --- |
| `keyword` | text | 否 | 匹配远端资源名。⚠️ 见下 |
| `startTime` | date | 否 | `YYYY-MM-DD HH:mm:ss`；用 `buildStudyCourseTimeRange` 生成 |
| `endTime` | date | 否 | **开区间**（结束日 +1 天）；同上 |
| `pageNo` | number | 否 | 默认 1 |
| `pageSize` | number | 否 | 默认 20（`useListPageModule({styleV2:true})`） |

**没有** `type`，也不接受硬塞 —— 它是"这一页是哪一页"的定义。

## ⚠️ 关键字：在本租户下**命中即报错**

这是本轮最反直觉的一条实测结论，而且**用户自己在页面上也照样踩**：

| 请求 | 结果 |
| --- | --- |
| `keyword=经营`（有命中） | **HTTP 200 + `code:500`**「用户查询结果超过500条，请缩小name条件或调用已有分页接口」 |
| `keyword=zzz_not_exist_xyz`（无命中） | HTTP 200 + `code:0`，`total=0` |
| 不传关键字 | HTTP 200 + `code:0`，`total=572` |

浏览器实测同样：在图文课程页填「经营」点查询 → 页面弹红字提示 + 表格「暂无数据 / 共 0 条记录」。

**根因（源码 + 运行时两侧都核过）**：
`StudyCourseServiceImpl#selectCourseList` 有两套分支。关键字非空时走 else 分支 →
远程按名查资源 → `getCourseByResourceIds`，而那个方法在拿到资源 id 之后**无条件**调用

```java
List<SysUserEntity> userList = hrUserApi.getUserList(null);   // 不带任何条件
```

这个入口在 `HrSysUserServiceImpl:725` 挂了兜底
（`MAX_LEGACY_USER_RESULTS = 500`，常量在同文件 `:110`）：

```java
if (records.size() > MAX_LEGACY_USER_RESULTS) {
    throw ServiceExceptionUtil.exception("用户查询结果超过{}条，请缩小name条件或调用已有分页接口", MAX_LEGACY_USER_RESULTS);
}
```

租户 1 的用户数远超 500 ⇒ 必抛。
**关键字的成败取决于它命中不命中**：命中 → 有资源 id → 走进那段取全量用户的代码 → 炸；
不命中 → 提前 `return new Page<>()` → 正常返回空列表。

SDK 的行为是把 `code:500` 抛成 `PortalApiError`（**不是**吞成空列表）。
这是刻意的：吞掉的话调用方会以为"真的没有数据"。

> 推论（**未实测**）：用户数 ≤500 的租户上，关键字查询应当可用。本仓库没有这样的租户，
> 所以这条只是推断，别当结论用。

## 尚未覆盖

- **写操作（新建 / 编辑 / 删除）全部没做。** 这几页在 `page-catalog` 里都标着 `write: true`。
  没做的理由是写链路**跨系统**：`POST /study/course/studycourse` 会先转发到智慧蛋鸡的
  `/api/study/course/add.json` 建远端资源，拿到 `resourceId` 后才往本地 `hr_study_course` 插一行；
  删除同理（`addCourse` / `deleteCourse`）。**建一条测试课程 = 在内容平台留下一个真实资源**，
  这属于"要先问清楚"的判断，不是"多写一个接口"的成本（先例：合同模板的「保存并提交」整支没做）。
- `order` / `orderField` 能改时后端怎么排序，没测（页面不发非空值）。
- 用户数 ≤500 的租户上关键字是否可用，没测（没有这样的租户）。

## SDK AI 说明契约（2026-09-22）

以下由真实 SDK 描述生成；权威数据为 src/catalog/contracts-*.ts。前文浏览器/冒烟记录是历史证据，本节不将源码和离线验证称作新的部署实测。

### `study-course-text-list`

查询 Portal 图文课程列表及该页可见的资源信息；与课堂/学员学习记录区分。

执行：`sdk.studyCourse.listText`；性质：read。查询 Portal 图文课程列表及该页可见的资源信息；与课堂/学员学习记录区分。

- 边界：仅说明当前已实现列表能力对应的 Portal 页面可见字段和操作标识；不要求解释外部内容管理端或后端完整 DTO。原始兼容扩展不是新增业务功能。

| 参数 | 意义与来源 |
| --- | --- |
| keyword | 远端资源名称关键字；当前租户历史实测命中资源时后端用户映射超过 500 条会报错，收窄名称不能保证修复；空结果也不能证明该路径可正常读取命中资源。；来源：用户给出的业务条件；格式和必填性按参数契约。 |
| startTime | 创建时间起 `YYYY-MM-DD HH:mm:ss`；与 endTime 成对，用 buildStudyCourseTimeRange 生成；来源：用户给出的业务条件；格式和必填性按参数契约。 |
| endTime | 创建时间止，**开区间**（结束日 +1 天）。用 buildStudyCourseTimeRange 生成，自己拼会少一天；来源：用户给出的业务条件；格式和必填性按参数契约。 |
| pageNo | 页码，默认 1；来源：用户给出的业务条件；格式和必填性按参数契约。 |
| pageSize | 每页条数，默认 20；来源：用户给出的业务条件；格式和必填性按参数契约。 |

返回：`{ list: object[], total: number }`。list=[] 为当前页无记录；total=0 表示该筛选无结果。保留筛选条件检查页码，不将空结果解释成权限判定。

- list[].news.diversionMark：导流开关，Portal 按 yes_or_no 字典显示；{"0":"否","1":"是"}
- list[].news.voiceState：页面语音状态：0 显示试听链接，1 显示失败，2 显示生成中；其他值不冒充成功；{"0":"成功","1":"失败","2":"生成中"}
- list[].news.showStyle：编辑页文章样式；{"1":"大图样式","2":"单图样式","3":"三图样式"}
- list[].news.maySee：导流为 1 时编辑页显示的可阅读量百分数，控件 0..50；不是累计查看次数；单位：%
- list[].news.generateVoiceMethod：生成语音弹窗上次选中的方式；{"1":"识别文字","2":"识别图片","3":"上传语音"}

- 消费：按页面列展示 news.title 和本契约字段；news 为空时保留课程行并标明资源不可用，不能判定课程未创建。
- 消费：creator 与当前用户 userId 相同是页面显示行操作的条件，不据此替代服务端鉴权。当前 SDK 只提供列表查询，页面新建/编辑、同步、评论、语音和禁言等动作没有因此成为可调用 SDK 能力。
- 消费：既有请求仍透传原始行以保持兼容；未列出的资源元数据、其他类型资源和扩展对象不属于本 Portal 页消费契约，不展示、不解释、不据此执行动作。
- 消费：分享时效按 Portal 编辑页原值展示，不补单位，不进行时间换算；视频 duration 和 maySee 有明确秒单位，不能混为 sharingLimitation 的单位。

完成条件：按用户要求交付本次筛选范围的结果；需要完整清单时继续翻页至覆盖 total，不能把当前页当全集。

- 失败处理：已知命中资源时后端可能报 500（用户映射拉取超过 500 条），即时通讯查询在既有租户实测同样失败；不要循环重试或宣称更精确关键字必能修复，空列表也不能证明命中资源路径正常。

逐字段嵌套结构、可空性、格式及证据由同一 describe 返回；完整生成参考见 ai-contract-reference.generated.md。
