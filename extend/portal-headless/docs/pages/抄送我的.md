# 抄送我的（`/dashboard/flow/task/copy/list`）

审批管理域「我的流程」四页里的第四页，也是这四页里**唯一一个真正自己的列表页**
（另外三页都不是：发起流程是自定义页面，待办/已办是同一个组件的复用方）。
四件套的其它三件分别在：能力定义与参数契约 → `src/capabilities/flow-task.ts`；
逐字段基准 → `baseline/flow-management.browser.json`；回归测试 → `test/flow-management.test.ts`。

它是这四页里**参数最"偏心"的一页**：四个可空字段分成两类，一类**整个丢掉**、一类**照发空串**。

## 页面标识

| 项 | 值 |
| --- | --- |
| 菜单路径 | `/dashboard/flow/task/copy/list`（菜单标题「抄送我的」，域 `flow`） |
| 权限码 | `/dashboard/flow/task/copy`（比菜单路径少 `/list`） |
| 路由文件 | `app/portal/views/dashboard/hr/flow/task/copy/list.vue` |
| 清单行 | `page-catalog.json` 的 `f396cb`，`kind` = 列表页(自定义 customLoad)，`write` = false |
| 菜单来源 | `app/portal/menus/hr.js:251` |
| module-type | **没有** —— 匹配不到任何规则；基准里浏览器**同样不发这个头** |
| http 实例 | **全局默认的 `platform.js`**（页面 `list.vue:102` 显式 import） |

| 写操作 | **无**。行上只有「详情」（跳流程表单详情页） |

## 逐字段基准

基准文件：`baseline/flow-management.browser.json` 第 4 条（打开页面时自动查询）。

```text
GET https://biz-api-test.wodecorp.cn/admin-api/bpm/process-instance/copy/page
    ?order=&orderField=&processInstanceName=&title=&pageNo=1&pageSize=20&_t=<ts>
```

请求头（**没有 `module-type`**）：`tenant-id` / `token` / `Accept-Language: zh-CN` /
`Accept: application/json, text/plain, */*`。

**参数顺序是契约的一部分**（`list.js:473-483` 的 `{ order, orderField, ..._form }` 再补分页；
`customLoad` 里再 `{...form, createTime: 格式化后的数组}` —— 换的是**值**，键的位置不变）：

```text
order, orderField, processInstanceName, title, startUserId, creator, status,
createTime[0], createTime[1], pageNo, pageSize, _t
```

（`startUserId` / `creator` / `status` / `createTime` 在空值时不出现，所以实际顺序里它们会"缺位"。）

### 四个可空字段分成两类（这一页最容易写错的地方）

页面挂了一个 `convertFetchForm`（`list.vue:159-166`），只对**三个**字段删空：

```js
for (const key of ['startUserId', 'creator', 'status']) {
  if (form[key] === null || form[key] === undefined || form[key] === '') delete form[key]
}
```

| 字段 | 控件 | 空值时 |
| --- | --- | --- |
| `processInstanceName` | `a-input` 文本 | **照发**：`processInstanceName=` |
| `title` | `a-input` 文本 | **照发**：`title=` |
| `startUserId` | 人员选择器（`portal-hxr-select-user`） | **整个丢掉** |
| `creator` | 下拉（`copy-creator-List` 的候选） | **整个丢掉** |
| `status` | 字典下拉 `bpm_process_instance_status` | **整个丢掉** |
| `createTime` | `a-range-picker`（**没有 `show-time`**） | **整个丢掉**（空数组被 qs 丢掉） |

一刀切"把空值都丢掉"会让 URL 少两个键（`processInstanceName=` 与 `title=`），
一刀切"空值都照发"会多三个键。基准第 4 条正是前者**照发**、后三者**不在**的样子。

### ⚠️ 时间区间：这一页有"两个零点"的坑

`list.vue:122` 只做 `.format('YYYY-MM-DD HH:mm:ss')`，**没有任何改写**（既没有 +1 天，
也没有归到当日边界）。但页面上的 `a-range-picker`（`list.vue:49`）**没有 `show-time`** ——
它给出的两个 dayjs 时刻都是**所选日期的零点**。于是：

> 用户在页面上选「9-01 ~ 9-10」，实际发出去的是
> `createTime[0]=2026-09-01 00:00:00` 与 `createTime[1]=2026-09-10 00:00:00`，
> **9-10 那一整天其实查不到**（只有 00:00:00 整点那一瞬）。

这是**页面自己的 bug**（本波只报告、不代改 Projects_Js）。SDK 的对策：

- `buildFlowTaskCopyTimeRange(start, end)` **要求显式给时分秒**（只接受
  `YYYY-MM-DD HH:mm:ss`），**不做任何改写** —— 要含结束日一整天请自己给 `23:59:59`；
- 参数说明里把这件事写死，并**明确禁止**照抄别的页面的 +1 天（会静默多查一天）。

## 参数契约

| 参数 | kind | 必填 | 说明 |
| --- | --- | --- | --- |
| `processInstanceName` | text | 否 | 流程名称，模糊匹配。空串**照发** |
| `title` | text | 否 | 审批内容，模糊匹配。空串**照发** |
| `startUserId` | search | 否 | 流程发起人的**用户 id**（不是姓名）。空值**不发这个键**。候选用 `base-user-search` |
| `creator` | search | 否 | 抄送发起人的**用户 id**。空值**不发这个键**。同上 |
| `status` | enum | 否 | 流程状态，字典 `bpm_process_instance_status`。【推断】取值未实测；候选用 **`base-dict-get`**（`dictType=bpm_process_instance_status`） |
| `createTimeStart` / `createTimeEnd` | date | 否 | 必须**成对**给；`YYYY-MM-DD HH:mm:ss`；**原样两端**（见上面那个坑） |
| `pageNo` / `pageSize` | number | 否 | 默认 1 / 20 |

两条本地校验（都是 `Promise.reject`、**不发请求**）：区间成对；两端格式必须是
`YYYY-MM-DD HH:mm:ss`（**date-only 会被拒**，正是为了不让人误踩"两个零点"）。

### 长选项参数（D6 / H35）：页面那两条全量拉，SDK **一条都不照抄**

| 页面挂载时发的候选请求（基准第 5、6 条） | SDK 的做法 |
| --- | --- |
| `GET /bpm/process-instance/copy/copy-creator-List`（**无参**全量） | **不提供**。`creator` 要的是用户 id，用 `base-user-search`（强制要关键字） |
| `GET /sys/user/getUserPageInfo?pageNo=1&pageSize=20`（人员选择器，会翻页） | **不提供**。同上 |

⚠️ 本地检出的组件写的是 `pageSize=200 / maxPages=100`，与基准那条的 `pageSize=20` 对不上
（本地检出声称落后于部署版本）——**两条路都不该照抄**，所以这条差异不影响结论。

## 操作步骤

```text
1. 进入「抄送我的」（/dashboard/flow/task/copy/list）
2. （可选）填流程名称 / 审批内容（两个纯文本）
3. （可选）选流程发起人 / 抄送发起人（两个人员选择器 —— 要给用户 id）
4. （可选）选流程状态（字典 bpm_process_instance_status）
5. （可选）选抄送时间区间（要给时分秒，否则整天查不到）
6. 查询
7. 行上「详情」→ 跳流程表单详情页（goFlowFormDetailByInstanceId），不是本能力的接口
```

## 真实验证

- **基准来自真实环境**：2026-09-21 由 `bsk` 抓于 `https://webtest01.wodecorp.cn/portal.html#/`
  （`baseline/flow-management.browser.json` 第 4 条）。
- **契约与基准逐字段一致**：`test/flow-management.test.ts` 比有序的 `[key, value]`，
  另有「三个选择器空值整个丢掉、两个输入框空串照发」「三个选择器给了值就各就各位」
  「空串形式的选择器同样被丢」「区间原样两端」「date-only 被拒」「单边要 reject」各一条。
- **没做**：SDK 对真实后端的**冒烟**（本波不跑浏览器、也没有这一页的 smoke 脚本）。

## 尚未覆盖

- **写操作：没有**。这一页行上只有「详情」一个动作，跳走之后做什么在流程表单那边。
- **两个人员候选入口**（`copy-creator-List`、`getUserPageInfo`）**刻意不做**，理由见上（D6 / H35）。
- **`status` 的取值表**没有枚举（页面是字典控件，未实测），只能标【推断】。
- **列表行的字段只在源码里核对过**（`processInstanceName` / `title` / `startUserName` /
  `status` / `processInstanceStartTime` / `taskName` / `creatorName` / `createTime` /
  `processInstanceId`），**没有拿真实响应体逐字段核过** —— 基准只抓了请求，没抓响应。
- **「详情」跳转的落点**（`/dashboard/flow/form/detail?...` 的具体 query）只从
  `flow/index.js` 的 `goFlowFormDetailByInstanceId` 读出，没有实际走一遍。

## SDK AI 说明契约（2026-09-22）

本节由当前 SDK 描述结果整理；说明权威来源为 `src/catalog/contracts-business.ts`。调用 `catalog.describe(id)`（或 `id-llm`）可得到参数来源、返回字段/状态、数据消费与后续映射；`catalog.describePage(页面路径)` 用于选择页面功能。以下更新以本节为准；前文历史请求/实测记录仍保留其记录日期。

### `flow-task-copy-list`

查询抄送给当前用户的流程通知；抄送不等于待审批。

- 执行：`sdk.flowTask.listCopy`；通过 `capabilities.invoke('flow-task-copy-list', args)` 调用时按 `params` 填参。性质：read。
- 参数：`processInstanceName` 可选 (string)；`title` 可选 (string)；`startUserId` 可选 (string)；`creator` 可选 (string)；`status` 可选 (string | number)；`createTimeStart` 可选 (string)；`createTimeEnd` 可选 (string)；`pageNo` 可选 (number)；`pageSize` 可选 (number)。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`{ list: object[], total: number }`。list=[] 为当前页无记录；total=0 表示该筛选无结果。保留筛选条件检查页码，不将空结果解释成权限判定。
- 字段：`list`、`total`、`list[].id`、`list[].processInstanceName`、`list[].title`、`list[].startUserName`、`list[].status`、`list[].processInstanceStartTime`、`list[].taskName`、`list[].creatorName`、`list[].createTime`、`list[].processInstanceId`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：按抄送时间与流程展示消息；不能把抄送 id 传给 task-action 批准。起止时间按字面时刻，不加一天。
- 完成条件：按用户要求交付本次筛选范围的结果；需要完整清单时继续翻页至覆盖 total，不能把当前页当全集。
- 后续：optional → `base-dict-get`：dictType=bpm_process_instance_status；解释流程状态（dictType ← context.dictType）；optional → `task-action-instance`：需要查看抄送流程详情；此步骤不授权审批（processInstanceId ← result.list[].processInstanceId）
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。
