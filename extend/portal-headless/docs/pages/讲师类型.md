> 这一页的**共享机制**（参数顺序怎么来的、空值发不发、时间区间怎么算）写在
> [学习管理域](./学习管理域.md) 里，这里只记这一页自己的东西。

| 项 | 值 |
| --- | --- |
| 菜单路径 | `/dashboard/base/teacher-level/list` |
| 权限码 | `/dashboard/base/teacher-level` |
| 路由文件 | `app/portal/views/dashboard/education/base/teacher-level/list.vue` |

| module-type | 12 学习管理 |

| 基准 | `baseline/study-teacher.browser.json` |
## ⚠️ 这一页走的是 **smart-layer-admin** 实例，不是 platform

请求落在 `smarterlayeradmintest.zhihuidanji.com/admin`，**另一个 host**。
这个实例的响应规则是 `smart-layer` 那一档（见 `src/context/http-instance.ts`）：
**不看 `ret`、看 `code`**；而且页面调用时都带 `isOriginal: true` ——
拿到的就是**整个响应体**，页面自己去取 `result.page.results`。

实测原始体（2026-09-21）：

```json
{"ret":"SUCCESS","code":200,
 "page":{"pageNo":1,"pageSize":2,"totalRecord":13,"totalPage":1,"results":[…]}}
```

⇒ 本能力把 `{page: {results, totalRecord}}` 归一成 `{list, total}`，与其它能力同形。
**响应里没有 `page` 时当场抛**，不静默返回空列表 —— 后者会让调用方以为"真的没有数据"，
而实际是响应形状变了。

## 实例是**逐请求**声明的，不是页面级规则

这一页的**列表**走 smart-layer-admin，而**删除**（`DELETE /study/base/studyteacher`）走 **platform**。
`src/context/http-instance.ts` 的 `isPageShapedPath` 注释写着这条道理：
"同一次页面操作里可能有多个实例，所以实例必须能逐请求指定，不能只当页面属性"。

本轮试过往 `HTTP_INSTANCE_PAGE_RULES` 加页面级规则，被 `test/http-instances.test.ts`
的相等性断言拦下 —— **它是对的**。

**代价（conventions 第 27 条）**：这个实例的 baseURL 必须由调用方显式给
（`createPortalHeadless({ httpBaseUrls: { 'smart-layer-admin': 'https://smarterlayeradmintest.zhihuidanji.com/admin' } })`），
没给就**拒绝发请求**（失败关闭），不会拿默认 baseURL 去凑。

## 它曾经"做不了"，原因是 SDK 当时没复刻这一族包络

早先 SDK 只实现了 `portal-standard` 一种包络，其余四档一律抛
`HttpInstanceUnsupportedError`。用户 2026-09-21 要求**按各实例自己的规则复刻**，
`src/http/client.ts` 里补上了 `applyEnvelope()` 的四条规则（测试 `test/http-envelope.test.ts`），
这两页才做得成。

## 参数契约

| 参数 | kind | 说明 |
| --- | --- | --- |
| `name` | text | 讲师姓名（模糊） |
| `level` | text | 讲师类型。页面是下拉但**取值域未实测**（无筛选时它根本不发这一项）→ 只透传、不给枚举 |
| `page` | number | 页码，默认 1。**参数名是 `page`，不是 `pageNo`**（页面覆写了 `fieldNamePageNo`） |
| `limit` | number | 每页条数，默认 20。**是 `limit`，不是 `pageSize`** |

⚠️ `level` 的初值是 **`undefined`**（不是空串）—— 与同域其它页"空值也照发"**相反**。
实测基准里也没有这一项。

## 真实验证（2026-09-21）

- `list({pageNo:1,pageSize:3})` → **133 条**（本页 3 条），归一后的 `total` 是数字。
- 冒烟：`smoke/read-study-module.mjs` 的 ⑥ 段。

## 写入口状态（2026-10-08）

- 新建 / 修改：`study-teacher-level-prepare-save` → `study-teacher-level-save`，分别 POST `insertTeacherLevel.lay` / `updateTeacherLevel.lay`。
- 启停：`study-teacher-level-prepare-status` → `study-teacher-level-status`，POST `/manage/updateTeacherLevelStatus.lay`，body `{id, status}`；虽然类型状态接口是 POST，仍需写后回查列表。
- 删除：`study-teacher-level-prepare-remove` → `study-teacher-level-remove`，GET `/manage/deleteTeacherLevel.lay?id=...`；这是实际删除，不是查询。对应 cancel 只放弃本地草稿。
- 编辑保存按页面 `omit(form, ['createTime', 'updateTime'])` 发送，保留 bridge 中的业务字段（例如 status）；smart-layer 返回无业务数据，必须回查 `study-teacher-level-list`。

`GET /manage/selectAllTeacherLevel.lay` 仍不单独开放：页面在一次挂载里重复请求，且候选已由列表能力覆盖。以上写入口没有浏览器/真实环境闭环证据，契约中的 gaps 保留该限制。

## 与讲师管理那一页的差别

- 页面表单是**空的**（`form: {}`），`customLoad` 只用了 `{ page: params.pageNo }`
  —— 所以请求上**只有 `page` 一个业务参数**（`token` / `_t` 是实例与客户端加的）。
- 实测它自己的默认页大小是 **15**（我没传 pageSize，后端回的是 `pageSize: 15`）。

## SDK AI 说明契约（2026-09-22）

本节由当前 SDK 描述结果整理；说明权威来源为 `src/catalog/contracts-business.ts`。调用 `catalog.describe(id)`（或 `id-llm`）可得到参数来源、返回字段/状态、数据消费与后续映射；`catalog.describePage(页面路径)` 用于选择页面功能。以下更新以本节为准；前文历史请求/实测记录仍保留其记录日期。

### `study-teacher-level-list`

查询讲师类型/等级配置；与讲师人员列表区分。

- 执行：`sdk.studyTeacher.listLevels`；通过 `capabilities.invoke('study-teacher-level-list', args)` 调用时按 `params` 填参。性质：read。
- 参数：`page` 可选 (number)。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`{ list: object[], total: number }`。list=[] 为当前页无记录；total=0 表示该筛选无结果。保留筛选条件检查页码，不将空结果解释成权限判定。
- 字段：`list`、`total`、`list[].id`、`list[].name`、`list[].level`、`list[].sort`、`list[].status`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：展示 name/level/sort；不要把类型 ID 当讲师 ID。
- 完成条件：按用户要求交付本次筛选范围的结果；需要完整清单时继续翻页至覆盖 total，不能把当前页当全集。
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。

## 本轮补齐（2026-09-26）：`.lay` 写入口（新建 / 修改）

页面表单 `[mode]/[id].vue` 的「保存」按 `isCreateMode` 二选一，两条都是
`smartLayerAdminHttp.post(...)`、**JSON body**、**smart-layer-admin 实例**：

| 能力 id | 请求 | 说明 |
| --- | --- | --- |
| `study-teacher-level-prepare-save` | 本地 | 校验表单并按 mode 选好端点，生成草稿，不发请求 |
| `study-teacher-level-save` | `POST /manage/study/insertTeacherLevel.lay`（create）/ `updateTeacherLevel.lay`（edit） | 真写 |

**参数契约**

- `mode`：`create` 打 `insertTeacherLevel.lay`，`edit` 打 `updateTeacherLevel.lay`；草稿里的 `url` 与 `mode` 不自洽时 SDK 拒绝发请求。
- `name`：必填、**≤10 字**、不能全是空格（页面 `rules.name` 三条）。
- `level`：**1~99 的整数**（页面 `a-input-number :min="1" :max="99" :precision="0"`）。
  ⚠️ 编辑态页面上这个输入框是 `disabled` 的、改不了，但页面仍会原样回传。
- `sort`：**1~999 的整数**（同款 a-input-number）。
- `id`：`edit` 必填（来自列表行）；`create` 不允许带（新建态 bridge 里没有记录）。

**body 键序**：create → `{name, level, sort}`；edit → `{id, name, level, sort}`（id 在最前，它是行数据里的第一个键）。

**⚠️ SDK 自己补的一次 `code` 判定**：页面上这两个保存调用**不带 `isOriginal`**，失败靠拦截器按 `code !== 200` 判；
而本页的页面上下文在接线处被整体配成 `isOriginal: true`（`applyEnvelope` 在 `isOriginal` 下不看 `code`）。
所以能力里自己判一次 —— 不补的话，业务失败会以"成功的 `undefined`"返回。

**⚠️ 返回值没有业务数据**：页面保存成功后只弹一句提示，不读响应体；失败靠抛错。
成功必须用 `study-teacher-level-list` 回查确认（条数 +1 且出现该 name / 字段已改），**不能只看请求没抛错**。

**幂等**：端点**没有 requestId**。修改写的是绝对值、重发终态相同；但**新建重发会多出一条同类型记录** ——
超时先回查列表再决定是否重发。

**已知差异（记进缺口）**：页面在编辑态是把 bridge 里的**整行**（去掉 `createTime`/`updateTime`）回传，
可能还带 `status`；SDK 只发 `{id, name, level, sort}` 这四个表单真有的控件。
依据是 smart-layer 后端（`.lay` 那一侧）**不在本仓库的两个固定检出内**，无法核实它是否依赖行上的其它字段。

**操作步骤**：`prepareSaveLevel` → 用户确认 → `saveLevel` → `study-teacher-level-list` 回查。
没有回滚接口：写错了只能再改一次，或先用讲师类型删除能力移除后重建。

**推断与缺口**：两个端点**没有浏览器基准**、**smart-layer 后端不可读**、尚未在真实测试环境执行过写操作。
