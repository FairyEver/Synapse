## 逐字段基准（**判据**）

```
GET /admin-api/manager/aiModelSelection/getByPage?order=&orderField=&pageNo=1&pageSize=20&_t=<ts>
```

能力发出的与基准**逐字相同**（断言在 `test/ai-model.test.ts` 的 J 组）。两处细节被基准证实：

1. **`callTypeList` 空数组真的不发**。页面的 `customLoad` 是
   `{ ...form, callTypeList: form.callTypeList?.join(',') || undefined }`
   —— 空数组 `[].join(',')` 得到 `''`，`||` 落到 `undefined`，被 `qs` 的 `skipNulls` 丢掉。
   有值时是**逗号连接的字符串**（qs 会把逗号编码成 `%2C`）。
2. `order` / `orderField` 照发（`useListPageModule` 的默认参数）。
3. 基准里这条列表请求出现 **2 次**（点「查询」重发一条只差 `_t` 的）⇒ 断言写成
   "存在一条相符"，不是"只出现一次"。

## 参数契约

| 参数 | kind | 说明 |
| --- | --- | --- |
| `callTypeList` | enum（多选） | 调用类型，**逗号连接**后发出；空数组 ⇒ 整项不发 |
| `pageNo` / `pageSize` | number | 默认 1 / 20（`styleV2`） |

| 值 | 含义 | 页面上这一档显示哪些字段组 |
| --- | --- | --- |
| 1 | APP对话 | 备选模型 + 默认模型（`defaultFirst`、单选） |
| 2 | Web对话 | 同上；**并且多一个「技能选择」** |
| 3 | 后端调用 | 提取参数 / 多模态 / 分析报告 / 意图识别 四组 |
| 4 | 前端意图识别 | APP 意图识别 + Web 意图识别 两组 |

## 写链路（`prepareSaveModelSelection` → `saveModelSelection` → `cancelCreatedModelSelection`）

### body 键序（**不是** JSON 里随便排的）

页面的 `customSubmit` 是**逐句追加**的，所以键序固定为：

```
callType → details →（有 id 时）id →（callType === 2 时）skillIds
```

- `details` 的每一项固定三键：`{ code, modelId, isDefault }`（页面 `buildDetails` 的书写顺序）。
- `skillIds` 是**逗号分隔的字符串**（`arrayToIds = arr.join(',')`，空数组得到 `''`）。
- `id` 夹在 `details` 与 `skillIds` **之间** —— 不是排在最前，也不是最后。

### 前置条件（后端代码证实）

- `add`：`callType` 必填；**`callType=2` 时 `skillIds` 非空**（空串 ⇒ 400「请求参数缺失:技能选择」）；
  **同一 `callType` 只能有一条**，重复创建 ⇒ 500「已有同调用类型，请勿重复创建」。
- `update`：`id` 必填；**不做**那个查重（所以改一条已经有的是合法的）。
- 两者成功后都会 `kbChatController.clearModelSelectionCache()` —— 会**真的清掉聊天侧的缓存**。

### 撤销

- 新建 ⇒ `cancelCreatedModelSelection(callType)`：`add` **不返回新 id**（后端 `success(null,"新建成功")`），
  但 `callType` 后端保证唯一，所以按它回查**比模型那条（按可能重名的 modelName 回查）可靠得多**。
  回查结果不是恰好 1 条时**拒绝**，不猜。
- 修改 ⇒ `restoreModelSelection(previous)`：把旧行**折回草稿形状**再 `update`。
  ⚠️ 这里要调用方自己折 —— 详情接口给的 `details` / `skillIdList` 与提交 body 的形状不一样，
  而页面那套折算（`getDetailFieldsFromData`）服务的是"表单里两个多选框互斥显示"，
  无头侧没有这个约束，**照抄它会变成"只能按页面的 UI 走"**，所以本能力刻意不搬。
- 删除 ⇒ **撤不掉**。

## ⚠️ 本能力**没有**搬页面的 UI 折算

`[mode]/[id].vue` 的 `getDetailFieldsFromData()` 有一整套折算：`details` 优先、空则退到
`modelIdList` 等四个平铺字段、再按 `callType` 过滤、`defaultSingle` 的档还要从备选里剔掉默认模型。
这些全是**表单互斥显示**的需要。`prepareSaveModelSelection` 因此只把**原始行**交给调用方
（`current`），要不要拆由调用方决定 —— 这是有意的取舍，不是漏做。

## 长选项参数

- **可用模型**（`modelId`）：`GET /manager/aiModelConfig/getAvailableList`，**无参数、一次全量**。
  页面挂载时就整份拉走灌进下拉。本能力单开 `ai-model-available-list`，`details` 那条参数用
  `lookup` 指过去（`keyword` 是**本地过滤**，不减少请求量）。
- **技能**：页面另外打 `GET /sys/tip-template/list?isPublish=<PUBLISH_YES>` 再本地
  `filter(isPublishedSkill)`。**本能力没有做这条**（它属于"提示词模板"域，不是本页的接口；
  而且页面对它做了 `isPublish` 的二次过滤）。要用请先走那个域的既有能力。

## 测到 vs 没测到

**测到**：列表 GET 与基准逐字段一致（含 `callTypeList` 空数组真的不发）；4 条能力的
定义与目录对齐；写 body 的键序与 `skillIds` 的逗号串形态（**按源码推导**，有变异反证）。

**没测到**：写接口一条都没在真机上跑过；`detail` 的真实响应字段名（`details` /
`skillIdList` / `modelIdList`）是读 Java DTO 得到的，没看真实响应体；
`details[].code` 的**合法取值域没有后端枚举可查** —— `AiModelSelectionDetailDTO.code`
是个自由字符串，页面自己写死了七个
（`model` / `extract_param` / `multimodal` / `analysis_report` / `intent_recognition` /
`app_intent_recognition` / `pc_intent_recognition`）。所以本能力的 `code` 参数是**透传**的，
不做白名单 —— 传错了后端大概不会报错，只会静默存进去。

### `ai-model-selection-save`

实际保存调用类型到各用途默认/备选模型以及技能绑定。

使用：用户明确调整模型路由；prepare只准备草稿不会保存。 行为：write。入口：`invoke('ai-model-selection-save', args)`。

- 新增同callType只能一条；callType=2 Web对话后端要求skillIds非空。
- details传数组[{code,modelId,isDefault}]；不是选中的模型ID数组，也不能用明细id代替modelId。
- 成功后后端清模型选择缓存；回执null不含ID。

参数：

| 参数 | 类型/格式/条件 | 含义与来源 |
| --- | --- | --- |
| `id` | number；可选 | 无/null新建，有值修改；来源：ai-model-selection-list.list[].id |
