## 列表参数、权限与返回字段

Portal 列表表单初值为 `orgIds: []`、`staffCode: ''`、`staffStatus: ''`、`status: ''`、`staffName: ''`。发送前补 `businessDate=YYYY-MM-DD`，并把组织数组转换为逗号分隔字符串；默认分页为 `pageNo=1`、`pageSize=20`。

```json
{
  "order": "",
  "orderField": "",
  "orgIds": "9,10",
  "staffCode": "S001",
  "staffStatus": 1,
  "status": 0,
  "staffName": "张",
  "businessDate": "2026-09-23",
  "pageNo": 1,
  "pageSize": 20
}
```

`status` 为 `-1`已停薪、`0`未起薪、`1`已起薪；`staffStatus` 是 Portal `job_status` 字典值。Java `page()` 先调用 `getRoleOrganizationTree(null, null)`：未选择组织时将角色可见组织全部写入查询，已选择组织时与可见组织取交集，空交集直接返回空页。因此空页不是权限绕过，也不能单独解释为“没有权限”。SDK 不发布全量组织树，只接受当前角色组织树/列表中已核实的 ID。

分页每页只接受 Portal 页面可选的 `10/20/50/100/200/500`。列表返回 `{ list, total }`；SDK 保留行中未知字段，但契约逐项说明以下页面消费字段：

`id`薪资办理记录ID、`staffId`员工ID、`staffCode`工号、`staffName`姓名、`idCard`身份证号、`organization/organizationName`所属组织、`startOrganizationName`起薪组织、`postName`岗位、`employmentType`用工类型、`ledgerId/ledgerName`账套、`salaryLevel/salaryLevelName/salaryLevelStandard`薪资等级及标准、`cardIssuingBank`开户行、`bankAccount`银行账号、`status`薪资状态、`legalPersonId/legalPersonName`纳税单位、`costCenterId/costCenterName`成本中心、`staffStatus`在职状态、`entryTime`入职时间、`salaryCategory`薪制类别、`wage`基本工资标准、`transactTime`起薪日期、`description`起薪说明、`stopTime/stopDescription`停薪信息、`emptyDate`清纳税开始时间，以及创建/修改审计字段。身份证号、银行账号属于敏感字段，不写入日志。

## 详情、表单与状态规则

详情请求为 `GET /salary/salarytransact/info`：列表行有记录 `id` 时按 `id` 查询；未起薪员工没有记录 ID 时按 `staffCode` 查询。编辑页另外读取 `GET /salary/ledger/getWebLedgerList`，并通过 Portal 候选组件读取纳税单位、成本中心、薪资等级。

起薪/编辑表单的请求字段沿用 Java `SalaryTransactDTO`：`id`、`transactTime`、`staffCode`、`organization`、`ledgerId`、`status`、`legalPersonId`、`costCenterId`、`salaryCategory`、`wage`、`salaryLevel`、`description` 及详情中的审计/停薪字段。规则如下：

- `transactTime` 必须是有效的 `YYYY-MM-DD`；Portal 表单没有显式 required，但 Java 起薪服务明确拒绝空起薪日期，SDK 按后端真实规则阻止空值。
- `staffCode` 起薪必填；账套 `ledgerId`、纳税单位 `legalPersonId`、成本中心 `costCenterId` 和说明 `description` 必填，说明最多 200 字。`salaryLevel` 和 `salaryCategory` 可以清空，工资标准保留数字或十进制字符串。
- 起薪使用 `POST /salary/salarytransact`；提交前应先调用 `checkStart`，返回 `0` 才能继续。返回 `1` 表示本记录已起薪，返回 `2` 表示其他组织已有起薪记录，不能绕过检查直接提交。
- 编辑使用 `PUT /salary/salarytransact`，只允许最新 `status=1` 的记录。Java `edit` 会把 `organization` 和 `staffCode` 置空后再更新，调用方不能把编辑理解成修改员工归属；SDK 保留详情字段但不承诺这两个字段可被改变。
- 停薪使用 `PUT /salary/salarytransact/stop`，请求体字段名是 `idList`、`stopTime`、`stopDescription`；单条页面实际发送一个元素的 `idList`。停薪日期早于当前北京时间日期时服务端立即改为 `-1`，未来日期在到期前仍可能保持 `1` 并由服务端排程。

## 批量动作、导出和文件

列表批量调整按钮只有在选中行非空且所有行 `status===1` 时打开。SDK 的 prepare 和 submit 同时要求 `idList` 非空不重复、`currentStatuses` 与 `idList` 等长且每项为 `1`：

| 动作 | 请求 | 请求体 |
| --- | --- | --- |
| 纳税单位 | `PUT /salary/salarytransact/editLegalPersonId` | `{ legalPersonId, idList }` |
| 成本中心 | `PUT /salary/salarytransact/editCostCenterId` | `{ costCenterId, idList }` |
| 清纳税开始时间 | `POST /salary/salarytransact/batchEmptyTaxDate` | `{ emptyDate: 'YYYY-MM', ids: idList }` |

清纳税接口后端会把月份拼成 `YYYY-MM-01` 保存；SDK 不把后端字段 `ids` 错写成 `idList`。

导出严格复刻 Portal 分支：没有选中行时发送当前筛选字段和 `businessDate`；有选中行时只发送去重后的 `staffCodeList` 和 `businessDate`，不把组织/状态筛选混入选中分支。返回值是非空文件的 `{ fileName, contentType, base64, byteLength }`。

批量起薪调用 `POST /salary/salarytransact/importExcel`，批量停薪调用 `POST /salary/salarytransact/stopBatch`，均使用 multipart 字段 `file`，Portal 的可达校验接受 `.xlsx/.xls`。批量起薪结果逐字段返回 `processedIds`、`processedStaffCodes`、`processedCount`、`eligibleStaffIds`、`eligibleStaffCodes`、`excludedStaffList`，排除项包括员工、业务日期和 `reasonCode/reason`。批量停薪成功回执可能为空，必须重新查询核对停薪结果。

模板下载是两段请求：先 `GET /salary/salarytransact/download` 或 `/stopdownload` 得到 OSS URL，再用同一会话下载非空二进制文件。SDK 不把第一段 URL 字符串当作文件内容。

## 操作步骤、失败处理与验证边界

1. 先用 `.list` 获取当前用户角色组织范围和记录状态；编辑或批量动作前使用最新详情/列表，不复用过期状态。
2. 起薪按 `checkStart → get → prepareStart → start → get/list 回查`；取消只丢弃草稿。
3. 编辑按 `get(status=1) → prepareUpdate → update → get 回查`；不能用名称代替候选 ID。
4. 停薪按最新 `status=1 → prepareStop → stop → get 回查`，区分立即停薪和未来排程。
5. 批量动作按最新全为 `status=1 → prepare → submit → list/get 逐条回查`；部分成功或超时不得盲目整批重传。
6. 文件按 `prepare → submit → 文件结果/列表回查`；空文件、非法扩展名、非法 Base64、非法日期/月、重复 ID、非法状态、分页值或必填字段在请求前失败；401/403、网络错误和后端业务错误原样抛出。
