# 费用用途管理（`/dashboard/finance/setting/fee-purpose/list`）

Portal「财务设置 → 费用用途管理」页面包含筛选列表、详情读取、新建/编辑表单、级联候选、行内启停和删除。能力只覆盖当前页面源码实际调用的端点；后端存在但页面未调用的费用用途分页候选 `/options` 不登记为本页能力。

## Portal 页面行为

列表初始表单为：`applicationType: undefined`、`feeCode: undefined`、`keyword: ''`、`status: 0`。页面在创建列表模块后将 `pageSize` 设为 `10`，分页仍支持 `10/20/50/100`。

列表 `loadPage` 只构造以下查询字段：

```json
{
  "pageNo": 1,
  "pageSize": 10,
  "applicationType": "申请单类型value或undefined",
  "feeCode": "费用代码或undefined",
  "keyword": "去首尾空白后的关键字或undefined",
  "status": 0
}
```

`status` 只有数值 `0` 或 `1` 时发送；选择“全部”时省略。列表可见列为 `applicationTypeName`、`feeName`、`purpose`、`updateTime`、`status`。状态显示为 `0=启用`、`1=停用`。

申请类型候选调用 `/application-type-options`，费用候选调用 `/fee-options`。费用候选必须带当前 `applicationType`；切换申请类型会清空旧 `feeCode` 和费用候选。页面搜索输入去首尾空白，空关键字不发送；浏览器 debounce 只属于交互层，SDK不人为延迟请求。

## 表单提交规则

新建页面只提交三个字段：

```json
{
  "applicationType": "表单选择的申请类型value",
  "feeCode": "String(formState.feeCode)",
  "purpose": "表单原始文本"
}
```

`purpose` 必须非空白且最多 15 个 Unicode 码点；Portal 使用 `Array.from`，Java 使用 `codePoints().count()`。`status` 不由页面提交，后端创建固定为 `0=启用`。申请类型、费用代码的合法组合、流程是否启用、字典是否启用和重复配置由后端最终校验。

编辑页只允许 `status=1` 的停用记录编辑，申请类型和费用输入框禁用，只提交 `{ id, purpose }`；不能通过编辑修改申请类型或费用代码。后端更新同样以 `status=1` 为条件保护。

启停提交的是绝对数值 `{ id, status }`，不是 toggle；从启用行停用发送 `status=1`，从停用行启用发送 `status=0`。启用时后端重新校验申请类型和费用组合。

删除只对 `status=1` 的停用记录显示，后端以逻辑删除执行；页面没有恢复接口。写操作应遵循 `prepare → submit → 按同一 ID 回查`，删除前必须明确告知不可恢复的页面边界。

## 权限与后端规则

- 列表和详情使用页面权限 `/dashboard/finance/setting/fee-purpose`；创建、编辑、启停、删除分别使用 `finance:fee-purpose:create`、`finance:fee-purpose:update`、`finance:fee-purpose:update-status`、`finance:fee-purpose:delete`。
- 申请类型和费用候选接口的后端权限是页面权限或 create/update-status 按钮权限的并集；SDK不把候选接口扩展成其它页面能力。
- `applicationType` 是稳定流程 key，`feeCode` 是当前类型下的费用代码字符串；`applicationTypeName`/`feeName` 只用于展示。
- 申请类型候选按当前租户已发布、启用的 BPM 流程返回；费用候选按对应流程允许的费用代码和启用字典返回，服务端最多返回 50 项。
- 后端 `get` 对历史停用记录可以回显名称，不要求流程当前仍处于启用；启用和创建则要求组合再次通过目录校验。
- 页面没有调用后端 `/options`；该接口用于其它申请页的费用用途候选，不属于本页目录。
