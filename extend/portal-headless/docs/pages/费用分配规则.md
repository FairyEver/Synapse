Portal「财务设置 → 费用分配规则」列表、详情、新建/编辑表单和行内启停按本页逐项核对。页面同时支持费用类别分摊和订单分配，两种规则的提交字段和后端业务校验不同。

## Portal 页面行为

列表由 `useListPageModule` 注入 `order`、`orderField`、`pageNo`、`pageSize`，默认页大小为20，页面选项为10/20/50/100。默认表单实际发送：

```text
order=&orderField=&unitIdList=[]&allocateCostCenterIdList=[]&acceptCostCenterIdList=[]&ruleType=cost_sharing_class&expenseTypeIdList=[]&indicator=null&status=1&pageNo=1&pageSize=20
```

状态筛选在列表请求中是数值 `1/0`；列表响应的 `record.status` 是 Boolean，行内启停请求发送 `!record.status`。顶部规则类型切换值是 `cost_sharing_class` 或 `cost_sharing_order`。列表可见按钮为新增/编辑、启停、查看，按钮权限分别由 `create`、`status`、`detail` 控制；编辑复用新增权限。

详情页读取同一条规则的所属单元、分配方成本中心、规则类型、费用类别、分摊指标、接收方成本中心或订单分配类型、费用分配顺序或产品组、规则描述。成本中心展示名称，但提交使用成本中心 ID。

## 表单提交规则

Portal 表单先去掉 `unitId`、`acceptOrg`，再按规则类型生成保存体：

| 字段 | 费用类别分摊 `cost_sharing_class` | 订单分配 `cost_sharing_order` |
| --- | --- | --- |
| `status` | 编辑沿用原值；新建为 `true` | 同左 |
| `allocateCostCenterIds` | 分配方成本中心 ID 数组，至少一项 | 同左，选择器只保留生产成本属性 |
| `acceptCostCenterIds` | 接收方成本中心 ID 数组，至少一项，不能与分配方重叠 | `[]` |
| `expenseType` | 必填，`expense_category` 中值以 `2` 开头的选项 | `null` |
| `orderAllocationType` | `null` | 必填，`1=生产订单`、`2=销售订单` |
| `indicator` | 必填，分摊指标 ID | 必填 |
| `ruleOrder` | 必填，整数1至10000 | `null` |
| `productGroups` | `''` | 多选产品组 ID 逗号字符串 |
| `description` | 必填，最多500字符 | 同左 |

新建和编辑在真正保存前都会请求同一 page 接口进行重复预检：`pageNo=1,pageSize=999`，按规则类型、分配方/接收方成本中心集合、分摊指标以及费用类别或订单分配类型/产品组比较，并排除编辑中的同一 `id`。重复时不发送最终写请求。

## 权限与后端规则

- 页面权限和数据范围由当前会话、租户及 Portal/Java 共同裁决；SDK 使用 `platform` 实例，不从浏览器提取凭据，也不让调用方手写 `module-type`。
- 订单分配时，所有分配方成本中心的组织财务属性必须为生产成本 `orgAttribute=1`。
- 类别分配时，如果任一分配方成本中心的 `orgAttribute=1`，费用类别必须是 `29`（空舍费），且后端字典必须存在该配置。
- 类别分配的分配方和接收方成本中心不能重叠；分配方/接收方不能为空的规则由页面和后端分别校验。
- 后端启用规则还会做唯一性校验；SDK 的 page 重复预检是 Portal 行为的复现，不替代后端最终裁决。
- SDK 可接收成本中心对象快照进行前置组织属性校验；没有快照时不伪造组织属性，仍让后端校验，以免把不完整候选误判为合法。

## 后端与 SDK 对齐

Java `ExpenseAllocationRuleController` 提供 page、get、create、update、updateStatus；`ExpenseAllocationRuleSaveReqVO` 接收 `Long` ID、规则分支字段、成本中心 ID 数组和描述；响应包含列表页面和详情页面使用的成本中心对象、字典名称及迁移字段。SDK 不登记页面不可达的 `list-by-*` 和 `migrate-cost-centers` 端点。

SDK 在 `src/capabilities/finance-setting-allocation-rules.ts` 集中实现：页面默认请求键、列表状态数值/响应 Boolean 的区分、Long ID 字符串保留、表单分支校验、成本中心重叠和组织属性校验、Portal 重复预检、最小保存载荷、坏响应拒绝和绝对状态启停。

### `finance-setting-allocation-rules-list`

按页面筛选和分页读取费用分配规则列表，保留后续详情、编辑和启停所需的完整行字段。

返回：`{ list: object[], total: integer }`。list=[]且total=0表示当前筛选没有记录；权限、网络或响应形状失败会抛错，不改写为空列表。

- list[].status：当前绝对状态；true启用、false停用；{"true":"启用","false":"停用"}
- list[].ruleType：规则类型；cost_sharing_class为费用类别分摊，cost_sharing_order为订单分配；{"cost_sharing_class":"费用类别分摊","cost_sharing_order":"订单分配"}

- 消费：保留同一行完整id和status；需要写入前先get刷新详情，不能用名称或当前页序号定位。
