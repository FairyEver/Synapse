## 能力与权限

- 页面权限：`/dashboard/report/insurance-summary`。
- 页面使用 `platform` 实例，页面推导的 `module-type` 为 `14`。
- 列表接口：`GET /salary/report/standardUnitCostsPage`；Portal源码中的完整地址为 `/admin-api/salary/report/standardUnitCostsPage`，SDK通过platform实例补上前缀。
- 这是只读分页页；Portal没有导出、创建、修改或删除动作，SDK不增加这些方法。

## 筛选和分页参数

Portal表单初始值是 `standardUnitId=null`、`costMonth=dayjs()`。提交前只把月份格式化为 `YYYY-MM`，其余字段原样保留：

| 页面字段 | SDK 参数 | 发送值 |
| --- | --- | --- |
| 标准化经营单元 | `standardUnitId` | ID；未选择发送 `null` |
| 年月 | `costMonth` | 当前月默认 `YYYY-MM`；清空时发送 `null` |
| 页码 | `pageNo` | 默认 `1` |
| 每页条数 | `pageSize` | styleV2默认 `20`，只接受Portal页大小选项 |

SDK固定保留Portal分页排序槽：

```json
{
  "order": "",
  "orderField": "",
  "standardUnitId": 225,
  "costMonth": "2026-09",
  "pageNo": 1,
  "pageSize": 20
}
```

## 返回字段和后端聚合

页面展示：标准化经营单元、年月、五险人数、公积金人数，以及单位缴纳的养老/失业/工伤/医疗/生育/五险合计/公积金和个人缴纳的养老/失业/医疗/大额医疗/五险合计/公积金。金额字段按服务端 `BigDecimal` 原值返回；`total` 只用于分页。

Java查询按标准化单元连接其下级组织的社保费用，按标准化单元成本中心连接公积金费用：

- `fiveInsurancePersonNum` 和 `providentFundPersonNum` 在Service层按标准化单元下级组织分别统计 `cost_type=2` 的记录数。
- 单位/个人各项金额由 `SalaryDocumentDao.xml` 对社保费用和公积金基数、比例进行 `SUM`。
- `fiveInsuranceUnitCostTotal` 和 `fiveInsurancePersonalCostTotal` 是DTO计算属性，分别由五项单位金额和四项个人金额相加。
- DTO中存在 `companyBase`、`individualBase`、`companyRatio`、`individualRatio`、`month`、`staffCode` 等可选字段；若后端返回，SDK保留并在返回契约中说明，但页面当前不展示这些字段。
