## 参数契约

**没有分页**（`customLoad` + `getDataListIsPage` 默认 `false`），返回整棵树
（后端 `CommonResult<List<KpiTemStructureDTO>>`）。顺序逐字：

`order → orderField → templateType → _t`

| 字段 | 默认 | 谁给的 | 说明 |
| --- | --- | --- | --- |
| `order` | `''` | 页面钉死 | 空串照发 |
| `orderField` | `''` | 页面钉死 | 空串照发 |
| `templateType` | `0` | 调用方（枚举） | `0` 年度 / `1` 月度，下拉 `:allowClear="false"` ⇒ 永远有值、永远发 |

## ⚠️ 与模板内容页的那一处**唯一**差别

**这一页把「切换 `templateType` 即重查」的 `watch` 注释掉了**
（`template-structure/list.vue:149` 那一行 `// watch(() => rrList.formState.templateType, rrList.logicFetch)`）。
两页都只能点「查询」才重查，所以从用户角度两页一样 —— 记一笔是因为
**注释掉的代码不算数**（`docs/conventions.md` 第 28 条）：它不构成契约，别把它当"页面会自动重查"。

同页的另一处与模板内容一致：「名称」不上请求（`omit(form, ['templateName'])` 后本地过滤），
要按名字找用 `filterTreeNodeByName(rows, keyword, isTemplateLeaf)`。

## 已覆盖的读写动作

接口见 `KpiTemStructureController`（与模板内容对称），已接入统一目录并按 `prepare → submit → cancel` 建模：

- **删**：`DELETE /performance/temstructure/kpitemstructure`，body 是**裸数组 `Long[] ids`**
  （页面 `customDelete` 里 `http.delete(url, { data: list })`，`mapTree` 收子节点 —— 递归删除）。
- **建 / 改**：`POST` / `PUT /performance/temstructure/kpitemstructure`。
- **子页面**：`./template/edit/<id>`（编辑模板结构）—— 真正改结构的是里面的
  `POST /performance/temstructure/kpitemstructure/saveStructure`，不在本页。
- 行内「使用情况」走 `components/view-usage.vue` 的 `usedInfo`（`fromType: 3`）。

SDK 还覆盖基础详情、深层详情读取/保存、模板结构候选和使用情况；候选能力的页面路径与权限
固定为模板结构页，不借用模板内容页上下文。删除严格发送裸 ID 数组，真实环境写冒烟仍未执行。

## SDK AI 说明契约（2026-09-22）

本节由当前 SDK 描述结果整理；说明权威来源为 `src/catalog/contracts-business.ts`。调用 `catalog.describe(id)`（或 `id-llm`）可得到参数来源、返回字段/状态、数据消费与后续映射；`catalog.describePage(页面路径)` 用于选择页面功能。以下更新以本节为准；前文历史请求/实测记录仍保留其记录日期。

### `perf-manage-template-structure-list`

读取模板结构全树；templateType=0 年度、1 月度，默认年度。

- 执行：`sdk.perfManageTemplate.listTemplateStructures`；通过 `capabilities.invoke('perf-manage-template-structure-list', args)` 调用时按 `params` 填参。性质：read。
- 参数：`templateType` 可选 (string | number)。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`object[]`。[] 表示本次查询没有条目；这是数组，不读取 list/total。
- 字段：`[].id`、`[].name`、`[].parent`、`[].parentIds`、`[].children`、`[].updateTime`、`[].updaterName`、`[].type`、`[].templateType`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：递归 children；type=0 文件夹、1 才是业务模板，与利润树 type=1 文件夹的规则相反。名称查找在本地完成，不发送不存在的筛选参数。
- 完成条件：交付模板结构名称、ID 和目录路径；本能力不编辑模板。
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。


验证：`test/ai-contract-business.test.ts` 直接检查 SDK 描述输出及业务夹具；本批未重放真实写操作。逐能力状态、证据与反证见 [补齐清单](../ai-contract-business-evidence.md)。
