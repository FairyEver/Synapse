# 用户扩展

页面路径：`/dashboard/sale/sys/user/list`；菜单权限：`/dashboard/sale/frame/sys/user`；销售页面 `module-type=60`。

本页属于提示词保留范围的「系统设置 → 销售设置」，不是独立的销售或生产一级菜单。Portal提示新增组织、用户须前往人系统，因此SDK不发布新增用户能力。表格中的“移交”会进入隐藏移交路由，该路由实际读取承接组织树、待移交客户组织并提交移交；这些可达动作归入本页能力。

## 能力定义

| 能力 | SDK 方法 | Portal 请求 | 性质 |
| --- | --- | --- | --- |
| 用户分页 | `sale-sys-user-list` / `saleSysUser.list` | `GET /admin-api/sales/user/page`，额外 `useSystem=6` | 读 |
| 状态/角色选项 | `sale-sys-user-status-options`、`sale-sys-user-role-options` | 状态字典分页；HR角色候选必须带非空关键字，按`name`和受限分页读取 | 读 |
| 公司/机构/销售上级树 | `sale-sys-user-company-tree`、`.organizationTree`、`.salesTree` | `GET /admin-api/sales/organization/tree`，按入口传不同参数 | 读 |
| 详情、店铺和销售部候选 | `sale-sys-user-get`、`.shops`、`.childOrganizations` | 用户详情、`user-tenant-shops`、`user-sales-child-organizations` | 读 |
| 外销商品类型 | `sale-sys-user-item-kind-options` | CRM `GET /vue/sys/dict/listData?type=item_kind` | 读 |
| 内销物料 | `sale-sys-user-domestic-material-codes`、`.domesticMaterialList` | `get-materiels`、`materiel-list` | 读 |
| 用户编辑 | `sale-sys-user-prepare-update` → `sale-sys-user-update` | `PUT /admin-api/sales/user/update` | 写 |
| 角色/店铺/销售部/外销属性 | 各自 `prepare` → `update` 能力 | `PUT /admin-api/sales/user/update`，按动作只发送对应字段 | 写 |
| 内销物料 | `sale-sys-user-prepare-domestic-save` → `sale-sys-user-save-domestic` | `POST /admin-api/sales/domestic-business-setting/save` | 写 |
| 单条启停 | `prepare-stop` → `stop`、`prepare-open` → `open` | `PUT /admin-api/sales/user/update`，状态2/1 | 写 |
| 批量启停 | `prepare-batch-stop` → `batchStop`、`prepare-batch-open` → `batchOpen` | `POST /batch-disable`、`POST /batch-enable`，JSON数组 | 写 |
| 客户移交 | `transfer-target-tree`、`transfer-customer-organizations`、`prepare-transfer` → `transfer` | `undertakeTree`、`user-sales-child-customer-organizations`、`PUT /undertakeUpdate` | 读/写 |
| 导出 | `sale-sys-user-export` / `.export` | `GET /admin-api/sales/user/export`，返回文件对象 | 读文件 |

除 CRM 商品类型字典外，请求均使用 Portal `platform` 实例并带页面推导的 `module-type=60`。按钮权限分别是：编辑 `sys:user:edit`，销售部范围 `sys:user:edit:office`，外销和内销业务 `sys:user:edit:business`，停用/启用 `sys:user:stop`、`sys:user:open`，批量停用/启用 `sys:user:stopBatch`、`sys:user:openBatch`，移交列 `sys:user:transfer`，导出 `sys:user:export`。SDK执行层复刻Portal的状态门禁；动作权限由目录权限、当前会话和后端响应共同决定，不能把“有页面能力”表述成“必然有按钮权限”。

## 参数契约与提交规则

### 列表和导出

Portal表单默认值为：

```text
orgId='', username='', mobile='', realName='', roleId='', salesStatus=1
```

列表请求实际发送：

```text
order='', orderField='', orgId, username, mobile, realName, roleId,
salesStatus, useSystem=6, pageNo=1, pageSize=20
```

分页大小沿用Portal的 `10/20/50/100`。`orgId`来自公司树节点`id`，`roleId`和`salesStatus`使用候选的`value`，不能把展示标签当提交值。每次查询会记录 `searchedValid = String(salesStatus) === '1'`，页面动作显示和准备阶段门禁都以这次实际筛选状态为准。

导出复刻 `rrList.formState`：发送筛选字段和当前 `pageNo/pageSize`，不发送列表 `customLoad`额外加入的 `useSystem`，也不发送公共列表排序字段；SDK使用当前会话请求头，不把Portal浏览器token放进URL。

### 用户编辑表单

Portal详情先请求 `/admin-api/sales/user/detail/{id}`，编辑表单默认包含：

```text
userType='', realName='', username='', organizationId=null, orgPath='',
mobile='', salesOrganizationId='', salesStatus=1, ...detail
```

唯一表单校验是 `salesOrganizationId` 必填，且不能等于详情中的 `salesId`（源码使用宽松相等）。提交事件直接发送整份 reactive `form`，因此SDK的 `prepareUpdate` 保留用户明确提供的整份表单和未知扩展字段，只校验 `id`、`salesOrganizationId` 及自身上级规则；不额外发请求。确认后把同一 `draft` 交给 `update`。

销售上级树请求为空参数，表单的提交值是树节点 `salesId`，不是节点 `id`、名称或路径。编辑按钮需要 `sys:user:edit`；停用筛选下仍可查看详情，但角色、店铺、销售部、业务属性编辑按钮按Portal的状态和权限规则处理。

### 角色、店铺、销售部和业务属性

这些动作都是对同一用户的部分更新，不能把一个弹窗的字段误合并到另一个动作：

```json
{ "id": 10, "roleIds": [3, 4] }
{ "id": 10, "shopIds": [21, 22] }
{ "id": 10, "officeIds": ["S-201", "S-202"] }
{ "id": 10, "businessAttributeMap": { "21": ["item_kind_a"] } }
```

- 角色弹窗先读详情中的 `roles[].id`，候选来自HR角色名称关键字查询（必须提供非空关键字，按页读取）；只在启用筛选且有 `sys:user:edit` 时可编辑。
- 店铺弹窗同时读详情和 `user-tenant-shops`；没有可管辖店铺时Portal直接提示并不提交。提交只发送 `shopIds`，不能把店铺对象数组发给后端。
- 销售部候选来自 `user-sales-child-organizations`；页面把 `name`映射为label、`salesId`映射为value，提交 `officeIds`时仍是销售组织`salesId`数组。编辑需要 `sys:user:edit:office`，查看不写入。
- 外销业务弹窗同时读取CRM `item_kind`、详情和店铺；每个店铺的商品类型值组成 `businessAttributeMap[shopId]`。提交只发送value，不发送label；编辑需要 `sys:user:edit:business`，查看不写入。

以上三个业务弹窗以及角色、店铺编辑准备阶段都要求当前列表筛选为启用状态1；Portal在停用筛选下只允许查看相应内容。

### 客户移交隐藏路由

用户扩展列表在拥有 `sys:user:transfer` 时显示“移交”。点击后，Portal通过桥接保存当前行并进入 `/dashboard/sale/setting/transfer/form`：

1. 用原用户 `id` 调用 `GET /admin-api/sales/organization/user-sales-child-customer-organizations`，可带 `filterName`，返回行的 `organizationId` 是勾选值。
2. 调用 `GET /admin-api/sales/organization/undertakeTree`，固定发送 `isSalesTree=true`；承接树组件只允许选择 `salesType=3` 的销售组，并从所选节点的 `users[0].salesId` 取得承接用户。
3. 至少勾选一个客户组织且选择承接销售组后，`prepareTransfer` 只准备草稿；取消不写入。确认后 `transfer` 只提交：

```json
{ "salesOrganizationId": "承接销售组salesId", "salesId": "承接用户salesId", "organizationList": ["客户组织organizationId"] }
```

`sourceUserId` 只用于写后回查，不会发送给 `undertakeUpdate`。成功、超时或响应丢失后，按原用户重新读取待移交客户组织，不能只凭 `true` 回执宣称客户已完成移交。

### 内销物料

切换内销页时先请求：

```text
GET /admin-api/sales/domestic-business-setting/get-materiels?userId=<用户ID>
GET /admin-api/sales/domestic-business-setting/materiel-list
```

物料列表参数为 `organizationId`、`userId`、`materielName`、`materielCode`、`factoryName`、`materielCategory`、`supplierName`、`shopName`、`pageNo`、`pageSize`，并带公共列表的空 `order/orderField`。`organizationId`来自用户详情，不是销售组织ID。表格以 `materielCode`作为跨页选择键，`selectable=false`的行不可选择。

保存前只取用户确认行的 `materielCode`，按选择顺序用逗号拼接：

```json
{ "userId": 10, "materials": "M-1,M-2" }
```

不能提交物料ID、物料对象或把 `materiels` 响应字段误改成 `materials`数组。内销保存需要当前筛选为启用状态1，并要求 `sys:user:edit:business`对应的业务属性编辑入口可写。

### 启停和批量操作

单条操作固定提交：

```text
停用：PUT /admin-api/sales/user/update，{ id, salesStatus: 2 }
启用：PUT /admin-api/sales/user/update，{ id, salesStatus: 1 }
```

单条停用仅在当前筛选启用且有 `sys:user:stop` 时显示；单条启用仅在当前筛选非启用且有 `sys:user:open` 时显示。批量按钮还要求有勾选行，并固定发送JSON数组本身：

```text
POST /admin-api/sales/user/batch-disable，body=[10,11]
POST /admin-api/sales/user/batch-enable，body=[10,11]
```

SDK在 `prepare` 阶段拒绝空数组、重复ID、非法ID和不匹配的筛选状态；用户取消只丢弃草稿，不发请求。

## 逐字段基准

| 字段 | 来源/含义 | 提交形态 |
| --- | --- | --- |
| `id` | 用户记录主键 | 详情、部分更新、启停；不能用工号或姓名替代 |
| `salesId` | 用户当前销售组织ID | 只用于阻止选择自身为上级 |
| `organizationId` | 人系统所属组织ID | 内销物料筛选的`organizationId`，不换成`salesOrganizationId` |
| `salesOrganizationId` | 编辑表单销售上级选择值 | 来自销售树节点`salesId`，必填且不能等于`salesId` |
| `salesStatus` | 销售用户启停状态 | 查询默认1；停用2；启用1 |
| `roles[].id` / `roleIds[]` | 角色对象/角色ID | 角色保存只发送ID数组 |
| `shopIds[]` | 用户管辖店铺ID | 店铺部分更新字段 |
| `officeIds[]` | 用户销售部范围salesId | 销售部部分更新字段 |
| `businessAttributeMap` | 店铺ID到CRM商品类型value数组 | 外销部分更新字段；不发送label |
| `materiels` | 后端已分配物料编码逗号串 | 读取时拆成`codes`；保存字段为逗号串`materials` |
| `list[].isAssigned` / `selectable` | 同组织占用与当前可选状态 | 只控制物料选择，不作为保存字段 |
| `roleNames`、`orgPath`、`tenantName` | 页面展示文本 | 只读，不用于猜测ID |

## 操作步骤与验证

1. 先读取状态、角色和公司/侧栏机构树，再按当前筛选调用 `list`；需要编辑时从当前行ID调用 `get`。
2. 用户编辑先读 `salesTree`和`organizationTree`，确认 `salesOrganizationId`后调用 `prepareUpdate`；用户取消不写入，确认后将同一草稿交给 `update`。
3. 角色、店铺、销售部、外销和内销弹窗先读取各自详情/候选，分别调用对应 `prepare`；不要跨动作复用或合并提交字段。
4. 单条/批量启停先核对当前筛选状态和权限，再调用 `prepare`，取得明确确认后提交；取消不发请求。
5. 每次写请求成功、超时或响应丢失后，都按用户ID刷新列表/详情；内销保存还要回查 `domesticMaterialCodes`和物料列表；客户移交还要回查原用户的待移交客户组织。不能只凭`true`回执报告已经落库。
6. 导出调用 `export`，保存非空Base64文件；默认文件名为`用户.xlsx`。
