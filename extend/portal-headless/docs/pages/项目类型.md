# 项目类型

页面：`/dashboard/technology/setting/project-type/list`。菜单来自 `app/portal/menus/technology.js` 的“科技管理 → 设置 → 项目类型”，权限 `/dashboard/technology/setting/project-type`。

本页不是财务项目的“项目类型”字典，也不是科技项目实例或类型模板映射。审计报告从页面文字提取出的“启用”是状态标签，不是独立按钮；固定前端页面没有独立启停、详情、导入导出、打印、上传下载或子页面。

## 参数契约

### 查询

- `pageNo` 默认 1，须为正整数；`pageSize` 默认 20，须为 1 至 500 的整数，不接受 `-1` 全量。
- `code`、`name` 省略时发送 `null`。固定前端没有说明精确还是模糊匹配，按后端真实结果解释，不编造。
- `projectDomain` 可省略或为 `null`；已知值仅 `biology`（生物）、`information`（信息）、`engineering`（工程）。
- 本页自建 `query`，不是 renren `useListPageModule` 表单；不得擅自添加 `order` / `orderField`。

### 新增/编辑

- `typeCode`、`typeName` 必填且不得全为空格。固定前端没有长度/格式上限，SDK不增加未证实限制。
- `codeAbbreviation` 可省略或为 `null`；非空时为 1 至 12 位小写字母数字并以小写字母开头。空字符串沿页面原值提交。
- `roleCodes` 至少一项、不重复；新选择来自 `project_owner`（项目负责人）、`project_member`（项目成员）、`evaluation_recorder`（评价登记人）、`promotion_owner`（推广负责人）。新增省略时与PC默认一致，选择全部四项。
- `projectDomain` 新增时必选上述三类之一。编辑弹窗禁用该字段，更新只从 `current` 保留，不接受 `changes.projectDomain`。
- `status` 数值 0=启用、1=停用，新增默认 0。它随表单保存，不是独立启停接口。
- `sort` 是非负有限数或 `null`，新增默认 0。PC只设置 `min=0`，没有整数精度约束，所以SDK不擅自拒绝小数。
- `remark` 为字符串或 `null`，新增省略发送空字符串。
- 编辑弹窗直接使用列表行，没有详情请求。`current` 必须来自最新 `list[]` 或前一准备结果；`changes` 只允许缩写、角色、名称、状态、排序、备注。类型编码和项目大类保持不变。
- `id` 是列表记录主键，不是 `typeCode`；数值须为安全正整数，长ID保留无前导零的十进制字符串。

## 逐字段请求与返回

以下成功请求形态来自前端固定源码推导。浏览器仅实际观测到分页 GET 路径及“HTTP 200、业务包络报资源不存在”的失败，未取得成功请求的完整查询序列、上下文头或响应体：

| 动作 | HTTP | 参数/请求体 |
|---|---|---|
| 查询 | GET `/admin-api/technology/setting/project-type/page` | query 按 `pageNo,pageSize,code,name,projectDomain` 顺序 |
| 新增 | POST `/admin-api/technology/setting/project-type/create` | JSON `id:null,typeCode,codeAbbreviation,roleCodes,typeName,projectDomain,status,sort,remark` |
| 编辑 | PUT `/admin-api/technology/setting/project-type/update` | JSON `id,typeCode,codeAbbreviation,roleCodes,typeName,projectDomain,status,sort,remark` |
| 删除 | DELETE `/admin-api/technology/setting/project-type/delete` | query `{id}`，不是请求体 |

`prepareCreate` 与 `prepareUpdate` 不发网络。create/update/remove 显式丢弃后端成功业务值，最终返回根 `undefined`；不伪造新建ID、布尔结果或删除条数。

列表最终返回 `{list,total}`，只投影页面显示和编辑需要的字段：

| 字段 | 语义 |
|---|---|
| `list` / `list[]` | 当前页数组 / 一条项目类型，不是全部记录 |
| `list[].id` | 记录主键，供编辑、删除；不是类型编码 |
| `list[].typeCode` | 类型编码，编辑禁用 |
| `list[].codeAbbreviation` | 编号缩写；缺失为 `null` |
| `list[].roleCodes` | 适用角色编码数组；后端缺失时按PC弹窗逻辑补全部四项 |
| `list[].typeName` | 类型名称 |
| `list[].projectDomain` | 项目大类编码；三项已知值映射中文，未知值按页面原文显示 |
| `list[].status` | 页面仅数值0显示启用，其余显示停用；写入只接受0/1 |
| `list[].sort` | 排序原值；`null` 不等于0 |
| `list[].remark` | 备注，只在编辑弹窗消费；可 `null` |
| `list[].updateTime` | 更新时间原文；可 `null`，未证实时区/格式，不做转换 |
| `total` | 相同筛选条件下总记录数，不是当前页长度 |

后端额外审计字段不属于页面消费契约。`list=[]` 只表示当前页为空；`total=0` 才表示当前筛选无记录。

## 操作步骤与清理

1. 查询：`list(query)`；需要完整结果时保持筛选条件递增页码，累计达到 `total` 或遇空页后停止。
2. 新增：`prepareCreate` → `create(prepared.draft)` → 用原 `typeCode + typeName` 调 `list`，逐页找到唯一精确匹配行并核对大类、角色、状态、排序、缩写和备注。create 返回 `undefined`，不能直接得到新ID。
3. 撤销本次新增：只有在回查唯一识别本次记录后，使用该行 `id` 删除，再按原编码和名称回查原ID不再出现。0条或多条候选时停止，不能删除同名其他记录。
4. 编辑：保留最新列表行 → `prepareUpdate({current,changes})` → `update({current:prepared.draft})` → 按编码和目标名称列表回查同一ID与目标字段。
5. 恢复本次编辑：确认没有需保留的并发修改后，再次调用 update，将 `prepared.previous` 的六个可编辑字段写回；这是再次写入，不是服务端事务回滚。恢复后再次列表核对。
6. 删除：调用前保留所选行 `id/typeCode/typeName` → `remove(id)` → 用编码和名称逐页回查原ID不再出现。页面没有恢复接口；DELETE超时先回查，不自动重删。

本组写能力没有SDK或后端幂等键，不接受 `requestId`。重复create可能造成重复记录或业务错误；写超时一律先查询。401/403、HTTP错误、网络和后端业务包络失败原样抛出，不能当空列表或成功。测试环境已经出现传输层HTTP 200但业务报资源不存在，不能拿HTTP成功冒充功能成功，也不得改猜其他URL。
