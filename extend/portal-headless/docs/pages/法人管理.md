## 能力与 AI 说明

| 能力 ID | SDK 方法（单个对象参数） | 行为 |
|---|---|---|
| `hr-org-corporation-list` | `orgCorporation.list(query?)` | 分页查询法人及两个文本筛选 |
| `hr-org-corporation-get` | `orgCorporation.get({id})` | 读取编辑详情，并将 `mainInvestIds` 归一为数组 |
| `hr-org-corporation-main-invest-options` | `orgCorporation.mainInvestOptions({keyword})` | 按关键字读取可用法人候选，返回 `id/name` |
| `hr-org-corporation-create` | `orgCorporation.create({name,mainInvestIds?,remark?})` | 只提交页面创建字段，无业务返回值 |
| `hr-org-corporation-update` | `orgCorporation.update({id,name,mainInvestIds?,remark?,...detail})` | 复刻编辑页详情展开、旧字段删除和 save 请求体 |
| `hr-org-corporation-prepare-remove` | `orgCorporation.prepareRemove({ids})` | 去重 ID、读取敏感配置，不执行删除 |
| `hr-org-corporation-send-delete-code` | `orgCorporation.sendDeleteCode({ids})` | 按需向配置手机号发送验证码 |
| `hr-org-corporation-remove` | `orgCorporation.remove({ids,smsRequestId?,code?})` | 按需校验短信后批量逻辑删除 |

能力实现和同文件 AI 契约：`src/capabilities/org-corporation.ts`，测试：`test/org-corporation.test.ts`。契约已接入共享能力目录、单用户/多用户门面、invoke 和 `catalog.describe(id)` / `-llm` / `describeMethod(path)`；共享目录返回的就是本页字段、动作映射和验证边界。

候选是长选项。虽然 Portal 组件为了本地搜索会全量拉取可用法人，SDK 遵循 `docs/conventions.md` 的无头调用约束，要求非空 `keyword` 并把它作为同一接口的 `name` 参数；因此不宣称一次调用已经取得全部候选。

## 参数与返回契约

- 列表默认逐字段发送 `{order:'',orderField:'',name:'',mainInvest:'',pageNo:1,pageSize:20}`。`name` 是法人名称筛选，`mainInvest` 是投资主体法人名称筛选；两者按页面原值发送。页码和每页数必须为正整数。
- 列表返回 `{list,total}`。`list` 是当前页，`total` 是后端当前查询范围的总数；页面展示 `id/name/mainInvestNames/mainInvestName/remark/useNumber`。`mainInvestNames` 为空时页面回退 `mainInvestName`，备注为空时显示横杠。
- 法人 ID 是法人库主键，不是组织 ID。删除即使只有一条也发送数组；SDK 去重但保留每个首个 ID 的原始字符串/数字表示。
- 创建严格投影 `{name,mainInvestIds,remark}`。`name` 必填、不得全为空格、最多 50 个字符；保留用户首尾空格。`remark` 最多 200 个字符，可为空字符串，不允许非空且全为空格。`mainInvestIds` 不是数组时按页面规则归一为 `[]`；数组元素必须是正整数法人库 ID，不能传名称或组织 ID。
- 编辑页先 GET 详情。Portal 的 `customLoad` 把缺失的 `mainInvestIds` 变成 `[]`；`customSubmit` 展开详情对象，删除 `mainInvest`、`mainInvestName`、`mainInvestNames`，再确保 `mainInvestIds` 为数组后 POST save。SDK 保留详情中的其他服务端字段，以复刻该请求体；创建不会保留这些字段。
- 后端保存会验证目标法人属于当前租户、名称不重复，以及每个投资主体 ID 属于当前租户、未删除且可用；明确传空数组会清空既有投资主体关系。
- `get` 返回详情 DTO（同时保留 `superOrganizationId/superOrganizationName/status/isDel/creator/createTime/updater/updateTime/tenantId` 等服务端字段），SDK 只对 `mainInvestIds` 做数组归一。
- `mainInvestOptions` 只返回投影后的 `{id,name}[]`；空结果是 `[]`，请求失败不解释为空。候选 ID 必须回填 `mainInvestIds`。
- create、update、remove 成功均为 `undefined`，不伪造新 ID、修改后对象或删除数量。写入完成或超时必须按契约回查。
- `prepareRemove` 返回 `{ids,verificationRequired,phone}`。只在敏感配置为空，或 `isDel` 严格等于数值 `1` 时免短信；准备阶段不锁定引用关系。
- 需要短信时，`sendDeleteCode` 返回 `{smsRequestId}`；它是服务端短信记录标识，不是幂等键。验证码只能由收件人提供，不猜测、不写日志。没有 SDK/后端幂等包装，短信或写入超时不自动重发。

## 请求逐字段依据

| 操作 | HTTP | 请求 |
|---|---|---|
| 列表 | `GET /org/corporation/page` | `params: order,orderField,name,mainInvest,pageNo,pageSize` |
| 详情 | `GET /org/corporation/{id}` | 路径法人库 ID；详情缺失的 `mainInvestIds` 归一为 `[]` |
| 投资主体候选 | `GET /org/corporation/getAllLegalPerson` | Portal 组件无参数；SDK 为长候选安全边界发送 `params: {name: keyword}` |
| 创建 | `POST /org/corporation/save` | JSON `{name,mainInvestIds,remark}` |
| 编辑 | `POST /org/corporation/save` | 详情展开后删除三个 legacy 字段，补齐 `id/name/mainInvestIds/remark` |
| 敏感配置 | `GET /org/sensitive/info` | 无业务参数；读取 `mobile/isDel` |
| 发送验证码 | `GET /sys/sms/send` | `params: {phone: mobile, templateId:'17709'}` |
| 验证验证码 | `GET /sys/sms/checkSms` | `params: {requestId: smsRequestId, code: 用户验证码}`；失败不发 DELETE |
| 删除 | `DELETE /org/corporation` | JSON 去重后的法人库 ID 数组；页面没有调用 `checkCanDelete` |

所有请求通过 platform 页面上下文，由共享请求层注入当前用户、租户、语言和推导出的 `module-type=11`，并统一拆标准响应包络。后端删除会在事务中阻止已被组织/标准化单元/其他投资主体使用的法人，不能用前端 `useNumber` 计数替代它。

## 操作流程与验证

1. 查询：`list` → 按用户输入传 `name/mainInvest` → 逐页读取并保留目标行的法人库 `id`。
2. 创建：校验页面字段 → `create` → 创建前后完整分页，按 ID 差异并精确核对名称、备注和投资主体关系；取消创建页且未提交时没有业务副作用。
3. 编辑：`get({id})` → 用户修改 `name/mainInvestIds/remark` → `update` → `get({id})` 核对三项最终值。
4. 删除：只从最新列表选择 `useNumber===0` 行 → `prepareRemove` → 若需要且用户确认，`sendDeleteCode` → 用户提供 code → `remove` → 完整分页确认目标 ID 已不存在。准备或短信弹窗阶段可取消；删除成功后没有恢复接口。
5. 选投资主体：`mainInvestOptions({keyword})` → 用户选择候选 `id/name` → 将 ID 数组填入创建或编辑的 `mainInvestIds`，不能把名称提交给 save。

离线验证已完成：`pnpm typecheck`；`pnpm build`；`pnpm exec vitest run test/org-corporation.test.ts`（14 例）；测试同时读取固定 Portal/Java 源码，覆盖列表默认值与筛选、详情、候选、创建/编辑请求体、字段校验、权限/禁选静态规则、敏感配置分支、短信顺序、失败阻断和 AI 契约结构验证。

反证已执行并恢复：把编辑请求体中删除 legacy 字段的任一语句改坏，编辑请求体断言会红；把 `checkSms` 后继续 DELETE 的语义改坏，验证码失败阻断断言会红；把短信步骤 `smsRequestId` 的来源改为错误字段，AI 映射断言会红。恢复后目标测试重新通过。
