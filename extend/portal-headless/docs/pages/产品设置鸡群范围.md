# 产品设置鸡群范围

页面路径：`/dashboard/product/setting/base-setting/user-dict/list`。

## 页面能力定义

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询类型候选 | `product-setting-user-dict-type-list` / `productSettingUserDict.typeList` | `GET /sys/dict/userDictTypeList` |
| 查询列表 | `product-setting-user-dict-list` / `productSettingUserDict.list` | `GET /sys/dict/userDictPage` |
| 启用 | `product-setting-user-dict-enable` / `productSettingUserDict.enable` | `GET /sys/dict/enable` |
| 停用 | `product-setting-user-dict-deactivate` / `productSettingUserDict.deactivate` | `GET /sys/dict/deactivate` |

请求使用 `product` HTTP 实例，不发送 `module-type`。菜单权限为 `/dashboard/frame/base-setting/user-dict`；页面查询权限为 `management:user-dict:query`，启用和停用受 `management:user-dict:submit` 控制。

## 参数契约与提交规则

页面挂载时先读取类型候选，再读取列表。类型接口的后端结果是 `typeList`，Portal 映射为最终下拉候选：`description → label`、`type → value`。列表是 `useListPageModule` 的 `customLoad`，默认请求参数为：

```json
{
  "order": "",
  "orderField": "",
  "type": "",
  "pageNo": 1,
  "pageSize": 20
}
```

分页大小遵循页面支持的 `10/20/50/100`。Java 返回 `page` 包络，Portal `customLoad` 消费 `list`、`records` 或 `rows`及 `total`、`count`；SDK统一返回 `{ list, total }`，并保留状态动作所需的行 ID。

状态动作严格按当前列表行 ID发送：

```json
{ "dictId": "当前列表行的id" }
```

Portal 当前行 `status === 1` 时调用 `GET /sys/dict/deactivate`，否则调用 `GET /sys/dict/enable`。SDK将两个端点暴露为两个明确方法，不替调用方隐式反转状态。停用可能被 Java 业务规则拒绝：至少保留一项，且已被鸡群或孵化数据使用的选项不能停用。

页面源码还保留 `modal-form-content.vue` 和 `POST /sys/dict/userDictSave` 的表单代码，表单字段为 `id/type/description/label/value`，其中 `type/label/value` 必填；但新建按钮已被注释，列表没有编辑入口，当前 Java `DictController` 也没有 `userDictSave` 映射。因此该表单不可达，SDK不注册保存能力，也不把这段死代码当作可用提交规则。

## 逐字段基准

类型候选：

| 字段 | 含义 |
| --- | --- |
| `value` | 字典类型值；传给 `list({ type })`。 |
| `label` | 页面下拉展示文本；由后端 `description` 映射。 |

列表行：

| 字段 | 含义 |
| --- | --- |
| `id` | 字典数据 ID；启用、停用的 `dictId` 来源。也兼容 Portal 代码读取的 `dictId`/`dictID`。 |
| `value` | 品种或代次等字典值。 |
| `label` | 页面展示名称。 |
| `description` | 字典类型展示名称。 |
| `type` | 字典类型值，与类型候选的 `value` 对应。 |
| `status` | `1` 启用、`0` 停用。 |
| `statusStr` | Java 生成的状态展示文本。 |
| `total` | 当前类型筛选条件下的总记录数。 |

## 操作步骤、权限和证据边界

1. 调用 `typeList()`，用候选 `value` 构造用户的类型选择。
2. 调用 `list({ type, pageNo, pageSize })`，从最新列表行取得非空 `id` 和 `status`。
3. 用户明确确认后，按目标状态调用 `enable({ dictId })` 或 `deactivate({ dictId })`。
4. 请求成功或超时都重新 `list()`，按同一 `dictId` 回查 `status`；不能只把 `true` 回执当作已落库。

本轮逐页核对了 Portal 菜单、列表、遗留表单、页面权限、Java `DictController`/`DictVO`/`HRDict`/Mapper/Service、SDK 请求和离线反证测试。尚未在真实测试环境使用浏览器会话执行类型读取、列表读取和启停回查；离线测试不替代真实环境证据。
