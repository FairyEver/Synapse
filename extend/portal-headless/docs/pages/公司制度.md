## Portal 页面行为

列表调用 `GET /admin-api/system/policy/tree`，只提交名称筛选及列表基础的空排序字段，不提交 `pageNo/pageSize`；Portal 对返回树的叶子节点移除 `children`。文件夹和制度共用删除接口，制度节点另有下载、学习人员和共享入口。

文件夹表单读取 `GET /admin-api/system/policy/get?id=...`，新建调用 `POST /admin-api/system/policy/create-file`，编辑调用 `PUT /admin-api/system/policy/update`；根目录的 `pid` 提交为 `0`，角色授权随 `roleIds` 提交，`type` 固定为 `1`。

制度表单的制度类型来自 `GET /admin-api/system/policy-category/simple-list`。创建调用 `POST /admin-api/system/policy/create`，把每个上传文件转换为 `{ name, fileUrl, type: 2, directoryList }`；编辑仍调用 `PUT /admin-api/system/policy/update`，只发送 Portal `pick` 的字段。目录和章节按数组顺序重新生成 `第X章`、`第X节`。

“学习人员”调用 `GET /admin-api/system/policy/getStudent`，发送 `name/mobile/isRead/pageNo/pageSize/policyId` 和空排序字段。无权限内容读取固定字典 ID `1225814271879340854`，保存到 `/sys/dict/data` 并覆盖 `updateDate`。共享 type 固定为 `1`，读取和保存使用 `/admin-api/system/share-user/getShare`、`/admin-api/system/share-user/createShare`；保存成员只提交 `{ id }`。

## 表单与权限规则

- 文件夹名称必填、最多 50 个字符；根目录提交 `pid=0`，`roleIds` 必须是已核实的角色 ID 数组。
- 制度必须有制度类型 `category`、关联组织 `organizationId` 和至少 1 个、最多 10 个已上传文件；只接受 Portal 的 doc、docx、pdf MIME 类型，提交使用 OSS URL，不把本地路径当 `fileUrl`。
- 制度目录/章节的已有内容必填且最多 50 个字符；编辑时保留 `fileUrl`，只提交 `id/name/fileUrl/pid/type/category/organizationId/directoryList`。
- 制度删除、文件夹递归删除、角色授权、共享、学习人员和列表结果均受当前会话、租户、页面权限以及后端资源数据范围约束。SDK 不把空数组或 `true` 回执当作业务回查证据。
- “无权限内容”文本框由 Portal 限制最多 200 个字符；SDK 保留字典对象字段并按 Portal 时间格式更新 `updateDate`。

## 后端与 SDK 对齐

Java `HrPolicyController` 提供树、详情、上级文件夹候选、制度创建、文件夹创建、更新、删除和学习人员分页；`HrPolicyCategoryController` 提供制度类型候选；`HrPolicyServiceImpl` 负责租户、创建人、资源/角色授权、名称重复、文件夹递归删除和目录章节重建。`HrShareUserController` 的共享接口明确 type `1=制度`。

实现文件：`src/capabilities/company-policy.ts`；AI 说明：`src/catalog/contracts-company-policy.ts`。SDK 将文件夹和制度写操作拆为 `prepare → submit`，取消只丢弃本地草稿；写入成功或超时后按 ID、父目录+文件名、固定字典 ID 或共享资源 ID 回查。下载把 Portal 的 `http` URL 提升为 `https` 并返回非空文件字节。
