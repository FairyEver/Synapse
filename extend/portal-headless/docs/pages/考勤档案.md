## 真实请求序列（打开页面时）

基准文件：`baseline/attendance-archive-sheet.browser.json`

| # | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 1 | GET | `/admin-api/org/hrAttendanceSheet/page?order=&orderField=&isArchived=1&pageNo=1&pageSize=20&_t=…` | 列表页挂载时 `rrList.logicFetch()` |
| 2 | GET | `/admin-api/org/organization/getAllOrganizationByType?type=1&_t=…` | 部门选框的候选 |
| 3 | GET | `/admin-api/org/organization/getAllOrganizationByType?type=2&_t=…` | 班组选框的候选 |

### 三个必须记住的点

1. **`isArchived=1` 不是筛选条件，是"这一页是哪一页"的定义。**
   考勤表页 `/dashboard/attendance/attendance-sheet/list` 打的是**同一个接口**，
   发出的 query 是 `order=&orderField=&pageNo=1&pageSize=20` —— 与本页只差 `isArchived`。
   所以这个参数**没有**进参数契约：开放出去，调用方就能在"查考勤档案"这个能力上
   静默拿到未归档考勤表的数据，接口、字段、分页全都一样，不会有任何报错。

2. **两个选框的候选是全量拉取的，班组实测 922 条。**
   `portal-hxr-select-user-department/index.vue` 在挂载时把该 type 的组织**整表**拉下来塞进 `a-select`。
   这在浏览器里是"能用但慢"，无头下不可接受（设计 D6 / H35）。所以 SDK 的
   `searchOrganizations()` **强制要关键字**，在本地按名称过滤后限量返回（默认 20、上限 50）。

3. **`module-type` 这个头在浏览器里读的是 cookie，不是当前页的 URL。**
   前端 `getCurrentModuleType()` 取的是 `getCurrentMenuPath()`，而它是
   `cookie.get('hr-0.0.0-menuPath')` —— 路由守卫 `syncMenuContext(to.path)` 在每次导航时写入。
   cookie 是**同一个浏览器 profile 全局共享**的，不分标签页。实测症状：本页 URL 一个字没变，
   只要同一浏览器里有另一个标签页跳到 `/dashboard/assignment/assignment/list`，
   本页再发请求时 `module-type` 就从 **11 变成 12**（学习管理，那条规则匹配 `/dashboard/assignment/`）。
   SDK 侧不受影响（`resolveModuleType(页面路径)` 是确定性的），但**抓基准时这条要注意**：
   基准里的 `module-type` 要拿规则表复核，不能直接当答案抄。

## 参数契约

| 参数 | kind | 必填 | 说明 |
| --- | --- | --- | --- |
| `yearMonth` | date | 否 | 必须是 `YYYY-MM`。格式由页面选择器决定，传错**后端不报错、只是查不到**，所以本地挡（`assertYearMonth`） |
| `departmentId` | search | 否 | 长选项。`lookup` → `attendance-org-search`（`keyword`），页面实测全量 17 条 |
| `organizationId` | search | 否 | 长选项。同上，全量 922 条，**必须先问用户关键字** |
| `pageNo` / `pageSize` | number | 否 | 默认 1 / 20 |

请求参数的**顺序是契约的一部分**（D20 逐字段一致）：
`order, orderField, isArchived, yearMonth, departmentId, organizationId, pageNo, pageSize, _t`。
表单初值为 `null` 的三项由 qs 的 `skipNulls` 丢掉——浏览器也不发。
实现按固定表拼参数（`buildListParams`），调用方实参的书写顺序不影响结果。

候选来源 `attendance-org-search`：`keyword`（必填）+ `type`（1=部门 / 2=班组，必填）+ `limit`（默认 20，上限 50）。
过滤在本地做，因为这个接口只有 `type` 一个入参（实测请求就是 `?type=1`），服务端不支持按名搜。

## 真实验证记录（2026-09-20，测试环境）

`smoke/with-portal-token.sh node smoke/read-attendance-archive-sheet.mjs`：

```text
module-type：11 组织管理

① 列表（无筛选）：共 105 条，本页 5 条
   GET /admin-api/org/hrAttendanceSheet/page?order=&orderField=&isArchived=1&pageNo=1&pageSize=5&_t=<ts>
   #153 沃德博创 / 数据中心 / 2026-1 / 5 人
② 列表（yearMonth=2026-08）：共 0 条
   GET /admin-api/org/hrAttendanceSheet/page?order=&orderField=&isArchived=1&yearMonth=2026-08&pageNo=1&pageSize=1&_t=<ts>
③ 部门（type=1）：全量 17 条，名称含「办公室」的 2 条
③ 班组（type=2）：全量 922 条，名称含「办公室」的 3 条
④ 无关键字被拒（未发请求：true）
```

三条结论：

- 列表请求的 URL 形状被后端接受，且与浏览器基准逐字段一致（含参数顺序与不发 `null` 项）
- `yearMonth=YYYY-MM` 这个格式后端认（2026-08 查询成功返回，只是那个月确实没有归档数据）
- 长选项的规模是测出来的，不是估的：部门 17、班组 922

## 尚未覆盖

- **「取消归档」是写，本页没有做**。它的实现在页面里是
  `http.get('/org/hrAttendanceSheet/unArchiveSheet', { params: { id } })` ——
  **用 GET 改数据**（后端 `HrAttendanceSheetController.unArchiveSheet` 同样是 `@GetMapping`），
  而且行上有二次确认（"确定要取消归档吗？"）。没有实际执行过，也没有写进能力定义。
  注意 `page-catalog.json` 给这一页标的 `write: false` 是**错的**：清单的判定规则是
  `tools/generate/generate.mjs:229` 的 `/http\s*\.\s*(post|put|delete)\s*\(/`，这个写操作走的是 `get`，扫不到。
- **「预览」跳转后的页面**（`../attendance-sheet/detail/:id/item`）没看，它把整行记录塞进
  `bridgeSet()` 的 query 里，是另一条链路。
- **部门 / 班组是否会互相约束**：模板上看两个选框互不联动（没有 `@change`），
  但没有逐个组合试过；后端 `HrAttendanceSheetSelectDTO` 也只是两个平级字段。
- **`yearMonth` 传非法格式时后端的确切行为**只从代码推断（DTO 是 `String`，不校验），
  没有故意打过一次。

## SDK AI 说明契约（2026-09-22）

本节由当前 SDK 描述结果整理；说明权威来源为 `src/catalog/contracts-business.ts`。调用 `catalog.describe(id)`（或 `id-llm`）可得到参数来源、返回字段/状态、数据消费与后续映射；`catalog.describePage(页面路径)` 用于选择页面功能。以下更新以本节为准；前文历史请求/实测记录仍保留其记录日期。

### `attendance-archive-sheet-list`

查已归档考勤表；固定 isArchived=1，按月份/部门/班组筛选历史归档记录。

- 执行：`sdk.attendanceArchive.list`；通过 `capabilities.invoke('attendance-archive-sheet-list', args)` 调用时按 `params` 填参。性质：read。
- 参数：`yearMonth` 可选 (string)；`departmentId` 可选 (string)；`organizationId` 可选 (string)；`pageNo` 可选 (number)；`pageSize` 可选 (number)。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`{ list: object[], total: number }`。list=[] 为当前页无记录；total=0 表示该筛选无结果。保留筛选条件检查页码，不将空结果解释成权限判定。
- 字段：`list`、`total`、`list[].id`、`list[].departmentName`、`list[].organizationName`、`list[].year`、`list[].month`、`list[].userCount`、`list[].updateName`、`list[].updateTime`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：展示 departmentName、organizationName、year-month、userCount；归档记录不代表实时考勤。
- 完成条件：按用户要求交付本次筛选范围的结果；需要完整清单时继续翻页至覆盖 total，不能把当前页当全集。
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。


### `attendance-org-search`

按名称关键字查考勤部门(type=1)或班组(type=2)候选，供考勤表筛选使用。

- 执行：`sdk.attendanceArchive.searchOrganizations`；通过 `capabilities.invoke('attendance-org-search', args)` 调用时按 `params` 填参。性质：read。
- 参数：`keyword` 必填 (string)；`type` 必填 (string | number)；`limit` 可选 (number)。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`object`。可选字段缺省或 null 时展示为空，不当作数值 0。
- 字段：`list`、`list[].id`、`list[].name`、`total`、`matched`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：展示 list[].name，用同条 id 填筛选；matched 超出返回条数时请收窄关键字。total 不可作为搜索结果数。
- 完成条件：按上述数据消费规则交付查询结果；本能力的读取到此结束。
- 后续：optional → `attendance-archive-sheet-list`：type=1 候选只填 departmentId；type=2 候选只填 organizationId；不要把同一 id 同时填两个字段（departmentId ← list[].id；organizationId ← list[].id）；optional → `attendance-statistics-list`：type=1 候选只填 departmentId；type=2 候选只填 organizationId；不要把同一 id 同时填两个字段（departmentId ← list[].id；organizationId ← list[].id）
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。
