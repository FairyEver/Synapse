## 请求规则

列表默认请求参数为：

```text
name=&isUsed=&orgId=&archiveStatus=2&pageNo=1&pageSize=20
costDateStart=&costDateEnd=&order=desc&orderField=id
```

Portal 的月份范围选择器返回 `YYYY-MM` 字符串，SDK 按页面的 `convertFetchForm` 转换为 `costDateStart` 和 `costDateEnd`；未选择月份发送两个空字符串。`isUsed` 使用 `0=未使用`、`1=已使用`，未选择时保留页面原始空字符串。`orgId` 是角色组织树节点 ID，Java 服务会展开该组织的下级组织，并叠加当前用户的数据权限；SDK 不接受组织名称替代 ID，也不把它扩展成用户全部组织。

列表响应是 `{ list, total }`。`list` 只代表当前页，`total` 只用于分页。每行保留个税主记录 ID、员工、身份证号、组织全路径、岗位、归属月份、归档状态、工资单据使用状态、操作人、创建时间和 `specialList`；专项明细保留类型、金额、费用日期、归档状态及审计字段。金额和空值按后端原值保留，Portal 展示的子女教育等列只是从 `specialList[].specialType` 取值。

## 写入与导出规则

取消归档必须先执行：

```text
prepareUnarchive({ ids }) → 用户确认 → unarchive({ ids }) → 用原筛选 list 回查
```

提交体固定为 `{ ids: [...], status: 1 }`。后端按专项明细执行实际处理和资格检查，返回 `processedIds`、`processedStaffCodes`、`processedCount`、`eligibleStaffIds`、`eligibleStaffCodes` 和 `excludedStaffList`。`processedCount` 不是请求 ID 数量；存在排除项时必须展示原因并按回查结果判断最终状态。取消确认只丢弃本地草稿，不发送请求。

导出严格复现 Portal 的 `selectState.join(',')`：SDK 将选中的个税主记录 ID 按顺序连接为 `idList`，不把当前筛选条件或分页偷偷改成导出条件；返回非空二进制文件的文件名、Content-Type、Base64 和字节数。页面未选中时仍发送空字符串，后端可能拒绝，不能把它描述成“导出全部”。

## 权限与边界

- 所有请求使用 `platform` axios 实例，并由 SDK 会话注入 `module-type=14`；权限码固定为 `/dashboard/salary/person-tax-file`。
- 列表的 `orgId` 只是在 Portal 已有数据权限之上增加组织筛选，不能扩大可见范围。
- `idCard` 是敏感字段，调用方应按原值消费并避免写入日志。
- 空列表表示当前筛选没有记录，不表示用户没有权限；空资格回执表示本次没有实际处理记录，不表示请求失败。
