## 能力与 AI 说明

| 能力 ID | SDK 方法（单个对象参数） | 行为 |
|---|---|---|
| hr-organization-type-list | hrOrganizationType.list(query?) | 分页读取；发送 name，但当前服务端不筛选 |
| hr-organization-type-create | hrOrganizationType.create({name,remark?}) | 创建；成功无返回 ID |
| hr-organization-type-prepare-remove | hrOrganizationType.prepareRemove({ids}) | 读取敏感配置，只读 |
| hr-organization-type-send-delete-code | hrOrganizationType.sendDeleteCode({ids}) | 按需向配置手机号发送验证码 |
| hr-organization-type-remove | hrOrganizationType.remove({ids,smsRequestId?,code?}) | 按需验证后批量逻辑删除 |

定义和执行：`src/capabilities/hr-organization-type.ts`。AI 契约：`src/catalog/contracts-hr-organization-type.ts`，导出 `HR_ORGANIZATION_TYPE_AI_CONTRACTS` 与 `HR_ORGANIZATION_TYPE_METHOD_CONTRACTS`。共享目录、单用户/多用户门面、invoke 和描述注册由主代理接线；只有接线后 `catalog.describe(id)`、`-llm`、`describeMethod(path)` 实际返回才算下发给 AI。

`hr-organization-type-create` 的能力定义显式声明 `moduleType: null`。这是浏览器基准覆盖页面默认推导的特例：能力仍属于组织类型列表页，但保存请求不能因 pagePath 自动补 `module-type=11`。其余四项沿用页面推导值 11。

## 参数与最终返回

- 列表默认发送 `{order:'',orderField:'',name:'',pageNo:1,pageSize:20}`。页码与每页数必须为正整数。
- `name` 是页面可见查询字段，但当前测试部署和固定后端 SQL 均未应用它。调用方必须完整分页后本地匹配；`total` 是未删除记录总数，不是名称命中数。
- 列表返回 `{list,total}`。页面显示 `name/remark`；`id` 用于删除；`useNumber` 是关联组织计数，只有严格为数值 0 的行可选。额外审计字段不属于页面消费契约。
- 名称必填、不全为空格、最多 50 字符；备注最多 200 字符，可空串，不允许非空且全为空格。SDK 保留用户输入的首尾空格并只投影 `name/remark`。
- 创建成功为根 `undefined`，没有新 ID。通过创建前后完整分页 ID 集合差异，再精确核对名称/备注识别新记录；多个候选时不能猜。
- 删除输入 `ids` 为组织类型主键数组，即使一条也传数组；不得传组织 ID 或名称。SDK 校验正整数形式并去重。
- `prepareRemove` 返回 `{ids:string[],verificationRequired:boolean,phone:string|null}`，只读取配置，不检查或锁定组织关联。ID 必须来自最新列表且 `useNumber=0`；后端 DELETE 会再次以真实关联阻止占用记录。
- `sendDeleteCode` 返回 `{smsRequestId:string}`，这是短信发送记录，不是幂等键。验证码只由真人提供，不猜测、不写日志。
- `remove` 成功为根 `undefined`，没有删除条数。任一 ID 被使用时后端拒绝整批，不是部分成功；成功后完整分页确认所有 ID 消失。
- 所有写动作均无 SDK/后端幂等键。创建/删除超时先回查；短信超时先等真人收件，不自动重发。

## 请求逐字段基准

| 操作 | HTTP | 请求上下文与字段 |
|---|---|---|
| 列表 | GET `/org/organizationType/page` | pageRequest；module-type 11；params order/orderField/name/pageNo/pageSize |
| 创建 | POST `/org/organizationType/save` | formRequest；明确不发 module-type；JSON name/remark |
| 敏感配置 | GET `/org/sensitive/info` | pageRequest；module-type 11；无业务参数 |
| 发送验证码 | GET `/sys/sms/send` | pageRequest；params phone=配置 mobile、templateId='17709'；真实短信分支未抓基准 |
| 验证验证码 | GET `/sys/sms/checkSms` | pageRequest；params requestId=发送记录、code=真人验证码；真实短信分支未抓基准 |
| 批量删除 | DELETE `/org/organizationType` | pageRequest；module-type 11；JSON 去重后的 ID 字符串数组 |

platform 客户端统一补 `/admin-api`、注入租户/会话/language 头并拆标准响应包络。创建请求与列表页请求必须来自同一用户、同一租户，但 module-type 行为不同。

## 操作流程、验证与反证

创建：记录创建前完整分页 ID 集合 → create → 再完整分页 → 取新增 ID 并精确核对 name/remark。取消创建页且尚未提交时只返回上一页，无业务副作用；提交后要撤销只能按删除保护链处理，且被组织使用时不能删除。

删除：list → 只选择 `useNumber=0` 行 → prepareRemove → 如需验证且用户继续，sendDeleteCode → 真人提供 code → remove → 完整分页按 ID 确认消失。prepare 或短信弹窗阶段可停止；DELETE 成功后没有恢复动作。

离线验证命令：`pnpm exec vitest run test/hr-organization-type.test.ts`。覆盖列表默认参数、失效筛选说明、创建字段投影及独立 formRequest、表单保护、敏感配置分支、短信顺序、批量删除、前置失败阻断和 AI 动作映射。该测试不发网络请求。

关键语义反证要求：

1. 把 create 改走 pageRequest，创建独立请求断言变红。
2. 把列表 total 说明改成“名称筛选命中数”，名称筛选契约断言变红。
3. 删除 checkSms 或让验证失败后继续 DELETE，请求顺序/阻断断言变红。
4. 把短信步骤的 `smsRequestId` 来源改成 `args.ids`，映射断言变红。

仍未完成：启用短信配置时的发送、真人收件、校验及删除；短信两条请求的浏览器逐字段基准。浏览器闭环和共享接线后的 SDK 闭环均已清理测试记录，但短信分支仍不能据此宣称已验证。上述缺口同步保留在实际 AI 契约中。
