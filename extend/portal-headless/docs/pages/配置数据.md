## 列表参数与返回字段

列表请求为 `GET /admin/dict/type/page`，Portal 表单初值为 `dictName=''`、`dictType=''`；SDK 同时补 `order=''`、`orderField=''`、`pageNo=1`、`pageSize=20`。`sale.js` 请求拦截器最终把 `pageSize` 改成后端所需的 `limit`。名称和类型筛选都由 Java 服务做模糊匹配；服务端通过逻辑删除模型排除已删除类型。页面没有自定义排序控件，不对后端默认排序作业务承诺。

返回 `{ list, total }`：

- `list` 是当前页字典类型记录，`total` 是筛选后的总数；需要全量时必须翻页。
- `list[].id` 是字典类型主键，用于详情、编辑、删除及进入字典数据子页。
- `list[].dictName` 是中文名称；`list[].dictType` 是英文类型代码，子页按它关联字典数据。
- `list[].sort` 是页面展示的排序整数；`remark` 是备注。
- `createDate`、`updateDate` 保留服务端时间原值，可能为字符串、数字或 `null`。

## 创建与编辑表单

详情页使用 `useFormPageModule({ objectURL: '/admin/dict/type' })`：编辑先 `GET /admin/dict/type/{id}`，创建提交 `POST /admin/dict/type`，编辑提交 `PUT /admin/dict/type`。表单字段和规则为：

- `dictName` 必填；Portal 使用必填校验，Java `@NotBlank` 拒绝空字符串和全空格。
- `dictType` 必填；同样由 Java `@NotBlank` 校验。
- `sort` 默认 `0`，最小值 `0`；SDK 只接受非负安全整数。
- `remark` 默认空字符串；页面没有额外长度或非空校验，SDK 保留用户原字符串。

创建和更新成功均为无业务数据的 CommonResult，SDK 返回 `undefined`。创建后按精确 `dictType` 查询并核对名称、类型、排序、备注，再取得新 ID；更新后按原 ID `get` 回查。更新时不能用字典数据条目 ID 替换字典类型 ID。

## 删除与权限规则

列表配置 `deleteIsBatch: true`，因此单删和多选删除都向 `DELETE /admin/dict/type` 发送 JSON 数组。SDK 会把 ID 规范化为字符串并去重；空数组、非法 ID 在请求前失败。后端 `deleteBatchIds` 执行字典类型的逻辑删除，权限和租户范围由当前 sale 会话决定。

删除类型不等同于已核实删除其下所有字典数据；进入子页逐项检查属于另一个页面的业务步骤。删除请求成功或超时后，按此前记录的 `dictType`/`dictName` 分页回查根列表，核对目标 ID 已消失，未核实前不重发。

字典数据子页使用 sale 实例，列表配置为 `getDataListURL: '/admin/dict/data/page'`、`deleteURL: '/admin/dict/data'`、`deleteIsBatch: true`，请求 body 是选中数据 ID 数组，不是字典类型 ID。SDK 的 `prepareRemoveData({ ids })` 只做去重和 ID 校验；确认后 `removeData({ draft })` 发送一次 `DELETE /admin/dict/data`。没有服务端取消接口，确认前取消只丢弃草稿。Java 固定检出对应 `ManageSysDictDataController` 的删除签名为 `@DeleteMapping`、`@RequestBody Long[] ids`。

## 操作步骤、失败处理与验证边界

1. 先用列表查询定位字典类型；编辑先 `get`，进入子页时传 `list[].id`。
2. 创建/编辑提交完整字段，空回执不能代替名称或 ID 回查。
3. 根类型删除传所选类型 ID 数组；进入子页删除时先 `prepareRemoveData`，确认后把同一 `draft` 交给 `removeData`，调用成功后按字典类型和数据 ID 回查。
4. `@NotBlank`、`@Min(0)`、权限、网络和后端业务错误原样失败，不转换为空列表；写入超时先回查。

未覆盖真实环境浏览器请求基准、线上写入回查和子级字典数据删除的实际清理状态；本轮未修改共享 AI 契约/接线文件，待主线补齐新增能力说明与 invoke 映射。
