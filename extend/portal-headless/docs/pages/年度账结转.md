## 能力定义

| 能力 ID | SDK 方法 | 页面动作 | 副作用 |
| --- | --- | --- | --- |
| `finance-setting-annual-carryforward-list` | `financeSettingAnnualCarryforward.list(query?)` | 按账套、会计期间、结转状态分页查询 | 无 |
| `finance-setting-annual-carryforward-prepare-transfer` | `financeSettingAnnualCarryforward.prepareTransfer(args)` | 校验批量/单条结转输入，生成年度显示草稿 | 无网络、无写入 |

嵌套 `detail/balance` 页面仍绑定“对账”按钮并调用 `POST /admin-api/finance/annual-closing/reconcile`，但固定 Java 检出没有该路由。按“不可交付能力不应暴露”规则，SDK 不提供详情对账或本地取消对账能力；待后端补齐并确认路由后再单独接入。账套选择器属于候选数据来源，不在本页复制其无关键字全量拉取能力；批量操作使用选择器实际返回的ID，单条操作按Portal源码把列表行 `id` 放进 `accountingSetIds`。

## 参数契约

### 列表

`list(query?)` 的查询对象为：

```ts
{
  accountingSetIds?: Array<string | number>
  periodYear?: string       // YYYY；省略时为 Asia/Shanghai 当前年
  closingStatus?: 0 | 1     // 0 未结转，1 已结转；省略表示不筛选
  pageNo?: number           // 默认 1
  pageSize?: number         // 默认 20，只允许 10/20/50/100
}
```

SDK 按 Portal 列表配置的键序发送：`order`、`orderField`、`accountingSetIds`、`periodYear`、`closingStatus`、`pageNo`、`pageSize`。默认值为 `''`、`''`、`[]`、当前年、`undefined`、`1`、`20`；platform 的 GET 序列化会跳过 `undefined`，空账套数组也不形成有效筛选值。

### 结转准备、结转和取消结转

结转准备和结转接受：

```ts
{
  accountingSetIds: Array<string | number> // 必填，至少一个且不能重复
  periodYear?: string | number             // YYYY；transfer省略时为当前年
}
```

取消结转接受相同对象，但 `periodYear` 必填。ID 必须是安全正整数或无前导零的正整数字符串；长 ID 保留字符串，不转成可能失真的 JavaScript number。

`prepareTransfer` 返回：

```ts
{
  draft: { periodYear: number, accountingSetIds: Array<string | number> }
  fromYear: number // toYear - 1，仅用于复刻弹窗展示
  toYear: number
}
```

真实 HTTP 载荷为：

```text
POST /admin-api/finance/annual-closing/close
{ periodYear: number, accountingSetIds: Array<string | number> }

POST /admin-api/finance/annual-closing/cancel-close
{ periodYear: number, accountingSetIds: Array<string | number> }
```

两个写接口都只接受后端成功数据 `true`；SDK 不把 `false`、缺失响应或异常改写成成功。后端分页请求字段是 `accountingSetIds`、`periodYear`、`closingStatus`、`pageNo`、`pageSize`，`periodYear` 在请求中是 `YYYY` 字符串；后端写入 VO 把它解析为年份字符串，SDK 对外允许字符串或四位整数并在载荷中发送整数。

最重要的 ID 区分：

- `list[].id` 是年度账结转记录主键；Portal 当前单条结转和单条取消把它放入 `accountingSetIds`，SDK按调用方传入值原样发送。
- `list[].accountingSetId` 是后端响应中的账套主键，与 `id` 分开保留；SDK不会静默用它替换Portal单条载荷。
- `id` 与 `accountingSetId` 是否相等、以及后端最终按哪个值生效，未做真实环境验证；这是Portal与后端字段语义之间的已记录风险。

## 逐字段基准

### 列表返回

SDK 最终返回 `{ list, total }`，只公开页面列及写动作需要的字段；未知后端字段丢弃：

| 路径 | 类型 | 含义 | 空值/状态 |
| --- | --- | --- | --- |
| `list` | array | 当前页记录 | `[]` 表示当前页为空，不等于所有筛选无数据 |
| `list[].id` | string \| number | 年度账结转记录主键 | 不作为写入账套 ID |
| `list[].accountingSetId` | string \| number | 后端响应中的账套主键 | 与Portal单条载荷分开保留 |
| `list[].tenantName` | string \| null | 所属企业 | `null` 表示后端未关联名称 |
| `list[].accountingName` | string \| null | 账套名称 | `null` 表示后端未关联名称 |
| `list[].accountCode` | string \| null | 账套编码 | `null` 表示后端未关联编码 |
| `list[].periodYear` | string | 会计年度 | `YYYY` |
| `list[].closingStatus` | 0 \| 1 | 结转状态 | `0` 未结转；`1` 已结转 |
| `list[].closingTime` | string \| null | 结转时间 | 后端格式 `yyyy-MM-dd HH:mm:ss`；未结转或取消后可为 `null` |
| `list[].closingByName` | string \| null | 结转操作人显示名 | 未结转或取消后可为 `null` |
| `total` | integer | 当前筛选结果总数 | 不是当前页长度 |

Portal 表格列为所属企业、账套名称、账套编码、会计期间、结转状态、结转时间、操作人。状态显示为“已结转/未结转”；时间和操作人为空时页面显示占位符，但 SDK 保留后端 `null`，不填充展示文本。

### 静态推导的请求形状

Portal 列表表单默认值是 `accountingSetIds=[]`、`periodYear=formatDay(new Date(),'YYYY')`、`closingStatus=undefined`，并调用 `/admin-api/finance/annual-closing/page`。styleV2 分页默认 `pageNo=1`、`pageSize=20`，选项为 10、20、50、100。

批量结转弹窗显示 `去年 → 当前年`，账套选择至少一个，提交 `/admin-api/finance/annual-closing/close`；批量取消弹窗要求取消年份和至少一个账套，提交 `/admin-api/finance/annual-closing/cancel-close`。单条按钮锁定一行并复用结转弹窗，单条取消直接提交。

Java 当前检出静态代码显示：

- `/page` 返回 `list/total`，按账套、年份、状态过滤，并按组织范围限制账套；缺少当前年度记录时服务端会初始化记录。
- `close` 要求记录存在且未结转；一月账期未开账或已结转时拒绝；成功后写入状态、时间、操作人。
- `cancel-close` 要求记录已结转；若下一年度已有凭证则拒绝“已发生业务，不允许取消结转”；成功后状态变为 0，并清空结转时间和操作人。
- 两个写接口返回 `CommonResult<Boolean>`，成功业务数据为 `true`，没有逐账套结果。

以上均为当前 Portal/Java 源码推导和离线测试证据，不是浏览器或真实环境观察。

## 操作步骤与验证

### 只读查询

1. 按账套、年度、状态调用 `list`，保留每行的 `id` 与 `accountingSetId`；单条动作使用 `id`，批量动作使用选择器ID。
2. 分页直到累计记录数达到 `total`；空页只说明当前页没有记录。
3. 需要单条结转或取消时，用最新列表行的 `id` 和 `periodYear` 形成动作输入，复刻Portal载荷；批量操作使用选择器实际值，不要用已过期列表或详情桥接数据替换它们。

### prepare → transfer → cancel

1. `prepareTransfer({ accountingSetIds, periodYear })` 生成无副作用草稿，展示 `fromYear → toYear` 并确认账套。
2. 用户确认后调用 `transfer`；返回 `true` 只表示后端请求成功。
3. 重新 `list` 查询同一年度和每个实际发送的 `accountingSetIds` 值，确认全部 `closingStatus=1`，并读取结转时间/操作人后，才报告结转生效。
4. 只有用户明确要求撤销且最新状态仍为已结转时，调用 `cancelTransfer`；它是独立逆向写请求，不是 SDK 自动回滚。
5. 再次 `list`，确认全部目标为 `closingStatus=0`，且 `closingTime`、`closingByName` 已清空或为 `null`。若后端以“已发生业务，不允许取消结转”拒绝，保留错误，不重试或臆报成功。
