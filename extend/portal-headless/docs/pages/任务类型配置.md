## 参数契约

页面调的是 `taskTypeConfigApi.list()` —— `params` 是**显式空对象** `{}`
（`app/portal/utils/hr/task-type-config/api.js` 的 `list (params = {})`），
后端那个方法（`KpiTaskConfigController#getConfigList`）也**一个参数都不收**。
所以 URL 上只有 `_t`：

| 字段 | 默认 | 谁给的 |
| --- | --- | --- |
| `_t` | 时间戳 | 客户端（GET 防缓存） |

**返回体要再拆一层**：页面自己写的是 `unwrapTaskTypeList(result)` ——

```js
const data = result?.data || result || {}
return Array.isArray(data) ? data : (data.list || data.records || [])
```

用的是 `||` 不是 `??`；本能力把这段**原样复刻**（`unwrapTaskTypeList`，可单独测）。
后端 `data` 里到底套的是数组还是 `{list|records}`，**没有实测**（见下），三种都收。

行字段（抄 `KpiTaskTypeConfigDTO`）：`taskType` / `taskTypeName` / `selfEditable` /
`leaderEditable` / `progressScoring` / `formulaEnabled` / `buttonCount` /
`updaterName` / `updateTime` 等。

## 已覆盖的写动作

- **改规则**：`PUT /performance/task-type-config/update`，已通过
  `perf-manage-task-type-config-prepare-update` → `perf-manage-task-type-config-update` →
  `perf-manage-task-type-config-cancel-update` 接入目录；
  body `{ id, taskType, selfEditable, leaderEditable, progressScoring }`
  （后端 `KpiTaskTypeConfigUpdateDTO` 里三个布尔都是 `@NotNull`）。
  页面自己还有两条互斥规则：`formulaEnabled` 为真时不能开 `progressScoring`；
  员工可自评时领导必须可评分。

prepare/cancel 均不发请求；submit 严格保持 Portal 的 body 键和值，并在
`formulaEnabled=true` 或 `selfEditable=true && leaderEditable=false` 时于提交前拒绝非法组合。
真实环境写冒烟仍未执行。
- ⚠️ `api.js` 里另有 `button/{list,create,update,status,sort,delete}` 六个端点
  （`/performance/task-type-config/button/*`）—— **本页一个都没调**，
  它们是别的组件/页面的，别因为同一个文件就当成这一页的写入口。
- 页面还有一条「失败可重试」的分支：请求抛错时表格换成 `a-result` +
  「重新加载」按钮（`loadError`），不是业务能力。

读取各任务类型允许的自评、领导评分及进度/公式计分开关。

- 执行：`sdk.perfManageTemplate.listTaskTypeConfigs`；通过 `capabilities.invoke('perf-manage-task-type-config-list', args)` 调用时按 `params` 填参。性质：read。
