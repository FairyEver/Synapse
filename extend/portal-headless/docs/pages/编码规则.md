# 编码规则（`/dashboard/contract/code-rule/list`）

本页覆盖 Portal「合同 → 编码规则」表单的当前规则读取、新建、编辑、编码预览和保存回查。它是合同配置页面，不扩展合同列表、合同模板或合同创建页面的其他接口。

证据边界：已逐字段核对 Portal 页面、合同编码预览工具和 Java `ContractCodeRuleController`、请求 VO、DO、Service；SDK 请求投影、前端必填/枚举规则、预览格式和成功回执有离线测试。当前没有启动测试门户，因此真实租户读请求和 `prepare → create/update → get` 写入回查尚未称为实测。

来源锚点：Portal `CodeReview_Projects_Js@test/portal/main@acab69acc77b6d6c0da21310cdfd26b91a01641e`；Java `CodeReview_Mall_Platform_Java@test/test@0f1a55718ebc1987affb8bf245106e809dd51da4`。

## 一、页面上下文和权限

| 项 | SDK/Portal 事实 |
| --- | --- |
| 页面 | `/dashboard/contract/code-rule/list` |
| 页面权限 | `/dashboard/contract/code-rule` |
| HTTP 实例 | `platform`；逻辑路径由实例补 `/admin-api` 前缀 |
| `module-type` | 不命中页面规则；SDK 定义为 `null`，不主动发送 |
| 数据范围 | Java DO 继承租户基类；当前规则读取按当前租户取最新一条，SDK不接受其他租户/规则范围参数 |

页面进入时调用 `GET /hr/contract-code-rule/getContractCodeRule`。返回 `null` 时页面走创建分支；有规则时保存 `id` 并走更新分支。

## 二、已接入能力

调用门面为 `sdk.contractCodeRule.<method>`，能力说明由 `catalog.describe(id)` 和 `catalog.describe(id, { format: 'llm' })` 返回。

| 能力 ID | 方法 | 请求/效果 |
| --- | --- | --- |
| `contract-code-rule-get` | `get` | 读取当前租户最新规则；未配置返回 `null` |
| `contract-code-rule-prepare-create` | `prepareCreate` | 本地校验并生成 `id=null` 草稿，不发请求 |
| `contract-code-rule-create` | `create` | `POST /hr/contract-code-rule/create`，返回新规则 ID |
| `contract-code-rule-prepare-update` | `prepareUpdate` | 本地校验并生成含 ID 的完整草稿，不发请求 |
| `contract-code-rule-update` | `update` | `PUT /hr/contract-code-rule/update`，要求 `true` 回执 |
| `contract-code-rule-preview` | `preview` | 本地生成页面格式示例，不发请求 |

## 三、表单与预览规则

| 字段 | 页面规则 | 提交语义 |
| --- | --- | --- |
| `fixedPrefix` | 必填，最多 6 个字符 | 保留用户输入值，不自动改成名称或 ID |
| `dateStyle` | 必填：`1=年`、`2=年-月`、`3=年-月-日` | 发送数字枚举 |
| `serialLength` | 必填：`4`、`6` 或 `8` | 发送数字枚举 |
| `description` | 可空 | 按页面原值发送；无描述为 `null` |
| `id` | 创建时为 `null`，更新时必填 | 更新时必须保留当前规则 ID |

Portal 预览为：`固定前缀 + 日期文本 + 随机流水号`。日期文本分别为 `YYYY`、`YYYYMM`、`YYYYMMDD`；流水号由数字和大写字母组成，长度为 `serialLength`。SDK `preview` 允许提供固定 `date`/`serial` 做可重复验证，省略时使用当前本地日期并随机生成流水号。

页面只把“保存”按钮绑定到当前 `isUpdate` 分支：当前没有规则时 POST 创建，有规则时 PUT 更新。SDK 不把 Java 控制器虽然存在但页面未调用的分页、详情按 ID、删除和导出接口加入本页能力。

## 四、操作步骤、失败处理和回查

1. 调 `get`；返回 `null` 时准备创建，否则保存完整对象作为更新基准。
2. 调 `prepareCreate({ ...表单字段 })` 或 `prepareUpdate({ draft: 当前完整对象 })`，确认固定前缀、日期格式、流水号长度和描述。
3. 用户确认后，把同一个草稿传给 `create({ draft })` 或 `update({ draft })`；取消只丢弃草稿，不发请求。
4. 创建返回 ID 或更新返回 `true` 后，再调 `get` 逐字段核对当前租户最新规则。响应超时先回查，不能盲目重放创建/更新。
5. 规则变更只影响后续新建合同的编码，Portal 明确提示不会改写历史合同编码。

字段校验、会话失效、页面权限、租户数据范围、网络和标准响应错误均抛出。`get` 返回 `null` 不是权限错误；`create` 没有有效 ID、`update` 不是 `true`，都不能报告写入完成。
