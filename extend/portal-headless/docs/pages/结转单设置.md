## 参数契约与逐字段基准

列表默认参数为：

```text
order=&orderField=&accountingEntityType=undefined&status=1&pageNo=1&pageSize=20
```

筛选 `accountingEntityType` 只接受 `standard_unit`（标准化单元）或 `corporation`（法人主体）；`status` 是绝对状态 `0=停用、1=启用`，默认1；页码从1开始，页大小只接受 `10/20/50/100`。

新建和编辑按页面 `formState` 展开提交以下字段：

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `id` | 新建为空字符串；编辑为主键 | 新建页面默认值会随表单一起提交 `id:''` |
| `accountingEntityType` | 是 | `standard_unit` 或 `corporation` |
| `accountingScopeOrgIds` | 是 | 组织树多选后的非空ID数组，不能重复；节点对象取 `value` |
| `externalSalesBelongType` | 是 | `sales_org` 或 `delivery_org` |
| `validType` | 是 | `range` 或 `long_term` |
| `effectiveStart` | 是 | 月份格式 `YYYY-MM` |
| `effectiveEnd` | `range`时是 | 不早于开始月份；`long_term`时按 Portal 发送空字符串 |
| `status` | 是 | `0` 或 `1`，默认1 |

`create` 返回新记录ID；`update` 只接受后端 `true` 回执。列表和详情保留 `id`、主体类型、组织范围、归属方式、有效期、状态、创建人和创建时间；`null` 不替换成空文本或0。组织树节点至少保证 `id`、`name`、`pid`、`children`，并保留页面用到的 `isCorporation` / `isStandardUnit` 标记。

### 状态请求的源码/后端冲突

Portal 固定源码调用：

```js
http.put('/admin-api/finance/settlement-setting/update-status', { params: { id, status } })
```

这会把 `{params:{id,status}}` 作为 PUT 第二参数，即实际请求 body；Java controller 则声明 `@RequestParam("id")` 和 `@RequestParam("status")`。SDK按 Portal 实际源码保留 `data: { params: { id, status } }`，并在契约中标记这一冲突，不能把它说成已在真实环境兼容验证。若部署网关实际要求 query 参数，需要新的基准证据后再变更实现和测试。

## 操作步骤、失败处理与验证边界

1. 新建：先读组织树，使用节点ID组装 `accountingScopeOrgIds`，再 `prepareCreate` → `create`，返回ID后用 `get`/`list`回查。
2. 编辑：先取得同一ID的完整详情，`prepareUpdate({current, changes})` 会生成完整提交体和 `previous`，确认后调用 `update`。
3. 启停：使用最新列表行调用 `prepareSetStatus` → `setStatus`；返回 `true` 后回查同一ID。需要恢复时提交同一 `previous`。
4. 非法枚举、组织数组、月份范围、状态、分页或响应形状在本地失败；401/403、网络错误、后端业务错误和非 `true` 写回执不静默成功。

本节点已完成静态源码核对、离线请求夹具、表单边界、状态 body 冲突和 AI 映射反证；未启动浏览器，未执行真实测试环境读请求，也未执行 `prepare → submit → cancel` 写闭环。页面无删除/取消动作，创建数据的清理需受控运维处理。

## 核算范围清单（`scope-modal.vue`）

`GET /admin-api/finance/settlement-setting/scope-list?id=<结转单设置ID>`，无分页参数，返回数组。

后端 `SettlementSettingServiceImpl#getSettlementScopeList` 的语义**不是"把勾选的组织列出来"**，而是四步展开：

1. 读出该条设置的 `accountingScopeOrgIds`（JSON 数组）；空则直接返回 `[]`。
2. 用 `getDescendantByAncestor` 把勾选组织展开成"勾选 + 全部后代"，去重。
3. 按 `orgId` 升序排，**超过 `SCOPE_MAX = 500` 时只取前 500 条**（性能保护，静默截断）。
4. 逐条按该设置的 `accountingEntityType` 过滤（`standard_unit` 只留 `isStandardUnit=1`，`corporation` 只留 `isCorporation=1`），最后再按 `orgId` 升序返回。

返回字段：`orgId`、`orgName`、`orgCode`、`isStandardUnit`(0/1)、`isCorporation`(0/1)、`level`、`fullPath`；页面表格列依次是组织名称、组织编码、隶属路径、层级、标准化单元、法人主体，布尔标记用 `formatBooleanFlag` 显示成"是/否/—"。

### 两条必须写明的状态（都影响这个动作能不能用）

1. **这个组件在固定检出里没有任何引用点**。整仓 grep `scope-modal` 只有它自己一处命中：`list.vue` 与 `[mode]/[id].vue` 都没有 import 它，表单里的「核算范围」用的是 `portal-finance-tree-select-post-tree`。也就是说这个动作当前在 Portal 界面上**没有入口**。按 conventions 第 28 条，注释/未挂载的东西不算用户能做的事；但按第 33 条又不能把一个后端真实存在、组件契约完整的动作当成"不需要的功能"排除，所以：**能力交付，可达性缺口记在 `boundaries` 与 `gaps` 里**，调用方需要先向用户说明这一点。
2. **整个 `SettlementSettingController` 挂着 `@ConditionalOnProperty(erp.finance.settlement.enabled=true)`，默认关闭**（`SettlementFeatureFlag` 的注释写明"默认关闭…生产环境上线日由运维改配置后重启"）。开关没开的部署上，本能力连同本页其它结转单设置能力一律 404。这属于部署事实，SDK 不据此推断可用性。
