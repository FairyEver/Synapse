## Portal 页面行为

### 树形列表和组织筛选

- 列表 `customLoad` 调用 `GET /admin-api/inventory/approval-config/list`，公共列表逻辑会把 `order=''`、`orderField=''` 和表单中的 `orgId` 一起放入查询参数；默认组织值是 `null`，不发送分页参数。
- 后端返回树数组。Portal 用 `mapTree` 加工节点，并只为缺少业务 `id` 的分组节点生成随机 `id8()` 表格 key；子项继承父节点的 `unitId`、`unitName`。这个随机 key 不是可写入后端的业务 ID。
- 行内操作只出现在叶子配置项上：调用 `PUT /admin-api/inventory/approval-config/update`，载荷只有 `{ id: record.id, isRequiresApproval }`，其中状态是 Boolean。
- 页面有组织树筛选和 `unitIdList` 聚合逻辑，但没有可达的删除按钮；Java 虽然存在删除端点，本页不把它注册成 SDK 页面能力。

### 批量新增弹窗

- 打开弹窗先调用 `GET /admin-api/inventory/stock/typeList`，候选的 `value` 是 `type-subtype`，`label` 是显示名称。
- 每行要求 `unitId`、`typeIds` 和 `isRequiresApproval`；Portal 允许删除所有行并提交空数组，Java 的批量服务对空数组直接返回，因此 SDK 不凭空添加“至少一行”的页面规则。
- 提交前先执行表单校验，然后把每个 `typeIds` 拆成 `type`、`subtype`，从候选中匹配 `subtypeName`，并把 `1/0` 转换为 `true/false`：
  `POST /admin-api/inventory/approval-config/batch-create`，请求体是转换后的数组。
- 用户取消新增只关闭弹窗，不发送写请求。批量写入成功或超时后必须重新查询，并按 `unitId/type/subtype` 逐项回查，不能只依据 `true` 回执报告每条记录都已落库。

## Java 后端与权限规则

`ApprovalConfigController` 的根路径是 `/inventory/approval-config`，本页实际使用 `GET /list`、`POST /batch-create` 和 `PUT /update`。相关接口均要求 `@ss.hasPermission('/dashboard/material/approval-configuration')`；页面请求使用当前用户会话和租户上下文。

`ApprovalConfigPageReqVO` 包含 `orgId` 并继承分页参数，但 Controller 将列表页大小设为 `PAGE_SIZE_NONE`，所以 Portal 收到的是完整树数组。Mapper 过滤 `deleted = 0`，指定组织时通过 `hr_organization_relation` 取组织后代，并按 `iac.create_time DESC` 排序。

`ApprovalConfigSaveReqVO` 的批量字段是 `unitId`、`typeList` 和 Boolean `isRequiresApproval`；子项字段是 `type`、`subtype`、`subtypeName`。服务层会按 `unitId/type/subtype` 拒绝重复配置，错误信息为“配置类型已存在,请检查重试”；空批量数组直接返回。更新前校验记录存在，Boolean 状态由后端保存。

## SDK 能力与说明

实现文件为 `src/capabilities/inventory-approval-config.ts`，AI 契约为 `src/catalog/contracts-inventory-approval-config.ts`。能力按列表、类型候选、批量新增准备/提交、审批开关准备/提交拆分；写能力遵循 `prepare → submit`，取消只丢弃草稿。

SDK 明确保留以下页面规则：列表参数包含 `order`、`orderField`、`orgId`；页面未命中 module-type 时不发送该请求头；批量新增使用 `typeList` 和 Boolean；行内更新使用 `PUT` 且只提交 `id` 与 `isRequiresApproval`；不把分组随机 key 当业务 ID；不把 Java 中页面不可达的删除端点误注册为本页能力。
