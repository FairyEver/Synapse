# 产品设置日清日结

页面路径：`/dashboard/product/setting/business-manage/day-liquidation/list`。

菜单归属是 `系统设置 → 生产设置 → 业务管理 → 日清日结`。这里的“生产设置”是 Portal 保留的“系统设置”子菜单，不是范围外的独立生产业务菜单。

## 页面能力定义

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询日清日结 | `product-setting-day-liquidation-list` / `productSettingDayLiquidation.list` | `GET /base/dayLiquidation/list` |
| 查询场区栋号 | `product-setting-day-liquidation-building-list` / `productSettingDayLiquidation.buildingList` | `GET /config/building/getByFarmId` |
| 查询批次号 | `product-setting-day-liquidation-batch-list` / `productSettingDayLiquidation.batchList` | `GET /base/dayLiquidation/getBatchAndSex` |

请求使用 `product` HTTP 实例，补 `devicetype=PC`，不发送 `module-type`。菜单权限为 `/dashboard/frame/business/day-liquidation`；页面没有独立的 query/submit 权限常量，场区选择器默认 `authList=1`，后端列表和候选接口仍按当前会话权限处理。

页面只有读取和筛选，没有新建、编辑、删除、详情或导出动作，SDK不扩展不可达写接口。

## 参数契约与页面联动规则

页面类型和值域固定为：

| type | 页面文案 | 场区选择器 `typeList` |
| ---: | --- | ---: |
| 1 | 入孵 | 3（孵化场） |
| 2 | 验蛋 | 3（孵化场） |
| 3 | 出雏 | 3（孵化场） |
| 4 | 雏鸡日记录 | 1（雏鸡场） |
| 5 | 蛋鸡日记录 | 2（蛋鸡场） |

场区候选由公共 `portal-product-select-farm` 组件读取 `/config/farm/getFarmByQuery`，默认 `authList=1`，因此 SDK调用方必须使用当前用户有权限的场区ID。选择类型会清空场区、栋号和批次；选择场区会清空栋号和批次并读取栋号候选。

列表查询的页面请求参数如下，`scope`始终由Portal固定为 `1`：

```json
{
  "order": "",
  "orderField": "",
  "type": 4,
  "farm": "场区ID",
  "building": "栋号ID或null",
  "businessId": "批次组ID",
  "startDate": "YYYY-MM-DD或null",
  "endDate": "YYYY-MM-DD或null",
  "scope": 1,
  "pageNo": 1,
  "pageSize": 20
}
```

页面批次下拉请求 `/base/dayLiquidation/getBatchAndSex` 后，把每项映射为：

```json
{
  "label": "batch",
  "value": "batch__groupId"
}
```

提交列表时，Portal无条件执行 `businessId.split('__')[1]`，所以 SDK也只发送第二段 `groupId`。调用方应把 `batchList`返回的 `value` 原样传给 `list`，不要把 `label`或批次号当作 `businessId`。

分页默认 `pageNo=1`、`pageSize=20`，页面支持 `10/20/50/100`。日期必须是 `YYYY-MM-DD`；Portal没有开始日期不能晚于结束日期的前端规则，SDK不擅自增加该限制。

## 逐字段基准

| 字段 | 含义 |
| --- | --- |
| `list[].farm` | Java DTO中的场区ID字段；当前列表SQL未显式填充，可能为 `null`。 |
| `list[].farmName` | 服务端按查询场区回填的场区展示名称。 |
| `list[].typeName` | 服务端根据type生成的入孵、验蛋、出雏、雏鸡日记录或蛋鸡日记录。 |
| `list[].recordDate` | 业务记录日期，`YYYY-MM-DD`。type=1/2/3分别对应入孵、验蛋、出雏日期；type=4/5对应日记录的操作日期字段。 |
| `list[].opDate` | 操作日期，`YYYY-MM-DD`；type=1/2/3来自对应操作日期，type=4/5来自日记录创建日期。 |
| `list[].name` | 操作人真实姓名。 |
| `list[].disparityDay` | `DAYS.between(recordDate, opDate)`的结果；是有方向的自然日差值。 |
| `total` | 当前筛选条件下的总记录数。 |

栋号候选：

| 字段 | 含义 |
| --- | --- |
| `value` | `Building.id`；传回 `list.building`。 |
| `label` | `Building.shortName`；仅用于展示。 |

批次候选：

| 字段 | 含义 |
| --- | --- |
| `value` | `${batch}__${groupId}`；传回 `list.businessId`，列表请求再取第二段。 |
| `label` | `batch`；仅用于展示和页面搜索。 |

## Portal 与 Java 的已知差异

Java批次候选服务对 `type>3`调用鸡群批次查询，对 `type<=3`只把 `farm`设置为 `Hatch.hall`；虽然Portal仍把 `type/building/scope`一并发送，后端孵化分支当前没有使用这几个字段。

日清日结列表的 type=4/5 SQL按 `flock_group_id`过滤；type=1/2/3 SQL按 `sh.batch`过滤，而Portal批次下拉最终传的是 `groupId`。列表SQL当前还没有使用 `farm/building`条件。SDK保持Portal实际请求形状并将该差异写入说明和测试，不按类型偷偷改成另一种请求。

## 操作步骤、权限和证据边界

1. 选择type；按上表确认场区类型映射，并从当前用户有权限的场区候选中取得farm。
2. 场区变化后调用 `buildingList({ farmId })`，把候选的value用于building；不要复用旧栋号。
3. 调用 `batchList({ type, farm, building })`，把返回的value原样作为list的businessId。
4. 调用 `list({ type, farm, building, businessId, startDate, endDate, pageNo, pageSize })`；SDK固定发送scope=1并按Portal规则拆分businessId。
5. `list=[]`表示当前页没有记录；`total=0`才表示当前筛选条件没有记录。权限、网络或响应结构错误会抛出，不能当作空列表。

本轮逐页核对了Portal菜单、路由权限、列表源码、公共场区选择器、公共分页实现、Java Controller/VO/DTO/Service/Mapper、SDK请求和离线反证测试。尚未在真实测试环境使用浏览器会话执行五种type的场区/栋号/批次联动和列表读取；type=1/2/3的批次组ID与Java按batch过滤的差异也尚未在真实数据上闭环确认。
