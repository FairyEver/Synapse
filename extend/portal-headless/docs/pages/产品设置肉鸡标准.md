# 产品设置肉鸡标准

页面路径：`/dashboard/product/setting/standard-manage/standard-broiler/list`。

## 页面能力定义

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询列表 | `product-setting-standard-broiler-list` / `productSettingStandardBroiler.list` | `GET /base/standardBroiler/page` |
| 准备新建 | `product-setting-standard-broiler-prepare-create` / `productSettingStandardBroiler.prepareCreate` | 不发请求 |
| 新建 | `product-setting-standard-broiler-create` / `productSettingStandardBroiler.create` | `POST /base/standardBroiler/save` |
| 准备编辑 | `product-setting-standard-broiler-prepare-update` / `productSettingStandardBroiler.prepareUpdate` | 不发请求 |
| 编辑 | `product-setting-standard-broiler-update` / `productSettingStandardBroiler.update` | `POST /base/standardBroiler/save` |
| 准备删除 | `product-setting-standard-broiler-prepare-remove` / `productSettingStandardBroiler.prepareRemove` | 不发请求 |
| 删除 | `product-setting-standard-broiler-remove` / `productSettingStandardBroiler.remove` | `DELETE /base/standardBroiler/{id}` |

页面属于 `门户 → 系统设置 → 生产设置 → 标准库管理`，不是独立顶层生产系统。请求使用 `product` HTTP 实例，固定追加 `devicetype=PC`，本页不发送 `module-type`。菜单和路由权限为 `/dashboard/frame/standard-library/standard-broiler`。

Portal 页面声明了 `base:standard-broiler:query` 和 `base:standard-broiler:submit`；查询没有单独调用 query 权限，新增、编辑和删除由 `permissionCheck(permissions.submit)` 控制。SDK保留该权限事实，服务端仍执行当前会话的实际权限校验。

## 参数契约与表单提交规则

列表是 `useListPageModule({ styleV2: true, customLoad, getDataListIsPage: true })`，页面代码在脚本末尾显式执行首次 `logicFetch()`。默认请求参数为：

```json
{
  "order": "",
  "orderField": "",
  "year": "",
  "type": "",
  "age": "",
  "variety": "",
  "pageNo": 1,
  "pageSize": 20
}
```

类型筛选实际使用 `1=日龄、7=周龄`；日龄/周龄查询值由文本输入框传递。分页支持 `10/20/50/100`。

新建和编辑弹窗只有年度、日龄/周龄配置了 `required` 规则；新建类型默认 `1=日龄`，品种和六个指标可以为空。年度范围为 `1970` 至 `10000000`，日龄/周龄范围为 `0` 至 `10000000`，其他数值控件范围为 `-10000000` 至 `10000000`。

累计存活率按页面百分数输入，提交时严格除以 `100`；其他指标不做百分比换算：

```json
{
  "year": 2026,
  "type": 7,
  "age": 21,
  "variety": "V1",
  "totalConsumeMaterialStandard": 2400,
  "totalSurvivalRateStandard": 0.85,
  "deathEliminateStandard": 2,
  "consumeMaterialStandard": 120,
  "feedMeatRatioStandard": 1.6,
  "avgWeightStandard": 2200
}
```

Java 分页接口会把数据库中的累计存活率比例小数乘以 `100` 后返回，例如数据库值 `0.85` 返回 `85`。Portal 编辑弹窗回显时又执行 `列表值 * 100`，提交时再执行 `输入值 / 100`；这是页面当前源码的二次换算路径。SDK 的 `prepareUpdate()` 接收的是 Portal 编辑弹窗的 formState 值，并保留 `...props.raw` 中的扩展字段，再覆盖编辑字段和ID。用户取消新建、编辑或删除确认时只丢弃本地草稿，不发送写请求。

## 逐字段基准

| 字段 | 含义 |
| --- | --- |
| `id` | 肉鸡标准记录ID；编辑和删除目标。 |
| `year` | 年度。 |
| `type` | 年龄类型；`1` 日龄、`7` 周龄。 |
| `age` | 日龄或周龄数值，单位由 `type` 决定。 |
| `gen` | 代次；Java实体字段，页面列表不展示。 |
| `variety` | 品种字典值；保存和筛选使用。 |
| `varietyName` | Java DTO的品种名称扩展字段；当前Controller没有补充，页面不直接使用。 |
| `line` | 品系；Java实体字段，页面列表不展示。 |
| `totalConsumeMaterialStandard` | 只鸡累计耗料标准，可为空。 |
| `totalSurvivalRateStandard` | 累计存活率标准；列表响应是服务端乘 `100` 后的数值，保存草稿是页面输入除以 `100` 后的比例小数。 |
| `deathEliminateStandard` | 当日死淘数标准，可为空。 |
| `consumeMaterialStandard` | 只鸡耗料标准，可为空。 |
| `feedMeatRatioStandard` | 累计料肉比标准，可为空。 |
| `avgWeightStandard` | 平均体重标准，可为空。 |
| `total` | 当前筛选条件下的记录总数。 |

SDK保留后端返回的页面无关扩展字段，但不把它们当作页面业务字段；网络、权限、Java业务错误或响应结构错误会抛出，不降级为空列表。

## 逐页操作步骤、权限与证据边界

1. 用 `list()` 读取最新列表，确认目标行的 `id`、年度、年龄类型、日龄/周龄和指标值。
2. 新建先调用 `prepareCreate()`；编辑先按 Portal 回显规则把列表累计存活率转换为弹窗值，再调用 `prepareUpdate()`，确认 `draft` 保留当前行ID和raw字段。
3. 用户明确确认后，把同一 `draft` 原样交给 `create()` 或 `update()`；成功或响应不确定后重新调用 `list()` 回查。
4. 删除先调用 `prepareRemove({ id })`，用户确认后调用 `remove({ id })`；成功或响应不确定后重新查询，确认目标ID不再出现。
