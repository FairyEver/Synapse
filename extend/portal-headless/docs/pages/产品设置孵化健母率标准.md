# 产品设置孵化健母率标准

页面路径：`/dashboard/product/setting/standard-manage/standard-hatch/list`。

## 页面能力定义

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询列表 | `product-setting-standard-hatch-list` / `productSettingStandardHatch.list` | `GET /base/standardHatch/page` |
| 查询日龄段选项 | `product-setting-standard-hatch-age-stage-options` / `productSettingStandardHatch.ageStageOptions` | `GET /egg/standardAgeStage/list` |
| 准备新建 | `product-setting-standard-hatch-prepare-create` / `productSettingStandardHatch.prepareCreate` | 不发请求 |
| 新建 | `product-setting-standard-hatch-create` / `productSettingStandardHatch.create` | `POST /base/standardHatch/save` |
| 准备编辑 | `product-setting-standard-hatch-prepare-update` / `productSettingStandardHatch.prepareUpdate` | 不发请求 |
| 编辑 | `product-setting-standard-hatch-update` / `productSettingStandardHatch.update` | `POST /base/standardHatch/save` |
| 准备删除 | `product-setting-standard-hatch-prepare-remove` / `productSettingStandardHatch.prepareRemove` | 不发请求 |
| 删除 | `product-setting-standard-hatch-remove` / `productSettingStandardHatch.remove` | `DELETE /base/standardHatch/{id}` |

页面属于 `门户 → 系统设置 → 生产设置 → 标准库管理`，不是独立顶层生产系统。请求使用 `product` HTTP 实例，固定追加 `devicetype=PC`，本页不发送 `module-type`。菜单和路由权限为 `/dashboard/frame/standard-library/standard-hatch`。

Portal 页面声明了 `base:standard-hatch:query` 和 `base:standard-hatch:submit`；查询没有单独调用 query，新增、编辑和删除由 `permissionCheck(permissions.submit)` 控制。SDK不绕过服务端当前会话的实际权限校验。

## 参数契约与表单提交规则

列表使用 `useListPageModule({ styleV2: true, customLoad, getDataListIsPage: true })`，并在脚本末尾调用 `loadAgeStageOptions()`。默认列表请求参数为：

```json
{
  "order": "",
  "orderField": "",
  "ageStage": "",
  "hall": "",
  "gen": "",
  "variety": "",
  "year": "",
  "genDown": 0,
  "pageNo": 1,
  "pageSize": 20
}
```

列表表单中孵化厅、代次、年度、是否降代有 `required` 规则；首次加载仍按上述默认状态请求。日龄段选项来自单独的 `/egg/standardAgeStage/list`，`ageStageOptions()` 返回 `id` 与 `stage`；场区选择器使用 `typeList=3`、`authList=0` 读取场区，列表行的 `hall` 是ID，不应把名称代替ID提交。分页支持 `10/20/50/100`。

新建和编辑弹窗中年度、日龄段、代次、孵化厅、品种、是否降代、健母率、蛋雏比、雏鸡体重、受精卵孵化率、不含血受精率、满意度有 `required` 规则；`abnormalFemaleRate` 没有 `required` 规则，允许为空。年度范围为 `1970` 至 `10000000`，其余数字输入范围为 `-10000000` 至 `10000000`。

健母率、残母雏率、受精卵孵化率、不含血受精率按页面百分数填写，保存时严格除以 `100`；残母雏率为空时保存草稿为 `null`。蛋雏比、雏鸡体重、满意度不做百分比换算：

```json
{
  "year": 2026,
  "ageStage": "age-1",
  "gen": "G1",
  "hall": 101,
  "variety": "V1",
  "genDown": 1,
  "healthyFemaleRate": 0.82,
  "abnormalFemaleRate": 0.60,
  "eggChickRatio": 1.25,
  "chickWeight": 42,
  "fertilizedHatchingRate": 0.90,
  "excludedBloodFertilityRate": 0.88,
  "satisfaction": 95
}
```

Java `StandardHatchServiceImpl` 的详情和分页响应会把四个率字段从数据库比例小数乘以 `100`；例如数据库值 `0.82` 返回 `82`。Portal 编辑弹窗直接使用接口原值回显，提交时再除以100。SDK的 `prepareUpdate()` 接收弹窗表单值，保留 `...props.raw` 中的扩展字段，再覆盖编辑字段和ID。

## 逐字段基准

| 字段 | 含义 |
| --- | --- |
| `id` | 孵化健母率标准记录ID；编辑和删除目标。 |
| `year` | 年度。 |
| `ageStage` | 日龄段ID；通过 `ageStageOptions()` 映射名称。 |
| `gen` | 代次字典值。 |
| `hall` | 孵化厅/场区ID；由场区选择器的 `typeList=3` 返回。 |
| `hallName` | 可选名称扩展字段；StandardHatch实体当前未声明，通常为空。 |
| `variety` | 品种字典值。 |
| `genDown` | 是否降代；`0` 否、`1` 是。 |
| `healthyFemaleRate` | 健母率标准；列表响应是服务端乘100后的百分数值，保存草稿是输入除100后的比例小数。 |
| `abnormalFemaleRate` | 残母雏率标准；同样按乘100/除100处理，表单可为空。 |
| `eggChickRatio` | 蛋雏比标准；服务端原始数值。 |
| `chickWeight` | 雏鸡体重标准，单位克；服务端原始数值。 |
| `fertilizedHatchingRate` | 受精卵孵化率标准；按乘100/除100处理。 |
| `excludedBloodFertilityRate` | 不含血受精率标准；按乘100/除100处理。 |
| `satisfaction` | 满意度标准；服务端原始数值。 |
| `total` | 当前筛选条件下的记录总数。 |

SDK保留后端返回的页面无关扩展字段，但不把它们当作页面业务字段；网络、权限、Java业务错误或响应结构错误会抛出，不降级为空列表。

## 逐页操作步骤、权限与证据边界

1. 先用 `ageStageOptions()` 取得日龄段ID与名称，再用 `list()` 读取最新列表，确认目标行的ID、年度、日龄段、孵化厅、代次、品种、是否降代和指标值。
2. 新建先调用 `prepareCreate()`；编辑先按Portal弹窗当前值准备 `prepareUpdate()`，确认 `draft` 保留当前行ID和raw字段。
3. 用户明确确认后，把同一 `draft` 原样交给 `create()` 或 `update()`；成功或响应不确定后重新调用 `list()` 回查。
4. 删除先调用 `prepareRemove({ id })`，用户确认后调用 `remove({ id })`；成功或响应不确定后重新查询，确认目标ID不再出现。

本轮逐页核对了Portal菜单、路由、列表、弹窗、日龄段与场区选择器、product HTTP、权限实现、Java `StandardHatchController`/`StandardHatch`/`StandardHatchServiceImpl`/Mapper/`StandardAgeStageController`、SDK请求和离线反证测试。尚未在真实测试环境使用浏览器会话执行列表、选项、`prepare → submit → 回查`及删除闭环；当前证据为Portal/Java源码和离线请求形状测试。
