# 定时任务

## 能力定义与页面范围

平台设置 → 定时任务，菜单 `/dashboard/platform/system/regular/task/list`，权限为
`/dashboard/platform-v2/system/regular/task`。页面使用 platform-mall-admin.js，列表、编辑和执行请求不发送 `module-type`。

列表只有“编辑”和“执行”两个动作。编辑页通过列表动作的 bridge 直接把整行记录放入表单，`formLoad` 不再 GET 详情；当前 Portal 没有新建、删除、暂停/恢复入口，
SDK 不发布这些后端存在但页面不可达的接口。

依据 Portal `test/portal/main @ acab69acc77b6d6c0da21310cdfd26b91a01641e` 的 `list.vue`、`[mode]/[id].vue`、`task.vue`、`mall.v2.js`，以及 Java
`test/test @ 0f1a55718ebc1987affb8bf245106e809dd51da4` 的 `ManageScheduleJobController`、`ScheduleJobDTO` 和 `ManageScheduleJobServiceImpl`。

## 能力和请求

| 能力 | SDK 方法 | 请求 | 页面行为 |
|---|---|---|---|
| `platform-system-schedule-list` | `list(query?)` | GET `/mall-manage-api/sys/schedule/page` | 页面未启用 styleV2，默认 pageSize=10 |
| `platform-system-schedule-prepare-update` / `…update` | `prepareUpdate({form})` / `update({form})` | 不发请求 / POST `/mall-manage-api/sys/schedule/update` | 编辑页提交 bridge 后的整份表单 |
| `platform-system-schedule-prepare-run` / `…run` | `prepareRun({id})` / `run({id})` | 不发请求 / GET `/mall-manage-api/sys/schedule/run`，query `{idList:id}` | 手动立即执行；页面传的是单个 id，不是数组 |

列表请求参数为 `{order:'', orderField:'', pageNo, pageSize}`，返回 `{list,total}`。行字段为 `id/beanName/params/cronExpression/status/remark/createDate`；
状态 `0` 为暂停、`1` 为正常，备注为空时页面只在展示层显示“无”，SDK 保留原始空值。

## 表单提交规则

编辑入口用 `actionEdit(record, record)` 把列表行作为 bridge。表单只有 `cronExpression` 一项 required 校验，空字符串请求前失败；页面没有 trim 或长度校验。
开关的 `checkedValue/unCheckedValue` 是数值 `1/0`，SDK 对提交中的 status 保持这两个数值。请求体是完整 form，不是差异 PATCH；因此 SDK 保留 bridge 表单中的
`id/beanName/params/cronExpression/status/remark/createDate` 及未知字段，只要求合法的 `id` 和非空 `cronExpression`。

操作顺序：`list()` → 用户选择一行 → `prepareUpdate({form})` → 用户确认 → `update({form})` → 重新 list 按同一 ID 逐字段核对。现有 `update` 已覆盖 Portal `POST /sys/schedule/update`，本轮仅完成核对与定向测试，没有新增动作。
页面取消只返回列表，不发请求；后端没有撤销接口，更新超时先回查再决定是否重试。

手动执行顺序：最新列表行 ID → `prepareRun` → 用户确认 → `run`。页面成功提示只代表执行请求成功返回，不代表定时任务业务已经完成；执行没有 requestId，超时不能直接重发。
