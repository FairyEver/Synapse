## Portal 页面行为

列表页只有名称筛选，调用 `GET /admin-api/system/license/tree` 并把返回树映射为 Portal 表格数据：无子节点时移除 `children` 并补 `childrenCount=''`。文件夹可以编辑、新建下级目录、创建下级证照和删除；证照可以编辑、共享设置和删除。

证照编辑页先调用 `GET /admin-api/system/license/get?id=...`，证照类型来自 `GET /admin-api/system/license-category/simple-list`。新建/编辑提交前把表单数组转换成后端字符串：`fileUrl`、`pdfUrl`、`pdfName` 用逗号连接，提醒人员用 `staffCode` 逗号连接，本单位法人取首个人员的 `staffCode/name`。保存分别调用 `/admin-api/system/license/create` 或 `/admin-api/system/license/update`。

“识别证照”先检查 `GET /admin-api/system/license/isHaveTipTemplate`，再把第一张图片和类型 POST 到 `/admin-api/system/license/pictureRecognition`；识别结果只是待确认表单值，不是保存凭据。共享弹窗的资源类型固定为 `2`，读取 `/admin-api/system/share-user/getShare`，保存 `/admin-api/system/share-user/createShare`。

## 表单与权限规则

- 证照名称最多 50 个字符；证照类型、上级文件夹、关联组织、取得时间必填。
- 非永久证照必须填写到期时间和至少一个到期提醒人员；永久证照发送 `endTime=null`。
- `isOur=1` 时法人从人员候选中取首项 `staffCode/name`；`isOur=0` 时使用外部法人名称，最多10个字符。工号不能猜成用户 ID。
- 图片和 PDF 至少上传一种；图片最多 1 张，PDF 最多 10 项，页面只接受 `application/pdf`。上传 URL 必须来自 OSS 上传能力。
- 文件夹名称最多 50 个字符，根目录提交 `pid=0`；文件夹角色授权随 `roleList` 提交。后端同名拒绝，文件夹中仍有证照时拒绝删除。
- 目录树、证照详情和共享设置均受当前租户、页面权限、创建人/证照资源授权和后端数据范围约束；SDK 不扩大权限，也不把空结果当作授权成功。

## 后端与 SDK 对齐

Java `HrLicenseController` 提供树、详情、创建、更新、创建文件夹、删除、证照识别和模板检查；`HrLicenseServiceImpl` 负责租户、创建人、证照资源授权、名称唯一、提醒人员和文件夹非空删除约束。共享由 `HrShareUserController` 的 `type=2` 资源共享接口完成。

实现文件：`src/capabilities/certificate-license.ts`；AI 说明：`src/catalog/contracts-certificate-license.ts`。SDK 把 Portal 可达的读取、准备、提交、删除、识别和共享动作都接入同一 `certificateLicense` 门面，写能力必须经过准备草稿、用户确认、提交和回查；取消仅丢弃本地草稿，没有虚构服务端取消接口。
