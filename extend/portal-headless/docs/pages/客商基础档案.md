# 客商基础档案（`/dashboard/finance/setting/opening-supplier/list`）

本页覆盖 Portal「系统设置 → 财务设置 → 客商基础档案」的列表、详情、创建/编辑表单、启停、删除、模板、整批导入和导出。它是保留范围中「系统设置」的后代页面；不是被排除的独立顶层「财务」系统，因此只登记该页面实际可达的客商链路，不扩展 Java 中同一 Controller 的 payee、related、history 等不可达接口。

证据边界：已逐页核对 Portal 菜单、列表组件、详情和表单，逐字段核对 Java Controller、Page/Save/Resp/Bank VO、服务和 Excel 服务；SDK 请求投影、表单校验、权限端点、文件边界、响应投影和反证均有离线测试。当前没有在真实测试门户执行读冒烟或写入闭环，不能把离线请求称为真实持久化证据。

## 三、逐字段页面基准

### 3.1 列表请求和消费

Portal 列表公共模块补充 `order=''`、`orderField=''`、`pageNo` 和 `pageSize`。默认请求体为：

```text
order=&orderField=&name=&code=&companyIds=[]&status=0&pageNo=1&pageSize=20
```

可见筛选映射如下：

| 页面字段 | 请求字段 | 规则 |
| --- | --- | --- |
| 客商名称 | `name` | 默认空字符串 |
| 客商编码 | `code` | 默认空字符串 |
| 客商分类 | `categoryCode` | 有值时发送；清空时不限制 |
| 所属公司树 | `companyIds` | ID数组，默认空数组；服务端再与当前授权公司求交 |
| 状态 | `status` | `0`启用、`1`停用；默认0 |
| 供应链金融 | `supplyChainFinance` | 有值时发送布尔筛选 |
| 分页 | `pageNo/pageSize` | 默认1/20；页面支持10/20/50/100 |

列表行至少消费 `id`、`name`、`code`、`categoryName`、`companyName`、`originalCompanyUpdate`、`supplyChainFinance`、`originalPartyName`、`updateTime` 和 `status`。长 ID 保留字符串；名称、分类名称和公司名称是展示值，不能替代保存 ID/编码。

### 3.2 公司树、分类和原客商候选

- `companyTree` 返回 `id/name/fullName/isCorporation/children`；只有 `isCorporation=1` 的节点可以作为 `companyId`，非法人节点只用于树展示。
- `listCategoryOptions` 返回 `id/code/name`；表单保存使用 `categoryCode`，不能把分类名称当作编码。
- `originalOptions` 默认关键字为空字符串；编辑时传 `excludeId` 排除当前客商，`originalPartyId` 必须来自候选 ID，不能选择自身。
- `generateCode` 只按 `companyId` 请求服务端编码预览；它返回的是编码字符串，不是客商主键，是否自动使用仍由 `autoAssignCode` 决定。

### 3.3 创建/编辑表单提交规则

Portal 表单字段与 SDK 草稿的规则如下：

| 字段 | 创建 | 编辑 |
| --- | --- | --- |
| `name` | 必填，最多500字符 | 页面禁用，沿用当前值 |
| `code` | `autoAssignCode=false`时必填；只允许字母和数字，最多500字符 | 页面禁用或自动编码，沿用当前值 |
| `autoAssignCode` | 默认false；开启且有公司时调用 `generateCode` | 沿用快照 |
| `companyId` | 必填，必须是法人公司节点 | 页面禁用，沿用当前值 |
| `categoryCode` | 可选，来自分类候选 | 可编辑 |
| `originalCompanyUpdate` | 必填布尔值 | 可编辑 |
| `originalPartyId` | `originalCompanyUpdate=true`时必填 | 同样条件必填，不能指向自身 |
| `supplyChainFinance` | 默认false | 可编辑 |
| `bankAccounts` | 动态银行账户数组 | 可编辑 |

提交时只保留服务端业务字段；`companyName`、`categoryId`、`categoryName`、`originalPartyName`、`rowKey` 等展示/页面字段不进入 SDK 保存载荷。银行账户的空行被过滤；任一行填写银行、支行或账号时必须有 `bankId`，支行最多500位，账号只允许数字且最多50位。后端还会校验启用状态下的公司范围、编码/名称唯一性、分类、原客商关系、银行是否有效及银行账户重复。

### 3.4 启停、删除和文件规则

- 启停使用绝对数值 `status`：`0` 启用、`1` 停用，不使用 toggle；成功回执为 `true` 后按同一 ID 回查。
- 删除只提交 `id`；服务端会拒绝有原客商关系、子关系或业务引用的记录。删除成功后必须刷新列表确认目标 ID 消失。
- 模板下载返回 `客商基础档案导入模板.xlsx`；导入支持 `.xlsx/.xls`，解码后文件大小必须大于0且不超过20MB。
- Portal 与 Java 导入均按整批校验：空行跳过，任一行校验失败则整批失败；公司、分类、银行的 ID/名称一致性、编码/名称重复、账号格式和授权范围由服务端最终判断。
- 导出按当前筛选导出 `客商基础档案.xlsx`；Portal 的导出载荷剔除 `pageNo/pageSize`，SDK同时不发送 `order/orderField`。

## 四、权限与后端对齐

Portal 的页面权限、按钮权限、会话 token、tenant-id 和公司数据范围共同决定可用性。Java `FinancePartyController` 当前源码中的 `@PreAuthorize` 是注释状态，因此本节点只记录 Portal 按钮权限和服务端实际业务校验，不把源码注释状态当作线上权限结论。

Java Controller 与页面实际调用一一对应：`create`、`update`、`delete`、`get`、`page`、`generate-code`、`change-status`、`company-tree`、`category-options`、`original-options`、`template`、`import`、`export`。同一 Controller 的 `company-options`、`related-options`、`payee-options`、`payee-page`、`history/page` 没有被本页面调用，不登记为本页能力。

SDK 对 Java VO 的关键约束保持一致：Long ID 可以用字符串传递；保存名称最多500位；编码最多500位且仅字母数字；公司和原公司关系按条件必填；银行支行最多500位、账号最多50位数字；列表状态默认0；导入最大20MB且整批校验。
