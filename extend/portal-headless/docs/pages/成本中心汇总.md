## 参数契约与逐字段基准

列表默认发送 `order=''`、`orderField=''`、`name=''`、`insuranceCost=''`、`fundCost=''`、`salaryCost=''`、`organization=''` 和 `pageNo=1&pageSize=20`。组织字段是ID，不是名称。

导出沿用页面通用 `actionExport`，只发送五个表单字段，不发送 `order/orderField/pageNo/pageSize`；文件名优先取响应 `Content-Disposition`，缺失时回退为 `成本中心.xlsx`。

列表行字段为 `name`、`staffCode`、`idCard`、`insuranceCost`、`fundCost`、`salaryCost`、`fullPath`。三个成本中心字段是页面显示文本，SDK不从文本推断成本中心ID。

## 操作步骤、失败处理与验证边界

1. 需要组织筛选时先读取角色组织树，再提交节点ID。
2. 按 `total` 分页；导出前沿用相同表单筛选。
3. 用户明确要求维护时调用本地路由动作，由支持Portal路由的调用方进入子页；不能把汇总列表当维护表单。
4. 非法组织ID、分页、树、分页响应或空文件在本地失败；权限、网络和后端业务错误原样抛出。

已完成页面源码、Java字段、分页/导出参数和路由语义的离线核对；本页没有写接口，因此不存在本页的 `prepare → submit → cancel` 写闭环；维护子页尚未扩展。

## 维护子页列表（`hr/manage/cost-center/maintenance/list.vue`）

`GET /admin-api/salary/costcenter/manage-page`，能力 `manage-cost-center-maintenance-list` / `manageCostCenter.listMaintenance`。

入口是汇总页的本地路由动作 `manage-cost-center-maintenance`（`router.push('./maintenance/list')`）。子页表格只有两列：成本中心编码、成本中心名称。

请求参数顺序：`order`、`orderField`、`code`、`name`、`pageNo`、`pageSize`。

- `code` / `name` 是**模糊匹配**（后端 `like`）。页面用 `convertFetchForm` 先 `trim`，空值转 `undefined`，qs 的 `skipNulls` 把 undefined 整条丢掉 —— 所以空筛选时 URL 上**没有** `code`/`name` 这两个键（不是发送空字符串）。SDK 完全照这个规则做：`'   '`、`''`、`null` 都会被当成"不筛"。
- `pageSize` 默认 20（子页用了 `styleV2`），选项是 `useListPageModule` 的全局默认 10/20/50/100。⚠️ 这与汇总页那份允许 200/500 的校验**不是同一组**，所以 SDK 在维护列表这条路径上单独判。

### 后端实际怎么查（页面参数有两项后端不读）

`SalaryCostCenterServiceImpl#getManagePage`：

- `pageNo` 为空或 <1 → 归一到 **1**；`pageSize` 为空或 <1 → **10**，并 `Math.min(size, 500)` 封顶。
- `code` / `name` 各自 `StrUtil.trim` 后 `like`，空白不拼条件。
- **固定 `is_del = 0`**，且 **`order by id asc`** —— 页面发的 `order` / `orderField` 后端**根本不读**。SDK 为与页面请求逐字一致照样发这两个键，但说明里不承诺"排序由调用方控制"。

### 本能力不覆盖的部分

子页的「**删除**」（`DELETE /salary/costcenter`，`data: [record.id]`）与「编辑」没有接入本能力：它们是另外两个动作，本轮派单范围只到列表。删除按钮的可达性与权限本轮未复核，`gaps` 里已登记。
