# 智能助手（`/dashboard/chat`）

本页覆盖 Portal 顶部保留菜单「智能助手」的模型/技能读取、历史对话、聊天 SSE、回答评价、技能展示顺序和制度预览。它不把聊天回答里的 `router`、`pcRouter`、侧栏卡片或任意 URL 当成新的 SDK 页面入口；这些动作必须交给对应目标页面的能力和权限继续处理。

证据边界：已逐段核对 Portal `ChatConversation.vue`、聊天 API、技能排序弹窗、制度预览组件和聊天动作适配器，并核对 Java 的 PC chat、技能顺序和制度接口控制器。SDK 请求投影、FormData 顺序、附件/图片上限、SSE 心跳与错误终止、反馈 URL 和技能排序边界有离线测试；当前没有启动测试门户，因此真实模型调用、真实 SSE 分片、反馈落库、制度预览权限和写入回查仍未称为实测。

来源锚点：Portal `CodeReview_Projects_Js@test/portal/main@acab69acc77b6d6c0da21310cdfd26b91a01641e`；Java `CodeReview_Mall_Platform_Java@test/test@0f1a55718ebc1987affb8bf245106e809dd51da4`。

## 一、页面上下文、权限和范围

| 项 | SDK/Portal 事实 |
| --- | --- |
| 菜单与页面 | Portal 顶部「智能助手」；`/dashboard/chat` |
| 页面权限 | `/dashboard/chat`；聊天可用列表和历史控制器标注 `PermitAll`，技能顺序接口要求已认证 |
| HTTP 实例 | `platform`；SDK 逻辑路径由实例补 `/admin-api` 前缀，反馈的原始 GET 是例外 |
| `module-type` | 无页面匹配规则；SDK 定义为 `null`，不主动发送该头 |

本页属于提示词保留的 Portal 顶级入口。生产、财务等独立顶级菜单没有因为聊天回答可以跳转到它们就被纳入本页范围；聊天动作只保留为返回数据，目标能力仍需单独检查权限。

## 二、已接入能力

调用门面为 `sdk.chat.<method>`，目录能力 ID 以 `chat-` 开头；每项说明由 `catalog.describe(id)` 和 `catalog.describe(id, { format: 'llm' })` 返回。

| 能力 ID | SDK 方法 | 请求/效果 |
| --- | --- | --- |
| `chat-available-list` | `availableList` | `GET /ai/pc/chat/getAvailableList`，固定默认 `callType=2`，返回模型和技能候选 |
| `chat-history` | `history` | `GET /ai/pc/chat/history`，默认 `pageNo=1,pageSize=20` |
| `chat-stream` | `stream` | `POST /ai/pc/chat/chatStream`，multipart 表单，返回过滤心跳后的 SSE 事件生成器 |
| `chat-feedback` | `feedback` | 复刻页面原始 `GET ai/updateUseful.json?c=...&id=...&useful=...` |
| `chat-skill-order` | `skillOrder` | `GET /ai/pc/chat/skill-order/get`，返回当前用户顺序、默认顺序和定制状态 |
| `chat-prepare-save-skill-order` | `prepareSaveSkillOrder` | 本地校验技能顺序，不发请求 |
| `chat-save-skill-order` | `saveSkillOrder` | `PUT /ai/pc/chat/skill-order/save`，提交 `{ skillIds }` |
| `chat-reset-skill-order` | `resetSkillOrder` | `PUT /ai/pc/chat/skill-order/reset`，请求体为 `null` |
| `chat-policy-preview` | `policyPreview` | `GET /system/policy/get?id=...`，返回制度详情；SDK 不下载或渲染文件 |

## 三、参数和页面提交规则

### 3.1 模型、技能和历史

- `availableList` 必须按页面传 `callType=2`；Java 控制器默认值是 3，但 Portal 页面明确覆盖为 2，SDK 不采用后端默认值。
- `skills[].id` 只能用于 `skillId`，`models[].id` 只能在未选技能时用于 `modelConfigId`。选中技能时，SDK 与页面一样不发送 `modelConfigId`。
- `history` 的 `list[].id` 是回答记录 ID，可传给 `feedback`；`contentItems` 是结构化回答内容，不能只取 `answer` 丢弃结构化字段。分页默认 20，继续加载按 `pageNo` 递增。

### 3.2 聊天表单

`stream` 按 Portal `ChatConversation.vue` 的实际顺序创建 `FormData`：

```text
question → type=1 → skillId → requestId(去掉连字符的UUID)
→ platform=PC → agentOrchestration → intent/categoryIds/moduleIds/imageIds(非空才追加)
→ modelConfigId(没有skillId时才追加) → files(重复字段)
```

`question` 会先 `trim`。没有文本时，必须至少提供 `skillId` 或附件；页面在只选技能时会先把技能 prompt 组成最终问题，SDK 调用方应传入已经整理好的最终文本。附件最多 5 个、图片最多 1 张；SDK 接受 `{ name, data, contentType?, encoding? }`，字符串默认按 base64 解码，不能传本地文件路径。

`agentOrchestration` 省略时读取平台字典的 `is_open` 值；`intent`、`categoryIds`、`moduleIds`、`imageIds` 为空时不追加字段。请求带 `version=3`，并以原始流方式读取响应。

SSE 规则：heartbeat 不向调用方产出；普通事件按到达顺序产出；事件出现非空 `msg`/`errorMsg` 时停止并保留该错误事件；事件 `data.id` 非空时按 Portal 规则结束，作为后续反馈 ID。自然 EOF 没有最终 ID 时不能报告回答已经完成。

### 3.3 反馈、技能顺序和制度预览

反馈值只有 `1=有用`、`0=无用`。Portal 用原始 `fetch` 把会话 token 放在 `c` 查询参数，路径没有 `/admin-api` 前缀且不追加 GET `_t`。Java 当前控制器源码声明的是 POST，和 Portal 的 GET 存在冲突；SDK 保留页面真实请求并在说明中标记为待真实环境核验，不能把请求发出当成反馈已落库。

技能排序弹窗至少勾选 1 个、最多 8 个，不能重复；恢复默认不是保存空数组，而是单独调用 `reset`。保存成功或结果不确定后，应重新调用 `skillOrder` 核对 `skills` 顺序和 `customized`。后端 DTO 允许的数量上限不改变页面的 8 项约束。

制度预览只接收回答动作中的制度 ID，返回 `fileUrl` 等详情字段。Portal 再将 `fileUrl` 交给文件预览组件；SDK 不自动打开 URL、下载文件或绕过制度页面权限。

## 四、操作步骤、失败处理和回查

1. 调 `availableList`，从同一结果选择技能或模型；需要上下文时准备页面原值的意图/模块参数。
2. 用户确认问题、附件和模型/技能后调用 `stream`，逐事件消费 `answer`/`contentItems`，保留最终 `data.id`。
3. 只有用户明确评价时才调用 `feedback`；反馈请求返回成功但未完成真实回查前，不能宣称评价已生效。
4. 技能顺序先调用 `prepareSaveSkillOrder`，展示并让用户确认，再调用 `saveSkillOrder`；恢复默认调用 `reset`。写入后重新调用 `skillOrder`。
5. SSE 错误、自然 EOF、权限/会话失效和接口业务错误均按失败处理；不要因为收到了 HTTP 响应或部分文本就重试整个非幂等聊天请求。
6. 事件中的目标路由、侧栏类型和 `routerParameter` 只作为待处理动作信息；需要执行时调用对应已登记页面能力，并重新遵守目标页的权限、状态和回查规则。
