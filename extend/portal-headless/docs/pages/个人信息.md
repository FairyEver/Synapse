# 个人信息（`/dashboard/me/personal/list`）

本页覆盖 Portal「人力 → 我的信息 → 个人信息」页面及其可达的 `simple/hr/form/025` 编辑流程。它属于提示词保留的 `portal/hr/人力` 范围，不是被排除的独立「生产」系统；SDK 只实现本页可达的员工个人资料读取和个人信息变更流程，不扩展到人员管理页的通用员工 CRUD。

证据边界：已逐页核对菜单、根页面、025 表单、流程打开入口、表单校验、提交字段投影、审批人节点调用和 Java Controller/DTO/服务状态规则，并用离线请求断言锁定关键行为。尚未在真实测试门户执行当前用户/无权限/跨员工 `staffId` 矩阵、读取冒烟或真实 `prepare → submit → 流程回查`；固定 Java 检出中也未发现 Portal 使用的审批人前置接口 HTTP 映射，需在目标部署环境确认网关或其他模块是否提供该路径。

来源锚点：Portal `CodeReview_Projects_Js@test/portal/main@acab69acc77b6d6c0da21310cdfd26b91a01641e`；Java `CodeReview_Mall_Platform_Java@test/test` 固定检出。

## 二、已接入能力

调用门面为 `sdk.mePersonal.<method>`；能力说明由 `catalog.describe(id)` 和 `catalog.describe(id, { format: 'llm' })` 返回。

| 能力 ID | SDK 方法 | 请求/效果 |
| --- | --- | --- |
| `me-personal-get` | `get` | `GET /org/staff/{staffId}`，读取当前员工详情 |
| `me-personal-prepare-edit` | `prepareEdit` | 本地返回 `simple/hr/form/025`、`staff_info_change`、`bpmMode=edit` |
| `me-personal-prepare` | `prepare` | 按 Portal 表单规则构造草稿，`POST /hr/staff-info-change/getRequiredStartUserSelectTasks` 获取节点 |
| `me-personal-submit` | `submit` | 校验审批人选择，`POST /hr/staff-info-change/create` 创建变更单并返回变更单 ID |
| `me-personal-change-get` | `getChange` | `GET /hr/staff-info-change/get?id=...`，回查变更单快照和流程状态 |

不登记本页不可达的员工通用 CRUD，也不把 Java Controller 中存在但本页没有调用的 `update`、`delete`、服务端 `cancel` 暴露为个人信息能力。流程撤回应归属于实际可达的流程/待办页面能力。

## 三、逐字段基准、表单规则和提交链

### 3.1 读取结果和字段归一

`mePersonal.get` 返回 `/org/staff/{staffId}` 的对象，至少保留 Portal 表单会消费的主表字段和明细列表：`name`、`staffCode`、证件/联系方式/学历字段、`entryTime`、`seniorityBeforeEntry`、`entrySeniority`、`totalSeniority`、`staffDuties`、`otherPosts`、`workList`、`educationalList`、`familyList`、`professionalList`、`positionalList`、`contractList`，以及兼职组织相关字段。

读取响应中的 `id` 必须是正整数员工 ID。`staffDuties`、`otherPosts` 在 Portal 详情中是逗号分隔字符串；表单初始化后拆为数组，提交前再分别连接回字符串。普通编辑初始化把 `seniorityBeforeEntry`、`entrySeniority`、`totalSeniority` 做 `Number(value) || 0` 归一，表单的 `watchEffect` 最终按前两项之和重算 `totalSeniority`。SDK 的草稿也固定输出这三个数字，其中 `totalSeniority = seniorityBeforeEntry + entrySeniority`。

Portal 普通编辑初始化把 `result.otherOrganizationInfoList` 放入 `formState.otherOrganizationList`，因此 SDK 的普通草稿同样使用 `otherOrganizationList` 作为提交字段；如果调用方明确传入已编辑的 `otherOrganizationList`，保留该编辑结果。

### 3.2 子表和字段投影

普通编辑提交体来自 `...formState`，因此工作经历、家庭情况、职业资格、职称信息和兼职组织列表保留表单状态中的业务字段。学历列表由 Portal 的固定白名单投影，每项只保留以下 18 个字段，缺失值补 `null`：

```text
startTime, endTime, school, speciality, degree, academicDegree,
educationalSystem, learningStyle, isFullTime, isUnifiedRecruitment,
isHighestDegree, isFirstDegree, degreeFile, academicDegreeFile,
educationType, havingRentalSubsidies, rentalFile
```

合同列表按 Portal 的 `normalizeContractListForSubmit` 处理：`termType = 2`（无固定期限）时删除该项 `endTime`；其他合同保留原字段。创建变更单时，Portal 的 `transformUndefinedToNull: true` 语义由 SDK 归一为 `null`。

### 3.3 页面显式校验

SDK 只复刻 025 表单实际声明的 rules，不把没有 `:rules` 的主表展示字段擅自改成必填。

| 列表 | 校验 |
| --- | --- |
| `educationalList` | `school`、`speciality` 必填，最多 50 字符且不能全为空格；`educationalSystem`、`learningStyle` 最多 50 字符且不能全为空格 |
| `workList` | `companyName`、`department`、`duties`、`salaryRange` 最多 50；`description`、`leaveReason` 最多 200；均不能全为空格 |
| `familyList` | `name` 最多 10；`duties`、`unit`、`education` 最多 50；`mobile` 最多 15；`remark` 最多 200；均不能全为空格；`age` 为整数且最小 1 |
| `professionalList` | `type`、`name` 最多 50；`level`、`code`、`highestLevel` 最多 20；`unit` 最多 50；`remark` 最多 200；文本不能全为空格；非空 `code` 只能数字和字母 |
| `positionalList` | `name` 最多 50；`level`、`reviewMethod`、`code` 最多 20；`unit` 最多 50；文本不能全为空格；非空 `code` 只能数字和字母；`remark` 在 Portal 没有 rules，不能额外校验 |

校验失败在 SDK 本地终止，不能发送审批人节点请求；空列表表示没有该类明细，不表示无权限。

### 3.4 `prepare → submit → 回查` 和取消

1. `get({ staffId })` 读取当前员工详情；只使用当前会话员工 ID，不从任意员工列表推断授权。
2. `prepare({ current, changes })` 合并明确修改字段，执行上述字段归一、白名单投影、合同期限处理和校验，然后 `POST /hr/staff-info-change/getRequiredStartUserSelectTasks`。响应必须是节点数组；空数组表示本次不需要人工选择节点。
3. 用户按每个 `tasks[].id` 选择审批人后，`submit({ draft, tasks, startUserSelectAssignees })` 校验节点 ID、最少/最多人数、重复用户和正整数用户 ID，再 `POST /hr/staff-info-change/create`。请求体为 `{ ...draft, startUserSelectAssignees }`，返回值必须是正整数变更单 ID。
4. create 成功只代表变更单创建受理，不代表员工主数据已经审批生效。使用 `getChange({ id })` 回查 `staffId`、提交字段、`status` 和 `processInstanceId`；审批完成后再用 `get` 核对员工主表。
5. 用户在编辑页取消时丢弃草稿和节点选择，等同 Portal `goBack`，不调用 create，也不调用 `/cancel/{id}`。

固定 Java 检出中的 `StaffInfoChangeController` 有 create/get/cancel 等映射，但没有发现 `getRequiredStartUserSelectTasks` 的 HTTP 映射；Portal 确实调用该路径。SDK 保留 Portal 的真实请求，不以相似接口替换，线上是否由网关或其他模块提供需实测确认。Java 服务静态证据显示 create 后状态为 `SUBMITTED`，同一员工已有提交中变更时会拒绝重复提交；全局登录、租户、页面权限和数据范围裁决不由本页源码单独证明，不能把任意 `staffId` 访问宣称为安全。
