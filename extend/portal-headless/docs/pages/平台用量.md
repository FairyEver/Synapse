## ⚠️ 这一页是 conventions 第 28 条点名的「最易漏」形态

`platform-usage/list.vue` **只有 12 行**，正文是：

```vue
<ModelUsageContent :statistics-dimension="statisticsDimension"/>
```

`statisticsDimension = STATISTICS_DIMENSION.platform`（= **3**）写死在这里。
**整个页面看不到一个 `http` 字样** —— 它把实现交给了
`app/portal/views/dashboard/common/model-usage/` 这个**共享目录**
（个人用量 / 企业用量 / 平台用量三档共用同一批组件，靠 `statisticsDimension` 分流）。

真正的请求在三处：

1. `common/model-usage/api.js` —— **显式** `import { http } from '…/platform.js'`（全部 14 个函数）。
2. `composables/useQuotaList.js:22` 与 `useUsageAnalytics.js:43` ——
   从 `common/libs/renren/list.js` 引 `useListPageModule` 且**不传 `http`** ⇒
   落回 `common/libs/renren/config.js` 的全局默认（`app/portal/main.js:42-48` 注入的正是 platform.js）。
3. `components/ApplyRecordModal.vue:75` 同上。

⇒ **实例结论仍是 `platform`**，但推导路径是「§26 全局默认」+「§28 从 preset/裸 import 引」。

## 逐字段基准（**判据**）

```
GET /admin-api/ai-token/quota-usage/page?quotaCycle=3&statisticsDimension=3&pageNo=1&pageSize=20&_t=<ts>
GET /admin-api/ai-token/quota-usage/summary?quotaCycle=3&statisticsDimension=3&_t=<ts>
GET /admin-api/system/tenant/page?name=&pageNo=1&pageSize=200&_t=<ts>
```

前两条与能力发出的**逐字相同**（断言在 J 组），并证实了三件原先只是推导的事：

1. **`order` / `orderField` 真的不在** —— 这一页的 `customLoad` 走的是
   `buildQuotaQuery({...form, statisticsDimension})`，而那个构造器**按自己的参数表重建对象**
   （`cleanQuery`），列表模块拼上去的 `order`/`orderField` 活不下来。
   ⚠️ 这与本域其它三页**相反**（那三页 `order`/`orderField` 照发），别互相照抄。
2. **`quotaCycle` 初值真的是 3（月）**（额度 Tab 的 `form` 初值 `QUOTA_CYCLE.month`）。
3. `modelName` 初值是 `''` ⇒ 被 `cleanQuery` 丢掉（不是 `null` 那一档，但结果一样不发）。

### 第三条基准是**长选项全量拉取**，本能力刻意不照抄

`fetchTenantList({name: ''})` → `loopFetch(…, { pageSize: 200, maxPages: 100 })` ——
**挂载时翻页拉全租户**（最多 100 页 × 200）。基准里只出现一次（说明测试租户总数 ≤ 200），
但这是**"碰巧一页拉完"**，不代表它不会翻 100 页。

按 conventions 第 11 条，本能力**不照抄**：`tenantId` 做成 `kind:'search'`，
`lookup` 指回 SDK 已有的 `base-tenant-list`。J 组有一条断言锁"本能力一条
`/system/tenant/page` 都不发"。

（`base-tenant-list` 那条是**本地关键字过滤**、不是服务端 `name=`，两者对"取候选"等价；
差别只在请求量 —— 一处是 100×200，一处是它自己的分页策略。）

## 「平台」这一档**没有**申请入口（别照别的档补）

`QuotaTab.vue:128`：`showApplyAction = statisticsDimension !== STATISTICS_DIMENSION.platform`
—— 平台档**刻意不显示**「申请提升」。所以 `POST /admin-api/ai-token/apply/create`
**不属于本页**，本能力没有它。

（「申请记录」按钮是另一回事：它由 `buttonPermissionFlag('ai-token:apply:query')` 控制、
在这一页也会显示，打的是 `apply/page?statisticsDimension=3` —— 那条归到
[模型列表](./模型列表.md) 的 `ai-model-apply-record-list`，接口与参数完全相同，
本页没有为它单开一条。）

## 降级语义：一路失败不拖垮其余（**有意的偏差**）

页面的聚合方式与 SDK 不一样，这里记清楚：

| 场景 | 页面实际做的 | 本能力做的 |
| --- | --- | --- |
| 额度 Tab 挂载 | `Promise.all([fetchQuotaSummaryData(), rrList.logicFetch()])`，**每个 fetcher 自己 try/catch** 把失败吞成空值 | 两个方法各自独立，调用方自己决定 `Promise.all` 还是串行 |
| 用量 Tab 挂载 | `Promise.all([...])`，同上（**每个 fetcher 内部 try/catch**） | `platformUsageAnalytics()` 并发四条 + **各自 settle**，返回 `errors` 记账 |

页面那层 `try/catch` 是"静默吞掉"，本能力**保留"不拖垮其余"的语义但把失败报出来**
（与 `study-statistics.learningSummary` 同一套 `errors` 约定）—— 一次统计查询挂掉
不应该让调用方以为"真的没有数据"。

⚠️ **别把 `usage/{trend,model-ratio}` 当成"只有带 modelId 才发"**：页面的
`fetchUsageSummaryData` / `fetchUsageRankingData` 打的是
`buildUsageQuery({...formState, statisticsDimension})`，而 `formState` **里就有 `modelId`**
—— 所以带 `modelId` 进来时**四条都带它**。`includeBreakdowns: false` 才是"少发三条"的开关。

## 未做 / 未验证

**没做的（有理由，不是漏）**：

1. **`quota-usage/daily-progress` 刻意不做**：`common/model-usage/api.js:4` 有
   `fetchDailyQuotaProgress()`，但后端 `AiTokenQuotaUsageController:85` 把这个映射
   **整行注释掉了**（该控制器现在只有 `/progress` 与 `/open/progress`），
   而页面调用点还带着 `silenceOnError: true` —— 这是个**已经失效且没人发现**的调用。
   conventions 第 28 条的精神：注释掉的东西不算数。
2. **`usage/export`（导出 xls）没做**：`responseType: 'blob'`，不是 JSON 接口；
   而且它在用量 Tab 的导出按钮上，属于"文件下载"而不是数据查询。
3. **`usage/record`（`POST`）没做**：那是**写入侧**（记录一次调用），由网关/服务端调用，
   不是这个页面发的。
4. **`fetchModelDetail`（`/manager/aiModelConfig/get/{id}`）没在这一页单开**：它归
   [模型列表](./模型列表.md) 的 `ai-model-detail`，接口完全相同。

**没验证的**：这一页 6 条能力**全部只读**，且**两条主请求已与基准逐字段对齐**；
但第三条基准（`tenant/page`）与本能力**故意不同**（长选项），所以"页面确实会翻 100 页"
这一点**没有实测**（基准只抓到一次）。用量 Tab 的四条分析接口**基准里没有**
（抓基准时页面停在额度 Tab）⇒ 它们的参数形状是**按源码推导的**，J 组无法覆盖，
只能等一次"带 `?tab=usage` 的抓取"。

### `platform-usage-usage-list`

分页查询模型调用记录，分析Token、扣减、限流和失败原因。

使用：定位某次requestId、某模型/用户的调用；汇总图用analytics。 行为：read。入口：`invoke('platform-usage-usage-list', args)`。

- 平台维度固定3；quotaCycle默认2周、timeRangeType默认2本月。
- requestId是被查询的模型调用编号，不是本SDK写入幂等键；输入Token、输出Token和总Token不能三项相加。

参数：

| 参数 | 类型/格式/条件 | 含义与来源 |
| --- | --- | --- |
| `quotaCycle` | number；1 \| 2 \| 3；可选 | 1日/2周/3月，调用明细默认2周；与额度页默认3月不同；来源：用户需要的额度观察周期；可选值：1=日额度；2=周额度；3=月额度 |
| `timeRangeType` | number；1–5；可选 | 1今日/2本月/3近7天/4近30天/5自定义；默认2；来源：用户选择的调用时间区间；可选值：1=今日；2=本月；3=近7天；4=近30天；5=自定义 |
| `startTime` | string；YYYY-MM-DD 或 YYYY-MM-DD HH:mm:ss；可选 | 自定义起点；纯日期补00:00:00；来源：用户选择的日期 |
