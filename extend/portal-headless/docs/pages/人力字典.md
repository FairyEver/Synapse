# 人力字典（`/dashboard/platform/setting/dict-mall/hr/list`）

## 能力定义

本页属于 Portal 保留范围中的「平台设置 → 平台字典 → 人力字典」，不是独立人力业务菜单。Portal wrapper 为
`app/portal/views/dashboard/platform/setting/dict-mall/hr/list.vue`，共享实现为
`app/portal/views/dashboard/common/setting/dict-platform-mall/all/**`，菜单权限为
`/dashboard/platform-v2/setting/dict-mall/hr`。

SDK 门面为 `platformDictMallHr`，登记与共享页面相同的 11 个动作：类型分页、类型详情、类型新增、类型编辑、类型删除；字典数据分页、详情、新增、编辑、单条删除和批量删除。页面固定使用 `useSystem=1`，调用方不能从本页改写所属系统。

## 参数契约

根列表使用 `platform` HTTP 实例和 `/adminmanage-api/system/dict-type/page`，请求参数为 `order=''`、`orderField=''`、`useSystem=1`、`name=''`、`type=''`、`tenantEditable=undefined`、`pageNo=1`、`pageSize=20`。分页大小只允许 Portal 下拉的 `10/20/50/100`。

类型表单默认 `useSystem=1`、`name=''`、`type=''`、`tenantEditable=0`、`remark=''`、`status=0`；`name`、`type` 必填。SDK 自动注入 `useSystem=1`，显式传入其他系统值会在发请求前拒绝。

字典数据子页沿用当前路由 `dictType`，分页请求为 `/adminmanage-api/system/dict-data/page`；数据表单默认 `id=''`、`dictTypeId=dictType`、`label=''`、`value=''`、`status=0`、`sort=0`、`remark=''`，`label` 和 `value` 在 blur 时必填。保存请求分别使用 `PUT/POST /adminmanage-api/system/dict-data/{update|create}`，并把 bridge 产生的 `dictType` 一并提交。

类型和数据 ID 保留长整数的字符串形态。所有写入只在收到有效回执并完成回查后才能报告成功；权限、平台归属、类型状态和后端校验错误原样抛出。Portal 数据子页批量删除发送 `{ ids }`，而 `ManageDictDataController` 只声明单个 `Long id`，该差异作为独立能力如实暴露，不能假报成功。

## 逐字段基准

- 类型返回保留 `id/name/type/status/remark/createTime/useSystem/tenantEditable`，进入“字典数据”必须使用同一行的 `type`，不能把类型 `id` 当作 `dictType`。
- 数据返回保留 `id/sort/label/value/dictType/status/colorType/cssClass/remark/createTime/tenantId/platform`；平台管理页不按 `platform` 字段提前禁用数据操作，最终可写性由平台服务归属校验决定。
- `ManageDictTypeController` 提供类型 create/update/delete；类型服务校验记录存在、名称/类型唯一和子数据约束。`/admin-api` 的租户 Controller 是另一套接口，不适用于本页。
- 平台管理数据服务查询和写入固定使用 `tenant_id=0`，创建校验类型启用，更新/删除校验平台归属。

## 操作步骤

1. 先调用 `platformDictMallHr.typeList`，保留返回行的 `type`、`id` 和完整字段；页面自动固定 `useSystem=1`。
2. 点击“字典数据”时把该行 `type` 传给 `dataList`；不要猜测类型代码，也不要传类型主键。
3. 新增、编辑或删除前先读取当前详情/列表，写操作完成后按原 `dictType` 分页回查；超时先核实，不要盲目重试。
4. 若后端返回权限、平台归属或协议错误，报告失败及原始错误；批量删除尤其不能把 `ids` 请求当成单 ID 删除已经成功。
