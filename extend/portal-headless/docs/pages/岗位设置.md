# 岗位设置（`/dashboard/post/post-setting/list`）

Portal「人力 → 岗位管理 → 岗位设置」包含目录树分页、名称搜索、详情/编辑、新建岗位或目录、敏感删除、薪资等级候选、模板下载、自定义导出、新增导入和导入更新。本页只登记 Portal 当前页面实际可达的接口；Java Controller 中存在但页面未调用的接口不作为本页能力。

## 2. 参数契约与表单提交规则

### 列表

Portal 的 `customLoad` 逐字构造以下请求：

```json
{
  "parentId": 0,
  "keyword": "",
  "dataType": "仅在keyword非空时为2",
  "selection": false,
  "pageNo": 1,
  "pageSize": 20
}
```

`templateName` 先 `trim`。关键字为空走 `GET /org/hrpost/treePage`，非空走 `GET /org/hrpost/searchPage` 并固定 `dataType=2`；`parentId` 缺省按页面发送 `0`；`pageSize` 最大为 `100`。Portal 把每行直接的 `children` 删除后交给表格，SDK 保持这一行为。跨层搜索返回的 `ancestorPath` 用于解释目录路径，不能因为没有 `children` 就断言没有下级。

列表行的 `dataType` 为 `1` 时表示目录，可用其 `id` 继续查询下级；为 `2` 时表示岗位，可进入详情、编辑、导出或删除。`postTypeName`、薪资等级 ID 和目录路径是展示/后续操作所需的字段，名称不能反向当作 ID。

### 详情、新建和编辑

详情把后端 `postType` 数组 `join(',')` 成页面表单字符串；后端父级字符串 `"0"` 按页面规则归一为 `null`。页面表单默认值为：`roleIdList=[]`、`parent=null`、`name=''`、`postType=''`、`dataType=1`、`gender=2`、薪资上下限为 `null`，五个文本字段为空字符串。

| 字段 | Portal 规则 | 请求语义 |
| --- | --- | --- |
| `name` | 必填、不能全为空格、最多 50 个字符 | 岗位或目录名称 |
| `postAssignment` / `educationalRequirement` / `experienceRequirement` / `abilityRequirement` | 可空；有值时不能全为空格，最多 500 个字符 | 原样文本 |
| `remark` | 可空；有值时不能全为空格，最多 200 个字符 | 原样备注 |
| `dataType` | 页面值为 `1` 或 `2` | `1=文件夹`、`2=岗位` |
| `gender` | 页面值为 `0`、`1` 或 `2` | `0=男`、`1=女`、`2=无要求` |
| `parent` | 根目录为空；详情返回字符串 `"0"` 时归一为 `null` | 上级目录 ID |
| `postType` | 页面值是逗号分隔字符串 | 提交时严格执行 `form.postType?.split(',') || []`；空字符串会得到 `[""]` |
| `salaryLevelMin` / `salaryLevelMax` | 可空；两者都能在薪资候选中找到时按排序比较 | 提交薪资等级 ID |
| `salaryLevelMinName` / `salaryLevelMaxName` / `salaryLevelName` | 仅 UI 展示 | 提交前删除 |

新建和编辑都调用同一个 `POST /org/hrpost/save`。新建草稿不带 `id`；编辑必须保留详情中的 `id`，后端据此进入更新分支。编辑以最新 `get` 结果为基准，非页面 UI 字段原样保留，`changes` 只允许覆盖页面表单字段。

薪资候选按页面 `sort` 升序排列；缺少排序值的记录放在末尾。只有上下限 ID 都在候选中时才检查顺序；下限排序位置大于上限时，Portal 阻止提交。候选读取失败或 ID 不在候选中时，SDK 不伪造该范围校验，后端仍会最终校验。

### 删除、权限和文件

- 删除前先发送裸 ID 数组到 `/org/hrpost/checkCanDelete`；子节点、组织占用等后端保护失败时不能继续。
- Portal 的敏感操作配置来自 `/org/sensitive/info`。需要保护时先向配置手机号发送模板 `17709` 验证码，再以用户提供的 `code` 和 `requestId` 调用 `/sys/sms/checkSms`；校验返回 `ret=SUCCESS` 后才发送删除请求。
- `/org/hrpost` 删除请求体是裸 ID 数组，不是 `{ ids }`。删除没有页面恢复接口，成功或超时后必须列表回查。
- 模板和自定义导出均按二进制文件返回，SDK交付文件名、MIME、字节数和标准 Base64；Base64 由调用方保存。
- Portal 两个上传控件只接受 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`；SDK 不因 Java 兼容能力而放宽到 `.xls` 或其它 MIME。
- 新增导入的根目录 `parentId` 按 Portal 发送 `null`；两个上传接口都使用 multipart 字段 `file`。

## 4. 操作步骤与未覆盖项

1. `list` 读取当前目录；需要完整编辑字段时用 `get({ id })`，薪资范围校验使用 `salaryLevels()` 的结果。
2. 新建使用 `prepareCreate → create`；编辑使用最新详情 `get → prepareUpdate → update`。用户取消时只丢弃草稿，不调用提交能力。
3. 删除使用 `prepareRemove`；需要短信时依次执行 `sendDeleteCode → remove`，无需短信时确认后直接 `remove`。完成或超时后都按 ID/父目录回查。
4. 导入使用 `prepareImport → importFile` 或 `prepareImportUpdate → importUpdate`；取消只丢弃文件预览，不上传。导入完成或超时后按文件中的岗位标识回查列表和详情。
