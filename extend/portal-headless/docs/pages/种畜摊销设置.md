## Portal 页面行为

列表使用 `styleV2: true` 和 `customLoad`，初始表单为：

```json
{
  "status": 1,
  "generations": [],
  "breeds": [],
  "lines": []
}
```

`useListPageModule` 还会追加 `order`、`orderField`、`pageNo`、`pageSize`；默认请求体逐字段为：

```json
{
  "order": "",
  "orderField": "",
  "status": 1,
  "generations": [],
  "breeds": [],
  "lines": [],
  "pageNo": 1,
  "pageSize": 20
}
```

页面支持页大小 `10/20/50/100`。可见列为代次、品种、品系、鸡群状态、种摊计提方法、计提种摊日龄、计提种摊日龄系数、种摊提取天数、净残值率、更新时间和操作列。状态筛选是绝对数值：`1=启用`、`0=停用`。

操作列只根据 `record.status` 和 `finance:setting:livestock-amortization:status` 显示“启用/停用”。新建按钮受 `finance:setting:livestock-amortization:create` 控制。当前列表没有跳转编辑或导出动作。

## 表单提交规则

新建表单默认字段为：

```json
{
  "generation": null,
  "breed": null,
  "line": null,
  "depreciationMethod": "1",
  "accrualAgeDays": null,
  "accrualAgeCoefficient": null,
  "accrualMaxDays": null,
  "netSalvageRate": null,
  "flockStatus": null
}
```

代次、品种、计提种摊日龄、计提种摊日龄系数、种摊提取天数和净残值率有必填规则；代次、品种和品系对应Java的最多100字符限制；种摊提取天数和计提种摊日龄为最小0的整数；净残值率为最小0且不能大于1。品系、计提方法和鸡群状态没有必填规则，计提方法控件禁用且默认字符串`1`。

Portal `customSubmit` 展开整个表单，并只对四个数字字段执行 truthy 转换：

```json
{
  "accrualAgeDays": "form.accrualAgeDays ? +form.accrualAgeDays : null",
  "accrualAgeCoefficient": "form.accrualAgeCoefficient ? +form.accrualAgeCoefficient : null",
  "accrualMaxDays": "form.accrualMaxDays ? +form.accrualMaxDays : null",
  "netSalvageRate": "form.netSalvageRate ? +form.netSalvageRate : null"
}
```

因此数字字符串`"0"`会发送数字`0`，数字`0`则会按源码发送`null`；SDK测试锁定该边界。Java创建服务默认把状态设置为启用，并按代次、品种、品系、鸡群状态和启用状态检查重复配置。

表单监听净残值率或种摊提取天数，按`(1 - 净残值率) / 种摊提取天数`计算日龄系数；提取天数不大于0或结果不大于0时回填`null`。这是本地计算，不代表服务端已保存。

## 权限与后端规则

- 页面权限为`/dashboard/finance/setting/livestock-amortization`。
- 新建使用`finance:setting:livestock-amortization:create`；启停使用`finance:setting:livestock-amortization:status`。
- 当前页面没有编辑、删除、导出按钮；不能因Java存在`/update`或`/export-excel`就绕过页面动作扩展SDK。
- Java保存VO对代次、品种使用`@NotBlank`和最多100字符，对品系使用最多100字符；数值字段在Schema中标为必填，但当前源码未为这些数值加Bean Validation，最终以服务端实际校验为准。
- Java创建默认`status=1`；启用配置按代次、品种、品系、鸡群状态检查重复。状态接口要求`id`和`status`为请求参数，但Portal把它们包在Axios PUT第二参数的`params`属性中，实际请求体为`{params:{id,status}}`；SDK按Portal实际请求形状发送，并将该静态冲突列为风险，不能把离线回执称为线上成功。
- 页面和SDK使用`platform`实例，module-type按页面推导为null；凭据、租户、最终权限和数据范围由会话及后端裁决。

## 后端与 SDK 对齐

Java `BiologicalAssetDepreciationConfigController` 的 page、get、create、update-status与页面实际可达动作逐项登记；`update`和`export-excel`仅作为静态反证保留，不注册为当前页面能力。SDK保留长ID、Decimal原值、列表POST体、表单数字转换、创建默认字段、启停body.params形状和本地公式；不伪造当前页面没有的编辑/删除/导出能力。
