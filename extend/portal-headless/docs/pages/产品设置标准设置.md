# 产品设置标准设置

页面路径：`/dashboard/product/setting/hatch-manage/unit/list`。

菜单归属是 `系统设置 → 生产设置 → 养殖预案 → 标准设置`。这里的“生产设置”是系统设置内的 Portal 子菜单，不是范围外的独立生产业务菜单。

## 页面能力定义

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询标准设置 | `product-setting-hatch-manage-unit-list` / `productSettingHatchManageUnit.list` | `GET /programUnit/getList` |
| 准备新建 | `product-setting-hatch-manage-unit-prepare-create` / `productSettingHatchManageUnit.prepareCreate` | 本地表单校验，不发请求 |
| 新建 | `product-setting-hatch-manage-unit-create` / `productSettingHatchManageUnit.create` | `POST /programUnit/add` |
| 准备编辑 | `product-setting-hatch-manage-unit-prepare-update` / `productSettingHatchManageUnit.prepareUpdate` | 本地表单校验，不发请求 |
| 编辑 | `product-setting-hatch-manage-unit-update` / `productSettingHatchManageUnit.update` | `POST /programUnit/update` |
| 准备删除 | `product-setting-hatch-manage-unit-prepare-remove` / `productSettingHatchManageUnit.prepareRemove` | 本地确认前准备，不发请求 |
| 删除 | `product-setting-hatch-manage-unit-remove` / `productSettingHatchManageUnit.remove` | `GET /programUnit/delete?id=...` |

请求使用 `product` HTTP 实例，补 `devicetype=PC`；本页没有页面推导出的 `module-type`，因此不发送该请求头。菜单权限是 `/dashboard/frame/breeding-plan/unit`；查询、提交、删除权限分别是 `program:unit:query`、`program:unit:submit`、`program:unit:delete`。SDK只复刻页面请求，不绕过服务端权限。

## 参数契约与提交规则

列表表单字段是 `classification`（指标归类）、`search`（指标名称），并固定发送 `scope=1`。指标归类候选来自Portal全局平台字典 `standard_class`，不是本页单独请求。公共列表模块加入 `order=""`、`orderField=""`、`pageNo` 和 `pageSize`；styleV2默认每页20条，页面支持10、20、50、100。页面首次自动加载可能在归类为空时发送空字符串，SDK保留这一实际请求形状。

新建和编辑表单的归类、文本类型、名称、编码全部必填。文本类型只有三种：`1` 纯文本、`2` 富文本、`3` 数值。只有 `contentType=3` 时，单位和小数位数才进行必填校验并提交用户值；纯文本和富文本会把 `unit`、`scale` 固定提交为空字符串。Java `ProgramUnitLayController`在新增和更新时也会拒绝数值类型缺少 `scale` 的请求，并按 `code` 检查重复。

Portal编辑提交对象先展开当前行 `raw`，再覆盖 `id`、`classification`、`contentType`、`name`、`code`、`unit`、`scale`，因此SDK保留列表行扩展字段。新建表单状态的 `id` 初始为 `undefined`，JSON序列化时不会发送id。

删除是GET并只发送当前列表行的 `id`，后端将ProgramUnit软删；不能改成DELETE。

## 逐字段基准

| 字段 | 含义 |
| --- | --- |
| `list` | 当前归类、名称筛选和分页下的ProgramUnit标准设置记录；后端分页或前端保留的直接数组响应都可转换为此形状。 |
| `total` | 当前筛选条件下的总数；直接数组响应时等于数组长度。 |
| `list[].id` | ProgramUnit记录ID；编辑和删除目标。 |
| `list[].classification` | 指标归类原始字典值；编辑回填字段。 |
| `list[].traitTypeName` | 指标归类展示名称；表格第一列。 |
| `list[].name` / `code` | 指标名称 / 指标编码；新建和编辑都必填。 |
| `list[].unit` | 指标单位；数值类型使用。 |
| `list[].contentType` | 文本类型数值：1纯文本、2富文本、3数值；页面本地映射展示。 |
| `list[].contentTypeName` | 后端可能提供的类型展示扩展字段；页面当前不依赖它。 |
| `list[].scale` | 数值类型小数位数；非数值类型可能为空。 |
| `prepareCreate().draft` | 已通过条件表单校验、尚未发送请求的新建ProgramUnit对象。 |
| `prepareUpdate().draft` | 已按Portal raw透传和字段覆盖规则整理、尚未发送请求的编辑对象。 |
| 写操作结果 `true` | 请求未抛错的本地确认，不代表服务端已按预期落库。 |

## 操作步骤、权限和证据边界

1. 使用当前用户会话和租户上下文调用 `list()`；需要筛选候选时先读取 `standard_class` 字典。
2. 新建时调用 `prepareCreate()`，经用户确认后把同一份 `draft`交给 `create()`；取消只丢弃本地草稿。
3. 编辑时把最近一次列表行与用户修改结果交给 `prepareUpdate()`，经用户确认后把同一份 `draft`交给 `update()`；取消不发请求。
4. 删除前调用 `prepareRemove()`，明确获得用户确认后再调用 `remove()`；取消不发GET。
5. 新建、编辑或删除成功、失败或响应不确定后，都重新调用 `list()`回查；不能只依据 `true`宣布业务状态已改变。

本轮逐页核对了Portal菜单、路由、列表、弹窗、公共分页、product响应解包，以及Java `ProgramUnitLayController`、`ProgramUnit`实体和 `ProgramUnitMapper.xml`。当前没有真实测试环境浏览器会话的列表/新建/编辑/回查/删除闭环证据。
