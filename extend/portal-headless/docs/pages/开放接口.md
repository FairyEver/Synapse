# 开放接口（`/dashboard/platform/intelligence/prompt/interface/list`）

> 这一组的**共享机制**（三页都落默认 `platform` 实例、都**不发** `module-type`、
> 三页参数装配各不相同在哪、写链路 `prepare → submit → cancel` 怎么分）
> 写在 [`src/capabilities/ai-prompt-tool.ts`](../../src/capabilities/ai-prompt-tool.ts) 的文件头，
> 这里只记这一页自己的东西。

| 项 | 值 |
| --- | --- |
| 菜单路径 | `/dashboard/platform/intelligence/prompt/interface/list` |
| 权限码 | `/dashboard/platform/intelligence/prompt/interface` |
| 路由文件 | `app/portal/views/dashboard/platform/intelligence/prompt/interface/list.vue` |

## ⚠️ 权限码这一页在 v2 菜单里**没有** `platform-v2` 前缀

`app/portal/menus/mall.v2.js:232`：

```js
{ title: '开放接口', path: '/dashboard/platform/intelligence/prompt/interface/list',
  permission: '/dashboard/platform/intelligence/prompt/interface' },
```

这是**如实**的一条 —— 同组的「业务事件绑定技能」「工具提示词绑定」在 v2 菜单里都带 `platform-v2`，
只有它不带。页面自己的 `<route>` 块里**根本没有 `permission`**，所以能力定义取的是目录
（`generated/page-catalog.json`）里那一条，与菜单逐字相同。

## `api.js` 里 URL 是拼接的常量，先展开

```js
export const OPEN_API_REGISTRY_CREATE_URL = '/admin-api/system/openApiRegistry/create'
export const OPEN_API_REGISTRY_UPDATE_URL = '/admin-api/system/openApiRegistry/update'
export const OPEN_API_REGISTRY_PAGE_URL   = '/admin-api/system/openApiRegistry/getByPage'   // ← 不叫 /page
export const OPEN_API_REGISTRY_DETAIL_URL = '/admin-api/system/openApiRegistry/get'
export const OPEN_API_REGISTRY_DELETE_URL = '/admin-api/system/openApiRegistry/delete'
export const OPEN_API_REGISTRY_SCAN_URL   = '/admin-api/system/openApiRegistry/scanByUrl'
```

四处**容易照抄错**的地方：

1. **列表叫 `getByPage`**，不叫 `/page`（`OpenApiController` 的 `@GetMapping("/getByPage")`）。
2. **详情的 id 在路径上**：`` http.get(`${DETAIL_URL}/${id}`) `` ⇒ `/admin-api/system/openApiRegistry/get/5`
   —— URL 上**一个 query 参数都没有**（只有拦截器补的 `_t`）。
3. **删除路径与 query 都带 id**：`` http.delete(`${DELETE_URL}/${record.id}`, { params: { id: record.id } }) ``
   ⇒ `DELETE …/delete/5?id=5`。后端 `@DeleteMapping("/delete/{id}")` 只读 `@PathVariable`，
   query 上那个它**不看** —— 但浏览器确实两个都发，SDK 忠实复刻（D20）。
   （对比：同组的业务事件 / 工具提示词绑定都只带 query。）
4. **扫描接口的参数顺序是 `baseUrl` → `url`**（页面里 `params: { baseUrl, url }`），
   与后端方法签名（`@RequestParam String url` 在前）**相反** —— 对象键序就是 URL 上的顺序。

另外 `create` / `update` 都写了 `http.post(url, body, { useJsonPost: true })`：
**`useJsonPost` 只被 `zhdj-app-lay.js` / `zhdj-cms.js` 的拦截器消费，`platform.js` 不看它**
（`grep -rn useJsonPost` ：消费它的只有那两个文件，引用 `platform` 的这些页面里它是个空开关）—— 那是个空开关，
请求体本来就是 axios 默认的 JSON。SDK 不复制这个 flag。

## 列表：键序（源码推导，等基准复核）

`customLoad` 直接就是 `getOpenApiRegistryPage`，它逐个挑四个字段：

```js
{ pageNo, pageSize, name, status: normalizeStatusForQuery(form.status), enabled: normalizeEnabledForQuery(form.enabled) }
```

⚠️ **与业务事件那一页相反**：`name` 是**原样传**（表单初值 `''` ⇒ `name=` **照发**），
只有 `status` / `enabled` 会在 `'' || == null` 时变成 `undefined` 被 `qs` 丢掉。所以无筛选时是：

```
GET /admin-api/system/openApiRegistry/getByPage?pageNo=1&pageSize=20&name=&_t=<ts>
```

`name` 后端是**前缀匹配**（手写 SQL：`AND name LIKE CONCAT(#{params.name}, '%')`，
`OpenApiMapper.xml:97-99`）—— ⚠️ 与同组「业务事件绑定技能」那页的 `eventName`（MyBatis-Plus
`likeIfPresent` ⇒ **包含**）**正好相反**；`status` / `enabled` 是等值。
`apiPath`（前缀）与 `groupName`（等值）后端也支持过滤，但**页面没有这两个控件**，能力里没登记。
排序写死 `update_time desc`。

## 写链路：三个写动作，两个能撤

| 动作 | 能力 | 请求 | 撤销 |
| --- | --- | --- | --- |
| 注册 | `-create` | `POST …/create` | 走 `-remove`（create 返回 `success(null)`、**不回传 id**） |
| 修改 | `-update` | `POST …/update` | `cancel` 把 GET 到的那份重算写回 |
| 删除 | `-remove` | `DELETE …/delete/{id}?id={id}` | ⚠️ **撤不回**（逻辑删除、无恢复接口）⇒ `cancel` 抛 |

请求体的键序逐字抄 `buildOpenApiRegistryCreatePayload`：

```
{ name, apiPath, httpMethod, scopeKey, groupName, description,
  responseExample, sort, status, enabled, params }        ← update 时 id 追加在最后
```

三处细节别改：

- **`sort` 是字符串**：`String(form.sort || '')`（后端字段是 `Integer`，数字字符串能被 Jackson 收下，
  空串会被当成 null）。表单初值是 `'1'`。
- **`required` 是字符串 `'true'`/`'false'`**（后端 `OpenApiParamVO.required` 是 `Boolean`，
  Jackson 把 `"true"` 转成 `true`）。
- **参数树的 `sort` 按同级下标重排**成 `'1','2',…`，不是保留调用方给的顺序值；
  空节点被 `hasParamValue` 丢掉。

⚠️ 还有一条**只在前端**的规则：`prepare` 会跑页面的 `validateParamTree`。
编辑器新建出来的空行**默认就带 `position: 'query'`**，而 `hasParamValue` 把 `position` 也算作"有内容"
⇒ 留着没填完的空行**存不下去**（页面报"参数存在未填写完整的参数"）。SDK 搬了同一条，
不然会发出一个页面上根本发不出去的请求。

⚠️ 删除按钮还有一条**只在前端**的拦截：`record.isBound` 为真时按钮是删不动的
（"该接口已被提示词绑定，无法删除"），**后端没有这条校验**。SDK 如实透传、不做预检查
（预检查要另打一次列表/详情，而且查完也不保证删的时候还没被绑）。

## 两条**明确不进能力**的东西

### 1. `buildOpenApiRegistryMarkdown()`（`interface/markdown.js`）—— 纯前端渲染，**不是请求**

它把一条接口详情渲染成"写给 LLM 调用"的 Markdown：基本信息 / 请求 / Headers·Path·Params·Body
四张参数表 / 返回示例 / curl 示例。页面在「复制 → Markdown」里调它，然后 `navigator.clipboard.writeText`。

**它一个请求都不发**（连 `getOpenApiRegistryDetail` 都是调用方先取的）。按"能力 = 页面上的一个接口"
这条口径，它**不进能力**。要把它变成能力，得先决定"把一个渲染函数搬进 SDK"算不算能力 ——
那是另一个决策（`docs/design.md` 的 F2 提到过它的定位），不在本轮范围。

### 2. 接口的「测试」按钮（`interface/share.js` 的 `testInterface`）—— 裸 axios，**不是 Portal 接口**

```js
const response = await axios.request({ url: buildTestUrl(form.apiPath, params.path), method: httpMethod, … })
```

- `url` 是**用户在表单里填的 `apiPath`** —— 可以是**任意地址**，不经过 platform 实例、
  不补 `/admin-api`、不带租户与 token 头；
- method / params / headers / body 全部由表单的参数树决定；
- 它**有副作用**：`testAndSyncOpenApiRegistry` 会把测试结果（`status` / `responseExample`）
  **写回接口详情**（`updateOpenApiRegistry`）—— "点一下测试"是一次**真写**。

把它做成能力等于给无头开一个"向任意地址发任意请求"的口子，而且它本身不是 Portal 的接口。
真要做，应该拆成 `prepareTest`（只测、**不写回**）/ `submitTestResult`（写回）两步 —— 本轮不做。

## 基准（`baseline/ai-prompt-tool.browser.json`，2026-09-21 抓到）

这一页在基准里有**三条**请求，其中**只有一条是页面自己发的**：

| 请求 | 是谁发的 |
| --- | --- |
| `GET /admin-api/org/sensitive/info` | ❌ **不是这一页** —— app 外壳的全局敏感词检查，跟着每页一起被抓进来 |
| `GET /admin-api/bpm/task/list-by-category?finished=1&pageNo=1&pageSize=10` | ❌ **不是这一页** —— 外壳的待办角标 |
| `GET /admin-api/system/openApiRegistry/getByPage` | ✅ 这一页的列表请求 |

三条列表契约**全部与源码推导逐字段相符**（含键序），**没有冲突**：

```
GET /admin-api/system/openApiRegistry/getByPage?pageNo=1&pageSize=20&name=&_t=<ts>
```

另外基准给了一条**浏览器实测**（不再是推断）：`headers` 里只有
`Accept` / `Accept-Language` / `tenant-id` / `token` —— **没有 `module-type`**，
与"规则表里匹配不到就不发"完全一致（conventions 2 / D34）。

**基准是什么、不是什么**：这一轮**全是只读 GET**（一个写请求都没发），所以
`get` / `create` / `update` / `delete` / `retry` 的形状**仍然只有源码 + 后端代码两份证据**，
没有浏览器证据。别把"列表对上了"读成"这一页整页都验过了"。

### 基准**没有**覆盖的（仍然只有源码 + 后端代码两份证据）

1. `name` 的**匹配语义**：基准里 `name=` 是**空的**，所以它只能证明"空串照发"，
   **证明不了**"前缀匹配" —— 前缀这条的证据是后端手写 SQL（`OpenApiMapper.xml:97-99`
   的 `AND name LIKE CONCAT(#{params.name}, '%')`），属于**后端代码证实**，不是基准证实；
2. 请求体的键序与 `sort`/`required` 的类型（字符串）；
3. `DELETE …/delete/{id}?id={id}` 的双 id 形态；
4. `create` / `update` 的 `Content-Type`；
5. `scanByUrl` 的 `baseUrl`/`url` 顺序与形状。

### ① 只读冒烟（风险：无）

| # | 请求 | 前置条件 | 期望 |
| --- | --- | --- | --- |
| 1 | `GET /admin-api/system/openApiRegistry/getByPage?pageNo=1&pageSize=20&name=&_t=<ts>` | 账号能进这一页 | `ret=SUCCESS`、`data={total,list}`（**注意键名是 `total` 在前**，`PageData`） |
| 2 | `GET …/getByPage?…&name=<某个接口名的前缀>&_t=` | 注册表里有数据 | 只回前缀命中的那些；空 `name=` 与不带 `name` 结果**应当一致** |
| 3 | `GET /admin-api/system/openApiRegistry/get/<某个已存在的 id>?_t=<ts>` | 有 id | `ret=SUCCESS`，含 `params` 参数树、`status`、`enabled` |
| 4 | `GET /admin-api/system/openApiRegistry/scanByUrl?baseUrl=https://biz-api-test.wodecorp.cn&url=agreement&_t=<ts>` | 无 | `ret=SUCCESS`、返回一批 `{name,httpMethod,apiPath,groupName}`；匹配不到时返回**业务错误**"未找到匹配的接口"（不是 500 空数组） |

顺便核对：`/admin-api` 只出现一次；请求头里没有 `module-type`。

### ② 真写一轮：注册 → 撤销（风险：**中**）

⚠️ 这一条写进的是**开放接口注册表**（`system_open_api`），那是「个人令牌 scope 白名单」的数据源。
所以测试数据必须：**`enabled = 0`（不开放）**、名字带 `SDK-TEST-`、`scopeKey` 用一个不会撞的假值、
**同一轮内删掉**。

- **prepare**：`prepareCreate({ name: 'SDK-TEST-开放接口-<YYYYMMDDHHmm>', apiPath: '/admin-api/sdk-test-probe', httpMethod: 'GET', scopeKey: 'sdk:test:probe', groupName: 'SDK测试', description: 'SDK 验证用，可删', sort: 0, status: 0, enabled: 0, params: [] })`
  - 期望：**不发请求**；`httpMethod` 建议先调 `base-dict-get(dictType='open_api_http_method_type')` 确认候选里有 `GET`
- **submit**：`POST …/create`，body 的 11 个键按上面那个顺序
  - 期望 `ret=SUCCESS`（`msg` 是"新建成功"）；**响应里没有新 id**
- **确认存在**：`getByPage?…&name=SDK-TEST-开放接口-<YYYYMMDDHHmm>` → 取到 `id`
- **撤销**：`prepareRemove(id)` → `submit` → `DELETE …/delete/<id>?id=<id>`
  - 撤销后**再查一次列表**确认为空

### ③ 真写一轮：修改 + 撤销（风险：**中**，⚠️ **会改到已有数据** —— 只拿②里那条自建记录跑**）

- 用②里那条自建的记录（**不要**动真数据）：`prepareUpdate({ id, description: 'SDK-TEST-改过的描述' })` → `submit`
  - 期望：`prepare` 那次 `GET` 到的 `params` 树被原样带进 body（`sort` 会被重排成 `'1','2'…`）
- **撤销**：`cancel(plan)` → `POST …/update`
  - 撤销后再 `GET` 一次，`description` 回到"SDK 验证用，可删"

### ④ 参数树的往返要单独看一眼（风险：无）

- 拿一条**真实的**接口（如 ③ 改的那条）跑 `prepareUpdate({ id })`（只给 id），
  比对 `plan.request.data.params` 与 `GET` 回来的 `params` 的**条数**：
  - 若条数变少，说明有节点被 `hasParamValue` 丢掉 —— 那是**预期行为**（页面也这么丢），
    但要确认丢掉的确实是空节点；
  - 若 `prepare` 抛"参数存在未填写完整的参数"，说明**库里真的存着**一条填不完整的参数
    （那是历史数据，页面今天打开这一条也存不回去）—— 如实记下来，`SDK` 不替它兜底。

### ⑤ **不要跑**（本清单里明确排除）

- 「测试」按钮那条（`testInterface`）：**裸 axios 打到用户填的任意地址** + 把结果**写回详情**，
  两个理由都不该在验证轮里跑。
- 「复制 → Markdown」：纯前端剪贴板，与后端无关。

### ⑥ 撤销不了时怎么收尾

- 注册成功但 `delete` 失败：**留着**并给出 `id` + `name`，由派单方删；
  ⚠️ 这一条要**优先**收尾（注册表里多一条 `enabled=1` 的记录会影响个人令牌的可选范围；
  我们要求 `enabled=0` 就是为了把影响压到最小）。
