# 平台设置 → 安全配置

## 能力定义

- Portal 页面：`/dashboard/platform/system/security-config/list`
- 菜单权限：`/dashboard/platform-v2/system/security-config`
- HTTP 实例：`platform`
- `module-type`：页面不发送；SDK 也不注入
- 后端根路径：`/adminmanage-api/adminmanage/platform-config`

这是提示词保留的「平台设置」子树页面，不是独立的生产业务页面。Java 后端把配置保存在平台级 `system_platform_config` 表中；本页不擅自增加租户筛选。

SDK 能力：

| 能力 | SDK 方法 | 写入 | Portal 对齐规则 |
| --- | --- | --- | --- |
| `platform-system-security-config-list` | `platformSystemSecurityConfig.list()` | 否 | 查询后归一为五个固定分组 |
| `platform-system-security-config-prepare-update-values` | `prepareUpdateValues(configs)` | 准备 | 只生成当前分组的完整值数组 |
| `platform-system-security-config-update-values` | `updateValues(configs)` | 是 | `PUT /update-values`，提交整组 |
| `platform-system-security-config-prepare-create` | `prepareCreate(form)` | 准备 | 只生成新增字段投影 |
| `platform-system-security-config-create` | `create(form)` | 是 | `POST /create`，返回新 ID |
| `platform-system-security-config-prepare-update` | `prepareUpdate(form)` | 准备 | 只生成元数据字段投影 |
| `platform-system-security-config-update` | `update(form)` | 是 | `PUT /update`，不修改 `configValue` |
| `platform-system-security-config-prepare-remove` | `prepareRemove(record)` | 准备 | 仅 `isBuiltin=false` 可准备 |
| `platform-system-security-config-remove` | `remove(record)` | 是 | `DELETE /delete?id=...`，不可恢复 |

## 参数契约

列表返回对象只包含以下五个数组：`identity_auth`（身份鉴别）、`session_mgmt`（会话管理）、`intrusion_prevention`（入侵防范）、`audit`（审计）、`cryptography`（密码学）。未知服务端分组不向调用方暴露；每行包含：

`id`、`configKey`、`configName`、`configGroup`、`valueType`、`configValue`、`defaultValue`、`optionsJson`、`description`、`isBuiltin`、`sort`、`remark`、`updateTime`。

ID 保留字符串形态，避免 Java Long 超出安全整数后被改写。组内排序复刻 Portal 的 `sort` 后 `Number(id)` 比较；超出 JavaScript 安全整数时可能比较为相等，此时保留服务端返回顺序。排序不会改写 ID。

`updateValues(configs)` 的 `configs` 必须是当前分组完整数组，每项只含：

```json
{ "id": "配置ID", "configValue": "字符串值" }
```

空字符串必须保留。`BOOLEAN` 使用 `true`/`false` 字符串，`INTEGER` 使用整数文本，`MULTI_CHOICE` 使用 JSON 数组字符串；最终值类型和选项合法性由 Java 服务端再次校验。

`create(form)` 的字段投影为：`configKey`、`configName`、`configGroup`、`valueType`、`configValue`、`defaultValue`、`optionsJson`、`description`、`sort`、`remark`。`configGroup` 必须由调用方从当前 Portal `activeGroup` 显式传入，SDK 不猜测当前分组。Portal 新建表单的其他默认值按 `valueType` 联动：

- `BOOLEAN`：当前值/默认值 `false`，选项 `null`
- `INTEGER`：当前值/默认值 `0`，选项 `null`
- `STRING`：当前值/默认值空字符串，选项 `null`
- `SINGLE_CHOICE`：当前值/默认值空字符串，选项 `[]`
- `MULTI_CHOICE`：当前值/默认值 `[]` 字符串，选项 `[]`

缺省排序为 `99`，缺省说明和备注为空字符串。页面只在提交前检查配置键、配置名称非空；后端还会校验配置键为小写点分格式、配置键唯一以及值与 `valueType/optionsJson` 匹配。SDK 不把后端规则伪装成页面本地校验。

`update(form)` 只提交：`id`、`configKey`、`configName`、`configGroup`、`description`、`sort`、`remark`。它不携带 `configValue`，值修改必须调用整组保存能力。

`remove(record)` 必须传同一 `list()` 结果中的 `id` 和 `isBuiltin`。`isBuiltin=true`、缺省或不明确时，SDK 在发请求前拒绝；后端也会再次拒绝删除内置项。

## 逐页基准与操作步骤

1. 调用 `list()`，从目标固定分组取得完整行数组和原始 ID。
2. 修改值时只在本地构造该分组完整 `configs`；先调用 `prepareUpdateValues` 查看请求体，再由用户确认后调用 `updateValues`。
3. 创建时按 `prepareCreate → create`；成功或超时后重新 `list()`，用完整 `configKey/configName/configGroup/valueType` 回查唯一记录。
4. 编辑元数据时按 `prepareUpdate → update`；成功或超时后重新 `list()`，确认同一 ID 的元数据变更且 `configValue` 未被改写。
5. 删除时只能对当前列表中的自定义行按 `prepareRemove → remove`；成功或超时后重新 `list()`，确认目标 ID 已消失。
6. Portal 只有本地“重置本组/放弃修改”，没有服务端撤销接口；Java 删除也没有恢复接口。因此不能编造 `cancel` 能力。真实环境写入必须先保留原值，响应不确定先回查，删除按不可恢复操作处理。

权限事实：Portal 菜单和路由使用 `/dashboard/platform-v2/system/security-config`；本页 Java Controller 没有逐操作 `@PreAuthorize`，只证明请求进入全局认证链，不证明调用方已通过 Portal 菜单权限。SDK 返回后端错误，不把它降级成空分组或成功。
