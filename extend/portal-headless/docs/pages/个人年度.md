> 本页是绩效管理域「协议类」五页之一。**参数顺序怎么来的、五页之间有哪七处不一样**

## 列表：表单是空的

`useListPageModule({ …, form: {} })`（`list.vue:76-110`）—— 没有 `convertFetchForm`、
没有任何筛选控件（表单区只有「创建年度双赢协议」按钮）。所以列表接口除分页外**零业务参数**：

`order → orderField → pageNo → pageSize → _t`

| 参数 | kind | 说明 |
| --- | --- | --- |
| `pageNo` / `pageSize` | number | 默认 `1` / `20`（`styleV2: true` → 20） |

与[个人月度](./个人月度.md)同形，差别只有端点（`kpiyearprotocol` vs `kpimonthprotocol`）。

## 第二个读：`getYearProtocolConfig`

这一页挂载时**还会发第二个请求**（`list.vue:71-74`）：

```js
const { state } = useAsyncState(() => http.get('/sys/dict/data/getYearProtocolConfig'), '')
```

结果渲染成页面上那一行 `{{ state }}`（时间节点及扣分标准）。基准 `[7]` 实测它真的在，
且 URL 上**只有 `_t`**。所以它是**这一页读路径的一部分**，做成了独立能力
`perf-year-protocol-config-get`（零参数）。

⚠️ **两条能力共用同一个 `pagePath`**，这是**有意**的：把「列表筛选参数」和
「零参数配置读」合成一条契约，AI 反而更容易填错。仓库里已有先例
（`generalApprovalCapabilities` 与 `leaveApplicationCapabilities` 共用 `/dashboard/flow/form/edit`）。

⚠️ 这个接口的**响应体没有测到**（基准只抓请求、不抓响应），所以 `getYearProtocolConfig()`
返回 `Record<string, unknown>` —— **本能力不声明字段、不做归一化**，不知道的东西不编。

## 逐字段基准

（`baseline/perf-agreement.browser.json`，`_t` 已归一）

```
[8] GET /admin-api/performance/protocol/kpiyearprotocol/page
        ?order=&orderField=&pageNo=1&pageSize=20&_t=<ts>
[7] GET /admin-api/sys/dict/data/getYearProtocolConfig?_t=<ts>
```

**与源码推导逐字段一致（含键顺序）**，一处修正都不需要。

## 真实验证（2026-09-21）

本波**没有打真实后端**（没有冒烟、没有凭据）。验证方式是：

- **基准逐字段回归**：`test/perf-agreement.test.ts` 比 URL、比有序的 [key,value]、
  比 `module-type` 头（= 13）；配置那条另比"URL 上只有 `_t`"、且断言它**只出现在这一页**
  （其它四页的基准里都没有 `getYearProtocolConfig`）。
- **反证**：本页没有专属变异；它对公共部分的改动敏感，逐条见各页的「反证记录」。

**没测到的**：列表的真实返回；**`getYearProtocolConfig` 的响应字段一个字都没测到**
（只知道它存在、被这一页调用、零业务参数）。

## 尚未覆盖

  （默认 `false`，`list.js:228`）⇒ 实际是 `DELETE /performance/protocol/kpiyearprotocol/{id}`，
  **没有 body**，不是批量删。
- **创建 / 编辑 / 详情**：三个路由页（`../common/create/new` 等）；创建先弹「选择模板」
  再 `actionCreate({ id, year })`（年度没有 month）。
- **行内动作**（`useActionButtons`）：页面 `columns` 里列了「查看 / 修改 / 变更 / 审核 / 评分」，
  其中**会改状态的**有
  - 「撤销」`POST /performance/protocol/kpiyearprotocol/cancel?id=`
  - 「作废」`GET /performance/protocol/kpiyearprotocol/nullify?id=`
  - 「变更」→ `POST /performance/protocol/kpiyearprotocol/changeStatus`

  行内按钮按 `record.actionButtons` 动态渲染，**不是**固定清单。
- 页面上「时间节点及扣分标准」是纯展示，没有接口。

## SDK AI 说明契约（2026-09-22）

本节由当前 SDK 描述结果整理；说明权威来源为 `src/catalog/contracts-business.ts`。调用 `catalog.describe(id)`（或 `id-llm`）可得到参数来源、返回字段/状态、数据消费与后续映射；`catalog.describePage(页面路径)` 用于选择页面功能。以下更新以本节为准；前文历史请求/实测记录仍保留其记录日期。

### `perf-year-agreement-list`

查询当前用户个人年度协议；仅分页。

- 执行：`sdk.perfAgreement.listYearAgreements`；通过 `capabilities.invoke('perf-year-agreement-list', args)` 调用时按 `params` 填参。性质：read。
- 参数：`pageNo` 可选 (number)；`pageSize` 可选 (number)。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`{ list: object[], total: number }`。list=[] 为当前页无记录；total=0 表示该筛选无结果。保留筛选条件检查页码，不将空结果解释成权限判定。
- 字段：`list`、`total`、`list[].id`、`list[].name`、`list[].year`、`list[].month`、`list[].promoterName`、`list[].creatorName`、`list[].signatoryName`、`list[].createTime`、`list[].status`、`list[].actionButtons`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：展示协议名、年月、创建人及签订人；按动态字典解释 status。actionButtons 仅用于解释页面可选动作，本组 SDK 没有签订、评分、撤销或状态变更写能力。
- 完成条件：在请求的数据范围交付协议列表；不要宣称签订/变更已完成。
- 后续：optional → `base-dict-get`：按 protocol_status 查询当前字典，将返回 value 与业务行状态/类型值转成同一字符串后匹配 label；没有匹配时显示原码并说明标签未配置（dictType ← literal:"protocol_status"）
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。


### `perf-year-protocol-config-get`

读取个人年度协议页顶部的签订时间提示文本；不是字典对象或分页结果。

- 执行：`sdk.perfAgreement.getYearProtocolConfig`；通过 `capabilities.invoke('perf-year-protocol-config-get', args)` 调用时按 `params` 填参。性质：read。
- 参数：无参数。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`string`。空文本说明未取得可展示的配置；不要猜截止日。
- 字段：`$`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：直接展示文本；需要结构化时间节点请调用 perf-manage-protocol-config-read。
- 完成条件：交付年度签订时间提示。
- 后续：optional → `perf-manage-protocol-config-read`：dictType=protocol_config；需要按配置键获取原始时间值（dictType ← context.dictType）
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。
