## 能力与权限

- 页面权限：`/dashboard/report/fund-payment-summary`。
- 列表和人员明细使用 `platform` 实例，页面推导的 `module-type` 为 `14`。
- 列表接口：`GET /salary/salaryfundcosts/paymentSummaryPage`。
- 人员明细接口：`GET /salary/salaryfundcosts/paymentSummaryDetailPage`。
- 列表页是 styleV2 分页，默认 `pageNo=1`、`pageSize=20`；排序槽固定发送 `order=''`、`orderField=''`。

## 列表参数基准

Portal 表单只有部门多选和年月区间：

| 页面字段 | SDK 参数 | 发送值 |
| --- | --- | --- |
| `orgIds` | `orgIds` | 数组连接为逗号字符串；未选发送 `''` |
| `costDateRange[0]` | `costDateRange[0]` | `YYYY-MM` 转 `YYYY-MM-01`；未选发送 `null` |
| `costDateRange[1]` | `costDateRange[1]` | `YYYY-MM` 转 `YYYY-MM-01`；未选发送 `null` |
| 页码 | `pageNo` / `pageSize` | 与页面状态一致 |

示例请求参数：

```json
{
  "order": "",
  "orderField": "",
  "costDateStart": "2026-09-01",
  "costDateEnd": "2026-10-01",
  "orgIds": "9,10",
  "pageNo": 2,
  "pageSize": 50
}
```

列表返回 `{ list, total }`。金额字段按服务端 `BigDecimal` 原值消费；`status` 为 `0待提交、1待审核、2待付款、3已驳回、4已付款`。

## 人员明细弹窗

页面点击人数或“查看详情”后调用 `paymentSummaryDetailPage`。`summaryId` 与 `summaryIds` 二选一；聚合行必须使用 `socialFundSummaryIds`，不能用展示名称代替。可选的 `depositUnitIds` 和 `name` 仍按页面顺序发送，返回包络为 `{ title, page: { list, total } }`。

## 公积金缴纳单表单规则

列表页“创建缴纳单”进入 `/simple/hr/form/019`，这是同一保留菜单的可达写能力，SDK 以 `prepare → submit → paymentDetail` 表达：

1. `useYearMonth` 必须为 `YYYY-MM`，`paymentDate` 必须为 `YYYY-MM-DD`，`organizationId` 和 `organizationName` 必须来自当前用户有权限的组织树。
2. `type` 由页面固定为 `2`，表示公积金缴纳单，不由调用方改写。
3. `socialFundSummaryVOList` 不能为空。没有选择缴存单位时，每行必须有 `socialFundSummaryId`；选择了 `depositUnitIds` 后按缴存单位聚合，每行必须有非空 `socialFundSummaryIds`，并删除单个 `socialFundSummaryId`。
4. 页面按 `amount`、`providentFundTotal`、`totalPersonal + totalCompany` 的顺序计算每行金额，保留两位小数后计算 `totalAmount`；SDK 不信任调用方传入的合计。
5. 预算明细发送为 `{ budgetDetailNo, budgetDetailId }[]`。Java 服务会重新计算预算金额并执行预算校验、占用；余额不足或预算无效会拒绝创建。
6. `prepare` 请求 `/hr/social-fund-payment/getRequiredStartUserSelectTasks`。审批节点是动态返回的，必须使用返回项的 `id` 建立 `startUserSelectAssignees`，不能按节点名称猜测。
7. `submit` 会再次按页面规则请求审批节点，然后 POST `/hr/social-fund-payment/create`；这会创建单据、更新关联汇总状态、占用预算并发起 `provident_fund_payment` 审批，不能把接口成功当作审批完成。
8. 提交成功返回业务单据 ID，不是流程实例 ID。必须回查 `paymentDetail`，区分 `id`、`processInstanceId` 和 `status`。撤销使用 POST `/hr/social-fund-payment/cancel` 的业务单据 ID，撤销后仍需回查。
