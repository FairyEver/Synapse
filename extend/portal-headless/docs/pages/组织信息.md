# 组织信息（`/dashboard/me/organization/list`）

本页覆盖 Portal「人力 → 组织管理 → 组织信息」页面：当前员工基本信息，以及当用户是组织负责人时可见的组织树、职务候选和四类统计查询。它属于提示词保留的 `portal/人力` 范围；这里的组织统计接口是人力页面依赖，不扩展到独立顶层「生产」「财务」「采购」或「销售」系统。

证据边界：已逐页核对菜单、根页面、普通员工分支、负责人分支、组织树组件、职务组件和统计筛选，并逐项核对 Java Controller、DTO、服务端数据范围与图表字段。SDK 请求投影、module-type、默认空值、ID/日期校验和 AI 说明反证有离线测试；尚未在真实测试门户执行本页读请求、负责人/非负责人权限矩阵或统计数据对照。

来源锚点：Portal `CodeReview_Projects_Js@test/portal/main@acab69acc77b6d6c0da21310cdfd26b91a01641e`；Java `CodeReview_Mall_Platform_Java@test/test`。

## 一、页面上下文、权限和范围

| 项 | SDK/Portal 事实 |
| --- | --- |
| 菜单路径 | `/dashboard/me/organization/list` |
| 页面权限 | `/dashboard/me/organization/list`；菜单与路由元信息一致 |
| HTTP 实例 | `platform`；SDK 使用 `/org/...` 逻辑路径，由实例补 Portal 的 `/admin-api` 前缀 |
| `module-type` | `11`（组织管理）；页面业务请求按 Portal 规则带 `module-type: 11` |
| 页面形态 | 只读自定义页面；没有列表分页器、详情路由或保存按钮 |
| 负责人分流 | 首先读取 `getAllDirectOrgList`；数组非空显示负责人统计，空数组显示普通员工信息，但两个分支都会读取 `getStaffBaseInfo` |
| 数据范围 | 当前会话、租户、页面权限、角色组织范围和组织负责人关系共同决定；SDK 不提取或替换凭据 |

页面没有 POST、PUT、PATCH、DELETE，也没有表单提交。页面中的 `<a-form>` 只承载组织、标准单元、职务和月份筛选；图表类型与半年/一年切换是本地渲染，不是写操作。

## 二、已接入能力

调用门面为 `sdk.meOrganization.<method>`；能力说明由 `catalog.describe(id)` 和 `catalog.describe(id, { format: 'llm' })` 返回。

| 能力 ID | SDK 方法 | 请求/效果 |
| --- | --- | --- |
| `me-organization-direct-org-list` | `listDirectOrganizations` | `GET /org/organization/getAllDirectOrgList`，读取当前用户所辖组织，用于页面分支判断 |
| `me-organization-staff-base-info` | `getStaffBaseInfo` | `GET /org/staff/getStaffBaseInfo`，读取当前员工页头和基本信息 |
| `me-organization-organization-tree` | `organizationTree` | `GET /org/organization/getRoleOrganizationTree`，读取当前会话可见组织树 |
| `me-organization-duty-options` | `dutyOptions` | `GET /org/hrduty/all`，读取负责人统计的职务候选 |
| `me-organization-establishment-chart` | `getEstablishmentChart` | `GET /org/organization/getDirectOrgPostNumber?orgId=...`，读取编制图表 |
| `me-organization-employee-statistics` | `getEmployeeStatistics` | `GET /org/organization/getDirectOrgStaff?date=...&orgId=...`，读取员工统计小结 |
| `me-organization-organization-statistics` | `getOrganizationStatistics` | `GET /org/organization/getDirectOrgInfoV2?orgId=...&dutyId=...&standardUnit=...`，读取组织员工分布图表 |

不登记组织维护的新增、修改、删除、导入、导出，也不登记生产/财务等独立系统的组织树接口。标准单元 `standard_cell` 候选来自 Portal 全局字典初始化，不伪造一个页面内重复的字典能力。

## 三、逐字段基准、筛选和“提交”规则

### 3.1 页面初始化和负责人分支

根页面先请求：

```text
GET /admin-api/org/organization/getAllDirectOrgList
```

返回数组非空时渲染 `director.vue`，否则渲染 `directorNot.vue`。两个分支都请求：

```text
GET /admin-api/org/staff/getStaffBaseInfo
```

员工基本信息的关键字段为 `name`、`staffCode`、`postName`、`headImg`、`organization`、`organizationName`、`leader`、`leaderName`、`employmentType`、`entrySeniority` 和 `baseInfo[]`。`organization` 是统计接口的组织 ID；`organizationName` 只是展示文本，不能代替 ID。`baseInfo[]` 保留后端顺序，每项为 `key/value`。

### 3.2 负责人候选请求

负责人分支的组织选择器使用：

```text
GET /admin-api/org/organization/getRoleOrganizationTree
```

不发送关键字、`pageNo`、`pageSize` 或全量组织替代接口；节点 `id` 是后续统计请求的唯一组织值来源，`children` 层级原样保留。

职务选择器使用：

```text
GET /admin-api/org/hrduty/all
```

Portal 展示 `dutyName`，提交筛选时把所选 `id` 映射为 `dutyId`。它是全量候选读取，不提供空关键字搜索，也不把职务维护的保存/修改/删除接口纳入本页能力。

### 3.3 统计请求和默认值

员工基本信息加载后，编制和员工统计使用其 `organization` 作为默认组织。组织、标准单元或职务筛选变化时，Portal 请求参数如下：

| 页面行为 | 请求字段 | SDK 规则 |
| --- | --- | --- |
| 编制图表 | `orgId` | 必须为正整数 ID；来自员工信息 `organization` 或组织树节点 `id` |
| 员工统计小结 | `date`, `orgId` | `date` 为真实 `YYYY-MM-DD`；页面月份选择器仍以该格式提交；`orgId` 必填 |
| 组织员工统计 | `orgId`, `dutyId`, `standardUnit` | 初始及清空状态都发送 `dutyId=''`、`standardUnit=''`；不会擅自替换成 `null` 或默认选项 |

实际逻辑请求为：

```text
GET /admin-api/org/organization/getDirectOrgPostNumber?orgId=<orgId>
GET /admin-api/org/organization/getDirectOrgStaff?date=<YYYY-MM-DD>&orgId=<orgId>
GET /admin-api/org/organization/getDirectOrgInfoV2?orgId=<orgId>&dutyId=<dutyId>&standardUnit=<standardUnit>
```

`getDirectOrgInfoV2` 返回的 `ChartData[]` 是位置型结果：每项有 `title`、`unit`、`lineData[]`；数据线有 `mark`、`points[]`；点有 `x`、`y`、可选 `z`。Portal 会过滤 `title === '单元分布'`，并按图表顺序消费职务、员工人数、年龄、学历和司龄分布，SDK 不排序、不合并、不把 `x` 中的“较上月增加/减少”改写成新枚举。

员工统计小结的 `x` 也可能是后端生成的“持平”或“较上月增加 N↑”文本；`y` 是后端原始数值。编制图表的 `mark` 可能是“实际人数”“目标编制”等，均按原值返回。

### 3.4 表单提交与本地操作

本页没有业务提交规则：筛选变化只触发 GET，图表柱状/折线切换和半年/一年切换只改变本地展示数据，不产生网络请求。不存在 `prepare → submit → cancel` 写闭环；调用方不应为了“查询完成”虚构写入回查。

## 四、操作步骤、失败处理和验证边界

1. 先调用 `listDirectOrganizations` 判断是否进入负责人统计分支；它为空不是请求失败。
2. 调用 `getStaffBaseInfo` 展示当前员工信息；只有 `organization` 是合法组织 ID 时才调用组织统计。
3. 负责人需要组织筛选时调用 `organizationTree`，需要职务下拉时调用 `dutyOptions`；只把候选 `id` 交给统计方法。
4. 按页面筛选调用 `getEstablishmentChart`、`getEmployeeStatistics` 或 `getOrganizationStatistics`；标准单元和职务清空时保留空字符串。
5. 统计返回空数组表示当前会话和筛选下没有图表；会话、租户、权限、数据范围、网络和响应结构错误均抛出，不降级为空结果。
6. 本页是只读页面，不存在保存、取消提交、删除或导出业务数据；真实门户读请求和不同用户权限对照需单独记录，离线测试不替代真实证据。
