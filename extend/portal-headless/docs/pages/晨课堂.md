## Portal 可达来源

列表页实际绑定了 `rrList.actionCreate()`、`rrList.actionEdit(record)`、单删/批删、
`actionStatus(record)` 和“课堂记录”弹窗。详情表单是
`daily-lesson/[mode]/[id].vue`；它保存后继续提交出勤和课堂记录。学生管理文件
`daily-lesson/student/[id]/item-list.vue` 存在，但当前晨课堂列表没有绑定跳转按钮；本次
仍按用户指定的隐藏学生页逐项保留请求形状，并不把不存在的按钮当成 Portal 菜单动作。

周课堂中被注释的 `actionStudent` 同样不计入可达证据。

Portal 固定检出 `CodeReview_Projects_Js@test/portal/main` 的 `acab69a…` 中，以下源码给出
本页证据：

- `list.vue`：`GET /study/lesson/studylesson/lessonList`，表单固定 `type: '1'`；删除配置
  `deleteURL: '/study/lesson/studylesson'`、`deleteIsBatch: true`；状态按钮只有
  `record.isRelGrade === 1` 时渲染，提交 `PUT /study/lesson/studylesson/publish`。
- `[mode]/[id].vue`：详情 `GET /study/lesson/studylesson/{id}`；表单保存调用
  `POST /study/lesson/studylesson/saveLesson`，把 `time` 拆为 `startTime/endTime`，并移除
  `lessonStudyStudentDTOList`；保存后并行保存出勤和记录。
- `components/course-record.vue`：列表“课堂记录”弹窗调用
  `GET /study/lesson/lessonrecord/selectAttendanceStatus`、`GET /study/lesson/lessonrecord/getLessonRecord`、
  `POST /study/lesson/lessonrecord/studentManage`、
  `POST /study/lesson/lessonrecord/saveLessonRecordV1`。
- `student/[id]/item-list.vue`：学生列表为
  `GET /study/lesson/studylessonstudentrel/studyStudentList`；行按钮是 PUT `moveOut`，
  批量按钮由 `useListPageModule` 直接发 DELETE `moveOut`；该页行内出勤按钮另发
  `GET /study/lesson/studylessonstudentrel/updateAttendanceStatus?id=...`。

## 端点与能力

列表仍使用 `GET /study/lesson/studylesson/lessonList`，参数顺序为
`order → orderField → type=1 → title → gradeNames → status → createTimeStart/End →
startTimeStart/End → pageNo → pageSize`。日期筛选结束日是 +1 天开区间，晨课堂两端格式均为
`YYYY-MM-DD 00:00:00`。

动作实现位于 `src/capabilities/study-lesson.ts`，按 Portal 页面上下文分别使用
`requestDaily`，主要能力 ID 如下：

| Portal 动作 | 能力 ID | 实际请求 |
| --- | --- | --- |
| 读取详情 | `study-lesson-daily-detail` | `GET /study/lesson/studylesson/{id}` |
| 保存晨课堂 | `study-lesson-daily-prepare-save` → `study-lesson-daily-save` → `study-lesson-daily-cancel-save` | `POST /study/lesson/studylesson/saveLesson` |
| 删除课堂 | `study-lesson-daily-prepare-delete` → `study-lesson-daily-delete` → `study-lesson-daily-cancel-delete` | `DELETE /study/lesson/studylesson`，body 为 `[id,...]` |
| 发布/取消发布 | `study-lesson-daily-prepare-publish` → `study-lesson-daily-publish` → `study-lesson-daily-cancel-publish` | `PUT /study/lesson/studylesson/publish`，body `{ id, status }` |
| 读取课堂出勤 | `study-lesson-daily-attendance` | `GET /study/lesson/lessonrecord/selectAttendanceStatus?lessonId=...` |
| 保存出勤 | `study-lesson-daily-prepare-attendance` → `study-lesson-daily-attendance-save` → `study-lesson-daily-cancel-attendance` | `POST /study/lesson/lessonrecord/studentManage`，body 为出勤 DTO 数组 |
| 读取课堂记录 | `study-lesson-daily-record` | `GET /study/lesson/lessonrecord/getLessonRecord?id=...` |
| 详情表单记录 | `study-lesson-daily-record-prepare-save` → `study-lesson-daily-record-save` → `study-lesson-daily-record-cancel-save` | `POST /study/lesson/studylesson/saveLessonRecordV1` |
| 列表记录弹窗 | `study-lesson-daily-course-record-prepare-save` → `study-lesson-daily-course-record-save` → `study-lesson-daily-course-record-cancel-save` | `POST /study/lesson/lessonrecord/saveLessonRecordV1` |
| 学生列表（隐藏页） | `study-lesson-daily-student-list` | `GET /study/lesson/studylessonstudentrel/studyStudentList` |
| 学生行移入/移出 | `study-lesson-daily-student-prepare-move-out` → `study-lesson-daily-student-move-out` → `study-lesson-daily-student-cancel-move-out` | PUT `/study/lesson/studylessonstudentrel/moveOut`，body `{ lessonId, staffCodeList, type }` |
| 学生页批量按钮 | `study-lesson-daily-student-prepare-batch-delete` → `study-lesson-daily-student-batch-delete` → `study-lesson-daily-student-cancel-batch-delete` | DELETE 同一 `moveOut`，body 直接为学生行 `[id,...]`，无 query |
| 学生出勤切换（隐藏页） | `study-lesson-daily-student-attendance-toggle` | `GET /study/lesson/studylessonstudentrel/updateAttendanceStatus?id=...` |

`studentManage` 的 prepare 会把每行的 `lessonId` 覆盖为当前课堂 ID；行移出时 Portal
按当前 `status === 1` 生成 `type: 2`（移出），否则生成 `type: 1`（取消移出）。
页面的批量 DELETE 并不转换成 Java 的 `staffCodeList` DTO，而是保留 renren list 模块的
真实 body；Java 是否接受这一条需真实环境验证。

## 门禁与跨页依赖

- 所有能力的 `pagePath`/权限仍指向本菜单页，主线接线时不能把隐藏路由当成新的菜单
  上下文，也不能省略学习管理的 module-type 推导。
- 详情保存按钮是 `!!rrForm.formState.status` 门禁；prepare 在 status truthy 时拒绝。
  页面字段仍按 Portal 保留：`type=1`、`lessonKind=0`、`gradeIds`、`gradeStaffCodeList`、
  `title`、`hostCode`、`lessonType`、`time`、`info`、`lessonContentList`、`lessonPlan`。
- 发布按钮要求列表行 `isRelGrade === 1`；删除的 Java 服务还会拒绝已发布课堂（status=1），
  prepare 在已知状态为 1 时提前拒绝。
- 页面保存返回的 `lessonId` 是后续 `studentManage`、`saveLessonRecordV1` 的输入依赖；
  Portal 页面在同一提交中并行保存出勤与记录，SDK 通过独立能力保留该顺序依赖。
- `cancel` 只取消本地草稿。Java 固定分支没有对应的回滚接口。

## 学习记录子页（`record/[id]/item-list.vue`，2026-09-26 补）

隐藏子路由 `record/[id]/item-list.vue`（没有菜单项）。**晨/周/月三页的这份文件逐字相同**
（晨与周只差两个模板属性），所以三页的请求形状完全一样，差别只在页面上下文。

⚠️ **但这一页到不了，所以没有对应能力。** 晨课堂列表的「课堂记录」打开的是**弹窗**
（`daily-lesson/list.vue:172-173` 的 `createModal`，`content: ../components/course-record.vue`），
固定检出里**没有任何代码** push 到 `daily-lesson/record/[id]/item-list`（全仓
`grep -rn 'daily-lesson/record'` 零命中）。

按 conventions 第 28 条「能渲染不等于用户能做的事」——与「直播课程」（`src/capabilities/study-course.ts`
文件头）同型：路由文件在、按 URL 直接打开也能渲染，但**用户到不了这一页** ⇒ **不进 SDK**，
因此这一页**没有** `study-lesson-daily-record-list`。

（2026-09-26 决策：这条一度按派单表建过，复核可达性后删除。）

| 页面位置 | 能力 ID | 实际请求 |
| --- | --- | --- |
| `deleteURL` + `deleteIsBatch: true`（`:87-88`） | `study-record-remove`（绑在周课堂页） | `DELETE /study/statistics/studystudyrecord`，**body 是 ID 数组**，没有 query |

### 删除既不是 GET、也不是 `${deleteURL}/{id}`

`common/libs/renren/list.js:517` 的 `deleteIsBatch: true` 分支是
`_http.delete(deleteURL, { data: id ? [id] : selectState.value })`：单行删发 `[id]`、多选删发选中的数组。
通用删除那条 `${deleteURL}/${id}` 的路径这一页**没走** —— 按路径参数写就不是浏览器发的东西。

### `-1` 是一个有业务含义的返回，不是传输错误

`StudyStudyRecordServiceImpl:349-357`：只要这批 id 里有一条 `is_adm_add = 0`（学员自学产生的记录），
service 直接 `return -1`，控制器把它转成 `ret:"FAIL", code:500, msg:"线上学习学员不可移出，请重新选择"`
（`StudyStudyRecordController:99-108`）—— **整批一起失败**，不会"能移的先移"。
页面只对 `isAdmAdd === 1` 的行渲染「移出」按钮，但**批量按钮没有这个过滤**，所以用户自己也会踩到。
SDK 把这条写进契约的 `failures`，并要求先回列表按 `isAdmAdd` 把 0 的行剔除。

### 三页拆几个能力

三条 `studystudyrecord/list` 按页拆成三个能力（各页的 `boundaries` 写明只服务哪一页）；
删除合成**一个** `study-record-remove`：三页的请求逐字节相同、module-type 推导也同为
12（学习管理），拆三份只会得到三个一模一样的定义。它的 `pagePath` 落在**周课堂**
——三页里只有周课堂列表真的 push 到自己的 record 子页，绑在可达的那一页更贴近事实
（详见 [周课堂](./周课堂.md)）。
