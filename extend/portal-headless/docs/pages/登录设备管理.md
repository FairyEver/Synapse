入口：Portal 顶栏头像菜单「设备管理」，打开弹窗，不是独立侧栏菜单。

## 能力定义与调用

| 能力 ID | SDK 方法 | 效果 | 页面接口 |
| --- | --- | --- | --- |
| `portal-device-list` | `portalDevice.list()` | read | GET `/device/list.json` |
| `portal-device-count` | `portalDevice.getCount()` | read | GET `/device/count.json?clientType=pc` |
| `portal-device-prepare-remove` | `portalDevice.prepareRemove(targetDeviceCode)` | prepare | 只调用设备列表 |
| `portal-device-remove` | `portalDevice.remove(targetDeviceCode)` | write | 先列表，GET `/device/kick.json?targetDeviceCode=...`，再列表核实 |

`GET kick` 是写入，不能按 HTTP 方法套只读重试。没有 `requestId` 防重。

工厂 `createPortalDeviceCapability(request, { currentDeviceCode? })`，`request` 必须绑定当前用户会话并走集中 `createPageCall`。主门面用 `config.portalDevice.currentDeviceCode`，多用户门面用每次 `forSession({portalDevice:{currentDeviceCode}, ...})` 显式提供，不从服务级配置继承。调用方提供 `httpBaseUrls['zhdj-app']`，缺失时失败关闭，不借用 Portal 主后端 host。当前页面实例只发会话 token 与语言头，不发 tenant-id/module-type；账号设备范围不应描述成租户设备范围。

当前设备标识来自调用方已知的真实设备上下文。SDK 不读取浏览器指纹、不生成替代标识。缺少它时允许列表和数量查询，`isCurrent=null`，禁止准备/执行移除。工厂复制当前设备标识，各用户实例互不共享此上下文。

## 参数契约

`targetDeviceCode` 是非空字符串，源自 `portal-device-list` 的选中设备 `[].deviceCode`，原样传递；不得使用设备名称、人员 ID 或猜测值。准备和实际移除都要求目标不是本机，且在当前账号实时设备列表中。实际移除会再次检查，准备结果不是服务端锁。

`portal-device-list` 和 `portal-device-count` 无参数。所有 ID、输入与返回语义由 `src/catalog/contracts-portal-device.ts` 的 `PORTAL_DEVICE_CONTRACTS` 提供给 `catalog.describe()`；主接线方接入 `ai-contracts.ts` 与能力/调用注册表；测试通过真实单用户 `catalog.describe("portal-device-prepare-remove-llm")`、`capabilities.invoke` 与多用户门面验收，不以该文件存在替代描述检查。

## 逐字段静态基准

| 返回字段 | SDK 行为与页面含义 |
| --- | --- |
| 列表根 | 裸数组；兼容后端裸数组或 `{list:[]}`；本机先排，其余稳定保序；格式错误抛出，不能伪证移除成功 |
| `deviceCode` | 登录设备标识，必需非空字符串，移除输入来源 |
| `deviceName` | 可缺席/可空；页面空值显示“未知设备” |
| `loginApp` | 可缺席/可空；数值 2 为 PC，其他分 APP；已知 1=手机，未知值保留 |
| `loginAppName` | 终端展示名；空值显示破折号 |
| `loginTypeName` | 登录方式展示名；空值显示破折号 |
| `activeArea` | 最近活动地区；空值不显示 |
| `activeTime` | 原始字符串/数字/空值；数值和可转数字字符串按毫秒时间戳在展示端本地时区渲染，非数字字符串原样显示；0/空字符串/缺席显示破折号 |
| `isCurrent` | SDK 增加；true=本机不可移除，false=已知非本机，null=未给真实本机标识，不能按 false 处理 |
| `currentCount` | `count || 0`，单位台，只计 PC |
| `maxCount` | `maxCount || 5`，单位台；后端 0 也回退 5，与页面一致，不能当服务端真实限额证明 |
| 准备根 | 单台设备对象，字段同上；只读，不表示已移除 |
| `targetDeviceCode` | 实际执行移除的设备标识 |
| `removed` | 真值仅表示 kick 后独立列表已无目标；false 表示目标仍在，不报告成功；复查失败抛结果不确定 |

设备白名单不透传 token 等未参与页面展示的扩展字段。静态类型尚缺外部后端及线上响应证明，已在 AI 契约 gaps 保留。

## 操作步骤与失败处理

1. 获取设备列表和 PC 数量，按 loginApp 分组，展示当前设备。
2. 用户指定一台非本机设备后准备，读取它当前展示信息；`result.deviceCode → targetDeviceCode`。
3. 执行移除，再次读取列表检查目标，然后发 kick 并独立列表复查。
4. `removed=true` 才报告设备已从列表移除；不承诺全部历史 token 立即失效。false 或网络结果不确定先刷新列表，不直接重发 kick。
5. 页面无撤销动作，不能自动注册设备试图恢复原会话。
