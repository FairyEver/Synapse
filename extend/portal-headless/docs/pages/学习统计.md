## 四个 POST，路径**自带 `/admin-api` 前缀**

页面源码里就是 `http.post('/admin-api/hr/zhdj-study-statics/summary', payload)` —— 前缀是**写死**的。
`platform.js` 的前缀拦截器对已带 `/admin-api` 的不再补，所以这是**刻意**的，不是笔误。
SDK 照抄（能力实现里也是拼 `/admin-api${path}`）。

payload 是 `{ lessonId, organizationId }`，`by-staff` 那一条再加 `pageNo`/`pageSize`。
页面是 `Promise.allSettled` 并发发的 —— 能力保持同样的语义：**一路失败不拖垮其余**，
返回里带一个 `errors` 记下哪一路挂了。

## 两个入参都是必填（页面上是两个下拉都选完才发）

`lessonId`（班课）与 `organizationId`（组织）。⚠️ 页面的**组织**下拉是
`GET /org/organization/getTree?roleId=`，班课那一侧还有一条 `smart-layer-app` 的
`/api/zhdj/studyLessonCatalogue/getChapterTree?type=2` —— **两条候选入口本能力都没有做**
（都是长选项参数；而且后者走的是另一个实例）。要用请先问用户关键字。

## 真实验证（2026-09-21）

抓基准时这一页**不发**这四个请求（页面要求两个下拉都选完才发），所以
`baseline/study-statistics.browser.json` 里只有它的两条候选请求 ——
**请求形状是源码读出来的**。那一轮之后**专门补了一次真机验证**：
从晨课堂取一条真实班课（`lessonId=198577`）、从班级列表取一条真实组织（`organizationId=1`），
四个 POST 全部返回 `ret=SUCCESS / code=0`：

| 端点 | 返回形状 |
| --- | --- |
| `summary` | `{dueCount, viewCount, viewRate, likeCount, likeRate, commentCount, …}` |
| `by-organization-chart` | `{series, xAxis}` |
| `by-organization` | `array`（这条班课下是空数组） |
| `by-staff` | `{list, total, summary, summaryRows}` |

`smoke/read-study-module.mjs` 的 ④ 段把这四个 POST 固化成了每次可复跑的检查 ——
它用**班级行上的 `organizationIdList[0]`** 取组织 id，**刻意不去拉那棵组织树**
（`getTree` 实测 1547 个节点，是长选项参数）。

⚠️ 班级行里**没有** `orgId` 这个字段名，实测是 `organizationIdList`（数组）与
`managementCenterId` —— 第一次写冒烟时按 `orgId` 取，取到 `undefined` 才发现。

  它们各自的候选从哪来没有展开（组织树那条已知是 1547 节点）。

### `study-statistics-learning-summary`

查询选定班课和组织的智慧蛋鸡学习行为统计；汇总、组织图表、组织表格、员工分页四路并发读取。

执行：`sdk.studyStatistics.learningSummary`；性质：read。查询选定班课和组织的智慧蛋鸡学习行为统计；汇总、组织图表、组织表格、员工分页四路并发读取。

- 边界：POST 只是查询，没有记录学习行为副作用。四路采用 allSettled 语义，失败被收集到 errors；调用 resolve 不保证四路都成功。

| 参数 | 意义与来源 |
| --- | --- |
| lessonId | 智慧蛋鸡课程或子内容 ID，取用户选定路径末节点，不是本地班课 ID；来源：contract-support-learning-course-search 返回 list[].id；由用户选定，不能以名称、编码或其他实体 ID 替代；候选：contract-support-learning-course-search list[].id |
| organizationId | 学习统计页面权限组织树所选 id，不从其他域组织猜测；来源：contract-support-learning-organization-search 返回 list[].id；由用户选定，不能以名称、编码或其他实体 ID 替代；候选：contract-support-learning-organization-search list[].id |
| pageNo | 页码，默认 1；来源：用户给出的业务条件；格式和必填性按参数契约。 |
| pageSize | 每页条数，默认 20；来源：用户给出的业务条件；格式和必填性按参数契约。 |

返回：`object`。可选字段缺省或 null 时展示为空，不当作数值 0。

- summary.viewRate：查看覆盖率；百分比 0..100，保留两位小数，不再乘 100；单位：%
- summary.likeRate：点赞率；百分比 0..100，保留两位小数，不再乘 100；单位：%
- summary.commentRate：评论率；百分比 0..100，保留两位小数，不再乘 100；单位：%
- summary.forwardRate：转发率；百分比 0..100，保留两位小数，不再乘 100；单位：%
- summary.favoriteRate：收藏率；百分比 0..100，保留两位小数，不再乘 100；单位：%
- byOrganization[].viewRate：学习率（浏览率）；百分比 0..100，保留两位小数，不再乘 100；单位：%
- byOrganization[].commentRate：评论率；百分比 0..100，保留两位小数，不再乘 100；单位：%
- byOrganization[].likeRate：点赞率；百分比 0..100，保留两位小数，不再乘 100；单位：%
- byOrganization[].forwardRate：转发率；百分比 0..100，保留两位小数，不再乘 100；单位：%
- byStaff.list[].hasView：是否观看；{"0":"否","1":"是"}
- byStaff.list[].hasLike：是否点赞；{"0":"否","1":"是"}
- byStaff.list[].hasComment：是否评论；{"0":"否","1":"是"}
- byStaff.list[].hasForward：是否转发；{"0":"否","1":"是"}
- byStaff.list[].hasFavorite：是否收藏；{"0":"否","1":"是"}

- 消费：先检查 errors；null 分路加 errors 对应键表示失败，不是零统计。可交付成功分路并标出缺失项。图表 data 与 xAxis 按索引配对。员工是否观看/点赞等为整数标记，不能根据 VO example 把它当 JSON boolean。

完成条件：四路 errors 都为空并按用户范围交付；若部分失败，应明确部分结果而不能报告完整统计。

- 失败处理：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。
