# 采购字典（`/dashboard/setting/dict-platform/supply/list`）

## 页面范围

本页属于 Portal「系统设置 → 系统字典 → 采购字典」，菜单权限为 `/dashboard/setting/dict-platform/supply`，业务键为 `supply`。采购 wrapper 的四个路由均复用公共字典页面，并把 `SYSTEM_SUPPLY_VALUE` 固定为 `5`。

本能力覆盖根列表及从“字典数据”进入的子页：类型分页、数据分页、数据详情、数据新建、数据编辑、数据单条删除。根页的类型新建/编辑/删除按钮被注释，数据页没有批量删除、导入或导出入口，因此不登记这些能力。

## 能力定义与请求

- HTTP 实例：`platform`。
- module-type：当前规则表未命中，不发送。
- 类型列表：`GET /admin-api/system/dict-type/page`。
- 类型列表参数按 Portal 发送 `order=''`、`orderField=''`、`useSystem=5`、`name`、`type`、`pageNo`、`pageSize`。`pageNo` 默认 `1`，`pageSize` 默认 `20`，只接受 `10/20/50/100`。
- 字典数据列表：`GET /admin-api/system/dict-data/page`，发送 `order=''`、`orderField=''`、`dictType`、`label`、`status`、`pageNo`、`pageSize`；清空状态时 `status=undefined`。
- 详情：`GET /admin-api/system/dict-data/get?id=<数据ID>`。
- 新建：`POST /admin-api/system/dict-data/create`，请求体为 `id=''`、`dictTypeId=dictType`、`dictType`、`label`、`value`、`status`、`sort`、`remark`；省略值的默认值为 `status=0`、`sort=0`、`remark=''`。
- 编辑：`PUT /admin-api/system/dict-data/update`，发送 `id`、`dictType`、`label`、`value`、`sort`、`status`、`remark` 及调用方透传字段；平台共享行不允许编辑。
- 单条删除：`DELETE /admin-api/system/dict-data/delete?id=<数据ID>`；平台共享行不允许删除。

## 参数与字段契约

类型列表返回 `{ list, total }`。`list[]` 的关键字段为：

| 字段 | 含义 |
| --- | --- |
| `id` | 字典类型主键；进入数据页必须使用同一行的 `type`，不能把 `id` 当 `dictType` |
| `name` / `type` | 类型名称 / 类型代码；`type` 是后续数据查询的 `dictType` |
| `status` | `0=开启`、`1=关闭` |
| `remark` / `createTime` | 备注 / 创建时间原值 |
| `useSystem` | 所属系统；本页筛选值为 `5=采购` |
| `tenantEditable` | 是否允许租户维护数据；租户接口查询强制为 `1` |

数据分页返回 `{ list, total }`。`list[]` 保留 `id`、`sort`、`label`、`value`、`dictType`、`status`、`colorType`、`cssClass`、`remark`、`createTime`、`tenantId`、`platform`。`tenantId=0` 为平台共享，正数为租户私有；`platform=true` 时页面只读。

表单约束由 Portal 与 Java DTO 共同锁定：`dictType`、`label`、`value` 非空且最长 100 个字符；`sort` 为非负整数且必传给后端；`status` 只能为 `0/1`；备注可为空。SDK 在请求前校验非空、ID、分页、状态和排序；后端还校验当前租户、类型启用、`tenant_editable=1`、租户归属及字典值唯一性。

## 操作步骤与失败规则

1. 先调用采购类型分页，使用返回行的 `type` 作为数据页 `dictType`；不要使用类型 `id`。
2. 需要查看数据时调用数据分页；需要编辑时先用数据 ID 读取详情，保留完整字段后提交修改。
3. 新建、编辑、删除收到新 ID/`true` 不能直接当作业务终态：应再按同一 `dictType` 分页回查，分别确认新行出现、字段已更新或目标 ID 消失。
4. 参数校验失败、平台行只读、字典类型不可维护、非当前租户、权限、网络或后端业务错误都会抛出；不会降级为空列表或误报成功。写请求没有 requestId 幂等保证，超时先回查，不能盲目重试。
