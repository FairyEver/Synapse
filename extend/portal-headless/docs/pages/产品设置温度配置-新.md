# 温度配置-新

## 页面能力定义

| 项目 | 基准 |
| --- | --- |
| Portal 页面 | `/dashboard/product/setting/season/list` |
| 菜单标题 | 温度配置-新 |
| 页面权限 | `/dashboard/frame/breeding-plan-new/season` |
| 范围归属 | `系统设置 → 生产设置 → 养殖预案`；不包含独立顶层生产模块 |
| HTTP 实例 | `platform` |
| module-type | 不发送；本页没有页面推导结果 |
| 主数据接口 | `/flockSimu/rearingPlan/areaTempConfig/page`、`/get`、`/save`、`/delete`、`/delete-list` |
| 依赖接口 | `/system/area/tree`、`/flockSimu/rearingPlan/tempBand/page` |

SDK 能力组为 `productSettingSeason`：地区树、启用温度段、列表、详情、保存准备/提交、单个删除准备/提交、批量删除准备/提交。写操作保持 `prepare → 用户确认 → submit → list/get 回查`，取消只丢弃本地草稿。

## 参数与提交契约

### 列表

- 筛选字段为 `provinceCode`、`cityCode`、`districtCode`；省级选择清空市和区，市级选择清空区。
- `pageNo` 默认 `1`，`pageSize` 默认 `10`，页面支持 `10/20/50`。
- 只发送非空的六位行政区编码；SDK不把地区名称当作编码。

### 初始依赖

页面加载时并行读取：

1. `GET /system/area/tree`；
2. `GET /flockSimu/rearingPlan/tempBand/page`，固定参数 `{ pageNo: 1, pageSize: 5, status: 1 }`；
3. 读取温度配置列表。

新建弹窗依赖启用温度段数据；依赖为空时 Portal 不打开新建弹窗。

### 保存

Portal 表单只提交：

```json
{
  "areaCode": "区优先，其次市，最后省",
  "tempBands": [
    {
      "tempBandId": "温度段ID",
      "dateRanges": [
        { "startMonth": 1, "startDay": 1, "endMonth": 12, "endDay": 31 }
      ]
    }
  ]
}
```

SDK 不发送 `status`、`remarks`、地区名称、温度名称或温度上下限；这些字段只用于展示或由服务端保留。

表单和服务端规则逐条对齐：

- 省必选；市必须依赖省，区必须依赖市；最终 `areaCode` 必须是六位数字。
- `tempBands` 必填且最多 5 项；`tempBandId` 不能重复；未使用的温度段可以传空 `dateRanges`，但至少一项温度段必须有日期范围。
- 月份为 1–12，日期按月份校验；2 月最多 28 日，2 月 29 日无效。
- Java 服务端额外要求已配置温度段按 `sortNo` 连续、日期范围不能重叠，并覆盖全年 365 天；SDK 在 `prepareSave` 阶段提前阻止不满足条件的草稿。

### 删除

- 单个：`DELETE /flockSimu/rearingPlan/areaTempConfig/delete`，参数 `{ areaCode }`。
- 批量：`DELETE /flockSimu/rearingPlan/areaTempConfig/delete-list?areaCodes=...&areaCodes=...`，最多 50 个六位编码；SDK去重后按重复 query 参数发送。

## 返回字段基准

### 地区温度配置

`list` / `get` 返回 `areaCode`、省市区编码和名称、`tempBandCount`、`operatorId`、`operatorName`、`operationTime`、`status`、`remarks`、`tempBands`。`tempBands[]` 返回 `tempBandId`、`bandCode`、`bandName`、`lowerTemp`、`upperTemp`、`sortNo`、`status`、`dateRanges`；`dateRanges[]` 返回四个整数月日字段。

列表结果为 `{ list, total }`；网络、权限、Java业务错误或响应结构错误抛出，不伪造空列表。

### 草稿

`prepareSave` 返回 `{ draft }`，其中 `draft` 只含最终 `areaCode` 和规范化后的 `tempBands`。`prepareRemove` 返回 `{ areaCode }`；`prepareRemoveBatch` 返回去重后的 `{ areaCodes }`。这些结果尚未改变服务端。

## 逐页操作步骤、权限与证据

1. 读取 `areaTree` 和 `tempBandList`，用地区节点 `id` 填充省/市/区，用启用温度段初始化日期表单。
2. `list` 按当前筛选分页读取；编辑先用行内 `areaCode` 调用 `get`，详情温度段作为编辑初始值。
3. 新建或编辑时调用 `prepareSave`；把 `draft` 展示给用户确认，确认后原样交给 `save`，取消不发请求。
4. 删除时调用 `prepareRemove` 或 `prepareRemoveBatch`，用户确认后再提交对应写能力。
5. 保存成功或响应不确定后调用 `list` / `get`，逐项核对地区、温度段、日期覆盖和操作时间；删除后逐项确认目标编码不再出现。

源码基准为 Portal `season/list.vue`、`TemperatureModalContent.vue`、`utils.js`、平台 HTTP 客户端和温度配置接口对接文档；后端基准为地区温度配置 Controller、请求/响应 VO、温度段 Controller、地区 Controller 及 `RearingPlanAreaTempConfigServiceImpl`。本节点已用离线源码锁定与请求形状测试覆盖；真实租户的地区树、温度段存在性和写入终态仍需真实环境按上述步骤复核。
