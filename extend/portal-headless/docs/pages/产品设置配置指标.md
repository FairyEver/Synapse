# 产品设置配置指标

页面路径：`/dashboard/product/setting/business-manage/configure/list`。

菜单归属是 `系统设置 → 生产设置 → 业务管理 → 配置指标`。这里的“生产设置”是 Portal 保留的“系统设置”子菜单，不是范围外的独立生产业务菜单。

## 页面能力定义

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询配置指标 | `product-setting-configure-list` / `productSettingConfigure.list` | `GET /config/traitIndex` |
| 读取编辑详情 | `product-setting-configure-get` / `productSettingConfigure.get` | `GET /config/traitIndex/{id}` |
| 本地准备编辑草稿 | `product-setting-configure-prepare-update` / `productSettingConfigure.prepareUpdate` | 不发请求 |
| 提交编辑 | `product-setting-configure-update` / `productSettingConfigure.update` | `POST /config/traitIndex` |

请求使用 `product` HTTP 实例，补 `devicetype=PC`，不发送 `module-type`。菜单权限为 `/dashboard/frame/business/configure`；列表、编辑、删除按钮分别受 `broiler:configtest:query`、`broiler:configtest:edit`、`broiler:configtest:delete` 控制。

页面只有编辑入口，没有可达的新建入口。页面虽然渲染删除按钮，但调用的是未配置 `deleteURL` / `customDelete` 的通用 `actionDelete`；当前 Java `TraitController` 也没有 DELETE 映射，因此 SDK 不暴露删除能力。

## 参数契约与表单提交规则

列表是 `useListPageModule` 的 `customLoad`，页面 `getDataListIsPage=false`，因此不发送 `pageNo`、`pageSize`，最终返回数组。请求参数固定为：

```json
{
  "order": "",
  "orderField": "",
  "name": "指标名或编码前缀",
  "type": 1
}
```

Java 查询使用 `name LIKE CONCAT(name, '%') OR code LIKE CONCAT(name, '%')`，所以 `name` 是名称或编码前缀，不是任意包含匹配。响应在 Portal product axios 中按单键包络解开，页面最终消费 `list`、`records`、`rows` 数组；SDK同时兼容 SDK 响应层收到的 `page` 包络并返回数组。

编辑前必须保留详情返回的 `id`。Portal 弹窗提交体是一个对象，不是数组：

```json
{
  "id": "当前配置指标ID",
  "type": 1,
  "code": "字段编码",
  "name": "字段名称",
  "fieldType": "字段类型字符串",
  "multipleAttribute": "字段属性",
  "defaultValue": "默认数值",
  "minValue": "最小数值或空字符串",
  "maxValue": "最大数值或空字符串",
  "decimalPlace": 0,
  "required": "默认展开/是否必须字典值",
  "unit": "字段单位"
}
```

`id` 只在编辑记录有值时追加；本页面没有 SDK 新建能力。`type` 固定为 `1`。`code`、`name`、`fieldType`、`multipleAttribute` 必填；`minValue`、`maxValue` 使用 Portal 的自定义数字校验，允许空字符串，拒绝非数字字符串；`decimalPlace`按页面数字控件规则为非负整数。其余字段按页面默认值保留：`minValue='0'`、`maxValue=''`、`decimalPlace=0`、`required='1'`，文本空值发送空字符串。

当前 Portal 对象提交与 Java `TraitController.add(@RequestBody List<Trait>)` 的数组签名不一致。SDK 保持 Portal 实际发送的对象形状，不擅自改成数组；真实环境未闭环前，POST成功回执不能被解释为已落库。

## 逐字段基准

| 字段 | 含义 |
| --- | --- |
| `id` | 配置指标ID；由列表/详情取得，编辑提交和回查使用。 |
| `code` | 字段编码。 |
| `name` | 指标名称。 |
| `fieldType` | 字段类型原始值：`1`文本、`2`数字、`3`日期、`4`下拉框、`5`单选、`6`多选。 |
| `multipleAttribute` | 字段属性字典值。 |
| `defaultValue` | 默认值。 |
| `minValue` / `maxValue` | 数字字段的最小/最大值；页面允许空字符串。 |
| `decimalPlace` | 数字字段的小数位数，非负整数。 |
| `required` | 页面“默认展开”字段提交的字典值；Java实体注释语义为 `1`必须、`2`不必须。 |
| `unit` | 字段单位。 |
| `general` | Java实体中的通用标识，列表/详情可能返回。 |
| `dateType` | 日期字段的日、周、月或年类型，列表/详情可能返回。 |
| `dicts` | 多属性字段对应的字典类型，列表/详情可能返回。 |
| `createDate` / `updateDate` | 创建/修改时间。 |
| `remarks` | 备注。 |
| `delFlag` | 删除标记；正常记录为 `0`。 |
| `type` | 后端类型；本页面提交固定为 `1`。 |

## 操作步骤、权限和证据边界

1. 使用当前用户和租户会话、并确认拥有菜单权限及 `broiler:configtest:query`，调用 `list({ name })`。
2. 从列表行取得 `id`，调用 `get({ id })`，把完整详情交给 `prepareUpdate`，不要丢弃未编辑字段。
3. 用户确认编辑后调用 `prepareUpdate`；校验失败时不发请求，用户取消时丢弃草稿。
4. 只把同一份 `draft` 交给 `update`，并确认拥有 `broiler:configtest:edit`。SDK发送 Portal 对象，不转换成数组。
5. POST返回成功或超时时，按同一 `id` 调用 `get`逐字段回查；不能只把 `true` 当作业务落库证据。
6. 不调用删除：页面删除入口没有有效URL处理器，Java控制器也没有 DELETE 接口；不能根据删除权限字符串猜测接口。

本轮逐页核对了 Portal 菜单、列表、编辑弹窗、公共列表删除实现、Java `TraitController`、`Trait`、`TraitDao.xml`、`TraitService`、SDK请求和 AI 契约测试。离线测试覆盖了请求字段、返回解包、权限边界、表单校验、删除缺口和对象/数组形状差异；尚未在真实测试环境使用浏览器会话执行查询、详情及 `prepare → POST → 回查`闭环，尤其未确认当前 Java `List<Trait>` 接口是否接受 Portal 发送的对象。
