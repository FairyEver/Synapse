## 能力定义

| 页面动作 | 能力 / 方法 | 请求 |
| --- | --- | --- |
| 列表筛选、分页 | `report-retirement-salary-list` / `.list` | `GET /hr/retire-staff-salary/page` |

| 编辑 | `prepareUpdate` → `update` | 本地准备 → `PUT /hr/retire-staff-salary/update` |

## 参数契约与逐字段基准

### 列表

列表首次查询的请求参数与 Portal 一致：

```json
{
  "order": "",
  "orderField": "",
  "name": "",
  "idCard": "",
  "organizationId": "",
  "useYearMonth": null,
  "status": null,
  "pageNo": 1,
  "pageSize": 20
}
```

`name`是姓名模糊条件；`idCard`是身份证号条件；`organizationId`来自角色组织树；`useYearMonth`按`YYYY-MM`发送；`status`只有`0`未使用和`1`已使用。页大小沿用Portal选择项，仅允许`10/20/50/100/200/500`。返回`{ list, total }`，`list`是当前页，`total`用于翻页，空列表不是权限证据。

每行包含`id`、`useYearMonth`、`name`、`idCard`、`organizationId`、`organizationName`、`status`、`remark`和12个金额字段：`enterpriseSalary`、`heatingFee`、`holidayAllowance`、`additionalInsurance`、`subsidy`、`transportFee`、`bookFee`、`laborFee`、`laundryFee`、`medicineFee`、`otherFee`、`actualAmount`。金额保持服务端原值，可为数字、十进制字符串或`null`。

页面底部合计使用当前页`listData`逐字段`Number(value) || 0`求和并格式化为两位小数，不是筛选条件下的全量合计；SDK返回原始分页数据，不伪造合计。

### 新建和编辑表单

Portal表单的必填字段只有：`useYearMonth`、`name`、`idCard`、`organizationId`。年月控件必须格式化为`YYYY-MM`；`organizationName`不是用户另填的字段，而是根据角色组织树选中的`organizationId`取得的全路径快照，必须随请求发送。12个金额输入框允许清空，SDK将空值统一发送为`null`。

创建/编辑的请求体按页面字段发送：

```json
{
  "useYearMonth": "2026-09",
  "name": "张三",
  "idCard": "身份证号",
  "organizationId": 9,
  "organizationName": "总部/财务",
  "enterpriseSalary": 100,
  "heatingFee": null,
  "holidayAllowance": null,
  "additionalInsurance": null,
  "subsidy": null,
  "transportFee": null,
  "bookFee": null,
  "laborFee": null,
  "laundryFee": null,
  "medicineFee": null,
  "otherFee": null,
  "actualAmount": "180.00"
}
```

编辑请求另外必须带当前记录`id`。若编辑详情带有`status`或`remark`，Portal会因展开详情对象而将其原样带回；SDK只允许它们作为可选透传字段，不能把`status`当成普通编辑动作。`prepareCreate`和`prepareUpdate`只做本地校验和载荷生成，用户取消时丢弃草稿，不发写请求。

### 删除、导入和创建汇总

删除必须同时提供列表最新的`id`和`currentStatus`。只有`currentStatus=0`才生成删除草稿；`1`在请求前失败，即使绕过前端按钮，后端也会拒绝。删除成功或超时后应重新查询确认记录状态/是否消失，不能只凭`true`回执报告完成。

模板下载固定传`fileName=退休人员工资模板`，SDK返回`fileName`、`contentType`、Base64内容和原始`byteLength`，空文件抛错。导入文件名必须是`.xml`、`.xlsx`或`.xls`，内容必须是非空标准Base64；请求使用multipart字段`file`。后端按Excel中的组织全路径匹配当前可见组织，存在未知组织时整体导入失败；成功后必须重新列表核对导入记录。

创建汇总的请求体为：

```json
{
  "organizationId": 9,
  "organizationName": "总部/财务",
  "useYearMonth": "2026-09",
  "staffIdList": [101, 102]
}
```

`staffIdList`必须非空、去重，并来自当前`status=0`的退休人员列表。后端创建汇总、建立人员关系并把所选明细改成`status=1`；返回汇总ID后应调用`reportRetirementSalarySummary.detail`核对人员和明细状态。该接口没有本页安全的取消/回滚动作，成功或超时都不能盲目重试。

## 操作步骤、失败处理与验证边界

1. 先用`.list`取得当前用户可见的组织、明细ID和状态；编辑时再用`.get`取得完整详情。
2. 新建/编辑先调用对应`prepare`，检查年月、身份、组织全路径和12个金额字段；用户确认后按契约映射逐字段调用写能力，取消时不发请求。
3. 删除先以最新状态调用`prepareRemove`，确认后调用`remove`；`status=1`不得提交。
4. 导入先调用`prepareImport`检查文件，确认后提交同一份Base64文件；成功或超时后重新列表核对。
5. 创建汇总前核对组织、月份和每个未使用明细ID；提交后到汇总明细页核对关系和`status=1`，没有可安全撤销动作。
6. 非法ID、月份、必填文本、金额、状态、页码、页大小、文件扩展名、Base64、重复人员ID在请求前失败；401/403、网络错误和后端业务错误原样保留。
