## 参数契约：**没有 `order`/`orderField`**

这一页是自己写的 `a-table` + `a-form` + 一个 `reactive` 分页对象，
**不用 `useListPageModule`**，所以 `list.js:474-475` 那两项固定开头**从未存在**。
它自己的调法是（`list.vue:432-441`）：

```js
formulaDefinitionApi.page({ pageNo: pagination.current, pageSize: pagination.pageSize, ...filters })
// filters = reactive({ taskType: undefined, formulaName: '', enabled: undefined })
```

⇒ 键序 **`pageNo → pageSize → taskType → formulaName → enabled → _t`**（`pageNo` 打头）。

| 参数 | kind | 默认 | 说明 |
| --- | --- | --- | --- |
| `pageNo` | number | `1` | 页面里这个值叫 `pagination.current`，序列化出去是 `pageNo` |
| `pageSize` | number | `20` | 后端是 `PageParam`：**`pageNo ≥ 1` 且 `pageSize ≤ 500`** 有 `@NotNull`/`@Max` 校验 |
| `taskType` | text | **不发** | 任务类型。取值先问 `listFormulaScenes()`（页面就是拿它灌下拉的） |
| `formulaName` | text | `''` | 公式名称（模糊）。初值是**空串**，照发 `formulaName=` |
| `enabled` | boolean | **不发** | 是否启用。**布尔**，`enabled=false` 照发（不是空值） |

⚠️ **`taskType` / `enabled` 不传时整项不出现在 URL 上**：页面的初值是 `undefined`，
platform 拦截器的 `qs.stringify(…, { skipNulls: true })` 把它整个丢掉。
本能力照做（`defaultValue: undefined`），所以首屏 URL 只有 **4 个键**。

## 逐字段基准

（`baseline/perf-manage-config.browser.json` 的 `formula/definition/page` 那条，`_t` 已归一）

```
GET /admin-api/infra/formula/definition/page?pageNo=1&pageSize=20&formulaName=&_t=<ts>
```

**与源码推导逐字段一致（含键顺序）**。同一页的 `formula/scene/list` 那条是任务类型候选：

```
GET /admin-api/infra/formula/scene/list?_t=<ts>
```

它**一个参数都没有**（页面就是 `http.get(url)`），对外的入口是 `listFormulaScenes()`。

**基准里没有的键**：`order`、`orderField`、`taskType`、`enabled` —— 前两个这一页从不发，
后两个是 `undefined` 被丢掉了（不是"基准漏抓"）。

## 这一页的读不止列表一条

页面的三个抽屉/弹窗各读一处（列表与候选由本页读取能力提供，其余只读详情仍按页面链路处理）：
「查看规则」→ `GET /infra/formula/definition/get?id=`；
「引用模板明细」→ `GET /performance/temcontent/kpitemprotocol/formula-references?formulaDefinitionId=`；
发布历史 → `GET /infra/formula/revision/list?definitionId=`。

行里的 `configJson` 是**结构化公式配置的 JSON 字符串**，页面每处都自己 `JSON.parse`
（解析器是页面自己的 `structured.js`）。本能力**不解析**它：那是页面逻辑，
无头复刻一份解析器只会多一份会漂的副本。

## 动作覆盖边界

- **保存并发布**已接入：`prepareFormulaDefinitionSave` → `saveAndPublishFormulaDefinition` →
  `cancelFormulaDefinitionSave`，请求为 `POST /admin-api/infra/formula/definition/save-and-publish`。
  它会直接发布新修订；调用方必须确认这是全公司共用的绩效公式变更，并按返回修订与列表回查。
- 页面上的启用/停用、删除、试算以及三个查看抽屉仍未登记为本页 SDK 能力；本次不把后端存在但
  页面没有稳定入口的接口当作已覆盖，缺口保留在范围审计中。

## SDK AI 说明契约（2026-09-22）

本节由当前 SDK 描述结果整理；说明权威来源为 `src/catalog/contracts-business.ts`。调用 `catalog.describe(id)`（或 `id-llm`）可得到参数来源、返回字段/状态、数据消费与后续映射；`catalog.describePage(页面路径)` 用于选择页面功能。以下更新以本节为准；前文历史请求/实测记录仍保留其记录日期。

### `perf-manage-formula-definition-list`

查询计分公式定义、启用状态、场景与模板引用数。

- 执行：`sdk.perfManageConfig.listFormulaDefinitions`；通过 `capabilities.invoke('perf-manage-formula-definition-list', args)` 调用时按 `params` 填参。性质：read。
- 参数：`pageNo` 可选 (number)；`pageSize` 可选 (number)；`taskType` 可选 (string)；`formulaName` 可选 (string)；`enabled` 可选 (boolean)。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`{ list: object[], total: number }`。list=[] 为当前页无记录；total=0 表示该筛选无结果。保留筛选条件检查页码，不将空结果解释成权限判定。
- 字段：`list`、`total`、`list[].id`、`list[].formulaName`、`list[].description`、`list[].taskType`、`list[].taskTypeName`、`list[].sceneTaskTypeName`、`list[].sceneCode`、`list[].sceneRevision`、`list[].enabled`、`list[].configJson`、`list[].templateReferenceCount`、`list[].referenceCount`、`list[].bindingCount`、`list[].totalReferenceCount`、`list[].updaterName`、`list[].updateTime`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：展示 formulaName、taskTypeName、enabled；configJson 必须解析后再解释规则，解析失败不能猜公式。引用数按 templateReferenceCount ?? referenceCount ?? bindingCount 取首个非空值。
- 完成条件：按用户要求交付本次筛选范围的结果；需要完整清单时继续翻页至覆盖 total，不能把当前页当全集。
- 后续：optional → `perfManageConfig.listFormulaScenes`：无参数调用，取 taskType ?? taskTypeCode 为筛选值；同类型选最新 sceneRevision，显示 taskTypeName/sceneName。
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。


公开但未注册方法也可通过 `catalog.describeMethod(sdkPath)` 获取独立契约：`perfManageConfig.listFormulaScenes`、`perfManageConfig.getDictTypeId`、`perfManageConfig.getProtocolDeductRule`、`perfManageConfig.listProtocolDeductRuleHistory`。原始 create 不防重；优先使用注册的防重创建能力。
