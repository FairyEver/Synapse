# 账套管理

- 页面：`/dashboard/finance/setting/accounting-manage/list`
- 实际系统：门户（顶层菜单没有 `system`，由 PC 系统选择器归入门户）
- 权限根：`/dashboard/finance/setting/accounting-manage`
- HTTP：`platform`；页面无法推导 `module-type`，浏览器与 SDK 均省略该头
- 源码锚点：前端 `d3cf56bdc76c73c5eb9252be84b9b39b3900b48e`，后端 `dcb3f360194e63c33cfd7ef9df4360355ff13533`

两份固定检出均在要求的分支且工作区无本地修改，但 `git pull --ff-only` 因内网 Git 主机不可达失败。因此下面的静态结论只锚定到上述提交；部署行为以 2026-09-22 独立浏览器基准为准。

## 参数契约

列表固定发送 renren 空值与分页：

```text
GET /admin-api/finance/accounting-manage/page
order=&orderField=&accountCode=&accountingName=&accountingStandardsApply=&periodYear=&status=0&pageNo=1&pageSize=20
```

可选 `corporationId` 为法人库 ID；为空时 browser/SDK 序列化后不出现在 URL。`status` 是绝对值：`0=启用`、`1=停用`。`periodYear` 为 `YYYY`。列表页大小只支持 10、20、50、100。

创建必填：

- `accountingName`：非空且不能全空格。
- `accountCode`：四位数字字符串，保留前导零；后端要求未删除账套间全局唯一。
- `corporationId`：法人库 ID，不是组织树 ID。
- `accountingStandardsApply`：平台字典值，不是字典记录 ID 或标签。
- `isLongTerm`：`0=时间范围`、`1=长期有效`。
- `startTime`：`YYYY-MM-DD`。
- `endTime`：时间范围时必填、与开始日同年且不早于开始日；长期有效时 SDK 发送空字符串。
- `periodId`：会计期间主记录 ID。时间范围只选开始日同年期间；长期有效可选开始年及以后期间。
- `accuracyId`：启用会计精度主记录 ID。

可选字段为 `industry`、`creditCode`、`taxCode`、`businessAddress`、`contacts`、`contactPhone`、`valueAddedUserId`。手机号非空时须为合法 11 位中国大陆手机号。币种不是输入：后端固定写 `currencyType=0`（人民币）；状态也不是输入，创建固定发送 `status=0`。

`setStatus` 同时接收最新列表行的 `currentStatus`、相反的绝对目标 `status` 与 `isEnable`。当前停用且目标启用时，只有 `isEnable=1` 才与 PC 可点击状态一致；状态相同或缺少启用许可时 SDK 在发请求前拒绝。

法人和人员候选可能较长。PC 法人组件会每页 200 遍历，SDK不照抄：两项搜索都要求非空关键字、默认每页 20、最多 100。人员接口固定 `statusList=1,4`，即在职与返聘。

## 最终返回逐字段基准

`list` 返回 `{ list, total }`。`list[]` 只保留 PC 列表、详情及动作需要的字段：

- 标识与基本信息：`id`、`accountingName`、`accountCode`、`currencyType`。
- 法人/准则/性质：`corporationId`、`corporationName`、`accountingStandardsApply`、`natureId`、`natureName`。真实公开 SDK 冒烟发现 11 条启用账套中有 2 条历史记录的 `corporationId=null`，浏览器法人列为空；不得从名称、其他账套或当前组织补 ID。查询、详情和启停仍使用账套自身 `id`，新建仍必须从法人候选选择法人 ID。
- 时效/期间：`isLongTerm`、`startTime`、`endTime`、`periodId`、`periodYear`。
- 精度：`accuracyId`、`accuracyName`、`accuracyCurrencyType`、`accuracyDecimalQuantity`、`accuracyDecimalUnitPrice`、`accuracyDecimalAmount`；三项小数位单位为“位”。
- 联系信息：`industry`、`creditCode`、`taxCode`、`businessAddress`、`contacts`、`contactPhone`。
- 增值会计与状态：`valueAddedUserId`、`valueAddedUserName`、`status`、`isEnable`、`createTime`。

详情能力直接校验并返回用户选择的最新 `list[]` 快照，不发 GET。部署详情展示账套性质与精度小数位，而固定前端检出没有完全体现该展示差异；浏览器证据优先，相关字段保留，但其多种空值尚未逐一观测。

候选返回：

- 法人 `{ list: [{ id, name }], total }`。
- 准则 `{ list: [{ id, value, label }] }`；提交 `value`。
- 期间 `{ list: [{ id, year }], total }`。
- 精度 `{ list: [{ id, name, currencyType, decimalQuantity, decimalUnitPrice, decimalAmount }] }`。
- 人员 `{ list: [{ id, realName, username, label }], total }`，`label` 为“姓名(工号)”。

导出返回 `{ fileName: '账套管理.xls', contentType, base64, byteLength }`。PC 用 `window.open` 直连同一个 `VITE_ZHDJ_PLATFORM_API` host；SDK使用同一 `platform` base URL 与会话头请求 `arraybuffer`，不打开浏览器窗口。空文件拒绝。真实部署返回 MIME `application/vnd.ms-excel;charset=UTF-8`、4317 字节，但文件头是 `PK`，即 OpenXML ZIP 容器；服务端仍固定声明 `.xls`，调用方做格式校验时必须看文件头，不能只看扩展名。

创建返回后端分配的账套主 ID（字符串或安全整数）；启停接口只接受后端根数据严格为 `true`。两者都不能只凭响应声明业务闭环：创建按编码/名称/状态分页回查同一 ID；启停按目标状态分页回查同一 ID。

## 操作步骤

创建：

1. 分别取得法人、会计准则、会计期间、会计精度；需要增值会计时用非空关键字搜索人员。
2. 调 `prepareCreate` 校验并向用户展示草稿。长期有效时确认 `endTime=''`；币种和状态不由用户覆盖。
3. 用户明确保存后，为该意图生成 `requestId`，调 `createIdempotent`。
4. 按 `accountCode`、`accountingName`、`status=0` 分页回查根返回 ID，并核对法人、期间、精度和日期。未唯一回查前不自动重发。

启停：

1. 从最新列表取得 `id/currentStatus/isEnable`；目标 `status` 必须相反。
2. 停用行启用前确认 `isEnable=1`；页面对其他停用行禁用按钮。
3. `PUT /admin-api/finance/accounting-manage/enableOrStop` body 为 `{ id, status }`。
4. 按目标状态分页回查同一 ID。要恢复时重新读取最新行，再发第二次写并再次回查；启用恢复可能因同法人已有启用账套失败。

创建能力使用 SDK 进程内短窗口防重；`requestId` 不发给后端，不跨进程。启停不接收防重键，虽然写绝对目标状态，超时仍须先回查，不能拿旧列表行并发重发。

## 未验证与外部差距

- 两固定源码检出无法联网更新，尚不能证明远端没有新增动作或字段。
- 公开门面、服务端门面、invoke、describe 与方法契约已接线。2026-09-22 真实 SDK 复跑完整返回 11 条启用账套，其中 2 条历史账套 `corporationId=null`；本地详情、四类候选、导出与说明入口均通过。
- 真实导出为 4317 字节，MIME 仍称 `.xls`，字节却是 `PK`/OpenXML 容器；这是部署端命名与内容不一致，SDK没有伪改服务端文件名。
- 创建与启停没有真实写闭环。PC 无删除或编辑，无法安全清理自建账套，因此不能用现有业务记录做测试，也未修改现有业务账套。
- 部署详情比固定前端源码多展示账套性质和会计精度小数位；这些字段已按浏览器范围进入返回契约，但 null/历史数据变体仍待基准补齐。
