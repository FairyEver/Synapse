# 财务字典（`/dashboard/setting/dict-platform/finance/list`）

## 能力定义

本页属于 Portal「系统设置 → 系统字典」，不是「平台设置 → 平台字典」下的同名页面。
菜单权限为 `/dashboard/setting/dict-platform/finance`，财务 wrapper 将共享字典页的
`useSystem` 固定为 `SYSTEM_FINANCE_VALUE=2`。页面使用 `platform` HTTP 实例，请求路径由该实例补齐
`/admin-api`；当前页面路径未命中 Portal 的 `module-type` 规则，因此不发送 `module-type`。

实际可达能力只有：

- 财务字典类型分页查询，按字典名称、字典类型模糊筛选；
- 从类型行进入字典数据子页，按 `dictType`、标签、状态分页查询；
- 读取数据详情、新增数据、编辑租户自有数据、单条删除租户自有数据。

类型新增/编辑/删除、批量删除、导入和导出没有在本页启用：根页对应按钮在 Portal 源码中被注释，
数据页只有新增、编辑、单条删除。后端虽保留部分导出或平台管理接口，也不扩大本页能力边界。

## 参数契约

类型列表请求为 `GET /admin-api/system/dict-type/page`，SDK 固定发送：
`order=''`、`orderField=''`、`useSystem=2`、`name`、`type`、`pageNo=1`、`pageSize=20`。
`pageSize` 只接受 Portal 分页器的 `10/20/50/100`。返回分页中的 `type` 是进入字典数据子页的
`dictType`；不能把类型行的 `id` 当成 `dictType`。

数据子页请求为 `GET /admin-api/system/dict-data/page`，参数为
`order=''`、`orderField=''`、`dictType`、`label=''`、`status=undefined`、`pageNo=1`、`pageSize=20`。
数据表单的 `label`、`value` 必填；`sort` 默认 `0` 且不能为负数；`status` 为 `0=开启`、`1=关闭`；
创建请求同时提交 `dictTypeId=dictType` 和 bridge 得到的 `dictType`。

类型行保留 `id/name/type/status/remark/createTime/useSystem/tenantEditable`；数据行保留
`id/sort/label/value/dictType/status/colorType/cssClass/remark/createTime/tenantId/platform`。
长整数 ID 保留后端返回的字符串或安全整数形态；时间保留原值，不做时区换算。

## 逐字段基准

实测源码证据（固定检出已更新至 Portal `test/portal/main`，锚点 `acab69acc7`）：

- `app/portal/menus/common.js` 登记路径和权限；四个 finance wrapper 只注入 `SYSTEM_FINANCE_VALUE`，
  其余行为来自 `common/setting/dict-platform/all/**`。
- 根页只展示类型列表和“字典数据”入口，筛选字段是 `name/type`；类型写按钮、根页批量删除和类型编辑/删除
  均在注释中。字典数据页筛选 `label/status`，提供新增、编辑、单条删除，并对 `platform=true` 的行禁用编辑和删除。
- 根页和子页都导入 `app/portal/utils/http/platform.js`，实际调用 `/admin-api/system/dict-type/*`、
  `/admin-api/system/dict-data/*`。

实测 Java 源码证据（固定检出 `test/test`，锚点 `0f1a55718eb`）：

- `DictTypeController` 的分页会强制 `tenant_editable=1`；类型 create/update/delete/export 明确返回无权限。
- `DictDataController` 的分页、详情、新增、修改、删除和导出属于租户接口；`DictDataServiceImpl` 查询合并
  平台共享数据与当前租户数据，写入要求明确租户上下文、字典类型启用且记录归属当前租户。
- 平台共享行由响应字段 `platform` 表示；租户接口的写操作不允许修改或删除平台行。

推断与边界：

- `module-type=null` 是根据当前 Portal 规则表对该页面路径未命中的推导结论；本页没有独立浏览器网络基准，
  不能把它描述成真实请求抓包结果。
- 后端 DTO 中存在的 `colorType/cssClass` 仅兼容保留；当前 Portal 表单不展示、不要求调用方用它们做业务判断。
- 请求成功只表示后端接受请求；不代表数据已业务生效。分页 `list=[]` 与 `total=0` 是空结果，权限、网络和
  后端校验失败必须作为错误处理，不能降级为空页。

## 操作步骤

1. 调用 `settingDictPlatformFinance.list`，按需传 `name/type/pageNo/pageSize`；保留结果行的 `type`、`id` 和完整字段。
2. 用户选择“字典数据”时，把同一行的 `type` 传给 `settingDictPlatformFinance.dataList` 的 `dictType`；不要猜代码或传类型主键。
3. 新增时提交 `dictType/label/value`，可选 `sort/status/remark`；编辑前用 `dataGet` 取得详情，再提交完整字段。
4. 只有 `platform` 不为 `true` 的行可编辑或删除；删除只传数据条目 `id`，不能用类型 ID。
5. 写请求返回新 ID 或 `true` 仍需按原 `dictType` 分页回查，核对 ID 和字段；超时先回查，不要盲目重试。
