## 参数契约与逐字段基准

列表默认请求保留页面实际发送的字段：

```text
order=&orderField=&name=&businessType=&businessDetail=&orgAttributes=&cashItem=&status=0&pageNo=1&pageSize=20
```

`status` 是绝对状态：`0=启用`、`1=停用`。`orgAttributes` 和 `cashItem` 是页面状态中仍会发送的旧键，不作为当前可见业务筛选解释。列表行保留 `id`、`name`、`businessType`、`businessDetail`、`createTime`、`updateTime`、`status`；长ID保持字符串，时间保持后端原值。

新建表单的基础规则：

| 字段 | 规则 |
| --- | --- |
| `name` | 必填，最多100个字符 |
| `businessType` | 必填，使用 `voucher_business_type` 字典值 |
| `businessDetail` | 必填，使用当前业务类型对应的场景字典值 |
| `entry` | 至少一组凭证信息；每组至少一条借方和一条贷方 |
| `entry[].summary` | 必填 |
| `entry[].accountingSetType` | 必填，账套字典整数值 |
| 借/贷行 `subjectId` | 必填，会计科目ID |
| 借/贷行 `subjectAmount` | 必填非空数组，金额代码不是金额数值 |

Portal 的 `customSubmit` 不是直接把表单分录原样提交：每组分录先做 `borrowList.concat(lendList)`；每行的 `subjectAmount`、`addInfo` 数组分别以英文逗号 `join` 成字符串，`cashItemList` 和 `type` 原样保留。五个业务详情对象 `outlay`、`income`、`allocate`、`inventory`、`transfer` 随顶层表单一起发送，未使用的对象也保留页面默认空字段；状态默认发送 `0`。

金额选项返回 `amountCode`、`amountLabel`、`sort`；提交分录时使用 `amountCode`，不能把标签文字当代码。导出请求去掉 `order`、`orderField`、`pageNo`、`pageSize`，只发送名称、业务类型、业务场景、旧筛选键和状态；文件名按Java源码为 `凭证模版基础信息.xls`。

状态按钮源码把当前列表行展开后仅替换 `status`，所以 `prepareSetStatus` 的 `draft` 是完整列表行，不是 `{id,status}` 两字段；`previous` 可在用户明确要求恢复时再次提交。预览是本地路由 bridge，列表行通常不含完整分录，不能把它当作详情读取。

## 操作步骤、失败处理与验证边界

1. 读取列表后，详情使用同一行 `id` 调用 `get`；金额选项使用当前表单的 `businessType` 和 `businessDetail`。
2. 新建执行 `prepareCreate` → 用户确认 → `create`；返回ID或请求超时后按同一ID回查 `get/list`。页面没有删除或取消创建接口，不能伪造 `cancel`。
3. 启停执行 `prepareSetStatus` → `setStatus`，提交完整 `draft`；`true` 回执后按同一ID回查状态，恢复时使用保存的 `previous`，不是事务回滚。
4. 导出消费 `base64`、`byteLength`、`contentType`；空文件、非法ID、名称长度、空借贷分录、空金额数组、错误借贷类型或坏响应在发请求前/收到响应后失败。

本节点已完成静态源码核对、表单转换夹具、状态整行 body、导出、金额选项、坏响应和 AI 映射反证；未启动浏览器，未执行真实测试环境读请求，也未执行真实 `prepare → submit → cancel` 写闭环。固定源码中的状态请求与部署兼容性仍需真实基准验证。

## 常用摘要候选（隐藏弹窗 `modal-mark.vue`）

`GET /admin-api/finance/abstract-manage/page`，能力 `finance-setting-voucher-templates-abstract-list` / `financeSettingVoucherTemplates.listAbstracts`。

弹窗没有菜单项，是**隐藏组件**，被两处 `createModal` 打开：

| 调用点 | 选中后写什么 |
| --- | --- |
| `[mode]/[id].vue:448`（凭证模板表单） | `entry[index].summary = data.abstracts`、`entry[index].summaryId = data.id` |
| `app/portal/components/portal/finance/vouchers-table/index.vue:591`（通用凭证表格） | 该行的 `mark = data.abstracts`、`markId = data.id` |

两处都只消费 `id` 与 `abstracts`；`quickNumber`、`status`、`createTime`、`tenantName` 只是后端 `AbstractManageRespVO` 的透传字段。

请求参数（顺序即 URL 顺序）：`order`、`orderField`、`searchKey`、`status`、`pageNo`、`pageSize`。

- `searchKey` 初值是空字符串（弹窗用的是 `a-input-search`，回车/点按钮才触发查询）。后端 `AbstractManageMapper` 只在它非空时拼 `and(abstracts LIKE %key% or quickNumber = key)`，所以空串等价于"不加关键字条件"，不是"按摘要为空筛选"。
- **`status` 页面写死 0**（`form: { searchKey: '', status: 0 }`），页面上既没有状态下拉也没有状态列。SDK 同样钉死该值、不开放给调用方 —— 因此这里返回的不是"全部常用摘要"。`AbstractManageDO.status` 在后端没有字典登记（字段注释只有"状态"两个字），**0/1 的业务含义未知**，SDK 不解释、也不向用户解释。
- `pageSize` 默认 **10**：这个弹窗的 `useListPageModule` 没有 `styleV2`（`list.js:391` 的 `styleV2 ? 20 : 10`），选项仍是全局默认的 10/20/50/100。
