## 参数契约

**POST，body 就是参数对象**（`customLoad: async (params) => http.post(url, params)`，
`salary/adjust/list.vue:116-122`）。没有 `_t`。

顺序逐字取自页面 `form:` 初值（`salary/adjust/list.vue:123-129`）：

```
order → orderField → year → month → name → staffCode → orgIdList → pageNo → pageSize
```

初值：`{ year: '', month: '', name: '', staffCode: '', orgIdList: [] }`

⚠️ **注意 `year`/`month` 在 `name` 之前** —— 与[奖励导入](./奖励导入.md)（`name` 打头）
以及[考核导入](./考核导入.md)（也是 `name` 打头）**都不一样**。三页三个字段序。

## 逐字段基准

```
POST /admin-api/salary/basedata/hrsalarymanagement/adjustPage
Content-Type: application/json
{"order":"","orderField":"","year":"","month":"","name":"","staffCode":"","orgIdList":[],"pageNo":1,"pageSize":20}
```

同页还抓到 `GET /admin-api/org/organization/getRoleOrganizationTree?_t=<ts>`
—— 组织下拉的候选，不是列表请求，**不提供**。

## ⚠️ 这一页与兄弟页最不一样的两处

| # | 这一页 | 对比 |
| --- | --- | --- |
| 1 | **`year`/`month` 默认是空串**（基准里就是 `""` / `""`） | 奖励导入默认**当前年月**（`"2026"` / `9`） |
| 2 | 字段序 `year → month → name → staffCode` | 另外两页都是 `name` 打头 |

`month` 的空值是**空串**，不是 `0`、不是 `null`（基准确认）。本契约照发空串，
没有做任何"空就丢掉"的加工 —— 少发一项就不与浏览器逐字段一致（conventions 第 4 条）。

页面还开了 `selectable: true` + `selectCrossPage: true`（跨页多选），
但那只影响「批量调整」按钮的取数，**不影响列表请求**。

## 真实验证

**本波没有对真实环境发过任何请求。** 已验证的是：

- `test/perf-salary.test.ts`：不传参时，**body 的每一个字段（含值）与基准逐字段一致**；
  另有一条钉住"字段序里 `year`/`month` 在 `name` 之前"。
- 反证：把 `year`/`month` 顺序对调 → 红 2 条。

列表**返回**的真实条数没有测过。

## 敏感字段

⚠️ 返回行同样是**逐人逐月的工资数据**，另外还多两项**调整值**：

| 字段 | 含义 |
| --- | --- |
| `adjustScore` | 调整考核分数 |
| `adjustProfit` | 调整利润总金额 |
| `adjusterName` | 最后修改人（**指向具体员工**） |
| `name` / `staffCode` | 姓名 / 工号 |

其中 `adjustScore` / `adjustProfit` / `adjusterName` / `adjustRemark` 是**具名字段**
（列表定位与语义需要），`name`/`staffCode` 也是。
**更敏感的那一类在这一页没出现**（这一页的列里没有身份证号、没有基本/考核/利润工资明细）——
那些在[奖励导入](./奖励导入.md)，处理方式见那一页的「敏感字段」一节。

## 动作审计与覆盖边界

本页的唯一业务写动作是调整工资，接口和表单规则已按 Portal 页面与后端 `saveAdjust` 控制器/服务静态核对。它直接覆盖工资调整数据，没有服务端撤销动作，必须把用户确认和证据边界说清楚。

| 入口 | Portal 请求 / 规则 | SDK 使用边界 |
| --- | --- | --- |
| 行内「调整」/ 顶部「批量调整」 | `POST /salary/basedata/hrsalarymanagement/saveAdjust`；body 字段顺序为 `adjustScore → adjustProfit → adjustRemark → idList`。`adjustScore` 必填，范围 `-99999..99999`；`adjustProfit` 可选，若填写同范围校验；`adjustRemark` 可空但不能是纯空白，最长 500；`idList` 必须是显式行 ID 数组。 | `prepare` 先校验字段并形成草稿；`submit` 发送明确的 `idList`；`cancel` 放弃草稿、不发请求。成功后必须按这些 ID 重新查询列表，核对调整分数、利润、备注和修改人。没有服务端 cancel/undo。 |
| 组织筛选候选 | `GET /org/organization/getRoleOrganizationTree`，约 580 KB 整棵树。 | 不照抄为本页能力；只使用页面权限范围内、调用方明确提供的组织条件。 |

### `idList` 与跨页选择的静态疑点

Portal 页面声明了 `selectCrossPage: true`，但 `handleAdjustMultiple()` 又从 `rrList.listData` 按选中 ID 过滤后再组装用户数组。仅凭源码无法证明最终 `idList` 一定包含所有跨页选择项；因此 SDK 只接受调用方明确给出的 `idList`，不声称自动复现 Portal 的跨页并集行为，也不把“勾选过跨页”当作已验证事实。

### prepare → submit → cancel

1. `prepare` 应先取得待调整行的当前值，校验 `adjustScore`、`adjustProfit`、`adjustRemark` 和非空且唯一的 `idList`，形成待确认草稿，不发请求。
2. `submit` 发送 `POST saveAdjust`；成功后重新查询列表并逐个 ID 核对结果。不能只依据 HTTP 成功或空响应判断工资数据已正确更新。
3. `cancel` 仅放弃草稿，不调用接口；由于后端没有撤销动作，提交后发现错误只能按业务流程重新调整，不能假定 SDK 可以回滚。

### 证据边界

字段校验、请求形状和权限上下文来自 Portal 源码及 Java 服务静态审计。当前没有真实浏览器批量选择、工资调整或提交后列表复核冒烟；跨页选择并集、空值在真实服务上的覆盖效果、权限拒绝响应和幂等性均未实测，不能写成已验证证据。

## SDK 新增动作契约索引

本节是页面源文档维护区。`<!-- ai-contract-business:start -->` 后的生成片段目前只展示列表能力；新增动作的用途、参数、返回和步骤以 [`src/catalog/contracts-business.ts`](../../src/catalog/contracts-business.ts) 及 `catalog.describe(id)` / `catalog.describe(id + '-llm')` 为准。

保存写入口必须通过 `invoke` 传非空 `requestId`；同一次超时重试原样复用，新的业务意图使用新值。`requestId` 只用于 SDK 本地防重，不进入 Portal body。

`orgIdList` 的可执行候选是 `contract-support-role-organization-search`，参数为组织名称关键字和 `scope=performance`，值取 `list[].id`。这是绩效角色组织树 ID，不是普通部门 ID。`idList` 没有等价的独立候选能力，只能从 `perf-salary-adjust-list.list[].id` 选取，不能用人员或组织 ID 替代。

- `perf-salary-adjust-prepare-save`：参数为 `adjustScore`、`adjustProfit`、`adjustRemark`、`idList`；输出 `{ draft: { adjustScore, adjustProfit, adjustRemark, idList } }`。只做本地校验和草稿装配；确认时按 `result.draft.*` 映射给 `perf-salary-adjust-save`，取消只丢弃本地草稿，不带能力目标、不发请求。
- `perf-salary-adjust-save`：参数同上，成功返回 `null | undefined`。它直接写工资调整数据；调用方须在提交前保存目标列表条件为 `context.adjustFilter`，写后用该上下文查询并按 `idList` 逐行核对调整分数、金额、备注和修改人。空回执不等于完成；没有服务端 cancel/undo，超时先读回再决定是否重试；写后复核是完成条件。

失败处理：校验失败按 Portal 的范围、备注和 ID 数组规则修正后重新 prepare；跨页选择只能由调用方提供最终 `idList`，SDK 不声称复现页面的跨页并集；权限、网络或不确定写入结果按证据边界处理。没有真实浏览器调整和写后列表复核，不能报告工资已改成功。

## SDK AI 说明契约（2026-09-22）

以下由真实 SDK 描述生成；权威数据为 src/catalog/contracts-*.ts。前文浏览器/冒烟记录是历史证据，本节不将源码和离线验证称作新的部署实测。

### `perf-salary-adjust-list`

查询工资找齐调整记录，年月默认不筛选；不会自动补齐工资。

执行：`sdk.perfSalary.listSalaryAdjust`；性质：read。查询工资找齐调整记录，年月默认不筛选；不会自动补齐工资。

- 边界：使用当前 SDK 用户与租户的数据权限；页面上下文由 SDK 绑定，调用方不要另拼 module-type。

| 参数 | 意义与来源 |
| --- | --- |
| year | 年度，`'YYYY'` **字符串**（年选择器 value-format）。⚠️ 这一页与「奖励导入」不同，**默认空串**。用 buildSalaryYearMonth 生成；来源：用户给出的业务条件；格式和必填性按参数契约。 |
| month | 月份 1..12，**数字**（不是 '09' 这种补零字符串）。⚠️ 同上，**默认空串**；来源：用户给出的业务条件；格式和必填性按参数契约。 |
| name | 姓名（模糊匹配）；来源：用户给出的业务条件；格式和必填性按参数契约。 |
| staffCode | 工号；来源：用户给出的业务条件；格式和必填性按参数契约。 |
| orgIdList | 角色组织树所选组织 ID 数组；只选择 selectable=true 的节点；来源：contract-support-role-organization-search 返回 list[].id；由用户选定，不能以名称、编码或其他实体 ID 替代；候选：contract-support-role-organization-search list[].id |
| pageNo | 页码，默认 1；来源：用户给出的业务条件；格式和必填性按参数契约。 |
| pageSize | 每页条数，默认 20；来源：用户给出的业务条件；格式和必填性按参数契约。 |

返回：`{ list: object[], total: number }`。list=[] 为当前页无记录；total=0 表示该筛选无结果。保留筛选条件检查页码，不将空结果解释成权限判定。

- list[].adjustProfit：调整利润总金额，保留正负号；页面调整控件明确标“元”，不除以 100；单位：元

- 消费：展示原分数/金额正负号及备注；多次调整不能在没有业务主键与周期核对时累加。

完成条件：按用户要求交付本次筛选范围的结果；需要完整清单时继续翻页至覆盖 total，不能把当前页当全集。

- 失败处理：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。

逐字段嵌套结构、可空性、格式及证据由同一 describe 返回；完整生成参考见 ai-contract-reference.generated.md。
