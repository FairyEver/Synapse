# 人工成本计提分配表

页面路径：`/dashboard/report/labor-cost-allocation/list`。

## 页面能力定义

同一个 Portal 页面有两个 Tab，SDK 用 `allocationType` 区分：`salary` 为工资成本，`socialFund` 为社保公积金；缺省为 `salary`。

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询列表与合计 | `report-labor-cost-allocation-list` / `reportLaborCostAllocation.list` | 工资：`GET /admin-api/hr/salary-cost-accrual-allocation/page` + `/sum`；社保：`GET /admin-api/hr/social-fund-cost-accrual-allocation/page` |
| 准备新建 | `report-labor-cost-allocation-prepare-create` / `.prepareCreate` | 不发请求 |
| 新建 | `report-labor-cost-allocation-create` / `.create` | `POST /admin-api/hr/{salary|social-fund}-cost-accrual-allocation/create` |
| 准备编辑 | `report-labor-cost-allocation-prepare-update` / `.prepareUpdate` | 不发请求 |
| 编辑 | `report-labor-cost-allocation-update` / `.update` | `PUT /admin-api/hr/{salary|social-fund}-cost-accrual-allocation/update` |
| 准备删除 | `report-labor-cost-allocation-prepare-remove` / `.prepareRemove` | 不发请求 |
| 删除 | `report-labor-cost-allocation-remove` / `.remove` | `DELETE /admin-api/hr/{salary|social-fund}-cost-accrual-allocation/delete/{id}` |
| 下载导入模板 | `report-labor-cost-allocation-download-template` / `.downloadTemplate` | `GET /admin-api/hr/{salary|social-fund}-cost-accrual-allocation/download-template` |
| 准备导入 | `report-labor-cost-allocation-prepare-import` / `.prepareImport` | 不发请求 |
| 导入 | `report-labor-cost-allocation-import` / `.importExcel` | `POST /admin-api/hr/{salary|social-fund}-cost-accrual-allocation/import`，multipart 字段 `file` |

页面菜单权限为 `/dashboard/report/labor-cost-allocation`，属于薪酬管理 `module-type=14`，所有请求使用 Portal 的 `platform` HTTP 实例。Portal 的 `platform.js` 会补 `/admin-api`，SDK 方法内部使用不带此前缀的 `/hr/...` 路径。

## 列表、Tab 与合计规则

列表请求参数固定为：

```json
{
  "order": "",
  "orderField": "",
  "useYearMonth": null,
  "organizationId": null,
  "standardUnitId": null,
  "status": null,
  "pageNo": 1,
  "pageSize": 20
}
```

月份由 Portal 月选择器转换为 `YYYY-MM`。分页选项为 `10/20/50/100`。状态值为 `0=待计提`、`1=待月结`、`2=已月结`。

工资成本 Tab 的 `customLoad` 用同一筛选参数并行请求 `/page` 和 `/sum`，SDK 返回的 `summary.predictedPayableAmount` 来自 `/sum`。社保公积金后端没有 `/sum`，Portal 直接对当前页的 8 个金额字段求和，SDK以相同规则返回 `summary`。

列表行字段包括 `id`、`useYearMonth`、`standardUnitId`、`standardUnitName`、`departmentId`、`departmentName`、当前 Tab 金额字段、`status` 和 `statusName`。ID 必须作为提交值，名称只是组织树生成的路径快照。

组织和标准化单元都由共享组件通过 `/org/organization/getRoleOrganizationTree` 提供。SDK不另造下拉选项接口，调用方应使用当前会话实际可见的组织树候选。

## 表单提交与状态规则

新建和编辑页面的公共必填字段是：月份、标准化单元、部门。工资成本 Tab 还要求 `predictedPayableAmount`；社保公积金 Tab 还要求以下 8 个字段：

```text
predictedUnitPension
predictedUnitMedical
predictedUnitUnemployment
predictedUnitCriticalIllness
predictedUnitMaternity
predictedUnitWorkInjury
predictedUnitSocialSecurityTotal
predictedUnitProvidentFundTotal
```

金额字段按 Portal `a-input-number` 的 `precision=2` 作为数值提交；Portal 没有声明额外的正负范围规则，SDK不擅自增加范围限制。请求体包含 `useYearMonth`、标准化单元/部门 ID 与名称快照，以及当前 Tab 对应金额字段；`allocationType` 和 `status` 只用于 SDK 选择端点与执行状态门禁，不写入后端请求体。

列表中状态为 `1` 或 `2` 时，Portal 的编辑和删除动作都被拦截并提示“财务已计提/已封账无法编辑/删除”。SDK 的 `prepareUpdate`、`update`、`prepareRemove`、`remove` 均要求当前状态为 `0`，不能用 SDK 绕过页面门禁。创建由 Java 服务端强制设为状态 `0`，后端还按月份+部门防止重复新增。

## 模板下载与文件导入

模板下载弹窗要求组织和月份，发送：

```json
{
  "organizationId": 123,
  "useYearMonth": "2026-09"
}
```

工资成本和社保公积金模板文件名分别为 `工资成本计提分配模板.xlsx`、`社保公积金计提分配模板.xlsx`。SDK返回非空文件的 `base64`、字节数和内容类型。

导入接受 `.xml`、`.xlsx`、`.xls`，SDK先校验文件名、标准 Base64 和非空内容，再用 multipart 字段 `file` 提交。`prepareImport` 只做本地预览；用户取消时丢弃预览，不发请求。

## 逐页操作步骤与证据边界

1. 选择 `allocationType`，用 `list()` 读取当前 Tab，确认记录 ID、月份、组织、部门、金额和状态。
2. 新建调用 `prepareCreate()`；编辑从当前列表行带上 `status` 调用 `prepareUpdate()`；只有状态 `0` 会生成草稿。
3. 用户明确确认后，把同一份 `draft` 原样交给 `create()` 或 `update()`；成功或响应不确定后按同一 Tab 调 `list()` 回查。
4. 删除先用列表行的 `id` 与 `currentStatus` 调 `prepareRemove()`，确认后把同一草稿交给 `remove()`；成功或响应不确定后回查 ID 是否消失。
5. 导入先 `prepareImport()`，确认文件后调用 `importExcel()`；导入成功或响应不确定后按月份、组织、部门回查，不能只相信成功文案。

本轮逐页核对了 Portal 菜单、列表两个 Tab、列表合计、筛选/分页、编辑页、模板弹窗、权限和 platform 请求，及 Java 两个 Controller、Page/Save/Response VO、Service、状态枚举和 DO。尚未在真实测试环境使用浏览器会话执行两个 Tab 的列表、模板、导入及 `prepare → submit → 回查` 闭环；当前证据为 Portal/Java 源码和离线请求形状测试。
