# 产品设置鸡群批次状态

页面路径：`/dashboard/product/setting/business-manage/batch-status/list`。

## 页面能力定义

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询批次状态 | `product-setting-batch-status-list` / `productSettingBatchStatus.list` | `GET /flockStatus/list` |
| 查询场区栋号 | `product-setting-batch-status-building-list` / `productSettingBatchStatus.buildingList` | `GET /config/building/getByFarmId` |
| 查询推荐终止日期 | `product-setting-batch-status-recommend-end-day` / `productSettingBatchStatus.recommendEndDay` | `GET /flockStatus/recommendEndDay` |
| 本地准备终止草稿 | `product-setting-batch-status-prepare-termination` / `productSettingBatchStatus.prepareTermination` | 不发请求 |
| 终止批次 | `product-setting-batch-status-termination` / `productSettingBatchStatus.termination` | `POST /flockStatus/termination` |
| 恢复批次 | `product-setting-batch-status-activate` / `productSettingBatchStatus.activate` | `POST /flockStatus/activate` |

请求使用 `product` HTTP 实例，补 `devicetype=PC`，不发送 `module-type`。菜单权限为 `/dashboard/frame/business/batch-status`；查询受 `management:batch-status:query` 控制，编辑状态受 `management:batch-status:submit` 控制。页面没有创建、删除或修改批次基础资料的可达入口，SDK不扩展这些接口。

## 参数契约与表单提交规则

列表是 `useListPageModule` 的 `customLoad`，唯一必填筛选字段为场区 `farm`。Portal 初始表单和SDK请求参数为：

```json
{
  "order": "",
  "orderField": "",
  "farm": "场区ID",
  "building": "",
  "stageEndingFlag": "",
  "variety": "",
  "line": "",
  "lineVer": "",
  "gen": "",
  "scope": 1,
  "pageNo": 1,
  "pageSize": 20
}
```

`stageEndingFlag` 为数字 `0` 或 `1`：`0=未终止`、`1=已终止`；`0` 是有效筛选值，不能按空值丢弃。场区变化时Portal先清空栋号，再用场区ID读取栋号候选；SDK返回的 `value` 是栋号ID，`label` 是 `shortName`，不能把展示文本当作请求ID。分页大小遵循页面支持的 `10/20/50/100`。

终止/恢复共用页面弹窗：

- 弹窗状态由列表行是否有 `stageEndDate` 初始化；开启“终止”时才校验 `stageEndDate` 必填。
- 日期选择器不允许选择早于该行 `stageStartDate` 的日期；`prepareTermination` 同样执行这个边界校验。
- 第一次终止固定发送以下body，`isConfirm=0`：

  ```json
  { "groupId": 101, "stageEndDate": "2026-09-30", "isConfirm": 0 }
  ```

- Java服务在发现鸡群转移、鸡只转移或日记录时，会返回 `isConfirm=1` 的二次确认结果。用户明确同意后，才用同一个 `groupId` 和 `stageEndDate` 重发 `isConfirm=1`；用户取消时不再发请求。
- Portal的product响应拦截器会把只有一个 `data` 字段的响应解包，因此服务端的 `data.isConfirm=1` 在该实例中可能以数字 `1` 到达页面；SDK同时兼容数字 `1` 和对象包络，但不会自动替用户确认继续。
- 恢复严格发送 `POST /flockStatus/activate`，body为 `null`，`groupId`放在query参数中。

## 逐字段基准

| 字段 | 含义 |
| --- | --- |
| `list[].id` | 底层鸡群记录ID；页面状态动作不用它。 |
| `list[].groupId` | 批次组ID；终止、恢复和推荐终止日期的目标参数。 |
| `list[].batch` | 批次号。 |
| `list[].farmName` | 场区展示名称。 |
| `list[].buildingName` | 场栋展示名称。 |
| `list[].stageStartDate` | 进鸡日期；终止日期的最小可选边界。 |
| `list[].stageEndDate` | 终止日期；为空时页面展示“未终止”。 |
| `list[].maleQty` / `list[].femaleQty` | Java按批次组计算后的公鸡/母鸡数量。 |
| `list[].varietyName` / `list[].lineName` | 品种/品系展示名称。 |
| `list[].lineVer` | 品系版本。 |
| `list[].genName` / `list[].genNucleusName` | 代次/世代展示名称。 |
| `total` | 当前场区和筛选条件下的总记录数，不是当前页长度。 |

栋号候选：

| 字段 | 含义 |
| --- | --- |
| `value` | `Building.id`；传回 `list({ building })`。 |
| `label` | `Building.shortName`；仅用于页面展示。 |

终止结果：

| 字段 | 含义 |
| --- | --- |
| `completed` | 本次请求未要求二次确认，服务端已接受终止。不能替代列表回查。 |
| `confirmationRequired` | 服务端要求用户明确确认后再发送 `isConfirm=1`。 |
| `message` | 服务端提示文本；没有提示时为 `null`。 |

## 操作步骤、权限和证据边界

1. 先用有查询权限的当前用户调用 `list({ farm, ... })`，从同一行取得 `groupId`、`stageStartDate` 和当前状态。
2. 场区切换时丢弃旧栋号，调用 `buildingList({ farmId })`，把候选的 `value` 传回新的列表查询。
3. 终止时先调用 `prepareTermination({ groupId, stageStartDate, stageEndDate })`；用户取消只丢弃草稿。
4. 用户明确提交后调用 `termination({ draft })`。若返回 `confirmationRequired=true`，展示服务端提示，只有用户明确同意才调用 `termination({ draft, isConfirm: 1 })`。
5. 恢复时用户明确确认后调用 `activate({ groupId })`。
6. 终止或恢复成功、超时或确认结果不明确时，都按原场区和筛选条件重新 `list()`，按 `groupId` 回查 `stageEndDate`；不能只把 `true` 或 `completed=true` 当作最终业务证据。

本轮逐页核对了Portal菜单、列表、弹窗、页面权限、Java `FlockStageStatusController`/`FlockTransferListVO`/`TerminationBatchVO`/`FlockDTO`/Mapper/Service/`BuildingController`、SDK请求和离线反证测试。尚未在真实测试环境使用浏览器会话执行场区/栋号联动、列表读取及 `prepare → termination(0) → confirmation(1) → 回查`或恢复闭环；离线测试不替代真实环境证据。
