# 考勤统计（`/dashboard/attendance/attendance-sheet/list`）

> 2026-09-22：已新增考勤表编辑/保存、归档/取消归档、删除和统计簿能力，见[考勤表操作](考勤表操作.md)。下文保留原列表验证记录，“未做写操作”为历史状态；本次新增写链尚未真实SDK验证，考勤簿与打印仍缺失。

阶段① 第三条业务线（考勤域）的**第二个页面**，也是第一条「**同一后端接口、两个页面**」的记录：
它与考勤档案（`docs/pages/考勤档案.md`）打的是同一个 `GET /org/hrAttendanceSheet/page`，
**唯一差别**是档案页多一个 `isArchived=1`。

四件套的其它三件分别在：能力定义与参数契约 → `src/capabilities/attendance-statistics.ts`；
逐字段基准 → `baseline/attendance-statistics.browser.json`；回归测试 → `test/attendance-statistics.test.ts`；
真实环境只读冒烟 → `smoke/read-attendance-statistics.mjs`。

它要回答的问题只有一个：

> 当两个页面共用同一个接口时，「能力」的边界画在哪里？
> 页面清单给的 `write` 标志、浏览器抓到的请求、`pagePath` 推导出来的 module-type，
> 哪些能直接用、哪些必须复核。

## 筛选条件与列表字段（实测自真实页面）

筛选区在一行里（`common-fold`）：

| 控件 | 形态 | 对应参数 | 备注 |
| --- | --- | --- | --- |
| 部门 | `portal-hxr-select-user-department :type="1"` | `departmentId` | `a-select` + 虚拟列表，候选**全量拉取** |
| 班组 | `portal-hxr-select-user-department :type="2"` | `organizationId` | 同上，另一个 type |
| 操作 | 查询 / 重置 / 新建 | — | 「新建」是写入口，本页没做 |

**这一页没有月份选择器** —— 考勤档案页有一个（`yearMonth`），这一页没有。所以参数契约里
既没有 `yearMonth`，也没有档案页钉死的 `isArchived`（实测请求里两样都没有）。

列表列：序号 / 名称 / 部门 / 班组 / 人员数量，行尾有「编辑」「归档」「预览」「删除」四个动作。
其中「编辑 / 归档 / 删除」都带 `:disabled="!!record.isArchived"` —— 这个细节本身就是证据：
**这一页的列表里会出现已归档的行**（见下面「这一页不筛归档状态」）。

就是因为用了后一种顺序）。

## 三个必须记住的点

### 1. `isArchived` 是这两个页面的分界，所以这一页**没有**这个参数，而且硬传会被拒

考勤档案页把 `isArchived` 钉死成 1，本页**一个字都不发**（浏览器也不发）。
无头侧的做法与档案页**刻意不同**：

| | 档案页 | 本页 |
| --- | --- | --- |
| 硬传 `isArchived` | 静默无效（永远是 1） | **拒绝**，并提示改用 `attendance-archive-sheet-list` |

理由：档案页只有"已归档"这一个值，钉死不会让调用方丢掉任何他想要的东西；
而本页的调用方如果真的传了 `isArchived`，说明他想要的是**另一个页面**的数据 ——
这时静默返回另一种数据，正好是仓库里反复出现的那类"不报错但是错的"（与 D34 相反的那一支）。

### 2. 这一页**不筛**归档状态，它不是"未归档列表"

实测（见下面真实验证记录）：无筛选时共 **118** 条，而档案页（`isArchived=1`）是 **105** 条；
本页首 5 条里有 **2 条** `isArchived` 为真（如 `#153`）。
⇒ 这一页是「**全部考勤表**」，是档案页的**超集**，不是它的补集。
页面上那三个 `:disabled="!!record.isArchived"` 也印证了同一点。

这条会直接影响 AI 的用法：想拿"还没归档的考勤表"**不能**靠这一页减去档案页，
`isArchived=0` 这条查询路径没有被验证过（见「尚未覆盖」）。

### 3. `module-type` 这个头在浏览器里读的是 cookie，不是当前页的 URL

与考勤档案、作业管理两条线踩到的是同一个坑，本轮**当场又踩到一次**：
前三条（页面挂载时）是 `module-type: 11`，随后并行任务在同一个浏览器里跳到
`/dashboard/assignment/` 下的页面（那条规则是 12 学习管理），第四条（本页的「查询」，
URL 一个字没变）就变成了 `module-type: 12`。

所以：**基准里的 `module-type` 要拿规则表复核，不能直接当答案抄**（比对请求头时用第一条）。
SDK 侧不受影响 —— `resolveModuleType('/dashboard/attendance/attendance-sheet/list')` 是确定性的 11。

### 4. 候选入口是**复用**档案页的，本文件不另建

两个页面的部门 / 班组选框是同一个组件、同一个接口、同一个 `type` 取值，
而且同域、module-type 同为 11，所以档案页那条 `attendance-org-search` 的页面上下文对本页同样成立。
再建一个内容一样的候选能力，只会让调用方猜该用哪个。
`test/attendance-statistics.test.ts` 有一条用例专门锁"复用没有落空"（被指向的能力真的存在、
真的有关键字参数、`pagePath` 与推导前提对得上）。

## 参数契约

| 参数 | kind | 必填 | 说明 |
| --- | --- | --- | --- |
| `departmentId` | search | 否 | 长选项。`lookup` → `attendance-org-search`（`keyword`），`type=1`，实测全量 17 条 |
| `organizationId` | search | 否 | 长选项。`lookup` → 同上，`type=2`，实测全量 922 条，**必须先问用户关键字** |
| `pageNo` / `pageSize` | number | 否 | 默认 1 / 20 |

请求参数的**顺序是契约的一部分**（D20 逐字段一致）：
`order, orderField, departmentId, organizationId, pageNo, pageSize, _t`（第 4 条实测请求即此顺序）。
表单初值为 `null` 的两项由 qs 的 `skipNulls` 丢掉 —— 浏览器也不发。
实现按固定表拼参数（`buildListParams`），调用方实参的书写顺序不影响结果。

对照档案页的契约：两页的参数表**只差一个 `isArchived`**（档案页有且钉死，本页没有），
其余部分逐字段相同 —— 这正是"共用接口、两个页面"在参数层的长相。

四条结论（都是**实测**）：

- 列表请求的 URL 形状被后端接受，且与浏览器基准逐字段一致（含参数顺序、含不发 `null` 项）
- 这一页的列表是**全部考勤表**（118 ⊇ 105），**不筛**归档状态

- 硬传 `isArchived` 在没有发出任何请求的情况下被拒（④ 的 `未发请求：true` 由 adapter 的 URL 日志给出）

## 反证（故意改坏实现，确认测试会红）

10 组变异，全部当场变红，改回后 19 条用例全绿（脚手架只改
`src/capabilities/attendance-statistics.ts`，跑完逐字节还原）：

| 变异 | 红了几条 | 抓它的用例 |
| --- | --- | --- |
| 把 `departmentId/organizationId` 挪到 `pageNo/pageSize` 之后 | 2 | 带筛选的 URL 与基准一致 / 参数顺序由契约决定 |
| 去掉 `isArchived` 守卫 | 2 | 硬传被拒且不发请求 / 守卫本身 |

| 默认 `pageSize` 20 → 10 | 2 | 无筛选 URL 与基准一致 / 带筛选 URL |
| 把 `isArchived` 加进请求表 | 4 | 两条 URL + 参数顺序 + 「一个字都不提 isArchived」 |
| `lookup` 指向不存在的候选能力 | 1 | 跨文件复用是真的 |

## 尚未覆盖 / 与档案页的差异

- **这一页的写操作一个都没做**（「归档」「删除」「新建」）。源码层面能确定的是：
  「归档」是 `http.get('/org/hrAttendanceSheet/archiveSheet', { params: { id } })`
  —— **用 GET 改数据**，与档案页的「取消归档」互为反向操作；
  「删除」走 renren 列表模块的通用 `_http.delete('<deleteURL>/<id>')`
  （`common/libs/renren/list.js:517`），即 `DELETE /org/hrAttendanceSheet/delete/{id}`。
  两条都**没有实际执行过**，也都扫不到 `page-catalog.json` 的写判定规则
  （`tools/generate/generate.mjs:229` 只找 `http.post|put|delete(`），
  所以清单给这一页标的 `write: false` 是**错的**（档案页的 `write: false` 也是同样的原因错）。
- **`isArchived=0` 这条查询路径没有验证过。** 本页的能力不发这个参数，
  所以"未归档的考勤表"目前**没有**获取路径：既不能靠本页减档案页（本页是超集），
  也不能传 `isArchived=0`（被本地拒绝）。要补，得先实测后端认不认这个值。
- **两个选框是否会互相约束**：模板上看没有 `@change`，后端 DTO 也只是两个平级字段；
  与档案页一样，没有逐个组合试过（本次选的是部门 38 + 班组 46，返回 0 条，没有报错）。
- **「预览」「编辑」「新建」三个跳转都没跟。** 它们都 `bridgeSet()` 把整行塞进 query
  再跳到 `../attendance-sheet/detail/:id/item` 之类的页面，是另外的链路。
- **接线没有做**：能力（`attendance-statistics-list`）**刻意没有**注册进
  `src/capabilities/index.ts` 与 `src/capabilities/invoke.ts`，由派单方统一接线。
  因此现在 `sdk.capabilities` 里看不到它，冒烟脚本是从 `src/` 直接构造能力跑的
  （脚本头部写了原因，接线后可以换成 `sdk.attendanceStatistics.list(...)`）。
  另有一个可预期的副作用：`tools/generate/derive-aliases.mjs` 是**扫目录**读能力的，
  新文件会让它的能力条数 +1，而 `test/aliases-derived.test.ts` 有一条
  「目录扫到的 == 应用真正加载的」的断言 —— 这一步要等接线（并重跑 `pnpm docs`）之后才自洽。

## SDK AI 说明契约（2026-09-22）

本节由当前 SDK 描述结果整理；说明权威来源为 `src/catalog/contracts-business.ts`。调用 `catalog.describe(id)`（或 `id-llm`）可得到参数来源、返回字段/状态、数据消费与后续映射；`catalog.describePage(页面路径)` 用于选择页面功能。以下更新以本节为准；前文历史请求/实测记录仍保留其记录日期。

### `attendance-statistics-list`

查考勤统计表的当前列表；与历史档案共用表接口，但本能力不限定 isArchived=1。

- 执行：`sdk.attendanceStatistics.list`；通过 `capabilities.invoke('attendance-statistics-list', args)` 调用时按 `params` 填参。性质：read。
- 参数：`departmentId` 可选 (string)；`organizationId` 可选 (string)；`pageNo` 可选 (number)；`pageSize` 可选 (number)。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`{ list: object[], total: number }`。list=[] 为当前页无记录；total=0 表示该筛选无结果。保留筛选条件检查页码，不将空结果解释成权限判定。
- 字段：`list`、`total`、`list[].id`、`list[].name`、`list[].departmentName`、`list[].organizationName`、`list[].userCount`、`list[].isArchived`、`list[].updateName`、`list[].updateTime`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：以部门、班组和年月区分各张表；userCount 是表内人数，不是缺勤人数。
- 完成条件：按用户要求交付本次筛选范围的结果；需要完整清单时继续翻页至覆盖 total，不能把当前页当全集。
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。


验证：`test/ai-contract-business.test.ts` 直接检查 SDK 描述输出及业务夹具；本批未重放真实写操作。逐能力状态、证据与反证见 [补齐清单](../ai-contract-business-evidence.md)。
