# 字典配置

## 1. 能力定义

| 项目 | 内容 |
| --- | --- |
| Portal 页面 | `/dashboard/sale/sys/dict/list` |
| 菜单权限 | `/dashboard/sale/frame/sys/dict` |
| 按钮权限 | `sys:dict:edit`（新建、编辑、删除、保存、添加键值共用） |
| module-type | `60` |
| HTTP 实例 | `crm`（Portal `app/portal/utils/http/crm.js`） |
| SDK 能力文件 | `src/capabilities/sale-sys-dict.ts` |
| AI 契约 | `src/catalog/contracts-sale-sys-dict.ts` |
| 回归测试 | `test/sale-sys-dict.test.ts` |

这页是销售菜单下的旧 CRM “字典配置”，不是同名的平台字典，也不是 `/dashboard/sale/setting/dict/list` 的“配置数据”。页面可以查看当前租户的 CRM 字典记录；`brandId !== 0` 或 `itemId !== 0` 的商城源数据只展示来源标签，不显示编辑、删除和添加键值动作。

能力清单：

| 页面动作 | SDK 能力 | 写入 |
| --- | --- | --- |
| 分页查询、按标签/类型/描述筛选 | `sale-sys-dict-list` / `saleSysDict.list` | 否 |
| 读取类型下拉选项 | `sale-sys-dict-type-list` / `saleSysDict.typeList` | 否 |
| 添加键值前读取当前类型最大排序 | `sale-sys-dict-max-sort` / `saleSysDict.maxSort` | 否 |
| 准备新建或添加键值 | `sale-sys-dict-prepare-create` / `saleSysDict.prepareCreate` | 否 |
| 保存新建或添加键值 | `sale-sys-dict-create` / `saleSysDict.create` | 是 |
| 准备编辑当前列表行 | `sale-sys-dict-prepare-update` / `saleSysDict.prepareUpdate` | 否 |
| 保存编辑 | `sale-sys-dict-update` / `saleSysDict.update` | 是 |
| 准备删除 | `sale-sys-dict-prepare-remove` / `saleSysDict.prepareRemove` | 否 |
| 单条删除 | `sale-sys-dict-remove` / `saleSysDict.remove` | 是 |

## 2. 参数契约

列表请求实际发送：

```text
GET /vue/sys/dict/list
params = {
  order: '', orderField: '', label: '', type: '', description: '',
  pageNo: 1, pageSize: 20
}
```

Portal 自定义加载把 CRM 返回的 `{ list, count }` 转成 SDK 的 `{ list, total }`。列表记录的 `id` 是编辑/删除主键；`brandId`、`itemId` 决定该行是否是页面可操作的本地字典记录。

表单弹窗字段是 `value`、`label`、`type`、`description`、`sort`、`remarks`。页面对前三项的 Ant 表单规则都标记为 `required: false`，描述、排序和备注没有必填规则；SDK保留这一事实，但 CRM 后端实体仍可能因长度、`sort` 非空或重复值拒绝请求。新建弹窗默认 `sort=10`；添加键值先调用：

```text
GET /vue/sys/dict/getMaxSort?type=<当前行.type>
```

非空返回值加 `10` 后作为新键值排序。

创建与编辑共用同一请求：

```text
POST /vue/sys/dict/save
Content-Type: application/x-www-form-urlencoded
data = <prepareCreate/prepareUpdate 返回的完整草稿>
```

编辑直接使用当前列表行作为弹窗原始值，并在 Portal 中移除 `createDate`、`updateDate`；页面没有独立详情 GET。删除是单条路径请求：

```text
DELETE /vue/sys/dict/<当前列表行.id>
Content-Type: application/x-www-form-urlencoded
```

## 3. 逐字段基准

| 字段 | 页面来源/规则 | SDK处理 |
| --- | --- | --- |
| `id` | 当前列表记录主键 | 编辑/删除必须保留；不接受用 `type`、`label` 或 `value` 替代 |
| `value` | 弹窗“键值”，页面无必填规则 | 作为字符串提交；空值是否可落库由 CRM 后端决定 |
| `label` | 弹窗“标签”，页面无必填规则 | 作为字符串提交；空值是否可落库由 CRM 后端决定 |
| `type` | 筛选项及弹窗“类型” | 添加键值使用当前行的 `type`；不把类型名转换成记录 ID |
| `description` | 筛选项及弹窗“描述” | 空字符串照发 |
| `sort` | `a-input-number`，页面默认10、最小值0 | 非负数字或 `null`；不把空值伪造成其它排序值 |
| `remarks` | 弹窗“备注” | 空字符串照发 |
| `brandId`/`itemId` | 后端来源标记 | 原样返回，用于识别页面不可编辑的商城源数据 |
| `createDate`/`updateDate` | 列表返回的时间 | 返回给调用方；编辑提交时不应带入表单草稿 |

## 4. 操作步骤与证据

1. 需要类型下拉时调用 `typeList`；把每个字符串同时作为选项的 label/value。
2. 调用 `list` 查询并保留当前行的完整字段和 `id`。只对 `brandId=0 && itemId=0` 的行展示页面同样的编辑/删除/添加键值动作。
3. 添加键值时先用当前行 `type` 调用 `maxSort`，将非空结果加10；新建普通字典类型则使用弹窗默认 `sort=10`。
4. 调用 `prepareCreate` 或 `prepareUpdate` 生成草稿，向用户展示并等待确认；取消只丢弃草稿。
5. 用户确认后调用对应 `create`/`update`。两者都是 `POST /vue/sys/dict/save`，不能改成平台字典的 POST/PUT。
6. 删除必须先 `prepareRemove`，经用户确认后调用 `remove`；成功或超时后回到 `list`，逐页核对目标 ID 是否消失。
7. 保存成功没有可靠的新 ID 回执；保存或超时后按 `type`、`value`、`label` 等字段回查，匹配不唯一时报告不确定，不盲目重试。

证据来自 Portal `test/portal/main` 的菜单、列表和弹窗源码，以及 Java `test/test` 的 `DictVueController`、`Dict`、`DictService`、`DictDao.xml`；`test/sale-sys-dict.test.ts` 锁定请求形状、表单字段、权限、CRM实例、module-type 和反例。尚未在真实测试环境执行本页读写及写后回查，不能把离线测试当成线上写入证据。
