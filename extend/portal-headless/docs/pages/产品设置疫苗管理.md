# 产品设置疫苗管理

页面路径：`/dashboard/product/setting/base-setting/vaccine/list`。

## 页面能力定义

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询列表 | `product-setting-vaccine-list` / `productSettingVaccine.list` | `GET /config/vaccine/page` |
| 本地准备新建/编辑 | `product-setting-vaccine-prepare-save` / `productSettingVaccine.prepareSave` | 不发请求 |
| 保存 | `product-setting-vaccine-save` / `productSettingVaccine.save` | `POST /config/vaccine/save` |
| 删除 | `product-setting-vaccine-remove` / `productSettingVaccine.remove` | `DELETE /config/vaccine/delete` |

请求使用 `product` HTTP 实例，不发送 `module-type`。菜单权限为 `/dashboard/frame/base-setting/vaccine`；查询受 `base:vaccine:query` 控制，新建、编辑、删除受 `base:vaccine:submit` 控制。

## 参数契约与表单提交规则

列表是 `useListPageModule` 的 `customLoad`，初始表单和请求参数为：

```json
{
  "order": "",
  "orderField": "",
  "diseaseName": "",
  "vaccineName": "",
  "antibody": "",
  "pageNo": 1,
  "pageSize": 20
}
```

疾病名称、疫苗名称和抗体是前缀筛选；页面没有把“进口/国产”作为列表筛选条件。分页大小遵循页面支持的 `10/20/50/100`。Java `PageParam.responsePage` 返回 `page` 包络，SDK统一返回 `{ list, total }`。

新建和编辑共用弹窗，提交前只校验五项：疾病名称、疫苗名称、进口/国产、毒株、生产厂家；抗体可为空。`prepareSave` 和 `save` 始终保留以下七个字段：

```json
{
  "id": "",
  "diseaseName": "禽流感",
  "vaccineName": "疫苗A",
  "imported": 0,
  "strain": "H5",
  "manufacturer": "厂家A",
  "antibody": ""
}
```

- `imported` 只能是数字 `0` 或 `1`：`0=国产`、`1=进口`；`0` 是有效值，不能按空值过滤。
- 新建的 `id` 是空字符串；编辑保留当前列表行的 ID。
- `antibody` 虽然可空，也必须保留为 `''`，不能删除字段。
- 用户取消时只丢弃本地草稿，不调用保存接口。

删除只使用当前列表行 `record.id`，严格发送 `DELETE /config/vaccine/delete` 和查询参数 `{ id }`。Java 服务按 ID 软删除；SDK不扩展页面没有调用的详情、导入或疫苗厂家级联接口。

## 逐字段基准

| 字段 | 含义 |
| --- | --- |
| `id` | 疫苗记录 ID；编辑和删除目标。 |
| `diseaseName` | 疾病名称；Java列表服务可能把存储的疾病字典ID映射为展示文本。 |
| `vaccineName` | 疫苗名称。 |
| `imported` | `0` 国产、`1` 进口。 |
| `strain` | 毒株。 |
| `manufacturer` | 生产厂家。 |
| `antibody` | 抗体，可为空。 |
| `updateDate` | 最近修改时间，表格展示字段。 |
| `createDate`、`sapDescription`、`sapCode`、`unit` | Java实体/查询字段；当前表格不直接展示，但 SDK保留。 |
| `total` | 当前筛选条件下的总记录数。 |

## 操作步骤、权限和证据边界

1. 用 `list()`读取最新列表，确认目标行的 `id` 和七个字段。
2. 新建或编辑先调用 `prepareSave()`；用户取消则丢弃 `draft`。
3. 用户明确确认后，把同一 `draft`交给 `save()`；成功或超时用 `list()`按 ID 回查。
4. 用户确认删除后调用 `remove({ id })`；成功或超时重新查询并确认目标 ID 不再返回。

本轮逐页核对了 Portal 菜单、列表、弹窗、页面权限、Java `VaccineController`/`Vaccine`/`VaccineDTO`/`VaccineVO`/Mapper/Service、SDK请求和离线反证测试。尚未在真实测试环境使用浏览器会话执行列表、`prepare → save → 回查`及删除闭环；离线测试不替代真实环境证据。
