## Portal 可达来源

`monthly-lesson/list.vue` 的创建按钮确认后进入 `voting/[mode]/[id].vue` 或
`nonvoting/[mode]/[id].vue`；编辑按 `monthKind` 进入对应路由。列表还绑定单删/批删、
发布/取消发布、会议记录弹窗、决议和评分记录入口。当前月课堂的创建/编辑表单不是旧的
`monthly-lesson/[mode]/[id].vue`，因此两组 `saveMonthLesson` 与旧记录接口必须区分。

Portal 固定检出 `CodeReview_Projects_Js@test/portal/main` 的 `acab69a…` 中：

- `list.vue`：`GET /study/lesson/studylesson/lessonList`，固定 `type: '3'`；状态按钮在
  列表行上调用 `PUT /study/lesson/studylesson/publish`；“会议记录”弹窗使用
  `components/month-course-record.vue`。

## 端点与能力

列表参数顺序为
`order → orderField → type=3 → title → gradeNames → status → createTimeStart/End →
startTimeStart/End → pageNo → pageSize`。月课堂使用 `YYYY-MM-DD HH:mm:ss`，结束日为 +1 天开区间。

动作实现位于 `src/capabilities/study-lesson.ts`，月课堂使用独立 `requestMonthly`：

## 门禁与跨页依赖

- 列表和所有动作保持 `/dashboard/lesson/monthly-lesson` 权限及页面 module-type 推导。
- 表决类表单固定 `type=3, monthKind=1`，非表决固定 `type=3, monthKind=2`；保留
  `gradeIdList`、`title`、`hostCode`、`time`、参会人/嘉宾、议案字段。保存按钮由
  `!!rrForm.formState.status` 禁用，prepare 在 status truthy 时拒绝。
- `handleGradeChange` 的依赖顺序是 `getLastMonthLessonByGradeId`，无结果才调用
  `getGradeInfo`；不要把两个 helper 合并成一个未在 Portal 出现的接口。
- 发布按钮只在关联班级条件满足时可见；删除的 Java 服务仍拒绝已发布课堂，prepare 在已知
  status=1 时拒绝。
- `monthLessonRecord` 需要当前详情中的参会人、嘉宾、议案和 `studyLessonRecordDTO`；
  它不是 `saveMonthLesson` 的隐式后续，也没有回滚接口。
- `cancel` 只取消本地草稿；月课堂已提交的后端状态不能由 cancel 撤回。

### 三处最容易写错的地方

1. **`getMotionByLesson` 的 `name` 不发到服务端。** 页面 `customLoad` 只把 `lessonId` 放进
   params，名称是拿回整段数组后 `item.name.includes(form.name)` **在本地**过滤的，
   并且把 `total` 设成过滤后的长度。SDK 逐字复刻这个可观察行为（`name` 一律不进 query），
   唯一差别是页面在 `item.name` 为 null 时会抛 `TypeError`，SDK 按空串处理。
2. **两个"议案列表"打的是两个接口，语义不同。** `getMotionByLesson` 按 `lessonId` 取该课堂全部议案
   （名称本地过滤）；`getMotionRateListByLesson` 名称走**服务端 LIKE**，且 SQL 额外要求
   `hr_study_lesson.status = 1` ⇒ **只返回已发布课堂的议案**。两者不能互换。
3. **`getRateListByMotionId` 是 POST 但纯读**（`StudyLessonMotionServiceImpl#getRateListByMotionId`：
   select + 字典/用户回填 + 内存过滤，没有任何 insert/update）⇒ 按 `read` 登记，不按 HTTP 方法判定。
   另外它的 `flowerStr` 是 `flower + 1`（`flower = 6` 时固定 `"6+"`），`flowerContent` 来自
   `motion_flower` 字典 —— 三个字段不是一回事。

督办任务那条：`businessId` 收的是**课堂 ID**、`featureId` 收的是**议案 ID**、`type` 是页面写死的业务类型 1。
页面给每条加 `isSend: false` 并按 `isComplete` 把未完成的排前面，那是弹窗自己的展示状态与顺序，
SDK 不伪造 `isSend`、也不重排服务端顺序。同一弹窗里的「撤销」「发送提醒」是另两个接口，本轮未覆盖。

### `-1` 是一个有业务含义的返回

`StudyStudyRecordServiceImpl:349-357`：这批 id 里只要有一条 `is_adm_add = 0`（学员自学产生的记录），
service 直接 `return -1`，控制器转成 `ret:"FAIL", code:500, msg:"线上学习学员不可移出，请重新选择"`
（`StudyStudyRecordController:99-108`）—— 整批一起失败。
页面只对 `isAdmAdd === 1` 的行渲染「移出」按钮，批量按钮没有这个过滤。
