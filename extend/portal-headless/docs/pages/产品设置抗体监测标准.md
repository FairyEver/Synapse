# 产品设置抗体监测标准

页面路径：`/dashboard/product/setting/standard-manage/antibody/list`。

## 页面能力定义

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询列表 | `product-setting-antibody-list` / `productSettingAntibody.list` | `GET /base/antibody/page` |
| 准备新建 | `product-setting-antibody-prepare-create` / `productSettingAntibody.prepareCreate` | 不发请求 |
| 新建 | `product-setting-antibody-create` / `productSettingAntibody.create` | `POST /base/antibody/save` |
| 准备编辑 | `product-setting-antibody-prepare-update` / `productSettingAntibody.prepareUpdate` | 不发请求 |
| 编辑 | `product-setting-antibody-update` / `productSettingAntibody.update` | `POST /base/antibody/save` |
| 准备删除 | `product-setting-antibody-prepare-remove` / `productSettingAntibody.prepareRemove` | 不发请求 |
| 删除 | `product-setting-antibody-remove` / `productSettingAntibody.remove` | `DELETE /base/antibody/{id}` |

页面属于 `门户 → 系统设置 → 生产设置 → 标准库管理`，不是独立顶层生产系统。请求使用 `product` HTTP 实例，固定追加 `devicetype=PC`，不发送 `module-type`。菜单权限为 `/dashboard/frame/standard-library/antibody`。

Portal 页面中的 `base:antibody:query` 和 `base:antibody:submit` 目前均为注释，不是启用的按钮权限；页面上的 `permissionCheck(permissions.submit)` 实际传入 `undefined`，按 Portal 当前 `permissionCheck` 实现会放行。SDK不伪造这两个权限码，服务端仍执行当前会话的权限校验。

## 参数契约与表单提交规则

列表是 `useListPageModule({ styleV2: true, customLoad, getDataListIsPage: true })`，默认请求参数为：

```json
{
  "order": "",
  "orderField": "",
  "antibody": "",
  "evaluation": "",
  "pageNo": 1,
  "pageSize": 20
}
```

`antibody` 是个体抗体项目筛选文本；`evaluation` 为 `evaluation_level` 字典值，Java实体语义为 `-1=差、0=中、1=优`。分页支持 `10/20/50/100`。

新建和编辑弹窗只将类型、抗体监测项目名、三个数值字段和评价组成提交对象。类型为 `1=育成鸡`、`2=产蛋鸡`；抗体监测项目名、类型和评价必填；均值起、均值止、保护率起、保护率止、个体保护值在 Portal 表单中都不是必填，空值按 `0` 提交。

Portal 页面上保护率和个体保护值按百分数输入，提交时严格除以 `100`：

```json
{
  "type": 1,
  "antibody": "IBD",
  "upLimit": 10,
  "downLimit": 2,
  "upProtectionRate": 0.75,
  "downProtectionRate": 0.25,
  "protectionValue": 0.5,
  "evaluation": 1
}
```

例如页面输入 `75`，请求体发送 `0.75`；列表返回的仍是服务端比例小数，展示时才乘以 `100`。页面数值输入范围为 `-10000000` 到 `10000000`，SDK在准备阶段复刻该边界。编辑提交会先展开 `...props.raw`，因此 SDK 的 `prepareUpdate` 会保留列表行中的扩展字段，并覆盖编辑后的已知字段和百分比换算值。

用户取消新建、编辑或删除确认时只丢弃本地草稿，不发送写请求。

## 逐字段基准

| 字段 | 含义 |
| --- | --- |
| `id` | 抗体监测标准记录ID；编辑和删除目标。 |
| `type` | `1` 育成鸡，`2` 产蛋鸡。 |
| `antibody` | 抗体监测项目名称；Java实体 setter 会去除首尾空白。 |
| `upLimit` / `downLimit` | 均值起/止，原始数值，不做百分比换算。 |
| `upProtectionRate` / `downProtectionRate` | 保护率起/止，服务端比例小数；页面展示时乘以100。 |
| `protectionValue` | 个体保护值，服务端比例小数；页面展示时乘以100。 |
| `evaluation` | `-1` 差、`0` 中、`1` 优。 |
| `total` | 当前项目和评价筛选条件下的总记录数。 |

SDK保留后端返回的页面无关扩展字段，但不把它们当作页面业务字段；网络、权限、Java业务错误或响应结构错误会抛出，不降级为空列表。

## 逐页操作步骤、权限与证据边界

1. 用 `list()` 读取最新列表，确认目标行的 `id` 和编辑字段。
2. 新建先调用 `prepareCreate()`；编辑先调用 `prepareUpdate()`，确认 `draft` 中的保护字段已经是比例小数。
3. 用户明确确认后，把同一 `draft` 原样交给 `create()` 或 `update()`；成功或响应不确定后重新调用 `list()` 回查。
4. 删除先调用 `prepareRemove({ id })`，用户确认后调用 `remove({ id })`；成功或响应不确定后重新查询，确认目标ID不再出现。

本轮逐页核对了 Portal 菜单、列表、弹窗、product HTTP、权限实现、Java `AntibodyController`/`Antibody`/`AntibodyServiceImpl`/Mapper、SDK请求和离线反证测试。尚未在真实测试环境使用浏览器会话执行列表、`prepare → submit → 回查`及删除闭环；离线测试不替代真实环境证据。
