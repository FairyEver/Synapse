# 方法库（孵化预案）

## 能力定义

- 页面：`/dashboard/product/setting/hatchery-manage/method-lib/list`
- 菜单/路由权限：`/dashboard/frame/hatchery-plan/method-lib`
- Portal 页面是 `hatchery-manage/method-lib/list.vue` 包装器，实际复用 `hatch-manage/method-lib/list.vue`。
- HTTP 实例：`product`。
- 页面路径没有命中 Portal 的 `module-type` 规则，SDK 不发送 `module-type`；Java 控制器的默认值 `43` 不等于浏览器实际请求头。
- 页面按钮权限：查询声明 `program:method-lib:query`，新建/编辑/查看方法 `program:method-lib:submit`，删除 `program:method-lib:delete`；源码没有用 query 权限包住列表请求，SDK不绕过页面或服务端权限。

## 页面能力与端点

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |

## 参数与提交规则

列表筛选字段是 `variety`、`gen`、`tempId`，默认均为空字符串，并固定发送 `scope=1`。Portal 公共列表模块补充 `order=''`、`orderField=''`、`pageNo` 和 `pageSize`；SDK 默认 `pageNo=1`、`pageSize=20`，只接受 `10/20/50/100`。

舍内温度选项由 `getTempInList` 返回；Portal 将 `id` 映射为下拉 `value`，将 `inTitle` 映射为 `label`。SDK保留原始字段，并返回这两个映射字段。

新建弹窗的品种、代次、舍内温度（表单键 `tempId`）必填。上传控件只接受 `.xls` 和 `.xlsx`，但文件不是必填项。SDK文件输入为 `{ fileName, base64, contentType? }`，空文件、非法Base64或非Excel扩展名在本地拒绝。

Portal 构造FormData的键顺序固定为：

```text
variety
gen
tempId
suiteCode
file（选择文件时）
flag（重复预案二次提交时）
```

新建没有可见的 `suiteCode` 输入项，但页面仍发送 `suiteCode || ''`。首次请求不发送 `flag`。如果返回 `flag=1`，页面弹出“替换 / 增加 / 覆盖”选择，分别对应 `1 / 2 / 3`；SDK返回 `{ status: 'conflict', flag: 1 }`，不替用户选择。用户选择后必须把同一份 `draft` 和明确的 `flag`再次提交。

编辑表单的品种、代次、舍内温度和 `suiteCode` 必填；Portal JSON固定发送 `id`、`variety`、`gen`、`tempId`、`suiteCode`、`file:null`。页面没有处理Java返回的编辑覆盖标记，SDK保持页面行为：请求未抛错返回 `true`，不能把它当作业务终态。

## Portal 与 Java 的字段差异

Java `HatchMethodLibController` 的孵化接口和 `ProgramSuiteHatchMapperExt.xml` 使用 `ageStage` / `age_stage`：列表返回 `variety`、`gen`、`ageStage`、`suiteCode`，服务按 `ageStage`补 `ageStageName`；导入和编辑也按 `ageStage`查找或更新。

当前复用的 Portal 组件在孵化路由下只切换了接口前缀，表单和列表筛选仍使用 `tempId`，并将 `tempId`发送给 `/hatchProgram/methodLib`。SDK按浏览器实际请求保留 `tempId`，不会静默改名为 `ageStage`。因此当前固定分支源码存在前后端字段错位：若Java严格按 `ageStage`校验，Portal与SDK的创建/编辑都会被服务端拒绝或无法正确更新；这不是SDK可以隐瞒的成功状态。返回对象同时保留Java的 `ageStage/ageStageName`，Portal预期但后端未返回的 `tempId/tempName`按 `null`表达。

## 返回字段

| 字段 | 含义 |
| --- | --- |
| `list` | 当前页孵化方法库记录。 |
| `total` | 当前筛选条件下的总条数。 |
| `list[].variety` / `varietyName` | 品种编码 / 展示名称。 |
| `list[].gen` / `genName` | 代次编码 / 展示名称。 |
| `list[].ageStage` / `ageStageName` | Java孵化列表实际返回的日龄段编码 / 展示名称。 |
| `list[].tempId` / `tempName` | Portal组件预期的舍内温度字段；孵化Java列表SQL不返回，通常为 `null`。 |
| `list[].suiteCode` | 编辑和删除目标业务编码；不能从名称猜测。 |
| `list[].id` | Portal表格的 `idKey`；Java DTO没有该字段，通常为 `null`。 |
| `list[].flag` | Java DTO保留的覆盖标记；列表SQL不选择，通常为 `null`。 |
| `create.status` | `submitted` 表示请求未抛错；`conflict` 表示必须由用户选择 `flag`。 |
| 下载结果 `base64` | 模板二进制的标准Base64，需由调用方保存为 `fileName`。 |

## 操作步骤、回查与取消

1. 调用 `temperatureOptions()`取得Portal下拉候选，再用 `list()`读取页面数据；编辑和删除只使用最近列表中的 `suiteCode`。
2. 新建先调用 `prepareCreate()`。用户取消时只丢弃草稿；确认后首次调用 `create({ draft })`，冲突时展示三项选择并用同一草稿调用 `create({ draft, flag })`。
3. 编辑先调用 `prepareUpdate()`。用户取消时不发请求；确认后把同一份草稿交给 `update()`。
4. 删除先调用 `prepareRemove()`并取得明确确认。取消只丢弃本地 `suiteCode`；确认后才调用 `remove()`。
5. 新建、编辑、删除成功或响应不确定后都重新调用 `list()`回查；分别核对目标记录是否出现/更新/消失。由于Java使用 `ageStage`而Portal提交 `tempId`，回查时必须同时观察这两个字段。
