## Portal 页面行为

页面通过 `timePeriod` 在按月度和按年度之间切换：

| 模式 | 接口 | 请求中的 month | 期间规则 |
| --- | --- | --- | --- |
| `1` 按月度 | `POST /org/hrWorkSchedule/getUserAttendanceListByMonth` | 当前选择的两位月份字符串 | 月份选择器禁用未来月份 |
| `2` 按年度 | `POST /org/hrWorkSchedule/getUserAttendanceListByYear` | `null` | 年份选择器禁用未来年份 |

两种模式都发送同一组排序、筛选和分页字段。月度默认当前年月，组织未选择时发送 `[]`，姓名和工号初始值为 `null`：

```json
{
  "order": "",
  "orderField": "",
  "month": "09",
  "year": "2026",
  "organizationIdList": [],
  "name": null,
  "staffCode": null,
  "pageNo": 1,
  "pageSize": 20
}
```

年度请求只把 `month` 改为 `null`。后端根据 `month` 是否为空计算月份或整年，并按入职、离职、退休、考勤组生效日、节假日、异常半天记录计算应出勤、实际出勤和休假天数。异常 tooltip 使用 `absentListGroupByType[].typeStr/count`；类型标签来自 `absent_type` 字典，SDK 不猜枚举。

点击“查看考勤日历”时，Portal 通过 bridge 传递当前行的 `userId` 和 `yearMonth`，进入日历页后调用：

```json
GET /org/hrWorkSchedule/getUserAttendanceList?yearMonth=2026-09&userId=7
```

日历消费 `attendanceInfoDTOList`：`isHoliday=1` 显示“休”，非节假日且没有异常时显示“班”，异常记录按 `startDate`、`type` 和 `amPm` 显示。`finaStartDate`、`finalEndDate` 限制员工有效考勤日期范围。日历切换月份会重新请求；未来月份由后端拒绝。

## 异常处理提交规则

“考勤异常处理”弹窗可以添加人员，并为每名人员添加一个或多个时段。提交到 `POST /org/hrWorkSchedule/absenceUser` 的 body 是数组，不是 `{ users: ... }` 包装对象：

```json
[
  {
    "userId": 7,
    "name": "张三",
    "absentUserByTypeList": [
      {
        "type": 3,
        "absentDate": "2026-09-01",
        "workShiftType": 1,
        "absentFileList": [{ "url": "https://oss.example/a.pdf", "name": "a.pdf" }]
      }
    ]
  }
]
```

Portal 表单规则和 SDK 本地反证如下：

- 至少选择一名人员，每名人员至少有一个时段；`userId` 来自带关键字的人员候选，不把工号当用户 ID。
- 每个时段必须有 `type`、`absentDate` 和 `workShiftType`；班次 `1` 是上午、`2` 是下午、`3` 是全天。
- 同一用户同一天不能重复上午、重复下午，也不能把全天与其它班次混用。
- 异常类型值来自 `absent_type` 字典；类型 `3、4、7、8、9` 必须有附件，其它类型可以没有附件。
- 附件先用已有 `base-upload-file` 上传到 `HR/risk`，页面只接受 `application/pdf`，每个时段最多 10 项；提交时只消费附件的 `url/name`。

后端先逻辑删除同一用户同一天的旧记录，再新增本次记录；全天会拆成上午、下午两条记录。用户未绑定考勤组时后端拒绝。接口无 `requestId`，成功响应无业务回执，不能用 HTTP 成功代替写入证据；提交后必须刷新列表或日历回查。Portal 的“取消”只是关闭弹窗，没有服务端 cancel 接口，因此本页没有虚构 `prepare` 或 `cancel` 能力。

## 后端与权限核对

Java `HrWorkScheduleController` 在 `${orgPath}/hrWorkSchedule` 下提供月度列表、年度列表、员工日历和 `absenceUser`。月度和年度入口最终复用 `getUserAttendanceListByMonth`，后端按 `month=null` 判断整年；服务层叠加当前用户 `DataScope`、角色组织筛选、有效员工和考勤组约束。

异常处理服务对每个用户检查有效考勤组，调用 OSS 资源保存附件，按用户/日期逻辑删除旧关系后插入新的 `HrAttendanceUserRelEntity`；全天写入两条 `amPm` 记录。SDK 不把异常处理误解为审批流程，也不替后端自动补回查。

组织候选复用 `contractSupport.roleOrganizationSearch({ scope: 'attendance', keyword })`。人员候选使用已有 `base-user-search`，必须先提供关键字并让用户确认候选 ID，避免照抄 Portal 全量人员接口。

### `attendance-schedual-information-list`

按月度或年度、组织、姓名和工号读取当前用户数据范围内的员工考勤汇总分页列表。

执行：`sdk.attendanceSchedualInformation.list`；性质：read。操作 Portal「组织管理 → 考勤管理 → 排班信息」页面的月度/年度查询、员工考勤日历或考勤异常处理入口。

- 边界：页面权限是/dashboard/attendance/attendance-schedual-information；请求使用 platform HTTP 实例和 module-type=11。
- 边界：timePeriod=1 时调用月度接口并发送 YYYY-MM 对应的 year 与两位 month；timePeriod=2 时调用年度接口并发送 month=null。两种接口由后端同一个服务按 month 是否为空计算期间。
- 边界：year 和 month 不能选择未来期间；organizationIdList 必须来自 contractSupport.roleOrganizationSearch({ scope: "attendance", keyword }) 的候选 ID。
- 边界：异常类型展示使用 absent_type 字典；users[].absentUserByTypeList[].type 必须是该字典的真实值，不要猜数字含义。
- 边界：absenceUser 是实际写操作：后端先逻辑删除同一用户同一天旧记录，再保存新记录；全天会拆成上午、下午两条记录。接口没有 requestId，响应没有业务回执。

| 参数 | 意义与来源 |
| --- | --- |
| timePeriod | 查询模式；1按月度，2按年度，页面默认1。；来源：用户明确选择的页面模式 |
| year | 年份选择器值，YYYY；默认当前年份且不能晚于当前年份。；来源：用户明确选择的年份 |
| month | 月度模式的月份值，MM；默认当前月份且不能晚于当前月份；年度模式会发送null。；来源：用户明确选择的月份；年度模式省略 |
| organizationIdList | 角色组织树多选结果的组织 ID 数组；未筛选时发送 []。；来源：contractSupport.roleOrganizationSearch({ scope: "attendance", keyword }) 的 list[].id；用户确认选择后组成数组；候选：contract-support-role-organization-search list[].id |
| name | 姓名模糊筛选；页面初始值为 null。；来源：用户输入的姓名 |
| staffCode | 工号模糊筛选；页面初始值为 null，后端按工号匹配。；来源：用户输入的工号文本 |
| pageNo | 从1开始的页码；页面默认1。；来源：调用方分页状态 |
| pageSize | 每页条数；Portal 分页器支持10、20、50、100，默认20。；来源：调用方分页状态 |

返回：`{ list: object[], total: number }`。list=[] 表示当前页没有员工；total=0 才表示当前筛选没有员工。权限、会话、网络或响应形状错误会抛出，不降级为空页。

- list[].absentListGroupByType[].count：该类型异常天数；后端半天记录按2条折算1天；单位：天

- 消费：用 total 判断是否继续翻页；list[].userId 是考勤日历和异常处理的用户目标。
- 消费：absentListGroupByType[].typeStr/count 只用于页面 tooltip 汇总，不要用它代替 calendar 的逐日明细。
- optional：用户点击某行“查看考勤日历”且 list[].userId 非空 → `attendance-schedual-information-calendar`。把列表当前模式的 year-month 快照和同一行 userId 传给日历；日历切换月份后重新调用。 映射：{"userId":"result.list[].userId","yearMonth":"user.selectedYearMonth"}
- optional：用户在月度模式打开“考勤异常处理” → `attendance-schedual-information-absence-user`。先让用户用 base-user-search 选定人员并填写每个时段，再提交；列表查询本身不修改异常。 映射：{"users":"user.confirmedUsers"}

完成条件：返回当前模式和筛选的一页员工考勤汇总；列表读取不修改考勤数据。

- 失败处理：未来月份/年份、分页、日期、班次冲突、必需附件、用户 ID、权限、未绑定考勤组、网络或响应形状错误原样抛出；不把空列表当作权限成功。
- 失败处理：absenceUser 完成后必须重新调用 list 或 calendar 核实；超时先回查，未确认前不要直接重复提交。

- **仍有缺口**：已完成 Portal/Java 逐页静态核对与离线请求断言；尚未在真实测试环境执行月度/年度列表、日历、异常处理写入及回查。
