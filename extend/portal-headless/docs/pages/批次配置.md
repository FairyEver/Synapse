# 批次配置（`/dashboard/material/store/batch-setting/list`）

物料批次配置页面的分页查询、物料与分类候选、按物料/分类批量新建、批次启停和关闭状态删除。Portal、Java 与 SDK 已按菜单、列表、表单组件、请求体、权限与后端校验逐文件核对。

## Portal 页面行为

### 列表和筛选

- `customLoad` 调用 `GET /admin-api/inventory/asset-batch-config/page`。公共列表参数按页面初值发送 `order=''`、`orderField=''`、`materielName=null`、`categoryId=null`、`pageNo=1`、`pageSize=20`。
- `materielName` 是物料名称筛选；`categoryId` 来自分类树，Java 服务会展开为所选分类及后代分类后查询物料配置和分类配置。
- 列表展示后端返回的分类路径、物料名称/编码、涉及单元、单位、物料状态、批次开关、修改时间和修改人。列表SQL当前不一定返回 `shelfLifeDays`，SDK将缺失值表达为 `null`。

### 候选与新建

- 顶部“选择可选物料”组件实际通过 `GET /admin-api/supply/materiel/page`、`status=1` 分页拉取全部启用物料，再在浏览器本地按名称/编码筛选；这是长选项行为。SDK 的 `searchMaterials` 要求关键字，并将其映射为 `matNameOrCoder`，避免无头调用无界全量加载。
- 分类选择器实际请求 `GET /admin-api/inventory/asset-depreciation-config/get-materiel-category-tree?level=5`，树节点的 `name` 由 `catName` 得到；涉及组织选择器实际请求 `/admin-api/supply/organization/tree?isFactory=1&includeParents=1`，只有 `isFactory === 1` 的节点可选。
- 新建入口先选择 `single` 或 `category`。按物料模式的每行表格字段是物料、物料号、分类展示、保质期、基本单位和涉及组织；按分类模式的字段是分类、组织、分类层级和保质期。保质期输入框允许 `0`，按整数天提交。
- 按物料实际提交：`POST /admin-api/inventory/asset-batch-config/batch-create-materiel`，数组每行是 `materielId`、`materielCode`、`standardUnitId`、`standardUnitName`、`unit`、`shelfLifeDays`。按分类实际提交：`POST /admin-api/inventory/asset-batch-config/batch-create-materiel-category`，数组每行是 `categoryId`、`categoryName`、`standardUnitId`、`standardUnitName`、`shelfLifeDays`。页面不提交 `configType`，后端端点分别补 `1` 和 `2`。
- Portal 提交前校验必填字段和当前表格内的“同一物料/分类 + 同一组织”重复组合；SDK 在 `prepareCreateMateriel` / `prepareCreateCategory` 中执行相同门禁，并额外拒绝空数组和负数/小数天数。

### 启停、删除和权限

- 当前行 `batchEnabled=true` 时按钮是“关闭”，调用 `PUT /admin-api/inventory/asset-batch-config/disable-batch`；当前为 `false` 时按钮是“开启”，调用 `PUT /admin-api/inventory/asset-batch-config/enable-batch`。两者都以 `id` query 传参，body 是 `null`。
- 只有 `batchEnabled=false` 的行显示删除按钮，调用 `DELETE /admin-api/inventory/asset-batch-config/delete?id=...`。SDK 的 `prepareRemove` 要求调用方带上列表当前状态并拒绝开启状态。
- Controller 的查询、批量创建、启停和删除均受页面权限 `/dashboard/material/store/batch-setting` 保护；本页面没有独立的 create/edit/delete 按钮权限声明。

## Java 后端校验与边界

`AssetBatchConfigController` 实际提供通用 `create`、`batch-create`、`update`、`get`、导出等端点，但批次配置 Portal 当前页面不可达这些入口，SDK 不把它们伪装成页面能力；只接入页面实际调用的批量新建、启停和删除。

服务层只接受 `configType=1`（物料）或 `2`（分类），要求标准单元、物料/分类ID存在，并按同类型、同组织、同物料/分类做重复检查；按类型会清理互斥字段。删除仅校验记录存在，Portal 的“开启状态不显示删除”规则由 SDK 在准备阶段复刻。列表分类筛选由服务展开自身及子分类，响应包含物料状态和组织名称等展示字段。

## SDK 能力与说明

实现文件为 `src/capabilities/inventory-asset-batch-config.ts`，AI 契约为 `src/catalog/contracts-inventory-asset-batch-config.ts`，均已接入 `catalog.describe`、`-llm` 和通用 `capabilities.invoke`。

能力按以下路径组织：

- `list`、`searchMaterials`、`materialCategoryTree`、`unitTree`；
- `prepareCreateMateriel → createMateriel`；
- `prepareCreateCategory → createCategory`；
- `prepareEnableBatch → enableBatch`、`prepareDisableBatch → disableBatch`；
- `prepareRemove → remove`。

所有写操作都要求先准备草稿；取消只丢弃草稿。批量创建、启停和删除成功或超时后，都必须按物料/分类+组织或业务ID回查列表，不能把 `true` 回执直接当成业务终态。
