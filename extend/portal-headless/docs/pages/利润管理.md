> 六页共用的东西（参数顺序怎么推、谁分页谁不分页、`selection` 为什么钉死、

## 参数契约

这一页**没有分页**（`customLoad` + `getDataListIsPage` 默认 `false`），
返回的是**整棵树**（后端 `CommonResult<List<KpiProfitListDTO>>`）。

| 字段 | 默认 | 谁给的 | 说明 |
| --- | --- | --- | --- |
| `order` | `''` | 页面钉死 | 列表模块加的，页面没有这个控件 |
| `orderField` | `''` | 页面钉死 | 同上 |
| `_t` | 时间戳 | 客户端 | 防缓存 |

⇒ 顺序逐字：`order → orderField → _t`。**空串也照发**（`?order=&orderField=`），不是省略。

## ⚠️「名称」这一栏**不是请求参数**

表单字段叫 `templateName`，但 `customLoad` 第一句就是
`omit(form, ['templateName'])` —— 它**不上请求**，过滤发生在**返回的树上**
（`reduceTree` + `item.name.includes(...)`，只留 `type === 2` 的利润，且结果变平）。

所以能力里**没有** `name`/`templateName` 参数。要按名字找用
`filterTreeNodeByName(rows, keyword, isProfitLeaf)`（`isProfitLeaf` 就是 `type === 2`）。
顺带：后端 DTO 其实**有** `name` 字段、支持服务端过滤，是页面没用 ——
无头与浏览器保持一致，也不发。

## 逐字段基准

```
https://biz-api-test.wodecorp.cn/admin-api/performance/basedata/kpiprofit/page?order=&orderField=&_t=<ts>
```

单测里比的是**有序的** `[key, value]`（键顺序也要一致），见

## 真实验证

- **基准**：`baseline/perf-manage-template.browser.json`（派单方 2026-09-21 用 `bsk` 在测试环境
  抓到的那条真实请求，`_t` 已归一化、token 已脱敏），与本能力构造的 URL 逐字段一致（含键顺序）。
- **回归测试**：`pnpm vitest run test/perf-manage-template.test.ts`。
- ⚠️ **没做**：真实后端冒烟（这一波不开浏览器、不取凭据）。所以**响应形状没有实测** ——
  树的结构、`lineType` 的取值域都是按源码/DTO 推的，不是打出来的。

## 已覆盖的读写动作

页面上的实际 JSON 读写入口已接入 `perfManageTemplate`，所有写动作都按
`prepare → submit → cancel` 暴露（下载页面不注册为 JSON 能力）：

- **删**：`DELETE /performance/basedata/kpiprofit`，body 是 **`{ ids: [...] }`**
  （后端签名 `Map<String, List<Long>>`，不是裸数组）。删目录时页面先
  `searchFiles` + `flatTree` 把整棵子树的 id 收齐 —— **递归删除**。
- **建 / 改**：`POST` / `PUT /performance/basedata/kpiprofit`。
- **导入利润**：`POST /performance/basedata/kpiprofit/import`，**multipart**，
  字段 `file` / `type` / `parentId`。
- **同步公式**：`GET /performance/basedata/kpiprofit/formulaUpdates`（是 **GET**）。
- **模板下载**：`GET /performance/basedata/kpitarget/download`，走
  `newPageWithPlatformAuth` 开新页 —— **浏览器下载，不是 JSON 接口**，不该做成能力。
- **子页面**：`./profit-data?id=<profitId>`（预测/实际利润和公式，另有自己的读写接口）。

对应能力包括 `profit-detail`、新建/编辑/递归删除、导入、利润数据保存、公式同步、
行/变量/年份/使用情况查询；导入严格保持 multipart 的 `file → type → parentId` 键序，
删除严格发送 `{ ids }`，写响应不确定时按同一 ID 或业务字段回查。真实环境写冒烟仍未执行。

## SDK AI 说明契约（2026-09-22）

本节由当前 SDK 描述结果整理；说明权威来源为 `src/catalog/contracts-business.ts`。调用 `catalog.describe(id)`（或 `id-llm`）可得到参数来源、返回字段/状态、数据消费与后续映射；`catalog.describePage(页面路径)` 用于选择页面功能。以下更新以本节为准；前文历史请求/实测记录仍保留其记录日期。

### `perf-manage-profit-list`

读取利润库全树；名称搜索需要在返回树本地筛选。

- 执行：`sdk.perfManageTemplate.listProfits`；通过 `capabilities.invoke('perf-manage-profit-list', args)` 调用时按 `params` 填参。性质：read。
- 参数：无参数。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`object[]`。[] 表示本次查询没有条目；这是数组，不读取 list/total。
- 字段：`[].id`、`[].name`、`[].parent`、`[].parentIds`、`[].children`、`[].updateTime`、`[].updaterName`、`[].type`、`[].lineType`、`[].unit`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：递归 children，保留祖先路径；目录不能当利润指标参与汇总。
- 完成条件：交付利润项、类型、单位及所属目录。
- 后续：optional → `base-dict-get`：按 profit_type 查询当前字典，将返回 value 与业务行状态/类型值转成同一字符串后匹配 label；没有匹配时显示原码并说明标签未配置（dictType ← literal:"profit_type"）
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。
