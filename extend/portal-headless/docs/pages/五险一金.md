## 参数契约：六页里唯一**完整**的一套

它是纯声明式那一类，`useListPageModule({ getDataListURL, getDataListIsPage: true, form })`
—— 参数完全由 `list.js:473-483` 拼：`order`/`orderField` 打头、表单字段居中、分页在尾。

⇒ 键序 **`order → orderField → name → idcard → pageNo → pageSize → _t`**。

| 参数 | kind | 默认 | 说明 |
| --- | --- | --- | --- |
| `order` / `orderField` | text | `''` | 页面没有这两个控件（`list.js` 加的）。**两个都非空**才进后端的排序分支 |
| `name` | text | `''` | 姓名。后端 `HrInsuranceFundServiceImpl.getWrapper` 里是 `wrapper.like(...)` —— **服务端模糊筛** |
| `idcard` | text | `''` | 身份证件号。同上，也是 `like` |
| `pageNo` | number | `1` | 后端取的就是 `pageNo` 这个名字（`Constant.PAGE = "pageNo"`） |
| `pageSize` | number | `20` | ⚠️ 这条路径（`CrudServiceImpl` → `BaseServiceImpl.getPage`）**没有上限校验**（直接 `Long.parseLong`），别拿它去拉全表（D6 / H35） |

### 与同域另外两页正相反：这里的输入框是**服务端**筛

指标管理页的「名称」是本地过滤（后端不认 `name`），标准管理页线上版走 `searchPage`
（跨层搜索）。只有这一页是老老实实的 `like` 查询。**三页的输入框长得一样，行为三样。**

`order`/`orderField` 这里**照发空串**：后端 `BaseServiceImpl.getPage()` 确实读这两个名字，
但排序分支要求 `isNotBlank(orderField) && isNotBlank(order)` —— 两个都空 ⇒ 恒不排序。
