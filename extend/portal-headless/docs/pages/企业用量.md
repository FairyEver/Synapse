# 企业用量（`/dashboard/setting/enterprise-usage/list`）

本页是 Portal「系统设置 → 企业用量」入口，页面主体复用 `common/model-usage`，但入口固定 `statisticsDimension=2`（企业）。它不是平台用量页，也不是独立的生产模块；SDK 不允许调用方把企业维度改成个人或平台维度。

证据边界：已逐行核对 Portal 企业入口、共享额度/用量组件、申请弹窗、申请记录弹窗、导出和功能模块候选请求，以及固定检出 Java Controller、ReqVO、RespVO/DO 和权限注解；已用离线请求夹具覆盖参数、字段映射、错误映射、导出和表单反证。尚未在真实测试环境使用当前账号执行读取、无权限/跨租户矩阵或真实 `prepare → submit → cancel` 写入回查，以下未标记为实测的内容均是源码推导。

来源锚点：Portal `CodeReview_Projects_Js@test/portal/main`（读取时 HEAD `acab69acc7`）；Java `CodeReview_Mall_Platform_Java@test/test`（读取时 HEAD `0f1a55718eb`）。

## 一、页面上下文、权限和范围

| 项 | Portal/SDK 事实 |
| --- | --- |
| 菜单路径 | `/dashboard/setting/enterprise-usage/list` |
| 页面权限 | `/dashboard/setting/enterprise-usage` |
| HTTP 实例 | `platform` |
| `module-type` | 不发送；该页面不匹配模块规则，和 Portal 一致 |
| 统计维度 | 固定 `statisticsDimension=2`（企业） |
| 用量/额度查询按钮 | `ai-token:usage:query`；页面将它传入共享内容组件 |
| 申请记录按钮 | `ai-token:apply:query`；只控制申请记录查询 |
| 数据范围 | 当前有效会话、当前租户和后端数据权限；企业维度不是跨租户管理员查询 |
| 筛选差异 | 企业根页面有用户名称和明细筛选；没有平台页的 `tenantId` 筛选和租户全量候选 |

`common/model-usage/api.js` 还存在 `/ai-token/quota-usage/daily-progress` 的旧函数，但固定 Java Controller 的映射已注释、页面没有有效消费链路，因此没有登记为能力。`POST /ai-token/usage/record` 是服务端记录调用，也不是本页面发出的请求。

## 二、能力清单

本工作单位提供 `createSettingEnterpriseUsageCapability(request)` 和对应的 12 项能力定义；共享注册、门面接线和生成物由上层工作单位按用户指定边界接入。

| 能力 ID | SDK 方法 | 请求/效果 |
| --- | --- | --- |
| `setting-enterprise-usage-quota-list` | `listQuota` | `GET /admin-api/ai-token/quota-usage/page`，企业额度分页 |
| `setting-enterprise-usage-quota-summary` | `getQuotaSummary` | `GET /admin-api/ai-token/quota-usage/summary`，额度汇总，不带分页 |
| `setting-enterprise-usage-usage-list` | `listUsage` | `GET /admin-api/ai-token/usage/page`，企业调用明细分页 |
| `setting-enterprise-usage-usage-analytics` | `usageAnalytics` | `GET usage/{summary,trend,model-ratio,module-ranking}`；按独立请求记录错误 |
| `setting-enterprise-usage-usage-detail` | `getUsageDetail` | `GET /admin-api/ai-token/usage/detail?id=...`，`id` 是用量记录 ID |
| `setting-enterprise-usage-usage-export` | `exportUsage` | `GET /admin-api/ai-token/usage/export`，返回 Base64 文件对象 |
| `setting-enterprise-usage-function-module-list` | `listFunctionModules` | `GET /admin-api/ai-token/common/function-module-list`，关键字只做本地过滤 |
| `setting-enterprise-usage-model-detail` | `getModelDetail` | `GET /manager/aiModelConfig/get/{id}`，`id` 是模型 ID |
| `setting-enterprise-usage-apply-prepare` | `prepareApply` | 本地校验并生成提交 body，不发请求 |
| `setting-enterprise-usage-apply-submit` | `submitApply` | `POST /admin-api/ai-token/apply/create`，提交额度提升申请 |
| `setting-enterprise-usage-apply-record-list` | `listApplyRecords` | `GET /admin-api/ai-token/apply/page`，申请记录分页 |
| `setting-enterprise-usage-apply-cancel` | `cancelApply` | 只丢弃尚未提交的本地草稿，Portal 没有服务端取消端点 |

只有 `setting-enterprise-usage-apply-submit` 是写能力。返回申请 ID 只表示申请记录已受理，不表示审批通过或额度已经生效。

## 三、请求参数与逐字段基准

### 3.1 额度 Tab

- 默认 `quotaCycle=3`（月）、`pageNo=1`、`pageSize=20`；列表和汇总请求都固定带 `statisticsDimension=2`。
- `modelName`、`userName`、`usageStatus` 按页面筛选发送；空字符串、`null`、`undefined` 按共享 `cleanQuery` 丢弃。
- 列表返回 `{ list, total }`。额度行字段按 Java `AiTokenQuotaUsageRespVO` 消费：`modelId`、`modelName`、`tenantName`、`quotaCycle`、`cycleQuota`、`monthlyQuota`、`weeklyQuota`、`dailyQuota`、`usedQuota`、`remainingQuota`、`usageRate`、`maxTokenPerRequest`、`resetTime`、`usageStatus`、`usageStatusName`。金额/Token 数量保留后端原值，`null` 或缺失不能解释成 0。
- 汇总返回 `cycleTotalQuota`、`cycleUsedQuota`、`cycleRemainingQuota`、`currentCycleAvailableQuota`；不带 `pageNo/pageSize`，字段缺失和 `null` 继续按缺失处理。
- 额度行的 `modelId` 是后续查看用量、查看模型上下文或打开申请表单的来源，不能把 `modelName` 或数组下标当 ID。

### 3.2 用量 Tab

- 默认 `quotaCycle=2`（周）、`timeRangeType=2`（本月）、`pageNo=1`、`pageSize=20`；请求固定带 `statisticsDimension=2`。
- 企业根入口的主筛选支持 `modelId`、`userName`、`functionModule`、`callStatus` 和日期范围；明细筛选还支持 `requestId`、`userBelong`、`memberLevel`、`limitType`、`quotaDeducted`。`tenantName` 只用于模型上下文入口，不产生平台租户筛选。
- `dateRange` 接收 `[开始日, 结束日]`。十位 `YYYY-MM-DD` 日期会被补成 `startTime=00:00:00`、`endTime=23:59:59`；已有时间部分保持原样。
- 分页明细返回 `{ list, total }`。Java `AiTokenUsageRecordRespVO`/DO 可被页面详情消费的字段包括：`id`、`modelId`、`modelName`、`requestId`、`functionModule`、`userName`、`tenantName`、`userBelongName`、`memberLevelName`、`inputTokens`、`outputTokens`、`totalTokens`、`consumedQuota`、`quotaDeducted`、`quotaBefore`、`quotaAfter`、`tenantQuotaBefore`、`tenantQuotaAfter`、`callStatus`、`callStatusName`、`limitType`、`durationMs`、`durationMsStr`、`failureReason`、`errorCode`、`callTime`、`maxTokenLimit`、`tokenLimitPerMinute`、`flowLimited`、`windowUsedTokens`、`quotaRuleTotalQuota`、`flowRuleTokenLimit`、`baseQuotaTotal`、`baseMaxToken`。未知或新增后端字段原样保留在行对象中，但说明只承诺页面实际消费字段。
- `callStatus` 的 Java 语义为 `1` 成功、`2` 限流、`3` 额度不足、`4` 失败；`limitType` 的页面筛选值为 `FLOW`（流速）或 `QUOTA`（额度）。
- 用量详情使用 `list[].id` 调用详情端点；它与模型详情使用的 `modelId` 严格区分。

### 3.3 汇总、趋势和排行

`usageAnalytics` 至少请求 summary；企业根入口默认同时请求 trend、model ratio、module ranking。模型上下文入口可传 `includeBreakdowns=false`，此时只请求 summary。返回结构为：

```text
{
  summary,
  trend,
  modelRatio,
  moduleRanking,
  errors
}
```

- `summary` 的页面使用字段包括 `statisticsRange`、`totalCallCount`、`successCallCount`、`limitedCallCount`、`quotaNotEnoughCallCount`、`failedCallCount`、`inputTokens`、`outputTokens`、`totalTokens`、`totalConsumedQuota`、`currentCycleQuota`、`currentCycleUsedQuota`、`currentCycleRemainingQuota`。
- `trend[]` 包含 `date`、`consumedQuota`、`callCount`、`totalTokens`。
- `modelRatio[]` 包含 `modelId`、`modelName`、`consumedQuota`、`callCount`、`totalTokens`。
- `moduleRanking[]` 包含 `functionModule`、`consumedQuota`、`callCount`、`totalTokens`。
- 四路请求独立结算；某一路失败时对应结果为 `null`，`errors` 以 `summary`、`trend`、`modelRatio`、`moduleRanking` 为键保存错误消息，不能把失败伪装成空统计。

### 3.4 导出和功能模块候选

- 导出沿用用量筛选条件，不带分页，要求 `responseType=arraybuffer`。SDK 返回 `{ fileName, contentType, base64, byteLength }`；默认文件名是 `模型用量明细.xls`，非二进制响应抛错。
- 功能模块接口本身不接收筛选参数；页面请求一次拿到候选，`keyword` 只在 SDK 本地过滤。Java 当前返回 `String[]`，候选为空或关键字无匹配时返回 `[]`，接口错误继续抛出。

## 四、额度提升申请：`prepare → submit → cancel`

Portal `ApplyFormModal.vue` 的规则是：`modelId` 必填；`expectedMonthlyQuota` 和 `expectedMaxToken` 至少填一个；填写值必须是非负整数；`reason` 去除首尾空白后不能为空且最多 200 个字符。

提交 body 的准确映射：

```text
modelId                         <- draft.modelId
currentMonthlyQuota            <- draft.monthlyQuota
expectedMonthlyQuota           <- draft.expectedMonthlyQuota
currentMaxToken                <- draft.maxTokenPerRequest
expectedMaxToken               <- draft.expectedMaxToken
statisticsDimension = 2
reason                         <- draft.reason
```

`modelName` 只用于页面禁用展示，不发送。`prepareApply` 输出原始 `draft`、最终 `payload` 和 `warnings`；`submitApply` 会重新执行同一套本地校验并只接受后端返回的申请 ID；`cancelApply` 只返回 `{ cancelled: true }`，代表提交前丢弃本地草稿。

固定 Java `AiTokenQuotaApplySaveReqVO` 对 `expectedMonthlyQuota` 声明了 `@NotNull @Positive`，而 Portal 允许只填最大 Token 或填 0。SDK 保留 Portal 本地规则，同时在这两种情况下返回 warning，不能据此宣称后端必然接受。创建接口标注 `@PermitAll`，但仍需要有效会话；申请记录列表还受 `ai-token:apply:query` 控制。

申请记录请求默认 `pageNo=1`、`pageSize=20`、`statisticsDimension=2`。`dateRange` 按 Portal `buildApplyQuery` 原样发送 `startDate/endDate`，不补时分秒；页面值 `0/1/2/3` 也原样透传。固定 Java 当前申请状态枚举是 `0` 待处理、`3` 已驳回、`4` 已处理，页面筛选标签与 Java 枚举存在差异，不能仅凭页面标签解释审批状态。

提交超时、响应不明确或用户要确认是否创建时，先用 `listApplyRecords` 按模型、时间和状态回查；后端创建接口没有 requestId 幂等协议，回查确认前不要盲目重试。提交成功后本页面没有服务端撤回能力。

## 五、失败、空值和权限语义

- 会话过期、当前租户不匹配、页面权限不足、按钮权限不足、后端业务错误、网络错误和响应结构错误都向调用方抛出；不能把权限错误转换成空列表。
- 列表 `list=[]` 且 `total=0` 只表示当前筛选没有数据；汇总字段的 `null` 或缺失不等于 0。
- 申请表单本地校验失败不发请求；Java 更严格校验产生的差异通过 warning 暴露。
- 统计四路中的单路失败不会阻断其它路，但失败路保留在 `errors` 中；这与页面分块降级展示一致。
- 所有请求都使用当前用户绑定的 `platform` 会话实例；不能从浏览器提取凭据，也不能把私人令牌当作页面会话。
