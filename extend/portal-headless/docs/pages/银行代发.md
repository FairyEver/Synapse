## 能力定义

| 页面动作 | 能力 / 方法 | 请求 |
| --- | --- | --- |
| 筛选、分页 | `report-bank-pay-list` / `.list` | `GET /admin-api/salary/report/bankDropshippingPage` |
| 普通导出 | `report-bank-pay-export` / `.export` | `GET /admin-api/salary/report/exportBankDropshipping` |
| 按银行导出 | `report-bank-pay-export-by-bank` / `.exportByBank` | `GET /admin-api/salary/report/exportByBank` |

页面只有读/导出动作，没有写入接口，不伪造 `prepare → submit → cancel`。

## 参数契约与逐字段基准

列表请求键序固定为 `order`、`orderField`、表单字段、`pageNo`、`pageSize`。表单字段为 `orgId`、`salaryMonth`、`ledgerIds`；月份按 `YYYY-MM` 发送，页面默认当前月份，账套多选数组按顺序连接成逗号字符串。默认页码为 1、页大小为 20，页大小遵循 Portal 的 10/20/50/100/200/500 选项。

导出请求只发送表单字段，不发送排序和分页字段。普通导出使用 `银行代发表.xlsx`；导出弹窗的 `mode=2` 转换为 `cardIssuingBank=农业`，`mode=3` 转换为 `cardIssuingBank=建设`，分别使用中国农业银行和中国建设银行文件名。

列表返回 `{ list, total }`。当前页可见列包括工资月份、姓名、部门全路径、证件号码、开卡银行、银行账号和实发工资；证件号码、银行账号及工资属于敏感数据，SDK保留服务端原值，不在日志中输出。页面底部合计只针对当前页。

组织树和账套候选由 Portal 自动加载，SDK不复制全量长候选；调用方必须提供已经核实的组织/账套 ID，不能用名称替代。

## 操作步骤、失败处理与验证边界

1. 用已核实的 `orgId`、`salaryMonth` 和 `ledgerIds` 调用 `.list`，按 `total` 翻页并保留当前页行原值。
2. 普通导出调用 `.export`；按银行导出调用 `.exportByBank({ mode: 2|3, ...筛选 })`，不要把 2/3 直接当作后端 `cardIssuingBank`。
3. 非法 ID、月份、页码、页大小、银行模式或空文件会在请求前/响应校验时失败；权限、网络和后端错误原样抛出。
4. 当前只完成静态源码和离线请求核对，真实测试环境读/导出 smoke 与部署版本一致性仍待执行。
