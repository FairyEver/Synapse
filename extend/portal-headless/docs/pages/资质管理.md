# 资质管理（`/dashboard/certificate/qualifications/list`）

风险防控域的资质分页列表、完整表单和共享设置。Portal、Java 与 SDK 按本页逐项核对；Java 中仅供 APP 的详情接口和页面不可达的导出端点不属于本页面能力。

## Portal 页面行为

列表通过 `GET /admin-api/hr/aptitude/page` 查询，当前页面可见筛选为 `name`、`organizationId`、`issuingAuthority`、`manageOrganizationId`，初始值均为 `null`。请求还发送 `order=''`、`orderField=''`、`pageNo=1`、`pageSize=20`。页面可达操作是新建、编辑、共享和删除；导出按钮在模板中被注释，虽然脚本保留了不可达的导出函数，SDK 不注册导出能力。

表单详情通过 `GET /admin-api/hr/aptitude/get?id=...` 读取。新建调用 `POST /admin-api/hr/aptitude/create`，编辑调用 `PUT /admin-api/hr/aptitude/update`，删除调用 `DELETE /admin-api/hr/aptitude/delete?id=...`。提交前把 `awardedDate`、`lastAwardedDate`、`endTime` 保持为 `YYYY-MM-DD`，`remindUser`、`pdfUrl`、`pdfName` 数组分别逗号连接；长期有效时页面隐藏到期字段，并按 Portal 的空值规则提交。PDF 上传只接受 `application/pdf`，页面最多保留5项。

共享弹窗使用 `/admin-api/system/share-user/getShare` 和 `/admin-api/system/share-user/createShare`，资质资源的 `type` 固定为 `11`；读取保留 `name/managerType` 展示，保存时四类成员只发送 `{ id }`。

## 表单、权限和数据规则

- `organizationId`、`isForever`、`name`、`awardedDate`、`lastAwardedDate`、`issuingAuthority`、`reportOrganizationId`、`manageOrganizationId`、`depositAddress`、`pdfUrl` 必填；`isForever=0` 时 `endTime`、`remindTime`、`remindUser` 也必填，`isForever=1` 时这三个字段在页面隐藏。
- `name` 最多50字符；`issuingAuthority`、`depositAddress` 的控件最多1000字符；提醒月数为1至99999的整数；日期按 `YYYY-MM-DD` 提交。
- 附件只允许 PDF，最多5项；`pdfUrl` 与 `pdfName` 必须按下标成对，提交时分别逗号连接；至少上传一个附件。提醒人员提交为人员 ID 逗号串，不能用姓名或员工工号替代。
- 列表、详情、写入和共享受当前会话、租户、页面权限及后端数据范围约束。Java `AptitudeDO` 继承 `TenantBaseDO`；SDK 不扩大权限，也不把空列表或 `true` 回执单独当作业务完成证据。

## 后端与 SDK 对齐

Java `AptitudeController` 提供本页面所需的分页、详情、创建、更新和删除；`AptitudeSaveReqVO` 使用 Long ID、LocalDate 日期、Integer 标记/提醒月数和逗号字符串字段。`AptitudeServiceImpl` 在分页时补充组织名称；`AptitudeMapper` 按名称、颁发机构、申报部门、管理部门和所属组织查询。共享枚举为 `APTITUDE(11, "资质")`。`getInfoByApp` 与 `export-excel` 不因存在于 Controller 就注册进本页面能力。

实现文件：`src/capabilities/qualification.ts`；AI 说明：`src/catalog/contracts-qualification.ts`。SDK 将页面可达动作接入 `qualification` 门面；写能力按 `prepare → submit → 回查`，用户取消只丢弃本地草稿，不虚构服务端取消接口。
