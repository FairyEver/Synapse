## 列表与详情字段

列表保留主记录 `id`、员工姓名 `staffName`、工号 `staffCode`、身份证号 `idCard`、组织 `organizationName`、岗位 `postName`、状态 `status`、操作人 `updaterName`、操作时间 `updateTime`、审计字段和 `specialList`。Portal 的七个金额列不是后端独立字段，而是从 `specialList[].specialType` 映射：`1` 子女教育、`2` 住房租金、`3` 住房贷款利息、`4` 赡养老人、`5` 继续教育、`6` 婴幼儿照护、`7` 大病医疗。

默认列表请求为：

```text
GET /salary/salarypersontaxForecast/page
order=&orderField=&name=&staffCode=&idCard=&pageNo=1&pageSize=20
```

响应必须是 `{ list, total }`；`list` 是当前页，`total` 只用于分页。空列表表示当前筛选没有记录，不表示用户没有权限。

详情加载时，Portal 将后端数值 `staffCode` 转成字符串，并把每个专项的 `costStart`、`costEnd` 投影为 `costTime`；两端不完整时回填空数组。表单保存时保留 Portal 的根字段和专项未知字段，但不把表单专用 `costTime` 发送给后端。

## 表单提交规则

表单固定七个且不重复的 `specialType`，员工 `staffCode` 和状态 `status` 是必填项；状态为 `0=已失效`、`1=生效中`。金额保留数字或十进制字符串，按 Portal `a-input-number` 规则限制为非负且最多两位小数；空金额保持空值语义。

每个专项的月份选择器使用 `picker="month"`、`value-format="YYYY-MM-DD"`。提交时严格复现 Portal：

```text
costTime = [任意日期A, 任意日期B]
→ costStart = A所在月第一天
→ costEnd   = B所在月最后一天

costTime = [] 或两端不完整
→ costStart = null, costEnd = null
```

保存和删除都必须分为准备、用户确认、提交、重新查询四步。成功空回执不当作已获得新 ID；删除是后端软删除，必须回查列表确认。导入返回 `null` 表示没有附加提示，返回字符串时必须展示后端提示，不能将其当作全部成功。导入文件字段固定为 `file`，MIME 必须是标准 xlsx 类型。

## 人员资格、权限与边界

- 所有请求使用 `platform` axios 实例，并由 SDK 会话注入 `module-type=14`；权限码固定为 `/dashboard/salary/person-tax-handle`。
- Portal 人员选择器会无关键字分页拉取人员，再按当天业务日期分批调用 `/salary/staff-eligibility/check`，只显示 `eligibleStaffCodes`。SDK 不复制这个无界全量候选入口；调用方应先用已有员工搜索能力取得并核实 `staffCode`，再调用表单或显式的 `eligibilityCheck`。
- 资格回执的 `processedCount` 是实际处理数量，不是请求数量；`excludedStaffList` 的原因必须保留并展示给调用方。
- `id`、`staffCode` 必须来自当前用户可见记录或已核实员工结果；当前用户的后端数据权限仍由 Portal 服务端执行，SDK 不扩大范围。
- `idCard` 是敏感字段，按原值消费并避免写入日志。
