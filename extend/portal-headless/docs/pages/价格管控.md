# 价格管控

## 1. 能力定义

- 菜单归属：门户 → 系统设置 → 销售设置 → 价格管控。
- 页面路径：`/dashboard/sale/setting/price-control/list`。
- 可达流程表单：`/simple/sales/form/005`，流程定义 `guide_price_apply`。
- 页面权限：`/dashboard/sale/setting/price-control`。
- module-type：`60`（销售管理）。
- 请求实例：Portal platform（`VITE_ZHDJ_PLATFORM_API`）。
- 页面动作权限：申请 `setting:price-control:guide-apply:apply`，查看 `setting:price-control:guide-apply:view`，撤回 `setting:price-control:guide-apply:withdraw`，重新发起 `setting:price-control:guide-apply:resubmit`，作废 `setting:price-control:guide-apply:void`，停用 `setting:price-control:guide-apply:stop`，删除 `setting:price-control:guide-apply:delete`。
- 第三方收款管控开关在当前 Portal 源码中没有 `buttonPermissionFlag` 判断；SDK 保留原始读写接口，并以服务端授权和响应为准。
- 本页属于保留的 `系统设置 → 销售设置` 子树；下一页“低价设置”另行实施，隐藏的旧标准配置编辑路由不计入本页。

## 2. 参数契约

### 价格管控标准Tab

品类选项请求为：

```text
GET /admin-api/sales/price-control-config/categoryList
```

标准列表请求为：

```json
{
  "pageNo": 1,
  "pageSize": 20,
  "categoryId": null,
  "itemName": null,
  "officeId": null
}
```

请求为 `GET /admin-api/sales/price-control-config/list`。组织筛选来自销售组织树，SDK接收组织ID数组并按Portal转换为逗号字符串；空数组发送 `null`。标准行的 `statusValue` 是Portal列表侧的派生状态：`1`待生效、`2`生效中、`3`已过期。

标准Tab查看时，没有 `applyId` 就不发查看请求；有 `processInstanceId` 走通用流程详情，否则用 `applyId` 打开005详情。停用按钮只在 `status=1`、`statusValue=2` 且具备停用权限时显示。删除前先请求：

```text
GET /admin-api/sales/price-control-standards/approval-status?id=<id>
```

返回提示文本时停止；无提示才允许用户确认后发送：

```text
DELETE /admin-api/sales/price-control-standards/delete?id=<id>
```

隐藏标准表单实际绑定 `POST /admin-api/sales/price-control-standards/create` 和 `PUT /admin-api/sales/price-control-standards/update`。表单字段为 `orgId`、`controlDate`、`categoryId`、`itemId`、`skuId`、`controlType`、`guidePrice`；`controlType` 由 Portal 固定为 `1`，创建时 `id=null,status=1`，编辑时保留表单的 `id/status`。提交体先剔除 `controlDate/controlPeriod`，再把日期范围拆成 `controlStartDate/controlEndDate`，其余 Portal 表单字段原样保留。

```json
{
  "orgId": "org-1",
  "controlStartDate": "2099-01-01",
  "controlEndDate": "2099-01-10",
  "categoryId": 11,
  "itemId": 21,
  "skuId": 31,
  "controlType": 1,
  "guidePrice": 3.6,
  "id": null,
  "status": 1
}
```

七个表单字段均按页面必填规则校验；日期必须为完整有效范围，指导价非负且最多两位小数。该隐藏表单没有额外的 SDK 状态门禁或按钮权限判断；服务端授权仍由请求结果决定。prepare 取消只丢弃草稿，不发送 POST/PUT。

### 指导价申请Tab

申请列表请求为 `GET /admin-api/priceControlApply/page`，Portal的查询参数为：

```json
{
  "pageNo": 1,
  "pageSize": 20,
  "categoryId": null,
  "orgIds": null,
  "status": null,
  "controlPeriodStart": "可选YYYY-MM-DD",
  "controlPeriodEnd": "可选YYYY-MM-DD"
}
```

日期范围只有完整两端时才发送起止参数；组织数组转换为 `orgIds` 逗号字符串。状态使用平台字典 `bpm_process_instance_status_approval` 的数值：`1`审批中、`2`审批通过、`3`审批驳回、`4`已取消、`5`已废除。

品类树请求为 `GET admin-api/priceControlApply/categoryTree`。Portal将节点映射为 `catId/catName`，并将 `Number(level) !== 2` 的节点置为不可选；SDK返回同样的 `disabled` 派生字段。只有未禁用的二级节点可作为 `categoryId`。选定品类后分别请求：

```text
GET admin-api/priceControlApply/itemList?categoryId=<categoryId>
GET admin-api/priceControlApply/skuList?itemId=<itemId>
```

### 005指导价申请表单和提交

PC表单必填：管控组织、管控周期、管控类型、管控品类、审批标识，且至少保留一行商品明细。提交前业务校验如下：

- `orgId` 按Portal转换为字符串；`categoryId` 必须来自可选二级品类。
- `controlDate` 必须是两个 `YYYY-MM-DD` 日期；结束日期不能早于开始日期，且必须严格晚于当天。
- `controlType` 为 `1`（按指导价）或 `2`（按当地市场报价）。
- 每行 `itemId`、`skuId`、`guidePrice` 必填；价格为非负数字，最多两位小数；`unit` 空字符串转换为 `null`。
- `approvalTag` 必填；`reason` 可空，Portal和后端上限均为500字符；附件最多50项，每项保留 `name/url`，可带 `size`。

Portal唯一提交请求体为：

```json
{
  "orgId": "1",
  "controlStartDate": "2099-01-01",
  "controlEndDate": "2099-01-10",
  "categoryId": 11,
  "controlType": 1,
  "approvalTag": "chick",
  "reason": "价格调整",
  "attachments": [{ "name": "说明.pdf", "url": "https://oss.test/a.pdf" }],
  "items": [{ "itemId": 21, "skuId": 31, "guidePrice": 3.6, "unit": "只" }]
}
```

请求为 `POST admin-api/priceControlApply/create`，返回申请业务ID并启动 `guide_price_apply` 流程。详情回显的明细 `id`、`itemName`、`specInfo` 只用于展示，不能带回提交请求；被注释掉的 `getRequiredStartUserSelectTasks` 不属于当前页面实际提交链路。

### 申请动作和第三方开关

- 撤回：仅 `status=1`，发送 `DELETE admin-api/priceControlApply/cancel`，参数 `{ id }`；后端还要求当前用户是申请人。
- 重新发起：仅 `status=3/4`，Portal打开005编辑页，不在列表页额外发接口；SDK以详情回显和prepareCreate覆盖提交表示该流程。
- 作废：仅 `status=2`，发送 `PUT /admin-api/priceControlApply/void`，请求体为 `null`，参数 `{ id }`；后端生成的标准也会被删除。
- 停用：保留标准列表原记录展开字段，追加 `controlType=1`、`status=0`，并将 `controlPeriod` 拆为 `controlStartDate/controlEndDate`，发送 `PUT /admin-api/sales/price-control-standards/enableOrStop`。
- 第三方收款管控读取 `GET /sales/third-party-payment/setting`，更新 `PUT` 同一路径，正文严格为 `{ enabled: boolean }`。

## 3. 逐字段基准

| 字段 | 页面含义 | 空值/归属 |
| --- | --- | --- |
| `id` | 标准或申请业务主键 | 来自当前列表/详情；不能用流程实例ID替代 |
| `processInstanceId` | BPM流程实例ID | 有值时查看走通用流程详情；不是业务ID |
| `orgId` / `orgFullName` | 管控组织ID/名称 | ID提交，名称只展示；列表筛选用销售组织树ID数组 |
| `controlPeriod` | 标准/申请展示周期 | 标准停用时必须能拆成两个日期；申请创建使用两个独立日期字段 |
| `categoryId` / `categoryFullName` | 管控品类ID/名称 | ID来自可选二级树节点，名称不能代替ID |
| `itemId` / `itemName` | 商品ID/名称 | 商品ID来自当前品类候选；名称只展示 |
| `skuId` / `specInfo` | 规格ID/文本 | 规格ID必须来自当前商品候选；`specInfo`不进入create |
| `guidePrice` | 标准表格字符串或申请明细数字 | 标准列表可能为两位小数或“-”；提交明细为非负数字，最多2位小数 |
| `controlType` | 管控方式 | 申请提交为1/2；标准停用按Portal固定为1 |
| `approvalTag` | 审批标识 | 来自平台字典值，提交给流程变量；不能只提交展示标签 |
| `reason` | 申请原因 | 空值发送null；最多500字符 |
| `attachments` | OSS附件资源数组 | 可空；每项至少有name/url，最多50项 |
| `status` / `statusName` | 申请流程状态/展示名 | 动作判断使用数值，不从名称猜测 |
| `statusValue` | 标准生效状态 | 只有2允许停用；它不是申请status |
| `items[].id` | 详情回显明细ID | 只读回显，提交时必须剔除 |
| `items[].unit` | 商品单位 | 空字符串按Portal转换为null |
| 第三方开关 | 是否开启第三方收款管控 | GET返回boolean；PUT只发送enabled |

## 4. 操作步骤与证据

1. 查询标准Tab时先调用 `sale-price-control-category-list`（需要品类筛选时），再调用 `sale-price-control-standard-list`；保留目标行完整字段。
2. 查询申请或打开005表单时先调用 `sale-price-control-application-category-tree`；只选择 `disabled=false` 的二级节点，再调用商品候选和规格候选能力。
3. 用户确认提交时调用 `sale-price-control-prepare-create`，展示整理后的请求草稿；取消只丢弃草稿，确认后把同一 `draft` 交给 `sale-price-control-create`。
4. 隐藏标准表单创建/编辑分别调用 `sale-price-control-prepare-standard-create` 或 `sale-price-control-prepare-standard-update`；用户确认后交给对应 submit，取消只丢弃草稿。POST 创建返回的ID应回查标准列表，PUT 编辑按同一ID回查。
5. create返回ID、超时或响应丢失后调用 `sale-price-control-application-get` 逐字段回查；成功只表示流程已启动，不表示审批通过。
6. 撤回和作废必须先以列表当前 `status` 调用对应prepare能力，确认后再提交；写入结束或超时后刷新申请列表核对状态。
7. 停用必须以当前标准行的 `status=1/statusValue=2` 为前提；删除必须先做审批状态校验，再确认和删除。写入结束或超时后刷新标准列表核对同一ID。
8. 第三方收款管控开关修改后立即调用 `sale-price-control-get-third-party-setting` 回查；不要把PUT成功提示当作最终状态。
