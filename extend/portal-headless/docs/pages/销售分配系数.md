## 参数契约与逐字段基准

列表默认请求保留 Portal 表单中实际发出的遗留字段：

```text
order=&orderField=&unit=null&allocateOrg=&ruleType=null&expenseType=null&indicator=null&status=1&pageNo=1&pageSize=20
```

调用方可额外提供 `tenantName`、`productGroupId`、`categoryId`、`status`、`pageNo`、`pageSize`。ID 必须是安全正整数或无前导零的正整数字符串；分页大小只接受 `10/20/50/100`。页面筛选控件源码与列表内部旧表单字段并不完全一致，SDK保留默认请求键但不把旧键暴露成业务筛选。

新建表单的实际提交字段只有：

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `productGroupId` | 是 | 产品组ID；源码中控件被注释，但校验与 Java 保存对象仍要求该字段 |
| `categoryId` | 是 | 分类树多选后的非空ID数组，不能重复 |
| `coefficient` | 是 | `a-input-number`；0 至 10000，最多两位小数；它是系数，不是百分比 |

`create` 返回新记录ID。状态是绝对值：`0=停用`、`1=启用`；`prepareSetStatus` 要求目标状态与当前行相反，并保留 `previous` 供再次提交恢复。页面没有创建后的取消/删除动作，成功或超时必须按ID回查，不能把 HTTP 成功当作落库证据。

返回列表只投影页面实际消费的 `id`、`tenantName`、`categoryName`、`coefficient`、`status`、`updateTime`；`coefficient=null` 保留为空，不补成0。详情只返回页面详情使用的 `id`、租户名、分类名和系数，不推断后端未返回的产品组或状态。

## 操作步骤、失败处理与验证边界

1. 需要详情时使用当前列表行的 `id`；需要新建先 `prepareCreate`，确认 `draft` 后再 `create`。
2. 启停前取得同一行最新 `status`，调用 `prepareSetStatus` → `setStatus`；返回 `true` 后按同一ID回查。
3. 超时先回查再决定是否重试；恢复操作只能把同一 `previous` 作为新的绝对状态提交，不是事务回滚。
4. 非法ID、分类数组、系数、状态或分页在发请求前失败；401/403、网络错误、后端业务错误和错误响应形状不改写为空或成功。
