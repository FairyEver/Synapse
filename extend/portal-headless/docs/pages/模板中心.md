## 能力定义与请求契约

SDK 能力定义和 AI contract 分别位于：

- `src/capabilities/technology-setting-template.ts`
- `src/catalog/contracts-technology-setting-template.ts`

### 模板族

| 能力 | Portal 请求 | 参数与请求体 | 页面用途 |
| --- | --- | --- | --- |
| `technology-setting-template-list` | `GET /admin-api/technology/setting/template/page` | query：`pageNo`、`pageSize`、`code`、`name`、`projectDomain`；默认 `1/20/null/null/null` | 列表筛选和分页 |
| `technology-setting-template-create` | `POST /admin-api/technology/setting/template/create` | body：`{ id: null, templateCode, templateName, projectDomain, status, remark }` | 新建模板族基本信息 |
| `technology-setting-template-update` | `PUT /admin-api/technology/setting/template/update` | body：`{ id, templateCode, templateName, projectDomain, status, remark }` | 编辑基本信息；编码和项目大类原样保留 |
| `technology-setting-template-remove` | `DELETE /admin-api/technology/setting/template/delete` | query：`{ id }` | 删除模板族；页面提示已有版本时不能删除 |

模板保存接口不接收首个版本字段。页面新建是两个独立请求：先保存模板族，再使用返回的模板ID创建首个版本。模板保存成功、首版保存失败时，只重试第二步，不能重复创建模板。

### 模板版本

| 能力 | Portal 请求 | 参数与请求体 | 页面用途 |
| --- | --- | --- | --- |
| `technology-setting-template-version-list` | `GET /admin-api/technology/setting/template/version/page` | query 固定为 `{ templateId, pageNo: 1, pageSize: 500 }` | 版本抽屉、配置前选择草稿 |
| `technology-setting-template-version-create-initial` | `POST /admin-api/technology/setting/template/version/create` | body 只有 `{ templateId, versionNo, versionName }` | 新模板的首个版本 |
| `technology-setting-template-version-create` | `POST /admin-api/technology/setting/template/version/create` | body：`{ templateId, sourceVersionId: null, versionNo, versionName, remark }` | 新建全新草稿 |
| `technology-setting-template-version-copy` | `POST /admin-api/technology/setting/template/version/copy` | body：`{ templateId, sourceVersionId, versionNo, versionName, remark }` | 复制已有版本为草稿 |
| `technology-setting-template-version-publish` | `POST /admin-api/technology/setting/template/version/publish` | query：`{ id }`，body 为 `null` | 仅草稿版本可发布 |
| `technology-setting-template-version-disable` | `PUT /admin-api/technology/setting/template/version/disable` | query：`{ id }`，body 为 `null` | 仅已发布版本可停用 |

### 版本编辑器配置

| 能力 | Portal 请求 | 参数与请求体 | 页面用途 |
| --- | --- | --- | --- |
| `technology-setting-template-version-config-get` | `GET /admin-api/technology/setting/template/version/config` | query：`{ templateVersionId }` | 编辑器初始化版本元数据和当前节点配置 |
| `technology-setting-template-version-config-prepare-save` | 无请求 | `templateVersionId` 与扁平 `nodes[]` 本地校验；节点只含 `sourceNodeId`、`parentSourceNodeId`、`sort`、`items` | 保存/发布前准备草稿 |
| `technology-setting-template-version-config-save` | `PUT /admin-api/technology/setting/template/version/config` | body：`{ templateVersionId, nodes }`；`items[]` 只含 `templateItemId`、`displayName`、`isRequired`、`sort` | 保存草稿；发布前必须先完成此步骤 |

编辑器初始化随后按 `projectDomain` 调用模板基础配置的节点树和启用配置项候选接口。节点树返回的展示字段、节点 `children`、配置项的 `itemType/itemName` 等只用于编辑器展示，不能拼进版本配置 PUT body。配置项 `displayName` 可为空字符串；`isRequired` 必须是布尔值，业务组件保存时按页面规则为 `false`。

版本列表字段为 `id`、`versionNo`、`versionName`、`versionStatus`、`publishTime`、`total`。状态含义是 `draft=草稿`、`published=已发布`、`disabled=已停用`。页面用 `total === list.length` 判断500条请求是否取全；未取全时不能自动认定存在唯一草稿。

## 参数、校验和序列化

### 模板基本信息

- `templateCode`、`templateName`：必填且不能全为空格。固定 Portal 没有声明长度或格式上限，SDK 不添加猜测限制。
- `projectDomain`：只能是 `biology`、`information`、`engineering`。
- `status`：只能是数值 `0`（启用）或 `1`（停用），省略时为 `0`。
- `remark`：可为字符串或 `null`；新建省略时按页面默认发送空字符串。
- 编辑必须以当前列表行作为 `current`。`templateCode` 和 `projectDomain` 是页面禁用字段，`changes` 只允许 `templateName`、`status`、`remark`；传入锁定字段或未知字段会在请求前失败。
- 列表行只投影页面消费字段；后端额外字段不会进入 SDK 返回值，也不能反向拼进更新请求。

### 版本表单

- `templateId` 和 `sourceVersionId` 使用记录主键，不接受名称、编码或列表下标替代。
- `versionNo`、`versionName`：必填且不能全为空格。新建模板首版分别受页面 `maxlength=32` 和 `maxlength=100` 约束；固定版本抽屉未声明额外长度限制。
- 全新版本必须使用 `sourceVersionId: null` 并调用 `version/create`；复制版本必须提供来源版本ID并调用 `version/copy`。
- `remark` 可为空，按页面表单序列化为空字符串。
- 发布前要求调用方提供当前列表行的 `currentStatus: draft`；停用前要求 `currentStatus: published`。该字段只做页面按钮前置门禁，不发送给后端。

ID 接受安全正整数或不带前导零的正十进制字符串；非法输入不会发请求。响应分页必须有数组 `list` 和非负安全整数 `total`，列表行缺少页面实际消费字段时抛错，不把错误降级为空列表。

## 返回字段与消费方式

模板列表返回：

- `list[].id`：模板族主键，用于编辑、删除和版本列表；不是模板编码。
- `list[].templateCode`：模板编码，编辑时只保留。
- `list[].templateName`：模板名称。
- `list[].projectDomain`：项目大类编码；已知三项映射为生物/信息/工程，未知值原样保留。
- `list[].status`：原始数值；页面只有数值 `0` 显示启用，其余显示停用。读取到未知值时不能声称它等于标准值 `1`。
- `list[].remark`：备注，可为 `null`。
- `list[].updateTime`：更新时间原值，可为 `null`；不做时区或格式换算。
- `total`：符合当前筛选条件的总数，不是当前页长度。

版本列表返回：

- `list[].id`：版本主键，用于配置/查看、复制、发布和停用。
- `list[].versionNo`、`list[].versionName`：版本展示字段。
- `list[].versionStatus`：版本绝对状态；未知状态原样保留，不自动归类。
- `list[].publishTime`：发布时间原值；未发布时可以为 `null`。
- `total`：该模板族版本总数。

写接口的最终 SDK 返回：模板/版本创建返回根ID；更新、删除、发布、停用返回 `undefined`。这些返回值只说明请求未抛错或服务端给了ID，不能替代写后列表回查。

## 页面操作步骤

1. 查询：按默认或用户筛选调用 `list`，保留完整列表行及 `total`。
2. 编辑：用户选定同一列表行，调用 `prepareUpdate`；确认后将 `draft` 交给 `update`，完成或超时后按同一ID回查。
3. 新建模板：调用 `prepareCreate`，确认后先 `create` 模板基本信息；拿到模板ID后调用 `createInitialVersion`；任一步失败都保留已返回的ID，避免重复创建。
4. 版本管理：以模板族ID调用 `listVersions`。全新草稿走 `prepareVersionCreate → createVersion`，复制走 `prepareVersionCopy → copyVersion`；成功或超时后重新读取版本列表。
5. 发布/停用：仅按当前版本行的绝对状态调用对应能力；发布后回查 `published`，停用后回查 `disabled`。
6. 配置：用版本ID调用 `getVersionConfig`，按返回的 `projectDomain`读取节点树和启用配置项候选；用户编辑后执行 `prepareVersionConfigSave → saveVersionConfig`，保存成功或超时都用同一版本ID回读配置。
7. 发布：编辑器发布按钮的顺序是“先保存当前配置，再发布版本”；配置保存失败时不得调用 `publishVersion`。发布请求本身只带版本ID和 `currentStatus=draft` 前置门禁，不携带节点配置。
8. 删除：用户确认后调用 `remove`；成功或超时后按原ID回查列表确认消失。后端拒绝删除时保留错误，不用删除动作替代清理版本。

写请求没有 `requestId` 或撤销接口。遇到超时、网络中断或路由跳转失败，先回查；模板创建的两步提交和版本创建后的编辑器跳转必须分别处理，不能盲目重发。
