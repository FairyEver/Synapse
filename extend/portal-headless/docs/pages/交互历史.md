### 基准的覆盖边界

那一份 14 条里：**0 条非 GET**、没有带筛选值的请求、也没有带 `id` 的
`getChatListByPage`。所以这一页：

- **有基准背书**：无筛选列表请求（`getChatListByPage?order=&orderField=&pageNo=1&pageSize=20&_t=<ts>`）。
- **仍然只有源码推导**：`updateChatInfo` / `convertHotQuestion`（method、URL、body）、
  10 个筛选位的键位、以及 `getChatRow` 那条"页面从不发"的查询。

## 列表：10 个筛选位 + 区间

无筛选时的键序 —— ⭐ **基准证实**：

```
GET /admin-api/manage/ai/getChatListByPage?order=&orderField=&pageNo=1&pageSize=20&_t=<ts>
```

（基准里这一页的那条与能力构造出来的逐字段一致；测试是 `test/ai-interaction-qa.test.ts` 的 B2 组。）

传了值的会插回**声明位置**；没传的（`null`）整项不出现。全部 15 个键的声明顺序是：

```
order, orderField, platform, isHot, question, nickname, userName, phone, answer,
display, status, pageNo, pageSize, startDate, endDate
```

⚠️ 表单里 `date` 夹在 `display` 与 `status` **之间**，而 `customLoad` 是
`{ ...omit(form, ['date']), startDate, endDate }` ⇒ `omit` 删掉 `date` 之后 `status` 顶上来、
**其余相对顺序不变**，两个时间字段**追加到最后**。所以 `startDate`/`endDate` 排在 `pageSize` 之后。

| 字段 | 取值 | 后端语义（`AiQuestionInfoMapper.xml` 的 `findListByPage`） |
| --- | --- | --- |
| `platform` | `'APP'` / `'PC'`（下拉就是这两个字符串） | `z.platform = #{params.platform}` |
| `isHot` | `0` 否 / `1` 是 | `0` → `is_hot = 0 **or** is_hot is null`；`1` → `is_hot = 1` |
| `question` | 文本 | `question like '内容%'`（**前缀**） |
| `answer` | 文本 | `answer like '内容%'`（**前缀**），且 `!= ''` 才算 |
| `nickname` / `userName` | 文本 | `zhdj_user.nickname` / `user_name` 前缀匹配 |
| `phone` | 文本 | `u1.phone = #{params.phone}`（**等值**，不是模糊） |
| `display` | `1` 显示 / `0` 不显示 | `display = #{params.display}` |
| `status` | `1` 赞 / `0` 踩 / `-1` 无操作 | 分别翻译成 `useful = 1` / `useful = 0` / `useful is null` |
| `startDate` / `endDate` | `YYYY-MM-DD HH:mm:ss` | `z.create_time >= / <=`，**不做 ±1 天** |

⚠️ **`0` 与 `-1` 是有效值**：`isHot=0`、`display=0`、`status=-1` 都会照发。
（`src/http/client.ts` 用的是 `qs` 的 `skipNulls` —— 只跳 `null`/`undefined`，**不跳 `0`、`-1`、空串**。）

## ⚠️ 页面上**声明了**删除，但点不到 ⇒ 本能力不做删除

`list.vue` 的 `useListPageModule` 里写着 `deleteURL: '/manage/ai/logicalDelete'`、
`deleteIsBatch: true`、`selectable: true`、`selectCrossPage: true` —— 但**模板里没有任何删除入口**：
`common-fold` 里只有「查询 / 重置」两个按钮，行内动作只有「转为热门」与「显示 / 不显示」。

**声明了但用户点不到 = 用户做不到**，与 conventions 第 28 条（被注释掉的菜单项）是同一条道理。
所以**不暴露** `removeChat`，`/manage/ai/logicalDelete` 是通过「热门问题」页那个删除按钮接进来的
（见 `src/capabilities/ai-interaction-qa.ts` 的 `removeHotQuestions`）。

## 两个写操作

### ① 显示 / 不显示：`PUT /admin-api/manage/ai/updateChatInfo`

```
body: {"id":<问答行 id>,"display":0|1}
```

页面（`actionUpdateDisplay`，行内有二次确认框「确定要显示/不显示吗？」）：

```js
const updateData = { id: record.id, display: record.display === 1 ? 0 : 1 }
await http.put('/manage/ai/updateChatInfo', updateData, { useJsonPost: true })
```

⚠️ **`useJsonPost: true` 在 `platform.js` 里是个空转的开关** —— 那个字样只在
`zhdj-app-lay.js` / `zhdj-cms.js` 的拦截器里被读（`grep -rn useJsonPost app/portal/utils/http/`）；
`platform.js` 不认它，body 之所以是 JSON，是因为 axios 对普通对象本来就 JSON 序列化。
所以无头侧不需要任何对应开关。

⭐ 能力的 `setChatDisplay(id, display)` 收的是**目标值**（不是 toggle）：页面在客户端算好绝对值
再发，能力也要求调用方算好 —— 做成 toggle 就会变成不幂等的（与 `base-image-set-status` 同理）。
**撤销 = 用原值再调一次**，原值从 `prepareSetChatDisplay(id, 目标值)`（= `getChatRow`）拿。

### ② 转为热门：`POST /admin-api/manage/ai/convertHotQuestion`

```
body: {"id":<问答行 id>,"sort":<≥1 的整数>}
```

页面在弹窗 `components/change-hot-topic.vue` 里发，`pick(formState, ['id','sort'])`
—— **不含 `question`**；`question` 只是弹窗里显示给用户看的。

后端 `AiQuestionHotInfoServiceImpl.saveInfo(id, sort)` 做两件事：

1. `zhdj_ai_question_info.is_hot = 1`（按 `id`）；
2. 往 `zhdj_ai_question_hot` **插一条**：`type=1`（人工）、`is_hot=1`、`del_flag=0`、
   `questionCode = md5(question)`、`create_id` = 当前登录用户。

⚠️ **不去重、`checkSort` 是注释掉的**：同一条问答转两次就是两条热门问题行。
所以 `prepareConvertChatToHot` 会先读一次那一行并给出 `alreadyHot` / `warnings`，
**但不替调用方拒绝**。

⭐ **撤销办法（干净）**：`DELETE /manage/ai/logicalDelete`，body `[新热门行 id]`
—— 后端那条逻辑删除**会按 `question_code` 把问答行的 `is_hot` 一并改回 0**。
能力的 `cancelConvertedHotQuestion(hotId)` 就是它。
因为 `convertHotQuestion` **不回传新热门行的 id**，撤销前要先按问题文本回查：
`listHotQuestions({ role: 'user', question })`。

## 一个「页面从不发」的查询：`getChatRow`

`ai-interaction-chat-get` 打的是同一个 `/manage/ai/getChatListByPage`，但带了 `id`：

```
order=&orderField=&id=<id>&pageNo=1&pageSize=1
```

依据是**后端 mapper 有 `params.id` 分支**（`AiQuestionInfoMapper.xml`：
`<if test="params.id != null"> and z.id = #{params.id}</if>`），
而页面自己永远只带列表参数（这一页**没有详情页**）。
归类：**后端代码证实 + 推断**，**没有**浏览器基准。它的用途是"写之前先读当前值"。

## 真实验证（**读路径有基准，写链路未做**，如实记）

- **读**：列表请求有基准背书（`getChatListByPage`，无筛选那条逐字段一致）。
- **写**：`updateChatInfo` 与 `convertHotQuestion` **一次都没发过**。原因是这一单的约束：
  派单明确「不授权用浏览器、不要 `bsk`、不要新建 smoke 脚本」，而取测试环境会话 token 的唯一受控入口
  是 `smoke/with-portal-token.sh`（它起的正是 `bsk` 会话，`docs/conventions.md` 第 8 条）；
  基准也只是**只读抓取**（0 条非 GET）。所以这里没有"实际请求 / 响应"可记 ——
  是**没发出去**，不是"返回成功就当验证过了"。

要补的话，写链路要跑成 `prepare → submit → cancel` 三段：

1. `prepareSetChatDisplay(id, 目标值)` 拿到 `currentDisplay`；
   `setChatDisplay(id, 目标值)`；再 `getChatRow(id)` **独立证明** `display` 真的变了；
   `setChatDisplay(id, currentDisplay)` 撤销。
2. 挑一条**当前 `isHot !== 1`** 的问答行（先 `listChats({ isHot: 0 })`）：
   `prepareConvertChatToHot({ id, sort })` → `convertChatToHot(...)` →
   `listHotQuestions({ role: 'user', question })` **独立证明**热门行出现了 →
   `cancelConvertedHotQuestion(hotId)` → 再查一次确认它不在了、且那条问答回到 `isHot=0`。

`sort` 挑一个当前没被占用的值（后端不校验唯一性，但占了会与别人的排序打架）。
测试数据带 `SDK-TEST-` 前缀、同一轮内撤销。

## 基准兑现了什么 / 还剩什么没判据

**已落成真断言**（B2 组）：

- ✅ 无筛选列表请求与基准**逐字段一致**（URL、键序、`_t` 位置、`order=`/`orderField=` 空值）。
- ✅ 这一页"页面自己的请求只有那一条"（去掉两条外壳请求后去重只剩 1 条）——
  顺带**证伪了一条猜测**：上面「声明了但点不到」那段说的"没有删除请求"，
  基准里也确实没有任何非 GET 请求。
- ✅ 不发 `module-type`（基准 14 条的 `headers` 只有四个键）；请求头逐键一致。

**仍然没有判据**（留着 `it.todo`）：

- ❌ 带筛选值的请求形状（10 个筛选位的键位、`isHot=0`/`display=0`/`status=-1` 是否照发）
  —— 基准只抓了"挂载时无筛选"那一条，一个筛选值都没填。
- ❌ `PUT /updateChatInfo` 与 `POST /convertHotQuestion` 的 method / body 逐字节（0 条非 GET）。
- ❌ `getChatRow` 的 `params.id` 分支在真机上是否真取回那一行（基准那条 `getChatListByPage` 没带 `id`）。
