# 方法设置（孵化预案）

## 能力定义

- 页面：`/dashboard/product/setting/hatchery-manage/method/list`
- 菜单/路由权限：`/dashboard/frame/hatchery-plan/method`
- Portal 页面是包装器 `hatchery-manage/method/list.vue`，实际导入并复用 `hatch-manage/method/list.vue`；SDK 复用接口、表单和响应行为，但能力页面路径与菜单权限独立绑定到孵化预案页面。
- HTTP 实例：`product`；页面没有可推导的 `module-type`，不发送该请求头。
- 页面按钮权限：查询 `program:method:query`，新建/编辑 `program:method:submit`，删除 `program:method:delete`。
- 能力：查询列表、准备/提交新建、准备/提交编辑、准备/提交删除；提交接口返回 SDK 本地 `true`，不把它解释为已回查的业务记录。

## 参数契约

列表调用 `GET /programUnit/getList`，按 Portal product 页面发送：`order=''`、`orderField=''`、`classification`、`search`、`scope=1`、`pageNo`、`pageSize`。`classification` 来自 Portal 平台字典 `method_class`；页面的筛选规则标记它必填，但首次自动加载仍可能发送空字符串，因此 SDK 允许省略并按页面发送空值。分页默认 `pageNo=1`、`pageSize=20`，只接受页面支持的 10、20、50、100。

新建调用 `POST /programNew/methodLib/createTrait`，编辑调用 `POST /programNew/methodLib/editTrait`，删除调用 `GET /programNew/methodLib/deleteTrait?id=...`。新建和编辑表单的 `traitType`、`name`、`title1`、`title2`、`title3` 均为必填；数字 `traitType` 按 Portal 弹窗转成字符串。编辑输入保留当前列表行的 raw 扩展字段，再覆盖 `id、traitType、name、title1、title2、title3`；`classification` 和 `traitName` 分别作为缺失 `traitType` 和 `name` 时的回填来源。

## 逐字段基准

列表返回 `{ list, total }`。`list` 是当前筛选和分页下的记录，不是全量数据；SDK 兼容 Java page 包络中的 `records/list/rows`，并保留未列出的后端扩展字段。页面使用的字段为：

- `list[].id`：ProgramUnit 方法记录 ID；编辑和删除目标，缺失时不能安全执行写操作。
- `list[].classification`：方法归类原始字典值；编辑回填的备用来源。
- `list[].traitTypeName`：方法归类展示文本。
- `list[].name`：方法名称；为空时编辑回填使用 `traitName`。
- `list[].traitName`：后端兼容的备用方法名称字段。
- `list[].title1`、`list[].title2`、`list[].title3`：一级、二级、三级标题；编辑提交时均必填。
- `total`：当前筛选条件的记录总数，不是当前页数组长度。

准备能力只在本地校验和生成草稿，不发请求。新建草稿会显式带 `id: undefined`，JSON 序列化时不会发送该字段；编辑草稿会保留 Portal raw 对象扩展字段。取消新建或编辑只丢弃草稿，不调用写接口；取消删除只丢弃待确认的 ID。

## 操作步骤与证据

1. 确认当前用户拥有孵化预案页面权限和对应按钮权限，按 `method_class` 字典值查询列表。
2. 新建或编辑先调用对应 `prepare`，把返回的 `draft` 展示/确认后再交给 `create` 或 `update`；不要自行补 `age、traitCode` 或切换到其他接口。
3. 删除先用当前列表行的 `id` 调用 `prepareRemove`，用户确认后调用 `remove`；Portal 使用 GET 删除，不改写为 DELETE。
4. 新建、编辑、删除请求成功或响应不确定后，必须再次 `list`，分别按方法 ID、名称和三个标题确认写入或按同一 ID 确认消失；`true` 和接口消息都不是独立的落库证据。

依据包括 Portal `app/portal/menus/product/operation.js`、`hatchery-manage/method.vue`、包装列表页及其复用的 `hatch-manage/method/list.vue`、`modal-form-content.vue`、公共分页模块和 `app/portal/utils/http/product.js`；后端依据 `ProgramUnitLayController.java`、`MethodLibController.java`、`ProgramNewStandardLibTraitDTO.java`、`ProgramUnitMapper.xml` 与 `ProgramNewServiceImpl.java`。当前未启动浏览器，也未在真实测试环境执行列表、新建、编辑、回查、删除闭环；离线测试锁定了请求方法、路径、参数、表单校验、响应解包、权限上下文和取消/回查语义。

后端现有 `createTrait/editTrait/deleteTrait` 仍出现按 `age、traitCode` 和 `fm_simu_program_lib` 处理的代码，而 Portal 当前页面提交的是 `traitType、name、title1、title2、title3`，列表又来自 `ProgramUnit`。SDK 保留 Portal 的实际请求，不用相似的 `programUnit/add/update` 替换，也不伪造写入成功；真实环境若拒绝该协议，必须按失败处理并记录为后端协议差异。
