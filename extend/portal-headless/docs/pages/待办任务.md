# 待办任务（`/dashboard/flow/task/todo/list`）

审批管理域「我的流程」四页里的第二页。四件套的其它三件分别在：
能力定义与参数契约 → `src/capabilities/flow-task.ts`；逐字段基准 → `baseline/flow-management.browser.json`；
回归测试 → `test/flow-management.test.ts`。

**这一页最要紧的事实是：它不是一个独立的页面。**

| 项 | 值 |
| --- | --- |

（同批的「发起流程」才是真正的自定义页面。）

## 与 `backlog-task-examine-list` 的关系（读这一页的人必看）

页面本体：

```vue
<!-- app/portal/views/dashboard/hr/flow/task/todo/list.vue -->
<PageView :finished="1" :componentMode="true" key="todo"/>
```

它 import 的就是 `docs/pages/待办事项.md` 那一页的组件，**同一个接口、同一套参数**：

| | `/dashboard/backlog/task-examine/list` | **本页** |
| --- | --- | --- |
| 能力 | `backlog-task-examine-list` | `flow-task-todo-list` |
| 接口 | `/bpm/hr/task/list-by-category-web` | 同 |
| 右上角「待办/已办」切换器 | **有**（`showTab && !componentMode`） | **没有**（本页传了 `componentMode`） |
| `finished` | **开放**（用户点得到 1 / 2） | **钉死 1**（用户切不了） |
| `selectType`（时间范围） | 开放（但只对 `finished=2` 有意义） | **钉死 1**（那个下拉的 `v-if` 是 `finished === 2`，本页渲染不出来） |

**分开建两个能力的判据**（与本仓库既有的那条口径一致，见 `src/capabilities/backlog-task-examine.ts`
文件末尾那张表）：**用户能不能在页面上到达那个状态**，不是"换个值会不会拿到别处也有的一批数据"。

⇒ 调用方怎么选：

- 要**在一条调用里同时看待办和已办**（或要看 `finished=2`）→ 用 `backlogTaskExamine.list({ finished })`。
- 只要**这一页固定看到的待办** → 用 `flowTask.listTodo()`（等价于 `finished=1`，但写不出别的值）。
- 两条能力打**同一个后端接口**，参数一致，结果可互相印证。

⚠️ `docs/pages/待办事项.md` 里有一节写着「SDK 只导出**一个**能力（`backlog-task-examine-list`），
这是刻意的」，那条结论**已经被本轮修改**（用户 2026-09-21 复核后同意分开建）。
两份文档如果对不上，以本页与 `src/capabilities/flow-task.ts` 的「基准对照」一节为准。

⚠️ 另有一个**同名不同接口**的坑，别混：基础能力 `base-todo-list` 打的是
`/admin-api/bpm/task/list-by-category`（**没有 `-web` 后缀**），`finished` 是三态
（缺席 = 全部 562 条）。它不是本页的接口。

## 逐字段基准

基准文件：`baseline/flow-management.browser.json` 第 2 条（打开页面时自动查询）。

```text
GET https://biz-api-test.wodecorp.cn/admin-api/bpm/hr/task/list-by-category-web
    ?order=&orderField=&name=&title=&startUserName=&finished=1&selectType=1&pageNo=1&pageSize=20&_t=<ts>
```

请求头（**没有 `module-type`**）：`tenant-id` / `token` / `Accept-Language: zh-CN` /
`Accept: application/json, text/plain, */*`。

**参数顺序是契约的一部分**（`common/libs/renren/list.js:473-483` 的
`{ order, orderField, ...form }` 再补分页），实现按固定表拼，调用方实参顺序不影响结果：

```text
order, orderField, name, title, createTime[0], createTime[1], startUserName,
finished, selectType, processCategory, pageNo, pageSize, _t
```

三条与别页不同的地方：

**1. 空值**照发**（空字符串，不是省略）。** 没填筛选时 URL 上照样有 `order=` `name=` `title=`
`startUserName=`（约定第 4 条）。唯一的例外是 `processCategory`：它的初值是 `null`
（`route.query.taskKey || null`），被 qs 的 `skipNulls` 丢掉，所以默认**连键都没有**。

**2. `createTime` 没有「结束日 +1 天」。** 这一页没有 `convertFetchForm`，两个值原样进 qs、
序列化成 `createTime[0]` / `createTime[1]`（qs 默认的 indices 形式，方括号编码成 `%5B`/`%5D`）。
照抄学习管理域那套 +1 天会**静默多查一天**；要含 9-10 一整天得自己给 `2026-09-10 23:59:59`。

**3. `selectType` 在请求里恒有，但这一页的控件没渲染。**
`formState.selectType` 的初值恒为 1，控件只是被 `v-if="finished === 2"` 藏起来了。
**「控件没渲染」不等于「参数不存在」** —— 基准第 2 条里就明明白白有 `selectType=1`。
SDK 照这个来：键照发、值钉死。这一点与 `docs/pages/待办事项.md` 记的是同一件事。

## 参数契约

| 参数 | kind | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | text | 否 | 流程名称，模糊匹配 |
| `title` | text | 否 | 审批内容，模糊匹配 |
| `createTimeStart` / `createTimeEnd` | date | 否 | 必须**成对**给；格式 `YYYY-MM-DD HH:mm:ss`；**没有 +1 天改写** |
| `startUserName` | text | 否 | 发起人**姓名**（纯文本模糊匹配，**不是人员选择器**，所以本页没有长选项参数） |
| `processCategory` | text | 否 | 流程分类。**⚠️ 传不对的值后端会 500**，见下 |
| `pageNo` / `pageSize` | number | 否 | 默认 1 / 20 |
| `finished` | — | — | **钉死 1，不开放** |
| `selectType` | — | — | **钉死 1，不开放**（本页那个下拉渲染不出来） |

两条本地校验（都是 `Promise.reject`、**不发请求**）：区间必须成对给；两端都必须是
`YYYY-MM-DD HH:mm:ss`。见 `test/flow-management.test.ts`。

### ⚠️ `processCategory` 是坏的（后端 bug）

值不是某个**真实存在的流程分类**时**一律 500**（业务 code，HTTP 仍是 200），空串也 500，
而完全不传这个键就是好的。根因在后端
`BpmHrTaskServiceImpl.webGetTaskListByCategory`（`modelMapGroupCategory.get(...)` 取到 `null`
之后直接 `.stream()`）。完整的三层证据写在 `docs/pages/待办事项.md` 的
「`processCategory` 这一条是坏的」整节，这里不重复。

SDK 的处理：**默认不传**（所以默认调用是好的、和浏览器打开页面一致）、
kind 是 `text` 不是 `enum`（不把那组注定 500 的深链值当契约发出去）。

## 操作步骤

```text
1. 进入「待办任务」（/dashboard/flow/task/todo/list）
2. （可选）填流程名称 / 审批内容 / 发起人（三个都是纯文本模糊匹配）
3. （可选）选发起时间区间
4. 查询
5. 行上：「办理 / 详情 / 跟进」——都在别的页面或弹窗里，本能力不覆盖
```

**这一页没有**右上角的「待办/已办」切换器，也没有「时间范围」下拉 —— 两个都因 `componentMode`
或 `finished !== 2` 而不渲染。要那两种状态请用 `backlogTaskExamine` 或「已办任务」页。

## 真实验证

- **基准来自真实环境**：2026-09-21 由 `bsk` 抓于 `https://webtest01.wodecorp.cn/portal.html#/`
  （`baseline/flow-management.browser.json` 第 2 条）。
- **契约与基准逐字段一致**：`test/flow-management.test.ts` 比有序的 `[key, value]`，
  另有「`finished` 与 `selectType` 都改不动」「区间没有 +1 天」「单边/坏格式要 reject」
  「`processCategory` 默认不发、给了才出现在原位」各一条。
- **没做**：SDK 对真实后端的**冒烟**（本波不跑浏览器、也没有这一页的 smoke 脚本）。

## 尚未覆盖

- **写操作：办理 / 批量办理 / 跟进**。这些在**别的页面或弹窗**里：
  「办理」跳 `/dashboard/backlog/task-examine/...`（按 `processInstance.category` 分几种表单）、
  「批量办理」先把选中行塞进 `bridgeSet()` 再跳 `/dashboard/backlog/task-examine/batch-process`、
  「跟进」是同页弹窗。**单条的通过/驳回/转办/委派/回退已经有能力**：
  `src/capabilities/task-action.ts` 的 `task-action-approve` / `-reject` / `-transfer` /
  `-delegate` / `-return` / `-batch-approve` / `-batch-reject`，**本页不重复建**。
- **`result` / `category` 的取值语义**（`result === 2` 才显示「办理」、`category === null` 才显示
  「办理」）只从模板与 `useActionButtons.js` 读出，**没有逐个取值构造数据去验证渲染分支**。
  这些字段本能力原样返回，不做解释。
- **`processCategory` 的合法取值表没有枚举出来**（只实测了 `human_process` 可用），所以只能开成 `text`。
- **`isBatchSelectable` 的判定**（`category === null || category === '8'`）只从源码读出，未验证。

## SDK AI 说明契约（2026-09-22）

本节由当前 SDK 描述结果整理；说明权威来源为 `src/catalog/contracts-business.ts`。调用 `catalog.describe(id)`（或 `id-llm`）可得到参数来源、返回字段/状态、数据消费与后续映射；`catalog.describePage(页面路径)` 用于选择页面功能。以下更新以本节为准；前文历史请求/实测记录仍保留其记录日期。

### `flow-task-todo-list`

查询我的待办任务，固定 finished=1；查全公司任务流水应使用 flow-manage-task-list。

- 执行：`sdk.flowTask.listTodo`；通过 `capabilities.invoke('flow-task-todo-list', args)` 调用时按 `params` 填参。性质：read。
- 参数：`name` 可选 (string)；`title` 可选 (string)；`createTimeStart` 可选 (string)；`createTimeEnd` 可选 (string)；`startUserName` 可选 (string)；`processCategory` 可选 (string)；`pageNo` 可选 (number)；`pageSize` 可选 (number)。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`{ list: object[], total: number }`。list=[] 为当前页无记录；total=0 表示该筛选无结果。保留筛选条件检查页码，不将空结果解释成权限判定。
- 字段：`list`、`total`、`list[].id`、`list[].name`、`list[].createTime`、`list[].processInstance`、`list[].processInstance.id`、`list[].processInstance.title`、`list[].processInstance.startUserNickname`、`list[].processInstance.category`、`list[].processInstance.result`、`list[].processInstance.businessKey`、`list[].canWithdraw`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：展示 name、processInstance.title/startUserNickname，办理用任务 id，跟踪流程用 processInstance.id；两者不能互换。只读列表不会批准或撤销审批。 processCategory 必须真实存在；空字符串和消息深链 taskKey 可能使后端 500，未选择分类时省略该字段。
- 完成条件：交付待办/已办清单；用户要求办理时仍需继续到 task-action 上下文。
- 后续：optional → `task-action-instance`：需要查看或办理时先读流程实例（processInstanceId ← result.list[].processInstance.id）；optional → `task-action-workflow-path`：查完整审批链，找到属于当前用户且可办理的任务再选择办理动作（processInstanceId ← result.list[].processInstance.id）
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。
