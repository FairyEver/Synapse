# 前端日志（`/dashboard/setting/log/list`）

## 页面范围与证据

门户 → 系统设置 → 前端日志，权限 `/dashboard/setting/log`，只在 Portal 非生产环境的菜单中挂出，使用 `platform` HTTP 实例，不发送 `module-type`。

页面源码 `app/portal/views/dashboard/hr/setting/log/list.vue` 的页面标题和表格称为“前端日志”，但实际请求的是 `/admin-api/sys/menu/menuListNotBySystem`，返回 HR 菜单树而不是浏览器日志事件。页面只有 `text`、`finger` 两个筛选输入和分页外观，没有新增、编辑、删除、导出或详情动作；请求也未启用分页。

Portal 证据：`app/portal/menus/common.js`、上述页面，固定提交 `bbcfc35154`。

Java 证据：`HrSysMenuController`、`HrSysMenuServiceImpl`、`SysMenuDao.xml`、`SysMenuDTO`，固定提交 `b7a359adc9e`。Controller 没有显式页面动作权限注解；服务端无查询参数，SQL 返回未按系统过滤的菜单记录并由 `TreeUtils.build` 组装 `children` 树。离线参数、递归字段和错误边界由 `test/setting-frontend-log.test.ts` 锁定，未把真实环境请求称为已实测。

## 能力与实际语义

| 页面动作 | SDK 能力 / 方法 | 副作用 |
| --- | --- | --- |
| 读取菜单树 | `setting-frontend-log-list` / `settingFrontendLog.list(query?)` | 只读；返回根节点数组和递归 `children` |

Portal 仍会提交 `text`、`finger`，SDK 保留相同请求形状；由于后端 Controller、Service 和 SQL 都不接收或消费它们，不能向调用方承诺筛选会改变结果。页面只在非生产菜单中可见，不应把该能力解释为生产环境可用的日志查询入口。

## 参数与返回契约

- 默认请求参数为 `{ order: '', orderField: '', finger: '', text: '' }`；传入 `null` 按 Portal 形状归一为空字符串。
- 返回值是根节点数组，不是 `{list,total}` 分页包；后端 `TreeNode` 继承提供递归 `children`。
- 节点保留 `id`、`pid`、`name`、`url`、`menuType`、`project`、`icon`、`permissions`、`sort`、`createDate`、`parentName`、`useSystem` 和 `children`，长 ID 可以是字符串。
- `pid=0` 表示根节点；`menuType` 后端约定 `0=菜单、1=按钮`；`permissions` 可能是逗号分隔的多个授权标识；`useSystem` 是归属编号，不改变接口返回“不区分系统菜单树”的事实。
- `[]` 是服务端确实返回空树；登录、权限、网络、非数组响应或坏节点不会被转成空树，而会失败。

## 操作步骤与失败处理

1. 使用当前会话调用 `settingFrontendLog.list`，需要筛选时传 `text`/`finger`；不要据此假设后端已过滤。
2. 递归遍历根数组与 `children`，按 `url`、`name`、`permissions` 或 `useSystem` 做调用方侧解释。
3. 把页面标题和真实返回语义分开记录；返回菜单节点不等于前端日志事件。
4. 权限、登录、网络、响应结构和节点类型错误原样报告，不以空数组掩盖失败。
