# 标准管理

## 能力定义

- 页面：`/dashboard/manage/standard/list`
- 菜单权限：`/dashboard/manage/standard`
- HTTP 实例：`platform`；页面推导 `module-type=13`，列表当前按页面规则使用 `treePage/searchPage`
- 能力 ID：`perf-manage-standard-list`、`perf-manage-standard-prepare-save-data`、`perf-manage-standard-save-data`、`perf-manage-standard-cancel-save-data`、`perf-manage-standard-role-post-tree`（详情页候选树，见下），以及既有导入、删除能力

`listStandards(query)` 的 `keyword` 为空时调用 `GET /performance/kpistandard/treePage`，非空时调用 `GET /performance/kpistandard/searchPage` 并固定 `dataType=2`；`selection=false`、`pageNo` 和 `pageSize` 由页面请求形状决定，`pageSize` 上限为100。

## 参数契约

标准详情页不是只提交表格行，而是把整个 `formState.value` 作为 body。已核对的核心字段为：

```ts
{
  id: string | number,
  name: string,
  standardType: 0 | 1,
  unit: string,
  organizationList: Array<string | number>,
  header: string[],
  dataList: Array<{
    standardKey: string | number,
    standardValue: string[],
    ...页面/Java回显字段
  }>,
  orgTreeIdList: Array<string | number>,
  orgPostIdList: Array<string | number>,
  ...Java TreeNode/页面回显字段
}
```

`prepareStandardDataSave` 校验上述字段并保留额外回显字段；`submitStandardDataSave({ draft })` POST `/performance/kpistandard/saveStandardData`，不包装、不裁剪成裸数组；`cancelStandardDataSave()` 只做本地取消。

## 「使用标准岗位」的候选树（标准详情页）

标准详情页（`standard/[mode]/[id]` 渲染的 `standard-data.vue:33-38`）里
「使用标准岗位」这一项挂的是 `standard/components/post-select.vue`，
它自己发一条只读请求：

```
GET /admin-api/org/organization/getRoleOrganizationPost?roleId=&_t=<ts>
```

- 能力 id：`perf-manage-standard-role-post-tree`；方法 `getStandardRolePostTree(query)`；
  唯一参数 `roleId`，**页面永远发空串**（组件的 `roleId` 默认 `''`，调用处没传），
  Spring 把空串绑成 `null` ⇒ 按**当前登录用户的角色**算可见范围。
- 返回的是**一棵树**，后端把**组织节点**与**岗位节点**混在同一棵上：

  | 节点 | `id` | `postId` | `orgPostId` | 能不能选 |
  | --- | --- | --- | --- | --- |
  | 组织 | 真组织 id | 无 | **无** | ❌（页面 `disabled: !item.orgPostId`） |
  | 岗位 | **拼出来的** `organizationId + "" + postId` | 岗位 id | `hr_organization_post.id` | ✅ |

  ⚠️ **岗位节点的 `id` 不是主键**，是后端把两个 id 当字符串拼起来的
  （`HrOrganizationServiceImpl:3466`），只用于树组件回显。**落库的是 `orgPostId`**：
  页面 `onTreeChange` 把所选节点的 `orgPostId` 收集成 `orgPostIdList`，
  同时 `v-model:value` 把节点 `id` 收进 `orgTreeIdList`。这两个数不能互换。
- ⚠️ 同一页里另外两版组织树写法在源码中是**注释掉的**（`standard-data.vue:20-31`：旧的
  `component-organization-select` 与 `portal-hxr-tree-select-role-org`，都指
  `/org/organization/getRoleOrganizationTree`）。页面里生效的是最后那一版
  （注释写着「4月22日长建让改成这个」），按项目规则**注释掉的不进 SDK**。
  保存 DTO 里的 `organizationList` 字段仍然存在，但页面已经不用它了。
- **没有基准**：这一条在详情页发，基准只抓了列表页。测试锁的是源码调用形状 + Java 字段规则 + 契约语义。

## 逐字段基准

Portal `standard-data.vue` 初始状态包含 `standardType/name/unit/organizationList/header/dataList/orgTreeIdList/orgPostIdList`。详情读取后以 `{ ...data, header: data.header || [''], dataList: data.dataList || [] }` 更新，新增行生成 `standardKey` 与按表头长度填充的 `standardValue`。保存前执行表单校验，然后直接调用：

```js
await http.post('/performance/kpistandard/saveStandardData', formState.value)
```

Java `KpiStandardController` 的 `@PostMapping("saveStandardData")` 接收 `StandardDataDTO` 并执行 `ValidatorUtils.validateEntity`。DTO 字段与上述 body 对齐；其 `KpiStandardDataDTO` 行字段包含 `standardKey` 和 `standardValue`。Service 会使用 `organizationList`、`orgPostIdList` 更新授权，删除旧标准数据，再按 `id/header/dataList` 保存表头和行。

菜单权限存在；该保存方法当前未声明额外的 Spring 权限注解，SDK 不把这理解为绕过菜单/服务端鉴权。

## 操作步骤

1. 先取得标准详情，保留返回的 Java `TreeNode`/页面回显字段。
2. 修改 `header`、`dataList[].standardKey`、`dataList[].standardValue` 或授权数组；保证每行 `standardKey` 可解析为 ID。
3. 调用 `prepareStandardDataSave`，确认标准 ID、授权范围、表头和将覆盖的行数据。
4. 用户确认后调用 `submitStandardDataSave`；成功回执后重新读取详情确认表头、行和授权已落库。
5. 用户取消时调用 `cancelStandardDataSave`，不发请求。
