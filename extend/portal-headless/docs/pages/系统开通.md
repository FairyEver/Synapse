# 系统开通

## 1. 能力定义

页面路径：`/dashboard/setting/integration/list`
页面权限：`/dashboard/setting/integration`
HTTP 实例：`platform`
`module-type`：不发送。

本页属于保留范围内的“系统设置”。页面展示人力、财务、物料、生产、供应、销售六个集成开关，以及组织筛选、备注和编辑/新建动作。这里的 `productionEnabled` 只是系统开通页面的一个字段，不是独立生产根模块；独立生产页面仍不属于本次范围。

SDK 登记的能力：

- `system-integration-list`：查询分页列表。
- `system-integration-get`：按组织ID读取编辑表单。
- `system-integration-prepare-create` / `system-integration-create`：准备并创建配置。
- `system-integration-prepare-update` / `system-integration-update`：准备并保存编辑配置。

Portal 的组织选择器调用无界全量组织树。SDK 不把它发布为独立的大结果能力，调用方需提供已知 `orgId`，或从本页列表/详情获取组织ID。

## 2. 参数与提交契约

列表请求严格发送：

```text
GET /admin-api/system/org-module-switch/page
{ order: "", orderField: "", orgId: null|ID, pageNo: 1..., limit: 20|10|50|100 }
```

详情请求为 `GET /admin-api/system/org-module-switch/get`，参数只有 `orgId`。详情中的六个 `0/1` 开关按 Portal 的 `normalizeFromApi` 转成布尔值，备注 `null` 转为空字符串。

创建和编辑都必须先 `prepare`，再把完整 `draft` 交给写能力。最终请求严格为：

```json
{
  "orgId": 101,
  "hrEnabled": 1,
  "financeEnabled": 0,
  "inventoryEnabled": 1,
  "productionEnabled": 0,
  "supplyEnabled": 0,
  "salesEnabled": 1,
  "remark": "备注"
}
```

布尔值按 Portal 的 `boolToInt` 转为 `0/1`；六个开关不能只提交差异字段。`orgId` 必填，备注最多200个字符，空备注提交空字符串。后端返回非负整数影响条数；该数字不等于详情，且后端可能对目标组织及其子孙组织执行 upsert。

Java 中存在但页面未调用的 `/list`、`/batch-config-by-string` 不纳入 SDK；本页没有删除、导出或服务端撤销接口。

## 3. 逐字段基准

列表/详情记录字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 配置记录主键，长整数按字符串原样保留 |
| `orgId` | 保存目标组织ID |
| `orgName` | 组织名称 |
| `orgFullPath` | 组织全路径，用于区分同名组织 |
| `hrEnabled` | 人力开关 |
| `financeEnabled` | 财务开关 |
| `inventoryEnabled` | 物料开关 |
| `productionEnabled` | 生产集成开关，仅属于本页字段 |
| `supplyEnabled` | 供应开关 |
| `salesEnabled` | 销售开关 |
| `remark` | 备注；详情可能为 `null` |
| `createTime` / `updateTime` | 服务端原始时间，不转换时区 |

`list` 返回 `{ list, total }`。写能力返回后端影响条数；写入成功或超时后必须按 `draft.orgId` 调用 `system-integration-get`，必要时再用列表核对级联影响。`prepare` 或用户取消只丢弃草稿，不发请求；已提交后没有 Portal 可达的回滚动作。

## 4. 操作步骤与验证

查询：调用 `system-integration-list`，按 `total` 继续分页；从 `list[].orgId` 进入编辑时先调用 `system-integration-get`。

创建：组织ID和用户意图 → `system-integration-prepare-create` → 用户确认后 `system-integration-create({ draft })` → 用 `system-integration-get({ orgId })` 回查六个开关和备注。取消时丢弃 `draft`。

编辑：`system-integration-get({ orgId })` → 合并用户明确修改 → `system-integration-prepare-update` → `system-integration-update({ draft })` → 按同一 `orgId` 回查。编辑页组织选择器禁用，不能把 `id` 当成 `orgId`。
