# 产品设置预案品种

页面路径：`/dashboard/product/setting/hatch-manage/variety/list`。

菜单归属是 `系统设置 → 生产设置 → 养殖预案 → 预案品种`。这里的“生产设置”是系统设置内的 Portal 子菜单，不是范围外的独立生产业务菜单。

## 页面能力定义

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询预案品种 | `product-setting-hatch-manage-variety-list` / `productSettingHatchManageVariety.list` | `GET /sys/parameter/page` |
| 准备新建 | `product-setting-hatch-manage-variety-prepare-create` / `productSettingHatchManageVariety.prepareCreate` | 本地表单校验，不发请求 |
| 新建 | `product-setting-hatch-manage-variety-create` / `productSettingHatchManageVariety.create` | `POST /sys/parameter/save` |
| 准备编辑 | `product-setting-hatch-manage-variety-prepare-update` / `productSettingHatchManageVariety.prepareUpdate` | 本地表单校验，不发请求 |
| 编辑 | `product-setting-hatch-manage-variety-update` / `productSettingHatchManageVariety.update` | `POST /sys/parameter/save` |
| 准备删除 | `product-setting-hatch-manage-variety-prepare-remove` / `productSettingHatchManageVariety.prepareRemove` | 本地确认前准备，不发请求 |
| 删除 | `product-setting-hatch-manage-variety-remove` / `productSettingHatchManageVariety.remove` | `GET /sys/parameter/delete?id=...` |

请求使用 `product` HTTP 实例，补 `devicetype=PC`；本页没有页面推导出的 `module-type`，因此不发送该请求头。菜单权限是 `/dashboard/frame/breeding-plan/variety`；查询、提交、删除权限分别是 `program:variety:query`、`program:variety:submit`、`program:variety:delete`。SDK 只复刻页面请求，不绕过服务端权限。

## 参数契约与提交规则

页面列表没有可见筛选字段，公共列表模块仍会发送 `order=""`、`orderField=""`、`pageNo` 和 `pageSize`；styleV2 默认每页20条，页面支持10、20、50、100。路由存在 `suiteId` 时，Portal 会把它追加到列表请求参数；当前 Java `/sys/parameter/page` 只显式接收 `pageNo`、`pageSize`，所以 SDK 保留实际请求字段，但不宣称后端一定按 `suiteId` 过滤。

新建和编辑表单状态包含 `id`、`name`、`code`、`caption`、`icon`、`variety`、`gen` 七个字段。`name`、`code`、`caption` 必填；图标、品种、代次没有 Portal 必填规则。表单初始化使用 `raw?.field || ''`，所以缺失值提交为空字符串。新建的 `id` 固定为空字符串，Java 以此进入新增分支；编辑使用当前行的 `id`，缺失时按 Portal 表单状态提交空字符串。

编辑弹窗不是把当前行对象整体展开提交，而是只从表单状态发出上述七个字段；列表行的 `genName`、`varietyName` 等展示扩展字段不会进入保存请求。品种和代次的下拉值是字典 value，不要把展示名称代替 value。页面处理器还会在路由有 `suiteId` 时把它追加到保存 body；SDK 的 `create` / `update` 接受可选 `suiteId` 以复刻这个请求形状。

Java `ParameterController` 的 `save` 接收 `Parameter`：空 `id` 调用新增，非空 `id` 调用更新；`delete` 对指定 id 做软删除。`ParameterServiceImpl` 在列表结果中用缓存补充 `genName`、`varietyName`。当前实体没有 `suiteId` 字段，不能从后端源码证明该扩展字段会参与数据过滤或持久化。

## 逐字段基准

| 字段 | 含义 |
| --- | --- |
| `list` | 当前分页下的 Parameter 预案品种记录；SDK 兼容后端 page/list/records 形状并保留原始扩展字段。 |
| `total` | 当前分页查询的记录总数；不是当前页长度。 |
| `list[].id` | Parameter 记录 ID；编辑和删除目标。 |
| `list[].name` / `code` | 品种名字 / 编码；新建和编辑必填。 |
| `list[].caption` | 品种说明；新建和编辑必填。 |
| `list[].icon` | 图标地址；可为空。 |
| `list[].variety` / `varietyName` | 品种字典值 / 展示名称；提交使用 value，展示使用 name。 |
| `list[].gen` / `genName` | 代次字典值 / 展示名称；提交使用 value，展示使用 name。 |
| `prepareCreate().draft` | 已通过 Portal 新建校验、尚未发送请求的七字段对象，`id` 固定为空字符串。 |
| `prepareUpdate().draft` | 已按 Portal 编辑表单字段裁剪并校验的七字段对象。 |
| 写操作结果 `true` | 请求未抛错的本地确认，不代表服务端已按预期落库。 |

## 操作步骤、权限和证据边界

1. 使用当前用户会话和租户上下文调用 `list()`；如果当前 Portal 路由有 `suiteId`，把它传给 `list({ suiteId })`。
2. 新建时调用 `prepareCreate()`，经用户确认后把同一份 `draft` 交给 `create()`；如果有路由 `suiteId`，一并传入；取消只丢弃本地草稿。
3. 编辑时把最近一次列表行与用户修改结果交给 `prepareUpdate()`，经用户确认后把同一份 `draft` 交给 `update()`；取消不发请求。
4. 删除前调用 `prepareRemove()`，明确获得用户确认后再调用 `remove()`；取消不发 GET。
5. 新建、编辑或删除成功、失败或响应不确定后，都重新调用 `list()` 回查；不能只依据 `true` 宣布业务状态已改变。

本轮逐页核对了 Portal 菜单、路由、列表、弹窗、公共分页、product 响应解包，以及 Java `ParameterController`、`Parameter`、`ParameterDTO`、`ParameterServiceImpl` 和 `ParameterMapper.xml`。当前没有真实测试环境浏览器会话的列表/新建/编辑/回查/删除闭环证据。
