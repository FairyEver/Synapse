# 方法库指标（生产设置旧版）

## 能力定义

- 页面路径：`/dashboard/product/setting/hatch-manage/method-lib/indicator/list`。
- 到达方式：旧版方法库列表行的“查看方法”；父页面把 `suiteCode` 放入路由 query。
- 页面来源：Portal 直接使用 `hatch-manage/method-lib/indicator/list.vue`，不是 `hatchery-manage` 包装器。
- 父页面权限：`/dashboard/frame/breeding-plan/method-lib`。
- 页面动作权限：查询 `program:method-lib-indicator:query`，新建/编辑 `program:method-lib-indicator:submit`，删除 `program:method-lib-indicator:delete`。
- HTTP 实例：`product`，其 `baseURL` 是 Portal 的 `VITE_FM_API`。当前 Portal `build/env/.env.build.test` 为 `https://fmtest.zhihuidanji.com/flockSimu`；本仓库离线夹具使用显式的 `https://biz-api-test.wodecorp.cn/flockSimu`。调用方必须按目标环境显式提供 base URL；旧版服务端路径是在该 base URL 后追加 `/programNew/...`。本页没有 `module-type` 推导结果，SDK不发送 `module-type`。

## 页面能力与端点

| 页面动作 | SDK 能力 / 方法 | Portal 请求 |
| --- | --- | --- |
| 查询方法名称动态选项 | `product-setting-hatch-method-lib-indicator-trait-code-options` / `productSettingHatchMethodLibIndicator.traitCodeOptions` | `GET /programUnit/getTraitList`，`classification=String(traitType)`、`searchType=2` |

## 参数契约

### 查询和动态选项

列表筛选字段是 `traitType`、`traitCode`、`age`、`suiteCode`，固定发送 `scope=1`，默认 `age=1`、`pageNo=1`、`pageSize=20`；分页只接受 Portal 支持的 `10/20/50/100`。页面复用组件会丢弃 `order` 和 `orderField`，SDK不补发。

`traitType` 使用 Portal `method_class` 字典的实际 value，不把展示文本当成值。traitType 为空时，`traitCodeOptions` 按页面行为本地返回 `[]`；有值时才请求 `/programUnit/getTraitList`，并固定 `searchType=2`，只查询“方法”维度。候选返回保留后端字段并补充 `label=name`、`value=code`、`contentType/title1/title2/title3`。

### 新建

`prepareCreate` 校验并保留：

- `traitType`：方法归类，必填；
- `traitCode`：方法名称编码，必填，通常来自动态选项的 `value`；
- `contentType`、`title1`、`title2`、`title3`：由动态选项回填，可为空；
- `age`：日龄，正整数，页面默认1；
- `txt`：方法内容，去除首尾空白后不能为空，原始长度不超过3000；
- `suiteCode`：父方法库业务编码，页面无可见输入项，缺省保留为空字符串。

首次 `create` 固定发送 `flag=0`。Java 返回 `flag=1` 时只返回 `{ status: 'conflict', flag: 1 }`，不得自动覆盖；用户明确确认后，用同一 draft 调用 `create({ draft, flag: 1 })`。取消只丢弃 draft，不发送第二次请求。

### 编辑、删除和导出

编辑草稿包含当前行 `id`、方法归类、方法名称、内容类型、三级标题、日龄和方法内容。`suiteCode` 若提供，只用于写后回查，SDK不会把它放入 `editTrait` 请求体。旧版 Java 服务的 `editTrait` 可能按 `contentType/scale/min/max` 重算 `txt`；Portal当前表单没有这些数值输入，因此SDK不凭空补值。

删除只使用当前行非空 `id`，HTTP 方法是 GET，不是 DELETE；`suiteCode` 可保留作删除后回查上下文。导出复用筛选条件和 `scope=1`，不发送分页参数；返回 `{ fileName, contentType, base64, byteLength }`，缺少文件名时使用 `方法库方法.xlsx`。

## 返回结构

列表返回 `{ list, total }`：`list` 是当前页，`total` 是筛选结果总数，不是当前页长度。页面实际使用的字段包括：

| 字段 | 含义 |
| --- | --- |
| `id` | 方法指标记录 ID，编辑/删除目标；空值不可安全操作。 |
| `suiteCode` | 所属方法库预案业务编码，用于查询和写后回查。 |
| `traitType` / `traitTypeName` | 方法归类值 / 展示名称。 |
| `traitCode` / `traitName` | 方法名称编码 / 展示名称。 |
| `title1`、`title2`、`title3` | 方法层级标题。 |
| `age` / `ageType` | 旧版 Java 与 Portal 使用的日龄 / 日龄类型；查询和新建由服务端固定 `ageType=1`。 |
| `contentType` / `contentTypeName` | 内容类型值 / 展示名称。 |
| `scale`、`unit`、`min`、`max` | Java返回的精度、单位和数值范围；页面不编辑这些字段，原值保留。 |
| `txt` | 方法内容文本。 |

空 `list` 或 `total=0` 表示没有匹配记录，不代表权限或网络失败。权限错误、网络错误、Java业务错误和响应结构错误均抛出，不降级为空列表。写请求返回 `true` 或 `submitted` 只表示请求未抛错，不等于已落库或业务终态，必须重新 `list` 回查。

## 操作步骤

1. 从父方法库列表行取得 `suiteCode`，用 `traitCodeOptions` 获取候选，再用 `list` 查询指标。
2. 新建调用 `prepareCreate`；用户确认后首次调用 `create`。若返回 `conflict`，询问是否覆盖；只有明确确认时才用同一 draft 和 `flag=1` 二次调用。成功或响应不确定时按 `suiteCode + traitCode + age` 回查。
3. 编辑调用 `prepareUpdate`；确认后调用 `update`，取消不发请求。成功或响应不确定时按 `suiteCode + traitCode + age` 回查内容。
4. 删除调用 `prepareRemove` 并取得确认；确认后调用 `remove`，再按 `suiteCode` 回查并确认目标 `id` 不再出现。
5. 导出直接调用 `export`，将 `base64` 按 `fileName` 保存。

## Portal / Java 源码推导与新版差异

Portal 与 Java 源码共同证明旧版使用：

- Portal `product.js` 的 `VITE_FM_API` baseURL；旧版页面相对路径 `/programNew/methodLib`，Java控制器完整映射为 `flockSimu/programNew/methodLib`；
- `method_class` 字典（同一共享页面在孵化新版路径下切换为 `hatch_method_class`）；
- `program:method-lib-indicator:*` 三个动作权限，父权限是 `/dashboard/frame/breeding-plan/method-lib`；
- `/programUnit/getTraitList` 的 `classification` + `searchType=2`；
- 指标页 JSON 的 `createTrait/editTrait`、`flag=0/1` 冲突协议、GET 删除和二进制导出；
- 旧版 `ProgramNewStandardLibTraitDTO` 返回 `age`、`ageType`、`scale` 等字段。孵化新版使用另一套 `/hatchProgram/methodLib` Java协议，不能把新版的 `hour` 字段或 `/hatchProgram` 路径套到旧版。

源码锚点（本次未执行用户禁止的 Git 拉取）：Portal `acab69acc7`，Java `0f1a55718eb`。源码推导是当前检出上的证据，不替代线上基准。
