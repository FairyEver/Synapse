# 流程实例（`/dashboard/flow/process-instance/manager/list`）

审批管理域「流程治理」四页里的第三页，也是这四页里**唯一有写操作会动到别人单据**的一页。
四件套的其它三件分别在：能力定义与参数契约 → `src/capabilities/flow-manage.ts`；
逐字段基准 → `baseline/flow-management.browser.json`；回归测试 → `test/flow-management.test.ts`。

这一页看的是**全公司**的流程实例（管理员视角），
与各流程表单线的 `*-my-instances`（「我的流程」，`/bpm/process-instance/my-page`）**不是一回事**。

## 逐字段基准

基准文件：`baseline/flow-management.browser.json` 第 11 条（打开页面时自动查询）。

```text
GET https://biz-api-test.wodecorp.cn/admin-api/bpm/process-instance/manager-page
    ?order=&orderField=&name=&title=&pageNo=1&pageSize=20&_t=<ts>
```

请求头（**没有 `module-type`**）：`tenant-id` / `token` / `Accept-Language: zh-CN` /
`Accept: application/json, text/plain, */*`。

**参数顺序是契约的一部分**（`list.js:473-483`）：

```text
order, orderField, startUserId, name, title, processDefinitionId, category, status,
createTime[0], createTime[1], pageNo, pageSize, _t
```

（空值不出现时会"缺位"。）

### 三个性质

**1. 空串照发、`null` 不发 —— 两类的区别在 `form` 的初值上。**
这一页**没有** `convertFetchForm`，`form` 里：

| 字段 | 初值 | 结果 |
| --- | --- | --- |
| `name` / `title` | `''` | **照发**：`name=` `title=` |
| `startUserId` / `processDefinitionId` / `category` / `status` | `null` | 被 qs 的 `skipNulls` 丢掉（无头下由 SDK 的 `client.ts` 复刻同一句 `qs.stringify(..., { allowDots: true, skipNulls: true })`） |

⚠️ 与同文件的 AI审核配置页**正相反**：那一页把空串整个丢掉（连 `order=` 都没有），
这一页空串照发。判据只有一条：**那一页的源码怎么写的**。

**2. 时间区间是「按天归边的闭区间」。** `customLoad` 里调 `formatCreateTimeRange()`：

```js
index === 0 ? dayjs(item).startOf('day').format('YYYY-MM-DD HH:mm:ss')
            : dayjs(item).endOf('day').format('YYYY-MM-DD HH:mm:ss')
```

⇒ 起点 `<开始日> 00:00:00`、终点 `<结束日> 23:59:59`（**即便传进来的时间带时分秒，
也会被归到当日边界** —— 页面就是这么写的）。

⚠️ **不要与学习管理域那几页的「结束日 +1 天」开区间混**（`buildStudyLessonTimeRange`）：
两者都能"含住结束日"，但**相差一天**，写串了会**静默多查或少查一天**。
本页的 helper 是 `buildFlowManageDayRange()`。

**3. 基准里没有带时间区间的请求**（打开页面时区间是空的），所以第 2 条是**从源码读出来的，
基准没有复核到** —— 这一条要记在账上。

## 参数契约

| 参数 | kind | 必填 | 说明 |
| --- | --- | --- | --- |
| `startUserId` | search | 否 | 发起人的**用户 id**（不是姓名）。不传=不过滤。候选用 `base-user-search` |
| `name` | text | 否 | 流程名称，模糊匹配。空串照发 |
| `title` | text | 否 | 审批内容，模糊匹配。空串照发 |
| `processDefinitionId` | text | 否 | 所属流程。⚠️ 页面这里是**文本输入框**（不是下拉），给流程定义 id / key 的字符串 |
| `category` | text | 否 | 流程分类。页面是下拉（候选走 `/bpm/category/simple-list` 的无参全量），编码与字典 `bpm_model_category` 同源 |
| `status` | enum | 否 | 流程状态，字典 `bpm_process_instance_status`。【推断】取值未实测；候选用 **`base-dict-get`**（`dictType=bpm_process_instance_status`） |
| `createTimeStart` / `createTimeEnd` | date | 否 | 必须**成对**给；用 `buildFlowManageDayRange()` 生成（按天归边） |

两条本地校验（都是 `Promise.reject`、**不发请求**）：区间成对；两端格式必须是
`YYYY-MM-DD HH:mm:ss`。

## 页面列与返回结构

列表列：流程名称 / 审批内容 / 流程分类 / 流程发起人 / 发起部门 / 流程状态 / 发起时间 /
结束时间 / 耗时 / 当前审批任务 / 流程编号 / 操作。

- **发起人是嵌套的**：列的 `dataIndex` 是 `['startUser','nickname']` 与 `['startUser','deptName']`，
  不是顶层 `startUserName`。SDK 的 `ProcessInstanceRow` 原样保留这个嵌套。
- **「当前审批任务」是数组**：`record.tasks`，页面用 `a-tag` 逐个渲染 `task.name`
  （`tasks` 为空时 `convertList` 会补成 `[]`）。
- 耗时为 `durationInMillis`（毫秒），页面 `formatPast2()` 处理，`> 0` 才显示，否则「-」。

## 长选项参数（D6 / H35）：页面挂载时那三组全量拉，SDK **一条都不照抄**

基准第 12-21 条就是它们，**十条**：

| 页面发的（基准） | 用途 | SDK |
| --- | --- | --- |
| `GET /system/user/simple-page?pageNo=1..9&pageSize=500`（九条，**最多 4500 人**） | 「发起人」下拉 | **不提供**。`startUserId` 要用户 id，用 `base-user-search`（强制要关键字） |
| `GET /bpm/category/simple-list`（一条，无参全量） | 「流程分类」下拉 | **不提供**。分类码与字典 `bpm_model_category` 同源，用 **`base-dict-get`**（`dictType=bpm_model_category`） |

⚠️ **本地检出与部署版本的漂移（这一处实测到了）**：本地
`process-instance/manager/list.vue:217` 写的是 `/system/user/simple-list`，
而**基准（部署版本）打的是 `/system/user/simple-page`**（分页 9 次 × 500）。
两者都是"全量拉人员"，**结论不变**（不照抄）；但引用接口名时**以基准为准**。

## 操作步骤

```text
1. 进入「流程实例」（/dashboard/flow/process-instance/manager/list）
2. （可选）选发起人（人员选择器——要给用户 id）
3. （可选）填流程名称 / 审批内容 / 所属流程
4. （可选）选流程分类 / 流程状态
5. （可选）选发起时间区间
6. 查询
7. 行上：「详情」（跳流程表单详情页）；`record.status === 1` 时另有「取消」——
   弹窗填取消原因 → DELETE /bpm/process-instance/cancel-by-admin { id, reason }
```

第 7 步的「取消」由 `prepareAdminCancel` → `submitAdminCancel` 完成；只有列表行
`record.status === 1` 才能准备，reason trim 后必须非空。

  区间语义也**没有**在真实环境验证过（基准里没有带区间的请求）。

## 动作覆盖边界

- `DELETE /bpm/process-instance/cancel-by-admin` body `{ id, reason }` 已接入；服务端仍会按实时
  流程状态和权限复核。SDK 当前只有离线请求契约与负向测试，尚未在真实环境撤销业务流程。
- **「详情」的落点**（`goFlowFormDetailByInstanceId` → `/dashboard/flow/form/detail?...`）
  只从 `flow/index.js` 读出，没有实际走一遍。
- **流程分类候选的编码表**没有枚举（与字典 `bpm_model_category` 同源只是推断）。
- **`status` 的取值表**没有枚举（字典控件，未实测）。
- **列表行的字段只在源码里核对过**，**没有拿真实响应体逐字段核过**（基准只抓了请求，没抓响应）。

## SDK AI 说明契约（2026-09-22）

本节由当前 SDK 描述结果整理；说明权威来源为 `src/catalog/contracts-business.ts`。调用 `catalog.describe(id)`（或 `id-llm`）可得到参数来源、返回字段/状态、数据消费与后续映射；`catalog.describePage(页面路径)` 用于选择页面功能。以下更新以本节为准；前文历史请求/实测记录仍保留其记录日期。

### `flow-manage-process-instance-list`

管理员视角查询全公司数据权限范围内流程实例；不是“我发起的”或“我的待办”。

- 执行：`sdk.flowManage.listProcessInstances`；通过 `capabilities.invoke('flow-manage-process-instance-list', args)` 调用时按 `params` 填参。性质：read。
- 参数：`startUserId` 可选 (string)；`name` 可选 (string)；`title` 可选 (string)；`processDefinitionId` 可选 (string)；`category` 可选 (string)；`status` 可选 (string | number)；`createTimeStart` 可选 (string)；`createTimeEnd` 可选 (string)；`pageNo` 可选 (number)；`pageSize` 可选 (number)。完整来源、枚举、条件必填与默认值由 SDK 同次返回。
- 返回：`{ list: object[], total: number }`。list=[] 为当前页无记录；total=0 表示该筛选无结果。保留筛选条件检查页码，不将空结果解释成权限判定。
- 字段：`list`、`total`、`list[].id`、`list[].name`、`list[].title`、`list[].categoryName`、`list[].startUser`、`list[].startUser.nickname`、`list[].startUser.deptName`、`list[].status`、`list[].startTime`、`list[].endTime`、`list[].durationInMillis`、`list[].tasks`、`list[].tasks[].id`、`list[].tasks[].name`。嵌套字段、可空性及业务含义见同次返回的 `returns.fields`。
- 消费：展示 name/title/startUser.nickname/startUser.deptName；tasks[].name 是当前节点，不是新流程名称。耗时以毫秒换算。
- 完成条件：按用户要求交付本次筛选范围的结果；需要完整清单时继续翻页至覆盖 total，不能把当前页当全集。
- 后续：optional → `base-dict-get`：dictType=bpm_process_instance_status；解释流程状态（dictType ← context.dictType）
- 失败/不确定：权限或会话错误要交由用户恢复权限/登录后再读；不要通过换租户、换页面上下文绕过。业务校验失败按原错误修正参数，网络失败的只读查询可重试。
