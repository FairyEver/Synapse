## 1. 参数顺序是**推出来的**，基准只用来复核

`common/libs/renren/list.js:473-483` 把列表参数拼成：

```js
const _form = convertFetchFormTrigger(cloneDeep(formState.value))
const params = { order: orderType.value, orderField: orderField.value, ..._form }
if (getDataListIsPage) { params.pageNo = …; params.pageSize = … }
// → _http.get(getDataListURL, { params }) → platform 拦截器 qs 序列化 + 补 _t
```

⇒ **顺序恒为** `order → orderField → convertFetchForm 的返回值 → pageNo → pageSize → _t`
（URL 自带 query 再排最后；本模块没有页面这么干）。

所以每个能力的参数表就是「那一页 `convertFetchForm` 的返回值原样展开」，前面补
`order`/`orderField`（页面没有这两个控件，钉死成空串），后面补分页。
**本轮 13 条真实 URL 逐字核对，全部吻合**（另有 4 条 POST 单独补跑）—— 这条方法以后可以直接用。

两处例外，别照抄：
- **`order`/`orderField` 有的页面表单里也写了**（学员统计、班课统计）。对象展开时值被覆盖、
  **键的位置留在第一次出现的地方**，所以最终仍是 `order` 打头。实测印证。
- **班课统计会在 `customLoad` 里把空值参数整个丢掉**（见 §3）。

## 2. 五个"同域不同形"，是本模块最容易写错的地方

| # | 坑 | 在哪几页 | 实测量 |
| --- | --- | --- | --- |
| 1 | **空值照发**（空字符串，不是省略） | 绝大多数页 | `keyword=&startTime=` 都真实在 URL 上 |
| 2 | **空值整个丢掉** | **班课统计** | 无筛选时 URL 只剩 `?pageNo=1&pageSize=20&_t=…` |
| 3 | **时间字段名三种** | 讲师统计 `startTime`/`endTime`；班课统计 `startTimeCondition`/`endTimeCondition`；学习管理/学习统计 `startStudyTime`/`endStudyTime`；学员统计**没有**时间 | 逐条见各页文档 |
| 4 | **区间语义两种** | 多数是「结束日 +1 天」的**开区间**；**班级统计是闭区间**（原样取两端） | 班级统计默认「今天~今天」 |
| 5 | **`type` 的位置两种** | 课堂三页把 `type` 放在**表单里**（`convertFetchForm` 透传）；课程域那三页把 `type` 烧在 **URL** 上 | 见 §4 |

## 3. 三处「页面自己会拉全量，本 SDK 不照抄」

页面为了让下拉能本地搜，挂载时会把**整张表**拉下来。无头照抄会把整个表冲进调用方的上下文
（设计 D6 / H35）。本模块遇到三处：

| 位置 | 页面发的 | 本 SDK 的做法 |
| --- | --- | --- |
| 课堂三页 / 学员统计 / 学习管理 | `GET /study/grade/studygrade/page?pageSize=99999` | 交回给 `study-grade-search`，**强制要关键字** |
| 班级统计 | `GET /study/base/studymanagementcenter/getAllCenter?roleId=` | 不提供；要用请自己给 id |
| 讲师管理 | `GET /manage/getAllProfessorPage.lay`（分页正常） | —— |

`study-grade-search` 的做法：**强制要关键字** → 用 `name` 查（后端的模糊匹配）→ **再在本地过滤一次**
（保证"关键字真的出现在结果里"这件事可预期）→ 按 `limit` 截断。返回
`{ list, total, matched }`，`total` 是后端报的总数、`matched` 是过滤后的条数 —— 两者不同名是**有意**的：
调用方需要知道"后端一共多少、我拿到多少"，好判断要不要让用户再收窄。

## 4. 课堂三页：同一个接口，靠**表单里的 `type`** 分片

`/study/lesson/studylesson/lessonList` 一个接口，`type='1'|'2'|'3'` 分晨/周/月。
**与课程域那三页正好相反**（那边 `type` 是 URL 上的 query）。

三页的 `convertFetchForm` **各不相同**：

| 页面 | 字段 |
| --- | --- |
| 晨课堂 | `type, title, gradeNames, status, createTimeStart/End, startTimeStart/End` |
| 周课堂 | `title, gradeNames, type, linkNum, teacherName, publishTimeStart/End, createTimeStart/End, startTimeStart/End, endTimeStart/End` |
| 月课堂 | 与晨课堂同名同序 |

时间格式也有两种：**晨课堂**那一页的格式串写的是字面量 `YYYY-MM-DD 00:00:00`
（没有 `HH:mm:ss` 占位，选出来的一律是零点）；周/月是 `YYYY-MM-DD HH:mm:ss`。
三页**都是结束日 +1 天**。

## 5. ⚠️ 两条如实记的账

### 5.1 讲师管理 / 讲师类型：曾经"做不了"，是因为 SDK 没复刻那一族包络（**已解决**）

这两页的**列表**走 `smart-layer-admin` 实例（host `smarterlayeradmintest.zhihuidanji.com/admin`）。
SDK 早先只实现了 `portal-standard` 一种响应包络，其余统称 `not-replicated` 并**明确抛错**。

用户 2026-09-21 的要求是：**按各实例自己的规则复刻**，判据以页面上真实发生的行为为准。
于是 `src/http/client.ts` 加了 `applyEnvelope()`，四条规则逐字复刻各实例响应拦截器的原文：

| 档 | 实例 | 判据 | 出处 |
| --- | --- | --- | --- |
| `portal-standard` | platform 那一族（14 个） | `ret !== 'SUCCESS'` 即失败 | `platform.js` |
| `smart-layer` | `smart-layer-admin` / `smart-layer-app` | **不看 `ret`**；`code === undefined` 放行、`code !== 200` 失败；没 `data` 时退到 `pages` | `smart-layer-admin.js:49-81` |
| `zhdj-sms` | `zhdj-sms` | `ret !== SUCCESS` **且** `code !== 200` 才失败；后两条同 `smart-layer` | `zhdj-sms.js:34-70` |
| `mall-app` | `mall-app` | `Number(code) !== 0` 即失败 | `mall-app.js:15-24` |

三处最容易照抄错的，都在 `applyEnvelope()` 的注释里标了（也各有用例）：
`smart-layer` **完全不看 `ret`**；`zhdj-sms` 在 `ret` 失败但 `code === 200` 时**不抛**；
`smart-layer`/`zhdj-sms` 的最后一句是 `return data ? data : pages`（**`pages` 是第二选择**）。

**反证**（`test/http-envelope.test.ts` 26 例）：改坏 `smart-layer` 的判据 → 红 7；
去掉 `pages` 兜底 → 红 3；`mall-app` 判据换成 `code !== 200` → 红 4。
另有一处**等价变异**：把 `zhdj-sms` 的两段对调，穷举 7 种 `ret`/`code` 组合行为完全一致
—— 所以"两段谁先谁后"不是契约，**"`code === 200` 时不抛"才是**。那句"顺序不能换"的注释已改掉。

### 5.1b 这两页**不是"页面级一个实例"**

列表走 smart-layer-admin，而删除（`DELETE /study/base/studyteacher`）走 **platform**。
`src/context/http-instance.ts` 的 `isPageShapedPath` 注释写着这条道理：
"同一次页面操作里可能有多个实例，所以实例必须能逐请求指定，不能只当页面属性"。

本轮试过往 `HTTP_INSTANCE_PAGE_RULES` 加页面级规则，被 `test/http-instances.test.ts`
的相等性断言拦下 —— **它是对的**。现在用请求级 `httpInstance`。

### 5.2 页面挂载时拉的**全量候选**没照抄

见 §3。另外课堂三页/学习管理页的请求 URL 里都能看到那条 `pageSize=99999`，
基准文件里保留着它 —— 那是**页面**发的，不是本 SDK 发的。

## 6. 写操作：本模块**一个都没做**

20 项里带写的不在少数（删学员 / 删班级 / 班级启用停用 / 班课发布·删除 / 学员导入…）。
本轮**只做读**，理由与课程域那几页同一个：

- 删除**不可逆**（学员、班级、班课都是真实业务数据）；
- 班课的「发布」会改变他人可见状态；班级的「启用/停用」影响范围更大；
- 这些属于「要不要在测试环境里造/改真实业务数据」的判断，不是"多写一个接口"的成本。

**已经查清、随时可以做的两条**（将来做的时候省一轮侦察）：

- **班级管理的启用/停用是两步写**：先 `PUT /study/grade/studygrade/updateStatus`，
  成功后再 `PUT /study/grade/studygrade`（body 都只有 `{ id, status }`）——
  形状正好是 `prepare → submit`。**删班级**是 `DELETE /study/grade/studygrade`（批量）。
- **学员管理的删除带前置检查**：`customDelete` 先
  `GET /study/base/studystudent/isStudentInGrade?studentIds=…`，命中就提示
  「XXX已在「YYY」中」而不发删除。那一步已经做成只读能力 `study-student-check-in-grade`。

## 8. 本轮顺带修掉的三个真问题

1. **基准钩子只脱敏请求头、不脱敏 URL**，而 `smart-layer-*` 把 token 塞在 GET 参数里 ——
   抓讲师管理那页时实测 **25 处完整 JWT 落进了捕获缓存**（已当场洗掉；仓库里没有留）。
   `tools/baseline/install-hook.js` 现在会脱敏 URL 上带 `token`/`ticket`/`sign`/`secret`/`access_key` 的参数。
   抓完**扫一眼**仍然是好习惯：`grep -c 'eyJ' 你的捕获文件` 应当是 0。
2. **别名推导器的正则要求 `id`/`title`/`pagePath` 三行紧挨着** —— 在 `title` 与 `pagePath`
   之间写一行注释，那条能力就会被**静默漏掉**（推导器说 178、SDK 实际 179）。
   已放宽为允许夹注释行。症状只有 `capabilityCount === CAPABILITIES.length` 那条断言会红。
3. **页面级实例规则加不得**（见 §5.1b）。
4. **`tokenInParams` 实例的 `token` / `_t` 顺序写反了**：各实例的请求拦截器逐字写着
   `config.params = { ...config.params, ...{ token }, ...{ '_t': … } }` —— **token 在前**。
   SDK 原来先加 `_t` 再加 `token`。这一族是 axios 默认序列化，**对象键序就是 URL 上的顺序**，
   所以这与浏览器不逐字一致（由讲师管理那条基准抓到，`client.ts` 已修正）。
