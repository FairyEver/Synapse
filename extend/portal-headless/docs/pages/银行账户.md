## 能力定义

| 能力 ID | 公开方法 | effect | 请求 | 用途 |
| --- | --- | --- | --- | --- |
| `finance-setting-receiving-account-list` | `financeSettingReceivingAccount.list(query?)` | `read` | `GET /admin-api/finance/receiving-account-number/page` | 按页面筛选分页读取银行账户 |
| `finance-setting-receiving-account-corporation-options` | `financeSettingReceivingAccount.corporationOptions()` | `read` | Portal 源码 `GET /org/corporation/getAllLegalPerson`（platform 实例补 `/admin-api`） | 把列表行 `corporationId` 映射为法人名称 |
| `finance-setting-receiving-account-prepare-create` | `financeSettingReceivingAccount.prepareCreate(input)` | `prepare` | 无网络请求 | 按新建表单规则生成完整保存草稿 |
| `finance-setting-receiving-account-create` | `financeSettingReceivingAccount.create(input)` | `write` | `POST /admin-api/finance/receiving-account-number/create` | 新建银行账户，返回主键 |
| `finance-setting-receiving-account-prepare-set-status` | `financeSettingReceivingAccount.prepareSetStatus(input)` | `prepare` | 无网络请求 | 生成绝对启停状态和previous快照 |
| `finance-setting-receiving-account-set-status` | `financeSettingReceivingAccount.setStatus(input)` | `write` | `GET /admin-api/finance/receiving-account-number/enableOrStop?id=&status=` | 启用或停用银行账户，成功回执为 `null` |

所有能力都绑定页面路径、页面权限、`httpInstance: platform`、`moduleType: null`。创建需要 `finance:setting:receiving-account:create`，启停需要 `finance:setting:receiving-account:status`；按钮权限由服务端最终裁决。

## 参数契约

### `list(query?)`

Portal 表单初值和 `common/libs/renren/list.js` 的组装顺序决定了列表默认请求参数：

    order=&orderField=&organizationId=&corporationId=&bank=&bankAccount=&accountType=&tenantName=&status=0&pageNo=1&pageSize=20

| 参数 | 类型 | 默认/空值 | 语义与约束 |
| --- | --- | --- | --- |
| `organizationId` | `string \| number` | `''` | 所属组织 ID；省略、不传或 `null` 表示不筛选 |
| `corporationId` | `string \| number` | `''` | 所属法人库 ID；不是组织 ID；省略、不传或 `null` 表示不筛选 |
| `bank` | `integer` | `''` | `belong_bank` 字典值；不传表示不筛选 |
| `bankAccount` | `string` | `''` | 银行账号文本；Java Mapper 对该值做前缀匹配 |
| `accountType` | `integer` | `''` | `receiving_account_type` 字典值；不传表示不筛选 |
| `tenantName` | `string` | `''` | 企业名称前缀筛选；Portal 输入框只向 `admin` 用户展示 |
| `status` | `0 \| 1` | `0` | 绝对状态：`0` 启用，`1` 停用；不是 toggle |
| `pageNo` | `integer` | `1` | 从 1 开始 |
| `pageSize` | `integer` | `20` | 只接受 Portal styleV2 的 `10/20/50/100`，不接受 `-1` 全量 |

SDK 只接受当前页面真正发送的筛选字段；后端 VO 中的 `businessType`、`orgIds`、`includeCurrentOrgAndParents`、`createTime` 等没有被本页表单发送，不作为本能力输入。

### `corporationOptions()`

无业务参数。Portal 对响应兼容数组和 `{ data: [] }` 两种形状；SDK 返回统一的法人候选数组。法人 ID 必须是安全正整数或其十进制字符串，名称必须是字符串。

### `prepareCreate(input)` / `create(input)`

新建表单实际 POST 字段如下；`create` 发送 `prepareCreate` 返回的 `draft`，不发送 Java VO 中本页没有使用的 `businessType`、`id` 等字段。

| 字段 | 类型 | 规则和默认值 |
| --- | --- | --- |
| `organizationId` | `string \| number` | 必填，组织树主键 |
| `corporationId` | `string \| number` | 必填，法人库主键 |
| `bank` | `integer` | 必填，`belong_bank` 字典值 |
| `bankBranch` | `string` | 必填，最多200个字符 |
| `accountType` | `integer` | 必填，`receiving_account_type` 字典值；表单默认1 |
| `bankAccount` | `string` | 必填，保留前导零 |
| `accountBusiness` | `integer[]` | 必填且非空，表单默认 `[1]` |
| `accountMinimum` | `number \| string \| null` | 可空，最小0、最多两位小数；省略时按页面初始值发送 `''` |
| `isUsed` | `0 \| 1` | 页面默认1；当填写限额时仍必须是0或1 |

`create` 返回新记录ID。Portal 没有创建后的删除或可逆撤销接口；成功或超时都要用 `list` 回查同一ID和保存字段，清理只能转交受控运维。

### `prepareSetStatus(input)` / `setStatus(input)`

`prepareSetStatus` 接收最新列表行和绝对 `targetStatus`，要求目标状态与当前 `status` 相反，返回：

    { draft: { id, status: targetStatus }, previous: { id, status: currentStatus } }

`setStatus` 只发送 `GET` 查询参数 `{ id, status }`，不是 PUT body；Portal 成功回执为 `null`。回执或超时后必须用 `list` 回查同一ID；若用户明确要求恢复，可在确认当前仍为目标状态后提交 `previous` 作为补偿写，这不是事务回滚。

## 逐字段基准

### 银行账户分页结果

SDK 最终返回 `{ list, total }`，不是 Portal 原始包络。

| 路径 | 类型 | 页面消费 |
| --- | --- | --- |
| `list` | `array` | 当前页，不代表全量 |
| `list[].id` | `string \| number` | 行主键；用于启停草稿和回查 |
| `list[].organizationId` | `string \| number \| null` | 所属组织 ID |
| `list[].corporationId` | `string \| number \| null` | 法人库 ID，与法人候选 `id` 关联 |
| `list[].tenantName` | `string \| null` | 所属企业原文 |
| `list[].orgName` | `string \| null` | 所属组织原文 |
| `list[].bank` | `integer \| null` | `belong_bank` 字典值 |
| `list[].bankBranch` | `string \| null` | 开户行 |
| `list[].bankAccount` | `string \| null` | 收款账号；保持字符串，不能转数字 |
| `list[].accountType` | `integer \| null` | `receiving_account_type` 字典值 |
| `list[].accountBusiness` | `string` | 逗号分隔的 `account_business` 字典值；Portal 直接 `.split(',')` |
| `list[].accountMinimum` | `number \| string \| null` | 账号最小限额原值；不把 `null` 当 0 |
| `list[].isUsed` | `integer \| null` | `yes_no` 字典值 |
| `list[].status` | `integer` | `0` 启用，`1` 停用 |
| `list[].createTime` | `string \| number \| null` | Portal `formatDate` 使用的原值，不由 SDK 换算时区 |
| `total` | `integer` | 当前筛选条件总数，不是当前页长度 |

`businessType` 虽在 Java 响应/查询模型中存在，但该列表模板没有消费它；SDK 不将它扩展进页面返回契约。响应扩展字段同样不作为可展示或可操作数据。

### 法人候选结果

SDK 返回 `Array<{ id: string | number; name: string }>`：

| 路径 | 类型 | 语义 |
| --- | --- | --- |
| `[]` | `object` | 一个当前会话可见法人 |
| `[].id` | `string \| number` | 法人库主键，与 `list[].corporationId` 同命名空间 |
| `[].name` | `string` | 法人名称，用于页面显示 |

匹配不到法人时不按名称相似度、组织名称或租户名称补造映射。

## 操作步骤与失败处理

1. 如需查询账户，调用 `financeSettingReceivingAccount.list(query?)`；保留 `total`，需要全量时固定筛选逐页读取，直到累计达到 `total` 或返回空页。
2. 如需显示法人名称，调用 `financeSettingReceivingAccount.corporationOptions()`，以 `list[].corporationId === [].id` 精确关联；不要把 `organizationId` 当法人 ID。
3. 新建时先调用 `prepareCreate`，核对草稿中的组织、法人、字典值和账号字符串，再把 `draft` 交给 `create`。
4. 启停时从最新列表行调用 `prepareSetStatus`，提交绝对状态；保存 `previous` 以便必要时补偿。
5. 通过字典原值解释 `bank`、`accountType`、`accountBusiness`、`isUsed`；SDK 不猜运行时字典标签。
6. 写请求返回后或超时后都要回查；创建没有页面可逆撤销，启停恢复是补偿写。

参数错误、分页响应缺失 `list/total`、行 ID 非法、`accountBusiness` 不是字符串、法人候选缺少 `id/name`、新建字段不满足表单规则或启停回执不是 `null` 时 SDK 抛错，不改写成空结果。401/403、网络错误和后端错误也不等价于“没有账户”；恢复会话或权限后再读或回查。

- 离线实测：request stub 锁定默认/筛选请求键序、分页范围、页面字段投影、`accountBusiness` 字符串保护、法人数组/`data` 数组响应、创建 POST、启停 GET、tenant/token 和不发 `module-type`。
- 反证：坏分页、非法 ID/状态/页码、错误 `accountBusiness`、坏法人候选、表单必填/限额规则、非null启停回执和删除 AI 输出字段的测试会失败；已恢复到通过状态。
- 推断：platform 对 `/org/corporation/getAllLegalPerson` 补 `/admin-api`、Portal 空值序列化和 Java 字段类型来自源码/请求层实现，未用浏览器抓包复核。

- 写能力：已按Portal源码实现离线的 `prepareCreate → create` 和 `prepareSetStatus → setStatus`；未调用真实写接口。创建没有可逆cancel，启停previous仅作为同接口补偿载荷，均需回查确认。
