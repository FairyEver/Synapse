## Portal 页面行为

筛选表单只有三个字段：

| 控件 | 参数 | Portal 规则 |
| --- | --- | --- |
| 姓名 | `name` | 初始值 `null`，输入值原样发送 |
| 组织筛选 | `organizationIdList` | 角色组织树多选，未选择时发送 `[]` |
| 年份 | `year` | `value-format="YYYY"`，默认当前年份，不能选择未来年份 |

列表使用 `customLoad` 调用 `POST /org/holiday/getYearRest`。`useListPageModule` 在 `getDataListIsPage: true` 下自动把排序和分页字段合并进请求体，实际 body 顺序和字段为：

```text
order, orderField, name, organizationIdList, year, pageNo, pageSize
```

Portal 当前列表列把“工号”也绑定到 `name`，因此网页上会重复显示姓名；后端实际返回的 `staffCode` 仍由 SDK 保留，不能为了修正网页显示而改写源数据。

剩余天数不是后端独立字段，页面直接计算：

```text
remainingAnnualLeaveDays = shouldYearRestDays - actualYearRestDays
```

点击“查看已休日期”只把当前行和所选年份传给本地弹窗，不发第二个请求。弹窗消费 `absentListByYearRest[]`；`amPm === 1` 显示“上午”，其它非空值显示“下午”。

导出使用 `POST /org/holiday/exportYearRest`，请求 data 是当前表单的三个字段：

```json
{ "name": null, "organizationIdList": [], "year": "2026" }
```

导出不带 `order`、`orderField`、`pageNo` 或 `pageSize`。Portal 固定下载名为 `年假管理表.xlsx`。

## 后端与权限核对

Java `HrHolidayController` 在 `orgPath/holiday` 下提供 `getYearRest` 和 `exportYearRest` 两个 POST 端点。服务层根据年份计算应休天数、按半天记录数除以 2 计算已休天数，并返回 `absentListByYearRest`、起止日期和员工组织/岗位信息；导出把分页大小设为 `-1` 后复用同一计算逻辑。

列表查询还受当前用户的数据范围、有效员工条件和 `organizationIdList` 过滤约束。SDK 不绕过这些约束，也不把“能导出文件”解释成有业务写权限。

组织树候选复用 `contractSupport.roleOrganizationSearch({ scope: 'attendance', keyword })`。Portal 组件会拉整棵角色组织树；无头调用必须先要关键字，再在 SDK 本地限量过滤，提交时只把用户确认的 `list[].id` 组成 `organizationIdList`，避免把超大候选集直接交给调用方。

### `attendance-annual-leave-list`

按 Portal 年份、姓名和角色组织筛选读取年假管理分页列表。

执行：`sdk.attendanceAnnualLeave.list`；性质：read。操作 Portal「组织管理 → 考勤管理 → 年假管理」页面的查询或导出入口。

- 边界：页面权限是/dashboard/attendance/attendance-annual-leave；请求使用 platform HTTP 实例和页面 module-type=11，调用方不要另拼权限头或把组织管理范围改成其它页面范围。
- 边界：列表接口虽然是 POST，但页面没有新建、编辑、删除或审批动作；导出 POST 也只是读取文件，不能按 HTTP 方法把它报告成业务写入。
- 边界：organizationIdList 必须来自 contractSupport.roleOrganizationSearch({ scope: "attendance", keyword }) 的候选 ID；候选搜索必须有关键字，不能无头照搬 Portal 全量组织树。
- 边界：Portal 的“工号”列当前错误使用 name；SDK 同时保留后端 staffCode 和页面实际重复姓名的事实，不擅自修正页面显示语义。

| 参数 | 意义与来源 |
| --- | --- |
| name | 姓名模糊筛选；页面初始值为 null，传入字符串时保留用户输入，不自动把空字符串改成其它条件。；来源：用户明确提供的姓名筛选 |
| organizationIdList | 角色组织树选中的组织 ID 数组；未筛选时发送 []，不是单个组织 ID。；来源：contractSupport.roleOrganizationSearch({ scope: "attendance", keyword }) 的 list[].id；用户确认选择后组成数组；候选：contract-support-role-organization-search list[].id |
| year | 年份选择器值，YYYY 字符串；页面默认当前年份且禁止未来年份。；来源：用户明确选择的年份 |
| pageNo | 从 1 开始的分页页码；Portal 默认 1。；来源：调用方分页状态 |
| pageSize | 每页条数；Portal 分页器支持 10、20、50、100，默认 20。；来源：调用方分页状态 |

返回：`{ list: object[], total: number }`。list=[] 表示当前页没有记录；total=0 才表示当前筛选没有记录。权限、会话、网络或响应形状错误会抛出，不降级为空页。


- 消费：用 total 判断是否需要继续翻页；list[].shouldYearRestDays、actualYearRestDays 和 remainingAnnualLeaveDays 的单位都是天。
- 消费：查看已休日期时直接消费 list[].absentListByYearRest；amPm===1 是上午，其它非空值按 Portal 规则显示下午。
- 消费：需要文件时将同一组 name、organizationIdList、year 映射给 attendance-annual-leave-export；不要把 pageNo、pageSize 或 order/orderField 传给导出。
- optional：用户要求下载当前筛选的年假表 → `attendance-annual-leave-export`。沿用当前筛选条件调用导出；导出请求不带列表分页参数，返回文件后保存 base64 内容。 映射：{"name":"args.name","organizationIdList":"args.organizationIdList","year":"args.year"}

完成条件：返回当前筛选的一页和 total；读取成功不等于拥有任何写权限。

- 失败处理：权限、租户、网络或响应形状错误原样抛出；非法年份、组织 ID、分页、空文件和缺少 list/total 不降级为空结果。
