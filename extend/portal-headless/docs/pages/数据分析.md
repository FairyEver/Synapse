## 权限码：当前四页均使用生效的 v2

| 页面 | 目录里的权限码 | 目录的 `menuSource` |

`<route lang="yaml">` 块使用同一条 **v2** 权限；`mall.js` 只作为历史对照。

两代对可见性判定**等价**（`src/catalog/visibility.ts:116` 的 `normalizeVisibilityKey()`

## 逐字段基准（**判据**）

六条，每条**只有 `_t`**（基准原文）：

```
GET /admin-api/manage/ai/getStatsAnsRightRate?_t=<ts>      交互成功率
GET /admin-api/manage/ai/getStatsByTime?_t=<ts>            各时段提问次数（折线）
GET /admin-api/manage/ai/getKnowledgeRecordRank?_t=<ts>    知识库文档调用次数排行
GET /admin-api/manage/ai/getAiToolRecordRank?_t=<ts>       AI 工具调用次数排行
GET /admin-api/manage/ai/getAiToolClickRank?_t=<ts>        AI 工具点击次数排行
GET /admin-api/manage/ai/getQuestionKeywordHeat?_t=<ts>    提问关键词热词
```

能力发出的六条与基准**逐字相同**（J 组逐条断言）。基准证实了两件事：

1. **不给区间时 `startTime`/`endTime` 真的不发**。页面的 `getDateRangeParams()` 是
   `range[0]?.format?.('YYYY-MM-DD') ?? null` —— 日期选择器没选时 `dateRange` 是 `[]`，
   落到 `null`，被 `qs` 的 `skipNulls` 丢掉。（**初值是 `null` 而不是空串**，
   所以"空值照发"那一档不适用。）
2. 六条**路径都不带 `/admin-api`**（页面就是这么写的），由 `platform.js` 的拦截器补。
   后端 `AiInfoManageController` 的 `@RequestMapping("/manage/ai")` 印证了这一点。

## 参数契约：只有一对可选日期

| 参数 | kind | 说明 |
| --- | --- | --- |
| `startTime` | date | `YYYY-MM-DD`（页面 `format('YYYY-MM-DD')`，**不补时分秒**）；不给就不发 |
| `endTime` | date | 同上 |

注意这一页**不做**别的页面那种 `00:00:00` / `23:59:59` 补全
（那是 `common/model-usage/utils.js` 的 `normalizeStartTime/normalizeEndTime`，
属于用量明细那条链路）。后端签名是 `(String startTime, String endTime)`，两个都可选。

## 「六张图」与页面元素的对应

| 返回字段 | 页面元素 | 图形 | 页面怎么用 |
| --- | --- | --- | --- |
| `answerRightRate` | 交互成功率 | 饼 | 页面自己算 `(rightRate*100).toFixed(2)`，并显示 `right`/`wrong` 条数 |
| `statsByTime` | 各时段提问次数统计图 | 折线 | 取 `data.x` / `data.y` |
| `knowledgeRecordRank` | 知识库文档调用次数排行 | 列表 | **直接当数组渲染** `{name, callCount}` |
| `aiToolRecordRank` | AI 工具调用次数排行 | 柱 | 取 `data.x` / `data.y` |
| `aiToolClickRank` | AI 工具点击次数排行 | 柱 | 取 `data.x` / `data.y` |
| `questionKeywordHeat` | 提问关键词热度排行 | 词云 | `[{keyword, heat}]` → `{name, value}` |

本能力**不做页面那层计算**（`×100`、`toFixed(2)`、`{keyword,heat}→{name,value}`）——
那些是把数据喂给 echarts 的需要，不是接口契约。

## 降级语义：**有意的偏差**（页面不是 `allSettled`）

| 时机 | 页面实际做的 | 本能力做的 |
| --- | --- | --- |
| **挂载** | 五个 `getXxx()` **各自 fire-and-forget 并发**跑（`list.vue:161/179/194/210/227`），第六个（关键词热词）在 `word-cloud.vue` 自己发起 —— 六个互不等待，**谁也不 catch**，失败的只会变成一条未处理的 rejection | 六条并发 + **各自 settle**，返回 `errors` 记账 |
| **点「搜索」** | `handleSearch()` **顺序 await** 五个、**没有 try/catch**（`list.vue:124-137`）—— 前面一挂**后面就不再发** | 同上（一次并发取回） |

本能力统一到"并发 + 各自 settle + `errors`"这一档（与
`study-statistics.learningSummary` 同一套约定）：**一次统计查询挂掉不应该让调用方
静默地少拿五张图**。这是**刻意的偏差**，理由写在这里，不是照抄错了。

⚠️ 基准**看不出**并发还是顺序（只有 6 条请求的先后记录，没有时间戳可用）——
所以这一条**没有判据**，K 组留了 `it.todo`。

## 未做 / 未验证

**没做的**：

- 页面上的**导出 / 下钻跳转**都没有（这一页除了「搜索」「重置」和一个日期区间，
  没有别的写入口 —— **全页只读，没有写链路、没有真机验证清单**）。
- 词云那个组件的 `maskImage`（一张内联 base64 PNG）是**纯渲染**的东西，不做。

**没验证的**：

- 六条的**响应体形状**（`{x,y}` / `[{name,callCount}]` / `[{keyword,heat}]`）是
  **读页面代码**得到的，没看真实响应。能力**不做字段裁剪**，原样透传。
- 后端 `AiInfoManageController.getStatsAnsRightRate(String startTime, String endTime)`
  两个参数**没有 `@RequestParam` 注解**（靠 Spring 按名字绑定）—— 实测基准证明"不发也能调通"，
  但**区间格式**（后端怎么解析 `YYYY-MM-DD`）没有实测。

## 测到 vs 没测到

**测到**：六条 GET 与基准**逐字段一致**（含"只有 `_t`"）；不给区间时两个参数真的不发
（基准证实）；能力定义与目录逐字对齐；
一路失败不拖垮其余 + `errors` 记账（有反证）。

**没测到**：六条的响应体形状；后端对日期区间的解析；并发 vs 顺序（基准没有时间戳）。

## SDK实际返回的AI说明（2026-09-22复核）

以下内容由 `src/catalog/contracts-ai-model.ts` 同一权威契约渲染；SDK通过 `catalog.describe(id).ai`、`catalog.describePage(pagePath)` 和 `catalog.describeMethod(sdkPath)` 实际提供。无需调用方读仓库。字段来源是固定前后端源码辅助证据；历史浏览器23条GET只验证请求，不充当响应或写闭环证据。本轮没有重放线上写操作。

### `data-analysis-overview`

取得智能交互成功率、时段提问、知识文档调用、工具调用/点击及提问热词六组分析。

使用：分析智能交互质量与热点；Token配额/计费分析使用platform-usage。 行为：read。入口：`invoke('data-analysis-overview', args)`。

- 并发各自settle，失败项null且errors有原因；不同于页面顺序await搜索。
- rightRate/wrongRate是0–1比例，展示百分比需乘100；不要套用平台用量已为百分比的usageRate。

参数：

| 参数 | 类型/格式/条件 | 含义与来源 |
| --- | --- | --- |
| `startTime` | string；可选 | 回复时间起 `YYYY-MM-DD`；不给就不发（页面初值 null）；来源：用户明确的业务条件；枚举按本参数options填写 |
| `endTime` | string；可选 | 回复时间止 `YYYY-MM-DD`；不给就不发；来源：用户明确的业务条件；枚举按本参数options填写 |

SDK返回：`{ answerRightRate, statsByTime, knowledgeRecordRank, aiToolRecordRank, aiToolClickRank, questionKeywordHeat, errors }`。成功数组为空是无数据；null为失败，结合errors而非替换成0。

失败/防重：401或403先核对会话/租户及实际动作权限；菜单可见性不是权限裁决。 参数和形状错误保留原始消息；空页与请求失败不能混同。
