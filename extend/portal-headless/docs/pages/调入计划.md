## 组织权限与请求规则

Portal 页面使用：

```text
GET /org/organization/getRoleOrganizationTree
GET /hr/recruitment-plan/page
```

请求使用 `platform` 实例，页面上下文是权限 `/dashboard/org/transfer-in-plan` 和 `module-type=11`。通用组织树接口由 Java Controller 将 `moduleType` 写入当前登录会话，再由服务层按当前用户、租户和角色组织数据范围构造树；SDK 不改用生产专用的 `getRoleOrganizationTreeProductionModule`。

列表页概览请求严格复现 Portal：

```text
pageNo=1&pageSize=1000&status=2&planYear=当前年份YYYY
```

它不发送 `organizationId`。详情页严格发送：

```text
pageNo=1&pageSize=1000&status=2&organizationId=组织ID或null&planYear=YYYY或null
```

其中 `status=2` 是招聘计划“已审批”，不是通用布尔值。`organizationId` 和计划行 `id` 都保留字符串形式的长 ID，不能用名称、数组下标或 `postId` 替代。

列表页的“整体情况”和组织行人数不是分页 `total`：Portal 会递归收集当前节点及其下级组织 ID，再按 `organizationId` 匹配计划行并将 `planNumber` 求和；展示排序先放人数大于0的行，再按人数降序。SDK 返回原始树和分页行，调用方必须按这条规则消费，空 `planNumber` 展示时按0处理但不能篡改原始返回。

## 详情字段与岗位任职要求

详情表原样使用：

- `organizationFullPath || organizationName` 与 `postName` 组成组织全路径-岗位；
- `planNumber` 为调入人数；
- `salaryRangeName` 为后端展示文本，不把薪资等级 ID 当作金额；
- `urgency` 为紧急程度；
- `arrivalDate` 为到岗时间原始值。

岗位弹窗在有 `postId` 时调用 `GET /org/hrpost/{postId}`。SDK 保留 Java `HrPostDTO` 的原始字段：`gender`、`educationalRequirement`、`experienceRequirement`、`abilityRequirement` 等，不新增或静默重命名字段。当前 Portal 模板读取的是 `genderRequirement`、`educationRequirement` 和 `postRequirement`，其中 `educationRequirement` 与后端 `educationalRequirement` 不同；岗位接口失败或返回空时，Portal 会继续使用计划行的 `postTypeName`、`postName`、`requirementText` 兜底。调用方不能把字段名差异误报为已经存在的后端字段。

## 路由动作

列表整体情况、组织叶子行和组织行进入详情时，Portal 路由为：

```text
/dashboard/org/transfer-in-plan/detail/{组织ID}
```

没有组织节点时使用真实的占位路由 `/dashboard/org/transfer-in-plan/detail/0`，不表示组织 ID 为0。

详情页的“简历库”和“上传简历”都调用同一个路由：

```text
/dashboard/staff/recruitment-plan/resume/{招聘计划ID}
```

缺少招聘计划 `id` 时 Portal 直接不跳转，SDK 对应返回 `null`。进入简历库后的简历查询、上传、面试和写操作属于招聘计划简历库页面，不由本节点冒充提供。
