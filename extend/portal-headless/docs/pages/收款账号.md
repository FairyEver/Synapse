# 收款账号

## 1. 能力定义

- Portal 菜单：系统设置 → 销售设置 → 收款账号。
- 页面路径：`/dashboard/sale/order/payment-account/list`。
- 页面权限：`/dashboard/sale/frame/order/payment-account`。
- module-type：`60`。
- 请求实例：列表、详情、组织树、银行级联使用 `platform`（`VITE_ZHDJ_PLATFORM_API`）；品类树使用 `platform-mall-admin`（`VITE_MALL_ADMIN_API`）。
- 按钮权限：新建 `sale:order:payment-account:create`，编辑 `sale:order:payment-account:edit`，删除 `sale:order:payment-account:delete`。
- 当前页面实际能力：列表、组织树、品类树、开户行候选、银行候选、收款账号候选、详情、准备新建/编辑/删除、新建、编辑、删除。页面没有导出入口，不暴露后端的 `export-excel`。

## 2. 参数契约

### 列表

Portal 公共列表始终发送以下参数：

```json
{ "order": "", "orderField": "", "pageNo": 1, "pageSize": 20 }
```

`pageSize` 只接受 Portal 全局分页选项 `10/20/50/100`；响应为 `{ list, total }`。列表展示 `officeName`、`itemName`、`merchantCode`、`receiptAccountNo`、`updateTime`、`updaterName`。

### 组织、品类和银行级联

- 组织树请求 `GET /admin-api/sales/organization/tree?salesTypeMax=1`。节点的 `id` 是 `officeId`，`name` 仅展示；`salesType` 为 `0` 或 `1` 时可选，否则 `disabled=true`。
- 品类树请求 `GET /sys/categoryCat/getTree`，页面只把顶层节点的 `catId/catName` 映射为选项，提交值是 `catId`，不是名称；`lv2/lv3` 原始结构保留在返回中。
- 组织选定后请求 `GET /admin-api/sales/manual-order/get-bank-branch-list`，参数 `{ organizationId }`。
- 组织和开户行都存在时请求 `GET /admin-api/sales/manual-order/get-bank-list`，参数 `{ organizationId, bankBranch }`；返回 `bank` 作为下一级编码，`bankName` 作为展示文本。
- 组织、银行编码和开户行都存在时请求 `GET /admin-api/sales/manual-order/get-bank-account-list`，参数 `{ organizationId, bank, bankBranch }`。
- 任一级联前置值缺失时，SDK 与 Portal 一样返回空数组且不发请求。组织变化清空开户行、账户名和账号；开户行变化清空账户名和账号；账户名变化清空账号。

### 表单和权限

页面 required 字段是 `officeId`、`itemKindCode`、`receiptAccountName`、`bankName`、`receiptAccountNo`；`itemKindCode` 至少选择一项。`merchantCode`、`instCode`、`branchName`、`branchInstCode`、`publicKey` 可为空。Portal 没有长度、格式或数值范围校验，SDK 不新增限制。

详情页在 `/dashboard/sale/order/payment-account/[mode]/[id]`，详情响应的 `itemKind` 按逗号切成 `itemKindCode`；`office`、`createDate`、`updateDate` 是页面状态或回显字段，不提交。

提交转换严格复刻 `customSubmit`：

- `itemKindCode` 每项转字符串后用逗号 join 为 `itemKind`。
- 新建 POST `/admin-api/sales/ccb-account/create` 删除 `id`，返回新记录 ID。
- 编辑 PUT `/admin-api/sales/ccb-account/update` 必须带当前 `id`。
- 删除 DELETE `/admin-api/sales/ccb-account/delete` 使用当前记录 `id` 查询参数。
- 编辑和删除只接受后端布尔回执 `true`；SDK 校验通过后返回 `undefined`，不是把错误回执当成功。

## 3. 逐字段基准

列表/详情字段来自 `SalesCcbAccountRespVO`：

| 字段 | 页面含义 | 提交规则 |
| --- | --- | --- |
| `id` | 收款账号记录主键 | 编辑、删除必须使用当前值 |
| `officeId` / `officeName` | 销售组织 ID / 名称 | 只提交 `officeId` |
| `itemKind` / `itemKindCode` | 逗号分隔品类 ID / 页面回显数组 | 提交时数组 join 成字符串 |
| `merchantCode` | 善付通商户号 | 可空 |
| `bankName` | 开户行名称 | 必填；租户系统类型为 2 时页面提供候选联想 |
| `receiptAccountName` | 收款银行账户名称 | 必填 |
| `receiptAccountNo` | 收款银行账号 | 必填，按字符串处理 |
| `branchName` | 支行名称 | 可空 |
| `instCode` | 总行联行号 | 可空 |
| `branchInstCode` | 开户行联行号 | 可空 |
| `publicKey` | 善付通密钥 | 可空 |
| `createTime` / `updateTime` | 创建/更新时间 | 只读，不提交 |
| `updaterName` | 最后更新人 | 列表展示 |
| `creator` / `updater` / `deleted` / `tenantId` | 后端原始字段 | 只读，不能伪造租户或删除标记 |

## 4. 操作步骤与证据

1. 先调用组织树和品类树，使用可选组织节点的 `id` 和品类节点的 `catId` 组装表单。
2. 按组织 → 开户行 → 银行 → 账户名的顺序加载级联候选；候选为空时不猜测编码。
3. 编辑先调用详情，使用详情中的 `officeId`、`bankName`、`receiptAccountName` 回填级联数据。
4. 新建或编辑先调用对应 `prepare`，检查必填字段并等待用户明确确认；取消只丢弃草稿，不发写请求。
5. 确认后把同一份草稿交给 `create` 或 `update`；删除先 `prepareRemove`，确认后再 `remove`。
6. 写请求成功、超时或响应丢失后，使用新 ID或原 ID重新 `get/list`，逐字段核对；不能只凭 HTTP 成功回执报告完成。
