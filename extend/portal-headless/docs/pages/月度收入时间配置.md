## 能力定义

| 能力 ID | SDK 方法 | 页面动作 | 副作用 |
| --- | --- | --- | --- |
| `finance-setting-monthly-income-time-config-list` | `financeSettingMonthlyIncomeTimeConfig.list(query?)` | 管理员按租户/业务类型分页查询 | 无 |
| `finance-setting-monthly-income-time-config-get` | `financeSettingMonthlyIncomeTimeConfig.get()` | 普通用户读取当前租户四类截止日配置 | Portal 后端 `get` 会先 `ensureDefaults`，缺少记录时可能插入默认25日配置 |
| `finance-setting-monthly-income-time-config-update` | `financeSettingMonthlyIncomeTimeConfig.update({ items })` | 普通用户保存四类截止日配置 | `PUT` 批量覆盖当前租户配置 |

页面没有启停、删除、新增、单条编辑或独立取消接口。管理员分支由 `username === 'admin'` 或 `superAdmin === 1` 判定，只显示 `page` 分页表；普通用户分支调用 `get`，保存按钮由 `finance:monthly-income-budget-edit-config:update` 控制。页面“取消”只恢复最近一次读取的本地 `initialItems`，不发请求。

## 参数契约

管理员列表的请求参数按 Portal `useListPageModule` 逐字段发送：

```text
order='', orderField='', tenantId=undefined, bizType=undefined, pageNo=1, pageSize=20
```

`tenantId` 是平台管理员筛选的租户主键；`bizType` 只能是 1、2、3、4；分页条数只能为 10/20/50/100。SDK保留 `undefined` 参数键，统一 platform HTTP 层序列化时跳过未提供值。

普通用户保存载荷为：

```ts
{
  items: [
    { bizType: 1, lockDay: 25, remark: '' },
    { bizType: 2, lockDay: 25, remark: '' },
    { bizType: 3, lockDay: 25, remark: '' },
    { bizType: 4, lockDay: 25, remark: '' },
  ]
}
```

四类业务类型固定为：1 月度收入预算（资金）、2 月度收入预算（预测）、3 其他资金流入预算（资金）、4 其他资金流入预算（预测）。每项必须出现一次，`lockDay` 是每月截止自然日且必须为 1–31 的整数；`remark` 沿用读取值，`null` 按 Portal 表单逻辑发送为空字符串。`id`、`tenantId` 和页面标签不是 update 字段。

## 逐字段基准（源码推导，未浏览器实测）

页面所有请求均导入 `app/portal/utils/http/platform.js`，请求路径已经带 `/admin-api`：

```text
GET /admin-api/finance/monthly-income-budget-edit-config/page
params = { order: '', orderField: '', tenantId, bizType, pageNo, pageSize }

GET /admin-api/finance/monthly-income-budget-edit-config/get
params = {}

PUT /admin-api/finance/monthly-income-budget-edit-config/update
body = { items: [{ bizType, lockDay, remark }, ...] }
```

统一客户端会携带当前会话 token、`tenant-id` 和语言头；本页 `moduleType=null`，不发送 `module-type`。`GET` 请求由 platform 实例追加防缓存 `_t`，这是请求层行为，不属于能力参数。

管理员 `list` 返回 `{ list, total }`，每行只保留页面展示/筛选说明需要的字段：

- `list[].id`：配置记录主键，平台列表行标识；不放入普通用户 update 载荷。
- `list[].bizType`：四类业务类型数值。
- `list[].lockDay`：截止自然日；可为 `null`，页面显示破折号。
- `list[].remark`：备注原值；可为 `null`。
- `list[].tenantId`：所属租户主键。
- `total`：当前租户/业务类型筛选条件下的记录总数，不是当前页长度。

普通用户 `get` 由 Portal 的 `createItems` 语义归一为固定四项：按 `bizType` 排序，缺少的类型补 `{ lockDay: null, remark: '' }`，后端 `remark=null` 补为空字符串。`update` 返回根值 `true`；它不返回更新后的配置，不能代替写后 `get` 回查。

Java 静态源码显示：`get` 与 `update` 会先补齐缺失默认记录，默认 `lockDay=25`；update 请求的 `items` 非空，逐项 `bizType` 非空、`lockDay` 由后端校验为 1–31。当前控制器对 `get/page` 的菜单权限注释为联调期间仅保留登录态，update 明确要求 `finance:monthly-income-budget-edit-config:update`；部署环境的实际权限行为未验证。

## 操作步骤与撤销/补偿

1. 普通用户先调用 `get()`，按 `bizType` 将四项绑定到表单标签，保存完整的原始四项作为 `initialItems`。
2. 用户只修改明确要求的 `lockDay`；四项都必须是 1–31 的整数。调用 `update({ items })`，SDK按业务类型 1、2、3、4发送三字段载荷。
3. `update` 返回 `true` 只代表服务端接受请求。随后调用 `get()`，逐项核对四个 `lockDay`；未回查前只能报告请求回执，不能报告配置已生效。
4. 未提交时的“取消”直接使用此前保存的 `initialItems` 恢复本地表单，不调用后端。已提交后的恢复也只能在用户明确要求、且回查确认当前值仍为本次目标时，把 `initialItems` 作为一次新的 `update`；这不是事务回滚。

管理员只使用 `list` 分页读取跨租户配置；`list[].tenantId` 仅用于识别/筛选，不能据此把平台管理员列表行直接当成普通用户 update 输入。
