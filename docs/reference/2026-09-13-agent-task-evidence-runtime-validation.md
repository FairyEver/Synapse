# 长任务进度、证据与完成门禁验证

状态：五项修复已实现；2026-09-14 完成最终回归、两轮真实百炼 48 图验收和真实取消专项。各轮源码差异与未覆盖边界如下，不能解释为任意长任务永不失败。

## 问题与修复

“第一次成功”导出有 611 条历史、220 对工具调用/结果、5 个 SDK 执行代，48 张原图被读取 94 次。这些数字说明执行曾推进，不证明原要求全部完成。历史报告还曾混淆未知 Session ID、附件 size/byteSize、累计缓存 token 与当前上下文；有一次长报告包含重复段落和思考标签。导出缺少完整原生流，不能追溯断言所有重复都来自模型或 Renderer。

| 用户要求的修复 | 当前实现 | 验证边界 |
|---|---|---|
| 1. 保留进度，避免维护后重建任务 | DataRepository 的版本化任务 journal；原始/规范路径与原件版本、Read 区间、取得/呈现/处理分别记录；同一逻辑任务跨 SDK 代及显式继续复用 | 进程重启不自动执行；不是整历史存储迁移 |

## 本轮实测发现的额外故障

- 已取得图片重呈现前，模型先重读旧图，耗尽干净会话。现由 Runtime 优先准入待续接原图，并按干净会话的可用请求体分批，余项不计已尝试。
- 大文本已保存但完整引用放不下时直接停止。现于原生批次屏障交接；新 Read 通过宿主 artifact 身份、完整哈希、原始范围和保存元数据行偏移关联原材料。
- SDK iterator 的 Assistant 事件可能晚于下一批 hook。现以 PostToolBatch 固定集合，下一主线程 PreToolUse、后继 PostToolBatch 或正常 Stop 确认前一批，不能误清当前未呈现结果。
- 其它 Hook 可以改写已经取得的 Read 结果。SDK 0.3.245 的 PostToolBatch 提供模型转换后的文本（行号加 tab）或图片 content block；必须核对转换后的内容，不能拿它与原始工具结构直接比较。
- 工具参数格式错误时，SDK 可跳过 PreToolUse 直接产生失败批次；后继 PostToolBatch 必须先确认上一批，不能用空集合覆盖已交付但未确认的原图。否则模型会反复重读，耗尽干净会话。已用真实 SDK 的无效 TaskUpdate 回归。
- 空文件的原生文本结果按一行计量，模型侧为固定空文件提醒；BOM 与 CRLF 也由原生解码处理。转换校验须兼容这些格式，不得把有效读取误判为篡改。
- macOS 的 /tmp 与 /private/tmp、/var 与 /private/var 可指向同一文件。清单同时固定规范路径，避免第一次以另一种写法读取时漏掉准入检查或拒绝有效回执。
- 模型曾只登记后 40 张图片便封存范围。初次封存或显式重开后封存必须包含已有的材料回执；过早封存可用 reopen:true 追加缺项再封存，旧单元不可删除或替换。验收按 49 份原件的规范路径逐一核验，不能用相同的总数掩盖漏项；额外登记生成的答案文件不会替代任何原件。
- 已封存输入范围后读取生成的答案文件，重复提交 seal 曾被误判为遗漏输入。现重复封存为幂等操作，不强制把输出校验加入输入清单；初次封存与显式重开仍检查缺项。journal 与真实已安装 SDK 的输出核验序列均有回归。
- 受控取消曾先中止 SDK transport，再调用 interrupt，导致无法获得停止确认。现在外部取消先关闭新工作准入，经 interrupt 确认、close、iterator 结束后才释放 transport；预先取消的请求不创建 SDK 执行。保留未确认停止时的失败保护。
- 路径规范化现在设 3 秒边界；没有登记范围时不对下一次 Read 额外解析原件路径，避免不必要的文件系统等待挂住进度钩子。超时身份维持未知，不计为完成。该保护不保证操作系统或原生 SDK 对任意挂载点的读取永不阻塞。
- Task 工具被当前工具列表、显式禁用或 Persona 策略排除时，只保留已有读取证据，覆盖核验标记不可用；不要求模型反复调用被禁止的工具，不扩张权限。
- 只在最初 system prompt 中提醒保存进度并不可靠。增加工具回执反馈、未登记范围的结束门禁，以及已呈现材料进入下一份材料之前的提交约束。清单和已得出发现直接进入有界续接摘要，减少为了找进度反复读取所有检查点。

## 协议与故障回归

使用已安装 SDK 0.3.245、隔离 loopback 和真实 ConversationRouter / SessionManager / ClaudeSDKSession / DataRepository。验证的出站模型请求确实包含原图；图片标记在此为脚本化协议答案，不作为真实视觉理解证明。

- 两组 48 张原图，分别在第 17、11 张施加已保留成本，多次交接后全部单元与发现保留，计数动作一次，原件未变，请求均小于 6 MiB。
- 18 张并行待呈现图片分到两个干净批次，先拒绝未获执行的其它操作，之后全部呈现；每件重呈现一次，没有额外副作用。
- 正常文本区间、缺页、重叠、原生/宿主截断、版本变化、目录别名与完整保存结果的范围恢复。
- 空清单假 PASS、已知范围缺失、过期 revision、冲突发现、旧代写入、分页超过 100 行、保存失败、取消及显式恢复。
- 原有停止超时、创建失败、权限撤销、原件变化、检查点损坏、重启与无终态退出保护继续保留。增量检查点保留祖先校验引用；当前页保存失败不得提交恢复。
- 相同消息重复投递、不同消息相同文字、原生重复报告一次补正、仍异常时失败；其它 Hook 改写后不得发送下一请求或确认完整呈现。
- 实时 IPC、持久历史回放及 MCP 共用 timeline schema 保留相同的覆盖评估、失败与可恢复状态；普通配置备份排除任务证据。完整进度分页导出保留计量和匿名身份，不附私有 artifact 原文；已提交发现仍按任务证据导出。

## 真实百炼方法

使用用户现有百炼 qwen3.8-max 配置，经原生 Runtime 与 SDK 调用官方 Anthropic 兼容端点。凭据只从本机既有配置解密到进程内存，不写入仓库或测试证据。每轮隔离目录和新会话，保留原失败对话不变。后续运行把独立答案清单保存在输入目录的外部 evidence 目录；本轮既有目录中的 sidecar 保留原样，并逐条审核工具访问，不能把读取验收答案当作视觉成功。

输入包含 48 张四位标记 PNG 与 records.json（48 条编号/文件记录）。普通样本 720×480；大尺寸轮的前四张为 970×1866，其余 44 张为 720×480，字节量接近问题原图。给模型的自然中文请求仅描述核对全部材料、写出逐图答案、不改原件及一次计数动作，没有要求分块行数、Task metadata 或交接步骤。运行时协议由产品本身注入。

独立 oracle 检查：48 行答案顺序和值逐一正确、无重复文件名、原件及记录文件未变化、计数恰好一次且在第一代执行、实际至少两次自动交接、所有待续接图片确认呈现、49 份原始材料身份逐一匹配、全部覆盖并处理（额外辅助材料不抵扣原件）。最后一项不会替代标记答案核对。终态后另从持久 journal 检查每张图片的正确数字已经保存为无冲突发现，并关联同版本、完整且已呈现的原图回执；不能只保留“已读”计数。

预算保持 200,000 token 原生整理、5 MiB 安全预算、6 MiB 硬上限。SDK maxTurns=128（每代）、输出环境设置 4096。压力只在隔离夹具添加保留成本，不修改产品阈值。新夹具先保存源码指纹/样本清单，55 分钟时通过现有取消路径收束，60 分钟的外层测试超时仅作最后保护；不缩减材料数量。

早期 A/B 因真实 Runtime 故障失败；C/D 达到旧夹具 20 分钟上限，不能计作成功，也没有最终源码指纹；E 在干净会话内重复消耗图片容量后按保护停止。所有失败保留，不通过放宽成功断言隐藏。全部 14 轮开发与验收数据保存到同目录 JSON，失败不计入通过样本。

## 交付边界

没有新增依赖、公开 MCP 工具、权限范围、开发服务器或应用启动，没有执行用户原任务或改写原始日志。原生 Task metadata 是内部提交入口；完成评估仅作为既有结果/错误的可选字段。整历史存储迁移、通用副作用幂等事务、任意语义正确性判定与长期内存性能不在本轮完成声明内。单请求和单图片仍有限制，不能描述为无限上下文。
