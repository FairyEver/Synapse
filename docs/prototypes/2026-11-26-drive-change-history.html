1. 版本留存策略

  • 上传覆盖、在线编辑、协同检查点与历史恢复均生成不可变版本记录。
  • 所有历史版本长期保存，仅由文档所有者显式删除时释放存储与配额。

2. 变更历史回溯

支持查看单次改动、任意起止版本对比及指定时间段内的累计变更，并保持与当前文档正文一致的权限边界。

    产品定位与核心目标

    把「版本管理」与「变更回溯」职责拆清：历史版本弹窗继续承担轻量级的版本清单与下载/恢复/删除操作；新增的变更历史独立页提供接近 Git 的干净阅读环境，专门回答「这篇文档从创建至今改了什么」「某段时间里累计改了什么」「某两次版本之间有什么差异」。

    入口轻量不侵入 在历史版本弹窗顶部（表格上方右侧）新增「变更历史」按钮，点击新开独立页面 /drive/items/:itemId/changes，不改变原弹窗尺寸与表格操作。
    三种回溯视角 单次修改（vN-1 → vN）、范围对比（任选基准/目标版本或时间段累计净变更）、按次总览（类似 git log -p 串联展开每次改动）。
    时间段与来源筛选 支持「创建至今 / 近 7 天 / 近 14 天 / 自定义时间段」与来源（编辑 / 协同编辑 / 上传 / 恢复）筛选，可一键把当前时间段切换为累计 Diff。

    页面信息架构与交互规范

    • 顶栏：因在新标签页打开，不放多余的返回按钮；仅保留文档名 +「变更历史」标签与右侧三种查看模式切换，保持页面干净克制。
    • 筛选栏：时间段胶囊 + 自定义起止日期 + 来源筛选；右侧显示命中变更次数与累计 +新增 / -删除 行数，并提供「查看该时段累计变更」快捷按钮。
    • 左侧时间线（Commit Rail）：竖向连接轨串联每个版本节点，展示版本号、当前 徽标、来源、+X / -Y、时间与自动提取的一句话改动摘要（无需人工写 commit message）。点击节点在右侧展示差异；范围模式下高亮基准到目标的区间。
    • 右侧 Diff 检视器：支持统一视图（Unified）与分栏对比（Split）切换、仅看改动（自动折叠未改行并支持点击展开）与完整文档切换，并在修改行内提供字词级高亮（inline word diff）。
    • 安全衔接现有操作：在 Diff 顶栏保留「下载此版本」与「恢复到此版本」（沿用既有二次确认弹窗，恢复后生成新版本，不覆盖历史）。

    边界条件与数据契约建议

    • 文件类型边界：仅文本类文件（Markdown、TXT、HTML 源码、代码/JSON/YAML）显示「变更历史」入口；图片、PDF、压缩包等二进制文件保持仅在弹窗内下载/恢复，不进入文本 Diff 页。
    • 权限边界：与现有历史版本一致，仅文件所有者登录态可访问；公开分享链接不暴露历史版本或变更历史。
    • 单版本与初始创建：文档只有 v1（或在时间线选中 v1）时，右侧以全量新增形式展示初始创建内容；选中某个通过「恢复」生成的版本时，副标题明确标注 恢复自 vX（复用 restoredFromVersionId）。
    • 大文档与性能：建议服务端新增按需 Diff / 版本内容读取接口（仅拉取当前对比涉及的 2 个版本，限制单文件最大文本 Diff 体积，例如 1 MiB；「按次总览」按页懒加载，默认展开最近 5~10 次，避免一次性拉取上百个完整快照）。
    • 待清理版本：deletePending: true 的历史版本在时间线中置灰标为「待清理」，不可选作 Diff 对比目标。
