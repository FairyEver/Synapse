Synapse 手机端 · 录音

列表 / 详情 / 录音中 / 后台

这一版做了什么

手机端「录音」Tab 现在已经有列表和详情，但只能看，不能录——没有麦克风采集、没有上传、没有权限申请。这一版补上采集这一头，并把详情页做成和电脑端一致的两个平级视图。

与电脑端逐条对齐

  1. 名字：两端都叫「录音」。Tab、页面标题、空状态、错误提示、删除确认，全站一个词。
  2. 详情是两个平级视图：语音 / 文字，切换是粘性的（切到别的录音仍保持当前视图）。电脑端右栏是什么，手机端就是什么。
  3. 文字就是一段转写：腾讯云返回什么显示什么，按句子并成自然段（约 110 字一段）。没有纪要、没有发言人、没有时间戳、没有搜索。
  4. 删除只有一个动作：录音和文字一起删，行从列表消失，不可恢复。
  5. 记录异常退出，静默收尾：录到一半被杀进程/强退，已经录到的部分按正常录音保留，直接进列表、照常转写，界面上不出现任何询问。
  6. 没有暂停：录音页只有「取消」和「完成」，与电脑端一致。
  7. 波形是主题色，不是红色。 语音备忘录的红色是它自己的品牌主色；Synapse 的主题只有一个强调色，而且它只表示「需要人」。所以录音按钮也不做红的。
  8. 状态与文案逐条沿用：转写中 / 转写失败 / 还没有录音 / 转写还在进行，完成后文字会自动补全。/ 这段录音里没有识别到语音。/ 录音已删除 · 文字仍保留。
  9. 界面任何位置都不出现云盘、上传、上传中、云端、服务器。

手机端独有、电脑端没有的

  1. 开始录音在导航栏右上角的加号，和终端完全一致（那边是 .toolbar 里的 topBarTrailing 加号）。静止时是裸符号，列表一滚，整条导航栏收成玻璃、加号跟着变成玻璃圆。点它进录音页，不先起名字——电脑端也是点「开始录音」直接进，名字事后在详情页点标题改。空状态里另有一枚「开始录音」胶囊。
  2. 这个加号不像终端那样有禁用条件。终端的加号在没选电脑 / 电脑离线时会置灰，因为终端得由电脑来建。录音是手机本地采、服务端转写，不依赖任何一台电脑在线，所以它一直可用。
  3. 录音页可以收起：下滑或点收起，录音继续，App 内顶部出现一枚玻璃胶囊（计时 + 停止）。可以接着去看终端、云盘、别的录音。
  4. 锁屏实时活动 + 灵动岛：录音中锁屏能看到计时和停止；灵动岛常驻。
  5. 后台录音：切到后台、锁屏都继续录。
  6. 波形不会因为异常退出而丢：手机上录音必须落一个 m4a 文件，波形能事后从文件重算再补传。电脑端那条「恢复回来的录音是平线」的已知缺陷，手机上不存在。

系统集成

录音要住进系统里。下面这些 UI 都不是 App 自己画的，是系统按 ActivityKit / ControlWidget / App Intent 的模板渲染的，Synapse 只提供数据和动作。图见下面「系统集成」那一栏。

  1. 灵动岛三态——紧凑（波形图标 + 计时）、最小（两个实时活动并存时收成一个点）、展开（图标 / 计时 / 波形 / 取消 / 完成）。
  2. 锁屏实时活动——锁屏上直接看计时和波形，不解锁就能取消或完成。
  3. 控制中心控件——从右上角拉下来就能开始录音，不用先找 App。
  4. 主屏长按 App 图标——快捷操作里「开始录音」排第一。
  5. 录音中状态栏的橙色麦克风指示点——系统自己画的，App 什么都不用做，但截图、客服话术和「为什么这里有个橙点」都要能解释。

还有两样没画，因为要等你先拍板：锁屏播放控件（Now Playing，回放时才出现）和 Siri / 快捷指令 / 侧边按钮（「用 Synapse 开始录音」）。两者和实时活动上的按钮共用同一份 App Intent，加进来很便宜，但要先确定详情页做不做播放。

系统集成的三笔账

  1. 要推翻一条有意为之的决定。 Info.plist:72 写着「No UIBackgroundModes on purpose」——App 现在故意不声明任何后台模式，注释里的理由是「声称一个没人用的后台能力，App Review 会问」。后台录音必须加 UIBackgroundModes: audio，那条注释和理由要一起改。
  2. 要新建一个 Widget 扩展 target。 灵动岛、实时活动、控制中心控件在 iOS 上都只能放在 WidgetKit 扩展里，主 App 放不了。你说不要桌面 Widget——那个扩展里就是不放主屏 Widget，但 target 本身绕不开；主 App 的 Info.plist 还要加 NSSupportsLiveActivities。这是本次唯一一处新增构建产物，打包、签名、TestFlight 都会跟着变。
  3. 全仓没有 App Intents。 实时活动的按钮、控制中心控件、侧边按钮、Siri 快捷指令都是 App Intent，要从零建一套。好处是四个入口共用同一份 intent，不重复写。

顺手发现的两处不齐

一、转写完成的推送还写着「逐字稿」。 正文现在是「转写已完成，逐字稿可以看了。」（server/src/meeting/meeting-transcription.service.ts:346）。「逐字稿」正是这次重构明令删掉的词——文案表里写着「一律不出现：……逐字稿……」，两端界面也都改成「文字」了，只有这条推送漏在外面。原型里我按对齐后的写法画。改它是一行的事，但它是用户可见文案，等你挑：

  • 转写完成，文字可以看了。——我的推荐，说了结果也说了下一步
  • 转写完成。——最短，但没说要去哪看
  • 文字转好了。——更口语，和其余文案的语气不太一致

二、麦克风用途说明没提录音。 NSMicrophoneUsageDescription 现在写的是「用于把说的话转成文字填进终端输入框，以及录像时收录声音。」——授权弹窗上就长这样，录音不在里面。要补一句，因为权限弹窗是用户第一次见到录音功能的地方。

这条边界是这次要改的

旧设计文档 2026-09-19-meeting-recording-design.md 的 §9 把「手机端录音」写成非目标，理由是"会牵出后台录音权限、中断处理、上传稳定性一整条链路"；两栏重构文档 §8 沿用了它。这一版把它推翻，下面四条链路要正式认下来：

  • 麦克风权限（已有 NSMicrophoneUsageDescription，语音输入在用）与后台音频 mode
  • AVAudioSession 中断：来电、闹钟、其他 App 抢占麦克风
  • 后台与挂起状态下的分片上传（需要 URLSession 后台会话）
  • 手机发出的录音和电脑发出的，在服务端是同一条记录，列表两端共享

材质只用在控件上

Liquid Glass 全部用在浮在内容之上的东西：Tab 栏、录音按钮、导航按钮、录音胶囊、分段控件、弹窗。正文和转写文字永远在实色卡片上——终端那次材质把 11pt 的字糊成灰斑的教训，在正文上同样成立。

四个待拍板

一、详情页做不做播放？这一版做了，做成「语音 / 文字」两个视图，因为你说的是「能看原来的录音，能看文字」——两件事对应两个视图，也正是电脑端右栏的样子。代价是手机上要新增：音频下载签名、边下边播、波形定位、后台播放的音频会话管理（和录音会话会打架）。如果只要文字，把「语音」视图整个去掉即可，原型里其余部分不受影响——那详情页就只剩一张文字卡，正是现在的样子。我倾向做，因为录完就想听是最自然的下一步。

二、麦克风被别的 App 抢走怎么办？来电、闹钟、微信语音、别的 App 放视频，iOS 会直接掐掉录音会话。电脑上不存在这个场景，所以没有先例。我选的是：自动暂停，占用结束后自动恢复，界面上写明「录音已暂停」，恢复后继续录同一条。为什么不是直接结束这条：一场四十分钟的会，一个电话就断了，而且不能续。为什么不是静默录进一段空白：那会让转写结果里多出一段莫须有的静音。注意这里用户不能手动暂停，暂停只由系统中断触发，所以和「没有暂停」不冲突。

三、录音中那一屏要不要给一点红色？入口改成导航栏加号之后，按钮本身已经没有配色的余地了——它跟终端一样是单色符号。剩下能上色的只有录音页里的滚动波形和「取消 / 完成」两个按钮，我按主题色做了，理由见上面第 7 条。iPhone 上「录音＝红」是有肌肉记忆的，但那是 Synapse 第一次为一个功能引入品牌色，电脑端得一起跟上才不会两端分叉，而桌面端的波形早就是主题色。我倾向不引入。

四、录音中允许离开录音页吗？我做成允许——录音继续，顶部出现玻璃胶囊，灵动岛和锁屏同步。替代方案是录音期间锁死在录音页，更简单也不会误操作，但四十分钟的会里用户什么都干不了。我倾向允许。
