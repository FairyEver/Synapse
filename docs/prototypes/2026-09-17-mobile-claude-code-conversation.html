手机端创建 Claude Code 对话

产品需求与交互原型 · 2026-09-17

一句话：手机上「选参数」，电脑上「照办」。
手机把项目、供应商、模型三件事发给电脑，电脑用自己本地的配置和密钥，在项目目录里起一个内置 Claude Code。手机全程不接触任何 API Key。

为什么只能这么设计

桌面端 ⌘ + 加号 走的是一条只有电脑能走的路：

  1. 解析默认供应商与模型（pickInitialProviderModelSelection，读全局默认 config.agent.defaultProviderModel，回退到当前激活 / 首个可用供应商）；
  2. 主进程 createClaudeCodeTerminal({projectId, providerId, modelTier}) 取该供应商的凭据环境；
  3. 按档位解析出真实模型名，写一份 0600 的临时 settings.json；
  4. 在 项目目录 里用这份临时环境起一个终端进程，标题 Claude Code · 项目名。

这里第 2、3 步是死结：凭据只存在于主进程，设计上从不进渲染进程、也不进终端记录；手机端与电脑之间又只有一条由云端转发的窄链路，云端明确「不解释、不存储」。所以它不可能变成「手机自己开一个 Claude Code」。

而手机端本来就是瘦客户端——终端仍然跑在电脑上，手机看到的是电脑合成好的行，手机只发意图、电脑执行。把「创建」也做成一条意图，正好落进现有架构，不用新增一条通道。

这条功能补的是闭环的入口 「Claude Code 提问 / 要授权 → 推送 + 锁屏批准」这条链路已经完整存在了。缺的只是在手机上把它开起来。做完之后，出门在外才第一次能完整跑完一轮。

交互

入口：终端列表的 +，弹一个从底部升起的面板

面板默认停在约 3/4 屏高，可以继续往上拉满；顶部是分段选择器：对话（默认选中）与终端。两段各自对应电脑上两个不同的侧边栏：

分段选什么电脑上对应结果
对话 项目（「本地对话」+ 已配置项目） Agent 对话侧边栏的顶层分组（app.agent.group.list） 在该项目目录里建一个 Claude Code 对话
终端 终端分组 终端应用左侧的终端分组 在该分组里建一个普通终端

分段切换的是「你要新建什么」，不是「你在看什么」 这一点容易读错：建好的 Claude Code 对话照样会出现在「终端」页的列表里（落在电脑的默认终端分组下）。分段只决定这次从哪个面进去、按哪套分组去选目标——两个入口，一个列表。

默认供应商与模型这条能力，落在哪

桌面端敢一键完成，靠的是两件事：

  1. 那个 + 挂在某个项目行上——项目本身是已知的，不用选；
  2. 供应商和模型的默认值由电脑当场解析，解析不出来才回退到弹窗。

手机上的 ＋ 在导航栏，没有第 1 点这个上下文。所以要把这条能力补齐，得补两处：

参数默认从哪来说明
项目 记住上次在这个手机上建过的项目，预选好并标「上次」；首次使用没有默认，就退化成从列表里选一个 补上桌面「项目行自带上下文」那一半
供应商 / 模型 不写死，交给电脑解析——和桌面 ⌘+加号 用同一套规则 只显示未归档的；四档，每档显示解析后的真实模型名，避免用户选了不知道选的是什么

关键判断：默认值由电脑算，不由手机算 手机请求里供应商和模型都可以缺省，缺省时电脑按 config.agent.defaultProviderModel 解析。这样「手机上的默认」和「电脑上 ⌘+加号 的默认」永远是同一个东西，不会因为两端各算一遍而分叉。

这不是新发明——桌面端自己的 MCP 能力 app.agent.conversation.create 已经是这个形状：入参里供应商和模型可选，缺省就走 createLocalAgentConversation 里同一份选型函数。手机端照抄这个形状即可，不必另立一套。

于是「对话」段长这样

三行参数都已经解析好，加一颗主按钮：

项目      Synapse  [上次]        ›
供应商    Anthropic 官方        ›
模型      Opus                  ›

        [    开始对话    ]

＋ → 开始对话 = 两次点击，零个决定。三行里没有任何一行需要用户先读再判断——这正是「默认供应商模型」这条能力的落点：它不是把值预填进输入框，而是让用户不必做那个决定。

要换项目、供应商或模型，点对应那行进面板内的下一层（顶部换成返回 + 标题），不再叠第二层面板。

「终端」段不这么改：它保持现在的行为——点分组即建，不加确认按钮。因为终端分组没有可省的默认值，硬加一颗「开始」只是纯摩擦。两段在这里不一致是故意的：对话段有默认可省，终端段没有。

想过、但不建议：把 ＋ 本身做成真·一键（长按才开面板） 这样确实能压到一次点击，但代价更大：
· ＋ 现在的语义是「我要新建东西」，直接建出一个用户没点过名的对话会让人意外；
· 首次使用没有「上次的项目」，必然建错地方；
· 长按是隐藏手势，换项目这件事会变成没人发现得了的功能；
· 桌面端敢一键，是因为失败能回退到弹窗（「快捷创建无法解析可用模型或创建失败时，也回退到同一弹窗」）。手机上弹窗本来就是开着的，没有非要抢那一次点击的理由。

真正值得省的是判断，不是点击。上面那个方案把判断省掉了，这个方案只是把点击藏起来。

创建之后

电脑返回新的会话 id，手机直接进入终端页——和现在新建终端一样，落地即能看、能输入。

不做特例：尺寸一律「优先移动端」，分组不另建 在手机上建 Claude Code 对话，本质就是开一个终端、附带一条启动命令——和平时先开终端再跑 Claude Code 是同一件事。所以它不在尺寸上另立规则（与「新建终端」完全一致，默认由手机决定栅格），也不用给它单独开一个分组：落点与桌面端 ⌘+加号 一致，进电脑上的默认分组，靠标题「Claude Code · 项目名」和「需要我」标记被人认出来。

失败与离线

  • 电脑不在线：不排队、不假装成功。创建必须由电脑执行，所以如实说明并保持禁用。
  • 创建失败（电脑缺内置 Claude Code runtime、供应商凭据缺失、项目不可用）：面板保持打开，供应商 / 模型的选择不丢，错误就地显示在面板里。桌面端已有的文案口径直接复用。
  • 电脑端版本太旧：老版本电脑会回「不支持的操作」。手机要把它翻成一句能照做的话，而不是原样抛错误码。

非目标

  • 不在手机上管理供应商——增删改、填 Key 全部留在电脑。手机只做只读选择。
  • 不支持中途换模型。模型是启动参数，换等于重开；手机上重开一次比加一个伪切换更诚实。
  • 不动桌面端「智能体对话」那条线（SDK 聊天）。本次只做 Claude Code 终端对话。
  • 不做手机端排队创建。电脑关机就是关机。
  • 不顺手接「已保存命令」。手机协议里其实已经有 launchCommand，但手机端既没有界面、也拿不到命令列表，一直是条死路。它和本次是同一个形状（开终端 + 启动命令），将来可以一并收口，但不是这次。

已定

叫法统一到「Claude Code」 桌面端按钮现在写的是「创建终端cc对话」，而它建出来的会话标题是「Claude Code · 项目名」——同一个东西两个名字。界面上一律用 Claude Code，「cc」只留在模板文件名这类内部位置。桌面端那个按钮文案一并改成「创建 Claude Code 对话」。

尺寸不做特例，也不考虑 Claude Code 在手机宽度下的排版 手机上建 Claude Code 对话就是「开终端 + 一条启动命令」，与平时先开终端再跑 Claude Code 是同一件事。尺寸沿用新建终端的既有行为（优先移动端），不为它新增设置或第三种显示模式；TUI 在窄宽度下的观感不在本次范围内。

验收标准

  1. 电脑在线时，点 ＋ → 点「开始对话」，两次点击、零个决定就建出一个 Claude Code 对话并直接进入终端。
  2. 第二次打开面板时，项目 / 供应商 / 模型三行都已经是上次用的值，用户不需要读它们就能直接按「开始对话」。
  3. 面板默认停在约 3/4 屏高，向上能拉满，向下能关掉；分段默认停在「对话」。
  4. 「终端」段的行为与现在完全一致（点分组即建），原有使用习惯不被打断。
  5. 手机全程不出现、不传输任何 API Key 或供应商地址。
  6. 电脑不在线时不能创建，且说清原因。
  7. 创建失败不产生半成品会话；面板保持打开，三行的选择不丢。
  8. 电脑端缺内置 Claude Code runtime 时，手机看到的提示与桌面端同一口径。
  9. 老版本电脑 + 新手机：提示升级，不崩、不卡在加载中。

给实现者的边界（不属于用户可见文案）

  • 新增一条意图（形如 createAgentConversation），字段为 projectId / providerId / modelTier，均可选，另带初始 cols/rows/deviceLabel。初始尺寸必须随创建一起到达，否则 shell banner 会永久烙在旧宽度上（ADR 0063）。
  • 桌面端执行逻辑必须抽成 service 方法后被意图复用，不要照抄一份 ipc-claude-code-terminal.ts。
  • 「对话」段那份项目列表，就是电脑上 app.agent.group.list 的结果（「本地对话」+ 已配置项目，形状 {projectId, name, isDefault}）——直接复用，不要另建一套选项目录。它和「供应商摘要」都只含 id、名称、四个档位对应的模型名，不含 baseUrl、不含任何密钥；建议做成按需拉取的独立意图，不要塞进按内容变化下发的会话摘要里，避免常驻流量。
  • 授权沿用 terminal.session.create（带初始尺寸时再加 terminal.session.resize），与现有 create 一致，并经过权限与审计。
  • 手机端新建终端当前没有随 create 带初始 cols/rows（靠后续 resize 补），与 ADR 0063 不一致。新意图不要再继承这个缺口。

右侧可点击操作：列表的 +、面板里的三行参数、开始对话；顶部分别是各状态。
