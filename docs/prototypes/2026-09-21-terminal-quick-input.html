终端快捷输入 · 原型

  • 接的是哪个「快捷输入」：Synapse 里那个 System App（快捷输入，存 app.quick-input.items）。Agent 对话里已经接上了，终端这次是把同一份句子接进命令条。手机端也已经在用这份数据。
  • 入口在命令条最左侧，而且是钉住的。命令条本身是横向滚动容器，指令一多最左边的东西会被滚出去 —— 所以这颗键放在滚动区之外，跟手机端「左固定 · 中横滑」是同一种做法。
  • 点一句只落进输入框，不执行。和语音输入、手机端同一条口径：整句文字写进命令行/TUI 输入框，执行与否留给按 Enter。句子是多行的，写入时按 bracketed paste 包一层，避免第二个换行被当成回车。
  • 名单为空时这颗键不出现。与 Agent 对话里的做法一致（quickInputs.length === 0 时不渲染菜单），不摆一个点开是空的按钮。
  • 面板是深色的，因为终端那一块自己带 .dark。应用浅色主题下窗口壳是浅的，终端永远是深的；面板浮在终端上，所以取深色 token。
  • 名字已经分开：终端工具栏原来那套自定义按钮改叫快捷命令，跟手机端面板里的叫法一致；「快捷输入」这个词留给这个 App 里的句子。两处不再同名。

名字怎么分

  • 终端工具栏那颗铅笔（第一屏里带 ? 的那颗）打开的弹窗，原来标题叫「自定义快捷输入」，管的是命令按钮：名称 + 内容 + 是否回车。存在 app.terminal.toolbar-actions，跟「快捷输入」App 里的句子没有关系。改叫「快捷命令」。
  • 改完之后，三处叫法就一致了：终端工具栏上的命令按钮、那个弹窗、手机端面板里的「快捷命令」段。而「快捷输入」只剩一个意思 —— 用户在「快捷输入」App 里维护的句子。
  • 要改的字符串都在那个弹窗里（标题、表单标题、空态、删除确认、两条 aria-label），加上工具栏那颗铅笔的 aria-label 和自定义按钮的 aria-label，没有别的联动。
