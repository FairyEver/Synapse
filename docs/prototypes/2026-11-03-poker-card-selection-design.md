# 卡牌舞台：八类选择能力

日期：2026-11-03。范围：HTML 交互原型。用户要求把选择交互设计为基础能力供卡牌组合调用；本稿与原型一起用于评审，不修改正式游戏、服务端协议、能力注册表或数据库。

原型入口：[卡牌舞台](./2026-11-03-poker-card-stage.html)。保留牌桌叠加、错落入场、轻微悬停、选牌聚焦与出牌反馈。顶部“选择交互演示”可直达八类交互，并补充消耗／复制、驱散／净化、单候选和无合法目标场景。

## 统一契约

卡牌只声明前置 `choices` 和可选的后续 `followUp`；UI 不根据卡牌 ID 决定使用哪一种选择器。`profiles` 把现有领域选择翻译为表现配置，`selectors` 注册八个渲染器。原型保留现有请求字段 `hole`、`player`、`targetHole`、`color`、`ability`、`status`；候选最后提交 `candidateIndex`。

```ts
type SelectionRequest = {
  key: string
  ui: 'own-hole' | 'player' | 'opponent-hole' | 'color'
    | 'ability' | 'status' | 'poker-candidate' | 'ability-candidate'
  label: string
  options: { value: string; label: string; meta?: unknown }[]
  dependsOn?: string[]
  purpose?: 'consume' | 'copy'
}
```

- `options` 是授权后的合法集合。原型由 `fixtureChoices` 制造；正式接入应使用服务端 `PokerCardChoiceSpec` 的 value 与合法范围，展示元信息也只能取当前受众获准的数据。
- 每个渲染器只处理 request 与选中值，统一输出 `data-choice-key`、`data-value`、`aria-pressed`。事件、合法性验证、确认门槛与摘要由公共控制器负责。
- `setChoice` 验证选项与依赖，变更上游值时递归清空下游。`reconcileChoices` 在可选集合刷新时反复清理失效项，直到依赖稳定；禁止用旧目标启用确认。
- 值是实例标识或服务端槽位值。显示名称不作提交值，同名实例用本轮局部序号区分，不展示 UUID。
- `dependsOn` 必须形成有向无环关系。未满足依赖的步骤禁用，保留下一步必要提示。
- 选择与确认分开。材料牌的“将额外消耗”和“原牌保留”在确认前展示；未确认的返回不改变牌和筹码。

## 八类表面

| ui | 视觉与行为 | 卡牌调用 |
|---|---|---|
| own-hole | 本人两张明牌；显示选中描边与标记 | 01、03、04、06、07、08、09、17 |
| player | 玩家头像与姓名；合法集合区分其他玩家、其他真人、持能力牌真人 | 04、05、13、14、15、19、20、49、53 |
| opponent-hole | 按玩家排列的底牌槽位，未知牌只显示牌背；不合法槽位不可选 | 18 |
| color | 红／黑两个带文字和花色的选项，依赖目标暗牌 | 18 |
| ability | 其余能力牌的缩略卡面，支持横向浏览与同名实例序号 | 24、26、30 消耗；29 复制并保留 |
| status | 按玩家／全场分组，显示效果名、次数、阶段期限、底牌槽位及同名序号 | 45 全部公开可驱散效果；46 仅本人可驱散负面效果 |
| poker-candidate | 实际 1—3 张扑克牌铺开，预选后确认替换既定槽位 | 06 |
| ability-candidate | 实际 1—3 张能力牌铺开，预选后确认加入手牌 | 25 |

04 组合 `HOLE + PLAYER`；18 组合 `HIDDEN + COLOR`，颜色依赖目标暗牌。其他所有前置选择沿用现有卡牌定义中的 profile。原型包含当前 60 种定义及其完整 choices 配置：23 种有前置选择；06 与 25 有候选后续，其中 06 同时有前置选择。没有增加 07 的手动择高、03 的手动选人、08／09 的颜色选择或 35／36 的历史暂存选择。

## 生命周期与显示边界

1. 选能力牌 → 生成当前合法 requests → 补齐选择 → 核对目标摘要和实际费用 → 明确施放。
2. 06／25 施放成功后进入候选。来源牌已经消耗，收起只隐藏舞台；重开恢复同一批候选和预选，不重新抽牌、不重新扣款。
3. 候选一张也保留明确确认；候选选择只允许提交实际存在的索引。超时采用第一张，原倒计时不因界面开关重置。
4. 无合法目标、材料缺失、没有可取回的暂存或筹码不足时，说明原因并禁用施放。其他牌当前不可施放不妨碍它成为合法材料。
5. 有筹码代价时，在固定底栏呈现代价／豁免／实付；免费不再重复提示。净化忽略追加卡费。原型以 10 筹码为 1BB，筹码不与钻石混用。
6. 私密查看在本人情报视图展示。花色与点数分别只展示获准部分，牌序预览失效后保留失效说明。未知对手底牌不进入选择器 DOM。
7. 持续效果用实例描述；防护和反制自动触发，不创建对方即时响应弹窗。被抵挡与未成功提交区别展示。
8. 统一支持方向键移动焦点、原生按钮 Enter／Space 选择、Tab 焦点约束、Escape 返回与入口焦点恢复；减少动态效果时保留选中态和结果。

## 布局与文案

- 覆盖层锁定视口，顶部公共牌／倒计时及底部操作不滚动；确认、返回、收起、费用与必要的目标摘要统一放在底栏。
- 中间查看区始终保留左右两列，窄屏也不将右侧内容排到卡牌下方。左侧卡面按可用高度等比适配，右侧 `.inspect-details` 为唯一纵向滚动节点，卡牌在滚动区外。
- 卡面在中间区域垂直居中；右侧用独立 `.inspect-body` 的自动上下外边距让短内容居中，内容超出时从顶部开始滚动，卡面不受影响。
- 重要信息优先放大：桌面完整牌效 18px、窄屏 16px，选择标签 16—17px、目标与效果名 15—16px，主按钮 18px。窄屏左侧只保留较大的牌名和插画，完整牌效集中在右侧，避免依赖缩小的卡面规则文字。
- 游戏表面沿用现有卡面与黄铜／深绿材质，增强目标徽章、卡背、选中描边及施放按钮的压边；不增加装饰性说明或新的游戏操作。
- 状态列表不再建立嵌套纵向滚动；材料牌和对手底牌仅保留必要的横向轨道，选择后恢复原滚动位置。手牌和候选卡面按中间可用高度适配，不通过滚动覆盖层容纳卡面。
- 移除重复牌名／类别、操作教学、步骤摘要、就绪提示及第二个返回入口。保留完整牌效、选择 label、材料消耗／保留含义、收费和不可用原因；依赖步骤的提示仅供读屏使用。

## 原型与正式接入的边界

`fixtureChoices`、`applyDemoOutcome` 和演示牌池只用于本地交互评审。原型没有网络请求，不是第二套游戏规则引擎，也不能证明完整 60 张牌的资金、触发链、随机公平性或并发正确性。正式接入必须复用当前控制版本、报价版本、原 actionId 恢复、服务端候选保留和已提交结果投影，不能以本地演示计算替代服务端裁决。

本轮以 Node/jsdom 核对选择器组合、材料用途、隐私、过滤、候选恢复、费用、键盘和异步关闭状态；没有启动浏览器、应用或开发服务。CSS 与 DOM 检查不代表已完成真实浏览器的宽窄屏视觉验收。
