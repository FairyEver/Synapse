# 云端待办事项：第一阶段原型

状态：用户已于 2026-10-11 认可原型，包括 PC 白色列表卡片修订，并确认[后续详细设计](../../superpowers/specs/2026-10-11-cloud-todos-design.md)。[实施计划](../../superpowers/plans/2026-10-11-cloud-todos.md) 待审阅与选择执行方式。此目录只包含设计原型，不注册应用、API 或 MCP 能力，不改变 Synapse 的运行行为。

## 已确认需求

- 增加内置应用「待办事项」。用户可以手动维护，也可以通过 Synapse Skill 让 AI 增删改查。
- 单列列表，无应用内侧栏。顶部只保留「未完成 / 全部」，每次打开默认选中「未完成」。
- 勾选表示完成。完成后从「未完成」消失，在「全部」中可以恢复。
- 只有登录账号后才能使用。服务器是唯一数据来源，所有业务操作调用 Synapse 服务端 API。
- 桌面端与 iOS 使用同一份账号数据。手机主页增加入口，不依赖某台电脑在线。
- 用户已明确选择增加截止日期和提醒。

## 本版原型

原型复用仓库当前 shadcn/Radix 组件及全局主题，没有新增依赖或独立配色。桌面实际复用 `EmbeddedSystemAppShell` 与 `SystemAppWindowShell`，演示只有一条应用顶栏。

移动端是**布局与交互示意**，使用网页控件演示操作，不是原生 SwiftUI 渲染结果。正式实现应采用下文所列系统控件，不照搬网页组件外观，也不自行仿造 Liquid Glass。

原型中的条目、日期和完成状态均为示例；时间参照固定为 **2026-10-11 10:00，Asia/Shanghai**。演示登录、保存、通知权限和跨端切换只改变原型内存，不联系账号服务。原型宿主可保存预览状态，这与正式产品的云端存储无关。

### 桌面端

- 启动台增加「待办事项」入口。沿用内置应用的内嵌、Dock 与独立窗口宿主，原型演示启动台内嵌形态。
- 一条顶栏：左侧返回与应用名，中间「未完成 / 全部」，右侧「新建」。
- 灰色页面背景上用一张白色卡片承载整个列表，复用 `Card` 与 `bg-card` 主题。
- 每行依次为完成控件、事项正文、更多菜单。正文区域可点击编辑，不只限于标题文字。
- 正文显示标题、单行备注、已设置的截止时间和提醒。无时间或提醒时不占位。
- 已完成项显示勾选、划线标题和「已完成」，避免只靠颜色区分状态。
- 新建与编辑使用普通表单弹窗；更多菜单提供编辑、完成／恢复、删除。

### iPhone 与 iPadOS

- 从「主页」功能清单进入，保留「主页 / 终端 / 通知 / 我的」顶层导航。
- 事项页用单列列表和「未完成 / 全部」分段控件；导航栏提供返回和新建。
- 点完成圆圈改变状态；点正文编辑；菜单提供删除和完成／恢复的替代操作。
- iPhone 新建／编辑使用系统 sheet，左上取消、右上添加／保存。iPadOS 使用系统居中表单 sheet，待办内容仍不增加侧栏。
- 宽窗口收窄正文的阅读宽度；窄窗口让元信息换行，不改变筛选或业务状态。原型里的 iPad 切换只演示单列组织，不代表已完成真实设备适配验收。

### 字段与时间

| 字段 | 本版建议 |
| --- | --- |
| 标题 | 必填 |
| 备注 | 可选 |
| 截止时间 | 可选，日期与时间；不填写时无截止时间 |
| 提醒 | 默认为不提醒；截止时、提前 10 分钟／1 小时／1 天、自定时间 |
| 自定提醒时间 | 可独立于截止时间设置 |
| 完成状态 | 未完成／已完成；允许恢复 |

截止时间和提醒相互独立：有截止时间不等于自动开启提醒。提醒必须指向未来时刻；相对提醒缺少截止时间时，表单提示补齐或改选自定时间。保存后列表只展示已设置的字段。

完成／恢复后给出撤销入口。完成和删除取消尚未触发的提醒；已写入通知列表的历史通知不撤回。恢复事项时，未来且尚未发送的提醒可以重新启用；已过期或已经发送过的提醒不自动补发，应由用户明确设置新时间。原型演示过期时间不再恢复提醒；发送记录的判定留给正式服务端实现。

### 列表组织候选

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 平铺单列，按截止时间排序（本版推荐） | 与用户指定的简单列表一致；没有额外分区 | 时间相隔较大的事项仍在同一列表 |
| 在同一列按逾期／今天／以后分组 | 期限更醒目，仍保留两枚筛选标签 | 多出分组标题，事项更改日期后会跨分组移动 |

原型采用平铺方案：未完成事项按截止时间先后排列，逾期自然在前，无截止时间在后。「全部」中未完成在前、已完成在后。正式设计还需固定同时间条目和完成历史的稳定排序。

## 云端、AI 与提醒的设计方向

本节记录原型阶段的设计方向；最终业务契约以已确认的详细设计为准，不是已提供的接口或既有能力清单。

- 服务器按登录身份关联条目；API 不让调用者自选 `userId`。列表、读单条、新建、编辑、删除、完成和恢复均校验归属。
- 桌面 renderer 继续通过窄而类型化的 preload bridge 操作；主进程与 iOS 各复用现有集中网络客户端。AI 的 MCP 能力也调用同一套账号 API，不直接写本地 Database 或 SQLite。
- Synapse Skill 增加待办事项领域指南，覆盖检索、新建、编辑、删除、完成和恢复。AI 先检索定位现有条目；同名多项或日期含糊时澄清，不猜测对象或时间。
- 支持「把预约车辆保养记录到待办，明天上午 9 点提醒」「把提交报销单标记完成」「把车辆保养改到周五」「列出未完成事项」「删除续费域名」等请求。这些语句只说明预期交互，原型没有执行 AI 工具调用。
- 云端持久化提醒时间并负责到点触发，复用现有账号通知记录、在线桌面投递和生产 APNs 通路。待办提醒需要新增明确的通知来源与条目目标；不能借用终端待处理，也不能让桌面 Automation 的在线状态决定提醒是否触发。
- 每次提醒版本最多创建一条账号通知。重试使用稳定标识去重；编辑、完成和删除与提醒版本失效需要在服务端协调。设备弹窗受系统通知权限与 Focus 控制，服务端成功不代表用户一定看到横幅。
- 通知点击回到对应事项。完整设计应定义删除后目标、冷启动、未登录、切换账号和迟到请求的行为，并同步桌面与 iOS 路由及能力注册文档。
- 云端变化后在线客户端重取相关数据，打开、前台恢复和重连时刷新。退出／切换账号清理内存条目与草稿，拒绝旧账号迟到结果。不提供本地离线写入队列。
- 时间存储为 UTC 瞬时值，界面按当前时区展示；AI 必须明确解析用户语句的时区。原型只演示上海时间，跨时区语义在详细设计中固定。

## 状态与无障碍

原型可切换正常、未登录、加载失败、空列表、通知权限关闭五个状态。失败页面有重试；未登录页面提供登录；完成、删除均有明确反馈，删除先确认具体条目。

正式实现应验证 320pt 窄窗口、iPadOS 窗口缩放、动态字体、深浅外观、VoiceOver、键盘／指针与减弱动态效果。完成控件和编辑正文须有独立的可访问名称及不重叠的触摸目标。状态文字不能仅依赖颜色，手势必须有可见替代操作。

## Apple 官方依据

2026-10-11 核对 Apple 当前官方文档数据；项目工程最低部署版本为 iOS 18。

| 选择 | 官方依据与适用方式 |
| --- | --- |
| 两枚相关状态筛选 | [Segmented controls](https://developer.apple.com/design/human-interface-guidelines/segmented-controls) 建议用分段控件切换紧密相关的子视图；[SwiftUI segmented](https://developer.apple.com/documentation/swiftui/pickerstyle/segmented) 从 iOS 13 可用 |
| 文字事项列表与点击反馈 | [Lists and tables](https://developer.apple.com/design/human-interface-guidelines/lists-and-tables) 支持易扫描的文字行及清晰的状态／导航反馈 |
| 从主页进入事项页 | [NavigationStack](https://developer.apple.com/documentation/swiftui/navigationstack) 提供平台返回行为，从 iOS 16 可用；复用现有主页导航栈，不另嵌一条栈 |
| 新建／编辑表单呈现 | [Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets) 支持短任务表单；iOS 单页表单取消在顶部左侧、完成在右侧，iPadOS 采用 page／form sheet |
| 日期与时间输入 | [DatePicker](https://developer.apple.com/documentation/swiftui/datepicker) 支持日期及可选时间，从 iOS 13 可用；[Pickers](https://developer.apple.com/design/human-interface-guidelines/pickers) 为具体控件选择提供依据 |
| 窗口和字体变化 | [Layout](https://developer.apple.com/design/human-interface-guidelines/layout) 要求随窗口、方向与动态文字适配；单列是用户的产品要求，不是 Apple 对所有 iPad 应用的规定 |
| 原生颜色、状态与可访问操作 | [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) 建议系统语义颜色、充分触摸目标及不只靠颜色表达状态 |
| 权限与提醒强度 | [Managing notifications](https://developer.apple.com/design/human-interface-guidelines/managing-notifications) 要求通知权限并尊重系统投递规则；本版建议普通提醒，不默认突破 Focus |
