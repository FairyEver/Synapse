一句话结论

底栏从 终端 / 录音 / 消息 / 我的 收敛为 主页 / 终端 / 我的 三个位置，并且从此不再增加。新增能力一律进入「主页 → 功能」；通知从底栏移到主页右上角的铃铛。

为什么改

旧：终端 │ 录音 │ 消息 │ 我的      ← 4 个槽位，已被单点功能占满
新：主页 │ 终端 │ 我的            ← 3 个槽位，永久固定

主页
 ├─ 待处理卡（只在真有会话卡住时出现）────→ 终端 · 那个会话
 ├─ 通知铃铛（右上角，带未读角标）────────→ 通知面板
 └─ 功能
     ├─ 录音 ─────────────────────────────→ 录音列表 → 录音详情
     ├─ 新建会话 ─────────────────────────→ 表单
     ├─ 剪贴板历史 ───────────────────────→ 列表
     └─（云盘 / 自动化 / 内容库 / 数据库…按同一结构陆续接入）

终端
 └─ 当前电脑 → 会话列表 → 终端画布（隐藏底栏的沉浸工作区）

我的
 ├─ 账号 │ 电脑
 ├─ 终端 │ 录音 │ 通知
 └─ 诊断 │ 关于

旧结构的三个问题：

  • 底栏槽位被单点功能占死。iOS 的 TabView 最多五个、舒适区三到四个。录音和消息各占一格之后，云盘、自动化、内容库、数据库这些桌面端已经存在的能力就没有位置了——要么挤进「我的」，要么再开一个 tab，两种都只会让底栏继续膨胀。
  • 「消息」占着最贵的位置，做的是中转站的活。通知的意义是「带你去某个地方」，它本身不是目的地。用户来这里不是为了读消息，而是为了点进去处理会话或看转写。
  • 「我的」是平铺的杂物间。账号、显示密度、已连接的电脑、诊断四段直接铺在一屏，每加一个设置就长一行，没有分类。

三个位置的固定含义

位置含义放什么
主页中枢：所有入口，以及「有没有人需要你」功能清单、待处理、通知面板
终端工作现场：控制电脑上的会话电脑切换、会话列表、终端画布
我的配置：账号与本机行为分类列表，点进去才是具体设置

关于「终端固定在左侧」：终端排在第二格，但它永远在同一位置、永远不被折叠进别的入口、一键直达、进入后占满整屏（隐藏底栏）——这是「固定」的实质。把主页放在第一格，是为了让通知有一个不属于任何业务的常驻落点，也正是您提出的方向。真机行为不做特殊处理：冷启动落主页，从后台恢复保持上次的 tab（TabView 的默认行为）。

关键决策

决策理由
底栏永远三个，不再增加位置是稀缺资源，功能不是。这条要写进规则文档，否则下次又会为一个新功能开一格。
通知不占 tab，改为右上角铃铛 + 通知面板它是覆盖层，不是目的地。面板里点一条就直接去往目标（会话或录音）——比「消息 tab → 列表 → 详情 → 再跳转」少两步。
通知详情不再单独成页正文进到行里显示。通知的价值在「带你去哪」，不在「读它的全文」。现有的 NotificationDetailView 可以删掉。
常驻性由三处共同承担① 主页右上角常驻铃铛；② 主页 tab 上的琥珀小圆点（在任何一屏都能看见有未读）；③ 已有的系统推送与 App 图标角标。所以「不占底栏」不等于「找不到」。
角标用琥珀，不用系统红沿用 Theme.attention：全应用只有一个「有人需要你」的颜色。会话行的「等待输入」和铃铛角标是同一件事的两种呈现。这条可以否决——想回到 iOS 惯用的红色，把两处改成 Color(.systemRed) 即可。
「我的」外层只放分类，值放二级页按您的要求。例外只有两行：账号显示昵称、电脑显示当前电脑名 + 在线圆点。这两个值是「你现在处在什么状态」，不是「一个可以调的设置」，一眼可见比点进去再退出来有用。不想要的话去掉这两个值即可。
主页的「待处理」卡只在真有会话卡住时出现没有内容就不占位置。它和终端会话行上的琥珀徽章是同一份数据，不引入第二套状态。
剪贴板历史从终端挪进「功能」它现在挂在终端列表的设备行上。它不绑定任何会话、可以独立进入，属于「功能」；挪出来之后终端那一页也干净了——设备行加会话，不再混着别的东西。它仍然是按电脑分开的，这一点在页面里写清楚了。这条是否采纳由您定，不采纳就是留在终端页、功能里少一项。
「即将支持」分组明确标注原型里列出桌面端已有、移动端待接入的四项，是为了展示结构在功能变多后长什么样，不是假装已经可用。真实实现时这一组不存在，直到对应能力上线。

「我的」的分组

账号  ── 昵称、邮箱、退出登录
电脑  ── 已连接的电脑（单选当前）、离线状态
终端  ── 显示密度（紧凑 / 正常 / 稀疏）
录音  ── 麦克风权限
通知  ── 系统通知权限、通知中心入口、图标角标
诊断  ── 记录诊断日志 → 诊断日志（记录终端屏幕内容、时间范围、占用、导出、删除全部）
关于  ── 版本与构建号、问题反馈、开源许可

七个分类，与 iOS「设置」同构：图标 + 名称 + 右侧值 + 箭头，点进去才是二级页；诊断下面还再有一层日志页，共三层。

其中终端和录音眼下各只有一项设置——这是分类结构的代价，也是它的用处：这两个分类将来会长出东西，现在就把位置留好，好过将来重新组织页面。若您觉得「显示密度」不值得多点一次，把它提回外层一行即可，其余分类不受影响。

需要落地的技术要点

1. Tab 枚举

RootView.swift 的 Tab 从 terminals, meetings, inbox, settings 收敛为 home, terminals, settings，selectedTab 默认值改为 .home。重按回列表的 tabSelection / popToRoot 逻辑照旧，只是枚举变短。

2. 深链路由必须整体改

handleRoute 现在会写 selectedTab = .meetings / .inbox，这些落点全部改走主页：

  • .meeting(id) → selectedTab = .home，主页栈推入「录音列表 → 该录音」。
  • .message(id) → 先 reloadNotifications()，再按这条通知自己的 target 决定去哪，不再进入一个「消息」位置。
  • .terminal(...)、.newRecording、.liveRecording、Widget 链接 → 终端相关的落点不变，只是不再有 .inbox 兜底。

docs/agents/mobile-adaptive-layout.md 里「通知、Widget 与其他深链要设置功能、电脑和条目三层目标」这条继续有效，只是「功能」的含义从底栏 tab 变成了主页栈里的位置。

3. 主页需要一个自己的导航栈

主页现在是「列表 + 可下钻」，要接 AdaptiveFeatureNavigation 同一套模式：宽窗左列表右详情，紧凑窗单列下钻。录音列表 → 录音详情是标准列表详情，直接复用现有的 MeetingListView / MeetingDetailView，不新写一套。

嵌套深度为 主页 → 录音列表 → 录音详情 三层。iPadOS 上不要为此再叠一个 NavigationSplitView：主页 tab 用 NavigationStack 推入录音列表，列表详情仍交给 AdaptiveFeatureNavigation 处理宽窗并排。

4. 通知面板

用 .sheet 承载现有 InboxView 的内容（原型里为了不依赖脚本做成了推入的一屏，效果一样），保留「待处理 / 未读 / 全部」分段与「全部已读」。行点击后先 dismiss，再按 target 路由。NotificationRouter 的 target 解析逻辑可以直接复用。

5. iPadOS

TabView(.sidebarAdaptable) 不变，三个 tab 在侧边栏里就是三项。「我的」宽窗用分类列表 + 右侧内容——这正是 AdaptiveSettingsView 已经在做的事，只需把 SettingsCategory 从四个扩到七个。

6. 需要同步更新的位置

  • docs/agents/mobile-adaptive-layout.md：顶层导航从「终端 / 录音 / 消息 / 我的」改为「主页 / 终端 / 我的」，并补上「底栏不新增槽位、新功能进主页功能清单」这条硬规则。
  • docs/agents/capability-registry.md 的 Deep Link 行：iOS 路由计数与入口说明。
  • SynapseMobile/README.md 的导航结构一节。
  • AGENTS.md 与移动端专题规格里所有提到「消息 tab」「录音 tab」的地方。
  • RELEASE_NOTES_PENDING.md：底栏结构变化属于用户可感知变化，必须记录。

功能增长时会发生什么

这是本次改版唯一真正要买到的东西。假设半年后再加云盘、自动化、内容库、数据库、密钥、用量监控六项：

旧结构新结构
底栏已经满了，只能塞进「我的」，或把某个功能降级仍然是三个，一个字都不动
新功能落点没有定义，每次都要重新讨论主页 → 功能，按分组插一行
用户学习成本每次动底栏，肌肉记忆作废位置恒定，只有清单在变长

功能超过十二项左右时，「功能」页需要加搜索框和「常用」置顶；在那之前分组列表就够了。这个阈值不必现在决定。

不在此次范围内

  • 不改终端的画布、键盘、语音输入与网格上报逻辑。
  • 不改录音的会话生命周期，也不增加纪要、发言人等已取消的产品层级。
  • 不改主机名、权限模型与任何服务端协议。
  • 「功能」清单的分组名（记录 / 工具 / 数据…）留到真实功能齐备时再定——现在只有三项可放，过早分组是空的。

顺带发现的两处不一致

① 版本号的位置。现在挤在终端页顶栏第二行的「状态 · 版本号」，横屏时还要让位。「关于」页收下它之后，终端顶栏那一行可以去掉，会话画布多出一行高度。

② AppConfiguration.swift 的注释与实现不符。该文件注释写「API Base URL 在设置里选择」，但代码里没有任何对应界面，只能靠启动参数或 -SynapseAPIBaseURL 改。这是一个独立的、与本次改版无关的既有问题，列在这里供您决定是否单独处理——本原型没有为它加设置项。

关于这个原型本身

它不含一行 JavaScript。您第一次打开时看到空白页，原因有两个：我漏掉了初始渲染调用，而且分享页的查看器是否执行脚本本身就不确定。所以这一版改成纯 CSS 驱动——导航用 radio + label，可见性用 :checked 选择器。任何能显示 CSS 的地方它都能用，包括微信、钉钉、飞书里的内置浏览器。

代价：只有「状态」类交互是可点的——切 tab、进出功能、二级页、通知分段、录音「文字 / 语音」、电脑单选、几个开关、全部已读。真正需要写入数据的动作（创建会话、开始录音、导出日志、退出登录）在原型里是死的，按下去没有反应。这是原型，不是可以用的版本。

需要您拍板的两点

① 角标颜色：沿用琥珀（推荐，与「等待输入」同一语义），还是回到系统红？

② 「电脑」和「账号」两行在外层直接显示值：这是对您「值放二级页」要求的一处例外，因为它们反映的是状态而不是设置。要严格只有分类名的话，去掉这两个值即可，其余不受影响。

另有一项请一并定：剪贴板历史是否从终端挪进「功能」（见上面的决策表）。
