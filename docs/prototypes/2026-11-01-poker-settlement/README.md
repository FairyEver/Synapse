# 德州扑克结算面板交互原型

日期：2026-11-01。只供设计评审，未接入游戏、服务端或数据库。所有人物与金额为虚构示例。

后续用户已认可此视觉并要求正式接入及逐手全员准备，最新规则见 [每手结算与全员准备](../../superpowers/specs/2026-11-01-poker-settlement-ready-design.md)。本原型保留初稿供回溯，其中关于五秒自动收起/续局的建议已被新规则取代。

打开同目录 `index.html` 即可使用，不需要网络或开发服务器。默认打开「我获胜」；关闭面板可选择其余六种场景。源代码复用已安装的 HeroUI React 3.2.7、默认浅色 token 和项目现有扑克牌 SVG，生成单文件离线 HTML，无新增依赖。

## 设计决策

- 第一眼看结果：赢家与获胜原因放在左侧，本人净输赢和「收回 − 投入」放在右侧。收池玩家可能净变化为零，不能直接把收池金额称作净赢。
- 公共牌随后展示；完整结算属于系统表面，采用 HeroUI Modal，真实牌面作为内容。主体保留原生 Header / Body / Footer 分区、默认留白和正文滚动。
- 用最佳五张解释胜负，标明每张来自手牌还是公共牌。点击全员列表的「比牌」，可以切换查看其他已公开玩家的最佳组合。
- 全员列表默认展开：手牌、牌型、投入、收回、净变化、剩余。窄屏把投入、收回、剩余收进数字列的纵向信息，保留全部金额；底池分配按需进入另一标签页。
- 主池、边池与未跟注返还分别列示，注明参与人和实际分配。返还不计入赢得的底池总额。标准与 32 张短牌使用各自牌型顺序。
- 仅呈现服务端允许公开的底牌，未公开位置显示牌背及文字。弃牌不推断或虚构牌型。本人手牌仍可见。
- 自制深色赌场风、满屏庆祝动画会削弱快速核对的目的，因此沿用当前游戏的浅色系统面板与克制的状态色。

## 正式接入时的行为建议（尚未实现）

- 每个新结算 handId 自动弹出一次，重连不重复弹出。取服务端 `nextHandAt` 展示真实剩余时间，下一手开始前收起并返回牌桌；绝不暂停服务器或延长当前 5 秒手间隔。
- 用户可以随时关闭，从本人的牌局记录重新打开静态快照；快照必须固定本手的 board、rules、seats、pots，不能混入下一手数据。打开面板不触发下一手、不重发操作、不重挂游戏或重播历史音画。
- 原型为了评审保持打开，不执行真实倒计时。「下一手开始前自动收起」是拟议正式行为，不代表已接入。
- 沿用现有 `PokerSettlementView` 和权限投影，不新增前端获取暗牌的能力。精确最佳五张与胜因需复用可信、遵循本手 rules 的判牌逻辑；历史字段缺失时显示可确认的信息。
- 正式验收覆盖 2–10 人、平分余数、多个边池、返还、本人弃牌/未参与、历史字段缺失、重连去重、下一手时间、390×667 / 390×844 / 桌面、键盘焦点与 reduced motion。
