微信 → Synapse 的对应

左端「语音 / 键盘」常驻切换键照搬
输入框右侧的麦克风快捷入口去掉 —— 与左端切换键等价，两个入口只会让人猜哪个不一样
语音态输入框变「按住 说话」照搬，宽度与位置不变
松开 → 发语音消息松开 → 转文字 → 识别结束就发送
上滑到左区「取消」左滑取消
「滑到这里 转文字」（右区）右区改成锁定 —— 恒定转文字之后，右区本来没有第二个出口，正好给锁定用
（微信没有锁定）右滑锁定：手松开、继续说、说完点「确定」发送
录音时全屏变暗不遮罩 —— 终端输出要能一边说一边看
波形气泡实时转写气泡 —— 流式识别本来就有字可显示，不假装有波形
表情面板不做
按住时长不设上限，按住多久都行（微信也是）；锁定态就是为长时间输入准备的

待拍板

  1. 「识别完就发送」在终端上等于立刻执行命令。这推翻了你 09-16 定的「终端只填命令行、不补回车」。终端要不要例外 —— 终端落地等确认，对话面松手即发送？
  2. 输入框里已经有字时不自动发送（本原型的规则）：语音是来补全一句话的，就把转写追加进去等你确认；输入框是空的，才当成"说一整句就发出去"。这条要是觉得绕，可以改成无条件发送。
  3. 锁定态的转写要不要多行。原型给了三行 —— 输入栏会长高，手机上终端可视区跟着变矮（桌面端不受影响）。要更稳就收成一行。
  4. 锁定的出口除了「确定」还要「放弃」（本原型左侧那个 ✗）—— 不然录错了只能发出去才能脱身。

键盘收起时，输入栏直接坐在屏幕底边；点输入框会起系统键盘，点工具栏最左边的 ⌨ 起应用自己的按键面板 —— 这两件事没动。
