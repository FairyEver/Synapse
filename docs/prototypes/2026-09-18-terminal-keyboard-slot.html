2面板怎么变

改前（现在）

它是个 .sheet，浮在整个界面之上，把工具栏和输入框一起盖住。还有一个下拉把手、可以往上拖到全屏。

改后

它占据的就是系统键盘那个槽位：工具栏和输入框原样待在上面、跟着一起被顶上去，终端也照旧跟着底部上移。没有"盖住"，没有悬浮阴影，没有下拉把手，也拖不动——它现在是一个键盘，不是一个抽屉。

内容不满一屏时，尾部留白怎么办

用上面那两个开关切着看：贴顶是现状（内容从顶往下长，底部留白），贴底是提案（内容的底边贴着工具栏，上面留白）。

贴底的好处正是你提的那件事：键盘弹起时不用"跟着上移"，因为内容本来就贴在底边上，可视区变矮它自然还在那儿。

代价有两个：① 只要没满屏，每来一行新输出整块就往上顶一格；② 它和"手机只是把电脑整屏缩放着看、逐格一致"有张力——去掉尾部空行之后，提示符在手机上的位置就和电脑上不一样了。

固定高度的代价，先摆在明处

四页一个高度，就得取够放全键盘的那一档（高约 370）。所以切到常用 / 方向 / 功能这三页时，下面会空出一块——左边把面板切到「常用」页就能看到。

换来的是：切分类时手底下的东西完全不动，工具栏和终端也不会再被顶一次。这也是这个面板最早的写法（那时四个分类共用 152 的键位格高度，注释写的就是"免得切页时面板在手指底下挪动"）。

3已经查实的旧问题

你最早报的"系统键盘把终端内容盖住"，查下来是故意的，而且现在真机上表现正确：

TerminalTextView.swift:318
// The keyboard appearing shrinks this view. Nothing new was appended,
// so no snapshot runs — without this the newest output would slide
// below the fold and the user would have to scroll to find it.
if bounds.height != lastLayoutHeight { … if isPinnedToBottom { scrollToBottom() } }

它只在 isPinnedToBottom（用户本来就在底部）时生效；翻到历史里看旧内容时故意不把你拽回底部。保留这样。

唯一可能的残留边角：内容没超出可视区时"贴底"没有可滚的余量。你那张最早的截图疑似就是这种情况。要不要我按"会话刚启动、内容不满一屏、再弹键盘"复现一次确认？

4明确不做

  • 系统键盘的任何行为、样式、输入法。
  • 面板里的按键内容、分类、锁存交互（上一轮刚做完，这次一个字不动）。
  • 工具栏那排按钮。
  • 面板的拖拽调整、全屏 detent。
