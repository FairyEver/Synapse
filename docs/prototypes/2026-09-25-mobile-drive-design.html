把云盘搬到手机上

底栏不加格。云盘从「主页 → 功能 → 云盘」进入，进去以后是一套「文件」App 形态的层级浏览器：文件夹下钻、面包屑回跳、长按菜单、左滑删除、多选、预签名直传、系统分享。 除本地同步之外的云端文件能力，在手机上都能用。

范围 SynapseMobile/SynapseMobile/Features/Drive/ 服务端不改动 复用现有上传通道 iPhone 与 iPadOS 共用一套逻辑

0一句话结论

云盘是「主页」这一格的一页，不是第四个 tab。 手机端底栏被规则固定在三个位置（docs/agents/mobile-adaptive-layout.md:8）， 新能力一律进「主页 → 功能」。云盘进的是那张功能清单。

进去之后，云盘是一个 Files 式层级浏览器：一切围绕「我现在在哪个文件夹」展开， 而不是围绕「我选中了哪一项」。服务端已经有现成的浏览器快照接口 （GET /api/drive/browser/owner/root 与 /items/:itemId）， 一次请求就带回「当前项 + 面包屑 + 子项分页 + 可下载性」，是给移动端量身定做的形状。

1为什么不是「列表 → 详情」

仓库规则要求「列表 → 详情」类功能接入 AdaptiveFeatureNavigation，并允许在 不用它时于设计文档中说明理由（docs/agents/mobile-adaptive-layout.md:36）。云盘是那个例外，理由有三条：

  1. 云盘的主交互是下钻，不是选中。AdaptiveFeatureNavigation 的模型是 「一份选中 ID 同时驱动宽窗并排与紧凑窗下钻」。文件树里「点文件夹」和「点文件」是两个不同的 动作：前者换掉整个列表，后者打开一份伴随内容。硬塞进一个 selection 会让 NavigationSplitView 的折叠语义和列表自己的下钻栈争抢同一个返回手势。
  2. iPadOS 上「文件」App 的形状是浏览列 + 预览列，不是列表 + 详情。浏览列自己还要能 往下走。这是 NavigationSplitView 的 sidebar 里带一层 NavigationStack， 而 AdaptiveFeatureNavigation 不接受自定义列结构。
  3. 预览不是目的。录音那种「列表 → 详情」里，详情是终点；云盘里预览是顺手看一眼， 看完还要继续往下翻。它值得在宽窗占一列，但不值得让导航为此改形状。

代价是云盘要自带一层 NavigationSplitView 外壳。这笔账换来的是：紧凑窗下 只有一条导航栈（文件夹下钻和文件预览都走它），宽窗下左边浏览、右边预览，折叠与展开不重置 当前位置。这是本设计里唯一必须实测的一处，见 §11。

2范围与取舍

桌面端的云盘由三层构成：浏览器（列表 / 上传 / 下载 / 新建 / 改名 / 移动 / 删除 / 预览 / 简介）、 分享层（分享链接、网页分享、公开素材）、同步层（本地文件夹绑定、冲突解决）。 手机端的取舍按这三层划分。

2.2 不做的

能力不做的理由
本地同步 / 绑定 / 镜像 / 挂载 用户已明确排除。另外这一层的前提是「本地有一个稳定路径」，iOS 沙盒里没有与桌面端 ~/Documents/项目 等价的东西，绑定的另一端无处安放。
文件夹上传（整棵子树） iOS 的文档选择器没有自然的「选一个文件夹」入口；服务端的文件夹上传上限是 1000 文件 / 12 层，这样的长任务在移动网络上不可控。多文件上传已经覆盖真实需求。
网页分享（Site）创建与管理 Site 的工作流是「在电脑上备好一套静态产物，再发布出去」。手机上既没有产物目录， 也无法在千文件级别的预检里做决策。分享链接已覆盖绝大多数分享需求。
版本历史 桌面端的界面里也没有这个入口（只有 MCP 有）。服务端版本是全量拷贝， 逐个下载到手机的流量代价与收益不成比例。
在线编辑 桌面端界面同样没有内嵌编辑器。改文件属于「在电脑上或浏览器里做的事」， 手机端只读预览。
云盘搜索 服务端 GET /api/drive/items 没有 search 参数；唯一支持全量的 /items/tree 是递归整棵树。做「只搜当前已加载那一页」的搜索是假的，会在 用户以为搜了全盘的时候漏掉东西。等服务端补上搜索参数再做，见 §11。
网格 / 缩略图视图 服务端没有缩略图端点。网格视图只能画类型图标，那不是「文件」App 的网格， 只是一个更大的列表。补上缩略图端点后才有意义。
文件复制 服务端没有 copy 接口，桌面端也没有这个功能。
后台续传 上传地址有效期 15 分钟，而后台 URLSession 需要一套可持久化的任务队列与 URL 续签。本期做前台上传 + 进度 + 失败重试，把「切后台就断」如实告诉用户。
离线缓存 / 收藏 / 最近 / 标签 服务端没有对应的数据模型。造一个本地的「收藏」会与桌面端分叉。
新增深链 docs/agents/capability-registry.md 规定 iOS 深链计数保持不变。

2.3 排序为什么放在本地

服务端列表的排序是写死的 [type asc, createdAt desc]，不接受参数。手机端因此 在已加载的范围内排序。这与分页配合时会有一个诚实的边界：加载第 2 页后，第 1 页里 按新排序本该靠前的项不会自己浮上来。

处理方式：把排序做成视图偏好而不是数据查询，并在加载更多时保持同一份排序函数作用 于追加后的完整数组。默认值「文件夹在前 + 名称升序」与服务端的自然顺序一致，所以默认状态下 不会出现这个偏差；用户主动切成「按大小」时偏差才可能出现在跨页处。这一条写进 §11 的待办： 服务端加上 sort / order 参数后改为服务端排序。

4逐屏规格

4.1 入口 · 主页功能行

在「录音」与「新建会话」之间插一行，副标题「服务端上的文件」，不带右侧值（用量太长， 放进去会把这一行撑成两行），恒可用（云盘是纯服务端能力，与「有没有电脑在线」无关）。

行副标题右侧值点击可用性
录音会议录音、转写与回听录音条数换这一格为录音页恒可用

4.2 云盘主屏

自上而下：大标题「云盘」→ 面包屑（深度 ≥ 2 时出现）→ 内容列表 → 底部入口。

  • 导航栏：左「返回主页」（紧凑窗）；标题居中显示当前文件夹名；右「···」菜单 （新建文件夹 / 上传文件 / 排序 / 选择 / 全部刷新）。
  • 面包屑是一行可横向滚动的按钮，点任意一级直接跳过去。深度 0 和 1 不显示—— 只有一层时它就是重复的标题。
  • 列表：文件夹在前，然后按当前排序。行高 52pt（≥ 44pt 命中区）， 左图标 29pt，名称一行，副标题一行（文件=大小 · 修改时间；文件夹=修改时间）。
  • 上传中的项作为一个独立分组显示在列表顶部：文件名 + 进度条 + 百分比 + 取消按钮。与「文件」App 把进行中的操作顶到最上面一致。
  • 列表末尾两个入口行：回收站（副标题「N 项」，为 0 时不显示值）、公开素材。
  • 列表最底部一行用量：「已用 1.24 GB / 5 GB」，右对齐、次要色、不可点。
  • 滚动到底部自动加载下一页；已加载完且还有更多时显示「载入更多」按钮兜底。

4.5 分享

表单三段：有效期（3 天 / 7 天 / 30 天 / 1 年 / 永久，默认永久）、密码（开关， 默认关）、访问权限（仅阅读 / 登录后可编辑 / 指定邮箱可编辑，默认仅阅读）。

创建成功后弹结果页，两行链接各自带「拷贝」：链接与带密码链接；密码本身 单独一行可拷贝。已有活跃分享时不再重复创建，直接进结果页并提示「链接未变」。

指定邮箱可编辑是唯一需要输入的地方，用一个逗号分隔的多行输入框，提交前按逗号 / 空格 / 换行切分并去重。

4.6 回收站

列表按「移入时间」倒序，行副标题显示「原路径 · 移入时间」——恢复时要知道它会回到哪去。 两个动作：恢复到原路径、从回收站移除（后者不可撤销，红色，二次确认）。公开素材的回收站 条目用同一份列表，只是恢复走另一条接口。

4.7 公开素材（直链）

它是人可读的扁平列表（服务端规定公开素材是平铺的、允许重名），所以不做文件夹。 行副标题显示「访问 N 次 · 最近访问时间」。工具栏的 ＋ 走与云盘上传同一套通道， 只是 prepare 换成 /public-assets/uploads/prepare。上传后直接给出 /files/<assetId> 直链。

4.8 显示简介

一个 sheet，五行：名称、种类（带扩展名）、大小、修改时间、位置（完整路径，可长按拷贝）。 有活跃分享时追加一行「分享」→ 点进去到分享结果页。

5.2 多选

工具栏「选择」进入编辑模式。行的左侧出现选择圈，底部换成一条工具条：左侧计数 （「已选 3 项」）+ 右三个动作 移动 / 导出 / 删除（未选任何项时全部置灰）。 导航栏左侧变成「完成」，右上「全选 / 取消全选」。

服务端没有批量接口，批量动作逐个调用单条接口并逐项报告结果：成功的从列表移除， 失败的保留选中并在 notice 里汇总「3 项删除成功，1 项失败」。不做「全部成功才生效」的原子语义—— 那会让一次网络抖动把 20 个已经成功的操作回滚掉。

5.3 上传

  1. 选来源：文件（系统文档选择器，可多选）、照片、拍照。 三个 picker 已经存在（Features/Terminal/TerminalFilePicker.swift），直接复用。
  2. 每个文件：POST /api/drive/uploads/prepare → 拿到预签名 PUT 地址 → FileUploader 上传并回报进度 → POST /uploads/:sessionId/complete。
  3. 同名处理：prepare 的响应里带 overwrite 字段。非空时先确认 「已存在同名文件，上传将覆盖它」，确认后带 expectedItemId 重发 prepare。 字段缺失（旧服务端）时按「未知」处理，不阻断。
  4. 并发上限 2 个，避免在移动网络上互相抢带宽。任一项失败可单独重试， 不重试其他已成功的项。
  5. 取消：调 /uploads/:sessionId/cancel 释放预留的配额。
切到后台会断。上传地址 15 分钟过期，且本期不用后台 URLSession。 离开 App 超过系统给的后台执行窗口后，进行中的上传会失败并停在列表里等重试。 这一条必须写进 RELEASE_NOTES_PENDING.md。

5.4 下载与导出

只有一个动作：系统分享面板。「存储到文件」是面板里的一个动作，所以不需要单独做一个 导出按钮。单个文件与多选都走同一条路：先把字节下到临时目录，再把文件 URL 交给面板。

下载必须自己带 Bearer，不能把 URL 交给系统。 owner 下载路由是 GET /drive/items/:id/download，在 /api 前缀之外， 且需要 Authorization 头。所以不能交给 AsyncImage、 QuickLook 的远程模式或 SFSafariViewController—— 它们加不了自定义头。先用 URLSession + header 下到临时文件，之后一切都用本地文件。

文件夹走同一个路由，服务端自动打包成 zip 返回。是否提供这个动作看浏览器快照的 canZip；下载前用行内提示说明「文件夹会打包下载」，避免用户以为要等很久却没反馈。

7.2 分层

照录音模块的范式：Models（Decodable 结构体 + DriveText 纯函数）→ Store（@MainActor @Observable，方法显式收 using client: APIClient）→ View（列表 / 预览 / sheet）。网络由 SynapseAppModel 透传，不新建第二套连接。 错误统一走 model.notice(...)，破坏性操作走视图内 .alert。

不用 UIDevice.userInterfaceIdiom 判断宽窄——用 @Environment(\.horizontalSizeClass)，这是布局规则明确允许的判据之一。

7.3 六个必须知道的坑

坑说明与处理
下载路由不在 /api 下 AppConfiguration.apiBaseURL 是 https://synapse.d2.pub/api， 而下载是 https://synapse.d2.pub/drive/items/:id/download。需要新增 apiOrigin（去掉尾部 /api），照 liveMobileURL 的既有做法。
Bearer 进不了 URL 下载与预览必须用 URLSession + Authorization 头下到临时文件。 参考 APIClient.downloadMeetingAudio(from:to:) 的既有实现。
size 是字符串 服务端是大整数，DTO 里是 string。解码成 Int 会在大文件上崩， 用 Int64(size) 并在失败时回落为 nil。
上传地址 15 分钟过期 PUT 收到 401/403 时重新 prepare 一次再传，不要直接报失败。重试只做一次。
overwrite 字段可能缺失 旧服务端不返回它。缺失 = 未知，不阻断上传、不弹覆盖确认。
紧凑窗下的嵌套折叠 NavigationSplitView 的 sidebar 里有一层 NavigationStack， 紧凑窗折叠后两者共用一个栈。这是本设计唯一必须实测的一处，见 §11。

7.4 RootView 的最小改动

现在 homeTab 用 homePath.last == .recordings 一个布尔量决定 「换这一格内容」还是「走栈」。云盘加入后它变成两个判据。最小改动是把这一段收敛成一个 「这一格当前该显示哪一页」的 switch：

enum HomeRoute: Hashable { case recordings, clipboard, drive }

@ViewBuilder
private var homeTab: some View {
    switch homePath.last {
    case .recordings: recordingsPage
    case .drive:      drivePage          // 与 recordingsPage 同构：整格归它所有
    default:
        NavigationStack(path: $homePath) { HomeView(...) .navigationDestination(...) }
    }
}

云盘页自带「返回主页」按钮（落在浏览列那条栏上，与「···」同一行），行为与录音页一致： 调 popToRoot(.home)。切页动画的触发量也要从单个布尔量改成 「当前是不是功能页」，否则推入剪贴板历史那一下会被这条动画接管。

10.1 单元测试（SynapseMobileTests）

  • DriveText：字节格式化边界（0 / 999 / 1000 / 1.5 GB）、日期相对文案、 扩展名 → 种类的映射表逐项、超长扩展名截断。

10.2 行为验证（SynapseMobileUITests）

  1. 主页 → 云盘 → 下钻三层 → 面包屑回跳到第二层 → 返回主页，位置与滚动保持。
  2. 长按行 → 重命名 → 列表出现新名字；再重命名回原名（避免污染测试账号）。
  3. 新建文件夹 → 删除它 → 回收站里能看到 → 恢复 → 回到原位置。
  4. 左滑删除一条 → 二次确认 → 消失；回收站里出现，原路径正确。
  5. 多选两项 → 移动到一个文件夹 → 目标文件夹里能看到。
  6. 分享一个文件 → 结果页出现 /share/ 链接 → 停止分享 → 行尾的分享标记消失。
  7. 上传一个测试文件 → 进度到 100% → 列表出现它 → 下载导出到「文件」App。
  8. 断网（Network Link Conditioner）下进入云盘 → 错误态与重试可用；恢复网络后重试成功。
  9. 窗口：iPhone 竖 / 横、iPadOS 全屏横 / 竖、半窗、1/3 窗、浮窗全走一遍， 确认折叠与展开不重置当前文件夹与多选。

11风险与待实测

风险影响应对
紧凑窗下 sidebar 与内层栈的折叠关系 可能出现两条导航栏，或返回手势把用户带回错误的层级 模拟器上实测 iPhone 竖 / 横与 iPadOS 半窗、1/3 窗。不成立就回退： 紧凑窗下不叠 NavigationSplitView，直接用单列 NavigationStack， 预览改成 sheet。两列并排只在 regular 宽度下启用
跨页排序的偏差 用户切「按大小」后，第 2 页加载时第 1 页顺序不重排 默认排序与服务端一致所以不触发；文档写明；服务端补 sort 参数后改为服务端排序
竖屏下预览列丢失 iPadOS 竖屏 + 半窗时右侧空间不足 宽度阈值保守取值（预览列 < 320pt 就折叠），宁可多折叠一次
大文件预览的等待 几百 MB 的文件下载后才能看，用户以为卡住 预览前显示已下载字节与进度，可取消；超过 50 MB 先问一句
上传中断的挫败 切后台失败没有任何预见 上传开始时就写清「离开 App 会中断」；失败项留在列表里可重试；写进待发布说明
云盘入口的可发现性 主页功能行从 3 行变 4 行，云盘排在第二 副标题「服务端上的文件」明确它的范围；不置灰，保证任何时候都能进
后续可做（本期不做，已论证） 云盘搜索（等服务端 items 加 search 参数）、网格与缩略图视图 （等缩略图端点）、版本历史（等桌面端界面先有入口）、网页分享 Site 管理、 后台续传（需要可持久化的上传任务队列）。
