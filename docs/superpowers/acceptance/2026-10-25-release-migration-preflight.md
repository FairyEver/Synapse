## 2026-10-25 隔离 PostgreSQL 预演

使用本机 PostgreSQL 16.15，在新建的临时数据目录中启动仅接受私有 Unix socket 连接的数据库。没有连接生产库，也没有读取生产数据或凭据。

1. 执行本次两项迁移之前的全部 86 项迁移，建立旧版完整结构。
2. 插入一个虚构用户和四条通知，覆盖已读/已删除状态、站内信原始链接、自定义分组、用户 URL、其他来源及空链接。
3. 用 `pg_dump` 备份旧库，再用 `pg_restore --exit-on-error` 恢复到另一个隔离库。
4. 在恢复库应用 `20261023000100_mail_internal_namespace` 与 `20261024060000_add_user_contact_email`。
5. 逐字段比较迁移前后的通知和用户记录：只有匹配的来源、分组和系统链接发生预期变化；投递去重键、已读/删除/创建时间及其他字段完全相同。新增联系邮箱为 null，已有用户字段不变。
6. 重复执行命名空间更新，结果不变；通知投递去重的唯一索引仍在。最后正常停止临时数据库。

结果全部通过。命令日志保存在本机 `/tmp/synapse-review-r4-postgres.log`。正式部署仍须由 `deploy.sh` 对当时的生产备份执行恢复预演、最终备份和恢复验证；本次虚构数据预演不能替代这些步骤。
