# Agent MCP 设置实机验收

2026-10-24 用户明确授权启动应用、操作本机设置、新建测试对话及核对实际请求。使用当前工作区的 `pnpm dev:desktop`，没有切换分支、创建 worktree 或发布应用。

## 证据方法

通过 Electron 真实窗口操作设置和对话，使用现有 DeepSeek Provider。临时将该 Provider 的 SY 请求地址指向本机回环转发器，再以 HTTPS 转发至原端点；请求正文原样转发，认证头仅在内存中转发，不记录。记录的是实际 HTTP 请求正文的脱敏副本，不是根据启动参数推算的工具列表，也不把 SDK StreamEvent 当作原始 SSE。

本机证据位于仓库忽略目录 `work/agent-mcp-e2e/`：`evidence.json` 保存请求元数据，`wire-summary.json` 归纳正式推理请求，`<序号>-<阶段>-request.json` 保存脱敏正文。请求原始字节长度和 SHA-256 在脱敏前计算，避免将重排后的 JSON 当作原始字节。标题生成和 `/count_tokens` 请求单独存在，未计入下表的正式推理工具数。

创建了 3 个 `E2E-MCP-20261024` 测试对话，共 6 轮消息；第一个基线回合进行了只读 SY 工具索引搜索，之后均要求直接回复固定标记。没有发送邮件或外部消息，没有要求模型读取业务文件。

## 实际结果

| 操作 | 请求序号 | 正式请求工具数 | 实际结果 |
| --- | --- | --- | --- |
| Chrome、REA 等开关开启，新建对话 A | 2、3 | 58 | 27 个基础工具、29 个 Chrome 工具、2 个 SY 路由工具 |
| 关闭 Chrome、REA，继续对话 A 的 B 回合 | 24 | 29 | Chrome 定义全部消失，A 回合历史仍在请求中 |
| 维持关闭，新建对话 C | 46 | 29 | 新对话从第一轮就不含 Chrome 定义 |
| 重新开启 Chrome、REA，关闭 SY Figma，继续对话 C 的 D 回合 | 67 | 58 | Chrome 的 29 个定义恢复，C 回合历史保留；Figma 不再进入发现状态清单 |
| 修复诊断后，仅开启 Chrome、REA，新建对话 E | 89 | 58 | 关闭的 SY 连接器不再被误报为不可用 |
| 全部可选 MCP 关闭，继续对话 E 的 F 回合 | 110 | 29 | 发现状态只剩 `synapse-mcp`，正式请求只保留基础工具与 SY 路由，E 回合历史保留 |

上述 7 次正式推理 HTTP 请求均返回 200，界面显示预期回复。关闭 Chrome 实际移除了 20,454 字节的工具定义；请求总大小还受历史消息影响，不能用总字节差冒充固定节省量。各阶段系统提示正文为 45,213 字节；排除 SDK 自身变化的 billing attribution 后，系统提示内容哈希一致，未因开关清除规则或系统上下文。

全部可选 MCP 关闭后的实机发现阶段约为 0.7 秒，未关闭时因存在 pending 服务约为 5.6 秒。这是该次本机观测，不是性能承诺或多次采样的统计结论。

搜索、刷新、重新进入页面、切换默认工作区/Synapse 项目范围均实际操作；关闭状态在刷新和开发进程重启后保留。内部 SY 开关保持只读。

## 发现与修复

关闭 SY Figma 后，原实现仍将其放入“预期连接”清单，虽然 SDK 已正确禁用它，日志仍报 `expected-server-unavailable`。修复为从预期清单中排除 SDK settings 中按名称拒绝的服务器；原有拒绝策略仍传入 discovery 和正式查询。新增两个回归用例分别覆盖显式预期名称和从配置推导名称，两例先复现失败，修复后通过。实机复测中预期清单为空，未再出现这条误报。

## REA 的验证边界

REA 开启时，本次 SY 发现阶段多次显示 `pending`，超过既有 5 秒期限后按现有规则跳过；关闭后，它从发现清单中消失。单独使用同版本原生 SDK 初始化同一本机 REA，约 4.9 秒才连接，独立 stdio 初始化约 2.3 秒。此处能确认开关控制了发现和加载，但不能宣称本次实际请求曾完整加载 REA 的工具 schema，也不能据此给出关闭 REA 节省多少 token 的结论。未通过延长全局期限掩盖该启动边界；开启状态仍表示 SY 未额外禁用，不等于服务器已连接。
