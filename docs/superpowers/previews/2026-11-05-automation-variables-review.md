# 自动化变量入口原型评审

日期：2026-11-05。状态：待评审的 HTML 交互原型，不是已实施的产品规格。

原型：[自动化变量](./2026-11-05-automation-variables-prototype.html)。直接打开本地文件即可，无网络资源和构建依赖。示例数据不连接实际账号或自动化服务。

## 现状与问题

- `desktop/src/modules/automation/editor/trigger-executor-builder.tsx` 将触发器 manifest 的变量交给左侧查看组件，同时通过 `triggerVariables` 传给执行器配置表单。
- `desktop/src/modules/automation/editor/trigger-variables-dialog.tsx` 虽然保留 Dialog 命名，当前实际是内联展开。分组、搜索、变量路径与复制操作占据触发面板高度。
- `desktop/src/action-runtime/action-prompt-field.tsx` 又维护一份搜索列表，通过 Popover 在提示词光标或选区插入。Agent 与 Claude Code 配置复用该字段。
- 这两个入口的意图有区别：一个了解触发器产出，一个在具体字段中使用。需要消除的是重复的重型展示和两套目录实现，不是删除其中一种意图。

## 提案

触发器标题右侧只保留一个 `fx` 图标按钮，辅助名称及悬停提示为「查看触发变量」。不再在配置卡中展开目录，不常驻变量数量。配置收起后仍可查看；没有配置表单的站内信触发器也保留入口。

提示词框底部工具栏末端提供 `fx 插入变量`。从字段发起，插入目标明确，不需要全局判断最近聚焦的输入框。项目、供应商、模型、权限及数值控件不出现变量入口。

两个入口打开同一变量窗口：

| 项目 | 查看模式 | 选择模式 |
|---|---|---|
| 标题 | 触发变量 | 插入变量 |
| 上下文 | 来自哪个触发器 | 触发器来源与目标字段 |
| 静态变量行 | 复制完整模板，保留窗口 | 插入完整模板，关闭窗口 |
| 动态变量行 | 展开路径输入后复制 | 展开路径输入后插入 |
| 焦点恢复 | 查看入口 | 原输入框及光标 / 选区 |

沿用现有事件内容、触发信息、触发器配置分组。邮件和 Webhook 默认展示事件内容，定时默认展示触发信息；「全部」可查看完整目录。使用横向分组按钮，避免在弹窗内再建立一套重型侧栏。搜索匹配当前分组下的名称与完整变量路径；无结果提供清除筛选操作。

静态变量点击即完成，不增加「选中，再确认」的额外步骤。模板保持可读的 `{{trigger.xxx}}` 文本，不引入 chip 编辑器或公式编辑器。动态路径可选，留空引用现有基础变量；填写时预览最终模板，路径字符与现有运行时正则保持一致。复制失败明确提示并选中模板供手动复制。

## 对现有架构的约束

变量仍由 `AutomationTriggerManifest.variables` 声明。当前目录元数据包含 key、label、group、dynamic，以及可选 description、example，不是一套完整的运行时白名单。原型未虚构实时值或试运行数据：邮件 18 项、站内信 15 项、Cron 8 项、Webhook 23 项均对应当前声明。

`desktop/electron/action-runtime/template-variables.ts` 仍在执行时构造字符串变量表并替换模板。对象可序列化为文本，嵌套字段使用点路径；本提案不增加表达式求值、自动转义、上游节点或工作流绑定。

正式实现建议将共用变量窗口放在 `desktop/src/action-runtime/`，由左侧触发器组件和 `ActionPromptField` 薄组合调用。继续使用现有 shadcn/Radix 的 Dialog、Button、Input 和滚动组件；来源仍通过现有 props 传入，不新增 IPC、持久化或服务。原型为了独立打开使用原生 HTML 控件和同源主题 token，未把它们作为新的生产组件体系。

首次只替换现有查看入口与提示词插入入口。后续命令、脚本或 HTTP 文本字段可按其已支持模板替换的范围接入同一窗口，不因输入框较大就默认支持变量。不得将 fx 注入所有 Input/Textarea 或全局监听输入框。

更换触发器时继续保留执行草稿、更新目录，并检查被替换触发器声明过而新触发器不再提供的引用。不得因目录元数据不全而否定既有运行时变量。

现行 `2026-11-05-automation-inline-editor-design.md` 规定左侧内联展开，本原型根据用户本次要求提出替代方案，尚未修改该生产规格。实施时需同步更新该规格与对应 UI 规则；本次不提前将待评审提案改成长期产品约束。

## 原型范围与验收

保留现有白色标题区、浅灰工作区、左右配置面板、独立附加条件和随内容滚动的保存区；窄窗口上下排列。提供邮件、站内信、Cron、Webhook 和未选择触发器场景，浅深主题、查看 / 复制 / 选择 / 动态路径、无搜索结果、切换触发器与失效引用反馈。

评审时重点体验：左侧查看不改变配置区高度；在提示词中定位光标或选中文字再插入；取消不改变原文；Webhook 引用整体与指定子路径；复制失败；窄窗口的展开弹窗；键盘与焦点恢复。

未改生产代码、调度、权限、存储、MCP 或 Skill 契约，未执行保存、启用、部署和真实邮件操作。仅创建评审文件，因此无需向用户发布说明中加入尚未实施的功能。
