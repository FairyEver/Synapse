# 卡牌游戏覆盖层实施计划

**Goal:** 将已确认的卡牌舞台原型接入正式牌桌，提供八类通用选择，替换卡牌 HeroUI 弹窗。
**Architecture:** 复用 `usePokerCards`、服务端 choices、报价和待选协议；表现适配器只整理获准数据。覆盖层挂载在牌桌根节点，不改变画布。系统管理及 Roll 面板保持原组件。
**Tech Stack:** React、TypeScript、现有 CSS / 本地插画、Vitest / jsdom、现有隔离 Vitest Browser。
**Spec:** `docs/prototypes/2026-11-03-poker-card-selection-design.md` 和同目录 HTML；用户要求“按照这个实施吧”。

## Global Constraints

- 当前仓库、当前 main 实施，不新建分支或 worktree；不加依赖、不操作真实牌局或数据库。
- 使用八类通用选择，不按卡牌 ID 编写流程，不复制原型模拟引擎。
- 顶底固定、左卡固定且居中，只有右侧详情纵向滚动；窄屏继续左右布局。
- 只有 hover 抬牌；不自动聚焦、不恢复焦点、不增加键盘快捷键或焦点陷阱。实际选中只静态标记。
- 明确确认才写入；不乐观扣费、不以已捕获错误的 Promise 解决代表成功；恢复原请求与隐私隔离不变。
- 游戏更新不进入发布说明。完成必要验证后仅提交本次改动，不 push。
- 用户已允许隔离浏览器测试；使用固定数据，不连接真实对局。

## Review Focus

- 服务端选项撤回、同名实例、不可主动施放的材料、猜色依赖、只有一张候选与待选关闭重开。
- 请求迟到、账号/房间/手/控制/行动点切换、报价变化与未知结果，不能泄漏或重放旧上下文。
- 窄屏及矮横屏展开几何、右侧唯一纵向滚动、无焦点抬牌、减少动态效果、画布不重新挂载。
- 公共状态/历史与本人情报仍可访问，暗牌和私密结果不进入公开 DOM；不渲染原始 UUID。
