## 约束与任务

1. 补充可选公开 `handLog` 投影及严格响应 schema。按本手快照身份合并实际盲注、下注与成功 Roll start；choose 只完成原记录，不重复计费；不公开账号、入座 ID、旧牌、候选、判断或提示词。热/归档一致。查询绑定当前 handId，最多1000条原始动作；超过或有缺口时显式标记不完整，不能拿尾部计算全手总览。保留原 recentActions 最近30条与本人 AI 隐私。
2. 先写服务/协议回归并运行失败，再实现；覆盖盲注短筹码、Roll start/choose/重抽、排序、归档、截断、身份和私密字段。
3. HeroUI 三 Tab 面板，默认日志仅按阶段显示公开行动，标明实际追加或 Roll 支付和次数。总览用完整 potContributions / rollLedger 显示整手及逐人合计、普通/超级次数、补偿、按轮次拆分和已有完整结算；缺数据明确不可用，不推算成零。AI 页仅本人可看判断/提示词，其他视角显示不可用。
4. 更新 Table 入口和关闭标签，维持面板互斥、画布不重挂、焦点返回和850px行为；身份/房间/手牌/视角变化重置页签上下文。正文单独滚动，头部保留标题及 Tab。
5. 补充交互回归，调整现有入口与结算定位测试；运行扑克专项、shared schema、Dashboard/Server类型与UI边界检查。同步游戏规则、MCP描述/schema、系统Skill/Agent指南，注册数量不变。审查后只提交本次修改。

## 验收

- 日志无累计指标、资产行、玩家汇总或结算摘要，Roll 与下注按同一 seq 排列，盲注精确，choose 不重复。
- 总览不从 recentActions 或事件缓存算整手；同座换人沿用本手原姓名与身份；缺字段与零值区分；补偿状态区分待结算/到账/取消。
- 三个 Tab 始终按既定顺序；AI 私密内容不因视角或入座变化泄漏。旧响应可展示标为不完整的最近下注；不混入上一手事件。
- 验证仅使用测试夹具；未经用户明确要求不启动浏览器，实际展开视觉验收如实标记未执行。
