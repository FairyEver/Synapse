# 云盘同步批量读取

用户已确认直接实现批量条目、父目录和增量变更查询；保留独立游标、单项错误及写入版本校验，不做哈希优化。在当前 main、当前目录执行。

## 接口与边界

- `POST /api/drive/items/batch`：最多 100 个去重条目 ID，返回每项的条目、完整父目录链、当前版本与 ETag，失败按项返回；不暴露 storage key，不跨账号读取。父链按层共享查询并限制深度和总节点数。
- `POST /api/drive/changes/batch`：最多 20 个独立请求，每项携带唯一 requestId、rootItemId、cursor、rootPathHint 和最多 100 条变更的 limit。返回每项的 page 或错误；游标过期、分页、移出原目录和部分失败沿用已有语义。服务端合并查询，不循环调用单项 HTTP 或单项 list。
- 桌面完整批次校验身份、条目 ID、缺失/重复结果后再使用。只读快照仅在当前同步检查阶段有效，不能作为覆盖/删除前的新鲜读取。
- UI 使用私有的同步批量条目 IPC；不新增公开 MCP capability、Workflow、Automation 或 Deep Link。

## 执行步骤

1. 共享 DTO、服务端批量条目与变更查询，先建立权限、父链、独立分页/游标/错误回归，再实现接口。
2. 集中账号客户端接入分块批量读取、限流等待和响应校验；普通单项读取继续保持最新状态。
3. 同步引擎集中预取有效同步根，复用首个变更页及本轮根状态，后续分页合并；取消和账号切换不消费旧结果。对齐检查批量读取前后元数据与版本，保留逐文件下载哈希与服务端写入预条件。
4. UI 批量读取父链、接入私有 IPC，补齐能力清单例外、同步设计、Skill 指南和待发布说明。
5. 运行服务端/桌面专项测试、类型检查、IPC 生成一致性及架构约束；复核 diff 后只提交本任务。

## 验证重点

- 16 个空闲同步根使用一批条目和一批变更，不再逐根单项读取。
- 一根失败不推进它的游标，其他根仍继续；分页和过期各自处理。
- 外部账号、缺失条目、父链环/缺失、异常响应不能变成本地删除。
- 覆盖前版本变化仍拒绝执行；哈希与冲突保护不变。
