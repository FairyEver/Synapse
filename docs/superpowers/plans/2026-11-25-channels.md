# 频道（Channels）v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Synapse's credential-authenticated realtime event relay **频道（Channels）v1** across `@synapse/shared`, `server/`, `dashboard/`, `document/`, and `desktop/` (MCP + System Skill).

**Architecture:** A single-instance NestJS `ChannelsModule` persists `Channel`, `ChannelToken` (`syc_...` SHA-256 hashed), and `ChannelRetainedEvent` (up to 20 keys/channel) in PostgreSQL while an in-memory `ChannelHub` manages active WebSocket connections, Presence, hidden Console observers, a 100-item / 5-minute broadcast ring buffer, rate limiting, and slow-consumer protection. Clients connect via native WebSocket (`/api/open/v1/channels/:channelId/ws`, first-frame `auth` or Upgrade Bearer header) or publish statelessly via HTTP POST (`/api/open/v1/channels/:channelId/events`), reusing `UserApiKey` with new `channels.*` scopes and channel resource scoping; Dashboard Console, OpenAPI docs, and 12 desktop MCP tools expose the three product surfaces.

**Tech Stack:** TypeScript 6, NestJS, Prisma (PostgreSQL), `ws`, Zod, HeroUI v3 + React 19 + TanStack Router/Query, VitePress, Electron 44 MCP capability registry, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-25-channels-design.md`

## Global Constraints

- Product Chinese name is **频道** across Console nav/titles, OpenAPI docs, API Key capability labels, MCP descriptions, and `RELEASE_NOTES_PENDING.md`; English/code identifier is `channels` / `Channel`.
- Runtime Open API (`/api/open/v1/channels/...`) and Open WS (`/api/open/v1/channels/:channelId/ws`) MUST ignore cookies and SY login JWTs; never authenticate via URL query parameters.
- Existing `UserApiKey` records MUST NOT implicitly gain `channels.*` scopes; default `channelAccessMode = "selected"`, `channelIds = []`; only `all_owned` + `channels.manage` may create channels via Open API.
- No server-side `Idempotency-Key` receipt table, no persistent event history, no channel trash bin, no cross-account channel collaborator ACL, no Cloud Table / Workflow / Automation linkage, no new Desktop System App / Dock / Deep Link.
- Limits: event payload `<= 64 KiB` UTF-8, WS frame `<= 128 KiB`, HTTP POST body `<= 128 KiB` (Nginx `256k`), `meta <= 2 KiB` UTF-8, max 20 active tokens/channel, max 20 retained event names/channel, 100 production connections/channel + 5 Console debugger observers/channel, 300 connections/account, 2000 global connections, WS auth timeout 5s, heartbeat 25s (2 missed = disconnect), slow-consumer threshold `bufferedAmount > 512 KiB`, rate limits 10/s (burst 30) per WS and 30/s (burst 60) HTTP POST per channel.
- Desktop code MUST pass `pnpm --filter @synapse/desktop run check:hard-constraints`; no `console.log` in production code; Dashboard UI MUST follow `dashboard/CLAUDE.md` & `dashboard/DESIGN.md` (HeroUI v3, no literal colors, no nested cards).
- Sensitive access logs disabled in both `server/src/app.module.ts` (`hasSensitiveRequestUrl`) and `server/nginx.conf` (`access_log off`).

## Review Focus

1. **Multi-byte UTF-8 size boundaries (`payload <= 64 KiB`, `meta <= 2 KiB`)**: CJK payloads whose JS `.length` is under 65536 but UTF-8 byte length exceeds 65536 MUST be rejected (pinned in Task 1).
2. **URL query token rejection on WS upgrade (`?token=...` / `?access_token=...`)**: Upgrade requests carrying credentials in query parameters MUST be rejected with HTTP 400 / WS `4001` rather than silently accepted or ignored (pinned in Task 5).
3. **Retain overwrite at the 20-key ceiling**: When a channel already stores 20 retained event names, overwriting an existing event name MUST succeed while inserting a 21st distinct event name MUST fail with `RETAIN_LIMIT_EXCEEDED` (pinned in Task 4).
4. **Slow consumer or broken socket during fan-out**: A subscriber with `bufferedAmount > 512 KiB` or a failing `send()` MUST be disconnected with `4008` without aborting delivery to healthy subscribers in the same broadcast (pinned in Task 3).
5. **Desktop MCP account change mid-request**: Switching or logging out of the desktop account while an `app_channels_*` call is in flight MUST abort and return `CHANNEL_ACCOUNT_CHANGED` without leaking data across accounts (pinned in Task 8).
