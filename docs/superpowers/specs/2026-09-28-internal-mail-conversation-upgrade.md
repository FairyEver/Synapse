# 站内信往来体验升级

> 2026-09-28 补充：后续组织收件人能力将发送格式升级为 v3，支持多级组织动态展开、移除 50 人上限，并从桌面、iOS 与 MCP 指南移除回复全部。本文的 v2 格式和回复全部描述仅适用于该次升级；现行边界以 `docs/agents/module-boundaries.md` 为准。

本设计取代 `2026-09-27-internal-mail-design.html` 中关于「不提供抄送」及回复、转发、会话数据的首版约定。站内信仍只在同团队具体账号间投递，不接入外部电子邮件。

## 产品行为

- 收件箱和已发送箱仍逐封列信。列表标出回复或转发；详情分别显示发件人、To、Cc、正文、附件和关联往来。
- To 至少一人；To/Cc 合计最多 50 位，不能重复或包含发件人。回复仅预填原发件人；回复全部保留原 To/Cc 分组、加入原发件人并排除自己。对本人已发送信件回复时，以原 To 为新的 To；回复不自动附原附件。
- 回复写信时展开直接来源信的只读引用；发送后在详情默认折叠。转发清空 To/Cc，可不写附言，默认选中原信附件且可移除。原信的发件人、To/Cc、时间、主题和直接来源正文由服务端固定为不可变快照。更早的引用不递归复制，避免正文随轮次膨胀。
- 回复继承原往来；转发开启新往来。往来中只显示本人仍有权查看的信件，点击某一封才将那一封设为已读。原信被隐藏后，新信中的引用快照仍可阅读；转发收件人不会因为该引用获得原信读取权。
- 发送失败保留写信内容与附件选择；预览过期、团队成员变化、原信或附件失效均要求重新预览。通知发给 To/Cc 的并集，继续只含安全摘要。

## 服务端契约

- `POST /api/mail/send-previews` 使用 `formatVersion: 2`、`toIds`、`ccIds`、`subject`、`body`、`attachmentIds`、`forwardAttachmentIds` 和可选 `relation: {kind: "reply" | "forward", messageId}`。旧请求得到 426 更新提示。预览返回分组收件人、完整引用、附件及团队。最终发送仍用 `previewId` 和 `clientRequestId`。
- `GET /api/mail/messages` 保持逐封分页；摘要追加分组收件人与操作标识。`GET /api/mail/messages/:id` 追加往来标识、来源和引用快照。`GET /api/mail/messages/:id/context?cursor` 按发送时间分页，仅返回当前账号仍可见的同一往来信件。
- 收件记录存 To/Cc 角色；信件存往来标识、回复或转发来源和引用快照。预览固定这些值。回复、转发在预览及发送事务内按当前账号读取权和原信团队复核，发送时重新确认全部成员有效。
- 转发附件在预览阶段从站内信对象存储复制到当前发件人的待发对象，和本地新增附件共用 10 个上限；失败副本走持久删除队列，未发送副本沿用七天清理。绝不从云盘复制附件。

## 三端与 AI

- 桌面端沿用 System App 三栏与 shadcn 主题；iOS 沿用主页入口、`AdaptiveFeatureNavigation` 和系统写信 sheet。窄窗、宽窗共用数据和选中信件 ID；引用使用可折叠的只读区域。
- MCP 新增 `app.mail.context.list`；现有预览工具升级为 v2 输入。系统 Skill 必须把 To/Cc、全文引用及实际附件纳入对话确认，`confirmed: true` 仍不构成服务端验证的用户确认凭证。
- 旧客户端可继续读取新信；旧格式发送预览得到更新提示，防止写入语义不完整的信件。
- 在服务端正式切换前，连接旧服务端的新版桌面与 iOS 客户端可展示旧信：旧收件人归入 To，Cc 为空，不从旧 `replyToId` 猜测回复或转发。旧服务端不提供关联往来或新版发送语义，完整功能仍以服务端切换为前提。

## 正式环境切换

1. 先完成数据库与 `mail/attachments/` 对象备份并验证可恢复，预演迁移。暂停站内信写入，完成服务端迁移。
2. 在新格式信件写入前，仅执行一次 `server/scripts/purge-legacy-mail.sql`。它仅清理所有账号的旧站内信、待发预览、站内信来源通知和附件元数据；附件对象进入持久删除队列。脚本发现新格式信或预览时拒绝执行。
3. 核对信件、收件记录、预览、附件元数据、通知 outbox 及 `source=mail` 的通知均为零；等待清理任务把对象删除队列降为零。然后恢复写入，发布桌面和 iOS 新版并检查新信发送、回复全部、转发附件和深链。

首次切换不能直接运行普通 `bash deploy.sh`：它会在数据库迁移后立即启动新服务，没有执行本次定向清理的停顿点。运维需在停服、最终备份和迁移完成后、启动新服务前执行清理 SQL 并核对结果；若任一步失败，保持写入暂停并按已验证的备份恢复。后续常规部署仍使用 `deploy.sh`。

不新增密送、外部邮件、草稿、归档、定时发送或撤销发送。

## 2026-09-28 批量整理补充

收件箱列表可只看未读，并提供当前用户的精确收件箱、已发送箱和未读计数。当前用户可将收件箱全部设已读、按 1–100 个不同信件 ID 批量软删除，或清空完整收件箱／已发送箱；搜索条件与客户端已加载页不限制清空范围。批量删除返回实际处理数和未处理 ID，重复调用只处理仍可见的副本。桌面、iOS 和 MCP 共用服务端权限边界；AI 自行依据用户指令和可读信件内容选择操作目标。
