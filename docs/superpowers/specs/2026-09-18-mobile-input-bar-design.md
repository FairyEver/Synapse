## 1. 要解决什么

手机端会话屏底部是一条输入栏。终端与 Agent 对话共用它 —— 屏幕上同一条栏，没有第二个输入区。

现在的结构是四个平级的元素：

```
[＋] [ 输入命令 …………………… ] [🎤] [➤]
```

三件事要改：

1. **语音是一个按钮，但它改变的不是"做一件事"，而是"怎么输入"。** 它和附件、发送并排，用户得先认出一个图标才想得起"哦，还能说话"。
2. **录一句话要瞄准三个位置。** 点 🎤 开始、点 ✓ 结束，不想承认就点 ✗ —— 而 ✗ 落在最左边（＋ 的位置）、✓ 落在最右边（发送的位置），中间隔着整条输入框。
3. **🎤 夹在输入框和发送键之间，是整条栏上最窄的落点。**

微信的底部输入栏是另一套结构，中文用户对它有肌肉记忆：**左端一个常驻的键盘/语音切换键**，切到语音态之后**输入框整块变成「按住 说话」**，按住、说完松手。语音在那里不是按钮，是输入栏的一种模式。

这次要的就是这个：借它的结构，把语音从"输入栏里的一个按钮"变成"输入栏的一种状态"。

## 2. 现状与它的来历

### 2.1 三端语音输入的口径是 09-16 定的

`docs/superpowers/specs/`（三端语音输入那轮）定下了几条，其中两条与本次直接相关：

- **触发用点击开始 / 点击结束，不是按住说话。** 当时三端一起定的。
- **结束录音后文字落到输入框，用户再点发送；不直接发送。** 终端那条更严：只填命令行，不补回车 —— 命令错一个字符可能就是破坏性操作。

这两条在桌面端和 iOS 端都已上线。

### 2.2 iOS 端现在的录音落点

`SynapseMobile/SynapseMobile/Features/Terminal/TerminalScreen.swift:538` 的 `inputBar` 在录音期间**不新增第二行**，而是就地换语义：转写占输入框的位置、✗ 占 ＋ 的位置、✓ 占发送的位置，🎤 那一格收起来把宽度让给文字（同文件 `:601`）。

上一轮（`docs/superpowers/specs/2026-09-17`，语音输入完善那轮）定过三条规则：**落点唯一**（转写写进输入框本体，不另起一行）、**永远看得到最新**（滚动到最新的字）、**录音不改变几何**（栏高与按钮位置不变，只换图标语义）。这三条本次要分情况继承，见 §3.6。

### 2.3 语音的进入与呈现是一对纯值

`SynapseMobile/SynapseMobile/Features/Voice/VoiceInputBar.swift`：

- `:11` `VoiceInputController` —— 录音的状态机（权限、采集、连接、送包节奏、收尾），不认识视图；
- `:300` `VoiceInputPresentation` —— 录音期间输入栏该显示什么，不认识控制器以外的状态。

两个都是纯值，`SynapseMobileTests/VoiceInputPresentationTests.swift` 逐条钉着它们。这次改造要保住这个形状：**手势判定也要是新的一块纯值**，不能写进视图里。

## 3. 决策

### 3.1 触发手势：iOS 用按住说话，桌面端保持点击（已拍板）

产品负责人在原型评审时选定：**iOS 单端采用微信的按住说话，桌面端的 Agent 对话与终端继续保持点击开始·结束。**

桌面端不复用按住，理由是那边的手不是同一个：鼠标按住不放说话不自然，而且桌面端那套交互已经上线并有测试钉着。三端手势就此分叉，这是有意接受的代价，写进 §7。

### 3.2 结构：左端常驻切换键，＋ 移到输入框右侧

键盘态：

```
[🎙] [ 输入命令 …………………… ] [＋] [➤]
```

- **最左是键盘/语音切换键**，位置永远不变 —— 这是微信那套结构里唯一的锚点，它动了整套就散了。
- **＋ 从最左移到输入框右侧**（发送的左边）。腾出左端给切换键，顺序也与微信一致。
- **去掉输入框右侧那个 🎤。** 微信那里还有一个声波图标作快捷入口，但它与左端切换键完全等价 —— 两个入口只会让人猜哪个不一样。切换键就是唯一入口。

按钮总数不变（切换键顶替了原来的 🎤），输入框宽度不变。

### 3.3 转文字落地后自动切回键盘态

松手 → 文字落进输入框 → **输入栏回到键盘态**，光标在末尾，发送键亮起。

理由：文字要看得见才谈得上"由用户确认"。留在语音态的话输入框位置是「按住 说话」，刚落地的字没地方显示。这也让 §2.1 那条"文字落到输入框、用户再点发送"原样成立。

代价是连着说两段要再按一次切换键。接受。

### 3.4 录音时不遮罩终端

微信按住后会整屏变暗。这里不遮：终端正在跑东西的时候，输出还要能看到。这是对微信的一处有意偏离。

### 3.5 砍掉微信的「滑到这里 转文字」右区

微信按住后底部有两个大字区：左「取消」、右「滑到这里 转文字」。右区存在的前提是**默认出口是发语音** —— 滑过去才是转文字。

我们恒定转文字，没有第二个出口，右区无事可做。只保留**上滑取消**一个手势区。

### 3.6 转写在气泡里，不在输入框里（与"落点唯一"的关系）

上一轮定的「落点唯一、不另起一行」针对的是**点击式录音时长出来的第二条横条** —— 屏幕下方同时摆着转写行和 ✗/计时/✓ 行。那条规则在点击式里继续有效，一个字不改。

按住式是另一回事：**手指正压在输入栏上**，把转写写进输入框等于没显示。所以按住式下转写的落点在**手指上方的气泡**里，气泡跟着输入栏上浮，有一个朝下的尖指向按住的位置。落点仍然只有一个，只是它随手势走。

同一条规则还推出两件小事：

- **气泡显示实时转写**，不是波形。流式识别本来就有字可显示；波形是我们没有的量（上一轮已经定过：不假装有波形）。
- **气泡里的字分两级**：已定稿的句子正常色，还在变的当前句次要色，末尾一个光标。这与 `AsrTranscript.stable` / `.unstable` 一一对应。

### 3.7 进入语音态前先预检

按住式下，"按下去才发现不可用"是白按一次。所以**按切换键的那一刻**就把能查的查掉，查不过就不切态：

- **麦克风权限**：`AudioCapture.requestPermission()`（`SynapseMobile/SynapseMobile/Features/Voice/AudioCapture.swift:83`）。首次会弹系统授权框 —— 用户正好在这个动作里要语音，这是对的时候。
- **连接**：`SynapseAppModel.connectivity`（`:1185`）。`.noServer` 即"网络已断开"。

查不过的表现：**留在键盘态**，输入栏上方浮一条提示（复用现有的终端提示条，见 §5.1），文案见 §4.7。

**"语音识别未配置"不进预检**：它是平台侧的配置问题，唯一能自救的人是部署方，预检它只是白搭一次网络往返。它留给真正去签名的时刻 —— 签失败即失败，见 §5.1。

## 4. 交互规格

### 4.1 几何不变量

沿用上一轮的"录音不改变几何"，扩展成三条：

1. **输入栏高度不变。** 任何状态下都是现在的高度。
2. **四个位置不动。** 切换键、输入框、＋、发送各占一格，任何状态下都不搬家 —— 录音期间也一样。
3. **按键不搬，就不到别处去找。** 录音期间不可用的键淡出（保留占位），不消失、不被替换。

### 4.2 键盘态

```
[🎙 切换]  [ 输入命令 …………………… ]  [＋]  [➤]
```

与现状的差别只有两处：🎤 从输入框右侧挪到最左并改成切换键；＋ 从最左挪到输入框右侧。点切换键 → 进入语音态。

### 4.3 语音态

```
[⌨ 切换]  [      按住 说话      ]  [＋]  [➤ 淡出]
```

- 输入框整块变成**按钮**（不是文本域）：底色用 `secondarySystemBackground`、居中、文字「按住 说话」。宽度与位置与输入框完全一致。
- 切换键换成键盘图标，点它回键盘态。
- ＋ 在语音态仍可用（不淡出）——与微信一致，它不产生歧义。
- 发送键淡出且不可点：此刻没有可发的文字。

**进入语音态时收起键盘**（系统的和自绘面板都收，复用 `TerminalScreen.swift:133` 的 `dismissKeyboards()`）。键盘面板与语音态不能同时在。

### 4.4 按住

手指（或指针）按在「按住 说话」上：

- 立刻进入录音：调 `VoiceInputController.start(signing:)`，与点击式同一入口。
- 输入框那一格原地变**按压态**（底色加深），文案「聆听中」。
- 切换键、＋、发送淡出且不可点（手指在这一格，别处不该抢）。
- **气泡从输入栏上方浮出**，内容是实时转写，最多两行，永远滚到最新。
- 气泡下方一行提示：**「松开 转文字」**。
- **accessoryBar 不淡出、保持可用** —— 上一轮产品负责人明确要的："可以一边说话一边按快捷键，终端在跑东西时用得上"。

### 4.5 滑动与取消

按住期间手指上移：

- 上移超过 **70pt**（= 1.6 倍最小点按尺寸 `Metrics.minimumTapTarget` = 44）→ 进入**取消就绪**：
  - 气泡底色变 `systemRed`、文字转白；
  - 提示文字变**「松开 取消」**。
- 滑回 70pt 以内 → 取消就绪撤销，回到上面那一态。
- 阈值是一个常量，只在一处定义，判定做成**纯值**（见 §6 实施约束）。

### 4.6 松手

松手时按当时的状态分三种走法：

| 松手时 | 做什么 | 输入框 |
|---|---|---|
| 取消就绪 | `VoiceInputController.cancel()` | **回滚到按住之前的内容**，一个字不改 |
| 不在取消区，识别到了字 | 收尾 → 落字（见 §4.7） | 追加转写 |
| 不在取消区，一个字都没有 | 收尾 → 回键盘态 | 不变，占位显示「没有听到声音」 |

**松手不等于落地。** 松手到文字出现之间有一段收尾等待（引擎把最后一句定稿，上限 1200ms，`VoiceInputBar.swift:75`）：

- 气泡**保持显示**，提示文字变**「转文字中」**；
- 这段时间里输入栏其余部分维持录音态的淡出状态；
- 拿到结果后气泡消失、文字落进输入框、输入栏回键盘态 —— 三步在同一个渲染里发生，不做出"气泡先消失、文字稍后冒出来"的两段感。

### 4.7 落地规则

1. **追加，不覆盖。** 沿用 `TerminalScreen.swift:743` 现有 `finishVoice()` 的规则：`draft` 为空就直接是转写结果，非空则用一个空格连接。
2. **不发送、不回车。** 终端那条铁律：文字只进输入框。
3. **落地后回键盘态**，发送键按 `draft` 是否为空启用。
4. 落地成功给一次 `Haptics.commit()`（与现有 `finishVoice()` 一致）。

### 4.8 文案表

按住式新增的全部文案只有这几条，别的不要编：

| 处 | 文案 |
|---|---|
| 语音态输入框 | `按住 说话` |
| 按住、未识别到内容 | `聆听中` |
| 气泡下方提示（默认） | `松开 转文字` |
| 气泡下方提示（取消就绪） | `松开 取消` |
| 气泡下方提示（收尾中） | `转文字中` |
| 按住 3 秒没出字（气泡内） | `没有听到声音` |
| 松手后一个字都没有（输入框占位） | `没有听到声音` |
| 麦克风权限被拒（提示条） | `麦克风权限未开启 · 设置 › Synapse › 麦克风`（带「设置」动作） |
| 识别未配置（提示条） | `语音识别未配置` |
| 网络断开（提示条） | `网络已断开` |

`VoiceInputController.Failure.message` 里现有的三条（`没有听到声音` / `网络已断开` / `语音识别未配置`）原样复用，不新编同义句。

## 5. 边界与异常

### 5.1 三种进入前的失败

按 §3.7 预检。提示条的落点复用现有的终端提示（`model.raiseTerminalMessage`，`TerminalScreen.swift:254` 那一路），权限那条带「设置」动作跳到系统设置。

### 5.2 录音中途失败（断网 / 识别未配置）

`VoiceInputController` 现在的做法是把 `phase` 置成 `.failed(...)` 并**留在录音条上**，由 `VoiceInputPresentation` 给出重试键（`VoiceInputBar.swift:330`）。

按住式下**不留**：录音已经不可能继续，而用户的手指还按着。

- 失败发生时**立刻结束录音**、气泡消失、提示文字消失；
- 输入栏**回键盘态**；
- **已经识别到的文字照样落进输入框**（追加），一个字不丢；
- 浮一条提示条说明原因（§4.8）。

失败后用户的手指若还按着，松手不再产生任何动作。

### 5.3 识别为空

"没听到"和"空结果"是同一件事（`VoiceInputBar.swift:137` 的既有判定），走同一条路：回键盘态 + 输入框占位显示「没有听到声音」。

**不弹提示条**：它不是一个需要被知道的事件，是一句就地的说明；且下一个动作（再按住）就会把它清掉。

### 5.4 静音提示

按住 3 秒（`VoiceInputBar.swift:234` 的既有阈值）没有任何字返回：气泡内的文案变「没有听到声音」，**但录音继续**（现有语义：用户接着说就能接上）。声音一到，文案回到转写。

### 5.5 来电与切后台

`handleInterruption`（`VoiceInputBar.swift:269`）判定为"不是用户的取消，已经定稿的文本留着"。按住式下这段文字没有地方停 —— 手指已经不在了，录音条也不会自己留在屏幕上。

规格：**中断 → 立即结束录音 → 已识别到的文字落进输入框 → 回键盘态**，并在提示条上说明这次被打断了（文案见实施计划，属新增条目：`录音被打断`）。一个字都不丢。

### 5.6 60 秒上限

腾讯云 `Hy-ASR-3.0-preview` 对单次识别的音频长度有上限（约 60 秒，见三端语音输入那轮的实测口径）。现在 `sendOneChunk`（`VoiceInputBar.swift:225`）只会一直发，直到用户点 ✓。

按住式下要显式处理，否则会撞上一个真实的错：

- 到 60 秒由服务端收尾并断开；
- 断开走 `handleSocketFailure` → `phase = .failed(.network)`；
- 用户还按着手指，屏幕上却写「网络已断开」——**这是误报，网络好得很**。

规格：**本地计时到 ~58 秒主动走收尾路径**，与用户松手完全同路（气泡提示「转文字中」→ 落地 → 回键盘态），不等服务端把连接关掉。

> 实施者注意：上限的准确秒数以实际引擎为准，先在真机上跑一次 60 秒按住确认断开时机，再定本地阈值。**这一条是本设计里唯一没有把握的地方**，实测结论回写本文档。

### 5.7 按下即松

按下不足约 200ms 就松手：`start()` 是异步的（要签名、起采集），松手时可能 `phase` 还是 `.idle`。

规格：**松手时若控制器还没进入录音态，调用 `cancel()`，不产生任何结果**（不落字、不提示）。这不是"没听到"，是用户的手滑了一下。

### 5.8 与 accessoryBar 的关系

accessoryBar（`TerminalScreen.swift:452`）在录音期间保持可用（§4.4）。它上面的「回车」在某些路径上会触发发送（`TerminalScreen.swift:522`），那是既有行为，本次不动。

### 5.9 离开屏幕

`TerminalScreen` 的 `onDisappear` 已经在调 `voice.cancel()`（`:251`）。按住式下补一条：**松手事件与离开屏幕之间的竞态**由 `cancel()` 兜底 —— 离开屏幕后落地逻辑不得再写 `draft`。

## 6. 实施约束

- **手势判定必须是纯值。** "当前偏移算不算取消就绪"做成一个不认识视图、不认识控制器的小类型（输入起点与当前点，输出 `speaking` / `cancelling`），单测逐条钉。视图只负责把坐标喂进去。
- **阈值只定义一处。** 70pt 写在那个纯值里，视图不许有第二份。
- **`VoiceInputController` 本身尽量不动。** 它的 `start` / `confirm` / `cancel` 三个入口正好就是按住式要的三个动作，只是调用时机从"两次点击"变成"按下 / 松开"。确实需要新的，才是新方法。
- **点击式（现状结构）保留可用**：原型里两种结构都在。这次实现的目标是替换 iOS 的默认结构，现状那套（`VoiceInputPresentation` 的 `RightKey`、✗/✓ 那对键）在改造后不应留下无路可走的死代码 —— 要么删干净，要么留一条明确的开关。实施计划里给了建议。

## 7. 有意的三端差异

改造之后三端不再手势一致，这是拍过板的：

| | 触发 | 落点 | 录音期间的辅助键 |
|---|---|---|---|
| 手机端（本次） | 按住说话 | 气泡（手指上方）→ 松手后落进输入框 | accessoryBar 保持可用 |

## 8. 验收基线

以下是"做完之后必须成立"的可断言事实：

**结构与几何**

1. 键盘态从左到右依次是：切换键、输入框、＋、发送。输入框宽度与改造前一致。
2. 语音态从左到右依次是：切换键、按住说话的按钮、＋、发送。**这四个元素的 x 坐标与键盘态逐个相同。**
3. 录音期间（按住中）切换键、＋、发送淡出但**位置不变**；输入栏高度与键盘态一致。

**切换**

4. 语音态点切换键 → 回键盘态；键盘态点切换键 → 语音态（预检通过时）。
5. 进入语音态时系统键盘与自绘面板都被收起。
6. 麦克风未授权时点切换键：**不进语音态**，出现带「设置」动作的提示条。
7. 连接断开（`connectivity == .noServer`）时点切换键：不进语音态，出现「网络已断开」。

**按住与松手**

8. 按住「按住 说话」→ 出现气泡；气泡里的转写随识别结果增长；气泡最多两行且滚到最新。
9. 按住期间上移超过 70pt → 气泡变红、提示变「松开 取消」；滑回 → 复原。
10. 取消就绪时松手 → `draft` 与本条消息之前的**完全一致**（回滚），不回键盘态之外的任何副作用。
11. 正常松手且识别到内容 → 提示先变「转文字中」，随后文字追加进 `draft`、输入栏回键盘态、发送键启用。
12. `draft` 非空时再录一句：结果是原内容 + 一个空格 + 转写。
13. 松手时一个字都没有 → 回键盘态，输入框占位是「没有听到声音」，`draft` 不变。
14. 按下不足 200ms 松手 → 什么都不发生（不落字、不提示）。

**失败与中断**

15. 录音中途断网 → 立刻结束录音、回键盘态、已识别的文字落进 `draft`、出现「网络已断开」提示条。
16. 来电打断 → 已识别文字落进 `draft`、回键盘态、出现中断提示条。
17. 按住到引擎上限 → 自动走收尾（不是「网络已断开」）。

**终端行为不变**

18. 转文字落地**不发送、不回车**：`draft` 有内容时终端没有任何新输出。
19. 录音期间 accessoryBar 的各键**可以按**。

**纯值层面（单测）**

20. 手势判定：起点与当前点相差 69pt → `speaking`；70pt → `cancelling`；再回到 10pt → `speaking`。
21. 转写为空、纯空白、只有未定稿尾巴三种输入下的落地判定各自正确。

## 9. 非目标

- **不做表情面板。**
- **不做语音消息**（不发送音频、不做波形气泡、不做时长）。这一条整体只产出文字。
- **不改桌面端**（Agent 对话与终端的语音交互保持现状）。
- **不改服务端**，不新增协议、不新增权限、不新增接口。
- **不做热词自定义界面**（热词表是服务端的事）。
- **不做多语言切换**（中英混合沿用引擎现状）。
- **不做计时、不做脉冲红点、不做假波形**（上一轮已定）。
- **不改 accessoryBar、键盘面板、附件（＋）菜单本身的能力** —— 只改它们的落点与可用性。
