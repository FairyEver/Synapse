## 1. 要解决什么

手机端会话屏底部是一条输入栏。终端与 Agent 对话共用它 —— 屏幕上同一条栏，没有第二个输入区。

现在的结构是四个平级的元素：

```
[＋] [ 输入命令 …………………… ] [🎤] [➤]
```

三件事要改：

1. **语音是一个按钮，但它改变的不是"做一件事"，而是"怎么输入"。** 它和附件、发送并排，用户得先认出一个图标才想得起"哦，还能说话"。
2. **录一句话要瞄准三个位置。** 点 🎤 开始、点 ✓ 结束，不想承认就点 ✗ —— 而 ✗ 落在最左边（＋ 的位置）、✓ 落在最右边（发送的位置），中间隔着整条输入框。
3. **🎤 夹在输入框和发送键之间，是整条栏上最窄的落点。**

微信的底部输入栏是另一套结构，中文用户对它有肌肉记忆：**左端一个常驻的键盘/语音切换键**，切到语音态之后**输入框整块变成「按住 说话」**，按住、说完松手。语音在那里不是按钮，是输入栏的一种模式。

这次要的就是这个：借它的结构，把语音从"输入栏里的一个按钮"变成"输入栏的一种状态"。

还要解决两件它没有的事：

4. **松手之后不该再点一次。** 说一句话就是发一句话 —— 松开、识别完就送出去，中间不必插一次"发送"（§3.6）。
5. **长输入得能腾出手。** 一条长提示词按住不放地说是受罪。要有一个把手放开、继续说、说完再确认的形态（§4.9 锁定态）。

## 2. 现状与它的来历

### 2.1 三端语音输入的口径是 09-16 定的

`docs/superpowers/specs/`（三端语音输入那轮）定下了几条，其中两条与本次直接相关：

- **触发用点击开始 / 点击结束，不是按住说话。** 当时三端一起定的。
- **结束录音后文字落到输入框，用户再点发送；不直接发送。** 终端那条更严：只填命令行，不补回车 —— 命令错一个字符可能就是破坏性操作。

这两条在桌面端和 iOS 端都已上线。

### 2.2 iOS 端现在的录音落点

`SynapseMobile/SynapseMobile/Features/Terminal/TerminalScreen.swift:538` 的 `inputBar` 在录音期间**不新增第二行**，而是就地换语义：转写占输入框的位置、✗ 占 ＋ 的位置、✓ 占发送的位置，🎤 那一格收起来把宽度让给文字（同文件 `:601`）。

上一轮（`docs/superpowers/specs/2026-09-17`，语音输入完善那轮）定过三条规则：**落点唯一**（转写写进输入框本体，不另起一行）、**永远看得到最新**（滚动到最新的字）、**录音不改变几何**（栏高与按钮位置不变，只换图标语义）。这三条本次要分情况继承，见 §3.7。

### 2.3 语音的进入与呈现是一对纯值

`SynapseMobile/SynapseMobile/Features/Voice/VoiceInputBar.swift`：

- `:11` `VoiceInputController` —— 录音的状态机（权限、采集、连接、送包节奏、收尾），不认识视图；
- `:300` `VoiceInputPresentation` —— 录音期间输入栏该显示什么，不认识控制器以外的状态。

两个都是纯值，`SynapseMobileTests/VoiceInputPresentationTests.swift` 逐条钉着它们。这次改造要保住这个形状：**手势判定也要是新的一块纯值**，不能写进视图里。

## 3. 决策

### 3.1 触发手势：iOS 用按住说话，桌面端保持点击（已拍板）

产品负责人在原型评审时选定：**iOS 单端采用微信的按住说话，桌面端的 Agent 对话与终端继续保持点击开始·结束。**

桌面端不复用按住，理由是那边的手不是同一个：鼠标按住不放说话不自然，而且桌面端那套交互已经上线并有测试钉着。三端手势就此分叉，这是有意接受的代价，写进 §7。

### 3.2 结构：左端常驻切换键，＋ 移到输入框右侧

键盘态：

```
[🎙] [ 输入命令 …………………… ] [＋] [➤]
```

- **最左是键盘/语音切换键**，位置永远不变 —— 这是微信那套结构里唯一的锚点，它动了整套就散了。
- **＋ 从最左移到输入框右侧**（发送的左边）。腾出左端给切换键，顺序也与微信一致。
- **去掉输入框右侧那个 🎤。** 微信那里还有一个声波图标作快捷入口，但它与左端切换键完全等价 —— 两个入口只会让人猜哪个不一样。切换键就是唯一入口。

按钮总数不变（切换键顶替了原来的 🎤），输入框宽度不变。

### 3.3 模式只由切换键改

**一次输入结束之后，输入栏留在语音态。** 发送了、按 §3.6 的例外落进了输入框、一个字都没听到、左滑取消、固定态里收摊 —— 全都一样：**模式不动，只由左端那个切换键改**。

> **2026-09-18 改判。** 这一节原先是反过来的 ——「一次输入结束之后一律回键盘态」，理由是文字要看得见才谈得上确认。产品负责人在真机上用下来判它错了：**切到语音就是为了连着说**，每说完一句被打回键盘态，等于每句都要再按一次切换键，而那个切换键正是他明确要求「不用每次都去点」的东西。原话：「我应该切换到语音之后，它就不要自动再切换到别的模式上去。」
>
> 两处代价如实记下来，都判为可接受 —— 它们都不是「发出去了」，而用户要的是别自己跑掉：
>
> - **按 §3.6 的例外追加进输入框的转写看不见**（输入框只在键盘态显示）。要点一下切换键才看得到那行字。
> - **§5.3 那句「没有听到声音」没有显示位置**：它落在输入框的占位符上，而语音态下输入框不在屏幕上。它会留在那儿，切回键盘态时看得见。
>
> 实现上这件事只有一个把手：`chooseVoiceMode`（模式 + 偏好一起改）**只有切换键调**。其余路径碰都不碰那一格 —— 多一个调用方就多一条「用户没让它切、它自己切走了」的路。

> **同一天的补充：模式本身会被记住。** 用户选过一次语音态之后，**下次进任意终端默认就是语音态**，不用每次再点一次切换键；切回键盘态同样会被记住（`terminal.inputBar.voiceMode`，随终端走而不是随会话走）。记的就是切换键那一下 —— 与这一节同一条规则：只有切换键改模式。
>
> 进来时**只读已经给着的麦克风权限、不问**：进来的时候用户还没有要说话，系统授权框该出现在他按切换键或按住那一格的时候（§3.8）。查不过（权限没给、或当时断网）就静静留在键盘态，不浮提示 —— 提示留给切换键那条路，否则每进一个终端都浮一条。偏好不跟着回写，权限补上或网络回来之后它自己就生效。

### 3.4 录音时不遮罩终端

微信按住后会整屏变暗。这里不遮：终端正在跑东西的时候，输出还要能看到。这是对微信的一处有意偏离。

### 3.5 右区改成「锁定」，滑动轴从上下改到左右

微信按住后底部有两个大字区：左「取消」、右「滑到这里 转文字」。

我们恒定转文字，微信那个右区（"转文字"）本来没有对应物 —— 而**锁定**正好需要一块地方（§4.9）。于是：

| 按住时 | 结果 |
|---|---|
| 左滑 ≥ 70pt | 取消：松手丢弃，留在语音态 |
| 右滑 ≥ 70pt | 锁定：松手之后继续录 |
| 不滑 | 松手 → 转文字 → 发送（§3.6） |

**轴定成左右，不是微信的上滑。** 两个区左右排在一条栏上，滑动方向与它们一一对应；一个轴，判定就是一次比较，不需要"先上滑再分左右"。

### 3.6 松手即发送（输入框本来是空的时候）

松手 → 转文字 → 识别结束 → **直接把这句发出去**，不要求用户再点一次发送。

这是对 09-16 那轮"文字落到输入框、用户再点发送"的修改。语音输入的常见用法是"说一句话 = 发一条消息"，中间再插一次点击是多余的。

**但有一条例外，必须写死：输入框里已经有字时，不发送，改成追加。**

输入框里有内容，说明用户正在编辑（改一个路径、补一个参数）。这时候把转写追加进去等他确认是安全的一侧；把"他打的半句话 + 刚说的半句话"一起送走是危险的一侧。规则读起来也顺：语音是来补全一句话的，就补进去；是来说一整句的，就发出去。

**没有识别到内容就不发送** —— 无可发送，走 §5.3。

> **已拍板（2026-09-18）：接受这个后果，终端也不例外。** 说一句发一句正是手机端终端要的形态 —— 那里多半是在跟 Claude Code 说话（"帮我把这个函数改成异步的"），不是一个字符一个字符地敲 shell。
>
> 09-16 那条「只填命令行、不补回车」是给**点击式**定的：点 ✓ 之前用户已经看过一遍文字，那一步确认就是它的安全来源。按住式下没有那一步 —— 把文字留在输入框里，等于把"说一句话"变成"说一句 + 点一次"，正好回到这次要改掉的东西。
>
> **风险如实记下**：中文 ASR 会把 `pnpm` 听成 `PMPM`，自动执行一条听错的命令可能不可逆。缓解手段是「左滑取消」和 §4.9 的锁定态（长话、危险的话先锁定、看清了再点确定），**不是**给每次语音都加一道自动确认。

### 3.7 转写在气泡里，不在输入框里（与"落点唯一"的关系）

上一轮定的「落点唯一、不另起一行」针对的是**点击式录音时长出来的第二条横条** —— 屏幕下方同时摆着转写行和 ✗/计时/✓ 行。那条规则在点击式里继续有效，一个字不改。

按住式是另一回事：**手指正压在输入栏上**，把转写写进输入框等于没显示。所以按住式下转写的落点在**手指上方的气泡**里，气泡跟着输入栏上浮，有一个朝下的尖指向按住的位置。落点仍然只有一个，只是它随手势走。

同一条规则还推出两件小事：

- **气泡显示实时转写**，不是波形。流式识别本来就有字可显示；波形是我们没有的量（上一轮已经定过：不假装有波形）。
- **气泡里的字分两级**：已定稿的句子正常色，还在变的当前句次要色，末尾一个光标。这与 `AsrTranscript.stable` / `.unstable` 一一对应。

### 3.8 进入语音态前先预检

按住式下，"按下去才发现不可用"是白按一次。所以**按切换键的那一刻**就把能查的查掉，查不过就不切态：

- **麦克风权限**：`AudioCapture.requestPermission()`（`SynapseMobile/SynapseMobile/Features/Voice/AudioCapture.swift:83`）。首次会弹系统授权框 —— 用户正好在这个动作里要语音，这是对的时候。
- **连接**：`SynapseAppModel.connectivity`（`:1185`）。`.noServer` 即"网络已断开"。

查不过的表现：**留在键盘态**，输入栏上方浮一条提示（复用现有的终端提示条，见 §5.1），文案见 §4.8。

**"语音识别未配置"不进预检**：它是平台侧的配置问题，唯一能自救的人是部署方，预检它只是白搭一次网络往返。它留给真正去签名的时刻 —— 签失败即失败，见 §5.1。

## 4. 交互规格

### 4.1 几何不变量

沿用上一轮的"录音不改变几何"，扩展成三条：

1. **输入栏高度不变。** 任何状态下都是现在的高度。
2. **四个位置不动。** 切换键、输入框、＋、发送各占一格，任何状态下都不搬家 —— 录音期间也一样。
3. **按键不搬，就不到别处去找。** 录音期间不可用的键淡出（保留占位），不消失、不被替换。

这三条管的是键盘态、语音态与按住期间。**锁定态（§4.9）是唯一的例外**，理由写在那里。

### 4.2 键盘态

```
[🎙 切换]  [ 输入命令 …………………… ]  [＋]  [➤]
```

与现状的差别只有两处：🎤 从输入框右侧挪到最左并改成切换键；＋ 从最左挪到输入框右侧。点切换键 → 进入语音态。

### 4.3 语音态

```
[⌨ 切换]  [      按住 说话      ]  [＋]  [➤ 淡出]
```

- 输入框整块变成**按钮**（不是文本域）：底色用 `secondarySystemBackground`、居中、文字「按住 说话」。宽度与位置与输入框完全一致。
- 切换键换成键盘图标，点它回键盘态。
- ＋ 在语音态仍可用（不淡出）——与微信一致，它不产生歧义。
- 发送键淡出且不可点：此刻没有可发的文字。

**进入语音态时收起键盘**（系统的和自绘面板都收，复用 `TerminalScreen.swift:133` 的 `dismissKeyboards()`）。键盘面板与语音态不能同时在。

### 4.4 按住

手指（或指针）按在「按住 说话」上：

- 立刻进入录音：调 `VoiceInputController.start(signing:)`，与点击式同一入口。
- 输入框那一格原地变**按压态**（底色加深），文案「聆听中」。
- 切换键、＋、发送淡出且不可点（手指在这一格，别处不该抢）。
- **气泡从输入栏上方浮出**，内容是实时转写，最多两行，永远滚到最新。
- 气泡下方一行提示：**「松开 转文字」**。
- **accessoryBar 不淡出、保持可用** —— 上一轮产品负责人明确要的："可以一边说话一边按快捷键，终端在跑东西时用得上"。

### 4.5 滑动：取消与锁定

按住期间手指左右移动：

- **左移超过 70pt** → 取消就绪：气泡底色变 `systemRed`、文字转白，提示变**「松开 取消」**；输入栏那一格里「取消」二字高亮。
- **右移超过 70pt** → 锁定就绪：气泡底色变深（`ink`）、文字转白，提示变**「松开 锁定」**；「锁定」二字高亮。
- 回到阈值以内 → 撤销，回到默认态（提示「松开 转文字」）。
- 阈值 70pt = 1.6 × `Metrics.minimumTapTarget`（44）。**一个常量，一处定义，判定做成纯值**（§6）。方向只看位移的符号，不引入第二个阈值。

按住期间输入栏那一格是手势的图例，常驻显示：

```
取消 ←      聆听中      → 锁定
```

中间那格跟着手势变（`聆听中` / `松开 取消` / `松开 锁定`），两侧在就绪时高亮。手指压着中间，但两侧的字在边上，看得见 —— 滑动不用猜。

> 与 iOS 的边缘返回手势不冲突：那一格离屏幕左缘还有 60pt（切换键 44 + 两侧 padding），而系统只认最边上那 20pt。

### 4.6 松手

松手时按当时的状态分三种走法：

| 松手时 | 做什么 | 输入框 |
|---|---|---|
| 左区（取消就绪） | `VoiceInputController.cancel()`，**留在语音态** | **回滚到按住之前的内容**，一个字不改 |
| 右区（锁定就绪） | 不结束 —— 进入锁定态（§4.9），录音继续 | 不变 |
| 中间，识别到了字 | 收尾 → 发送或落地（§4.7） | 发送则清空，追加则变长 |
| 中间，一个字都没有 | 收尾（模式不动，§3.3） | 不变，占位留给切回键盘态时显示「没有听到声音」 |

**松手不等于落定。** 松手到文字出现之间有一段收尾等待（引擎把最后一句定稿，上限 1200ms，`VoiceInputBar.swift:75`）：

- 气泡**保持显示**，提示文字变**「转文字中」**；
- 这段时间里输入栏其余部分维持录音态的淡出状态；
- 拿到结果后气泡消失、文字落定（发出去或落进输入框）—— 两步在同一个渲染里发生，不做出"气泡先消失、文字稍后冒出来"的两段感。模式不动（§3.3）。

### 4.7 发送与落地

1. **`draft` 为空 → 直接发送。** 转写就是这一条消息的全部内容，终端走既有的 `sendCommand`。
2. **`draft` 非空 → 追加，等确认。** 沿用 `TerminalScreen.swift:743` 现有 `finishVoice()` 的规则：`draft` + 一个空格 + 转写。
3. **一个字都没识别到 → 什么都不发、什么都不落**（§5.3）。
4. 发送/落地成功给一次 `Haptics.commit()`（与现有 `finishVoice()` 一致）。

### 4.8 文案表

按住式新增的全部文案只有这几条，别的不要编：

| 处 | 文案 |
|---|---|
| 语音态输入框 | `按住 说话` |
| 按住、未识别到内容 | `聆听中` |
| 按住时那一格的图例 | `取消` / `锁定` |
| 气泡下方提示（默认） | `松开 转文字` |
| 气泡下方提示（取消就绪） | `松开 取消` |
| 气泡下方提示（锁定就绪） | `松开 锁定` |
| 气泡下方提示（收尾中） | `转文字中` |
| 按住 3 秒没出字（气泡内） | `没有听到声音` |
| 松手后一个字都没有（输入框占位） | `没有听到声音` |
| 锁定态左端 | `放弃` |
| 锁定态顶部 | `录音中` |
| 锁定态右端 | `确定` |
| 麦克风权限被拒（提示条） | `麦克风权限未开启 · 设置 › Synapse › 麦克风`（带「设置」动作） |
| 识别未配置（提示条） | `语音识别未配置` |
| 网络断开（提示条） | `网络已断开` |

`VoiceInputController.Failure.message` 里现有的三条（`没有听到声音` / `网络已断开` / `语音识别未配置`）原样复用，不新编同义句。

### 4.9 锁定态

右滑锁定之后手指可以走了。输入栏从"按住的那一格"变成一条**录音会话栏**：

```
[✗]  [ 录音中                             ]  [确定]
     [ 转写，最多三行，永远滚到最新……      ]
```

- **左端 ✗ = 放弃**：整段丢掉，**模式不动**。与左滑取消同一条路 —— 取消就是取消，不是改模式；要打字，切换键就在左边那一格。
- **中间是转写**，从气泡**回到输入栏本体**：手指走了，气泡就没有存在的理由，§3.7 那条"落点唯一"在这里重新成立。最多三行，永远滚到最新。
- **顶上那行 `录音中`** 不是废话：麦克风还开着这件事，不写出来只能靠猜，而它决定"我是不是可以走开去做点别的"。
- **右端「确定」= 结束录音** → 收尾 → 按 §4.7 发送或追加（模式不动，§3.3）。做成实心胶囊（`TerminalKeyPill(prominent:)` 那一族的形态），它是一次长输入的落槌。
- 锁定态**不做计时**（§9），也不因为有上限而收尾（§5.6）。

**锁定态允许改几何。** §4.1 那三条是给按住态定的 —— 手指压着屏幕时任何位移都会让人找不着北。锁定态是持续态，输入栏长高到三行，手机上终端的可视区跟着变矮，这是有意的取舍：三行转写换来"能回看刚才说了什么"，对一段长提示词比几行终端输出值。

代价要处理干净：**手机本地重排，不向电脑报新的网格。** 与系统键盘弹起时同一条规则 —— `reportGridToDesktop`（`TerminalScreen.swift:114`）只在 `phoneDriven` 且键盘没起时上报。报的话，桌面 PTY 会为一次语音输入 resize 两次（进锁定、出锁定各一次），而桌面看不到手机上的这条栏。桌面端本身不受影响。

## 5. 边界与异常

### 5.1 三种进入前的失败

按 §3.8 预检。提示条的落点复用现有的终端提示（`model.raiseTerminalMessage`，`TerminalScreen.swift:254` 那一路），权限那条带「设置」动作跳到系统设置。

### 5.2 录音中途失败（断网 / 识别未配置）

`VoiceInputController` 现在的做法是把 `phase` 置成 `.failed(...)` 并**留在录音条上**，由 `VoiceInputPresentation` 给出重试键（`VoiceInputBar.swift:330`）。

按住式下**不留**：录音已经不可能继续，而用户的手指还按着。

- 失败发生时**立刻结束录音**、气泡消失、提示文字消失；
- 模式**不动**（§3.3）—— 断网不该顺手把用户的语音态收走，网回来接着按住就是；
- **已经识别到的文字照样落进输入框**（追加），一个字不丢；
- 浮一条提示条说明原因（§4.8）。

失败后用户的手指若还按着，松手不再产生任何动作。

### 5.3 识别为空

"没听到"和"空结果"是同一件事（`VoiceInputBar.swift:137` 的既有判定），走同一条路：**什么也不发送**（§4.7 第 3 条），输入框占位写成「没有听到声音」，模式不动（§3.3）。

那句占位是给键盘态看的：用户切回键盘态时它就在输入框上（改写 `draft` 时清掉）。语音态下这一轮**看起来就是没有反应** —— 松手之后面板收了、什么也没发。这是 2026-09-18 改判时被明确接受的代价（§3.3）。

**不弹提示条**：它不是一个需要被知道的事件，是一句就地的说明；且下一个动作（再按住）就会把它清掉。

### 5.4 静音提示

按住 3 秒（`VoiceInputBar.swift:234` 的既有阈值）没有任何字返回：气泡内的文案变「没有听到声音」，**但录音继续**（现有语义：用户接着说就能接上）。声音一到，文案回到转写。

### 5.5 来电与切后台

`handleInterruption`（`VoiceInputBar.swift:269`）判定为"不是用户的取消，已经定稿的文本留着"。按住式下这段文字没有地方停 —— 手指已经不在了，录音条也不会自己留在屏幕上。

规格：**中断 → 立即结束录音 → 已识别到的文字落进输入框**（模式不动，§3.3），并在提示条上说明这次被打断了（文案见实施计划，属新增条目：`录音被打断`）。一个字都不丢。

### 5.6 时长不设限（客户端换连接续写）

**语音输入不限时长。** 用户想按住说三分钟就让他说三分钟：不加计时、不加上限提示、不做自动收尾、到点也不停。三端一致。

> **2026-09-18 二次更正。** 本节此前两次写成「引擎 60 秒只是强制断句，不需要任何新机制」，**那个结论是错的**。
>
> 现用引擎 `Hy-ASR-3.0-preview` 是混元内测版，**不接受 `needvad`** —— 服务端签名一直带着 `needvad=1`（`server/src/voice/asr-signature.ts:98`），是引擎不支持。于是它落到「未开 VAD 时单次连续识别最长 60 秒」这条规则上。探针直连实测（本地合成 161 秒中文语音，1:1 实时率送包）：**第 60.90 秒收到 `{"code":4014,"message":"音频过长, 请设置参数needvad为1"}`，随后连接被掐（1006），攒下的一整段文字全部丢失**；换句话说 4014 那句提示是误导。对照组 `16k_zh` / `16k_zh_large` / `16k_zh_en_2.0` 跑满 161 秒不断。
>
> 不换引擎：ADR 0217 记着实测「`Hy-ASR-3.0-preview` 明显比 `16k_zh_en_2.0` 准，且支持热词」，为一条可以绕开的连接寿命限制牺牲识别质量不划算。
>
> **那个错误结论随 v1.0.3 发出去过。** `docs/releases/v1.0.3.md` 里写着「手机端语音输入不再限制时长」——已发布的说明不改，事实以本节与本次待发说明为准。

**规格：客户端在连接快到 60 秒时，预热一条新连接再原子接棒，转写接着往下写。**

- 连接的年龄从**握手完成**算起 —— 引擎数的是它收到的采样，不是用户按下的时刻。
- 连接年龄到 **46 秒**开始预热下一条（实测握手 0.26 秒，留足余量）；到 **50 秒**无条件接棒。中间的这几秒用来挑一个**停顿**（本拍音频均方根低于 0.01）在停顿处接，接缝两边都不缺字；一直不停就在 50 秒处从词中间切开。
- 接棒是**拍的边界上一次指针交换**：本拍音频进新连接，旧连接只负责把最后一句定稿回来。音频从不经过「无处可去」的状态，既不重也不漏。
- 旧连接定稿回来（`final:1`，实测 1.0~1.2 秒）后，接缝从「暂定」变「定稿」。定稿版是引擎对整个前缀的重写，**换掉**暂定的那一份。
- 门控取错只会退化、不会越界：阈值取到极端时最坏退化成「永远走硬顶」，绝不越过 60 秒。这条性质由单测钉住。

**用户视角没有任何变化**：不弹错、不打断、界面上没有计时也没有上限提示（验收基线 24 条不变）。轮换全程 `phase` 保持 `.listening`，一次都不借 `.failed` 过渡。桌面端同样实现（用户 2026-09-18 确认破例，理由：同一根因、同一份代码形状）。

**签名链路**：轮换只重复调用既有的 `POST /api/voice/asr/session`，每次新 `voice_id`，无幂等无缓存，与 ADR 0217「每次连接都重新签」一致。实测 644 秒的连接跨过了 300 秒签名有效期仍在正常断句，所以签名 TTL 只约束握手、不约束会话寿命，轮换节奏只受引擎那条 60 秒约束。限流 30 次/分，轮换约 1.3 次/分。

**接缝质量（阶段 A 实测，3 组 × 2 个接缝 = 6 个样本）**：全部是「硬顶」接缝（连续说话、没有停顿可挑，从词中间切开），结果**没有一个出现重复或丢字**。定稿版对整段前缀的重写要么**改掉了识别错字**（`首次` → `首字`）、要么**做了归一化**（`300 毫秒` → `300ms`、`Intent` 保持原样）、要么**补齐了句末标点**；冻结版里停在半句的尾巴被完整续上。定稿往返 1.03~1.06 秒（3/3），2 秒的上限余量充足。

**为什么定稿版一定要替换整段前缀**：引擎收到 `end` 会把**整段前缀重发一遍**（实测 `46.35s conn#1 <- index=0 slice=2 final=0 长度=226`，而冻结时是 227 字），不是只补尾巴。所以定稿回来就把接缝整段换掉，而不是往后拼——这是接缝干净的结构性原因。

**已知残余**：更早的一次探针（另一组参数、定稿超时）观察到过接缝尾部 1~2 字的重复（如「还有一件是是键盘面板」）。本次 3 组未复现。两者的区别是**定稿有没有按时回来**：回来了就整段替换；没回来（超过 `SETTLE_TIMEOUT_MS`）就只能保留冻结版，而冻结版可能正停在半截词上，随后活连接的文本从它后面接上，接缝处就会出现重复或残字。这正是把上限从 1.2 秒放宽到 2 秒的原因，也是这一残余唯一已知的成因。

### 5.7 按下即松

按下不足约 200ms 就松手：`start()` 是异步的（要签名、起采集），松手时可能 `phase` 还是 `.idle`。

规格：**松手时若控制器还没进入录音态，调用 `cancel()`，不产生任何结果**（不落字、不提示）。这不是"没听到"，是用户的手滑了一下。

### 5.8 与 accessoryBar 的关系

accessoryBar（`TerminalScreen.swift:452`）在录音期间保持可用（§4.4）。它上面的「回车」在某些路径上会触发发送（`TerminalScreen.swift:522`），那是既有行为，本次不动。

### 5.9 离开屏幕

`TerminalScreen` 的 `onDisappear` 已经在调 `voice.cancel()`（`:251`）。按住式下补一条：**松手事件与离开屏幕之间的竞态**由 `cancel()` 兜底 —— 离开屏幕后落地逻辑不得再写 `draft`。

## 6. 实施约束

- **手势判定必须是纯值。** "这次按住现在算哪一态"做成一个不认识视图、不认识控制器的小类型（输入横向位移，输出 `speaking` / `cancelling` / `locking`），单测逐条钉。视图只负责把坐标喂进去。
- **阈值只定义一处。** 70pt 写在那个纯值里，视图不许有第二份。
- **`VoiceInputController` 本身尽量不动。** 它的 `start` / `confirm` / `cancel` 三个入口正好就是按住式要的三个动作，只是调用时机从"两次点击"变成"按下 / 松开"。确实需要新的，才是新方法。
- **点击式（现状结构）保留可用**：原型里两种结构都在。这次实现的目标是替换 iOS 的默认结构，现状那套（`VoiceInputPresentation` 的 `RightKey`、✗/✓ 那对键）在改造后不应留下无路可走的死代码 —— 要么删干净，要么留一条明确的开关。实施计划里给了建议。

## 7. 有意的三端差异

改造之后三端不再手势一致，这是拍过板的：

| | 触发 | 长输入 | 落点 | 结束之后 | 录音期间的辅助键 |
|---|---|---|---|---|---|
| 手机端（本次） | 按住说话 | 右滑锁定，手可以走 | 气泡 → 锁定后回到输入栏 | 松手即发送（有草稿时改为追加） | accessoryBar 保持可用 |
| 桌面端 Agent 对话 | 点击开始·结束 | 点击本身就是锁定 | 输入框本体 | 落进输入框，等确认 | 无 |
| 桌面端终端 | 点击开始·结束 | 同上 | 命令条整条替换 | 落进命令条，不补回车 | 无 |

差异的根据是手不同（拇指按住说话 vs 鼠标点击），不是三端各写各的。任何一端再改，三处一起看这张表。

注意「长输入」那一栏：桌面端的**点击开始·结束本身就是锁定** —— 点一下开始、手就自由了，再点一下结束。手机端要有锁定，只是因为按住式默认把手指占住了。同一个意图，两边各自的形态。

**这三条不分叉，三端一致**：不设时长上限（§5.6）、不做计时、没有识别到内容就什么都不发。

## 8. 验收基线

以下是"做完之后必须成立"的可断言事实：

**结构与几何**

1. 键盘态从左到右依次是：切换键、输入框、＋、发送。输入框宽度与改造前一致。
2. 语音态从左到右依次是：切换键、按住说话的按钮、＋、发送。**这四个元素的 x 坐标与键盘态逐个相同。**
3. 录音期间（按住中）切换键、＋、发送淡出但**位置不变**；输入栏高度与键盘态一致。

**切换**

4. 语音态点切换键 → 回键盘态；键盘态点切换键 → 语音态（预检通过时）。
5. 进入语音态时系统键盘与自绘面板都被收起。
6. 麦克风未授权时点切换键：**不进语音态**，出现带「设置」动作的提示条。
7. 连接断开（`connectivity == .noServer`）时点切换键：不进语音态，出现「网络已断开」。

**按住与松手**

8. 按住「按住 说话」→ 出现气泡；气泡里的转写随识别结果增长；气泡最多两行且滚到最新。
9. 按住期间那一格常驻显示 `取消 ← 聆听中 → 锁定`，中间那格跟手势变。
10. 按住期间左移超过 70pt → 气泡变红、提示变「松开 取消」、左侧「取消」高亮；滑回 → 复原。
11. 按住期间右移超过 70pt → 气泡变深色、提示变「松开 锁定」、「锁定」高亮；滑回 → 复原。
12. 取消就绪时松手 → `draft` 与本条消息之前的**完全一致**（回滚），**留在语音态**。
13. 正常松手且识别到内容、`draft` 为空 → 提示先变「转文字中」，随后**这句话被发送出去**（终端出现这一行），输入框是空的，**仍在语音态**（可以接着按住说下一句，§3.3）。
14. `draft` 非空时松手 → **不发送**，转写追加到 `draft` 后面（原内容 + 一个空格 + 转写），**仍在语音态**（那行字要点切换键才看得见，§3.3）。
15. 松手时一个字都没有 → **仍在语音态**，什么都不发送；「没有听到声音」写进输入框占位，切回键盘态时看得见。
16. 按下不足 200ms 松手 → 什么都不发生（不落字、不提示）。

**锁定态**

17. 右区松手 → 不结束录音：气泡消失、输入栏变 `[✗] [录音中 + 转写] [确定]`，转写继续增长。
18. 锁定期间**不点任何东西**，转写一直长；屏幕上没有任何计时或上限提示。
19. 点「确定」→ 收尾（提示「转文字中」）→ 按 §4.7 发送或追加 → **仍在语音态**。
20. 点「✗ 放弃」→ 整段丢弃、**什么也不发送**、**仍在语音态**。
21. 锁定态输入栏变高时**不向桌面报新网格**（`sendGridSize` 在这个窗口内不被调用）；退出锁定也不报。

**失败与中断**

22. 录音中途断网 → 立刻结束录音、**仍在语音态**、已识别的文字**按 §4.7 处理**（空 `draft` 就发出去）、出现「网络已断开」提示条。
23. 来电打断 → 同上，提示条说明被打断。
24. 按住一分钟以上不被中断：转写持续增长、屏幕上**没有**任何计时或上限提示，也**不出现**「网络已断开」。
    - 判据取「数字口播」：每 30 秒报一个不同的数字，连续说到 3 分钟。落地文字里**每个数字恰好出现一次、顺序正确**。接棒点在 46 / 96 / 146 秒附近（每次换连接重新计时），正好夹在两个数字中间——丢字或重复必然打乱数字的个数或顺序，肉眼可判。
    - 沉默 60 秒后再说话同样不该被掐：引擎数的是它收到的采样，静音也算时长（4014 的实测成因），所以这条和连续说话走的是同一条路径。
    - 内侧证据：`AsrRenewalTests` 13 条 + 桌面 `asr-renewal.test.ts` 15 条 + `voice-session.test.ts` 换连接 12 条。**集成层（`VoiceInputBar` / `VoiceSession` 之外）没有自动化**，真机走查是发布前检查项。

**终端行为不变**

25. 麦克风权限被拒、识别未配置、网络断开三种情况点切换键，都**不进语音态**，输入框与终端没有任何变化。
26. 录音期间 accessoryBar 的各键**可以按**。

**纯值层面（单测）**

27. 手势判定：位移 −69pt → `speaking`；−70pt → `cancelling`；+70pt → `locking`；从 −90pt 回到 −5pt → `speaking`。
28. 转写为空、纯空白、只有未定稿尾巴三种输入下，"该不该发"的判定各自正确（前两种不发）。

## 9. 非目标

- **不做表情面板。**
- **不做语音消息**（不发送音频、不做波形气泡、不做时长）。这一条整体只产出文字。
- ~~**不改桌面端**（Agent 对话与终端的语音交互保持现状）。~~ **2026-09-18 用户确认破例**：根因（`Hy-ASR-3.0-preview` 不吃 `needvad`，单连接 60 秒被掐）与 iOS 完全相同，接法也是同一份代码形状（连接代号 + 冻结前缀 + 原子接棒），分开做等于把同一个坑踩两遍。桌面端一并实现，其余四条非目标。另三条经复核**依然成立**：§9「不改服务端」——轮换只重复调用既有的 `POST /api/voice/asr/session`，每次新 `voice_id`，服务端零改动，引擎上限是客户端常量；§9「不设时长上限」——轮换是**连接寿命管理**，用户侧仍然想说多久说多久，不加计时也不加提示；§9「不做连续听写」——那条指跨多次录音不自动拼条，轮换发生在同一次录音、同一段转写之中，不产生新落点、不触发发送。
- **不改服务端**，不新增协议、不新增权限、不新增接口。
- **不做热词自定义界面**（热词表是服务端的事）。
- **不做多语言切换**（中英混合沿用引擎现状）。
- **不做计时、不做脉冲红点、不做假波形**（上一轮已定）。
- **不设时长上限**，也不加任何"还能说多久"的提示（§5.6）。
- **不改 accessoryBar、键盘面板、附件（＋）菜单本身的能力** —— 只改它们的落点与可用性。（2026-09-19 追加一条：输入区上方新增「最新一张图」的悬浮预览，见 §10。＋ 菜单本身仍未改动。）
- **不做"继续追加一段"的连续听写**：说一句落一句，连着说的几句话不会被自动接成一条。§3.3 的"留在语音态"省掉的只是"再按一次切换键"，不是把两句合成一句。

## 10. 追加：最新一张图的悬浮预览（2026-09-19）

### 10.1 要解决什么

刚截的图、刚拍的照片，本来就是要发到电脑上那台终端的那一张。现在的路是：点 ＋ → 照片和视频 → 在相册里翻到刚那张 → 选中。

系统已经知道是哪一张了。用户比系统多做的这三步，全是白做的。

### 10.2 决策

1. **形态是悬浮缩略图，不是 ＋ 菜单里的一格。** ＋ 是原生 `Menu`，iOS 的原生菜单项只有一个图标位，摆不下一张看得清的预览；要做成"菜单上方一张大图"，就得把整个 ＋ 换成自绘面板。而悬浮缩略图比"开菜单再点"还少一步 —— 它不需要先开任何东西。

2. **这是全 App 唯一一处自己读相册的地方。** 其余每一条取图的路都经过系统选择器（`PHPickerViewController` 跑在别的进程里，双方都拿不到对方的相册）。「最新的一张」这件事问不了选择器 —— 选择器只在有人挑完之后才回答问题 —— 所以它必须直读相册，也必须新增 `NSPhotoLibraryUsageDescription`。这条推翻的是 09-18 之前"App 不需要相册权限"那句结论，不是它的理由。

3. **授权问在「用过一次照片和视频」之后。** 原生 `Menu` 没有"将要打开"的回调，点 ＋ 那一下拦不到，所以"点 ＋ 就弹授权"这个时机做不到。退而求其次的三个时刻里选了这一个：它正好发生在用户刚为了一张相册里的图走完那三步之后，此刻问"能不能读你的相册"有人答得上来。**不做**首次进终端页就问 —— 那是在为一个用户还不知道存在的功能索取权限。

4. **只看五分钟之内的那一张。** 这句话是"你刚刚拍了/截了一张"，更早的图不是这句话。拍摄时间落在未来的一律不算新鲜（备份恢复、跨设备同步、时区跳过的时钟差会把一张旧图说成刚拍的），宁可这次不提议。

5. **已经露过面的不再飘。** 气泡发走的那张、用户刚在相册里手动选过的那张、以及已经浮出来过一次的那张，都记一笔。前两种不记的话，授权一给、或者切回一次前台，同一张图立刻又浮出来，用户会以为上一次没发出去；第三种不记的话，它会在每次切回前台时重复浮一次 —— 那不是"检测到变化"，只是重复打扰（2026-09-19 真机反馈后补上这一条）。

6. **露五秒，然后自己走。** 五分钟决定这一刻有没有得提议，五秒决定它露多久（`recentPhotoDisplayDuration`）。五秒是产品负责人定的，同时意味着**不做关闭按钮** —— 一条五秒钟后自己就不成立的说法，没有人需要为它专门点一下叉。它也不是常驻的一格：常驻的缩略图会变成输入栏上永远多出来的那一块。

7. **新的一张要能立刻顶掉旧的，靠的是相册自己的变化通知。** 第一版在这条路上靠的是一个"截屏通知 + 等一秒再查"的猜测，真机第一次实测就错了：截第二张时第一次查还在写，查到的是上一张，而那一发没有第二次机会 —— 气泡里一直停着旧的那张。等久一点只是把猜错的时间推后，问题在猜本身。现在监听 `PHPhotoLibraryChangeObserver`：入库是相册自己的事，什么时候完成只有它知道，它在完成时报一声（2026-09-19 真机反馈后改的）。

8. **发送走原来那条路。** 落到的是 `PickedFile`，进的是 `hand(_:)` —— 和从相册里挑一张完全同一条，包括 HEIC 转 JPEG、终端在等回答时的那个确认框、以及中转条上的一切。

### 10.3 规格

- **几何**：64×64 缩略图，圆角 12，**2 点边框**。右下角距输入区（accessoryBar ＋ 输入栏这一组）顶边 8 点，距屏幕右边缘 12 点。
- **边框的颜色是固定值**（`Theme.canvasRing`，白度 0.55），不跟着外观走：它压在终端画布上，而画布在两种外观下都是那块固定的近黑。第一版用的是 `separator`，深色下它是 29% 的白，压在画布边缘上实测看不清 —— 用户的原话是"在黑色背景下就看不出来边框了"（2026-09-19 真机反馈后改的）。
- **不参与布局**：和录音浮层共用同一个零高度锚点。它占一行就会改掉报给电脑的格子数。
- **出现与消失**：从右下角缩放 0.9 ＋ 淡入起步，`.snappy(0.3)` 落定；开着「减弱动态效果」时只淡入。露满五秒自己走，不需要任何操作。
- **让位**：录音浮层可见时不出现 —— 那块面板铺满整条，底下压着一张缩略图，点下去就发走了。
- **没有文案**：只有图。缩略图本身就是它要说的那句话，配一句"你可能有张照片要发"是在替用户念一张他自己刚拍的图。
- **无障碍**：标识 `recent-photo`，标签「发送最近的照片」。

### 10.4 自检基线

1. 没授权时：输入栏上方什么都不出现，＋ 菜单与其它入口一切照旧。
2. 用过一次「照片和视频」并挑中一张之后，出现系统相册授权询问。拒绝 → 什么都不出现，且**不再问第二次**。
3. 授权后，相册里最新一张图是五分钟内产生的 → 输入栏上方浮出它的缩略图；点一下 → 与从相册挑同一张完全相同的发送流程。
4. 它浮在那里不动，五秒后自己消失，不需要任何操作。
5. **在它正在显示、或者已经消失之后，再截一张新图 → 新的那张立刻把它顶掉／浮出来。** 这是"实时检测变化"那条的全部内容，也是第一版没做到的地方。
6. 点过之后它不再出现；切后台再回来、切走再切回这一页，也都不再出现（同一张图只浮一次）。
7. 最新一张图是五分钟之前的 → 不出现。
8. 拍摄时间在未来的那一张 → 不出现。
9. 录音浮层出现时它让位；录音结束、这张还没露过面 → 回来。
10. 终端处于"等待回答"时点它 → 与从相册发一张一样，先问一次再发。

### 10.5 非目标

- **不做多张**（不摆一排缩略图）。一排就成了一条常设入口，而它是一句时机性的提议。
- **不做相册浏览**（不在 App 里翻相册）。
- **不为「仅选中的照片」做修补入口**。这种情况下读不到刚截的图是它的必然代价，但气泡是一个被动的提议，把系统设置的入口摆在它上面，比不提议更打扰。
- **不提示"你没有授权"**。没授权和"这张不够新"在屏幕上是同一件事。
- **不做气泡上的取消按钮 / 关闭叉**。它自己会走；按时间是唯一需要的那条出口。
