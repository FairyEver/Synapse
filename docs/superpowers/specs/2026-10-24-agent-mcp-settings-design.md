# 设置中的 Agent MCP 管理

用户已于 2026-10-24 授权实施。本文修订 2026-08-28 MCP 管理中心中“只在会话顶栏、不进入设置”的入口限制。会话动态增删、OAuth 和重连不在本次范围。

## 行为

- 设置 → MCP 分开显示“Agent 使用的 MCP”和现有 SY 对外注册。
- 页面进入及刷新时重新读取本机 Claude Code 用户 MCP、所选项目 MCP、本地项目覆盖、启用插件和 SY 连接器；不连接服务器、不发模型请求。默认范围为默认 Agent 工作区，可选择已配置的普通项目。
- 配置清单显示名称、来源和在 SY 中的启用状态。配置存在不代表连接成功；读取失败不能当成空列表。来源与策略受 SDK 的作用域/原生策略约束；未知或未解析的插件/受管来源必须说明，不能宣称完整。
- 开关保存到 SY 的本机配置，只记录禁用的服务器名。对所有由 SY Agent Runtime 启动的查询生效，不编辑 ~/.claude.json、.claude/settings.json、.mcp.json 或插件文件，不影响外部 CLI。
- 启用表示移除 SY 的额外禁用，不能越过 Claude Code 原有拒绝或企业策略。内部 synapse-mcp / synapse-tool-router 合并为 Synapse，只读显示为内置。
- 禁用通过 SDK settings.deniedMcpServers 施加，在最初 discovery 和最终 strict 查询前都存在；不只在 canUseTool 中拦截。保留所有原始 settingSources、Skill、规则和权限设置。
- 运行中任务不被打断；下一轮检查禁用策略，变更则安全关闭并 resume 同一 SDK 会话，不重放请求。历史内容不清除，不保证关闭后旧上下文立刻缩小。
- UI 不显示命令参数、env、headers、凭据或原始配置错误。刷新不能重新开启用户关闭的服务器，未发现但已禁用项保留以便恢复。
- 插件必须使用 SDK 原始服务器键 `plugin:<插件>:<服务器>`，不能使用 transcript 中规范化后的工具名前缀作为禁用键。清单读取祖先项目配置以及插件内联配置；MCPB/远程声明等无法静态解析的来源显示范围提示。
- 主动关闭的 SY 连接器不进入本轮预期连接清单，不能将用户禁用误报为连接失败；原始 SDK 拒绝策略仍保留。

- 实机 REA pending 修复曾为系统 DNS socket 增加沙箱例外；后续用户明确移除整层私有存储沙箱，该例外不再需要。并发 MCP pending 启动预算仍为 10 秒，控制请求仍为 5 秒。启动取消会关闭 discovery，不发送排队 prompt、不进入 fallback；清理失败维持停止未确认。

## 验证

临时目录中的源配置前后字节完全一致；覆盖用户/项目/本地合并、插件来源、错误与敏感字段不外泄、重复刷新、连续开关、SDK 启动参数和策略变化重建。Renderer 测试覆盖刷新、失败恢复、项目选择和开关。测试不调用真实 MCP 或发送邮件。

原生 SDK 集成验证使用显式 opt-in 的临时 stdio 假服务，对比启用时确实启动、禁用时不启动。SDK 自身首次运行会在 `.claude.json` 初始化机器/迁移元数据，这是既有 CLI 行为；测试单独断言 MCP 定义不变和项目源文件字节不变。设置清单/开关服务本身的源文件仍断言逐字节不变。

用户后续授权的真实窗口操作、Provider 请求正文、会话恢复、配置恢复及 REA 启动边界见 [实机验收记录](../acceptance/2026-10-24-agent-mcp-settings.md)。
