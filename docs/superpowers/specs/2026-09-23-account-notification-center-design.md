# 账号消息中心

> **2026-10-06 iOS 展示修订（覆盖此前 iOS 面板约定）：**账号通知的数据、接口、MCP 能力、权限和桌面消息中心保持不变。iOS 顶层底栏固定为「主页 / 终端 / 通知 / 我的」，通知由独立的「通知」页面承载，不再由主页右上角入口打开覆盖面板。通知列表中的每一行只有一个点击动作：先按通知目标执行后续操作；站内信通知整行进入对应站内信，不提供单独的正文图标。没有目标的通知在通知页面打开正文。下文涉及桌面消息中心的面板与阅读区时仍按桌面行为执行。

## 边界

> **2026-10-11 待办提醒：**新增服务端来源 `todo-reminder`，正文只保存待办标题，使用普通 active 提醒。提醒事务先写通知与持久投递记录，提交后复用既有账号实时连接与生产 APNs；失败重试不新增通知。已读或删除记录停止外部投递，原提醒时间超过 24 小时后停止重试。它不进入终端待处理，不扩展桌面发送来源白名单；定位规则见 [云端待办设计](2026-10-11-cloud-todos-design.md)。

服务端 `UserNotification` 是历史、未读、待处理标记和删除状态的唯一来源。桌面全局消息面板与 iOS 独立通知页面按账号读取同一份记录；保留 90 天。普通操作成功 Toast 不入库，不导入 Bark 历史，不提供导出或全文搜索。消息中心没有独立 System App 或 Dock 项；当前账号的通知管理可通过 MCP 操作。

来源固定为外部接口、终端待处理、终端完成、站内信、录音转写、待办提醒和 System Notifier 正式触发。终端消息只保存安全的会话标识、标题和状态，不存提示词、终端输出、最后一行或工具参数。待处理由终端状态决定，与已读独立；会话不再等待时解除待处理，历史保留。

> **2026-09-28 修订：**账号消息中心现在经 `app.account.notification.*` 向 MCP 提供当前用户的列表、详情、精确未读数、已读与软删除操作；仍不注册独立 System App、Dock、Workflow、Automation 或 Deep Link。

## 投递与状态

新消息先入库，再广播 `notification.changed` 给在线设备，并向账号下注册的 iPhone 发送 APNs。推送失败不删除记录；客户端在启动、重连、打开消息中心时拉取，实时变化按消息 ID 去重。消息详情打开后标记已读，已读与软删除会广播至账号设备。桌面面板按「全部、未读、待处理」筛选：全部清空会软删除当前账号所有消息，未读的全部已读会标记当前账号所有未读消息，待处理的全部忽略只软删除当前待处理消息，不解除终端的待处理状态。过期记录由服务端定期物理清理，读取时也排除超过 90 天的记录。

`active` 在桌面显示原生通知、在 iOS 显示普通 APNs；`passive` 仅入列表；`timeSensitive` 在 iOS 使用系统时效性提醒，桌面按普通提醒。终端待处理保留原有 APNs 快捷操作，普通点按先按消息 ID 取回那一条，再按它自己的目标直接去往会话、录音或站内信；没有目标或只有外部链接的，在 iOS 通知页面打开正文。iOS 通知行不区分站内信与其他来源，整行只有一个后续操作；桌面消息中心仍按下方桌面阅读区规则显示原信。原始通知来源本机已弹横幅或 Toast 时，不再重复弹一次。系统通知的呈现受操作系统通知设置约束。

> **2026-09-29 桌面交互补充：**桌面消息中心保持全局入口与账号通知存储，使用列表与阅读区并排的宽面板；窄窗在列表和阅读区间切换。列表继续只展示通知的安全摘要。选择站内信通知后，凭 `targetId` 从站内信读取本人有权查看的原信，展示主题、发件人、收件人和完整正文；读取失败时保留通知摘要并提供重试。阅读通知与阅读站内信分别更新各自的已读状态；通知可重新标为未读。单条删除先给短暂撤销窗口，之后才提交软删除；清空全部和忽略待处理先确认，后者仍不解除终端待处理。原信、终端、录音和外部链接的跳转保持各自现有权限与目标边界。

> **2026-10-02 来源筛选补充：**桌面列表在状态页签旁提供默认「全部」的来源下拉菜单：系统通知（`system-notifier`）、Agent 待回复（`terminal-attention`）、Agent 回复完成（`terminal-complete`）、站内信（`mail`）、录音转写（`meeting-transcription`）、外部通知（`external`）。分类只按 `source` 判断，已解除待处理的记录仍归 Agent 待回复历史；「待处理」状态另要求 `resolvedAt` 为空。列表接口与既有 MCP 列表工具增加可选 `source`，与未读或待处理条件取交集，待处理搭配其他来源返回空列表；服务端先筛选再分页，改变筛选条件从第一页重新读取。不传 `source` 保持原行为，未知来源仍出现在「全部」。来源筛选不缩小批量操作范围：全部已读与清空全部仍作用于当前账号，忽略待处理仍作用于当前账号全部待处理通知。

发布来源筛选时先部署支持 `source` 的服务端，再发布桌面客户端；旧客户端不传来源条件时行为不变。

桌面弹不弹原生通知，由 System Notifier 的「本机通知」开关与「静音通知」开关决定（见 `2026-07-23-system-notifier-v1-design.md`）：桌面收到一条账号消息后，实时连接把标题与正文交给 System Notifier 呈现，它按这两颗开关决定弹不弹、静不静音。关掉「本机通知」的机器不弹任何账号消息的原生通知，但仍会收到实时事件并刷新面板；Terminal 自己那套可点击的 Claude Code 通知由 Terminal 的开关管理，不受这里影响。

## 外部接口与隐私

待办目标只接受服务器 `todo-reminder` 来源与严格事项 ID，读取通知并标记已读后，再以当前账号只读定位；目标不在第一页时单项读取，已完成事项进入全部。不存在、删除与不可访问统一提示；未登录等待登录，新导航或身份变化取消旧请求。桌面消息中心提供「查看待办」，System Notifier 公共请求仍只有标题和正文，原生横幅不增加点击回调。外部通知 query 不能替换来源、来源键或目标。

来源筛选补充「待办提醒」（`todo-reminder`），属于账号通知的普通来源，不计入终端待处理。此分类不扩展桌面通知创建白名单，也不增加通知 MCP 工具。iOS 普通通知点按在重取与已读后可进入待办，与会话、录音和站内信遵循同一后续操作规则。

`notification.send` 是独立 API 密钥权限。`POST /api/open/v1/notifications` 接收标题、正文、可选分组、HTTPS 链接和提醒级别，返回消息 ID。长度校验、每分钟 60 次限流和密钥范围内的 `Idempotency-Key` 去重在服务端执行。接口不兼容 Bark URL，也不支持图片、铃声、重要警告、持续响铃、推送加密或多服务器。

> **2026-09-24 修订：通知接口改用三种传参形状。** 下面这段是本节的原始设计，其中「只允许 `POST /api/open/v1/notifications`、不接受 `Authorization` 之外的凭证位置」已被取代；其余边界（不支持图片、铃声、重要警告、持续响铃、复制动作、推送加密、自定义 TTL、多服务器）继续有效。当前实现是 `POST /notifications`（密钥在请求体 `key`）、`POST /notifications/{key}`（密钥在路径段）和 `GET /notifications/{key}/{title}/{body}`（密钥与标题正文都在路径段），密钥随请求携带，三种形状都不接受 `Authorization` 头。长度校验、限流、`Idempotency-Key` 去重和返回结构不变。权威约束见 `docs/agents/module-boundaries.md` 的「Console 用户 API 秘钥」一节，机器契约见 `/api/open/openapi.json`。

> **2026-10-15 修订：放开「点按复制正文」一项。** 本节上面两处不支持清单里的「复制动作」都已被取代：接口现在接受可选 `copyOnTap: boolean`（路径式用 `?copyOnTap=1`，只认字面量 `1`），用户在手机上点这条通知即把正文复制到剪贴板。只放开这一项——图片、铃声、重要警告、持续响铃、自动复制、复制标题、复制到指定位置、推送加密、自定义 TTL、多服务器与 Bark URL 兼容继续不支持。开关只在 JSON 请求体里能表达，表单编码下发不出来。权威设计见 [通知点按复制设计](2026-10-15-notification-tap-to-copy-design.md)，边界约束见 `docs/agents/module-boundaries.md` 的「Console 用户 API 秘钥」一节。

消息标题和正文以明文存于 Synapse 服务端，并可能出现在系统锁屏预览中。API 密钥与通知正文不得进入日志。System Notifier 的正式触发就是**创建一条消息**：账号未登录或离线时它发不出去，那就什么都不发生（不发、不补、本机也不另弹一条）；「发送通知」开关关掉同样完全不发，它与本机呈现的两颗开关互不门控；测试通知永远只显示在本机。其 MCP 与 Workflow 的成功返回语义不受发送结果影响。
## 2026-10-12：云盘文档互动来源

来源增加服务端拥有的 `drive-discussion`，不进入桌面写入白名单。新评论/留言及回复复用账号中心、Live 与 APNs；可选 `driveDiscussion` 元数据驱动“查看评论／留言／回复”，缺省回退“查看文档”。来源筛选与精确未读数、批量已读/删除范围不变。定位按本人通知 ID 重取后进入既有云盘阅读器；详情和系统横幅没有新增发送或点击契约。原分享来源缺失、停用、过期或文件移出分享时链接不可用。完整边界见 [文档互动通知设计](2026-10-12-drive-discussion-notifications-design.md)。

### 2026-10-13 文档互动上下文

通知列表和系统提醒使用两行短摘要；详情读取通知创建事务保存的纯文本快照，显示完整文档标题、评论原文、被回复者与内容及本次内容。快照独立于当前文档变化，旧通知缺省回退原摘要。手机点按继续直达，长按提供详情入口并复用既有已读/重取与账号隔离。详见文档互动通知设计的上下文增强约束。
