# 账号消息中心

## 边界

服务端 `UserNotification` 是历史、未读、待处理标记和删除状态的唯一来源。桌面全局消息面板与 iOS「消息」Tab 按账号读取同一份记录；保留 90 天。普通操作成功 Toast 不入库，不导入 Bark 历史，不提供导出或全文搜索。消息中心没有独立 System App、Dock 项或 MCP 工具。

来源固定为外部接口、终端待处理、终端完成、录音转写和 System Notifier 正式触发。终端消息只保存安全的会话标识、标题和状态，不存提示词、终端输出、最后一行或工具参数。待处理由终端状态决定，与已读独立；会话不再等待时解除待处理，历史保留。

## 投递与状态

新消息先入库，再广播 `notification.changed` 给在线设备，并向账号下注册的 iPhone 发送 APNs。推送失败不删除记录；客户端在启动、重连、打开消息中心时拉取，实时变化按消息 ID 去重。消息详情打开后标记已读，已读与软删除会广播至账号设备。桌面面板按「全部、未读、待处理」筛选：全部清空会软删除当前账号所有消息，未读的全部已读会标记当前账号所有未读消息，待处理的全部忽略只软删除当前待处理消息，不解除终端的待处理状态。过期记录由服务端定期物理清理，读取时也排除超过 90 天的记录。

`active` 在桌面显示原生通知、在 iOS 显示普通 APNs；`passive` 仅入列表；`timeSensitive` 在 iOS 使用系统时效性提醒，桌面按普通提醒。终端待处理保留原有 APNs 快捷操作，普通点按先按消息 ID 打开详情。原始通知来源本机已弹横幅或 Toast 时，不再重复弹一次。系统通知的呈现受操作系统通知设置约束。

## 外部接口与隐私

`notification.send` 是独立 API 密钥权限。`POST /api/open/v1/notifications` 接收标题、正文、可选分组、HTTPS 链接和提醒级别，返回消息 ID。长度校验、每分钟 60 次限流和密钥范围内的 `Idempotency-Key` 去重在服务端执行。接口不兼容 Bark URL，也不支持图片、铃声、重要警告、持续响铃、复制动作、推送加密或多服务器。

消息标题和正文以明文存于 Synapse 服务端，并可能出现在系统锁屏预览中。API 密钥与通知正文不得进入日志。System Notifier 正式触发仅在账号已登录且在线时尽力同步完整标题和正文；离线或未登录时仅本机显示且不补发。测试通知永远只显示在本机。其 MCP 与 Workflow 的成功返回语义不受云端同步结果影响。
