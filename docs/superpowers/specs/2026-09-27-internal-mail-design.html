站内信

同一团队成员之间发送可阅读、可回复、可附文件的私有信件。桌面与 iOS 共用账号收件箱，Agent 可按用户指令生成文档并发送。

现有能力与新增边界

团队

服务端已有 Team 与 TeamMembership。成员由管理员维护，用户可加入多个团队。当前普通用户没有团队查询入口，也没有团队协作权限。

云盘与 Agent

云盘能保存文件、版本与分享；Agent 已有文档生成及云盘 MCP。站内信附件应引用发送时的文件版本，并给收件人独立的信件访问权。

通知与跨端

账号消息中心负责提醒和未读，桌面与手机可接收实时变化及推送。信件正文、收发记录和已读状态需要单独持久化，通知只负责引导打开信件。

本方案是对 2026-09-19「团队不产生可见行为」阶段性边界的后续扩展：团队关系只用于站内信的收件人资格，不引入团队角色或团队级云盘权限。实现时须同步修订该专题规则。

iPhone 与窄窗口

主页「功能」列表增加「站内信」。列表点入详情，返回后保留原分段与滚动位置；写信为单独编辑页。宽 iPad 窗口用既有 AdaptiveFeatureNavigation 并排展示列表与详情，窗口收窄自动折叠。

关键路径

  1. 1. 选择团队，收件人搜索仅列出该团队的有效成员。
  2. 2. 编辑主题、正文与附件；桌面和手机共用服务端草稿。
  3. 3. 发送前服务端再次核验团队成员关系和附件版本。
  4. 4. 每位收件人拥有自己的未读、删除状态，发件人可见已发送。

产品规则

身份与收件人

每人只有一个账号收件箱，汇集所有所属团队的信件。写信时必须选定一个团队；一次发送的所有收件人、发件人必须同时属于该团队。多团队成员不可在一封信中跨团队混选。收件人用用户 ID 标识，界面显示昵称、handle 与团队；不输入外部邮箱地址。

收发与会话

左侧只保留「收到 / 已发送」两个主分类。支持主题、正文、多人收件、附件、回复、回复全部、转发、搜索和自动保存草稿。草稿从「写信」入口继续编辑，不增第三个主分类。发送请求使用幂等键，避免重试产生重复信件。

附件

可附本地文件或本人云盘文件，Agent 生成的云盘文档也走同一路径。发送时固定文件版本，收件人经信件权限读取该快照；源文件后续修改、移动或取消公开分享，不改变已投递附件。附件不自动进入收件人云盘，也不创建公开分享链接。

成员变化

禁用账号、已退出团队的用户不可成为新信收件人。发出后退出团队，历史信仍留在个人信箱，但不能再以原团队回复或转发，除非重新加入。删除团队保留历史信和发送时的团队名快照，阻止该团队的新发送；删除个人信件只隐藏自己的副本。

通知与隐私

新信写库成功后广播变更，并向收件账号发提醒。通知中心仅展示「收到站内信」与发件人，不复制正文和附件内容；点击按信件 ID 打开站内信。站内信未读数独立于通知未读数，显示上限沿用 99+。服务端日志和推送不记录信件正文。

首版范围

首版不接外部邮件，不提供邮箱地址、抄送/密送、群发名单、定时发送、撤回、团队角色或团队共享信箱。附件类型与大小上限在实现前按现有云盘能力确定，前后端使用同一份配置。

能力架构

层新增职责复用与边界
服务端团队内成员发现；草稿、信件、参与者状态、附件快照；列表分页、搜索、发送事务与审计。复用 UserAuthGuard、TeamMembership、Drive 版本及账号广播。正文不写入 UserNotification。
桌面端独立「站内信」System App；收到/已发送列表、详情、写信、附件选择、未读状态。复用 System App 窗口、shadcn 组件、窄类型 preload bridge；主进程负责认证与网络。
iOS / iPadOS主页功能入口、列表详情、写信、系统文件选择与推送落点。手机直连服务端，不依赖电脑在线；复用 AdaptiveFeatureNavigation、账号认证与通知数量规则。
MCP + Skill按团队找人、建草稿、附文档、发送、查询、阅读、回复与标记已读。新 mail domain；工具走同一服务端校验。Skill 指导 Agent 先解析同名成员和团队，再发送。

拟议数据边界

MailThread 保存会话与团队 ID/名称快照；MailMessage 保存发送者、主题、正文、发送时间和幂等键；MailParticipant 保存每个参与者的已读与隐藏状态；MailAttachment 保存发送时的版本及访问授权；MailDraft 保存跨端草稿。收件箱与发件箱都由参与者身份投影，不复制信件正文。

拟议 MCP 工具组

app_mail_team_list、app_mail_recipient_search、app_mail_draft_save、app_mail_send、app_mail_message_list、app_mail_message_get、app_mail_message_reply、app_mail_message_mark_read。工具名是方案，尚未注册。Skill 放入系统 Skill 包的 mail 领域，并与 MCP schema 一起发布。

Agent 发文档的完整路径

1 生成Agent 生成并保存云盘文档，取得不可变版本。

2 找人按指定团队查用户 ID；同名或多团队歧义时向用户确认。

3 发送用户明确说「发给…」后提交正文与附件版本；服务端原子校验。

4 回执返回信件 ID、团队、收件人及发送结果，失败不声称已发出。

实施与验收

实施顺序

  1. 1. 先定团队成员查询、信件 ACL、附件快照与数据库迁移。
  2. 2. 上线服务端 API、实时事件、推送与审计，再接桌面和 iOS 共享契约。
  3. 3. 桌面独立应用与 iOS 主页功能同时覆盖收、发、读、回复、草稿。
  4. 4. 注册 MCP、系统 Skill、能力清单并补齐 Agent 指南；同步修订团队旧规格。

必须通过的场景

  • 两人或多人同团队发送成功；跨团队混选、禁用用户、离团用户发送失败。
  • 多团队用户选择团队后只看到对应成员；同名用户能区分。
  • 桌面发送后手机离线重连可收到；未读与删除跨端一致。
  • 源文档更新或撤销分享后，收件人仍能读取发送时附件版本。
  • 手机在 iPhone、iPad 全屏、半窗和窄窗均能写信、读信、返回原列表。
  • Agent 工具重试不重复发送，失败有明确回执；未明确指定收件人时不发送。
