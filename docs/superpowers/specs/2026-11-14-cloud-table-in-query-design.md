# 云表多值筛选性能修复

用户已授权按核查方案实施，保持当前 main 和现有部署边界。

## 目标

统计表 `key in [...]` 曾返回 `DB_STATEMENT_TIMEOUT`；同表单值等值查询正常。生产只读 EXPLAIN 显示前者扫描记录表，后者使用已有 JSONB GIN 索引。

## 方案

业务字段的非空 `in` 候选沿用 `eq` 的 JSONB 包含谓词，候选之间 OR；空值仍使用原来的 null-safe 比较，系统字段仍使用原类型比较及 UTC 时间归一化。保持字段校验、100 候选上限、表/权限/软删除边界、分页绑定和 2 秒 SQL 预算。无数据库迁移、索引或新依赖。

## 运维边界

本机 TeamRobot 只正常停止遗留独立 statistics，保留数据库/outbox，不启动或重载 PR 主服务。MacMini 继续采集；远端清理、发布积压与安全接入通过站内信交接。SY 生产切换不得使用包含无关云资源退役/数据库迁移的整版发布脚本；只准备本次修复，核对 PR 活动与安全切换条件后上线，条件不满足时明确保留待部署状态。

## 验证

先用单测固定可索引谓词、空值、false/0/空字符串、日期与系统字段行为，再实现最小变更。使用现有隔离 PostgreSQL 测试验证匹配结果与权限/分页；本机缺少依赖时如实记录。只读对照生产 SQL 计划与耗时，验证多值查询不再扫描全部统计块。相关云表测试、server 类型检查和构建通过后本地提交，仅包含本次修改。
