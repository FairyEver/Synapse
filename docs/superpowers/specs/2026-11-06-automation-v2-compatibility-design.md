# Automation V2 长期兼容设计

日期：2026-11-06。用户已选择保留现结构并授权直接完成设计、实现和验证，无需再次审批。

## 目标与边界

保留单 trigger、单 executor、独立 conditions/policy 的 V2 结构。新客户端持续读取历史 V2；不认识的新配置只隔离对应任务，不能静默丢字段、误执行或清理。V1 继续停用、只读、不迁移。本次不增加业务配置、不新增依赖、不启动应用、不部署、不 push。

## 方案比较

- 采用：保留结构，加入格式修订、统一兼容检查、原始数据保留及按条目隔离。复用现有注册表和 validation 诊断。
- 未采用：重排为 spec/status 或扩展大口袋。迁移范围大，不能直接解决未知字段执行和保存问题。

## 契约

- `schemaVersion` 是整体结构版本；新建仍为 2。新增可选 `formatRevision`，缺省按 1，新建显式写 1；它不是编辑计数 `configVersion`，也不改变 DataRepository namespace 版本。
- 当前支持 V2 修订 1；未来修订、未知条件/执行语义、未知触发器或执行器只读保留。兼容检查由主进程统一执行，所有运行、启用和保存入口复用；Renderer 接收派生 `readOnly` 和既有 validation。
- 缺省只匹配 undefined；null、非整数、0 和负数不降级为修订 1。未来版本绝不自动降级或覆盖。未来转换必须在明确的修订边界提供纯转换及回归测试；本次没有需转换的数据，不创建空迁移框架。
- 存储校验只约束稳定的条目外壳，不在存储层限定业务枚举。scope/policy/conditions 的语义在单任务校验中处理，避免一条未来策略使整个集合不可读。仍要求稳定外壳的 id/name/refs/时间及计数字段；损坏 JSON 和完全不符合外壳的数据沿用 DataRepository 错误，不承诺恢复任意损坏文件。
- 保存严格校验写入参数。触发器/执行器 schema 的未知字段（包括嵌套字段）不得被 parse 静默丢弃。未知执行配置只读保留，已知但不合法的配置仍可编辑修复。原始配置和未知顶层元数据经 repository 的 spread 保留；不向 MCP 原样透传未知数据。
- policy 更新合并旧策略而不是重建；已知值必须显式校验，不能强制把未知值改为 skip。
- `trigger` / `executor` patch 继续整体替换，conditions 继续 undefined 保留、null 清空；传输层不静默丢弃未知写入字段。
- 执行语义变化（新增条件、策略、改变既有字段含义）必须提高 formatRevision；纯展示元数据及保持旧行为的可选字段可以保持修订。未来 revision 由支持它的新客户端负责转换，禁止用 bump 代替迁移实现。
- 自动清理仅针对明确退役清单，未知执行器不是退役执行器；未来修订或未来 schemaVersion 不参与清理。备份恢复保留未来配置，版本不支持时强制停用，清除派生 nextRunAt；邮件仍清除本机订阅。
- IPC 读响应可承载未来版本/策略的稳定形状及只读诊断；MCP 继续白名单摘要，公开工具数量不变。

## 验证

覆盖缺省修订、新建修订、未来/非法修订、未知嵌套配置、严格 schema、未知策略、未知类型、单条隔离、全部运行入口、编辑和启用拒绝、V1 隔离、清理和备份往返。运行自动化专项测试、相关 Renderer/IPC/存储测试、typecheck 和硬约束检查。不启动应用。

## 风险与回滚

旧版（本改动发布前）客户端无法被追溯修复，不能保证它读取未来配置的安全。新增执行语义必须提高修订，未来升级须实现对应转换。回滚代码不修改任务配置；保留新增修订字段，禁止批量降低版本或清理未知任务。
