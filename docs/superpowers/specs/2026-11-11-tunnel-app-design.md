# 内网穿透应用设计

日期：2026-11-11

状态：设计草案，待用户批准；已完成独立 builder check，未发现阻塞实施计划的重要未决问题；尚未开始产品实现。

范围：Synapse Desktop、Shared、Server，以及公网 DNS / TLS / 入口配置。

## 1. 目标与已经确认的要求

在 Synapse 内增加独立的「内网穿透」应用。用户只填写本机端口并点击「申请」，后台真实分配公网 HTTPS 子域名，将外部请求代理到申请时那台电脑上的对应服务，再把真实响应返回访问者。

用户已明确确认：

- 同时支持本地网站和接口；网站需要能够打开、跳转和操作。
- 每条映射使用独立子域名，采用 Synapse 原生集成方案。
- 拿到链接即可访问，不要求访问密码或 Synapse 登录。
- 一个账号可以申请多个链接，分别对应本机端口，同时使用。
- 链接长期固定；停止、退出、断网、重启不改变地址。
- 启动 Synapse 后自动恢复之前开启的映射。
- 申请必须真实经过后台接口；不在界面中生成虚假可用链接。

「网站可用」包含普通 HTTP、二进制、上传下载、重定向、Cookie、WebSocket 和 SSE。它不意味着能自动改造所有写死 localhost 或专有开发协议的网站。

## 2. Approaches

| 路线 | 收益 | 代价 | 决定 |
| --- | --- | --- | --- |
| A：原生集成，复用账号、设备身份、Node 网络能力和现有 ws 依赖 | 申请、归属、启停、恢复与 Synapse 一致；不附带额外二进制 | 自行实现并验证隧道生命周期、背压和代理兼容 | 用户选择 A |
| B：内置 frpc / frps | 复用成熟穿透传输实现 | 增加进程、跨平台产物、升级和凭据管理 | 未选择 |

原生集成使用**独立控制连接和数据连接**，不把网站字节塞入现有 Live、通知、终端或 Automation 事件。

## 3. 本设计提出的默认决定

以下是设计建议，不应表述为用户已逐项确认；批准本文即接受这些默认值，用户也可以修改。

- App ID / capability namespace：`tunnel`；中文名「内网穿透」。启动器可见、可独立开窗、可手动固定 Dock，不自动加入默认 Dock。
- 正式链接：`https://<label>.tunnel.d2.pub`；测试用 `tunnel-test.d2.pub` 不直接转为正式域名。
- `label` 使用 16 个密码学随机字节的 32 位小写十六进制字符串，不包含账号、电脑名称或端口。比路径令牌更严格地遵守 DNS label 字符限制。数据库唯一约束处理碰撞。
- 内部 ID 沿用服务端现有 Prisma 默认 ID 习惯，与公网 label 分离。公网 label 不承担管理认证。
- 目标是申请电脑的 `http://localhost:<port>`；只接收整数端口 `1–65535`。不增加名称、主机、路径、协议等必填字段。
- 本地解析固定在回环接口：优先 `127.0.0.1`，仅在提交业务字节前的连接拒绝等明确未建立连接情况下尝试 `::1`；不解析用户提供主机名。
- 新申请默认开启，即使本地服务暂未启动，也保留已申请地址并显示不可达。
- 每条映射绑定账号与申请时的设备安装身份；另一台电脑不会自动接管。
- 支持修改本机端口，地址不变；同一设备同一端口允许有多个独立链接，不隐式合并用户申请。
- 支持逐条启停、复制、浏览器打开和删除。删除需现有标准确认交互；删除地址永久退役，不重新分配给其他映射。
- 第一版提供对应 MCP 管理能力；不增加 Workflow Node、Automation Action、Deep Link、手机或 Console 管理页面。

## 4. 范围与非目标

### 必须交付

- 真实申请、固定地址、多条并行代理、逐条启停、修改端口、删除。
- 网站路径和原始查询串保留，包括 `/api`、`/assets`、刷新后的子页面路径。
- HTTP 请求与响应双向流式转发；WebSocket 双向转发；SSE 及时下发。
- 断网、休眠、服务端重启后重连；恢复开启状态，不重放访问者请求。
- 跨账号、跨设备隔离，登出 / 换号 / 停用后的连接清理。
- 正式通配符 DNS、可信 TLS、自动续期及可回滚的入口部署。

### 第一版不做

- 任意 TCP / UDP、SSH、数据库端口或 CONNECT 正向代理。
- 自定义域名、自定义子域名、密码访问、团队共享、账号授权访问、计费系统。
- 转发到任意局域网 IP、远程主机，或替用户启动 / 重启本地服务。
- 请求正文或响应正文的保存、请求历史回放、离线请求队列。
- 自动修改用户项目、重写 HTML / JS、为同一网站发现和穿透其他端口。
- 更换电脑、重装丢失设备凭据后的自动域名接管；保留旧映射并明确不可恢复原因，不把旧地址绑定到新电脑。

## 6. 产品流程

### 申请

1. 用户在应用输入一个端口，点击「申请」；需要当前 Synapse 账号已登录且管理服务可用。
2. 主进程校验端口，检查本机网络操作权限，并持久化本次申请意图及稳定请求标识。
3. 主进程调用后台分配接口。后台事务记录账号、设备、端口和唯一 label，返回固定 URL 与版本。
4. 本地保存经用户授权的绑定。启动专用隧道连接，后台确认当前设备已就绪后进入「运行中」。
5. 地址分配成功和转发就绪是两件事：本地服务不可达时仍显示地址及「本地服务不可用」，不谎报申请失败、不再次分配。

### 启停、修改与删除

- 停止保持域名与端口；服务端先撤销准入并终止本映射活动流，再确认停止。
- 开启使用原地址，需在原设备具有相应本地授权；开始或恢复连接后才显示运行中。
- 修改端口使用乐观版本校验；新端口重新检查本地授权。变更成功后旧版本活动流关闭，不让旧票据指向新端口。
- 删除以服务端成功为准，立即拒绝新访问、结束活动流、停用本地恢复；保留退役 label，永不重用。
- 云端变更失败保留原状态；结果未知时查询原请求结果，不换请求标识重复创建。

### 自动恢复

- 不阻塞主窗口创建。账号就绪、设备身份及本机授权恢复后，后台读取当前设备映射并恢复 `enabled=true` 的项目。
- 不要求先打开「内网穿透」页面。关闭该应用页面不停止穿透；退出 Synapse 才断开运行通道。
- 网络暂不可用时有界退避并加入抖动，恢复后使用原域名。
- 本地服务未启动时保持开启意图，应用显示不可达；后续请求 / 有界探测确认服务恢复。
- 用户登出或切换账号立即关闭旧账号所有控制与数据流，清除内存授权；不得自动使用磁盘中的其他账号凭据继续穿透。
- 换号后回到原账号，只在同一设备与本机授权仍有效时恢复；停止的项目不自动开启。

## 7. 数据归属与一致性

### 云端是域名分配和启停意图的权威

建议新增领域表（名称可按 Prisma 习惯调整）：

- `UserTunnel`：内部 ID、userId、clientInstanceId、port、label、enabled、revision、createdAt、updatedAt、deletedAt。
- `(label)` 全局唯一；删除后保留该值。查询始终带当前 userId / 设备条件和分页限制。
- 创建操作持久记录 `requestId`、请求摘要与结果引用；`(userId, requestId)` 唯一。相同 ID 和相同参数返回原结果；参数冲突拒绝；已删除对象不因重试复活。
- `TunnelDeviceCredential`：userId、clientInstanceId、设备凭据哈希及撤销状态。不得保存设备凭据明文。

`enabled` 表示用户希望开启，不等于当前连接状态。online、连接代次、活动流和一次性票据仅在运行时内存中持有；重启全部失效，不能从数据库假装恢复在线。

### 本机保存运行授权，不建立第二套域名分配权威

- 通过 DataRepository 管理 `app.tunnel.bindings`（sqlite，local-only）和 `app.tunnel.credentials`（encrypted-json，local-only）；记录带 schemaVersion。
- 本地绑定包含账号、映射 ID、设备身份、已经批准的端口与云端 revision，以及申请操作请求标识；不保存请求 / 响应内容。
- 自动恢复必须同时满足云端开启、本机绑定一致、当前账号 / 设备一致、PermissionGuard 授权有效。
- 配置备份或同步不得把开启的穿透授权移植到另一台设备；本地凭据不出现在普通数据导出中。
- 云端成功、本地提交失败时保留云端地址并显示待恢复 / 待确认；重试复用原请求结果。未完成本机授权前不处理代理请求。
- 对启停 / 删除 / 修改使用 revision 比较和同映射串行操作。晚到响应不得覆盖新状态。

## 8. 认证与设备绑定

复用账号认证与设备标识，不把 Live 的 `clientInstanceId`、设备名称、机器摘要或公网 label 当作认证证明。

- 首次使用时，本机生成 32 个随机字节的设备密钥，先经加密 DataRepository 持久化，再向后台登记哈希。
- 注册需有效用户身份。同一账号 / clientInstanceId 已登记时，只接受能证明持有原设备密钥的请求，不能凭同一账号 token 静默覆盖原绑定。
- 管理操作校验账号归属。创建、启用及修改端口还需与正在操作的原设备证明绑定；不把 Renderer 传入的任意设备 ID 当作授权。
- 控制连接使用当前账号 Bearer 认证，并在有限大小、有限时长的 hello 中证明设备密钥。设备密钥及认证帧不记日志。
- 控制连接每 20 秒心跳，45 秒未响应视为离线；定期通过现有账号认证服务复核账号与访问 token，有效期结束或账号失效即断开。token 更新经专用认证更新消息重新验证。
- 不新增绕过现有账号登出、禁用、改密失效语义的长期用户 token。服务端撤销通知与心跳复核覆盖已经建立的长连接。
- 同一账号 / 设备仅一个当前控制代次；新连接经过完整验证后替换旧代次，旧代次及其活动流和未用票据全部失效。

## 9. 控制面与数据面

### 入口

- 管理 REST：`/api/tunnels` 下的本人认证接口，遵循现有 Controller → Service → Prisma 层次。
- 专用控制 WSS：`/api/tunnels/control`。
- 专用数据 WSS：`/api/tunnels/data`。
- 控制 / 数据协议在 `shared/` 中版本化，拒绝不支持的版本和格式；二者不扩展 Live 消息联合类型。

### 网站流量与管理 API 物理分流

服务端新增独立的原始 HTTP ingress listener，生产只绑定容器内 `127.0.0.1:3002`，不映射宿主机端口。开发使用 Synapse 预留范围内的 `127.0.0.1:19703`，同步开发端口表与启动配置。

- Caddy 的 `*.tunnel.d2.pub` 统一转给现有宿主机回环入口 `3000`，保留经过校验的 Host。
- 容器 Nginx 为严格的 tunnel 主机名设置独立 server 分流到 `3002`，普通站点继续走现有 API / dashboard。
- tunnel 主机下的任何路径（包括 `/api/tunnels`、`/api/live/desktop`、`/console`）都只能代理本地服务，绝不进入 Synapse 管理路由或现有 WebSocket gateway。
- ingress 使用 Node HTTP 处理原始流，不经过 Nest 的 JSON / 表单 / Cookie 解析、平台 CORS、页面 CSP 或正文日志中间件。
- listener 由业务模块通过 bootstrap 装配，随服务有界关闭；不引入新的公开监听端口。Electron 桌面不为穿透绑定本地监听端口。
- 从严格 Host 中解析唯一 label；多重 / 无效 Host、错误后缀、非单层 label 直接拒绝，不使用请求体、query 或客户端自报 userId 选择目标。

### 一次访问

1. ingress 从 Host 查到启用映射，并找到所属账号、设备的当前就绪控制代次。
2. 生成一次性高熵数据票据，绑定映射 ID、revision、账号、设备、控制代次及服务端请求 ID，10 秒过期；只在内存保存摘要。
3. 控制连接通知该设备建立数据 WSS。数据连接需账号认证，并提交一次性票据；只允许原设备 / 原代次原子消费一次。
4. 桌面再次校验本机绑定、端口、revision、开启状态及权限，连接固定回环端口。
5. 双方明确确认数据通道就绪后才发送业务字节。通道承载 HTTP 连接字节，使用现有 ws 的二进制 / stream 能力和 Node 流背压，不用 JSON / Base64 搬运正文。
6. 每个普通 HTTP 请求独享一个数据连接，不复用上游 keep-alive；完成响应后释放。WebSocket 升级后该连接保持双向转发，直到关闭。

控制帧只承载有界元数据。业务数据不与控制帧混流；握手后禁止再把二进制正文解释为控制消息。客户端取消、任一端关闭、停用、修改、删除、连接换代和身份失效均必须释放双端连接、票据、计时器和并发配额。

## 10. HTTP 与网站兼容契约

- 保留方法、原始路径和查询串，不添加 `/port/<id>` 前缀，不对编码路径反复 decode / encode。
- HTTP 传输由 Node HTTP parser / serializer 处理，不手拼可注入的请求头字符串。
- 请求和响应删除 hop-by-hop 头、Connection 指定的头，以及不再成立的长度 / 分帧信息；正常压缩字节、二进制、流式分块不解压、不重序列化。
- 上游 Host 默认改为本机目标 `localhost:<port>`，支持常见开发服务的 Host 校验。公网原始 Host / scheme 由服务端覆盖设置可信的 `X-Forwarded-Host` / `X-Forwarded-Proto`，不沿用访问者伪造值。
- 保留应用自身的 Authorization、Cookie、Origin 和 Referer 语义，不注入 Synapse 的账号 token / 设备密钥，不把平台登录 Cookie 加进隧道请求。不自动放宽应用 CORS / CSRF 校验。
- 对 Location 中精确指向本目标 localhost / 127.0.0.1 / ::1 及端口的绝对 HTTP 地址改为对应公网 HTTPS origin；同源根路径和正常相对地址直接保留，其他第三方跳转不改写。
- Set-Cookie 保留多值和标准属性；移除精确指向本机目标或公网 tunnel 上级域的 Domain 属性，使其成为当前公网主机的 host-only cookie。不得把域改成 `.d2.pub` / `.tunnel.d2.pub`，也不允许 HTTP 响应借上级域 Cookie 影响其他映射；其他 Cookie / 安全属性不推测修改。
- 不透传访问者伪造的 Forwarded / X-Forwarded-* 身份头。统一构造可信转发信息；客户端 IP 只能来自经过配置校验的入口链。
- WebSocket：转发正常的 upgrade handshake、子协议、非 101 拒绝响应，以及双方 parser 已读的 head 字节；101 之后仅转发字节，不双重解析浏览器 WS 帧。不让另一条映射消费该连接。
- SSE：不积攒完整响应、不缓存，Caddy / Nginx / Node 全链路及时 flush；普通请求也不通过边缘缓存分享用户内容。
- 同时保留 Host / 路径解析、头大小、帧大小、超时与并发上限，拒绝请求走私和无限缓冲；不实现 HTTP/2 到本机、h2c 或任意 Upgrade 协议。公网 HTTP/2 可以在 Caddy 终止并转为内部 HTTP/1.1。
- 只承诺代理这个端口。页面写死另一个 localhost 端口、OAuth 白名单、特定 Origin 校验、显式 HMR host / clientPort 等需本地项目自身适配；不静默修改项目或禁用它的安全设置。标准同源 Vite 页面和 WS HMR 必须作为验收用例。
- 不把不同子域名误认为不同浏览器 site：这些地址仍属于 `d2.pub`，不能只依赖 SameSite 防护。上线前验证 tunnel 页面不能利用浏览器会话写入 Synapse 管理面；对平台 Cookie 认证的写操作执行精确受信 Origin 校验，拒绝 tunnel Origin，保持已有 Bearer 客户端语义。校验范围与现有认证组件复用，不能仅依靠 CORS。若验收发现必须改变平台 Cookie 格式或其他项目的认证模型，应先报告范围变化，不静默扩大到其他应用。

## 11. 状态、错误与资源预算

持久意图与运行状态分开：

| 状态 | 含义 | 恢复方式 |
| --- | --- | --- |
| 申请中 | 分配尚未确认 | 查询原 requestId，不重复分配 |
| 已停止 | enabled=false | 用户开启 |
| 连接中 | enabled=true，控制 / 设备就绪尚未确认 | 后台重连 |
| 运行中 | 当前代次认证、映射确认、本地连接检查成功 | 请求仍单独处理连接失败 |
| 本地服务不可用 | 设备在线，但回环端口不可达 | 保持地址与开启意图，服务恢复后继续 |
| 电脑离线 | 当前设备没有有效控制连接 | 同台电脑登录 / 重连 |
| 待授权 / 配置不一致 | 本机授权缺失或绑定与云端不一致 | 显式恢复，不自动扩大授权 |

外部未知地址返回 404，已删除地址返回 410，停止 / 离线返回 503，本地连接失败返回 502，建立通道或响应头等待超时返回 504，超出额度返回 429 / 503（分别对应账号 / 全局容量）。错误响应不透露本机端口、设备标识、系统路径、账号或底层异常。

若响应头已发出后发生错误，终止当前流，不能把错误 HTML 混入下载或 SSE。映射可继续使用，但不重放本次请求。

初始预算是设计默认，可通过受校验的部署配置调整，不能在 UI 上假装无限制：

- 每账号最多 100 条未删除映射；同映射最多 16 条、同账号最多 64 条、全局最多 256 条活动数据流。
- 请求正文最多 64 MiB（流式计数，Content-Length 已超限时提前返回 413）；响应流不因累计文件大小缓存到内存。
- 握手 / 控制帧最多 8 KiB，二进制消息最多 64 KiB；单方向待发缓冲最多 256 KiB，全局待发缓冲预算 64 MiB。达到背压阈值暂停读取，不丢正文、不靠无限队列维持连接。
- 本机连接最多 5 秒；数据建立最多 10 秒；响应头最多 30 秒。普通 HTTP / SSE 业务空闲最多 5 分钟，SSE 无固定总时长；WebSocket 使用双端连接存活检查，没有固定业务总时长。
- 限制匿名新建连接速率，配额按账号及映射聚合；WS / SSE 在整个存活期占用名额。精确速率值及负载压测调参留给实施者，不能把限制只放在桌面。
- 本地 IPv4 → IPv6 回退只允许在未提交业务字节前发生；请求发出后不因网络错误自动重试，尤其不能重复 POST。

## 12. 桌面应用、能力与工程边界

本节描述操作契约，不确定最终视觉布局；后续 UI 继续使用现有应用壳和 shadcn / Radix 组件，不生成新视觉系统。

- 入口位于 `desktop/app-capabilities/tunnel/`，按 shared / main / renderer 分层，业务服务通过 ServiceRegistry 组装。
- 顶栏 / 独立窗口复用 SystemAppWindowShell，不增加第二条应用顶栏。
- 申请表单唯一必填项为「本机端口」，操作为「申请」。不显示 DNS、证书、ticket、代理协议等实现参数。
- 列表展示公网链接、本机端口、所属电脑、启停意图和运行状态。默认显示当前电脑，允许只读查看当前账号其他电脑的映射；不能从本机开启另一台电脑的端口。
- 已停止、申请失败、待授权、本地不可达、登录失效与空列表分别给出必要状态。错误绑定到具体操作，不隐藏已分配地址。
- 菜单、复制、启停与删除遵循项目默认组件和尺寸；多窗口操作以主进程及云端 revision 为准。
- Renderer 只用窄类型化 preload bridge；不直接访问网络、文件、密钥或端口。
- 网络、连接恢复、本机回环连接均经过 PermissionGuard / AuditSink；首次用户动作完成必要授权，后台恢复不静默授予新权限，也不阻塞主窗口等待审批。
- 通过 EventBus 发布有界状态变化，不广播业务正文、凭据或数据帧。日志只记映射内部 ID、结果类型、状态、耗时和流量计数，不记 URL query、Cookie、Authorization 或请求 / 响应内容。

建议 capability / MCP 共用六项业务操作：

| 规范操作 | 作用 |
| --- | --- |
| `app.tunnel.mapping.list` | 按当前账号 / 可选当前设备分页读取摘要 |
| `app.tunnel.mapping.get` | 读取一条本人映射与运行状态 |
| `app.tunnel.mapping.create` | 当前电脑申请端口映射，支持稳定请求标识 |
| `app.tunnel.mapping.update` | 当前电脑修改端口，带 expectedRevision |
| `app.tunnel.mapping.set_enabled` | 当前电脑逐条启停，带 expectedRevision |
| `app.tunnel.mapping.delete` | 删除本人映射并永久退役地址，带 expectedRevision |

列表 / get 可以返回完整公网 URL，因为访问本来不要求另行认证；设备密钥、数据票据和账号 token 不进入 MCP。分页风格与续页字段按现有 DTO 明确说明。

实施时同步 capability registry 的应用、MCP、Dock 与例外说明；确认 Workflow / Automation / Deep Link 均无增量。补充系统 Skill 包与 Agent 指南；以当前注册基线计算数量，不能复制旧文档中的过时总数。

## 13. 正式基础设施与证书续期

- 正式新增 `*.tunnel` 的 DNS A 记录和 `*.tunnel.d2.pub` 通配符证书。`*.d2.pub` 或单域名 `synapse.d2.pub` 证书不能覆盖这一层。
- 优先复用现有 ACME 客户端和 DNSPod 验证能力，不为本功能擅自替换共享 Caddy 镜像、安装插件或覆盖其他站点。
- 自动续期需要部署侧 DNSPod 授权。当前未获取该授权，不把浏览器登录当成可用于长期续期的 API 凭据；具体可用授权方式实施时核对 DNSPod 和现有 ACME provider 契约。
- DNS 凭据只用于部署 / 续期，按系统支持收窄权限，保存在服务器既有受保护凭据位置；不进源码、桌面、业务表或普通日志。
- 续期任务提前续签，将候选证书写入独立位置，检查域名、有效期、链和私钥匹配，Caddy validate 成功后安装并热加载；失败保留仍有效旧证书，不能覆盖成损坏文件。需有可观察的续期失败状态。
- 正式上线前必须验证自动签发 / 续期及 Caddy 加载链路；手动测试证书不能代替此验收。
- Caddy 和 Nginx 的 tunnel 分流禁用访问正文 / query 日志、缓存、请求 / 响应缓冲，保留 WS Upgrade 和 SSE。未知 tunnel label 必须落在专用入口而不是现有应用兜底。
- 正式域名启用是部署步骤，不在每次申请时操作 DNS、申请证书或 reload 入口。
- 保留共享入口配置快照与校验，采用带精确标记的增量修改；回滚只撤销本功能区块，不覆盖期间其他项目的修改。

## 14. 验证与交付

### 需要的回归证据

1. 申请 / 幂等 / 乐观锁 / label 碰撞与永久退役；跨账号拒绝；同账号其他设备不能冒领或开启。
2. 多端口同时访问；同端口多个链接；修改、停止、删除立即撤销旧流与票据。
3. 模拟同一设备重启、断网和服务端重启，原域名恢复；关闭应用页面不停止；登出 / 换号关闭旧流。
4. HTTP 方法、原始编码路径、query、多值头、二进制、压缩、分块上传、大下载与取消；无完整正文缓冲；未重放非幂等请求。
5. SSE 首段及时到达及持续推送；浏览器 WS 消息、子协议、拒绝升级、head 字节和关闭；普通同源前端网站、深路由刷新、资源、登录 Cookie、本机 Location、Vite HMR。
6. 浏览器打开真实 HTTPS 域名验证系统信任，不使用忽略证书错误；创建配置后新增随机 label 仍可访问。
7. 无效 Host、路径伪造、ticket 重放 / 过期 / 跨映射 / 跨设备 / 旧 revision、未认证大帧、慢客户端、超限、端口不可达和权限拒绝。
8. tunnel 域名访问 `/api` / `/console` / Live 路径不能访问 Synapse 管理面；恶意 tunnel 页面不能借访问者的平台 Cookie 或上级域 Set-Cookie 完成管理写入；现有站点与 Live / Webhook 不受新增入口影响。
9. 本地 DataRepository 导入 / 导出不能移植开启授权；并发窗口不产生重复申请，未知结果可以查询恢复。
10. Caddy / Nginx / API / Desktop 全链路流式与关闭测试，续期候选验证及失败保留原证书。

## 15. 部署与回滚

- 数据迁移只新增本领域表和索引，不改已有用户数据；先备份、迁移预演，再按部署步骤启用。
- Server / ingress 与入口规则就绪后再允许创建正式映射；旧桌面不注册控制连接，不影响既有功能。
- 保留独立部署开关，关闭后停止新申请和公网准入，现有域名分配记录不删除。
- 先阻断新请求，再有界结束活动流；服务退出不得无限等待 WS / SSE。
- 回滚应用版本时保留域名 / 操作记录和已发布 schema；不能通过删表或重新分配 label 假装回滚。
- DNS / TLS / 入口分别保留恢复点；不要撤销其他项目的证书、DNS 或共享 Caddy 设置。
