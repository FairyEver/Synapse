## 确定行为

1. 面额 1、5、10、25、100、200、500，各有固定颜色。按每笔实际追加拆分：501 为 500+1；五笔 100 仍为五枚 100，原始累计库存不换成大面额；绘制超过200枚时按第9条等值合并。
2. 玩家剩余筹码按其服务端可用余额呈现，不把冻结补偿计为可用。少量面额可混摞，同一摞按面额连续分组；轻微固定错位、旋转和簇状布局，刷新不随机洗牌。
3. 普通下注直接从玩家前方飞入普通底池。Roll start 的实际费用进入另一堆；choose 不重复扣费、添筹码。两堆物理和金额均隔离。
4. 服务端提供按逐笔拆分累计的面额计数和最近公开资金动作。刷新/重连恢复精确筹码堆，不重播历史动画；不依赖最近30条普通动作猜测整手面额。盲注按本手原始参与者与实际短筹码计算。
5. 普通底池的主池、边池、平分和返还完全使用 settlement.pots.shares；Roll 补偿使用 settlement.seats.rollReceived。普通派发后再释放补偿，不在前端推断赢家或重算受益人。
6. 展示余额在派发期间扣留尚在飞行中的收入，落地后增加；底池数字随入池/离池逐位滚动。所有筹码派发和数字动画结束，才允许自动或手动打开结算面板。
7. 初次打开已结算手牌直接显示最终余额和结算，不重放历史派彩。重复轮询不重播，快速连续动作不丢掉仍在飞行的批次；换手、换房、换账号/视角、隐藏页面、布局变化或卸载会清理旧动画与回调。
8. 保留既有三场景 contain、座位/暗牌权限、玩家信息入口、底栏和系统面板；结算继续使用原有 HeroUI，准备必须显式执行。
9. 减少动态效果时即时完成展示，但不跳过金额更新。所有金额必须完整绘制为实体筹码，不使用数量标记、文字溢出或截断。静态筹码堆和飞行动画共享200枚目标：未超过时保留原面额；超过时先用原有不大于500的面额等值整理，仍超限则由超出的枚数反推需要将多少对500合并成1000，只引入满足目标所需的最少1000筹码，面上显示小写“1k”。如果最大1000面额下仍无法满足200枚目标，允许超过目标继续全部绘制。1k仅属于展示类型；原始库存、逐笔记录、公开schema、资金与派彩核对保持原面额和金额。

## 玩家余额逐位滚动（2026-11-02）

- 本人及其他所有座位的剩余筹码金额统一复用底池的逐位滚动组件，金额增减、进位和千位分隔均沿用现有行为；派彩仍在筹码落地后更新展示余额。
- 各座位的数字动画独立计入结算屏障，不能因普通底池及 Roll 费用动画结束就提前打开结算。座位卸载会解除对应数字动画状态。

## 动画性能维护（2026-11-02）

- 等值筹码计数复用布局和筹码组件，边缘八个标记合成一个SVG路径；保留原有面额、数量、错落位置和飞行数量。实体厚度使用圆形阴影及等效2D压缩，替代逐枚三重滤镜和3D变换；静止数字不常驻声明will-change。
- 新飞行批次先集中读取每个唯一锚点，再启动动画；已有批次不重复测量。数字仅在打断已有动画时批量读取位置，使用未缩放的自身高度衔接，避免contain缩放下跳动。

## 逐枚筹码音画同步（2026-11-02）

- 用户要求声音次数对应实际变化的筹码，与下注金额无关；每一声对应一枚筹码动画结束。
- 筹码碰撞只由实际飞行元素的落地完成事件触发：WAAPI 的单枚 `finished` 成功回调，或 CSS 降级的单枚 `animationend`。覆盖普通下注、Roll 费用、普通派彩、返还及 Roll 补偿；飞行筹码沿用第9条等值整理后全部绘制，一枚落地只发一声；不按合并前原始枚数补声。
- 不再从快照金额、街末收池或本人净赢金额生成碰撞/落袋组合，避免与真实落地重复。静态筹码堆重排、首次进入、历史重连及减少动态效果即时完成均不制造落地声；取消、失效及重复结束事件不发声，兜底计时器只解除展示屏障。
- 使用现有单枚 `chip-lay-1.ogg`，轻微改变播放速度和单枚力度，不随金额提高音量。逐枚声音保留尾音，后续落地及快照类反馈不截断它们；静音、失焦、隐藏及卸载仍立即停止全部声源。
- 不新增组件、依赖、接口、MCP 能力或系统 Skill 参数，不改变资金/准备协议；游戏更新不进入发布说明。
