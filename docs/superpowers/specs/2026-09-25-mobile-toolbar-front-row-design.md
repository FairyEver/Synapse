## 1. 要解决什么

手机工具栏中间那一排，此前全部是电脑的投影：电脑的内置键（`回车`、`Ctrl+C`、`Clear`、`/exit`、`/clear`）加上用户自己写的指令，一起随 `mobile.toolbar` 发下来。

这条规则让「手机需要一颗键」变成「先教会电脑」。手机的处境和电脑不一样：它没有物理键盘，所以它需要方向键和 `Tab`，而这两颗在电脑的内置表里根本没有——要让手机拿到它们，得先在电脑的工具栏上加两颗粒子。两端的按钮长得像，需要的键却不同，强行绑成一件事只会越来越别扭。

这一轮把它们拆开：**前段各端在自己的代码里定义，协议只负责传用户自己写的那部分。**

---

## 2. 决策

### 2.1 前段各自定义

| | 前段（固定键） | 后段 |
|---|---|---|
| 电脑 | 自己的内置键，在能力包的注册表里（现状不变） | 用户写的指令 |
| 手机 | 自己的七颗，在 `TerminalToolbarState.frontRow` | 用户写的指令（电脑下发） |

`Clear` 仍然只在电脑上：它清的是电脑自己的渲染器，到不了 PTY，画在手机上只会显得按了没反应。

### 2.2 协议只传用户自定义

`mobile.toolbar` 的 `buttons` 从此只装用户写的条目，**协议本身一个字没改**（没有新字段、没有新消息、服务端不用动）。生产这一份的是 `main/mobile-toolbar.ts`，它现在是一个纯函数：把存下来的自定义动作逐条原样搬成按钮，不 trim、不加引号、不转义——手机执行的必须是用户写的那条命令，逐字符相同。

### 2.3 手机的前段是哪七颗

```
↑   ↓   Tab   回车   Ctrl+C   /exit   /clear
```

- **方向键和 `Tab` 打头**，因为终端里的选择就是用它们拨的；`回车` 紧随其后，把选择交出去。
- **`Tab` 不只是补全**：Claude Code 每轮回答结束后会预测下一句、以暗色 ghost 文本画在输入框里，接受它的按键是 `→` 或 `Tab`——那段字并不在输入缓冲里，只按回车提交的是空输入，什么也不会发生。手机上这两颗原本就在键盘面板第一页（`2026-09-20` 那轮挪上去的），只是要先点开面板才够得到；现在它们在栏上，接受一次建议不必先开面板。
- **`Ctrl+C` 与两条斜杠命令保留原来的 id**（`interrupt`、`slash-exit`、`slash-clear`），按下它们的行为与电脑下发时逐字节相同，既有测试也因此继续按原来的名字找得到它们。
- **`Ctrl+L` 不在表里**：它是电脑自己的 clear，和 `Clear` 同一条理由。

### 2.4 前段跟着一起横滑

七颗一共 426pt（见 §4 的账），钉在滚动外面放不下，所以**前段就是横滑区的最前面**，⌘ 与 ⇧ 仍然钉在两端。默认第一屏看到的是 `↑ ↓ Tab 回车`，要看用户自己的指令才需要往左滑——这与电脑端工具栏的形状也一致（它同样是「自己的键在前、用户的指令在后、整条一起滚」）。

代价写在明面上：滑到右边时前几颗会滑出屏幕。换来的是用户自加的指令看得见、够得着。

### 2.5 回车不画两遍

前段已经有 `回车`，所以它不再出现在后段。过去由电脑下发的 `回车` 是**为了手机**才存在的一颗（电脑有键盘，不需要它），它现在回到了它该在的地方。

## 3. 协议与两端的边界

- **协议**：`MobileToolbarPayload` 不变。`buttons` 的语义收窄为「用户写的条目」，文档注释同步。
- **桌面端**：`main/mobile-toolbar.ts` 从「注册表 + 用户动作 + 字节表」的投影缩成一个纯映射；`KEY_BYTES` 与 `MOBILE_KEYS` 的对照不再参与投影，但它们自己的规格（字节表必须逐条正确、两套词汇必须是同一集合）搬到 `main/__tests__/key-bytes.test.ts` 继续守着。
- **桌面端自己的工具栏**：一个字没改，仍然读 `shared/toolbar-actions.ts` 的注册表。
- **手机端**：`TerminalToolbarState` 的前段是 `frontRow` 常量；`adopt` 只收 `group == .custom` 的条目，`buttons(forSelected:)` 返回「前段 + 该电脑的自定义」。

## 4. 几何

工具栏左右各 12pt 内边距；iPhone 393pt 宽时中间共 281pt（已扣掉两端各 44pt 的 ⌘ 与 ⇧）。胶囊按 `.subheadline` 等宽字体 + 12pt 内边距量：

| 键 | 宽 |
|---|---|
| `↑` / `↓` | 48（最小宽兜底） |
| `Tab` | 51 |
| `回车` | 54 |
| `Ctrl+C` / `/clear` | 78 |
| `/exit` | 69 |

前段七颗合计 **426pt**，远大于 281pt——这就是 §2.4 必须横滑的原因，也是「七颗常驻」这个方案在手机上不成立的原因。

## 5. 边界与异常

### 5.1 电脑比手机旧（还在下发内置键）

新手机只收 `group == .custom`，所以旧电脑多下来的四颗内置键会被丢掉，由手机自己的前段顶上。**不会有重复的 `回车`。** 反过来，旧手机收到的 `buttons` 里没有内置键了，它的工具栏会少掉 `回车`/`Ctrl+C`/两条斜杠命令——需要用的时候把手机一起升上去。

### 5.2 电脑一台指令都没配

`buttons` 为空是合法答案，含义是「这台电脑上没有用户写的东西」。栏上仍然是前段七颗，**不会画出一条空栏**。

### 5.3 电脑从没发过这条消息

与 5.2 在手机上看不出区别，都是前段七颗。这正是要保证的性质：没有物理键盘的手机，一条空栏等于什么都答不了。

### 5.4 切电脑 / 退出登录

- 切到另一台电脑：前段不变，后段换成那台电脑的自定义（没有就是空的）。
- 退出登录：后段清空（那是另一个账号的电脑的命令），前段保留——它属于手机，登出不会让它忘了怎么按回车。

### 5.5 用户加了很多指令

横滑区没有上限，前段会被推到屏幕外。这是 §2.4 接受的代价。

---

## 6. 实施约束

- 协议零改动：`MobileToolbarPayload`、`MOBILE_KEYS`、服务端转发都不动。
- `KEY_BYTES` 与 `MOBILE_KEYS` 必须继续是同一集合：手机发的是键名，电脑在 `service.ts` 里把键名换成字节写进 PTY。
- 手机前段的 id、label、action 由 `TerminalToolbarTests` 逐条钉死——它是本地常量，没有别的地方会替它检查拼写。

---

## 7. 验收基线

1. 打开终端，横滑区第一屏是 `↑ ↓ Tab 回车`，四颗都能点到。
2. 按 `↑` → 电脑端收到 `key:ArrowUp`；按 `Tab` → `key:Tab`；按 `回车` → `key:Enter`。
3. 电脑发来四条内置键 + 两条自定义 → 栏上是 **11** 个 `toolbar-` 元素：两颗固定键 + 手机前段七颗 + 自定义两颗。**内置键不在后段重复出现。**
4. 电脑发来空列表 → 自定义那部分为空，前段七颗仍在，`toolbar-enter` 存在。
5. 电脑发来一条自定义指令 → 它排在前段之后，横滑一次够得到，按下电脑收到同样的字节。
6. ⌘ 与 ⇧ 两颗固定键不随横滑移动（改前的性质不能退化）。
7. 手机自定义指令的增删改仍然整体替换（不是合并）。
8. `pnpm --filter @synapse/desktop run test` 与 typecheck 通过；手机端 `TerminalToolbarTests` 通过。

---

## 8. 非目标

- **改键盘面板**：两页、修饰键锁存、面板一档高度，一个字不动。
- **改协议**：不加字段、不加消息。
- **改电脑自己的工具栏**：内置键仍然是它的前段，`Clear` 仍然只在它那里。
- **把前段钉在滚动之外**：宽度不允许（§4），见 §2.4。
- **让用户编辑前段**：它是系统固定的，两端都写在代码里。
- **iPad 专门适配**。
