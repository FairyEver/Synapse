# Agent 对话过程折叠设计

日期：2026-06-27
更新：2026-08-25
范围：`desktop/src/modules/agent/` 对话时间线渲染层

## 背景

Agent 一轮执行可能连续产生 thinking、工具调用、工具结果和多段 assistant 文本。主时间线如果逐项展开，会反复打断阅读；如果过程组的 React key 随末尾事件变化，用户手动折叠后又会被当作新组创建，并在自动跟随模式下造成布局抖动和重复滚底。

目标体验与 Codex 一致：运行时可以查看当前过程，轮次完成后只保留最终回答，其他内容统一收进紧凑的“已处理”折叠组。

## Hard Rules

- 用户消息始终在主线展示。
- 已完成轮次只有最后一条 assistant 消息作为最终回答在主线展示。
- thinking、工具调用、工具结果、phase、可见 SDK annotation 和中间 assistant 消息都属于过程信息。
- 活跃轮次尚未产生可确认的最终回答，当前 assistant 流式文本也属于展开的过程组；轮次完成后再把最后一条 assistant 消息提升为最终回答。
- 失败、取消、超时或中断的轮次不得把中间 assistant 文本提升为最终回答。
- 待处理权限请求、不可恢复错误和失败、取消、超时结果必须保持主线可见。
- 图片型工具结果与其他工具结果遵循同一折叠规则，不建立单独展示分支。
- 分组只改变 renderer 展示结构，不改 timeline canonical model、历史记录、导出、IPC schema 或 Agent Runtime。

## 展示投影

展示层先执行现有 `timelineDisplayEntries`，继续把匹配的 `toolCall + toolResult` 合为一个 entry；随后按用户消息划分轮次。

每个已完成轮次按以下顺序生成 display nodes：

```text
用户消息
[已处理]  thinking、工具和中间 assistant，默认折叠
最终 assistant 回答
```

如果轮次没有过程内容，则不生成空折叠组。历史中没有用户锚点的兼容数据按一个 root 轮次处理。

待处理权限或终止错误会切断过程段并直接渲染；其前后的过程段继续保留。最终回答仍位于该轮次末尾。

## 稳定分组身份

过程组 ID 使用其前置主线锚点：

```text
process:<userMessageId>
process:<permissionOrErrorItemId>
process:root
```

不得把组内末尾事件 ID、事件数量或持续时间纳入 ID。thinking、工具进度、工具结果和中间文本继续追加时，同一过程组必须保持相同 ID 和 React key。

## 生命周期与展开状态

过程组生命周期只有两种：

- `active`：仅当前 `sending` 轮次，默认展开并显示“处理中”。即使一个工具刚返回且下一个事件尚未到达，也保持 active。
- `completed`：历史轮次或当前轮次结束后，默认折叠并显示“已处理”。

用户手动状态按 `groupId + lifecycle` 保存：

- 用户手动折叠 active 组后，本轮追加事件不得重新展开。
- active 转为 completed 时使用 completed 默认值，因此结束后强制折叠。
- 用户手动展开 completed 组后，普通重渲染不得再次折叠。
- 手动状态只保留在当前页面生命周期，不写入持久化数据。

## 时间与滚动

- active 组的持续时间从最早过程事件计算到当前时间。
- completed 组使用组内事件的实际起止时间，非法时间戳不显示时长。
- 折叠状态不进入聊天内容信号，不单独触发自动滚底。
- pinned 状态下的流式内容更新继续正常自动跟随；用户离开底部后仍暂停跟随。

## 非目标

- 不改变 `appendAgentTimelineEvent` 的消息合并与持久化语义。
- 不删除、改写或合并历史中的中间 assistant 消息。
- 不修改权限审批、附件、SDK、Provider 或会话恢复逻辑。
- 不新增样式、颜色、动画、依赖或新的界面文案。

## 验证要求

- 完成轮次只留下最后 assistant 回答，中间 assistant 和全部工具过程位于折叠组。
- 多个用户轮次各自保留最终回答，组 ID 以对应用户消息稳定锚定。
- 活跃组跨工具返回间隙保持 active，追加事件前后 ID 不变。
- 手动折叠 active 组后追加事件仍关闭；完成后默认关闭；completed 组可稳定手动展开。
- 失败、取消、超时不提升半成品回答，权限和终止状态仍直接可见。
- 图片工具结果随过程折叠，普通直接回答不产生空过程组。
- 展示状态重渲染不触发额外滚动，正常流式跟随测试保持通过。
