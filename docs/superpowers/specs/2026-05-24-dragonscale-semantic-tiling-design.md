# DragonScale Semantic Tiling Internalization Design

## Goal

Implement DragonScale semantic tiling as a Synapse-owned TypeScript service so knowledge-base projects can detect likely duplicate or overlapping wiki pages without copying or running `scripts/tiling-check.py` from the user's vault.

This is the next DragonScale migration slice after the current main-branch sequence:

1. internal upstream-script vendoring plus `DragonScaleAddressService`;
2. post-turn ingest address finalization;
3. read-only `DragonScaleBoundaryService`;
4. this phase: semantic tiling service and report generation.

The older umbrella spec called semantic tiling "Phase 5" because boundary scoring was listed as Phase 4. In the current implementation sequence, boundary scoring has already landed as phase 3, so this document names the next execution slice phase 4.

## Source Baseline

The upstream behavior baseline remains `AgriciDaniel/claude-obsidian` commit `75d3b6f`, using the vendored local oracle:

- `desktop/resources/knowledge-base/dragonscale/upstream/tiling-check.py`

The current upstream `skills/wiki-lint/SKILL.md` still describes semantic tiling as DragonScale Mechanism 3: an opt-in lint helper that runs `tiling-check.py --peek` and then `tiling-check.py --report wiki/meta/tiling-report-YYYY-MM-DD.md` when ready.

## Current Synapse State

Already implemented:

- User vault templates do not receive DragonScale scripts, skills, commands, hooks, agents, or full operational `CLAUDE.md` files.
- Vendored upstream scripts live under `desktop/resources/knowledge-base/dragonscale/upstream/`.
- Address allocation is handled by `DragonScaleAddressService`.
- Ingest address assignment is handled by `KnowledgeBaseIngestFinalizer`.
- Boundary scoring is handled by `DragonScaleBoundaryService`.
- Knowledge-base Agent behavior is isolated through `desktop/electron/services/knowledge-base/agent-contribution.ts`.

Missing:

- No TypeScript service replaces `tiling-check.py`.
- No Synapse-controlled embedding provider exists for knowledge-base tiling.
- `.vault-meta/tiling-cache.json` is not maintained by Synapse.
- `wiki/meta/tiling-report-YYYY-MM-DD.md` is not generated by a Synapse service.

## Hard Rules

- Do not copy `tiling-check.py`, helper scripts, Agent skills, commands, hooks, agents, or full operational prompts into the user vault.
- Do not invoke a shell script for the production semantic tiling path.
- Semantic tiling must be available only to knowledge-base services or knowledge-base project contributions.
- Ordinary Agent conversations, Scheduler runs, Workflow runs, and non-knowledge-base projects must not load tiling behavior.
- Page bodies may be POSTed only to a local Ollama endpoint by default.
- Remote embedding endpoints require an explicit option and must never be enabled through an untrusted environment variable alone.
- Symlinked pages and paths resolving outside the vault root must be skipped before content is read or embedded.
- Synapse may write knowledge-base data files:
  - `.vault-meta/tiling-cache.json`
  - `.vault-meta/.tiling.lock` if the implementation keeps a visible lock file
  - `wiki/meta/tiling-report-YYYY-MM-DD.md` only when the caller asks for a report
- Synapse must not modify source files under `.raw/` during tiling.
- This phase must not add a broad SDK custom-tool framework unless the user explicitly approves that separate runtime change.

## Upstream Behavior To Preserve

### Ollama Defaults

- Default URL: `http://127.0.0.1:11434`.
- Default model: `nomic-embed-text`.
- Health endpoint: `GET /api/version`.
- Model endpoint: `GET /api/tags`.
- Embedding endpoint: `POST /api/embeddings` with `{ "model": model, "prompt": body }`.
- Local hosts are `127.0.0.1`, `localhost`, and `::1`.
- Non-local `OLLAMA_URL` is rejected unless remote use is explicitly allowed.

### Status Mapping

The TypeScript service should not expose process exit codes as its primary API, but it must preserve the same distinctions:

| Upstream exit | Service status | Meaning |
| --- | --- | --- |
| `0` | `ok` | Report/check completed. |
| `2` | `usage-error` | Invalid option, unsafe URL, unsafe report path, or invalid thresholds. |
| `3` | `cache-corrupt` | Cache exists but is unreadable or structurally invalid. |
| `4` | `scale-exceeded` | Candidate page count exceeds the hard limit. |
| `10` | `ollama-unreachable` | Ollama health check failed. |
| `11` | `model-missing` | Ollama is reachable but the requested embedding model is absent. |

### Page Scope

Scan `wiki/**/*.md`.

Skip:

- symlinked files;
- paths resolving outside the vault root;
- files larger than `128 KiB` when encoded as UTF-8;
- unreadable or invalid UTF-8 files;
- filenames `_index.md`, `index.md`, `log.md`, `hot.md`, `overview.md`, `dashboard.md`, `Wiki Map.md`, and `getting-started.md`;
- paths under `wiki/folds/` and `wiki/meta/`;
- frontmatter `type: meta` and `type: fold`.

Semantic tiling scope is every eligible wiki page, not only `type: concept`.

### Frontmatter And Body

- Parse only the first YAML-style block delimited by `---`.
- Only `type` is required for filtering in this phase.
- Embed and hash the body after frontmatter removal.
- Frontmatter-only changes must not trigger embedding recomputation.

### Cache

The cache file remains:

```text
.vault-meta/tiling-cache.json
```

Compatible shape:

```json
{
  "version": 1,
  "model": "nomic-embed-text",
  "embeddings": {
    "wiki/concepts/Alpha.md": {
      "hash": "sha256...",
      "embedding": [0.1, 0.2],
      "computed_at": "2026-05-24T00:00:00Z"
    }
  }
}
```

Hash input is:

```text
model=<model>
<body>
```

Behavior:

- Missing cache creates an empty cache.
- Different cache model invalidates all entries.
- Unknown version, invalid JSON, or non-object `embeddings` returns `cache-corrupt`.
- Entries for deleted or no-longer-eligible pages are pruned on successful save.
- Cache writes use stable pretty JSON and a trailing newline.
- Cache writes use an atomic temporary file inside `.vault-meta/`.

### Thresholds

Read optional thresholds from:

```text
.vault-meta/tiling-thresholds.json
```

Default when missing:

```json
{
  "version": 1,
  "model": "nomic-embed-text",
  "bands": {
    "error": 0.9,
    "review": 0.8
  },
  "calibrated": false,
  "calibration_pairs_labeled": 0
}
```

This phase should read but not create the thresholds file by default, matching upstream behavior.

Invalid thresholds should return `usage-error` with a clear issue rather than silently falling back.

### Pair Scoring

- Compute cosine similarity for every pair of embedded pages.
- If embedding dimensions differ, skip that pair and record a warning.
- Emit pairs where similarity is `>= bands.review`.
- Error band: `similarity >= bands.error`.
- Review band: `bands.review <= similarity < bands.error`.
- Sort pairs by similarity descending.
- Similarity display is four decimals in markdown reports.

### Scale Limits

- Warn at more than `500` candidate pages.
- Return `scale-exceeded` above `5000` candidate pages.
- The service report should include the warning instead of printing to stderr.

## Target Architecture

```text
desktop/electron/services/knowledge-base/dragonscale/
  tiling-types.ts
  ollama-embedding-provider.ts
  tiling-service.ts
```

The service is a main-process knowledge-base service:

```ts
class DragonScaleTilingService {
  peek(projectPath: string, options?: DragonScaleTilingPeekOptions): Promise<DragonScaleTilingPeekResult>
  check(projectPath: string, options?: DragonScaleTilingCheckOptions): Promise<DragonScaleTilingCheckResult>
}
```

It should not depend on Agent runtime, Scheduler, Workflow, renderer code, or shell execution.

## Public Types

```ts
export type DragonScaleTilingStatus =
  | "ok"
  | "usage-error"
  | "cache-corrupt"
  | "scale-exceeded"
  | "ollama-unreachable"
  | "model-missing"

export interface DragonScaleTilingCheckOptions {
  readonly rebuildCache?: boolean
  readonly reportPath?: string
  readonly ollamaUrl?: string
  readonly model?: string
  readonly allowRemoteOllama?: boolean
  readonly now?: Date
}

export interface DragonScaleTilingPair {
  readonly similarity: number
  readonly leftPath: string
  readonly rightPath: string
}

export interface DragonScaleTilingCheckResult {
  readonly status: DragonScaleTilingStatus
  readonly generated: string
  readonly model: string
  readonly ollamaUrl: string
  readonly thresholds: DragonScaleTilingThresholds
  readonly scanned: number
  readonly embedded: number
  readonly skipped: Record<string, number>
  readonly cacheHits: number
  readonly recomputed: number
  readonly orphansPruned: number
  readonly errors: readonly DragonScaleTilingPair[]
  readonly reviews: readonly DragonScaleTilingPair[]
  readonly reportMarkdown?: string
  readonly reportPath?: string
  readonly warnings: readonly string[]
  readonly message?: string
}
```

The exact type names may change to match local conventions, but the status and result information must remain available for tests and future lint integration.

## Embedding Provider

Add an injectable provider interface so unit tests do not require Ollama:

```ts
export interface DragonScaleEmbeddingProvider {
  isReachable(url: string): Promise<boolean>
  hasModel(url: string, model: string): Promise<boolean>
  embed(input: { readonly url: string; readonly model: string; readonly text: string }): Promise<readonly number[]>
}
```

Production implementation:

- `DragonScaleOllamaEmbeddingProvider`;
- uses Node/Electron built-in HTTP capabilities, no new dependency;
- enforces response byte limits;
- enforces request timeouts;
- validates that embeddings are non-empty numeric arrays.

## Report Writing

`check(projectPath, { reportPath })` may write a markdown report, but the path must be confined to the vault root.

Default intended report path for future lint integration:

```text
wiki/meta/tiling-report-YYYY-MM-DD.md
```

Report format should preserve the upstream sections:

- `# Semantic Tiling Report`
- generated, model, ollama URL, thresholds, calibration state
- pages scanned, embedded, skipped
- skipped reasons
- cache hits, recomputed, orphans pruned
- `## Errors (similarity >= X)`
- `## Review (Y <= similarity < X)`

This report is a knowledge-base artifact, so writing it under `wiki/meta/` is allowed when requested.

## Concurrency

Synapse is the production writer, so the first TypeScript implementation may use a process-wide per-vault lock, matching the address service pattern.

The cache write itself must still be atomic via a temporary file and rename.

The service may create `.vault-meta/.tiling.lock` for compatibility/observability, but it should not claim OS-level `flock` parity unless implemented without new dependencies.

## Integration Scope

In scope for this phase:

- service implementation;
- Ollama provider implementation;
- cache and threshold handling;
- optional report writing;
- tests proving vault safety and upstream-compatible behavior;
- exports from the knowledge-base barrel.

Out of scope for this phase:

- changing `/wiki lint` to call the service automatically;
- adding Claude SDK custom tools or MCP tools;
- adding renderer UI for tiling diagnostics;
- automatic page merging or duplicate resolution;
- replacing the broader AI-written lint report.

Future integration should wire `/wiki lint` or a knowledge-base-only SDK tool to this service after the service is stable.

## Error Handling

- Missing `wiki/` returns `ok` with zero pages, zero pairs, and no report errors.
- Missing Ollama returns `ollama-unreachable`, not a thrown exception.
- Missing model returns `model-missing`, not a thrown exception.
- Cache corruption returns `cache-corrupt` and does not overwrite the cache.
- Invalid remote URL or unsafe report path returns `usage-error`.
- Embedding errors for individual pages skip that page and increment `skipped.embed_error`.
- Report write failure should reject because the caller explicitly requested a write.

## Testing Strategy

Required tests:

- `peek` reports Ollama reachability, model presence, cache state, and threshold state.
- Local Ollama URL is accepted; remote URL is rejected unless `allowRemoteOllama` is true.
- Missing `wiki/` returns `ok` and does not create `.vault-meta/`.
- `check` creates `.vault-meta/tiling-cache.json` only after Ollama/model readiness.
- symlinks and path escapes are skipped before read/embed.
- meta/fold/system pages are excluded.
- body hashes ignore frontmatter-only changes.
- cache hits avoid recomputing embeddings.
- `rebuildCache` recomputes embeddings.
- cache model mismatch invalidates old entries.
- corrupt cache returns `cache-corrupt` without overwrite.
- deleted page cache entries are pruned after a successful check.
- thresholds default correctly when missing.
- custom thresholds split error/review bands correctly.
- invalid thresholds return `usage-error`.
- report writes are confined to the vault.
- report markdown matches the upstream section structure.
- no user-vault templates gain scripts, skills, commands, hooks, or Agent files.

Compatibility tests:

- Use a deterministic fake embedding provider for service semantics.
- Keep the vendored Python script as an oracle for static pieces where practical:
  - default thresholds shape;
  - cache hash input;
  - markdown report headings and summary fields.
- Do not require a live Ollama server in CI.

## Non-Goals

- No automatic lint-command wiring.
- No cross-process lock parity with Python `fcntl.flock` unless a later implementation explicitly adds it.
- No remote embedding provider configuration UI.
- No vector database or approximate nearest-neighbor index.
- No semantic tiling for ordinary projects.

## Acceptance Criteria

- `DragonScaleTilingService` computes duplicate-page candidate pairs without shelling out.
- Production tiling never copies scripts into the user vault.
- Page bodies are never sent to a remote endpoint unless explicitly allowed by options.
- Cache and report writes stay confined to the knowledge-base vault.
- Tests cover cache behavior, security guards, threshold behavior, report shape, and fake-provider pair scoring.
- Knowledge-base barrel exports the service and public result types for future internal callers.
