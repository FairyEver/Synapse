# Workflow Call Node Design

> 日期：2026-06-07
> 状态：设计确认，等待用户审阅

## 背景

当前 Synapse 工作流支持参数、节点变量绑定、Prompt/Switch/HTTP/Script/End 等节点，以及外层 DAG 执行模型。用户希望在一个工作流中新增节点来调用另一个工作流，让复杂流程可以拆成可复用的子工作流。

核心难点是子工作流也有自己的 `params`。调用节点必须能在不中断运行的情况下，把父工作流上下文、上游节点输出和静态内容映射成子工作流参数。

## 目标

- 新增 `workflow_call` 节点，用于在父工作流中调用另一个已保存工作流。
- 调用节点运行时自动构造子工作流参数，不弹出半程参数填写窗口。
- 子工作流参数采用“变量绑定 + 模板文本”的方式设置，和现有 Prompt/End 节点心智一致。
- 调用节点输出只取子工作流 End 节点最终 `output`。
- 父工作流不锁定子工作流版本；每次运行读取子工作流当前已保存版本。
- 通过调用栈和最大嵌套深度避免递归调用。

## 非目标

- 不支持锁定子工作流版本。
- 不支持运行中弹窗补充子工作流参数。
- 不支持选择子工作流内部任意节点输出。
- 不支持跨工作流共享完整运行状态 UI；第一版只在父节点结果中保留子运行摘要。
- 不扩展工作流参数类型；第一版沿用当前 `text` 和 `number`。
- 不破坏外层工作流 DAG 约束。

## 节点配置模型

新增节点类型 `workflow_call`，显示名为“调用工作流”。

```ts
interface WorkflowCallNodeConfig {
  workflowId: string
  variables: WorkflowVariableBinding[]
  paramTemplates: Record<string, string>
}
```

字段含义：

- `workflowId`：要调用的子工作流 ID。运行时读取该工作流当前保存版本。
- `variables`：调用节点自己的变量绑定，来源沿用现有三类：父工作流参数、上游节点输出、静态值。
- `paramTemplates`：子工作流参数模板。key 是子工作流参数名，value 是支持 `{{变量名}}` 插值的模板文本。

示例：

```text
节点变量
  search_result = 上游节点「搜索」输出
  max_count = 父工作流参数「max_count」
  audience = 静态值「内部汇报」

子工作流参数
  topic = 请根据 {{search_result}} 输出摘要
  limit = {{max_count}}
  style = 面向 {{audience}}，语气克制
```

## 编辑器交互

调用节点配置面板分三块：

1. 选择工作流
   - 下拉选择一个已保存工作流。
   - 不能选择当前正在编辑的工作流。
   - 选择后读取子工作流当前 `params`。

2. 节点变量
   - 复用现有节点变量绑定 UI。
   - 变量来源可以是父工作流参数、上游节点输出或静态值。

3. 子工作流参数
   - 每个子工作流参数一行。
   - label 使用参数描述；没有描述时使用参数名。
   - 文本参数使用文本输入或多行文本输入。
   - 数字参数仍允许模板，但运行前必须渲染为有效数字。

选择子工作流后，编辑器可生成初始模板：

- 如果父工作流已有同名参数，模板填 `{{同名参数}}`。
- 否则如果调用节点已有同名变量，模板填 `{{同名变量}}`。
- 否则如果子参数有默认值，模板留空，运行时使用子默认值。
- 否则模板留空，并在校验中提示必填缺失。

## 运行时语义

调用节点执行流程：

1. 根据 `workflowId` 读取子工作流当前保存版本。
2. 检查调用栈：
   - 当前调用栈中已存在该 `workflowId` 时失败。
   - 嵌套深度超过 5 时失败。
3. 解析调用节点 `variables`，得到节点变量表。
4. 使用节点变量表渲染 `paramTemplates`，得到 `childParams`。
5. 按子工作流当前 `params` 校验并补默认值。
6. 用同一个 `abortSignal`、同一个 `actor` 和继承的项目上下文启动子工作流运行。
7. 子工作流完成后映射结果：
   - `completed`：调用节点成功，`output` 等于子工作流 End 输出。
   - `failed`：调用节点失败，错误为子工作流错误摘要。
   - `cancelled`：调用节点取消。

调用节点不自动打开子 Runner 窗口。父工作流 Runner 只显示调用节点自身进度和结果；节点结果中保存子运行摘要，供后续做“查看子运行详情”入口。

```ts
interface WorkflowCallNodeOutputs {
  childWorkflowId: string
  childWorkflowName: string
  childRunId: string
  childStatus: "completed" | "failed" | "cancelled"
}
```

父工作流下游节点只能读取调用节点的 `output`，也就是子工作流 End 输出。

## 版本语义

父工作流节点只保存 `workflowId`，不保存子工作流 definition snapshot 或 version hash。

这意味着：

- 子工作流修改并保存后，父工作流下次运行自动使用新版。
- 父工作流保存时不需要因为子工作流版本变化而更新。
- 运行记录仍应保存当次实际执行的子工作流版本信息，便于排查。

## 递归保护

第一版采用两层保护：

- 保存或校验时阻止直接自调用：工作流 A 中不能配置调用 A。
- 运行时维护调用栈，阻止间接循环：A -> B -> C -> A 会失败。

最大嵌套深度为 5。超过后调用节点失败，避免无意嵌套导致执行器长时间占用资源。

错误示例：

```text
调用链包含循环：A -> B -> A
工作流嵌套层级超过 5
```

## 参数校验

保存/编辑校验：

- `workflowId` 不能为空。
- `workflowId` 不能等于当前工作流 ID。
- `paramTemplates` 中引用的 `{{变量名}}` 必须存在于调用节点 `variables`。
- 调用节点变量来源仍需满足现有规则：父参数必须存在，上游节点必须可达。

运行前校验：

- 子工作流仍然存在。
- 子工作流当前版本本身通过 `validateWorkflow`。
- 调用栈没有循环。
- 嵌套深度不超过 5。
- 子工作流必填参数都能从模板或默认值得到。
- 数字参数渲染后必须是有效数字。

多余模板处理：

- 如果子工作流删除了某个参数，调用节点中对应模板在运行时忽略。
- 编辑器可以显示失效提示，但不阻断保存，避免子工作流参数调整导致父工作流无法编辑。

## 错误提示

错误提示保持短句，并指向用户可修复对象：

```text
子工作流不存在
子工作流参数「topic」缺少必填值
子工作流参数「limit」必须是数字
调用链包含循环：A -> B -> A
子工作流校验失败：节点「生成摘要」缺少模型配置
```

子工作流失败时，父调用节点失败。父工作流继续沿用现有失败传播规则。

## 可观测性和日志

日志记录结构化摘要：

- `parentWorkflowId`
- `parentRunId`
- `parentNodeId`
- `childWorkflowId`
- `childWorkflowName`
- `childRunId`
- `paramKeys`
- `depth`

日志和追踪不记录参数值，只记录参数名列表和数量，避免泄露用户输入。

取消语义：

- 子工作流使用父调用节点传入的同一个 `abortSignal`。
- 父工作流取消时，正在执行的子工作流立即取消。

## 实现边界

运行时可以复用并逐步抽取现有工作流执行能力：

- 第一版可通过 `WorkflowEngine.run(...)` 执行子工作流，但需要传递调用栈上下文。
- 如果后续循环节点落地，应将子图/子流程执行能力抽成共享 runner，避免 `workflow_call` 和 `loop` 重复维护调度逻辑。

调用节点 executor 需要能读取子工作流定义，因此运行时依赖应增加窄接口，例如：

```ts
interface WorkflowCallRuntimeDeps {
  getWorkflowDefinition(id: string): Promise<WorkflowDefinition | null>
  runChildWorkflow(input: RunChildWorkflowInput): Promise<WorkflowRunResult>
}
```

该接口由主进程 workflow bootstrap 注入，避免节点 executor 直接依赖存储服务或 IPC。

## 测试

主进程/运行时：

- 调用节点把父参数、上游输出、静态值渲染成子工作流参数。
- 文本参数支持固定内容和变量插值混合。
- 数字参数渲染为有效数字时可运行，非法数字时报错。
- 子工作流默认值在模板缺失时生效。
- 子工作流必填参数缺失时调用节点失败。
- 子工作流 End output 成为调用节点 output。
- 子工作流失败时父调用节点失败。
- 父工作流取消会取消子工作流。
- 直接自调用被校验阻止。
- A -> B -> A 间接循环在运行时失败。
- 嵌套深度超过 5 时失败。

Renderer：

- 调用节点配置面板可以选择子工作流。
- 选择子工作流后展示其当前参数列表。
- 同名父参数或同名变量可以自动生成初始模板。
- 模板引用未绑定变量时显示校验错误。
- 子工作流删除参数后，多余模板显示失效提示但不阻断编辑。

回归：

- 现有工作流参数弹窗只在顶层运行前出现，调用节点运行中不弹窗。
- 现有 Prompt/End/Switch 变量绑定校验不受影响。
- 现有工作流列表运行、编辑器运行、运行历史和 Runner hydrate 行为不变。
