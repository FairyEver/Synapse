## 1. 要解决什么

产品负责人拿 ToDesk 的键盘面板截图提的：手机端终端那块面板要**长得像一块电脑键盘**，不要像一片按键格。

看截图能看出差的不是配色，是**结构**：ToDesk 面板里，数字在字母上面，回车和空格在拇指底下，功能键和方向键在右边成块 —— 而当时的 Synapse 面板是「键盘页十列铺满 + 导航页两块键簇」，两页各按各的排法，跟真键盘的排布没有关系。

同时砍掉一栏：ToDesk 的「游戏键盘」不做。

## 2. 现状与它的来历

### 2.1 面板是什么

`SynapseMobile/SynapseMobile/Features/Terminal/TerminalKeyboardPanel.swift` 一个文件。顶部一个 `.pickerStyle(.segmented)` 切两个分类：

| 分类 | 内容 |
|---|---|
| 键盘 | `esc` `tab` `⇧tab` `⌫` `回车` 横一行；修饰键行 Ctrl/Shift/Alt；数字行；三行字母 |
| 导航 | 方向键倒 T + 六键簇（home/end/pgup/pgdn/del，Insert 那格留空） |

面板高度固定 351，坐在键盘槽位里（不是 sheet），与系统键盘互斥。

### 2.2 修饰键锁存的三条规则（本轮不变）

- 点一下修饰键 → 锁住；再按一个字母 → 组合生效；**发完自动弹回**。
- 0.35 秒内点第二下 → **锁定**，可以连着按同一个组合；再点一次解开。
- 一次只锁一个：第二个修饰键按下时把第一个**换掉**，不叠加。

第三条的理由是硬事实：能发出去的组合全都只需要一个修饰键，而允许两个同时锁上会让**整块键盘全暗**——没有任何一个「双修饰 + 字母」有对应字节。

### 2.3 读数条是什么

上一轮加的：`Ctrl + _ → 0x03 · 中断当前进程`。它同时是安全网和教学——「不会有一颗按了没反应的键」这句承诺靠它兑现。

**本轮砍掉**，理由见 §3.5。

## 3. 决策

### 3.1 两个分类 → 两个 tab → 没有 tab（同日晚改）

`键盘 / 导航` 没了，换成 **电脑键盘**（下面那块两页的板子）和 **手机键盘**（系统键盘）两段。

**当晚把这两段也去掉了。** 产品负责人看真机截图定的：这块面板只在点工具栏那颗 ⌘ 时出现，**它上面不该压着任何东西**；而「手机键盘」本来就不是这块板子的另一页 —— 系统键盘点输入框就能叫起来，为此在面板顶上留一栏，等于把「同一件事有两个入口」摆在那里。去掉之后顶上那三行（分页器、工具栏、输入栏）一起让位，屏幕下半部分就是一块电脑键盘，收它的路是**点键盘外侧那块画布**。

- **不做游戏键盘。** 产品负责人明确排除。
- 板子内部**自己翻页**，翻页器是板子底下那两个点，不是分类切换器。
- **面板开着时工具栏与输入栏整条让位**（`TerminalScreen.barsStandDown`）。例外只有一个：**正在录音**时不让 —— 录音浮层挂在输入栏那一组上，而手指可能还压在「按住说话」那一格里，把栏从手底下抽走会让那次录音没有收尾的地方。这种时候面板照旧开在两条栏下面，退化成改造前那副样子。
- **竖屏收面板只有点画布一条路**（那颗 ⌘ 随工具栏一起让位了）。横屏不同：那一行把顶栏并了进去，⌘ 长在上面那条栏里，面板开着时它还在，再点一次也能收。

### 3.2 第一页：数字 + 三行字母

```
 1  2  3  4  5  6  7  8  9  0
 Q  W  E  R  T  Y  U  I  O  P
 A  S  D  F  G  H  J  K  L  ⌫
 Z  X  C  V  B  N  M  Space  Enter
```

- 十列铺满整宽；`Space`、`Enter` 各占 1.5 个键宽，和真键盘一样是宽键。
- **字母键帽只画大写**（`Q`），发出去的是小写，锁 Shift 或 Caps 时是大写 —— 真键盘的键帽就是这么印的，系统键盘也是。键帽不重绘。
- **数字键帽画两档**（`!` 在上、`1` 在下），锁 Shift 时发上面那个。这条比 ToDesk 多一个图例：ToDesk 的数字行只有一位，但它的符号行证明了双图例是它自己的画法，而**一颗发 `!` 却只写着 `1` 的键**正是这套面板一直在避免的事（§3.7）。

### 3.3 第二页：符号行 + F 键与导航块

```
 =  ±  {[  }]  |\  :;  "'  <,  >.  ?/
 Esc  Tab  ~`  PrtScr  ScrLK  Pause
 F1   F2   F3   Ins   Home   PgUp
 F4   F5   F6   Del   End    PgDn
 F7   F8   F9   Caps  ↑
 F10  F11  F12  ←     ↓      →
```

- 符号行十列铺满，其余四行六列铺满 —— **同一页里两种列宽**，因为 F 键那半边三列、导航那半边三列，而符号行是一整行。
- `PrtScr` `ScrLK` `Pause` 三颗**照画**（产品负责人选的「严格照抄」），但终端里没有对应字节，见 §3.7。
- 双图例键（`{[`、`}]`、`` ~` ``…）：**左边的字符是 Shift 那档**，和真键盘印法一致。

### 3.4 修饰键行：Ctrl / Shift / Alt / ⌘，四颗等宽，两页常驻

在分类切换器下面，左边是「组合键模式」开关 + 文字，右边四颗平分剩下的宽度。

**开关用的是系统绿，不是 `Theme.ink`。** App 的全局 tint 是 `ink`（= `Color.primary`），深色下是白色，而 iOS 开关的圆点也是白的 —— 两者同色，一颗开着的开关看上去就是一块没有圆点的白方块。所以这颗开关（以及设置页那颗同根因的）显式取 `Theme.switchOn`，也就是被全局 tint 覆盖掉的平台默认值。这是 2026-09-19 真机截图修的一处。

**放 ⌘ 是照抄，但它是一颗死键。** 理由是一条硬事实：macOS 的终端里 **⌘ 被终端 App 自己吃掉**（⌘C 复制、⌘V 粘贴、⌘K 清屏），**没有字节能送到 PTY**。上一轮据此把它排除在外；本轮的取舍变了——产品负责人要的是「一眼看出这是电脑键盘」，而电脑键盘上那里就有 ⌘。所以它照画，但**压暗**，按下去只有警告触觉。

（这条推翻了 `2026-09-17-terminal-full-keyboard-design.md` §3.2 的「不放 Command」。当时否掉它是为了「不要有一颗按了没反应的键」；本轮的解法不是删掉它，而是把「没反应」变成「看得出来发不出去」。）

### 3.5 读数条砍掉

它占 34pt，而这一版的面板要放六行键。产品负责人定：砍掉，那 34pt 全部给键高。

**代价写在明处**：四颗死键按下去只剩「压暗 + 一次警告触觉」，没有文字说明原因。这是有意的取舍，不是遗漏。

锁存状态本身仍然看得见：锁住的修饰键反色，锁定的那一个右上角多一个点。

### 3.6 「组合键模式」开关：开 = 可锁存，关 = 收起修饰键行

字面意思。关掉之后修饰键那一行整行消失，板子退化成一块纯字符键盘——给只想打字符的人。

关掉时若有修饰键锁着，**先把锁清掉再收**，否则状态留在那里而没有东西在表明它。

### 3.7 没有字节的键：画出来，压暗，不发

`PrtScr`、`ScrLK`、`Pause` 在终端里没有对应字节（ToDesk 是往远端 PC 发扫描码，我们是往 PTY 发字节，两回事）；`⌘` 见 §3.4。

它们的处理沿用面板**本来就有的**那套 `.unavailable` 语义：键画在它该在的位置，压暗，按下去一次 `Haptics.warning()` 且一个键都不发。

### 3.8 `⇧tab` 不再有独立键，改由 Shift + Tab 拼

**这一条推翻了 `2026-09-17-terminal-full-keyboard-design.md` §3.7。**

当时给它独立键的理由是「Shift 在全键盘页、Tab 在常用页，跨页拼不出来」。**那个理由在本轮不成立了**：修饰键行两页常驻，Tab 在第二页，于是 `Shift → Tab` 在第二页拼得出来。

照 ToDesk 的键位排，电脑键盘上本来就没有 `⇧tab` 这样一颗键，所以它不再单列。**代价说明白**：它从一次点击变成两次，而且必须先翻到第二页。Claude Code 切权限模式靠它，所以这是一个真实的退步——若实测下来太贵，加回一颗独立键是一行的事。

### 3.9 修饰键与命名键：一条规则和两个例外

修饰键行两页都可见，所以命名键（Tab、方向键、F 键…）必须回答「锁着修饰键时我意味着什么」，而不是无视它：

| 锁着什么 | 命名键发什么 |
|---|---|
| 无 | 它自己 |
| Shift | **只有 Tab 成立** → `Shift+Tab`；其余**拒绝**（终端里没有 `Shift+Enter` 这样的字节） |
| Alt | `Escape` + 它自己（Alt 在终端里就是 ESC 前缀，`Alt + ←` 正是 readline 的「退一个词」） |
| Ctrl | **一律拒绝** |

Ctrl 那一行不是保守，是必须：终端里没有 `Ctrl+Enter` 的字节，而**发一个裸 `Enter` 出去会提交用户正在写的那条提示**。拒绝是这对选择里安全的那一半，而且它是**看得见的**那一半——键会压暗。

## 4. 协议

### 4.1 新增 13 个键名

白名单从 **38 项扩到 51 项**，全部**追加在末尾**（append-only：每个键名都是手机/云端/桌面三方按字符串匹配的标识符）。

| 键名 | 字节 |
|---|---|
| `F1`…`F4` | `\x1bOP` `\x1bOQ` `\x1bOR` `\x1bOS` |
| `F5`…`F12` | `\x1b[15~` `\x1b[17~` `\x1b[18~` `\x1b[19~` `\x1b[20~` `\x1b[21~` `\x1b[23~` `\x1b[24~` |
| `Insert` | `\x1b[2~` |

`Ctrl+I` / `Ctrl+M` 仍然不在表里，理由不变（它们的字节是 Tab 和回车已经占着的）。

### 4.2 五处同步

`MOBILE_KEYS` 的改动必须同时落到五处，漏任何一处都是运行时才炸的错：

| # | 位置 | 漏了会怎样 |
|---|---|---|
| 1 | `shared/src/mobile-live.ts` 的 `MOBILE_KEYS` | 云端不认新键名 |
| 2 | `shared/src/mobile-live-constants.cjs` 的 `exports.MOBILE_KEYS` | 同上（CommonJS 镜像） |
| 3 | 同文件上方 JSDoc 的 `@type {readonly [...]}` | 类型提示与真值不符 |
| 4 | `desktop/app-capabilities/terminal/main/service.ts` 的 `KEY_BYTES` | 云端放行、电脑端抛异常 |
| 5 | `desktop/app-capabilities/terminal/shared/contract-schema.ts` 的 `terminalSemanticKeySchema` | zod 校验先把请求拒掉 |

手机端的镜像是 `SynapseMobile/SynapseMobile/Core/Protocol/LiveProtocol.swift` 的 `enum MobileKey`。

### 4.3 发版顺序（硬约束）

**必须 服务端 → 桌面端 → 手机端。**

服务端**代码一行都不用改**（它用的是 `shared` 里的 `isMobileIntent`），但**必须先部署**——它打包进去的是那个旧版本的 `shared`。旧云端遇到不认识的新键名会**切断整条连接**，用户看到的是「设备莫名离线」，日志里只有一句校验失败。

新手机 + 旧桌面端：新键名被电脑端拒绝，用户看到一次失败提示。**升级完成前，其它键位不受影响。**

### 4.4 投影不受影响

`desktop/app-capabilities/terminal/main/mobile-toolbar.ts` 的 `reverseKeyBytes()` 会把 `KEY_BYTES` 反查成「字节 → 键名」，用来把桌面内置工具栏投影成手机端的按钮。新增的 13 个字节序列**没有任何一个**出现在桌面内置动作里，所以**不会多出按钮**，投影结果与改动前逐项相同（`mobile-toolbar.test.ts` 钉住）。

## 5. 几何

| 量 | 值 | 怎么来的 |
|---|---|---|
| 面板高 | **346** | `8 + (42+8) + 板 + (8+14) + 14`，板高见下一行；两页同高 |
| 键高 | 36 | |
| 键距 | 6 | 一样宽，板子才读成一个网格 |
| 行距 | 42 | 键高 + 键距；一颗键的点击盒就是这 42 |
| 板高 | **252** | 六行 × 42，两页都是它 |
| 键宽（十列页） | 屏宽定，约 32 | `(宽 − 9×6) / 10` |
| 键宽（六列页） | 屏宽定，约 56 | `(宽 − 5×6) / 6` |
| 修饰键行 | 42 | 比下面的键高一档，照 ToDesk |

**行距在每一行自己的高度里，`VStack` 不再另加一道间距。** 一颗键的点击盒比键高高出一个键距，两颗相邻的键之间那道缝就是上面那颗键多出来的那 6pt —— 缝归谁已经有答案了（归上面那颗），而板子只需要一个数。这一条是 2026-09-19 修掉的一个 bug：点击盒那 6pt 曾经以「布局高度」的形式又被算了一次，纵向的缝于是变成 12pt 而横向还是 6pt，板子读起来是几排按钮而不是一个网格。**同时板子也因此比面板高了 36pt**，第二页装不下、要滚才够得着底行。

**面板高度是一个数：346，两页同高。** 它当天走了一个来回 —— 先是一档（390），真机截图看下来第一页底下空出 84pt，改成随页走（306 / 390）；同日晚把顶上那三行去掉之后又回到一档。**这一轮的理由和第一轮不同**：那 84pt 当时是白扔的，现在它买的是「翻页时终端一动不动」，而腾出来的地方正好装得下它。板子也是两页同高（252），所以第二页的底行不靠滚动就够得着，第一页底下那两行空着 —— 那是**有意的**，画在 Space 底下。

面板开着时手机本来就**不**向电脑上报网格（`TerminalScreen.reportGridToDesktop` 的守卫），远端 PTY 不会跟着重排。

**竖屏给满；横屏按可用高度压下来并让板子在面板里滚**（`KeyboardPanelMetrics.height(fitting:)`），沿用上一轮的机制。

**面板高度的每一次变化都撞出过一个既有 bug，当初那 33pt 那次已一并修掉。** 画布变矮时 UIKit 会把滚动位置钳回新的合法区间，而那一次回调算出来的「离底距离」和读者往上翻**一模一样**，于是终端把跟随判成了「他翻上去看历史了，别打扰」——而这是个单向棘轮：`isPinnedToBottom` 一旦翻假就没有东西能翻回来，重新贴底的两处都以它为真为前提。表现是**面板开着时新输出全部落在可视区外面**。修在 `TerminalTextView.scrollViewDidScroll`（`8fb17564b`）：画布高度或 inset 刚变过、且回调不是拖拽/惯性时，只许重新贴上底、不许解除跟随。这一版翻页不再动高度，跳变只剩开、关两次 —— 比「随页走」那一版还少，但这仍然是那条判别的回归项（§7 第 24 条）。

旧面板（351pt）之所以没踩到，只是因为画布刚好还装得下——它绿得侥幸，不是那条路走对了。所以**面板高度不再是踩在运气上的**，往后再调不用重新试边界。

## 6. 与 ToDesk 对不齐的地方

有意的，不是没做到：

1. **配色不用它的蓝。** App 只有一个强调色（琥珀，含义是「需要人」），修饰键和翻页点因此取中性语义色（反色 / `Theme.ink` / `tertiaryLabel`）。加一个蓝色会是这个 App 里的第二个强调色。
2. ~~**分类切换器用系统分段控件**，不是 ToDesk 那个左对齐文字 + 蓝下划线 + 右侧「收起键盘」图标。~~ **同日撤销**：分类切换器整个没有了（§3.1）。ToDesk 那个「收起键盘」图标也没有照抄 —— 收键盘的手势是点画布。
3. **手机键盘不能像截图那样「面板还在、系统键盘从下面升起来」。** iOS 不许我们自己的视图压在系统键盘上方，而 `inputAccessoryView` 的位置已经被输入栏占了。这一版连「收起这块、叫起那块」的切换键都不留（§3.1）：系统键盘就是点输入框，而输入框属于面板会收起的那条栏。
4. **ToDesk 顶上那一行（切键盘、设置、收起）不存在。** 它的位置是空的 —— 产品负责人要的是「一块纯电脑键盘」，顶上那一行无论装什么都会把键盘变成屏幕下方的一截。
5. **修饰键取名 `Ctrl` / `Shift` / `Alt`**，不是 `Control` / `Shift` / `Option`。沿用 App 已有的叫法，也与协议里的键名（`Ctrl+A`）一致。
6. **数字键帽画双图例**（§3.2），ToDesk 只有一位。

## 7. 验收基线

逐条走，每一条都要能说出「怎么验的」。

1. 面板顶上**什么都没有** —— 没有分页器、没有「游戏键盘」、没有「键盘 / 导航」，而它上面也不压着工具栏和输入栏：屏幕下半部分就是一块电脑键盘。
2. 打开面板落在第 1 页，板子底下两个点，第一个是实的。两页之间能左右滑动，滑动途中看得见另一页跟手过来（不是松手才整块换掉）。
3. 第 1 页四行：数字、QWERTY、ASDF+⌫、ZXCVBNM+Space+Enter；`Space` 与 `Enter` 比字母键宽。
4. 第 2 页六行：符号行、`Esc Tab ~` PrtScr ScrLK Pause`、以及四行「F 键左三列 + 导航右三列」；`↑` 在 `←` 正上方，第 4 行最后一格是空的。
5. `F1`–`F12`、`Ins` 都在，且**按 F1 电脑端收到 `key:F1`**（新协议名真的过了一遍 wire）。
6. `PrtScr` 按下去**一个键都不发**（等一个来回之后终端里的最后一行没变）。
7. 修饰键行两页都在，四颗等宽：`Ctrl` `Shift` `Alt` `⌘`；`⌘` 压暗。
8. 「组合键模式」关掉 → 修饰键那一行整行消失；打开 → 回来。
9. 点 `Ctrl` → 它反色；再点 `a` → 电脑端收到 `Ctrl+A`；发完 `Ctrl` 弹回。
10. 双击 `Ctrl` → 锁定（右上角一个点）；连按 `c`、`d` 发出两个组合且仍锁着；再点一次解开。
11. 锁 `Shift` 按 `a` → 发出**文本 `A`**；按 `1` → 发出**文本 `!`**。
12. 锁 `Shift` 按 `Tab` → 电脑端收到 `Shift+Tab`。
13. 锁 `Ctrl` 按 `Tab` → **一个键都不发**，且 `Tab` 压暗。
14. 锁 `Alt` 按 `b` → 电脑端收到**同一次 intent 里的两个动作**：Escape，然后文本 `b`。
15. 锁 `Ctrl` 按 `i` → 收到 `Tab`；按 `m` → 收到 `Enter`。
16. 不锁任何修饰键按 `a` → 发出**文本 `a`**（小写）。
17. `Caps` 按一下 → 发亮；按 `a` → 发出**文本 `A`**；再按一下 `Caps` 关掉，按 `a` → 发出**文本 `a`**。
18. `Caps` 开着时按 `1` → 发出的仍是**文本 `1`**（Caps 只碰字母，和真键盘一致）。
19. **点键盘外侧那块画布 → 面板收起，工具栏和输入栏一起回来**，点输入框能叫起系统键盘。面板重新打开时仍落在第 1 页。
20. 翻页后再翻回来，锁着的修饰键被清掉。
21. **翻页时终端一动不动**（两页同高）；第一页底下空着两行键的位置，画在 Space 底下。
21b. **录着音的时候点 ⌘**：面板照旧开在两条栏下面，输入栏（连同录音浮层）不消失。
22. **板子纵向的缝和横向的缝一样宽（都是 6pt）。** 在真界面上量：同一列两颗相邻键的 `minY` 之差是 **42**（键高 36 + 键距 6），同一行两颗相邻键的 `minX` 之差减去键宽也是 6。对不上就是 §5 那个 bug 回来了。
23. **翻页不会够不着底行**：第 2 页六行全部可视（`F12` 那一行直接点得到），板子不滚。
24. 面板开着时按一颗键，新出现的行落在终端可视区里（终端跟着最新一行走）。这是 §5 那条既有 bug 的回归项：把 `scrollViewDidScroll` 的判别退回无条件重算，它必须变红。
25. 终端不在跑时每一颗键都不可点（含修饰键与翻页点）。
26. 浅色与深色模式下，键、修饰键行、翻页点都取系统色（切到深色看一遍）；**「组合键模式」那颗开关在深色下能看见圆点**（应用根的 tint 是白色时它看不见，见 §3.4）。

## 8. 非目标

- **游戏键盘。** 产品负责人明确排除。
- **双修饰组合**（`Ctrl+Shift+X`）。终端里没有对应字节，设计上也不给这个状态（§2.2）。
- **`Ctrl+\`、`Ctrl+Space`、`Ctrl+]`**。不在 `Ctrl+A–Z` 的字母表里，没有场景逼着要。
- **长按弹菜单、自定义面板按键、给面板做增删改。** 面板是**按键**，不是命令。
- **给手机端做工具栏的增删改入口。**
- ~~**让面板高度按页变化**（ToDesk 那样）。§5 已定一档高度。~~ 2026-09-19 当天走过一个来回：先撤销、改随页走，当晚因为顶上三行去掉、腾出了地方，又回到一档。**当前口径见 §5：一档，346。**
- ~~**面板顶上的分类切换器。**~~ **同日作废**：分页器和「手机键盘」那一项一起没有了（§3.1）。
- **面板上留一行放别的控件**（设置、收起键盘这类 ToDesk 顶上有的东西）。顶上什么都不放是有意的。
- **iPad 专属布局。**
- **改系统键盘的任何行为。**
