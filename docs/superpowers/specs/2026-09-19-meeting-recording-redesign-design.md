# 录音 · 两栏重构

> 这份文档改的是已经上线的「会议记录」（2026-09-19 实施）。**本次它改名为「录音」**，理由见 §3.9。它**推翻**了 `docs/superpowers/specs/2026-09-19-meeting-recording-design.md` 里的若干条结论，第 2 节逐条列出。没列到的部分继续有效。
>
> 原型（可点，浏览器打开）：`~/Desktop/录音重构/原型.html`

---

## 1. 为什么要改

上线后第一次真实使用，暴露了三个问题和一个"用着用着觉得多余"的清单。

**一、列表和详情是两个页面。** 现在点一条记录是整页切进详情，看完要「返回」再进下一条。用户要的是左边列表、右边详情，点左栏右栏就换。

**二、音频和文字挤在同一页。** 现在波形在顶部，下面挂「纪要 / 逐字稿」两个 tab。用户要的是**两个平级的视图**：语音是一个视图，文字是另一个视图，音频有自己的位置，不是文字的附庸。

**三、删掉的录音还在列表里。** 用户原话是"已经删除的录音怎么还在上面显示？"——现在那个「删除录音」删的只是音频对象，这条录音（标题、逐字稿、纪要）原样保留，所以行不会消失，详情页顶上还挂着一整条「录音已删除 · 逐字稿和纪要保留」。

他的心智模型是**删除就是把这条删掉**。这条要按他的理解改。

**四、多余的东西。** 用户逐条点名要去掉的：纪要、发言人命名、逐字稿搜索、逐字稿里的发言人色条和时间戳跳转、以及左栏那条「发现一段未完成的录音」（配丢弃 / 完成两个按钮）。

## 3. 决策

### 3.1 左列表，右详情

一栏列表 + 一栏详情并排，左栏点选、右栏就地换内容。**没有「返回」这个动作**，因为它没有可返回的地方。

左栏只有列表本身：没有顶部标题、没有搜索、没有筛选、没有任何按钮和提示条。它就是一个列表。

选中一条时自动选中第一条——不给用户一个"什么都没选"的空右栏。

### 3.2 右栏只有两个视图：语音、文字

平级的两个视图，切换不重置选中，**切换是粘性的**：用户在语音视图看第二条记录，右栏还是语音。唯一的例外见 §4.5（转写失败）。

### 3.3 语音视图就是一个播放器

一整段铺满宽度的波形（与录音页那条滚动窗口不同，这仍是有意的）+ 播放头 + 播放键 + ±15 秒 + 当前时间 / 总时长。点波形任意位置跳到对应时间。

**没有**时间刻度尺、缩略图、倍速、字幕跟随、以及播放时显示"当前这句"的浮条（原型里做过，用户明确说不要）。

### 3.4 文字视图就是一段转写

腾讯云返回什么就显示什么，按自然段排开。

**没有**纪要、没有逐字稿分栏、没有发言人、没有时间戳、没有搜索、没有发言人命名。

腾讯云按句返回，渲染时把句子并成自然段（约 110 字一段），读起来像一篇文章而不是流水账。

### 3.5 删除只有一个动作

行内「⋯」菜单里的「删除」= **录音和文字一起删掉，行从列表消失**，确认后不可恢复。

代价说清楚：想"只删音频、留下文字"就没有入口了。用户明确选了这个代价。

后端目前**没有**整条删除的接口（`meeting.controller.ts` 里 `DELETE` 只有录音分片和录音本身两处），要新增，并且是级联删除——见 §6。

### 3.6 录音没录完就退出：静默收尾，当成正常录音

**规则**：录音过程中进程被杀、强退、更新重启，已经录到的部分**按正常录音处理**——自动收尾、进列表、照常转写。

**界面上不出现任何询问**。没有"发现一段未完成的录音"，没有丢弃 / 完成，用户不需要知道发生过异常退出。

要提前认下的代价：这段录音会照常送去转写，**0.8 元/时照算**。用户明确要这个行为。

已知缺陷：这样恢复回来的录音**没有波形**。波形只存在内存里，进程一死就没了，只能用已传字节数估一个时长。所以那条录音的语音视图会是一条平的线。这一版先接受，不做特殊界面。

### 3.7 砍掉的能力，连同它们的入口一起砍

纪要（生成 / 编辑 / 待办）、发言人命名、逐字稿搜索、逐字稿结构化（发言人 + 时间戳）。

判断标准是用户的原话："不需要什么纪要和逐字稿，它就是直接就是显示一段文字。"

**要顺手做的清理**：这些能力对应的后端接口、IPC、preload bridge、类型和测试，如果重构后没有别的调用方，一起删掉，不要留成死代码。具体清单见实施计划。

### 3.8 列表选中态需要一个主题 token

当前主题里 `--muted` 同时用作 hover 和选中，两者区分不开（浅色 0.97 / 深色 0.269，`--accent`/`--secondary`/`--sidebar-accent` 都是同一个值）。

**需要新增一个语义化的列表选中色**，原型里暂用 `--selected`（浅色 `oklch(0.945 0 0)`，深色 `oklch(0.3 0 0)`）。要按 `.claude/rules/design.md` 的口径把它作为一个正式 token 加进 `globals.css`，不要在页面里写死。

### 3.9 这个名字不再是「会议」

它什么都能录——访谈、课堂、灵感、随手一段话。叫「会议」就把场景绑死了，用户的原话是："叫会议它就绑定到了某一个场景中，其实是这个东西它肯定是什么都能录音的。"

**全站只有一个词：录音。**

| 位置 | 现在 | 改成 |
|---|---|---|
| 手机底部 Tab | 会议 | 录音 |
| 手机页面标题 | 会议记录 | 录音 |
| 手机空状态 / 错误提示 | 还没有会议记录 / 读取会议记录失败 | 还没有录音 / 读取录音失败 |
| 桌面端启动台名称 | 会议记录 | 录音 |
| 桌面端窗口标题 | 会议记录 | 录音 |
| 桌面端空状态 / 错误提示 | 还没有会议记录 / 读不到会议记录 | 还没有录音 / 读不到录音 |
| 删除确认 | 删除这条会议记录？ | 删除这条录音？ |
| 右栏空态 | 没有可显示的会议 | 没有可显示的录音 |

**为什么不用长度折中。** 一度考虑过手机 Tab 用短名、别处用「语音备忘录」，两个原因否掉了：

1. **「语音备忘录」正是 macOS 自带 App 的中文名**，装了 Synapse 的电脑上启动台和 Dock 里会并列出现两个同名应用。
2. 产品里**已经有一个「语音输入」**（按住说话转文字、不存声音）。再加一个「语音*」，两个都叫语音、一个存声音一个不存，用户无从区分。

用一个词走到底反而最省事，也让手机 Tab 保持两字宽，和「终端 / 需要我 / 我的」排在一起不突兀。

**代码内部命名本期不动。** 数据表 `Meeting`、接口 `/meetings`、模块目录 `desktop/src/modules/meeting/`、iOS 的 `Features/Meeting/` 全部保持原样。理由是改表名和接口路径要动线上数据和迁移，风险与收益不成比例，而且用户看不到这些名字。**列成一次单独的内部清理，不混进这次重构**——重构要动的地方已经够多了。

## 4. 交互规格

### 4.1 左栏列表

宽约 286px，背景 `--sidebar`，与右栏之间一条边框。

| 元素 | 内容 |
|---|---|
| 标题 | 用户可改，默认「新录音」 |
| 次要信息 | 时间 · 时长，右侧标出状态（转写中 / 转写失败） |
| 右侧 | 时长，等宽数字 |
| 悬停 / 选中 | 出现「⋯」按钮 |

整行可点。行内的「⋯」是次要操作，点击不能触发选中。

### 4.2 右栏头

标题（可点击重命名）+ 次要信息（时间 · 时长）+ 右侧「复制全文」和「⋯」（重命名 / 删除）。

> 2026-09-19 补记：「复制全文」是后加的（这一版原本只写了「⋯」）。加它是因为转写文字要能
> 一键带走，不必手动从长文里全选。**放在头部而不是文字卡片里**：一场会四十分钟，卡片里的
> 按钮往下翻就找不到了，头部在滚动区外，随时够得着。没有文字可复制时（空态、失败态）按钮
> 置灰而不是消失，免得旁边的「⋯」跟着跳位。

### 4.3 语音视图

```
┌──────────────────────────────────────────┐
│  ▁▃▅█▇▅▃▂▁▃▅▇█▇▅▃▂▁▃▅▇█▇▅▃▂▁▃▅▇█▇▅▃▂▁▃ │  ← 整段铺满，已播部分用前景色
└──────────────────────────────────────────┘
      [↺15]   [▶]   [15↻]      0:12 / 19:24
```

### 4.4 文字视图

就是段落，**装在一张卡片里**（`bg-card`）——语音那边的波形框本来就有这层卡片，两边保持
一致；切「语音 / 文字」时内容宽度也因此不跳。上面没有工具栏，「复制全文」在详情头部（§4.2）。

> 2026-09-19 补记：卡片是后加的。原来文字直接铺在页面底色（`--surface`）上，而同一个位置
> 的语音视图却有一张卡片，切过去像换了一个软件。没有文字可显示时**不套这张卡片**：提示块
> 自己就是一张卡片，套起来就是卡片套卡片。

转写还在进行时：卡片顶部一条进度条 + 一行「转写还在进行，完成后文字会自动补全。」，下面显示已经转好的部分。

### 4.5 状态

| 状态 | 右栏表现 |
|---|---|
| 转写中 | 语音可正常播放；文字显示进度 + 已转好的部分 |
| 转写失败 | **默认切到文字视图**，显示失败原因 + 「重试」。重试不需要重新上传 |
| 已完成 | 正常 |
| 录音被删（历史数据） | 语音显示「录音已删除 / 文字仍保留，切到「文字」查看」；文字正常 |

「录音被删」这个状态今后不会由桌面端产生（删除已经是一整条）。保留它是因为历史数据里还有，以及别的端可能删过音频。

### 4.6 录音页

**完全不变。** 见旧 §3.5 / §4.2。

> 2026-09-19 补记：后来单独做过一次纯表现层的打磨（§2 那条「不要顺手改」针对的是重构时的顺手改动，不是禁止后续专门排期）。打磨口径是**元素和行为一个不加**——计时、5 秒右对齐滚动波形、提示行、取消 / 完成这四样和它们的文案原样保留，只改了间距节奏、计时字号、给波形加了一个承载面（旧 §4.2 的界面图里本来就有这个框）、以及播放器与列表的交互反馈。

### 4.7 手机端

列表不变（标题、时间、时长、状态徽标），副标题去掉发言人数。

详情页从「纪要 / 逐字稿」两栏变成**一段文字**，与电脑端的文字视图一致：没有发言人、没有时间戳、没有搜索、没有纪要。

> **2026-09-19 补记**：这段的「手机端不做播放，所以详情页就只有这一样东西」被推翻了。
> 当晚做的「手机端录音」那一版给手机端补上了语音视图——音频有了自己的位置，和文字是
> 两个平级视图，与电脑端一致。见 `2026-09-19-mobile-recording-design.md`。

### 4.8 文案表

| 位置 | 文案 |
|---|---|
| 左栏空状态 | 还没有录音 + 「开始录音」 |
| 列表状态 | 转写中 / 转写失败 |
| 语音视图 - 录音已删除 | 录音已删除 / 文字仍保留，切到「文字」查看。 |
| 文字视图 - 转写中 | 转写还在进行，完成后文字会自动补全。 |
| 文字视图 - 转写失败 | 转写失败 + 失败原因 +「重试」 |
| 文字视图 - 空 | 还没有文字 / 这段录音里没有识别到语音。 |
| 删除确认 | 删除这条录音？/ 「<标题>」的录音和文字会一起删除，无法恢复。/ 删除 |
| 删除成功 | 已删除 |

**一律不出现**：云盘、上传中、上传进度、云端、服务器、纪要、逐字稿、发言人、生成纪要。

## 5. 边界与异常

- **列表为空时**：右栏显示「没有可显示的录音 / 在左边选一条，或者开始一段新录音。」
- **删掉当前选中的那条**：自动选中剩下的第一条；一条都不剩则显示上面的空状态。
- **重命名**：行内「⋯」的「重命名」会先把这条选中，再在右栏标题处就地编辑。回车提交，Esc 取消。
- **转写进行中**：列表轮询刷新，完成后徽标自己变；不弹进度页。
- **播放中切到文字视图**：播放继续，切回语音时播放头位置正确。

### 6.2 整条删除要新增的东西

**新增 `DELETE /meetings/:meetingId`。**

好消息：`Meeting` 的 5 张子表（MeetingRecording / MeetingTranscriptionJob / MeetingUploadPart / MeetingTranscriptSegment / MeetingSpeaker）在 Prisma 里全部是 `onDelete: Cascade`，删 meeting 这一行就级联清完了（`server/prisma/schema.prisma:1071` 起，迁移里的 DB 级联见 `prisma/migrations/20260919120000_meeting_recording/migration.sql:146-161`）。

但**光删数据库不够**，还要：

1. **删 COS 里的音频对象**（`meeting-recordings/<recordingId>`，走 `MeetingStoragePort.deleteObject`）。
2. **中止未完成的分块上传**，否则碎片会一直按量计费。

**有一个可以直接抄的先例**：`cancelRecording`（`server/src/meeting/meeting.service.ts:410-420`）做的就是"中止分块上传 + `meeting.delete`"。

**但它有一个缺陷，不要照抄**：当录音已经完成（`uploadId` 已被置为 null）时，它**不会删对象**，会留一个孤儿 COS 对象。整条删除必须把"已完成的音频对象"和"未完成的分块上传"两条路都覆盖到。

**腾讯云侧不用管**：ASR 没有删除任务的 API（`tencent-asr.ts` 只有 `createRecTask` 和 `describeTaskStatus`），任务记录靠 `expiresAt` 自然过期。

### 6.3 要下线的写入接口与 bridge

这些接口重构后**没有调用方**，一起删掉，不要留成死代码：

| 层 | 位置 | 内容 |
|---|---|---|
| HTTP | `meeting.controller.ts:174` | `PUT /:meetingId/speakers/:speakerId` |
| HTTP | `meeting.controller.ts:199` | `PUT /:meetingId/minutes` |
| IPC | `electron/modules/meeting/ipc.ts` | `nameSpeaker`、`saveMinutes`、`generateMinutes`、`findPendingRecording`、`readSpooledParts` |
| bridge | `preload.ts:516-543` | `entry.speakerName`、`entry.saveMinutes`、`entry.generateMinutes`、`recording.pending`、`recording.spooledParts`、`recording.remove` |

`DELETE /:meetingId/recording`（只删音频）桌面端不再调用。**接口本身保留**——历史数据里还有 `status=deleted` 的录音，"录音被删"这个状态要继续能显示。

**保留不动**：`GET /:meetingId/transcription/retry`（转写失败要有出路）、`GET audio-url`、`GET peaks`、`PATCH rename`、list / get。

改完同步更新 `docs/agents/capability-registry.md` 的 IPC 数量和描述。

### 6.4 DTO 字段一律不删（重要，别自作聪明）

`speakers`、`minutes`、`segments` 里的 `speakerId` / `startMs` 这些字段，**服务端继续照常返回**，只是两端的界面不再渲染它们。

理由：手机端 `MeetingDetail.speakers` / `segments` 是**非可选数组**（`SynapseMobile/SynapseMobile/Features/Meeting/MeetingModels.swift:76-77`）。服务端一旦不返回，**还没升级到新版本的手机 App 详情页会直接解码失败**。用户手机上装的是 TestFlight 版本，升级不是同步发生的。

数据库里存的转写结果（说话人编号、词级时间戳）也原样保留——将来要恢复这些能力，数据还在。

### 6.5 静默收尾怎么实现

现状：`spool.ts` 的 `sweepStaleSpools`（`spool.ts:95-119`）在启动时只删 24 小时以上的旧分片目录，**不通知服务端收尾**。所以服务端那个任务一直是 `pending`，`GET /recordings/pending` 才查得出来，前端才有"发现一段未完成的录音"那个询问。

做法：主进程新增一个 `finalizePendingRecording()`——内部按 `findPendingRecording → 逐片 uploadPart → completeRecording` 走，时长用 `receivedBytes / (64_000/8) * 1000` 估算（逻辑就是现在 `index.tsx:118-144` 的 `resumePending`），然后在 `bootstrap/descriptors.ts` 的启动流程里调用它。

**不新增 IPC**，前端彻底不知道这件事的存在。启动时只跑一次，注意并发保护。

### 6.6 手机端

- `Features/Meeting/MeetingDetailView.swift`：删掉「纪要 / 逐字稿」分栏，只留一段文字；去掉发言人、时间戳、搜索。
- `Features/Meeting/MeetingListView.swift`：副标题去掉发言人数。
- `Features/Root/RootView.swift:77`：底部 Tab 的 `Label("会议", ...)` → `Label("录音", ...)`。
- **保留**：列表、状态徽标、5 秒轮询、转写完成推送。
- **不做播放**（沿用现状，详情页注释里写明了不做）。

### 6.7 已知缺陷

恢复回来的录音没有波形（波形只在内存里）。这一版接受，语音视图会是一条平的线。

## 7. 验收基线

逐条验证，不要只跑测试就收工。

**布局**

1. 左栏是列表，没有任何标题、搜索、按钮或提示条。
2. 点左栏任意一行，右栏内容跟着换，页面上不存在「返回」。
3. 打开模块时默认选中第一条。

**右栏**

4. 右栏只有「语音」「文字」两个视图，没有第三个入口。
5. 切视图不重置当前选中的录音。
6. 语音视图有波形、播放键、±15 秒、当前时间 / 总时长；点波形能跳转。
7. 文字视图只有段落文字，没有搜索框、发言人、时间戳、纪要、待办。
8. 文字段落是按句子并为自然段的，不是一句一行。
9. 播放中切到文字、再切回语音，播放头位置正确。

**删除**

10. 「⋯」菜单里只有「重命名」和「删除」。
11. 删除确认框说明录音和文字一起删除。
12. 确认后行从列表消失；取消不动数据。
13. 删掉当前选中的那条后，右栏落到剩下的第一条。

**异常退出**

14. 录音中途强杀进程（或直接退出应用），重新打开：**左栏不出现任何询问**，那次录音已经作为一条正常记录存在，并且正在转写或已转写完成。

**转写状态**

15. 转写中的记录，文字视图能看到进度和已经转好的部分。
16. 转写失败的记录，点它在右栏直接看到失败原因和「重试」，不需要手动切视图。
17. 重试不重新上传音频。

**手机端**

18. 录音 Tab 的列表还在，副标题不再显示发言人数。
19. 详情页只有一段转写文字，没有「纪要 / 逐字稿」分栏、没有发言人、没有时间戳、没有搜索。
20. 转写中的记录仍会在手机上自动刷新到「已完成」。
21. **拿一个旧版本的 App 连上改过之后的服务端，详情页仍然打得开**（验证 DTO 字段没有偷偷删掉，见 §6.4）。

**不变的部分（回归）**

22. 录音页与重构前完全一致：波形贴右边缘从右往左长、密度固定、5 秒窗口。
23. 波形和播放控件用主题色，深色模式自动跟随，没有自定义颜色。
24. 界面任何位置都不出现「云盘」「上传」「云端」「服务器」。
25. 录音页点「完成」立刻回列表，不出现等待。

**命名（见 §3.9）**

26. 电脑端和手机端全仓搜不到「会议」两个字——用户可见文案、注释、文档都干净，只有 `meeting` 这种内部目录名和表名除外。
27. 手机底部 Tab 是「终端 / 录音 / 需要我 / 我的」，四个标签字宽一致，没有换行或截断。

## 9. 已定的口径

评审中拍板、实施时不要再问：

1. **删除就是一个动作**，录音和文字一起删，行消失。用户明确选了"没有只删音频的入口"这个代价。
2. **异常退出的录音当正常录音处理**，界面上不出现任何询问；照常产生转写费用是可接受的。
3. **`RELEASE_NOTES_PENDING.md` 里「Synapse 不会把声音存下来」那句仍然不动**（它的适用范围是手机端语音输入面板）。旧设计 §10 第 1 条里"删除后列表里可见「录音已删除」"这半句作废。
4. **波形仍然是纯原生画布，不新增依赖**（沿用旧 §10 第 3 条）。
5. **手机端一起改。** 纪要的生成入口只在电脑上，电脑砍了，手机的纪要栏就永远空着；两端留着中间态不如一次改齐。
   （末尾「手机端本轮仍不做播放」于 2026-09-19 被推翻，见 §4.7 的补记。）
6. **服务端 DTO 字段不删**，只是两端不再渲染。原因是手机端 `speakers` / `segments` 是非可选数组，服务端一停返回，没升级的 App 详情页就解码失败。见 §6.4。
