# 云表列表记录数

用户要求在 Console 表列表显示各表记录数，避免列表统计消耗数据库性能，并在完成后部署服务端。用户已要求直接实施；在当前 `main` 工作区开发，不新建分支或覆盖已有云表查询修改。

## 方案与边界

- 逐表实时 COUNT 会随记录规模增长；定时全表刷新仍会反复扫描且存在延迟，均不采用。
- 采用独立 `CloudTableStats` 元数据，每表一个 BIGINT 未删除记录计数。列表随最多 51 个表摘要批量读取统计，不查询记录表、不逐表发请求。
- 由数据库触发器在同一事务维护增量，覆盖 Console、REST、MCP、批量、幂等、回滚和维护删除。INSERT/DELETE 按语句汇总；UPDATE 仅在 deletedAt 的空值状态变化时执行，普通内容修改不更新统计。tableId 仍由服务端确定，不提供移动记录能力。
- 独立统计行避免更新正在被业务事务 FOR SHARE 锁定的 CloudTable 元数据；同表写入仍有少量计数行写入/锁开销，不承诺绝对零成本或无限写吞吐。
- 建表时初始化统计行；新增、删除、恢复以及含这些操作的混合批次先锁统计行再修改记录。普通内容更新不加统计锁，幂等重放不重新修改计数。这样避免批次与单条删除之间引入反向锁等待。
- 迁移在事务内阻止记录写入，一次性初始化历史计数并安装触发器；正式部署沿用现有停服、备份和预演流程。脚本失败时仅自动回退镜像，不自动恢复数据库；若回退旧应用，还需按脚本输出的手工恢复指引处理迁移前数据库，不能长期仅回退镜像后保留触发器，因为旧写入路径没有统一统计锁顺序。恢复前须核对切换后是否已有新写入。
- 只有有效 `permissions.read === all` 返回 `recordCount` 数字，否则返回 null，避免仅本人可读/仅写权限获知整表总数。新空表为 0，安全整数溢出显式拒绝。
- 列表和表回收站增加“记录数”列，右对齐、千位分隔，null 显示“—”。计数不含记录回收站，不新增排序、轮询或接口。
- 同步 OpenAPI、API 文档、系统云表指南和模块边界；不新增 MCP 工具、注册能力、依赖或公开计数行为。

## 验证

真实隔离 PostgreSQL 覆盖历史回填、批量与混合写入、重复重试、事务失败、并发、删除恢复及清理；列表单测拒绝任何记录表读取并覆盖 ACL/scope/安全整数。Dashboard 单测检查实际记录数显示，执行类型检查、构建和 UI 边界检查。未启动浏览器，不宣称视觉验收。部署后检查在线资源和统计元数据。
