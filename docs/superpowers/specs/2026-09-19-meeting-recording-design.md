## 1. 要解决什么

开会的时候人在听，就没法记。会后凭记忆补，补出来的东西失真；会议录音躺在手机里没人愿意再听一遍。

这个功能让用户只做一件事：**按下录音，然后专心开会**。剩下的——转文字、分说话人、出纪要——在后台完成，用户想起来看的时候结果已经在那里。

用户提出的三条硬要求，全部是设计约束：

1. **录音必须上传到云端之后才开始转文字。**
2. **转文字的过程中，用户可以关掉电脑。**
3. **转文字完成后可以浏览结果。**

第 2 条决定了整个架构（见 §3.2），不是体验优化，是前提。

## 2. 现状与它的来历

### 2.1 现有的语音输入是什么

`desktop/src/modules/voice/` 是「按住说话、边说边出字」的实时字幕。音频走 WebSocket 直连腾讯云实时识别，**PCM 只在内存里过一遍就发走，不落任何文件**。它是为一次说几十秒设计的。

### 2.2 为什么不能直接复用它

| 限制 | 位置 | 后果 |
|---|---|---|
| 单条识别连接 60 秒上限 | `desktop/src/modules/voice/asr-renewal.ts` | 靠 46 秒预热、50 秒强制接棒绕开，这是为短句设计的复杂度，长录音扛不住 |
| 音频只在内存，不落盘 | `desktop/src/modules/voice/asr-pcm.ts` | 会议中途进程退出，全部丢失 |
| 只能实时推流 | 同上 | 用户必须全程在线；关掉电脑这条要求直接不成立 |

结论：会议录音是**另一条独立链路**，不复用现有语音输入的任何代码。

### 2.3 平台媒体存储（粘贴图片那条链路）

`server/src/drive/platform-media-storage.ts` + `drive-document-hosted-image.service.ts`。文档里粘贴的图片走这条：独立的 COS 桶（`PLATFORM_MEDIA_COS_*`），对象路径 `document-images/${imageId}`，服务端签发预签名 PUT 直传，上传后回查大小与文件头，记录落 `DocumentHostedImage` 表，删除是硬删对象 + 记录标删除态，备份只带对象清单不含内容。

**会议录音走同一条链路，换个路径前缀。** 详见 §3.3。

### 2.4 「Synapse 不会把声音存下来」这句承诺的来历

`RELEASE_NOTES_PENDING.md` 里，手机端语音输入面板由「录音中」改称「识别中」，配的解释是「这块面板做的是把你说的话变成文字，**Synapse 不会把声音存下来**」。

那句话的适用范围是语音输入面板，本功能与它不直接冲突。但用户会把两处放在一起读，所以 §3.10 规定了本功能的措辞口径。

### 2.5 服务端与推送现状

- 服务端是 NestJS 模块化单体 + Prisma + PostgreSQL，**没有通用异步任务队列**，也没有 Bull/Redis。
- 「建表当队列 + `@Cron` 轮询消费」是既有范式（`SkillRepositoryObjectCleanupTask`）。
- 服务端推桌面端：`live-desktop.gateway.ts` 的 `broadcastToUser`，完整先例是 webhook 投递那条链路。
- 服务端推手机：`MobilePushService`（APNs），目前只有终端审批一个业务入口，可复用。

## 3. 决策

### 3.1 识别引擎：`16k_zh_en_meeting`（天籁 ASR，大模型 2.0 档）

腾讯云 ASR 的「大模型版」不是独立产品，是同一个接口里的引擎参数取值，按计费分 1.0 / 2.0 两档。会议场景只有两个候选：

| | **16k_zh_en_meeting** | 16k_zh_en_2.0 | 16k_zh（通用） |
|---|---|---|---|
| 定位 | 多人对话专用 | 通用高精度 | 通用 |
| 重叠发声 | 官方点名最优 | 未特化 | 未特化 |
| 中英混说 | 支持 + 31 种方言 | 支持 + 31 种方言 | 少量英语 |
| 说话人分离 | 支持 | 支持 | 支持 |
| 角色分离（声纹认人） | 不支持 | 支持（增值） | 不支持 |
| 口语转书面语 | 不支持 | 不支持 | 支持（增值） |
| 单价 | 0.8 元/时 | 0.8 元/时 | 1.75 元/时 |

**选它。** 官方原文：「在多人对话场景下，`16k_zh_en_meeting` 引擎对于多说话人重叠发声的转写准确率与说话人分离准确率均表现突出，建议使用时配合开启说话人分离。目前已应用在腾讯会议、元宝录音笔等产品。」开会抢话是常态，这一项压倒其他所有指标。

两个已知取舍，都是接受的：

- **用不了「口语转书面语」和「语义分段」**（`ResTextFormat` 4/5 只支持 `8k_zh`/`16k_zh`）。把语气词清理和结构化交给 Synapse 自己的 Agent 做，做得更好，还不额外收费。
- **用不了「角色分离」**（声纹认人，`SpeakerDiarization=3` 只支持另两款引擎）。改为先出「发言人 1/2/3」，让用户填一次真名，全篇自动套用。

**成本**：大模型 2.0 档**无免费额度**（通用档每月 10 小时免费）。按每月 20 场 1.5 小时会议算，24 元；同样用量走通用档扣掉免费额度反而要 35 元。一场 1.5 小时会议约 **1.2 元**。

### 3.2 走异步接口，转写任务归服务端

腾讯云有三种长音频转写方式，只有一种符合「上传后可以关机」：

| 接口 | 调用方式 | 为什么不用 |
|---|---|---|
| 录音文件识别极速版 | 同步 | 客户端必须挂住连接等结果，最长 2 小时。关机即前功尽弃 |
| 实时语音识别 V2 | 流式 | 必须边说边推流，只能录在线会议 |
| **录音文件识别 `CreateRecTask`** | **异步** | **选用**。提交即返回任务号，结果 24 小时内随时来取 |

任务记录必须落在**服务端**。放桌面端就得让 Synapse 一直开着、电脑不睡，一旦退出任务就断了。放服务端，用户点完「完成」就可以合上电脑，第二天打开结果就在那里。

### 3.3 音频存平台媒体存储，不进云盘

会议录音**不是用户云盘里的东西**：不占用户云盘配额，不出现在云盘列表、搜索、同步里，用户在云盘里看不到它，界面上也不说它在哪。

| 项 | 做法 |
|---|---|
| 存储位置 | 平台媒体 COS，对象路径 `meeting-recordings/${recordingId}`，与 `document-images/` 平级 |
| 与云盘的关系 | 互不相干 |
| 上传方式 | 服务端代理分片写入（理由见 §6.1），客户端不持有存储凭证 |
| 上传后校验 | 服务端回查对象大小与文件头，通过后才记为可用 |
| 备份 | 维持现状：只带对象清单，不含音频内容 |
| 删除 | 硬删对象，记录保留删除状态——用户看得见「已删除」确实生效 |

**脱离云盘配额不等于没有成本**：音频是平台的存储开销。单条录音设 5 小时上限（约 140 MB），录音到 4 小时时提示。

### 3.4 边录边传，结束只补尾片

录音过程中每 2 秒产出一个音频分片，字节攒到 1 MB 就传走一片（这是对象存储分块上传的最小分片，约合 128 秒音频）。

**结束录音时只需要补齐最后一片**，所以「完成」是瞬间的，用户可以直接离开这个界面去做别的。

| 环节 | 做法 |
|---|---|
| 分片来源 | 编码器按时长切片，每片 2 秒，同一路音频同时喂给振幅分析 |
| 上传单位 | 字节攒到 1 MB 传一片 |
| 服务端 | 每片到达后写入同一个对象的对应区间 |
| 结束录音 | 补齐尾片、完成合并、提交转写，界面立刻回到列表 |
| 取消录音 | **中止**这次分块上传并丢弃已传分片 |

### 3.5 录音界面只回答两个问题

录音时用户只需要确认两件事：**是不是在录**、**麦克风到底听没听见**。所以这一屏只有：一个小波形、一个计时、取消 / 完成两个按钮。

没有暂停——会议中途要暂停的需求，远少于误触的成本。

**没有声音时直接把结论写出来**：开头一直听不到声音，就在波形下方显示「没有听到声音」。不指望用户会看波形判断，听不到就是听不到。一旦听到过一次就永远不再提示，开会中途不打扰。

麦克风权限被拒时显示「未取得麦克风权限，波形为示意」，不拿假波形冒充真的。

### 3.6 波形：真数据、主题色、5 秒右对齐滚动

- **必须是真数据。** 麦克风流同时喂给编码器和分析节点，每 28 毫秒取一次时域数据算振幅。不是随机柱状图。
- **密度固定。** 一个采样永远占同样宽的槽位，所以录得越久不会把整段压进同一个框里，而是旧的从左边滚出去。
- **贴右边缘、从右往左长。** 最新的在右边缘，早的往左排；装满前左边的空位空着。
- **只回看最近 5 秒。** 槽位数同时受时间窗口和画布宽度限制，取小的那个，保证最新的柱子不会被挤出右边缘。
- **配色用主题前景色**（`--foreground`），随深浅色主题走。语音备忘录的红色是它自己的品牌主色，Synapse 不引入自定义颜色。

### 3.7 回放做减法

会议详情顶部一条**可点击定位**的波形加一个播放按钮，就够了。

没有时间刻度尺、没有缩略图、没有快进快退、没有倍速。逐字稿才是这一页的主体，音频是用来「听一下当时怎么说的」，点波形就能跳。

回放那条波形是**整段铺满宽度**的（与录音中那条滚动窗口不同，这是有意的）：它的作用是一眼看完整个会议。

### 3.8 纪要用 Agent 出，不用腾讯云的增值服务

转写完成后，用户可以一键生成纪要。这件事由 Synapse 自己的 Agent 完成，而不是买腾讯云的「口语转书面语」增值服务——那项服务只支持通用引擎，用不了我们选的会议引擎，而且 Agent 还能顺带出结构化议题和待办。

### 3.9 说话人：先编号，用户可命名

腾讯云返回的是「发言人 1/2/3」。逐字稿顶部提供「发言人命名」，用户填一次真名，全篇自动套用。不引入声纹（见 §3.1）。

### 3.10 界面不体现上传，不体现存储位置

- **录音中不出现任何与上传有关的信息。** 上传进度、分片、云端状态一概不显示。
- **不出现「云盘」字样。** 录音不在云盘里，任何暗示它在云盘的文案都是错的。
- **转写中的状态可以显示**（列表里一个「转写中」徽标），这描述的是任务进度，不暴露存储位置。
- **不显示「可以关闭电脑」。** 这句话虽然是真的，但说出口就等于告诉用户处理不在本机进行，与「用户不感知存储在哪」的口径冲突。**已定：不说。**

## 4. 交互规格

### 4.1 会议列表

一行一场会议，整行可点。

| 元素 | 内容 |
|---|---|
| 标题 | 用户可改，默认「新录音」 |
| 次要信息 | 时间 · 时长 · 发言人数 · 录音是否还在 |
| 徽标 | 转写中 / 已完成 / 转写失败 |

「录音已删除」只在删除后显示；录音还在时不必特意说。

### 4.2 录音页

```
              新录音
              00:42
     ┌────────────────────────────┐
     │              ▁▃▅█▇▅▃▂▁▃▅▇█ │  ← 64px 高，贴右边缘，从右往左长
     └────────────────────────────┘
            没有听到声音              ← 只在一直没声音时出现

        [ 取消 ]        [ 完成 ]
```

### 4.3 会议详情 / 逐字稿

顶部：可点击定位的波形 + 播放按钮 + 当前时间 / 总时长 + 「删除录音」。

Tabs：纪要 / 逐字稿。

逐字稿：搜索框 + 「发言人命名」；每条含发言人（带颜色条）、时间戳（可点跳转）、文本。

### 4.4 纪要

由逐字稿生成，分议题、结论、待办三段。待办可勾选，带负责人与时间。可编辑。

### 4.5 文案表

| 位置 | 文案 |
|---|---|
| 列表空状态 | 还没有会议记录 |
| 列表主操作 | 开始录音 |
| 录音页标题 | 新录音 |
| 录音页无声提示 | 没有听到声音 |
| 录音页无权限 | 未取得麦克风权限，波形为示意 |
| 录音页操作 | 取消 / 完成 |
| 完成 toast | 录音已保存 |
| 取消 toast | 录音已取消 |
| 列表徽标 | 转写中 / 已完成 / 转写失败 |
| 详情删除 | 删除录音 |
| 删除后提示 | 录音已删除 · 逐字稿和纪要保留 |

**一律不出现**：云盘、上传中、上传进度、云端、服务器。

### 4.6 音频参数

| 项 | 取值 |
|---|---|
| 编码 | AAC / m4a，64 kbps，单声道 |
| 体积 | 约 28 MB/小时 |
| 采样 | 16 kHz 单声道（引擎要求，`ChannelNum=1`） |
| 分片 | 编码每 2 秒一片；上传每 1 MB 一片 |
| 上限 | 单条 5 小时 |

腾讯云识别的请求参数（服务端持有）：

| 参数 | 取值 |
|---|---|
| `EngineModelType` | `16k_zh_en_meeting` |
| `ChannelNum` | `1`（16k 音频只接受单声道，传 2 会被直接拒绝） |
| `SourceType` | `0`（URL。base64 通道上限仅 5 MB，装不下会议） |
| `SpeakerDiarization` | `1` |
| `SpeakerNumber` | `0`（自动分离。16k 引擎不支持指定人数） |
| `ResTextFormat` | `1`（带词级时间戳） |
| `FilterModal` | `1`（过滤部分语气词） |
| `FilterDirty` | `1` |
| `ConvertNumMode` | `1`（默认值） |
| `HotwordList` | 参会人姓名、项目名、产品术语，上限 128 个 |

## 5. 边界与异常

| 情况 | 处理 |
|---|---|
| 麦克风权限被拒 | 不阻断录音，走示意波形，界面明说 |
| 一直没有声音 | 波形下方显示「没有听到声音」，听到后永久消失 |
| 录音中途进程退出 | 已传走的分片留在服务端，本机只留未上传部分；重新进入时提示「发现一段未完成的录音」 |
| 取消录音 | 中止分块上传并丢弃已传分片，不留残留（见 §6.2） |
| 分片上传中断 | 分片重传即可，已确认写入的区间不重传 |
| 提交任务失败 | 任务表保留记录，由 `@Cron` 重试（最多 5 次）；音频不丢 |
| 转写失败 | 详情页显示失败原因与「重试」，重试不需要重新上传 |
| 引擎判定音频不可识别 | **一次就判失败，不重试**。引擎已经真的跑过这段音频并拒绝了它，换任务号重投同一份字节结果只会一样；用户要的是尽快看到失败和「重试」按钮，而不是等五分钟的自动重试 |
| 任务号 24 小时后失效 | 结果一旦取回立即落库；超期未取回的重试一次，仍失败则提示用户 |
| 引擎长时间没有读过这段音频（`AudioDuration` 一直是 0） | 超过 15 分钟（`MEETING_TRANSCRIPTION_STALL_MS`）**当场判失败**，原因写「这段录音里没有检测到说话内容，无法转写。」。判据是 `AudioDuration`：引擎只要真读到过就一定会回填（实测 6 秒到 34 秒的音频都在 5 秒内填好），所以「等够了还是 0」等于它根本没碰过。**不误杀长录音**——这个数一有值兜底立刻让路，该等多久的照等 |
| 音频超过 5 小时 | 提交前按 5 小时切分，逐段提交后拼接结果 |
| 静音或无人说话 | **走不到「逐字稿为空」那条路**：开着 `SpeakerDiarization=1` 提交时，引擎既不回结果也不报错，长时间停在「处理中」（`Status` 恒为 1、`AudioDuration` 恒为 0），直到几十分钟后由腾讯云自己判失败（实测两条：47 分 16 秒、51.9 分钟，错误都是 `Failed to recognize audio!`）。同一条音频关掉分离几秒就出结果，所以卡住的是引擎的说话人分离本身，与采样率（16k/48k 都复现）和网络都无关。这种录音由上面那条 15 分钟兜底收敛成「没有检测到说话内容」的失败 |
| 删除录音时转写还在进行 | 任务不受影响——腾讯云在提交那一刻就已经把音频拉走了 |
| 用户手动删除录音后又想听 | 逐字稿和纪要保留，播放区显示「录音已删除 · 逐字稿和纪要保留」 |

## 6. 实施约束

### 6.1 分块上传要从零建，且必须走服务端代理

全仓没有任何分块上传的先例。更要紧的是：**当前用的对象存储 SDK 签不了单个分片的预签名地址**——`getObjectUrl` 的签名动作写死成整文件的读或写，而 SDK 自己上传分片用的是另一个动作。

所以**由服务端代理分片**：客户端把分片交给服务端，服务端写进对象存储的同一个对象。

附带好处是服务端不需要任何音频处理能力。仓库里没有 ffmpeg，也没有 sharp，靠对象存储自身的合并就能出单文件，绕开了自建拼接的整条路。代价是音频字节过一次服务端，按 28 MB/小时算可以忽略。

### 6.2 取消必须真正「中止」，不是「删除」

现有的两套上传过期清理（Drive 会话、文档图片）都只删最终对象，**删不掉一次未完成的分块上传留在桶里的分片**——那些碎片会一直按量计费。

取消录音必须额外走一步中止分块上传。仓库里这个调用零使用，是新写的。

### 6.3 `file://` 下不能用 AudioWorklet

生产环境渲染进程是 `file://` 页面，`audioWorklet.addModule` 会因跨源限制失败，而开发环境用 `http://localhost` 根本看不出来——现有语音输入模块正是因此退回 `ScriptProcessorNode`。

波形分析走 `AnalyserNode`，不涉及模块加载，没有这个限制。

**本轮不引入波形库，用原生画布。** 已经调研过：将来若要换库，选 `wavesurfer.js` 7.x——它的实时波形实现本身就是分析节点加定时轮询，整包里 `worklet` 零命中，这条限制对它不成立（BSD-3，核心 11.7 KB gzip，支持直接喂振幅数组不发网络请求）。不用 Peaks.js（不支持实时录音波形、LGPL-3、用 Blob Worker 在 `file://` 下的风险更隐蔽）；不用 react-audio-visualize（停更两年、只吃音频文件、只有柱状）。

**绘制逻辑封装在单独的 `waveform` 模块里，将来换库只动这一个文件。**

### 6.4 密钥只在服务端

腾讯云的 AppID / SecretID / SecretKey 全部由服务端持有并签名，桌面端不接触。这与现有语音输入的既有约定一致（`server/src/voice/asr-signature.ts`）。

### 6.5 需要新加一个下载签名地址

现有平台媒体存储只有上传签名和「经服务端流式转发」两条路，没有预签名下载。腾讯云必须自己去拉音频，所以要么给存储层加一个下载签名方法，要么走别的转发路径。这是落地时绕不开的一处新增。

### 6.6 依赖边界

**不新增任何依赖。** 波形用纯原生画布实现。其余全部复用现有能力：平台媒体存储、服务端 cron 范式、桌面端推送通道、手机端推送。

## 7. 与相邻改动的关系

- **语音输入那轮**：同一条「不存声音」的承诺，但适用范围不同。本功能必须在录音页明说「录音会保存」，因为录音不在云盘里，用户不会在别处偶然发现它——没有别的地方会替它说明。
- **手机端终端文件上传那轮**：那轮反复提到的 100 MB 是**云盘**的单文件上限。本功能的音频不进云盘，与该上限无关。
- **终端会话**：无关。

## 8. 验收基线

逐条验证，不要只跑测试就收工。

**引擎与链路**

1. 服务端提交的引擎是 `16k_zh_en_meeting`，`ChannelNum=1`、`SourceType=0`、`SpeakerDiarization=1`、`SpeakerNumber=0`、`ResTextFormat=1`。
2. 任务记录落服务端；桌面端退出后重新打开，任务仍在推进。
3. 转写结果按段落落库，含说话人编号与起止时间。

**存储**

4. 音频对象路径是 `meeting-recordings/${recordingId}`。
5. 音频不出现在用户云盘的任何入口：列表、搜索、同步。
6. 界面任何位置都不出现「云盘」「上传」「云端」「服务器」字样。
7. 删除录音后，对象真的没了；逐字稿和纪要仍在。

**录音**

8. 录音中波形来自真实麦克风：对着麦克风说话波形随之起伏，安静时伏下去。
9. 波形密度固定：录 1 分钟和录 5 秒，柱子的宽度和间距一样，不是越录越密。
10. 波形贴右边缘、从右往左长；装满 5 秒后旧的从左边滚出去。
11. 开头一直没声音时显示「没有听到声音」；出声之后不再出现。
12. 拒绝麦克风权限后不崩，显示「未取得麦克风权限，波形为示意」。
13. 波形与播放图标用的是主题色，深色模式下自动变亮，没有自定义颜色。

**边录边传**

14. 录音过程中分片持续上传，界面无任何上传相关显示。
15. 点「完成」后立刻回到列表，不出现上传页、不出现等待。
16. 点「取消」后，服务端不留任何分片（含未完成的分块上传）。
17. 录制长于 5 秒后，「完成」的响应时间与录音时长无关。

**转写与纪要**

18. 列表出现「转写中」徽标，完成后自动变「已完成」并推送通知。
19. 逐字稿按发言人分段，时间戳可点击。
20. 「发言人命名」填一次，全篇套用。
21. 纪要能一键生成，含议题 / 结论 / 待办三段。
22. 转写失败时详情页有失败原因与「重试」，重试不需要重新上传。

**回放**

23. 详情页波形是整段铺满宽度，与录音中那条滚动窗口不同。
24. 点波形任意位置能跳到对应时间，播放头跟着走。
25. 播放按钮状态正确（播放中显示暂停图标）。
26. 刚录完的会议能真的播放出声音。

## 10. 已定的口径

三条在评审中拍板、实施时不要再问的决定：

1. **`RELEASE_NOTES_PENDING.md` 里「Synapse 不会把声音存下来」那句不动。** 它的适用范围是手机端语音输入面板。会议记录在录音页单独说明「录音会保存，用于转写」，并让每条录音都能单独删除、删除后列表里可见「录音已删除」。
2. **界面上不出现「可以关闭电脑」。** 转写中只显示一个状态，不做解释。理由见 §3.10。
3. **波形用纯原生画布，不新增依赖。** 绘制逻辑封装在单独的 `waveform` 模块里。理由见 §6.3 与 §6.6。
