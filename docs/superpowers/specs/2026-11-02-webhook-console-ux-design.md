# Webhook 控制台信息架构与交互重构

日期：2026-11-02
状态：用户已选择“按建议直接完成重构”，并说明本地服务已经启动；复用现有服务进行界面验收。
范围：`dashboard/` 的普通用户 Webhook 列表、配置、全局触发记录及管理员历史记录。

## 用户目标

从产品经理角度重构相关页面的组织与展示，充分使用 HeroUI，让用户容易找到接入配置、判断最近投递状态并排查具体请求。

## 现状与问题

- 列表名称不可直接进入配置，详情和查看记录分别通向不同页面，单个 Webhook 的任务上下文中断。
- 配置详情以同等权重排列 URL、Public ID、日期和最近状态，复制接入地址缺少直接入口。
- 重命名、启停、重置密钥、删除并排出现，日常操作与破坏性操作没有分层。
- 历史页需要手填内部 Webhook ID；日期没有可见标签，也没有清除筛选入口。
- 客户端列使用 `1/2/2`，用户无法直接知道数字分别表示什么。
- 请求详情把请求元数据、正文预览、回执与错误平铺，排查顺序不清晰。
- 重置提示宣称新 URL 只显示一次，与现有可恢复完整 URL 的接口行为不符。

## 方案比较

1. 仅调整现有表格与表单。影响最小，但保留配置与单个 Webhook 历史割裂的问题。
2. **建议：列表进入单个 Webhook 工作区，按配置与触发记录分区，同时保留全局历史。** 日常管理与排查衔接，复用现有接口与表格，不要求新增后端能力。
3. 把所有列表、配置和历史压进一个主从分栏页面。大屏切换快，但窄屏、深链和多层详情更复杂，本次不建议。

## 页面与任务组织

### Webhook 列表

- 保留分页表格，以名称作为进入详情的主要链接；列聚焦名称、启用状态和最近触发结果。
- 标题区提供“新建 Webhook”和“全部触发记录”。已有桌面入口 `/console/webhooks?action=create` 继续直接打开创建表单。
- 行内提供记录入口与次要操作菜单；重置密钥和删除使用独立危险操作组并保留确认。
- 没有触发记录时显示“尚未触发”，不将其标记为成功或失败。
- 所有搜索或筛选必须准确表达服务端范围；不把当前分页的本地过滤冒充全量搜索。

### 单个 Webhook

- 明确的返回列表入口、名称、启用状态；使用 HeroUI Tabs 分出“配置”和“触发记录”。
- 配置按“接入地址”“基本设置”“危险操作”组织。URL 与复制相邻，默认遮蔽含密钥地址，支持显隐；legacy hash-only 地址不可复制，提供重置密钥入口。
- 名称与启用状态按字段组织，保留保存反馈、请求中的禁用状态及错误提示。
- Public ID、创建和更新时间为次要元信息，不与接入操作争夺视觉权重。
- 重置提示准确说明旧地址立即失效、外部服务需要更新；删除提示说明地址失效但历史记录保留。
- 触发记录复用全局历史表格，锁定当前 Webhook 范围，不重复整页 Header/Main，不再要求用户重新选择 Webhook。

### 全局触发记录

- 保留普通用户与管理员现有路由、接口、权限隔离及已删除 Webhook 的历史入口。
- 普通用户通过名称选择已有 Webhook，选项需分页加载，不能只取首批后让其他项无法选择。
- 已删除或无法加载的指定 Webhook 仍保留筛选值与清除入口；不因管理列表缺少该项而清空历史条件。
- 管理员没有管理其他用户 Webhook 的接口，不借用当前普通用户列表；保留明确标注的 Webhook ID 筛选和用户筛选。
- 状态、开始日期、结束日期使用可见标签与一致的 HeroUI 字段布局；提供清除筛选与刷新。
- 筛选变化回到第一页，日期区间反转时给出字段错误，避免发送错误查询；分页、排序及筛选尽量与 URL 保持一致，浏览器前进后退能还原。
- 表格保留接收时间、Webhook 快照名称、投递状态、桌面端回执和请求摘要；客户端数量必须附带明确含义。管理员额外显示用户。

### 请求详情抽屉

- 顶部先显示投递状态、接收时间和错误。
- 使用 HeroUI Tabs 区分“请求”和“桌面端回执”，默认展示请求摘要。
- 请求区展示方法、脱敏路径、类型/体积和已有正文预览；Query 与 Headers 通过 Accordion 按需展开。
- 回执区明确在线、已发送、已确认及失败数量，逐个展示设备、投递状态和时间；没有回执时显示必要空状态。
- 长名称为关闭按钮留出空间；长 JSON/路径可换行，正文有单一可滚动区域，操作与标题保持可见。

## 不变的业务边界

- 不新增依赖，不修改后端、数据库、桌面自动化或投递协议。
- 状态只说明接收、转发和确认收到，绝不等同于本地自动化匹配或执行成功。
- 不新增重试、回放、补发、队列、测试请求发送或原始 payload 能力。
- 每个 Webhook 最近 100 条历史的保留策略不变；删除后历史仍可查询。
- 历史只使用现有脱敏数据，不展示完整含密钥 URL、Authorization、Cookie 或原始正文。
- 普通用户和管理员的身份、数据范围、路由入口不变。
- HeroUI 3.2.7 默认浅色主题与原生组件变体；白色浮层中的表单控件使用 secondary，避免自定义皮肤与卡片嵌套。
- 当前仓库 main 上已有 cloud-tables 未提交改动，不修改、不暂存。
