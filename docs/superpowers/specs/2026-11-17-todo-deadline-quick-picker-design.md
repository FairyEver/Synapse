# 待办截止时间快速选择设计

日期：2026-11-17。

状态：用户已选定“快捷优先”的两段式弹层方案；本文待最终确认，尚未修改产品代码。

## 目标

在桌面待办顶部快速创建区，把原生 `datetime-local` 输入替换为统一的截止时间弹层。用户既能一键设置常用时间，也能通过日历和本地时间输入精确选择。

快捷项：

| 文案 | 计算规则 |
| --- | --- |
| 1 小时后 | 点击时的本地时间加 1 小时 |
| 今天中午 | 本地当天 12:00 |
| 今天 17:00 | 本地当天 17:00 |
| 明天中午 | 本地次日 12:00 |
| 1 天后 | 本地日历次日，保持当前时分 |
| 2 天后 | 本地日历后天，保持当前时分 |

每个快捷项同时显示对应的准确日期与时间，例如“今天中午 / 11月17日 12:00”，避免歧义。

## 范围

- 只改桌面快速创建区的截止时间入口，不改变待办接口、数据模型、提醒服务或列表排序。
- 继续使用现有 `due` 本地时间草稿和 `todoLocalToUtc` 转换；保存仍是分钟精度，秒与毫秒为 0。
- 不隐式开启提醒，不改变“相对提醒必须有截止时间”的现有校验。
- 编辑待办弹窗本次继续使用现有原生日期时间输入；可以复用同一个新组件，但不扩大本次界面改动范围。
- 不新增提醒类型、重复任务、全天截止或服务端能力。

## 交互

### 打开与关闭

- 点击创建区的“截止时间”按钮打开 Radix Popover；触发器继续显示当前截止值或“截止时间”。
- 弹层默认进入“快捷”视图。Esc、点击外部或点击关闭按钮均关闭弹层，不写入草稿。
- 点击可用的快捷项后，立即写入本地 `due` 草稿并关闭弹层，焦点回到截止时间触发器。
- 切换到“自定义”视图后，日历和时间输入只修改弹层内草稿；点“完成”才写入正式草稿并关闭。
- “取消”丢弃本次自定义修改并关闭；已有截止时间保持不变。

### 快捷项

- 弹层使用两列三行按钮，每个按钮包含主文案和准确时间副文案。
- 相对项在点击时按当前本地时间重新计算，不按弹层首次打开时间计算。
- 绝对项不晚于当前时间时保持原位、禁用并显示“已过”，不使用隐藏或删除。“今天中午”和“今天 17:00”分别独立判断。
- 写入前再次校验目标时间；如果弹层打开期间跨过了时间点，则刷新禁用状态，不写入已过去的时间。
- 已存在的截止时间只有在与某个当前可用快捷项完全一致时才显示为选中；不强行把近似时间匹配成快捷项。

### 自定义

- 自定义视图直接展示月历、上一月/下一月操作、时间输入和“取消 / 完成”。
- 已有截止时间时，以该值初始化日历和“HH:mm”时间。
- 尚无截止时间时，默认取当前时间后的下一个整点，日期跟随该时刻，例如 `09:12` 显示当天 `10:00`，`23:12` 显示次日 `00:00`；用户可以继续修改。默认值在打开自定义视图时固定，不随后台时间漂移。
- 日期或时间不完整、无效时，“完成”禁用；提交时继续使用现有 `todoLocalToUtc` 校验。
- 时间输入中按 Enter 等同于“完成”，必须阻止外层快速创建表单提交。
- 已有截止时间时提供“清除截止时间”。清除只移除 `due`，不静默改动提醒选择；若仍有相对提醒，保存时沿用现有提示，要求补齐截止时间或改选提醒方式。

## 布局

弹层宽度控制在约 `320–360px`，随窗口边界自动翻转，并复用现有 Popover、Button、Input、Field、Calendar 和主题 token。

```text
┌──────────────────────────────┐
│ 设置截止时间              ×  │
│ ┌──────────┬───────────────┐ │
│ │   快捷   │    自定义     │ │
│ └──────────┴───────────────┘ │
│ ┌────────────┬─────────────┐ │
│ │ 1 小时后   │ 今天中午    │ │
│ │ 10:12      │ 12:00       │ │
│ ├────────────┼─────────────┤ │
│ │ 今天 17:00 │ 明天中午    │ │
│ │ 17:00      │ 12:00       │ │
│ ├────────────┼─────────────┤ │
│ │ 1 天后     │ 2 天后      │ │
│ │ 11月18日   │ 11月19日    │ │
│ └────────────┴─────────────┘ │
└──────────────────────────────┘
```

自定义视图沿用相同弹层外壳，主体替换为月历和时间行；不嵌套第二个弹层，不把快捷项塞进原生日期控件。

## 方案取舍

- 双栏总览：快捷项、日历和时间全部同屏，高度低，但弹层横向明显变宽，视觉负担最大。
- 标准单列：快捷项、日历、时间纵向排列，最接近 shadcn 官方组合，但弹层较高，常用操作需要跨过日历。
- 快捷优先：默认只呈现可一键完成的常用时间，自定义日期进入第二视图；少一次视觉扫描，符合快速创建场景。代价是手动日期多一次视图切换。

用户选择快捷优先方案。

## 实现边界

- 新增一个待办专用的截止时间选择器，内部拆出快捷项计算与格式化 helper，便于固定边界测试。
- 使用 shadcn 官方组合方式补充 `Calendar` 源码组件；`react-day-picker` 已是现有依赖，不新增日期运行时依赖。
- `TodoQuickCreate` 改为打开新弹层，不再渲染原生 `datetime-local`；`useTodoEditor` 的字段契约保持不变。
- 快捷项、当前时间判断和日历选中状态只在 renderer 内处理，不进入 IPC 或服务端。
- 使用现有 `data-track` 命名体系记录打开、视图切换和快捷项选择；不记录用户选择的绝对时间。
