# Agent 长运行容量契约与实施边界

状态：部分实施。2026-09-13 的修改没有完成有界历史存储、全窗口页缓存或视口虚拟化；下表明确区分当前代码与后续目标。不得将本设计作为长期性能验收通过的证据。

## 已实施的窄边界

| 所有者 | 常量 / 单位 | 当前行为 | 验证 |
| --- | --- | --- | --- |
| Renderer React measure guard | `REACT_MEASURE_RETENTION_LIMIT = 256` 条；单个原始名称最多 256 UTF-16 code units | 仅识别 React 的 `Components ⚛` track 和 `Scheduler ⚛` trackGroup；沿用进入原生序列化前移除 detail 的保护；以 `synapse.react:` 独立名称保留记录，超量按名称清理；卸载释放。业务 measure、mark 和 longtask 观察器不清空 | 1k/10k/100k 次写入、同名业务记录保留、重复 scheduler 名称、卸载 |
| 单个全文查看器 | `AGENT_CONTENT_CHUNK_BYTES = 64 * 1024` UTF-8 bytes；`AGENT_CONTENT_PREVIOUS_CURSOR_LIMIT = 128` 个 UTF-16 offset | 当前只保留一个正文段；超过回退游标预算丢弃最旧游标，回退耗尽时提供“返回开头”；全文仍可重新逐段读取。关闭释放正文和游标；目标切换、关闭和卸载使旧请求失效；同一窗口同时最多一个未完成逻辑请求 | 400 次前进和回退、300 次开关、晚到响应、重复点击、失败重试 |
| 时间线计时文字 | 每个已挂载活动 phase / process duration 一个 1 秒 interval | interval 只更新计时子组件，终态和卸载清理；Timeline 本身不再订阅每秒时钟 | 计时继续前进而时间线数组访问为 0；300 次计时组件挂载/卸载后 timer 回落为 0 |
| 会话仓储实例 | 每个 conversation ID 一条现有串行 mutation 队列 | append、最后记录元数据、问题响应与标题共享读改写队列；非标题保存只对实际变化的顶层字段应用 patch，避免旧快照回写 history、SDK ID、费用和标题 | 32 次并发追加与 SDK/费用/标题更新；原测试先失败，修复后通过 |

这些边界不能推导出全应用容量有界：多个 Renderer 的 measure 上限为 `256 × Renderer 数`；全文正文为 `64 KiB × 已打开查看器数`，游标为 `128 × 已打开查看器数`。当前没有全应用窗口准入预算；Timeline 中可挂载行数也仍无硬上限。计时器总数随已挂载活动行数增长，单项释放测试不等于总量验收。

正文预处理使用组件内 `useMemo`，依赖正文字符串。它只避免不变正文的重复脱敏与引用解析，不限制单条活动正文大小，也不替代显示缓存淘汰。

## P1/P2 的目标契约（尚未实施）

- 权威内容继续归 DataRepository，不允许另建业务 SQLite 或裸文件存储。摘要与历史必须分离；历史记录使用稳定 conversation ID + 单调序号，正文按引用分块。不能用空 history 冒充完整 Conversation 返回给旧消费者。
- 先扩展 DataRepository 的事务、索引游标和分块读写能力，再接仓储、IPC 和 Renderer。现有 `listWindow` 只能限定返回行数，`arrayTail` 仍对整 JSON 做数据库函数处理，不能作为历史分块存储。
- 目标查询每次最多 100 个记录描述符、1 MiB 投影；单个描述符、正文块及元数据也需要字节预算。超大元数据必须拆块，不能只截断 content。预算须在查询和序列化之前执行。
- 迁移必须具有版本、进度和原子切换标记，在主窗口创建后通过既有维护 Worker 运行。并发新写入需要 journal/事务衔接；迁移验证须包含中断恢复、附件引用、费用、工具/问题关联与导出。
- 旧大 JSON 的解析峰值是单独验收项。当前没有实现受控流式解析；仅把 JSON.parse 搬入 Worker 不能判定有界。未验证极端对象路径前不能启用真实数据库迁移。
- Renderer 页缓存目标同时控制条数、文本字节、页数、会话数，并按窗口/应用合计审计。可见页本身超量必须拆分；卸载后通过稳定 ID/cursor 重读。具体聚合数值须在 P0 固定窗口并发与视口后确认，不能把单对话预算乘以无限会话当成全局预算。
- UI `beforeIndex` 和 MCP inspect 的整轮边界兼容性必须分别维护；当前本次修改没有改变任一接口。记录游标、新高水位与旧接口的迁移方案尚未实现。

## P3/P4 的目标契约（尚未实施部分）

- 必须同时限制缓存数据、挂载行及单行正文；巨大过程组不能作为单个包含无限子项的虚拟行。现有直接依赖没有适用于时间线的通用虚拟列表，本次没有新增依赖或使用传递依赖。
- 活动 Markdown/思考需要有界片段与未闭合语法状态；本次没有字符截断、卸载历史或缩短任务来代替这项工作。
- 保留现有 50 ms、128 条 / 64 KiB、每 Renderer/对话一个未 ACK 批次与 512 KiB 等待预算。仍须核验多项目/对话总量、语义事件旁路及已 ACK 未 React commit 的积压。
- resync 必须以持久化高水位衔接快照；当前 refresh-tail 的无限缺口 backfill、失效快照和失败 ACK 路径仍待修复，不能报告背压恢复协议已经完整通过。
- React measure 的归属识别以已安装 React 19.2.5 源码为依据。升级 React 后必须复查其 track 标签；不能把无法识别的新记录类型默认视为已有上限。
