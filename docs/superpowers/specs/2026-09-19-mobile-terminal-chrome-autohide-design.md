# 手机端终端 · 三条栏自动收放与横屏排布 · 产品设计文档

2026-09-19。产品负责人对着真机截图提的两件事：**三条栏闲置三秒自己收起来，点一下屏幕回来**；
**横屏别让元素尺寸过大、别占掉太多纵向空间**。

本文档只写这两件事，以及它们与既有几份设计文档的关系。输入栏内部的形态、语音的两种模式，
一律不动。

> **2026-09-20 修订（本文档已按此改写）**：装到手机上用过之后，产品负责人定了两件事 ——
> **自己收栏只保留横屏**；竖屏的栏一直在，要收就点右上角菜单里新加的**「全屏」**。
> 另一件：**打字和说话的时候工具栏让位**，那两段时间里它按不到、只是占着一行。
> §2.1、§2.9、§2.10、§5 是这次写的。

---

## 1. 要解决什么

终端是全屏的地方，而这条屏幕上常驻着三行：

```
┌────────────────────────────────┐
│ ‹        Synapse #2        ⋯  │  顶栏   60pt
│ ⌘  [回车][Ctrl+C][/exit] ⇧    │  工具栏 44pt
│ [🎙] [    按住 说话    ] [＋][➤] │  输入栏 56pt
├────────────────────────────────┤
│            终端                 │
```

竖屏约 160pt，横屏（iPhone 15，可用高度约 372pt）占掉 43%。看一屏输出、等一条命令跑完、
读一段日志的时候，这三行没有一个在被人用 —— 而它们一直在。

## 2. 决策

### 2.1 三条栏一起收，一起放

收起来就是**全屏终端**：画布铺满整屏，一行都不浪费。

一起而不是各自收：它们是同一件事的三段（这一页是什么、这台电脑能按什么、我要输什么），
只收起其中一两条会留下一个说不清用途的残余。**顶栏 / 工具栏 / 输入栏，一起。**

**但"一起收"说的是这一组被收起来的时候，不是说这三条永不分离**（2026-09-20）。工具栏
在另两种时候自己让位，输入栏留在原处 —— 见 §2.10。那不是"收栏"，是那一行在这两段时间里
本来就按不到。

### 2.2 判据是两条，不是一条

「闲置三秒」只是一半。另一半是「屏幕上没有一件正在被使用的东西」：

| 禁制 | 为什么 |
|---|---|
| 系统键盘起来了 / 输入框有焦点 | 正在打字，把输入框收走是荒唐的 |
| 自绘键盘面板（⌘）开着 | 它坐在输入栏底下，收栏等于把键盘一起收走 |
| 语音正忙：手指压着 / 正在录 / 已固定 | **产品负责人点名的第一条**。举着手说话时界面不能动 |
| 表单、确认弹窗、附件选择器盖着 | 它们挡着栏，当场看不出差别；代价在关掉之后 —— 人放下重命名面板，看到的是一块没有栏的屏幕 |
| 「最新的一张图」悬浮预览挂着 | 它也是一条栏，和三条栏存亡与共 |
| 正在收放的动画里 | 否则一次收栏会被自己的动画拖成两次 |
| 读屏 / 切换控制开着 | 逐元素浏览时两次触摸之间可以隔很久，而屏幕上的栏正在被一条条念出来。苹果对自动隐藏界面的要求 |
| **竖屏** | 这个方向上就不该自己收，与"此刻在干什么"无关。见 §2.9 |

前面那些条是「用户正拿着这个东西」，最后两条不是 —— 而正因如此它们必须写下来：漏掉读屏
那一条，症状只在读屏用户的机器上出现，而这条路径平时没人走；漏掉竖屏那一条，症状是
「竖屏的栏自己跑掉了」，而那是这一版要改掉的东西。

判定抽成纯值 `TerminalChromeConditions`（`Features/Terminal/TerminalChromeIdle.swift`），
单测逐条走。理由与 `VoiceGridHold` 逐字相同：留在视图里，这一条就只能靠人在真机上举着手
盯三秒。

### 2.3 点一下画布唤回

画布上那一下点击原本只管收键盘，现在**同时**叫回三条栏。两件事不会打架：键盘开着的时候栏
本来就收不了（`isTyping`），所以"栏收着而键盘开着"这个状态构造不出来。

唤回之后计时从头开始 —— 不是"再等三秒才显示"，是**显示，然后重新开始数**。

### 2.4 拖动画布也算操作

读一屏长输出，读一半停下看两行 —— 屏幕上看不出任何动静，而三秒的计时照样在走。

不把拖动算进去的代价不止是"栏跑掉了"：画布变高，**电脑那边的终端跟着重排**，正在读的那
一屏会当面跳一下。所以 `TerminalTextView` 多了一条 `onUserScroll`，接在
`scrollViewWillBeginDragging` 上。

### 2.5 收起后告诉电脑：终端改成更大

栏让出的那几行**是真的让给了终端**，手机把新的行列数报给电脑，电脑上那个终端跟着重排
（`reportGridToDesktop`）。这是产品负责人选的那一侧：要的是真·全屏，代价是每次收放电脑端
会重绘一次。

滑动途中（0.22 秒）不报，落位后补报一次且只报一次 —— 与键盘槽位（`setKeyboardPanel`）
同一条规则、同一个理由：**报的是自己量到的尺寸，而滑动途中的尺寸是用户从没选过的中间值。**

### 2.6 横屏：三条栏压成两行

竖屏结构一个字不改。横屏（`verticalSizeClass == .compact`，即 iPhone 横屏）时顶栏让出
自己那一行，把返回与 ⋯ 交给工具栏：

```
横屏
┌──────────────────────────────────────┐
│ ‹  ● Synapse #2 · 运行中  ⌘ […] ⇧  ⋯ │  48pt
│ [🎙] [      输入命令 …      ] [＋] [➤] │  56pt
├──────────────────────────────────────┤
│              终端（全屏）              │
└──────────────────────────────────────┘
```

为什么是并成一行而不是把零件改小：**44pt 是点击目标的底线**（`Metrics.minimumTapTarget`），
缩了就是按不准。横屏能减的只有行数。四颗固定键（‹ ⌘ ⇧ ⋯）永不压缩，中间那段指令横滑拿走
剩余的全部宽度。

横屏的标题丢掉版本文本（`· 1.0.6 (13)`）与状态第二行：版本是报问题时引用的号，不是抬头
要看的东西，而这一行还要装下指令条。

横屏纵向占用因此从约 160pt 降到约 104pt（可用高度 372pt 的 43% → 28%）。竖屏不变。

**iPad 不在此列**：竖屏与横屏的 iPad 都是 `.regular`，一个字都不改。沿用既有口径
（`2026-09-18-mobile-terminal-toolbar-design.md` §5.9「iPad 上不专门适配」）。

### 2.7 横屏：键盘面板限高，内部可滚

自绘键盘面板是 351pt 固定高，那是**竖屏**的高度。横屏可用高度约 372pt，加上两条栏约
455pt —— 顶栏会被挤出屏幕。

横屏时面板按可用高度的一个比例压下来（`KeyboardPanelMetrics.height(fitting:)`，约 55%），
板子在面板内部滚动。竖屏装得下，`.scrollBounceBehavior(.basedOnSize)` 让它不滚。

**没有改成浮层。** `2026-09-18-terminal-keyboard-slot-design.md` §3.1「键盘占位、不遮罩
终端」这条规则仍然成立 —— 浮层会盖住终端的最后几行，而那正是敲命令时最要看的地方。

### 2.8 横屏：画布底色铺满两侧安全区

画布所在的整个 `VStack` 在安全区里，横屏时左右各留一条（灵动岛那一侧）。栏的底色铺出去
了，画布的底色也要铺出去，否则终端两边镶着两条系统色的边。

**铺的是底色，不是文字。** 文字照旧留在安全区里：这是 HIG 的做法，而且灵动岛真的会盖住
最边上那两三列。

### 2.9 自己收栏只发生在横屏；竖屏收栏靠菜单里的「全屏」

**这一条推翻了上一节的前提。** 装到手机上用过之后产品负责人定的：竖屏那三条栏**一直在**，
不再自己走。

理由是两边的账不一样：

| | 两条栏占掉 | 自己走掉被读成 |
|---|---|---|
| 竖屏 | 约 160pt（顶栏 60 + 工具栏 44 + 输入栏 56） | 「界面不见了」 |
| 横屏 | 约 104pt，占可用高度的 28% | 「腾地方了」，而且点一下画布就回来 |

所以竖屏这一条**不是把三秒改长**，是那一班岗到点了也不收。要收就让人点名收：**右上角 ⋯
菜单里新加的一行「全屏」**。

**这条判定读在"到点那一下"，不读在"上表那一刻"，位置在 `TerminalChromeConditions.isPortrait`。**
两个理由，第二个是实测出来的：

1. 它和 §2.2 那六条一样是**判定**，判定都住在那个纯值里，由单测逐条走完。
2. **`@Environment` 在定时任务里读不出当下。** 这一条是量出来的，不是推的：那一班岗是在
   `armChromeIdle` 里起的 `Task`，它捕获的是"上表那一刻"的视图值 —— `@State` 读的是共享
   存储（活的），`@Environment` 却是**那份副本里的快照**。横屏那一班恰好在转屏前后上表，
   快照里还是竖屏，到点一读，结论就成了「竖屏不收栏」：**横屏永远不收栏**。

   所以方向值有一个 `@State` 镜像（`TerminalScreen.isCompactHeight`），在转屏那一个入口里
   更新，此后谁读它读到的都是当下。曾经把它直接写在"上表"的守卫上，症状是三次上表只起来
   一班岗，而那一班立刻被下一次取消。

- 两个方向都留着这一行 —— 横屏也能把栏收起来，所以它不按方向出现或消失。
- **不做成「退出全屏」**：菜单长在顶栏上，而全屏的顶栏是没有的，所以这一行永远只可能被
  读到一个方向。收起来之后要回来点一下画布，这条手势本来就在（§2.3）。
- **转屏不是收栏的一条路。** 从横屏转回竖屏时，如果栏是收着的，**放回来**：横屏那条路会
  把"收着"这个状态带过界，而竖屏那一条恰恰是「栏一直在」。

### 2.10 打字和说话的时候，工具栏让位

产品负责人 2026-09-20 在真机上点的：这两种状态下那条工具栏**按不到，只是占着一行**。
让位的是**工具栏一条**，输入栏留在原处 —— 它在那两个状态下就是那个控件本身（一个自己
就是输入框，一个自己写着「松手 发送」）。

- **正在打字**：手在系统键盘上，眼前是输入框。要按指令先收键盘，而收掉之后工具栏自己
  就回来了。这一条对既有操作路径是有代价的（原先可以一边打字一边点指令），产品负责人
  认下这个代价。
- **正在说话**：工具栏一走，录音面板就往下落到那一行上，而不是把终端压得更矮。
- **横屏不在此列**：那一条栏把顶栏并了进去（返回、标题、⋯ 都在里面），收掉它收掉的是
  出口，不是一行指令。所以这一条只管竖屏的自绘工具栏。
- 与 §2.1 的"一起收"不冲突：那说的是三条栏一起**被收起来**，不是这三条永不分离。

## 3. 与既有设计文档的关系

- **`2026-09-18-mobile-input-bar-design.md` §4.1「几何不变量」**（输入栏高度不变、四个位置
  不动、按键不搬）**依然成立**：它们管的是栏**显示着的时候**。本轮的自动收放是栏整体在
  与不在，不是栏内部在动。
- **`2026-09-18-mobile-terminal-toolbar-design.md` §4.1「工具栏几何」**在竖屏下不变；横屏
  那一行是它的另一种拼法，零件与尺寸都取自它。**补一条**（2026-09-20）：那条几何说的是
  它**显示着的时候**，而它现在多了一种不在的时候 —— 打字与说话时它整条让位（§2.10），
  让出来的那一行归录音面板和终端。横屏那一条不在此列。
- **`2026-09-18-terminal-keyboard-slot-design.md` §3.1「占位不遮罩」**不变（§2.7）。

## 4. 实施约束

1. **闲置时长可被启动参数覆盖。** `AppConfiguration.terminalChromeIdleSeconds`，默认 3 秒，
   `-SynapseChromeIdleSeconds` 可改。这不是给用户的开关：UI 测试里有大量 15–90 秒的等待，
   3 秒的默认值会让它们在碰按钮的时候按钮已经不在屏幕上了，而失败会读成「工具栏不见了」。
   那些用例把时长顶到一小时，**机制一字不改，变的只有时钟**；真实机制由
   `ChromeAutoHideUITests` 用一秒的时长覆盖。
2. **收放期间不报网格**（§2.5）。`reportGridToDesktop` 的 guard 多一条 `!chromeIsSettling`。
3. **补报那次网格的班次要存得住。** 连续收放不能留下两个睡着的 Task 各自补报一次。
4. **每一个动作都要重新上表**（`noteChromeActivity()`）。漏一处不是"栏收早了一点"，是
   **用户刚按下的那颗键带着它的结果一起消失**。
5. **收栏时 `keyboardPanel` 不进条件分支**，因为它不是被收放的那三条栏之一。有一个状态
   是两条规则的**交点**：面板开着的时候点菜单里的「全屏」（`isKeyboardPanelUp` 挡的是
   计时器，挡不住人点名）—— 那是终端整屏、下面一块键盘，两边都还在。

## 5. 验收基线

**只有横屏那几条会自己收**（§2.9）。竖屏的第 1、2 条改成了「等过去也不动 + 菜单收栏」。

1. **竖屏**：进终端什么都不做，等过横屏那一档的三秒 —— 顶栏、工具栏、输入栏**一条都不动**。
2. **竖屏**：右上角 ⋯ 里的「全屏」→ 三条栏一起收掉，终端铺满整屏；点一下画布全回来。
   从全屏回来之后再等一轮，栏照样不动。
3. **横屏**：进终端什么都不做，三秒后三条栏一起消失；点一下画布全回来，再等三秒再收一次。
4. 按住「按住 说话」不松 —— 举着超过三秒，三条栏一动不动，录音不断。
5. 录音固定之后（手指已离开）持续超过三秒，三条栏一动不动。
6. ⌘ 面板开着超过三秒，三条栏一动不动。
7. 拖着读历史超过三秒，三条栏不动。
8. **点开输入框：工具栏让位，输入栏还在**（§2.10）；收起键盘，工具栏回来。
9. **录着音的时候：工具栏让位，输入栏还在**（那一格写着「松手 发送」）；录音结束，工具栏回来。
10. 转横屏：顶栏并进工具栏，只剩两行；终端铺到两侧安全区，两侧不见系统色。
11. 横屏开 ⌘ 面板：面板限高、内部可滚，顶栏仍在屏幕上。
12. **横屏收着栏转回竖屏**：三条栏自己回来。
13. 竖屏结构与本轮之前逐像素一致（除上面这些让位）。

## 6. 非目标

- 不做「点一下屏幕收起」（只有唤回，没有收起的手势；竖屏要收走菜单里的「全屏」）。
- 不用户可配的闲置时长、不做逐条栏的独立开关。
- 不改输入栏、语音、键盘面板的形态与内容。
- 不做 iPad 专门适配（§2.6）。
- 不改桌面端：它只是收到一个新的网格尺寸。
