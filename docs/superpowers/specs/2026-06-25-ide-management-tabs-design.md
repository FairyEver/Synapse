# IDE 管理页面层级与目录合并设计

## 背景

当前 Synapse 有两个相邻但分散的入口：

- `IDE 管理` 系统应用展示各 IDE 中扫描到的 Skill 和 Rule。
- `设置 > 本机IDE` 展示各 IDE 的全局规则目录和全局技能目录，并提供创建、打开目录操作。

两者都围绕本机 AI IDE 能力管理，但分散在不同入口里。合并后，用户应在 `IDE 管理` 中完成“看内容”和“看目录”两件事；设置页不再保留 `本机IDE` 分类。

合并后还暴露了一个新的布局问题：`内容 / 目录` 是应用内页面跳转，视觉上却容易被读成右侧内容区的筛选条件；左侧 IDE 列表反而更像一级导航。这个层级倒置会让用户误解当前页面结构，尤其是在 `目录` 页中，Header、左侧和右侧顶部控件的职责不够清楚。

## 目标

- 在 `IDE 管理` 系统应用内保留 App 级顶部 tab：`内容`、`目录`。
- 明确顶部 Header 只表示应用内页面跳转，不承载筛选条件。
- 明确 `内容` 页左侧是页面控制面板，承载 IDE、类型和范围。
- 明确 `目录` 页左侧是目录对象选择，只承载 IDE。
- 明确右侧顶部只表示当前对象标题和页面内操作，不承载筛选条件。
- `内容` 页保留现有 Skill / Rule 扫描视图。
- `目录` 页承接原 `设置 > 本机IDE` 的目录状态与创建、打开操作。
- 删除设置页中的 `本机IDE` 分类入口，不保留跳转或重复列表。
- 保持现有 shadcn/Radix、Tailwind token 和系统 App 顶栏规则，不新增自定义颜色、样式体系或说明性文案。

## 非目标

- 不改变 IDE 扫描、目录解析、目录创建的主进程能力。
- 不新增 IDE 类型或修改各 IDE adapter 的路径规则。
- 不把目录配置做成弹窗、详情页或设置向导。
- 不在 `目录` 页展示所有 IDE 总览。右侧只展示当前左侧选中的 IDE。
- 不把 `Skill / Rule`、`全局 / 项目` 提升到 Header。它们是 `内容` 页内部筛选。
- 不把左侧改成 `内容 / 目录`。页面级导航必须继续使用系统 App Header。

## 推荐信息架构

```text
IDE 管理
├─ 内容
│  ├─ 左侧：IDE + 类型 + 范围
│  └─ 右侧：当前 IDE 的内容列表
│     └─ 批量操作：取消选择 / 复制到... / 移到废纸篓
└─ 目录
   ├─ 左侧：IDE
   └─ 右侧：当前 IDE 的全局规则目录、全局技能目录、创建/打开操作
```

设置页移除 `本机IDE`：

```text
设置
├─ 账号
├─ 基础设置
├─ 资源仓库
├─ 项目和知识库
├─ 提示词片段
├─ 模型与供应商
├─ 私人令牌
├─ 诊断日志
└─ 关于 Synapse
```

## 层级规则

`IDE 管理` 必须遵守三层结构：

```text
Header = 应用内页面
左侧 = 当前页面控制面板
右侧顶部 = 当前对象标题 + 页面内操作
右侧主体 = 当前对象的数据、状态和结果
```

对应到当前版本：

```text
Header
  内容 | 目录

左侧
  Cursor
  Codex
  CC/Synapse
  Windsurf
  Antigravity
  Hermes

内容页左侧控制
  Skill | Rule
  全局 | 项目

内容页右侧顶部
  Cursor
  批量操作

目录页左侧控制
  Cursor
  Codex
  CC/Synapse

目录页右侧顶部
  Cursor
```

这条规则的产品含义是：用户先在顶部选择页面，再在左侧设置页面控制条件，右侧只阅读结果并执行上下文操作。不要把筛选控件放进右侧结果区。

## 布局

`IDE 管理` 使用系统应用窗口壳层的居中顶部 tab。顶部 tab 是 App 级视图切换，不放在内容区里临时绘制。

```text
┌──────────────────────────────────────────────────┐
│ ← IDE 管理                    [内容] [目录]   ⟳   │
├──────────────┬───────────────────────────────────┤
│ Cursor   18  │ 当前 tab 内容                      │
│ Codex    36  │                                   │
│ Claude   25  │                                   │
│ Windsurf  3  │                                   │
│ Antigravity  │                                   │
│ Hermes   26  │                                   │
└──────────────┴───────────────────────────────────┘
```

`内容` 页左侧是控制面板：先选择 IDE，再选择内容类型和范围。右侧顶部只显示当前 IDE 和批量操作。

```text
┌──────────────┬───────────────────────────────────┐
│ Cursor   18  │ Cursor                            │
│ Codex    36  │                                   │
│ Claude   25  │ ┌───────────────────────────────┐ │
│ Antigravity  │ │ skill/rule item                │ │
│ Hermes   26  │ └───────────────────────────────┘ │
│              │                                   │
│ Skill Rule   │                                   │
│ 全局 项目     │                                   │
└──────────────┴───────────────────────────────────┘
```

推荐内容页结构：

```text
┌──────────────┬───────────────────────────────────┐
│ Cursor   18  │ Cursor                     批量操作 │
│ Codex    36  │ ───────────────────────────────── │
│ Claude   25  │                                   │

│ 范围          │                                   │
│ 全局 项目      │                                   │
└──────────────┴───────────────────────────────────┘
```

`目录` 页复用同一左侧 IDE 列表，但不显示内容类型和范围控制。右侧只展示当前选中 IDE：

```text
┌──────────────┬───────────────────────────────────┐

│ Hermes   26  │                                   │
└──────────────┴───────────────────────────────────┘
```

## 交互

- 顶部 `内容 / 目录` 切换当前应用视图。
- `内容 / 目录` 是页面级切换，切换时保留当前左侧 IDE 选择。
- 左侧 IDE 选择同时作用于 `内容` 和 `目录` 两个视图。
- `内容` 页保留现有 `Skill / Rule`、`全局 / 项目` tab、批量选择、复制、移到废纸篓、详情弹窗和刷新行为。
- `Skill / Rule` 与 `全局 / 项目` 只在 `内容` 页左侧控制面板出现。
- 批量操作只在 `内容` 页出现，且只在选中 Skill 后展示。
- `目录` 页每行展示目录类型、目录状态、路径和操作。
- 存在的目录提供 `打开`。
- 不存在但有路径的目录提供 `创建并打开`。
- 不支持的目录显示 `不支持`，不展示路径操作。
- 加载失败显示短错误和 `重试`。
- 顶栏刷新按钮刷新当前应用数据。刷新后保留当前 App tab 和当前选中 IDE。
- 右侧主体的列表项仍保持整块内容可点击，文件路径的打开操作阻止冒泡。

## 文案

界面只保留必要标签和状态：

- App 级 tab：`内容`、`目录`
- 内容筛选：`Skill`、`Rule`、`全局`、`项目`
- 目录类型：`全局规则`、`全局技能`
- 状态：`打开`、`创建并打开`、`不支持`、`未创建`、`加载失败`、`重试`

不写功能介绍段落，不解释“此页面用于管理 IDE 目录”，不在设置页留下迁移提示。

## 数据与边界

- `目录` 页应继续使用现有 `window.synapse.editor.getGlobalDirectories()`、`createDirectory()` 和 `shell.showItemInFolder()` 能力。
- 目录数据可以在 `IDE 管理` 内单独加载，也可以和扫描数据并行加载；实现时应避免把目录状态混进 Skill / Rule 扫描 item。
- 目录状态属于 IDE 全局配置，不属于内容扫描结果。类型上建议保留独立数据结构。
- 删除设置分类时，应同步删除设置分类配置、侧栏入口和相关面板引用。保留底层目录 hook 或逻辑时，需要移动到 `editor-scan` 模块或共享位置，避免 settings 模块继续拥有 IDE 管理 UI。
- 页面结构代码应把 Header page tab、sidebar controls、right content result 分成清晰状态，不要把内容筛选混进右侧结果区 toolbar。

## 状态

`目录` 页至少覆盖：

- loading：显示紧凑加载状态。
- error：显示错误文本和 `重试`。
- unsupported：目录类型不支持。
- missing：目录路径存在但文件夹未创建。
- ready：目录存在，可打开。
- no-data：桥不可用或没有目录结果时显示 `未检测到编辑器目录`。

## 测试

需要覆盖：

- `IDE 管理` 顶部渲染 `内容 / 目录` App 级 tab。
- 切换到 `目录` 后，左侧选择 Cursor 只显示 Cursor 目录。
- `目录` 页不渲染 `Skill / Rule`、`全局 / 项目` 内容筛选。
- `内容` 页左侧控制面板渲染 `Skill / Rule`、`全局 / 项目`，右侧结果区不渲染这些筛选。
- `内容` 页右侧顶部渲染当前 IDE 标题，并将批量操作限制在选中 Skill 时出现。
- 目录不存在时显示 `创建并打开`，点击后调用创建目录并刷新。
- 目录存在时显示 `打开`，点击后打开目录。
- 不支持规则目录的 IDE 显示 `不支持`。
- 设置页分类不再包含 `本机IDE`。
- `内容` 页原有 Skill / Rule、全局 / 项目筛选和批量操作不回退。

## 实施顺序建议

1. 在 `EditorScanModule` 中保留 App 级 `内容 / 目录` tab，把它视为唯一页面级导航。
2. 将 `内容` 页的 `Skill / Rule` 与 `全局 / 项目` 移入左侧控制面板。
3. 将 `内容` 页和 `目录` 页的右侧顶部简化为当前 IDE 标题和上下文操作。
4. 将目录读取与操作逻辑保留在 `editor-scan` 模块或共享 hook，避免 settings 模块继续拥有 IDE 管理 UI。
5. 删除 settings 中的 `本机IDE` 分类和面板引用。
6. 补测试并确认设置页、IDE 管理页行为。
