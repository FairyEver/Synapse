## 1. 要解决什么

手机端终端屏，工具栏在输入框上方横着一条：最左一颗 ⌨，右边是一串指令胶囊（回车、Ctrl+C、/exit、/clear …）。四件事：

1. **左侧那颗 ⌨ 会被滑走。** 整条 bar 是一个横向 `ScrollView`，指令一多，最左那颗键跟着一起滚出屏幕，想开键盘面板得先把 bar 滑回起点。
2. **指令一多就没有全局视野。** 十几条指令只能一条条横扫着找；而手机用户往往记不住自己在电脑上加过哪些。
3. **电脑上「快捷输入」里配的那些句子，手机上够不着。** 那些句子恰恰是手机上最想用的——手机上打字最贵，一句话在电脑上敲一次，在手机上就该一次点出来。
4. **上下两颗同形的键会被当成一件事。** 输入栏左端已经是键盘图标（另一轮），工具栏最左再来一颗 ⌨，相邻两行同一个图形，用户分不清按哪个。

第 4 条不是需求，是登记：它决定了第 1 条里那颗键**换图标**，而不是原地保留。

## 2. 现状与它的来历

### 2.1 工具栏是什么

`SynapseMobile/SynapseMobile/Features/Terminal/TerminalScreen.swift` 的 `accessoryBar`：

```swift
ScrollView(.horizontal, showsIndicators: false) {
    HStack(spacing: 8) {
        Button { toggleKeyboardPanel() } label: { Image(systemName: "keyboard") }   // ← 这颗
        divider
        ForEach(buttons) { … }                                                       // ← 电脑的按钮
    }
    .padding(.horizontal, 12)
}
```

按钮来自电脑：`mobile.toolbar` 消息推下来，`TerminalToolbarState` 按 `desktopClientInstanceId` 归属，没收到过的电脑退回一份内置兜底（回车 / Ctrl+C / /exit / /clear）。

### 2.2 那条 bar 为什么整体横滑

因为 ⌨ 和指令当初被放进了同一个 `HStack`。那时按钮只有四条，谁也没想到它会横向溢出。现在溢出是常态——用户自己加的指令没有上限。

### 2.3 ⌨ 按钮和键盘面板

⌨ 打开的是**按键面板**：一个键位格，装着系统键盘打不出来的键（esc、⇧tab、tab、⌫、回车、方向键、home/end/pgup/pgdn、del、Ctrl 组合）。它是"输入"的东西，不是"指令"。

面板的**形态**归另一份文档管（`2026-09-18-terminal-keyboard-slot-design.md`：从浮层改成占版面的一个槽位）。本轮**不动它的形态和内容**，只换它入口那颗键的图标和位置。

### 2.4 「快捷输入」在电脑上是什么

桌面端有一个 App 叫「快捷输入」：一张表，两列——内容、操作。用户自己往里加句子，就是一段纯文本，没有标题、没有分类、没有变量。

- 存储：DataRepository 命名空间 `app.quick-input.items`，一条长这样：`{ id, schemaVersion, content, sortOrder, createdAt, updatedAt }`（`desktop/electron/runtime/data-repo/schemas/quick-input.ts`）。
- 校验：`content: z.string().min(1)` —— **只有下限，没有上限**（`app-capabilities/quick-input/shared/schema.ts`）。这一条决定了 §5.3。
- 服务：`core.quick-input`，注册在 `desktop/electron/bootstrap/descriptors.ts:594`，`criticality: "degraded"`，有 `list()` 和一个 `changed` 事件。

### 2.5 手机与电脑之间现有的那条通道

`mobile.toolbar` 是现成的一条同类消息，形态可以直接照抄：

| 环节 | 位置 |
|---|---|
| 消息名与 envelope 联合 | `shared/src/live.ts`（`LIVE_MESSAGE_TYPES`、`LiveMobileServerMessage`、两处 `isLiveEnvelope` 校验） |
| Payload 类型与校验、字节预算 | `shared/src/mobile-live.ts` |
| 桌面端组装并发出 | `mobile-gateway-service.ts` 的 `flushToolbar()`（指纹去重）→ `live-connection-service.ts` 的 `sendMobileToolbar()` |
| 服务端转发 | `live-desktop.gateway.ts:606` 按 type 逐条 dispatch → `mobile-live-relay.service.ts` 的 `handleToolbar()`（fanout，**不缓存**） |
| 手机端接收 | `RealtimeClient.swift` 的 `onToolbar` → `SynapseAppModel.toolbar`（`TerminalToolbarState`） |
| 协议在手机端的镜像 | `LiveProtocol.swift`，文件头就写着 "Mirror of `shared/src/live.ts` and `shared/src/mobile-live.ts`" |

服务端**不是透明转发**：它按消息类型逐条分支，漏一条就静默丢掉。这是 §6.2。

## 3. 决策

### 3.1 左侧那颗键的图标：⌨ 换成 ⌘（`command`）

键盘图标留给输入栏左端。⌘ 和键盘的轮廓差别最大，最不像一个键帽，且 iOS 上「⌘ = 快捷键」的认知最稳。

被否掉的：`escape`（还是键帽，两行相邻仍然像同一件事）、`control`（同）、`keyboard.badge.ellipsis`（还是键盘）。

**它仍然开同一个面板**：换的只是脸，`toggleKeyboardPanel()` 的行为一个字不改。无障碍标签保持「打开键盘」。

### 3.2 结构：左固定 · 中横滑 · 右固定

```
[⌘] │ [ 回车 ][ Ctrl+C ] │ [ /exit ][ /clear ] [ 构建 ] [ 部署 ] …   │ [⇧]
 ↑左固定              ↑ 中间横滑，指令再多也只滑这里                ↑右固定
```

两侧不进 `ScrollView`，与中间共用同一行高度。分组分隔线（1px 竖线）仍跟着指令一起滚，因为它是**指令列表自己的**结构。

### 3.3 右侧新键：上箭头，开指令面板

图标 `chevron.up`。面板开着时这颗键保持按下态（`surface3` 底），关掉恢复。

### 3.4 面板分两段：快捷命令 / 快捷输入

顶部一个 iOS 分段选择器。两段的高度、面板高度都不变，切段只换内容。

**能不能分段由这台电脑决定**：电脑发过 `mobile.quickPhrases`（哪怕是空列表）→ 两段；从没发过（旧版本）→ **分段器整条不出现**，面板就是今天的单段样子。

这条规则照抄 `TerminalToolbarState` 的哲学：一个从没发过的电脑和一台"用户还没配"的电脑是两个不同的答案，把它们混成一个会让人对着空列表以为自己的配置丢了。区分依据同样是 `desktopClientInstanceId`。

### 3.5 快捷命令段：保持浮动排法，分组之间加一根横线

胶囊白底（面板是灰底，`systemBackground` 上的胶囊才立得起来），从左到右、排满换行。**分组之间一根通栏横线**，意思等于横滑区那根竖线：跨过它，指令就换了一类。

首页的横滑是"一条线"，这里是"一片"——同一份数据，两种看法：找不到就用横滑（贴近手指、不离开终端），不记得有什么就打开面板一眼扫完。

点了**立即发送**（与今天的工具栏完全一致），面板收起。

被否掉的：把命令段也做成列表（指令标签短，浮动更省地方，而且用户要的是"一眼看全"，不是"逐行读"）；分组用小标题（多出一层文案，且横滑区没有标题，两边会不一致）。

### 3.6 快捷输入段：Apple 的列表，一行，点了只填不发送

insetGrouped：灰底、白卡片、圆角 10、行高 44、分隔线左缩 16、正文 17pt。**每行只占一行，放不下的省略**（`lineLimit(1)` + 尾部省略）——短语是句子，让它折行会把卡片撑成一堵墙，也让"一眼扫十几条"这件事失败。

点一行 → 短语进输入框，**不发送、不唤系统键盘**。这是它和命令按钮最大的区别：命令是动作，短语是文字。文字要落在一个用户接下来还要继续编辑的地方，所以光标在末尾，键盘由用户自己决定什么时候起来。

**行不禁用**：终端不在跑时命令胶囊照旧变灰（它点了就发，发不出去就不该能点），但短语行照旧可点——它做的事和用户手动往输入框里打字是同一件，而输入框在终端结束后仍然是可编辑的。

### 3.7 预览：行右一颗眼睛，只读，文字可选可复制

每行右侧一颗 `eye`。它解决的问题是 3.6 那半截省略号：**看不见的那部分要能看全**。

- 点它 → 一个完整预览浮层，显示这条短语的全文。
- 图标不能有第二个意思：`eye` 是「看一眼」，排除了纸飞机、上箭头（发送）、`chevron.right`（还有下一页）。
- 预览里的文字是**普通可选文本**（`.textSelection(.enabled)`）：长按能勾选、能复制。
- 预览里**没有**「填入输入框」按钮。它是只读的，看完点外面关掉。（这一条是产品负责人明确否掉的。）
- 浮层浮在面板**之上**，关掉预览回到面板，面板保持打开、原段原位。

### 3.8 打开面板默认停在上次那段

用户上次停在「快捷输入」，下次打开还是「快捷输入」。跨 App 重启也记得。

**不因为那段是空的就自动跳回「快捷命令」**：悄悄替用户改掉他上次的选择，比让他看见一次空状态更糟——空状态里写着原因，跳回去则什么都不说。

### 3.9 数据走一条新的推送消息

新增 `mobile.quickPhrases`，与 `mobile.toolbar` 同构：桌面端推、服务端 fanout 不缓存、手机端按 `desktopClientInstanceId` 归属。

**不新增权限、不新增 MCP 工具、不进能力注册表**：这是用户自己的电脑发给他自己的手机，走的是既有的那条连接；`app.quick-input.items` 本来就是这台电脑上这个账号自己的数据。

### 3.10 长按预览不做（本轮）

相册那种「按住抬起、继续按住展开成大弹窗」的交互被明确排除在本轮之外，理由三条：

1. **入口重复**：行右已经有一颗看得见的预览键，长按是同一个动作的第二条路。
2. **和行自己的点击手势打架**：点行 = 填入。长按与点击落在同一个目标上，误触的代价是一条短语悄悄进了输入框。
3. **成本不成比例**：SwiftUI 里抬起 + 背景虚化是 `.contextMenu` 白送的，但「继续按住长大成大弹窗」不是系统行为，要自己接长按手势、定时器，还要处理"抬起过的那一下不能算点击"。

留作后续可选项，见 §9。

## 4. 交互规格

### 4.1 工具栏几何

- 高度与今天一致：竖向 padding 8 + 胶囊高约 35（`terminalKeyPill()` 的既有尺寸），整条约 51。
- 左固定块：`[⌘ 胶囊] [1px 竖线]`，左边距 12，两块之间 8。
- 中间横滑区：左右各 8 内边距，胶囊间距 8，分组之间 1px × 16pt 竖线。
- 右固定块：`[1px 竖线] [⇧ 胶囊]`，右边距 12。
- 三块同高，`alignment: .center`。
- 横滑区给一个最小宽度（约一条最宽胶囊 + 24），窗口更窄时优先压缩它，两侧两颗键永不压缩、永不隐藏。

### 4.2 面板几何与拖动

- `.sheet` + `.presentationDetents([.medium, .large])` + `.presentationDragIndicator(.visible)`。
- 默认半屏；往上拖到全屏；往下拖过一半松手即关。
- 面板**没有标题**。
- 面板底是分组列表灰（`systemGroupedBackground`）；命令段的胶囊是白底，短语段的卡片是白底。

### 4.3 分段器

- `.pickerStyle(.segmented)`，`[快捷命令 | 快捷输入]`，横向 padding 16，高 32。
- 电脑没发过 `mobile.quickPhrases` 时整条不出现（§3.4）。
- 切换不改变面板高度，不移位。

### 4.4 快捷命令段

- 白底胶囊，`terminalKeyPill()` 同款；从左到右、排满换行。
- 分组之间通栏 1px 横线，前后各留出与胶囊间距同量的空隙。
- 点胶囊：`runToolbarButton` → 发送 → 面板收起 → 输入框聚焦（今天的既有行为，不改）。
- 终端不在跑：胶囊变灰不可点（既有）。

### 4.5 快捷输入段

- 白卡片，圆角 10，行与行之间内缩 16 的 1px 分隔线。
- 行高 44，左右 padding 16，正文 17pt，`lineLimit(1)`、尾部省略。
- 行右预览键：30×30 的点击区，图标 19pt，颜色 `secondaryLabel`；点它不触发整行的填入。
- 点行：面板收起 → 短语进输入框 → 光标在末尾 → 不发送 → 不唤键盘。
- 空态：卡片位置一行说明文案「电脑上还没有快捷输入」，灰字 13pt。

### 4.6 预览浮层

- **系统 sheet，第二层**：全宽、顶部圆角、系统拖条、下拉关闭，默认半屏、可拖到全屏。
- 内容：短语全文，正文 17pt，可滚动，**可选择可复制**（`.textSelection(.enabled)`）。
- 关闭只看两处：下拉、或点背后变暗的那一层。
- 不唤键盘；**面板保持原样**（原段、原位置、仍然开着）。
- 原型里那张"左右留白 12 的浮动卡片"是近似画法，**不照抄**：那是手搓的壳子，系统 sheet 免费给拖条、下拉关闭、深色适配。同 §6.6 的理由。

### 4.7 文案表

| 场景 | 文案 |
|---|---|
| 分段器左段 | 快捷命令 |
| 分段器右段 | 快捷输入 |
| 短语列表空态 | 电脑上还没有快捷输入 |
| ⌘ 键的无障碍标签 | 打开键盘（沿用，不改） |
| ⇧ 键的无障碍标签 | 全部指令 |

除了空态那一句，本轮不新增任何用户可见的文案。没有标题、没有说明句、没有引导。

## 5. 边界与异常

### 5.1 电脑上一条短语都没配（收到过空列表）

分段器在，第二段是空态文案。这是**正确**的答案：用户确实还没配。

### 5.2 电脑从没发过这条消息（旧版本 / 新配对）

分段器不出现，面板只有命令段——也就是今天的形态。判据是 `ownerDesktopClientInstanceId == 选中的电脑`，与 `TerminalToolbarState.buttons(forSelected:)` 同一条规则。

### 5.3 短语超长

电脑端 `content` 没有长度上限，而手机上一行只显示一行字。协议层给单条一个上限（**4096 字符，与工具栏文本同值**）：

- 超出的**整条不发**，不是在中间截断。理由与工具栏的字节预算同源：一条被截短的短语，插进输入框以后和用户在电脑上写的那句不是同一句了，而用户按下发送时以为它是。
- 桌面端为此记一条 `warn`，不静默。

### 5.4 短语很多

整包按字节预算（**64 KiB，与 `maxToolbarBytes` 同值**）丢尾：装不下的后面的条目不发，不截断任何一条。实测五十条短语约 3 KB，这条是为"不可能"准备的。

### 5.5 电脑离线 / 切到另一台电脑

列表**跟着连接走**，服务端不缓存（与工具栏同一条理由）。切到另一台电脑：显示那台电脑的短语；没收到过就是 §5.2 的样子。断线期间保留最后一次收到的（与工具栏一致）。

### 5.6 退出登录

跟随 `toolbar.reset()` 一起清空——那些是另一个账号的电脑上的句子。

### 5.7 终端不在跑

命令胶囊照旧变灰；短语行照旧可点（§3.6）；预览键照旧可点。

### 5.8 面板开着时终端在输出

面板是浮层，终端在后面继续跑，被盖住的正是最新那几行。这是浮层的固有代价，**已确认接受**——它和键盘面板不是一回事：键盘面板要"一边看一边按"，指令面板是"挑一条就走"。两者的形态不同，是有意的。

### 5.9 旋转与窄屏

两侧固定块永不压缩（§4.1）。分段器和卡片随宽度自适应。iPad 上不专门适配（沿用现状）。

### 5.10 上次停在「快捷输入」，这次这台电脑没发过短语

分段器不出现（§5.2）→ 直接显示命令段。不显示空态，因为"这台电脑还不支持"和"你还没配"是两件事（§3.4）。

## 6. 实施约束

### 6.1 协议在三个地方各有一份，必须同一次改完

`shared/src/live.ts`、`shared/src/mobile-live.ts`、`SynapseMobile/SynapseMobile/Core/Protocol/LiveProtocol.swift`。漏掉手机端那一份的表现是**静默不显示**：没有报错，没有日志，只是那一段永远空着。

### 6.2 服务端必须加一条转发分支

`mobile.*` 不是透明转发：`live-desktop.gateway.ts` 按 type 逐条 `if`，漏了这条，桌面端的消息会被丢掉，手机永远收不到，而桌面端那边看起来是发成功了的。

### 6.3 不新增权限、不新增 MCP 工具、不需要改能力注册表

这条消息不是用户可操作能力，是终端回传的一条数据，与 `mobile.toolbar` 同级。`docs/agents/capability-registry.md` 不用动；`app.quick-input.*` 的既有 capability 和 MCP 表面一个都不改。

### 6.4 短语只落手机本地，不走 intent

点一行只写手机输入框的 draft。这是"不唤键盘"能成立的原因，也是它和命令按钮的分界线。**不要**为了对称给短语也发一条 intent。

### 6.5 服务端不缓存

一份属于一台已经不在的电脑的短语列表，比没有列表更糟——它看起来像那台电脑还在。

### 6.6 列表的观感来自系统语义，不来自手写的数字

行高 44、正文 17pt、分隔线内缩 16、卡片圆角 10：这些是 iOS 分组列表的既有值，用系统默认能拿到的就用系统默认，不要手写一串魔数去"还原"它。

## 7. 与相邻两轮改动的关系

## 8. 验收基线

逐条去验，不要只跑测试就收工。

1. 工具栏最左是一颗 ⌘，不是 ⌨。
2. ⌘ 打开/关闭的还是原来那个按键面板，内容、分类、行为一个字没变。
3. 指令再多（造 14 条），⌘ 和 ⇧ 两颗键始终在屏幕上，位置不动。
4. 中间横滑区从头滑到尾，两侧两颗键不动。
5. 指令分组之间是竖线，位置与桌面端一致（第一条斜杠命令之前）。
6. 点 ⇧ 打开面板：默认半屏、顶部有系统拖条、可拖到全屏、拖过一半松手关掉。
7. 分段器两段；切换两段，面板高度和位置都不动。
8. 快捷命令段：白底胶囊、从左到右、排满换行；分组之间一根通栏横线，横线之后是下一组的第一颗。
9. 点命令胶囊 → 立即发送、面板收起（与改造前逐条一致）。
10. 快捷输入段：白底卡片、行高 44、行间分隔线左缩 16。
11. 每行只占一行，放不下的行尾省略（造一条长短语验）。
12. 点一行 → 短语进输入框、光标在末尾、面板收起。
13. 第 12 条**不发送**（终端里没有多出那一行），也**不弹出系统键盘**。
14. 行右一颗眼睛；点它不会触发第 12 条。
15. 预览浮层浮在面板之上；关掉预览，面板仍然开着、还在原来那段。
16. 预览里的文字能长按勾选、能复制。
17. 预览里没有「填入」按钮；点卡片外、下拉拖条都能关掉。
18. 关掉面板再打开，还停在上次那段；杀掉 App 重开也一样。
19. 电脑上一条短语都没配 → 分段器在，第二段是空态文案。
20. 电脑从没发过这条消息（旧版本）→ 分段器不出现，面板只有命令段。
21. 换到另一台电脑 → 显示那台电脑的短语；没收到过就回到第 20 条的样子。
22. 终端不在跑：命令胶囊变灰不可点，短语行和预览键照旧可点。
23. 一条超过 4096 字符的短语不出现，其余短语照常显示，且不出现被截断的句子。
24. 在电脑上改一条短语，手机上能看到更新。
25. 退出登录再登录，短语列表不残留上一个账号的。
26. 浅色与深色模式下，卡片、分隔线、灰底都取系统色（切到深色看一遍）。

## 9. 非目标

- **长按预览**（相册式抬起、继续按住展开成大弹窗）。理由见 §3.10，留作后续可选项。
- 在手机上新增 / 编辑 / 删除短语或指令——编辑属于电脑。
- 短语的搜索、分组、排序、拖拽、置顶。
- 把短语做成自动化动作、MCP 工具或系统快捷指令。
- 面板里显示短语的元数据（创建时间、修改时间、来源）。
- 服务端缓存这份列表。
- 「电脑上改了短语，手机立刻看到」以外的实时性要求（§6.5 的兜底时机已够）。
- 桌面端 UI 改动：桌面端只多发一条消息，界面一个字不改。
- iPad 专门适配。
- 改输入栏、改语音、改键盘面板的形态与内容。
