# UX 体验打磨审查

## 背景

Synapse 即将进入团队内部小范围使用阶段。需要在发布前对全应用做一次体验打磨，确保核心流程顺畅、错误处理完善、交互反馈到位。

## 目标

按用户旅程从首次启动到日常使用，系统性走查所有功能模块，发现并修复体验问题。

## 非目标

- 不重构架构
- 不添加新功能
- 不改变视觉设计
- 不做性能优化

## 审查维度

| 维度 | 检查内容 |
|------|----------|
| 操作反馈 | 按钮点击后是否有 loading/disabled 状态，异步操作是否有进度指示 |
| 错误处理 | try/catch 是否给用户可理解的提示，是否有恢复路径（重试按钮等） |
| 空状态 | 列表为空时的展示，是否有引导性文案或操作入口 |
| 边界情况 | 网络断开、文件不存在、并发操作、输入为空等场景 |
| 文案 | 是否清晰一致，不含技术术语，不含废话 |

## 审查阶段

### 阶段 1：首次启动流程

覆盖模块：仓库初始化（repo onboarding）、编辑器扫描（editor-scan）、身份设置（identity）

重点：新用户第一次打开应用的完整路径，任何卡住都会导致用户流失。

### 阶段 2：内容管理

覆盖模块：Rules、Skills、Prompts 的浏览、创建、编辑

重点：日常高频操作，交互流畅度和操作反馈。

### 阶段 3：安装与同步

覆盖模块：安装到编辑器、仓库同步、内容发布

重点：跨系统操作（文件系统 + Git），失败场景多，错误提示要清晰。

### 阶段 4：辅助功能

覆盖模块：设置、数据库（data-store）、定时任务（scheduler）、Agent

重点：非核心但团队会用到的功能，确保基本可用。

### 阶段 5：全局体验

覆盖范围：导航、ErrorBoundary、键盘交互、响应式布局

重点：贯穿全应用的基础体验。

## 执行方式

- 每阶段先读代码找问题，小问题直接修复
- 大问题（涉及架构变更或行为变化）先与用户确认
- 每阶段修完简要汇报改动内容
