# 邮箱 App 与站内信领域拆分设计

日期：2026-10-23。状态：用户已确认完整设计并要求进入实施计划；产品范围、存储方案和交互草图已确认。本文是规划，不表示功能已经实现。

独立 Builder Check 已完成，结论为没有阻碍制定实施计划的重要缺口。

## 1. 目的与已确认决策

让使用阿里企业邮箱的 Synapse 用户在桌面端完成日常收发信，也让用户的 Agent 通过 MCP 和 Synapse Skill 操作同一套邮箱能力。邮箱是通用客户端，阿里邮箱是首个预设和首个正式验收对象。

用户已确认：

- 新 App 显示名「邮箱」，App ID / 深链域名 `mail`；原「站内信」改为 `mail-internal`，不保留旧兼容入口。
- 两个领域分别使用 `synapse://mail/<id>`、`synapse://mail-internal/<id>`。
- 首期只做桌面邮箱，不新增手机端邮箱功能。
- 账号只配置在当前电脑，可以添加多个账号；左上切换账号。
- SY 仍在运行时，关闭邮箱窗口后继续收信并提醒新邮件。
- 写信支持常用文字样式、图片、粘贴与附件。
- 采用「本地元数据索引，正文和附件按需读取并缓存」。
- 已确认交互草图：文件夹、列表、详情三栏；右上写邮件；独立写信窗口（2026-10-23 体验调整确认）。

下文中的同步频率、缓存预算、草稿冲突策略和库选型由设计提出，随完整设计确认成为首期默认行为，非用户逐项指定。

## 2. 范围与边界

### 首期交付

1. 阿里邮箱快捷配置；可填写 IMAP / SMTP 参数的通用配置入口。通用入口只承诺标准协议能力，不宣称其他服务商已通过兼容性验收。
2. 多账号、连接检查、修改配置、暂停同步、移除本机账号。
3. 收件箱、已发送、草稿、垃圾邮件、回收站及服务端自定义文件夹；分页、搜索、未读筛选、星标、已读状态、移动、回收站恢复及明确选择的永久删除。
4. 读信、查看 To/Cc、正文图片、附件下载、复制邮件 ID 和正文。
5. 新邮件、回复、回复全部、转发；To/Cc/Bcc、富文本、内嵌图片、附件、手动保存草稿。
6. 后台同步、断线恢复、本机新邮件提醒。
7. 同等业务能力的 MCP 和 Skill；输入、结果、错误以及搜索完整性可供 Agent 判断。
8. 站内信领域改名，保留现有信件、附件、往来、权限和业务行为。

### Non-Goals

- 不新增手机端邮箱、Web 邮箱、云端代收、配置漫游、跨设备同步本地缓存或本机草稿。
- 不支持 POP3、Exchange 专有接口、OAuth 登录向导、通讯录/日历同步、邮件规则、定时发送、群发营销、已发送撤回、邮件端到端加密。
- 不承诺完整离线镜像、服务端未开放历史的检索、SMTP 接受后的最终送达或已读回执。
- 不把站内信改造成 SMTP 邮件；站内信的团队成员、组织投递和平台公告规则保持独立。
- 不增加专用 Workflow 节点或 Automation Action。首期自动化入口是 MCP；持续收信由本机服务负责。
- 不保留旧站内信 App / MCP / 深链别名，不把失效旧链接猜测为新邮件。

## 3. Approaches

| 方案 | 收益 | 代价 / 限制 | 决策 |
| --- | --- | --- | --- |
| 本地元数据索引，正文/附件按需缓存 | 列表与筛选快；避免首次下载全部附件；能绕开阿里部分搜索异常 | 未缓存正文的搜索要继续下载，必须报告覆盖范围 | 用户选定方案 1 |
| 全量离线镜像 | 离线全文检索与历史阅读完整 | 首次同步时间、磁盘、删除一致性成本更高，服务端仍可能限制可见历史 | 不采用 |
| 每次直接查询服务端、不建索引 | 本地持久化少 | 网络延迟直接影响操作；无法可靠绕开已测到的搜索和统计差异 | 不采用 |

选择方案 1 的主要依据是前两轮阿里邮箱真实测试，而非假设标准 IMAP 的所有语义都成立。

## 4. 已有证据与兼容性要求

测试归档原标识为 `synapse://mail/cmvkgnn990frfmq2p33m4v9rc`（改名实施前属于站内信）。本文只保留结论，不保存账号密码、真实收件人或邮件正文。

| 已观察到的行为 | 对实现的要求 |
| --- | --- |
| IMAP TLS 993、SMTP TLS 465 可用；能列文件夹、取摘要、解析正文与附件、发送、转发和回复 | 正式实现要以可重复的适配器测试和真实账号验收复核 |
| IDLE 收到新邮件事件；断线后可重新选择信箱并按 UID 获取增量 | IDLE 作为变化提示，持久同步游标与补偿查询保证恢复 |
| `STATUS` 数量与选择信箱后的可见数量有差异 | 界面区分已索引数量、服务端报告数量与同步状态，不把任一数字假称为完整历史 |
| FROM / SUBJECT / BODY 搜索被拒绝，某 HEADER 查询成功但漏掉已知命中 | 阿里预设默认使用本地文本索引；日期和标记条件可用服务端收窄，但文本命中不能依赖异常接口 |
| 样本中可见最早日期约为一年前 | 是否存在邮箱服务端可见期限制仍待核实，不能写成已确认的一年规则 |
| `UID COPY` 在测试账号上表现为移动，原信消失；未声明 MOVE | 阿里适配器不得使用普通 COPY + DELETE 通用假设；首期不向用户提供跨文件夹复制 |
| Seen / Flagged 可以增删；Answered 删除返回成功但状态仍保留 | 已读/星标写后校验；回复标记按观察结果处理，不对外承诺能撤销 Answered |
| 草稿 APPEND、临时邮件 UID 删除与清理通过 | 草稿替换与永久删除仅针对精确 UID，禁止裸 EXPUNGE 波及其他邮件 |
| SMTP 提交后阿里自动保存已发送 | 阿里不得额外 APPEND 产生重复 Sent；通用账号需明确 Sent 保存策略 |
| QQ 转发 SMTP 接受且 Sent 可查；未检查 QQ 最终收件箱；发给自身的回复已在收件箱读取 | 分开报告 SMTP 接受、Sent 副本核验和实际收件，不把前两项当最终送达 |

这些是特定测试账号的证据，不是所有阿里部署或新库默认行为的保证。适配器需显式保存 provider 策略；不确定时返回不可用或待核验，不能用破坏性探测猜测能力。

## 5. 身份与站内信迁移

| 表面 | 站内信 | 外部邮箱 |
| --- | --- | --- |
| App ID / 目录领域 | `mail-internal` | `mail` |
| capability namespace | `mail_internal` | `mail` |
| capability 示例 | `app.mail_internal.message.get` | `app.mail.message.get` |
| MCP 示例 | `app_mail_internal_message_get` | `app_mail_message_get` |
| 深链 | `synapse://mail-internal/<id>` | `synapse://mail/<id>` |
| Skill 章节 | `mail-internal/` | `mail/` |
| 数据归属 | 现有账号服务端存储 | 本机，按 SY 身份隔离 |

沿用项目 App ID 短横线、capability namespace 下划线约定。原站内信的 17 个 MCP 工具整体改名，不保留原名转发。新邮箱工具即使使用同名后缀也采用全新的严格 schema，必须拒绝旧站内信格式。

迁移要求：

- 原 `desktop/src/modules/mail/` 和能力包里的站内信代码迁入对应 `mail-internal` 领域，新 `mail` 实现独立。禁止对仓库中的字符串 `mail` 进行无差别全量替换。
- Dock、启动器、窗口恢复、已保存的 App 偏好使用一次性幂等迁移将原 `mail` 归入 `mail-internal`；保留顺序、固定状态和窗口语义，不把用户原站内信窗口误开为外部邮箱。2026-10-23 后续 Dock 需求覆盖此前「新邮箱不默认固定」的决定：两款邮件应用默认固定在末尾，顺序为站内信 `mail-internal` → 邮箱 `mail` →「应用」`launcher`。改名后再执行独立迁移 `dock.mail-apps-introduction.v1`，旧配置即使曾取消固定也只重新加入一次，其余应用相对顺序保留；用户随后可移除和排序，不再自动恢复。
- 新增 Dock 迁移 ID，不改已发布的 `dock.mail-introduction.v1`。迁移失败保留原配置，不标记完成。
- 站内信客户端/服务端公开领域入口随之改为 `mail-internal`，包括 `/api/mail-internal/...`、管理端对应站内信 API、通知 source 和最新通知目标生成逻辑；实际路径清单由实施计划搜索核对。旧 `/api/mail/...` 不保留别名，旧客户端需要升级。
- 现有数据库物理表、邮件 ID、附件存储 key 不为命名整齐而重建；按需迁移通知 source / outbox 等可执行领域字段，保留去重标识、已读及删除状态。不要重发历史通知、清理历史信件或改写信件正文中的旧链接。
- 手机不新增外部邮箱；只同步其已有站内信 API / source / 深链引用改名。网页、管理后台、共享通知常量、发布脚本和站内信 API 调用者同步调整。
- 新旧入口的切换是一次协调升级：开发完成后备份并预演必要的数据迁移，再更新服务端与各端。本文不授权部署或发版。无兼容入口意味着旧客户端的站内信能力在切换后失效，必须在发布说明明确。

外部邮件生成本机不透明 ID（建议 `em_` 加随机标识），记录到账号、邮箱文件夹、UIDVALIDITY、UID 的映射。Message-ID 只是辅助证据，不是唯一主键。移动后有服务端映射或可证明的唯一匹配时更新 locator，保持本机 ID；证据不足时保留失效目标，不能打开“看起来相似”的邮件。UIDVALIDITY 变化使旧 locator 失效，重新索引后也不得仅靠同 UID 复用。

两类链接只接受一个合法路径 ID，不接受 query、fragment 或编码分隔符。链接不携带邮箱地址、凭据或授权。外部链接只在配置及索引所在电脑、对应 SY 身份下有效；其他电脑显示不可用，不远程找回账号。链接定位本身只读；用户打开阅读区后，按 UI 阅读规则标记已读。MCP `get` 不隐式设已读。

## 6. 界面与账号接入

交互草图于本对话中获得认可。实现复用现有 System App 壳、ResizablePanel、shadcn 组件和主题 token，不将临时 HTML 草图复制进产品。

- 左栏顶部切换邮箱，下面是系统文件夹、自定义文件夹、同步状态和设置。首期逐账号查看，不增加统一收件箱。
- 中栏支持列表分页、搜索、全部/未读、选中与批量操作；选中邮件右侧阅读。切换账号取消旧请求、清空选择，防止迟到响应串号。
- 详情展示发件人、To/Cc、时间、主题、正文和附件，提供回复、回复全部、转发、已读、星标、移动、删除，以及复制邮件 ID 和正文。阅读工具栏左侧直接显示「回复」「转发」「复制ID」，右侧显示「更多」；更多菜单包含「回复全部」「复制正文」，菜单与右侧按钮对齐。复制ID使用本机邮件 ID，复制正文使用已完整读取的纯文本，加载中、读取失败或正文截断时禁用正文复制。
- 新建、回复、回复全部、转发使用独立原生写信窗口；阅读窗口与写信窗口各自保留状态。同一意图或已保存草稿复用窗口，不覆盖未保存编辑。2026-10-24 按用户要求调整响应式门槛：依据应用内容区宽度，达到 53rem 时保留信箱、列表与阅读三栏，低于该宽度在列表与详情间切换；达到 33rem 时保留信箱侧栏，更窄时用账号和文件夹选择器。本设计不表示手机适配。
- 列表顶部采用固定高度工具栏：默认只显示勾选、搜索和必要状态图标；搜索时原位替换输入框，默认包含正文；选中后显示不换行的数字及单一操作菜单，“移动至”为二级菜单。索引及不完整搜索通过提示气泡/状态弹层说明并保留继续检索入口。
- 列表整行应用悬停/激活背景；阅读区回复工具栏固定在顶部，其下元信息、附件和正文自然平铺并一起滚动，不再将元信息与正文分区滚动。正文高度随内容变化，链接在原文位置通过受控能力打开，不在头部重复列出。邮箱类型使用无装饰图标的整行单选框，高级设置靠右。
- 新账号向导先选「阿里邮箱」或「其他邮箱」。阿里默认 `imap.qiye.aliyun.com:993`、`smtp.qiye.aliyun.com:465`，TLS 校验证书；普通页面填写邮箱地址、密码/客户端授权码、可选显示名。服务器详情可展开修改。
- 通用配置允许 IMAP / SMTP 主机、端口、TLS 或强制 STARTTLS，以及明确的 Sent 保存策略；不允许明文认证、跳过证书校验或自动降级。账号用户名默认邮箱地址，可在高级设置覆盖。
- 连接测试分别返回收信/发信认证结果，不发送测试邮件。首次失败保留非敏感输入并给出可执行错误提示，不能把“SMTP 可认证”说成“已能投递”。
- 移除账号只删除本机连接、缓存及本机草稿，不删除服务端邮件；有未发送草稿或不确定发送结果时必须先展示影响。服务端草稿仍留在服务端。

## 7. 本机服务、存储与安全

### 服务边界

`desktop/app-capabilities/mail/shared/` 定义契约，`main/` 集中账号、同步、邮件操作、草稿、发送和附件服务；`desktop/src/modules/mail/` 承载 Renderer 模块。UI 和 MCP 共用核心服务。主进程通过 ServiceRegistry 注入；IPC 使用 IpcRegistry，变化通知使用 EventBus。Renderer 只能访问窄类型 preload bridge。

外部邮箱不增加服务端邮箱存储或业务代理。当前 SY 登录身份是本机数据分区键；暂时离线但身份仍有效可读本机缓存。退出/切换身份停止旧连接和任务、撤销内存资源、屏蔽旧数据；不自动删除持久数据，切回原身份可恢复。MCP 也必须校验当前身份，不接受调用者伪造 owner。

### 持久化

使用 DataRepository 注册 `app.mail.accounts`、`app.mail.credentials`、`app.mail.folders`、`app.mail.messages`、`app.mail.drafts`、`app.mail.operations`、`app.mail.sync-state`、`app.mail.assets` 等命名空间；每条记录包含 schemaVersion 和归属，列表查询必须有条件、上限和稳定 cursor。名称为建议，最终 schema 由实施计划核对。

- 账号配置、文件夹、locator、摘要、同步进度和操作回执是结构化元数据。
- 密码/授权码用已有 `encrypted-json` / OS safeStorage 后端，密钥不可用时阻断保存与连接，不回退明文。密码写入仅经本机受控配置流程；MCP 可打开配置界面、管理非敏感字段、检查状态，不能读取或接收密码。
- 正文、原始 MIME、图片、附件与草稿大内容作为本地文件资产，数据库只放元数据、摘要和引用，不把字节塞入 SQLite。资产属于外部邮箱，不复用 Agent 的业务归属、不上传 Drive / 平台图片存储。
- 实施时通过 DataRepository 的受控资产存储扩展封装文件写入；若当前没有可复用通用设施，新增最小文件资产适配层，元数据仍由 DataRepository 管理。业务 service 不直接裸写文件。该扩展必须遵守 PermissionGuard / AuditSink、路径约束、临时文件原子替换及失败清理规则。
- 本地受管路径只使用生成 ID，不能信任邮件文件名或 MIME 路径。下载到用户选定目录走文件写入权限，拒绝路径穿越、符号链接绕过与隐式覆盖。
- 拟定可清理缓存预算 1 GiB，LRU 只清理可重新获取的正文/附件；草稿、待发快照、发送未知回执及其资产不能被当缓存淘汰。空间不足返回明确失败并保留已保存草稿。设置提供清理缓存，不清理凭据或待发内容。
- 配置、凭据、邮件缓存和草稿不进入 SY 云同步、共享包、自动上传的诊断或跨设备备份。正文缓存不宣称额外磁盘加密；凭据的 OS 加密和邮件缓存的本机隔离是不同保障。

### 内容隔离

邮件和附件都是不可信输入。HTML 采用白名单清洗，并在无脚本、无表单和顶层导航能力的隔离阅读容器中显示；CSP 限制所有主动资源。2026-10-23 用户批准 sandbox 仅开启 `allow-same-origin`，供父页面读取正文高度和接管链接点击；不得开启 `allow-scripts`。邮件样式、脚本、事件与自带 data 属性仍剥离，链接由清洗器替换为本地片段及应用生成的索引，父页面按受控 URL 表打开。正文样式不得影响 SY UI。纯文本有安全回退。

远程图片默认不加载，用户对当前邮件显式允许后经受控网络流程获取；不能绕过检查访问本机、私网或重定向到受限地址。CID 图片只解析为当前邮件资产。附件不自动执行，外链走现有受控打开能力。

网络、秘密读取、附件读取/导出均有权限与审计。日志不包含密码、正文、收件地址列表、原始 MIME 或认证响应。MCP 返回的邮件内容标记为外部数据，Skill 明确其中指令不构成操作授权。

## 8. 同步、索引、搜索与通知

### 同步

每个账号独立同步状态，收件箱 IDLE 常驻；操作连接由账号级队列协调邮箱锁，避免后台 IDLE 与移动/删除竞争。服务不阻塞主窗口启动。

首次连通先取文件夹和最新一页摘要（建议 50 条），建立收件箱 UID 基线，再后台按可见历史分批索引元数据。建议每批 100 条、全局最多两个账号同时补历史；正文和附件不随历史索引全部下载。界面及时可用并展示索引状态。

2026-10-24 同步状态修正：工具栏读取真实运行时任务，只有 running 显示旋转；暂停、失败、认证失效、取消与状态读取失败显示静态状态。同步完成后收起整个状态入口及索引数量，不保留占位；再次同步或出现异常时重新显示。索引数量与服务器报告总数按账号展示，总数未知时只显示已索引数量。失败保留已完成批次进度，实际重试开始才恢复运行态；指定文件夹仅改变同步优先级，不能将单个文件夹完成误报为整个账号完成。搜索 coverage 与同步任务状态分别表达。

IDLE 事件触发有界增量同步，不直接依据事件次数增加未读数。无 IDLE 时默认 60 秒轮询；其他文件夹默认 5 分钟校对，打开文件夹或手动刷新可立即同步。瞬断采用带抖动退避，认证失败停止重试并提示重连。超时、休眠、唤醒、网络切换均取消旧请求并复验身份与 UIDVALIDITY。

新增 UID 追踪不能替代删除/标记同步；周期校对服务器 UID 集合和标记，分批检查变更。只在完整成功的校对范围内认定邮件删除，不能把查询失败或不完整结果当不存在。UIDVALIDITY 变化重建该文件夹 locator；旧详情给出失效状态。

### 搜索

默认按当前账号查本地已索引的主题、发件/收件地址、摘要，支持文件夹、时间、未读、星标条件。全文搜索优先查已缓存正文；用户明确要求更广范围时启动可取消、有批次与字节预算的按需正文扫描，不能无界下载整箱附件。

返回 `coverage`：查询范围、元数据同步是否完成、正文已扫描数、待扫描数是否已知、服务端可见范围是否确定、截断/失败原因及继续扫描 cursor。UI 简明显示“已索引邮件”或“正文扫描中”等实际范围；MCP 不得把未完成搜索的零结果当作没有邮件。普通分页 cursor 与扫描任务 cursor 分开。

### 提醒

提醒只通过本机原生通知适配器，不调用会写账号消息中心并推送其他设备的 `system-notifier.notification.trigger`。复用底层本机通知基础设施和权限处理，点击回到相应邮件；原公开 System Notifier 语义不变。

每账号开关，默认开启。先保存新邮件和去重状态再请求显示；基线前的历史不提醒，基线建立后新到邮件正常提醒。按账号/文件夹/UIDVALIDITY/UID 去重；重连补到的真实新邮件可以汇总，不逐封洪泛。通知是尽力显示；崩溃恢复优先不重复通知，不承诺 exactly-once 显示。操作系统禁用通知仍正常收信，设置页显示状态。

SY 进程退出或电脑休眠时无法继续收信；恢复后补同步。关闭邮箱面板不停止同步，不增加系统常驻守护进程或改变 SY 既有退出行为。

## 9. 邮件操作与发信状态

### 文件夹与整理

特殊文件夹优先从服务器能力/属性解析，不能仅靠中文名称猜测；缺少 Drafts / Sent / Trash 时明确让用户选择映射，不静默覆盖或创建系统文件夹。支持创建、重命名、删除普通自定义文件夹；只允许删除空文件夹，禁止删除系统文件夹。

2026-10-24 文件夹管理入口：新建保留在邮箱设置的「普通文件夹」，侧栏不增加新建按钮；普通文件夹支持右键重命名和删除。重命名弹窗预填原名称，删除需确认且由主进程重新校验没有邮件和子文件夹；失败保留弹窗并显示原因。右键不改变当前邮件视图，删除当前文件夹成功后返回全部邮件；系统文件夹与全部邮件、星标邮件等虚拟视图不提供管理菜单。账号或身份切换后关闭旧操作弹窗，迟到结果不更新新视图。

单封和最多 100 个显式 ID 的批量已读、星标、移动、删除共享同一核心服务，返回每项成功/失败/未知结果；首期不增加无边界“一键清空全箱”。删除默认移到 Trash，只有在 Trash 内永久删除才执行精确 UID 删除；不支持安全 UID EXPUNGE 的服务端拒绝永久删除，不降级为全箱 EXPUNGE。

阿里移动按已验证兼容策略实施并检查源/目标；不再追加第二次删除。通用账号优先 UID MOVE，无能力则仅在安全目标映射和精确删除机制成立时执行 COPY + UID 删除。超时后先查询结果，不能盲目重放移动。安全移动不可用时明确报错，不自动改成永久删除。

### 富文本与草稿

正文支持段落、常用字号、粗体、斜体、下划线、有序/无序列表、链接、图片和撤销重做；不做页面排版或复杂 Office 格式保真。粘贴保留安全基础格式，移除脚本、危险链接和活动内容；本地粘贴图片转为附件资产及 CID，发送 multipart HTML + plain text。

2026-10-24 按用户反馈调整写信表单：收件人、按需展开的抄送和主题使用已有 InputGroup，将 label 与输入内容保持同一行；抄送入口放在收件人行末。格式工具栏使用组件标准紧凑尺寸及组间分隔，不通过大外边距或扩张命中层拉开图标。地址错误绑定到对应字段，提供 invalid 状态与描述关联，修改其他字段不消除该错误；修改对应地址后清除。其他操作错误放在输入区附近，链接弹窗中的错误不同时重复到正文。

暗色与小窗口验收补充：账号连接和设置更新在 Renderer 复用原共享 schema 校验，给出对应字段的中文提示，不将内部校验 JSON 直接显示给用户；主进程的严格校验保留。设置操作错误固定显示在弹窗底部，避免藏在长表单末尾，修正相关输入后清除；普通文件夹名称使用可见且关联输入框的标签。链接错误单独属于链接弹窗，修改、取消或切换写信会话时清除，不带回写信页面或下一封草稿。

写信取消自动保存及切换应用/关闭时的隐式保存。新信与回复准备只在内存构造编辑内容，首次显式“保存草稿”或发送时才创建持久草稿；发送前仍保存并冻结必要快照。已保存草稿继续使用 revision/CAS 和服务端 Drafts 同步，本地保存与远端同步结果分别显示。关闭窗口时，只有内容相对打开或最近保存时确有变化，且仍有收件人、抄送、非空主题、正文、附件或内嵌图片，才提供保存并关闭、放弃修改、取消；编辑器初始化、空白格式、清空全部内容或撤销还原均不触发提示。保存失败保留窗口，放弃已有草稿的修改不改动原保存版本；空白新信直接关闭不留草稿。加载过程中允许关闭，迟到结果不得恢复内容或创建草稿；准备失败允许重试。离线可起草但不自动排队发送。

正在编辑的附件通过窗口生命周期内存租约免于缓存清理；关闭或身份变化释放租约，未保存导入沿既有过期资产维护回收，不生成草稿。首次保存不会改变编辑会话标识或丢掉进行中的附件/图片导入；保存后的草稿 ID 登记到原窗口以便复用。

草稿带 revision；UI 和 MCP 更新使用前置版本，不静默覆盖对方。打开已有远端草稿保留源 UID/版本。远端有变化时保留本地副本并要求选择版本。APPEND 新草稿确认后才删除被替换的旧 UID；APPEND 结果未知先核验，不盲目再追加。未取得 UIDPLUS 证据且无法唯一识别新副本时保留旧草稿与待核验状态。丢弃草稿只删除其明确关联副本。

### 回复与转发

回复优先 Reply-To，否则 From；回复全部合并 To/Cc 并排除当前账号配置的自身地址，原 Bcc 不向收件人披露；新增 Bcc 只能由用户/Agent 明确提供。引用源信正文，设置 In-Reply-To / References；附件默认只在转发时带入，用户可移除。转发支持普通正文引用及原信 EML 附件方式。

### 发信

同一发送管线供 UI 和 MCP 使用：草稿修订 → 固定内容预览 → 持久发送操作 → SMTP 提交 → 回执 → Sent 对账。

- 预览冻结 account、From、To/Cc/Bcc、主题、HTML/纯文本、引用、附件 hash/大小、Message-ID 和 draft revision。阿里 From 默认登录邮箱，其他发件身份必须显式配置并验证，不允许 Agent 任意伪造。
- MCP 使用稳定 `clientRequestId` 和预览 ID。相同请求同内容返回已有结果，不同内容拒绝。预览建议 10 分钟过期，内容或附件变化需重新生成。
- 持久状态至少区分 `prepared`、`submitting`、`accepted`、`partial`、`failed`、`unknown`；必须先保存 `submitting` 再触网。
- SMTP 最终接受仅表示服务器接受，不表示对方收件箱送达。部分收件人拒绝时返回 accepted / rejected 分组，不自动整封重试；用户可对拒绝部分另建发送。
- 提交后连接断开、进程重启停留在 submitting 或收到不确定回执，都进入 unknown。用固定 Message-ID、Sent 与已知服务器回执有限对账；没有查到不等于未发，不能自动重发。
- 阿里 Sent 由服务端自动保存。通用配置明确 `server`（自动）或 `client`（客户端保存）策略；client 策略只在 SMTP 已接受后追加一次，追加失败只重试保存，不重发 SMTP。
- accepted / partial 后不把原草稿当可再次发送的普通草稿；保留只读快照和结果，明确重发才创建新操作。failed / unknown 保留全部内容。发送状态与附件资产不能随普通缓存清理丢失。
- 发信授权沿用项目规则：用户已经授权且收件人、内容、附件明确时，Agent 检查预览后直接发送；只有歧义、超范围、必要用户审阅或用户要求先看才再询问。调用者声明不冒充服务端验证过的用户确认。

## 10. MCP 与 Synapse Skill

沿用 Synapse 的 `search` / `invoke` 工具发现与执行入口，新增业务定义不增加旁路 HTTP 邮箱 API。下表给出覆盖范围，实施计划再将动作固化为逐个 schema 和注册数量。

| 能力组 | 必须覆盖的动作 | 关键约束 |
| --- | --- | --- |
| 账号 | list/get、打开配置、非敏感设置更新、连接检查、暂停/恢复、移除 | 不输入/输出凭据；结果携带可用能力及诊断 |
| 文件夹 | list/create/rename/delete、系统文件夹映射 | 服务端实际对象 ID；系统文件夹保护 |
| 同步 | 请求同步、状态/进度、取消历史扫描 | 返回任务 ID，不能长期阻塞一次调用 |
| 邮件 | list/get/count、搜索/继续搜索、正文获取 | 接受 ID 或完整 reference；分页与 coverage；读取不设已读 |
| 整理 | read/star、move、trash/restore、permanent-delete | 账号归属、精确 ID、批量上限、逐项结果 |
| 草稿 | create/get/list/update/delete，按源信准备回复/全部回复/转发 | revision 冲突、附件与引用快照 |
| 附件 | 导入本机文件、列出、下载、读取有界文本元数据、原信 EML 导出 | 受控路径/资产 ID，校验实际大小；不隐式上传云盘 |
| 发送 | preview、send、operation.get/list | 幂等键、授权声明、部分失败与 unknown |

附件“读取有界文本元数据”只表示文件名、类型、大小、CID、hash 等元数据，不解析附件正文；需要解析文件时由已有文件工具承接。

所有修改有 PermissionGuard / AuditSink；非敏感账号设置不等于 secret 权限，读信不等于发信授权。移除账号、永久删除使用对应高风险分类。返回稳定错误码，至少区分未配置、未登录、认证失败、网络不可用、权限拒绝、目标失效、版本冲突、能力不支持、扫描不完整、发送未知。

Skill 在权威目录 `desktop/app-capabilities/synapse-skill/skill-package/` 新建邮箱章节、迁移站内信章节并更新总索引。覆盖：领域辨别、首次接入、账号选择、分页/搜索覆盖范围、读信不改状态、回复/转发、附件路径、草稿到预览/发送、幂等重试、未知结果对账、批量整理、安全边界和阿里兼容性。示例只使用虚构账号。

## 11. 实现建议与可由实施者决定的细节

建议引入专用开源库处理协议和编辑，避免把前期 TLS 实验脚本或草图的 execCommand 编辑器变成生产实现：

- IMAP：[ImapFlow](https://imapflow.com/docs/)，仍需自有阿里适配策略，不能未经测试依赖默认移动行为。
- SMTP 与 MIME 组装：[Nodemailer](https://nodemailer.com/)；读取解析：[MailParser](https://nodemailer.com/extras/mailparser)，优先流式处理大附件。
- 富文本：[Tiptap](https://tiptap.dev/docs/editor/getting-started/overview) 的 React 与必要开源扩展；不引入协作、云端或付费服务。
- HTML 清洗：[DOMPurify](https://github.com/cure53/DOMPurify)，与隔离容器、资源策略一起使用，清洗库不能替代沙箱。

以上是新增依赖提案，本文确认前不安装；确认后实施计划需核对许可证、确切版本、Node/Electron 构建兼容性、依赖体积及打包路径。既有可复用安全实现优先；具体扩展包、文件拆分、批处理调优与测试 fixture 组织由实施者决定，不需要再询问布局偏好。

首期实现需要受控文件资产基础设施、索引、同步状态机和两类 App 命名迁移，属于完整功能项目，不是替换一个页面。库选型通过不等于账号兼容性通过。
