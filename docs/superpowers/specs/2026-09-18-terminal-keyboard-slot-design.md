## 1. 要解决什么

手机端终端屏底部有工具栏和输入框。工具栏最左边那颗 ⌨ 点开，是一个**键盘面板**：顶上一排分类，下面是该分类的键位格。

三件事要改：

1. **面板是浮在整个界面上方的一张 sheet。** 它把工具栏和输入框一起盖住——用户既看不见自己在按哪一排按钮，也看不见终端最下面那几行。而面板的用途恰恰是"一边看终端一边按"，被盖住的正好是要看的那部分。
2. **面板高度按分类给**（常用/方向/功能 一档、全键盘 一档）。切分类时面板上下边缘会动，工具栏和输入框也跟着再被顶一次。
3. **终端内容不满一屏时贴着顶、底部留白。** 键盘（无论系统的还是面板）弹起来，可视区变矮，底部那几行就被挤出可视区；用户得自己往上滑才能找回来。

第 3 条要单独说明一句：它**不是**键盘没把内容顶上去——工具栏和输入框一直是被顶上去的，终端可视区也确实变矮了。滑出去的是**终端内容自己**：内容比可视区短的时候它贴着顶，所以矮下去的那部分是从底部切掉的。

## 2. 现状与它的来历

### 2.1 面板为什么是 sheet

上一轮把「控制」那一栏改成全键盘时，面板被设计成"从屏幕下方升起的键盘面板"，用了 `.sheet` + `.presentationDetents([.height(静止高度), .large])`，并带一个下拉把手、可以往上拖到全屏。

`.sheet` 在 iOS 上就是**浮层**：它不参与底下那层视图的布局，底下那层也不知道自己被盖住了。这正是第 1 条的来源。

### 2.2 系统键盘那条其实是对的，不要再改

产品负责人最初报告"键盘把终端内容盖住了"，复查后确认**真机上的表现符合预期**，而且代码里是**故意**这么写的。证据在 `SynapseMobile/SynapseMobile/Features/Terminal/TerminalTextView.swift:318`：

```swift
// The keyboard appearing shrinks this view. Nothing new was appended, so
// no snapshot runs — without this the newest output would slide below the
// fold and the user would have to scroll to find it.
if bounds.height != lastLayoutHeight {
    lastLayoutHeight = bounds.height
    if isPinnedToBottom { scrollToBottom() }
}
```

注释里那句 "the newest output would slide below the fold and the user would have to scroll to find it"，就是用户当初描述的症状本身。**这条逻辑保留原样。**

它只在 `isPinnedToBottom` 为真时生效，判定来自 `scrollViewDidScroll` 的 `distanceFromBottom < 40`——也就是说，用户翻到历史里看旧内容时**故意不**把他拽回底部（同一处的注释：`if they scrolled up to read something, leave them where they are`）。这一条同样保留。

### 2.3 那几行空白是谁的

第 3 条里"底部留白"，从代码上看有两种可能：

- **手机自己的剩余空间**：电脑那个终端只有 N 行，手机的格子能放更多行，多出来的是渲染层的空白；
- **TUI 自己画的行**：电脑的终端有 M 行，Claude Code 在它那 M 行里只用了上面一部分，下面几行是它画出来的空白。

两种情况的改法不同。但**不需要先做一次专门的测量**：§3.3 的做法（给滚动视图加一个顶部 inset）在两种情况下都安全——

- 是第一种，inset 把内容推到底边，问题解决；
- 是第二种，内容与可视区本来就相等，`max(0, 可视区高 − 内容高)` 恰好是 0，等于什么都没做，屏幕上一切照旧。

所以它是"要么修好、要么无害"。实现时顺手打一行日志看一眼它到底有没有生效即可（见实施计划阶段 0），**不单列为一步**。若实测发现是第二种且产品上仍要求贴底，那是一个**新问题**——需要裁掉 TUI 自己的行，会改变"手机上看到的行数与电脑一致"这条既有契约，必须回来重新决策，不在本次范围内。

## 3. 决策

### 3.1 面板改为"坐在键盘槽位里"

面板不再是 sheet，而是**屏幕自己布局里的一行**，位置就是系统键盘的位置：工具栏和输入框在它上方、原样保留、不被覆盖，终端可视区相应地变矮。

一句话概括产品语义：**它现在是一个键盘，不是一个抽屉。**

- 没有悬浮阴影、没有下拉把手、没有圆角容器；
- 面板和系统键盘**互斥**（这一条已经是现状）：点 ⌨ 时输入框失焦、系统键盘收起；
- 面板内的按键、分类、锁存交互**一个字都不改**（上一轮刚做完）。

### 3.2 固定高度，四页一样，不可拖拽

面板高度**两页相同**，取够放键盘那一档。**当前值 351** —— 起始值曾是 370，四页并两页、键改成正方形之后收到 351（见 `2026-09-18-terminal-keyboard-two-pages-design.md` §2.5）。

- 去掉 `.large` detent 与 `.presentationDragIndicator`；
- 切分类时面板上下边缘不动，工具栏和输入框也不会再被顶第二次。

**代价写在明处**：常用/方向/功能三页下面会空出一块。换来的是"切页时手底下的东西完全不动"。

这与面板最早的写法一致——四个分类共用同一个键位格高度，当时的注释写的就是"免得切页时面板在手指底下挪动"。上一轮的"按分类给高度"是本次要取消的。

### 3.3 内容不满一屏时贴底

终端内容比可视区短的时候，**内容的底边贴着工具栏那一侧**，不再在下方留白。

- 做法：滚动视图的 `contentInset.top = max(0, 可视区高度 − 内容高度)`。内容满了之后这个值自然变 0，退回正常的终端滚动，不影响翻历史。
- 对**系统键盘和面板一视同仁**——这是关于"内容怎么摆"的规则，不是关于"谁把可视区压矮了"的规则。
- 附带效果：这条做完之后，键盘弹起时内容**不需要再"跟着上移"**，因为它本来就在底边上。§2.2 那段逻辑继续保留（内容超过一屏时仍然要靠它）。

**代价**（产品上接受）：

1. 只要没满屏，每来一行新输出，整块内容就往上顶一格。现在（贴顶）是新输出往下长、屏幕上部稳住。
2. 它与"手机只是把电脑整屏缩放着看、逐格一致"有张力：去掉尾部空行之后，提示符在手机上的位置与电脑上不一样了。产品负责人认可这个取舍——在手机上，要看的东西永远紧挨着键盘更重要。

### 3.4 互斥与收起规则

面板是键盘，所以它遵循键盘的语汇：

| 操作 | 结果 |
|---|---|
| 点 ⌨ | 面板升起；（若系统键盘开着）系统键盘收起 |
| 再点一次 ⌨ | 面板收起 |
| 点输入框 | 面板收起、系统键盘升起 |
| 点终端画布 | 面板收起（与系统键盘"点别处收起"一致） |

第一条是现状；后三条是这次新明确的——面板不再盖住输入框和画布之后，"点它们"才第一次成为可能。

## 4. 非目标

以下都是**有意不做**，不要顺手加：

- **系统键盘的任何行为、样式、输入法**。§2.2 已经说明它是故意的，不要"顺手修一下"。
- **面板里的按键内容、分类、锁存交互**。上一轮刚定稿实现，本次一个字不动。
- **工具栏那排按钮**。
- **面板的拖拽、全屏 detent、下拉把手**。§3.2 明确取消。
- **裁掉 TUI 自己画的空行**。见 §2.3：那会改变"手机上看到的行数与电脑一致"这条契约，是另一个问题。
- **桌面端与云端**。本次是纯客户端 UI，不涉及协议、不涉及 `MOBILE_KEYS`、不需要按服务端 → 桌面端 → 手机端的顺序发版。

## 5. 验收基线

逐条走，每一条都要能说出"怎么验的"。

1. 点 ⌨ → 面板从底部升起，**占据系统键盘的位置**：工具栏和输入框仍在它上方、可见、没有被覆盖。
2. 面板弹起时终端可视区变矮，内容不滑出可视区（底部那几行仍看得见）。
3. 面板高度**四页相同**：在 常用 / 方向 / 功能 / 全键盘 之间切换，面板上下边缘不动，工具栏和输入框也不动。
4. **面板不可拖拽**：没有下拉把手；在面板上向下滑不会把它收起、也不会改变高度。
5. 再点一次 ⌨ → 面板收起，终端恢复原高度。
6. 面板弹起时**点终端画布** → 面板收起。
7. 面板弹起时**点输入框** → 面板收起、系统键盘升起；两者**不同时出现**。
8. 系统键盘弹起时，工具栏和输入框在其上方、可见（现状，回归项）。
9. **内容不满一屏时，内容的底边贴着工具栏**，下方不再留白；此时弹起任一种键盘，内容都不动。
10. **内容超过一屏时行为不变**：在底部则跟随新输出；翻到历史里则不被打扰（§2.2 的两条都保留）。
11. 面板里的按键与上一轮完全一致（回归）：`⇧tab`、锁 `Ctrl` 按 `a` 发出 `Ctrl+A`、`I`→`Tab`、`M`→`Enter`、`Alt`+`b` 一次 intent 两个动作、双击锁定与解锁。
12. 收起面板后终端重新变高，且仍停在底部（不跳回顶部）。

## 6. 开放项

这几条本次**不定**，留给实施时按实际情况判断，但要在回报里说明怎么定的：

1. **面板固定高度取多少。** 起始值 370（够放全键盘的四行 + 读数条 + 提示行），后收到 351（六行 + 常用键那一行）。以真机上"能放下且不挤压上方终端"为准。
2. **点终端画布收起面板这条要不要留。** §3.4 定了要，理由是键盘的语汇；但如果真机上发现"一边看一边按"时误触太多，可以撤掉，只留 ⌨ 切换。
3. **面板弹起时是否要让输入框失焦。** 现状是点 ⌨ 时先 `inputFocused = false`，保留。
