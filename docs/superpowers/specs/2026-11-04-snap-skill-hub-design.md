# Snap Skill Hub 首版设计

日期：2026-11-04

状态：设计待用户审阅；方案 A 已选择，尚未授权进入实现。

范围：网页登录后的 Skill 商店、服务端 API、本地 MCP、现有 Skill 安装器的 Hub 来源。

## 1. 目标与确认记录

Snap Skill Hub 只存储和分发 Agent Skill。用户可以让 Codex 等本地 AI 把已制作的 Skill 发布到本人账号，随后由其他有权限的用户在网页发现并安装到本机编辑器。

已由用户确认：

- 产品全称为 **Snap Skill Hub**，简称 **Skill Hub**。保留用户给出的名称；不据此更改 Synapse 客户端名称或协议。
- 云端不编辑 Skill 正文、脚本、附件或目录；内容更新必须重新上传整个 Skill。
- 展示图标、显示名称和介绍允许在网页修改，也能通过 API 修改。
- 上传接受单 Markdown 文件或 ZIP；本地 MCP 另外接受目录，由客户端处理为上传包。
- 可见范围为私有、公开、选择团队，默认公开；所有访问必须登录。
- 公开表示所有正常登录的用户可访问；所选团队的成员均可访问。只有上传者能修改、发布新版和删除。
- 成功更新包时自动记录版本。首版由使用者主动重新安装，不做自动更新或后台版本订阅。
- AI 操作依赖本地客户端运行并登录。用户选择方案 A：客户端负责检查、整理和打包，通过本地 MCP 调用云端 API。

下文中的接口名称、数量限制及未单独讨论的行为是**本设计的建议**，随本文一起待审；不得描述为用户已经逐项确认。本文批准后再编写实施计划。

## 2. 方案选择

| 方案 | 分工 | 取舍 | 选择 |
| --- | --- | --- | --- |
| A | AI 创作和修正文件；客户端检查、准备包并上传；服务端校验、存储和鉴权 | 本地处理工作更多，但各 AI 共用规则、可复用预检查结果 | 用户已选择 |
| B | AI 自行检查并压缩；客户端接收成品并上传 | 客户端较薄，但易漏附件、错误嵌套目录或带入本机文件 | 不采用 |

网页和本地客户端共用云端业务 API。MCP 是本地能力适配层，不复制服务端业务规则，也不把云端凭据交给 AI。首版不增加独立远程 MCP 或 API Key 接入。

## 3. 首版范围

提供登录后的商店列表、搜索、详情、我的上传、上传和上传新版本、编辑展示资料与可见范围、删除、包下载和安装到本机。详情提供只读 `SKILL.md`、文件清单及版本历史，帮助使用者了解将安装的内容；没有在线代码编辑器。

不包含评分、评论、收藏、付费、推荐算法、榜单、审核发布流程、团队共同编辑、所有权转让、Fork、依赖安装、脚本运行、自动更新、桌面商店和 iOS Hub 入口。商店式展示表达图标、名称、介绍和安装关系，不照搬 App Store 的营销板块。

上传即发布，没有草稿条目或另一步上架。包未完整校验和存储成功前，列表中不出现新条目，旧条目的当前版本也不变化。

## 4. 对象、身份与权限

### 4.1 条目与包分开

条目保存永久 `skillId`、上传者、图标、显示名称、介绍、可见范围、团队授权、当前版本和资料修订号 `revision`。版本保存不可变 `versionId`、递增编号、发布时间、可选更新说明、包清单和摘要。

包内 `SKILL.md` 的 `name` 是安装目录与 Skill 调用名称的依据；显示名称是商店资料。编辑显示名称不会修改包内 `name`。首次发布时可从 frontmatter 预填显示名称、介绍；后续上传不自动覆盖用户维护的展示资料。

不同作者允许上传同名 Skill；身份由 ID 决定，不以标题、文件名或用户名合并。首版同一条目的包内 `name` 保持不变；需要改调用名称时创建新条目，避免重新安装留下两个目录。

### 4.2 可见范围

| 模式 | 当前访问规则 |
| --- | --- |
| `private` | 仅上传者 |
| `public`，默认 | 所有活跃且正常登录的用户 |
| `teams` | 上传者，以及至少属于一个有效授权团队的活跃登录用户 |

团队可多选，选择时只能添加上传者当前所属的团队，至少选一个。对团队成员的判断使用实时成员关系，不保存成员快照，不授权给组织或某个角色。

默认公开只应用于首次创建。上传新版及资料修改没有提供 visibility 时保留原权限，不能把私有条目重置为公开；显式切到 private/public 时清除团队授权，切到 teams 时与所选团队一起原子保存。

**建议的成员变化口径**：团队授权是条目上的明确共享关系，不随上传者加入新团队自动扩张；上传者离开某个已授权团队后，该团队的共享暂停，重新加入可恢复，上传者仍可移除这项授权。团队被删除时移除对应授权；没有有效授权时维持 `teams` 模式且仅本人可见，不自动改成公开。保存资料时允许移除失效团队，不能通过旧团队 ID 新增或重新授权。实施时同步更新“团队不承载资源权限”的历史边界，明确这只是 Hub 的读取授权。

公开、私有和团队模式都不改变维护权：普通用户只能维护自己的条目，团队管理员或其他成员没有代改权；首版不增加管理员 Hub 内容管理界面。账号禁用后拒绝本人操作，其他人也不能再读取其条目。

列表、搜索、详情、图标、正文预览、版本历史、包下载和安装准备共用同一权限谓词，并在数据库分页前过滤。未登录返回 401；无读取权、已删除或不存在统一返回不可用，避免泄露名称、存在性和团队信息。

变更可见范围立即约束后续请求，旧版本继承当前条目权限，不保留旧公开下载入口。已经下载或安装的本地副本继续由本机用户持有，不提供远程撤回或卸载。

## 5. 包格式与本地准备

### 5.1 输入与标准形式

- 单个 `.md` 文件：必须是带有效 Skill frontmatter 的 Skill 主文件，转换为包根 `SKILL.md`，保留正文和 frontmatter 字节，不将普通文章自动改写为 Skill。
- ZIP：接受根目录含 `SKILL.md`，或仅有一个外包目录且其中含 `SKILL.md` 的形式。只移除这一层外包目录，不递归猜测入口，不接收多个 Skill 的集合。
- 本地目录：必须有根 `SKILL.md`；目录本身不直接成为云端输入，由客户端生成 ZIP。
- 最终包只有一个根 Skill，可包含 `scripts/`、`references/`、`assets/` 等正常附件。云端只存储和读取，不执行其中任何程序。

校验 `SKILL.md` 为有效 UTF-8，frontmatter 至少有非空字符串 `name` 和 `description`，正文非空；`name` 使用项目已有 Skill 命名规则。保留其他合法 frontmatter 字段，Hub 不替作者重写内容。具体 YAML 能力和长度限制以实施时核对的现有解析器为基础，不能静默丢字段。

本设计建议沿用本地安装来源的量级：主文件最多 1 MiB，单附件最多 10 MiB，合计最多 50 MiB，最多 100 个附件，目录深度最多 8；上传压缩文件也最多 50 MiB。ZIP 中目录及被忽略条目同样有独立的计数、解析时间和解压预算，不能只约束最后保留的文件。数量、路径和字节限制放共享契约，UI、MCP、服务端一致。

### 5.2 本地预检查

客户端按用户明确提供的来源路径进行有界读取，不扫描主目录寻找 Skill，不修改来源目录：

1. 解析主文件、枚举附件，检查文件类型、路径、大小、重复名称和跨平台兼容性。
2. 沿用现有发布排除规则：不打包 `.env`、`.env.*`（根 `.env.example` 除外）、其它隐藏项、符号链接、`node_modules` 和系统压缩元数据；Synapse 安装身份文件属于排除项。排除目录不递归读取，`.env` 不为预览而读取。
3. 指南要求 AI 检查实际发布内容并移除已知真实凭据；工具不得根据正文中的 token、Authorization、URL 参数模式或 `id_rsa`、`.pem`、`.key` 文件名硬阻断。若复用已有风险提示，只作为不含命中值的非阻断提示，首版不增加独立内容审查器，不复用问题反馈的宽泛脱敏模式作为发布准入。
4. 检查能静态解析的本地 Markdown 链接和资源路径，缺失时报告；不声称能验证脚本中的动态路径或远程依赖。
5. 给出主文件信息、文件清单、总字节、排除项、阻断问题及非阻断提示。AI 根据结果修改本地文件后重新准备。
6. 生成只含最终文件的不可变临时快照和包，计算内容指纹，返回 `preparedSourceId`，不通过 MCP 返回 ZIP/Base64 正文。

仅明确格式、路径和资源预算错误阻断；不以泛化“质量评分”作为发布门槛。客户端不运行 Skill 或安装第三方依赖来证明有效。

准备结果绑定当前账号、认证代次、MCP 调用者及最终快照，建议 30 分钟过期。发布读取该快照，不重新读取可能已改变的来源目录；修过源文件后必须再次准备。切换账号、退出、重启或过期使句柄失效，临时资产由 DataRepository 管理并后台回收，不裸写业务文件或阻塞窗口启动。

服务端不相信客户端检查结论，重新校验每个上传。直接上传包内出现上述排除的 `.env`、隐藏项或控制文件时拒绝，并报告应在本地移除；除外包目录和系统压缩元数据外不静默丢文件。服务端也不得增加正文凭据模式准入。符号链接、硬链接/特殊文件、加密/多卷归档、路径穿越、绝对路径、重复条目及文件/目录冲突均拒绝；大小写及 Unicode 等价冲突按跨平台规则拒绝，不能在解压后靠覆盖解决。

## 6. 版本机制与并发

### 6.1 三种不同的版本信息

- `versionNumber`：服务端按 Skill 递增的整数，展示为 `v1 / v2 / v3`，不要求作者填写 SemVer。
- `versionId`：不可变云端快照标识，安装和下载固定它。
- `revision`：条目的并发修订号；包发布、资料/权限修改和删除都推进它，展示资料变化不增加包版本。

服务端以最终文件的相对路径、字节长度和 SHA-256 构造固定排序、无歧义编码的清单，再计算 `contentFingerprint`。外包目录名、ZIP 时间戳、压缩级别、条目顺序不参与；文件名和实际字节参与，不 trim 正文或改写换行。另保存 `archiveSha256` 校验下载包本身，不能混用两种摘要。

与**当前版本**内容相同的上传返回 `unchanged` 和当前版本，不产生新版本，不修改展示资料。恢复到曾经发布过、但不同于当前版本的内容仍创建下一版，例如 `v4` 可以与 `v1` 内容相同；因此不能把 `(skillId, contentFingerprint)` 设为所有版本的唯一键。

### 6.2 写入与重试

首次发布要求稳定 `requestId`；上传新版要求 `skillId + expectedVersionId + requestId`；资料更新与删除要求 `expectedRevision + requestId`。新版本不携带资料更新，避免同时改变他人正在编辑的资料；发布事务只更新版本相关字段并推进当前 revision，不覆盖其他资料。

服务端在事务内锁定条目、再次检查归属和当前状态、校验版本条件、分配编号并写入成功回执。两个更新同一基础版本的调用最多一个成功，另一个明确返回版本冲突。先检查基础版本，再判断 `unchanged`，不利用相同包绕过冲突。

幂等作用域为账号、动作和 requestId；同键同请求返回原结果，同键不同请求拒绝。包摘要纳入请求摘要。服务端持久保存写入回执，至少覆盖 24 小时重试窗口；关联条目/版本保留首次创建请求标识，防止回执清理后重复创建。删除后以最小墓碑保留请求去重信息，首版不提供恢复。回执不保存包正文、介绍、凭据或签名下载地址。

网络中断不代表发布失败；AI 和客户端用同一 requestId 查询/重试，不能换 ID 自动再发。超出可确认窗口时先读取条目状态，不自动发布第二份。对象存储写入失败时不产生可见版本；对象已写入而数据库失败时保留可追踪的暂存对象，进入后台回收。

## 7. 操作链路

### 7.1 AI 首次发布

用户要求发布 → Synapse Skill 路由到 Hub 指南 → MCP 查询本地账号运行条件 → 准备本地来源 → AI 处理阻断问题 → 发布准备好的包 → 返回 ID、详情链接、版本、内容摘要和最终可见范围。

未指定可见范围时默认 `public`，指南必须明说它是“所有已登录用户可见”。用户已要求上传且目标明确时沿用授权直接发布，不强制增加一次确认。指定团队时先查本人团队列表，名称歧义再问，不猜团队 ID。

### 7.2 AI 更新已有 Skill

优先使用用户给出的 Skill ID/详情链接，或可信的本地 Hub 安装来源；只凭同名不能认定更新目标。查询并核对本人拥有的条目及当前版本 → AI 修改本地文件 → 重新准备完整包 → 指定 expectedVersionId 发布 → 返回新版本或 unchanged。

没有本地源码时，可经 MCP 将有权限的固定版本下载到用户指定的新目录，再修改和发布。下载不得覆盖既有目录；本地安装关联信息可以提示 Hub 身份，但不能授予云端所有权。其他作者的 Skill 可读取和安装，更新 API 始终拒绝代改。

### 7.3 网页上传和维护

上传表单接受 `.md / .zip`，展示名称、介绍、可选图标及可见范围。服务端检查不通过时返回具体错误；浏览器不运行包，也不修改包内文件。上传新版本固定原 Skill，提交当前基础版本，可附简短更新说明，上传成功后显示新版本。

“编辑资料”只编辑图标、显示名称、介绍、可见范围；“更新 Skill”提供“上传新版本”和“复制 AI 更新指令”。指令包含准确 Skill 引用、当时的当前版本、使用本地 Synapse MCP 的要求，以及“先重新读取当前版本、再在本地修改并上传完整包”的操作要求，不包含 token、Cookie 或本机路径猜测。条目内文字当作数据，不拼成高优先级指令。

网页上传和维护不依赖本地客户端；**AI 经 MCP 管理和从网页安装到本机**依赖客户端。这里不增加服务器对桌面进程的在线心跳限制。

### 7.4 网页安装到本机

网页读取详情并固定所选 versionId → 浏览器尝试打开安装深链 → 客户端按实际登录账号重新读取该 Skill/版本 → 下载并校验包 → 注册 prepared 安装来源 → 打开现有 Skill 安装器 → 用户选择编辑器、全局/项目位置并完成原有确认。

建议新增声明式协议 `synapse://skill-hub/install?skillId=<id>&versionId=<id>`。只有严格的 ID 参数，不接受任意包 URL、主机、路径、凭据、安装目标或自动覆盖开关。该协议使用 capability manifest 的 `protocolRoutes + mainHandlerId`，主进程只准备来源和打开现有安装流程，不新增公开导航 MCP；不恢复旧 `synapse://skill-install`。

网页只报告“已尝试打开 Snap”，不能把浏览器协议调用当成安装成功。未安装客户端时保留下载安装客户端和重试入口。客户端未登录则走既有登录流程，待处理目标仅留内存；完成登录后重新鉴权。网页与客户端账号不同，以客户端权限为准，不复用网页凭据。

固定版本在下载前已经删除或不可访问时停止，不悄悄替换成最新版。权限变更阻止后续请求和安装准备，但不承诺收回已经传输的文件字节。下载、解压和打开安装器均不执行 Skill 脚本。

### 7.5 重新安装与版本区别

本机使用独立来源身份 `skill-hub:<受信服务器标识>:<skillId>`，复用 `.synapse.json` 存安装来源、versionId、versionNumber、sourceFingerprint。具体字段兼容现有 `repositoryVersion / sourceFingerprint`，不得误认已退役的 cloud-skill-repository 身份。

现行模块规则中“.synapse.json 只存资源仓库身份”不包含这一新来源；本设计拟新增明确的 Hub 安装来源例外，须随设计批准及实现同步更新规则。旧 `.synapse.repository.json` 继续只作发布排除，不恢复旧云身份的读写或关联。

只有用户再次进入 Hub 安装链路时，才查询所选云端版本并比较该安装位置；不增加全局 Hub 轮询、自动拉包或更新通知。网页不推测本机是否已安装。

| 本机与选定来源 | 安装器行为 |
| --- | --- |
| 没有安装 | 正常安装 |
| 同一 Skill、同一版本 | 显示当前版本，允许重新安装 |
| 同一 Skill、不同版本且内容不同 | 显示“已安装 v2，本次 v4”等信息，用户确认重新安装 |
| 版本不同但内容指纹相同 | 说明内容一致，允许重新安装以更新来源记录，不强称内容有更新 |
| 同名但来源身份不同 | 沿用同名冲突/替换确认，不能视为同一 Skill |
| 缺少或损坏来源元数据 | 标为来源/版本无法确定，不能猜成最新版或自动覆盖 |

第一版安装主入口使用最新版，历史列表允许用户明确选择旧版再安装；不提供把服务端当前指针回退到旧版的独立操作。选旧版时表达“版本不同/安装此版本”，不能统一误报“可更新”。安装前快照是包内容指纹的依据，环境变量替换和安装器生成的身份文件不改变包身份；安装记录不证明本地文件后来没有被修改。覆盖处理和用户确认沿用现有安装器，安装过程继续保持原子写入及恢复约束。

## 8. 网页信息组织

功能结构先确定，具体视觉、断点和组件组合留给实施计划；未创建网页原型或启动浏览器。

- Hub 列表：默认展示本人可见的条目，提供“全部 / 我的上传 / 团队共享”范围及名称、介绍搜索；默认最近发布排序，不做安装量榜单。公开目录不能把私有或其他团队条目带入计数和搜索结果。
- 条目：图标、显示名称、简短介绍、作者、当前版本和必要的可见范围标识。
- 详情：上述资料、安装到 Snap、下载包、只读 Skill 主文件、文件清单和分页版本历史。只有本人显示资料编辑、上传新版本和删除操作。
- 我的上传：同一套条目和详情，只增加 owner 过滤，不另造资源类型或文件管理器。
- 删除：网页确认删除具体 Skill；删除后全版本不可访问，不提供回收站。MCP 根据用户对具体目标的删除授权执行，不因需要 requestId 或 expectedRevision 额外强制对话确认。

Hub 作为 Dashboard 登录区功能，复用 HeroUI v3、现有浅色主题、认证壳层、集中 API 客户端和路由守卫。桌面只复用安装器，不新增 Hub System App、默认 Dock 项或桌面商店。无需为首版增加团队管理、成员编辑或普通用户团队目录。

正文沿用现有安全的只读 Markdown 渲染，不运行原始 HTML/脚本，不因预览自动请求外部图片或执行包内网页。附件首版只提供文件清单与完整包下载，不新增任意附件在线执行或编辑入口。

## 9. MCP 与 API 建议契约

以下为**拟新增**契约，当前仓库并不存在这些工具或路由；实施时按同一语义生成 schema、索引和参考文档。

本地新增 `skill_hub` domain，通过现有仅有的 `search / invoke` 暴露。建议 10 项 capability；MCP 名称由 action 将点转换为下划线生成，例如 `app.skill_hub.package.prepare` 对应 `app_skill_hub_package_prepare`。

| capability action | 主要输入 | 作用 |
| --- | --- | --- |
| `app.skill_hub.skill.list` | scope、query、cursor、limit | 按当前权限分页查询，scope 支持可见、本人、团队共享 |
| `app.skill_hub.skill.get` | skillId 或详情引用 | 当前资料、当前版本、调用者权限及正文/清单读取信息 |
| `app.skill_hub.team.list` | cursor、limit | 只列本人团队的 ID 和名称，不返回成员信息 |
| `app.skill_hub.version.list` | skillId、cursor、limit | 分页版本信息 |
| `app.skill_hub.version.download` | skillId、versionId、destinationDirectory | 固定版本导出到新目录，返回本地路径及摘要 |
| `app.skill_hub.package.prepare` | sourcePath | 本地检查、快照与打包，返回准备句柄及检查结果 |
| `app.skill_hub.skill.create` | preparedSourceId、资料、visibility、teamIds、requestId | 首次完整发布 |
| `app.skill_hub.version.create` | skillId、preparedSourceId、expectedVersionId、requestId、可选 changeNote | 发布完整新版本 |
| `app.skill_hub.skill.update` | skillId、expectedRevision、requestId、变化的资料字段 | 只改资料和可见范围 |
| `app.skill_hub.skill.delete` | skillId、expectedRevision、requestId | 删除本人 Skill |

图标更新输入使用可选本地图片路径，由客户端通过上传通道处理，不能把任意图片 URL 交给服务端抓取。复用项目现有图片解码/尺寸限制，只接收经实际解码确认的 PNG/JPEG/WebP，不保存主动脚本格式；无图标时使用 Hub 默认图标。初始资料 create 和后续 update 均走同一图片规则。

Skill get 的正文默认只返回有限摘要和可读定位信息；需要完整源码时使用固定版本 download，不把 ZIP 或全部附件注入模型。列表/详情 DTO 不包含内部对象 key、COS 凭据、邮箱、认证 token 或其他团队成员资料。若 API get 提供只读正文，应按独立有界读取参数请求，不能默认夹带所有版本正文。

MCP 不接收 userId、ownerId、token、服务端地址或自定义认证头。调用开始绑定 AccountService 的 accountScope 和认证代次，所有网络请求及认证刷新使用同一 scope；切换账号取消请求并使准备句柄失效。已发送且可能成功的写请求保留原 requestId，不能自动改用新账号重试。

云端建议路由如下，所有端点均要求正常用户认证；浏览器复用 Cookie 会话及同源写保护，桌面复用当前登录 Bearer。首版不接入匿名、管理员会话或个人 API Key，也不要求用户手动取得 token：

| 路由 | 职责 |
| --- | --- |
| `GET /api/skill-hub/skills` | 有权限的列表及搜索 |
| `GET /api/skill-hub/skills/:id` | 资料、权限和当前版本 |
| `GET /api/skill-hub/teams` | 本人可选择的团队 |
| `POST /api/skill-hub/uploads` | 接收 Markdown/ZIP 或图标，校验后生成账号绑定临时 uploadId |
| `POST /api/skill-hub/skills` | 使用包 uploadId 与可选图标 uploadId 原子发布 v1 |
| `PATCH /api/skill-hub/skills/:id` | 修改资料、权限及可选图标引用 |
| `DELETE /api/skill-hub/skills/:id` | 删除整条 Skill |
| `GET /api/skill-hub/skills/:id/versions` | 版本历史 |
| `POST /api/skill-hub/skills/:id/versions` | 使用已校验的包 uploadId 发布新版 |
| `GET /api/skill-hub/skills/:id/versions/:versionId/package` | 鉴权后流式下载固定包 |
| `GET /api/skill-hub/skills/:id/versions/:versionId/main` | 鉴权后读取有界的只读主文件 |
| `GET /api/skill-hub/skills/:id/icon` | 按条目权限读取当前图标 |

uploadId 只代表当前账号、指定用途和已校验内容，建议 24 小时过期，不单独出现在商店；包与图标不能混用，不以知道 uploadId 代替鉴权。消费/绑定与写入回执同事务完成。上传失败、过期、未绑定或同内容未采用的对象由后台回收。

分页统一建议 cursor，默认 20、最大 100，固定排序键和 ID 次序；游标绑定筛选、身份及 scope。每个工具按仓库要求声明分页续页字段。删除/撤权后即使旧 cursor 仍有效，也重新过滤权限。

结构化错误至少区分未登录、权限不可用、包无效、来源过期、文件预算超限、资料冲突、包版本冲突、请求键冲突、存储失败及客户端/服务端版本不支持。错误提供下一步操作，不输出原始文件内容、凭据或请求体。

## 10. 数据、存储与删除

逻辑数据包含 Skill 条目、不可变版本、所选团队关联、受管对象及写入回执。团队关联独立索引；版本对 `(skillId, versionNumber)` 唯一；条目与版本的权限和最新指针在事务中维护。JSON 清单只包含有界的路径、大小及摘要，不存包字节。

新增专属 `SKILL_HUB_COS_*` 存储域及 `skill-hub/` 对象前缀，包、只读主文件派生对象和 Hub 图标统一归该域；不占 Drive 配额，也不混入 Platform Media。bucket 与旧 `SKILL_REPOSITORY_COS_*` 及其他运行域严格分离，配置校验必须拒绝复用。

只保存最终标准包、版本清单及只读主文件，不保留在线可变文件树。对象包括 archiveSha256/size、归属、用途、状态和引用；包内容摘要由服务端重算。图标替换后，新对象绑定成功才回收旧对象。

删除事务立即设条目 tombstone 并登记整条目对象删除任务，全版本立即不可读取。对象删除在后台有界执行，失败保留 key、状态和重试信息；不能先删引用再假报物理清理完成。未绑定上传过期同样进入此流程。首版不提供单独删某个历史版本、历史版本编辑或条目恢复；被删除 ID 和请求去重墓碑按明确维护策略保留。

新域上线必须一起支持数据库备份、对象清单、**实际对象字节**复制和恢复验证。不能沿用现有“数据库和清单已备份”就宣称 Hub 包可恢复；还必须记录备份保留与删除对象在备份中到期的行为。不得在本设计任务中配置桶、读生产数据或执行旧域退役脚本。

- AccountService 已有 authenticated fetch 与 accountScope；MCP 仍仅公开 search/invoke。团队是管理员维护的多对多成员关系。

建议新增服务端 `server/src/skill-hub/`、共享 `shared/src/skill-hub*` 契约、本地 `desktop/app-capabilities/skill-hub/` 能力包和 Dashboard 对应功能目录。它们是拟新增位置；实现者先核对现有目录约定。通用 ZIP 的纯校验如需共享，只提取本功能所需部分，不顺手重构所有来源或扩大工作流包规范。

实施时同步更新能力注册表、模块边界、存储配置、部署/备份规则、Synapse Skill 的 Hub 指南、根 SKILL 路由和生成 API 参考。新增预计 10 项 capability/MCP 索引、1 条声明式协议，System App/Dock/Workflow/Automation 无新增；最终数量必须实测注册表，不从历史计数机械相加。

旧退役脚本继续只清理旧桶的 `skill-repositories/`，新增对 Hub 桶的排除保护；新表不复用旧表名，不改写旧迁移，不恢复旧路由、工具别名和旧身份关联。部署预演不能访问或删除新旧生产桶。新域启用先完成配置、存储/备份验证和服务端迁移，再发布网页及桌面；旧客户端明确提示升级，不以未知协议或下载失败冒充可安装。

此刻只新增待审设计文档，不修改现行规则、代码或待发布说明；真正实施时按用户可感知变化更新 RELEASE_NOTES_PENDING.md。回滚应用不包含删新表/桶；上线迁移后的完整回滚需依赖已验证的数据库及对象备份，不在日常回滚里自动清理数据。

## 12. 验收与留给实现者的决定

必须覆盖：

1. Markdown、根 ZIP、单外包目录 ZIP、本地目录成功；普通文章、多个根 Skill、穿越、链接、重复路径、大小写冲突、加密包及预算超限失败。
2. 本地排除运行凭据/身份文件，云端复验；准备快照与后续源目录修改相互隔离，敏感命中值不进入工具结果或日志。
3. 三种模式以及默认公开、必须登录；列表/计数/正文/图标/历史包同权限；团队加入、移除、作者离队和团队删除的实时边界；非本人写入拒绝。
4. 自动编号、当前包判重、恢复旧内容生成新号、资料更新不产生包版本；并发发布和资料冲突、相同 requestId 重试、未知网络结果不会重复发布。
5. 临时上传过期、部分上传、数据库失败后的孤儿、删除任务失败重试、图标替换和真实备份恢复。
6. 冷/热启动深链、未登录、不同账号、参数非法、无权限/已删除版本、旧客户端；只打开安装流程，不能通过链接指定路径或自动覆盖。
7. 现有编辑器全局/项目安装、同版本重装、版本区别、同名冲突、多安装位置、安装中失败与恢复；macOS/Windows 实际适用边界。
8. MCP search/invoke 发现、顶层普通对象 schema、分页、调用者权限、账号切换/认证刷新、错误脱敏；旧云端路由和身份不重新生效。
9. 网页实际展开的上传、资料编辑、团队选择、更新与删除浮层，在桌面与窄屏覆盖焦点、长内容及边界；运行浏览器/应用测试仍需用户在实施阶段授权。

实现者可以决定内部文件拆分、索引具体写法、有界 worker 的调度参数、DTO/schema 命名和组件组合；不得自行增加功能、依赖、分支/worktree、启动服务、运行远端 CI 或部署。具体图片尺寸、字段长度及原有解析器可复用范围在实施计划中给出一致且可测试的值；若现有依赖无法满足安全 ZIP 处理，先说明缺口，再取得新增依赖授权。
