# 自动化 Claude Code 单次模式

用户已在 2026-11-05 确认实现并要求实测：Claude Code 执行配置增加默认不勾选的「单次模式」。不勾选时，本轮完成后停在交互输入框并保留终端；勾选时用内置 CLI 的 `--print` 执行初始提示词，CLI 自然退出后由现有 TerminalService 删除对应会话、分屏及空标签。

配置增加可选布尔 `singleRun`，缺省与 `false` 均保留已有行为；新任务默认 `false`。不改变触发频率、默认供应商/模型/权限、后台启动与焦点、不自动重发，以及首条 `UserPromptSubmit` 回执即结束自动化的契约。单次执行的后续完成或失败不改写已经结束的启动记录；记录的终端入口失效时继续显示既有不可用提示，不重建会话。

采用原生单次运行，放弃交互模式中监听 `Stop` 再强制关闭的方案：真实测试证明并行 Stop Hook 能在 Stop 已上报、后台任务数量为零后要求继续执行。单次模式跟随原生进程生命周期，不推断所有业务工作成功，也不保证 CLI 自己启动的后台任务已完成；实测内置 2.1.278 可带未完成后台任务退出。需要长驻、后台唤醒或继续交互时使用默认模式。

先前讨论中“失败后保留终端”是建议，现确认以进程退出为关闭依据；现行终端硬规则要求清理所有终态会话，不另建失败终端保留机制。启动确认前取消/超时仍不主动结束已创建的进程；之后退出时仍走原终端清理流程。

`singleRun` 仅用于带初始提示词的新启动，不允许与 continuation 混用或无提示词启用。只增加原生 `--print` 参数，不拼 shell、不自动审批、不修改用户全局配置、不新增依赖或公开工具。MCP 执行器发现、系统 Skill、能力清单、模块边界及发布说明同步。

验证：schema/默认值、勾选切换、执行器透传；真实 TerminalService + 受控 PTY 验证两种 argv、保持运行直到进程退出、仅清理本次会话、首条回执及临时 settings 清理。再用内置真实 CLI/PTY 验证普通交互保持、单次自然退出及 Stop Hook 继续后才退出。真实测试只在临时目录执行，不改业务任务配置，不提交凭据或终端正文。
