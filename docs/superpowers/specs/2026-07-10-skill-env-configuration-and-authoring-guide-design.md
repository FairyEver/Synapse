# Skill ENV 配置、密钥同步与作者指南设计

日期：2026-07-10

## 摘要

将 Skill 安装时的一次性正文变量替换升级为基于文件协议的可持续配置机制。

Skill 作者在根目录提交 `.env.example` 声明配置键，Synapse 安装时生成本地 `.env`。密钥名称与 `.env` 键名构成稳定关联。密钥值变化后，Synapse 不依赖安装记录，也不在已渲染正文中猜测旧值，而是实时扫描已知编辑器 Skill 目录中的 `.env`，列出受影响项并由用户一键更新。

资源仓库的“技能”标签增加“Skill 开发指南”入口。指南由本地 Markdown 文件渲染，说明新 Skill 的组织方式、旧 Skill 的迁移方法，并提供“修改现有 Skill”和“创建新 Skill”两段可复制提示词。

## 目标

- 让安装后的 Skill 配置可以在密钥值变化后被可靠发现，并通过串行队列逐项更新。
- 不建立持久化的 Skill 安装实例或密钥绑定数据库。
- 让关联关系存在于 Skill 自身的标准配置文件中。
- 保持已安装 Skill 离开 Synapse 后仍可独立运行，不要求运行时调用 Synapse MCP。
- 避免把真实配置继续写入 `SKILL.md`。
- 为 Skill 作者和本地 Agent 提供可执行的迁移与创建规范。
- 保留旧 Skill 的过渡兼容，不立即破坏现有安装流程。

## 非目标

- 不扫描整个磁盘寻找 Skill。
- 不监视文件系统并自动静默改写配置。
- 不判断某个键是 token、密码、地址还是普通设置。
- 不为每个安装实例保存持久化路径、来源或绑定关系。
- 不让 Synapse 在 Skill 运行时注入环境变量。
- 不要求 Skill 通过 Synapse MCP 读取配置。
- 不在本阶段为扫描和队列更新新增 MCP 工具。
- 不改变 Rule 的 `${{ NAME }}` 变量替换行为。

## 核心决策

### 文件协议

采用双文件 Dotenv 协议：

```text
my-skill/
├── SKILL.md
├── .env.example
├── .env
└── scripts/
```

- `.env.example` 是作者提交的配置声明，属于 Skill 包内容。
- `.env` 是安装后的本地运行配置，由 Synapse 生成或合并，不属于可发布内容。
- 作者决定键和值的业务含义，Synapse 只识别键名并管理值的写入。
- Skill 的脚本或程序负责从 Skill 自身目录加载 `.env`。
- `SKILL.md` 只描述调用方式，不直接嵌入真实配置值。

### 为什么不使用 YAML 或 XML

- Dotenv 是环境配置的通用格式，多数运行时已有原生或成熟加载方式。
- YAML 能表达更复杂的元数据，但会增加运行时解析依赖和字符串语义差异。
- XML 更冗长，缺乏适合本场景的生态优势。
- 本需求只需要稳定键名、值、注释和默认值，不需要嵌套数据结构。

### 为什么不能继续扫描正文

`${{ NAME }}` 被替换为真实值后，占位符和变量名已经丢失。事后扫描正文只能猜测值的位置，会误改普通文本，也无法处理值重复、值变化或用户手工编辑。因此新机制只扫描保留键名的 `.env`，不扫描 `SKILL.md` 中的真实值。

## Dotenv 格式约束

Synapse 按 Node.js DotEnv 语义解析 UTF-8 文件，并支持：

- 空行和以 `#` 开始的注释。
- `KEY=value`。
- 单引号、双引号和反引号包裹的值。
- 引号内多行值。
- 可选 `export` 前缀。
- 键名匹配 `[A-Za-z_][A-Za-z0-9_]*`。

Synapse 不执行变量展开、命令替换或 shell 表达式。值始终按普通字符串处理。

键名查找与当前密钥库保持一致，采用不区分大小写的匹配，但保留文件中的原始大小写。若同一文件存在仅大小写不同的重复键，或同一个键重复声明，扫描结果标记为冲突，Synapse 不猜测应修改哪一项。

`.env.example` 可以包含空值、非敏感默认值和注释，但不得包含真实 token、密码、私钥或生产连接信息。

## Skill 作者运行时约束

`SKILL.md` 不会自动加载 `.env`。真正消费配置的脚本必须显式加载 Skill 根目录的 `.env`，并且路径必须基于脚本文件位置计算，不能依赖调用时的当前工作目录。

Node.js 20.12 及以上版本优先使用内置能力：

```js
import { loadEnvFile } from "node:process"
import { fileURLToPath } from "node:url"

const envPath = fileURLToPath(new URL("../.env", import.meta.url))
loadEnvFile(envPath)

const token = process.env.GITEE_TOKEN
```

Python、Shell 或其他运行时可以使用项目已有的 Dotenv 读取能力。作者应优先复用已有依赖；没有明确必要时不为加载配置新增依赖。

纯 Markdown Skill 如果没有脚本或工具入口，无法安全、稳定地消费 `.env`。这类 Skill 不应要求 Agent 读取并复述 `.env`，需要配置时应增加受控脚本入口。

运行时要求：

- 缺少必需键时，错误可以包含键名，但不得包含其他配置值。
- 不输出完整 `.env`。
- 不把敏感值写入日志、错误详情、命令回显或生成文件。
- 不要求 Agent 把 `.env` 内容复制进对话上下文。

## 安装协议

### 安装前检查

主进程从 repository、prepared 或 local-directory 安装源读取 Skill 根目录的 `.env.example`，返回安全的键清单供安装器展示。

新安装时，每个键的初始值优先级为：

1. 用户在当前安装流程中确认或输入的值。
2. 密钥库中同名键的现有值。
3. `.env.example` 中的默认值。
4. 空字符串。

安装器延续现有的“是否保存到密钥库”确认流程。Synapse 不根据键名判断是否敏感。

### 新安装

安装核心在原子目录替换的 staging 目录中：

1. 复制正常 Skill 文件和 `.env.example`。
2. 按用户确认的键值生成 `.env`。
3. 对值进行 Dotenv 安全序列化。
4. 完成现有权限检查、审计和原子替换。

项目级安装在写入前明确提示：`.env` 可能包含敏感信息，用户应确认项目的 Git 忽略规则。Synapse 只提醒，不自动修改项目 `.gitignore`。

### 更新或重新安装

更新已有目标时，在替换旧目录前读取目标根目录 `.env`：

- 保留现有键值。
- 保留用户自行添加的键。
- 从新版 `.env.example` 补充缺少的键。
- 不因新版 `.env.example` 删除某个键而删除 `.env` 中的键。
- 不用 `.env.example` 的默认值覆盖已有 `.env` 值。

Skill 源包中的根级 `.env` 不作为可发布配置。资源仓库保存、导入或发布 Skill 时若发现根级 `.env`，应阻止继续并提示只提交 `.env.example`，避免把真实配置写入仓库。local-directory 安装源中的 `.env` 不直接复制到其他目标；目标值来自用户确认、密钥库或目标已有 `.env`。

## 旧机制兼容

### Rule

Rule 继续使用现有 `${{ NAME }}` 安装时替换，不纳入本次 `.env` 协议。

### 旧 Skill

没有 `.env.example`、仍在 `SKILL.md` 使用 `${{ NAME }}` 的旧 Skill 暂时保留原安装时替换能力，但安装器明确提示：

- 这些值写入正文后不能通过新扫描机制同步。
- 作者应使用“Skill 开发指南”迁移。

如果同一 Skill 同时存在 `.env.example` 和正文占位符，安装器分别展示：

- 可持续同步的 `.env` 键。
- 仅本次替换、后续不可同步的旧正文变量。

两类变量可以在过渡期共存，但 UI 不得把旧正文变量标记为可同步。

已经安装且只剩真实正文值的旧 Skill 无法可靠自动发现或迁移。它必须先由作者或本地 Agent 改造成 `.env.example`、`.env` 和运行时读取结构。

## 密钥库行为

### 名称是稳定关联键

密钥名称与 `.env` 键名共同构成文件协议中的稳定身份。为避免重命名后失去关联：

- 密钥创建后名称只读。
- 用户仍可修改值和描述。
- 需要新名称时创建新密钥，并同步修改 Skill 的 `.env.example` 和代码。
- 删除前先扫描受影响 Skill 并提示，但不删除任何 `.env` 键。

### 触发扫描

在密钥库 UI 中：

- 新建带值的密钥或修改密钥值后触发扫描。
- 只修改描述时不触发扫描。
- 安装器内部保存密钥后继续当前安装，不额外打开全局扫描结果。
- 每个密钥提供“扫描关联 Skill”操作，允许用户稍后重新扫描。

## 实时扫描

“实时扫描”表示每次用户触发时根据当前文件系统重新发现，不表示后台常驻监听。

扫描范围：

- 所有支持 Skill 的编辑器全局 Skill 目录。
- Synapse 已配置项目对应的项目级 Skill 目录。
- 每个 Skill 根目录中的 `.env`。

不扫描整个磁盘，不读取无关项目，不递归搜索 Skill 内任意深度的 `.env`。

扫描结果包含：

- 临时结果 ID。
- Skill 名称。
- 编辑器。
- 全局或项目范围。
- 配置路径。
- 状态：`needs_update`、`up_to_date`、`invalid`、`unwritable` 或 `unsafe_link`。
- 扫描时文件摘要，用于更新前竞争检查。

扫描结果不包含当前值、新值、密钥描述或其他 `.env` 内容。

### 临时扫描会话

扫描结果只保存在主进程内存中，并使用带有效期的 `scanSessionId` 和结果 ID。它用于防止 Renderer 构造任意写入路径，不写入 DataRepository、SQLite、配置文件或安装记录。

用户提交更新时，主进程：

1. 校验扫描会话仍有效。
2. 重新确认目标仍位于受支持的 Skill 根目录。
3. 拒绝越出根目录的符号链接。
4. 重新读取 `.env` 并比较文件摘要。
5. 确认目标键仍唯一存在。
6. 直接从密钥库读取最新值。
7. 原子修改目标值。

文件在扫描后变化时，该项标记冲突，不覆盖用户修改。单项失败不阻断其他选中项。

## “更新 Skill 配置”界面

保存密钥后发现关联项时打开模态框，列表字段为：

- 选择。
- Skill。
- 编辑器。
- 范围。
- 配置路径。
- 状态。

默认选中全部 `needs_update` 项。`up_to_date` 只展示状态，不可选择；格式错误、不可写和不安全链接展示简短原因。

主要操作为“更新选中项”。关闭模态框不会回滚密钥库的新值，也不会修改任何 Skill。更新完成后保留逐项结果：成功、失败或冲突。

真实值不出现在列表、toast、日志或错误详情中。

## 资源仓库 Skill 开发指南

### 入口

- 入口只在资源仓库“技能”标签激活时显示。
- 位于系统 App 顶栏右侧 actions 区。
- 使用 `BookOpen` 图标的紧凑 ghost 按钮。
- `aria-label` 与 tooltip 为“Skill 开发指南”。
- 嵌入应用列表时位于“新窗口打开”按钮左侧。
- 独立窗口中保持右对齐。

资源仓库继续使用 `SystemAppWindowShell` 的 actions slot，避免在页面内部复制一套顶栏。

### 模态框

- 标题：`Skill 开发指南`。
- 使用 `DialogContent showCloseButton={false}`、`DialogFrame`、`DialogFrameHeader` 和 `DialogFrameBody`。
- 主体固定最大高度并使用 `ScrollArea`。
- 文档正文复用 `MarkdownViewer` 的 plain surface。
- 不新增自定义颜色、自定义 CSS、卡片嵌套或营销文案。
- 两段提示词完整展示，每段标题旁有“复制提示词”按钮。
- 复制成功提示：`提示词已复制`。
- 复制失败提示：`复制失败`。

### 单一 Markdown 来源

指南保存为资源仓库模块内置 Markdown 文件，由 Vite 以 raw text 打包，离线可用。

为了让展示内容与复制内容保持同一来源，Markdown 文件使用两个受控区块：

```md
:::synapse-prompt id="upgrade-skill" title="修改现有 Skill"
完整提示词
:::

:::synapse-prompt id="create-skill" title="创建新 Skill"
完整提示词
:::
```

资源仓库模块的局部解析器把文档拆成普通 Markdown 段和提示词段。普通段继续交给 `MarkdownViewer`；提示词段使用标题、复制按钮和可选择的预格式化正文展示。解析器只接受两个已知 ID，缺少、重复或未知 ID 在测试和开发阶段视为文档错误。

### 指南正文结构

1. Skill 目录结构。
2. `.env.example` 与 `.env` 的职责。
3. Dotenv 格式规则。
4. Node.js、Python 等运行时如何读取配置。
5. Synapse 安装、扫描与更新行为。
6. 项目级安装的 Git 安全提醒。
7. 旧 Skill 迁移步骤。
8. 新 Skill 创建规范。
9. 修改现有 Skill 提示词。
10. 创建新 Skill 提示词。

## 内置提示词

### 修改现有 Skill

```text
请检查当前目录中的已有 Skill，并将它迁移到 Synapse Skill ENV 配置规范。直接修改文件并完成必要验证，不要只给建议。

要求：

1. 先阅读 SKILL.md、脚本、配置文件和现有测试，确认 Skill 的入口、运行时和当前配置来源。只修改完成迁移所需的文件，不做无关重构。
2. 查找 SKILL.md 或其他文件中的 `${{ NAME }}` 变量、硬编码 token、密码、API Key、地址及其他需要安装时配置的值。不要在回复、日志或最终总结中复述任何真实敏感值。
3. 在 Skill 根目录创建或完善 `.env.example`。使用标准 Dotenv `KEY=value` 格式；只写键名、必要注释和非敏感默认值，不写真实 token、密码、私钥或生产连接信息。
4. 让真正消费配置的脚本或程序从 Skill 根目录的 `.env` 读取值。路径必须根据脚本自身位置计算，不能依赖当前工作目录。
5. Node.js 20.12 及以上优先使用 `process.loadEnvFile()`；其他运行时优先复用项目已有的 Dotenv 能力。除非现有运行时没有可用方案，否则不要新增依赖。
6. 从 SKILL.md 和代码中移除真实敏感值，以及需要安装时写入正文的敏感占位符。SKILL.md 只说明如何调用脚本，不要求 Agent 读取、展示或复制 `.env`。
7. 如果当前源码中已经存在真实配置值，为保持本地运行可将它们迁移到本地 `.env`，但必须确保 `.env` 被 Git 忽略。不要创建包含真实值的 `.env.example`，不要把 `.env` 纳入提交或发布内容。
8. 如果无法确定某个配置值，不要编造。保留对应 `.env.example` 键为空，并让运行时在缺少必需键时返回包含键名的明确错误，但不得输出其他配置值。
9. 不要打印完整环境变量，不要把敏感值写入命令参数回显、日志、错误详情、缓存或生成文件。
10. 保持原有功能和入口兼容。运行现有测试；没有测试时执行最小可行验证，确认配置加载路径不依赖当前工作目录。
11. 完成后只总结修改的文件、声明的配置键名和验证结果，不展示任何配置值。
```

### 创建新 Skill

```text
请在当前目录创建一个符合 Synapse Skill ENV 配置规范的新 Skill。直接创建完整文件并完成必要验证，不要只输出示例。

要求：

1. 先根据当前需求确定 Skill 的职责、触发场景、运行入口和最小文件结构。保持职责单一，不添加与需求无关的功能。
2. 创建规范的 SKILL.md 和必要的 scripts、references 或 assets。SKILL.md 应说明何时使用、如何调用以及必要限制，不写真实 token、密码、API Key、私钥或生产连接信息。
3. 只有 Skill 确实需要外部配置时才在根目录创建 `.env.example`。使用标准 Dotenv `KEY=value` 格式；键名应稳定、清晰，只包含必要注释和非敏感默认值。
4. 不要创建带真实值的可提交 `.env`。如果为了本地验证必须创建 `.env`，先确保它被 Git 忽略，并且不要在回复或最终总结中展示其内容。
5. 让消费配置的脚本从 Skill 根目录 `.env` 读取值。路径必须根据脚本自身位置计算，不能依赖当前工作目录。
6. Node.js 20.12 及以上优先使用 `process.loadEnvFile()`；其他运行时优先使用已有原生能力或项目现有依赖。没有明确必要时不要新增依赖。
7. 对必需配置进行启动前校验。缺失时可以报告键名和修复动作，但不得输出其他配置值。
8. 不要要求 Agent 读取、展示或复制 `.env`；不要打印完整环境变量；不要把敏感值写入命令参数回显、日志、错误详情、缓存或生成文件。
9. 添加适合该 Skill 的最小测试或验证，至少确认从非 Skill 工作目录启动时仍能正确定位 `.env`，并确认缺少必需键时安全失败。
10. 完成后总结目录结构、需要用户配置的键名和验证结果，不展示任何配置值。
```

## 架构边界

### Dotenv 文档层

提供纯函数能力：

- 解析键、值和源位置。
- 校验重复键与格式错误。
- 生成新 `.env`。
- 在保留注释、顺序、引号和换行风格的前提下替换单个值。
- 合并 `.env.example` 中新增的键。

解析可使用 Node.js 内置 DotEnv 语义做值校验，并使用文档级 span 解析保留原始格式。更新不得通过重新序列化整个对象覆盖用户文件。

### Skill 配置服务

负责：

- 检查不同安装源的 `.env.example`。
- 生成安装配置计划。
- 在 staging 目录物化 `.env`。
- 更新安装时合并目标已有 `.env`。

### 扫描与更新服务

负责：

- 从 editor adapters 和已配置项目解析可信 Skill 根目录。
- 扫描根级 `.env`。
- 创建短期内存扫描会话。
- 对选中项做路径、摘要、键唯一性和符号链接复查。
- 调用现有权限、审计和原子文件写入能力。

### Secrets 集成

`SecretsService` 继续作为密钥 CRUD 的唯一业务入口。扫描服务通过受控接口按名称读取最新值，Renderer 不接收批量更新所需的真实值。

密钥扫描与队列更新首先作为 Secrets IPC/UI 能力提供，不新增 MCP action。队列采用内存串行执行：一次只处理一个 Skill，单项失败或冲突不阻塞后续项，结果按队列顺序返回；不保存持久化队列记录。现有 Secrets MCP、Synapse Skill 的 secrets 指南和 API reference 需要同步说明：

- 密钥名称可作为 Skill `.env` 键的关联名。
- 名称创建后不可修改。
- MCP 修改值不会静默改写 Skill 文件。
- 桌面端可显式扫描并由用户确认更新。

## 错误处理

- 安装源 `.env.example` 无效：阻止新协议物化，展示具体键名或行号，不展示值。
- `.env` 重复键：扫描结果标记格式错误，不修改。
- `.env` 不可写：保留该项并显示不可写。
- 目标是越界符号链接：标记不安全路径，不跟随。
- 扫描后文件变化：标记冲突，要求重新扫描。
- 扫描会话过期：不写入，提示重新扫描。
- 单项更新失败：继续处理其他选中项。
- 复制提示词失败：显示“复制失败”，不记录提示词正文。
- 指南文档解析失败：记录不含提示词正文的结构化错误，并显示“指南加载失败”。

## 安全与审计

- Secret create、value update、delete 继续使用 `secret.write` 权限。
- 扫描只读取已知 Skill 根目录中的固定文件名。
- 写入继续使用编辑器文件写权限检查和审计。
- 审计只记录密钥名、编辑器、范围、结果数量、目标文件名和结果状态。
- 日志、审计、事件、诊断、备份和错误不得包含 `.env` 值或完整文件内容。
- 更新值不经过 Renderer；Renderer 只提交扫描会话和结果 ID。
- `.env` 不进入资源仓库、诊断包或配置备份。

## 测试计划

### Dotenv 单元测试

- 空值、默认值、注释、空行和 `export`。
- 单引号、双引号、反引号和多行值。
- LF、CRLF、UTF-8 BOM。
- 值中的 `#`、`=`、引号和反斜杠。

- 定点替换保留注释、顺序、引号与换行风格。
- 合并只补缺失键，不覆盖或删除已有键。

### 安装测试

- repository、prepared 和 local-directory 源都能检查 `.env.example`。
- 新安装按既定优先级生成 `.env`。
- 更新安装保留目标已有值和额外键。
- 新版新增键被补充，删除声明不删除目标键。
- 项目级安装显示 Git 风险提醒。
- 源包根级 `.env` 不进入资源仓库或其他安装目标。
- 旧 Skill 正文替换继续工作并显示不可同步提示。
- Rule 安装行为不回归。

### 扫描与更新测试

- 扫描所有支持编辑器的全局目录和已配置项目目录。
- 不扫描未知目录或 Skill 内嵌套 `.env`。
- 不跟随越界符号链接。
- 结果不包含值。
- 已是最新、待更新、无效、不可写和不安全链接状态正确。
- 更新前文件摘要变化会阻止覆盖。
- 单项失败不阻断其他项。
- 原子写入失败保留原文件。
- 权限、审计、日志和错误不泄漏值。
- 扫描会话过期或伪造结果 ID 被拒绝。

### Renderer 测试

- 密钥名称在编辑态只读。
- 创建或修改值后触发扫描，描述修改不触发。
- 手动“扫描关联 Skill”可重新打开结果。
- 默认只选中待更新项。
- 关闭结果不修改文件。
- 更新结果正确展示成功、失败和冲突。
- 资源仓库指南入口只在“技能”标签显示。
- 嵌入和独立窗口的顶栏位置正确。
- 模态框渲染 Markdown 并可滚动。
- 两个提示词区块完整显示并复制准确文本。
- 缺少、重复或未知提示词区块触发文档错误。

## 验收标准

- 使用 `.env.example` 的 Skill 安装后，目标目录存在保留键名的 `.env`，`SKILL.md` 不需要写入真实值。

- 用户可以选择并一键更新，未确认前不修改任何文件。
- 更新不依赖持久化安装记录，也不在正文中搜索旧值。
- 更新不会覆盖扫描后发生的文件变化。
- 任何 UI、日志、审计和错误都不展示真实值。
- 旧 Skill 仍能安装，但明确标记正文变量不可同步。
- 资源仓库“技能”标签右上角可以打开开发指南。
- 指南完整说明新建和迁移方法，并能复制两段与展示内容完全一致的提示词。
