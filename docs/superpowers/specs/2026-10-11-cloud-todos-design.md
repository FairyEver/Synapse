# 云端待办事项设计

日期：2026-10-11。

状态：用户已于 2026-10-11 认可第一阶段交互原型，包括 PC 白色列表卡片修订，并确认本书面设计。[实施计划](../plans/2026-10-11-cloud-todos.md) 待用户审阅与选择执行方式；当前未开发、部署或注册这些能力。

原型依据：[第一阶段原型](../../prototypes/2026-10-11-cloud-todos/README.md)。

## 1. 目标与成功标准

增加内置应用「待办事项」。同一登录账号在桌面端、iPhone 与 iPadOS 维护同一份待办，也可以在 AI 对话中通过 Synapse Skill 增删改查。

用户已经确认：

- 只有「未完成 / 全部」两个标签，普通进入默认「未完成」，应用内没有侧栏。
- 完成后从「未完成」移除，在「全部」可恢复。
- PC 使用灰色页面背景，一张白色卡片承载整个列表。
- 标题、可选备注、完成状态、截止日期与时间、提醒。
- iOS 主页增加「待办事项」入口。
- 必须登录；所有业务数据与变更由 Synapse 服务端 API 提供。

本设计补足原型未决定的规则：跨端冲突、时间含义、提醒取消与去重、请求重试、账号切换及通知定位。它们属于用户已确认的后续实现方案，不是已有功能。

验收以完整链路为准：桌面手动新增、AI 查询或修改、手机看到相同结果；电脑关闭时服务器仍能触发已设置的提醒；完成事项后未触发的提醒被取消。

## 2. 范围与硬约束

- 这是个人账号数据，不属于项目、团队、选中的电脑或本机 Database。
- 不使用本地 SQLite、DataRepository、文件或浏览器持久存储保存待办正文、草稿或离线写入队列；客户端只保留当前账号的内存视图。认证凭据继续沿用现有账号存储。
- 退出或切换账号时清空内存条目、草稿、操作反馈和待跳转目标；迟到请求不得回填新账号。
- 不新增依赖。桌面沿用 shadcn/Radix 与主题 token，业务 renderer 放在 `desktop/src/modules/`；主进程经 ServiceRegistry、IpcRegistry、PermissionGuard 与 AuditSink 组装。
- iOS 最低部署版本保持 18.0，使用系统控件与现有 APIClient；不建立第二个 SynapseAppModel。
- `APNS_USE_SANDBOX` 保持 `false`；推送沿用生产 APNs。开发签名安装包无法接收此生产推送的既有约束不变。
- 本版不增加子任务、优先级、标签、清单分组、重复任务、协作分配、附件、离线编辑或 Workflow / Automation 节点。
- 待办任务不进入终端的「待处理」统计，也不改变通知底栏或通知未读数的 99 上限。

## 3. 界面与操作

### 3.1 桌面端

作为 System App 注册，可从应用入口打开、由用户固定到 Dock、在独立窗口中打开。沿用现有窗口宿主，不重复生成顶栏；默认不固定到 Dock。

顶栏左侧返回和「待办事项」，中间「未完成 / 全部」，右侧标准尺寸「新建」按钮。内容区在灰色 `bg-surface` 上使用一个现有 `Card`，浅色外观为白色 `bg-card`，深色外观遵循现有主题。列表行不另加卡片或自定义配色。

每行依次提供完成控件、正文、更多菜单。正文显示标题、最多一行备注、已设置的截止时间与提醒；点正文编辑。已完成标题划线并显示完成状态。更多菜单提供编辑、完成／恢复、删除。

新建和编辑使用现有 Dialog 表单；标题必填。提交期间禁用重复提交。成功后关闭表单并重新读取当前列表；失败保留草稿并显示必要错误。完成／恢复以服务端响应为准，成功后提供短暂撤销入口；撤销是携带最新版本的反向操作，发生跨端冲突时重新读取并告知，不能覆盖别人后续修改。

删除前确认具体标题，删除成功后移出列表。本版没有回收站或删除撤销。

### 3.2 iPhone 与 iPadOS

主页功能清单增加「待办事项」，使用已有主页导航栈进入单列事项页。入口与读写可用性只取决于账号及账号 API，不受选中电脑的在线状态影响。底栏继续是「主页 / 终端 / 通知 / 我的」。

事项页使用系统 List、导航栏的新建操作及两枚状态的 segmented Picker。点完成控件改变状态，点正文编辑；菜单提供可见的完成／恢复和删除操作，不把手势作为唯一入口。

新建／编辑使用系统 sheet 与 Form：取消位于顶部左侧，添加／保存位于右侧。iPadOS 用系统自适应表单呈现，内容仍是同一份单列列表；不复制网页原型的控件外观或自行仿造 Liquid Glass。日期与时间用 DatePicker，备注用系统多行输入，提醒使用系统选择控件。

保持有效草稿不因旋转、窗口缩放、功能切换或实时刷新丢失；账号切换是明确的清理边界。提供 VoiceOver 操作名、键盘和指针操作、动态字体与深浅外观支持。iPadOS 实际窗口与字体验收单独执行，网页原型不能代替。

### 3.3 列表组织与状态

未完成按截止时间升序，无截止时间的排在后面；同截止时间按创建时间升序、ID 升序稳定排序。无截止时间也按创建时间、ID 升序。全部先列出同样排序的未完成，再按完成时间倒序、ID 倒序列出已完成。

服务器分页，一页默认 50、最多 100 项。界面需要时显示「加载更多」，不增加第三个筛选标签、分组标题或独立统计卡片。改变筛选或收到变更后从第一页重新读取；普通进入重置为「未完成」。

首次加载显示现有加载组件。未登录显示登录操作，加载失败提供重试，空列表提供新建。已加载列表刷新失败时保留当前账号的内存内容并提示，不能清成空列表或将离线误报为零条。没有网络时禁止提交变更，不排队补写。

## 4. 数据模型与时间

所有以下名称均为拟新增契约。

### 4.1 待办条目

| 字段 | 契约 |
| --- | --- |
| `id` | 服务端生成的不可变 ID |
| `userId` | 服务端从认证身份确定，只在存储中使用，客户端不能指定 |
| `title` | 去除首尾空白后必填，最多 200 个 Unicode 码点 |
| `note` | 可选纯文本，最多 10,000 个 Unicode 码点，空值规范为 null |
| `dueAt` | 可选 UTC 瞬时值，允许已过去的截止时间 |
| `reminder` | `none`、`at_due`、`before_due` 或 `custom` |
| `offsetMinutes` | 仅 `before_due` 使用，允许 10、60、1440 |
| `remindAt` | 服务端计算或校验的 UTC 瞬时值；没有提醒时为 null |
| `reminderGeneration` | 时间或提醒配置变化时递增的提醒代际 |
| `reminderStatus` | `none / pending / sent / cancelled / expired`，分别表示无提醒、待触发、已触发、已取消、已过期 |
| `completedAt` | 未完成为 null；完成由服务器记录时间 |
| `version` | 初始为 1，每次实际变更递增，用于拒绝覆盖旧版本 |
| `createdAt / updatedAt` | 服务器时间 |
| `deletedAt` | 软删除标记，不返回到普通条目接口 |

完成历史持续保留，直到用户删除。删除的条目立即不可读取与编辑，内部墓碑保留 90 天后清理，以便处理提醒与重试；不提供恢复入口。通知仍沿用独立的 90 天保留规则，不将待办生命周期与通知生命周期混为一体。

### 4.2 日期、时区与提醒配置

截止日期包含时间，本版不提供另一种「全天截止」含义。界面按设备当前时区显示，API 接收带明确时区偏移的 RFC 3339 时间并规范为 UTC。旅行或切换设备时，已保存的瞬时值不变，显示转换为当前时区；夏令时变化由系统日期组件处理。

提醒默认关闭，截止时间不隐式开启提醒。`at_due` 使用截止时间；`before_due` 从截止时间减去指定分钟数；`custom` 可独立于截止时间设置。移除截止时间时，如果仍选择相对提醒，客户端与服务端都提示补齐或改选提醒方式，不静默改写。

新增提醒或改变提醒时间必须晚于服务器当前时间。用户输入精度为分钟，API 时间的秒与毫秒必须为 0；服务器拒绝过去的提醒。客户端校验用于即时反馈，不能替代服务端校验。已经触发或过期的提醒允许在只修改标题、备注时保留历史配置，不因此拒绝正常编辑。

AI 将相对日期解析为具体日期、时间和时区后调用 API；不能传「明天」等未解析文字。只说「周五」而没有截止时刻或提醒时刻时，先澄清时间，不擅自设置午夜或上午九点。

### 4.3 完成、恢复与提醒状态

- 完成取消尚未触发的提醒；已提交的账号通知属于历史，不撤回。
- 删除取消尚未触发的提醒；旧通知可继续保留，但目标访问返回统一的不可用提示。
- 恢复时，原提醒若仍在未来且该代际从未触发，重新启用；已触发或已过期的配置不自动补发。
- 编辑已完成条目不自动恢复状态，也不触发提醒。恢复后仍按上一条规则判断。
- 标题或备注变更不产生新的提醒代际；修改截止时间只有影响相对提醒计算时才产生新代际。修改自定提醒、相对提醒选项或关闭提醒会更新代际与待触发状态。
- 截止时间已过不等于完成；逾期项继续出现在未完成列表。

## 5. 服务端 API 与一致性

### 5.1 接口方案

复用现有 UserAuthGuard、集中校验、错误处理与 Prisma/PostgreSQL。新增的普通账号 API 不使用开放 API 密钥，不让桌面冒充服务端通知来源。

| 方法与拟新增路径 | 输入和结果 |
| --- | --- |
| `GET /api/todos` | `filter=pending\|all`、可选 `query`、`offset`、`limit`；返回 `items`、`nextOffset` |
| `GET /api/todos/:id` | 返回本人尚未删除的条目；不存在、已删除与非本人统一 404 |
| `POST /api/todos` | 标题、可选备注与时间、提醒配置、`clientRequestId`；返回创建后的条目 |
| `PATCH /api/todos/:id` | 字段补丁、`expectedVersion`、`clientRequestId`；返回新版本条目 |
| `PATCH /api/todos/:id/completion` | `completed`、`expectedVersion`、`clientRequestId`；返回新版本条目 |
| `DELETE /api/todos/:id` | `expectedVersion`、`clientRequestId`；返回删除结果 |

请求对象使用 strict schema，拒绝未声明字段。分页为 offset-based，`nextOffset` 为 null 表示读完；改变筛选或关键词后从 0 开始。分页期间变更可能导致重复或漏项，因此客户端按 ID 去重并在实时刷新时重读；不把分页宣称为冻结快照。

`query` 最多 200 个 Unicode 码点，在本人条目的标题与备注做不区分大小写的文本包含匹配；它供 AI 定位，不在已认可的界面里增加搜索栏。匹配必须先受账号和完成筛选约束，通配符作为普通文本处理。

补丁中字段缺省表示保留，null 表示清除可选值；标题不能清为 null。更新时间与完成操作不得通过普通字段补丁伪造。仅当完整候选条目有效时提交，不能先保存标题再失败于提醒字段。

### 5.2 并发、重试与身份

所有读写都在服务端按当前身份过滤。跨端编辑采用版本比较：`expectedVersion` 不匹配返回 409 与固定冲突码，界面保留草稿并提供重新载入，不能自动覆盖或自动合并时间配置；AI 重读后重新判断用户意图。

所有变更带稳定 UUID `clientRequestId`。同一账号、请求 ID 和规范化内容的重试不重复产生变更；同一请求 ID 对应不同内容返回 409。幂等收据与变更同一事务提交，收据保存 24 小时；客户端只重试这次原始请求，不为网络超时自动生成新 ID，也不在超过收据有效期后自动重放。创建记录另保留原始创建请求 ID，以防有效条目被重复创建。

重放响应不得将更旧的结果覆盖到内存：变更成功后重取当前服务器条目或第一页；按版本拒绝迟到的旧读取结果。保存前后都检查账号归属版本，退出、切换账号或取消读取后停止后续操作。普通凭据刷新不等于切换账号。

服务器在同一事务更新条目版本与提醒状态，事务提交后才发出拟新增 `todos.changed` 事件。事件只包含 ID 与版本，不含标题、备注或令牌，按账号发给桌面与手机；收到后重取相关视图。实时断线不妨碍有效 Bearer 认证的 REST 操作；进入页面、App 回到前台与连接恢复时补读。

## 6. 云端提醒与通知

### 6.1 触发与取消

服务端定时扫描到期、未完成、未删除、当前代际未触发的条目。正常扫描周期 30 秒，每批最多 100 项；实际设备呈现还受网络与系统调度影响，不承诺精确到秒。服务中断后，只补偿仍为待触发且到期未超过 24 小时的配置；更旧的标记为已过期。此补偿不重新启用被用户完成、删除或取消的提醒，也不改变恢复事项不补发过去提醒的规则。

触发事务重新锁定条目并复验账号、完成状态、删除状态、提醒代际和时间。只有复验通过才同时创建账号通知、标记该代际已触发并写入持久投递 outbox。提醒状态变更同样推进条目版本，提交后发布 `todos.changed`，编辑中的旧版本继续按冲突规则处理。outbox 不在客户端运行，事务内不得执行 APNs 或网络请求。

完成、删除与触发通过同一条目锁串行判定：完成／删除先提交，则不创建提醒；提醒先提交，则通知保留为已发生的历史。失效工作、旧代际和并发 worker 均不能重复创建通知。通知使用稳定 `sourceKey=todo:<id>:<generation>` 并依赖账号内唯一约束去重。

outbox 在提交后投递、失败时后台重试；重试复用同一通知 ID，不能再创建记录。进程崩溃后重扫未投递记录。APNs 请求发生于事务外，不能保证物理横幅严格恰好一次；使用稳定标识减少重复，验收区分一条账号记录与系统横幅。从原提醒时刻起超过 24 小时后停止外部投递重试并记录固定失败原因，账号通知仍可读取。已经读过或删除的通知不重试外部横幅。

### 6.2 现有通知边界

拟新增来源 `todo-reminder`，由服务端拥有；只扩展共享 `NOTIFICATION_SOURCES`，不加入 `DESKTOP_NOTIFICATION_SOURCES`。它不属于终端待处理，不通过 System Notifier 的发送接口再造一条通知。

通知标题为「待办提醒」，正文只包含事项标题，不复制备注；`targetId` 为待办 ID，使用普通 `active` 级别。沿用账号未读、删除、90 天保留与实时变化语义；桌面原生呈现仍交给现有 System Notifier，本机通知及静音开关继续生效。手机沿用已有生产 APNs 和系统权限，不使用 Critical Alerts 或默认突破 Focus。

所需改动只为待办新增事务内通知创建及提交后的投递边界，复用现有通知服务与网关；不重构其它通知来源或改变它们的成功语义。

### 6.3 目标定位

拟新增桌面与 iOS 路由 `synapse://todos/<id>`，只接受一个合法 ID，不接受附带的账号、标题、任意 URL 或修改指令。打开不会自动完成、删除或改写事项。

桌面从消息中心通知条目打开，iOS 从通知条目或系统通知打开；桌面原生横幅保持现有 System Notifier 单向呈现，不新增点击回调。点通知先按现有规则标记通知已读，再按当前账号读取待办。未完成目标在默认页定位，已完成目标切到「全部」并打开该项；该目标入口是普通进入默认未完成的唯一例外。已删除、无权限或不存在显示「事项已删除或无法访问」，返回列表，不泄露其他账号信息。

冷启动等待现有账号就绪；未登录先完成登录。后续用户导航或账号切换取消旧目标，迟到请求不抢回页面，也不操作选中电脑或终端。客户端启动后按通知 ID 重取目标，不仅依赖 APNs 中的提示文字。

## 7. AI 与能力注册

新增 `todos` capability domain。拟注册六个规范 action：

| Capability | MCP 索引名 | 含义 |
| --- | --- | --- |
| `app.todos.item.list` | `app_todos_item_list` | 按状态、关键词分页检索本人条目 |
| `app.todos.item.get` | `app_todos_item_get` | 精确读取，接受 ID 或完整待办路由引用 |
| `app.todos.item.create` | `app_todos_item_create` | 创建条目及可选提醒 |
| `app.todos.item.update` | `app_todos_item_update` | 带版本修改字段 |
| `app.todos.item.set_completed` | `app_todos_item_set_completed` | 带版本完成或恢复 |
| `app.todos.item.delete` | `app_todos_item_delete` | 带版本删除明确指定的条目 |

公开 MCP 继续只有 `search` / `invoke` 路由包装工具；上述名称属于检索索引，不直接加入 `tools/list`。IPC 使用同语义 operation id，preload 提供窄而类型化的 `window.synapse.todos.item.*`，主进程复用账号认证网络客户端与同一 API，不直接访问本地 Database。

系统 Skill 新增待办领域索引和 API 指南，并同步 Agent 指南。列表工具准确说明 offset 分页、`nextOffset`、UTC 时间与权限；修改工具准确说明版本和幂等请求 ID。

AI 创建时确认标题和时间含义；明确且已获授权的创建、完成、编辑或删除直接执行。修改或删除已有项先检索、精确读取并使用当前版本；多项同名、相对时间含糊或请求范围不明确时澄清，不按第一个搜索结果猜测。查询不改变完成状态、不设通知已读、不自动打开 UI。

已授权的「把提交报销单标记完成」「删除续费域名」无需额外的形式确认；它们仍须唯一定位并经过既有权限闸门。冲突或失败如实报告，服务端接受提醒只表示配置已保存，不声称手机已弹通知。

注册时同步 `docs/agents/capability-registry.md`：新增一个 System App、用户可固定 Dock 表面、六个 MCP 索引能力和一条桌面路由；iOS 路由另行计数。此设计阶段不修改现有注册数量，不为未实现能力添加“已提供”描述。

## 8. 实现边界与复用点

| 单元 | 责任与已核对的现有入口 |
| --- | --- |
| 服务端待办模块 | 新增 `server/src/todos/`，归属校验、分页、字段校验、版本与幂等事务；模型与迁移沿用 `server/prisma/` |
| 提醒 worker | 待办模块内调度与 outbox；复用 Nest Schedule、`server/src/notifications/notification.service.ts` 和现有 Live/APNs 网关 |
| 共享契约 | 在 `shared/src/` 声明待办 DTO、事件与时间规则；通知来源由现有 `shared/src/notifications.ts` 单点扩展 |
| 桌面适配 | 新增待办能力包与 dispatcher；复用 `desktop/electron/services/account-service.ts` 的认证请求，不复制 refresh 或 Authorization 注入 |
| 桌面界面 | 新增 `desktop/src/modules/todos/`，展示组件、表单与请求状态按责任分开；复用当前 System App 宿主、Card、表单及通知目标入口 |
| MCP 与 Skill | 按现有 domain registry 注册；扩展 `desktop/app-capabilities/synapse-skill/skill-package/`，更新检索索引与指南 |
| iOS | 新增待办业务 model 与系统界面；复用 `Core/Networking/APIClient.swift`、主页 `HomeRoute`、RootView 导航和现有 NotificationRouter |

本设计没有扩展开放 API 密钥的 scopes、部署环境变量或对象存储域。待办是 PostgreSQL 文本记录，随现有数据库备份；不需要 COS 文件、桌面数据迁移或本地数据导入。日志与审计只记录账号/条目 ID、操作、版本与结果，不记录标题、备注、推送正文、完整请求体或凭据。

## 9. 验证与上线

实施计划按服务端数据与 API、提醒与通知、桌面/MCP/Skill、iOS、整体验收划分可验证任务，各单元有清楚的输入输出和集成检查；本文件不是执行步骤清单。

| 验收类别 | 必须证明的行为 |
| --- | --- |
| 账号隔离 | 另一账号无法读、改、删或触发本账号条目；切换账号后迟到结果不回填 |
| 手动操作 | 默认未完成、白色 PC 列表卡片、增改删、完成、全部恢复、失败保留草稿 |
| AI 操作 | 同一账号 API、唯一定位、歧义澄清、版本冲突不覆盖、准确分页 |
| 时间 | 自定提醒可无截止时间；相对提醒缺截止被拒绝；服务器拒绝新设过去提醒；跨时区与夏令时显示正确 |
| 并发与重试 | 两端同时保存只有一个版本成功；超时重试不多建条目或通知；旧响应不覆盖新版本 |
| 提醒竞争 | 完成／删除与触发的两种提交顺序；多 worker、进程重启、旧代际、恢复已提醒项均不重复造通知 |
| 云端链路 | 电脑关闭时提醒仍触发；消息存储成功与横幅呈现区分；生产 APNs 配置不变 |
| 目标导航 | 桌面、手机、冷启动、未登录、已完成及已删除目标；旧跳转不打断用户新导航 |
| 原生适配 | iPhone、iPadOS 窗口缩放、动态字体、VoiceOver、深浅外观、键盘／指针，最低 iOS 18 |

产品实现后运行对应服务端/桌面专项测试、typecheck、desktop `check:hard-constraints`；触及打包边界时增加 `check:packaged-asar`。iOS 运行实际工程构建、业务测试与原生验收；业务单测不能代替设备界面与真实推送验证。

上线按数据库迁移与服务器、桌面端、iOS 顺序。迁移只新增相关表、列和索引，不清理现有用户数据。旧客户端继续处理已有通知来源；新客户端对旧服务器未提供接口给出明确升级提示，不能显示伪造空列表或改用本地存储。发版与部署沿用现有命令，仅在收到相应授权后执行。

产品实现同次更新 `RELEASE_NOTES_PENDING.md`、模块长期边界、能力注册清单、移动运行时约束、通知来源文档及系统 Skill。当前仅固定设计，不改运行时代码或待发布说明。
