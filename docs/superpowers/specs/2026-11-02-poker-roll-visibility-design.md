# Roll 玩家信息与决策界面

日期：2026-11-02。状态：用户确认设计后授权实施，并在实施中明确调整为「不直接显示，点击每个玩家区域弹出信息」。本文件以最新要求为准，之前的常驻摘要/座位数字方案已撤销。

## 目标与选择

- 牌桌不增加常驻换牌统计，不给座位追加次数/花费文字。
- 玩家区域整体可点击，键盘可聚焦并通过 Enter/Space 打开标准 HeroUI 玩家信息 Modal。
- 信息中显示玩家名称、座位、可用资金、状态、个人本手/房间换牌次数和支出；下方显示全桌本手/房间合计。房间累计覆盖建房以来全部牌局且包含本手。
- 换牌确认和超级三选一均保留公共牌、未发空槽、阶段、原剩余时间及本人手牌，便于对照决策。

## 交互与呈现

- 玩家信息与日志、牌型说明、下注、管理及 Roll 选择面板共用父级互斥。关闭/Escape 返回座位触发焦点，不提交动作或改变控制权。
- 账号/房间切换、目标座位消失或该座位换人时关闭旧信息，不能展示到新账号上下文。实时快照更新当前玩家统计，不维护浏览器累计账本。
- 维持现有顶栏、三场景 contain、座位坐标与底栏，不为统计改变几何。系统弹窗使用 HeroUI v3 默认浅色，牌面复用真实素材，必要数字不裁切。
- 长姓名放在 Body 中，正文有界滚动，Header/Footer 保留默认间距和固定操作。
- 换牌选项收紧留白，选中标记与文字并用，费用显示实际筹码/点数单位。费用说明：「费用不计入底池，分给其他未弃牌玩家，本手结束到账。」

## 数据和边界

- table.state/room.get追加可选rollStats：hand/room总量，以及最多10个当前/历史回显座位对应账号的hand/room汇总。不新增输入参数或工具。
- 服务端合并GamePokerRoll与不可变归档，以唯一Roll ID去重并按账号归属；每个成功start计一次，choose仅完成原记录。换座/重进不重置，同座位换人不继承。
- 不公开额外账号ID，key为房间作用域账号散列；不添加候选、旧牌、指定旧槽、私有提示词。旧响应缺统计显示不可用，不伪造零。
- 不改变玩法、价格、补偿、原倒计时、控制版本、幂等、未知请求恢复。无依赖/数据库迁移/发布说明增量，不部署、不push。

## 验证与授权

在当前仓库main原地开发，不切分支或worktree。用户允许无头Chromium固定数据验收；不连接业务库。服务端包含独立临时PostgreSQL单用户离线SQL测试，自动清理自建测试目录，没有端口监听或现有数据库访问。覆盖热冷去重、同账号重进、同座位换人、超级完成、总量与当前座位限定；UI覆盖点击各玩家、互斥、焦点、长内容、账号切换和公共牌。
