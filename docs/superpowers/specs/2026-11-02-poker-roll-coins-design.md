# Roll 每手金币

2026-11-02 用户批准实施。当前仓库、当前分支原地开发，不切分支、不创建worktree，不部署、不push，不记录发布说明。

## 规则与存储

启用Roll的新手牌在引擎RollState保存coinPolicy={limit:12,normal:1,super:3}。各参赛者从本手全部成功start历史按档位计算余额；不增加可漂移的余额计数或数据库字段。normal/super扣1/3金币，筹码仍按roll-v1递增加价、费用独立补偿、支付后至少留1筹码。最多12次普通、4次超级或等额混合。跨街不恢复，下一手重新12；刷新、重启、接管、离桌/回座不补充。无购买、转让、兑换、金币盈亏或房间配置。

旧手缺coinPolicy沿旧规则完成，不从当前配置推断或追扣；旧响应隐藏金币信息，现有房间下一手启用。原牌/候选隐私、原倒计时、控制权、行动资格不变。金币快照损坏或透支显式拒绝，不默默补足。

金币校验、抽牌、筹码扣费和补偿同事务。失败无副作用，余额不足代码POKER_ROLL_INSUFFICIENT_COINS；同UUID不重复扣费，并发由原房锁/行动序号保护。超级待选允许原槽付费重抽，旧候选仅成功后作废，金币/筹码不退；每次重抽都计入消耗。余额耗尽仍可免费选择当前已付候选，不能继续新Roll；超时照原首候选及超时动作处理。

## 接口与界面

RollQuote/PokerRollView增加可选coins={balance,limit}，RollOffer增加可选coinCost。table.state及wait本人报价共享引擎，待选wait额外含roll报价；请求参数不变，不增加工具/路由/迁移。公开视角不追加本人金币报价或候选。机器人继续依可用报价行动。

保留既有入口，正常文案为“Roll · 金币 9/12”；待选/未知分别优先“完成换牌”/“核对换牌”。HeroUI浅色Modal顶部显示本手余额，保留公共牌、阶段和倒计时。两档显示“1/3金币 + 当前筹码/点数费用”；确认区显示双项支出和扣后余额，按钮“确认换牌”。待选面板保留三张牌及免费选择，另显示普通/超级重抽及双项费用。余额0/不足3/筹码不足分别说明，不仅靠颜色；禁用不阻止打开查看原因。

不增加常驻信息行、商店或进度条。数字等宽，费用和原因可换行，Body滚动，Footer固定可见，保持面板互斥、原画布几何及键盘焦点。建房开关说明“每手12金币，普通1／超级3；另付筹码”。旧响应沿旧文案，不伪造余额。
