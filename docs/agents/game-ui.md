# 游戏 UI：系统外壳与局内界面

## 新版能力牌桌

- 新建卡牌房使用 `cards-v2`。建房仅保留卡牌模式开关。已有 `cards-v1` 和 Roll 房沿用各自的规则快照和对应界面。卡牌房仅限真人通过同源 Web 会话操作，机器人只做普通行动。
- 同一底栏中，本人底牌固定在能力牌左侧并保持静态。两类牌等高、同圆角，保留边框，牌面平铺。玩家底栏保留行动按钮和金额选项，无行动权或该项不可用时禁用按钮并关闭金额面板。能力牌仍可悬停或聚焦查看完整牌面、规则和现价。桌面手牌跨过白色底栏上沿，窄屏能力牌可横向滚动。
- 本人行动时把牌拖入桌面。每张牌通过定义声明取消边界和结果类型。换牌术、左右逢源、明察秋毫可在确认目标前退出。五选其一在出牌时承诺费用，左右逢源在确认目标时承诺费用；候选亮出后必须选择，重新载入从本人服务端状态恢复。先知之眼和明察秋毫在确认用牌后才给出私密结果。关闭结果只结束展示。
- 目标、候选、确认按钮和结果在居中的同一舞台组内。费用随本手状态更新，目标确认前可重看变化后的报价。右侧窄轨无底色、左边框和顶部图标，从新到旧显示公开行动图标与能力牌封面，长列表可纵向滚动。单项悬停显示白色圆角背景，悬停、聚焦或点按时详情锚定触发项并避开视口边缘。候选和私查结果仅出现在获准的本人舞台内。

以下旧建房选项、Roll 和暂存行为只适用于存量房间及对应规则版本。

2026-11-02 对局信息：牌桌顶部入口由“日志”改为“对局信息”，固定“日志 / 总览 / AI”三个Tab。日志仅按阶段合并实际盲注、普通行动及成功Roll start，不含累计指标、玩家汇总、资产或完整结算；choose只更新原Roll状态，不新增收费。总览复用本手potContributions/rollLedger，按原参赛身份展示累计下注、普通/超级次数、支出和补偿，可展开各轮投入；缺字段显示不可用，不从recentActions或近期事件推算。完整结算仅在总览；AI判断/提示词仅本人视角且已入座可见，其他视角显示不可用。身份、房间、手牌、视角变化重置Tab，保留面板互斥、焦点返回、画布和850px行为。

table_state/room_get可选公开handLog={handId,complete,entries}，绑定当前手牌。entries按seq排列，仅含seq/seatNo/displayName/street/action/amount/isAuto/actionSource及可选roll={kind,count,status}；street为preflop/flop/turn/river，action为small_blind/big_blind/fold/check/call/bet/raise/allin/roll，金额为实际追加或Roll费用。seq=-1/0为按本手初始筹码与规则恢复的实际小/大盲，正数沿用动作序号；choose不生成第二条，序号可有间隔。roll.status=pending/completed/replaced/cancelled，分别为待选/完成/被重抽替代/手牌取消，取消不表示费用到账。查询只取本手最近最多1000条原始动作，完整时额外含两笔盲注（最多1002项）；complete=false表示截断或缺口，不附加盲注，也不能算整手或各轮完整下注；缺字段表示不可用。姓名只取本手参赛快照，不公开userId/admissionId、底牌、候选、旧牌、槽位、note或persona。保留原recentActions最近30条普通行动及本人AI隐私；既有table.state/room.get只读扩展，无新工具、输入、路由、权限、迁移或写入。


2026-11-02 底池来源：既有底池标题、金额和筹码堆作为同一个可键盘操作入口，打开最大宽800px的标准HeroUI来源面板，按本手玩家展示累计投入和占比，保留已弃牌者投入，包含实际盲注和各轮下注，不含Roll费用。公开可选potContributions只从本手引擎累计投入或完整归档动作/原始盲注投影，使用本手参与者姓名及不透明身份，不以当前占座者/余额或最近30条动作推算。进行中显示当前底池，结算/取消后明确显示本手累计投入及状态，缺字段显示暂不可用。与Roll费用/玩家/日志等面板互斥，换手/房间/账号/视角关闭旧信息，关闭/Escape返回入口；保留原生Modal留白、正文滚动和既有动画锚点/结算屏障。没有新增收费、查询、路由、工具、迁移或发布说明。

2026-11-02 Roll费用明细：牌桌既有Roll费用标签、金额和筹码堆作为同一个可键盘操作入口，打开标准HeroUI浅色Modal，最大宽800px。来源与去向按本手真实成功start记录分别汇总，点击玩家筛选逐笔支付/补偿，可展开原分配；窄屏单列、正文滚动、Header/Footer保留原生留白。明细只读且不改变资金、钻石、控制权或倒计时；补偿资格与金额固定于扣费时，之后弃牌仍保留记录。显示待结算/已结算/已取消，取消的练习补偿不声称到账。table.state/room.get追加可选公开rollLedger，由热历史或归档与本手参与者快照白名单投影，不公开账号ID/入座ID/私牌；缺字段显示暂不可用，不从截断事件或当前占座者推算。账号、房间、手牌和视角切换关闭旧信息，接入既有面板互斥，关闭/Escape返回入口焦点。无新工具、接口、查询、数据库迁移或发布说明。

2026-11-02 钻石图标：Roll资源统一称为“钻石”，采用有透明高光与明暗切面的蓝色钻石SVG，覆盖入口、余额、费用、扣后余额、建房字段及不足/错误提示。复用PokerDiamondText，图形按周围字号缩放并使用主题token；隐藏文字与读屏单位同步为钻石。内部rollCoins/coins/coinCost/coinPolicy及错误码保留兼容，计费和存储规则不变。

2026-11-02 房主开局规则（取代历史自动开局描述）：首局房主免准备，其他可参与者准备后由房主手动开始；后续每手结算后房主也须准备，准备成功后返回牌桌，待全员准备再由房主手动开始。结算面板不提供开始入口。入座、最后一人准备、回座、离桌、机器人管理和后台调度均不自动发牌；程序陪练仍自动准备，真人点击准备、AI显式seat.ready。首局准备与开始的handId为null，后续绑定当前结算handId；控制版本和原控制权限不变。新增app.game.poker.room.start（Web POST /game/poker/rooms/:code/start），只允许房主显式调用，已入座房主须持当前控制权；旧请求过期必须重读，不得盲重发或凭继续意图自动开始。复用座位status=ready，不新增数据库字段或迁移。

Roll钻石余额只附在本人现有入口及HeroUI确认/待选面板，入口和弹窗仅显示钻石图标与当前数量，不显示Roll前缀、本手标签或余额上限。图标和数字用同一inline-flex行居中对齐；普通费用显示1颗图标，超级显示3颗图标，再接筹码/点数费用，费用行在选项底部对齐。删除底部支付及扣后余额摘要，不新增常驻信息行或进度条；待选面板提供原槽普通/超级重抽，按钮按余额和资格禁用，不在按钮下追加不足原因提示；余额耗尽仍保留免费选牌和原请求核对。原因和费用可换行，Body滚动、Footer操作可见，沿用面板互斥、三场景几何及焦点规则。详见 `docs/superpowers/specs/2026-11-02-poker-roll-coins-design.md`。

2026-11-02 钻石额度更新：建房可通过ruleOptions.rollCoins设置每手钻石，默认12，必须为1至2147483647之间的整数；创建后额度固定。普通/超级消耗固定1/3钻石，不提供费率配置；额度1或2时超级因钻石不足禁用。启用Roll的新手牌保存coinPolicy={limit:房间额度,normal:1,super:3}，各参赛者按本手全部成功start历史计算余额，跨阶段不补充、下一手恢复房间额度。刷新、重启、接管、离桌/回座不补充；仍另付筹码及冻结补偿，无购买、转让、兑换或钻石盈亏。旧房间缺rollCoins按12，旧手缺coinPolicy的历史兼容规则不变。

旧手缺coinPolicy沿旧规则完成，不从当前配置推断或追扣；旧响应隐藏钻石信息，现有房间下一手启用。原牌/候选隐私、原倒计时、控制权、行动资格不变。钻石快照损坏或透支显式拒绝，不默默补足。

RollQuote/PokerRollView增加可选coins={balance,limit}，RollOffer增加可选coinCost。table.state及wait本人报价共享引擎，待选wait额外含roll报价；建房请求增加可选ruleOptions.rollCoins，不增加工具/路由/迁移。公开视角不追加本人钻石报价或候选。机器人继续依可用报价行动。

2026-11-01 用户确定的长期方向：游戏作为内容运行在一个系统框架内。系统 UI 与游戏内部 UI 是两套完整的视觉体系；运行中系统面板按需出现。规则适用于游戏中心及后续接入的游戏；Dashboard 的系统实现基线为 HeroUI v3 默认浅色，详见 [Dashboard 规则](../../dashboard/CLAUDE.md) 与 [DESIGN.md](../../dashboard/DESIGN.md)。这里的“系统”是产品的功能外壳，不要求模拟 Switch/macOS，也不要求常驻边框或加载 Console Layout。

2026-11-01 后续用户批准每手结束展示完整 HeroUI 结算，并要求全员准备后续局，取代历史的五秒自动续局。程序陪练自动准备，AI通过MCP显式seat.ready，真人点击准备；关闭面板、查询和回座不准备。全员指有筹码且未暂离/待离桌的实际座位，新加入者也需确认。正文有界滚动，长内容换行，操作固定于原生Footer，不裁切或隐藏玩家金额；底池、返还和净盈亏分开。详见 `docs/superpowers/specs/2026-11-01-poker-settlement-ready-design.md`。

## 职责边界

| 系统层 UI | 游戏层 UI |
| --- | --- |
| 游戏中心、游戏入口、账户点数、补助、跨游戏会话 | 游戏场景、棋盘/牌桌、角色、卡牌、筹码等玩法对象 |
| 房间发现、创建、加入、等待/准备、房间配置和成员管理 | 当前回合、行动对象、剩余时间、血量/筹码等局内 HUD |
| 排位/榜单（若新增）、战绩、历史详情、选手档案与版本对比 | 直接玩法操作，如移动、出牌、弃牌、过牌、跟注和下注按钮 |
| 暂停菜单、设置、导航、音效开关、视角切换、提醒入口 | 玩法内选中、行动提示、局部标记和即时胜负反馈 |
| 日志/完整结算、AI 判断/提示词、机器人管理、入座/暂离/离桌、真人/AI 接管 | 发牌、翻牌、筹码流转、收池及与玩法同步的动画和音效 |
| 功能侧栏、弹窗、输入表单、参数滑块/预设、通用确认与加载/错误/重试 | 与场景直接关联的短结果摘要和状态提示 |

判断的是用户正在做什么，不是页面 URL、是否正在游戏、组件是否浮动或是否位于画布里。牌桌中的日志侧栏仍然是系统；画布外的弃牌按钮仍然是游戏。房间等待/准备页用系统 UI；已在牌桌上的“等待对手”、回合暂停原因等简短 HUD 可以继续用游戏表达，不要求新建等待页面。

扑克金额面板与全下确认属于系统：下注/加注主按钮保留玩法视觉，打开的金额输入、滑块和预设组成统一系统表单，全下使用系统确认。宽屏内嵌与窄屏浮层遵守同一视觉归属。打开金额面板不等于提交下注，确认步骤与未知结果重试语义必须保留。

## 呈现与实现约束

- 2026-11-02 建房带入额固定为1000/5000/10000/50000，点数/陪练均由服务端校验；数据库约束通过`20261102100000_game_poker_buy_in_presets`兼容新档位，同时保留历史500/2000及10座房的有效性，不改写存量房间或资金。迁移事务内原子替换`GamePokerRoom_rules`，锁等待5秒、执行30秒超时；生产执行前须备份并预演。已有新档位房间时不能直接恢复旧约束，应保留扩展约束或先明确处理这些房间，不自动改金额。
- 2026-11-02 结算全员列表按当前视角可见的最佳五张牌力降序排列，复用服务端标准/短牌判牌与踢脚比较；平手保持原顺序，无可比较牌型但可见手牌的玩家随后，未公开手牌置末。只在隐私投影后排序，不使用隐藏牌或净盈亏决定顺序。结算面板不显示准备名单、人数及等待提示，底部显式准备/接管操作与错误反馈保留，牌桌原有准备状态不变。
- 2026-11-02 扑克筹码采用已确认的实体筹码样式：面额1/5/10/25/100/200/500固定配色、同色连续分组和稳定错落堆叠；玩家前方显示剩余筹码。每笔追加独立拆分后累积，原始库存不按池底总额换大面额。静态堆和飞行展示超过200枚目标时等值整理，先用不大于500的面额，仍超限才反推最少1000筹码（显示1k）；最大面额仍放不下时允许超过目标，所有金额完整绘制，不截断或显示“面额×数量”文字。1k只属于绘制类型，不改公开库存schema和资金核对。普通下注直接飞入底池，Roll start费用进入独立堆，choose不重复入池。普通shares/返还派发后再派Roll补偿，展示余额落地才增加；筹码与逐位滚动金额全部完成后才能打开原有HeroUI结算。首次已结算、断流恢复、换手/身份/视角/布局只建立基线，减少动态效果即时完成。`chipState`只读公开展示投影，不参与资金、控制或准备裁决；详见 `docs/superpowers/specs/2026-11-02-poker-chip-presentation-design.md`。
- 2026-11-01 后续用户批准的 Dashboard 当前方向为亮色虚拟对局场：浅灰背景、白色抽象对局区、蓝色行动强调，移除深绿毛毡、厚桌沿、缝线和金色装饰，保留真实牌面与局内音画反馈。本节取代下文历史记录中保留旧材质和常驻右栏的描述。
- Dashboard 宽窄屏统一底部操作条，等待时仍保留其高度；日志/AI 判断/成员使用覆盖主区域的按需面板，开关不挤压或重挂画布。850px 边界控制紧凑顶栏与房间/会话单列呈现；下注/加注使用底栏常驻的最小、半池、一池档位和带金额的明确提交按钮；档位只选择，自定义在真实按钮上方展开，保留全下确认。未入座直接显示本人入座和接入 AI。
- 房间与进行中会话按各自容器宽度适配：850px 及以下使用独立 HeroUI Card 列表，宽屏保留原生 Table；不把表格行/单元格改成网格，以免保留单元格背景、圆角和阴影形成白块。两种呈现共享房间状态与操作权限，长房间名可换行，窄屏保留类型、人数、带入/盲注、倒计时和独立操作。
- 移动端覆盖320px竖屏及568/667px短横屏：大厅大金额、预览与插画受内容宽度约束；记录/档案的连续长文本可换行，实际窄容器中的对比使用独立系统卡片。低矮窗口保留可读画布最小高度，在牌桌主区内滚动，首次测量和尺寸变化居中；开关面板不重置主区尺寸或重挂画布。底栏保留最小高度并随操作换行增高，短横屏压缩顶栏留白；结算摘要固定两行并预留结果区，完整结算金额逐项显示。Roll短横屏沿用原生Dialog留白，通过容器可用宽高保留候选正文和页脚操作；待选牌不得阻止本人接管。
- 2026-11-02 用户要求还原本轮字号改动：横向场景沿用原HUD/座位状态24/22px、姓名/筹码20/28px配置，紧凑规则文字沿用原text-sm；窄屏卡片沿用原表格的对应正文/说明字号。继续通过换行、可收缩容器和滚动适配，不为满足缩放字号阈值再次放大横向场景文字。
- 三场景使用各自坐标和字号，整体 contain 缩放，不逆缩放局部文字。当前下注锚点并入座位反馈行，筹码动画仍测量真实 DOM；净结果替代重复状态，完整分池记录留在日志。390px 验收下关键 HUD/座位状态至少12px、筹码至少14px，覆盖390×667与390×844。结果栏始终预留空间，不遮顶部座位。
- `PokerSeatView.isHistorical` 表示仅供上一手回显的历史座位，不能参与管理或容量判断；`inCurrentHand` 按座位与账号共同匹配，false 时不绘制已拿牌，新座位显示下一手加入。两个字段可选，旧响应不推断参与状态；机器人管理必须具有有效 botId，待离桌的当前座位继续占位。
- 单次座位操作收到写入成功后关闭更多菜单；成员面板的连续机器人增删保持打开，成功更新列表、失败保留重试上下文。后续刷新失败明确提示操作已完成，不误导重发。窄屏牌局记录选择后进入同页详情，返回恢复列表滚动与焦点；大厅默认预览明确标为点数牌局。

- 首局无真人入座的陪练房主先进入系统准备页，选择机器人数量及本人/外部 AI 参与方式。先按现有 bot.add 顺序配齐阵容，再入座或申请外部 AI 接入；部分成功保留，未知响应复用创建标识，账号/房间切换与卸载停止后续写入。点数房和已经开手的房间不拦截。
- 成员管理使用顶部直接入口，桌面 Popover、850px 及以下 Drawer；统一成员身份、机器人增删、满员与延后生效状态，日志中不再承载陪练管理。暂离、AI 控制、旁观及等待接入状态提供直接恢复/复制/取消操作；手中暂离和离桌持续显示本手后生效。
- 金额自定义面板以底栏真实按钮为锚点就近向上展开，碰撞时在视口内避让；只放金额输入、范围、追加额、滑块和全下入口，不重复牌面、决策摘要或提交按钮。底栏高频档位只选择金额，主按钮明确提交；等待时保留工具栏所需高度。短窗口面板可滚动，主操作始终在底栏，关闭返回触发焦点、保留本轮金额；不得扩大暗牌读取或因开关面板挤压/重挂画布。当前方案取代此前固定右侧及表单内重复摘要的要求，见 `docs/superpowers/specs/2026-11-01-poker-nearby-betting-design.md`。
- 点数房入座按钮显示带入点数，入座前显示本人可用点数及读取失败重试；资金和容量仍由服务端裁决，不加重复确认。首局等待明确尚缺人数，暂离与缺筹码分别提示，不把未开局称为下一手加入；等待区提供复制房间链接的邀请操作，不自动发送、入座或扣点。入座/等待底栏按内容高度适配，运行中的玩法操作条维持原尺寸，展开系统面板不改变画布几何。
- 列表与牌桌统一 HeroUI AI 接入面板，明确“允许 AI 接入并复制指令”，已授权后只复制，失败保留已确认授权并可取消；完整 Agent 指令按需展开。关闭面板不撤销请求，房间列表通过服务端本人 myControl 投影持续显示等待或 AI 控制；复制、取消和接管均不绕过现有版本协议。账号/房间切换或卸载后的迟到响应不得继续写入、复制或刷新新上下文。

- 系统层复用所属子包的共享组件、语义 token、字体、间距、按钮与表单规范；Dashboard 使用标准 HeroUI 默认浅色，禁止扑克材质、游戏专属字体和自制游戏按钮进入系统控件。无需为每款游戏另造一套系统皮肤。
- 局内层允许作用域内独立的游戏美术、布局、HUD、按钮、动画与音效。不能用统一系统 UI 为由将牌桌、牌面或直接玩法操作整体改成后台表格/表单。
- 常态游戏只保留必要 HUD、玩法操作和系统入口；系统面板按需展开，关闭后继续呈现游戏。大厅、房间等待、记录等系统页面可完整占据页面；不强制增加常驻系统侧栏或边框。
- 同一空间可以承载两层，但必须区分表面与职责，不能把日志、管理和玩法按钮包在同一游戏皮肤面板中。无需仅为视觉分层更换业务状态所有者或新增并行业务逻辑。
- Portal 挂载位置只决定定位，不决定皮肤。系统浮层即使在游戏节点内，也必须隔离继承的颜色、字体、CSS 变量及选择器；不能通过覆盖 HeroUI 的 overlay/accent 等 token 将其游戏化。底层复用 HeroUI 不代表视觉已合规。
- 游戏插画、缩略图和真实牌面可作为系统页面里的内容，外层标题、状态、列表、按钮和表单仍是系统 UI。结果也按用途区分：桌面即时赢家反馈属于游戏，日志/历史的完整结算属于系统，牌面内容可复用。
- 系统层的操作入口/状态不能擅自改变玩法。打开菜单不自动暂停服务端倒计时，不离桌、不交接控制权、不隐式出牌；保留账户隔离、权限、隐私投影、控制版本、幂等、未知写结果及全下确认。
- 牌桌顶栏右侧提供“牌型大小”弹窗，按当前房间 variant 显示从大到小的排序和最小顺子；标准牌葫芦大于同花，32 张短牌同花大于葫芦。与结算页复用说明，纳入现有面板互斥，不因点数/陪练或 Roll 开关改变牌型排序；仅查看，不暂停牌局。
- 后续实现继续满足现有 850px 响应式规则、三场景 contain 等比缩放、面板互斥、焦点返回和窄屏主要操作不被遮挡；系统层不随游戏坐标缩放。关闭面板不得重挂游戏或重播历史音画。
- 验收需覆盖大厅/等待等系统页、纯局内状态、系统面板打开/关闭，以及宽窄屏、键盘、焦点、表单状态和主题隔离。仅源码阅读不能声称已完成视觉验收。

- 底栏卡牌按钮打开专用游戏覆盖层（用户于 2026-11-03 确认原型后授权实施），替代卡牌 HeroUI 面板；此例外仅限卡牌玩法，不改变 Roll、金额、管理等系统面板。目标由服务端 schema 列出；明确确认才施放。驱散/净化选项显示玩家或全场、剩余次数，实体标记显示当前持有者和底牌槽位；同名同状态实例另列序号，不用 UUID 或暗牌面帮助辨认。公共牌、原剩余时间、名义代价/豁免/实付、私密情报与公共状态分区显示。待选可关闭重开；公开视角无能力持牌/候选/情报 DOM。私人抽卡落空仅显示给本人，防护阻挡只显示安全公共反馈；星光消费实时公开根帧短暂展示，按帧去重、重连基线不补播、身份/手牌切换清理，减少动态效果时保留静态星形与结果。
- 卡牌舞台提供本人底牌、玩家、对手暗牌槽位、颜色、能力材料、公开效果、扑克牌候选、能力牌候选八类通用选择；服务端定义的 choices 决定流程，UI 不按卡牌 ID 分支。能力定义可选 `consumeSelected` 仅随获准的本人定义返回：true 为额外消耗，false 为复制且原牌保留，旧响应缺字段时不推断用途。不可主动施放的卡仍可作为合法材料；同名材料另列序号，效果沿用服务端的持有者/槽位/次数/实例序号。更换上游选择清除下游；撤回选项立即失效。
- 同一行动点内，从已确认的出牌记录展示本次结果；抽牌、抵挡、筹码和持续状态反馈留在舞台。私密情报、换后的底牌和已公开底牌直接呈现，本人情报仍保留历史。扑克牌候选先显示替换槽位和原牌，确认后展示结果。无目标、无材料、暂存不足、牌池空和阶段限制各自说明原因；颜色换牌落空或已达时间上限未能延时，均仅向本人说明。
- 舞台覆盖牌桌根节点，不挤压或重挂画布；顶部公共牌和原倒计时固定，待选确认留在底栏。用牌详情的返回和使用按钮紧跟规则与目标选项。左卡按中间高度适配且居中，只有右侧详情纵向滚动。窄屏保持左右布局，手牌/材料/候选可横向浏览，超过五张手牌分组。完整牌效桌面 18px、窄屏 16px；候选能力牌预选后也可在右侧阅读完整规则。
- 卡面仅 hover 抬起与轻微倾斜，入场动画结束后不占用 hover 的变换；真实选中仅静态描边。用牌详情按 Esc 返回手牌，按 Enter 沿用使用按钮的校验和确认。点击遮罩空白或在其他视图按 Esc 可关闭舞台，关闭后可继续同一待选。卡牌舞台不自动聚焦、不恢复入口焦点、不添加卡牌键盘切换或焦点陷阱。背景牌桌在舞台打开时 inert，关闭恢复。减少动态效果时保留静态选中与结果。
- Card 与 Roll 在请求前用按账号/房间隔离的 sessionStorage 保存并读回完整原请求；未知结果先读牌桌再核对原 UUID，不替换控制/阶段/报价。任一真实未确认请求或待选阻止新的主动卡牌、下注和另一系统的随机操作。存储不可用只禁止对应新写入，明确失败不能假装成功。
- 第二摞统一为“暂存”。新 chips-v2 响应提供通用 reserve 资金及完整根内实际金额/方向；按因果顺序存入、盗取、退款、最终分配，零实付不飞筹码。名义下注不作为真实资产。完整结算等待资金动画及数字落定；减少动态直接落结果。旧冻结账本只读适配，不迁移或改写历史。画布内部兼容锚点仍为 roll，已与来源类型脱钩。
- 暂存明细按原付款人、原待分身份及来源筛选，支出/盗取/退款/分配分列，缺源与截断明确说明；当前总额独立于明细截断。公开单张扑克牌使用 index/card 对，只渲染实际公开槽位，标记跟随实体换位，移除持续标记不删除历史事实。
- 以上开发阶段类型、规则和固定数据回归记录在卡牌实施计划；真实展开几何、键盘、窄屏及 `_e2e` 数据库验收由同计划 T17/T18 完成，未执行前不得以源码检查替代。
- 正式能力牌封面位于 `assets/ability-cards/v1/`，60 种各一张独立 GPT 插画，清单记录完整提示词、实际尺寸和哈希；精确模型未由工具提供。面板仅加载当前持牌/候选本地图片，禁止外部地址或占位图兜底。资源校验入口为 Dashboard `check:poker-card-assets`。
- 真实展开验收和隔离两局实牌证据见 [卡牌验收记录](../superpowers/acceptance/2026-11-03-poker-card-mode.md)，覆盖持牌、目标、两类候选、暂存筛选、结算、键盘及 850px 两侧画布复用。Vitest Browser 使用独立优化缓存，避免与开发页面互相触发刷新。

卡牌舞台接入与新验收见 [实施计划](../superpowers/plans/2026-11-03-poker-card-stage-implementation.md)及 [覆盖层验收记录](../superpowers/acceptance/2026-11-03-poker-card-stage.md)；旧卡牌验收记录描述的是之前的 Modal。待选可回看本人情报/公共状态并返回原预选；舞台状态呈现与对局总览的系统 Accordion 分开。窄屏恢复操作始终留在底栏内。

### 手牌任务的布局与文案

- 手牌栏打开的目标、候选、结果、私密情报和请求恢复共用「标题 → 内容 → 操作」三段。标题、选项组或结果、主按钮沿同一中轴；费用、状态和次操作不与主按钮横向拼接。短内容整体居中，内容超高时从顶部开始滚动，顶部公共牌和倒计时不滚动。卡面详情仍保留左卡右文的布局。
- 目标保留必要牌效和可辨认的玩家、牌槽、颜色或效果；组合选择保留各自分组，单一选择不再重复标题已表达的分组名。材料保留消耗或复制的区别；换牌候选显示将替换的槽位，结果直接显示新牌或情报。选中标记叠在选项边角，不改变宽高或挤动选项文字。正文、选项及按钮使用可读的界面字号，次要信息降一级。
- 两种卡牌界面的确认按钮统一为「确定」或「支付 N 筹码并确认」，金额取服务端实际报价，不另列免费、名义费用或豁免。报价变化仍需先接受新报价再确认；候选阶段不重复提示已付款。首次不可撤销的步骤之前保留必要提示；不可用原因和恢复错误单列。手牌任务允许放弃时只保留顶部关闭，结果用「完成」结束，强制待选不增加退出入口。
