# Use expiring single-writer leases for terminal automation

Each running terminal session permits at most one automated writer at a time, while the same caller may control different sessions concurrently and all authorized callers may continue to read status, history, and output without a write lease. Automated input uses a short-lived renewable lease bound to the session and an auditable caller. The lease expires immediately on timeout, explicit release, session exit, loss or deletion, or explicit user takeover; correctness never depends on detecting an MCP or HTTP disconnect.

The user always retains explicit takeover and emergency-stop paths. Takeover visibly invalidates the previous automated lease so UI and MCP input cannot interleave silently. A write lease grants input control only and conveys no permission to stop, delete, rename, or modify terminal groups. Accepted input returns a monotonically increasing session input revision and/or stable operation id for output and audit correlation; acceptance means only that the terminal service accepted the input, not that the foreground program processed or completed it. The concrete acquire, renew, and release tool shape remains a later interface decision.
