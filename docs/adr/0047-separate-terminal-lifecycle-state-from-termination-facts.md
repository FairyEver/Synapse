# Separate terminal lifecycle state from termination facts

Terminal sessions use `running`, `stopping`, `ended`, `failed`, and `lost` as their lifecycle states. `running` means the PTY is alive and the session may participate in normal input control; `stopping` means a stop request was accepted and ordinary new input is rejected while actual exit is pending; `ended` is set only after PTY exit is confirmed. A nonzero exit code remains an `ended` foreground-program result. `failed` is reserved for an unrecoverable terminal-infrastructure failure after session identity exists, while `lost` means a formerly running runtime can no longer be confirmed or recovered. Lifecycle, evidence-based attention, and automated write lease are orthogonal dimensions.

End facts separately retain `cause`, `exitCode`, `signal`, and `endedAt`, plus `stopOperationId`, `requestedBy`, and `requestedAt` when applicable. Normal Synapse shutdown and detection of a stale running record after restart use different causes. Allowed transitions are `running → stopping | ended | failed | lost` and `stopping → ended | failed | lost`; `ended`, `failed`, and `lost` are terminal until explicit deletion. A repeated stop request with the same idempotency identity returns the existing stop operation, a request against `stopping` reports the pending operation without sending another stop signal, and a request against a terminal state reports that state without a new side effect. Stop-call success means request acceptance only; callers must observe `ended`, `failed`, or `lost` before claiming termination. Concrete interrupt, graceful, and forced stop modes are decided separately.

This changes the persisted terminal schema. Implementation must introduce an explicit versioned migration for existing `exited`, `killed`, `failed`, and `lost` records, preserve historical fixtures, and use conservative legacy causes where prior data cannot prove a more specific fact. Loading must not silently guess, overwrite, or relabel old state outside the migration boundary.
