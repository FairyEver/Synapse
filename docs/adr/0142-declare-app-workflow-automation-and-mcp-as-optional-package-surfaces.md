# Declare App, Workflow, Automation, and MCP as optional package surfaces

A Capability is a versioned execution contract. A Built-in Capability Package is the built-in registration and delivery unit. Workflow Node, Automation Action, MCP Tool, System App, and Deep Link are explicit optional surfaces rather than consequences of a directory name, renderer folder, App ID, or catalog entry. The restricted JavaScript and controlled Node.js runtimes are separate built-in packages. Each contains one core capability, one Workflow Node, and one Automation Action, and contains no System App, MCP Tool, or Deep Link.

V1 introduces `BuiltinCapabilityPackageManifestV1`. It records a package version separately from each capability contract version and explicitly contains every surface key, including `systemApp: null`, empty `mcpTools`, and empty `deepLinks`. A System App object, when present, separately declares existence, launcher discovery, default and optional Dock behavior, window openability, and Deep Link exposure. Workflow and Automation discovery controls only creation pickers; hidden surfaces retain the identity and availability required to load and execute existing definitions.

Package manifests and their shared, main-process, and renderer contributions use explicit static registries. Runtime directory scanning is forbidden. Build-time and pre-start validation reject duplicate IDs, invalid SemVer, undeclared references, missing main or renderer contributions, contribution count mismatches, and illegal App, window, Dock, Deep Link, or MCP combinations. Capability catalog registration never creates an MCP tool. An MCP schema, action mapping, dispatcher route, or tool-list entry is valid only when the package manifest explicitly declares that MCP surface.

Registration, runtime availability, user enablement, and surface discovery are distinct states. Both script packages are always registered and have no user package toggle. A runtime initialization failure keeps their nodes and Actions editable but causes execution to return `CAPABILITY_UNAVAILABLE`; missing Node.js execution trust is instead `EXECUTION_TRUST_REQUIRED`. Workflow shares depend on capability ID and contract version, not package version, App identity, MCP exposure, or transient health.

The existing `desktop/app-capabilities` directory and `app.*` capability namespace remain for compatibility and do not imply an App. This change adds the new manifest, validators, registration assembly, the two script packages, and negative cross-surface tests. Existing packages, directories, System Apps, MCP domains, Actions, and Workflow nodes are not migrated opportunistically.
