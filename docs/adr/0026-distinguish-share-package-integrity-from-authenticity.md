# 区分工作流分享包完整性与来源真实性

V4 工作流分享包必须保留一个固定且唯一的 `manifest.json` 控制条目；为避免摘要自引用，它不列入自身的文件清单。除此之外，manifest 必须逐项列出全部包内文件及其大小和 SHA-256。导入端严格校验文件清单、重复路径、摘要、清单外条目和额外 manifest 条目，保证包内内容自洽并发现损坏或未同步更新的载荷。

内容摘要不能证明包由哪位同事生成，因为修改者可以重新计算摘要。当前版本不引入没有团队信任基础的设备密钥、首次信任或自签证书体系；未携带可信签名的包在风险步骤显示“来源未验证”，不得根据作者显示名称或摘要宣称可信。包格式预留基于制品摘要的可选签名字段，未来接入团队身份或可信公钥后可以通过兼容扩展启用；包若把签名验证声明为必需能力，而当前版本不能验证或验证失败，必须阻止导入。
