# Derive problem-feedback rate keys only from trusted network context

The application resolves limiter addresses only through configured `trust proxy` semantics and never trusts the first forwarded value directly; the single trusted Nginx ingress overwrites external forwarding headers, while direct connections outside a trusted chain use the socket address. IPv4 and IPv4-mapped IPv6 share one canonical IPv4 key, IPv6 uses a canonical `/64` key, and ports, zone IDs, and textual abbreviation differences are discarded. Unresolvable addresses share a fixed `unknown` bucket and remain under the global bucket. Raw and normalized addresses or prefixes exist only in the in-process Map, expire lazily after one idle hour, and are never hashed into persistence or exposed in logs, audits, metric labels, or responses. Nginx keeps only local shared-memory state for coarse pre-body protection, and forwarding headers prove no client identity.
