# 升级后自动恢复旧资源仓库中的工作流

新版本首次启动时自动扫描仍在配置中的资源仓库 `workflows/` 目录，从每个旧工作流中选择最新的有效版本，经过当前工作流文档迁移和校验后写入统一存储。恢复过程必须幂等，不覆盖同 ID 的现有工作流；发生内容冲突时保留两边数据并报告冲突，成功后也不自动删除旧源文件，以保证用户数据可恢复和可复核；不扫描整块磁盘或无法定位的已移除资源仓库。

首次加载中的找回扫描必须限制仓库数、工作流目录总数、单工作流历史版本数、单版本文件大小和总扫描时长。达到边界时保留已完成的找回结果并写入结构化诊断，未扫描来源不删除、不写入完成标记，后续应用启动仍可继续尝试。

找回扫描必须把已配置仓库作为文件系统边界：先把配置仓库固定解析为稳定的真实目录；`workflows/` 根和单个工作流目录必须是普通目录，禁止跟随其中的符号链接，并且解析后的真实路径必须保持在配置仓库内。目录在扫描期间被替换、越界或变成符号链接时，跳过该来源并写入不包含完整本地路径的结构化诊断。
