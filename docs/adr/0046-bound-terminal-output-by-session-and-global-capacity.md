# Bound terminal output by session and global capacity

Terminal output retention applies both a configurable rolling limit per session and a configurable global terminal-output quota; their concrete values are implementation settings rather than permanent product promises. A session exceeding its limit loses its oldest chunks. Global pressure follows a deterministic explainable order that removes the oldest output from ended or lost sessions first and affects running sessions only as a last resort. Initial retention is capacity-based and never silently expires output by age; any future time policy must be an explicit visible user setting.

Automatic eviction removes output chunks only. It preserves `sessionId`, title, lifecycle, timestamps, and required audit metadata, while explicit session deletion remains the only operation that removes identity, metadata, and retained output together. Even when no output remains, reads expose the retention policy, first and next sequence interval, cumulative discarded amount, most recent eviction time, and gap or truncation facts so empty retention cannot be mistaken for no historical output. Eviction and deletion audits record ranges, quantities, reasons, and outcomes without copying output bodies. Global output capacity does not solve unbounded session metadata; metadata lifecycle and paginated listing remain a separate product decision.
