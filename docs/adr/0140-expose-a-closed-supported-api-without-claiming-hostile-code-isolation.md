# Expose a closed supported API without claiming hostile-code isolation

Status: deprecated; replaced by accepted ADR-0204

The controlled Node.js host publishes a capability-versioned closed list of globals, module identifiers, exports, arguments, and facade methods. Anything absent is unsupported and does not become supported when Electron's bundled Node.js changes. V1 disables string code generation, static and dynamic imports, WebAssembly, `SharedArrayBuffer`, and `Atomics`; starts with zero-filled Buffer allocation; defers `node:os`; exposes only one-shot timers; routes fetch through the shared broker; and uses an explicit crypto export allowlist. Buffer, KeyObject, Stream, and other host objects may be used during execution but cannot be returned as the strict JSON result.

The filesystem surface consists only of the agreed nine asynchronous `node:fs/promises` facade methods—`readFile`, `writeFile`, `mkdir`, `readdir`, `stat`, `copyFile`, `rename`, `unlink`, and `rmdir`—plus matching error-first callback methods and `promises` on `node:fs`. Paths are strings. V1 excludes sync methods, handles, descriptors, file streams, append, truncate, links, watches, recursive remove or copy, and unlisted options. Read and write are limited to 16 MiB per file, copy to 256 MiB, readdir is single-level, bounded, and stably sorted, and rename is same-volume, non-overwriting, and never degrades to copy-and-delete. All calls remain subject to resource grants, `PermissionGuard`, audit, cancellation, and finalization.

This API list is a compatibility and defense-in-depth boundary, not by itself a hostile-code isolation guarantee. Node's VM is not a security mechanism, and native Buffer, crypto, stream, util, callback, error, constructor, prototype, and symbol objects injected across a context boundary may expose escape paths even when a module namespace is frozen. Implementation must first define a threat model and executable escape suite, replace cross-context natives with context-native wrappers or membranes where feasible, and specify freezing and wrapping for each namespace, export, class, instance, and prototype. If process, native networking, or native filesystem reachability cannot be disproved, product copy and permissions must continue to describe trusted local execution rather than a sandbox.

Console serialization must not intentionally invoke getters, proxy traps, or custom inspection hooks; values that cannot be observed without those effects receive a stable placeholder. One normalized error envelope must cover script and facade validation, permission denial, resource limits, disabled modules and dynamic code, broker failures, runner failures, and cleanup failures without exposing internal stacks, unapproved path contents, main-process errors, or native exception text.
