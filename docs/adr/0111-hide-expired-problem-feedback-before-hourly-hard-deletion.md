# Hide expired problem feedback before hourly hard deletion

Problem feedback expires by database time at `receivedAt <= CURRENT_TIMESTAMP - INTERVAL '180 days'`. Administrator lists always exclude expired rows from both data and total, so the retention boundary does not depend on cleanup timing. Cleanup runs once after service startup and hourly thereafter under a PostgreSQL advisory lock, deleting at most 1,000 rows per batch in `receivedAt, id` order until none remain. A failed batch rolls back and ends that run without tight retry; the next hour or startup tries again. Expiry writes no per-record audit and retains no IDs, bodies, excerpts, summaries, or hashes, only unaffiliated `retention_deleted` and `retention_failed` aggregate counts. There is no archive, trash, feedback-data backup, or extension. First-party restores contain no feedback rows; legacy or self-hosted external restores apply the same immediate visibility and deletion rules before administrator access.
