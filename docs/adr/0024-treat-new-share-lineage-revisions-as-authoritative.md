# 同一工作流分享谱系的新修订原地覆盖

为了避免同事反复分享同一工作流后产生重复副本，同一 `lineageId` 的相同修订采用幂等导入，新修订则把分享来源视为权威并原地更新已导入的整组工作流，不检测或合并接收方的本地修改。更新前必须生成可恢复快照，模型、项目和文件映射应尽量复用，全部工作流、内部引用和来源关系必须原子提交；失败时保持旧版本不变，已被用户删除的导入结果允许重新导入。原地更新必须保留该本地工作流已有的运行快照，使历史继续按当次运行定义显示。新版不再包含的旧子工作流只有在既无谱系外工作流引用也无运行历史时才自动删除；存在任一保留理由时必须解除谱系关系并保留，避免破坏其它流程或连带删除历史。

谱系更新不得与受影响的运行并发提交。若待更新或清理的工作流自身正在运行，或位于任一活动工作流的递归调用链中，必须阻止最终提交并让用户等待运行结束或自行取消后重试；导入不得自动取消运行。该限制避免父工作流已按旧定义启动、调用节点却在执行时加载到新版子工作流，从而形成一次运行混用两个分享修订。

谱系更新也不得覆盖活动编辑草稿。受影响工作流的编辑器存在未保存修改或正在保存时，必须阻止最终提交并提示用户先处理编辑窗口；编辑器没有未保存修改时允许提交，并在提交后自动加载导入定义。工作流保存和导入提交都必须携带并校验预期修订，避免预检完成后出现新的保存而被静默覆盖。这里的并发校验只保护活动草稿和提交竞态，不改变“来源修订覆盖接收方已保存修改且不做内容合并”的权威更新规则。

导入生成的工作流再次导出时必须创建新 `lineageId`，并通过 `derivedFrom` 记录原谱系和来源制品，避免多个同事从同一谱系分别导出后争夺权威更新顺序。需要保持原谱系时应直接转发原分享文件。

手动删除也必须维护引用和谱系完整性。仍被其它工作流调用的目标不得删除，并应向用户列出引用方。删除导入谱系的入口工作流时，可以默认清理同谱系内无外部引用且无运行历史的子工作流；其余成员解除谱系关系并保留。删除单个子工作流不级联其它内容。谱系最后一个成员被删除或解除关系后，必须删除来源记录及模型、项目、文件映射，避免长期保留本地路径；整组删除必须原子提交。

每个谱系只保留最近一次成功更新前的导入撤销点，不建设可浏览的通用工作流版本历史。导入失败始终自动回滚；成功后的撤销必须原子恢复工作流定义、被清理的子工作流、谱系关系、映射和导入时自动禁用的 Automation 状态，但不得删除工作流或 Automation 运行历史。只有受影响工作流仍处于刚导入修订时才允许撤销，导入后出现新的保存必须阻止撤销，避免再次覆盖用户的新编辑；下一次成功更新替换旧撤销点。
