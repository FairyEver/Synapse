# Bound terminal discovery and separate sensitive details

Every terminal collection interface has a default and hard maximum limit and uses an opaque stable cursor bound to the exact sort, filters, and query. Changing those conditions invalidates cursor reuse. Sessions sort by immutable `createdAt` plus `sessionId` as a unique tiebreaker so output or `updatedAt` changes cannot cause pagination drift; concurrent deletion produces a documented gap rather than reinterpreting the cursor. Filters include group, lifecycle, creation time and source, with optional title search. Titles and group names aid discovery only: sensitive reads and every write, stop, or delete operation ultimately require an exact unique id, and ambiguous names are never guessed.

`session.list` returns bounded summaries without output bodies. Any attention summary carries `detectedAt`, `throughOutputSeq`, or equivalent staleness facts and never claims to be a fresh observation. `session.get` returns one authorized metadata record without implicitly reading output. `group.list` returns summaries and command counts; group details, command lists, and command bodies are separate layers. Command bodies, working directories, shells, and similar sensitive fields require corresponding authorization and redacted audit. Initial behavior never automatically removes session identity or metadata, and diagnostics expose total sessions, terminal-state counts, and metadata storage size. Any future cleanup policy is a separate explicit decision and cannot hide deletion behind pagination.
