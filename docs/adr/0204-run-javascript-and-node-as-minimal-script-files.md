# Run JavaScript and Node.js as minimal script files

Status: accepted

JavaScript and Node.js are ordinary script-file capabilities rather than restricted code DSLs. JavaScript runs as a classic Chromium Dedicated Worker that receives one JSON message and uses its first `postMessage` as the strict-JSON result; Node.js runs a real CommonJS or ESM file through Electron's Node CLI mode, reads one JSON value from stdin, and succeeds only when it exits zero with exactly one JSON document on stdout. Console output is separate JavaScript logging, while Node stderr is logging and Node stdout is reserved for the result.

Synapse adds no API, module, filesystem, network, Secret, or package authorization layer. Node uses native process, environment, filesystem, network, subprocess, Worker, dynamic-code, WebAssembly, relative-module, and local `node_modules` behavior; Synapse does not install, bundle, declare, or make those dependencies portable. JavaScript uses the bundled Chromium classic Worker's natural behavior and promises only the absence of DOM, Node, Electron, and local-file APIs.

Only timeout, cancellation, disposable execution units, bounded result and logs, global concurrency, import-origin confirmation, and best-effort Node process cleanup remain. Workflow and Automation keep typed inputs, one public `outputs.result`, normal history persistence with a single content-saving switch, and no legacy output, independent App, Deep Link, or MCP surface.

The built-in packages start at package version `1.0.0`. JavaScript uses capability `app.javascript.script.execute@1.0.0`, Workflow node `javascript_run`, and Automation Action `builtin.javascript-run`; Node.js uses capability `app.nodejs.script.execute@1.0.0`, Workflow node `nodejs_run`, and Automation Action `builtin.nodejs-run`. Both package manifests explicitly declare `systemApp: null`, empty MCP and Deep Link surfaces, and one visible Workflow and Automation creation surface.

Both capabilities are registered as always available with no user enable toggle. Package and capability versions remain separate. The package manifest is the explicit source of truth for optional Workflow, Automation, MCP, System App, and Deep Link surfaces; filesystem layout does not create a surface.

Both runners accept a strict-JSON object assembled from typed bindings. JavaScript sends it once as the classic Worker's first input message and accepts the first Worker `postMessage` as the only strict-JSON result. Node writes it once to stdin and accepts stdout only when it contains one strict-JSON document surrounded by optional JSON whitespace; stderr is bounded logging, and normal exit code zero is still required after output is written. New nodes publish only `outputs.result`; legacy `node_output` remains an explicit string source while `node_value` resolves manifest-declared public structured outputs without coercion.

The default timeout is 60 seconds and the configurable range is 1–900 seconds. Input, result/stdout, source, and retained log content are bounded at 1 MiB; stderr and console truncation add one marker without failing an otherwise valid run. JavaScript and Node share one process-wide scheduler with two running units and eight queued units. The history switch defaults on; when off, persisted input, result, and logs are omitted while live Workflow values remain available to the current run.

When history saving is on, script inputs, results, and logs are persisted as produced within those size limits. They do not pass through field-name or regular-expression Secret redaction. This is deliberate: script data belongs to the user's program, and the single history switch is the control for persistence. Stable runner errors may still be sanitized before display.

Node defaults to CommonJS and can select ESM. Its temporary random `.cjs` or `.mjs` file is exclusively created with restrictive best-effort permissions directly in the resolved working directory, so file watchers may observe its short-lived creation and deletion. The working directory is the explicit node or Automation directory, otherwise the project workspace, otherwise Electron user data. The environment follows Synapse's terminal/process environment; stdin is the only formal input channel. Synapse waits for natural process exit and performs best-effort process-group or process-tree termination on timeout and cancellation, but detached descendants may survive.

Electron's `ELECTRON_RUN_AS_NODE` launcher flag is removed from the child environment before the user file starts and its internal preload argument is removed from `process.execArgv`; neither is a script input. The user file itself remains the selected `.cjs` or `.mjs` entry, preserving native `require`, import, `__filename`, `__dirname`, `import.meta`, `process.argv`, and local module-resolution behavior.

Local Workflow runs and enabling local Automations are the authorization acts. Script Automations are initially disabled and execution-relevant changes disable them again; changing only presentation or history saving does not. Before any node starts, an imported Workflow run collects all reachable unconfirmed imported Workflow revisions and displays their complete scripts in one confirmation; accepting confirms that set, while reimport resets the affected revisions. No file, network, package, Secret, or history authorization layer is added.
