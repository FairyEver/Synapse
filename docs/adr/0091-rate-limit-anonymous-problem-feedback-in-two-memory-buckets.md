# Rate-limit anonymous problem feedback in two memory buckets

Anonymous problem feedback uses two in-process token buckets evaluated at the same instant: a client-IP bucket with capacity 3 and refill of one token per 10 minutes, and a process-global bucket with capacity 30 and refill of one token per minute. After the HTTP body-size check and before content validation or persistence, a request acquires both tokens atomically; if either is unavailable neither is deducted, and invalid content still consumes an acquired pair so validation failures cannot bypass the limiter. A limited request returns stable `RATE_LIMITED` and is never retried automatically. IP keys exist only in memory, are lazily removed after one idle hour, and never enter the database, application logs, or audit; restart resets the buckets. This application limiter is the exact V1 authority, while the single supported Nginx ingress provides only coarse pre-body protection without logging feedback bodies.
