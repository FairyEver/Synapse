# Share one terminal object space without blanket control

Terminal UI and MCP share one object space for groups, sessions, and retained history rather than creating MCP-only terminals. Every session has an immutable, non-reusable `sessionId`; after process exit or Synapse restart the same identity remains available only for metadata and retained-history reads, restarting always creates a new session, and deletion invalidates both identity and history. UI-created sessions are discoverable through MCP and MCP-created or modified objects must appear in the UI in real time. Creation source and caller identity are audit metadata rather than default ownership boundaries.

Shared visibility does not grant every MCP client unrestricted control. Listing metadata, reading output, writing input, stopping processes, deleting sessions, and other operations remain separately authorizable and auditable according to their risk. The current implementation's single `shell.exec` check and default-allowed MCP user actor are not the long-term product contract; the design preserves operation-level risk classification and caller authorization without requiring this decision to choose the final authorization UI.
