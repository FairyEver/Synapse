# Separate retained terminal output from derived rendered views

Terminal history has two explicit representations. The terminal output stream is the authoritative record only within its current retained interval: reads expose sequence and time ranges, `firstSeq`, `nextSeq`, truncation and gap facts so callers can identify missing output. It preserves raw PTY data, including ANSI and redraw semantics, for incremental following, replay, and diagnosis, and is neither a permanent complete history nor a directly human-readable transcript.

The terminal rendered view is a bounded derivative produced with terminal-emulation semantics. It distinguishes the visible screen from scrollback and returns plain-text lines, dimensions, cursor state, generation time, the `throughOutputSeq` it covers, and `degraded` reasons when reconstruction is incomplete. Tail, pagination, or explicit line and byte limits prevent unbounded snapshots, and `throughOutputSeq` lets callers continue with incremental observations. Simply stripping ANSI may be offered only as a convenience derivative and can never claim to be the authoritative stream or rendered view. Because both representations may expose sensitive terminal content, each read remains separately authorizable, and audit records only requested ranges and outcomes rather than output bodies.
