# Return only stable first errors from problem-feedback submission

Problem-feedback submission validates in a fixed order: valid JSON under the existing 1 MiB HTTP limit, both rate-limit buckets, a strict object containing only `content`, the plain-text and 256 KiB rules, privacy categories in the exact priority `authentication_secret`, `local_path`, `identity`, `user_content`, `unsafe_url`, then `correlation_identifier`, and finally persistence. It returns only the first stable error: `INVALID_INPUT` with `field` limited to `request | content` and `reason` limited to `type | unknown_field | required | leading_or_trailing_whitespace | invalid_unicode | forbidden_character | too_large`; `PRIVACY_RISK` with the first category in that priority; or `RATE_LIMITED`, `SUBMISSION_FAILED`, or `SUBMISSION_OUTCOME_UNKNOWN` under their established persistence semantics. No entry point returns the body, fragments, actual length, raw failure, validation-library details, or any other unbounded diagnostic.
