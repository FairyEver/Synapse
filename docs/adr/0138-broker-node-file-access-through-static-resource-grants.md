# Broker Node file access through static resource grants

Status: deprecated; replaced by accepted ADR-0204

Node.js Script Execution V1 exposes controlled `node:fs` and `node:fs/promises` facades instead of native modules. Workflow nodes and Automation Actions use one filesystem contract. Trusted configuration declares static file or directory grants with independent `read`, `write`, and `delete` access; a file grant covers only that file and a directory grant covers descendants. Scripts may compute paths below those roots but cannot compute or acquire new roots. An optional fixed working directory must refer to a granted directory, relative paths fail without it, and neither `cwd` nor `chdir` is exposed.

Each logical filesystem call validates all arguments, resolves every source and target, checks the static grants, canonicalizes existing ancestors, rejects descendant symlinks, calls the shared `PermissionGuard`, performs the operation, and records one content-free audit outcome. Permission decisions may be cached as revocable run or persistent grants only when bound to the trusted actor, Workflow or Automation definition identity, revision, node or Action identity, resource root, and access set; they never become global path permissions. OS permissions remain the outer ceiling. Multi-path operations authorize every source and target before side effects: copy requires source read and target write, while move requires source delete and target write. Cross-volume move must define its copy-and-delete commit and failure behavior explicitly.

The root selected by the user may itself resolve through a symlink and is pinned to its real target and identity at execution start. Descendant symlinks may not be traversed, created, or read. V1 also excludes links, watches, locks, device files, sockets, and recursive deletion. `writeFile` uses same-directory exclusive staging, synchronization, target rechecking, and atomic commit; cancellation before commit cleans staging, while a completed commit wins over later cancellation. These controls prevent Synapse from intentionally producing partial writes and detect common target replacement, but they do not claim to defeat every hostile same-user TOCTOU, hardlink, mount, or platform-specific race and do not create a security sandbox.

Workflow sharing declares the Node execution capability version and every static local resource with exact read, write, and delete access. Importers remap resources and grant authority on the destination machine; source paths and approvals are not inherited. The share format must evolve to express delete independently. The public contract must enumerate the exact V1 facade methods and options rather than implying full Node filesystem compatibility.
