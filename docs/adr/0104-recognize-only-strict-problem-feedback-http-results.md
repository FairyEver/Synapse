# Recognize only strict problem-feedback HTTP results

Problem-feedback HTTP responses use UTF-8 JSON with `Cache-Control: no-store`. Durable persistence returns HTTP `200` with exactly `{ "success": true }`; determinate `INVALID_INPUT`, `PRIVACY_RISK`, `RATE_LIMITED`, and non-persistence `SUBMISSION_FAILED` use HTTP `400`, `422`, `429`, and `503` respectively, with no `Retry-After`. The server never returns `SUBMISSION_OUTCOME_UNKNOWN`; the desktop creates it only from transport uncertainty. The desktop recognizes a result only when the status and strict finite JSON shape match, including a contract-conforming perimeter `429`. Non-JSON, unknown fields or codes, mismatched status and body, interrupted or over-16-KiB responses, redirects, and non-contract intermediary `401`, `403`, or `5xx` responses are unknown outcomes because the POST may have reached persistence. Responses never include content, excerpts, lengths, record identifiers, timestamps, or raw failures.
