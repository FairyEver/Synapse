# Delete one problem-feedback record without a confirmation token

`DELETE /api/admin/problem-feedback/:id` accepts one canonical UUID v4 path parameter and no query or body. The Dashboard's existing confirmation dialog owns user confirmation; the API adds no forgeable flag, token, or second confirmation endpoint. Success returns HTTP `200` with exactly `{ "success": true }` and no content, identifier, or time. An invalid identifier returns `400` without table access or deletion audit. A valid missing or concurrently deleted record commits a `not_found` audit and returns `404`; only one concurrent delete succeeds. Delete or transactional-audit failure returns a stage-neutral `503` without putting the record ID in ordinary logs. The UI disables deletion while pending, then closes the Sheet and reloads the current page after success.
