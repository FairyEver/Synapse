# Extend the shared text writer for HTML

HTML file generation extends the existing Text File Writer instead of creating a private write path. `TEXT_FILE_FORMATS` adds `html` and `htm`; extension matching is case-insensitive, returned formats are normalized to lowercase, and requested paths are not rewritten. The Writer's App, MCP, Workflow, IPC, and internal Service boundary all support complete HTML text while preserving the existing permission, audit, target queue, concurrent-change checks, temporary file, and atomic commit implementation. HTML Generator accepts only absolute `.html` or `.htm` targets, always calls the same `TextFileWriterService.write` with UTF-8, and never exposes an encoding option.

The shared Writer rejects `.html` or `.htm` combined with `utf16le` through its authoritative schema and Service using the existing `INVALID_ENCODING` code and a safe message that states HTML supports only UTF-8. Writer App and Workflow forms prevent submission of the invalid combination without silently changing the selected value, while MCP, IPC, and internal callers remain protected by the Service. Existing `.txt`, `.md`, and `.csv` UTF-8 and UTF-16LE behavior is unchanged. Text Extractor's `extract_to_file` composition retains its own explicit `.txt`/`.md`/`.csv` restriction so the Writer expansion cannot broaden extraction outputs accidentally. The Writer does not parse, repair, validate, preview, or insert a charset declaration into HTML.

HTML and HTM extension matching is case-insensitive on every supported platform, returned `format` is lowercase, and the requested path remains unchanged. Cross-platform tests use native absolute-path semantics and include Windows drive, backslash, UNC, and device-path cases plus macOS symlink and actual filesystem case behavior; Writer remains the authoritative target-safety boundary.

The Writer capability version advances from `app.text_file_writer.file.write@1.0.0` to `@1.1.0`. Its Workflow node uniformly declares 1.1.0 for all newly exported paths, including txt/md/csv, because a path may be dynamic and export cannot reliably infer a lower format-specific requirement. New clients remain compatible with old 1.0.0 packages, while packages produced under the expanded contract correctly block older clients. HTML Generator file nodes declare only their own `app.html_generator.ejs_file.generate@1.0.0`; the bundled Writer is an internal implementation dependency rather than an additional share requirement. Workflow document schema remains at the already selected 2.5.0 for this change.
