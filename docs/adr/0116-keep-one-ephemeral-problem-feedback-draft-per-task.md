# Keep one ephemeral problem-feedback draft per task

Each Agent task may have at most one pending problem-feedback draft, and displaying a new draft invalidates the old one. Only the immediately following user message resolves it: an unambiguous affirmative starts one attempt, an edit produces a new full draft, and rejection, topic change, or other content invalidates it. Later confirmation cannot revive an invalid draft. Drafts and authorization do not cross tasks, conversations, Agents, or long-term memory; if compaction or recovery loses the exact displayed string, the Agent regenerates, redisplays, and reconfirms. Missing tools, denied host approval, cancellation, or determinate non-transmission still consume authorization. No local draft state, confirmation token, body hash, or persistent recovery record exists.
