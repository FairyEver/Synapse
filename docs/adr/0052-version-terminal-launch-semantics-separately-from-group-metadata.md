# Version terminal launch semantics separately from group metadata

Ordinary creation in a terminal group uses `inherit` and resolves one deterministic launch-settings snapshot, matching the UI's ordinary `+` action; group commands execute only when explicitly selected. The group's overall `groupRevision` may advance for names, membership, or other metadata, while a separate `launchRevision` advances only when working directory, shell, environment, or other session-launch semantics change. An `expectedLaunchRevision` therefore does not conflict merely because unrelated group metadata changed. Each command has its own `commandRevision`, and command launch validates both the expected launch and command revisions.

A created session records `groupId`, `launchRevisionApplied`, optional `commandId` and `commandRevisionApplied`, and redacted launch-snapshot facts. Later configuration changes never rewrite existing sessions. Display-only fields such as title do not alter launch semantics. Working-directory, shell, environment, or similar changes require an explicit `override` intent whose overridden fields are recorded and separately authorized and audited; ordinary optional fields cannot silently bypass inheritance. Invalid launch settings fail before `sessionId` creation. UI and MCP share the same resolution, validation, snapshot, and conflict behavior. Ordinary creation without a group likewise matches the UI's ordinary `+` behavior, resolving any future global launch defaults through an explicit default snapshot while keeping overrides separate.
