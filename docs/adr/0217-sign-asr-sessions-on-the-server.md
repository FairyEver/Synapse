# ADR 0217: Sign ASR Sessions on the Server and Hand Out the URL

## Status

Accepted

> 这篇的第一版写的是「在桌面主进程签名、每台机器自己配腾讯云密钥」。那是错的：
> 语音识别是**平台统一提供**的能力，不是一个每人都要自己申请一遍的设置。改动很小
> （签名逻辑一行没动，只是换了个持有密钥的地方），但结论完全不同，所以直接改在
> 这里而不是并列一篇取代它——第一版从未真正生效过。

## Context

语音输入要把麦克风音频送到腾讯云的实时语音识别，而腾讯云的要求是：客户端在
WebSocket 握手时带上 `secretid` 和用 SecretKey 算出来的 `signature`。

**密钥不能进客户端。** iOS 包会被分发到设备上，包里的任何东西都等于公开；桌面渲染
进程是 web 技术栈，一份密钥放在那里迟早会出现在某个日志或 devtools 面板里。

**密钥也不该由每个用户自己配。** 如果每台机器各自持有密钥，每个用户都要去腾讯云
注册、实名、开通、按自己的量付费——那就不是产品功能，是给用户派活。平台提供的是
一个基础能力：一把密钥、一份配额，所有人共用。于是密钥属于**部署**，不属于设备。

### 签名能不能脱离音频流

这是整件事可行的前提。签名原文是**被签名的请求本身**：把除 `signature` 之外的所
有握手参数按字典序排好，拼成一条不带协议的 URL，再对这条字符串做 HMAC-SHA1。音频
走的是握手成功之后的 WebSocket 数据帧，不参与签名。所以签名与音频是解耦的：可以先
把整条 URL 签好，再拿着它去连。

另一条路是 STS 临时密钥，这里走不通：这个接口的鉴权是 URL 上的 `signature` 参数，
不是云 API 的 TC3 签名，STS 凭证在协议里没有对应的传参位置。

## Decision

- **签名在服务端。** 密钥从 ENV 读（`TENCENT_ASR_APP_ID` / `_SECRET_ID` /
  `_SECRET_KEY`），服务端签出完整 URL 下发，客户端拿它直连腾讯云。密钥从头到尾没
  有离开过服务端。
- **三项齐了才算配好。** 缺任何一项都当没配，接口返回 502 +
  `VOICE_ASR_NOT_CONFIGURED`，客户端据此隐藏麦克风入口。宁可让入口不出现，也不要
  签出一条连不上的 URL 让用户对着麦克风白说一段。
- **两个接口，都不带参数。** `GET /api/voice/asr` 报可用性；`POST /api/voice/asr/session`
  签一条会话。引擎和热词是部署配置，`voiceId` 由服务端生成——调用方能决定的越少，
  能滥用的面就越小。签出来的 URL 花的是平台的语音配额，所以单独收了限流。
- **桌面端不签名，只转发。** 渲染进程经主进程（带登录态）去要 URL；主进程自己也不
  持有密钥。
- **手机直接连服务端，不经电脑中转。** 手机本来就连着服务端；走电脑反而多一个
  「电脑得在线」的前提，而那是终端功能才需要的。一开始实现成了经电脑的 intent 中
  转，后来删掉了——同一件事不该有两条路。
- **URL 有有效期，一次一签。** 默认 5 分钟。每次建立连接都重新签一次，`voice_id`
  也每次换新的；连接中断后旧的 `voice_id` 一律作废。签名过期或鉴权被拒（腾讯云返回
  4002）时客户端换一条新签名重连一次；服务端明确拒绝（如 4003 服务未开通）则不重连
  ——换个签名解决不了问题。

## Consequences

麦克风入口的可用性由服务端是否配好密钥决定，与用户装了什么、电脑在不在线都无关。

密钥轮换只发生在一个地方：部署方的 ENV。

签名是短时凭据，但拿到它的人可以在有效期内开一路识别，花的是平台的额度。所以它按
5 分钟签发，且只发给已登录的账号。

**实测记录**（用于选引擎，写在 `.env.example` 里）：同一段音频跑四个引擎，
`Hy-ASR-3.0-preview` 明显比 `16k_zh_en_2.0` 准，而且当前**支持热词**——官方文档那句
「上下文传入及热词增强即将开放体验」已经不成立。默认引擎因此选了它。
