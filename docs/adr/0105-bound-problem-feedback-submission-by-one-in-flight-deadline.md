# Bound problem-feedback submission by one in-flight deadline

The anonymous client uses one non-configurable 30-second deadline from the final pre-POST cancellation check through complete response validation. Cancellation before the POST prevents transmission, consumes the confirmation, and returns determinate `SUBMISSION_FAILED`. Once the underlying request begins, cancellation, timeout, process exit, or connection interruption produces `SUBMISSION_OUTCOME_UNKNOWN` and aborts the in-flight request without background waiting, retry, recovery, or persistence. A transport may still return `SUBMISSION_FAILED` after request creation only when it can positively prove that DNS, TLS, or connection establishment failed before any body was sent. A strict response received before the deadline keeps its normal meaning, and completion releases all body and response references without local files or state.
