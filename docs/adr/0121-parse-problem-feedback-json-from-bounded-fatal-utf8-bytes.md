# Parse problem-feedback JSON from bounded fatal UTF-8 bytes

The anonymous route has a dedicated parser bounded to 1,048,576 raw HTTP body bytes, checking `Content-Length` first and streamed bytes again before application limiting, shared validation, or logging. Fatal UTF-8 decoding rejects invalid, truncated, or BOM-prefixed input without replacement. Exactly one JSON value is accepted; trailing content and duplicate keys are rejected using a mature strict JSON capability or existing library, never a regex or fragile hand-written scanner. Pre-parse failures return stable HTTP `400` `INVALID_INPUT`: body overflow is `request/too_large`, while media, encoding, UTF-8, BOM, JSON, duplicate-key, and empty-body failures are `request/type`. They consume no application tokens but remain subject to proxy/WAF limiting and bypass raw-error logging. Valid JSON then enters the dual limiter and shared policy, and decoding standard `JSON.stringify({ content })` must reproduce the confirmed content exactly.
