# Observe terminal sessions with persistent revisions and watermarks

Every terminal session maintains a monotonically increasing persistent `stateRevision` that never resets or moves backward within its `sessionId`. Lifecycle, attention, lease, and other observable state changes advance it, including restart recovery and marking a stale runtime as lost. An observation returns one consistent snapshot with `generatedAt`, `stateRevision`, and `throughOutputSeq`; callers independently provide `afterStateRevision` and `afterOutputSeq`, and reads never consume shared output or move another UI or Agent cursor.

Existing changes return immediately. Otherwise a bounded observation waits for state or output changes, a terminal lifecycle state, cancellation, or its maximum wait. Timeout returns `changed: false` as an ordinary result and proves neither waiting nor not waiting. Results distinguish lifecycle, attention, lease, and output change types and return `nextStateRevision` and `nextOutputSeq`. Output respects a per-call byte limit and reports `hasMore` for immediate continuation. A cursor in an evicted output gap returns immediately with the gap, current available interval, and recovery cursor; invalid or future revisions follow an explicit error or correction contract and are never silently guessed. Per-session, per-caller, and global wait limits plus maximum duration and cancellation bound resources. Initial short long-polling is sufficient, while any future subscription must reuse the same revisions and watermarks rather than introducing a second observation model.
