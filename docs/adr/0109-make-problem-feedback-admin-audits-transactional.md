# Make problem-feedback administrator audits transactional

Problem-feedback administrator reads and deletes reuse the existing `AuditLog`, including its required IP for authenticated-administrator accountability, without changing the global schema or weakening the anonymous submission route's zero-IP boundary. The audit service gains an internal transaction-client path rather than a second table. Listing performs query, count, and one `admin.problem_feedback.list` audit in one transaction and returns no content if auditing fails. Single-record deletion and its audit are also atomic, so audit failure rolls back deletion; a missing record commits a `not_found` audit before returning `404`. Database unavailability permits neither access nor deletion and is not compensated by an ordinary log containing administrator or feedback-record identifiers. These audits still exclude content, excerpts, summaries, hashes, returned ID sets, search terms, and User-Agent.
