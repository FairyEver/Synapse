# Never implicitly terminate when deleting terminal objects

`session.delete` accepts only `ended`, `failed`, or `lost` sessions. Requests against `running` or `stopping` return a lifecycle conflict without sending termination or deleting data. “Terminate and delete” exists only as an explicit UI or caller orchestration of normal or forced termination, observation of a terminal lifecycle state, and an independently authorized deletion. Delete is a separate high-risk permission with redacted audit and is granted by neither an input lease nor stop permission.

Session deletion accepts an explicit idempotency identity so retries can return the original `deleteOperationId` and redacted deletion summary. Retention of that result and its tombstone is bounded by a later implementation policy and is not promised forever. Empty groups may be deleted directly. Non-empty groups first produce a bounded redacted preview containing session counts and states, command settings, and the history ranges to be removed. The preview has an explicit expiry and binds the current group revision; membership, command, or session-state changes invalidate it. Any running or stopping member blocks commit, and an accepted cascade removes only terminal sessions, retained output, group commands, and the group through a transactional or equivalently recoverable boundary that cannot silently leave a partially deleted group. MCP exposes no shortcut that deletes a group while silently force-killing its sessions.
