# Require exact local trust before Node script execution

Status: deprecated; replaced by accepted ADR-0204

Node.js script execution is classified as high-risk `trusted_local_code`. Three boundaries remain independent: `ExecutionTrustGuard` decides whether this exact local code execution is trusted, `PermissionGuard` and brokers authorize each filesystem, network, and Secret operation, and the one-shot Utility Process contains failures. A supported API allowlist, a user actor, an imported definition, or a resource grant never substitutes for execution trust.

Before a manual Workflow starts any side effect, it preflights every reachable Node.js node and child Workflow. Missing trust may be granted for this run or persisted for the current execution revision. Import confirmation creates no execution grant. A Node.js Automation is saved disabled after creation or an execution-relevant change; enabling atomically persists trust before enabling. Scheduled and missed runs never prompt. Missing, stale, or revoked trust prevents execution and puts the Automation in `EXECUTION_TRUST_REQUIRED`. An Automation that invokes Workflows binds the reachable child execution revisions as part of the same approval.

Persistent grants are local-only and bind the trusted user, definition identity, node or Action identity, exact script-text digest, capability version, host and module configuration, working directory, filesystem grants, network permissions, Secret reference identities, Automation trigger and execution policy, and reachable child Workflow revisions. Their canonical digest is `executionRevision`. Script bytes, entry identity, capability version, permissions, execution policy, or reachable execution revisions changing invalidates the grant; names, descriptions, node positions, runtime input values, and Secret value rotation do not. Existing Workflow revisions and Automation `configVersion` remain audit evidence but are not the authorization key because they also change for non-executable edits.

Approval shows the complete script, changes from the last approved script, capability version, file access, network and Secret references, and Automation schedule. Synapse does not offer a global “trust all Node.js scripts” choice. Grants can be revoked for one node or Action, one Workflow or Automation, or all Node.js execution. Revocation blocks new runs and broker calls and cancels an uncommitted run; completed external side effects are not rolled back. Grants are never exported in Workflow shares.

Restricted JavaScript has the distinct `restricted_code_with_brokered_network` risk class. It does not require local-code execution trust, but brokered network and Secret operations remain independently authorized. Synapse may publish that lower risk class only after implementation demonstrates that Node, `process`, and local filesystem authority are unreachable.
