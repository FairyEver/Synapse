# Separate terminal interrupt, terminate, and force terminate

Terminal control distinguishes three operations. Ctrl+C is a semantic input action that only attempts to interrupt the foreground task, leaves lifecycle unchanged, requires a valid automation write lease, and reports input acceptance rather than program response; a user's emergency interrupt may first invalidate the automation lease. Normal termination is a separate lifecycle operation authorized by stop permission, requires no write lease, moves an accepted request to `stopping`, and reaches `ended` only after confirmed exit. Forced termination is an explicitly requested higher-risk escalation with stronger authorization and separate audit, and no timeout policy may trigger it silently.

Repeated requests at the same termination level idempotently return the existing operation. Escalating a normal termination creates a new `forceOperationId` linked to the original `stopOperationId` rather than reusing one identity and obscuring the audit trail. A stopping session rejects ordinary input but remains readable and permits status observation and explicit force escalation. Termination promises only control of the Synapse-managed PTY session and processes or process tree that the platform can terminate with it; detached daemons, PM2-managed processes, and external services may survive and must be managed through their own commands. Whether deletion may implicitly terminate a running session remains a separate decision.
