# 工作流分享包不携带 Automation 实例

工作流分享以复现可手动运行的工作流程为边界，当前分享依赖集包含入口工作流及其递归子工作流，但不包含以这些工作流为执行动作的 Automation、触发器配置、启用状态、作用域、工作目录、执行策略或 Automation 运行历史。导出预检发现关联 Automation 时只显示数量和未包含提示；导入不得创建或启用触发器。

Automation 是具有独立生命周期和副作用的对象。将发送方的定时、Webhook 或其它触发配置自动复制到接收方环境，可能在未确认的时间和权限上下文中执行工作流，因此不能把它当作工作流内部依赖。分享包格式可以为未来扩展预留 Automation 模板能力，但该能力必须由发送方显式选择、由接收方明确确认，并在导入后保持禁用，不能改变当前默认边界。

同一谱系原地更新会保持接收方本地工作流身份，因此接收方已有的关联 Automation 也会继续绑定该工作流。导入计划必须使用新版工作流参数定义重新校验这些 Automation；仍兼容的 Automation 保持配置和启用状态，不兼容的 Automation 必须在最终确认中列出，并随导入事务禁用、标记为需要更新。其配置和运行历史继续保留，用户修复后可以重新启用。正在执行的关联 Automation 必须阻止导入提交，不得由导入自动停止。
