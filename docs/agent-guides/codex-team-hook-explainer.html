Architecture explained / v1.0.3

Codex 团队 Hook技术方案

成员把 Markdown 链接交给 AI，由 AI 安装和管理。本地 Hook 每次命中采集目录后，下载并执行远端采集器，把用户输入或最新回复写入专用云表。

macOS · Python 3.9+无需成员登录 Sy本地薄入口 · 远端维护采集逻辑
01

五个角色，各自负责什么

Public document操作 Markdown

解释安装、检查、诊断、配置、更新、卸载。

Member's AI成员的 AI

读取说明，询问姓名与目录，修改本机配置。

Local entry本地 launcher

响应 Codex 事件，匹配目录，下载并调用远端程序。

Remote logic远端 collector

提取卡片答案，执行过滤、字段映射、正文分片和单次提交。

Private records专用云表

匿名新增；原始对话不向匿名访问者开放读取。

Markdown 是给 AI 看的操作规程。它不参与每条消息的上报，也不会在每次 Hook 触发时重新读取。运行时下载的是 collector 脚本。

安装与管理这一层

“根据这个文件初始化 / 检查 / 卸载” → AI 重新读取同一份 Markdown → 只执行本次请求的动作。管理操作没有另一套 launcher CLI。

消息采集这一层

Codex 事件 → 本地启动器 → 远端脚本 → 云表。这里由程序自动执行，AI 不需要每轮自行决定是否上报。

一条消息，如何走完整条链路

选择一个情形，查看程序会执行到哪里。目录判断发生在下载之前；超时和异常最终都返回正常 Hook 输出，不要求 Codex 中断对话。

本页为交互示意，仅改变页面展示，不运行 Hook、不下载脚本、不提交记录。外层超时 15 秒；下载硬限 5 秒；远端执行硬限 6 秒。

    UserPromptSubmit 提供 prompt；Stop 提供 last_assistant_message。

    已触发

  2. 读取配置，匹配 cwd

    检查 enabled、姓名、根目录；按真实路径和路径组件匹配。

    命中

  3. 重新下载 collector

    请求稳定的公开 HTTPS 地址，校验长度、UTF-8 和 Python 语法。

    已下载

  4. 执行远端逻辑

    标准输入传 envelope v1；过滤、字段映射、分片在 collector 中处理。

    一条消息的所有分片装入一个批次；不自动重试或补发。

03

为什么改采集逻辑，不必逐台改 Hook

启动器保存的是稳定脚本地址。每次命中目录都重新下载，因此发布者替换同一地址的 collector 后，下一次触发会使用新版。文档、启动器、采集器分别管理版本。当前文档为 1.0.3，launcher 仍为 1.0.1、注册格式仍为 2；collector 1.0.2 增加提问卡片答案提取，已有 Hook 下次触发即可使用。

发布者改哪里

替换同一链接的 collector

例如提取卡片答案、更换目标表、过滤规则或字段映射，保持 envelope v1 兼容。

成员做什么

无需修改本地 Hook

只要协议和运行地址兼容，姓名、目录、注册命令都保持原样。

何时使用新内容

下一次命中目录的事件

已在运行的请求可能仍执行旧版；失败的历史消息不会补采。

初始化时，AI 核对 launcher 的固定 SHA-256。collector 则是发布者可更新的程序，运行时不通过固定 SHA 将其锁死；它以成员当前用户权限执行。成员需要信任这个发布者。

读取本机姓名、目录、启停配置内部请求过滤规则
按事件 cwd 判断是否在范围内目标云表和字段映射

04

发什么、存什么、谁能看

只取事件提供的正文

  • UserPromptSubmit → user读取 prompt；普通输入原样记录，提问卡片只保留用户填写的 answer。
  • Stop → assistant读取 last_assistant_message；不回扫整个聊天或 transcript。
  • 附带必要元数据成员自报姓名、匹配根目录名称、会话/轮次 ID、事件 ID、时间、平台和版本。

不主动收集其他内容

  • 不单独读取附件、思考或工具输出正文中本来包含这些文字时，仍按正文原样处理。
  • 不发送完整 Hook payloadenvelope 不含项目绝对路径、transcript 路径或其他未批准字段。
  • 不遍历项目文件目录配置用于判断事件是否匹配，不代表读取整个目录的文件。
配置根目录示例事件 cwd判断
/Projects/team-app/Projects/team-app/src命中，项目名为 team-app
/Projects/team-app/Projects/team-app-old范围外，不因字符串前缀相似而命中
一个或多个已选根目录重叠根目录的子目录采用最长匹配根；按真实路径解析

判断依据是事件 cwd。聊天中执行一次 shell cd，不表示事件 cwd 会随之改变。清空采集目录后，不匹配任何项目。

提问卡片先提取答案，再上报。原始卡片只通过本地 stdin 进入下载后执行的 collector；构造 POST 前仅提取 answer，不上传问题、卡片 ID 或包装 JSON。多题答案按顺序用空行分隔，保留答案内部换行、空格和 Unicode。空字符串答案不提交；结构异常不回退上传原文。普通文本与助手回复不做这项转换。

长消息：完整分片，一次提交

event_id · 1 / Nevent_id · 2 / N…event_id · N / N→ 按 part_index 重组原文
48 KiB每条 values 的 JSON 字节上限
900 KiB单个批次整体上限
100 条每批操作数上限
1 次每条消息的提交请求

分片按 UTF-8 JSON 的实际字节预算计算，保留中文、换行、引号和 emoji 原文。整批超限就放弃整条消息，不截断，也不拆成多批逐次发送。启动器原始输入上限为 4 MiB，远端源码上限为 256 KiB。

公开的是程序和说明

操作 Markdown、launcher 和 collector 是公开资源。成员配置不保存表 ID、表主 token 或 API Key；目标表只在 collector 中维护。

记录只开放匿名新增

“Codex 团队对话记录”云表不开放匿名读取、修改、删除和公开统计。成员无需 Sy 账号；表主用已登录身份回读。姓名自报，因此无法防止他人冒填。

05

所有管理动作，共用一份 Markdown

给成员的是一句话。具体步骤写在远端 Markdown 中，AI 每次接到管理请求都重新读取。姓名和采集目录由成员确定，可设置一个或多个目录，之后随时追加、移除或替换。

初始化：AI 具体会做什么

先检查已有安装和归属 → 复用已明确的姓名、目录，缺什么才询问 → 下载并校验 launcher → 创建权限受限的配置和安装回执 → 合并 UserPromptSubmit / Stop 两个 handler，保留其他 Hook → 按 Codex 正常机制审核 → 用合成输入和回复验收。

初始化先检查残留。已确认的卸载残留先清理，再重新收集本次姓名与目录；明确重装时也先删除旧安装，新配置默认 enabled=true，不静默复用旧姓名、目录或停用状态。只有完整健康安装的普通重复初始化保持幂等。

检查、诊断：默认只读

读取配置、回执、源码和必要权限，核对命令转义、事件、版本、目录匹配和最近 outcome。可有界获取公开文件做静态检查，但不执行 collector、不发测试记录、不创建备份或回执。无法读取官方信任状态时报告 unknown。

诊断只给证据、原因和建议。用户明确请求修复或测试上报时，才执行对应变更。

配置和启停：只修改指定字段

姓名、目录、enabled 分别修改；先验证、备份并核对并发变更。修改目录不重置姓名，也不启用停用中的 Hook。后续事件重新读取配置，不补采旧消息。启停只影响本方案，不关闭其他 Hook。

升级：先判断本地入口是否需要变

文档或 collector 更新本身不要求重装。启动器版本、源码、协议或运行地址确实变化时，才备份并升级本方案，保留成员配置和其他注册。本次 1.0.2 的注册格式增加内联缺失文件保护，即使 launcher 源码不变，也须更新旧的直接调用命令。更新保留成员配置；“重新安装”则先清理再全新配置。

卸载：删除本方案文件和注册

证明归属后，临时备份、停用并精确移除本方案 handler；等待有限在途窗口，再删除本方案 launcher、配置、回执、last-run、备份和已确认缓存，最终移除安装目录。成功后清理临时副本，不保留占位脚本或把旧配置搬到别处。保留其他 Hook；未知文件不盲删，未清理完不能报告完成。

格式 2 的注册命令自带内联保护：安装文件已删除时输出 {}、退出 0，不读输入、不重建目录。旧版聊天缓存的直接 Python 命令无法追溯修改，需关闭重开。官方全局信任记录无法安全定位时单独报告未核实，不清空全局数据库。卸载不删除云表、历史记录、公开素材或用户项目。

电脑上实际留下哪些文件

默认目录 ~/.codex/hooks/sy-team-capture/；如已设置 CODEX_HOME，则使用对应配置目录，AI 不修改该环境变量。

文件用途
launcher.py薄启动器；安装时核对发布源码 SHA-256
config.jsonversion=1、enabled、member_name、project_roots
installation.json安装来源、版本、SHA、精确 handler、归属和审核/验证情况

目录权限为 0700，主要文件为 0600。两个事件使用注册格式 2 的内联缺失文件保护，合并到 Codex 配置中；无需多装一个保护文件。必要时只修改 features.hooks 对应字段。命令通过参数数组和 shlex.join 生成，安全处理空格、引号和 $() 等特殊路径。

06

“配置好了”不等于“已经采到了”

配置已写入文件和注册存在
enabled=true本方案配置允许采集
官方已信任Codex 允许执行确切定义
事件已执行有程序运行证据
表主已回读正文与输入/回复核对一致

这些状态要分别判断。页面展示的是方案和历史验收，不是在检查你当前电脑。只看到 Hook 输出 {}，无法判断数据是否到达；last-run: success 也只是程序回执。

outcome / 现象说明
skipped / 没有新回执停用、范围外、空回复或不适用事件可能直接跳过，通常不更新 last-run。
filtered命中远端已知内部请求过滤规则。
invalid输入、协议、内容或容量不符合要求，不等于网络故障。
download_failed下载、完整性、语法、子进程启动或下载时限失败；本次不执行 collector。
script_failed / script_timeout远端程序异常或超过 6 秒；可能已发出请求，不能认定云端没有记录。
failed服务器明确拒绝；本版不自动重试。
unknown可能已提交，但没有有效完整回执；不重发，避免制造重复。
success收到合法提交回执；仍需表主独立回读才能确认正文。
  • 可信发布者动态代码每次下载的程序以当前用户权限执行，没有新增沙箱或签名体系。公开资源可读，不代表可以不信任发布者。
  • 有限等待，失败丢失同步调用外层 15 秒，无正文队列、后台常驻、自动重试或补发。超时不证明服务器未写入。
  • 过滤是尽力识别已知内部请求可过滤；未知内部请求和关联回复仍可能混入。Stop 文本也不保证覆盖所有客户端、继续回合和中断组合。
  • 首版范围与聊天缓存正式范围是 macOS + Python 3.9+；Windows 未验收。已有聊天可能缓存配置，需重新打开并独立验收；官方审核仍由成员完成。
