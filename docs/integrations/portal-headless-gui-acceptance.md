# Portal Headless 本机 GUI 验收

日期：2026-09-22。用户已启动 `pnpm dev`，SY 连接本机开发环境。所有应用点击、输入与页面观察均使用 Computer Use；没有通过直接调用内部 IPC 或伪造授权回调替代用户流程。

## 执行记录

| 场景 | 观察结果 |
| --- | --- |
| 未登录时打开 Portal 连接开关 | 提示“请先登录 Synapse”，不进入连接 |
| 点击 SY 登录 | 打开 localhost 的登录页，浏览器会话完成回调，桌面显示已登录 |
| Portal 授权 | 开关显示“连接中”；浏览器窗口暂时无法被 Computer Use 读取，由用户完成授权，桌面随后显示已连接 |
| 未连接时询问会议室占用 | AI 加载 Skill，search/invoke 找到扩展工具；取凭证失败后停止，没有编造业务数据 |
| 已连接后重试会议室占用 | 凭证工具成功，AI 直连 localhost:3000 的扩展后端，返回 4 个会议室及实际占用记录；首轮界面显示约 28 秒完成 |
| 查询本人今年年度协议 | 服务端配置中有该能力，但当前会话菜单目录不可见；未执行年度业务读取，不能据此认定部署缺失、无权限或无协议记录 |
| 修正后新会话同时查询会议室与年度协议 | 界面显示 51 秒完成；会议室结果再次返回，跨天记录按当天 00:00–23:00 描述；年度查询返回 CAPABILITY_NOT_VISIBLE，AI 正确区分服务端配置和会话可见范围 |

## 发现与修正

1. 首轮 AI 把到当日 23:00 的跨天占用概括为全天。补充 Skill 指引后，新会话明确保留 23:00–24:00 未被该记录覆盖的区别，也没有保证可以直接预订。
2. context 的 allowedCapabilities 被误读为当前会话能力，导致 AI 将年度目录缺失解释成漏部署。改为 configuredReadCapabilities；已配置但当前目录不可见时返回 CAPABILITY_NOT_VISIBLE，并增加合成回归测试。
3. 补充以业务结果为主的回答指引。新回复使用紧凑会议室表格，但年度协议部分仍包含较多技术名词；单次生成结果不代表模型每次都同样简洁。

通过应用内 Synapse Skill → CC/Synapse → 重新安装，更新了已有全局 Skill；然后创建新会话复测，没有修改其它客户端的 Skill 或权限模式。

## 验证与边界

- 后端专项 12 项、系统 Skill 与能力表面 33 项通过；后端 typecheck 通过。
- 没有创建、修改或取消 Portal 业务记录，没有更换身份、放开能力名单或绕过菜单限制。
- 本轮真实通过的是本机开发环境的会议室完整链路；年度协议只验证了不可见时的拦截与提示，未完成年度数据的成功读取。
- Portal 确认页由用户操作，未宣称自动化覆盖；未验证生产部署、其它账号、跨平台或凭证远程吊销。
- 验收文档不保存原始凭证、工具参数或完整业务数据。测试对话保留在应用的“本地对话”中供用户查看。
