真实数据库使用临时 127.0.0.1 PostgreSQL 实例、`skill_hub_e2e` 数据库、合成账号与本地临时对象目录。已执行包括 `20261104010000_skill_hub` 的 Prisma 迁移；测试结束移除了该实例和临时对象。没有对任何业务数据库执行迁移。

- 登录、第一页一条但实际多团队、正常发布、响应在提交后被夹具断开、原键回执、不同账号查不到他人回执、重放不新增资产、同内容返回 unchanged；旧版本不能下载。
- 从同一 v1 并发提交两个候选，恰好一个成功；等待真实 PostgreSQL 行锁期间分别移除成员、停用账号和更换维护者，原请求均被拒绝，没有新增包版本。
- 管理员通过真实接口交接、查看治理元数据和恢复；删除原贡献者账号后资产及显示记录仍存在。已软删除资产保护团队，缺少包字节拒绝恢复，补回原字节后恢复成功，图标和包字节保留。
- 备份实际持有 PostgreSQL 回收栅栏期间替换图标，GC 不处理对象；导出的旧图标与源字节一致，解除栅栏后旧图标可回收。这里验证的是实际栅栏与字节复制，并非生产 COS 恢复演练。
- Node 进程直接调用编译后的桌面 MCP `search/invoke` 路由，使用真实桌面包准备、SQLite/DataRepository、文件快照、Worker 和云客户端，账号来源注入合成 Bearer 且每次经真实 HTTP 认证。十项 Hub 工具均实际调用，旧工具不可用；公开表面仍只有两个顶层工具。未启动桌面应用或 MCP 网络服务。

浏览器检查了 320、768、1280 px 目录／详情和实际展开的团队选择、上传、商店资料冲突、版本错误、删除、分页指派、恢复及缺包失败。1600 px 验证三列布局。校验了对话框留白、边界、焦点、长名称／文件名、返回保留筛选，以及 PNG/JPEG/WebP 实际解码成 256×256 PNG。首轮发现长团队名撑开菜单，修正宽度后重新验收。截图由夹具写入 `/tmp/synapse-skill-hub-*-<宽度>.png`。

尚未验收：真实 Synapse 冷／热启动、系统协议注册、真实编辑器路径安装、桌面 Electron WebP 解码、生产 COS 和有签名发布包。生产迁移尚未执行；上线前需配置独立 Skill Hub 桶和可恢复的对象备份。回退时保留表、内部版本和对象字节，停用功能入口或回退应用代码；不能通过删表、清空桶或执行旧退役脚本回退。
