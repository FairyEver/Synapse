# 步骤 2：跑通 CICD

## 目标

从项目最早期就建立完整的 CI/CD 流水线，确保每次合并到主分支后能自动打包并发布安装包。这是产品设计文档第 47 节的核心要求。

## 要做的事

### 2.1 引入 electron-builder

- 安装 `electron-builder` 作为打包工具
- 在 `package.json` 中配置 `build` 字段，定义打包参数
- 配置产物：
  - **macOS**：DMG 安装包
  - **Windows**：NSIS 安装包（exe）
- 配置应用信息：appId、productName、图标等

### 2.2 配置 GitHub Actions 工作流

- 创建 `.github/workflows/release.yml`
- 触发条件：当代码合并到 `main` 分支时自动触发
- 流水线步骤：
  1. Checkout 代码
  2. 安装 Node.js 和 pnpm
  3. 安装依赖
  4. 构建渲染进程（`pnpm build:renderer`）
  5. 构建主进程（`pnpm build:electron`）
  6. 使用 electron-builder 打包
  7. 上传产物到 GitHub Release

### 2.3 多平台构建矩阵

- macOS 构建使用 `macos-latest` runner
- Windows 构建使用 `windows-latest` runner
- 两个平台并行构建

### 2.4 版本号管理

- 版本号从 `package.json` 的 `version` 字段读取
- Release tag 使用 `v{version}` 格式
- 每次发版前手动更新 `package.json` 中的版本号

### 2.5 自动更新基础准备

- 配置 electron-builder 的 `publish` 字段指向 GitHub Releases
- 后续步骤（步骤 18）会实现软件内的检查更新功能，此处只做基础配置

## 注意事项

### 签名问题

- macOS 打包需要代码签名，初期如果没有 Apple Developer 证书可以先跳过签名
- Windows 打包也可以先不签名，但要注意用户可能会看到安全警告
- 在 GitHub Actions 中通过环境变量 / Secrets 管理签名证书

### 产物命名

- 产物文件名应包含版本号和平台信息，例如：
  - `Synapse-0.1.0-mac-arm64.dmg`
  - `Synapse-0.1.0-win-x64.exe`

### GitHub Token

- 发布 Release 需要 `GITHUB_TOKEN`，GitHub Actions 内置提供
- 如果使用 electron-builder 的 `publish` 功能，需要配置 `GH_TOKEN` 环境变量

### 开发分支策略

- 日常开发在 `dev` 或功能分支上进行
- 合并到 `main` 触发打包发布
- 确保 `main` 分支始终是可发布状态

## 验收标准

1. 推送代码到 `main` 分支后，GitHub Actions 自动触发
2. 流水线成功完成，无报错
3. GitHub Releases 页面出现新的 Release
4. Release 中包含 macOS DMG 和 Windows exe 安装包
5. 下载安装包可以正常安装并启动应用
