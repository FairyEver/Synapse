# 步骤 5：Settings 模块

## 目标

实现 Settings 页面，采用声明式配置驱动的架构。这是产品设计文档第 37、38 节的实现。Settings 本质上是对本地 JSON 配置的可视化编辑。

## 要做的事

### 5.1 页面布局

- **左侧**：设置分类侧边栏
- **右侧**：当前分类下的设置项列表
- 整体交互参考 VSCode 设置页

### 5.2 声明式设置项定义

每个设置项应以声明式方式定义，包含以下字段：

```typescript
interface SettingItem {
  key: string;              // 配置的 key，对应 config.json 中的路径
  label: string;            // 显示名称
  description?: string;     // 描述说明
  category: string;         // 所属分类
  type: 'text' | 'select' | 'toggle' | 'number' | 'path' | 'list';  // 控件类型
  defaultValue: any;        // 默认值
  options?: { label: string; value: string }[];  // select 的选项
  validation?: (value: any) => string | null;    // 校验规则
  visible?: (config: Config) => boolean;         // 是否显示的条件
  scope: 'global' | 'repo';                      // 全局或仓库级
}
```

### 5.3 设置分类规划

根据产品设计，当前至少包含以下分类：

1. **通用** — 用户昵称、语言等全局设置
2. **仓库** — Git 仓库管理（添加/切换/删除仓库）
3. **内容** — Rules 目录名、Skills 目录名等仓库级设置
4. **项目** — 本地项目路径管理
5. **关于** — 版本信息、检查更新

### 5.4 仓库管理 UI

在仓库分类下实现：
- 仓库列表展示（名称、地址）
- 添加新仓库
- 切换当前激活仓库
- 删除仓库配置
- 切换仓库后**直接 reload 软件界面**（产品设计第 9.3 节）

### 5.5 用户信息设置

- 用户昵称 / 显示名称输入框
- 此昵称用于后续创建 Rule / Skill 时的 author 字段
- 也用于 PR 分支命名

### 5.6 渲染引擎

- 根据设置项的声明式定义，自动渲染对应控件
- 修改后立即保存到本地配置文件
- 不需要"保存"按钮，修改即生效（参考 VSCode 体验）

## 注意事项

- Settings 必须做成**易维护、易扩展、配置驱动**，不能写成散乱的 JSX
- 新增设置项时，只需要在定义数组中增加一条记录
- 切换仓库后 reload 界面，不要做复杂的无缝热切换
- 仓库添加后需要生成 UUID 作为本地缓存目录名（产品设计第 8.4 节）
- 关于/版本/检查更新部分在此步骤只做 UI 框架，实际更新逻辑在步骤 18 实现

## 验收标准

1. Settings Tab 下显示左侧分类 + 右侧设置项
2. 点击左侧分类可切换右侧内容
3. 修改设置项后，重启应用设置持久化
4. 可以添加和切换 Git 仓库配置
5. 设置项使用声明式定义，新增项只需添加配置
