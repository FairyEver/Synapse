# 步骤 17：安装流程与项目系统

## 目标

完成从“点击安装”到“真正写入目标位置”的完整链路，并实现项目路径管理。这是产品设计文档第 32、33、34、35、44 节的实现。

## 要做的事

### 17.1 项目系统

- 在全局配置中维护项目列表
- 每个项目至少包含：
  - `id`
  - `name`
  - `path`

- 项目本质是本地文件夹，不绑定任何编辑器

### 17.2 安装入口

- 用户从操作按钮下拉菜单中选择某个编辑器后
- 弹出第二层对话框，让用户选择：
  - 安装到全局
  - 安装到项目

### 17.3 全局安装

- 如果所选编辑器支持全局安装，则把内容写入对应全局目录
- 如果不支持，全局选项应禁用或隐藏

### 17.4 项目安装

- 如果用户选择项目安装：
  - 先选择某个已保存项目
  - 再根据编辑器 adapter 解析该项目下的目标位置

- 也可以提供“浏览目录”方式，作为项目列表之外的补充入口

### 17.5 Rule 安装行为

- Rule 安装为单文件写入
- 写入目标路径由 adapter 决定
- 如果目标文件已存在，可按覆盖策略直接替换

### 17.6 Skill 安装行为

- Skill 安装采用**整体覆盖**策略
- 如果目标目录已存在：
  - 不做增量合并
  - 直接用新目录整体替换旧目录

- 需要保证替换过程尽量原子化，避免半覆盖状态

### 17.7 复制能力接入

- Rule 允许复制正文到剪贴板
- 只有单文件 Skill 允许复制
- 多文件 Skill 菜单中不展示复制，或展示但禁用并给出原因

### 17.8 安装结果反馈

- 成功时给出明确反馈：
  - 安装成功
  - 已写入目标位置

- 失败时给出具体失败原因：
  - 目标目录不可写
  - 编辑器未安装
  - 项目路径不存在
  - 覆盖失败

## 注意事项

- 项目列表是全局共享的，不按编辑器分组
- “安装到指定目录”本质上应走与项目安装相近的能力，不要再单独造一套写入逻辑
- Skill 覆盖是明确的破坏性策略，必要时应有二次确认或清晰提示
- 写入文件前要确保父目录存在，失败时要清晰回滚
- 安装逻辑全部在主进程执行，避免渲染进程直接触碰用户文件系统

## 验收标准

1. Settings 中可维护全局项目列表
2. 选择编辑器后会出现全局 / 项目二次选择弹窗
3. Rule 可按编辑器规则安装到目标位置
4. Skill 安装会整体替换旧目录，而不是做增量合并
5. Rule 与单文件 Skill 支持复制，多文件 Skill 不支持复制
