# 步骤 13：内容生成与本地写入

## 目标

把 Rule / Skill 的创建请求转换为仓库中的真实文件结构，确保目录、文件名、元数据格式全部符合产品约束。这是产品设计文档第 15、16、17、18、19、26.2、27.2 节的实现。

## 要做的事

### 13.1 生成内容 ID

- 创建内容时生成统一 ID：
  - 格式：`uuid_timestamp`
- 该 ID 同时用于：
  - 目录名
  - `meta.json` 中的 `id`

### 13.2 生成 `meta.json`

- 根据创建表单和本地配置生成元数据
- 至少写入以下字段：
  - `id`
  - `type`
  - `title`
  - `description`
  - `category`
  - `icon`
  - `iconBg`
  - `author`
  - `gitUser`
  - `createdAt`

### 13.3 Rule 写入规则

- Rule 目录结构必须严格固定：

```text
rules/<id>/
  meta.json
  main.md
```

- 不允许出现第三个文件

### 13.4 Skill 写入规则

- Skill 目录结构至少包含：

```text
skills/<id>/
  meta.json
  main.md
  ...附件
```

- 所有附件保留原始相对目录结构

### 13.5 写入位置

- 写入目标是当前激活仓库的本地工作目录
- Rules 与 Skills 主目录名从当前仓库配置读取，不要硬编码成 `rules` / `skills`

### 13.6 安全校验

- 写入前进行以下校验：
  - 目标目录不存在同名 ID
  - Skill 附件路径不包含 `../` 等越界路径
  - Rule 不包含任何附件
  - 文件名固定为 `main.md` / `meta.json`

### 13.7 失败回滚

- 如果写入过程中某一步失败：
  - 不要留下半成品目录
  - 要么整项写入成功，要么整项清理干净
- 建议在临时目录生成完成后再移动到目标目录

## 注意事项

- 内容写入必须放在主进程执行，不要让渲染进程直接操作仓库目录
- `createdAt` 建议统一使用 ISO 时间字符串
- `author` 使用用户昵称，`gitUser` 使用当前 Git 身份，两者不要混淆
- `meta.json` 建议稳定格式化输出，方便后续 Git diff 阅读
- Skill 的附件路径要特别防止路径穿越问题

## 验收标准

1. 创建 Rule 时能生成合法的目录、`meta.json` 和 `main.md`
2. 创建 Skill 时能连同附件一起落盘，并保留目录结构
3. 目录名与 `meta.id` 完全一致
4. 写入失败不会留下半成品目录
5. Rules / Skills 主目录名来自仓库配置
