# 内置资源产品改造方案

## 背景

当前 Synapse 在创建本地仓库或初始化空目录时，会把应用包内的默认资源复制成仓库内容：

- `desktop/resources/templates/rules/synapse-test-rule`
- `desktop/resources/templates/skills/synapse-test-skill`
- `desktop/resources/templates/prompts/test-universal-prompt`

对应链路：

- `repository-template-service` 读取 `resources/templates/{rules,skills,prompts}` 下的 `meta.json`、`content.md` 和 Skill 附件。
- `repository-structure-service` 在 `createLocalRepository`、`initializeStructure` 中调用 `readRepositorySeedContents()`，再通过 `writeSeedContent()` 写入仓库目录。
- 写入后的默认资源和用户创建资源没有产品层面的区别，可以编辑、删除、进入最近删除、参与仓库同步。

这导致三个问题：

1. 默认资源污染用户仓库，初始化后仓库天然带有非用户资产。
2. 默认资源被编辑或删除后，软件升级无法可靠更新。
3. 默认资源和用户资产权限相同，无法表达“系统提供，仅可使用”的产品边界。

## 目标

把当前默认复制进仓库的技能、规则、提示词改造为系统内置资源：

- 不再随仓库初始化写入用户仓库。
- 在规则、技能、提示词各自模块中显示在固定分类“内置资源”下。
- 内置资源不可编辑、不可删除、不可永久删除、不可恢复。
- 内置资源可以下载。
- 内置规则和内置技能可以安装到编辑器。
- 内置提示词保持现有能力：可复制、可下载，不支持安装到编辑器。
- 内置资源只随软件版本更新，不随仓库同步或用户编辑变化。

## 非目标

- 不做在线资源市场。
- 不做用户自定义“内置”资源。
- 不把内置资源写进当前仓库的 Git 历史。
- 不迁移用户已编辑过的历史默认资源。
- 不改变 Rule、Skill、Prompt 的安装格式。

## 产品定义

### 资源来源

内容资源分为两类：

| 来源 | 含义 | 存储位置 | 可变更方 |
| --- | --- | --- | --- |
| 仓库资源 | 用户创建、同步、协作的内容 | 用户本地仓库 | 用户 |
| 内置资源 | Synapse 随应用发布的系统资源 | 应用安装包 | 软件更新 |

内置资源的稳定标识建议使用：

```text
builtin:<type>:<id>
```

示例：

- `builtin:rule:test-rule`
- `builtin:skill:test-skill`
- `builtin:prompt:test-universal-prompt`

对用户展示时不需要暴露 `builtin:` 前缀。

### 固定分类

每个内容类型都增加一个系统分类：

| 字段 | 值 |
| --- | --- |
| id | `builtin` |
| label | `内置资源` |
| order | `0` |

排序规则：

1. `全部`
2. `我的收藏`
3. `最近浏览`
4. 分隔线
5. `内置资源`
6. 原有业务分类
7. 分隔线
8. `最近删除`

`内置资源`分类只展示内置资源；普通分类不混入内置资源。`全部`包含普通资源和内置资源。

### 权限矩阵

| 操作 | 仓库资源 | 内置规则 | 内置技能 | 内置提示词 |
| --- | --- | --- | --- | --- |
| 查看 | 可用 | 可用 | 可用 | 可用 |
| 搜索 | 可用 | 可用 | 可用 | 可用 |
| 收藏 | 可用 | 可用 | 可用 | 可用 |
| 最近浏览 | 可用 | 可用 | 可用 | 可用 |
| 新窗口打开 | 可用 | 可用 | 可用 | 可用 |
| 复制正文 | 可用 | 可用 | 可用，提示仅复制主文件 | 可用 |
| 下载 | 可用 | 可用 | 可用 | 可用 |
| 安装到编辑器 | 按类型 | 可用 | 可用 | 不支持 |
| 编辑 | 可用 | 禁止 | 禁止 | 禁止 |
| 删除 | 可用 | 禁止 | 禁止 | 禁止 |
| 最近删除 | 可用 | 不进入 | 不进入 | 不进入 |
| 永久删除 | 可用 | 禁止 | 禁止 | 禁止 |
| 同步到仓库 | 可用 | 不参与 | 不参与 | 不参与 |

## 用户体验

### 内容列表

规则、技能、提示词模块仍保持当前结构：

- 左侧分类列表增加“内置”。
- 内容卡片保持现有卡片样式。
- 内置资源卡片显示在列表中，作者建议显示为 `Synapse`。
- 内置资源仍可通过搜索命中。
- 内置资源不显示同步中的状态。

不增加解释性横幅，不写“此分类用于……”之类说明。

### 详情页

详情页继续展示标题、简介、分类、作者、预览、源码、历史选择等现有结构。

内置资源详情页动作：

- 保留：下载、安装、复制、新窗口打开、收藏。
- 隐藏或禁用：编辑、删除。

建议直接隐藏“编辑”和“删除”，避免用户点击后才报错。

历史视图：

- 内置资源没有用户历史。
- 详情页历史选择可不展示，或仅显示一个当前版本。

### 下载

内置下载应复用现有导出格式：

- Rule：`.md`
- Prompt：`.md`
- Skill：`.zip`

Skill zip 内容应与当前安装格式一致，包含主说明文件与附件。

### 安装

内置安装应复用现有编辑器安装策略：

- Rule：走 `single-file` 安装策略。
- Skill：走 `directory-overwrite` 安装策略。
- Prompt：保持不支持安装。

变量替换、覆盖确认、目标目录选择等现有交互不变。

## 数据与模型

### 类型扩展

给内容摘要和详情增加来源字段：

```ts
type SynapseContentSource = "repository" | "builtin"

type SynapseContentSummaryBase = {
  source: SynapseContentSource
  readonly?: boolean
  // existing fields...
}
```

建议规则：

- 仓库资源：`source: "repository"`，`readonly: false`。
- 内置资源：`source: "builtin"`，`readonly: true`。

`readonly` 用于 UI 判断，`source` 用于业务分流。

### 内置资源清单

将当前 `resources/templates` 升级为内置资源目录，推荐命名：

```text
desktop/resources/builtin-content/
  rules/
    synapse-test-rule/
      meta.json
      content.md
  skills/
    synapse-test-skill/
      meta.json
      content.md
      files/
  prompts/
    test-universal-prompt/
      meta.json
      content.md
```

`meta.json` 继续保留现有字段，并增加：

```json
{
  "source": "builtin",
  "version": "1.0.0"
}
```

`version` 用于排查和未来展示，不要求用户当前可见。

### ID 策略

内部建议保留原始 id，同时在 IPC 层返回统一 id：

```text
builtin:<type>:<rawId>
```

下载、安装、详情读取时根据前缀路由到内置资源服务。

这样可以避免与仓库里同名 id 冲突，也避免内置资源被当作普通仓库目录读取。

### 作者和时间

内置资源建议固定：

| 字段 | 值 |
| --- | --- |
| createdBy | `synapse` |
| createdByDisplayName | `Synapse` |
| modifiedBy | `synapse` |
| modifiedByDisplayName | `Synapse` |
| createdAt | 内置资源版本发布日期，缺省可使用应用构建时间 |
| modifiedAt | 内置资源版本发布日期，缺省可使用应用构建时间 |

如果短期不想引入构建时间，可在 `meta.json` 增加 `updatedAt`。

## 系统设计

### 后端服务

新增 `builtin-content-service`：

职责：

- 从应用资源目录读取内置 Rule、Skill、Prompt。
- 校验 `meta.json`、`content.md`、Skill 附件。
- 返回符合 `SynapseContentMeta`、`SynapseContentDetail` 的对象。
- 支持读取内置 Skill 附件。
- 支持导出下载所需的文本或压缩包源数据。

建议接口：

```ts
listBuiltinContent(type): Promise<SynapseContentMeta[]>
getBuiltinDetail(type, builtinId): Promise<SynapseContentDetail>
getBuiltinContent(type, builtinId): Promise<SynapseTextContentFile>
isBuiltinContentId(id): boolean
parseBuiltinContentId(id): { type, rawId } | null
```

### 初始化链路

`repository-structure-service` 改造：

- `scaffoldNewLocalRepository()` 只创建目录结构，不写默认资源。
- `initializeStructure()` 只创建目录结构，不写默认资源。
- 删除对 `readRepositorySeedContents()` 和 `writeSeedContent()` 的初始化依赖。
- 保留 `rules/`、`skills/`、`prompts/` 目录和 `system/` 目录创建。

`repository-template-service` 改造方向：

- 重命名或拆分为 `builtin-content-service`。
- 不再被仓库初始化服务调用。

### 内容读取

`content-service` 改造：

- `listContent(type)` 返回仓库资源 + 内置资源。
- `getDetail(type, id)` 根据 id 判断读取仓库或内置。
- `getContent(type, id)` 根据 id 判断读取仓库或内置。
- `getHistory(type, id)` 对内置资源返回空数组或单版本。
- `listDeletedContent(type)` 只返回仓库资源。

列表合并排序建议：

- 默认按现有排序逻辑即可。
- 内置分类内按 `meta.order` 或标题排序。
- 如需固定内置资源顺序，可在 `meta.json` 增加 `order`。

### 内容写入

`content-submission-service` 和 IPC 层增加硬拦截：

- `updateContent`：如果 id 是内置资源，返回错误。
- `deleteContent`：如果 id 是内置资源，返回错误。
- `restoreContent`：如果 id 是内置资源，返回错误。
- `purgeContent`：如果 id 是内置资源，返回错误。

UI 会隐藏入口，但后端仍必须拦截。

### 下载与安装

`content-download-service` 改造：

- `exportAsTextFile()` 支持内置资源。
- `exportAsZipArchive()` 支持内置 Skill 附件从应用资源目录复制。

`content-install-service` 改造：

- Rule 安装读取内置正文。
- Skill 安装读取内置详情和附件。
- `repositoryRootPath` 仅用于仓库附件；内置附件应由 `builtin-content-service` 提供复制能力。

建议给安装策略传入统一的 `copyAttachment`，由上层根据 source 决定从仓库附件池或应用资源目录复制。

### 缓存

仓库索引 `content_index` 不存内置资源。

理由：

- 内置资源不属于仓库。
- 不需要 Git diff 增量更新。
- 随软件升级读取最新应用包即可。

前端 `RepositoryManager` 的 `contentCache` 可以继续缓存合并后的列表；刷新内容时重新从 IPC 获取即可。

## 兼容与迁移

### 新仓库

新建仓库和初始化空目录后：

- 目录结构存在。
- 不再出现默认 Rule、Skill、Prompt 的仓库目录。
- 页面中仍能看到“内置”分类和内置资源。

### 已有仓库

已有仓库里已经被复制进去的历史默认资源不自动删除。

原因：

- 用户可能已经编辑过。
- 自动删除会产生破坏性 Git 改动。

推荐处理：

- 保留为普通仓库资源。
- 新版软件同时显示内置版本。
- 若出现同名内容，用户可自行删除普通仓库副本。

### 重名处理

如果普通仓库资源与内置资源标题或 name 相同：

- 列表中同时展示。
- 普通资源按原分类展示。
- 内置资源只在“内置资源”分类展示。
- 安装时两者按各自 id 操作。

## 实施计划

### 第一步：停止初始化复制

目标：

- 新仓库不再写入默认资源。

改动：

- 修改 `desktop/electron/services/repository-structure-service.ts`。
- 移除初始化流程中 `readRepositorySeedContents()` 与 `writeSeedContent()` 的调用。
- 保留目录骨架创建。

验收：

- 新建本地仓库后，`rules/`、`skills/`、`prompts/` 为空或仅有 `.gitkeep`。
- 初始化空目录后不产生默认内容历史。

### 第二步：建立内置资源服务

目标：

- 应用能从安装包读取内置资源。

改动：

- 新增 `desktop/electron/services/builtin-content-service.ts`。
- 复用并改造当前 `repository-template-service` 的读取、校验、附件遍历逻辑。
- 将资源目录从 `resources/templates` 迁到 `resources/builtin-content`，或短期保留原目录但改语义。
- 更新 `desktop/package.json` 的 extraResources 配置。

验收：

- 打包前后均能读取内置资源。
- meta 校验失败时启动或调用接口给出明确错误。

### 第三步：内容列表合并

目标：

- 规则、技能、提示词列表展示仓库资源 + 内置资源。

改动：

- 扩展 `desktop/src/types/content.ts`，增加 `source` / `readonly`。
- 修改 `desktop/electron/services/content-service.ts` 的 list/detail/content/history 路由。
- 修改 `desktop/src/lib/content-categories.ts`，加入 `builtin` 分类统计。
- 修改前端筛选逻辑，让“内置”只包含内置资源。

验收：

- 无仓库内容时，三个模块仍显示内置资源。
- 点击“内置”只看到内置资源。
- 点击“全部”能看到内置资源和普通资源。

### 第四步：权限与动作

目标：

- 内置资源不能被编辑和删除，但能下载和安装。

改动：

- 修改 `ContentDetailDialog` / `ContentDetailMenubar`，内置资源隐藏编辑、删除。
- 修改 `content-submission-service` 或 `contentIpcModule`，对内置 id 拦截 update/delete/restore/purge。
- 修改 `content-download-service` 和 `content-install-service`，支持内置资源读取和附件复制。

验收：

- 内置资源详情页没有编辑、删除入口。
- 直接调用 IPC 删除内置资源会失败。
- 内置 Rule 可下载、可安装。
- 内置 Skill 可下载 zip、可安装，附件完整。
- 内置 Prompt 可复制、可下载。

### 第五步：测试与回归

目标：

- 防止初始化和权限回退。

建议测试：

- `repository-structure-service`：创建/初始化仓库不写默认资源。
- `builtin-content-service`：读取三类内置资源和 Skill 附件。
- `content-service`：列表合并、详情读取、内置历史返回。
- `content-submission-service`：内置资源写操作被拒绝。
- `content-download-service`：内置文本和 Skill zip 导出。
- `content-install-service`：内置 Rule / Skill 安装。

## 验收标准

1. 新建仓库后，仓库目录内不包含默认技能、规则、提示词内容。
2. 初始化空目录后，仓库目录内不包含默认技能、规则、提示词内容。
3. 规则、技能、提示词模块均有“内置资源”分类。
4. “内置”分类下展示随应用发布的系统资源。
5. 内置资源不可编辑、不可删除。
6. 内置资源不会进入“最近删除”。
7. 内置资源可以下载。
8. 内置规则和内置技能可以安装到编辑器。
9. 内置资源升级由软件版本控制，不依赖用户仓库同步。
10. 已有仓库里的历史默认资源不会被自动删除。

## 风险

### 旧默认资源重复出现

已有仓库可能已经存在默认资源，新版又显示内置资源。

处理：

- 接受短期重复。
- 通过“内置资源”分类清晰区分系统资源。
- 不自动删除用户仓库内容。

### 下载和安装依赖仓库附件池

现有下载、安装 Skill 时默认从仓库附件池复制附件。

处理：

- 内置服务提供附件复制能力。
- 下载和安装服务根据 `source` 分流。

### 前端只隐藏不够

用户或旧前端仍可能直接调用 IPC 写操作。

处理：

- IPC 或 service 层必须硬拦截内置资源写操作。

### 分类统计变复杂

当前分类统计按 `category` 字段聚合。内置资源需要固定分类。

处理：

- 内置资源返回 `category: "builtin"`。
- 普通资源如果历史上也使用 `builtin`，按普通资源处理时会进入“内置”分类。为避免歧义，应把 `builtin` 设为保留分类 id，新建/编辑表单不允许普通资源选择该分类。

## 推荐结论

采用“内置资源服务 + 内容列表合并 + 写操作硬拦截”的方案。

这个方案改动范围清晰，不污染用户仓库，也保留当前下载、安装、详情预览的大部分能力。初始化链路只负责仓库结构，系统资源由应用自身提供，产品边界更干净。
