## 必须修复的核心问题

当前 Feishu/Lark/Weixin QR 流程只是草稿：

- 点击 Feishu 后显示等待扫码，但没有二维码。
- 没有真实 begin。
- 没有真实 poll。
- 没有真实 save。
- 用户无法完成扫码接入。

这不是可接受状态。本阶段必须做完真实 QR onboarding 闭环。

## 必须实现的功能

### 1. Feishu / Lark QR onboarding

按旧 CC Connect 逻辑迁移：

```text
begin:
  init: POST https://accounts.feishu.cn/oauth/v1/app/registration action=init
  begin: action=begin, archetype=PersonalAgent, auth_method=client_secret, request_user_info=open_id
  返回 device_code, qr_url, interval, expires_in

poll:
  action=poll, device_code=<device_code>
  pending -> 继续等待
  slow_down -> interval += 5
  access_denied -> denied
  expired_token -> expired
  client_id + client_secret -> success
  tenant_brand=lark -> 切换到 https://accounts.larksuite.com 并 platform=lark

save:
  保存 app_id/app_secret/platform/owner_open_id/work_dir/agent_type
```

3S 迁移要求：

- 外部网络请求必须在 Electron main 侧服务执行。
- renderer 只能通过 typed preload/IPC 调用。
- UI 必须显示二维码。
- app_secret 只进入 secret 存储或 secret draft 写入链路，配置中只保存 secretRef。
- 成功后平台列表显示 configured Feishu/Lark。
- Lark 必须能从 poll 结果识别。

### 2. Weixin QR onboarding

按旧 CC Connect 逻辑迁移：

```text
begin:
  GET <api_base>/ilink/bot/get_bot_qrcode?bot_type=3
  返回 qr_key, qr_url

poll:
  GET <api_base>/ilink/bot/get_qrcode_status?qrcode=<qr_key>
  header iLink-App-ClientVersion: 1
  wait -> 继续等待
  scaned -> scanned
  expired -> 过期，可刷新或重试
  confirmed -> 必须含 bot_token 和 ilink_bot_id

save:
  保存 token/base_url/account_id/ilink_bot_id/ilink_user_id/work_dir/agent_type
```

3S 迁移要求：

- UI 必须显示二维码。
- `scaned` 要显示“已扫码，等待手机确认”。
- `confirmed` 后保存为 configured Weixin。
- token 只进入 secret 存储或 secret draft 写入链路，配置中只保存 secretRef。
- 过期时必须能重试或刷新二维码。

### 3. 手动平台表单补齐

当前 UI 只覆盖 Telegram。旧 Web Admin 的 `PlatformManualForm.tsx` + `platformMeta.ts` 覆盖更多手动平台字段。

要求：

- 优先基于 `connector-registry-service.ts` 的 descriptors 动态渲染手动平台表单。
- 覆盖至少旧 Web Admin 中已有的手动平台字段：telegram、discord、slack、dingtalk、wecom、qq、qqbot、line、weibo。
- secret 字段使用 password input，保存后只显示 secretRef/脱敏状态。
- 保存失败必须有明确错误反馈。
- 不要做独立平台商店，不要扩大到已确认不要的生态页。

### 4. Secret 真实保存

如果当前代码只生成 secretRef 和 secret draft，但没有把 secret value 写入安全存储，本阶段必须补齐。

要求：

- 使用现有 DataRepository `secrets` namespace 或项目已有 secret 写入机制。
- 如缺少 service，则新增最小 main 侧 service，不要在 renderer 保存 secret。
- secret 写入属于敏感操作，必须遵守 `PermissionGuard` / `AuditSink` / hard constraints。
- Raw TOML、日志、toast、report、git diff 不得出现测试 secret 明文。

### 5. UI 要求

- 使用现有 shadcn/ui 和 Tailwind token。
- 不写内联 style。
- 不写自定义颜色。
- 不做卡片套卡片。
- 不写“此功能用于...”这种废话。
- Feishu/Lark/Weixin QR 页面必须清楚显示：
  - 生成中
  - 二维码
  - 等待扫码
  - 已扫码，等待确认
  - 保存中
  - 已连接
  - 已过期
  - 已拒绝
  - 错误和重试
