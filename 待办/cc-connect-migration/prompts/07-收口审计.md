审计规则：

只允许输出两类问题：

A. manifest 中已有正式 ID 未闭合。
B. 有来源证据的新候选项，需要用户确认是否纳入正式范围。

禁止输出：

1. 泛泛优化建议。
2. 没有证据的可能遗漏。
3. 新架构设想。
4. UI 美化建议。
5. 与 CC Connect 功能全集无关的重构建议。

待办/cc-connect-migration/artifacts/7.1-final-audit.md
待办/cc-connect-migration/artifacts/7.2-reverse-coverage-check.md

如果 `待办/cc-connect-migration/artifacts/` 不存在，先创建该目录。

待办/cc-connect-migration/artifacts/7.1-final-audit.md 必须包含：

1. 审计结论：complete / incomplete
2. 未闭合正式 ID 列表
3. 产品设计未覆盖 ID 列表
4. 新发现候选项列表
5. 验收账本未通过项
6. 需要用户确认的 dropped / replaced / merged 项
7. 数据兼容、权限安全、golden 样本、人工验收、发布回滚未闭合项
8. 最终是否满足完成定义

1. 迁移期间新增或修改的页面、服务、API、IPC、preload API、数据模型、配置项、测试和状态项
2. 对应 CC ID
3. 对应 decision-log ID
4. 是否属于范围内
5. 范围外项处理方式

完成定义：

当 待办/cc-connect-migration/artifacts/1.2-feature-manifest.md 中所有正式 CC ID 都处于 done / merged / replaced / dropped，且 待办/cc-connect-migration/artifacts/4.1-verification-ledger.md 中对应验收项全部通过或有用户确认的豁免，则 CC Connect 迁移到 3S 完成。

同时必须满足：

1. 待办/cc-connect-migration/artifacts/7.2-reverse-coverage-check.md 中所有新增入口都能追溯到 CC ID 或 decision-log。
2. 数据兼容、权限安全、golden 样本、人工验收、发布回滚相关阻塞项均已关闭或有用户确认豁免。

如果满足完成定义，请明确写：

CC Connect 迁移闭环完成。

如果不满足完成定义，请只列出阻塞完成的具体 ID 和证据，不要扩展讨论。
