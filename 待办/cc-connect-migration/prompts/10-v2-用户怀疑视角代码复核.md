重点复核范围：

## A. 入口不是空壳

逐项检查 3S 中这些入口是否有真实代码路径：

1. 连接 / 项目列表 / 新建项目 / 项目详情。

4. 设置 > 服务商：全局 Provider、新增/编辑/删除、CC-Switch 导入、preset 助手。
5. 会话：会话列表、详情、历史 session、新建会话、发送输入框。
6. 会话事件：thinking、tool、result、error、permission、富消息、code copy。
7. 命令面板：打开、搜索、执行、结果面板、高风险确认。
8. 自动化：Cron、Heartbeat、Hooks 的列表、表单、启停、编辑、删除、测试。
9. 设置 > CC Connect：保存设置、Raw TOML 脱敏、reload、restart 确认、诊断。
10. Skills：内容库 / 项目扫描。

## B. 用户主链路

按用户实际使用顺序做静态代码追踪：

1. 新建项目。
2. 给项目添加平台。
3. 添加全局 Provider。
4. 把 Provider 绑定到项目。
5. 进入会话。
6. 新建 session。
7. 发送消息。
8. 查看事件/权限/富消息。
9. 打开命令面板执行安全命令。
10. 新建 Cron。
11. 配置 Heartbeat。
12. 创建 Hook。
13. 修改 CC Connect 设置。
14. 查看诊断。
15. 查看 Skills 项目扫描。

每一步都要给出代码证据路径，不能只写“应该可以”。

## C. 最容易出问题的地方

特别检查这些风险点：

1. UI 里按钮存在但没有 onClick / onSubmit。
2. UI handler 只改 React state，没有调用 preload/main。
3. preload 类型声明有，但 `desktop/electron/preload.ts` 没暴露。
4. IPC generated channel 有，但 module 没注册。
5. module 注册了，但 service registry 没有服务。
6. service 存在，但没有 DataRepository 持久化。
7. 测试只测纯函数，没有覆盖用户路径。
8. 表单保存敏感 token 明文。
9. 错误被吞掉或只 console.log。
10. 文案写“已完成/可用”，但代码实际 disabled。
11. source trace/report 说完成，但业务代码没有对应路径。
12. 仍有“后续批次接入/coming soon/暂未实现”之类过期文案。

## D. 与 CC Connect 源码的一致性

抽查至少 8 个关键能力，确认实现确实参考了旧源码，而不是凭空设计：

1. Provider 字段和 secretRef。
2. 项目 provider 绑定。
3. session list/detail。
4. chat send。
5. permission event。
6. command palette。
7. Cron 字段和 session mode。
8. Raw TOML 脱敏和 reload/restart。

需要读取对应的 `9.x-source-trace-*`，必要时再回到 `/Users/liyang/Desktop/code-guide/cc-connect-main` 用 `rg` 抽查旧源码。
