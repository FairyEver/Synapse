# 提示词 00：阶段验收门

把下面提示词完整发送给 Codex。每完成一个阶段后都运行一次。

```text
目标：对当前 CC Connect 迁移阶段的产物做验收门检查。只判断是否可以进入下一阶段，不扩展范围，不写业务代码。

请直接在当前仓库中读取当前阶段提示词列出的路径，不要要求用户手动粘贴文件内容。

不要依赖当前会话记忆判断这是第几次验收。请先检查 `待办/cc-connect-migration/artifacts/` 中是否已有当前阶段的验收报告，按已有报告数量判断本次是第几次验收。

验收报告文件名必须使用：

待办/cc-connect-migration/artifacts/0.<阶段编号>-validation-attempt-<次数>.md

示例：

待办/cc-connect-migration/artifacts/0.1-validation-attempt-1.md
待办/cc-connect-migration/artifacts/0.1-validation-attempt-2.md
待办/cc-connect-migration/artifacts/0.2-validation-attempt-1.md

如果这是同一阶段第 2 次或第 3 次验收，请先读取前一次验收报告和 A 的修复说明。

请读取：

1. 待办/cc-connect-migration/整体标准.md
2. 当前阶段提示词文件
3. 当前阶段已生成或更新的产物
4. 上一阶段产物
5. 当前仓库 AGENTS.md

验收规则：

1. 只检查当前阶段要求的产物是否满足提示词和整体标准。
2. 不允许提出没有来源证据的新功能。
3. 不允许输出泛泛优化建议。
4. 不允许把 open questions 当成正式功能。
5. 不允许跳过 manifest 中已有的正式 ID。
6. 如果发现问题，必须指向具体文件、具体 ID、具体字段。
7. 必须检查当前阶段是否满足端到端追踪规则：source inventory entry → CC ID → Synapse product baseline → product design location → migration map target → verification ledger item → development plan phase。
8. 如果 source inventory 中存在空白覆盖状态、未解释 excluded、未处理 blocked，不能输出 pass。
9. 同一阶段最多允许 3 轮验收失败。第 2 次失败时，只能输出真正阻塞下一阶段的问题。第 3 次失败时，必须要求进入 `待办/cc-connect-migration/prompts/00A-验收争议裁决.md`，不能继续普通复验。
10. 如果没有阻塞问题，明确输出 pass。

请输出：

阶段验收结论：pass / fail / needs-user-confirmation

同时写入本次验收报告：

待办/cc-connect-migration/artifacts/0.<阶段编号>-validation-attempt-<次数>.md

验收报告必须包含：

1. 阶段编号
2. 验收次数
3. 读取的产物文件
4. 验收结论
5. 阻塞问题
6. 需要用户确认的问题
7. 下一步动作

如果是 pass：

1. 写明可以进入的下一阶段。
2. 写明本阶段产物满足哪些完成条件。

如果是 fail：

1. 列出阻塞问题。
2. 每个问题必须包含：文件、位置或 ID、问题、修复要求。
3. 如果是覆盖问题，必须指出缺失链路是哪一段。
4. 必须写明这是当前阶段第几次 fail。
5. 不要输出非阻塞建议。

如果是 needs-user-confirmation：

1. 列出需要用户确认的功能 ID 或候选项。
2. 写明用户需要在纳入、合并、替代、丢弃中选择。

禁止输出：

1. 也许、可能、建议进一步、可以优化。
2. 没有证据的新需求。
3. 和当前阶段无关的重构建议。
4. 迁移实现代码。
```
