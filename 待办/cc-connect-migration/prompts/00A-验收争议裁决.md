# 提示词 00A：验收争议裁决

当同一阶段经过 A 执行、B 验收、A 修复、B 复验后仍无法通过时，把下面提示词完整发送给 Codex。

```text
目标：对当前阶段的验收争议做裁决，避免 A/B 无限循环。只判断是否阻塞进入下一阶段，不写业务代码，不扩展范围。

角色与职责：
你是验收争议裁决负责人。你的职责不是继续验收，也不是替 A 或 B 辩护，而是判断 B 当前 fail 的问题是否真的阻塞下一阶段。你只能裁决已有争议，不能新增问题。你的输出必须把问题裁成 continue-fix、pass-with-notes 或 needs-user-confirmation。

请直接在当前仓库中读取下面列出的路径，不要要求用户手动粘贴文件内容。

请读取：

1. 待办/cc-connect-migration/整体标准.md
2. 待办/cc-connect-migration/prompts/00-阶段验收门.md
3. 当前阶段提示词文件
4. 当前阶段产物
5. 待办/cc-connect-migration/artifacts/0.<阶段编号>-validation-attempt-1.md
6. 待办/cc-connect-migration/artifacts/0.<阶段编号>-validation-attempt-2.md
7. 待办/cc-connect-migration/artifacts/0.<阶段编号>-validation-attempt-3.md
8. B 最近一次验收结果
9. A 最近一次修复说明
10. 当前仓库 AGENTS.md

裁决规则：

1. 只裁决 B 当前列出的 fail 问题。
2. 不允许新增问题。
3. 不允许输出泛泛建议。
4. 每个 fail 问题必须逐条判断是否满足以下三个条件：
   - 有明确来源证据。
   - 违反当前阶段提示词的完成标准。
   - 不解决会导致端到端追踪链路断裂，或阻塞下一阶段。
5. 三个条件全部满足，才是阻塞问题。
6. 任一条件不满足，不得继续阻塞；只能转为 notes、open questions 或 needs-user-confirmation。
7. 如果这是同一阶段第 3 次验收失败，本轮必须给出裁决结论，不能要求继续普通复验。

请输出：

裁决结论：continue-fix / pass-with-notes / needs-user-confirmation

同时写入裁决报告：

待办/cc-connect-migration/artifacts/0.<阶段编号>-validation-decision.md

裁决报告必须包含：

1. 阶段编号
2. 已读取的验收报告
3. 裁决结论
4. 逐条问题裁决
5. 下一步动作

如果是 continue-fix：

1. 只列出真正阻塞的问题。
2. 每个问题必须包含：文件、ID 或入口、证据、违反的完成标准、断裂的追踪链路、修复要求。
3. 不允许包含非阻塞建议。

如果是 pass-with-notes：

1. 明确写：当前阶段可以进入下一阶段。
2. 列出被降级为 notes 的问题。
3. 说明为什么这些问题不阻塞。
4. 如需记录，写明应放入哪个 artifacts 文件。

如果是 needs-user-confirmation：

1. 列出需要用户确认的 ID、入口或候选项。
2. 每一项只给出可选决策：纳入 / 合并 / 替代 / 丢弃 / 暂缓。
3. 说明不确认会阻塞哪个后续阶段。

禁止输出：

1. 可能、也许、建议进一步。
2. 新发现问题。
3. 和当前阶段无关的问题。
4. 业务实现代码。
```
