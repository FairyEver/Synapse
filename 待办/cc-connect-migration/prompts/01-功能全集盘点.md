# 提示词 01：功能全集盘点

把下面提示词完整发送给 Codex。

```text
目标：把 CC Connect 的全部功能迁移到 3S。但本阶段只做功能全集盘点，不写迁移代码。

角色与职责：
你是源码与功能覆盖审计员。你的职责是从 CC Connect 的代码、文档、配置、测试和运行入口中提取有证据的功能全集。你不能做产品设计，不能写迁移方案，不能实现代码，不能凭经验补功能。你的输出必须让下一阶段能基于证据进行产品设计。

请直接在当前仓库中读取和写入下面列出的路径，不要要求用户手动粘贴文件内容。

请先读取：

1. 待办/cc-connect-migration/整体标准.md
2. 当前仓库 AGENTS.md

请从 CC Connect 的真实资产中提取可证据化的功能全集，并在当前项目中生成：

1. 待办/cc-connect-migration/artifacts/1.1-source-inventory.md
2. 待办/cc-connect-migration/artifacts/1.2-feature-manifest.md
3. 待办/cc-connect-migration/artifacts/1.3-open-questions.md

如果 `待办/cc-connect-migration/artifacts/` 不存在，先创建该目录。

范围包括但不限于：

1. Go 代码入口：main、command、HTTP API、RPC、事件、定时任务、服务、接口、数据结构。
2. 前端入口：路由、菜单、页面、按钮、弹窗、表单、快捷键、右键菜单、状态栏。
3. Electron 或系统能力：文件读写、进程、端口、shell、git、安装、下载、权限、日志。
4. 数据和配置：数据库表、配置文件、环境变量、本地缓存、导入导出。
5. 用户可见行为：主流程、异常流程、空状态、错误状态、加载状态。
6. 文档和测试：README、设计文档、测试用例、示例配置。

硬性要求：

1. 先生成 source inventory，再从 source inventory 提取 feature manifest。
2. source inventory 中每个入口都必须有覆盖状态：mapped / candidate / excluded / blocked。
3. source inventory 中每个 mapped 入口都必须写出对应 CC ID。
4. source inventory 中每个 excluded 入口都必须写排除原因。
5. source inventory 中每个 blocked 入口都必须写阻塞原因，并阻止进入下一阶段。
6. 每个正式功能项必须有来源证据。
7. 来源证据必须写到文件路径和具体位置；能写行号就写行号。
8. 不允许凭猜测添加功能。
9. 没有证据但看起来可能存在的内容，只能写入 待办/cc-connect-migration/artifacts/1.3-open-questions.md，不能进入正式功能全集。
10. 每个功能项必须分配唯一 ID。
11. 每个功能项必须写清楚：入口、输入、输出、副作用、用户可见结果、错误行为、迁移建议、验收标准、状态。
12. 不要写业务代码。
13. 不要生成开发计划。

待办/cc-connect-migration/artifacts/1.1-source-inventory.md 的表格字段至少包含：

Inventory ID
类型
来源证据

对应 CC ID
排除或阻塞原因

本阶段完成标准：

1. CC Connect 的源码入口、文档入口、配置入口、测试入口都已扫描并记录在 待办/cc-connect-migration/artifacts/1.1-source-inventory.md。
2. 待办/cc-connect-migration/artifacts/1.1-source-inventory.md 中没有空白覆盖状态。
3. 所有 mapped 入口都有对应 CC ID。
4. 所有 excluded 入口都有排除原因。
5. 所有 blocked 入口都被列为阻塞问题，不能进入下一阶段。
6. 所有有证据的功能都进入 待办/cc-connect-migration/artifacts/1.2-feature-manifest.md。
7. 所有无证据问题都进入 待办/cc-connect-migration/artifacts/1.3-open-questions.md。
8. 没有进行任何迁移实现。
```
