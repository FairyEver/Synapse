# 提示词 02：产品设计与信息架构

把下面提示词完整发送给 Codex。

```text
目标：基于 CC Connect 功能全集，设计这些功能迁移到 3S 后的产品组织方式。本阶段只做产品设计和信息架构，不写业务代码。

角色与职责：
你是产品信息架构负责人。你的职责是先分析当前 3S 的产品结构、功能结构、导航、app shell、UI 规范和文案风格，再把每个 CC ID 放到合适的菜单、页面、Tab、弹窗、设置项或后台能力中。你不能凭空设计新产品形态，不能设计没有 CC ID 支撑的新功能，不能写工程实现。你的输出必须让工程映射阶段能直接确定 UI 和模块落点。

请直接在当前仓库中读取和写入下面列出的路径，不要要求用户手动粘贴文件内容。

请读取：

1. 待办/cc-connect-migration/整体标准.md
2. 待办/cc-connect-migration/artifacts/1.1-source-inventory.md
3. 待办/cc-connect-migration/artifacts/1.2-feature-manifest.md
4. 待办/cc-connect-migration/artifacts/1.3-open-questions.md
5. 当前仓库 AGENTS.md
6. .claude/rules/design.md
7. .claude/rules/ui-rules.md
8. desktop/src/App.tsx
9. desktop/src/app-shell/
10. desktop/src/modules/
11. desktop/src/components/
12. desktop/src/components/ui/
13. desktop/src/styles/
14. desktop/components.json
15. 其他与当前 3S 导航、菜单、路由、页面、设置、状态栏、弹窗相关的文件

请先生成：

待办/cc-connect-migration/artifacts/2.1-synapse-product-baseline.md

再生成：

待办/cc-connect-migration/artifacts/2.2-product-design.md

如果 `待办/cc-connect-migration/artifacts/` 不存在，先创建该目录。

2.1 必须先分析当前 3S 产品和 UI 基线，至少包含：

1. 当前产品结构
2. 当前导航和菜单结构
3. 当前页面和模块分布
4. 当前设置入口和全局能力入口
5. 当前 app shell 布局
6. 当前 UI 组件库和视觉规范
7. 当前文案风格
8. 可复用的现有页面、组件、hook、service
9. 不适合新增独立菜单的区域
10. 设计约束和禁止事项
11. 分析依据文件列表

设计目标：

1. 说明 CC Connect 的功能迁移到 3S 后，应该如何组织在现有产品结构中。
2. 明确哪些功能进入新菜单，哪些功能并入已有菜单，哪些功能只作为设置项或后台能力。
3. 明确每个功能出现在哪个界面、哪个区域、哪个操作入口。
4. 明确主流程、次流程、异常流程和空状态。
5. 明确用户从 3S 当前界面进入这些能力的路径。
6. 明确哪些功能不应该做成独立页面，避免菜单膨胀。

硬性要求：

1. 待办/cc-connect-migration/artifacts/1.2-feature-manifest.md 中每个正式功能 ID 都必须出现在产品设计中。
2. 待办/cc-connect-migration/artifacts/2.2-product-design.md 必须显式承接待办/cc-connect-migration/artifacts/2.1-synapse-product-baseline.md。
3. 不允许出现没有 CC ID 支撑的新功能。
4. 不允许写泛泛的产品愿景、营销文案或界面废话。
5. 不允许设计装饰性首页、欢迎页、宣传页。
6. 不允许自定义视觉风格、硬编码颜色、渐变、装饰性 emoji、卡片套卡片。
7. 必须遵守 3S 当前 shadcn/ui、Radix、Tailwind token 的视觉基线。
8. 如果一个 CC 功能应被合并、隐藏、替代或降级为后台能力，必须记录原因和影响。
9. 如果某个功能的产品归属无法确定，标记为 needs-user-confirmation，不要自行拍板。
10. 不写业务代码。
11. 不生成工程迁移映射。
12. 不生成最终开发计划。

待办/cc-connect-migration/artifacts/2.2-product-design.md 必须包含以下章节：

1. 产品设计结论
2. 菜单与导航结构
3. 页面与功能归属矩阵
4. 用户主流程
5. 次级流程与后台能力
6. 空状态、错误状态、加载状态
7. 功能合并、替代、隐藏、废弃说明
8. 需要用户确认的问题
9. 与当前 3S 产品结构的差异和适配说明
10. 面向下一阶段的工程映射输入

页面与功能归属矩阵至少包含以下字段：

CC ID
功能名称
当前 3S 承接位置
产品归属
菜单或入口
页面或区域
主要操作
状态反馈
是否需要新页面
是否需要用户确认
说明

菜单与导航结构必须写成明确层级，例如：

3S
- 一级菜单
  - 二级页面或 Tab
    - 操作入口

本阶段完成标准：

1. 待办/cc-connect-migration/artifacts/2.1-synapse-product-baseline.md 已生成，并有分析依据文件列表。
2. 每个正式 CC ID 都有产品归属。
3. 每个正式 CC ID 都能看出用户在哪里使用。
4. 每个正式 CC ID 都能看出承接到当前 3S 的哪个菜单、页面、Tab、设置项、弹窗、后台能力或现有模块。
5. 菜单、页面、Tab、弹窗、设置项、后台能力边界明确。
6. needs-user-confirmation 项被单独列出。
7. 没有进行任何迁移实现。
```
