# 提示词 06：分批执行迁移

把下面提示词完整发送给 Codex。

重要：stage 06 分为两个模式。**第一次进入 stage 06 时，只允许执行“模式 A：拆分批次计划”，不得修改任何业务源码。** 只有在用户后续明确点名“开始执行 Dev-P0.x / Dev-P1.x / ...”时，才允许进入“模式 B：执行指定小批次”。

如果用户只说“执行 stage 06”“读取 06-分批执行迁移.md”“进入 Dev-P0”，但没有明确指定小批次编号，则必须按模式 A 处理并暂停。

````text

角色与职责：
你是 CC Connect 迁移执行负责人。你的职责是控制实现节奏，确保每次只做可独立验收的小批次。你不能扩展范围，不能顺手重构，不能修改无关功能，不能偏离当前 3S 的工程和 UI 约束。

核心迁移方式：
计划文件决定本批做什么、放哪里、如何验收；CC Connect 原源码和测试决定具体行为、字段默认值、边界条件、错误处理和状态机；3S 当前代码决定如何落到 Electron/TypeScript 架构里。写任何新代码前，必须先读取本批对应的 CC Connect 原源码和测试文件，不允许只根据计划文件重建相似功能。

CC Connect 原项目资产路径固定为：

```text

```

## 运行模式选择

先判断用户指令属于哪个模式：

### 模式 A：拆分批次计划

适用条件：

1. 用户第一次进入 stage 06。
2. 用户只要求“执行 stage 06”或“读取 06-分批执行迁移.md”。
3. 用户要求“先把 Dev-P0 拆成可独立验收的小批次”。
4. 用户没有明确指定某个小批次编号，例如 `Dev-P0.1`。

模式 A 只允许做这些事：

1. 读取 stage 06 输入文件。
2. 把 `5.1-development-plan.md` 中的 Dev-P0 到 Dev-P4 拆成更小的可独立验收批次。
3. 生成或更新 `待办/cc-connect-migration/artifacts/6.0-dev-batch-plan.md`。
4. 更新 `0.0-orchestrator-state.md`、`0.0-orchestrator-log.md`、`0.0-resume-prompt.md`，说明当前停在待用户确认具体小批次。
5. 汇报下一步可选的小批次编号。

模式 A 禁止事项：

1. 禁止修改 `desktop/` 下任何源码。
2. 禁止修改业务测试文件。
3. 禁止把 `1.2-feature-manifest.md` 中任何 CC ID 改为 done / merged / replaced。
4. 禁止把 `4.1-verification-ledger.md` 中任何验收项改为 pass。
5. 禁止生成 `6.x-execution-report-*`，因为尚未执行实现。
6. 完成 `6.0-dev-batch-plan.md` 后必须停止，等待用户明确指定小批次。

模式 A 生成批次计划时，必须为每个小批次增加：

1. `必须读取的 CC Connect 源码/测试线索`。
2. `必须读取的 CC Connect 源码`。
3. `必须读取的 CC Connect 测试`。
4. `源码搜索关键词`。
5. `原逻辑还原重点`。
6. `本批 commit message 模板`。

模式 A 的完成输出必须包含：

1. 已生成或更新的 `6.0-dev-batch-plan.md`。
2. 每个小批次的编号、覆盖 CC ID、修改范围、验收方式、前置条件和预计风险。
3. 下一步提示词模板，例如：`请执行 Dev-P0.1，只实现 <名称>，不得执行其他批次。`
4. 明确说明：本次没有写业务代码。
````
