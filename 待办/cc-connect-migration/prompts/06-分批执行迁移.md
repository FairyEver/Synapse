# 提示词 06：分批执行迁移

把下面提示词完整发送给 Codex。每次只执行一个阶段，不要一次性执行完整开发计划。

```text
目标：按照 待办/cc-connect-migration/artifacts/5.1-development-plan.md 执行指定阶段的迁移。

请直接在当前仓库中读取和写入下面列出的路径，不要要求用户手动粘贴文件内容。

本次执行阶段：

【在这里填写阶段编号和阶段名称】

请读取：

1. 待办/cc-connect-migration/整体标准.md
2. 待办/cc-connect-migration/artifacts/5.1-development-plan.md
3. 待办/cc-connect-migration/artifacts/1.2-feature-manifest.md
4. 待办/cc-connect-migration/artifacts/2.1-synapse-product-baseline.md
5. 待办/cc-connect-migration/artifacts/2.2-product-design.md
6. 待办/cc-connect-migration/artifacts/3.1-migration-map.md
7. 待办/cc-connect-migration/artifacts/4.1-verification-ledger.md
8. 当前仓库 AGENTS.md
9. 如果涉及 UI，读取 .claude/rules/design.md 和 .claude/rules/ui-rules.md

执行要求：

1. 只迁移本阶段列出的 CC ID。
2. 不迁移 development plan 以外的功能。
3. 不做顺手重构。
4. 遵守 3S 的 Electron main/preload/renderer 边界。
5. UI 使用现有 shadcn/ui、Radix、Tailwind token，不写自定义颜色、装饰性渐变、卡片套卡片和界面废话。
6. 业务逻辑不要写在 JSX 内联里。
7. 网络、存储、权限、日志、IPC 必须复用项目已有基础设施。
8. 按本阶段的验收方式补充或更新测试。
9. 完成后更新：
   - 待办/cc-connect-migration/artifacts/1.2-feature-manifest.md 中相关 ID 的状态和验收证据
   - 待办/cc-connect-migration/artifacts/4.1-verification-ledger.md 中相关验收项状态
   - 待办/cc-connect-migration/artifacts/5.1-development-plan.md 中本阶段状态
10. 生成本批执行报告，文件名使用 `待办/cc-connect-migration/artifacts/6.x-execution-report-<阶段短名>.md`，其中 `x` 是执行批次序号。

如果发现疑似遗漏：

1. 必须提供来源证据。
2. 有证据则写入 candidate，并说明是否需要用户确认纳入正式范围。
3. 没有证据则写入 open questions。
4. 不允许因此扩大本阶段实现范围。

本阶段完成标准：

1. 本阶段覆盖的 CC ID 已完成或明确阻塞。
2. 对应验收项已通过或记录阻塞原因。
3. 相关状态文件已更新。
4. 本批执行报告已写入 artifacts 目录。
5. 没有修改无关功能。
```
