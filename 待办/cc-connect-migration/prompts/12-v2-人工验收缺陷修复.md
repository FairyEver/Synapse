## 本次必须修复的缺陷

### P0：CUA-003 命令入口白屏

现象：

- 会话页点击输入区旁 `命令` 后 Electron 白屏。
- 白屏后 a11y 树仅剩空 HTML content。
- 需要通过 Windsurf `kill` + `dev` 重启。
- `status` 和 `/skills` 因此无法验收。

修复目标：

1. 点击 `命令` 不得白屏。
2. 命令面板能打开。
3. 搜索 `status` 能看到命令项。
4. 执行 `/status` 能显示结果或明确错误。
5. 执行 `/skills` 能指向 `技能 > 项目扫描`。
6. 如果命令加载失败，必须显示错误反馈，不得导致整个 app 白屏。

重点检查文件：

```text
desktop/src/modules/agent-sessions/index.tsx
desktop/src/types/agent-session.ts
desktop/src/types/bridge.ts
desktop/electron/services/agent-sessions-store-service.ts
desktop/electron/modules/agent-sessions/ipc.ts
desktop/electron/preload.ts
desktop/tests/unit/agent-sessions-store.test.ts
```

重点怀疑方向：

- renderer 点击 `命令` 后抛异常。
- 命令面板组件渲染依赖空值或 undefined 字段。
- shadcn Command/Dialog/Sheet 组合使用不当。
- 命令数据加载失败后没有错误边界。
- `/skills` 文案或结果结构不符合 renderer 渲染预期。

### P0：CUA-001 QR 平台保存草稿后不可见

现象：

- Feishu QR 进入 `等待扫码`。
- 点击 `保存草稿` 后 toast 显示 `草稿已保存`。
- 返回平台页仍显示 `暂无平台`。
- 项目平台数仍为 0。

修复目标：

1. 保存 QR 草稿后平台列表必须出现对应平台记录。
2. 项目概览平台数必须更新。
3. 记录可以是 disabled/draft，不要求真实扫码成功。
4. 如果当前设计不保存到列表，必须改为明确的未保存反馈；但优先按原 V2-B03 执行报告实现“保存草稿后出现平台记录”。

### P0：CUA-002 Telegram token 平台保存后不可见且无明确错误

现象：

- Telegram token 输入框是 secure field。
- 点击保存后返回平台页仍显示 `暂无平台`。
- 项目平台数仍为 0。
- 未显示明确错误。

修复目标：

1. 保存 Telegram token 后平台列表必须出现 Telegram 平台记录。
2. 平台记录不得显示 token 明文。
3. 项目概览平台数必须更新。
4. 如果保存失败，必须显示明确错误，不得假成功或静默返回。

重点检查文件：

```text
desktop/src/modules/connectors/index.tsx
desktop/src/modules/connectors/project-model.ts
desktop/src/types/config.ts
desktop/electron/services/connector-registry-service.ts
desktop/electron/services/config-store.ts
desktop/electron/modules/config/ipc.ts
desktop/tests/unit/connectors-project-model.test.ts
desktop/tests/unit/connectors.test.ts
```

重点怀疑方向：

- `onAddPlatformConnection` 只改了局部 state，未更新当前项目配置。
- 保存后没有重新读取 config 或 selected project summary。
- project summary 使用的 `platformConnections` 字段与保存字段不一致。
- QR draft / manual token 生成了 connection，但没有写入 `project.platformConnections`。
- Telegram `connectors.createDraft` 成功后只拿了 connector metadata，没有正确映射为 project platform connection。
- 错误被吞掉或 toast 成功与实际保存结果不一致。

## Computer Use 复测规则

修复完成后必须使用 Computer Use 进行定向复测。

1. `dev` / `D`：启动 Synapse。
2. `kill` / `Q`：杀掉 Synapse 相关进程。
3. `bump`：用户自己的提交按钮，禁止点击。
