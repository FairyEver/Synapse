# 提示词 04：验收账本设计

把下面提示词完整发送给 Codex。

```text
目标：基于功能全集、产品设计和迁移映射，生成可执行、可闭合的验收账本。本阶段只设计验收，不写业务代码。

请直接在当前仓库中读取和写入下面列出的路径，不要要求用户手动粘贴文件内容。

请读取：

1. 待办/cc-connect-migration/整体标准.md
2. 待办/cc-connect-migration/artifacts/1.2-feature-manifest.md
3. 待办/cc-connect-migration/artifacts/2.1-synapse-product-baseline.md
4. 待办/cc-connect-migration/artifacts/2.2-product-design.md
5. 待办/cc-connect-migration/artifacts/3.1-migration-map.md
6. 待办/cc-connect-migration/artifacts/1.3-open-questions.md
7. 当前仓库 AGENTS.md

请生成：

待办/cc-connect-migration/artifacts/4.1-verification-ledger.md

如果 `待办/cc-connect-migration/artifacts/` 不存在，先创建该目录。

要求：

1. 每个正式 CC ID 都必须有验收项。
2. 每个验收项都必须能判断通过或失败，不能是模糊描述。
3. 核心逻辑优先使用 golden tests。
4. UI 流程使用人工验收步骤或组件行为测试。
5. Electron main process 能力使用 service/repository/IPC 边界测试。
6. 数据迁移和配置兼容必须有输入样例、预期输出和副作用检查。
7. 对无法自动化的验收项，写清楚人工验收步骤。
8. 不要写业务代码。
9. 不生成最终开发计划。

待办/cc-connect-migration/artifacts/4.1-verification-ledger.md 的表格字段至少包含：

CC ID
验收类型
输入或前置条件
操作步骤
预期结果
验证方式
证据文件或命令
状态
备注

验收类型只能使用：

unit
golden
integration
renderer
manual
static-audit

本阶段完成标准：

1. 每个正式 CC ID 都有验收方式。
2. 每个验收方式都有明确通过条件。
3. 无法自动化的部分有人工验收步骤。
4. 没有进行任何迁移实现。
```
