# 14.3 Feishu/Lark Runtime Implementation Report

更新时间：2026-04-26 CST

## 结论

Stage 14 B02 已按 CC Connect Feishu/Lark runtime 主链路补齐 Synapse 主进程 runtime：

`QR save` -> `FeishuLarkRuntimeService.startOrReloadProjectConnection()` -> 官方 SDK WebSocket 长连接 -> event dispatcher -> `SynapseInboundMessage` -> `AgentSessionsStoreService.connectInbound()` -> outbound reply/create。

Feishu 与 Lark 保持两个 platform type：`feishu` 默认飞书域，`lark` 默认 Lark 域；QR registration 仍共用 Feishu registration API，并保留 `tenant_brand=lark` 后切换 accounts domain 的逻辑。

## CC Connect 对照

| CC Connect 逻辑 | Synapse 实现 |
| --- | --- |
| `init()` 注册 `feishu`、`lark` 两个 platform type | `ConnectorRegistryService` 只内置 `feishu`、`lark`，runtime 只启动这两类 |
| `newPlatform()` 读取 `app_id/app_secret/domain/allow_from/group_reply_all/share_session_in_channel/thread_isolation/progress_style/enable_feishu_card` | `ConnectorRegistryService` descriptors + `SynapseProjectPlatformConnection.options/secretRefs` 保存；runtime 读取对应字段 |
| `Start(handler)` 创建 SDK dispatcher 并启动 WebSocket | `FeishuLarkRuntimeService` 使用 `@larksuiteoapi/node-sdk` 的 `WSClient + EventDispatcher` |
| `OnP2MessageReceiveV1` -> `onMessage` -> `dispatchMessage` | `handleMessageEvent()` 解析 text/post/image/audio/file/merge_forward，生成 `SynapseInboundMessage` |
| `allow_from` | runtime 调用 `allowListAllows()`，同时传入 normalizer 复核 |
| `group_reply_all` + bot mention | runtime 通过 `/open-apis/bot/v3/info` 获取 bot open_id；获取失败时按 CC Connect 降级为群过滤不可用 |
| `share_session_in_channel` | runtime 生成 `${platform}:${chatId}` session key |
| `thread_isolation` | runtime 生成 `${platform}:${chatId}:root:${rootId|messageId}`，回复时 `reply_in_thread=true` |
| `Reply/Send` | SDK `client.im.v1.message.reply/create`，优先 reply 原消息，无 message id 时按 chat/open_id 发送 |
| `card.action.trigger` | runtime 支持 `perm:`、`askq:`、`cmd:` 入站分发；`nav:`、`act:` 当前无 Synapse card navigation handler，先忽略 |
| `application.bot.menu_v6` | runtime 将菜单 `event_key` 转为 slash command 入站 |
| secret | app_secret 只存 main 侧 secret store；runtime 受审计读取；renderer public QR state 不返回 secret |

## 新增依赖

- `@larksuiteoapi/node-sdk@^1.62.0`

原因：

- 官方 SDK 原生提供 Feishu/Lark WebSocket 长连接、event dispatcher 和 `im.v1.message.reply/create`。
- 用户已授权新增官方/最小必要依赖。
- 直接手写 WebSocket 鉴权、连接配置拉取、心跳、重连和 token 管理风险更高，也更偏离 CC Connect 使用官方 SDK 的实现方式。

替代方案：

- 手写 OpenAPI + WebSocket 协议：不采用，维护成本和鉴权风险高。
- 使用 SDK 高层 `LarkChannel`：不采用为主路径，因为该封装不覆盖 `application.bot.menu_v6`，而 Stage 14 明确要求 bot menu 迁移。
