# 14.1 Feishu/Lark Source Trace

更新时间：2026-04-26 CST

## 对照结论

CC Connect 的 Feishu/Lark 是完整平台 runtime，不只是配置保存。它把 `feishu` 与 `lark` 注册成两个 platform type，registration 共用 Feishu app registration API，运行时用 Lark 官方 SDK 的 WebSocket 长连接，事件进入 `core.Engine.handleMessage`，回复再通过 `im.message.reply/create` 发回。Synapse 当前缺口集中在 runtime lifecycle、event dispatch、session/agent 接入和 outbound send。

## 必须保留的字段语义

- `feishu` 与 `lark` 是两个平台 type，不合并。
- `app_id` 非敏感，可进入 config/renderer；`app_secret` 敏感，只能在 main 侧 secret store。
- `domain` 影响 runtime Open API 和 WebSocket 目标；Lark tenant/domain 切换不能丢。
- `allow_from` 为空或 `*` 表示开放；非空为逗号列表。
- `enable_feishu_card` 默认 true；卡片事件至少不能阻塞普通文本可用。
- `thread_isolation` 影响 sessionKey。
- `progress_style` 有 `legacy/compact/card` 三种合法值。
