## 还原到 3S 的逻辑

- 发送必须从 renderer 走 `window.synapse.agentSessions.send(...)` 到 main 侧，不在 React 内写本地假状态。
- main 侧沿用旧边界：
  - 空消息拒绝。
  - session 缺失拒绝。
  - main 侧 engine 先记录 user history，再处理结果/error/timeout。
  - error 不删除用户输入；renderer 恢复输入并显示可恢复错误。
- 3S 当前尚未接真实 CLI agent 进程，本批用已有 main 侧 `AgentEngineService` 承接 turn 状态机：
  - 单元测试直接注入 events 覆盖 success/error/timeout。
  - UI/IPC 调用无外部 agent runtime 时返回明确错误，仍完成 main 侧 send/error 闭环并保留输入。
- B08 再接事件流、thinking/tool/permission/rich message 展示。

## 边界和错误处理

- 输入 `trim()` 后为空：阻止发送并保留输入。
- 发送失败：恢复输入内容，保留当前 detail，显示错误。
- main 侧 `session not found`、`project not found`、`message is required` 直接向 renderer 返回。
- timeout 使用 `AgentEngineService` 的 `idleTimeoutMs/eventGapsMs` 路径测试。
- 成功时刷新 detail history，显示 user + assistant。
