# 2.2 Product Design

## 1. 产品设计结论

本设计承接 `待办/cc-connect-migration/artifacts/2.1-synapse-product-baseline.md` 的 3S app shell、设置入口、shadcn/Radix UI 基线和现有模块分布，并使用 `1.4-glossary-and-concept-map.md` 的统一命名。

CC Connect 迁移到 3S 后不复制原 Web Admin UI 菜单。3S 继续以现有 app shell 为主，只新增三个高频工作入口：

- 会话：承接 agent 对话、会话历史、流式事件、附件、文件引用、多 agent relay。
- 连接：承接聊天平台 connector、Bridge、Webhook、QR onboarding、连接状态。
- 自动化：承接 cron、heartbeat、hooks。

其他能力并入现有入口：

- 规则、技能、提示词：继续使用现有内容资产模块，承接 custom command、skill 资产和策略文档。
- 设置：承接项目、provider、权限、安全、后台服务、日志、更新、安装来源、Management API 状态。
- IDE：承接 agent CLI 可用性、终端观察。
- 数据库：只作为数据查看和诊断入口，不作为 CC 功能主入口。

## 4. 用户主流程

### 主流程 A：从连接到会话

1. 用户进入连接。
2. 添加平台连接，选择平台类型。
3. 输入凭证或扫码绑定。
4. 连接成功后进入会话。
5. 选择项目和 agent。
6. 发送消息。
7. 会话详情展示流式文本、工具事件、权限请求、附件和最终结果。

### 主流程 B：创建本地会话

1. 用户进入会话。
2. 点击新建会话。
3. 选择项目、agent、provider、权限模式。
4. 输入消息或选择提示词/命令。
5. 查看运行状态、停止或继续。

### 主流程 C：创建自动化任务

1. 用户进入自动化。
2. 在定时任务、Heartbeat 或 Hooks 中选择类型。
3. 选择项目和会话目标。
4. 配置 prompt 或 exec。
5. 保存后查看启用状态和最近运行结果。

### 主流程 D：配置服务商

1. 用户进入设置 > 服务商。
2. 新增 provider 或导入 cc-switch。
3. 选择适用 agent 和模型。
4. 在项目设置中引用 provider。
5. 会话新建时使用对应 provider。

## 9. 与当前 3S 产品结构的差异和适配说明

| 差异 | 适配 |
|---|---|
| 当前 3S 顶层只有内容资产、数据库、IDE、设置 | 新增会话、连接、自动化三个高频入口，其余并入设置 |
| CC Connect Web Admin 有独立侧边栏 | 不迁移该侧边栏，改用 3S 顶部 Tabs 和模块内侧栏 |
| CC Connect project = work_dir + agent + platforms | 3S 项目继续放在设置 > 项目，并在会话/连接中引用 |
| CC Connect provider 是 Web 顶层菜单 | 3S provider 放进设置 > 服务商 |
| CC Connect cron 是 Web 顶层菜单 | 3S cron、heartbeat、hooks 合并为自动化 |
| CC Connect system/config 是 Web 顶层菜单 | 3S 用设置分类承接 |
| CC Connect Bridge 同时服务 Web Chat 和外部 adapter | 3S 中 Bridge 归连接，聊天体验归会话 |
