## 原源码对照

- `core/engine.go`：复用 `handleMessage`、session lock、busy queue、`maxQueuedMessages=5`、permission wait、event idle timeout、`processInteractiveEvents` 的 `text/thinking/tool_use/tool_result/permission_request/result/error` 状态语义。
- `core/message.go`：复用统一 `Message`、`EventType`、`Event` 字段，包括 `SessionID`、`RequestID`、`ToolInputRaw`、token usage、tool result status/exit/success。
- `core/streaming.go`、`core/streaming_test.go`：复用 streaming preview 的事件追加、finalize、freeze/degrade 的事件流边界；本批迁移为 session event log，不迁移 UI preview。
- `core/engine_test.go`：复用 permission-while-send-blocked、queued messages FIFO、queue overflow、idle timeout reset/disabled、EventResult text fallback、tool progress ordering 和 session history 写入边界。
- `agent/claudecode/session.go`、`agent/codex/session.go`、`agent/opencode/session.go`、`agent/cursor/session.go`、`agent/gemini/session.go`、`agent/kimi/session.go`、`agent/pi/session.go`：复用各 adapter 归一到 core Event 的事件类型和 payload 字段。

迁移时保留的行为：

- Engine service 只执行纯状态机和 session event 映射，不启动真实 agent CLI、不启动 Electron/dev server/browser/Playwright。
- Session events append-only，按 session 自增 `seq`，可通过 injected publisher 接入 EventBus，禁止裸 `webContents.send`。
- Result event 内容为空时使用已累积 text segments 作为 assistant response。
- Permission request 默认进入 `waiting_permission`，auto approve 明确开启时才继续。
- Idle timeout 生成 `timed_out` terminal state 和 error event；busy queue 保持 FIFO，超过 5 条拒绝。
