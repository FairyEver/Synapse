# 9.1 v2 产品设计

## 设计结论

v2 不再沿用旧 `2.2-product-design.md` 的“三个入口就算替代 Web Admin”方案。新的产品设计以用户任务闭环为核心：

```text
项目中心
→ 平台连接
→ Provider 绑定
→ 会话使用
→ 命令执行
→ 自动化配置
→ 系统与安全设置
```

3S 不复制 CC Connect Web Admin 的 7 个旧菜单，但必须在 3S 中提供等价可操作路径。

## 导航原则

| 旧 Admin 页面 | v2 3S 位置 | 设计理由 |
| --- | --- | --- |
| 概览 `/` | 连接 > 运行概览 | 概览的核心是项目、平台和最近会话，不必单独做一级菜单 |
| 项目 `/projects` | 连接 > 项目列表/详情 | 连接模块必须以 project 为组织中心 |
| 服务商 `/providers` | 设置 > 服务商 + 项目详情 > 服务商 | 全局 provider 在设置；项目绑定在项目详情 |
| 技能 `/skills` | 技能 > 项目扫描来源 | 复用 3S Skills，但补项目/agent 维度 |
| 对话 `/chat` | 会话 | 保留为高频主入口 |
| 定时任务 `/cron` | 自动化 | 保留为高频主入口 |
| 系统 `/system` | 设置 > CC Connect / 管理员 / 调试 | 系统配置是低频设置，不做主工作页 |
| Login | 不迁移 | Electron 不需要 Web token 登录页 |

## 页面设计

### 会话

目标：让用户完成“打开已有项目会话、查看历史、发送消息、执行命令、切换 session”的核心任务。

| 区域 | 内容 | 必须可操作 |
| --- | --- | --- |
| 顶部 | 项目筛选、连接状态、创建本地会话 | 是 |
| 左侧列表 | 最近会话、项目会话卡、平台徽标、最近消息摘要 | 是 |
| 主消息区 | Markdown、代码块、工具事件、thinking、权限请求、错误 | 是 |
| 输入区 | 文本输入、附件、文件引用、发送、停止/继续 | 是 |
| 命令面板 | `/new`、`/model`、`/provider`、`/status`、`/cron`、`/skills`、搜索/分组 | 是 |
| 会话抽屉 | 历史 session、新建、切换、删除/重命名 | 是 |

空态要求：

- 无会话时，只给一个明确动作：新建本地会话或去连接项目。
- 选择项目但无消息时，显示输入区可用状态。
- Agent 启动失败时，保留输入内容并展示重试/查看日志。

### 连接

目标：让用户完成“项目创建、平台配置、Provider 绑定、项目级设置”的管理任务。

| 页面/区域 | 内容 | 必须可操作 |
| --- | --- | --- |
| 运行概览 | 版本、运行时长、项目数、平台数、最近活动、跳转入口 | 是 |
| 项目列表 | 项目名、agent、workdir、平台、会话数、最近活动 | 是 |
| 新建项目向导 | 项目名称、工作目录、agent 类型、平台选择 | 是 |
| 项目详情 > 概览 | 平台状态、会话入口、添加平台 | 是 |
| 项目详情 > 平台 | 平台连接列表、启停、测试、编辑、删除 | 是 |
| 项目详情 > 服务商 | 全局 provider 绑定、自定义 provider | 是 |
| 项目详情 > Heartbeat | 配置状态、启停、触发一次、最近运行 | 是 |
| 项目详情 > 设置 | agent/workdir/权限/语言/访问控制/禁用命令/删除 | 是 |

添加平台向导：

| 类型 | 首轮覆盖 | 表单/状态 |
| --- | --- | --- |
| QR 平台 | Feishu/Lark 或 WeChat 至少一类 | idle、waiting、scanned、expired、failed、success |
| 手动 token 平台 | Telegram 至少一类 | token、allow users、group/shared session、高级项 |
| 其他平台 | descriptor 展示 + unavailable/deferred | 不做虚假可用 |

### 自动化

目标：让用户完成“创建、编辑、启停、查看自动化任务”的闭环。

| Tab | 必须内容 | 必须可操作 |
| --- | --- | --- |
| 定时任务 | 任务列表、状态、下次运行、最近结果 | 新建、编辑、删除、启停、立即运行 |
| Heartbeat | 项目维度列表、interval、idle、session、最近运行 | 启用、暂停、恢复、触发一次 |
| Hooks | event、type、command/url、timeout、async、最近执行 | 新建、编辑、启停、删除 |

任务表单字段：

- project
- schedule preset / cron expression
- task type: prompt / exec
- prompt 或 command
- session key
- permission mode
- enabled
- silent/mute
- timeout

敏感规则：

- Exec 和 command hooks 必须触发权限确认和审计记录。
- 外部 HTTP hook 不自动真实触发，测试动作需要明确标注。

### 设置

目标：承接低频配置和管理能力，不把它们塞到主工作流里。

| 分类 | 内容 |
| --- | --- |
| 服务商 | 全局 provider 列表、添加/编辑/删除、CC-Switch 导入、preset 助手 |
| CC Connect | 附件发送、idle timeout、thinking/tool preview、stream preview、rate limit、脱敏配置查看 |
| 安全 | 访问控制、角色、禁用命令、脱敏策略、run_as_user doctor |
| 管理员 | Local API、Management API、reload config、restart service、daemon 状态 |
| 调试 | 日志级别、日志导出、运行诊断 |
| 关于 | 版本、更新、安装来源 |

Raw TOML 设计：

- 首轮只允许脱敏查看和导入预览。
- 不提供完整自由编辑。
- 所有 secret、token、API key 必须脱敏。

### 技能

目标：复用 3S Skills，但补齐 CC Connect 的项目/agent 扫描语义。

| 能力 | v2 设计 |
| --- | --- |
| 本地 skills | 增加项目/agent 过滤和扫描目录展示 |
| 推荐 skills | 不做 CC Connect 专属商店；如果 3S 有推荐来源，合并展示 |
| 项目详情关联 | 项目详情可显示本项目扫描到的 skills 数量和入口 |

## 首轮必须可用的用户路径

| 路径 | 验收口径 |
| --- | --- |
| 创建项目 | 用户能输入名称、workdir、agent，看到项目进入列表 |
| 添加平台 | 用户能在项目详情中打开平台向导，完成至少一类 QR 或手动平台配置草稿/保存 |
| 配置 provider | 用户能新增全局 provider，并绑定到项目 |
| 打开会话 | 用户能从会话列表或项目详情进入会话详情 |
| 发送消息 | 用户能输入消息，触发 main 侧 agent session，看到状态和结果/错误 |
| 切换 session | 用户能看到历史 session 并切换 |
| 打开命令面板 | 用户能搜索命令，执行安全命令并看到结果 |
| 创建 Cron | 用户能创建 Prompt 类型定时任务，看到任务列表和状态 |
| 配置系统项 | 用户能修改至少附件/preview/rate limit/log level 中的结构化设置 |

## 不进入首轮完成定义

| 能力 | 原因 |
| --- | --- |
| 旧 Web Admin 登录页和侧边栏 | 3S 不复制旧 Web 外壳 |
| Skills 推荐商店完整体验 | 并入 3S Skills，非 CC 首轮核心 |
| Provider 商店化 preset | 只保留配置助手 |
| Raw TOML 完整编辑 | 安全风险高，首轮只脱敏查看/导入 |
| 全平台完整配置 | 首轮只要求代表性 QR + 手动 token 平台 |
| Terminal Observer | 高级诊断，后置 |
| STT/TTS | 依赖 Chat/连接成熟后再开放 |
| daemon 安装/卸载 | 系统级敏感操作，后置或管理员确认 |

## 对当前空壳的处理

当前 `会话`、`连接`、`自动化` 入口可以保留，但必须在后续代码阶段逐步替换：

1. 静态状态卡替换为真实数据。
2. 空按钮必须连接到弹窗/向导或隐藏。
3. 纯描述卡必须改成列表、表单、状态或操作。
4. 未完成能力不得伪装成可用能力，应显示 `暂不可用` 或不展示。

## v2 完成定义

v2 产品设计通过的条件：

1. F-001 到 F-058 都能追溯到 `must / merge / defer / drop`。
2. 所有 `must` 都有明确 3S 页面和用户路径。
3. 所有 `merge` 都有明确承接模块和发现路径。
4. 所有 `defer/drop` 都有产品理由和用户确认点。
5. 不再以 service/test 作为产品可用证据。
6. 不复制旧 Web Admin 外壳。
