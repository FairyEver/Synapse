## 读取的旧源码

- `core/message.go`
  - `Event` 支持 `text`、`thinking`、`tool_use`、`tool_result`、`result`、`error`、`permission_request`。
  - tool 事件携带 `ToolName`、`ToolInput`、`ToolResult`、`ToolStatus`、`ToolExitCode`、`ToolSuccess`。
  - permission 事件携带 `RequestID`、`ToolName`、`ToolInput`、`ToolInputRaw`、`Questions`。
  - result 事件携带 `SessionID`、`Done`、token usage。

- `core/engine.go`
  - `processInteractiveEvents` 按 agent channel 顺序处理事件；thinking/tool/text/result/error/permission 都沿同一 turn 流转。
  - `EventThinking` 作为中间进度发送，不写入 assistant history。
  - `EventToolUse` 展示工具名和输入；`toolCodeLang` 对 Bash/shell 使用 `bash`，diff-like 内容使用 `diff`。
  - `EventToolResult` 优先用 `ToolResult`，否则用 `Content`；无输出时展示 no output fallback；可附带 status/exitCode/success。
  - `EventPermissionRequest` 停止 idle timer，调用 permission prompt，等待 `RespondPermission`。
  - relay 模式遇到 permission request 会自动 allow，并回传 `UpdatedInput`。
  - idle timeout 错误文本为 `agent session timed out (no response)`。

- `core/interfaces.go`
  - `AgentSession.RespondPermission(requestID, result)` 是权限响应唯一入口。
  - `PermissionResult` 字段为 `Behavior`、`UpdatedInput`、`Message`。
  - `Behavior == "allow"` 时带回 `UpdatedInput`；deny 可带 `Message`。
  - `CardSender` 不支持时必须走 `Card.RenderText()` fallback。
  - `InlineButtonSender` 不支持时按钮类消息退化为普通 reply。

- `agent/claudecode/session.go`
  - Claude Code 通过 `--permission-prompt-tool stdio` 接收 control request。
  - autoApprove/dontAsk/acceptEditsOnly 会在 session 内自动 `RespondPermission`。
  - 普通 permission request 生成 `EventPermissionRequest`，包含 request id、tool name、summary input、raw input。
  - `RespondPermission` 写入 `control_response`：
    - allow: `{ behavior: "allow", updatedInput }`
    - deny: `{ behavior: "deny", message }`
    - deny 默认消息为 `The user denied this tool use. Stop and wait for the user's instructions.`
  - 进程不 alive 时返回 `session process is not running`。

- `core/card.go`
  - 富卡片结构：`Header` + `Elements`。
  - 元素包括 markdown、divider、actions/buttons、note、list_item、select。
  - 按钮类型包括 `primary`、`default`、`danger`。
  - `RenderText()` fallback 输出 header、markdown、分割线、按钮 label、list item、select options。
  - `CollectButtons()`/`HasButtons()` 用于识别交互。

- `core/markdown_html.go`
  - Markdown fallback 支持 code fence、blockquote/callout、heading、list、inline code/bold/italic/link。
  - 对平台能力有限场景使用简单 HTML/文本表达，不依赖完整 Web Markdown 引擎。

- `core/bridge.go`
  - `BridgePlatform.SendCard`：adapter 不支持 `card` 时调用 `card.RenderText()` 走普通 reply。
  - `SendWithButtons`：adapter 不支持 `buttons` 时退化为普通 reply。
  - `serializeCard` 输出 JSON 字段：
    - header: `{ title, color }`
    - markdown: `{ type: "markdown", content }`
    - divider: `{ type: "divider" }`

  - `reply_stream`、`preview_start`、`update_message`、`delete_message` 都按 stream/update 事件更新同一个消息。

- `web/src/hooks/useBridgeSocket.ts`

## 还原到 3S 的逻辑

- 事件记录继续留在 main 侧，renderer 只通过 `window.synapse.agentSessions.*` 获取结果和响应权限。
- `send` 返回本轮有序 event records，保留旧 engine 的事件顺序语义。
- 权限请求返回 `pendingPermission`，UI 展示 allow/deny 操作；响应通过新增 IPC 回 main 侧，不在 React 中直接伪造 agent 状态。
- 当前 3S 尚未接真实 Claude/Codex runtime 的 live `AgentSession.RespondPermission`，因此本批只落可审计的 main 侧权限响应闭环：
  - 校验 request/session。
  - allow/deny 写入有序 event log。
  - 清除 pending permission。
  - unsupported/live-runtime 缺失时有明确状态，不假装继续 agent turn。
- 富消息沿用旧 card 字段和 fallback：
  - 支持 markdown/divider/actions/note/list_item/select。
  - 不支持 card/buttons 时使用文本 fallback。
  - 交互只产生 dispatch intent 或 permission response，不在展示层直接执行业务命令。
- Markdown/code/copy 首轮在会话模块内实现轻量渲染：普通段落保留换行，code fence 以 `<pre><code>` 展示并提供复制按钮。

## 边界和错误处理

- 空消息仍由 B07 main 侧拒绝。
- unsupported event type 映射为 `error`，保留 `originalType`。
- permission request 缺 `requestId` 时不允许响应。
- respond permission：
  - session 不存在返回 `session not found`。
  - request 不匹配返回 `permission request not found`。
  - decision 非 allow/deny 返回 `permission decision is required`。
  - deny 缺 message 时使用旧 Claude Code 默认拒绝语义的用户可读版本。
- 富消息 capability 缺失时不显示可点击控件，只显示 fallback 文本，避免丢失交互意图。
- 事件 UI 只展示必要状态文本，不把架构说明写进界面。
