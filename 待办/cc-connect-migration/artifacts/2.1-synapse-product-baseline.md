# 2.1 Synapse Product Baseline

## 当前产品结构

3S 当前是 Electron 桌面应用，主界面以本地仓库/项目为上下文，核心内容资产是规则、技能、提示词，并已有数据库、IDE 扫描和设置模块。

当前顶层内容类型由 `desktop/src/App.tsx` 聚合：

- 规则：`RulesModule`
- 技能：`SkillsModule`
- 提示词：`PromptsModule`
- 数据库：`DataStoreModule`
- IDE：`EditorScanModule`
- 设置：`SettingsModule`

启动前置状态包括仓库空状态、仓库缺失状态、身份门禁和同步弹窗，不应被 CC Connect 迁移绕过。

## 当前导航和菜单结构

当前一级导航是 app shell 顶部居中的 `Tabs`，由 `AppShellNavigation` 渲染。现有一级 Tab：

- 规则
- 技能
- 提示词
- 数据库
- IDE
- 设置

当前设置模块内部有独立分类侧栏：

- 通用
- 仓库
- 项目
- 工具
- 变量
- 数据服务
- 调试
- 关于
- 管理员

## 当前页面和模块分布

| 区域 | 现有模块 | 当前职责 | 可承接的 CC 功能 |
|---|---|---|---|
| 顶层内容资产 | `rules`、`skills`、`prompts`、`content` | 规则、技能、提示词的创建、详情、安装、复制、下载 | CC-012、CC-013、CC-023 的资产侧能力 |
| 数据库 | `data-store` | 本地表结构、数据行、schema 查看和编辑 | CC config/session/cron/provider 数据迁移后的调试查看，不作为主入口 |
| IDE | `editor-scan`、`cli` | 编辑器扫描、CLI 检测 | CC-003、CC-025 的工具可用性和终端观察入口 |
| 设置 | `settings` | 通用、仓库、项目、工具、变量、数据服务、日志、关于、管理员 | CC-005、CC-006、CC-014、CC-022、CC-032、CC-033、CC-034、CC-035 |
| App shell | `app-shell` | 顶部导航、同步状态、仓库切换、通知 | CC 运行状态、连接状态和后台任务摘要可接入但不替代现有同步状态 |

## 当前设置入口和全局能力入口

设置页通过 `SidebarContentLayout` 承载分类侧栏和内容区。现有可复用模式：

- 列表编辑：`RepositoryListEditor`、`ProjectListEditor`
- 分组设置：`SettingsGroup`、`SettingItemRow`
- 工具检测：`ToolsPanel`
- 日志导出：`LogExportPanel`
- 更新和版本：`AboutPanel`
- 管理员维护：`RepositoryMaintenancePanel`

CC Connect 的 provider、连接凭证、运行权限、daemon、日志、更新应优先进入设置分类或设置面板，而不是直接新增顶层页。

## 当前 app shell 布局

`AppShellLayout` 使用：

- 顶部 header：居中导航，右侧 actions。
- 内容区：全高 `section`，模块自行决定内部布局。
- 全局弹窗：仓库 onboarding、仓库切换、同步变更。

模块内常用布局是 `SidebarContentLayout`：左侧可调整宽度侧栏，右侧内容区。CC Connect 的会话、连接、自动化适合复用这个布局。

## 当前 UI 组件库和视觉规范

当前 UI 基线：

- shadcn preset：`radix-nova`
- primitive：Radix
- base color：neutral
- CSS variables：启用
- icon library：lucide
- 字体：Geist Variable

现有 shadcn primitives 覆盖 Button、Card、Input、Textarea、Label、Dialog、Tabs、DropdownMenu、Tooltip、Badge、Separator、Table、Sheet、Switch、Select、Empty、Spinner、Sidebar、Resizable、Command 等。

视觉纪律：

- 使用 `bg-background`、`text-foreground`、`bg-card`、`border-border`、`bg-muted`、`text-muted-foreground` 等 token。
- 不写页面级品牌视觉、渐变、硬编码颜色、装饰性元素。
- 表单用现有 Field/InputGroup/Select/Switch 等组合。
- 内部工具界面保持密度、对齐和可扫描性。

## 当前文案风格

当前文案偏操作型和状态型，例如“设置已保存。”、“正在同步仓库...”、“请先添加本地目录”。适合继续采用：

- 标题短。
- 状态短。
- 空状态给一个下一步。
- 错误直接说明发生了什么。

不应在 UI 中放迁移说明、架构解释、路线图、欢迎语或营销文案。

## 可复用的现有页面、组件、hook、service

| 类型 | 可复用项 | 适用方向 |
|---|---|---|
| Shell | `AppShellLayout`、`AppShellNavigation`、`AppShellActions` | 顶层入口和运行状态 |
| 模块布局 | `SidebarContentLayout`、`ModuleSidebar` | 会话、连接、自动化的列表详情布局 |
| 内容资产 | `createContentModule`、content dialogs | 命令/技能与现有资产模块对齐 |
| 设置 | `SettingsCategorySidebar`、`SettingsGroup`、`SettingItemRow` | provider、connector、权限、日志、更新 |
| 通知 | `useAppNotifications` | 保存、同步、重启、执行反馈 |
| 日志 | `createRendererLogger` | renderer 结构化日志 |
| Electron bridge | `window.synapse.*`、`getSynapseBridge` | 后续工程映射只能走 typed preload |
| Electron runtime | `ServiceRegistry`、`IpcRegistry`、`EventBus`、`NetworkServiceRegistry`、`PermissionGuard`、`DataRepository`、`ProjectContainer`、`Scheduling` | CC runtime、connector、automation、网络服务、敏感操作、数据存储 |

## 不适合新增独立菜单的区域

| 功能 | 原因 | 归属 |
|---|---|---|
| Provider CRUD | 属于运行配置和密钥治理，不是高频工作台 | 设置 > 服务商 |
| daemon / npm wrapper / update | 属于应用治理和发布，不是日常业务对象 | 设置 > 关于 / 调试 / 管理员 |
| Management API / Unix socket API | 是后台接口，不应暴露为用户页面 | 后台能力；设置中只显示开关/状态 |
| Web Admin UI | CC Connect 独立 SPA 的菜单不能照搬；3S 已有 shell | 功能拆分到 3S 现有和新增模块 |
| 安全策略细项 | 需要和权限、审计、密钥统一呈现 | 设置 > 安全 |
| 测试资产 | 验收来源，不是产品入口 | 后续验收账本 |

## 设计约束和禁止事项

- 不迁移 CC Connect Web UI 视觉，只迁移信息架构和行为。
- 不增加没有 CC ID 支撑的能力。
- 不把后台 API、daemon、npm、测试资产做成顶层菜单。
- 不绕过仓库空状态、身份门禁、typed preload 和 Electron 主进程边界。
- 不在 renderer 直接处理 shell、文件系统、端口监听、agent 子进程、密钥。
- 不使用自定义颜色、渐变、装饰性文案、卡片套卡片。
