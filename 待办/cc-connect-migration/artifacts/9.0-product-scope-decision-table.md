# 9.0 v2 产品范围裁剪表

## 结论

本表基于 `8.1` 到 `8.7`，重新定义 CC Connect 融合到 3S 的产品范围。旧 `1.2-feature-manifest.md` 中的 `done / merged / replaced` 不能再直接作为“产品可用”证据。

后续开发必须以本表为范围入口：

```text
must：必须做成用户可操作闭环
merge：必须承接能力，但融入 3S 现有模块或设置，不复制旧页面
defer：暂缓，不能阻塞首轮可用版本
drop：不迁移，必须有产品理由
```

## 裁剪原则

1. 迁移用户任务闭环，不迁移旧 Web Admin 外壳。
2. 任何 `must` 和 `merge` 都必须在 3S 中有明确入口、真实数据、可执行动作和验收标准。
3. `defer` 不等于遗忘，必须进入后续 backlog。
4. `drop` 只允许用于旧外壳、发布渠道、商店展示、重复生态页等非核心任务。
5. 用户已在 2026-04-26 确认 `F-004,F-027,F-028,F-030,F-051,F-058` 的裁剪结论，后续 v2 收口不再保留待确认裁剪项。

## 对后续计划的约束

1. 任何 `must` 项不能只用 service/test 证明完成，必须有 3S 用户路径。
2. 任何 `merge` 项必须写清合并到哪个 3S 模块，以及用户如何发现。
3. 任何 `defer` 项不能进入首轮完成定义。
4. 任何新增 `drop` 项必须保留用户确认记录；本表已记录 `F-004,F-027,F-028,F-030,F-051,F-058` 的用户确认。
