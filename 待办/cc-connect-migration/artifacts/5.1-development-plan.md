# 5.1 Development Plan

## 1. 完成定义

当 `待办/cc-connect-migration/artifacts/1.2-feature-manifest.md` 中所有正式 CC ID 都处于 done / merged / replaced / dropped，且 `待办/cc-connect-migration/artifacts/4.1-verification-ledger.md` 中对应验收项全部通过或有用户确认的豁免，则 CC Connect 迁移到 3S 完成。

## 2. 范围边界

范围内：

- `1.2-feature-manifest.md` 中 CC-001 到 CC-038 的正式功能。
- `2.2-product-design.md` 中固定的会话、连接、自动化、设置、IDE、规则、技能、提示词、数据库归属。
- `3.1-migration-map.md`、`3.2-data-compatibility-plan.md`、`3.3-permission-and-security-map.md` 中固定的工程、数据、安全边界。
- `4.1-verification-ledger.md`、`4.2-golden-test-cases.md`、`4.3-manual-acceptance-script.md` 中固定的验收证据。

范围外：

- 没有 CC ID 支撑的新功能。
- 旧 Web Admin UI 的视觉风格、侧边栏和 SPA 路由复刻。
- 不经用户确认的 dropped 功能。
- 未纳入正式范围的 open questions。
- stage 06 的实现执行。本计划只作为执行依据，不开始写业务代码。

## 3. 产品组织摘要

3S 只新增三个高频一级入口：会话、连接、自动化。

现有入口继续承接：

- 规则、技能、提示词：承接 command、skill 和策略资产。
- 设置：承接 provider、安全、项目、工具、管理、日志、更新、安装来源。
- IDE：承接 CLI 检测和 Terminal Observer。
- 数据库：只作诊断查看，不作为 CC 主入口。

## 7. 验收顺序

1. 每批完成后先运行阶段内 unit/golden/integration/renderer/static-audit。
2. 再执行对应 `4.3` 人工验收脚本。
3. 再运行 `pnpm desktop:check:hard-constraints`。
4. 再运行与修改范围匹配的 typecheck/test。
5. 更新 `1.2-feature-manifest.md` 的状态和验收证据。
6. 更新 `4.1-verification-ledger.md` 的状态和证据。
7. 更新 `5.3-decision-log.md` 和 `5.4-release-and-rollback-plan.md` 的实际结果。

## 8. 状态更新规则

- `todo`：尚未实现。
- `mapped`：已确认落点但未开始实现。
- `in_progress`：当前批次正在实现。
- `done`：功能已实现且 `4.1` 对应验收通过。
- `merged`：功能被合并到另一个 3S 能力，decision log 有原因和目标。
- `replaced`：功能由 3S 等价能力替代，decision log 有替代方案和验收证据。
- `dropped`：只有用户明确确认后才能使用。

## 9. 收口审计规则

收口审计只允许两类问题：

- manifest 中已有 ID 未闭合。
- 有来源证据的新候选项，需要用户确认是否纳入正式范围。

禁止输出泛泛优化建议。新增 UI、IPC、service、repository、network descriptor、settings category、automation type、connector type、agent type 都必须能追溯到 CC ID 或 `5.3-decision-log.md`。

## 12. 发布、灰度和回滚策略摘要

- 新入口默认走 feature flag：会话、连接、自动化、local API、Management API、daemon 管理、真实平台 connector、真实系统服务操作。
- 数据迁移先 dry-run，再写入 3S namespace；旧 CC 文件只读，不覆盖。
- 高风险平台、daemon、Management API、Webhook、Bridge 分批灰度，先 mock/测试账号，再小范围真实配置。
- 回滚优先关闭 feature flag、停止 NetworkServiceRegistry descriptor、停止 scheduler、保留用户数据备份。
- 发布前必须执行 `5.4-release-and-rollback-plan.md` 中对应批次的验证命令或人工验收脚本。
