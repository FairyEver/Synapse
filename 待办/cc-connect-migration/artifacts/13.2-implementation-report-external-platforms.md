# 13.2 实现报告：外部平台完整迁移

更新时间：2026-04-26 CST

## 总结

Feishu/Lark/Weixin QR onboarding 已从草稿 UI 迁为 Electron main 侧真实 begin/poll/save 闭环。renderer 不直接请求外部平台，也不接收 `app_secret/token`；成功凭据暂存在 main session，保存时写入 encrypted `secrets` 命名空间，项目平台连接只保存 `secretRefs` 和非敏感 options。

## 平台实现

| 平台 | 实现内容 | 旧逻辑来源 |
| --- | --- | --- |
| Feishu | main 侧 POST registration `init/begin/poll`；校验 `client_secret`；处理 `slow_down/access_denied/expired_token`；成功保存 `app_id` + `secretRefs.app_secret` | `core/setup.go`、`cmd/cc-connect/feishu.go` |
| Lark | 沿用 Feishu registration；poll 识别 `tenant_brand=lark` 后切换到 `https://accounts.larksuite.com`；保存为 `type=lark` | `core/setup.go`、`cmd/cc-connect/feishu.go` |
| Weixin | main 侧 GET ilink QR 和 status；带 `iLink-App-ClientVersion: 1`；识别 `wait/scaned/expired/confirmed`；confirmed 缺 `bot_token/ilink_bot_id` 报错 | `core/setup.go`、`cmd/cc-connect/weixin.go` |
| 手动平台 | descriptor 动态表单覆盖 telegram、discord、slack、dingtalk、wecom、qq、qqbot、line、weibo；secret 字段 password input；保存走 main secret store | `PlatformManualForm.tsx`、`platformMeta.ts`、`connector-registry-service.ts` |

## 安全边界

- 外部平台网络请求只在 Electron main 服务中执行。
- renderer 通过 typed preload/IPC 调用，不直接访问 Feishu/Lark/Weixin 外部网络。
- poll 成功得到的 `app_secret/token` 不返回 renderer。
- poll 中的外部请求异常会收敛为 `failed` 会话状态，renderer 展示错误并允许重试，不把可恢复轮询失败暴露成主进程未处理栈。
- secret 写入通过 `ConnectorSecretStoreService` 进入 encrypted `secrets` 命名空间。
- secret 写入前调用 `PermissionGuard.check(secret.write)` 并记录 `AuditSink`。
- 外部网络请求调用 `PermissionGuard.check(network.connect)` 并记录 `AuditSink`。
- 项目配置、Raw TOML、renderer 平台列表只保存/显示 `secretRefs`。

## 真实扫码验收

自动化使用 mock HTTP 覆盖 begin/poll/save 成功、过期、拒绝、slow_down、Lark 切换、poll transport failure 和 Weixin confirmed。真实手机扫码仍需要用户在应用显示二维码后扫码；Computer Use 已确认 Feishu/Weixin 二维码显示，实际扫码保存闭环记录为 `waiting_user_scan`。
