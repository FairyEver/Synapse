- `core/session.go`
  - `Session` 字段：`ID`、`Name`、`AgentSessionID`、`AgentType`、`PastAgentSessionIDs`、`History`、`CreatedAt`、`UpdatedAt`。
  - `GetOrCreateActive` 默认 session name 为 `default`。
  - `NewSession` 会更新 `activeSession[userKey]`；`NewSideSession` 不更新 active。
  - `SwitchSession(userKey, target)` 按 id 或 name 匹配，不存在返回 `session %q not found`。
  - `GetHistory(n)`：`n <= 0` 或超过总数时返回全部，否则返回最后 n 条。
  - `UserMeta` 保存 `user_name`、`chat_name`；`UpdateUserMeta` 只合并非空字段。
  - `SessionKeyMap()` 提供 session id 到 `session_key` 的反查和 active id 集合。
  - `load()` 读取 JSON 失败只记录错误并返回；缺失 map 初始化为空；旧 `__continue__` sentinel 会剥离为空。

- `core/management.go`
  - `GET /projects/{project}/sessions`：
    - `active_keys` 来自运行中 interactive states，映射 session key 到平台。
    - session 列表来自 `e.sessions.AllSessions()`，并结合 `SessionKeyMap()`。
    - `last_message` 只取最后一条 history，content 预览最多 200 字符。
    - `platform` 优先 live interactive platform，否则从 `session_key` 第一段推导。
    - `user_name`、`chat_name` 来自 `GetUserMeta(sessionKey)`。
  - `GET /projects/{project}/sessions/{id}`：
    - session 不存在返回 404 `session not found`。
    - `history_limit` 默认 50，仅当正整数时生效。
    - detail 返回 `agent_session_id`、`agent_type`、`active`、`live`、`history_count`、`history`。

## 还原到 3S 的逻辑

- 3S 新增 main 侧 `agent-sessions` IPC 域，不让 renderer 伪造列表。
- 会话数据模型沿用旧字段，使用 camelCase 类型：
  - list item：`id`、`project`、`sessionKey`、`name`、`platform`、`agentType`、`active`、`live`、`createdAt`、`updatedAt`、`historyCount`、`lastMessage`、`userName`、`chatName`。
  - detail 额外有 `agentSessionId` 和 `history`。
- 列表按 `updatedAt || createdAt` 倒序，摘要从真实 session history 的最后一条生成。
- detail 支持 `historyLimit`，默认 200；非正数或缺省按 repository 的完整 detail 边界处理。
- UI 只通过 `window.synapse.agentSessions.*` 读取 main 侧数据。
- B06 只完成读取、选择、切换和新建入口；真实发送和事件流在 B07/B08 接入。

## 边界和错误处理

- 项目缺失时返回空列表，不阻塞 UI。
- session 不存在时 main 侧抛出 `session not found`，renderer 显示错误状态并保留当前页面。
- session 标题优先 `name`，其次 `userName`，最后短 id。
- `platform` 为空时展示为 `-`，不从 UI 猜测。
- 空 history 显示空状态；不注入示例消息。
- 本批没有找到旧源码要求以外需要补猜的字段。
