## CUA-003 根因、修改、验证

根因：会话页命令面板把 `CommandInput`、`CommandList`、`CommandGroup` 和 `CommandItem` 直接放进 `CommandDialog`，没有包在 cmdk 必需的 `Command` 根组件里。点击 `命令` 打开面板时，cmdk 子组件缺少上下文导致 renderer 崩溃，Electron 显示白屏。

修改：
- `desktop/src/modules/agent-sessions/index.tsx` 新增 `AgentCommandPaletteContent`，用 `<Command>` 包裹命令输入和列表。
- 命令加载失败时清空旧命令并在命令面板空态显示错误文本，同时保留输入区错误反馈。
- 新增 `desktop/src/modules/agent-sessions/__tests__/command-palette.test.tsx`，覆盖 `/status`、`/skills` 渲染和加载失败反馈。

验证：
- 单测通过：命令面板内容可渲染 `/status` 和 `/skills`，加载失败显示 `读取命令失败。`。
- Computer Use：点击 `命令` 后命令面板正常打开，未白屏。

## CUA-001 根因、修改、验证

根因：`desktop/src/lib/config.ts` 的 `normalizeProjectConfig` 只保留项目基础字段、provider 和 workspace 字段，`platformConnections` 在 `updateConfig -> applySynapseConfigPatch -> sanitizeSynapseConfig` 链路中被丢弃。QR 草稿在 renderer 中生成并调用更新后，持久化返回的配置不含平台连接，所以列表仍为空、项目平台数仍为 0。

修改：
- `normalizeProjectConfig` 保留 `platformConnections`。
- 新增平台连接清洗函数，只保留 `draft/configured/disabled/invalid` 状态、基础展示字段、非 secret options、`secretRefs` 和时间戳。
- 同步保留 CC Connect 项目常用字段，避免保存链路继续丢失 `agentType`、`permissionMode`、`language`、`adminFrom`、`disabledCommands` 和 `heartbeat`。

验证：
- 单测覆盖 Feishu QR draft 经过 config patch 后仍在 `summarizeCcConnectProjects` 中计入平台数。
- Computer Use：Feishu QR 进入 `等待扫码` 后点击 `保存草稿`，平台列表出现 Feishu，项目概览平台数更新。

## CUA-002 根因、修改、验证

根因：与 CUA-001 相同。Telegram token 保存时 `connectors.createDraft` 已正确返回脱敏 connector 和 `secretRefs`，但项目平台连接写入配置后被 `sanitizeSynapseConfig` 丢弃，导致 UI 返回平台页仍为空。

修改：
- 同 CUA-001，配置清洗保留项目平台连接。
- 测试断言 Telegram 平台连接经过 config persistence 后仍保留 `secretRefs.token`，并且汇总平台数为 2。

验证：
- 单测覆盖 Telegram manual token 平台连接经过 config patch 后仍存在。
- Computer Use：Telegram token 输入框为 secure field；保存后平台列表出现 Telegram，项目平台数更新；列表只显示平台名、类型、状态、启用和 allow_from，未显示 token 明文。
