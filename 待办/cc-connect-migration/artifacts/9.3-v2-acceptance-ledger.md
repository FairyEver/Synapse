# 9.3 v2 验收账本

## 验收结论口径

v2 验收只承认真实用户路径，不再承认“service/test 已存在所以 done”。

每个 `must` 或 `merge` 功能通过验收时，必须同时具备：

1. 来源证据：对应 CC Connect Admin 页面或原源码路径。
2. 3S 入口：用户能在 3S 中找到。
3. 真实数据：不是固定空状态或硬编码数字。
4. 可执行动作：按钮、表单、命令、开关有真实 handler。
5. 错误反馈：失败时用户知道发生什么，并可恢复。
6. 自动验证：至少有单元/组件/集成测试覆盖关键逻辑。
7. 人工验收：有可按步骤操作的脚本。

## 总体验收门

| 验收门 | 通过标准 |
| --- | --- |
| 范围门 | F-001 到 F-058 都有 must/merge/defer/drop 结论 |
| 产品门 | 所有 must/merge 都有 3S 用户路径 |
| 代码门 | UI、preload/API、main service、data persistence 不缺层 |
| 源码门 | 每批执行报告列出 CC Connect 原源码和测试 |
| 空壳门 | 不存在无 handler 按钮、硬编码状态卡、误导性空列表 |
| 验证门 | typecheck、hard constraints、ipc codegen 通过 |
| 提交门 | 每批有合规 commit、报告和 handoff |

## 手工验收脚本

### A. 项目和连接

1. 打开 3S。
2. 进入连接。
3. 查看运行概览。
4. 新建项目，填写名称、workdir、agent 类型。
5. 在项目列表看到新项目。
6. 进入项目详情。
7. 打开添加平台。
8. 选择 QR 平台，确认看到 idle 状态和启动入口。
9. 选择手动 token 平台，确认看到 token、allow users、group/shared session。
10. 取消，不应保存敏感明文。

通过标准：

- 每步都有真实 UI 反馈。
- 不出现无动作按钮。
- secret 不在 renderer 明文持久化。

### B. Provider

1. 进入设置 > 服务商。
2. 新增 provider。
3. 填写名称、base URL、模型、agent type、API key。
4. 保存。
5. 回到项目详情 > 服务商。
6. 绑定该 provider。

通过标准：

- API key 显示为脱敏/secretRef。
- 项目详情能看到绑定结果。

### C. 会话

1. 进入会话。
2. 选择一个项目会话。
3. 打开历史 session 抽屉。
4. 切换 session。
5. 新建会话。
6. 输入消息并发送。
7. 查看发送中、事件、结果或错误。
8. 打开命令面板并搜索 `status`。
9. 执行安全命令并查看结果。

通过标准：

- 会话数据不是硬编码。
- 发送失败有可恢复反馈。
- 命令结果可见。

### D. 自动化

1. 进入自动化。
2. 新建 Prompt Cron。
3. 选择项目、schedule、prompt、session key、权限模式。
4. 保存后在任务列表看到任务。
5. 启停任务。
6. 编辑任务。
7. 删除任务。
8. 切换 Heartbeat，配置项目 heartbeat。
9. 切换 Hooks，新增 HTTP hook 或 command hook。

通过标准：

- Exec/command hook 必须出现权限提示。
- 最近运行或状态可见。

### E. 系统设置和诊断

1. 进入设置 > CC Connect。
2. 修改附件发送、preview、rate limit、log level。
3. 打开脱敏 Raw TOML 查看。
4. 进入管理员，查看 Local API / Management API 状态。
5. 尝试 reload/restart，确认出现明确确认提示。
6. 进入调试，导出日志。

通过标准：

- Raw TOML 不显示 secret/token/API key 明文。
- 高风险操作不直接执行。
- 操作结果有反馈。

## 不通过判定

出现以下任一情况，不能标记为 pass：

1. UI 只有空态，没有真实数据加载。
2. 按钮无 handler。
3. 表单只存在组件 state，不持久化。
4. 只改 service/test，没有 renderer 入口。
5. 只改 renderer，没有 preload/API/main 处理。
6. secret/token/API key 出现在日志、通知、Raw TOML 截图或 renderer 明文持久化。
7. 高风险操作无确认。
8. 没有读取 CC Connect 原源码。
9. 没有更新 `0.0-latest-handoff.md`。
10. 完成后没有 Bark 通知。

## v2 收口审计要求

最终审计必须生成：

```text
待办/cc-connect-migration/artifacts/9.4-v2-final-audit.md
待办/cc-connect-migration/artifacts/9.5-v2-reverse-coverage-check.md
```

审计必须回答：

1. F-001 到 F-058 的 must/merge 是否全部闭合。
2. defer/drop 是否有用户确认。
3. 3S 是否仍存在空壳入口。
4. P0/P1 用户路径是否全部可操作。
5. 业务代码是否均能追溯到 CC Connect 源码或 v2 决策。
6. 是否还有未提交业务代码。
7. 用户是否需要继续人工验收。
