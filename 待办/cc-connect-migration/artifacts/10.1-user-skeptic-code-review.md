## 总结结论

`pass_with_risks`

这次没有按 done 标签下结论，而是从用户入口反向追踪到 handler、preload、IPC、main service、持久化或执行边界。总体结论是：主要入口不是纯 UI 空壳，按钮多数有 handler，核心配置类操作能落到 preload/main/DataRepository；但有几类风险不能被“已完成迁移”掩盖：

- Chat 发送、命令高危执行、Heartbeat、Hook command、Bridge/Webhook/API/daemon 目前都有明确 main 侧路径，但没有真实 CC Connect agent/runtime/daemon 执行闭环。代码明确返回或记录 `runtime not connected`、`permission_required`、diagnostic-only 等状态。
- Provider API key 和平台 token 当前只形成 `secretRef` / `secret draft`，保存链路只持久化 metadata，没有找到把 draft secret value 写入 secrets namespace 的用户入口。
- QR 平台入口是项目连接 draft 保存，不是扫码登录或真实平台接入。
- Skills 项目扫描复用了真实 editor-scan IPC/service，但部分扫描失败会降级为空结果；Skills 自身测试只覆盖入口存在，未覆盖真实扫描服务。

所以：发布前可以进入人工验收，但不能把这些风险描述成“真实 CC Connect 全运行时已接通”。

## 用户主链路逐步追踪

1. Provider 保存链路：`ProviderSettingsPanel.saveProvider` 创建 `draft = createProviderDraft(...)`，但实际保存只把 `draft.provider` 放进 `nextProviders`，再走 `onSave -> config.update -> ConfigStore.update -> DataRepository core.config`。这证明 provider 不是空壳；同时也证明 `draft.secret` 没有在该链路中被持久化。
2. 平台连接链路：Telegram 表单调用 `window.synapse.connectors.createDraft(...)`，main 侧生成 connector metadata、secretRefs 和 secrets；UI 随后只把 `connectorDraft.connector` 映射成 project platform connection 并持久化到 config。原始 token 不落项目 JSON 是对的，但没有找到 secret value 后续保存动作。
3. Chat 发送链路：输入框 submit 调 `agentSessions.send`，IPC 到 `AgentSessionsStoreService.sendMessage`，main 侧会校验 project/session/message，追加 user history，再由 `AgentEngineService` 处理事件。没有注入 events 时默认事件是 `{ type: "error", error: "agent runtime is not connected" }`。
4. 权限链路：B08 的 UI button 会回到 `agentSessions.respondPermission`，main 侧校验 pending request 并追加 permission_response event。这里不是前端伪造状态；但 response event 和 pending map 属于内存 event log，不等于真实 Claude/Codex runtime 继续执行。
5. 自动化链路：Cron/Heartbeat/Hook UI 都经 `requireBridgeDomain("automation")` 到 IPC 和 main service。Cron 保存、启停、删除有 DataRepository；Exec 只做权限确认并保存 job。Heartbeat 默认 executor 是 no-op；Hook command 返回 permission_required，HTTP transport 默认未配置。
6. 系统诊断链路：设置页调 `config.getCcConnectDiagnostics`，main 侧返回 Bridge/Webhook/Local API/Management/daemon/doctor/update 的默认字段和本地路径检查。代码没有启动 socket、管理 API、daemon 或 updater。
7. Skills 链路：Skills tab 嵌入 `EditorScanModule lockedContentTab="skill" lockedScopeTab="project"`，扫描走 `window.synapse.editorScan.scanAll()`。服务会读取 config projects 并扫描文件系统；但若目录读取失败，部分 helper 返回空结果。

## 高风险缺口

### 1. Chat 发送闭环不是“真实 agent runtime 闭环”

- 证据：`desktop/electron/services/agent-sessions-store-service.ts:575-580` 在没有注入 events 时使用默认 error event：`agent runtime is not connected`。
- 影响：人工验收时用户点击发送，能够看到 main 侧响应和错误状态，但不会真正驱动 Codex/Claude Code。
- 归类：高风险发布说明项，不建议在产品文案中称为“已接入真实 Agent 会话发送”。

### 2. Provider / Connector secret value 未见持久化入口

- Provider 证据：`provider-settings-panel.tsx:328-352` 生成 `draft` 后只保存 `draft.provider`。
- Connector 证据：`connectors/index.tsx:1062-1084` 调用 `connectors.createDraft` 后只使用 `connectorDraft.connector`。
- 影响：配置里能看到 `secretRef`，但重启后没有证据证明 API key/token 可被 runtime 取回。当前测试只证明“不把明文写进 JSON”，没有证明“密钥写入安全存储”。
- 归类：高风险验收项；如果后续要真实连接 provider/platform，这会成为阻塞。

### 3. QR 平台入口是 draft，不是扫码接入

- 证据：`connectors/index.tsx:1174-1184` 只调用 `createQrProjectPlatformDraft` 并保存；`project-model.ts` 里该 draft status 为 `draft`、enabled 为 `false`。
- 影响：用户可能以为“开始设置”会启动二维码流程；实际只是本地草稿。
- 归类：中高风险产品预期项。

### 4. 高危命令、Heartbeat、Hook command/HTTP 都有执行边界

- 命令证据：高危命令 allow 后仍返回 `runtime not connected`，见 `agent-sessions-store-service.ts:444-450`。
- Heartbeat 证据：默认 executor 是 no-op，见 `automation-heartbeat-service.ts:145-151`。
- Hook 证据：command hook 返回 `permission_required`，HTTP transport 默认抛出 `http hook transport is not configured`，见 `automation-hooks-service.ts:176-230`。
- 影响：UI 操作和配置保存是真的，自动化真实执行不是完整 CC Connect runtime。

### 5. Skills scan 存在“失败变空”的静默降级

- 证据：`editor-scan-service.ts:36-75` 中 preview/meta/readdir 失败会返回空字符串、null 或空数组。
- 影响：权限/文件系统异常可能表现为“没扫到”，用户不一定能区分真的没有 skill 还是扫描失败。
- 归类：中风险，可在人工验收时重点测异常目录。

### 6. Diagnostics 是只读模拟/本地检查，不是运行管理 API

- 证据：`cc-connect-settings-service.ts:284-342` 返回 Bridge/Webhook/Management `enabled: false` 和默认 endpoint；daemon status 只依据 data dir 是否存在给 `unknown/stopped`。
- 影响：B14 完成的是诊断视图，不是 Bridge/Webhook/Local API/Management API server。
- 归类：范围裁剪项；`F-058` 已由用户确认按 merge/诊断体系处理。

## 不能由静态代码确认的事项

- 真实 Electron 运行时中所有 preload domain 是否在用户机器权限/窗口上下文里正常可用。
- Chat 输入在真实 app 中是否有可接受的用户体验，因为静态代码显示默认会返回 runtime not connected。
- Provider/connector secret 是否有外部流程写入 secrets namespace；本次 repo 静态搜索未找到对应用户入口。
- Bridge/Webhook/Local API/Management API 是否有未来运行时模块实际启动；B14 当前代码只做 diagnostics。
- 文件系统权限异常、符号链接复杂项目、超大 skill 文件在真实扫描中的表现。
