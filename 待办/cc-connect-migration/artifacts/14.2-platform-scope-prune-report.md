# 14.2 Platform Scope Prune Report

更新时间：2026-04-26 CST

## 结论

Stage 14 B01 已将当前内置外部平台范围裁剪为 Feishu/Lark。平台 registry 仍保留 `register()` 扩展能力，但默认 descriptors、QR schema 和添加平台 UI 不再暴露 Weixin、Telegram、Discord、Slack、DingTalk、WeCom、QQ、QQBot、LINE、Weibo 等平台。

## 修改内容

| 区域 | 处理 |
| --- | --- |
| built-in descriptors | `ConnectorRegistryService` 默认只注册 `feishu` 和 `lark` |
| Lark 字段 | 补齐与 CC Connect 共用 runtime 相关的 `group_reply_all`、`thread_isolation` |
| QR platform type | `ConnectorQrPlatform`、IPC `qrPlatformSchema` 只允许 `feishu/lark` |
| manual save | `saveManualPlatform` 对非 Feishu/Lark 返回错误，不写 secret、不写 config |
| 添加平台 UI | 弹窗只显示 Feishu 和 Lark，均走 QR onboarding |
| 历史配置 | 项目列表继续读取已有 `platformConnections`，非 Feishu/Lark 显示“不支持” badge，不删除数据 |
| 测试 | 更新 connector registry 与 QR onboarding 测试，覆盖非 Feishu/Lark 不可新增 |

## 保留的扩展性

- `ConnectorRegistryService.register()` 未移除，后续模块仍可显式注册新 connector descriptor。
- `SynapseProjectPlatformConnection.type` 仍是 string，历史配置不会因类型枚举收窄被丢弃。
- inbound normalizer/session/bridge 等通用平台抽象未删除，避免破坏后续扩展架构。
