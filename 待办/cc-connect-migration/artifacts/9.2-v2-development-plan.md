# 9.2 v2 开发计划

## 计划结论

旧 stage 06 不能继续作为开发主线。v2 开发计划必须从产品可用闭环出发，每个批次都要能让用户在 3S 中完成一个真实任务，不能只新增 service、test 或静态入口。

本计划不要求一次性完成所有 P2 高级能力。首轮目标是让 CC Connect 在 3S 中变成可用产品，而不是完整复制旧 Admin。

## 开发前置条件

进入代码执行前必须满足：

1. 用户确认 `9.0-product-scope-decision-table.md` 中的 `defer/drop` 推荐。
2. `9.1-v2-product-design.md` 作为唯一 v2 产品设计输入。
3. `9.3-v2-acceptance-ledger.md` 已生成并通过人工审阅。
4. 工作区无未提交业务代码改动，或用户明确允许携带文档改动继续。
5. 代码执行器必须读取 CC Connect 原源码，不能只按本计划写。

## 批次详情

### V2-B00 移除空壳完成假象

目标：

- 清理当前“看起来可用但实际不可用”的误导。
- 所有按钮必须有动作、明确禁用原因或隐藏。
- 所有静态数字和固定空态必须替换为真实加载状态或明确未接入状态。

修改范围：

- `desktop/src/modules/agent-sessions/`
- `desktop/src/modules/connectors/`
- `desktop/src/modules/automation/`

验收：

- `新建会话`、`添加连接`、`新建任务` 不再是无动作按钮。
- 用户不会误以为功能已经可用。
- 不增加新业务能力，只修正产品真实性。

### V2-B01 Project 数据和 UI 基础

目标：

- 建立 CC Connect project 作为 3S 中的核心对象。
- 在连接模块中展示项目列表和运行概览。
- 支持新建项目第一步：名称、workdir、agent 类型。

必须读取 CC Connect 源码：

- `web/src/pages/Dashboard.tsx`
- `web/src/pages/Projects/ProjectList.tsx`
- `core/projectstate.go`
- `config/config.go`

3S 落点：

- `desktop/electron/services/project-workspace-service.ts`
- 新增/扩展 `desktop/electron/modules/projects/`
- `desktop/src/modules/connectors/`
- `desktop/src/types/project.ts` 或既有 project 类型

验收：

- 项目列表来自真实数据。
- 新建项目写入 3S 数据层，不只存在于组件 state。
- 项目卡展示 agent、workdir、平台数量、会话数量占位/真实值。

### V2-B02 项目详情和平台状态

目标：

- 建立项目详情页/区域。
- Tab 包含概览、平台、服务商、Heartbeat、设置。

必须读取 CC Connect 源码：

- `web/src/pages/Projects/ProjectDetail.tsx`
- `web/src/pages/Projects/PlatformSetupQR.tsx`
- `web/src/pages/Projects/PlatformManualForm.tsx`

验收：

- 从项目列表进入详情。
- 详情展示项目字段和平台状态。
- 项目设置可查看 agent/workdir/权限/语言/访问控制。
- 删除项目必须有确认，不可误触。

### V2-B03 平台连接向导

目标：

- 实现添加平台向导。
- 首轮覆盖至少一类 QR 平台和一类手动 token 平台。

必须读取 CC Connect 源码：

- `web/src/pages/Projects/PlatformSetupQR.tsx`
- `web/src/pages/Projects/PlatformManualForm.tsx`
- `platform/telegram/telegram.go`
- `cmd/cc-connect/feishu.go`
- `cmd/cc-connect/weixin.go`

验收：

- 用户能选择平台。
- QR 平台显示 idle/waiting/expired/error/success 状态。
- 手动平台表单包含 token、allow users、group/shared session。
- 凭证保存使用 secretRef，不暴露明文。

### V2-B04 Provider 全局管理

目标：

- 设置 > 服务商 支持全局 provider CRUD。
- 支持 CC-Switch 导入预览。
- 支持 preset 助手，但不做 provider 商店。

必须读取 CC Connect 源码：

- `web/src/pages/Providers/ProviderList.tsx`
- `cmd/cc-connect/provider.go`
- `core/management.go`

验收：

- 添加/编辑 provider 表单可保存。
- API key 只进入 secretRef。
- CC-Switch 导入有冲突提示。
- preset 只作为预填助手。

### V2-B05 Provider 项目绑定

### V2-B15 最终收口审计

目标：

- 反向检查所有 `must/merge` 是否有真实用户路径。
- 检查所有 `defer/drop` 是否有用户确认。
- 检查没有新增空壳。

验收：

- `9.3-v2-acceptance-ledger.md` 全部 pass 或有用户确认。
- `git status --short` 无未提交业务代码。
- typecheck、hard constraints、ipc codegen 通过。
- 每个批次都有原源码对照、执行报告和 commit。

## 执行规则

1. 每批必须先读 CC Connect 原源码和测试。
2. 每批必须先查当前 3S 相关 service/type/preload/UI。
3. 每批必须同时补 UI、preload/API、main service、测试和人工验收证据，不能只补一层。
4. 每批完成后提交一次 commit。
5. 每批结束前更新 `0.0-latest-handoff.md` 并发送 Bark 完成通知。
6. 如果发现计划和源码冲突，暂停并写 blocker，不得自行跳过。

## 不允许的完成证据

以下不能单独作为完成：

- 组件能渲染。
- 有空态。
- 有按钮但没有 handler。
- 有 service 但无 preload/API/UI。
- 有 test 但用户路径不可用。
- manifest 写了 done。

## v2 首轮完成定义

首轮完成必须同时满足：

1. P0/P1 中所有 `must` 完成。
2. P1 中所有影响运行的 `merge` 完成。
3. P2 `merge/defer` 有明确后续计划。
4. F-001 到 F-058 都在 `9.0` 中有裁剪结论。
5. 3S 中不存在误导性空壳入口。
6. 用户能完成：创建项目、配置平台、配置 provider、进入会话、发送消息、查看历史、执行命令、创建自动化任务、修改关键系统设置。
