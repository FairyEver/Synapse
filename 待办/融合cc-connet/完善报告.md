## 2. 修复明细（按 Agent 给的编号）

### §1.1 ✅ 修复 — `service-registry/registry.ts:183` 静默吞错

`stopAll()` 的 fallback 路径 `} catch { ... }` 没有日志，无法诊断为何走 fallback。改为：捕获后写到第一个 entry 的 `lastError`，让 `inspect()` 之后能看到。

### §1.2 ✅ 修复 — `atomic-io.ts` 双重 catch 静默吞错 + 重复实现

合并 `writeTextFileAtomic` / `writeBinaryFileAtomic` 共有的 mkdir + tmp file + rename + cleanup 逻辑到内部 `writeAtomic(filePath, options, writeBody)`。两个公开函数现在只是 6 行的 thin wrapper。`rm.catch(() => {})` 替代了内嵌的 try/catch，注释解释了为什么吞二级错误是合理的（原写入错误才是关键）。

### §1.3 ✅ 修复 — IPC channel-collision 回滚信息不全

`IpcRuntimeError` 的 details 现在包含 `rolledBackCount`，consumer 能区分"第一个 method 就冲突"和"装了几个之后才冲突"。新增回归测试验证。

### §1.4 ✅ 修复 — DataRepositoryImpl.importAll 无校验

`as never` 已经被前置守门：`entry.schema.validate(data.singleton)` / `entry.schema.validate(item)`。不通过 schema 的 payload 在 import 时被静默丢弃（不破坏 namespace 的 invariant）。新增回归测试验证。

### §1.5 ✅ 修复 — EventBus.flushAllForTests 竞态

原实现遍历 `this.coalesceTimers` 的同时调 `this.coalesceTimers.delete(key)` 时通过 listener 重新 emit 会观察到部分清空的状态。改为：先 snapshot 所有 slot，立即 clear()，再 cancel + dispatch。dispatch 期间任何新 emit 不会污染快照集合。

### §1.6 ⚠️ 留档不修 — sealed flag 防护范围

Agent 建议 `reload()` / `inspect()` 也加 sealed 检查。这两个方法只读 + 在 register-after-startAll 防护已经生效，过度防御。留档说明，不改。

### §1.7 ✅ 修复 — `noopLogger` 重复实现

抽离到 `runtime/lib/test-helpers.ts:createNoopLogger`。三处 test 文件（`tests/fixtures/runtime.ts`、`project-container/__tests__/registry.test.ts`、`tests/unit/phase-0.5-integration.test.ts`）改为复用单一来源。剩余两处（`runtime/service-registry/registry.ts` 内部的 `_createNullLoggerForTests`、`bootstrap/__tests__/descriptors.test.ts`）属于不同上下文（前者是生产 fallback，后者用了 inline pattern），保留。

### §1.8 ⚠️ 留档不修 — 两个 StructuredLogger 接口

`runtime/logging/types.ts` 和 `runtime/service-registry/types.ts` 都有 StructuredLogger 接口。后者是 Phase 0.1 引入的占位，前者是 Phase 0.6 的真实接口。统一是大动作（影响所有 ServiceContext 消费者的类型签名），SPEC 也明确说"Phase 0.6 替换"——属于自然演进路径。留档不动。

### §1.9 ⚠️ 留档不修 — `coalesceKey` vs `makeKey` 表面相似

Event-bus 用 `domain|type|projectId|...` 一级拼接；metrics 用 `name|k=v&k=v` 二级拼接。表面看像但语义不同。Event-bus 已切换到 `buildKey()`；metrics 保留独立实现。

### §1.10 ✅ 修复 — atomic-io 重复 cleanup（同 §1.2）

### §1.11 ✅ 修复 — WindowManager `unknown` payload

通过 JSDoc 明确"payload schema 由 descriptor.create owner 校验"——不在 manager 层做校验是设计选择（不同 window 角色 payload 不同）。改注释而非加校验。

### §1.12 ⚠️ 留档不修 — IpcRegistry vs ServiceRegistry 接口语义不同

二者都是 register/list 模式但 context 注入方式不同（IPC 用 install callback、Service 用 contextProvider）——故意如此（IPC 需要 transport-agnostic，Service 需要 ctx 共享）。

### §1.13 ✅ 修复 — `stopAll` timeout 计算可能负数

把 `Math.min(perServiceTimeout, remaining || perServiceTimeout)` 改为更严谨的 `remaining === 0 ? 0 : Math.min(perServiceTimeout, remaining)`。当全局 deadline 已到，per-service 不再给"满血"机会。

### §1.14 ✅ 修复 — unref pattern 4 处重复

引入 `makeUnrefTimeout(ms, cb)` / `makeUnrefInterval(ms, cb)` 工厂，每个返回 cancel 函数。四处旧实现（service-registry / event-bus / scheduling / idle-reaper）全部切换。同时 `let timer: ReturnType<typeof setTimeout> | null = null` 这种形态降为 `let cancel: () => void = () => {}`，TS narrowing 也变干净。

### §1.15 ⚠️ 留档不修 — diagnostics process.platform

`process` 在 Node 中保证存在，过度防御。

### §1.16 ⚠️ 留档不修 — singleton-lock.ts 注释说"Phase 0.6 may re-home"

陈述事实，不是过期注释。

### §1.17 ⚠️ 留档不修 — migrations.ts `as unknown as To`

Migration runner 是泛型边界——consumer 自己保证 from/to 类型对得上。zod 接入是可选改进，不在硬约束里。

### §1.18 ✅ 修复 — IpcRegistry unregister() 不幂等

改为 `unregister: makeIdempotentDisposer(() => { ... })`。新增回归测试。

### §1.19 ⚠️ 留档不修 — EventBus subscribe 返回 unsubscribe 没有标记幂等

实际实现中 `set.delete(listener)` 重复调用是天然幂等（Set 的语义）。文档建议太琐碎，不补。

### §1.20 ⚠️ 留档不修 — extractError 不是 export

Logger 内部工具，当前没有外部消费者。export 等到有需求时再做。

### §1.21 ✅ 修复 — backend `isEnvelopeShape` 重复实现

抽到 `runtime/data-repo/envelope.ts`。json.ts 和 encrypted-json.ts 各删除一份重复（共 14 行）。

### §1.22 ⚠️ 留档不修 — main.ts 的 webContents.send + 注释

注释明确说"Phase 0.4 T4.5 follow-up 替换"——这是 deferred task 的 marker，不是过期。

`if (this.cancelTimer) return` 是 idempotent 设计，warning 反而是噪音。

filter 在每次 broadcast 时点取快照，不承诺跨 broadcast 一致性——文档已经说明这一点（manager.ts WindowManager 接口注释）。
