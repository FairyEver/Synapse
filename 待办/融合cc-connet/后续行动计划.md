### 已发现并修复 — 路径相关的运行时陷阱（commit fc04f97）

> 用户运行 P-1 时发现：dock 弹了图标但主窗口不显示，stdout 只有 macOS IMKClient 警告。

**根因**：T1.8 把 `createMainWindow()` 从 `electron/main.ts` 拆到 `electron/bootstrap/main-window.ts`，文件深了一层目录。`path.join(__dirname, "preload.js")` 和 `path.join(__dirname, "../../dist/index.html")` 都没跟着补一层 `..`，运行时报 ENOENT。

**为什么 typecheck / unit test / build 都没抓到**：这是**运行时路径**问题——编译期不验证文件实际存在，vitest 跑 mock，build 只做编译。**只能 GUI 启动才能发现**。

### 已发现并修复 — 把 fire-and-forget 误改成同步阻塞（commit 472b9e7）

> 修了 fc04f97 重启后，主窗口仍然不显示。日志最后一行停在 "Repository state resolved"。

**根因**：原 main.ts:209-228 把 `runScheduledMaintenanceIfDue()` 放在 `void (async () => {...})()` 里 fire-and-forget——故意不阻塞主流程，因为 git fetch 网络慢时会 hang。我把它移到 `repoMaintenanceDescriptor` 的 `async create(ctx)` 里 await 调用，结果 startAll() 的拓扑链就被 git fetch 卡死了，主窗口永远建不出来。

**修法**：descriptor.create 改为同步返回，里面保留 `void (async () => {...})()` IIFE 让 maintenance 在后台跑。

**经验教训（写入未来 refactor 指引）**：
- 应用层日志在 `~/Library/Application Support/Synapse/logs/synapse-<timestamp>.log`，**不打 stdout**。dev 启动后窗口异常时第一时间看这个文件
- 任何文件移位的 refactor PR，关键运行时路径（preload / loadFile / icon / userData 子路径）必须在 PR description 里列出"原相对路径 → 新相对路径"对照
- **拆 main.ts 时不只看"做了什么"，还要看"做的姿势"**：原代码用 `void (async () => {...})()` 不是装饰，是关键约束（"这一段不许阻塞主流程"）。任何这种 IIFE 必须在新位置保留同语义，不能改成 `async create()` await
- 后续 follow-up PR（特别是 F-3 handler 迁移）涉及文件位置变化或同步性变化时，必须**真跑一次 dev 启动验证**，不能仅靠单测和 typecheck
