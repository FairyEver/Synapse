# 不同编辑器存储规则

> 检索时间：2026-04-18  
> 检索原则：只采用官方文档 / 官方开发者文档 / 官方 Codelab。  
> 说明：本文把 Synapse 的两类内容映射到各编辑器的官方概念中：
>
> - `Rule`：持久指令、规则、custom instructions、memory file、AGENTS/CLAUDE 文件
> - `Skill`：多文件能力包；如果官方没有 `Skill` 这个术语，会明确写成“无官方 Skill，以下用 Workflow 对应”
>
> 额外约束：
>
> - 文中会尽量区分“官方原生概念”和“为 Synapse 做的语义映射”
> - 如果官方文档未明确写出路径 / 文件名 / 扫描范围，会直接写“未找到官方依据”

## 1. Cursor

### 全局规则

- 这里的 `Rule` 是 Cursor 官方原生 `Rules` 概念。
- 当前官方文档把全局规则定义为 `User Rules`，入口是 `Cursor Settings -> Rules -> User Rules`。
- 官方当前文档没有给出一个可直接写入的固定全局规则文件路径。
- 本轮可核实的官方页面只能确认它定义在 Settings 中；未找到 Cursor 官方明确公布的全局规则磁盘文件位置。  
  因此，对 Synapse adapter 来说，Cursor 全局 Rule 目前不应被建模为“官方公布的固定文件目录”。

来源：

- [Cursor Rules](https://cursor.com/docs/rules)

### 项目规则

- 原生项目规则目录：`./.cursor/rules/`
- 官方文档可核实支持项目根目录下的 `AGENTS.md`，作为 `./.cursor/rules/` 之外的规则输入
  - 注意：`CLAUDE.md` 在本轮可核实的官方文档中**未找到依据**，不应列为 Cursor 原生支持的规则文件
- 官方文档明确支持子目录 `AGENTS.md`，并按目录作用域自动生效：  
  “Cursor supports AGENTS.md in the project root and subdirectories”

来源：

- [Cursor Rules](https://cursor.com/docs/rules)

### 全局 Skill

- Cursor 官方已公开 `Agent Skills` 概念，`Skill` 以 `SKILL.md` 为核心。
- 官方文档明确的用户级（全局）Skill 目录：
  - `~/.cursor/skills/`（原生）
  - `~/.agents/skills/`（原生）
- 向后兼容扫描（官方文档明确列出）：`~/.claude/skills/`、`~/.codex/skills/`

来源：

- [Cursor Agent Skills](https://cursor.com/docs/skills)
- [Cursor 2.4 Changelog](https://cursor.com/changelog/2-4)

### 项目 Skill

- Cursor 官方已公开 `Agent Skills` 概念，`Skill` 以 `SKILL.md` 为核心。
- 官方文档明确的项目级 Skill 目录：
  - `.cursor/skills/`（原生）
  - `.agents/skills/`（原生）
- 向后兼容扫描（官方文档明确列出）：`.claude/skills/`、`.codex/skills/`

来源：

- [Cursor Agent Skills](https://cursor.com/docs/skills)
- [Cursor 2.4 Changelog](https://cursor.com/changelog/2-4)

## 2. Codex

> 这里的 `Rule` 是对 Codex 官方 `AGENTS.md` / `AGENTS.override.md` custom instructions 机制的 Synapse 语义映射；`Skill` 是官方原生概念。

### 全局规则

- 默认全局规则文件：`~/.codex/AGENTS.md`
- 如果设置了 `CODEX_HOME`，则全局规则位于 `$CODEX_HOME/AGENTS.md`
- 同层还支持 `AGENTS.override.md`，优先级高于 `AGENTS.md`

来源：

- [Codex AGENTS.md 指南](https://developers.openai.com/codex/guides/agents-md)

### 项目规则

- Codex 从项目根开始，一直走到当前工作目录，逐层读取：
  - `AGENTS.override.md`
  - `AGENTS.md`
  - 以及配置里的 fallback 文件名
- 如果 Synapse 要做“仓库级安装”，`<repo-root>/AGENTS.md` 是官方支持的位置之一
- 如果要做目录级细分规则，也可以安装到项目子目录中的 `AGENTS.md` / `AGENTS.override.md`

来源：

- [Codex AGENTS.md 指南](https://developers.openai.com/codex/guides/agents-md)

### 全局 Skill

- 官方用户级 Skill 目录：`$HOME/.agents/skills/<skill-name>/`
- Skill 是目录，不是单文件；入口文件是 `SKILL.md`

来源：

- [Codex Agent Skills](https://developers.openai.com/codex/skills)

### 项目 Skill

- 官方项目级 Skill 目录：`.agents/skills/`
- Codex 会从当前工作目录向上一直扫描到仓库根，所以这些位置都能被识别：
  - `$CWD/.agents/skills/`
  - 父目录中的 `.agents/skills/`
  - `$REPO_ROOT/.agents/skills/`
- 如果 Synapse 要做“仓库级安装”，`<repo-root>/.agents/skills/<skill-name>/` 是官方支持的位置之一

来源：

- [Codex Agent Skills](https://developers.openai.com/codex/skills)

## 3. Windsurf

### 全局规则

- 全局规则文件：`~/.codeium/windsurf/memories/global_rules.md`
- 这是一个单文件、全局 always-on 的规则入口

来源：

- [Windsurf Memories & Rules](https://docs.windsurf.com/windsurf/cascade/memories)

### 项目规则

- 工作区规则目录：`.windsurf/rules/*.md`
- Windsurf 还会自动发现：
  - 当前 workspace 根目录下的 `.windsurf/rules`
  - workspace 子目录里的 `.windsurf/rules`
  - Git 仓库里向上到 git root 的父目录 `.windsurf/rules`
- `AGENTS.md` 也会被同一套 rules engine 处理；根目录视为 always-on，子目录视为目录级规则

来源：

- [Windsurf Memories & Rules](https://docs.windsurf.com/windsurf/cascade/memories)

### 全局 Skill

- 原生全局 Skill 目录：`~/.codeium/windsurf/skills/<skill-name>/`
- 兼容扫描：`~/.agents/skills/`
- 如果启用了 Claude Code 配置读取，还会扫描：`~/.claude/skills/`

来源：

- [Windsurf Cascade Skills](https://docs.windsurf.com/windsurf/cascade/skills)

### 项目 Skill

- 原生项目 Skill 目录：`.windsurf/skills/<skill-name>/`
- 兼容扫描：`.agents/skills/`
- 如果启用了 Claude Code 配置读取，还会扫描：`.claude/skills/`

来源：

- [Windsurf Cascade Skills](https://docs.windsurf.com/windsurf/cascade/skills)

## 4. VS Code

> 这里的 `Rule` 对应的是 VS Code / GitHub Copilot 官方的 `custom instructions`。  
> 这里的 `Skill` 对应的是 VS Code 官方的 `Agent Skills`。

### 全局规则

- 用户级 instructions 位置：
  - `~/.copilot/instructions/`
  - `~/.claude/rules/`
  - 或与当前 VS Code Profile 关联的 user data（官方未给固定目录路径）
- VS Code 也支持用户级 `CLAUDE.md`：`~/.claude/CLAUDE.md`

来源：

- [Use custom instructions in VS Code](https://code.visualstudio.com/docs/copilot/customization/custom-instructions)

### 项目规则

- 项目级 always-on 规则文件：
  - `./.github/copilot-instructions.md`
  - `./AGENTS.md`（默认是 workspace root；多份嵌套 `AGENTS.md` 属于 experimental 能力）
  - `./CLAUDE.md` 或 `./.claude/CLAUDE.md`
- 项目级 file-based instructions 目录：
  - `./.github/instructions/`
  - `./.claude/rules/`
- 但要注意：VS Code **默认只在当前打开的 workspace 内**发现这些 customizations。  
  如果你打开的是仓库子目录，想让父仓库根目录的 instructions 一并生效，需要额外开启 `chat.useCustomizationsInParentRepositories`

来源：

- [Use custom instructions in VS Code](https://code.visualstudio.com/docs/copilot/customization/custom-instructions)
- [Customize AI in Visual Studio Code](https://code.visualstudio.com/docs/copilot/customization/overview)

### 全局 Skill

- 用户级 Skill 目录：
  - `~/.copilot/skills/`
  - `~/.claude/skills/`
  - `~/.agents/skills/`

来源：

- [Use Agent Skills in VS Code](https://code.visualstudio.com/docs/copilot/customization/agent-skills)

### 项目 Skill

- 项目级 Skill 目录：
  - `./.github/skills/`
  - `./.claude/skills/`
  - `./.agents/skills/`
- VS Code 还允许通过 `chat.agentSkillsLocations` 扩展额外的项目 Skill 目录
- 但同样要注意：默认只发现当前打开 workspace 内的 skills；父仓库根目录的 skills 发现不是默认行为，需要额外开启 `chat.useCustomizationsInParentRepositories`

来源：

- [Use Agent Skills in VS Code](https://code.visualstudio.com/docs/copilot/customization/agent-skills)
- [Customize AI in Visual Studio Code](https://code.visualstudio.com/docs/copilot/customization/overview)

## 5. Claude Code

> 这里的 `Rule` 默认映射到 Claude Code 的持久指令文件（`CLAUDE.md` / `CLAUDE.local.md`）。  
> 另外，Claude Code 还有官方原生 `rules` 目录：`~/.claude/rules/` 与 `./.claude/rules/`，适合路径级规则；`Skill` 是官方原生概念。

### 全局规则

- 用户级规则文件：`~/.claude/CLAUDE.md`
- 用户级 path-scoped 规则目录：`~/.claude/rules/`（官方原生，适合个人跨项目规则）

来源：

- [How Claude remembers your project](https://code.claude.com/docs/en/memory)

### 项目规则

- 项目级共享规则入口：`./CLAUDE.md` 或 `./.claude/CLAUDE.md`
- Claude Code 会从当前工作目录向上递归读取各级目录里的 `CLAUDE.md` / `CLAUDE.local.md`
- 当前工作目录子树中的嵌套 `CLAUDE.md` 会在 Claude 读取该子目录文件时按需加载
- 如果 Synapse 做“仓库级安装”，`<repo-root>/CLAUDE.md` 是官方支持的位置之一
- `CLAUDE.local.md` 适合个人、项目私有偏好，通常应加入 `.gitignore`

来源：

- [How Claude remembers your project](https://code.claude.com/docs/en/memory)

### 全局 Skill

- 用户级 Skill 目录：`~/.claude/skills/<skill-name>/SKILL.md`

来源：

- [Extend Claude with skills](https://code.claude.com/docs/en/skills)

### 项目 Skill

- 项目级 Skill 目录：`.claude/skills/<skill-name>/SKILL.md`
- Claude Code 会自动发现嵌套的 `.claude/skills/`
- 如果用了 `--add-dir`，其中的 `.claude/skills/` 也是会自动加载的例外项

来源：

- [Extend Claude with skills](https://code.claude.com/docs/en/skills)

## 6. Antigravity

> Antigravity 官方文档当前同时使用 `Rules`、`Skills` 和 `Workflows`。  
> 为了和 Synapse 的两类内容对应，下面优先使用 Antigravity 官方原生的 `Skill` 概念；`Workflow` 作为独立能力单独说明，不再代替 `Skill`。

### 全局规则

- 全局规则文件：`~/.gemini/GEMINI.md`

来源：

- [Getting Started with Google Antigravity](https://codelabs.developers.google.com/getting-started-google-antigravity)

### 项目规则

- 工作区规则目录：`your-workspace/.agents/rules/`

来源：

- [Getting Started with Google Antigravity](https://codelabs.developers.google.com/getting-started-google-antigravity)

### 全局 Skill

- 官方全局 Skill 目录：`~/.gemini/antigravity/skills/<skill-name>/SKILL.md`
- 另有独立的全局 Workflow 目录：`~/.gemini/antigravity/global_workflows/<workflow-name>.md`

来源：

- [Getting Started with Google Antigravity](https://codelabs.developers.google.com/getting-started-google-antigravity)

### 项目 Skill

- 官方项目 Skill 目录：`your-workspace/.agents/skills/<skill-name>/SKILL.md`
- 另有独立的工作区 Workflow 目录：`your-workspace/.agents/workflows/`

来源：

- [Getting Started with Google Antigravity](https://codelabs.developers.google.com/getting-started-google-antigravity)

## 7. 直接给 Synapse adapter 的落地结论

- Cursor
  - 全局 Rule：官方可核实信息仅到 `User Rules`（Settings 内）；未找到官方公布的固定文件路径
  - 项目 Rule：原生目录是 `./.cursor/rules/`；官方支持项目根及子目录 `AGENTS.md`（子目录按目录作用域自动生效）；`CLAUDE.md` 未找到官方依据
  - 全局 Skill：官方原生目录 `~/.cursor/skills/`、`~/.agents/skills/`；兼容扫描 `~/.claude/skills/`、`~/.codex/skills/`
  - 项目 Skill：官方原生目录 `.cursor/skills/`、`.agents/skills/`；兼容扫描 `.claude/skills/`、`.codex/skills/`

- Codex
  - 全局 Rule（映射到官方 `AGENTS.md`）：`~/.codex/AGENTS.md`
  - 项目 Rule（映射到官方 `AGENTS.md`）：仓库级安装可用 `<repo-root>/AGENTS.md`；子目录 `AGENTS.md` / `AGENTS.override.md` 也会参与合并
  - 全局 Skill：`~/.agents/skills/`
  - 项目 Skill：仓库级安装可用 `<repo-root>/.agents/skills/`；从当前目录到仓库根的 `.agents/skills/` 都会被识别

- Windsurf
  - 全局 Rule：`~/.codeium/windsurf/memories/global_rules.md`
  - 项目 Rule：`./.windsurf/rules/`
  - 全局 Skill：`~/.codeium/windsurf/skills/`
  - 项目 Skill：`./.windsurf/skills/`

- VS Code
  - 全局 Rule（映射到 custom instructions）：`~/.copilot/instructions/`
  - 项目 Rule（映射到 custom instructions）：官方支持 `./.github/copilot-instructions.md`、`./.github/instructions/`、`./AGENTS.md`（嵌套为 experimental）、`./CLAUDE.md` / `./.claude/CLAUDE.md`、`./.claude/rules/`；但默认仅发现当前打开的 workspace，父仓库发现需额外开启设置
  - 全局 Skill：`~/.copilot/skills/`
  - 项目 Skill：官方支持 `./.github/skills/`、`./.claude/skills/`、`./.agents/skills/`；父仓库发现需额外开启设置

- Claude Code
  - 全局 Rule（这里映射到 `CLAUDE.md`）：`~/.claude/CLAUDE.md`；官方原生 path-scoped rule 目录：`~/.claude/rules/`
  - 项目 Rule（这里映射到 `CLAUDE.md`）：仓库级安装可用 `<repo-root>/CLAUDE.md`；`./.claude/CLAUDE.md` 也受支持；若要用官方原生 path-scoped rule，则看 `~/.claude/rules/` / `./.claude/rules/`
  - 全局 Skill：`~/.claude/skills/`
  - 项目 Skill：`./.claude/skills/`

- Antigravity
  - 全局 Rule：`~/.gemini/GEMINI.md`
  - 项目 Rule：`./.agents/rules/`
  - 全局 Skill：`~/.gemini/antigravity/skills/`
  - 项目 Skill：`./.agents/skills/`
