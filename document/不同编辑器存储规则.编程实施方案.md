# 不同编辑器存储规则 — 编程实施方案

> 基于：`不同编辑器存储规则.核心.md`、`不同编辑器存储规则.md`、`仓库存储系统重构方案.md`  
> 整理时间：2026-04-18

---

## 一、整体定位

编辑器适配层负责将 Synapse 中的 Rule / Skill 内容，按照各编辑器的官方目录规则，解析出正确的安装目标路径。

核心原则（来自产品设计 §36）：

- 安装规则**写死在代码里**，不开放给用户配置
- 每个编辑器一个独立 adapter 文件
- 路径必须基于官方文档调研，不能靠猜

## 三、EditorAdapter 接口

```typescript
// electron/services/editor-adapters/types.ts
export interface EditorAdapter extends SynapseEditorAdapterSummary {
  resolveGlobalTarget(context: EditorAdapterResolveContext): Promise<SynapseEditorResolvedTarget>
  resolveProjectTarget(
    projectPath: string,
    context: EditorAdapterResolveContext,
  ): Promise<SynapseEditorResolvedTarget>
}

export type EditorAdapterResolveContext = {
  contentId: string
  contentType: SynapseContentType  // "rule" | "skill"
}
```

`SynapseEditorAdapterSummary` 字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `SynapseEditorId` | 编辑器唯一标识 |
| `label` | `string` | 展示名称 |
| `supportsGlobal` | `boolean` | 是否支持全局安装 |
| `supportsProject` | `boolean` | 是否支持项目安装 |
| `supportsRule` | `boolean` | 是否支持 Rule 安装 |
| `supportsSkill` | `boolean` | 是否支持 Skill 安装 |

## 四、解析结果类型

```typescript
// src/types/editor.ts
export type SynapseEditorResolvedTarget =
  | { status: "ready";       targetKind: "file" | "directory"; targetPath: string; ... }
  | { status: "unsupported"; targetKind: null; targetPath: null; message: string; ... }
  | { status: "unavailable"; targetKind: null; targetPath: null; message: string; ... }
```

- `ready`：路径已解析，可以执行安装
- `unsupported`：该编辑器本身不支持此组合（如 Cursor 全局 Rule）
- `unavailable`：理论上支持，但当前环境条件不满足（如目录不存在）

## 五、各编辑器适配规则

`✓` = 已实现　`○` = 待实现

### 5.1 Cursor ✓

| 场景 | 目标类型 | 目标路径 |
|------|----------|----------|
| 全局 Rule | `unsupported` | 官方未公布固定磁盘路径 |
| 全局 Skill | `directory` | `~/.cursor/skills/<contentId>/` |
| 项目 Rule | `file` | `<projectPath>/.cursor/rules/<contentId>.md` |
| 项目 Skill | `directory` | `<projectPath>/.cursor/skills/<contentId>/` |

前置检查（全局 Skill）：`~/.cursor/` 目录必须存在，否则返回 `unavailable`。

### 5.2 Codex ✓

| 场景 | 目标类型 | 目标路径 |
|------|----------|----------|
| 全局 Rule | `file` | `~/.codex/AGENTS.md`（或 `$CODEX_HOME/AGENTS.md`） |
| 全局 Skill | `directory` | `~/.agents/skills/<contentId>/` |
| 项目 Rule | `file` | `<projectPath>/AGENTS.md` |
| 项目 Skill | `directory` | `<projectPath>/.agents/skills/<contentId>/` |

前置检查（全局）：`~/.codex/`（或 `$CODEX_HOME`）目录必须存在，否则返回 `unavailable`。适用于全局 Rule 和全局 Skill。

`$CODEX_HOME` 优先级高于默认 `~/.codex`，通过 `process.env.CODEX_HOME` 读取。

## 六、共用工具函数（utils.ts）

| 函数 | 说明 |
|------|------|
| `createReadyTarget(opts)` | 构造 `status: "ready"` 结果 |
| `createUnsupportedTarget(opts)` | 构造 `status: "unsupported"` 结果 |
| `createUnavailableTarget(opts)` | 构造 `status: "unavailable"` 结果 |
| `createUnsupportedPlatformTarget(opts)` | 平台不支持时的快捷构造 |
| `expandHomeDirectory(value)` | 展开 `~` 前缀 |

| `getSkillDirectoryName(contentId)` | Skill 目录名 = `contentId.trim()` |
| `getRuleFileName(contentId)` | Rule 文件名 = `${contentId.trim()}.md` |
| `isSupportedEditorPlatform()` | 检查 `process.platform` 是否在支持集合内 |
| `pathExists(targetPath)` | 异步检查路径是否存在 |
| `resolveExistingProjectPath(projectPath)` | 检查项目路径是否存在，返回 `string \| null` |

支持的平台集合：`darwin`、`linux`、`win32`。

## 七、安装内容写入规则

安装目标路径由 adapter 解析，实际写入由上层服务执行（adapter 层不负责写入）。写入规则：

### Rule（`targetKind: "file"`）

- 目标是单个 `.md` 文件
- 如果目标文件已存在：**追加**内容（在文件末尾追加，加空行分隔）
- 如果目标文件不存在：直接写入

> 原因：多个 Rule 可能共享同一个全局文件（如 `CLAUDE.md`、`AGENTS.md`），追加是正确语义。

### Skill（`targetKind: "directory"`）

- 目标是一个目录
- 采用**整体覆盖**策略（产品设计 §44.2）：先删除旧目录，再写入新目录完整结构
- 不做增量合并，不保留旧文件

### resolveEditorInstallTarget 调用参数

```typescript
type SynapseResolveEditorTargetPayload = {
  editorId: SynapseEditorId          // "cursor" | "codex" | "claude-code"
```

## 额外约束（2026-04-18 更新）

- Rule / Skill 的仓库存储已经切到 history-based 模型；安装逻辑读取的是**当前版本**，不是旧版单层目录。
- Rule 下载 / 安装读取 `history/<latestHistoryDirname>/main.md`。
- Skill 下载 / 安装读取：
  - `history/<latestHistoryDirname>/main.md`
  - `history/<latestHistoryDirname>/attachments.json`
  - `attachments-pool/<sha256 分片路径>`
- Skill 附件在仓库存储层只保留 `{ originalName, sha256, size }`，不再保留旧版相对目录结构。

## 九、前端调用流程

```
用户点击安装菜单项
  → 选择编辑器（来自 getEditorAdapters() 列表）
  → 弹出作用域选择弹窗（全局 / 项目）
  → 若选项目，再选择项目路径
  → 调用 resolveEditorInstallTarget(payload)
  → 根据返回 status 决定后续：
      ready       → 执行实际安装写入
      unsupported → 提示该编辑器不支持此操作
      unavailable → 提示环境条件不满足（附 message）
```

## 十、新增编辑器 Adapter 的步骤

1. 在 `src/types/editor.ts` 的 `SYNAPSE_EDITOR_IDS` 数组中添加新 ID
2. 在 `electron/services/editor-adapters/` 下新建 `<editor>-adapter.ts`
3. 实现 `EditorAdapter` 接口，按第五章路径规则填写
4. 在 `electron/services/editor-adapters/index.ts` 中注册新 adapter

当前已注册：`cursor`、`codex`、`claude-code`。待实现：`windsurf`、`vscode`、`antigravity`（路径见第五章 5.4–5.6）。

> ⚠️ `windsurf` 和 `antigravity` 的路径需官方文档核实后再实现。`vscode` 全局路径存在根本性问题（无官方磁盘路径），项目级可先实现，全局暂定 `unsupported`。

## 十一、注意事项

1. **不能靠猜路径**（产品设计 §53.3）：所有路径必须有官方文档依据，来源注释写在 adapter 文件顶部。
2. **Skill 安装必须整体替换**（产品设计 §53.4）：不能误写成局部覆盖。
3. **平台检查前置**：每个 adapter 的 `resolveGlobalTarget` / `resolveProjectTarget` 都应先调用 `isSupportedEditorPlatform()`。
4. **Cursor 全局 Rule 是 `unsupported`，不是 `unavailable`**：这是官方设计限制，不是环境问题，两者语义不同。
5. **Codex `$CODEX_HOME` 环境变量**：优先级高于默认路径，必须在 `resolveCodexHomePath()` 中处理。
