# 步骤 9：Rules 与 Skills 列表浏览页

## 目标

实现 Rules 和 Skills 的主浏览界面，完成搜索、分类筛选、列表展示三件核心事。这是产品设计文档第 21、22、23 节的实现。

## 要做的事

### 9.1 抽象模块列表页骨架

- Rules 和 Skills 页面结构一致，应抽象出一套可复用页面骨架：
  - 左侧：搜索框 + 分类列表
  - 右侧：内容列表区域
- 可以保留模块级差异，但不要复制两套几乎相同的 JSX

### 9.2 左侧搜索区

- 顶部放搜索框
- 搜索框右侧放“新建”按钮 `+`
- 搜索范围只作用于当前模块：
  - Rules 页只搜 Rules
  - Skills 页只搜 Skills

### 9.3 左侧分类栏

- 分类项来自步骤 8 的配置与统计结果
- 支持点击切换当前分类
- 当前选中项要有清晰高亮状态
- 当分类数量为 0 时，是否显示该分类可统一约定：
  - 建议仍然显示，便于让用户知道完整分类体系

### 9.4 右侧内容列表

- 内容区使用“响应式卡片列表”，不要做表格，也不要做大尺寸营销卡
- 每个内容项至少包含：
  - 图标
  - 标题
  - 简介
  - 右侧操作区
- 图标背景色来自 `meta.iconBg`

### 9.5 列表筛选逻辑

- 最终列表由三个条件共同决定：
  1. 当前激活目录
  2. 当前分类
  3. 当前搜索词
- 搜索建议先做标题 + 简介的模糊匹配
- 后续如果需要再加作者、分类等搜索维度

### 9.6 页面状态处理

- 至少处理以下状态：
  - 初始加载
  - 空目录
  - 目录不存在
  - 当前分类下无结果
  - 搜索无结果
  - 读取失败

### 9.7 状态保持

- 切换顶级 Tab 后再回来，保留：
  - 搜索词
  - 当前分类
  - 列表滚动位置
- 避免用户每次切回来都回到初始状态

## 注意事项

- Rules 和 Skills 页面是两个独立业务模块，但视觉结构应尽量一致
- 当前阶段不要加入跨模块搜索，也不要加入复杂排序器
- 右侧操作区先按最终结构预留位置，后续步骤再接入下载、安装、复制
- 页面布局要适配可调整大小的桌面窗口，窄宽度下也不能挤坏文本
- 当前目录不是 Git 仓库时，列表仍可浏览本地内容，但刷新和“新建”入口应禁用
- 目录切换后应用会整体 reload，因此页面只需处理单次会话内的状态保持

## 验收标准

1. Rules 和 Skills 页面都具备搜索框、分类栏、内容列表
2. 搜索只影响当前模块
3. 点击分类后列表会正确筛选
4. 卡片能展示图标、标题、简介和操作区
5. Tab 来回切换后，搜索词和分类状态能保留
