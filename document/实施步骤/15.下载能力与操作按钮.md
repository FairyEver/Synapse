# 步骤 15：下载能力与操作按钮

## 状态：已完成

## 目标

实现统一的操作按钮组件，并让下载行为基于新的 history 存储模型工作。

## 要做的事

### 15.1 统一操作按钮

- 列表卡片和详情弹窗共用同一套 split button
- 左侧主按钮：下载
- 右侧下拉按钮：更多操作（安装、复制等）

### 15.2 Rule 下载

- 导出为 `<id>.md`
- 内容来自当前版本 history 的 `main.md`

### 15.3 Skill 下载

- 导出为 `<id>.zip`
- zip 顶层目录使用内容 `id`
- 固定包含：
  - `main.md`
  - `attachments/` 下的附件文件
- 附件文件名使用 `attachments.json.originalName`
- 附件内容从 `attachments-pool/<分片>/<sha256>` 读取

### 15.4 保存位置

- 通过系统保存对话框选择输出位置
- 预填默认文件名
- 下载是本地导出，不修改仓库

### 15.5 更多操作菜单

- 安装到编辑器
- 复制
- 其他后续动作复用同一入口

### 15.6 复制规则

- Rule 允许复制
- Skill 仅在没有附件时允许复制
- 不再用“Skill 目录里是否只有一个 `main.md` 文件”判断，因为仓库存储已经改成 `main.md + attachments.json + pool`

## 注意事项

- 下载读取的是“当前版本”，不是随便取某条 history
- 如果附件池中某个文件缺失，zip 中跳过该文件并记录日志，不让整个下载崩溃
- Skill zip 不保留仓库存储里的 pool 路径，也不保留旧版相对目录结构

## 验收标准

1. 卡片和详情弹窗复用同一套操作区
2. Rule 可下载为 `<id>.md`
3. Skill 可下载为 `<id>.zip`
4. Skill zip 能包含正文和附件
5. 复制显隐规则与新存储模型一致
