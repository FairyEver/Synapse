# 步骤 15：下载能力与操作按钮

## 目标

实现内容卡片右侧的操作按钮体系，先把“下载”主路径打通，并为后续安装菜单保留统一入口。这是产品设计文档第 30、31、33 节的实现。

## 要做的事

### 15.1 统一操作按钮组件

- 在卡片和详情弹窗中共用同一个操作按钮组件
- 结构采用 split button：
  - 左侧主按钮：下载
  - 右侧下拉按钮：更多操作

### 15.2 Rule 下载

- Rule 下载结果是一个 `.md` 文件
- 文件名使用内容 `id`，不要使用标题
- 导出结果例如：

```text
<id>.md
```

- 文件内容来自该 Rule 的 `main.md`

### 15.3 Skill 下载

- Skill 下载结果是一个 `.zip` 文件
- zip 文件名同样使用内容 `id`
- zip 内部目录结构应完整保留 Skill 目录结构
- 解压后的顶层目录建议使用 `id`

### 15.4 保存位置选择

- 下载时弹出系统保存对话框，预填默认文件名
- 默认建议打开用户的下载目录，但实际以系统保存对话框体验为准

### 15.5 更多操作菜单

- 右侧下拉菜单应预留后续能力入口，例如：
  - 安装到某编辑器
  - 安装到指定目录
  - 复制

- 当前步骤先把菜单结构搭好，安装逻辑在后续步骤落地

### 15.6 复制能力的显隐规则

- Rule 默认允许复制
- Skill 默认不允许复制
- 如果某个 Skill 实际只有一个 `main.md` 文件，没有其他附件，则允许复制

## 注意事项

- 文件名必须使用 ID，而不是标题，避免非法字符和重名问题
- Skill 打 zip 时要保留目录层级，不能把所有文件打平
- 操作按钮组件要复用，避免列表卡片和详情弹窗两套逻辑分叉
- 下载能力只依赖当前激活目录中的内容，不要求当前目录必须是 Git 仓库
- 下载是本地导出行为，不应修改仓库内容
- 复制能力虽然在本步骤定义规则，但真正写入剪贴板的实现可以跟安装菜单一起接入

## 验收标准

1. 卡片和详情弹窗都有统一的 split button 操作区
2. Rule 可下载为 `<id>.md`
3. Skill 可下载为 `<id>.zip`
4. 下拉菜单能展示更多操作入口
5. Rule 与单文件 Skill 的复制可用性规则清晰可判断
