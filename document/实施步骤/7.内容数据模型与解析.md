# 步骤 7：内容数据模型与解析

## 目标

落地新的 history-based 仓库存储模型：Rule / Skill 用永久 UUID 作为根目录名，每次修改写入一条完整 history 快照；列表读取走本地 SQLite 索引，详情按需读 history 文件。

## 要做的事

### 7.1 数据模型

- `meta.json` 只存出生信息，创建后永不修改：
  - `id`
  - `type`
  - `createdBy`
  - `createdByDisplayName`
  - `createdAt`
- `history/<dirname>/snapshot.json` 存当前版本元信息：
  - `title`
  - `description`
  - `category`
  - `icon`
  - `iconBg`
  - `modifiedBy`
  - `modifiedByDisplayName`
  - `modifiedAt`
  - `deleted`
- `history/<dirname>/main.md` 永远存完整正文
- `history/<dirname>/attachments.json` 永远存完整附件引用：
  - `files: [{ originalName, sha256, size }]`

### 7.2 目录结构

```text
repo/
  rules/
    <ruleUuid>/
      meta.json
      history/
        <timestamp>__<userId>__<rand6>/
          snapshot.json
          main.md
          attachments.json
  skills/
    <skillUuid>/
      meta.json
      history/
        <timestamp>__<userId>__<rand6>/
          snapshot.json
          main.md
          attachments.json
  attachments-pool/
    <sha256[0:2]>/
      <sha256[2:4]>/
        <sha256>
```

- 内容根目录名是 **32 位无横线 UUID**
- history 目录名是 **三段式**：`YYYYMMDDTHHmmssZ__<userId>__<rand6>`
- Skill 附件不再散落在内容目录下，统一走 `attachments-pool/`

### 7.3 当前版本判定

- 当前版本 = 所有 history 中 `snapshot.json.modifiedAt` 最大的那条
- 排序和冲突判定以 `snapshot.json.modifiedAt` 为准，不信任目录名时间戳
- 如果当前版本 `deleted: true`：
  - 列表页排除
  - 搜索排除
  - 详情页显示“该内容已被删除”

### 7.4 本地索引

- 列表页不直接扫文件系统，改为读取本地 SQLite `content_index`
- 索引只存在客户端本地缓存，不写回仓库
- 最小字段：
  - `id`
  - `type`
  - `title`
  - `description`
  - `category`
  - `icon`
  - `icon_bg`
  - `created_by`
  - `created_by_name`
  - `created_at`
  - `modified_by`
  - `modified_by_name`
  - `modified_at`
  - `deleted`
  - `latest_history_dirname`
  - `attachment_count`

### 7.5 主进程读取能力

- `listContent(type)`：从 `content_index` 读取未删除内容
- `readCurrentDetail(type, id)`：读取最新 history 的 `snapshot.json`、`main.md`、`attachments.json`
- `listHistory(type, id)`：列出全部 history 条目
- `readHistoryVersion(type, id, dirname)`：读取指定 history 的完整只读快照
- `readAttachmentFile(sha256)`：按需从 `attachments-pool` 读附件；缺失时降级返回空，不崩溃

### 7.6 IPC 接口

- `get-rules`
- `get-skills`
- `get-rule-detail`
- `get-skill-detail`
- `get-rule-history`
- `get-skill-history`
- `get-rule-history-version`
- `get-skill-history-version`
- 兼容已有下载 / 安装流程的内容读取接口继续保留

## 注意事项

- 渲染层只拿类型化结果，不直接拼仓库路径
- 解析失败的单条 history 允许跳过，但要记录日志
- 列表刷新依赖索引同步，不再靠“重新全量扫目录”
- `attachments.json` 只存 `{ originalName, sha256, size }`，不保留相对路径

## 验收标准

1. 列表页能从本地索引读取 Rule / Skill 列表
2. 详情页能读取当前版本
3. 历史面板能读取任意 history 快照
4. 软删除内容不会出现在列表中
5. 附件缺失时只降级提示，不导致详情崩溃
