# 步骤 12：Skill 创建流程

## 状态：已完成

## 目标

实现 Skill 创建模态框、附件拖拽和表单校验，完成多文件内容创建的前半段链路。这是产品设计文档第 24、25、27、43 节的实现。

## 要做的事

### 12.1 新建入口

- 在 Skills 页面搜索框右侧放置 `+` 按钮
- 点击后打开“新建 Skill”模态框
- 只有当前激活目录是 Git 仓库时，`+` 按钮才可用
- 模态框关闭前，同样禁止刷新

### 12.2 表单字段

- Skill 创建表单至少包含：
  - 标题（必填）
  - 简介（必填）
  - 分类（必填）
  - 图标（必填）
  - 背景色（必填）
  - 主说明文本输入框（必填）
  - 附件拖拽区域（可选）

### 12.3 附件拖拽与选择

- 支持拖入多个文件
- 最好同时支持拖入文件夹，便于保留原始目录结构
- 如果实现上拖文件夹不稳定，可补一个“选择文件/文件夹”按钮兜底

### 12.4 保留原始目录结构

- Skill 附件进入系统后，应保留用户拖入时的相对路径
- 前端要把每个附件整理成：
  - 原始文件对象
  - 相对路径
  - 文件大小

### 12.5 文件大小校验

- 单个附件大小限制 **10MB**
- 超限文件应在前端直接拦截，并给出明确提示
- 文件类型不做限制

### 12.6 附件列表管理

- 模态框内展示已选择的附件列表
- 至少支持：
  - 查看相对路径
  - 查看文件大小
  - 删除单个附件
  - 清空全部附件

### 12.7 提交数据结构

- 前端提交时生成类似结构：

```typescript
interface CreateSkillPayload {
  title: string;
  description: string;
  category: string;
  icon: string;
  iconBg: string;
  content: string;
  files: Array<{
    relativePath: string;
    size: number;
    file: File;
  }>;
}
```

## 注意事项

- Skill 的主说明文件依然由表单文本生成 `main.md`，不是让用户上传一个 `main.md`
- 如果附件相对路径重复，应在提交前拦截，避免后续写文件时互相覆盖
- 拖拽目录时要特别注意 Electron / Chromium 下目录遍历 API 的兼容性
- 表单关闭时不做草稿恢复，只做脏表单确认
- 当前目录不是 Git 仓库时，整个创建入口应禁用
- 创建阶段只负责组织输入数据，真正写入本地 Git 工作区留给后续步骤

## 验收标准

1. 点击 Skills 页 `+` 按钮可打开创建模态框
2. 表单包含主说明文本和附件拖拽区
3. 支持多文件选择，并保留相对路径
4. 单文件超过 10MB 会被拦截
5. 当前目录不是 Git 仓库时，`+` 按钮保持禁用
6. 提交时可生成包含附件信息的 `CreateSkillPayload`
