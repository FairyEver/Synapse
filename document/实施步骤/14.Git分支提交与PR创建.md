# 步骤 14：直接提交、立即推送与待同步队列

## 状态：已完成

## 目标

废弃“创建分支 + 发 PR”的旧流程，改为：**写 history → commit → 立即 push；失败则进入本地待同步队列**。

## 要做的事

### 14.1 基本提交流程

1. 确认当前目录存在且是 Git 仓库
2. 写入新的 history 快照
3. `git add`
4. `git commit`
5. 立即 `git push`
6. 成功后刷新本地索引

### 14.2 Git 身份

- 所有提交都使用统一机器人身份：
  - `user.name = "Synapse Bot"`
  - `user.email = "bot@synapse.local"`
- 真实作者来自 `snapshot.json.modifiedBy` / `modifiedByDisplayName`
- 不再读取用户自己的 Git name/email 作为内容作者

### 14.3 Commit message

- 创建 / 编辑 / 删除：
  - `[synapse] create rule <id8>`
  - `[synapse] update skill <id8>`
  - `[synapse] delete rule <id8>`
- 维护任务：
  - `[synapse] compaction <count> content`
  - `[synapse] gc <count> attachments`

### 14.4 Push 失败处理

- 成功：返回 `saved`，提示“已保存并同步”
- 失败：
  - 不打断用户填写流程
  - 把提交记录写入本地 `pending_pushes`
  - 工具栏上传按钮亮起
  - 返回“已保存，等待同步”

### 14.5 non-fast-forward

- 创建 / 编辑 / 删除的主动提交：
  - push 失败时允许 `git pull --rebase` 后重试一次
- 手动同步待推送内容：
  - 仍然允许 `pull --rebase` 后再 push
- 历史整理（compaction / gc）：
  - 不做 rebase 重试
  - 失败则保留为待同步提交，等用户后续统一 push

### 14.6 用户可见行为

- 不展示 branch
- 不展示 PR
- 不展示 commit hash
- 不要求用户配置 GitHub Token / GH_TOKEN / 平台 API

## 注意事项

- 提交前必须确保仓库 local config 已写入机器人身份
- 所有 Git 命令都在主进程执行
- 错误信息要区分网络、认证、无上游、非 Git 仓库等场景
- 列表中的新内容是“本地工作区当前状态”，不再依赖 PR 是否被合并

## 验收标准

1. 创建 / 编辑 / 删除不再创建分支
2. 系统不再发起 PR
3. push 失败时能进入 `pending_pushes`
4. 用户可手动同步待推送提交
5. UI 中不暴露 branch / PR / token 概念
