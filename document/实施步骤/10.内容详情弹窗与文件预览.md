# 步骤 10：内容详情弹窗与文件预览

## 目标

实现 Rule / Skill 的详情弹窗，让用户在不离开当前列表页的前提下查看完整信息和文件内容。这是产品设计文档第 42 节的实现。

## 要做的事

### 10.1 详情弹窗入口

- 点击内容卡片本体时打开详情弹窗
- 点击右侧操作按钮时不打开详情，而是执行对应操作
- 弹窗打开后，背景列表页保留原状态

### 10.2 弹窗头部信息

- 详情弹窗至少展示：
  - 图标
  - 标题
  - 简介
  - 作者
  - 创建时间
  - 分类
  - 下载 / 安装操作区

### 10.3 单文件预览

- 如果内容只有一个可预览文件，则直接显示文件内容
- Rule 固定只会预览 `main.md`
- 单文件 Skill 也直接展示该文件

### 10.4 多文件预览

- 多文件 Skill 在预览区域顶部提供 Tabs
- 文件顺序必须满足：
  1. `main.md` 永远第一个
  2. 其余文件按文件名排序

### 10.5 文本与二进制区分

- 文本类文件：
  - 直接以纯文本方式显示
  - 不做代码高亮
  - 不做富文本 Markdown 渲染
- 二进制文件：
  - 不预览内容
  - 只展示文件名、大小、存在状态

### 10.6 文件加载策略

- 打开弹窗时读取当前内容详情与文件数据
- 可以按需加载：
  - 先加载 meta 和默认文件
  - 切换到其他文件 Tab 时再读取对应文件
- 避免一次把大型多文件 Skill 全量塞到前端内存

### 10.7 交互收尾

- 支持 ESC 关闭
- 支持点击遮罩关闭
- 如果当前弹窗里有子操作（例如安装二次弹窗），要统一管理弹窗层级，避免焦点混乱

## 注意事项

- 当前 MVP 不做独立详情页，只做弹窗，不要引入额外页面路由
- 预览区要优先保证可读性，不追求复杂编辑器体验
- 长文本要有滚动容器，不能把弹窗整体撑得过高
- 详情弹窗中的下载 / 安装按钮，后续步骤会接真实逻辑，此步先把数据和结构打通
- 详情读取基于当前激活的本地目录，不依赖当前目录是否具备 Git 能力
- 如果文件读取失败，应只提示该文件失败，不要让整个详情弹窗崩溃

## 验收标准

1. 点击卡片可打开详情弹窗
2. 弹窗能展示完整元信息
3. Rule 可预览 `main.md`
4. 多文件 Skill 可通过 Tabs 切换文件
5. 文本文件可预览，二进制文件只显示基本信息
