# 步骤 6：本地仓库目录接入与同步

## 目标

实现“选择本地目录后探测 Git 能力，并在可用时执行手动同步”的能力。这是产品设计文档第 10、11 节的实现，也是后续创建与提交流程的前提。

## 要做的事

### 6.1 Git 操作封装

- 在主进程中封装 Git 操作模块
- 可选方案：
  - 使用 `simple-git` 库
  - 或使用 `isomorphic-git`
  - 或直接调用系统 `git` 命令
- 推荐优先直接调用系统 `git` 命令，行为更贴近用户本机已有的 Git 环境

### 6.2 本地目录选择

- 用户在 Settings 中点击“选择文件夹”，使用系统目录选择器选中一个本地目录
- 选中后只写入本地配置，不做仓库下载，不复制目录
- 显示名称可默认取目录名，后续按配置中的 uuid 进行内部引用

### 6.3 本地目录状态探测

- 选择目录后，主进程应检查：
  - 目录是否存在
  - 当前目录是否位于 Git 工作区中
  - 如果是 Git 工作区，是否能执行后续同步
- 渲染进程显示至少以下状态：
  - 目录不存在
  - 本地目录已连接（非 Git 仓库）
  - Git 仓库已连接

### 6.4 刷新机制

- 顶部栏右侧刷新按钮，点击后拉取当前仓库最新内容
- 刷新行为建议使用 `git pull --ff-only`
- 刷新完成后通知渲染进程重新读取数据
- 当前**不做自动同步**（产品设计第 10.4 节）
- 如果当前目录不是 Git 仓库，刷新按钮保持禁用

### 6.5 同步失败处理

根据产品设计第 10.5 节：
- 清晰提示错误原因（网络问题、认证失败、没有上游分支、目录不是 Git 仓库等）
- 支持用户回到自己常用的 Git 工具继续处理
- 当前不做软件内凭证录入界面

### 6.6 Git 凭证处理

根据产品设计第 11 节：
- 尽量不自己明文保存用户名密码
- 优先依赖系统凭证管理器（macOS Keychain / Windows Credential Manager）
- 或使用 Git 环境已有的凭证能力（`credential.helper`）
- 当前不提供仓库级凭证配置项

## 注意事项

- Synapse 不负责仓库下载或浅克隆，这些动作交给用户自己的 Git 工具
- 目录状态检查和同步都必须在主进程执行，不要在渲染进程中操作文件系统
- 刷新时如果网络失败，应友好提示而非崩溃
- 删除目录配置时不要删除用户本地文件
- 同步能力只对 Git 目录启用，非 Git 目录仍可作为本地内容源使用

## 验收标准

1. 在 Settings 中可以通过目录选择器添加本地目录
2. 目录添加后能正确显示“存在 / 不存在 / 是否为 Git 仓库”状态
3. 当前目录是 Git 仓库时，刷新按钮可用并能拉取最新内容
4. 当前目录不是 Git 仓库时，刷新按钮保持禁用
5. 同步失败时有清晰可理解的错误提示
