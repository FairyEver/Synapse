# 步骤 6：Git 仓库克隆与同步

## 目标

实现 Git 仓库的首次克隆、刷新同步功能。这是产品设计文档第 10、11 节的实现，是数据读取的前提。

## 要做的事

### 6.1 Git 操作封装

- 在主进程中封装 Git 操作模块
- 可选方案：
  - 使用 `simple-git` 库
  - 或使用 `isomorphic-git`
  - 或直接调用系统 `git` 命令
- 推荐使用 `simple-git`，成熟稳定且支持进度回调

### 6.2 首次克隆

- 用户在 Settings 中配置仓库后，触发首次克隆
- **必须使用浅克隆**：`git clone --depth=1`（产品设计第 10.3 节，强约束）
- 克隆目标目录：应用数据目录下以仓库 UUID 命名的子目录
- 克隆过程中必须有**进度条**展示（产品设计第 10.2 节）

### 6.3 克隆进度反馈

- 主进程执行 clone，通过 IPC 向渲染进程推送进度
- 渲染进程显示进度条或进度指示器
- 进度信息至少包含：当前状态文字 + 百分比（如果可获取）

### 6.4 克隆失败处理

根据产品设计第 10.5 节：
- 清晰提示错误原因（网络问题、认证失败、仓库不存在等）
- 支持重试
- 如果是认证失败，允许用户补充输入凭证信息
- 整体交互参考 SourceTree 的克隆体验

### 6.5 刷新机制

- 顶部栏右侧刷新按钮，点击后拉取当前仓库最新内容
- 刷新行为：`git pull` 或 `git fetch + reset`（因为是浅克隆，需要注意操作方式）
- 刷新完成后通知渲染进程重新读取数据
- 当前**不做自动同步**（产品设计第 10.4 节）

### 6.6 Git 凭证处理

根据产品设计第 11 节：
- 尽量不自己明文保存用户名密码
- 优先依赖系统凭证管理器（macOS Keychain / Windows Credential Manager）
- 或使用 Git 环境已有的凭证能力（`credential.helper`）
- 如果系统凭证不可用，考虑提供一次性输入的方式

### 6.7 本地仓库目录管理

- 目录命名使用仓库配置中的 UUID
- 目录位于 `app.getPath('userData')/repos/{uuid}/`
- 切换仓库时切换读取路径
- 删除仓库配置时清理对应本地目录

## 注意事项

- 浅克隆（`--depth=1`）是强约束，不可省略，避免仓库历史膨胀
- 首次克隆可能耗时较长，UI 必须有反馈，不能无响应
- 刷新时如果网络失败，应友好提示而非崩溃
- Git 操作全部在主进程执行，不要在渲染进程中操作文件系统
- 多个仓库的本地目录互相独立，不要共用

## 验收标准

1. 在 Settings 中添加仓库后，可以触发克隆
2. 克隆过程有进度展示
3. 克隆完成后本地目录正确创建，包含仓库文件
4. 克隆失败有清晰的错误提示，支持重试
5. 刷新按钮点击后能拉取最新内容
6. 浅克隆正确生效（`.git` 目录很小）
