# 步骤 4：本地配置系统

## 状态：已完成

## 目标

建立完整的本地配置持久化体系，包括配置文件的读写、默认值管理、分层合并机制。这是产品设计文档第 38、39、40 节的实现，也是后续所有功能的基础。

## 要做的事

### 4.1 本地配置文件

- 在用户的应用数据目录下（`app.getPath('userData')`）创建配置文件
- 格式：**JSON 单文件**，如 `config.json`
- 软件启动时读取此文件恢复配置
- 配置变更时写入此文件持久化

### 4.2 默认值集中管理

- 创建 `src/constants/defaults.ts`（或类似路径），集中定义所有默认值
- 包括但不限于：
  - 默认 Rules 目录名
  - 默认 Skills 目录名
  - 默认窗口行为
  - 其他初始值
- **默认值必须单点维护**，不能散落在代码各处

### 4.3 配置分层机制

实现三层配置合并：

1. **代码内默认配置** — 硬编码在代码中的 defaults
2. **用户本地 JSON 配置** — 用户通过 Settings 修改后持久化的配置
3. **运行时合并配置** — 启动时将两者合并，用户配置覆盖默认配置

### 4.4 全局配置 vs 仓库上下文配置

根据产品设计第 9 节，必须区分两类配置：

**跟随仓库切换的设置（仓库上下文）：**
- 本地目录路径
- Rules 主目录名
- Skills 主目录名

**不跟随仓库切换的设置（全局）：**
- 编辑器安装逻辑相关
- 项目列表
- 软件自身全局行为
- 用户昵称

### 4.5 Electron IPC 通信

- 主进程负责文件系统读写（配置文件的读/写）
- 渲染进程通过 IPC 请求读取/保存配置
- 在 `preload.ts` 中暴露安全的 API

### 4.6 仓库列表数据结构

- 配置中维护一个仓库列表，每个仓库包含：
  - `uuid`（唯一标识，用于本地配置内部引用）
  - `localPath`（用户选择的本地目录路径）
  - `name`（显示名称）
  - `rulesDir`（Rules 主目录名）
  - `skillsDir`（Skills 主目录名）
- 同时记录当前激活目录的 uuid
- 删除仓库配置时，只移除配置记录，不删除用户本地目录

## 注意事项

- 配置文件不存在时，应自动创建并写入默认值，不能报错
- 配置文件格式损坏时，应有容错处理（备份旧文件，重新创建）
- 读写操作应使用异步 API，避免阻塞主进程
- 配置文件路径不能硬编码，要使用 Electron 提供的标准路径 API
- IPC 通道命名要有统一前缀和规范，便于后续扩展

## 验收标准

1. 应用首次启动时自动在用户数据目录创建 `config.json`
2. 配置修改后重启应用，配置能正确恢复
3. 默认值集中在一个文件中定义
4. 渲染进程可以通过 IPC 读取和写入配置
