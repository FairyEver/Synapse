# 步骤 3：应用壳层与导航结构

## 目标

搭建整个软件的壳层（Shell），包括顶部导航栏、一级 Tab 切换、模块容器。这是产品设计文档第 5、6、7 节的实现。

## 要做的事

### 3.1 顶部导航栏（Header）

布局分三个区域：

- **左侧**：Logo + 产品名 "Synapse"
- **中间**：一级 Tabs — Rules / Skills / Settings
- **右侧**：刷新按钮（当前只放一个按钮，未来可扩展为工具栏）

### 3.2 一级 Tab 路由

- 点击 Tab 切换到对应模块的视图
- 不使用传统 URL 路由（Electron 桌面应用不需要），用状态管理即可
- 默认激活 Rules Tab

### 3.3 模块容器架构

按照产品设计第 7 节的要求，采用 **壳层 + 独立业务模块** 架构：

```
src/
  App.tsx                    # 壳层：Header + 模块容器
  modules/
    rules/                   # Rules 模块
      index.tsx              # 模块入口
    skills/                  # Skills 模块
      index.tsx              # 模块入口
    settings/                # Settings 模块
      index.tsx              # 模块入口
```

- 每个模块是一个独立目录，拥有自己的组件、状态、逻辑
- 壳层只负责渲染顶部栏和根据当前 Tab 切换模块
- 模块间不直接互相引用

### 3.4 刷新按钮

- 放在顶部栏右侧
- 当前点击行为：后续步骤实现（当当前目录是 Git 仓库时，拉取最新内容并刷新列表）
- 此步骤只做 UI 和事件绑定的 placeholder

### 3.5 窗口标题栏

- Electron 窗口应有合适的标题
- macOS 下考虑使用 `titleBarStyle: 'hiddenInset'` 实现沉浸式标题栏（可选）

## 注意事项

- **模块独立性**：三个模块的代码必须高度解耦。未来可能增加第四个、第五个模块，不能让所有逻辑耦合在一个大组件里
- **不过早引入路由库**：桌面应用用简单的状态切换即可，除非后续需求变复杂
- **Tab 切换不要销毁组件状态**：切换 Tab 后再切回来，之前的列表滚动位置和筛选状态应保留（可以用 `display: none` 或条件渲染配合状态保持）
- **响应式**：虽然是桌面应用，但窗口大小可变，布局要能适配不同窗口尺寸
- **刷新按钮默认按 Git 能力启用**：没有激活目录、目录不存在、或当前目录不是 Git 仓库时应禁用刷新
- **刷新按钮在模态框打开时应禁用**（产品设计第 45 节）

## 验收标准

1. 应用启动后显示顶部导航栏，包含 Logo、Tabs、刷新按钮
2. 点击 Tabs 可以切换到不同模块的占位视图
3. 三个模块的代码位于独立目录中
4. 当前目录不是 Git 仓库时，刷新按钮保持禁用
5. 窗口可自由调整大小，布局不会错乱
