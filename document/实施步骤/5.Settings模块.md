# 步骤 5：Settings 模块

## 状态：已完成

## 目标

实现设置页，并把新的身份系统、仓库维护入口和声明式设置项放进统一结构里。

## 要做的事

### 5.1 页面结构

- 左侧：设置分类
- 右侧：当前分类内容
- 保持声明式设置项渲染，不把设置页写成散乱 JSX

### 5.2 分类

当前至少包含：

1. **通用** — 身份、语言
2. **仓库** — 本地目录管理
3. **内容** — Rules / Skills 主目录名、历史整理入口
4. **项目** — 本地项目路径
5. **日志**
6. **关于**

### 5.3 身份区块

- 只读显示 `userId`
- 复制按钮
- 备份提示文案
- “恢复已有身份”入口
- 显示名称输入框

补充规则：

- `displayName` 不再属于全局配置 JSON
- 身份信息持久化到 `<userData>/user-identity.json`
- 恢复已有身份时要校验 32 位十六进制 ID，并允许自动去掉横线

### 5.4 仓库管理

- 添加 / 删除 / 切换本地目录
- 展示目录存在性和 Git 状态
- 当前目录不是 Git 仓库时，刷新、新建、提交相关入口禁用

### 5.5 内容分类下的维护入口

- 提供“整理历史记录”按钮
- 触发 compaction + 附件 GC
- 完成后给出轻量反馈
- 如果产生待同步提交，工具栏上传按钮应亮起

### 5.6 自动保存

- 常规设置项修改后立即保存
- 显示名称可用失焦或短 debounce 保存
- 不提供单独“保存设置”按钮

## 注意事项

- Settings 仍然是配置驱动结构，但身份区块和维护入口允许作为独立面板插入
- 不要再把“显示名称”写回旧的 config global
- 切换身份不会删除仓库历史，只影响后续新提交的作者信息

## 验收标准

1. 设置页能展示身份区块
2. 用户可复制和恢复 `userId`
3. 显示名称修改能持久化
4. 内容分类下可手动触发历史整理
5. 仓库与项目设置保持原有声明式结构
