# 步骤 11：Rule 创建流程

## 目标

实现 Rule 创建模态框和表单交互，完成从用户输入到提交请求对象的前半段链路。这是产品设计文档第 24、25、26 节的实现。

## 要做的事

### 11.1 新建入口

- 在 Rules 页面搜索框右侧放置 `+` 按钮
- 点击后打开“新建 Rule”模态框
- 模态框关闭前，顶部刷新按钮应禁用

### 11.2 表单字段

- Rule 创建表单至少包含：
  - 标题（必填）
  - 简介（必填）
  - 分类（必填）
  - 图标（必填）
  - 背景色（必填）
  - 正文文本输入框（必填）

### 11.3 图标与背景色选择

- 图标来自软件内置图标库
- 背景色来自预制颜色集合
- 选择后要有实时预览
- 预览重点是图标卡片效果，不需要正文预览

### 11.4 表单校验

- 提交前进行基础校验：
  - 必填项不能为空
  - 标题与简介去掉首尾空格后再判断
  - 正文不能为空
- 错误提示应贴近字段，不要只弹一个全局报错

### 11.5 提交数据结构

- 前端提交时组装明确的数据对象，例如：

```typescript
interface CreateRulePayload {
  title: string;
  description: string;
  category: string;
  icon: string;
  iconBg: string;
  content: string;
}
```

- 作者昵称不要让用户在表单里再输，应从 Settings 中读取

### 11.6 关闭与取消行为

- 用户点击取消或关闭时，如果表单已改动，建议给一次确认
- 但不要做自动草稿恢复，当前阶段没有草稿系统

## 注意事项

- Rule 不允许上传任何附件，也不允许上传现成的 `.md` 文件
- Rule 的正文来源只能是文本输入或粘贴
- 分类选项必须来自步骤 8 的预置分类配置，不允许自由输入
- 模态框打开期间要锁定会影响仓库状态的动作，尤其是刷新
- 表单层只负责采集和校验，不要在这里夹带 Git 写入逻辑

## 验收标准

1. 点击 Rules 页 `+` 按钮可打开创建模态框
2. 表单包含标题、简介、分类、图标、背景色、正文
3. 必填项缺失时会阻止提交并给出字段级提示
4. 图标和背景色支持实时预览
5. 提交时可生成结构清晰的 `CreateRulePayload`
