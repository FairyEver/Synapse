# 核心概念

Synapse 里一共有四个你需要知道的名词：**Rule**、**Skill**、**仓库**、**项目**。都很朴素，五分钟可以读完。

## Rule（规则）

**Rule 是一段可复用的文本**，通常是一段提示词、一条约束、一套风格说明。

它的特征是：

- 只有一段文字，没有附件。
- 用来告诉 AI"你应该怎么做"、"你不该怎么做"、"按什么风格输出"。
- 可以很短（一句话），也可以很长（上千字的规范文档）。

典型的 Rule 例子：

- "写 TypeScript 时不要用 `any`，宁可拆函数也不要类型断言。"
- "回复中文消息时，不使用表情符号，不说客套话，直接给结论。"
- "所有接口文档按：接口名、方法、入参、返回、示例 五段式写。"

## Skill（能力包）

**Skill 是一个带附件的能力包**。它比 Rule 更重，适合放那些"光靠一段提示词说不清"的复合能力。

一个 Skill 包含：

- **一份主说明**：告诉 AI 或使用者这个能力包是干嘛的、怎么触发。
- **若干附件**：示例文件、模板、参考数据、截图、脚本等。

典型的 Skill 例子：

- 一个"写周报"的能力包：主说明 + 3 份历史周报范本。
- 一个"分析日志"的能力包：主说明 + 日志示例 + 分析输出模板。
- 一个"生成单元测试"的能力包：主说明 + 代码样本 + 期望的测试风格。

::: tip 什么时候用 Rule，什么时候用 Skill？
规则只有一段话，用 Rule；要带附件、要让 AI 对照样本工作，用 Skill。
:::

## 仓库（Repository）

**仓库就是团队共享内容的那个目录。**

它可以是：

- 一个 Git 仓库（推荐）——方便团队协作、审核、版本追踪；
- 也可以只是本地一个普通文件夹——先用起来再说。

Synapse 打开的时候，你会选择一个仓库作为"当前数据源"。软件会从这个目录里读取 Rules 和 Skills，展示成可浏览、可搜索的列表。

**重要的是**：Synapse 不托管这些内容。内容就在你选的那个目录里，用什么 Git 平台、用什么备份方案、怎么做权限，都由你决定。Synapse 只是帮你漂亮地看到它们、方便地安装它们。

## 项目（Project）

**项目就是你自己电脑上的一个工作目录。**

比如你正在做的某个代码仓库、某个写作项目的文件夹、某个设计稿的工程目录……这些都叫"项目"。

项目和仓库的区别：

| 概念 | 作用 | 归属 |
| --- | --- | --- |
| **仓库** | 团队共享的 Rules / Skills 来源 | 团队 |
| **项目** | 你安装 Rule / Skill 的目标 | 你自己 |

当你在 Synapse 里点"安装到项目"时，选的就是这里列出的项目路径。同一个项目可以同时给 Claude Code、Cursor、Codex 用，Synapse 会按每个编辑器的规则把内容放到正确的位置。

## 四个概念之间的关系

```text
          仓库（团队共享）
         ┌──────────────┐
         │  Rule × N    │
         │  Skill × M   │
         └──────┬───────┘
                │  Synapse 读取并展示
                ▼
           你（桌面应用）
                │  一键安装
                ▼
       ┌────────┴────────┐
       ▼                 ▼
  全局（所有项目）    项目（指定目录）
```

理解了这四个词，你就已经掌握 Synapse 的全部核心概念了。接下来可以看 [功能特性](/guide/features)。
