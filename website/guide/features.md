# 功能特性

Synapse 的功能围绕一个中心："让好用的 Rules 和 Skills 从团队仓库，顺畅地流到你的日常工具里"。下面按你实际会用到的顺序来介绍。

## 1. 浏览与搜索

打开 Synapse，左侧是 **Rules** 和 **Skills** 两个主入口，切换即可看到对应的全部内容。

每个页面的布局都类似 App Store：

- **左侧**：搜索框 + 分类列表；
- **右侧**：内容卡片列表，每张卡片显示图标、标题、简介和操作按钮。

支持的使用方式：

- **搜索**：在左上角搜索框输入关键字，实时过滤当前模块内的内容。
- **分类筛选**：点击左侧分类，只看某一类。分类数量直接显示在侧边栏上，一眼看清团队沉淀在哪些方向。
- **刷新**：点右上角刷新按钮，从仓库拉取最新内容。

## 2. 查看详情

点击任意一个 Rule 或 Skill 卡片，会弹出详情窗口：

- 图标、标题、简介、作者、创建时间、分类；
- 正文预览；
- Skill 如果带多个附件，顶部会有 Tab 在不同文件之间切换；
- 右下角是下载和安装操作。

所有内容都是**只读预览**，你不会不小心改到团队仓库。

## 3. 下载到本地

每张卡片右侧都有一个「下载」按钮：

- **Rule** 下载为一个 `.md` 文本文件；
- **Skill** 下载为一个 `.zip` 压缩包，解压后是一个完整的能力包目录。

下载是纯本地操作，下载下来的文件放到哪里、怎么用，都由你自己决定。

## 4. 一键安装到 AI 编辑器

这是 Synapse 最核心的能力。Rule / Skill 卡片的「下载」按钮旁边有一个下拉菜单，展开后可以直接装到：

- **Claude Code**
- **Cursor**
- **Codex**

选了编辑器之后，软件会再问你一次：

- **全局安装**：装到当前电脑上这个编辑器的全局目录，所有项目都能用；
- **项目安装**：装到你选中的某个本地项目目录里，只在这个项目里生效。

全局还是项目，看你自己的使用习惯。两种方式你都不需要去手动拷贝、改配置文件——Synapse 已经按每个编辑器官方推荐的位置写好了。

::: tip 为什么不是每个编辑器都支持"全局"？
部分编辑器的全局规则只能通过自己的设置界面管理，Synapse 无法替它写入，这种组合会显示为"不支持"，按钮自动禁用。
:::

## 5. 创建并分享

除了使用别人沉淀的东西，你自己也可以创建 Rule 和 Skill 放进团队仓库。

在 Rules 或 Skills 页面的搜索框旁边，有一个加号按钮 `+`：

- **创建 Rule**：填标题、简介、分类、图标、底色、正文文本。保存即完成。
- **创建 Skill**：在 Rule 的基础上再加一个附件拖拽区——把相关文件拖进来就行，软件会保留你拖入时的目录结构。

点提交之后：

1. Synapse 在仓库目录里自动建好文件；
2. 用你仓库的 Git 能力创建一条待审核的提交；
3. 团队管理员在平台上合并这条提交，内容正式进入团队共享库；
4. 其他人刷新 Synapse 就能看到。

::: tip 我需要懂 Git 吗？
**不需要**。如果仓库已经配置好 Git，Synapse 会替你完成分支、提交、PR 的创建。你只需要填写内容。
:::

## 6. 多仓库切换

如果你同时参与多个团队，每个团队一个仓库，Synapse 允许你配置多个本地目录，在设置里切换当前激活的仓库。同一时刻只展示一个仓库的内容，界面不混乱。

## 7. 设置与个性化

设置界面参考 VSCode 的样式——左侧分组，右侧是该分组下的选项，典型可以设置：

- 仓库目录与 Rules / Skills 子目录名；
- 本地项目列表与别名；
- 你的显示昵称（用作内容作者署名）；
- 软件自动更新。

## 8. 自动更新

软件内置检查更新能力。发布新版本后，你会在软件里收到提示，一键下载并安装，重启即完成升级。
