# 4.0 问题修复记录

## 已修复问题

### 1. Phase 0.2 集成测试仍使用旧占位 schema 数据

现象：

- 首轮测试中 `desktop/tests/unit/phase-0.2-integration.test.ts` 失败。
- 新的 `audit`、`conversations` validator 拒绝旧数据形状，例如 `actor: "user"`、`resource: "/tmp/x"`、conversation 只有 `startedAt`。

原因：

- 本次把 placeholder schema 升级为业务 schema 后，旧集成测试数据不再是合法业务记录。

修复：

- 将 audit 测试数据升级为 `{ actor: { kind }, resource: { type, id } }`。
- 将 conversation 测试数据补齐 `sessionKey/history/active/createdAt/updatedAt`。
- 复测受影响测试通过。

### 2. File-backed DataRepository 工厂 JSONL 泛型不匹配

现象：

- `pnpm desktop:typecheck` 报 `JsonLinesNamespace` 的 `defaults/validate` 类型需要 `Record & { id: string }`。

原因：

- JSONL namespace 是 collection backend，注册时必须使用带 `id` 的 schema 类型。

修复：

- 在 `desktop/electron/runtime/data-repo/factory.ts` 的 JSONL 分支使用 `NamespaceSchema<IdentifiedRecordValue>`。
- 类型检查通过。

### 3. ControlledProcessRunner 错误变量被 TS 控制流缩窄

现象：

- `controlled-runner.ts` 中 `outputError?.message`、`spawnError?.message` 被推断为 `never`。

原因：

- 错误变量在事件回调闭包内赋值，TypeScript 对当前同步控制流做了过度缩窄。

修复：

- 增加 `errorMessage(error: Error | null)` 辅助函数，避免直接在被缩窄变量上取属性。
- 类型检查通过。

### 4. Project-scoped filter 类型转换过窄

现象：

- `scoped-data-repo.ts` 中 `{ projectId } as Partial<T>` 被 TS 判定为可能错误转换。

原因：

- `T` 是任意 namespace record，编译期无法证明必有 `projectId`。

修复：

- 先转换为 `unknown` 再转 `Partial<T>`，并由运行时 wrapper 负责 project-scoped namespace 的字段约束。
- 类型检查通过。
