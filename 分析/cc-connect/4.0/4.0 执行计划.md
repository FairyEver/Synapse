# 4.0 执行计划

## 假设与边界

- 只做“第零步：地基整理”，不实现 AgentRuntime、Feishu、Cron、Bridge UI、多工作区。
- runtime 基础设施可以按 Synapse 当前结构增强；业务逻辑不写入 `分析/cc-connect/4.0/`。
- 占位 schema 仍保持 `schemaVersion: 1`，因为当前仓库尚未把这些 CC Connect namespace 用作真实业务写入；本次把 v1 从 placeholder 升级为可用形状。
- project-scoped persistence 采用字段级隔离，而不是路径级隔离；这是本阶段最小可测方案。

## 修改文件列表与目的

1. `desktop/electron/runtime/service-registry/types.ts`
   - 用真实 runtime 类型替换 DataRepository/EventBus/PermissionGuard/ProcessRuntime placeholder。
   - 增加 `auditSink` 到 `ServiceContext`。

2. `desktop/electron/runtime/service-registry/registry.ts`
   - 默认 `createServiceRegistry()` context 改成真实轻量对象，供测试和 project-container 单测继续工作。

3. `desktop/electron/bootstrap/descriptors.ts`
   - 新增 `core.data-repository`、`core.permission-guard`、`core.audit-sink`、`core.process-runtime`、`core.network-registry`、`core.project-containers` descriptor。
   - 保持 runtime 纯基础设施，bootstrap 负责 glue。

4. `desktop/electron/bootstrap/registry.ts`
   - 注册新增 descriptor。
   - `buildContext()` 改成 registry-backed typed proxy，不再塞 placeholder。

5. `desktop/electron/runtime/data-repo/factory.ts`、`desktop/electron/runtime/data-repo/index.ts`
   - 新增 file-backed DataRepository 工厂，按 schema backend 创建 Json/EncryptedJson/JsonLines/SQLite namespace。
   - 用于 `core.data-repository` descriptor。

6. `desktop/electron/runtime/project-container/scoped-data-repo.ts`、`desktop/electron/runtime/project-container/types.ts`
   - 实现字段级 projectId 隔离 wrapper。
   - 明确全局 namespace 与 project-scoped namespace。

7. `desktop/electron/runtime/data-repo/schemas/placeholders.ts`
   - 升级 providers/projects/connectors/conversations/audit/outbox schema。
   - 保留 secrets schema。

8. `desktop/electron/runtime/process/controlled-runner.ts`、`desktop/electron/runtime/process/index.ts`
   - 新增受 PermissionGuard + AuditSink 保护的统一子进程启动边界。
   - 只提供基础 runner，不接 AgentRuntime。

9. `desktop/electron/runtime/network/registry.ts`、`desktop/electron/runtime/network/index.ts`
   - 扩展 descriptor lifecycle 和 audit hook。
   - `unregister()` 调用 lifecycle stop。

10. 测试文件
   - `desktop/electron/runtime/data-repo/__tests__/schemas.test.ts`
   - `desktop/electron/runtime/project-container/__tests__/scoped-data-repo.test.ts`
   - `desktop/electron/runtime/process/__tests__/controlled-runner.test.ts`
   - `desktop/electron/runtime/network/__tests__/registry.test.ts`
   - `desktop/electron/bootstrap/__tests__/registry.test.ts`
   - 必要时同步 service-registry 测试 context。

## 可能破坏的边界

- `ServiceContext` 类型变严，旧测试里手写 context 需要补真实对象或 cast。
- bootstrap registry 新增服务后，现有结构性测试的服务 id 列表需要更新。
- `ProjectScopedDataRepoImpl.namespace("providers")` 以后会自动过滤 projectId；需要后续业务服务用 `.underlying` 读取全局 provider。
- `NetworkServiceRegistry.register()` 增加 lifecycle 调用后，start 失败必须释放端口，否则后续注册会假冲突。
- `ControlledProcessRunner` 使用 `child_process.spawn()` 只能放在 `runtime/process/`；业务代码不得绕过。

## 对应测试

- Schema：
  - 验证 providers/connectors/conversations/audit/outbox 的完整有效对象。
  - 验证缺 `projectId/sessionKey/status/outcome` 等关键字段会失败。

- Project scope：
  - 同一 namespace 写入 p1/p2 后，`list/get/remove` 不串项目。
  - upsert 缺 projectId 时自动补；显式不同 projectId 时拒绝。
  - 全局 namespace（例如 `projects`）保持 pass-through。

- Process boundary：
  - allow：用户 actor 可运行一个短命令，audit 记录 allowed/exitCode。
  - deny：agent actor 默认被 PermissionGuard 拒绝，audit 记录 denied，且不 spawn。
  - failure：命令不存在或非零退出记录 failed。

- Network boundary：
  - 保留现有端口冲突、默认 `127.0.0.1`、重复注册、unregister 测试。
  - 新增 lifecycle start/stop 测试。
  - 新增 audit hook 测试。

- Bootstrap：
  - registry inspect 包含新增 core services。
  - topo plan 无环，新增依赖顺序正确。

## 验收标准

- 新 `ServiceContext` 不再是 placeholder；新增 CC Connect 服务可通过 context/registry 拿到 DataRepository、EventBus、PermissionGuard、AuditSink、ProcessRuntime。
- `ProjectScopedDataRepoImpl` 对业务 namespace 有真实 projectId 隔离。
- business schema 能支撑后续 AgentRuntime、provider、connector、scheduler、outbox、audit。
- Agent CLI 子进程只能通过受控 runner 边界接入，且有权限检查和审计。
- NetworkServiceRegistry 默认本地监听，能表达 auth/lifecycle/audit。
- 运行并记录：
  - 相关 vitest 单测
  - `pnpm desktop:typecheck`
  - `pnpm desktop:check:hard-constraints`
  - 必要时 `pnpm desktop:test`

## 回滚风险

- 本次改动集中在 runtime/bootstrap；若回滚，后续 AgentRuntime 仍会遇到 placeholder 和 project 数据串写问题。
- schema 仍是 v1，不会触发迁移；回滚风险主要是类型与测试，不涉及用户已有业务数据迁移。
- 新 runner 未被业务调用；即使有问题，也不会改变现有 app 行为，但会阻塞后续 AgentRuntime 接入。
