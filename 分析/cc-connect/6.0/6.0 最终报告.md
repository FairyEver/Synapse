# 6.0 最终报告

## 完成内容

本次完成 CC Connect 迁移计划“第二步：会话持久化、队列、权限和治理闭环”。范围限定在 Electron main/runtime 服务和单元测试，未做 UI、Feishu/Lark、Cron、Bridge、多工作区或 Provider UI。

已完成：

1. AgentSessionRepository
   - 基于现有 `conversations` namespace，没有新增平行存储。
   - 支持 active session、`sessionKey`、`name`、history、userMeta。
   - 保存 Agent 原生 session id、`agentType`、`pastAgentSessionIds`、`resumePolicy`。
   - 提供清理当前 agent session id 的方法，供后续 `/new`、切 Agent、切 Provider 复用。

2. Session lock 和 pending queue
   - `AgentRuntimeService` 对同一 `sessionKey` 建立串行队列。
   - busy 时普通消息只进入 pending queue，不中途写 stdin。
   - 队列上限默认 5，超限返回错误事件。
   - queued turn 在前一轮 result/error 后按顺序继续处理。

3. Permission pending
   - `AgentEvent` 增加 `permissionRequest`。
   - runtime 保存 pending permission，并暴露 `respondPermission()`。
   - 非 user actor 不能直接 allow。
   - allow 前走 `PermissionGuard.check()`，allow/deny/failed 均写 `AuditSink`。

4. Claude Code adapter MVP
   - 新增 `ControlledProcessRunner.start()` 支持长驻受控进程。
   - 新增 `ClaudeCodeAdapter`，启动参数为 stream-json + stdio permission prompt。
   - 支持 user JSON stdin、stdout stream-json 解析、`control_request`、`control_response`、关闭。

5. 输入和输出治理
   - 新增平台无关 `AgentGovernanceService`。
   - 覆盖 disabled commands、admin allowlist、role policy、user/global rate limit、banned words、outgoing rate limit、dedupe、旧消息过滤、allowlist、群聊 @ 过滤。

## 剩余风险

- `core.audit-sink` 仍是第零步 in-memory sink；本步已写入 AuditSink 接口，持久化 audit sink 可后续落地。
- Claude Code adapter 是 MVP：未迁移 provider proxy、allowedTools/disallowedTools、附件落盘、run_as_user。
- Outgoing limiter 当前提供 `allowOutgoing()` 入口，后续 connector/outbox 需要决定等待、排队或拒绝策略。
