## 3. CC Connect run_as_user

已阅读：

- `core/runas.go`
- `core/runas_check.go`
- `core/runas_audit.go`
- `cmd/cc-connect/runas_startup.go`
- `agent/claudecode/session.go`
- `agent/claudecode/claudecode.go`

CC Connect 行为：

- Unix 使用 `sudo -n -iu <user> --preserve-env=<allowed> -- <command>` 包裹进程。
- 默认 env allowlist 很小，避免透传 HOME、USER、LOGNAME、SHELL、PATH 和 secret。
- `VerifyRunAsUserCheap` 检查当前用户可免密切到目标用户，并检查目标用户不能再免密 sudo 回 supervisor。
- `PreflightRunAsUser` 检查 target user、workspace 读写和子目录权限风险。
- `RunIsolationProbe` 记录 supervisor、target、effective uid/gid、workspace 能力和 env 泄露风险。
- Windows 标记 unsupported。

Synapse 现状：

- `ControlledProcessRunner` 已统一 `agent.spawn` 和 `shell.exec`。
- runner 已有 env allowlist，但默认允许 `PATH/HOME/USER/SHELL` 等，不适合作为 run_as 默认。
- Agent spawn、custom exec、Scheduler exec 都已经使用 runner，适合在 runner 增加可选 isolation wrapper。

## 4. CC Connect Webhook

已阅读：

- `core/webhook.go`

CC Connect 行为：

- 默认 path `/hook`。
- 支持 Bearer、`X-Webhook-Token`、query token。
- `prompt` 和 `exec` 互斥。
- 多项目必须解析 project。
- prompt 构造 webhook message 并进入 Engine。
- exec 使用 shell 执行，timeout 后回传截断输出。

Synapse 映射：

- HTTP 服务必须经 `NetworkServiceRegistry`。
- 默认 disabled、`127.0.0.1`、token required。
- prompt 进入 `AgentRuntimeService`。
- exec 走 `ControlledProcessRunner`，并接入 run_as isolation。
- run 状态写入 `webhook.runs`，配置写入 `webhook.config`。

## 5. CC Connect Relay

已阅读：

- `core/relay.go`
- `cmd/cc-connect/relay.go`
- `core/api.go`
- `cmd/cc-connect/main.go`
- `core/engine.go` 的 `HandleRelay`、timeout partial、background drain、`/bind`。

CC Connect 行为：

- relay binding 持久化为 JSON。
- Agent 通过本地 API `/relay/send` 调用。
- target session key 为 `relay:<fromProject>:<chatID>`。
- relay session 独立于用户主会话。
- timeout 后返回 partial，并后台继续 drain。
- Feishu/群聊可见记录用于协作透明度。

Synapse 映射：

- 持久化改用 DataRepository：`relay.bindings`、`relay.runs`。
- Agent 入口复用 side-channel token，新增 `/relay/send`。
- source project/session 由 side-channel env 的 `CC_PROJECT`、`CC_SESSION_KEY` 推断。
- target prompt 使用 `AgentRuntimeService.sendNewSession` 或 relay 专用 collect API。
- visible 记录只对 Feishu reply target 做最小提示。

## 6. CC Connect Compress

已阅读：

- `config/config.go` 的 `AutoCompressConfig`
- `core/interfaces.go` 的 `ContextCompressor`
- `core/engine.go` 的 auto trigger、`cmdCompress`、`runCompress`、`processCompressEvents`
- Claude/OpenCode/iFlow adapter 的 `CompressCommand`

CC Connect 行为：

- 手动 `/compress` 要求 agent 支持 `ContextCompressor`。
- Claude 命令为 `/compact`。
- Auto-compress 在 final result 后、队列下一条消息前、同一 session lock 内触发。
- min gap 默认 30 分钟。
- 压缩事件不进入普通聊天 history。

Synapse 映射：

- 在 `AgentAdapter` 增加 compression capability。
- Claude Code 支持 `/compact`。
- Codex 当前无明确压缩命令，返回 unsupported。
- 配置和状态写入 `agent.compress_state`。

## 7. Hooks / Observer / STT / TTS / Ops

已阅读：

- `core/hooks.go`
- `core/observer.go`
- `core/tts.go`
- `cmd/cc-connect/instance_lock.go`
- `daemon/manager.go`
- `core/updater.go`

结论：

- Hooks 可后续映射为 EventBus + HTTP hook。shell hook 风险高，本阶段不默认实现。
- Observer 对 Synapse 价值较低，因为 Synapse 已经掌控 `AgentEvent`。
- STT/TTS 需要 provider 和音频平台能力，本阶段后置。
- Go daemon/self-update 不照搬。Synapse 保留 Electron 单实例和已有 updater，只补诊断、日志目录、服务状态。
