# 14.0 问题修复记录

## 1. bootstrap 与 schema 固定断言未同步

现象：

- `pnpm desktop:test` 首次运行失败 4 项。
- 失败集中在 descriptor/registry/schema 的固定列表断言。

处理：

- `desktop/electron/bootstrap/__tests__/descriptors.test.ts`
  - 补充 `core.side-channel` 对 `core.execution-isolation` 的依赖断言。
- `desktop/electron/bootstrap/__tests__/registry.test.ts`
  - 补充 `core.execution-isolation`、`core.relay`、`core.automation-ingress` 服务 ID。
  - 按真实依赖图同步 side-channel、scheduler、heartbeat、automation-ingress 依赖。
- `desktop/electron/runtime/data-repo/__tests__/schemas.test.ts`
  - 补充新增 namespace。
  - 补充新增 backend 类型断言。
  - 将 encrypted 断言调整为 `secrets` 与 `webhook.config`。

结果：

- `pnpm desktop:test` 通过，71 个测试文件、425 个测试用例全部通过。

## 2. side-channel 新增 relay 入口缺少统一限流与入口审计

现象：

- `/relay/send` 复用 side-channel 本地 token 鉴权与 `NetworkServiceRegistry`。
- 但 side-channel HTTP 层没有统一 rate limit 与入口级 audit，不满足 14.0 外部入口要求。

处理：

- 在 `desktop/electron/services/side-channel/side-channel-service.ts` 增加：
  - 每路径、每来源的分钟级限流，默认 120/min。
  - 未授权、限流、方法错误、入口允许的 `network.connect` 审计。
  - `/send`、`/cron/add`、`/relay/send` 共用入口防护。

结果：

- `pnpm desktop:typecheck` 通过。
- `pnpm desktop:test` 通过。
- `pnpm desktop:check:hard-constraints` 通过。

## 3. IPC codegen 本地检查失败

现象：

- `pnpm desktop:check:ipc-codegen` 失败。

原因：

- 新增 `ops` IPC 模块后，生成文件 `desktop/electron/generated/ipc-channels.generated.ts` 与 Git 已提交版本存在差异。
- 该检查脚本以“生成后工作区相对提交无 diff”为通过条件；在未提交本次生成物前会失败。

处理：

- 已确认差异只包含本次新增 `ops` IPC channel。
- 未擅自 staging 或提交文件。

当前状态：

- 生成物已在工作区更新。
- 该检查需在本次变更被纳入提交后通过。

## 4. Webhook 审计 resource 固定为默认路径

现象：

- Webhook 支持自定义 path，但入口审计 resource 最初固定写为 `webhook:/hook`。

处理：

- 将认证失败、执行成功、执行失败的审计 resource 改为 `webhook:${config.path}`。

结果：

- 自定义 path 场景下审计记录能反映真实入口。
- 最后一轮 `pnpm desktop:typecheck`、`pnpm desktop:test`、`pnpm desktop:check:hard-constraints` 均通过。

## 5. 打开日志目录缺少 PermissionGuard

现象：

- `ops.openLogDirectory` 已记录 audit，但调用 Electron `shell.openPath` 前没有先走 `PermissionGuard`。

处理：

- 在 `desktop/electron/modules/ops/ipc.ts` 中为 `fs.read.outside-userdata` 增加 PermissionGuard 检查。
- 拒绝时记录 denied audit 并抛错。
- 允许时记录 allowed audit 后打开日志目录。
- 将可选服务解析的空 catch 改为显式返回。

结果：

- 符合敏感操作先鉴权、再审计、再执行的顺序。
- 最后一轮 `pnpm desktop:typecheck`、`pnpm desktop:test`、`pnpm desktop:check:hard-constraints` 均通过。
