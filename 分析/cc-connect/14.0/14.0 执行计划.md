# 14.0 执行计划

## 1. 成功标准

- 13.0 前提检查通过。
- run_as_user 可配置、可 preflight、可 audit probe。
- Agent spawn、custom exec、cron exec、webhook exec 可接入 run_as_user。
- Webhook 默认 disabled，本地绑定，强 token，限流，payload 限制。
- Webhook prompt 进入 AgentRuntime。
- Relay 可通过 side-channel `/relay/send` 请求另一个项目 Agent。
- Relay session 不污染主会话，timeout 后后台 drain。
- `/compress` 可用，unsupported Agent 返回清楚结果。
- Auto-compress 在 final 后、队列下一条前、同一 session lock 内触发。
- 运维诊断返回关键服务状态和日志目录。
- 所有新增持久化通过 DataRepository。
- 所有敏感动作通过 PermissionGuard 和 AuditSink。
- 所有网络服务通过 NetworkServiceRegistry。
- 指定验证命令全部通过并记录。

## 2. 实施顺序

1. 扩展 DataRepository schema。
2. 扩展 `ControlledProcessRunner` 支持可选 process isolation。
3. 新增 `ExecutionIsolationService` 和项目级 run_as repository。
4. 将 AgentRuntime、custom exec、Scheduler exec 接入 process isolation。
5. 新增 `AutomationIngressService`、Webhook config/runs repository，并通过 `NetworkServiceRegistry` 注册。
6. 新增 `AgentRelayService`、relay repository，并扩展 side-channel `/relay/send`。
7. 扩展 AgentRuntime relay collect/timeout/drain 与 compression。
8. 增加 Feishu `/relay` 最小管理命令和 visible record。
9. 新增 ops diagnostics 服务和 IPC。
10. 按需补最小设置页 UI。
11. 补测试，运行指定验证命令。
12. 写测试记录、问题修复记录、最终报告。

## 3. 风险

- 当前工作区已有 13.0 未提交改动，14.0 改动必须避免回退。
- Codex 当前没有明确压缩命令，按 unsupported 处理。
- Relay partial 需要在 AgentRuntime live event loop 上收集，需避免破坏既有 queue 行为。
- Webhook 默认 disabled，若没有 UI 启用，需要通过 IPC 配置。
- run_as preflight 在本地环境可能因 sudo 权限失败，测试以构造/失败路径为主，不假设真实 sudo 可用。
