## 1. 当前项目约束

- `AGENTS.md`：新业务模块放 `desktop/src/modules/`；renderer 只能通过 `window.synapse.*`；IPC 只能通过 `IpcRegistry`；不裸用 `webContents.send`；敏感操作要过 `PermissionGuard` 和 `AuditSink`。

- `.claude/rules/ui-rules.md`：Tailwind 主要用于布局和 token；禁止硬编码颜色、渐变、装饰样式、冗余 UI 文案。

- `3.2 后续阶段复核与调整建议.md`：8.0 拆出 Management IPC、Renderer Chat、持久化审计、ReplyTarget/Outbox、命令策略边界。

## 3. Management API 对应

CC Connect：

- `core/management.go:33` `ManagementServer` 是全局管理 API，保存 `engines`、cron、bridge、provider callback。
- `core/management.go:210` `buildHandler` 集中注册 `/status`、`/projects/*/sessions`、`/send`、`/providers` 等路由。
- `core/management.go:391` `handleStatus` 返回 version、uptime、connected platforms、projects count、bridge adapters。
- `core/management.go:892` `handleProjectSessions` 返回 stored sessions、active keys、history count、last message；POST 可创建 session。
- `core/management.go:1100` `handleProjectSend` 校验 message 后调用 `e.SendToSession(...)`。
- `core/management.go:1126` `handleProjectProviders` 返回 provider 列表和 active provider，不暴露密钥。

Synapse 迁移：

- 使用 `desktop/electron/modules/agent/ipc.ts` 暴露 Electron 内部窄 IPC，而不是启动 HTTP Management server。
- IPC handler 通过 `core.project-containers` 打开项目并复用 `agent.runtime`、`provider.config`，不创建平行 Engine。
- `status/sessions/send/providers/pendingPermissions/respondPermission` 对应 CC Connect 本地管理能力；不做 cron、bridge、setup、global provider CRUD。

## 4. SendToSession / ReplyTarget 对应

CC Connect：

- `core/engine.go:7087` `SendToSession` 调用 `SendToSessionWithAttachments`。
- `core/engine.go:7090` `SendToSessionWithAttachments` 从 active interactive state 取 platform/replyCtx；没有 active state 时尝试通过 `ReplyContextReconstructor` 根据 sessionKey 重建。
- `core/interfaces.go:20` `ReplyContextReconstructor` 让平台能从 session key 重建主动回复上下文，供 cron/heartbeat/side-channel 使用。
- `core/bridge.go:49` `bridgeReplyCtx` 保存 platform、sessionKey、replyCtx。
- `core/bridge.go:296` `BridgePlatform` 实现 `ReplyContextReconstructor`。
- `core/bridge.go:420` `buildBridgeReconstructReplyCtx` 把 project、sessionKey、transport chat id 包进可扩展 reply envelope。

Synapse 迁移：

- 本阶段定义平台无关 `ReplyTarget`，先支持 `transport.kind = "local-renderer"`、`projectId`、`sessionKey`、`conversationId`、可选 `threadId/messageId`。
- `ReplyOutboxService` 写入 `outbox` namespace，支持 `pending`、`sent`、`failed` 的最小状态；后续 Bridge/Feishu/Cron 复用同一 target 模型。
- 本阶段不实现附件、不重建外部平台 reply ctx、不实现 Bridge side-channel。

## 5. Slash command 策略对应

CC Connect：

- `core/engine.go:1539` banned words 对 slash command 跳过。
- `core/engine.go:1596` slash 先进入 `handleCommand`。
- `core/engine.go:1599` 未识别 slash command 会 fall through 到 Agent。
- `core/engine.go:3342` `builtinCommands` 定义内置命令。
- `core/engine.go:3460` `handleCommand` 先处理 disabled/admin，再处理 built-in/custom/skill。
- `core/engine.go:3616` 未知命令先提示 `MsgUnknownCommand`，然后返回 false 继续发给 Agent。

Synapse 迁移：

- 继续保留 7.0 的安全默认：未知 slash 不发给 Agent。
- 新增明确分类：built-in、registered prompt command、agent-native allowlist passthrough、unsupported。
- Agent-native passthrough 必须显式 allowlist；本阶段 UI/远程默认不放行未知 slash。

## 6. Bridge 思想边界

CC Connect：

- `core/bridge.go:23` `BridgeServer` 是全局 WebSocket server，项目 Engine 获得轻量 `BridgePlatform`。
- `core/bridge.go:93` `bridgeMessage` 标准化平台消息。
- `core/bridge.go:313` `BridgePlatform.Reply` 通过 `sendToAdapter` 发 `reply` 消息。
- `core/bridge.go:741` 未知 bridge message type 只 debug，不影响已知消息。
- `core/bridge.go:952` 之后提供 bridge session 管理 REST。

Synapse 迁移：

- 本阶段只读取“标准消息 + reply target + adapter capabilities”的思想。
- 不实现 Bridge WebSocket、Bridge session REST、card action、typing、preview 或 side-channel send。
