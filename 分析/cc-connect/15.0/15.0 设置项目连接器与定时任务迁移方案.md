# 设置项目连接器与定时任务迁移方案

## 背景结论

当前实现把 `projectId` 接到了 `config.repositories[].uuid`，也就是“仓库/本地目录”。这和产品语义不一致。连接器应该属于设置里的“项目”，也就是 `config.global.projects[]`。

本次调整目标不是继续修补“设置 > 连接器”页，而是重排设置的信息架构：

- “连接器”不再是设置左侧独立分类。
- 连接器成为“项目”的属性。
- 一个项目可以没有连接器，也可以配置自己的飞书连接器。
- 定时任务从连接器弹窗中抽出来，成为设置左侧的顶层分类。

## 当前代码事实

### 项目与仓库混用

- 设置页当前把飞书连接器绑定到 `activeRepository.uuid`。
  - `desktop/src/modules/settings/index.tsx`
- Electron 侧 `listConfiguredProjects()` 当前从 `config.repositories` 生成项目列表。
  - `desktop/electron/bootstrap/descriptors.ts`
- 飞书连接器、SideChannel、Scheduler、Relay 等服务都通过这个列表解析 `projectId -> workspacePath`。

这导致代码里的 `projectId` 实际代表仓库 UUID，而不是设置里的项目 ID。

### 定时任务不是纯全局

定时任务 UI 可以做成全局入口，但任务数据本身不是“无归属”的全局对象。

当前 `ScheduledJobEntryV1` 包含：

- `projectId`
- `connectorId`
- `sessionKey`
- `channelKey`
- `workspaceKey`
- `workspacePath`
- `replyCtx`
- `cronExpr`
- `prompt` 或 `exec`

执行时 `CronExecutionService` 会：

- 用 `projectId` 找项目路径。
- 用 `connectorId` 找飞书回传目标。
- 用 `workspacePath` 或频道绑定解析实际执行目录。
- 最终打开对应项目的 AgentRuntime。

所以新“定时任务”页应该是全局聚合管理页，而不是把任务改成完全脱离项目。

## 目标信息架构

```text
设置
```

## 项目页交互方案

### 项目列表

每个项目保留现有展示：

- 项目名称
- 项目路径

每个项目增加连接器操作：

- 没有飞书连接器：显示“添加连接器”
- 已有飞书连接器：显示“连接器配置”

现有“修改”按钮保留名称和行为，只编辑基础信息：

- 项目名称
- 项目路径

### 添加项目弹窗

保持轻量，不引入连接器配置。

字段仍然只有：

- 项目名称
- 项目路径

保存后项目默认没有连接器。

### 修改项目弹窗

保持当前基础信息弹窗。

字段仍然只有：

- 项目名称
- 项目路径

连接器不放进这个弹窗，避免基础信息编辑变得过重。

### 添加连接器弹窗

入口：项目卡片上的“添加连接器”按钮。

弹窗内容复用当前飞书连接器里的“连接凭据”能力：

- 扫码授权
- 手动填写 App ID / App Secret / Owner Open ID
- 保存凭据

保存后关闭弹窗或切换到连接器配置状态。

### 连接器配置弹窗

入口：项目卡片上的“连接器配置”按钮。

建议使用 3 个 Tab：

1. 状态
   - 当前飞书连接器运行状态
   - App ID
   - 连接 / 断开
   - 最近错误

2. 凭据
   - 扫码授权
   - 手动凭据
   - 用于更换机器人或重新授权

3. 频道目录
   - 启用频道目录
   - 本地根目录
   - 按频道名自动绑定
   - 当前项目绑定
   - 共享绑定

不把定时任务放进这个弹窗。

## 定时任务页方案

新增设置分类：“定时任务”。

页面职责：

- 聚合展示所有项目下的定时任务。
- 聚合展示所有项目下的保活提醒。
- 支持按项目筛选。
- 支持按连接器状态筛选。
- 支持启用、停用、删除、立即运行、静默切换。

创建任务时必须选择：

- 项目
- 连接器
- 会话标识
- 执行内容
- Cron

如果某个项目没有连接器，不允许为它创建飞书定时任务。

## 后端调整方案

### 1. 修正项目来源

把当前 `listConfiguredProjects()` 从 `config.repositories` 改为 `config.global.projects`。

目标映射：

```ts
projectId: project.id
name: project.name
workspacePath: project.path
```

受影响服务：

- FeishuConnectorService
- SideChannelService
- Scheduler/CronExecutionService
- Relay
- AutomationIngress
- BridgeAdapter
- Ops

需要逐个检查这些服务是否应该绑定“项目”还是“仓库”。连接器、定时任务、远程执行应绑定项目。

### 2. 连接器数据继续按 projectId 存

保留现有连接器数据结构方向：

- `connector.projectId`
- `secretId(projectId)`
- `workspaceConfig` 在 connector 上
- `workspace.bindings` 仍用 project scope + channelKey

但 `projectId` 的来源改成 `config.global.projects[].id`。

### 3. 定时任务增加全局列表接口

当前 IPC 主要是项目维度：

- `feishuListScheduledJobs(projectId)`
- `feishuListHeartbeats(projectId)`

需要新增全局聚合接口：

- `listScheduledJobs()`
- `listHeartbeats()`

或者保守一点：

- Renderer 先读取所有项目，然后逐个调用现有 project API 聚合。

推荐后端新增全局接口，方便排序、筛选、权限和后续分页。

### 4. 创建任务仍必须落到项目

定时任务虽然在顶层页面管理，但创建时必须写入：

- `projectId`
- `connectorId`
- `sessionKey`
- 必要时写入 `workspacePath`

不要把定时任务改成没有项目归属的全局任务。

## 前端调整方案

### 1. 删除设置侧边栏“连接器”

从 `desktop/src/modules/settings/data.ts` 移除 connectors 分类。

### 2. 拆分 FeishuConnectorPanel

当前 `desktop/src/modules/settings/components/feishu-connector-panel.tsx` 同时承担：

- 连接状态
- 连接凭据
- 频道目录
- 定时任务

需要拆成模块级组件：

- `ProjectFeishuConnectorStatus`
- `ProjectFeishuConnectorCredentials`
- `ProjectFeishuWorkspaceDirectory`
- `ProjectFeishuConnectorDialog`
- `ProjectFeishuConnectorSetupDialog`
- `ScheduledTasksPanel`

原 `FeishuConnectorPanel` 可以删除，或临时保留为兼容壳，最终不再由设置侧边栏直接使用。

### 3. ProjectListEditor 接入连接器

`ProjectListEditor` 每个项目卡片增加：

- `添加连接器`
- `连接器配置`

组件需要按项目 ID 查询飞书状态：

- `feishu.getStatus(project.id)`

为了避免项目列表渲染时大量重复请求，可以做一个项目连接器状态 hook：

- `useProjectFeishuConnectorStatus(projectIds)`

第一版也可以逐项目轻量查询，后续再优化批量接口。

### 4. 新增 ScheduledTasksPanel

新增设置分类和页面组件：

- `desktop/src/modules/settings/components/scheduled-tasks-panel.tsx`

职责：

- 读取全部项目。
- 聚合任务和保活提醒。
- 展示项目名、连接器、会话、状态、下次执行、上次执行。
- 提供操作按钮。

## 迁移策略

因为当前线上/本地数据可能已经用仓库 UUID 存了连接器和任务，需要兼容迁移。

建议迁移规则：

1. 如果现有 connector.projectId 命中 `config.global.projects[].id`，保持不动。
2. 如果命中 `config.repositories[].uuid`，尝试按路径匹配 `config.global.projects[].path`。
3. 匹配成功则把 connector、secret、workspace bindings、scheduled jobs、heartbeats 的 projectId 迁到项目 ID。
4. 匹配失败则保留旧数据，但 UI 标记为“未匹配项目”，要求用户选择归属项目。

迁移必须保留旧数据备份，不做不可逆删除。

## 实施步骤

1. 修正项目解析来源
   - `listConfiguredProjects()` 改为读取 `config.global.projects`。
   - 更新相关测试，明确 projectId 是项目 ID。

2. 拆分飞书连接器组件
   - 状态、凭据、频道目录从当前大组件中拆出。
   - 定时任务从组件中移除。

3. 项目页接入连接器弹窗
   - 项目卡片增加连接器按钮。
   - 添加连接器弹窗只显示凭据。
   - 配置弹窗使用状态 / 凭据 / 频道目录 Tab。

4. 新增定时任务设置分类
   - 左侧侧边栏新增“定时任务”。
   - 新增聚合页。
   - 第一版至少支持查看、启停、删除、立即运行。

5. 补全全局任务接口
   - 新增 list all scheduled jobs / heartbeats IPC。
   - 返回项中带项目名和连接器状态，减少 renderer 拼装。

6. 数据迁移与兼容
   - 编写 projectId 迁移逻辑。
   - 对旧仓库 UUID 数据做路径匹配。
   - 无法匹配时不删除，交给 UI 处理。

7. 验证
   - 项目 A/B 各自配置不同飞书连接器。
   - 切换当前仓库不影响项目连接器配置。
   - 飞书消息进入项目路径执行。
   - 频道目录覆盖项目默认路径。
   - 顶层定时任务页能看到所有项目任务。
   - 定时任务执行仍能回传到对应飞书会话。

## 风险点

- `projectId` 名字已经广泛使用，短期不要大规模重命名，先修正来源和行为。
- 项目和仓库都带路径，迁移时必须避免路径相同但语义不同导致误绑。
- 定时任务顶层化容易让人误以为任务不属于项目，UI 必须显示项目列。
- 添加连接器弹窗和配置弹窗复用逻辑时，要避免复制过多状态代码，优先抽 hook。

## 不做的事

第一阶段不做：

- 不支持一个项目多个飞书连接器。
- 不支持连接器直接绑定任意未登记项目的文件夹。
- 不把定时任务改成无项目归属的全局任务。
- 不把项目基础信息和连接器配置塞进同一个长弹窗。
