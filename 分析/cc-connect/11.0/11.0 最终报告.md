# 11.0 最终报告：Feishu 多工作区与频道绑定

## 已实现能力

- Feishu connector 可配置多工作区开关、`baseDir`、频道名自动绑定和 idle 回收时间。
- Feishu 入站消息生成稳定 `channelKey`：普通群聊为 `feishu:<chatId>`，root/thread 存在时为 `feishu:<chatId>:root:<rootId>`，不包含 userId。
- 新增 `workspace.bindings` DataRepository namespace，支持 project/shared 绑定，project 优先、shared 兜底。
- Feishu 支持 `/workspace` 与 `/ws` 的查看、bind、route、init、unbind、list，以及 shared 子命令。
- 未绑定普通消息进入 init flow，不进入 Agent；`/workspace` 命令优先于 init flow。
- `AgentRuntimeService` 支持 per-message workspace context：history、AgentSessionId、live session、queue、pending permission、idle 状态按 workspace 隔离。
- Agent exec/live turn 使用绑定 workspace path；`CC_SESSION_KEY`、Feishu reply context 和 outbox destination 保持原始平台 sessionKey。
- 设置页增加 Feishu 多工作区配置、baseDir 选择、project/shared binding 列表和删除。

## CC Connect 映射摘要

- `workspace_binding.go` -> `WorkspaceBindingRepository` + `workspace.bindings` schema。
- `workspace_state.go` -> `AgentRuntimeService` workspace-aware state、active turn、idle reaper。
- `engine.go` 多工作区主流程 -> `FeishuConnectorService.handleMessage(...)` 中 command -> resolver -> init flow -> AgentRuntime。
- `engine.go` `/workspace` 命令 -> Feishu-only workspace command handler。
- `engine.go` channel/session 分离 -> `makeFeishuChannelKey(...)` 与 `AgentMessage.channelKey/workspaceKey`。

## 关键设计选择

- 选择扩展 `AgentRuntimeService`，不创建 synthetic ProjectContainer。这样 provider/model/mode/governance/PermissionGuard/AuditSink 仍绑定真实 project，内部只增加 workspace 维度。
- 本阶段仅实现 Feishu 路径；未引入 Lark、微信、Cron、Relay、Webhook 或跨平台 UI。
- convention 自动绑定只使用 Feishu 事件里的 `chat_name`；没有稳定频道名时依赖显式 `/workspace` 命令。
