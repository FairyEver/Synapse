# 11.0 执行计划：Feishu 多工作区与频道绑定

## 实现选择

本阶段采用“扩展 AgentRuntimeService 支持 per-message workspace context”，不创建 synthetic ProjectContainer。

原因：

- 当前 ProjectContainerRegistry 以真实 `projectId` 缓存容器；用 `projectId:workspace` 打开 synthetic container 会让 provider、model、mode、项目配置和审计 projectId 偏离真实项目。
- AgentRuntimeService 已经集中持有 providerConfig、ReplyTarget/Outbox、PermissionGuard、AuditSink、command router；扩展 runtime key、conversation metadata、workDir 选择即可达到 CC Connect 的 per-workspace session/live/queue 隔离。
- 对外仍保持原始 Feishu `sessionKey`，内部隔离只使用 `workspaceKey`。

## 分步

1. 数据模型与 repository
   - 新增 `WorkspaceBindingEntryV1` 和 `workspace.bindings` schema。
   - Connector 增加 `workspaceConfig`。
   - Conversation 增加 `workspaceKey/workspacePath/channelKey`。
   - 实现 `WorkspaceBindingRepository` 与单测。

2. Feishu channelKey 与配置
   - 新增 `makeFeishuChannelKey`。
   - normalizer 输出 `channelKey/channelName`，reply context 不变。
   - `ConnectorRepository` summary 暴露 workspace config。

3. Workspace resolver、init flow、命令
   - 实现 Feishu-only resolver、init flow 和 `/workspace`/`/ws` handler。
   - project/shared binding 优先级对齐 CC Connect。
   - 修改绑定的命令要求 Feishu admin。
   - route/init/git clone 经过 PermissionGuard/AuditSink；git clone 通过可替换 runner，测试不做真实网络。

4. AgentRuntime workspace context
   - runtime key 使用 `projectId:workspaceKey:sessionKey`。
   - conversation active 查询/id 写入 workspaceKey。
   - exec/live turn 使用 `message.workspacePath ?? project workDir`。
   - pending permission 保存 workspaceKey，响应回正确 live session。
   - idle reaper 关闭空闲 workspace live session，跳过 active turn。

5. FeishuConnectorService 集成
   - 未开启 multi-workspace 保持 10.0 路径。
   - 开启后命令优先、resolver 其次、init flow 兜底。
   - resolved 消息写入 workspace context 后进入同一个 project AgentRuntime。
   - 错误通过当前 Feishu reply context 返回。

6. IPC/preload/types/UI
   - 增加 get/update workspace config、list/unbind bindings、route bind 窄接口。
   - 设置页只做启用、baseDir、project/shared binding 列表和删除。
   - 使用现有 shadcn/Radix 组件和 token。

7. 验证与产物
   - 新增/更新测试。
   - 运行并记录：
     - `pnpm desktop:typecheck`
     - `pnpm desktop:test`
     - `pnpm desktop:check:hard-constraints`
     - `pnpm desktop:check:ipc-codegen`
   - 写 `11.0 测试记录.md`、`11.0 问题修复记录.md`、`11.0 最终报告.md`。

## 本阶段不做

- 不做 Lark、微信、Cron、Relay、Webhook、多平台泛化。
- 不做完整本地引用卡片渲染。
- 不做 Feishu 群名 API 拉取；仅支持事件内已有 channelName 的 convention 自动绑定。
- 不启动 dev server、浏览器、Playwright 或截图验证。
