# 11.0 源码映射：Feishu 多工作区与频道绑定

## 已读规则与阶段边界

- `AGENTS.md`：本阶段必须复用 ProjectContainer、DataRepository、PermissionGuard、AuditSink、ReplyTarget/Outbox、typed IPC；不得裸写 `ipcMain.handle/on`、`webContents.send`、业务数据 `fs.writeFile`、`http.createServer`；Renderer 只走 `window.synapse.*`。
- `.claude/rules/design.md` / `.claude/rules/ui-rules.md`：设置页扩展必须沿用 `radix-nova`、shadcn/Radix、Tailwind token；不写自定义颜色、内联样式、卡片套卡片和解释性废话。
- `2.1`：CC Connect 多工作区本质是单 project 内的 workspace-aware session router：channelKey -> binding -> workspace context -> per-workspace Agent/session。
- `3.1` / `3.2`：多工作区放在 Feishu connector 和 sessionKey/reply context 稳定之后；`sessionKey`、`channelKey`、`workspaceKey` 必须分清，`CC_SESSION_KEY` 不能使用内部 workspace key。
- `10.0`：Synapse 已具备 Feishu setup、WS runtime、message normalizer、ReplyTarget/Outbox、permission card 和设置页入口；未实现多工作区。

## 已知限制

- 当前 Feishu event 类型没有稳定群名/话题名获取接口。本阶段只在事件携带 `chat_name` 时做 convention 自动绑定；常规使用依赖 `/workspace bind|route|init`。
- Synapse 目前没有 CC Connect `renderOutgoingContentForWorkspace` 等完整本地引用渲染能力；本阶段不扩展远程引用卡片，只保证 workspace workDir 和敏感操作权限边界。
