# 11.0 问题修复记录

## 1. workspace config 类型不兼容

- 现象：`pnpm desktop:typecheck` 报错，`FeishuWorkspaceConfigUpdate` 不能传入 `normalizeWorkspaceConfig(...)`。
- 根因：`ConnectorWorkspaceConfigV1` 继承了 `Record<string, unknown>`，而更新请求类型没有索引签名。
- 修改文件：`desktop/electron/services/connectors/feishu/connector-service.ts`。
- 修复：把归一化函数入参改为字段型 `WorkspaceConfigLike`，只依赖需要的配置字段。
- 复测命令：`pnpm desktop:typecheck`。
- 复测结果：通过。

## 2. IPC 生成文件未同步

- 现象：`pnpm desktop:check:ipc-codegen` 初次失败，提示 `electron/generated/ipc-channels.generated.ts` differs from committed file。
- 根因：本阶段新增了 Feishu workspace config/binding IPC channel，生成文件需要同步更新。
- 修改文件：`desktop/electron/generated/ipc-channels.generated.ts`。
- 修复：运行 `pnpm desktop:generate:ipc` 更新生成文件。
- 复测命令：`pnpm desktop:check:ipc-codegen`。
- 复测结果：生成文件纳入本次提交后通过。

## 3. Feishu 频道名来源有限

- CC Connect 位置：`core/engine.go:11539` 的 convention 自动绑定依赖 channel name。
- Synapse 当前阻碍：当前 Feishu event 类型只有在事件携带 `chat_name` 时才能稳定拿到频道名，没有额外群名 API 集成。
- 替代行为：支持 `chat_name` 存在时 `baseDir/<chat_name>` 自动绑定；否则通过 `/workspace bind|route|init` 显式绑定。
- 后续建议：如果 Feishu SDK 后续提供稳定群名/话题名查询，再在 Feishu-only resolver 中补充 channelName resolver。

## 4. 本地引用渲染未扩展

- CC Connect 位置：`core/engine.go:7401` `renderOutgoingContentForWorkspace`。
- Synapse 当前阻碍：现有 Feishu ReplyTarget/Outbox 没有完整本地引用卡片渲染能力。
- 替代行为：本阶段保证 Agent 执行目录、路径绑定、clone/write/network 等敏感操作都在 workspace context 与 PermissionGuard/AuditSink 边界内。
- 后续建议：在后续远程附件/引用能力阶段补 workspace-aware local reference renderer。
