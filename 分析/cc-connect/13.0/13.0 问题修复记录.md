# 13.0 问题修复记录

## 1. Electron typecheck：readonly option 赋值

- 现象：`references.ts` 中 `ReferenceViewOptions` 是 readonly interface，`parseReferenceViewOptions` 内直接给 `head/context` 赋值导致 typecheck 失败。
- 修复：解析时使用局部可变对象，再作为 `ReferenceViewOptions` 返回。
- 复测：`pnpm --filter @synapse/desktop exec tsc -p tsconfig.electron.json --noEmit` 通过。

## 2. Electron typecheck：Feishu admin userId

- 现象：`isFeishuAdmin(connector, normalized.message.userId)` 传入 `string | undefined`。
- 修复：使用 `normalized.message.userId ?? ""`，只把确定的 Feishu userId 作为 admin 判断输入。
- 复测：`pnpm --filter @synapse/desktop exec tsc -p tsconfig.electron.json --noEmit` 通过。

## 3. `/show` 无目录文件引用

- 现象：`file.ts:2` 被当成完整文件名，导致 `stat file.ts:2` 失败。
- 原因：line suffix parser 只接受带 `/` 或 `\` 的 path。
- 修复：只排除 Windows drive-letter 形态，允许 `file.ts:2` 解析为 `file.ts` + line 2。
- 复测：`references.test.ts` 通过。

## 4. Custom exec 测试平台

- 现象：custom exec 默认只允许 `local-renderer`，测试消息使用 `local`，路由被拒绝。
- 修复：测试使用真实 Renderer 平台 `local-renderer`。
- 复测：`command-router.test.ts` 通过。

## 5. Bridge progress fallback 断言

- 现象：Bridge 无 update/card 能力时，tool result 现在返回紧凑进度文本，不再是裸 `ok`。
- 修复：测试断言改为匹配包含 `ok` 的紧凑进度内容。
- 复测：`bridge-adapter-service.test.ts` 通过。

## 6. Bridge capabilities snapshot 测试时序

- 现象：control-plane adapter 注册后 ack 与 snapshot 连续发送，测试第二次绑定 message listener 时可能错过 snapshot。
- 修复：测试在发送 register 前先用 `readJsonN(ws, 2)` 监听两条消息。
- 复测：`bridge-adapter-service.test.ts` 通过。

## 7. IPC codegen 检查

- 现象：`pnpm desktop:check:ipc-codegen` 初次失败，提示 `electron/generated/ipc-channels.generated.ts` differs from committed file。
- 原因：新增 Agent IPC 后生成文件已更新，但脚本用 `git diff --quiet -- electron/generated/ipc-channels.generated.ts` 检查 working tree。
- 修复：暂存 `desktop/electron/generated/ipc-channels.generated.ts`。
- 复测：`pnpm desktop:check:ipc-codegen` 通过。
