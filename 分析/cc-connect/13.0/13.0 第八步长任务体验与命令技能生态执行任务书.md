# 13.0 第八步执行任务书：长任务体验与命令/技能生态

## 0. 阶段定位

本任务书假设 12.0 已经完成。

也就是说，在开始本阶段前，仓库应已经具备：

- 本机 AgentRuntime 闭环。
- 会话、队列、权限、治理。
- Provider、模型与基础命令控制。
- Management IPC、Renderer Chat、持久化审计、ReplyTarget/Outbox。
- BridgeAdapterService 与本地 side-channel send。
- Feishu connector、Feishu 主动回复、Feishu 多工作区与频道绑定。
- Scheduler、Cron、Heartbeat、Feishu 主动回传。

13.0 的目标不是再增加新的平台入口，而是把已经跑通的 Agent 运行链路变得更可观察、更可操作、更可扩展：

- 长任务 stream preview。
- compact progress。
- 本地代码引用渲染。
- 安全的 `/show`。
- 完整 CommandRegistry。
- Custom Commands。
- SkillRegistry。
- 命令/技能发布到 Renderer command palette、Bridge capabilities、Feishu 可用命令列表。
- Agent-native slash allowlist 的产品化配置。

本阶段仍只要求 Feishu 作为真实远程平台。不要新增微信、Telegram、Slack、Discord、Lark 等平台。

## 6. 总体实现原则

### 6.1 AgentEvent 是核心，不要靠字符串拼 UI

stream preview、compact progress、reference render、command execution 都应该围绕现有 `AgentEvent`、`ReplyTarget`、`Bridge capabilities`、`Renderer timeline` 扩展。

不要在 Feishu connector、Bridge adapter 或 React 组件里临时解析一堆不可复用字符串。

### 6.2 平台能力探测优先

不同目标能力不同：

- Renderer 可以展示结构化 timeline。
- Bridge 可以使用 `preview_start`、`update_message`、`typing`、`capabilities_snapshot`。
- Feishu 如果已有 update/card 能力可以使用；如果没有，必须安全降级为文本。

不要为了 Feishu 强行重写所有平台的消息模型。

### 6.3 安全优先

本阶段会触及本地文件引用、`/show`、exec custom command、skills、Agent-native slash passthrough。

必须遵守：

- 本地文件读取必须限制在当前 workspace 或显式允许的目录内。
- 远程 Feishu 用户不能读取任意本机路径。
- exec command 必须走 PermissionGuard、AuditSink、ControlledProcessRunner。
- Agent-native slash passthrough 必须有 allowlist，不允许远程入口默认放行未知 slash。
- 不记录 secret 明文。

### 6.4 UI 必须遵守项目规范

涉及 UI 必须遵守：

- shadcn/ui。
- Radix。
- Tailwind token。
- 项目现有 design baseline。

禁止：

- 自定义颜色。
- hex/rgb/hsl 字面色。
- Tailwind 任意色值。
- 内联 style，动态计算值除外。
- 新 CSS module 或全局 CSS 覆盖。
- 卡片套卡片。
- 渐变、霓虹、emoji heading。
- UI 废话。

## 7. Stream preview 要求

### 7.1 核心行为

实现一个平台无关的 preview/progress 编排层。

建议命名：

- `AgentPreviewService`
- `StreamPreviewWriter`
- `ProgressEventFormatter`

可以按仓库现有命名调整，但不要把逻辑写死在 React 组件或 Feishu service 里。

必须支持：

- Agent 文本增量累积。
- 最小字符差异阈值。
- 最小刷新间隔。
- turn 完成时 finalize。
- tool/thinking 事件出现时 freeze 或切换到 progress。
- error 时关闭 preview 并记录失败状态。

### 7.2 Renderer 行为

Renderer Chat 不必完全模拟消息平台的 preview/update。

Renderer 应优先展示结构化 timeline：

- 用户消息。
- assistant streaming text。
- thinking/progress item。
- tool use。
- tool result。
- permission request。
- final result。
- error。

要求：

- 长任务执行时用户能看到系统仍在工作。
- 同一轮 assistant 文本不要刷成几十条消息。
- 任务完成后状态明确。
- permission request 不要被 preview/progress 挤掉。

### 7.3 Bridge 行为

Bridge adapter 如果声明支持：

- `preview`
- `update_message`
- `typing`
- `progress_card`

则发布对应事件。

如果不支持，降级为：

- 开始 typing。
- 适度发送文本进度。
- 最终发送完整结果。

必须更新 Bridge capabilities snapshot，让外部 adapter 能知道当前 host 支持哪些命令和 preview 能力。

### 7.4 Feishu 行为

Feishu 本阶段可以采用保守实现：

- 如果当前 Feishu reply service 已支持 update/card，则实现 compact progress。
- 如果不支持，不要临时堆复杂卡片，先用文本 fallback。
- final result 必须可靠回传。

Feishu fallback 不等于没有进度：

- 可以发送开始/处理中/完成的少量文本。
- 必须有 outgoing rate limit，避免刷屏。

## 8. Compact progress 要求

### 8.1 Progress 数据模型

新增或扩展 progress payload，至少表达：

- `turnId`
- `sessionKey`
- `workspaceKey`
- `status`: `running`、`done`、`error`
- `entries`
- `updatedAt`

entry 至少支持：

- `thinking`
- `tool_use`
- `tool_result`
- `text_delta`
- `permission`
- `error`

不要把完整大型 tool result 全塞进 UI 状态。需要截断或摘要。

### 8.2 Progress 策略

参考 CC Connect：

- 保留最近若干条 progress entry，建议 10 条。
- 频繁事件要节流。
- done/error 时 finalize。
- 平台不支持结构化 progress 时降级成文本。

### 8.3 权限请求

permission request 必须是独立强状态：

- Renderer 可操作 allow/deny。
- Bridge/Feishu 可以回传可操作按钮或文本指令，按当前能力降级。
- 不能因为 progress finalize 丢掉 pending permission。

## 9. Local references 要求

### 9.1 引用解析

实现或完善本地引用 parser。

至少支持：

- 相对路径。
- 绝对路径。
- markdown link。
- `file://`。
- `path:line`。
- `path:line:column`。
- `path#L10`。
- 简单 range。

必须排除：

- URL。
- code fence 内文本。
- inline code 内明显不是路径的文本。

### 9.2 Workspace 约束

所有本地引用必须按当前 workspace 解析。

要求：

- 相对路径基于当前 `workspacePath`。
- 绝对路径必须在当前 workspace 内，或在明确允许的目录内。
- 超出 workspace 的引用不能渲染成可点击能力。
- Feishu/Bridge 远程输出不能泄露任意绝对路径。

### 9.3 Renderer 点击打开

Renderer 中本地引用应变成可点击动作。

要求：

- 点击打开文件或定位行必须走 typed preload API。
- main process 做路径校验。
- 敏感路径或 workspace 外路径拒绝。
- 记录 audit。
- 复用现有 editor adapter/IDE registry，不要新造一套打开编辑器逻辑。

### 9.4 Feishu/Bridge 输出

远程平台不能直接点击本机文件。

建议：

- 渲染成相对路径和行号。
- 提示可用 `/show <path>` 查看片段。
- 不要暴露 workspace 外绝对路径。

## 11. CommandRegistry 要求

### 11.1 统一命令分类

必须把 slash command 分类稳定下来：

- built-in command。
- custom prompt command。
- custom exec command。
- skill command。
- agent-native passthrough。
- unsupported。

远程入口默认策略：

- built-in 执行内部逻辑。
- custom prompt 展开后进 AgentRuntime。
- custom exec 经过权限后执行。
- skill 构造成 invocation prompt 后进 AgentRuntime。
- agent-native slash 只有在 allowlist 中才透传。
- unsupported 不透传给 Agent。

Renderer 可提供更宽松策略，但必须是用户明确选择或配置，不允许隐式放行。

### 11.2 CustomCommand 数据模型

新增或完善 custom command schema。

字段建议：

- `id`
- `name`
- `description`
- `kind`: `prompt` 或 `exec`
- `prompt`
- `exec`
- `workDir`
- `source`
- `enabled`
- `allowedPlatforms`
- `adminOnly`
- `createdAt`
- `updatedAt`

要求：

- `prompt` 和 `exec` 互斥。
- name 规范化。
- `-` 和 `_` 兼容解析。
- disabled command 不发布、不执行。

### 11.3 Prompt 模板展开

必须对齐 CC Connect `ExpandPrompt`。

至少支持：

- `{{1}}`
- `{{2}}`
- `{{2*}}`
- `{{args}}`
- 默认值语法，如果 CC Connect 支持则照源码实现。

测试必须覆盖：

- 参数不足。
- 多词参数。
- 中文参数。
- 引号参数。
- 空参数。

### 11.4 Exec command

exec custom command 必须走：

- PermissionGuard。
- AuditSink。
- ControlledProcessRunner。
- workspace cwd 解析。
- timeout。
- 输出截断。

远程 Feishu/Bridge 入口执行 exec command 必须需要 admin 或显式 allowlist。

不要直接 `child_process.exec`。

### 11.5 `/commands` 管理命令

至少支持：

- `/commands`
- `/commands list`
- `/commands add`
- `/commands delete`

如果 CC Connect 还有更多子命令，以源码为准评估迁移。

Renderer UI 可以提供更清晰的创建/编辑表单，但聊天命令仍需要基本可用。

## 12. SkillRegistry 要求

### 12.1 复用 Synapse 现有 skills 模块

当前仓库已有：

- `desktop/src/modules/skills/`
- `desktop/src/config/content-types/skill.ts`
- `desktop/src/config/categories/skills.ts`
- `desktop/src/ide-definitions/shared-skill-frontmatter.ts`

必须先理解这些现有能力，再决定如何接入 AgentRuntime。

不要另起一套完全独立的 skill 数据模型，导致 UI skills 和 Agent slash skills 分裂。

### 12.2 Skill 发现

SkillRegistry 至少发现：

- 项目 `.agents/skills`
- 项目 `.codex/skills`
- 项目 `.claude/skills`
- 用户级 Codex skills 目录，如果当前项目已有路径约定
- 用户级 Claude skills 目录，如果当前项目已有路径约定

具体路径以 Synapse 和 CC Connect 源码映射为准。

### 12.3 SKILL.md 解析

必须支持：

- frontmatter `name`
- frontmatter `description`
- 正文 instruction
- 缺失 name 时的 fallback
- 名称规范化
- 缓存与刷新

### 12.4 Skill invocation

`/skill-name args` 应构造成 Agent prompt。

要求：

- prompt 结构参考 CC Connect `BuildSkillInvocationPrompt`。
- 保留当前 session/workspace/reply target。
- 走 AgentRuntime queue/permission。
- 不绕过 command governance。

### 12.5 Skill UI

如果现有 skills UI 已经能管理 skill，不要重做。

本阶段需要补的是：

- Chat command palette 能看到可调用 skill。
- skill detail 能显示它是否可作为 slash command 调用。
- 如果有刷新/扫描按钮，使用现有 UI 风格。

本阶段不要求做 skill marketplace 安装，除非仓库已有成熟基础。

## 13. CommandPublisher 要求

实现一个统一发布层，把可用命令发布到：

- Renderer command palette。
- Bridge capabilities snapshot。
- Feishu `/commands` 或 `/help` 输出。

发布时必须考虑：

- disabled commands。
- role/admin。
- 当前 platform。
- 当前 project。
- 当前 workspace。
- command 是否 enabled。
- skill 是否可用。
- agent-native slash allowlist。

不要让 UI 展示用户无权执行的 exec command。

## 14. Agent-native slash allowlist 要求

CC Connect 未知 slash 会提示 unknown 后继续发给 Agent。Synapse 在远程入口上必须更保守。

本阶段要提供产品化配置：

- 允许哪些 agent-native slash 透传给 Agent。
- 哪些入口允许透传：renderer、Bridge、Feishu。
- 默认远程入口不透传。
- renderer 可以单独允许。

建议 schema：

- `agentNativeSlash.allowlist`
- `agentNativeSlash.platforms`
- `agentNativeSlash.defaultPolicy`

必须测试：

- Feishu 未授权 unknown slash 不进 Agent。
- allowlist 中的 slash 进入 Agent。
- built-in command 优先于 allowlist。
- custom command/skill 优先于 agent-native passthrough。

## 15. Renderer command palette 要求

在 Chat 输入体验中增加命令面板。

要求：

- 使用 `desktop/src/components/ui/command.tsx` 或现有 shadcn command 组件。
- 输入 `/` 时可展示命令。
- 支持 built-in/custom/skill 分组。
- 支持搜索。
- 支持键盘选择。
- 选择后填入命令或直接执行，按现有交互选择最小改动。
- 不写说明废话。

显示信息应包括：

- 命令名。
- 简短描述。
- 类型。
- 是否需要 admin。

不要做复杂营销式空状态。

## 16. Bridge capabilities 要求

Bridge adapter 应能收到命令能力快照。

要求：

- 注册时发送 initial capabilities snapshot。
- commands/skills 变化时发送更新。
- snapshot 尊重 disabled/admin/platform policy。
- adapter 不支持 command palette 时不强推复杂 payload。

至少测试：

- 新增 custom command 后 capabilities 更新。
- 删除 command 后 capabilities 更新。
- skill 扫描刷新后 capabilities 更新。
- disabled command 不发布。

## 17. Feishu 命令可用性要求

本阶段不要求创建 Feishu 原生菜单。

但 Feishu 里应能：

- 通过 slash 调用 custom prompt command。
- 通过 slash 调用 skill。
- 通过 `/commands` 查看可用命令。
- 通过 `/show` 查看 workspace 内文件片段。
- 对 exec command 执行严格权限控制。
- 对 unknown slash 使用 allowlist 策略。

如果 Feishu 不支持 rich progress update，本阶段允许文本 fallback。

- Webhook。
- Relay。
- Observer。
- STT/TTS。
- daemon/self-update。
- run_as_user 完整 OS 隔离。
- 自动压缩 auto-compress。
- skill marketplace 安装。
- 大规模重做 Chat UI。
- 重新设计项目视觉风格。
- 启动 dev server 或打开 Electron/browser 验证，除非用户明确要求。
