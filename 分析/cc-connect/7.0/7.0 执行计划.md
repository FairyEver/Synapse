# 7.0 执行计划

## 目标

实现第三步：Provider、模型与基础命令控制。范围限定在 Electron main 侧服务、AgentRuntime 接入和单元测试；不做 Provider UI、Feishu/Lark、Cron、Bridge/API、side-channel、多工作区绑定。

## 计划

1. 准备与对齐
   - 确认从 `第二步` 创建 `第三步` 分支。
   - 阅读 `AGENTS.md`、3.1 总顺序、6.0 最终报告、6.0 源码映射、6.0 测试记录、7.0 任务书。
   - 复查 CC Connect 的 provider、model、mode、Codex、Claude Code 和命令路由源码。

2. ProviderConfigService
   - 扩展 `providers` schema 表达 active mode、agentTypes、env、thinking、per-agent overrides、Codex 选项。
   - 新增 `desktop/electron/services/provider-config/`。
   - 覆盖 global providers、project provider refs、project inline provider、active provider/model/mode、agentType 过滤。
   - secret 只在 `secrets` namespace 读取，普通 provider state 仅保存 `secretRef`。

3. Agent runtime view
   - Codex runtime view 生成 model/provider/baseUrl/effort/mode/env。
   - Codex 启动前写 `$CODEX_HOME/config.toml` 和 `auth.json`，文件写入经过 `PermissionGuard` 和 `AuditSink`。
   - Claude Code runtime view 生成 model/mode/env，第三方 base URL 使用 `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN`，并清空 `ANTHROPIC_API_KEY`。

4. 基础命令路由
   - 新增 AgentRuntime 内置命令路由，支持 `/model`、`/mode`、`/new`、`/status`。
   - 命令在进入 Agent 前处理，不进入 adapter。
   - `/model`、`/mode`、`/new` 关闭 live session 并清空当前 agent session id。
   - 未知 slash command 返回不支持错误，不转发给 Agent。

5. 测试与验证
   - 新增 provider-config、codex-runtime、command-router 测试。
   - 扩展 AgentRuntimeService 测试覆盖命令前置拦截和 session 清理。
   - 运行受影响单测、typecheck、全量 `desktop:test`、hard constraints。
