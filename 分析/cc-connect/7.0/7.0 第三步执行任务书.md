# 7.0 第三步执行任务书：Provider、模型与基础命令控制

## 一、步骤定位

第三步接在 `6.0 第二步：Agent 会话治理` 之后执行。当前仓库已经具备：

- `AgentRuntimeService` 的会话创建、会话续接、同会话队列、权限请求和治理入口。
- `CodexExecAdapter` 与 `ClaudeCodeAdapter` 的基础参数入口。
- `providers`、`secrets`、`projects` 等 DataRepository schema 占位。

本步骤的目标不是做远程连接、飞书、定时任务或 UI，而是把 Agent 启动参数从硬编码或构造参数推进到可持久化的产品状态：Provider、模型、模式和基础 slash 命令必须先稳定下来，后续飞书/定时任务/多工作区才能可靠地复用同一套运行参数。

## 二、本步骤目标

1. 建立 `ProviderConfigService`
   - 管理全局 provider。
   - 管理项目级 provider refs、内联 provider、active provider、active model、active mode。
   - API key 等敏感值只通过 `secretRef` 引用，不把明文暴露给 renderer 或普通事件。
   - 支持按 agentType 解析 provider，至少覆盖 `codex` 与 `claude-code`。

2. 生成 Agent runtime view
   - Codex：从 ProviderConfigService 解析 `model`、`provider`、`baseUrl`、`effort`、`mode`、env、Codex provider config 写入需求。
   - Claude Code：从 ProviderConfigService 解析 `model`、`mode`、env；第三方 base URL 使用 `ANTHROPIC_AUTH_TOKEN`/`ANTHROPIC_BASE_URL` 的兼容策略。
   - Adapter 不直接读仓库配置；由 service 层注入解析后的运行视图。

3. 建立基础命令路由
   - 支持 `/model`、`/mode`、`/new`、`/status`。
   - 这些命令由 Synapse runtime 内部处理，不转发给 Agent。
   - `/model` 修改 provider 当前模型并持久化；下一轮 Agent 使用新模型。
   - `/mode` 修改运行模式并持久化；下一轮 Agent 使用新模式。
   - `/new` 关闭当前 live session，清空当前 agent session id，让下一轮创建新会话。
   - `/status` 返回当前 provider/model/mode/session 状态。
   - 未知 slash command 必须有明确策略：默认按普通消息转发，或返回不支持错误；本步骤要在代码和测试里固定策略。

## 三、不能做的内容

- 不做 Provider UI，不改 renderer 可视界面。
- 不做飞书/Lark、Cron、Bridge/API、侧边通道、多工作区绑定。
- 不增加新依赖，除非先证明现有工具无法完成。
- 不把 secret 明文写进普通 JSON namespace、日志、event payload 或 renderer API。
- 不启动 dev server，不用浏览器/Playwright/Chrome DevTools 验证。
- 不绕开 `ServiceRegistry`、`DataRepository`、`PermissionGuard`、`AuditSink`、`IpcRegistry`、`EventBus` 等既有边界。

## 六、建议实施顺序

### A. 先建类型与 ProviderConfigService

建议新增或扩展：

- `desktop/electron/services/provider-config/`
- `desktop/electron/services/provider-config/provider-config-service.ts`
- `desktop/electron/services/provider-config/types.ts`
- `desktop/electron/services/provider-config/index.ts`
- `desktop/electron/services/provider-config/__tests__/provider-config-service.test.ts`

最小能力：

- `listGlobalProviders()`
- `upsertGlobalProvider(input)`
- `removeGlobalProvider(providerId)`
- `getProjectProviderState(projectId, agentType)`
- `setProjectProviderRefs(projectId, refs)`
- `setActiveProvider(projectId, providerId | null)`
- `setActiveModel(projectId, model)`
- `setActiveMode(projectId, mode)`
- `resolveRuntimeConfig(projectId, agentType)`

解析规则必须覆盖：

- global provider + project providerRefs。
- project inline provider 覆盖同名 global provider。
- agentType 过滤。
- per-agent overrides：endpoint、model、model list、Codex config。
- active provider 不存在时回退到项目 activeModel。
- provider model 更新优先更新 active provider；无 active provider 时更新 project activeModel。

### B. 再接入 AgentRuntimeService 工厂

建议修改：

- `desktop/electron/services/agent-runtime/index.ts`
- `desktop/electron/services/agent-runtime/agent-runtime-service.ts`
- `desktop/electron/services/agent-runtime/types.ts`

目标：

- `createAgentRuntimeProjectService()` 创建 runtime 时不再固定 `new CodexExecAdapter(runner)` 的静态空配置，而是让每轮 turn 或每次创建 session 前拿到 runtime view。
- 如果短期保留 Codex 默认 adapter，也要让 `/model`、`/mode` 的变更能影响下一轮。
- 为 live session 增加可控关闭方法，例如 `resetSession(sessionKey, platform)`，供 `/new`、`/model`、`/mode` 调用。

### C. 实现 Codex runtime view

建议修改：

- `desktop/electron/services/agent-runtime/adapters/codex-exec.ts`
- 视实现需要新增 `desktop/electron/services/provider-config/codex-runtime.ts`

目标：

- `buildCodexExecArgs` 已有参数入口，补足从 provider runtime view 到参数的连接。
- `$CODEX_HOME/config.toml` 写入要复刻 CC Connect 的 section upsert 语义。
- `$CODEX_HOME/auth.json` 写入要只写到 Codex home，权限和审计要覆盖。
- 测试必须验证：
  - provider/model/baseUrl/effort/mode 注入到 exec args。
  - config.toml upsert 不破坏其他 provider section。
  - auth.json 权限为 `0o600` 或等价安全策略。
  - secret 明文不进入普通 provider JSON。

### D. 实现 Claude Code runtime view

建议修改：

- `desktop/electron/services/agent-runtime/adapters/claude-code.ts`
- 视实现需要新增 `desktop/electron/services/provider-config/claude-code-runtime.ts`

目标：

- 将 provider baseUrl/apiKey/model/custom env 转换为 Claude Code env。
- 第三方 baseUrl 使用 `ANTHROPIC_AUTH_TOKEN`，同时清空或覆盖 `ANTHROPIC_API_KEY` 的策略要测试。
- 没有 baseUrl 但有 API key 时使用 `ANTHROPIC_API_KEY`。
- 支持 `ANTHROPIC_MODEL`。

### E. 实现基础 CommandRouter

建议新增：

- `desktop/electron/services/agent-runtime/command-router.ts`
- `desktop/electron/services/agent-runtime/__tests__/command-router.test.ts`

最小命令：

- `/status`
  - 返回当前 agentType、provider、model、mode、conversation id、agent session id。
- `/model`
  - 无参数：列出可选模型和当前模型。
  - `/model <model>` 与 `/model switch <model-or-index>`：切换模型。
  - 切换后关闭当前 live session，清空 current agent session id。
- `/mode`
  - 无参数：列出可选模式和当前模式。
  - `/mode <mode>`：切换并持久化。
  - 切换后关闭当前 live session，清空 current agent session id。
- `/new`
  - 关闭当前 live session，清空 current agent session id。
  - 不删除历史；如要清历史必须明确解释并测试。

未知 slash command：

- 推荐策略：返回 `不支持的命令：/xxx`，不发送给 Agent，避免把用户以为的控制命令误发给模型执行。
- 如果决定转发给 Agent，必须写入最终报告并说明安全权衡。

## 七、验收标准

代码验收：

- ProviderConfigService 能通过 DataRepository 读写 provider/project/secret 引用。
- API key 不在 renderer、普通 event、普通 provider namespace 或日志里明文出现。
- Codex 的 model/provider/baseUrl/effort/mode 能由 provider 配置生成。

- `/new` 后下一轮不会复用旧 agent session id。
- 未知 slash command 策略固定且有测试。
