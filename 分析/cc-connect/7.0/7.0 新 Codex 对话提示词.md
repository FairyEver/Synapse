## 本步骤要实现的功能

1. ProviderConfigService
   - 管理全局 provider。
   - 管理项目 provider refs、active provider、active model、active mode。
   - secret 只使用 `secretRef`，不把 API key 明文暴露给 renderer、普通 event、普通 provider JSON 或日志。
   - 支持按 agentType 解析 provider，至少覆盖 `codex` 与 `claude-code`。

2. Agent runtime view
   - Codex：从 provider 配置生成 `model`、`provider`、`baseUrl`、`effort`、`mode`、env，并完成 `$CODEX_HOME/config.toml` 与 `auth.json` 写入逻辑；敏感文件写入必须经过 PermissionGuard/AuditSink。
   - Claude Code：从 provider 配置生成 `model`、`mode`、env；第三方 base URL 使用 `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN` 策略。
   - Adapter 不直接读取 DataRepository，由 service 层注入解析后的 runtime view。

3. 基础命令路由
   - `/model`
   - `/mode`
   - `/new`
   - `/status`
   - 这些命令必须在进入 Agent 前处理，不发送给 Agent。
   - `/model`、`/mode` 修改持久化配置后，要关闭当前 live session 并清空 current agent session id，使下一轮使用新参数。
   - `/new` 要关闭当前 live session 并清空 current agent session id。
   - 未知 slash command 要有明确策略并写测试；推荐返回不支持错误，不转发给 Agent。
