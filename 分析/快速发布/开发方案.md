# 快速发布开发方案

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` to execute this plan.

## Goal

实现 IDE 扫描页中本地 Skill / Rule 的快速发布能力：

- 未关联仓库内容的本地项，在详情弹窗中显示 `发布到仓库`。
- 已有关联 `synapseContentId` 的本地项，在详情弹窗中显示 `从仓库中显示`。
- 点击 `发布到仓库` 后，基于本地扫描项生成创建草稿，切换到对应的 `技能` 或 `规则` 页面，自动打开现有创建弹窗，并填入能够确定的数据。
- 点击 `从仓库中显示` 后，切换到对应页面并打开仓库中该内容的详情弹窗。
- 不做分类 / 关键词预填，分类由用户自行选择。
- Skill 发布附件范围与扫描范围保持一致：扫描 Skill 文件夹时纳入的文件，发布时同范围纳入；`SKILL.md` 作为正文，其余同目录递归文件作为附件。

## Architecture

快速发布采用“扫描详情弹窗发起、主进程准备本地文件快照、渲染层复用现有创建表单、App Shell 负责跨 Tab 导航”的架构。

核心原因：

- Renderer 不能直接读本地文件和二进制附件，文件快照必须由 Electron 主进程完成。
- 规则 / 技能的创建、校验、保存已经存在，快速发布只负责生成 `initialValue`，不新建独立发布流程。
- App 当前只挂载 active tab，跨页面打开创建 / 详情弹窗需要 App Shell 承接一次 pending action。
- “从仓库中显示”应复用现有内容详情弹窗，避免出现第二套仓库内容展示逻辑。

## 已读代码结论

### IDE 扫描入口

- `desktop/src/modules/editor-scan/index.tsx`
  - 负责 `selectedEditorId`、`contentTab`、`scopeTab` 和 `ScanItemDetailDialog`。
  - 当前 `handleItemClick` 只传 `type/name/path/source/preview/fileCount/metadata`，需要补充 `synapseContentId`、CLI 名称、作用域、项目名、规则精确正文。
- `desktop/src/modules/editor-scan/components/global-overview.tsx`
  - 全局 Skill / Rule 列表入口，需要把 editor 上下文传给详情弹窗。
- `desktop/src/modules/editor-scan/components/project-overview.tsx`
  - 项目 Skill / Rule 列表入口，需要把 project 上下文传给详情弹窗。
- `desktop/src/modules/editor-scan/components/scan-item-detail-dialog.tsx`
  - 已有详情弹窗、复制内容、Finder 打开、Skill 文件列表。
  - 这里是新增 `发布到仓库` / `从仓库中显示` 按钮的最小入口。

### 扫描服务

- `desktop/electron/services/editor-scan-service.ts`
  - Skill 扫描以目录为单位，已识别 `.synapse.json` 中的 `synapseContentId`。
  - `readItemContent(filePath)` 对 Skill 会读取主文件，对 Rule 会读取整个文件。
  - `listSkillFiles(dirPath)` 递归列出 Skill 附件，跳过主文件、`.synapse.json`、隐藏文件。
  - 当前 Codex Rule 可能从同一个 `AGENTS.md` 中解析出多个规则段，如果快速发布继续读整个文件，会发布错误正文；需要在扫描结果中保留每条 Rule 的精确正文。

### 创建表单复用

- `desktop/src/modules/rules/components/rule-create-dialog.tsx`
  - 已支持 `initialValue?: SynapseCreateRulePayload | null`。
- `desktop/src/modules/skills/components/skill-create-dialog.tsx`
  - 已支持 `initialValue?: CreateSkillPayload | null`。
  - 当前附件 draft 主要面向浏览器 `File`，快速发布需要支持主进程返回的 `Uint8Array`。
- `desktop/src/modules/content/create-content-module.tsx`
  - 现有工厂未把跨模块 pending action 接进来，也未把 `initialValue` 透传到创建弹窗类型上。
- `desktop/src/modules/content/components/content-browser-page.tsx`
  - 现有详情弹窗只由列表点击打开，需要新增按 `contentId` 打开详情的外部请求入口。

### 跨 Tab 导航

- `desktop/src/App.tsx`
  - 只挂载当前 active tab，对应模块切换后才存在。
  - 快速发布必须由 App 层先切 tab，再把 pending action 传给目标内容模块消费。
- `desktop/src/app-shell/navigation.ts`
  - 当前只有设置页导航事件，可以新增内容打开事件或独立 `content-navigation.ts`。

## Data Contract

### 扫描项详情类型

扩展 `desktop/src/types/editor-scan.ts`：

```ts
export type EditorScanScope = "global" | "project";

export type ScanItemForDetail = {
  type: "skill" | "rule";
  name: string;
  path: string;
  source: string;
```

`content` 只用于 Rule 的精确正文，尤其是 Codex `AGENTS.md` 多段规则。Skill 正文和附件仍由主进程按目录快照读取，避免 renderer 信任过期列表。

## Field Mapping

### Rule

| 目标字段 | 来源 | 规则 |
| --- | --- | --- |
| `name` | 文件名 / metadata.name | 优先 `metadata.name`，否则文件名去 `.md`，再走现有 `normalizeCreateRulePayload` |
| `title` | 正文 H1 / 文件名 | 第一行 `# 标题` 优先，否则使用格式化后的文件名 |
| `description` | metadata.description / 正文首段 | 优先 metadata，否则取首个非标题、非 frontmatter 的正文段落 |
| `content` | Rule 精确正文 | 文件型规则为完整 md；Codex 段规则为该段规则正文 |
| `category` | 无 | 留空，不预填 |
| `icon` / `iconBg` | 默认值 | 使用现有创建 payload 默认值，只补一个可保存的默认 icon |

### Skill

| 目标字段 | 来源 | 规则 |
| --- | --- | --- |
| `name` | `SKILL.md` frontmatter name / 文件夹名 | 优先 frontmatter name，否则目录名 |
| `title` | frontmatter title / name | 优先 title，否则 name |
| `description` | frontmatter description / 正文首段 | 优先 description，否则正文首段 |
| `content` | `SKILL.md` 主说明内容 | 去掉 YAML frontmatter 后填入 |
| `category` | 无 | 留空，不预填 |
| `files` | Skill 文件夹快照 | 递归包含扫描范围内除主文件、`.synapse.json`、隐藏文件外的文件 |
| `icon` / `iconBg` | 默认值 | 使用现有创建 payload 默认值，只补一个可保存的默认 icon |

## Implementation Steps

### 1. 补齐扫描结果中的上下文与 Rule 精确正文

文件：

- `desktop/src/types/editor-scan.ts`
- `desktop/electron/services/editor-scan-service.ts`
- `desktop/src/modules/editor-scan/index.tsx`
- `desktop/src/modules/editor-scan/components/global-overview.tsx`
- `desktop/src/modules/editor-scan/components/project-overview.tsx`

改动：

1. 给 Rule scan item 增加可选 `content`。
2. Codex `AGENTS.md` 的每个规则段扫描结果写入该段精确正文。
3. 文件型 Rule 扫描结果写入完整文件正文，或在后续 prepare 阶段按 path 读取完整文件。
4. `handleItemClick` 传入：
   - `synapseContentId`
   - `editorId`
   - `editorLabel`
   - `scope`
   - `projectName`
   - `content`
5. Project / Global 列表点击时带上对应上下文。

验证点：

- Codex 同一 `AGENTS.md` 中多个规则打开详情时，预览和发布正文不串段。
- 已关联内容的扫描项在详情弹窗可以拿到 `synapseContentId`。

### 2. 新增主进程快速发布快照 IPC

文件：

- `desktop/electron/services/editor-scan-service.ts`
- `desktop/electron/modules/editor-scan/ipc.ts`
- `desktop/electron/preload.ts`
- `desktop/src/types/bridge.ts`
- `desktop/electron/generated/ipc-channels.generated.ts`

新增服务方法：

```ts
prepareQuickPublishDraft(
  request: EditorScanQuickPublishRequest,
): Promise<EditorScanQuickPublishDraft>;
```

Rule 行为：

1. 优先使用 `request.ruleContent`。
2. 没有 `ruleContent` 时读取 `itemPath` 文件。
3. 文件不存在、读取失败、正文为空时抛出可读错误。

Skill 行为：

1. 校验 `itemPath` 是存在的目录。
2. 按现有 Skill 主文件查找规则优先读取 `SKILL.md`。
3. 复用 `listSkillFiles` 的递归范围生成附件快照。
4. 附件返回 `originalName`、`size`、`bytes`。
5. 跳过主文件、`.synapse.json`、隐藏文件，保持扫描与发布范围一致。

IPC：

- 新增 channel `synapse:editor-scan:prepare-quick-publish-draft`。
- preload 暴露 `window.synapse.editorScan.prepareQuickPublishDraft(request)`。
- 运行 `pnpm --filter @synapse/desktop run generate:ipc` 更新 generated channel 文件。

健壮性：

- 读取时重新扫描文件系统，不信任详情弹窗里的旧附件列表。
- 任一附件读取失败时整体失败，并提示用户重新扫描或检查文件。
- 不在 renderer 暴露本地文件路径读取能力。

### 3. 新增快速发布 payload 构建工具

文件：

- `desktop/src/modules/editor-scan/lib/quick-publish.ts`
- `desktop/src/modules/editor-scan/__tests__/quick-publish.test.ts`

职责：

1. 将 `EditorScanQuickPublishDraft` 转换为 `SynapseCreateRulePayload` 或 `CreateSkillPayload`。
2. 复用现有：
   - `createEmptyRulePayload`
   - `normalizeCreateRulePayload`
   - `createEmptySkillPayload`
   - `normalizeCreateSkillPayload`
   - `normalizeSkillAttachmentName`
3. 提供纯函数：
   - `buildRuleQuickPublishPayload(draft)`
   - `buildSkillQuickPublishPayload(draft)`
   - `formatQuickPublishSourceLabel(item)`

规则：

- 不预填分类。
- 不预填关键词。
- 不新建一套校验规则，最终仍交给现有创建弹窗校验。
- Skill 附件 draft 支持 `bytes`：

```ts
export type SkillCreateFilePayloadDraft = {
  originalName: string;
  sha256?: string;
  size: number;
  file?: File;
  bytes?: Uint8Array;
};
```

同时更新 `desktop/src/modules/skills/utils.ts` 的 `serializeCreateSkillFiles`：

- 有 `file` 时保持现有逻辑。
- 有 `bytes` 时直接传给 content write payload。
- 有 `sha256` 且无 bytes / file 时视为已有附件复用。

### 4. 打通 App Shell 内容打开请求

文件：

- `desktop/src/app-shell/content-navigation.ts`
- `desktop/src/App.tsx`
- `desktop/src/modules/content/create-content-module.tsx`
- `desktop/src/modules/content/components/content-browser-page.tsx`

新增能力：

1. `requestOpenContentCreate(request)`：切换到 `rule` / `skill` tab，并打开创建弹窗。
2. `requestOpenContentDetail(request)`：切换到 `rule` / `skill` tab，并按 `contentId` 打开详情弹窗。
3. `MainApp` 订阅内容打开请求：
   - `setActiveTab(contentType)`
   - 保存 `pendingContentOpenRequest`
   - 目标模块消费后调用 `onPendingContentOpenRequestConsumed(requestId)`
4. `createContentModule` 支持：
   - create request：设置 `initialValue`，打开创建弹窗。
   - detail request：传给 `ContentBrowserPage`。
5. `ContentBrowserPage` 支持按 `contentId` 打开详情：
   - 等待 `items` 加载完成。
   - 找到对应 item 后打开现有详情弹窗。
   - 找不到时回调通知请求方。

边界：

- 只有当前仓库非删除内容会出现在列表里；已删除内容由发起方先用 `readDetail` 判断。
- `requestId` 避免 Strict Mode / effect 重跑导致重复打开。
- 模块切换期间不丢请求。

### 5. 修改扫描详情弹窗操作区

文件：

- `desktop/src/modules/editor-scan/components/scan-item-detail-dialog.tsx`
- `desktop/src/modules/editor-scan/lib/quick-publish.ts`
- `desktop/src/app-shell/content-navigation.ts`

UI 行为：

1. `item.synapseContentId` 存在：
   - 主按钮文案：`从仓库中显示`
   - 点击后调用 `readDetail(item.type, item.synapseContentId)`。
   - detail 存在且未删除：关闭扫描详情，发起 detail 打开请求。
   - detail 不存在或已删除：打开确认弹窗，允许 `作为新内容发布`。
2. `item.synapseContentId` 不存在：
   - 主按钮文案：`发布到仓库`
   - 点击后调用 `prepareQuickPublishDraft`。
   - 构建 payload。
   - 关闭扫描详情。
   - 发起 create 打开请求。

禁用条件：

- 没有 active repo。
- 仓库 profile 需要补充。
- 当前有 pending sync / push。
- 本地文件正在读取。
- 当前扫描项路径为空或读取失败。

错误处理：

- 读取失败：在详情弹窗内显示简短错误，保留弹窗。
- 创建弹窗打开后校验失败：复用现有表单错误展示。
- 附件过大 / 重名：复用 Skill 创建表单现有校验。

来源标识：

- 创建弹窗显示 `来自 Claude Code · 项目 Rule` 或 `来自 Codex · 全局 Skill`。
- 该文案通过 `sourceLabel` 传入现有 `ContentCreateDialog` 的 description，不额外增加解释性段落。

- `desktop/src/modules/skills/components/skill-create-dialog.tsx`

2. 通过现有 `FormDialog` description 展示来源。
3. `RuleCreateDialog` / `SkillCreateDialog` 继续使用 `useContentCreateForm(initialValue)`。

### 7. 已关联内容显示与降级发布

文件：

- `desktop/src/modules/editor-scan/components/scan-item-detail-dialog.tsx`
- `desktop/src/app-shell/content.ts`
- `desktop/src/app-shell/content-navigation.ts`

流程：

1. 点击 `从仓库中显示`。
2. 调用 `readDetail(type, synapseContentId)`。
3. 结果判断：
   - `deleted === false`：打开详情。
   - `deleted === true`：弹出确认，说明仓库内容已删除，可作为新内容发布。
   - throw / not found：弹出确认，说明仓库内容不可用，可作为新内容发布。
4. 用户选择 `作为新内容发布` 后走未关联发布流程，但不修改本地 `.synapse.json`。

不自动修复关联文件，避免误写用户本地扫描来源。

## Edge Cases

- **没有当前仓库**：详情按钮禁用，提示先切换仓库。
- **仓库 profile 未完成**：按钮禁用，复用创建页保存前置条件。
- **同步中 / 有待推送状态**：按钮禁用，避免创建状态与仓库状态冲突。
- **文件被删除**：prepare 阶段失败，提示重新扫描。
- **Skill 主文件缺失**：prepare 阶段失败，不打开创建弹窗。
- **Skill 附件读取失败**：整体失败，避免发布半截附件集合。
- **Skill 附件超 10MB**：创建弹窗校验拦截，用户可删除附件后继续。
- **Skill 附件重名**：创建弹窗校验拦截。
- **Skill 二进制附件**：以 `Uint8Array` 透传，不能通过字符串读取。
- **隐藏文件 / `.synapse.json`**：不作为附件发布。
- **Codex 多段规则**：发布当前扫描项对应的规则段，不发布整份 `AGENTS.md`。
- **已关联内容被删除**：显示降级发布入口，不自动覆盖关联。
- **已关联内容不在当前仓库**：按不可用处理，允许作为新内容发布。
- **重复点击按钮**：按钮进入 loading，使用 requestId 去重。
- **切换 Tab 后目标模块还未挂载**：App Shell 保存 pending action，挂载后消费。
