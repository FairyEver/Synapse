# 本地 Skill / Rule 快速发布产品设计

## 1. 目标

把 IDE 扫描页中本地可识别的 Skill 和 Rule 快速发布到当前 Synapse 仓库。

用户在本地 IDE 详情弹窗中点击发布后，系统切换到对应的「技能」或「规则」页面，自动打开新建弹窗，并尽量预填可确定字段；用户只补齐无法可靠推断的信息，确认后保存并走现有仓库同步链路。

这里的仓库只指当前激活的 Synapse 内容仓库。当前代码没有公开市场发布能力，也不把快速发布设计成新的远端分发入口。

## 2. 设计判断

推荐采用「详情弹窗一键带入新建弹窗」方案。

原因：

- 复用现有 Rule / Skill 新建弹窗、校验、重复名称提醒、仓库同步、身份拦截，不额外造一套发布表单。
- 用户可在熟悉的仓库页面完成最后确认，避免“扫描页发布成功但不知道去了哪里”的断层。
- 发布动作从本地来源发起，但最终所有权属于当前 Synapse 仓库，页面切换能强化这个心智。
- 对 Skill 附件、Rule 正文、分类、图标等已有差异保持一致处理，不把两个内容类型硬塞进同一个复杂弹窗。

不建议做独立“快速发布向导”。它会重复已有新建弹窗逻辑，还会让保存、冲突、同步、身份状态多一套入口，维护和用户理解成本都更高。

## 3. 用户链路

### 3.1 主链路

1. 用户进入 IDE 扫描页。
2. 用户选择编辑器、类型 Skill / Rule、范围 全局 / 项目。
3. 用户点击某个本地项，打开详情弹窗。
4. 详情弹窗顶部操作区展示「发布到仓库」按钮。
5. 用户点击后：
   - Rule 切换到「规则」页。
   - Skill 切换到「技能」页。
   - 自动打开新建弹窗。
   - 表单预填可确定信息。
6. 用户补齐分类、图标等不可确定字段。
7. 用户点击保存。
8. 使用现有保存与同步反馈：保存成功、已保存并同步、同步中、保存失败。

### 3.2 二次确认链路

如果当前扫描项已经有 `synapseContentId`，按钮文案改为「从仓库中显示」。

点击后优先跳到对应内容页并打开详情弹窗，而不是再次新建。若目标内容已删除或读取失败，再提供「作为新内容发布」入口。

### 3.3 用户改动保护

如果用户已经在目标页面的新建弹窗里编辑了未保存内容，再从扫描页触发发布：

- 如果是同一个来源项，保持当前草稿，不覆盖。
- 如果是不同来源项，先提示「放弃当前填写内容？」。
- 用户确认后再替换为新扫描项的预填草稿。

## 4. 信息架构

### 4.1 扫描详情弹窗

在现有「复制内容」「在 Finder 中显示」同一操作区增加主操作：

- 外部项且未发布：`发布到仓库`
- Synapse 来源或已关联仓库内容：`从仓库中显示`
- 无法读取内容：禁用，原因显示为 `内容读取失败`
- 当前仓库不可写：禁用，原因沿用现有仓库状态，如 `先完成当前目录的身份设置`、`正在同步变更，请稍后`

按钮位置建议放在操作区左侧第一个，作为当前详情弹窗的主要动作；复制、Finder、预览/源码仍保留原位置。

### 4.2 目标新建弹窗

不新增“导入来源”视觉区域，只在表单底部或标题旁展示极简来源标识：

`来自 Claude Code · 项目 Rule`

这条信息只用于确认来源，不解释实现，不写长说明。

## 5. 字段预填策略

原则：只预填确定性高的内容；不确定字段留给用户，避免系统猜错导致仓库内容质量下降。

| 字段 | Rule 预填 | Skill 预填 | 说明 |
| --- | --- | --- | --- |
| 名称 `name` | 从文件名去扩展名或 metadata.name | 从目录名或 metadata.name | 统一规范化为小写字母、数字、连字符 |
| 标题 `title` | Markdown 第一个 H1，其次文件名 | `SKILL.md` frontmatter name，其次第一个 H1，其次目录名 | 标题保留可读性，不强制英文 |
| 简介 `description` | 第一段正文或 H1 后第一句 | frontmatter description，其次第一段正文 | 超长时截断，用户可编辑 |
| 正文 `content` | 读取完整 md 内容 | `SKILL.md` 主说明内容 | 保留源码，不自动改写 |
| 分类 `category` | 不预填 | 不预填 | 用户必须手动选择 |
| 图标 `icon` / 背景 | 使用内容类型默认值 | 使用内容类型默认值 | 不根据文件内容猜视觉风格 |
| 附件 `files` | 无 | 扫描到的同一 Skill 文件夹内，除 `SKILL.md` 外的所有文件 | 发布范围与扫描范围一致；保留相对路径；超过大小、重复名按现有校验处理 |

## 6. 数据完整性

### 6.1 发布草稿对象

扫描页向目标模块传递一个发布草稿，而不是直接写仓库：

```ts
type QuickPublishDraft = {
  sourceType: "skill" | "rule"
  editorId: string
  scope: "global" | "project"
  sourcePath: string
  sourceName: string
  source: "synapse" | "external"
  synapseContentId: string | null
  payload: SynapseCreateRulePayload | SynapseCreateSkillPayload
}
```

草稿只负责打开新建弹窗和预填，不绕过现有表单校验。

### 6.2 校验要求

进入新建弹窗前需要完成：

- 源文件仍存在。
- Rule 正文可读取且非空。
- Skill 目录可读取，且 `SKILL.md` 可定位。
- Skill 附件范围与扫描结果一致，保留相对路径，过滤隐藏系统文件和无效路径。
- 名称满足现有 3-64 字符规则。
- 当前仓库 ready，且不处于阻塞同步状态。

保存时继续使用现有校验：

- 标题、简介、分类、正文必填。
- 图标或图片必填。
- 名称重复时展示现有重复提醒。
- Skill 单附件最大 10MB。
- Skill 附件名不重复。

### 6.3 重复发布处理

重复判断优先级：

1. `synapseContentId` 存在：视为已发布，主操作进入详情。
2. 当前仓库存在同名 `name`：打开新建弹窗但展示现有「名称重复」提醒，用户可改名或继续保存。
3. 路径与历史来源一致但无内容 ID：提示用户可能已发布过，仍允许继续。

## 7. 状态与异常

| 场景 | 体验 |
| --- | --- |
| 正在读取本地内容 | 按钮进入 loading，弹窗不关闭 |
| 读取失败 | 保留详情弹窗，提示 `读取失败` |
| 当前无仓库 | 按钮禁用，原因 `先选择本地目录` |
| 仓库身份未设置 | 按钮禁用，原因沿用 `请先完成当前目录的身份设置` |
| 正在同步 | 按钮禁用，原因 `正在同步变更，请稍后` |
| 目标页打开失败 | 停留 IDE 详情弹窗，提示 `打开发布页失败` |
| 用户关闭预填弹窗 | 若内容被编辑，沿用现有放弃确认 |
| 保存失败 | 沿用现有表单错误和 toast |

## 8. UE 细节

- 按钮文案只保留动作，不写解释型文案。
- 详情弹窗内不新增大段说明；来源、路径、文件数已经足够。
- 切换页面后新建弹窗直接获得焦点，优先聚焦第一个未通过校验或未填写字段。
- 已预填字段不加“自动填充”标签，避免视觉噪音。
- 分类不做关键词预填；焦点可以落在分类字段。
- 用户保存成功后停留在目标内容页，列表中出现新内容；不自动跳回 IDE 扫描页。
- 保存成功后再次扫描时，该项应显示为 Synapse / 已关联状态，避免重复发布。

## 9. 最小可交付范围

第一版只做单项发布：

- IDE 扫描详情弹窗增加发布入口。
- 支持 Rule 单文件发布。
- 支持 Skill 目录发布，包含附件。
- 支持跳转到对应页面并打开新建弹窗。
- 支持预填标题、名称、简介、正文、附件。
- 复用现有保存、重复名、同步、身份校验。

暂不做：

- 批量发布。
- AI 自动补全分类、简介或图标。
- 发布前 diff。
- 本地扫描项与仓库内容的复杂双向同步。
- 独立发布向导。

## 10. 成功标准

- 外部 Rule 从详情弹窗到保存完成，用户最多补 2 个必填字段。
- 外部 Skill 从详情弹窗到保存完成，附件结构不丢失。
- 已发布项不会默认再次新建，主操作为「从仓库中显示」。
- 保存失败、仓库不可写、读取失败都有明确状态。
- 新增链路不绕过现有内容表单校验和仓库同步。
